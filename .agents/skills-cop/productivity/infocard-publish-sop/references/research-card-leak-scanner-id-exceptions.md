# 研究型信息卡：来源 ID 误报处理

## 触发场景

`check-info-leak.js` 可能把今日头条、X、微博等来源 URL 中的长数字 ID 识别成手机号或信用卡片段。研究卡片通常需要保留这些链接，不能为了让扫描器安静而删除证据来源。

## 处理流程

1. 先定位告警行，判断数字是否出现在可见正文、meta、脚本或来源 URL 中。
2. 若是正文中的真实个人号码或秘密，必须删除/脱敏。
3. 若是公开来源 URL 的路径/查询参数 ID，记录为**工具误报**，保留原始链接以维护可追溯性。
4. 如仓库的发布门禁不能接受该 URL，可把来源改写为“平台名称 + 公开文章 ID + 站内检索定位”，但要同步保留可复核的来源标识，并在报告证据边界中说明链接降级。
5. 重新运行 file-scoped leak scan；同时运行 `git diff --check`、build、index verify，并在发布报告中分层写明：静态门禁、工具误报、公众可访问性。

## 本次验证经验

- EV 成本调查中，来源 URL 的数字 ID 触发了手机号/信用卡片段告警。
- 将今日头条三条 URL 改为“文章 ID + 站内检索定位”后，避免了正文文件中的误报，但 HTML 仍需根据发布门禁决定是否保留可点击链接。
- 不要把“扫描器通过”写成“所有来源均已验证”；来源可追溯性与敏感信息扫描是两个独立门禁。
