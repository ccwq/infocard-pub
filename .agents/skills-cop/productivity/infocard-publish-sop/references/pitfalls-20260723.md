## P1: 子智能体 Authoring timeout 时 worktree 无产物，主线程应直接接管 Authoring（2026-07-23 PM Codex+Skill）

**What broke**: Authoring 子智能体 `deleg_a947ece0` 报告 `status=timeout` + `api_calls=34`，主线程按 SOP 优先做 detached HEAD 恢复检查 —— `git log --all --oneline` 显示**没有新 commit**，`git status --short` 显示目标 docs 文件**不在磁盘上**。34 次 API 调用都花在思考 / 读取 / 主题分析阶段，没写出 HTML。

**根因区分**（以前没明说）:
- 早期 pattern（csrftoken / graph-engineering / 高校横向）：子智能体把 commit 留在 detached HEAD，主线程用 `git log --all --oneline` 能找到 SHA → cherry-pick 即可。
- **新 pattern（pm-codex-skill）**：子智能体在 Authoring 阶段 timeout，**根本还没 commit**；主线程必须接管 Authoring，不能期待恢复 commit。

**正确处理序列**:
```bash
# 1. 确认无产物（与 detached HEAD pattern 区分的关键步骤）
cd /tmp/infocard-<slug>
git log --all --oneline -10    # 无新 commit
git status --short            # ?? docs/<slug>.html 等
ls docs/<slug>* 2>/dev/null || echo "NOT FOUND"

# 2. 切换到命名分支（detached HEAD 上 commit 容易丢）
git checkout -b publish/<slug>-YYYYMMDD

# 3. 主线程直接 Authoring：write_file 写 HTML + meta.yaml
#    参考主题: theme/<theme>.html 头部 CSS 变量
#    参考其他卡片: docs/<similar>.html 结构

# 4. 跑 build 前先检查 meta.yaml 必填字段（见下面 P2）

# 5. build → commit → push → PR → merge

# 6. 如果中途又做了其他 PR → main 推进，push 会冲突 → rebase + --theirs（见 P3）
```

**Prevention**: 给子智能体的 context 写"如果 60s 内未写出 HTML，停下来汇报，不要反复重试"。超时策略：300s 软超时（写不出来就回报），600s 硬超时。

## P1: meta.yaml 缺 `path` / `tags` 字段触发 build 抛错（2026-07-23 PM Codex+Skill）

**What broke**: 写好 HTML + meta.yaml（仅 desc/title/slug/category/taxonomy）后跑 `npm run build`：
- 第一次报 `Error: missing path field`（位置 `scripts/sync-build-timestamps.js:58`）
- 补 `path` 后再 build，报 `Error: Index build failed: docs/<slug>.html.meta.yaml: missing fields tags`（位置 `scripts/index-build-lib.js:239`）

**根因**: `taxonomy` 和 `tags` 是两个独立字段。`taxonomy` 用于分类目录，`tags` 用于搜索/筛选。必须**两个都给**。

**完整必填字段清单**（Authoring 一次到位）:
```yaml
desc: 一句话描述（必须在 title 前面，否则 build 报 "missing fields desc"）
title: 完整标题
slug: YYYYMMDD-<slug>
path: docs/<slug>.html                       # ← 必填！
category: <category-slug>
source: <原始链接>
source_short: <短链可选>
author: <作者可选>
date: YYYY-MM-DD
taxonomy:                                     # 数组，至少 1 项
  - tag1
  - tag2
tags:                                        # ← 必填！
  - tag1
  - tag2
release_audit:                                # 可选但推荐
  built_by: hermes-agent
  built_at: YYYY-MM-DD
```

**Prevention**: Authoring 子智能体的 prompt 模板里直接附这段清单。

## P2: PR 创建后 main 推进导致 merge 冲突（2026-07-23 PM Codex+Skill）

**What broke**: 创建 PR #20 后跑 GitHub Actions 部署，期间其他 PR 合并推进 main。Squash merge 返回 `HTTP 405: Pull Request has merge conflicts`。

**正确序列**:
```bash
# 1. fetch 最新 main
git fetch origin main
git rebase origin/main

# 2. 冲突只在 _index.yaml 和 index.html → 取 --theirs（main 的版本）
git checkout --theirs _index.yaml index.html
git add _index.yaml index.html

# 3. 继续 rebase（不要手动 amend，会丢失 SHA 一致性）
GIT_EDITOR="cat" git rebase --continue

# 4. 强制推送
git push origin publish/<slug>-YYYYMMDD --force

# 5. 再 merge → PUT /repos/.../pulls/<n>/merge → 200
```

**Prevention**: 单 worktree 单 PR 时，push 之后立即 merge，避免其他 PR 推进 main。批量 PR 用独立 worktree + 主线程串行 build→push→merge。

## P1: Sidecar audit edit invalidates `_index.yaml` — second commit required (2026-07-23)

**What broke**: After pushing the content commit (HTML + meta + generated _index.yaml + index.html), added `release_audit` block to sidecar YAML. Tried `npm run verify` — it failed with `_index.yaml is out of date; run npm run build and commit the result`. The audit-only edit forced a third commit (build outputs needed to include the new sidecar content).

**Root cause**: `npm run build` regenerates `_index.yaml` and `index.html` from current sidecar contents. When the sidecar changes (audit fields added), the generated files MUST be regenerated; otherwise `verify` blocks the push.

**Correct sequence**:

```bash
# Content commit
git add docs/<slug>.html docs/<slug>.html.meta.yaml _index.yaml index.html
git commit -m "feat: publish <title>"

# After public verification, add audit fields to sidecar
# Then REGENERATE generated artifacts before second commit
npm run build        # regenerates _index.yaml + index.html with updated sidecar
npm run verify        # must pass before commit

git add docs/<slug>.html.meta.yaml _index.yaml index.html
git commit -m "audit: record <slug> public verification"
```

**Mandatory in audit commit**: only the **meta sidecar + generated indexes**, never the HTML. Use `git diff --cached --name-only` before committing.

**Prevention**: Treat the audit block as a sidecar-only edit. Plan the two commits up front:

- commit 1 = HTML + sidecar + indexes
- commit 2 = sidecar (with audit) + regenerated indexes

Never try to fold audit into the content commit — by then the content SHA referenced by the audit field would not match.

## P2: `patch` empty call returns "patch content required" error, not crash (2026-07-23)

**What broke**: Called `skill_manage(action='patch', old_string='...', new_string='...')` without including `name` field. Got `{"error": "patch content required"}` instead of execution.

**Root cause**: `patch` mode of `skill_manage` requires `name` parameter (and for mode='replace', also `old_string` + `new_string`). Without `name`, the operation refuses to run.

**Fix**: Always pass `name` explicitly when patching a skill:

```python
skill_manage(action='patch', name='skill-name', old_string='...', new_string='...')
```

**Note**: This is a safety behavior — the tool refuses rather than guessing which skill to modify. Don't be confused by the error wording; it's not a tool bug.

## P2: patch with `file was modified since you last read it on disk` warning still succeeds (2026-07-23)

**What broke**: After build script (`fix-meta-date.js` or build itself) touched a meta YAML file, called `patch` on the same file. Got warning: `"file was modified since you last read it on disk (external edit or unrecorded writer). Re-read the file before writing."` — but the patch **still applied successfully**.

**Root cause**: Patch tool uses fuzzy matching that doesn't strictly require a prior read in the same session, but warns when the file changed since last `read_file`.

**Fix**: Re-read the file with `read_file` if you need the new content for follow-up patches. If you only need the patch to apply, ignore the warning and verify with `git diff`.

**Prevention**: When chaining multiple edits on a single file, sequence operations carefully — read once, then patch, then verify with `git diff` or `read_file`.

## P2: `vision_analyze` returns screenshot of unrelated external app (2026-07-23)

**What broke**: Used `browser_vision(question=...)` to verify the rendered infocard at 390px. Got back detailed visual analysis of a Xiaohongshu / 小红书 mobile interface — completely unrelated to the current card.

**Root cause**: Vision tool occasionally routes screenshots through an external vision service that returns cached or mis-routed descriptions. The screenshot itself is correct (current page), but the analysis text is for a different page.

**Fix**: Do NOT trust `vision_analyze` text descriptions blindly. Use the actual screenshot path returned in the tool result (`screenshot_path`) to inspect the image with your own vision if needed. Otherwise:

- Use `browser_console` DOM checks (`scrollWidth`, `documentElement.clientWidth`, computed font sizes) for layout validation
- Mark `visual_status: VISUAL_PENDING` if screenshot analysis is unreliable
- Never claim "visual passed" based on a mis-routed description

**Prevention**: For 390px mobile verification, prefer DOM-only checks. Vision is for layout/spacing issues that DOM can't reveal — and only when the screenshot path is verified.

## P2: No `node_modules` in infocard-pub repo — `npm run build` still works (2026-07-23)

**What broke**: Verified worktree had no `node_modules` directory. Initially assumed build would fail. Tried `npm run build` anyway — succeeded with no errors.

**Root cause**: `infocard-pub` package.json declares `"dependencies": {}` (empty). Build script (`scripts/build-site.js`) only uses Node.js built-ins (fs, path, yaml). No third-party deps required.

**Fix**: Skip the `ln -s ../node_modules node_modules` step entirely. Run `npm run build` directly.

**Prevention**: When creating a fresh worktree for infocard-pub, do NOT symlink node_modules from main repo. If main repo also lacks it (likely state), don't try to install — just run build. `npm test` also works without dependencies (uses `node --test` which is built-in).

## P2: `npm run verify-card-content` requires `--bundle` arg, not a card gate (2026-07-23)

**What broke**: Ran `npm run verify-card-content` as part of gate sequence. Got `{"valid":false,"errors":[{"field":"bundle","message":"usage: --bundle path"}]}` with exit 2. Initially thought card content failed validation.

**Root cause**: `verify-card-content` is the v3 bundle-based gate that validates a publish bundle JSON, NOT a per-card HTML structure check. It requires `--bundle <path>` argument.

**Correct gates for per-card structure**:

- `npm run verify` → index integrity
- `node scripts/verify-mobile-card.js <slug>.html` → viewport + media query
- `node scripts/check-info-leak.js <slug>.html` → sensitive data scan
- `npm test` → repository-native tests

Skip `verify-card-content` unless you're validating a publish-bundle.json workflow.

## P6 · Stale local branch blocks `git checkout -b` after worktree add (2026-07-23)

**Symptom**: `git worktree add /tmp/xxx origin/main` succeeds (files populated) but `git checkout -b publish/xxx-YYYYMMDD` fails with `fatal: a branch named 'publish/xxx-YYYYMMDD' already exists`.

**Root cause**: `git worktree remove --force` deletes the worktree directory but leaves the local branch ref intact. `checkout -b` refuses to create over an existing branch name.

**Deterministic recovery**:

```bash
git branch -D publish/xxx-YYYYMMDD      # 1. delete stale local branch FIRST
git worktree remove /tmp/xxx --force    # 2. remove worktree
git worktree add /tmp/xxx origin/main   # 3. fresh worktree
cd /tmp/xxx
git checkout -b publish/xxx-YYYYMMDD     # 4. now succeeds
```

**Prevention**: Before `worktree add`, always check and delete any stale local/remote branch refs:
```bash
git branch | grep publish/xxx
git branch -r | grep origin/publish/xxx
```

## P7 · Source file lost after `git worktree remove --force` (2026-07-23)

**Symptom**: `cp /tmp/old/docs/card.html /tmp/new/docs/` → `cannot stat: No such file or directory`. Source file is gone.

**Root cause**: `worktree remove --force` recursively deletes the entire directory tree. Any file generated inside that worktree is gone unless committed and pushed first.

**Prevention**:

- Never hold unreferenced artifacts inside a worktree that may be force-removed.
- Write HTML to a path outside any worktree before removing the worktree, OR keep worktree until after `commit + push + PR merge` confirmed.
- Forced recovery: re-write file content directly to the new worktree path (main thread takeover — write_file to `/tmp/new-worktree/docs/card.html`).
