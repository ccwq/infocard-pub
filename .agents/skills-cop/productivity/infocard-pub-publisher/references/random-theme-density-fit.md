# Random theme density fit note

Use this note when a user says `发布信息卡 主题随机` for a GitHub repo or other dense technical source.

## Rule

- Randomness is only the tie-breaker. Start from the source shape first.
- For dense repo cards with features, matrices, install steps, and benchmarks, prefer manual/workbench themes (`blue-technical-manual`, `hardblue`, `darkblue`, `redswiss`).
- Reserve light paper/sticker themes (`q-style`, `paper-warm-style`, scrapbook) for genuinely lightweight explainers or small concept cards.
- If the first random draw conflicts with content density, reroll once rather than forcing a mismatched style.

## Why

A theme that is visually too light for a high-density repo card makes the card feel underbuilt even when the content is correct. The theme should amplify the source structure, not fight it.
