# 截图型对比卡：证据与事实分层

适用场景：用户提供一张或多张信息图、比较表、榜单截图、宣传图，要求“整理成信息卡”或“补充丰满内容”。

## 核心规则

1. **截图内容先入证据层**
   - 把图里可见的标题、模型名、数值、标签、注释、颜色分组、结构分区完整记录下来。
   - 用户配图要作为正文证据嵌入 HTML，不要只当风格参考。

2. **公开资料单独入事实层**
   - 对截图里的命名、指标、版本号、参数量、速度、榜单结论，先去找官方或一手资料。
   - 找到可核实来源后再写成“已核实事实”；找不到则写成“图中展示 / 暂未核实官方对应”。

3. **不要把宣传口径写成定论**
   - 图里的“之王”“领先”“No.1”这类话术，只能保留为图中说法或营销文案。
   - 正文结论用可验证表述：适用场景、部署成本、任务边界、能力边界。

4. **有不确定命名时要显式标注**
   - 例如：截图里出现的新模型名、非官方常见命名、版本号不一致时，标记为“图中展示 / 未核实官方对应”。

5. **卡片内容结构建议**
   - 图中证据
   - 事实校对
   - 参数对比
   - 选型建议
   - 风险与边界
   - 证据图/原图嵌入

## 实操要点

- 先保留原图，再写正文。
- 正文里把“图中内容”和“公开事实”分成两个小节。
- 若用户要求“补充丰满内容”，优先补：安装/下载/上手路径、适用场景、部署建议、和与其它模型的边界区别。
- 结论优先写“怎么选”，不要只复述“谁更强”。

## 常见错误

- 直接把截图中的版本名当官方型号写死。
- 只写宣传话术，不写可核实来源。
- 用户给了配图却没有嵌入正文。
- 把“图中展示”与“事实结论”混写成一段。
