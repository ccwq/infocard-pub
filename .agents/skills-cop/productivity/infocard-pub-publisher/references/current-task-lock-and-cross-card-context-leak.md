# 当前任务锁定与跨卡上下文串线（2026-06-15）

## 适用场景
同一仓库（尤其是 `infocard-pub`）里，连续处理多张信息卡：
- 今天改 X 卡，昨天刚做过人物卡
- 用户说“继续”“换图”“这两张图”“就用刚才那两张”
- 会话里同时存在：当前发布卡、昨天旧卡、风格参考图、内容图

## 事故模式
典型失败链：
1. 当前任务本来已经有明确 URL（例如 `https://x.com/i/status/2065806647742570880`）
2. 用户提到“这两张图”或“继续”
3. agent 没有先锁定当前卡的 slug/path
4. 近期刚处理过的另一张卡（例如昨天的人物卡）因为 **recency bias** 被错误带入
5. 结果开始修改完全无关的 HTML / 文案 / 图片，用户会直接质问“这和现在任务有什么关系？”

这不是单纯的“误解图片用途”，而是更上游的 **任务隔离失败**。

## 强制执行规则

### 1. 先锁定当前任务
在继续改卡、换图、调文案前，先明确三元组：
- `source URL`
- `slug`
- `HTML path`

示例：
- source URL: `https://x.com/i/status/2065806647742570880`
- slug: `20260614-x-ai-agent-treasure`
- HTML: `docs/20260614-x-ai-agent-treasure.html`

只要这三元组锁定了，后续所有“继续 / 换图 / 调文案”都只能落在这一张卡上。

### 2. 用户的指代默认绑定到当前卡
当用户说：
- “继续”
- “就用这两张图”
- “注意配文也要对应调整”

默认解释为：**继续修改当前锁定卡**，而不是回想最近做过的其它卡。

### 3. 昨天/历史任务只能作为背景，不能自动继承
即使：
- 昨天刚做过另一张卡
- 同一仓库里有很多相似 HTML
- 路径里正好有用户刚提到的人物/主题

也不能因为“最近见过”就把那个任务重新激活。

### 4. 一旦被用户指出串线，立即硬复位
如果用户明确说：
- “这和现在任务有什么关系？”
- “我有提 X 吗？”
- “这是昨天的卡，和今天无关”

处理原则：
1. 直接承认串线
2. 立即丢弃旧任务假设
3. 重报当前卡的 URL/slug/path
4. 从当前卡继续，不再解释旧卡内容

## 推荐回复模板

### 纠偏时
- “明白，刚才串线了。当前只处理这张卡：`docs/20260614-x-ai-agent-treasure.html`，对应 `https://x.com/i/status/2065806647742570880`。下面只改它。”

### 执行前
- “我现在只改这张卡：`20260614-x-ai-agent-treasure`。换图 / 配文 / build / push 都只落在这个文件上。”

## 与图片判断规则的关系
- `wikipedia-investigation-with-reference-images.md` 解决的是：**图是内容图还是风格参考图**
- 本文解决的是：**当前到底该改哪一张卡**

顺序必须是：
1. 先锁定当前卡
2. 再判断图片用途

如果第 1 步错了，第 2 步再正确也会改到错误文件上。
