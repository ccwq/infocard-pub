# 工具分享类仓库卡：Karakeep 这类“自托管工具”卡的可复用模式

## 适用范围
- 自托管工具、效率工具、收藏/书签/收件箱类产品
- 用户会把它当“工具分享/替代方案/开源推荐”来读
- 需要发布到 infocard-pub 的 GitHub 仓库技术卡

## 本次有效的卡片结构
1. 首屏先给结论：它解决什么痛点、适合谁
2. 用“可收藏内容 / AI 能力 / 平台覆盖 / Agent 集成 / 对比 / 安装”分块
3. 把“自托管”与“AI/Agent 友好”作为核心卖点，不要只写仓库简介
4. 与 Pocket / Raindrop / Linkwarden / Memos 等同类工具作对比，方便读者做选择
5. 把官方 CLI、Skills、REST API、SSO 作为“可接入能力”单独列出

## 证据抓取顺序
- 先读 README：定位、功能清单、文档、演示、替代品
- 再看 GitHub API：stars、forks、最新 push、最新 release
- 如 README 中有扩展/插件/移动端/云服务信息，放到平台覆盖区

## 发布注意点
- Q 主题适合这类“工具分享”卡：用暖米纸背景 + 彩色 pill，让信息更像手写工具卡而不是冷冰冰的产品页
- 安装代码块应短、可读、只保留最小可执行片段
- 对比表格在 390px 需保持可读，必要时缩成卡片栈，但不要删除核心对比维度
- 生成后要做公开页 200 验证和 `_index.yaml` 命中验证

## 这类卡最容易丢的内容
- 只写“这是个什么仓库”，没写“为什么要用它”
- 只写功能，没写同类替代与边界
- 只写安装命令，没写平台覆盖和 AI/Agent 接入能力
- 只写 README 原文，没做读者决策辅助
