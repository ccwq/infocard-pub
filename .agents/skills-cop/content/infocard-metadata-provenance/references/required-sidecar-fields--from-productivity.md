# Required meta.yaml fields

Every `docs/*.html.meta.yaml` sidecar in `infocard-pub` must have **all six** required fields. Missing any one causes `npm run build` to abort with a "missing fields X" error.

## Required fields

```yaml
slug: "YYYYMMDD-slug-name"          # unique identifier, no spaces
path: "docs/YYYYMMDD-slug-name.html" # ← required, not optional
title: "Card Title"
desc: "One-line description ≤210 chars" # summary for list/search
date: "YYYY-MM-DDTHH:MM:SS+08:00"   # release time (Asia/Shanghai)
updated: "YYYY-MM-DDTHH:MM:SS+08:00"  # ← required! must equal date; stabilizes _sort_ts
tags: ["tag1", "tag2"]              # search/filter labels
category: "knowledge" | "open-source-tool" | "investigation" | "skill" | "product"
```

## Why `updated` is required (2026-06-07)

`_sort_ts` (used for list ordering) is derived by `resolveBusinessSortTsNs()` with priority:
1. `updated` field value
2. `date` field value
3. **file mtime** of meta.yaml

When `updated` is absent, the script falls back to file mtime. But `npm run build` runs `fix-meta-date.js` first, which touching all meta.yaml files (updates mtime). This causes `_sort_ts` to differ between the local commit (when mtime was stable) and CI environment (new mtime after checkout). CI verify then fails with "_index.yaml is out of date" even though content is correct.

**Fix**: always write `date` and `updated` with identical values. This pins `_sort_ts` to a stable value regardless of mtime changes.

## Common failure: missing `path`

If `path` is omitted, `build-site.js` aborts:
```
Error: Index build failed:
- docs/{slug}.html.meta.yaml: missing fields path
```
Fix: add `path: "docs/{slug}.html"` to the sidecar, then re-run `npm run build`.
