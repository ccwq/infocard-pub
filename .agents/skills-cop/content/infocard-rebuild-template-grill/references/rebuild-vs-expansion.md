# Rebuild vs expansion for infocards

## User meaning to preserve
- **Rebuild** means re-author the structure/CSS/layout from scratch. Do not just add more text to an existing layout.
- **Expansion** means keep the current card skeleton and make the content denser/richer. It is allowed only when the user explicitly wants more content.
- If the user says the previous card is rough and they **like expansion**, prefer richer modules, deeper explanation, and a fuller evidence layer — but keep the chapter skeleton stable and the page legible.

## Practical rule
- If the user says **rebuild**: change structure/style first, content only as needed to preserve completeness.
- If the user says **update / expand / add data**: preserve the existing structure, but deepen the content, add examples, add comparison layers, and avoid thin summaries.
- Do not blend the two silently.

## Red flags
- Treating rebuild as synonym for expansion.
- Adding more content while leaving the broken structure untouched.
- Compressing content too aggressively when the user asked for richness.

## Verification
- Rebuild: verify layout, mobile, and that old visual bugs are gone.
- Expansion: verify the card is denser, clearer, and still readable; do not regress legibility or turn the card into a wall of text.
