# 信息卡密度验收检查单

## 背景

2026-06-01 subagent 生成的信息卡（韦东奕造谣案）被用户指出"根本不符合信息卡和信息密度的要求"。页面打开后只有标题，内容为空或极度稀疏。

## 用户硬性密度标准（2026-06-01 定）

| 密度等级 | 页面高度要求 | 适用场景 |
|---|---|---|
| **中等密度** | **≥ 2 屏**（mobile 390px 视口下） | 一般信息卡、事件复盘、产品调研 |
| **高等密度 / 高密度** | **≥ 3.5 屏**（mobile 390px 视口下） | 复杂调查、深度报告、多维度对比 |

**填充规则**：除非没有可挖掘的信息，否则必须达到对应密度的最低屏数。原文 < 2 屏内容时，应补充：相关背景、类比事件、传播机制分析、官方表述、核查方法、边界说明 — 不能因为原文短就发布稀疏卡。

## 密度否决项（一票否决）

以下任一情况出现，即判定为**不合格**，不得发布：
- [ ] 页面打开后**首屏无实质内容**（只有标题/标签，无正文）
- [ ] 总可读文字量 **< 200 字**（手机端）
- [ ] 页面结构只有 `banner + 标题`，无 `stats / section / 数据块`
- [ ] 页面内容与已有卡高度重复，只是改了个标题
- [ ] 结构看起来像"目录"而不是"信息卡"

## 密度合格项（上线门槛）

以下全部满足才可发布：
- [ ] 780px 视口下，首屏有 **stats 数据条 + 至少 1 个 section 标题 + 3+ 行正文**
- [ ] 手机端（390px）可读，无横向溢出，无字号过小
- [ ] 内容覆盖：核心数据 + 时间线 + 关键事实 + 来源
- [ ] 无旧模板回退（无 `.wrap/.banner + 纯标题` 这样的稀疏旧结构）
- [ ] 页面实际 DOM 内容量 ≥ 300 字（不含 CSS/JS）

## 发布前必须检查

```bash
# 1. 检查页面大小（字节数）
wc -c docs/$SLUG/index.html   # 应 > 5KB，否则内容太少

# 2. 检查结构行数（不含空行和CSS）
grep -v '^\s*$' docs/$SLUG/index.html | grep -v '<style' | wc -l  # 应 > 30行

# 3. 用 CDP 验证实际渲染
browser_navigate(url="https://ccwq.github.io/infocard-pub/docs/$SLUG/")
browser_vision(question="首屏有什么内容？总文字量大约多少？信息密度够吗？")
# 如果回答是"只有一个标题"或"几乎为空"，立即打回重做

# 4. 截图验收
# 截图必须显示完整的、有实质内容的信息卡，不是只有标题的空壳
```

## 常见导致密度不足的原因

1. **内容提炼不足**：只复制了标题和来源，没有展开核心事实
2. **旧模板回退**：使用了只有 banner + 标题的旧模板
3. **主题不匹配**：高信息密度内容用了低密度的 landscape 主题
4. **subagent 输出被截断**：长任务 subagent 在 max_iterations 达到时未完成内容就退出

## 修复路径

密度不足时，不要只改标题或加一行来源：
1. 参考已有合格卡片的结构（如 `shandong-zhong-dna-fraud`）重建内容
2. 确保包含：stats 数据条、时间线、关键事实、法律分析（若相关）、来源链接
3. 重新用 browser_vision 验证密度
4. 截图确认后再发布
