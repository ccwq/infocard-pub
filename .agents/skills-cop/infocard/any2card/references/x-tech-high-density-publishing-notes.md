# X 技术/工具帖高密度信息卡：会话沉淀

## 适用场景
- 输入是 X 技术观点帖、AI 编程工具帖、仓库介绍帖，且用户明确要“高密度信息卡”。
- 帖子包含多张配图、多个技术点、工具链/工作流/能力矩阵，适合做“证据 + 结论 + 边界”的卡片。

## 抽取与取证
1. **先找真实帖子目标页**
   - `browser_navigate` 可能只落到登录壳/引导页；此时不要直接放弃。
   - 用 `browser_cdp Target.getTargets` 找到真正的 X page target，再对该 target 执行 `Runtime.evaluate`。
2. **优先抽 DOM，不先依赖视觉模型**
   - 抽 `article.innerText` / `document.body.innerText` 作为正文。
   - 抽 `article img` / `document.images` 作为配图 URL。
   - 如果正文里有硬数字、列表、时间、作者名，优先保留原始写法。
3. **媒体本地化**
   - 把 `pbs.twimg.com` 图片下载到 `docs/assets/images/<slug>/`。
   - HTML 中统一用相对路径引用，避免热链失效。

## 高密度版卡片结构
- 标题：用帖子的“真实主张”，不要只复述 URL 或用户名。
- 首屏：
  - 1 句结论
  - 4 个统计块/关键事实
  - 一段短的定位说明
- 中段：
  - 4 张左右的证据图（读取顺序明确、图注要说明图在证明什么）
  - 4-8 个硬点拆解（每点只保留一个判断）
- 末段：
  - 原帖链接
  - 仓库/官网/文档入口
  - 一句话边界：它适合什么、不适合什么

## 验收重点
- 390px 首屏：标题、统计块、结论都能读，不能只在 DOM 里存在。
- 证据图：图注必须解释“这张图在证明什么”，不能只写“图1/图2”。
- 发布前：检查 `_index.yaml` 命中、Pages 200、图片路径可访问。
- 若卡片主题是“工具/工作台”，标题和正文要保持“能力型”叙述，不要做成目录页。
