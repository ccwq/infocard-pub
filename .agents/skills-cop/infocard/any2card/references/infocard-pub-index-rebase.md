# infocard-pub 发布与索引合并备忘

## 适用场景
当 any2card 生成的信息卡需要发布到 `infocard-pub` 仓库时，尤其是需要同步更新 `_index.yaml` 的场景。

## 必守原则
1. **卡片三件套同 bundle 处理**：`index.html`、`index.html.meta.yaml`、`report.md`（或同类报告文件）必须一起提交，不要只发单页。
2. **发布后必须验线上**：本地写入成功不代表已上线；至少核对：
   - 线上卡片页可访问
   - 首页索引中能检索到标题/slug
   - 首页总量或排序符合预期
3. **_index.yaml 冲突只做“增量合并”**：
   - 以 `origin/main` 的最新索引为基底
   - 仅插入/更新目标卡片
   - 保留远端已有卡片与顺序规则
   - 不要用旧的本地索引整文件覆盖
4. **远端比本地新时先合并再推送**：如果 push 被拒绝或 rebase/cherry-pick 触发 `_index.yaml` 冲突，先重建在远端最新索引上的版本，再继续提交。

## 推荐发布顺序
1. 生成 HTML / meta / report
2. 本地检查卡片页能直接打开
3. 提交并 push
4. 线上打开卡片页验证
5. 线上检查首页索引是否出现该 slug
6. 如首页计数异常，优先检查 `_index.yaml` 是否真正合并成功，而不是先怀疑页面内容

## 常见坑
- 只改了本地文件，没有完成 push，就以为“已上线”
- `_index.yaml` 出现冲突时，把新卡写进去了却误删了远端已有卡片
- 线上卡片页已发布，但首页缓存/索引未同步时，误把问题归为内容失败

## 相关技能
- `any2card`：卡片生成、版式、移动端可读性
- `infocard-pub` 相关发布流程应优先遵循仓库当前索引规则
