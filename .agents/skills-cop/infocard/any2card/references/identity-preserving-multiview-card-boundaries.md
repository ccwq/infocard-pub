# 人物身份保持与多视角生成：信息卡事实边界

适用于“几张照片生成同一人物不同面部角度 / 复原”主题的信息卡。

## 先定术语，避免过度主张

- **身份保持生成 / 多视角外观合成**：用参考照片约束生成模型，产出看起来属于同一人的新角度肖像。
- **三维脸部重建**：估计可旋转的脸部几何、表情或纹理参数；不等同于精密扫描。
- 不把以上任何一项写成“真实复原”“法医级复原”“可用于身份认证”。未拍摄到的侧脸、耳部、发际线等都含模型先验补全。

## 研究来源优先级

1. 模型/API 官方文档：输入图数量、编辑接口、模型名称与参数。
2. 论文项目页或官方代码仓库：身份保持机制、支持的底座（例如 SDXL/FLUX）、部署边界。
3. 第三方评测仅可作为体验证据，不能替代模型能力的确定性表述。
4. “Nano Banana”是广泛流传的产品别名；引用能力与 API 时，优先链接 Google Gemini 官方文档，不把同名第三方站点当官方来源。

## 可复用的方案分层

| 目标 | 建议路线 | 必须写明的限制 |
|---|---|---|
| 少量高质量成片、快速迭代 | 商业图像模型的多图参考/编辑 | 身份一致性是概率性结果，跨批次应使用锚图 |
| 私有部署、批量、姿态可控 | InstantID/PuLID 等 ID 条件 + 扩散底座 + 姿态控制 | 需要显存、权重与参数版本管理 |
| 可旋转的几何 | DECA/3DMM 后渲染，必要时生成式补纹理 | 几何估计不是高精度扫描，头发/遮挡区仍需补全 |

## 推荐呈现的实现流程

1. 采集 6–15 张清晰、跨角度照片；优先保证正脸与左右 30–60° 覆盖。
2. 去除强滤镜、极端表情、明显运动模糊；保留原图，避免过度磨皮。
3. 先由多图生成一个中性、统一光照的**身份锚图**。
4. 以锚图为主参考，每次只改变一个目标角度；保留镜头、光照、背景和表情。
5. 每个角度生成多候选，用人脸 embedding 仅作排序，再由人工核查眼距、鼻形、下颌、发际线等跨图连续性。
6. 输出和元数据标注为 AI 合成视角图；限制在明确授权的人像用途内。

## 卡片验收点

- 明确区分“外观一致性”与“几何精确性”。
- 每个模型路线同时给出适用目标、实现方式、限制。
- 提供可操作的锚图工作流，而不是只列模型名。
- 把授权、隐私、冒充与身份认证禁用边界做成独立可见区块。
