# 2026-07-25 crayon 主题对抗评审会话笔记

## 背景

用户要求基于小红书参考图创建 `infocard-crayon-style` 主题，并进行 2 智能体对抗评审，最多 4 轮。

## 原图真实视觉特征（校正）

原图小红书帖实际视觉特征：
- 暖米黄色背景（不是深色背景）
- 5 张独立彩色纯色块卡片（蓝/绿/紫/橙/黄各自深色版）
- 白色/浅色文字（因为底色是深色）
- 大号 emoji 图标在每张卡片内
- 圆角 + 柔和阴影
- "TOP 5"装饰副标题 + 编号装饰线 + 底部版权信息
- 无硬边框，拼贴式布局

**教训**：第一轮误判原图为"深色背景"，实际上原图背景是暖米黄。根源是参考图在小红书 UI 暗色主题下显示差异。

## 对抗评审流程记录

### R1（命名轮）
- Agent A（批评者）正确识别了背景色偏差问题
- 原图实际是米黄背景 + 黑字，而非暖白背景 + 白字
- 这是系统性的方向错误

### R1 修复（4项）
1. ✅ 背景色 `#f7f4ef` → `#f0ead8`（米黄纸底）
2. ✅ 黄色背景文字白字 → 深色 `#1c1c1c`（WCAG 对比度）
3. ✅ emoji 加 `aria-hidden="true"`（读屏噪音）
4. ✅ 代码块加 `overflow-wrap:anywhere; word-break:break-word`（长 token 溢出）

### R2（截图验证轮）
- 修复后截图背景已正确（米黄色）
- 仍存在差异：缺少"TOP 5"装饰、编号装饰线、版权
- 这些差异裁定为"可保留"（通用主题框架不应强加内容专属装饰）

## 关键教训

### 教训 1：参考图平台背景色可能欺骗视觉判断
- 小红书/抖音等平台 UI 暗色主题会叠加在内容上
- 不要仅凭截图判断背景色——需要用 `curl` 获取原始 HTML 确认 `:root` CSS 变量

### 教训 2：`_themes.yaml` 是单一事实源
- 主题注册信息在 `_themes.yaml` 中
- `themes.html` 由 `scripts/rebuild_themes.py` 自动生成
- 正确流程：更新 `_themes.yaml` → 运行 rebuild → 两文件一起提交
- 不要手动编辑 `themes.html`（会被下次 rebuild 覆盖）

### 教训 3：对抗评审结论裁定权在主线程
- 智能体只提供差异列表和修复建议
- 最终裁定（修复/保留）由主线程裁判决定
- 修复项上限 2-3 个（优先级排序），避免无限迭代

### 教训 4：主 checkout 边界
- 信息卡和主题工作只在当前主 checkout 进行，不创建或进入 worktree。
- 当前脏文件必须记录并排除在本次变更范围外；不得 reset、stash、clean 或顺带提交。
