# graph-paper card rebuild parity note

## When to use
Use this note when an existing infocard must be **rebuilt** to match `theme/graph-paper.html` more closely while keeping the original content intact.

## Rebuild rule
- Treat `theme/graph-paper.html` as the structural target, not just a color target.
- Rebuild means **section mapping + layout reconstruction**, not palette swapping or minor decoration tweaks.
- Preserve content by remapping it into the theme skeleton:
  - hero / title / lead
  - right-side graph shell as the main visual
  - 3-column explanatory blocks
  - notes / conclusion band
  - footer / provenance
- If the existing card has too much report-card density, reduce repetition and move information into the graph-first structure instead of deleting facts.

## Comparison workflow
1. Open the theme preview and the card preview side by side.
2. Compare these items first:
   - hero split ratio
   - graph shell dominance
   - section cadence and density
   - paper/grid texture
   - annotation / engineering-detail feel
3. Rebuild the card until the **structure language** matches the theme, even if the content set stays unchanged.

## Verification
- Use a browser screenshot of the rebuilt card and compare it against the theme preview.
- Visual parity is about layout hierarchy first, then texture and annotation detail.
- If a rebuilt card still reads like a report page, continue reducing text density and strengthening the graph-first hero.
