# Orchestration platform case note (Trinity / Plannotator / similar)

Use Color Material when the repository is a **platform runtime / orchestration control plane** rather than a single-purpose tool.

## What the card must surface
- A central control plane or gateway is the visual core.
- Left side should describe access / ingress / client workflow.
- Right side should carry evidence, screenshots, docs, or capability/protocol mapping.
- Bottom section should show lifecycle / phases / deployment loop.
- If the repo ships screenshots or a demo GIF, use them as the primary visual anchor.

## Good content buckets
- Problem → solution
- Control surfaces / API surfaces / CLI surfaces
- Scheduling, delegation, observability, audit trail, cost or policy governance
- Quick start / installation / deploy workflow
- Screenshots with labels: fleet graph, timeline, detail panel, dashboard

## Pitfalls
- Do not collapse this into a generic “feature list” card.
- Do not use a flat 2-column module list as the whole layout.
- Do not omit evidence imagery when the repo provides it.
- Do not let the deep panel become too light or text-gray; the center must feel like a control console.

## Useful examples from this session
- Trinity: sovereign agent runtime, isolated containers, fleet scheduling, delegation, audit trail, CLI/MCP, plus hero + graph + timeline screenshots.
- Plannotator: review/control-plane framing, with annotate / review / share workflows and image evidence.
