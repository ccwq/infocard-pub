# Q 版信息卡布局坑点（Pretty Mermaid 复盘）

## 适用场景
当用户明确要求“信息卡”“Q 版”“卡片风”“信息图”，尤其要求从某个 Skill / README / 仓库文档的使用角度重写时，优先参考此文件。

## 这次踩到的坑
1. **不要把 YAML frontmatter 直接放进 HTML 正文**
   - `---`、`name:`、`description:`、`tags:` 如果直接写在页面前部，会被浏览器当成正文，污染首屏。
   - 若只是给维护者看，可放入 HTML 注释；若需要发布元数据，应走仓库 meta 文件，不要和页面正文混写。

2. **信息卡不是 README 长页**
   - 先把内容压成“主卡 + 少量子卡 + 少量证据”，再决定是否补充细节。
   - 代码块、表格、长说明会把页面拉回“技术文档”气质。

3. **Q 版卡片要先统一视觉语言，再填内容**
   - 统一纸感背景、厚黑边框、圆角、模块边界、色板。
   - 再做主题网格、标签、命令块、记忆块。

4. **宽度/密度要卡片化，不要海报式横展开**
   - 主体应像单张卡，不要像产品落地页。
   - 模块越多，越应该收束成短句、标签、短代码片段，而不是整页分节。

5. **主题/示例要贴近用户命令本身**
   - 如果用户说“从 Skill 使用角度”，必须是安装 / 使用 / 记忆 / 典型命令 / 触发条件。
   - 若用户要求“找官网或第三方教程配图”，优先把常见图类型整理成可直接复制的示例块，不要只做概述。

## 快速检查清单
- [ ] 页面首屏看起来像卡片，而不是 README
- [ ] 没有 visible frontmatter
- [ ] 主卡信息高度凝练，子卡不超过必要数量
- [ ] 代码块数量和长度被控制在最少可读范围
- [ ] 主题区采用卡片/徽章/色块，而不是纯表格
- [ ] 装修风格与主题保持一致：纸感、手作感、圆角、厚描边
