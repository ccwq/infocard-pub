# handline 技术博客分享 / Recent Articles 导读模式

## 适用场景

当输入是一个博客首页、Recent Articles、Archive、Recent posts、文章列表页时，handline 不应只复刻“标题列表”。更好的做法是把它改造成一张“阅读地图”或“分享导读”。

## 目标

输出一张适合分享给别人的 handline 卡，让读者一眼看懂：
- 作者最近在持续讲什么
- 哪几篇是同一条系列线
- 哪些是观点类文章
- 如果只读 1-3 篇，应该怎么读

## 抽取信息的优先级

1. **系列主线**
   - 最近 2-4 篇是否构成连续教程或同一主题演进
   - 优先找“Build X From Scratch / Part 1 / Part 2”这类连续结构

2. **观点类文章**
   - 争议、趋势、判断、年终回顾、模型分析
   - 适合转成“趋势 + 解释 + 结论”

3. **技术写作 / 方法论类文章**
   - 关于 index.html、文章结构、信息组织、前端入口页、写作技巧
   - 适合转成“可复用经验”

4. **文章条目信息**
   - 日期
   - 标题
   - 阅读时长
   - 链接/路径
   - 一句摘要

## 推荐版式

### 首屏
- 标题：站点名 / Recent Articles
- 副标题：说明这不是纯列表，而是阅读入口
- 右侧黑盒：`recent list ≠ random links` / `series-first` / `share angle`
- 中央 quote band：一句总结这组文章的价值

### 中部流程
用 3-4 步说明如何把“最近文章”转成分享内容：
1. 看入口（找连续系列）
2. 抽主线（识别主题）
3. 选分享角度（教程 / 观点 / 写作）
4. 回原文（链接原文提炼方法）

### 底部内容区
建议拆成三块：
- 左：近期文章主线 / 条目列表
- 中：主题雷达 / 分类雷达
- 右：适合怎么分享 / 推荐阅读顺序

## 文案规则

- 不要写成“站点最近更新了什么”
- 要写成“这组文章说明了什么”
- 把“分享价值”放在标题和导语里，而不是藏在正文最后
- 若是系列型博客，优先强调“从哪篇开始读”

## 常见坑

- 只列标题，不解释主线
- 忽略阅读时长和日期，导致条目失去节奏感
- 没有推荐阅读顺序，分享价值下降
- 底部堆太多卡片，像目录页，不像 handline 阅读地图
- 为了整齐，把每篇文章做成同样权重，结果失去主题层级

## 成功信号

- 用户一眼能看出“最近在讲 agent / 写作 / 前端 / 观点中的哪一类”
- 列表页被改造成可转发的导读
- 页面结构仍然是 handline：纸感、手绘边框、清晰正文、阅读顺序稳定
