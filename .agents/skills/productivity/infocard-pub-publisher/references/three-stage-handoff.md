# 三阶段信息卡交付手册（调研 / 写卡 / 发布）

适用场景：用户要求“先调研，再写卡，最后主线程发布”，并且要求信息卡存疑项要保留标注。

## 1. 产物契约

### agent1（调研）
- 只做核验，不写 HTML / meta / wiki。
- 产出一个过程文件，必须返回**绝对路径**。
- 过程文件必须显式区分：已核实 / 未核实 / 存疑。

### agent2（写卡）
- 只能基于 agent1 过程文件写卡。
- 不调研新事实，不臆测补全。
- 写完后返回**实际写入路径**，并说明哪些地方保留了存疑标注。

### 主线程（发布）
- 先核对文件真实存在，再 build。
- verify 失败直接中止，不跳过。
- Pages / HTTP 失败按 10s / 30s / 60s 重试 3 次。

## 2. 常见失误

### 主题漂移
agent2 可能把近邻主题写错，例如把“Obsidian 插件”写成“Claude Code CLI”。

**预防**：
- prompt 中明确写“这是 X，不是 Y”。
- 让 agent2 在输出开头重述主体。
- 主线程检查 `title` / `slug` / `source_url` 是否一致。

### 路径契约失败
文件名看起来对，但实际写到了错误目录。

**预防**：
- 主线程只信绝对路径。
- 用 `read_file` / `ls` / `git status` 验证。
- 不要仅凭“任务完成摘要”判断成功。

## 3. 发布前检查
- slug 与主体一致
- meta 的 `date/updated` 使用当前 Asia/Shanghai 时间戳
- `desc` 单行纯文本
- wiki 草稿只写 draft，不碰 index
