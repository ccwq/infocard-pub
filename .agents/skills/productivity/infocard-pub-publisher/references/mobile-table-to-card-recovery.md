# 移动端密集表格转卡片栈

适用场景：技术卡中出现数据矩阵、存储映射、配置映射、能力对照、4 列及以上的桌面型表格，在 390px 视口下发生压缩、碎行、难读。

## 处理原则
- 不要只缩字号或压间距来“硬保留表格”。
- 如果表格的语义是“若干条目 + 3~4 个属性”，优先改成纵向卡片栈或定义列表。
- 桌面可保留 2 列，移动端必须回落到 1 列。
- 卡片内信息按“名称 → 归属/存储/说明”这类顺序重排，减少横向扫视成本。
- 对“参数 / 作用 / 默认/要点”这类技术配置表，优先用属性表（label-value stack / definition list）而不是继续保留 3 列 table；term 单独成行，作用/默认值拆成两条属性行。

## 验收
- 必须用 390px 视口复核目标 section，而不是只看整页是否“看起来还行”。
- 重点检查：是否仍存在四列挤压、是否需要反复横向扫视、是否有内容被压成碎行。
- 若用户明确指出某个 selector（例如 `section:nth-child(n)`），要针对该 section 单独截图验收。
- 用户若给出手机截图明确说“表格内容在水平方向上被挤压在一起”，这是局部结构失败，不是单纯字号问题；要把该表格改成属性卡而不是继续缩表格。

## 典型 CSS 思路
- 桌面：`grid-template-columns: repeat(2, minmax(0, 1fr))`
- 移动端：`grid-template-columns: 1fr`
- 列内文字用 `grid-template-columns` 做小型键值对，不再用整张表格。
- 长文本项优先放到独占整行的 `说明` 区，不要和其他三列抢空间。
