# infocard-pub 首页重构记录：真实修改时间排序与日期展示

## 背景
本次会话里，首页重构的关键要求是：
- 排序必须严格按**源文件真实修改时间**（HTML 或 `.meta.yaml` 任一改动都算）
- 首页高密度排版，但**不能丢元素**
- 日期要显示为**两行**：`新增` / `更新`
- 日期值要保留**完整格式**，不要缩成 `05/30`

## 可复用实现
### 1) 排序源
不要用 `git log` 的提交时间做首页顺序。更稳的做法是：
- 读取 `docs/*.html` 与对应 `docs/*.meta.yaml` 的 `st_mtime_ns`
- 取二者最大值作为该卡片的 `_sort_ts`
- 在 `_index.yaml` 里写入 `_sort_ts` 与 `_modified_date`

### 2) 构建范围
构建索引时只扫描 `docs/` 下的正规 `*.meta.yaml`。
这样可避免被仓库根目录下的临时 `.meta.yaml`、实验目录、草稿目录污染。

### 3) 前端渲染
- 首页不要再对 `_index.yaml` 做二次重排，直接按索引顺序渲染。
- 若必须二次兜底，只允许按 `_sort_ts`，再用 `title/slug` 稳定兜底。
- 日期 helper 不要截断年月日；高密度应该通过字号、行高、间距来实现，而不是删信息。

## 常见坑
- `date` 参与排序会破坏“严格按修改时间”的要求。
- 把日期值压成 `MM/DD` 会造成信息损失，和“日期包含修改时间”的要求冲突。
- 只改前端不改 `_index.yaml`，首页顺序会在缓存/重建后回弹。
- `_index.yaml` rebase 冲突时，不要手工合并冲突标记；直接按 `docs/` sidecar 重建索引。

## 验证
- `_index.yaml` 第一条应该对应最新变更的卡片。
- 首页第一条卡片左侧应显示两行日期：新增 / 更新。
- 线上页面需要清掉旧缓存后再看最终效果，否则会误判成“改了没生效”。
