# GitHub Repository Investigation Examples (Paired Bundles)

This reference captures real-world examples of paired investigation bundles (Report + Info Card) published to `infocard-pub`.

## Example 1: Claude Code Setup Plugin
**Topic**: Official Anthropic plugin for automated codebase analysis.
**Key Focus**: Distinguishing "recommended automation" from "automated execution".
**Structure**:
- `report.md`: Included official README definitions, X post claims, and community demand for alternatives (e.g., Codex).
- `index.html`: Focused on "Decision Support" rather than "List of Features".
- **Slug**: `20260531-claude-code-setup-plugin`

## Example 2: Kappa Graph — κ(G)
**Topic**: Epistemic knowledge graph system with grounding scores.
**Key Focus**: Grounding scores, contradiction preservation, and Rust-accelerated graph traversal.
**Structure**:
- `report.md`: Detailed architecture (FastAPI/PostgreSQL/AGE), technical differentiators (Grounding Scores vs GraphRAG), and use cases (Audit/Research).
- `index.html`: High-density stat grid for grounding levels and stack item flow for usage order.
- **Slug**: `20260531-kappa-graph-investigation`

## Quality Standard (The "Usability" Rule)
As per user feedback, these bundles must **not be generic**. They must provide:
1. **Core Problem Solved**: What pain point does it address?
2. **Ideal User**: Who is it for? Who should avoid it?
3. **First Step**: What is the first command or action the user should take?
4. **Reliability/Boundaries**: What are the limits of the tool/claim?
