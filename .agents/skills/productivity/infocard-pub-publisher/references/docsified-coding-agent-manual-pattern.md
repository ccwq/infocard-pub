# Docsified coding-agent manual pattern (session note)

Use when the source looks like a docs website / e-book for a coding agent or agentic engineering topic, especially when it contains phase tables, source-code comparisons, terminal screenshots, and multi-chapter walkthroughs.

## Strong signals
- Sidebar directory or chapter index on the left
- Explicit phase split such as Phase 1 / Phase 2
- Compare table mapping tutorial chapter → source file / source concept
- Prominent code volume claims (e.g. "~4300 lines")
- Terminal screenshot or CLI trace embedded in the README/page
- The source page itself is educational and structured, not marketing-led

## Publishing guidance
1. Use a handbooks/manual theme, usually blue-technical-manual.
2. Lead with the core learning value: "先能跑起来，再逐步加能力".
3. Promote chapter structure, architecture layers, and comparison tables over narrative fluff.
4. Use the docs/README screenshot as the hero evidence when it reveals the page structure better than a logo.
5. Keep the first fold in Chinese for Chinese readers; leave only source terms / repo names in English.
6. On mobile, preserve readability by reflowing tables into stacked cards if the page gets cramped.

## Verification reminder
- Desktop screenshot should still show the docs/manual feel.
- 390px full-page screenshot should have no horizontal overflow.
- Save/export buttons must sit in normal flow at the bottom, not float over正文.
