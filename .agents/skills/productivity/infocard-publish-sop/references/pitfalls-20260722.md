## P1: 子智能体 commit 在 detached HEAD，主线程 git log 看不到（2026-07-22）

**What broke**: 子智能体完成 commit 后，主线程在 worktree 内执行 `git log --oneline` 只显示主仓库的 3 个历史提交，没有看到子智能体的新 commit。误以为子智能体没有完成 commit，开始重建。

**Root cause**: 子智能体 commit 到 detached HEAD 时，该 commit 不在任何命名分支上。`git log --oneline` 默认只显示当前 HEAD 链上的历史，不显示其他 ref 上的 commit。用 `git branch -a` 或 `git log --all --oneline` 才能看到所有 ref 上的 commit。

**Recovery 动作**:
```bash
# 在 worktree 内执行
git branch -a | head -20          # 列出所有分支，包括 detached HEAD
git log --all --oneline | grep <slug>  # 全局搜索关键词
git show <sha>:docs/<slug>.html | head -3  # 验证内容存在

# 找到后创建命名分支
git checkout -b publish/<slug>-YYYYMMDD
# 然后继续 build→push→PR→merge
```

**Prevention**: 下发子智能体时在 context 中明确说明 "commit 到命名分支，不要留在 detached HEAD"。恢复时总是先执行 `git log --all --oneline | head -20` 再判断是否有产物。

## P2: GitHub API squash merge 返回 422 Unprocessable Entity（2026-07-22）

**What broke**: PUT `/repos/{owner}/{repo}/pulls/{number}/merge` 时传入 `commit_title` 和 `commit_message` 字段，GitHub 返回 422。

**正确序列**:
```python
# 只传 merge_method，不传其他字段
data2 = json.dumps({"merge_method": "squash"}).encode()
req2 = urllib.request.Request(url, data=data2, method='PUT',
    headers={"Authorization": f"token {token}", "Accept": "application/vnd.github.v3+json"})
with urllib.request.urlopen(req2) as r2:
    result = json.load(r2)
    print("MERGED:", result['merged'])
```

## P2: worktree 有未跟踪 node_modules 导致 git worktree remove 失败（2026-07-22）

**What broke**: 子智能体 symlink 了 `node_modules` 到 worktree，产生 `?? node_modules/` 未跟踪文件。`git worktree remove` 拒绝删除，提示 "contains modified or untracked files"。

**Root cause**: `git worktree remove --force` 只对"modified"文件生效，不对未跟踪文件生效。

**正确清理序列**:
```bash
# 先删除 symlink
rm /path/to/worktree/node_modules

# 再删除 worktree
git worktree remove /path/to/worktree

# 如果仍有其他未跟踪文件
git clean -fd /path/to/worktree   # 确认文件可丢弃后再执行
git worktree remove /path/to/worktree --force
```

## P2: rebase 冲突用 --theirs 后 amend 错误地包含历史文件（2026-07-22）

**What broke**: rebase 冲突后用 `git checkout --theirs` 取 worktree 版本的 _index.yaml 和 index.html，然后执行 `git commit --amend`，但 amend 包含了 worktree 中不在子智能体提交范围内的其他文件（如其他卡片的相关文件）。

**Root cause**: `git commit --amend` 会重写当前 commit 并将其父commit 改为当前 rebase branch 的最新 commit。在这个场景中，它把子智能体的 commit 和 origin/main 的 commit 混合了。

**正确序列**:
```bash
# rebase 冲突后
git checkout --theirs _index.yaml index.html
git add _index.yaml index.html
GIT_EDITOR="cat" git rebase --continue   # 用 rebase --continue 自动完成，不要手动 amend
```

**Prevention**: rebase 冲突解决后用 `rebase --continue`，不用手动 amend。
