# 内容门禁与事实保真

## 问题

`verify-card-content` 会用 `facts.json` 的 `required_sections` 和 `claims` 做页面文字匹配。若把事实包从带来源、归因和限定条件的完整陈述缩成页面中的短语，虽然门禁会通过，却损失了 Agent1 交付物作为可追溯证据的价值。

## 规则

1. `facts.json` 保留完整、可归因的事实：谁说的、是原文判断还是转述、必要的限定条件。
2. 内容门禁需要的短关键词/章节标题应来自独立的派生字段或 verifier 的关键词提取逻辑，不得反向降级事实包。
3. 非 GitHub 文章卡必须把作者、发布日期、来源 URL 与“作者判断 / 文中转述 / 编辑归纳”分层写清。
4. 门禁失败先检查匹配策略（HTML 解析、hero 提取、标题语义），不要先通过改短事实来消除错误。

## 验收

- Agent1 事实包完整且可读。
- 内容卡有明确来源/归因说明。
- 内容门禁以完整事实或显式派生关键词通过，而非靠牺牲证据精度。
