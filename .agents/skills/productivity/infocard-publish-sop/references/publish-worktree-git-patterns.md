# Publish Worktree Git Push Patterns

## Detached HEAD — Use Commit SHA, Not HEAD

Worktrees are created with `--detach` (from `git fetch origin main && git worktree add ... origin/main --detach`). This leaves Git in detached HEAD state.

`git push origin HEAD` fails with:
```
error: The destination you provided is not a full refname (i.e., starting with "refs/").
```

**Fix**: use the commit SHA directly:
```bash
git push origin <sha>:main
```

To get the SHA: `git rev-parse HEAD` or from the commit output.

## Stash Build Artifacts Before Rebase

When running 3+ parallel worktrees, each push advances `main`. Subsequent worktrees are behind by at least one commit and must rebase before pushing.

`_index.yaml` and `index.html` are regenerated by `npm run build` during rebase and will conflict.

**Stash → rebase → resolve with --theirs**:
```bash
# Save locally-modified build artifacts (if any)
git stash push -m "build artifacts" -- _index.yaml index.html

# Fetch latest main and rebase
git fetch origin main && git rebase origin/main

# If conflict on build artifacts:
git checkout --theirs _index.yaml index.html
git add _index.yaml index.html && git commit --amend --no-edit

# Push
git push origin HEAD:main
```

## Why Build Artifacts Must Not Be Committed

The card HTML and meta.yaml are the source of truth. `_index.yaml` and `index.html` are auto-generated from them by `npm run build`. Committing the generated files:

1. Creates spurious content conflicts during rebase
2. Duplicates information that lives in the source files
3. Makes the diff noisy and harder to audit

**Rule**: commit only `docs/<slug>.html` and `docs/<slug>.html.meta.yaml`.

## Pitfall: Wrong Worktree Remote After Creation

Worktrees created with `--detach` inherit git remotes from the parent repo's `.git`. If the parent repo's `origin` remote was changed or the worktree was created in the wrong context, the worktree silently picks up a **wrong remote URL**. All commits land in the wrong repository.

**Symptom**: After `git worktree add`, `git remote -v` shows `origin` pointing to `/tmp/some-other-bare.git` or a completely different path, not the infocard-pub repo.

**Detection** (run immediately after worktree creation):
```bash
git remote -v && git log --oneline -2
# Verify origin points to: /home/ccwq/qbox/opendir/project/infocard-pub/.git
# Verify HEAD commit matches current origin/main
```

**Fix**: Immediately reset the worktree's remote:
```bash
git remote set-url origin /home/ccwq/qbox/opendir/project/infocard-pub/.git
```

**Prevention**: Always run remote + HEAD check after `git worktree add`. If wrong, fix before writing any files.

## Pitfall: Two Repo Paths for infocard-pub

infocard-pub exists at **two paths**:
- `/home/ccwq/qbox/opendir/project/infocard-pub` — canonical (has `package.json`, `node_modules`, all npm scripts)
- `/home/ccwq/hermes-data/home/qbox/opendir/project/infocard-pub` — secondary (may lack `package.json`)

**Symptom**: `npm run build` fails with "ENOENT: no such file or directory, open 'package.json'" when running from the wrong path.

**Fix**: Use the path with `package.json`:
```bash
cd /home/ccwq/qbox/opendir/project/infocard-pub
```

## Pitfall: meta.yaml Timestamp Gate (verify-meta-timestamps.js)

`verify-meta-timestamps.js` enforces wall-clock `YYYY-MM-DD HH:MM:SS` format — **no ISO/T/Z/timezone suffixes**.

**Rejecting format**: `"2026-07-19T16:00:00+08:00"` (has `T` and `+08:00`).

**Required format**: `"2026-07-19 16:48:00"` (wall-clock, Asia/Shanghai implied).

**Fix before build**:
```bash
sed -i 's/date:.*/date: "2026-07-19 16:48:00"/; s/updated:.*/updated: "2026-07-19 16:48:00"/' docs/<slug>.html.meta.yaml
```

AgentKey and Web-Check both hit: rebase regenerated their `_index.yaml`/`index.html`, causing merge conflicts. Resolved by `git checkout --theirs` on those files, then `git commit --amend --no-edit`.
