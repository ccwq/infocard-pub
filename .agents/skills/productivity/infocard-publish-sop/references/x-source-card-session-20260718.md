# X 来源信息卡：会话经验（2026-07-18）

## 适用场景

用户提供 `x.com/i/status/<id>` 并要求创作、发布信息卡，尤其要求成品显式体现 X 内容和作者。

## 稳定流程

1. 先用现有 Chrome/CDP 或 `agent-browser --session <run-id>` 读取原帖；不要把稀疏壳页面、搜索摘要或跳转 URL 当成完整正文。
2. 优先保存结构化事实包：状态 ID、作者 display name、`@handle`、认证状态、发布时间、正文、是否回复/引用/转推、媒体、互动快照、所有展开链接。
3. 用 `api.fxtwitter.com/status/<id>` 与 X DOM 交叉核验；两个来源冲突时保留冲突，不猜测。
4. 将原帖事实与外部来源事实分层：`X 帖子称`、`官方文档确认`、`外部来源未确认`、`路线图/规划`。版本号、发布日期、能力上线状态不得跨层升级。
5. 完整链接必须逐条展示：链接名称、原始 URL、用途说明；不要把截断的链接文本直接当成 URL。
6. 若有公开媒体，先下载至声明的资产目录并检查 MIME、文件签名、尺寸和非零字节；失败时显式记录 `assets: []` 与 reason。
7. 卡片至少包含独立的“X 原帖与作者”区，展示 `GitHubDaily`、`@GitHub_Daily`、status ID、原帖 URL 和抓取时互动数据。内容要详细时，再展开背景、能力拆解、工作流、应用场景、限制与事实边界。

## 关键边界

- `X 帖子称 V3` 不等于外部来源已确认 V3 正式发布。
- “下一步将集成自主迭代”是路线图，不得写成当前已上线能力。
- 原帖提供的模型权重/文档/社区链接可作为来源展示；逐一 HTTP 可访问不等于模型版本、许可证或能力已经独立验证。
- 作者身份必须来自 X DOM/API 的一致结果；不能从账号路径、搜索结果或旧卡推断 display name。

## 验收清单

- HTML/Markdown/meta/manifest 的路径与 bundle 一致。
- HTML 可搜索到：X URL、status ID、作者名、handle、主题实体名、所有必需章节和事实边界。
- 本地链接/图片通过确定性检查；不要把 HTTP 200 单独称为内容事实验证。
- 视觉验收使用独立 `agent-browser` session；关闭该 session 自己创建的 tab，不碰用户其他 tab。
- 发布后详情页、公开索引、首页身份信息三项都命中；CDN 延迟按有限退避处理。
