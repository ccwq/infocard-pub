# Required meta.yaml fields

Every `docs/*.html.meta.yaml` sidecar in `infocard-pub` must have **all required fields**. Missing `category` or `tags` causes `npm run build` to **hard-abort with "missing fields category, tags"** — not a warning, a build blocker.

## Required fields

```yaml
slug: "YYYYMMDD-slug-name"          # unique identifier, no spaces
path: "docs/YYYYMMDD-slug-name.html" # ← required, not optional
title: "Card Title"
desc: "One-line description, must START with Chinese characters" # summary for list/search; NO English-first
date: "YYYY-MM-DDTHH:MM:SS+08:00"   # release time (Asia/Shanghai)
updated: "YYYY-MM-DDTHH:MM:SS+08:00"  # ← required! must equal date; stabilizes _sort_ts
tags: ["tag1", "tag2"]              # search/filter labels ← REQUIRED; build hard-blocks if missing
category: "knowledge" | "open-source-tool" | "investigation" | "skill" | "product" | "toolkit"  # ← REQUIRED
style: "darkblue" | "redswiss" | "hardblue" | ...  # must match actual theme used in HTML
```

## taxonomy (required sub-structure)

When user explicitly specifies taxonomy fields in constraints, all named fields are **mandatory**:

```yaml
taxonomy:
  tech_stack:     # ← required when user constraint specifies it
    - Python
    - Claude Code
  topics:         # ← required when user constraint specifies it
    - academic research
    - llm pipeline
  primary_content_type: open-source toolkit  # ← required when user constraint specifies it
```

> **Lesson (2026-07-13):** User specified `taxonomy v2.0: tech_stack / topics / primary_content_type 必填` for an Academic Research Skills card. Initial meta.yaml omitted all taxonomy fields, causing build to succeed but leaving the card semantically incomplete. Always honor explicit taxonomy constraints in user requests.

## Why `updated` is required (2026-06-07)

`_sort_ts` (used for list ordering) is derived by `resolveBusinessSortTsNs()` with priority:
1. `updated` field value
2. `date` field value
3. **file mtime** of meta.yaml

When `updated` is absent, the script falls back to file mtime. But `npm run build` runs `fix-meta-date.js` first, which touching all meta.yaml files (updates mtime). This causes `_sort_ts` to differ between the local commit (when mtime was stable) and CI environment (new mtime after checkout). CI verify then fails with "_index.yaml is out of date" even though content is correct.

**Fix**: always write `date` and `updated` with identical values. This pins `_sort_ts` to a stable value regardless of mtime changes.

## Common failures

### Missing `category` or `tags` (hard-abort)

```
Error: Index build failed:
- docs/20260713-academic-research-skills.meta.yaml: missing fields category, tags
```

Fix: add both fields to meta.yaml, then re-run `npm run build`.

### Missing `path`

```
Error: Index build failed:
- docs/{slug}.html.meta.yaml: missing fields path
```

Fix: add `path: "docs/{slug}.html"` to the sidecar, then re-run `npm run build`.

### New files not in HEAD (warning, non-blocking)

```
fatal: path 'docs/20260713-slug.html.meta.yaml' exists on disk, but not in 'HEAD'
```

This is a git warning, not a build error. The build succeeds. It means the file was created but not yet committed. Normal for fresh publish sessions.
