# 信息卡内容类型标准

## 核心原则

**内容类型决定结构，不是主题决定结构。**

同一主题可以有两种以上的内容形式，选哪种取决于读者最需要什么。不存在"万能模板"。禁止把所有主题压缩成“Hero + 统计卡片 + 链接”的通用模板。

写卡前必须在 authoring spec 中显式声明：
- `content_type`
- `content_subtype`
- `required_modules`
- `primary_source`
- `evidence_gaps`

每个必须模块都必须有具体事实、示例、命令、参数、关系或边界说明；只有模块标题而没有实质信息，视为未完成。

每张卡写之前必须：
1. 确定内容类型
2. 在本 Skill 中找到对应分类和必须模块
3. 确认该类型对应的必须模块
4. 不得省略任何必须模块
5. 可选模块按主题相关性添加

如果主题无法归入本 Skill 已定义的分类，**停止写卡并与用户讨论分类架构**；不得自行发明临时分类、把主题硬塞进最相近分类，或直接套用通用模板。新增分类必须先经过用户确认，再写入本 Skill 后实施。

## 类型一：工具类

定义：可安装、可运行的软件工具（CLI / 桌面 / 浏览器插件 / Web 工具）。

### 子类型：CLI / 脚本

**必须模块：**
- 安装命令（覆盖主流系统）
- 初次使用示例（最常用的一条命令）
- 核心参数说明（至少 3 个，含默认值和效果）
- 适用环境 / 依赖
- 许可协议

**更新卡额外要求：**
- 本次更新内容列表（change log 级别）

**可选模块：**
- 与同类工具对比
- 进阶用法
- 常见错误与处理

---

### 子类型：桌面 / GUI 应用

**必须模块：**
- 下载入口（官网 + GitHub Release）
- 安装方式（安装包 / 便携版 / 包管理器）
- 初次使用引导（3 步以内）
- 核心配置项（至少 3 个）
- 适用场景（什么人、什么任务）
- 许可协议

**更新卡额外要求：**
- 本次更新内容列表

**可选模块：**
- 与同类应用对比
- 快捷键清单
- 已知限制

---

### 子类型：浏览器插件 / Web 工具

**必须模块：**
- 获取地址（商店链接 / 直接下载 URL）
- 添加到浏览器步骤（3 步以内）
- 初步使用说明
- 核心设置项（至少 3 个）
- 注意事项（权限、隐私、数据留痕等）
- 适用场景

**更新卡额外要求：**
- 本次更新内容列表

**可选模块：**
- 权限说明
- 替代方案

---

## 类型二：数据集类

定义：以结构化数据为核心交付物的资源，供训练、评估或参考使用。

**必须模块：**
- 规模指标（样本量 / 时长 / 文件数 / 字段数）
- 字段 / Schema 定义（表格或列表，含数据类型和说明）
- 一条真实样本记录（不做任何脱敏的真实数据）
- 数据格式（JSON / CSV / Parquet / SQL 等）
- 获取方式（下载 / API / 申请流程）
- 许可协议
- 适用场景 / 用途限制

**如有基准测试结果：**
- 测试基准表

**可选模块：**
- 数据分布统计
- 质量评估方法
- 清洗或预处理建议
- 与同类数据集对比

---

## 类型三：集合 / 生态类

定义：多个独立条目（工具 / Agent / 角色 / 资源）的集合。

### 子类型：工具集合

**必须模块：**
- 收录清单总览（总数、来源）
- 分类方式（按什么维度分类）
- 每个分类下的代表性条目（含名称、简介、关键指标）
- 适用场景对照（场景 → 该选哪个分类）
- 安装 / 获取方式
- 许可说明

**可选模块：**
- 条目之间关系
- 如何组合使用
- 维护状态（是否活跃）

---

### 子类型：Agent / 角色集合

**必须模块：**
- 收录数量 + 来源
- 角色分类（按职能 / 部门 / 场景，每个分类给出 2-3 个代表角色）
- 代表角色简介（含核心人设、专业领域、典型工作流）
- 安装使用方式
- 精选推荐（按使用场景）

**可选模块：**
- 角色之间协作方式（如编排器）
- 如何选择适合自己的角色
- 角色更新频率

---

## 类型四：框架 / 平台类

定义：提供基础设施或运行环境，供他人构建自己产品的软件系统。

**必须模块：**
- 一句话定位
- 核心架构说明（模块关系，可文字可图）
- 支持的模型 / 工具 / 协议
- 快速启动（命令或步骤，5 步以内）
- 核心配置参数（至少 3 个）
- 生态周边（插件、模板、SDK）
- 许可协议

**可选模块：**
- 与同类框架对比
- 适用场景与限制
- 性能基准

---

## 类型五：技巧 / 方法论类

定义：以方法、策略、操作步骤为核心内容的条目。

**必须模块：**
- 背景：解决什么问题
- 原理简述（1-2 句话，非源码级）
- 适用场景
- 具体步骤或代码示例（可直接复制使用）
- **风险 / 边界说明**（必须有，不能只讲好处）

**可选模块：**
- Before / After 效果对比
- 常见误区
- 替代方案

---

## 类型六：模型卡

定义：以机器学习模型 / AI 模型为核心交付物的条目。

**必须模块：**
- 基本信息（版本、发布机构、发布日期）
- 关键能力（一句话 + 量化指标）
- 基准测试结果表（至少 3 个基准）
- 许可协议
- 使用限制 / 禁则（如有）
- 与同类型模型的差异（至少 1 个对比维度）
- 获取方式

**可选模块：**
- 训练数据概况
- 推理成本估算
- 适用硬件

---

## 类型七：API / 服务类

定义：以网络 API 或在线服务为核心交付物的条目。

**必须模块：**
- 端点说明（基础 URL + 主要端点）
- 鉴权方式
- 请求示例（可直接复制的 curl 或代码）
- 核心参数（至少 3 个）
- 返回格式示例
- 速率限制
- 适用场景

**如有定价：**
- 定价档位

**可选模块：**
- 错误码说明
- SDK 链接
- 与同类服务对比

---

## 类型八：研究论文类

定义：以学术论文或研究报告为核心内容的条目。

**必须模块：**
- 核心结论（一句话）
- 方法概述（200 字以内）
- 关键数据或图表描述
- 数据集或代码链接
- 引用格式信息
- 与前人工作差异

**可选模块：**
- 适用场景
- 复现难度
- 作者或机构背景

---

## 内容空洞诊断清单

写完后发布前，用以下问题自检。如有任何一项为"否"，该模块必须补充。

- [ ] 是否已确定内容类型？
- [ ] 该类型的必须模块是否全部覆盖？
- [ ] 是否有任何必须模块仅有标题而无实质内容？
- [ ] 技巧/方法论类：是否写了风险/边界？
- [ ] 数据集类：是否有一条真实样本记录？
- [ ] 工具类更新卡：是否列出了本次更新内容？
- [ ] 所有数据（数字/名称/链接）是否与 primary source 核对过？

## 与主题分配的关系

`infocard-theme-assignment` 决定用哪个视觉风格，`infocard-content-types` 决定用哪个内容结构。两者并行执行，互不替代。

theme 解决"看起来怎么样"，content type 解决"里面有什么"。
