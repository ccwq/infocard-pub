# 调研 → 事实包方法论：多智能体编排主题一手资料搜集

## 目的

为信息卡主题（如"AutoAgent / 自然语言驱动的多智能体编排"）执行一手资料搜集，输出可直接交给写卡代理的结构化事实包（fact pack）。

这是 any2card 三件套流水线（`research-to-infocard-three-file-pattern.md`）的**上游输入阶段**：
```
一手调研 → 事实包（本文） → 三件套（HTML + meta.yaml + wiki.md）→ 截图验收
```

## 核心约束（任务级，必须遵守）

| 约束 | 说明 |
|------|------|
| 不得修改仓库 | 只读，不执行 fork / PR / commit / push |
| 不得发布 | 调研文件留在本地，不主动推送 |
| 社交平台不作为成品来源 | 所有事实必须来自 GitHub / 论文 / 官方文档 / PyPI / 官方博客；社交帖子仅作线索 |
| 明确验证等级 | 每个事实项必须标注 ✅ 已验证 / 🔶 合理推断 / ❓ 未核实 |

## 调研项目核查清单

每个主题应对以下维度逐一核查：

```
□ 项目身份（名称、官方仓库 URL、文档站、当前版本号）
□ 作者 / 组织（主要作者、单位、维护组织）
□ 核心机制（解决的问题、关键技术抽象、核心 API）
□ 架构特点（数据流、模块关系、关键组件）
□ 安装与运行（pip / conda / npm 命令，3 行代码示例）
□ 许可证（精确到文件级，如 MIT / Apache-2.0 / CC-BY-4.0）
□ 活跃度指标（GitHub Stars / Forks / 最新提交日期 / 论文引用 / 版本发布）
□ 生态工具（GUI 工具、Studio、配套库）
□ 限制与注意事项
□ 对比总览（同类项目横比）
□ 一手来源 URL 索引
□ 叙事角度建议（2-3 个可选切入角度）
```

## 一手来源优先级（按优先级降序）

1. **GitHub 官方仓库** — Stars / Forks / License 文件 / README / 最后提交日期
2. **官方技术论文**（arXiv / 顶会）— 作者、单位、核心贡献、实验数据
3. **官方文档站** — API 签名、架构图、使用示例
4. **PyPI / npm 包元数据** — 版本号、依赖、许可证字段
5. **Microsoft Research / 官方博客** — 发布公告、版本说明、技术解读
6. **包内文件**（CITATION.cff / setup.py / pyproject.toml）— 作者信息、许可证精确版本

> ⚠️ CSDN / 博客园 / 知乎等中文博客仅作**线索**，不作为成品来源引用。同一事实须在上述一手来源中交叉验证。

## 调研工具组合

| 工具 | 用途 |
|------|------|
| `mcp__minimax__web_search` | 快速定位 GitHub 仓库、论文、官方博客 |
| `browser_navigate`（GitHub 官方） | 获取 Stars / Forks / 最新提交 / License 精确内容 |
| `read_file`（本地已下载文件） | 读取 CITATION.cff、pyproject.toml 等元数据 |
| `browser_vision` | 截图核验页面内容（备选，当文字提取不足时）|

> 推荐并行调用独立信息源（如同时对多个项目执行 web_search），再交叉验证结论。

## 典型工作流

```
1. 识别主题关键词 → 构造多路搜索查询（项目名 + 论文 + 许可证 + 版本）
2. 筛选候选项目（GitHub Stars 排序，过滤非活跃 / 非相关）
3. 逐项目执行"核查清单"（GitHub → 论文 → 文档 → 包元数据）
4. 对比总览表（多项目横比）
5. 整理一手来源 URL 索引
6. 输出结构化事实包（含验证等级）
7. 建议叙事角度（2-3 个可选）
8. 保存到本地（作为 any2card 上游输入）
```

## 关键陷阱

| 陷阱 | 症状 | 解法 |
|------|------|------|
| 博客当来源 | 输出中引用了 CSDN / 博客园 / 知乎链接 | 所有引用必须是 GitHub / arXiv / 官方文档；博客仅作线索 |
| Stars 数据过时 | GitHub 页面显示的 Stars 与实际不符 | 每次调研重新访问 GitHub 页面核验，不依赖历史记录 |
| 第三方 fork 冒充官方 | 引用了非官方的 fork 仓库 | 核查 org 名（microsoft / crewAIInc / langchain-ai 等） |
| 许可证文件缺失 | 仅看到 README 中的许可证声明 | 读取实际 LICENSE / pyproject.toml 文件内容 |
| 论文作者不完整 | 只引用第一作者 | 从 CITATION.cff 或 arXiv 页面获取完整作者列表 |
| 推断当事实 | 将趋势外推标注为"已验证" | 严格区分 ✅ / 🔶 / ❓ 三级 |

## 与三件套的衔接

事实包完成后，下一步由 `research-to-infocard-three-file-pattern.md` 接管，生成：
- `{slug}-infocard.html`
- `{slug}-infocard-meta.yaml`
- `{slug}-infocard-wiki.md`

事实包中"叙事角度建议"和"对比总览"直接作为 HTML 信息卡的内容框架输入。
