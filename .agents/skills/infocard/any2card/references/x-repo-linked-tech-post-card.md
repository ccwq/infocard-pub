# X 引用仓库 / 实验仓库型技术帖卡片笔记

适用场景：X 帖正文本身是技术观点、架构论证或产品宣发，但帖子同时引用了一个或多个 GitHub 仓库、实验仓库、README、benchmark repo 或 sister repo 作为证据。

## 生成原则

1. **帖子主张与仓库事实分开写**
   - 先提炼 X 帖自身的主张。
   - 再把仓库 README / 目录结构 / 关键实验结果作为证据块。
   - 不要把帖子情绪当成仓库事实，也不要把仓库 README 的自述直接写成第三方结论。

2. **主仓库 + 证据仓库都要核**
   - 如果帖子引用主仓库，优先分析主仓库 README、安装/触发逻辑、输出物和结构。
   - 如果还引用实验仓库 / sister repo，必须一起核查，尤其是 A/B、benchmark、case study、实验样本说明。
   - 卡片里要显式区分“主产品仓库”“证据仓库”“作者自测结果”。

3. **时间敏感数字要标注时点**
   - star、commit、release、readme 截图里的统计数字都可能随时间变化。
   - 若帖子引用了当时的 star 数，卡片里要写成“帖子当时值”，并额外标注“当前仓库主页值”或“当前核查时点值”。
   - 避免把两个时点的数据合并成一个事实。

4. **GitHub API 失败时的回退顺序**
   - 先试仓库公开页面和 raw README。
   - 再试浏览器 DOM / 页面源码。
   - 如果 API 返回 403 / rate limit，不要把它当作内容不存在；改用 raw 文本或公开网页继续。

5. **配图/README 图要本地化**
   - 如果卡片要复用仓库 README 的 banner、diagram 或实验图，先下载到本地再引用。
   - 不要把热链直接塞进最终信息卡，避免后续失效。

6. **结论要给“是什么 + 怎么用 + 边界”**
   - 这类卡不是“仓库介绍页”，而是“决策辅助页”。
   - 至少说清楚：它是什么、适合什么、安装/触发入口是什么、哪里是证据边界。

## 常见坑

- 只写 X 帖主张，不核仓库，导致卡片像观点海报。
- 只写仓库 README，不交代帖子主张，导致读者不知道为什么这个仓库被引用。
- 把当前时点的 star 数写成帖子当时的 star 数。
- 实验仓库里的作者自测结果写成第三方复现结论。
- 仓库图、diagram 直接热链，后续失效。
