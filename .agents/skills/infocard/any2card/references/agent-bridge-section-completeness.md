# Agent / Bridge 类卡片章节完整性

适用场景：本地 AI Agent、桥接器、控制面、工具链、多 Agent 能力对照、API/CLI/Workflow 说明、架构总览类信息卡。

## 必补章节（中文）
- **架构总览**：谁执行、谁转发、谁审批、谁续接。
- **Agent 能力矩阵**：至少对照结构化审批、AskUserQuestion、Resume、Fork（或等价能力）。
- **入口与证据**：最小使用顺序、第一步、前提条件、边界。

## 流程要求
- 如果用户指出“缺重要章节”“少了架构/矩阵”“还要中文”，不要只改标题或局部文案；要同步更新 `report.md` 和 `index.html`。
- 章节名、标签、按钮、注释、页脚等可见 UI 统一中文化；英文名只保留作检索锚点或来源对应。
- `Architecture Overview` 这类内容应优先以**可见流程图**呈现：横向节点 + 箭头 + 明确边界说明，而不是把步骤堆成普通列表。
- 若视觉验收反馈“仍像说明卡而不是流程图”，回到 HTML 结构重做，不要只调文字。

## 发布验收
- 本地预览后，再验收公开页 DOM 是否真的包含对应章节。
- 发布后若公开页暂时 404，先按缓存/部署延迟处理并轮询，再判断是否真正失败。
- 验收通过的标准是：页面内容、章节顺序、报告侧车、公开索引三者一致。
