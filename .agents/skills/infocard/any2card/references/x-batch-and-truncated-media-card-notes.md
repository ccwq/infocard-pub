# X 批量信息卡与截断媒体帖处理笔记

## 适用场景
- 用户一次给出多条 X/Twitter 链接，要求“依次创建/发布信息卡”。
- 批量任务中途被审批拦截、切到另一张卡，或用户追加新链接后又要求继续前面的批次。
- X API / vxtwitter 只返回截断正文，但 `mediaURLs` 或引用帖仍有信息。

## 任务连续性规则
1. 批量链接任务被打断后，不要把后续新链接自动理解为取消前序批次。
2. 若用户说“继续”“前面几条也要执行”“不要停止”，应恢复未完成批次，并明确列出哪些已发布、哪些仍待处理。
3. 批量发布时维护一个简短状态清单：抓取 → 生成 → 验收 → 提交/推送 → Pages/list 验证。
4. 若某次命令因审批/副作用阻断没有执行，记录为“未执行”，不要在后续状态里暗示已经写入或发布。

## 截断正文 + 配图证据处理
1. 当 `text` 明显截断但 `mediaURLs` 完整时，把配图当作证据层融入卡片；不要假装已经拿到完整线程。
2. 对配图做 OCR/视觉理解后，要显式标注“来自配图/插图”，并把它组织成信息层，而不是只贴图。
3. 对“10 个仓库/工具”这类列表帖，如果可见正文只到第 1 项，缺失条目不得虚构；可改为“可确认正文 + 插图证据层”模式。
4. 多图帖优先本地化所有图片到 `docs/assets/images/`，再用相对路径引用，避免热链失效。
5. 引用帖（QRT）要融入主卡：写成背景/传播叙事/补充证据，不要自动拆成另一个任务，除非用户明确要求分卡。

## 发布验收补充
- 每张卡必须验证：详情页 200、`/_index.yaml` 命中 slug、首页/list 可见计数更新、Git 工作区干净。
- 移动端基础检查至少覆盖：无横向溢出、`.page` padding 为 0、最小字号约 12.5–13px+、PNG 导出函数存在。
