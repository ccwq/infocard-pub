# 单卡 PWA 与 infocard-insta-pwa-skill 规格

## 问题与目标

信息卡站点已有整体 PWA，但部分卡片需要独立名称、图标、入口和独立窗口。用户需要按卡授权创建，不希望每张卡自动变成 App。首个实践是「我的提示词」信息卡；先完成该卡 PWA 的发布与助手侧验收，再基于真实经验创建项目级 `infocard-insta-pwa-skill`。

## 用户故事

1. 作为读者，我希望从手机主屏幕的专属图标打开指定卡片，快速进入目标内容。
2. 作为读者，我希望在支持的桌面浏览器中安装卡片，并以独立窗口打开。
3. 作为读者，我希望 App 有可辨认的名称和图标，不与全站 PWA 混淆。
4. 作为读者，我希望首屏和页尾都有安装入口；支持直接调起安装时均可触发，不能直接调起时看到适用于当前平台的手动说明。
5. 作为读者，我希望已有复制、计数、排序和数据导入导出继续工作。
6. 作为读者，我希望知道不同浏览器、App 和设备的计数不保证共享，并可用 JSON 迁移。
7. 作为维护者，我希望仅在明确授权时为指定卡接入，不自动给所有信息卡创建 PWA。
8. 作为维护者，我希望保留已发布卡的 URL 和正文，并避免干扰全站 PWA 与其他卡片。
9. 作为维护者，我希望 Skill 复用项目权威发布流程，不维护第二套发布 SOP。
10. 作为验收者，我希望先收到发布结果，再配合目标设备实机安装验证。

## 通用决策

- 新建项目级 Skill，名称严格为 `infocard-insta-pwa-skill`。发布一张普通卡后可询问是否创建 PWA，未获明确授权不得自动创建。
- 适用于新卡和已发布卡。历史卡保持原 URL，不因 PWA 接入重做正文。
- 每张卡按需配置独立的稳定 App 身份、名称、短名称、入口、图标和 standalone 展示；单卡范围尽量限定于当前卡，基于浏览器规范与实测验证。与全站 PWA 的身份和范围共存必须验证。
- 复用站点既有 Service Worker；不新增单卡 Service Worker，不擅改全站 Service Worker。此处不新增离线能力，也不要求禁止既有离线行为；应实测并说明联网、更新与断网表现。
- 专属图标按卡配置；Skill 固化图标格式、尺寸和验收方法，不固定所有卡图案。兼容不同平台的安装要求和限制。
- 单卡 PWA 页面在首屏（hero）和页尾（footer）各提供一个安装入口，可连同页面中部既有工具栏入口并存；多个入口共享同一触发状态（统一显示/隐藏）。按钮默认隐藏：仅在支持直接安装提示（`beforeinstallprompt`）或对应平台手动说明场景（如 iOS 的「添加到主屏幕」步骤）出现；已安装（standalone / `appinstalled`）或用户接受、取消后全部隐藏，避免误导性重复安装引导。此模式是单卡 PWA 页的固化要求，不泛化到普通信息卡。
- 计数保留在本地存储；不承诺普通网页、已安装 App 和不同设备共享。保留 JSON 导出和导入作为迁移路径。

## 首个实践：「我的提示词」

- 保持已发布卡的原 URL；名称和短名称为「我的提示词」。
- 图标采用卡片轮廓、文本行和复制符号，避免依赖小字号文字，验证手机图标尺寸下的辨识度。
- 摘要区域直接放导航，首屏可见；导航不显示分类标签；复制按钮紧凑，保持可操作性。
- 保留固定源的 26 项完整提示词、源顺序正文、导航和正文复制、成功计数、计数降序与源顺序平局排序、JSON 导入导出及既定失败处理。
- 本地 PWA 候选和视觉证据已存在；发布前重新核对精确文件、hash、manifest scope、安装行为和当前远端状态，不把候选或模拟误报为已发布或实机通过。
- 线上最新发布为提交 `a3abf2c3`（首屏 hero 与页尾 footer 安装入口，与工具栏入口共享触发状态）；本地未跟踪副本（卡页与测试文件）停在 `e35bf7c8` 状态，webmanifest 两版一致。同步前按权威流程重新核对本地与远端分叉。

## 测试与验收

- 以公开页面和真实浏览器可观察行为为主，配置及自动测试为辅。验证 manifest、稳定身份、入口（首屏与页尾位置、默认隐藏、共享状态）、图标、安装提示、独立窗口能力以及与站点 PWA 的共存。
- 验证 PWA scope 对目标卡、站点根页面及其他卡的实际导航影响；不凭字段相似性推断隔离或覆盖。
- 验证复制成功才计数、失败不计数、导航排序、刷新持久化、导出和合法／非法导入、存储失败降级。
- 真实截图审核当前版本的桌面与移动视口，使用可追溯的浏览器实测几何；不得将静态推导作为实测。HTML 修改后重新截图。
- 构建和发布按项目 `AGENTS.md` 的权威流程执行：默认主 checkout，经用户授权的隔离 checkout（含临时 clone）同样遵循候选、提升、验收和发布顺序。上线后回读目标卡、manifest、图标及索引入口，检查线上版本指纹与桌面／移动视觉。
- 先发布并完成助手侧可执行验收，再邀请用户在目标设备安装、检查图标、打开页面并反馈。实机反馈前标记「等待用户验证」；浏览器提示、模拟或 UA 覆盖不等于实机安装通过。「我的提示词」已获用户实机安装确认（2026-11-15，设备与浏览器型号未记录），该确认仅覆盖用户的实际设备，不推广为所有平台通过；其他平台仍以逐台实测为准。
- 已发布且助手侧验收后，根据实践创建 Skill；尚未经过用户实机确认的内容明确标记验证状态。

## 仓库边界与已知风险

- 同步前只读调查本地与远端分叉、路径重叠、删除方向和未提交内容，避免覆盖或丢失。只纳入本卡及必要生成物。
- 不提交 SAG2 或其他任务的未授权改动；临时 clone、Git worktree、stash、reset、clean 按项目 `AGENTS.md` 的工作区边界执行，不得借此绕过项目边界、覆盖或丢弃其他任务的现有工作，也不移动其他任务文件。
- 当前本地与远端存在分叉、同名未跟踪文件与索引脏改动；按实际状态验证并寻找合规处理路径。找不到安全路径时报告阻塞，不擅自扩大范围。
- 项目 Skill 的具体位置、路由与已有职责先按项目入口核实；先实践再沉淀，不重复发布 SOP。

## 不在范围内

- 默认给全部信息卡创建 PWA；云同步、账户体系或服务端计数；修改全站 Service Worker；保证离线可用或强制禁用已有缓存；替其他任务清理、提交或发布；未经确认的目标平台实机通过声明。
