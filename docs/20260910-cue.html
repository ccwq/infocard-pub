C

Cue

不是让 AI 更会写代码，而是先给它一套更好的审美参照和交互提示。

给 AI 建站工具补上审美和交互参考

当你用 Cursor、v0、Bolt 或 Framer AI 生成页面，真正的问题常常不是“不会写 React”，而是说不清想要的动效、Hero 结构、节奏和完成度。Cue 把人工精选的高质量组件参考与可复制 Prompt 放到一起，让你从“高级一点”变成可执行的设计输入。

人工策展

每个条目来自高质量网站、设计作品或生产组件，强调选品而不是机器填充数量。

Prompt-first

复制一段针对组件的提示，交给已有的建站工具，而不是再学习一个封闭编辑器。

工具中立

可用于 Bolt、v0、Cursor、Framer AI、ChatGPT 和 Claude，结果仍由你的工具生成。

味觉层

Cue 不托管项目、不部署代码、不运行模型，它提供的是判断和起点。

先记住：Cue 不是模板市场。你买到的是经过选择和表达的交互参考与 Prompt，不是一份固定的代码压缩包。
01

它解决什么问题：审美词穷，而不是语法不会

来源帖描述了一个很常见的 AI 建站场景：你知道自己想要 Awwwards 级别的丝滑微交互，向模型说“高级、灵动、有质感”，最后仍然得到一排相似的圆角卡片。模型缺的未必是生成代码的能力，而是缺少足够具体、足够高质量的视觉和交互参照。

Cue 的回答是把“感觉”拆成可观察的组件级参考。一个 Hero、导航、滚动揭示、卡片、按钮或转场，不只附带一句形容词，还可以通过参考案例、参数化的动效描述和 Prompt，告诉 AI 这部分应该怎样组织、怎样运动、怎样服务内容。

把模糊形容词改成可验收语言：不要只写“做一个高级 Hero”；说明内容层级、视觉焦点、进入方式、滚动行为、移动端退化方案、动效时长和完成后用户应该注意什么。
02

先分清楚：Cue 是什么，不是什么

它是

  • 人工精选的 UI 组件与交互参考库。
  • 面向 AI 建站工具的可复制 Prompt 库。
  • 帮助设计师、开发者和独立开发者减少从零构思的起点。
  • 一个强调“品位高于数量”的编辑层。

它不是

  • 不是 Figma 文件或固定模板下载包。
  • 不是替你调用大模型的 AI wrapper。
  • 不是托管项目、部署代码的平台。
  • 不是课程、订阅制 SaaS 或企业软件。

这一区分决定了你的预期：如果你需要可直接安装的 React 组件、可编辑的设计文件或一键部署，Cue 当前并不是完整替代品。它更像一套经过筛选的“设计起跑线”，最终代码仍然在你的项目和工具里产生。

03

它如何工作：浏览 → 选择 → 复制 → 生成 → 验收

01浏览组件，先看参考交互和适用语境。
02选择与你的页面任务和品牌方向匹配的条目。
03复制组件 Prompt，而不是复制一堆无上下文代码。
04粘贴到 Cursor、v0、Bolt、Framer AI、ChatGPT 或 Claude。
05在真实项目中改内容、接数据并做浏览器验收。

这个流程的关键不是“Prompt 越长越好”，而是参考和目标足够具体。一个好的 Prompt 应该帮助模型理解布局、状态、动效和边界；它不能替代你的产品信息架构，也不能替代真实设备测试。

04

第一次使用：用一个 Hero 做 30 分钟实验

第 1 步：先写页面合同

在打开 Cue 前，先写清楚页面服务谁、主任务是什么、用户要看到什么证据、移动端最重要的操作是什么。否则你很容易被漂亮的参考牵着走，最后只得到一个有动效但没有方向的首页。

页面：独立开发者的 API 监控产品首页
主任务：让访客理解价值并开始免费试用
首屏证据：实时状态、监控范围、一个可信的结果数字
动效预算：首屏一次进入动效，滚动区两处揭示
移动端：标题先读懂，CTA 不被动画推走
不接受：自动播放声音、过度视差、无法跳过的长动画

第 2 步：挑参考，不挑“风格标签”

不要只搜“dark premium hero”。按组件任务找：导航如何收起、Hero 如何建立层级、数字如何出现、卡片怎样在滚动时进入、按钮反馈是否让人知道操作成功。你是在选择行为参照，不是在购买某个网站的皮肤。

第 3 步：复制 Prompt 后补项目约束

将 Cue Prompt 粘贴进工具后，追加你的框架、字体、内容、路由、性能目标和无障碍要求。明确告诉模型哪些参考只用于交互逻辑，哪些视觉元素不能直接复制。

第 4 步：只验收一个核心组件

先让 Hero 工作，再扩展到下方区块。检查桌面、390px 移动端、键盘焦点、Reduce Motion、加载速度和真实文案。不要因为首屏好看就默认整页质量合格。

05

如何把 Prompt 变成可验收的工程输入

AI 最容易误解的是“像某某获奖网站”这种整体模仿请求。更可靠的做法是把 Prompt 变成组件规格，至少包含以下层次：

层次写什么验收问题
任务组件服务什么用户目标，完成后发生什么删掉动效后任务还清楚吗
结构容器、内容顺序、主次层级、响应式变化390px 时最重要的信息是否先出现
视觉字体角色、颜色 token、留白、对比和密度是否只是换了渐变和圆角
运动触发条件、时长、easing、延迟和退出方式运动是否解释状态，而不是制造噪音
状态默认、悬停、焦点、加载、错误、空和禁用键盘和失败路径是否被设计
边界减少动效、低带宽、长标题、无图和触控设备不满足理想条件时还能用吗

这样使用 Cue 的价值在于：它提供高质量参照，你负责把参照转换成适合自己项目的工程合同。模型负责实现，浏览器和用户负责验收。

06

别把“高级感”变成技术债

高完成度界面不等于更多动画。每加入一个滚动、视差、WebGL 或复杂转场，都要回答它为用户解释了什么。若答案只是“看起来更贵”，就应该评估成本。

  • 性能：首屏文字和主 CTA 先可用，重资源和非关键动效延后加载；观察 LCP、CLS、INP。
  • 可访问性：所有交互有键盘路径，焦点可见，动画响应 prefers-reduced-motion，颜色不是唯一状态信号。
  • 响应式：桌面上的横向叙事可能要在手机上变成纵向顺序，不要把桌面布局缩小后强塞进 390px。
  • 维护性：把颜色、间距、时长和层级写成 token，避免模型在每个组件里重新发明一套 CSS。
  • 版权与来源：参考某个作品的交互逻辑不等于可以复制它的素材、品牌资产或完整页面。
判断句：如果动效关闭后信息层级、操作路径和状态反馈都消失了，问题可能不是动效不够，而是内容结构没有站稳。

把一个条目拆成四个问题

  1. 它解决什么界面任务？是建立层级、引导点击、解释状态，还是让用户发现下一段内容？
  2. 它依赖什么条件？需要鼠标悬停、滚动、视频、WebGL、音频或特定屏幕宽度吗？
  3. 它应该如何退化？移动端、键盘、触摸屏、低性能设备和减少动效模式下是否仍然成立？
  4. 它怎样被证明有效？是提高理解、减少误操作、展示产品证据，还是只增加停留时长？

这四个问题能把“我喜欢这个效果”变成可迁移的设计知识。你可以参考一个网站的滚动揭示，但不必复制它的颜色、品牌、素材和完整页面结构；真正值得带走的是它如何安排注意力，以及这个安排是否适合你的任务。

小练习：打开一个你认为优秀的 Hero，关掉声音、动画和图片，只保留文字与按钮。如果用户仍然知道产品是什么、下一步做什么，这个组件才有可靠的结构基础。
07

Cue 不是唯一答案：什么时候自己建立参考库

如果你只做一次页面，直接使用公开的 Awwwards、Behance、Dribbble 或生产产品作为研究素材，可能比购买任何库更合理；如果你每周都在交付页面，人工策展库才可能带来复用价值。判断标准不是“哪个工具最酷”，而是你每月重复多少次寻找参考、解释动效和修正模型输出的工作。

直接研究公开案例

适合：预算有限、需要独特方向、愿意自己记录参考的人。

做法：建立组件分类、保存 URL、记录触发条件、截图关键状态，并为每条参考写“为什么有效”和“如何退化”。

使用 Cue

适合：想减少检索和表达成本、已在使用 AI 建站工具、愿意先从免费内容验证的人。

做法：先复制一个 Prompt，比较它与自己的规格差异，再决定是否值得长期使用。

无论采用哪种路径，都要保留自己的设计判断。参考库的最佳结果不是让所有页面长得一样，而是让你更快识别哪些结构值得借鉴、哪些动效只是装饰。

09

适合谁：有工具的人，而不是想找魔法的人

适合

  • 已经使用 Cursor、v0、Bolt、Framer AI、ChatGPT 或 Claude。
  • 每周需要交付 landing page 或营销页面的自由职业者和小团队。
  • 知道自己不想要通用模板，但还没有稳定参考库的独立开发者。
  • 愿意自己改内容、接数据、测性能和做无障碍验收的人。

不适合

  • 只想下载开源代码并立即部署的人。
  • 需要企业 SSO、私有部署、定制 SLA 的团队。
  • 希望 Cue 自动替自己完成产品设计和代码交付的人。
  • 不愿意检查参考来源、许可证和生成结果的人。
09

最终验收：这次生成真的比默认卡片好吗

  1. 页面主任务能否在 5 秒内说清楚，而不是只有一段氛围文案？
  2. Hero 的参考是否被转换成了具体结构，而不是简单换颜色？
  3. 动效是否有触发、时长、退出和 reduced-motion 规则？
  4. 长标题、长按钮、无图、低带宽和 390px 宽度是否正常？
  5. 键盘焦点、语义结构、对比度和替代文本是否可检查？
  6. 加载失败、空数据、错误和禁用状态是否有下一步？
  7. 代码是否使用项目已有的 token 和组件约定，而不是制造一套孤岛 CSS？
  8. 参考案例的素材、品牌和版权边界是否被保留？
  9. 你能否指出 Cue Prompt 具体改善了哪个决定，而不只是觉得页面“更高级”？
