第 1 步 · 把需求写成规格，而不是形容词

“做一个高级 Hero”模型接不住。可验收的写法是把任务、证据、动效预算和退化方案写清楚：

组件：Hero（首屏）
主任务：让访客理解价值并开始免费试用
首屏证据：实时状态、监控范围、一个可信的结果数字
动效预算：首屏一次进入动效，滚动区两处揭示
移动端：标题先读懂，CTA 不被动画推走
不接受：自动播放声音、过度视差、无法跳过的长动画
第 2–3 步 · 挑行为参照，Prompt 加项目约束

不要只搜 “dark premium hero”。按行为找：导航如何收起、数字如何出现、卡片怎样随滚动进入、按钮反馈是否说明操作成功。你选的是行为参照，不是某网站的皮肤。

把 Cue 的 Prompt 粘贴进工具后，补上你的框架、字体、内容、路由、性能目标和无障碍要求；明确哪些参考只取交互逻辑，哪些视觉不能直接复制。

把 Prompt 变成工程输入：六个层次

层次写什么验收问题
任务组件服务什么目标，完成后发生什么删掉动效后任务还清楚吗
结构容器、顺序、主次、响应式变化390px 时最重要的信息先出现吗
视觉字体角色、颜色 token、留白、对比是否只是换了渐变和圆角
运动触发、时长、easing、延迟、退出运动解释状态还是制造噪音
状态默认、悬停、焦点、加载、错误、空键盘和失败路径设计了吗
边界弱动效、低带宽、长标题、触屏条件不理想时还能用吗

别把“高级感”变成技术债

性能首屏文字与主 CTA 先可用；关注 LCP / CLS / INP
可访问性键盘路径 + 可见焦点 + prefers-reduced-motion
响应式桌面横向叙事在手机上改纵向顺序，不缩放硬塞
维护性颜色 / 间距 / 时长写成 token，禁止组件各自发明
版权参考交互逻辑 ≠ 复制素材、品牌资产或整页
判断句：如果关掉动效后信息层级、操作路径和状态反馈都消失了，问题不是动效不够，而是内容结构没站稳。
