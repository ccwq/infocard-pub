AnySearch Skill：不是一个搜索框，而是一条给 Agent 用的检索链

01 这个技能到底是什么
README 与 SKILL.md 都把它定义成一个实时搜索引擎技能：通用搜索、垂直领域搜索、并行批量搜索、URL 全文提取都打包在一起，目标是给 AI Agent 提供一套更像“工作流基础设施”的检索能力，而不是仅返回一串链接。
search batch_search extract list_domains Agent-friendly
02 它和普通搜索工具的差别

不是只找链接

`search` 负责发现信息，`extract` 负责把 URL 变成可读正文，避免只看 snippet。

不是单点调用

`batch_search` 适合多个独立问题并行检索，减少 Agent 来回切换的成本。

先判垂直领域

SKILL.md 明确要求：遇到金融、学术、旅行、健康、代码、地理等领域，先 `list_domains` 再搜，避免泛搜误差。

运行方式更轻

它不要求额外装 MCP 服务，而是用 bundled CLI 直接跑，降低接入门槛。

03 安装与配置要点
1
下载 zip，解压后移到技能目录（README 给了 Claude Code / OpenCode / Cursor / 通用路径示例）。
2
API Key 可选，但建议在 `.env` 里配置 `ANYSEARCH_API_KEY`；优先级是 `--api_key` > `.env` > 环境变量 > anonymous。
3
运行 `doc` 或直接用 CLI 验证，随后把推荐 runtime 写进 `runtime.conf`，以后直接复用。

05 适合哪些场景

最适合

  • 调研前的事实发现
  • 多主题并行搜索
  • 把 URL 直接提成正文
  • 垂直领域结构化查询

不该误用

  • 把它当单纯搜索框
  • 跳过 list_domains 就盲搜垂直题
  • 只看 snippet 不做 extract
  • 忽略 API Key / runtime 配置
06 一句话结论
TakeawayAnySearch 的核心不是“再装一个搜索工具”，而是把搜索、批量发现、正文提取和垂直领域判定整成一套可直接给 Agent 复用的检索链；对于高频查资料的 Agent，这种结构比单纯搜索更有生产力。
