01
它是什么

不是框架，是自带执行环境的 SuperAgent harness

DeerFlow 2.0 全称 Deep Exploration and Efficient Research Flow，是字节跳动开源的长程 SuperAgent 运行时——它不只是编排 LLM 调用，而是给 agent 一台真实的「计算机」去干活。

定位harness

从 Deep Research 框架进化为通用 agent harness

v1 是深度研究框架；社区把它用到了数据管线、PPT、仪表盘、内容工作流。字节意识到它本质是 harness 而非单一工具，于是从头重写了 2.0——与 v1 零共享代码。

  • 基于 LangGraph + LangChain
  • 自带文件系统、记忆、技能
  • 沙箱感知的代码执行
核心理念batteries included

「Use it as-is. Or tear it apart and make it yours.」

README 原话：开箱即用，或拆开重组。它不是一个需要你自己拼装的框架，而是一个已经跑起来的 agent 运行时，你只需要接入模型和配置。

  • 内置研究、报告、PPT、网页技能
  • 技能按需加载，不占上下文
  • 支持自定义技能和工具替换
长程任务minutes to hours

处理从几分钟到几小时的长程任务

GitHub 描述明确写着 handles different levels of tasks that could take minutes to hours。它通过子代理拆解、上下文压缩、文件系统暂存中间结果来维持长程连贯性。

  • 子代理并行 + 结构化汇报
  • 上下文自动摘要与卸载
  • 中间结果写入沙箱文件系统
02
核心能力

子代理编排 + 沙箱执行 + 长期记忆 + 技能系统

DeerFlow 的核心能力可以拆成四层：Lead Agent 拆解任务并编排子代理、沙箱提供真实执行环境、记忆跨会话持久化、技能系统按需加载专业能力。

能力 1sub-agents

子代理：并行拆解，结构化汇总

Lead Agent 在运行时动态生成子代理，每个子代理有独立上下文、工具和终止条件。子代理尽可能并行运行，汇报结构化结果，Lead Agent 综合成最终输出。

One harness, many hands. 一个研究任务可以扇出到十几个子代理，各自探索不同角度，再收敛成报告、网站或 PPT。
  • 子代理上下文隔离，互不干扰
  • token 用量追踪回追溯到分派步骤
  • 支持 parallel 执行
能力 2sandbox

沙箱与文件系统：agent 有自己的计算机

每个任务获得独立执行环境和完整文件系统视图：uploads/（你的文件）、workspace/（工作目录）、outputs/（最终交付物）。agent 可以读写编辑文件、查看图片、执行 shell 命令。

  • AioSandboxProvider：隔离容器执行
  • LocalSandboxProvider：按线程隔离目录，默认禁用 host bash
  • 支持 Docker / Kubernetes 沙箱模式
能力 3memory

长期记忆：跨会话记住你的偏好

大多数 agent 在对话结束后就遗忘一切。DeerFlow 跨会话构建持久记忆——你的画像、偏好、技术栈、常用工作流。用得越多，它越了解你。记忆存储在本地，完全由你控制。

  • 自动去重，避免重复事实堆积
  • 本地存储，隐私可控
  • 可通过 /memory 命令查看
能力 4skills

技能系统：按需加载的专业能力模块

技能是结构化的 Markdown 能力模块，定义工作流、最佳实践和参考资源。内置：研究、报告生成、PPT 创建、网页、图片/视频生成。支持自定义、替换和组合成复合工作流。

  • 渐进式加载——任务需要时才载入
  • /skill-name 斜杠命令显式激活
  • 支持 .skill 归档包安装
  • MCP Server 扩展工具
能力层做什么技术细节
子代理编排拆解长程任务，并行探索LangGraph 状态图，独立上下文隔离
沙箱执行跑代码、读写文件、生成交付物Docker / K8s 隔离容器，LocalSandboxProvider 回退
长期记忆跨会话记住用户画像与偏好本地存储，自动去重，/memory 可查
技能系统按需加载专业工作流Markdown 定义，渐进式加载，.skill 包安装
IM 渠道从聊天 app 接收任务Telegram/Slack/飞书/微信/企微/钉钉，无需公网 IP
可观测性追踪 LLM 调用与 agent 运行LangSmith + Langfuse 双后端支持
03
怎么上手

三步跑起来：clone → make setup → make docker-start

DeerFlow 提供交互式配置向导，约 2 分钟完成。Docker 是推荐路径，也支持本地开发模式。访问地址统一在 http://localhost:2026。

路径 ADocker 推荐

最短可用路径

git clone https://github.com/bytedance/deer-flow.git
cd deer-flow
make setup  # 交互式配置向导，~2 分钟
make docker-init  # 拉取沙箱镜像
make docker-start  # 启动服务

make setup 会引导你选择 LLM provider、搜索引擎、沙箱模式和安全偏好，生成 config.yaml 和 .env。随时可运行 make doctor 检查配置。

  • 生产部署：make up / make down
  • 访问 http://localhost:2026
  • 配置变更自动热加载（开发模式）
路径 B本地开发

不用 Docker 也能跑

Step 1
make check — 验证 Node.js 22+ / pnpm / uv / nginx
Step 2
make install — 安装前后端依赖 + pre-commit hooks
Step 3
make setup-sandbox — 预拉沙箱镜像（可选）
Step 4
make dev — 启动开发服务，热重载
模型配置

模型无关，推荐三款

DeerFlow 兼容任何 OpenAI-compatible LLM。官方推荐 Doubao-Seed-2.0-Code、DeepSeek v3.2、Kimi 2.5。最佳表现需要：100k+ 上下文、推理能力、多模态、强工具调用。

IM 渠道

从聊天 App 直接派活

支持 Telegram、Slack、飞书/Lark、微信、企微、钉钉。所有渠道无需公网 IP，配置后自动启动。/new 开新对话，/status 查线程，/models 列模型。

嵌入客户端

Python 嵌入式调用

DeerFlowClient 提供进程内直接访问，无需启动 HTTP 服务。支持 chat、stream、list_models、upload_files 等，返回与 HTTP Gateway 相同的 schema。

部署资源建议：本地评估 4vCPU/8GB 起步，推荐 8vCPU/16GB；长期运行服务器推荐 16vCPU/32GB。Linux + Docker 是推荐的生产部署目标。

05
边界与风险

它有系统命令执行权限——部署不当就是安全灾难

DeerFlow 设计为本地可信环境（127.0.0.1）运行。它拥有系统命令执行、资源操作和业务逻辑调用等高权限能力。部署到不可信环境等于开放后门。

1

高权限能力 = 高安全风险

README 安全公告明确警告：agent 具备系统命令执行、文件读写、资源操作能力。部署到 LAN、公网服务器或多端可访问环境而未做防护，可能被未授权调用执行高危操作。

2

2.0 是完全重写，v1 经验不完全适用

DeerFlow 2.0 与 v1 零共享代码。如果你之前用 v1（Deep Research 框架），迁移需要重新理解架构。v1 维护在 main-1.x 分支，但活跃开发已转向 2.0。

3

Gateway 单 worker 限制

生产环境默认单 Gateway worker（GATEWAY_WORKERS=1），因为运行状态在进程内。多 worker 会破坏运行取消、SSE 重连、IM 渠道。扩展靠加 CPU/RAM 而非加 worker。

场景适合不适合 / 需注意
本地可信环境部署个人开发、团队内部试用、研究实验直接暴露到公网或 LAN
长程任务自动化研究、报告、PPT、内容生成工作流需要 100% 确定性输出的场景
沙箱代码执行数据分析、脚本生成、文件处理LocalSandboxProvider 下 host bash 默认禁用，手动开启有风险
多用户共享通过 IM 渠道分发任务需配置认证网关 + IP 白名单

安全建议：IP 白名单（iptables/ACL）、认证网关（nginx 强预认证）、网络隔离（专用 VLAN）、持续跟进安全更新。核心原则——不要把 DeerFlow 直接暴露给不可信网络。
