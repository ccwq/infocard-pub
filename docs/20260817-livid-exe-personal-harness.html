01它真正整合了什么

◈持久 VM

首次下载 Debian 13 genericcloud raw image；APFS copy-on-write clone。daemon 退出会关机，但磁盘保留。

⌁两种 LLM 角色

VM 内 Agent 走 Ollama；Chat 窗口可走 ChatGPT subscription / Codex OAuth。两者不是同一条后端。

↗可编程发布

Cloudflare Tunnel + 本地 reverse proxy 可把 VM 端口暴露出去，但 remotely-managed tunnel 有权限前置条件。

◎节点同步

配对节点可同步 Workspace 与 app-data；peer 路由使用 Ed25519 签名，文件路径、大小与冲突处理都有边界。

02端口不是产品边界

7777 / 2222 / 8090
分别是 Web/API、SSH gate、reverse proxy 的默认入口；都可配置或关闭。绑定到 Tailscale / 非 localhost 前，应先设置 API token。
expose 不是“自动安全上线”
需要 Cloudflare API 权限；本地管理 cloudflared 还需手工 catch-all。unexpose 当前会留下 DNS record 与 ingress rule。

03版本边界：不要把旧 master 当今天的发行版

Firecracker / QEMU-WHPX
仓库旧 master 的文档与源码曾描述 Linux Firecracker、Windows QEMU + WHPX；当前 main README 的对外主线是 macOS。卡片不把旧路线写成当前 main 已稳定发布的跨平台能力。

04从源码开始，而不是下载二进制

git clone https://github.com/livid/exe cd exe make build ./exe init ./exe serve ./exe create demo ./exe ssh demo

本次审计未发现 GitHub Releases、tags 或根目录许可证文件；Quick Start 是源码构建路径。不要把它描述成已有正式二进制渠道，也不要擅自补 MIT / Apache。

05适合谁，不适合谁

适合

想把 Mac 上的个人 VM、开发服务、Agent 工作目录和远程入口收进一个可理解的控制面；愿意自己维护 daemon、密钥、Cloudflare 与网络边界。

不适合

需要正式发布二进制、明确开源许可证、跨平台稳定支持、自动重启、快照、virtiofs shares 或生产级多租户隔离的团队。
