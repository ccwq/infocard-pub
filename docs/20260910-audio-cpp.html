一 · 它解决什么问题why

想本地跑语音合成（TTS）、语音识别（ASR）或变声，通常要在 Conda/venv 里为每个项目单独配 Python 环境：CUDA 版本打架、依赖互相冲突、模型加载代码各写一套。audio.cpp 的做法是把推理引擎下沉到 ggml（llama.cpp 同源的 C++ 推理层）：一个二进制覆盖全部语音任务，推理核心零 Python 依赖，统一走 CLI、WebUI 或 REST API。Python 只在个别模型需要从 HuggingFace 下载或做 checkpoint 转换时出场（模型管理脚本），推理路径与它无关。

三个统一入口：CLI（audiocpp_cli --task <task> --model <path> --backend <backend>）、WebUI（audiocpp_server --ui --ui-management，含 Arena 多模型对比页）、REST API（/v1/audio/speech、/v1/audio/transcriptions、/v1/audio/alignments、/v1/tasks/run）。

性能定位（v0.7 发布基准，RTX 5090 单卡）：官方 README 给出的数字是部分 TTS 路径比 Python 快 1.8x–8x（Qwen3 TTS 1.83x，PocketTTS 3.68x，不同模型差异大）、端到端延迟降低 45%–85%；PocketTTS 离线 RTF=0.021（约 48x 实时），Supertonic 3 达 RTF=0.005（约 187x 实时）。GGUF Q8 量化包在部分模型路由上峰值显存降约 37%、速度最高 1.53x。这些是发布时基线数字，引用需带模型与硬件上下文。

④Docker

# macOS（最简路径）
brew tap 0xShug0/audio-cpp && brew install audio-cpp

# Linux 源码编译（CUDA 后端 + CLI/server 两个产物）
scripts/build_linux.sh --backend cuda --target audiocpp_cli --target audiocpp_server
# 前置：GCC 13+、CMake、NVIDIA CUDA Toolkit

# 定制模型集，显著缩短编译时间
scripts/build_linux.sh --model-set custom --models qwen3_tts,pocket_tts,qwen3_asr

# 下载模型（GGUF：HF audio-cpp/audio.cpp-gguf 或 ModelScope 镜像）
audiocpp_model_manager list
audiocpp_model_manager install qwen3_asr_0_6b_q8_0 --models-dir models

预编译覆盖：Windows（CUDA 12.4/13.3、Vulkan、CPU）、Ubuntu（Vulkan、CPU）、macOS（Metal）。注意 Linux 官方预编译不含 CUDA 包，CUDA 用户要么自行编译要么用 Docker。

四 · 首用：15 分钟跑通第一条语音first run

新手推荐 WebUI 路径（模型目录浏览、下载、切换、麦克风录音、语音库都有界面）：

audiocpp_server --ui --ui-management --backend cuda
# 浏览器打开 http://127.0.0.1:8080

想先走 CLI 验证推理，用中文最稳的 Qwen3 家族：

# TTS：中文合成
audiocpp_cli --task tts --family qwen3_tts --model models/<gguf> --backend cuda

# ASR：中文识别（offline 批处理 / streaming 流式两种模式）
audiocpp_cli --task asr --family qwen3_asr --model models/<gguf> --backend cuda

任务类型全景：vad|asr|diar|sep|gen|tts|clon|vc|s2s|align|vdes|spk|svc；后端可选 cpu|cuda|vulkan|metal|best。装完多个模型后，去 WebUI 的 Arena 标签（2026-09-09 新增）：多个模型共享同一输入并排生成、支持队列批量推理、附指标——选音色不用再一个个试。

五 · 验证与接入 APIverify

  • 健康检查：GET /health 返回正常即服务可用；GET /v1/models 列出已加载模型
  • TTS 接口：POST /v1/audio/speech，OpenAI 兼容形态，可直接替换现有代码里的 base URL
  • ASR 接口：POST /v1/audio/transcriptions；要词级时间戳等细节走 /v1/audio/transcriptions/details
  • 流式验证：同请求切 streaming 模式，确认首包延迟满足实时场景
  • 量化验证：BF16 与 Q8 各跑一次同文本，比对音质与显存占用后再定生产配置
  • 性能基线：用自己的主力模型记录 RTF，与 README 基线（RTX 5090）对比判断硬件是否达标

六 · 排障：高频坑位清单troubleshooting

1Windows CUDA 包启动失败：需把 cudart 压缩包解压到二进制旁边，否则 ggml-cuda.dll 加载失败——这是 Windows 用户最常见的第一坑。
2编译失败：Linux 检查 GCC 是否 13+；Windows 检查 Visual Studio Build Tools 是否勾选 C++ 桌面开发负载。
3非 CUDA 后端表现差：官方明确 CPU/Vulkan/Metal/HIP 是可移植性与测试路径，性能与模型覆盖低于 CUDA，属预期行为不是 bug。
4显存吃紧：lazy_load=true 只延迟首次加载，用过的模型仍常驻到服务退出；把 max_loaded_models 设为 1 可强制单模型内存隔离。
5个别模型安装时要 Python：部分模型包需要 HF 下载或 checkpoint 转换，此时调用 Python manager；推理本身仍无 Python。
