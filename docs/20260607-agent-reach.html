01
CORE JUDGMENT

Agent Reach 解决的不是“有没有一个爬虫”，而是“每次新 Agent 都要重新找工具、装依赖、配 Cookie、判断哪个平台又变了”的重复劳动。

它最值钱的地方

  • 把平台接入做成能力层：选型、安装、体检、路由、Skill 注册。
  • 上游变了就换后端顺序，不要求用户重学一套命令。
  • Agent 读了 SKILL.md 后，能自己判断“搜推特/看视频/读 GitHub/解析 RSS”该调什么。

不是它要做的事

  • 不是 SaaS，不需要注册 Agent Reach 账号。
  • 不是万能浏览器自动化；登录后操作网页、表单、多账号隔离仍属于 BrowserAct / OpenCLI 一类。
  • 不是替代上游工具：实际读内容仍直接调用上游 CLI/MCP。
一句话：Agent Reach 是 AI Agent 的互联网入口基础设施；它把“能看整个互联网”的工程杂活变成一次安装 + doctor 检测 + 可替换后端。

SUPPORTED PLATFORMS

最新 README 把平台明确拆成“装好即用”和“配置后解锁”。这比旧版“都能用”的说法更准确：免费渠道可以立刻跑，登录态渠道需要 Cookie / 浏览器会话。

04
INSTALL / UPDATE

给人看的入口

帮我安装 Agent Reach：https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md

帮我更新 Agent Reach：https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/update.md

安全模式：安装时使用 --safe 参数

给 Agent 的真实边界

  • 不要 sudo，除非用户明确授权。
  • 不要修改 `~/.agent-reach/` 之外的系统文件。
  • 不要在用户项目工作区 clone repo / 创建临时文件。
  • 上游工具仓库放 `~/.agent-reach/tools/`，临时文件放 `/tmp/`。
  • 安装后基础渠道：Web、YouTube、GitHub、RSS、Exa Search、V2EX、Bilibili basic。
05
CONFIGURATION / SECURITY

Cookie 统一配置方式

需要登录的平台（Twitter、小红书、雪球等）优先用 Cookie-Editor：浏览器登录 → Export → Header String → 发给 Agent。也可以尝试 `agent-reach configure --from-browser chrome` 自动提取 Twitter / 小红书 / 雪球 Cookie。

agent-reach configure twitter-cookies "PASTED_STRING"
agent-reach configure proxy http://user:pass@ip:port
agent-reach configure --from-browser chrome

安全底线

  • Cookie / Token 存在本机 `~/.agent-reach/config.yaml`，权限 600。
  • Cookie 等同完整登录权限，建议用专用小号，降低封号和泄露影响。
  • `--safe` 不自动装系统包；`--dry-run` 只预览。
  • 卸载可清理 `~/.agent-reach/`、skill 文件、mcporter MCP 配置。
06
OPERATIONAL PLAYBOOK

适合谁

  • 想让 Agent 自己搜网页、读视频、查仓库、看社媒。
  • 需要多平台统一接入，而不是每次重配工具。
  • 希望 doctor 能说明哪个渠道坏了、该怎么修。

不适合谁

  • 只想抓单一平台，不需要能力层。
  • 完全不能接受 Cookie / 登录 / 代理。
  • 希望一个黑盒替代所有上游工具。

更新策略

  • `agent-reach check-update` 先看版本。
  • 只升级已安装的上游工具，不擅自安装新工具。
  • 旧工具不要自动卸载，退役后端仍可作为 fallback。
07
FINAL TAKEAWAY
最终判断：Agent Reach 是“把互联网入口标准化给 Agent 用”的脚手架。它的长期价值在于维护一张持续换代的平台后端路线图：哪个平台还能零配置、哪个必须登录态、哪个后端已经退役、哪个后端是当前首选，都由 install / doctor / update 流程显式化。
