01
一句话判断

Agent Reach 把“让 Agent 上网找资料”这件事，从一堆零散脚本和登录配置，收敛成一次安装、一次配置、一个 doctor 检测。

它最值钱的地方

  • 让 AI Agent 从“只能写”升级到“能自己上网找、读、搜、总结”。
  • 把多平台接入变成一次安装，而不是每次任务都重新找工具、配代理、调 Cookie。
  • 底层不是再造一个爬虫平台，而是把现成的开源工具接成一个可复用的脚手架。

结论

  • 适合把 Agent 从“本地写作”扩展到“联网检索 / 读评论 / 抓视频 / 读仓库”。
  • 对外层用户来说，最重要的不是工具名，而是你只需要告诉 Agent “帮我配 XXX”。
  • 它的定位更像能力脚手架，不是一个想吞掉所有上游工具的封装框架。
关键一句：Agent Reach 的价值不是“自己做搜索”，而是把现成开源工具的选型、安装、认证、检测和注册，统一成一条可复用的上网能力链路。

快速上手：一条命令把 Agent 拉到能用状态

官方体验很明确：不用让人手动研究半天文档，而是直接让 Agent 自己完成安装与更新。

```bash
# 让 AI Agent 自己完成安装
帮我安装 Agent Reach：https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md

# 更新
帮我更新 Agent Reach：https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/update.md

# 安全模式（不自动装系统包）
帮我安装 Agent Reach（安全模式）：https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md
安装时使用 --safe 参数
```

安装后会发生什么

  • 安装 CLI 工具。
  • 自动检测并安装所需依赖，如 Node.js、gh CLI、mcporter、twitter-cli、rdt-cli 等。
  • 通过 MCP 接入 Exa 做全网语义搜索。
  • 根据是本地电脑还是服务器给出不同的配置建议。
  • 把使用指南注册进 Agent 的 skills 目录，后续可自动选工具。

装完后的验收点

  • 跑 agent-reach doctor 能看到每个渠道的状态。
  • Agent 能理解“帮我搜推特 / 看视频 / 查 Reddit / 读仓库”这类指令。
  • 需要认证的平台可继续按提示补 Cookie 或登录。

06
安全与边界：能用不等于该乱用

安全设计

  • Cookie / Token 只存本机 ~/.agent-reach/config.yaml，权限 600。
  • --safe 不自动改系统，只列出需要什么。
  • --dry-run 只预览，不做改动。
  • 上游组件是开源的，依赖链可审查。

边界 / 风险

  • 需要 Cookie 的平台仍然有封号与权限风险，建议用专用小号。
  • 服务器场景下，B站等平台可能需要代理。
  • Agent Reach 负责安装、注册、检测，不替代上游工具本身。
  • 它更像“能力分发层”，不是统一中间件。
安装 / 卸载入口
# 卸载
agent-reach uninstall

# 预览卸载，不真正删除
agent-reach uninstall --dry-run

# 只删 skill 文件，保留配置
agent-reach uninstall --keep-config

# 卸载 Python 包
pip uninstall agent-reach
07
适合谁 / 不适合谁 / FAQ 速览

适合

  • 要把 AI Agent 变成“会自己查资料”的工作流。
  • 需要在多平台之间做统一接入与统一体验的人。
  • 想减少每次都重配搜索、Cookie、代理、字幕工具的重复劳动。

不适合

  • 只想要单一平台抓取脚本，不需要统一能力层的人。
  • 完全不能接受 Cookie / 登录 / 代理配置的人。
  • 希望一套封装替代所有上游工具的人。
最终判断：Agent Reach 不是“一个更强的爬虫”，而是“让 Agent 能用现成工具上网”的能力分发层；它最适合做 AI Agent 的互联网入口基础设施。
