01核心哲学：AI 不是插件，是团队成员

传统项目管理工具怎么对待 AI？把它当成一个聊天机器人——在旁边开个对话窗口，让它回答问题、生成摘要。Paca 怎么对待 AI？给它一个座位，让它参与冲刺规划、从看板上认领任务、和人类一起更新任务状态、共同编写 BDD 规格。

冲刺规划

AI Agent 被分配到冲刺后，和人类一起出现在 Scrumban 看板上，实时更新状态。

BDD 协作

AI 帮助 Product Owner 和 BA 编写 Gherkin 场景规格，与人类协作者共同维护。

系统设计

AI 参与系统设计文档编写，让架构信息对整个团队实时可见。

任务认领

AI 从 backlog 中认领任务，实时更新任务状态，和人类成员在同一看板上协作。

感知与响应

AI 主动感知复杂度的涌现，像人类一样做出响应——而不是被动等待指令。

统一看板

人类和 AI 共享同一个实时 Scrumban 看板——没有单独的"AI 工作区"。

02技术架构
apps/webReact + TanStack Start + shadcn/ui（用户界面）
apps/mcp@paca-ai/paca-mcp（MCP 协议服务器）
services/apiGo + Gin（核心业务逻辑与 REST API）
services/realtimeNode.js + Socket.IO（实时事件广播，延迟~12ms）
services/ai-agentPython + FastAPI + OpenHands SDK（AI Agent 编排）
持久化

PostgreSQL 负责持久存储，Valkey（Redis fork）提供缓存与异步事件流。

E2E 测试

Playwright 提供完整的端到端测试套件，保障发布质量。

04/paca skills：自然语言命令管理 workspace
命令功能
/paca <task>通用任务、文档和冲刺操作，直接用自然语言
/paca-epic <requirement>将需求拆解为 Epic + 子 Story + 规格文档
/paca-clarify <ambiguity>识别需求模糊点，提出问题并更新 Paca 规格
/paca-breakdown <task>将任务拆解为独立、可估算的子任务
/paca-sprint根据 backlog 和团队容量规划冲刺
/paca-estimate <task(s)>估算故事点并回写任务
/paca-prioritize对整个 backlog 打分并设置优先级
/paca-do <task>执行任务，更新状态，保持文档同步
/paca-test <task>推导测试用例，运行测试，记录结果为评论
/paca-doc <request>在 Paca Docs 中编写或更新文档
/paca-setup交互式 MCP 连接向导

安装方式：从 Paca 实例的 GET /api/v1/skills API 拉取并安装到 Claude Code（~/.claude/commands/）、Gemini CLI（~/.gemini/commands/）、Cursor（.cursor/commands/）以及任何支持 AGENTS.md 协议的工具。

07WASM 插件架构
后端 WASM

用 Go、Rust 或 C 编写插件，编译为 WebAssembly，在严格权限模型下执行。

前端扩展

支持前端 UI 扩展，可在不修改核心代码的情况下添加自定义面板。

插件贡献 MCP 工具

已安装的插件可在运行时注册额外的 MCP 工具，自动出现在所有 MCP 客户端。

08GitHub 集成
仓库链接

将 GitHub 仓库绑定到项目，PR 管理、分支创建、仓库列表全部在 Paca 内完成。

PR × 任务关联

每个任务可以链接多个 PR，列出关联的 Pull Request，支持审查状态追踪。

分支管理

从任务直接创建分支（Paca 内置 branch 创建逻辑），不需要跳到 GitHub 操作。

Token 安全

GitHub Token 存储在项目级别，MCP 工具按 Agent 的项目权限动态过滤。

09BlockNote 文档

Paca 内置的文档系统基于 BlockNote（Notion-like 块编辑器），支持实时协作。BlockNote JSON 与 Markdown 自动双向转换——文档可以在 Paca 内直接编辑，也可以导出为 Markdown 供其他工具使用。
