Agent Orchestrator · 多智能体编程工作区

别再用终端追 Agent：把任务、分支、PR 和 CI 放进一块看板

Agent Orchestrator（AO）不是另一个编程模型，而是管理多个 coding agent 的本地工作区：每个任务拥有自己的 agent、branch/worktree 与反馈回路，总控 orchestrator 负责拆解、派发和跟进。

先判断：你需要的是“多 Agent 控制面”吗？

单个 Agent 的任务，直接开一个 worker；跨模块、跨阶段、需要持续跟进的目标，再交给项目级 orchestrator。

适合 AO

  • 同时跑多个独立编码任务
  • 需要避免 branch/worktree 互相污染
  • 要把 PR、CI、review 反馈回传给原 Agent
  • 需要查看谁在工作、谁阻塞、谁可合并

先别上 AO

  • 只有一个简单、一次性的脚本修改
  • 团队尚未定义 PR / CI / review 责任
  • 你期待它替代 coding agent 本身
  • 你只需要一个轻量终端别名

四层模型：任务为什么不会混在一起

One task · one worker · one feedback loop
Worker一个任务 + 一个 coding agent + 一个隔离工作区
Project Orchestrator理解项目上下文，拆解目标，创建/重定向 worker
KanbanWorking / Needs you / In review / Ready to merge
Feedback loop变更 → PR → CI → review → 返回原 worker
Git-backed worker 默认获得独立 branch 和 worktree；Scratch worker 使用 AO 管理的 branchless 目录。这里的隔离是 AO 的实现机制，不等于你可以忽略仓库权限、密钥和破坏性命令审查。

第一次使用：从一个明确任务开始

5-step operating loop
01 · Add repository把要管理的 Git 仓库加入 AO
02 · New task写清 outcome，选择 agent / model / interface，附相关文件
03 · Run isolated让 worker 在独立 branch/worktree 中实现
04 · Inspect state查看对话、终端、改动文件、预览、PR、CI、review
05 · Close loop把失败 CI 或 requested changes 回传给同一 worker，直到可合并

看板不是 KPI：它回答的是“现在该介入哪里”

Working

worker 正在实现，或已经准备好接收下一条指令。

Needs you

阻塞、缺输入、CI 失败、review requested changes 或信号丢失。

In review

PR 等待 checks 或人工 review，不要误判为已完成。

Ready to merge

已批准或可合并；仍保留 session 以便追溯。

边界与验收

官方事实：Apache License 2.0；支持 macOS、Windows、Linux 桌面下载；README 当前列出 27 个 coding agents。
来源帖使用“工头”作比喻。AO 的真实价值不是自动保证代码正确，而是把任务上下文、隔离执行、PR、CI、review 和人工介入点集中起来。引入后仍需检查权限、依赖安装、密钥暴露、worktree 清理和合并策略。
