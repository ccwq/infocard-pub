01 三大核心设计原则 — 与当前主流框架的背离

⚡ 极简单发推断 — 摒弃复杂 Agent 循环

核心主张：依靠强大基座模型进行一次性推理，摒弃复杂的智能体循环与多智能体协作。

底层逻辑：当基座模型能力跨越自验证与推理阈值时，果断废弃作为过渡补丁的外挂规划器。

工程意义：减少循环调用带来的 Token 浪费与不确定性积累，让模型直接给出最终答案。

✗ 当前主流 Agent 框架

  • ReAct / Plan-Execute 循环
  • 多智能体协作与角色分工
  • 外挂规划器（Planner）主导
  • 长程状态记忆与持久化
  • 工具调用自动化执行

✓ Fable 5 哲学

  • 极简单发推断
  • 无多智能体协作层
  • 基座模型自主规划
  • 无状态设计（零持久化）
  • 用户授权阻断外部操作

🛡️ 绝对安全与环境解耦 — 零信任架构

📦 无状态与零持久化 — 消除状态爆炸

架构设计：采用无副作用的只读挂载点，消除跨会话持久记忆带来的状态爆炸和不稳定。

商业考量：每次交互需重传历史上下文 — 确保逻辑连贯，同时增加 Token 消耗（有意为之）。

前端约束：严格禁用本地存储（localStorage），不留任何客户端持久化痕迹。

02 实践指导与最佳实践 — 从泄露中提炼工程方法
① 终止黑盒调用 — 用户意图授权前置阻断
在工程实现中，必须将用户意图授权作为外部交互的前置阻断点。任何工具调用都要经过授权审批链路，而非 SDK 自动执行。
② 拥抱无状态设计 — 最小权限 + 最干净运行时
为模型提供最小权限和最干净的运行时环境，减少外部依赖。无状态 = 无记忆泄漏 = 可预测性。
③ 框架做减法 — 跨越阈值即废弃外挂规划器
当基座模型能力已覆盖自验证与推理时，果断移除作为过渡补丁的外挂规划器。不要用复杂框架弥补模型能力的不足。
④ 上下文约束前置化 — 外部读取替代硬编码
通过强制读取环境变量文件（而非硬编码在 Prompt 中）注入上下文约束，保持 Prompt 本身的纯净与可审计性。
⑤ 白名单沙盒 — 主动限制而非被动防御
不是在运行时防御危险行为，而是从架构上让危险行为在沙盒外无法发生。
🔑 核心洞察：Tool Call ≠ Function Call

整个行业用 "function calling" 描述工具调用，让开发者下意识把它当函数调用处理。但工具背后是数据库、文件系统、邮件服务、生产 API — 每一次工具调用本质上是资源授权请求，必须进入授权 → 审批 → 审计链路，而不是被 SDK 自动执行。

04 对当前 Agent 框架的反思 — 1597 行的工程批判

🔄 ReAct/Loop 的过度设计

Fable 5 选择极简单发推断，意味着当模型足够强时，ReAct 循环和 Plan-Execute 框架只是增加 Token 消耗和不确定性的人为复杂性。

🧠 记忆系统的幻觉

跨会话持久化记忆带来状态爆炸和不稳定性。Fable 5 的零持久化选择，用 Token 换取可预测性和可审计性。

⚡ 工具调用的权限盲区

当前 Agent 框架将工具调用视为"函数执行"，而忽视了背后是数据库、API、Shell 等生产资源的授权请求。授权链路不可跳过。

🏗️ 外挂规划器的终点

外挂规划器（Planner）是模型能力不足时的过渡方案。一旦模型跨越自验证阈值，这些中间层应当被果断移除。

💡 核心反思

当前 Agent 框架设计者混淆了两件事：让模型"能做什么"（工具丰富度）和让模型"不该做什么"（安全边界）。Fable 5 的 1597 行大部分在说后者 — 而这恰恰是主流框架忽视最多的部分。

05 适用场景 — 哪些情况下值得借鉴 Fable 5 哲学

🛡️ 高风险 Agent 系统

涉及数据库写入、文件操作、外部 API 调用、邮件发送等具有不可逆副作用的操作。

🏢 企业级 Agent 部署

需要合规审计、操作溯源、权限分级的生产环境，必须建立授权审批链路。

🤖 高价值模型落地

当使用 GPT-4.5、Claude 4 Opus、Fable 5 等顶级模型时，优先考虑简化框架而非堆叠复杂度。

🔒 安全敏感场景

金融、医疗、法律、政府等高监管行业，严格白名单沙盒和用户授权阻断是合规必要条件。

📌 什么时候不适合照搬

对于低风险、长程任务、多步骤探索类场景，保留 ReAct 循环和记忆系统仍有价值。Fable 5 哲学是安全优先的工程选择，不是银弹。
