AI Content KB
审查优先，让 AI 输出永远可溯源

AI 原生知识库参考架构。AI 生成内容必须过 `.kb/staging/` + 人工审核才能进入知识库。原始素材、生成废料、最终成品严格三区隔离，从根本上杜绝 AI 幻觉污染知识库。

审查优先 三区隔离 来源可溯 Codex 集成 Obsidian

核心哲学：审查优先（Review-first）

人工审核

大多数知识库把原创想法、外部证据、已发布内容和 AI 生成文本混在一起。本模板为每种内容定义清晰角色，给 AI Agent 工作规则——在不静默污染原文或发布流程的前提下工作。

raw/ → sources/ → .kb/staging/ → wiki/ + products/
Originals

保持可信

原始笔记、判断、语音转录、原创研究、活跃草稿存于 raw/，AI 无法直接覆盖。

AI Output

保持可审

所有 AI 生成内容必须经过 `.kb/staging/` → 人工审核，不会在未审查状态下成为知识库事实。

三区隔离架构

raw/ — 原创输入

📝
raw/ — 原创输入
原创笔记、判断、语音转录、Owned 研究、活跃草稿。知识库的可信真相来源。

sources/ — 外部证据

🔗
sources/ — 外部证据
外部剪报、论文、书籍、报告、媒体转录。外部声明的可信真相来源。

products/ — 成品输出

✅
products/ — 成品输出
已审核发布的文章、课程、脚本、交付成果。已发布表达的可信真相来源。
wiki/ — 人类界面

非真相来源

概念、实体、地图、高价值笔记索引。必须引用原始文件，不能独立作为证据。

.kb/staging/

待审候选区

AI 草稿、wiki 候选、关系候选。未经人工审核不得晋升到 wiki/ 或 products/。

结构化关系：typed YAML sidecar 图

`.kb/links/` 存储带类型、带证据、带 hash 的 YAML sidecar 关系。这是机器可读的图数据层，AI 生成的内容可以一秒查出源头，彻底杜绝数据污染。

YAML Sidecar

类型化关系

每条边有类型（supports/contradicts/cites/extends 等）、证据来源路径、文件 hash 校验。

来源可溯

Hash 校验

原始文件变更时 hash 变化，关系图的证据引用可验证是否过期。

工具链：Codex + Obsidian

Codex 集成

AGENTS.md 驱动的 AI 工作流

根目录 AGENTS.md 定义 AI Agent 的摄取、查询、维护规则。AI 启动时先读 AGENTS.md，然后遵循项目规则工作。

Obsidian 兼容

纯 Markdown 无锁定

一切存为普通 Markdown、YAML、JSON 和文件夹。无需专用应用，开放为 Obsidian vault 即可用图形视图。

灵感来源：Karpathy LLM Wiki 模式

本项目受 Andrej Karpathy 的 LLM Wiki 模式启发：不可变原始来源 + LLM 维护的持久 Markdown wiki + 定义 agent 工作方式的仓库 schema（如 AGENTS.md）。本项目在此基础上增加了明确的来源角色、第一方成品层、审查优先暂存、类型化机器可读关系和内容创建工作流。

迁移与扩展

迁移旧有笔记库

安全迁移流程

备份 → 清单 → 映射审查 → 试点 → 验证 → 批量审核 → 割接。Agent 只读模式，不移动/复制/删除/修改原始文件。

扩展路径

渐进式扩展

先用文件验证内容角色和审查工作流，再在真实查询有需求时添加 manifest、搜索、嵌入或图数据库。

使用边界：73 Stars 为 GitHub API 实时检索值（新发布项目）。本仓库是参考架构和工作模板，非托管知识管理应用。Obsidian 和 Codex 均为可选接口，可靠的系统核心是仓库本身。AI 生成内容是否可信，不由 AI 决定，由人工审核决定。
