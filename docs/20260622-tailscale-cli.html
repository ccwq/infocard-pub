01 Getting started · 路径 · 通用 flag

tailscale 命令在哪里、怎么用

不同平台 tailscale 的位置不同；Linux 上一般在 $PATH 直接可用，macOS 需要把 GUI 内置 CLI 暴露出来，Windows 默认安装在 C:\Program Files\Tailscale。iOS / Android 没有 CLI。

linux tailscale <cmd> 二进制随 deb / rpm / brew 包安装，多在 /usr/bin/tailscale，可直接执行。
macos /Applications/Tailscale.app/Contents/MacOS/Tailscale App Store 版需在 PATH 中加入 alias，或者用 tailscale configure mac-vpn 后再通过 CLI 操作。
windows C:\Program Files\Tailscale\tailscale.exe 命令行用法与 Linux 一致；PowerShell 推荐设置环境变量后直接 tailscale。

Tab 补全

tailscale completion <shell> [--flags] [--descs] 支持 bash / zsh / fish / powershell。一次性加载与持久化两种方式。

# 当前会话临时加载（bash）
source <(tailscale completion bash)

# Linux 永久加载
tailscale completion bash > /etc/bash_completion.d/tailscale

# macOS Homebrew 永久加载
tailscale completion bash > $(brew --prefix)/etc/bash_completion.d/tailscale

# zsh / fish / powershell 同理，把 bash 换成对应 shell
tailscale completion zsh
tailscale completion fish
tailscale completion powershell

所有命令通用的 flag

Flag说明
--socket=<path>tailscaled 套接字路径。一般不需要改，除非你跑了多个 daemon 或自定义路径。
--flags=<true|false>仅 completion 用：是否在补全中提示 flag。默认 true。
--descs=<true|false>仅 completion 用：补全是否包含子命令描述。默认 true。

03tailscale up · 连接 + 鉴权 + 子网 / Exit Node

tailscale up — 主连接命令

无 flag 直接 tailscale up 即可建立连接。up 不仅连入，还固化偏好（subnet、exit node、shields、SSH、reauth…）。需要局部修改时改用 tailscale set。

tailscale up [flags]
Flag说明
--accept-routes接受其它节点 advertise 的子网路由。默认是否接受取决于操作系统：Windows / iOS / Android / macOS App Store / macOS Standalone 默认接受，其它平台默认不接受。
--advertise-exit-node把本机宣告为出口节点，承担 tailnet 的出向互联网流量。默认 false。
--advertise-routes=<cidr,...>把物理子网路由暴露给整个 tailnet，例如 10.0.0.0/8,192.168.0.0/24。
--exit-node=<ip|name>指定要使用的出口节点。传空值 --exit-node= 取消。
--exit-node-allow-lan-access使用 exit node 时仍允许访问本机 LAN。默认禁止。
--force-reauth强制重新鉴权。
--snat-subnet-routes linux禁用源 NAT，让远端看到原始 LAN IP。仅 Linux。
--stateful-filtering子网路由器 / 出口节点启用有状态过滤。默认关闭。
--shields-up阻止其它设备主动连入，适合只发起出向连接的个人设备。
--ssh运行 Tailscale SSH 服务端，按 tailnet 策略放行访问。默认 false。
注意：完整 flag 见官方 tailscale up 主题。up 是"声明式"的，未显式提供的偏好会被重置；只想动一两个开关请用 set。
04down / login / logout / switch · 连接生命周期

tailscale down

断开 tailnet，但保留登录信息。再次 tailscale up 无需重新鉴权。

Flag说明
--accept-risk=<risk>跳过风险确认。可选 lose-ssh、all 或空字符串。
--reason="<text>"当 AlwaysOn.Enabled + AlwaysOn.OverrideWithReason 策略启用时，必须给出断开原因。例：tailscale down --reason="DNS issues"。

tailscale login — 登录并加入 tailnet

登录的 flag 集合最大，覆盖 DNS、路由、exit node、auth key、自动化 OAuth、hostname、运维者、netfilter 等。常用项摘要：

Flag说明
--accept-dns接受 admin console 的 DNS 配置（默认接受）。
--accept-routes同 up。
--advertise-connector声明本机为 App Connector，承担域名导向的互联网流量。
--advertise-exit-node / --advertise-routes / --advertise-tags=<tags>出口节点 / 子网 / 标签声明，--advertise-tags 需要在 ACL 的 TagOwners 中授权。
--auth-key=<key>用预生成的 auth key 自动认证。注意 auth key 的处理安全。
--client-id / --client-secret / --id-token / --audience用 OAuth / workload identity federation 自动获取 auth key。--client-secret 与 --id-token 支持 file:<path> 形式。
--exit-node / --exit-node-allow-lan-access同 up。
--hostname=<name>覆盖 OS 主机名（同时改变 MagicDNS 名称）。
--login-server=<url>使用自托管控制平面（如 Headscale）替代官方的 https://controlplane.tailscale.com。
--netfilter-mode=<on|nodivert|off>设置 Linux netfilter 行为。
--nickname=<name>给当前账号一个昵称（配合 switch 使用）。
--operator=<user>非 root 用户运维 tailscaled。
--qr / --qr-format=<small|large>把登录 URL 输出为二维码。
--report-posture允许上报设备 posture。默认 false。
--stateful-filtering / --shields-up / --snat-subnet-routes / --ssh同 up 中的同名 flag。
--timeout=<duration>等待 Tailscale 服务初始化的最长时间。0s 表示无限等。
--unattended windows用户登出后 Tailscale 仍保持运行。仅 Windows。

tailscale logout

注销并使当前登录失效；下次 up 需要重新认证。ephemeral 节点 logout 后会立即从 tailnet 移除。

Flag说明
--reason若系统策略要求，必须提供登出原因。

tailscale switch — Fast User Switching

# 用邮箱切换
tailscale switch alice@example.com

# 用昵称切换
tailscale switch work

# 列出所有账号
tailscale switch --list --json
Flag / 子命令说明
--list列出可切换的账号。
--json以 JSON 输出账号列表。
remove <id> alpha从本机移除一个 Tailscale 账号（账号本身不会被删除，仅本机不可切换）。
05tailscale set · 局部更新偏好

tailscale set — 只改你显式给出的项

和 up 的"全量声明"不同，set 只更新显式给出的偏好，没传的不变。Fast User Switching 下，set 只影响当前活动 tailnet。

Flag说明
--accept-dns是否接受 admin console DNS。
--accept-risk=<risk>跳过风险确认（lose-ssh / all / 空）。
--accept-routes / --accept-routes=false是否接受其它节点 advertise 的子网路由。
--advertise-connector声明为 App Connector。
--advertise-exit-node / --advertise-exit-node=false开关 exit node 声明。
--advertise-routes=<cidr,...>逗号分隔的 CIDR 列表，空字符串表示取消所有声明。
--auto-update / --auto-update=false开关客户端自动更新。
--exit-node=<ip|name>支持 auto:any：跟踪推荐 exit node 并在条件变化时自动切换。--exit-node= 取消。
--exit-node-allow-lan-access同 up。
--hostname=<name>覆盖主机名（影响 MagicDNS）。
--netfilter-mode=<on|nodivert|off>Linux netfilter 模式。
--nickname=<name>账号昵称。
--operator=<user>非 root 用户运维 tailscaled。
--relay-server-port=<port>Peer Relay UDP 端口。0 = 随机；空字符串 = 关闭 relay 功能。
--relay-server-static-endpoints使用静态 endpoint 做 Peer Relay。
--report-posture允许上报设备 posture。
--shields-up / --shields-up=false开关 shields。
--snat-subnet-routes是否对 --advertise-routes 的流量做源 NAT。
--ssh / --ssh=false开关 Tailscale SSH 服务端。
--stateful-filtering子网路由器 / exit node 启用有状态过滤。
--update-check是否提示新版本。
--webclient / --webclient=false持久暴露 Web 接口到 tailnet 的 :5252。
06status / ip / whois / version · 状态查询四件套

tailscale status

默认输出可读表格，5 列：Tailscale IP、机器名、所有者邮箱、设备 OS、连接状态。状态字段含 active（直连 / relay / peer-relay）、idle、-，并显示 tx / rx 字节。

tailscale status

# 机器可读 JSON
tailscale status --json

# 统计 peer 走哪些 DERP 中继
tailscale status --json | jq -r '.Peer[].Relay | select(.!="")' | sort | uniq -c | sort -nr
Flag说明
--active仅显示有活动会话的 peer（不适用 web 模式）。
--browserweb 模式下自动打开浏览器，默认 true。
--header表格输出加列头，默认 false。
--json机器可读 JSON。格式可能调整。
--listen=<addr>web 模式监听地址，默认 127.0.0.1:8384。
--peers / --self是否展示 peer / 本机，默认 true。
--web启动 HTML 状态服务器。

tailscale ip [hostname]

默认同时返回 IPv4 / IPv6。给定 hostname 时查别的设备。

Flag说明
-4只返回 IPv4。
-6只返回 IPv6。
-1只返回一个地址，优先 IPv4。
--assert=<ip>断言节点的某个 IP 等于该值，常配合 tailscale wait 使用。

tailscale whois ip[:port]

给一个 Tailscale IP，返回 Machine（Name/ID/Addresses/AllowedIPs/Tags）、User（Name/ID）和 Capabilities。

tailscale whois 100.121.112.23
tailscale whois --json 100.121.112.23:443
Flag说明
--jsonJSON 输出。必须放在 ip 前面。
--proto=<tcp|udp>WhoIs 协议，留空 = 同时查。

tailscale version

Flag说明
--daemon也打印本机 daemon 版本。默认 false。
--json机器可读 JSON。
--upstream同时打印来自 pkgs.tailscale.com 的最新上游版本。默认 false。
--track=<stable|unstable|release-candidate>指定要检查的 track，留空 = 当前 track。
07netcheck / ping / nc / bugreport / metrics · 诊断与监控

tailscale netcheck

输出 UDP、IPv4 / IPv6、NAT 行为、HairPinning、PortMapping（UPnP / NAT-PMP / PCP）、最近 DERP 与各 DERP 延迟。Admin console 的 Machines 页面也能看到等价信息。

Flag说明
--every=<duration>非零时按该频率做增量报告。
--format=<json|json-line>输出格式，留空 = 人类可读。
--verbose详细日志。
--bind-address发送 / 接收探测包用的本地 IP。
--bind-port探测包使用的 UDP 端口。

tailscale ping <hostname-or-ip>

沿 Tailscale 链路做 ping，比系统 ping 多出连接类型、是否直连等细节。支持 4 种 ping 模式。

Flag说明
--c=<n>最多 ping 多少次。默认 10。
--icmp / --icmp=false走 WireGuard 内 ICMP，不经本机 OS 网络栈。默认 false。
--peerapi尝试访问 peer 的 PeerAPI HTTP 服务。默认 false。
--size=<n>ping 包大小。0 = 最小。
--tsmpTSMP 级别 ping，不经任一方 OS 协议栈。
--timeout=<duration>超时。默认 5s。
--until-direct建立直连后立即停止。默认 true。
--verbose详细输出。

tailscale nc <host> <port>

把目标的 host:port 接到本进程的 stdin / stdout，类似 OpenBSD netcat。

tailscale bugreport

v1.8 起可用。生成一个随机 BUG-ID 写入诊断日志，提交给官方支持团队定位问题。不包含个人信息，仅 BUG-ID 自身被使用。

Flag说明
--diagnose额外向日志写更多系统信息。默认 false。
--record暂停后再生成第二个 BUG-ID，把"问题复现前 / 后"两段都标记出来。

tailscale metrics

print在当前终端打印客户端指标。
write将指标写入文本文件，便于被监控系统采集。
08serve / funnel / cert · 暴露本机服务

tailscale serve — 仅 tailnet 内

把本地服务、静态文件夹或反向代理目标暴露到 tailnet 内部。要把同样的服务放到公网，改用 funnel。

tailscale serve <target>
tailscale serve <subcommand> [flags] <args>
status查看当前 serve 配置与状态。
reset清空 serve 配置。

tailscale funnel — 暴露到公网

允许 tailnet 外的互联网访问你 funnel 出的端口 / 路径。仅限 tailnet 内部访问时切回 serve。

status查看 funnel 状态。
reset清空 funnel 配置。

tailscale cert — Let's Encrypt 证书

为 tailnet 内的 HTTPS 服务签发证书。仅做文件输出：搬运到安装位置的证书需要你自己负责续签（证书 90 天有效）。如果通过 Caddy 等集成方式部署，则会自动续签。

tailscale cert hostname.tails-scales.ts.net

# 写入文件
tailscale cert --cert-file=cert.pem --key-file=key.pem hostname.tails-scales.ts.net
Flag说明
--cert-file=<path>证书输出路径。
--key-file=<path>私钥输出路径。
--min-validity=<duration>要求返回证书至少剩余的有效期。duration 由 Go 的 time.ParseDuration 解析（例 120h = 5 天）。超过 Let's Encrypt 上限会被截断。
--serve-demo不写文件，直接在 :443 演示该证书。
提示：需要把整目录文件直接对外暴露 / 反代某个 HTTP 服务，请用 tailscale serve，不要把 cert 当成 Web 服务器。
09ssh · Tailscale SSH

tailscale ssh <args>

建立一次基于 Tailscale 的 SSH 会话；在 userspace-networking 模式（无法直连）时它会通过本地 tailscaled 设置 ProxyCommand。自动校验目标 SSH host key（来自 coordination server 的广播）。

host仅给目标主机；会提示用户名。
user@host显式给定用户与目标主机。

host 可以是 MagicDNS 名（即使关闭了 --accept-dns），也可以是 Tailscale IP。

不可用平台：macOS 的 sandboxed 构建不支持 tailscale ssh，使用普通 ssh 客户端即可。

tailscale file — Taildrop

cp <files...> <target>:把文件复制给目标 host 的 Taildrop。

Flag（cp）说明

11lock / syspolicy / appc-routes · 信任 · 策略 · App Connector

tailscale lock — Tailnet Lock

管理 tailnet 的信任锚与节点签名。无子命令时等同 tailscale lock status。

init初始化 Tailnet Lock。
status查看 lock 状态。
add添加一个或多个受信签名公钥。
remove移除信任公钥。
sign签发某个 node key，并把签名提交到 coordination server。
注意：这是 zero-trust 关键组件，所有改动都会影响 tailnet 的认证矩阵。完整子命令 / flag 请参考官方 tailscale lock 主题。

tailscale syspolicy

list显示系统策略 / 重载策略 / 探索策略错误。
reload强制客户端重新加载并应用系统策略。

通用 flag：--json 以 JSON 返回。

tailscale appc-routes

查看 App Connector 配置的域名及已学到的路由数量。

Flag说明
--all同时打印已学到的域名 / 路由 + 策略中显式配置的额外路由。
--map打印学到的域名 -> 路由映射表。

tailscale wait · v1.96+

阻塞等到 Tailscale 资源（当前仅 Tailscale 接口与其 IP）可绑定，可设超时或无限等待。返回 0 表示成功；非 0 表示失败或超时。userspace-networking 模式只等待 tailscaled 进入 Running。

Flag说明
--timeout=<duration>超时秒数。0 = 无限等待。
 
# 等到接口就绪，再断言 IPv4 是某个具体地址
tailscale wait && tailscale ip --assert=100.121.112.23

# 服务启动前等 Tailscale 就绪（systemd 也可用 tailscale-online.target）

tailscale update

原地升降级 Tailscale 客户端版本。可用平台：Windows / Ubuntu / Debian（v1.36+）、macOS App Store / Synology（v1.48+）、QNAP / macOS Standalone（v1.54+）。

Flag说明
--dry-run仅显示将执行什么，不实际更新、不提示。
--track=<stable|release-candidate|unstable>检查指定 track。不传 = 当前 track。
--version=<v>显式更新 / 回退到指定版本。不能与 --track 同用。macOS 不支持。
--yes无交互直接更新。默认 false。
 
tailscale update                      # 同 track 最新版
tailscale update --yes                # 无交互
tailscale update --version=1.34.0     # 指定版本
tailscale update --track=unstable     # 切到 unstable
注意：降级到一个没有 tailscale update 的版本之后，将无法再用 CLI 回升，需要走系统包管理器手动升级。

tailscale licenses

输出客户端依赖的开源许可证信息。无 flag。

13边界与速查 · 常见陷阱

不会在 CLI 里出现的能力

no-cliiOS / Android官方明确：没有 CLI 支持，移动端通过 GUI 管理。
no-climacOS sandboxed build · tailscale sshApp Store sandbox 版本不支持 tailscale ssh，请用系统 ssh。
no-sudotailscale systray禁止以 sudo 运行，否则报错退出。
no-rollbacktailscale update如果升到没有 update 命令的版本，无法再用 CLI 回滚。

up / set / login 选哪一个

scenariotailscale up首次接入或想声明式重置所有偏好。未给出的偏好会回到默认。
scenariotailscale set已经连上、只想微调一个开关（如临时开 SSH）。其它偏好保留。
scenariotailscale login加新账号或通过 OAuth / auth key 在脚本里自动化注册节点。

诊断推荐顺序

# 1) 基本健康度
tailscale status
tailscale netcheck

# 2) 路径诊断
tailscale ping --c=3 --tsmp peer-hostname
tailscale ping --c=3 --icmp peer-hostname

# 3) 把信息打给官方支持
tailscale bugreport --diagnose
提示：把诊断阶段产出的 BUG-… 字符串和 status --json / netcheck --format=json 一并发给官方支持，效率最高。
