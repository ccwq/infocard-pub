理解核心概念

Inventory（主机清单）、Playbook（任务剧本）、Module（模块）、Role（角色）四个基础构件

ansible-doc -l # 列出所有模块

安装 Ansible

社区版免费安装，Python >= 3.9；企业版用 Red Hat AAP 提供额外管控能力

pip install ansible brew install ansible # macOS
3

编写 Inventory

声明目标主机、分组、变量。YAML 或 INI 格式，可对接 AWX / AAP 控制台管理

ansible-inventory -i hosts.yaml --list
4

部署 MCP 服务器

启用 Ansible MCP 服务器，让 AI 工具通过 MCP 协议发现资源、执行任务

ansible-mcp server start

AI 协作 + 人工审批

AI 规划 → Automation Orchestrator 审核 → Playbook 执行 → 结果回写

/approve --playbook=deploy.yml
CORE CONCEPTS
Ansible 四大构件
1

Inventory 主机清单

定义被管理的目标主机和分组，支持 INI / YAML / dynamic inventory（AWS、Azure、VMware 等云平台插件）。

2

Playbook 任务剧本

YAML 编写的声明式任务序列，描述"目标状态"而非"操作步骤"，天然幂等。

3

Module 模块

原子操作单元（apt、yum、file、template、shell 等 5000+ 内置模块），也可自定义。

4

Role 角色

可复用的 Playbook 结构化封装：tasks / handlers / vars / templates / files 按固定目录组织。

技术预览

Automation Orchestrator

AI 触发的所有操作必须通过预先人工审批的确定性 Playbook 执行。AI 负责规划和生成操作意图，人类负责批准实际变更，兼顾智能化与安全。

EDITION COMPARISON
社区版 vs 企业版 AAP

社区 Ansible（免费）

命令行工具集，支持 RHEL / Debian / Ubuntu / macOS / Windows / FreeBSD。模块 + Collections 生态免费使用。

RHAAP 上游组件

AAP 基于 Ansible Core + 十几个上游项目构建：AWX（控制平面）、Execution Environments、Automation Mesh、Hub（Collections 仓库）、Analytics 等。

AAP 企业特性

基于角色的访问控制（RBAC）、集中式清单管理、Job Templates、Workflows、审计日志、SSO/LDAP 集成、HA/DR。

选型建议

个人/小团队：社区版免费起步。有合规、RBAC、审计需求：选 AAP。有 AI 智能体集成需求：MCP 服务器 + AAP 组合。

MCP + AI AGENT WORKFLOW · MCP 连接 AI 智能体工作流

DISCOVER

PLAYBOOK EXAMPLE · 基础 Web 服务部署
# inventory.ini — 主机清单
[webservers]
web01.example.com
web02.example.com

[webservers:vars]
ansible_user=admin
http_port=8080

# deploy.yml — 部署 Playbook
---
- name: Deploy Nginx Web Server
  hosts: webservers
  become: yes
  vars:
    nginx_version: "1.24.0"

  tasks:
    - name: Install Nginx
      ansible.builtin.apt:
        name: nginx
        state: present
        update_cache: yes

    - name: Configure Nginx port
      ansible.builtin.template:
        src: nginx.conf.j2
        dest: /etc/nginx/nginx.conf
      notify: Restart Nginx

    - name: Start and enable Nginx
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: yes

  handlers:
    - name: Restart Nginx
      ansible.builtin.service:
        name: nginx
        state: restarted

# 运行命令
$ ansible-playbook -i inventory.ini deploy.yml --check  # 预演模式
$ ansible-playbook -i inventory.ini deploy.yml          # 正式执行

FAQ

常见问题解答

Q: Ansible MCP 服务器和 Automation Orchestrator 有什么区别？
MCP 服务器是 AI → Ansible 的连接层（GA），让 AI 发现清单、执行模块。Orchestrator 是管控层（技术预览），强制 AI 生成的操作必须经人工审批 Playbook 后才能执行。前者解决"AI 能否操作"的问题，后者解决"AI 操作是否安全"的问题。
Q: Ansible Lightspeed 支持中文吗？
Ansible Lightspeed 基于 IBM watsonx.ai，支持多语言输入，但 Playbook 语法输出遵循 Ansible 标准。AI 生成后需人工 review YAML 语法和幂等性。
Q: 企业用 Ansible 一定要买 Red Hat AAP 吗？
不一定。社区 Ansible 完整可用，Collections 生态免费。有以下需求再选 AAP：RBAC 多用户管控、Job Templates + Workflow 可视化、Execution Environment 隔离、HA/DR 部署、SSO 集成、审计合规。
Q: AI 生成的 Playbook 怎么保证安全？
三层机制：① MCP 服务器使用 Ansible 现有 RBAC 权限体系；② Orchestrator 要求 AI 操作经确定性 Playbook（无随机性、无外部依赖）；③ AAP 提供完整执行审计日志，支持变更回滚。
Q: Ansible 和 Terraform 选哪个？
Ansible：配置管理、应用部署、Orchestration，声明式但偏过程式，社区生态丰富。Terraform：基础设施即代码（IaC），状态驱动，幂等性强。两者可互补：Terraform 建基础设施，Ansible 做配置和应用管理。
Q: Windows 系统能用 Ansible 管理吗？
能。Ansible 的 ansible.windows 集合提供 WinRM/PowerShell Remoting 支持，可管理 Windows 主机（AD、SQL Server、IIS 等）。控制节点仍需 Linux/macOS，被管理节点支持 Windows Server 2012+。
