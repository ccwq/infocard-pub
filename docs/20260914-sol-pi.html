让 Pi 少重复工作，但先把四个效率开关逐个验明白

SoL-Pi 是 NVIDIA 开源的 Pi 独立扩展，不修改或内置 Pi 源码。它把四种机制接到 Pi 的公开扩展 API：编辑后融合验证、长文本结果句柄化、保留证据的日志压缩、在线上下文压缩。四项默认关闭；先开本地、无额外模型调用的前两项，再考虑会触发模型调用或自动续跑的机制。

核心判断：省 token 不是“删掉上下文”，而是让证据可回取、验证不重复、已完成步骤不占住活动窗口。

01

四个机制分别改哪里？先不要把“省钱”当成同一种功能

它们作用在工具调用、观察结果、委派日志和上下文窗口的不同位置。

Action Fusion / 工具融合

编辑或写入后，可在同一工具调用里顺手执行后续验证命令。减少“改文件 → 再发一轮验证”的重复往返。

适合：确定性的 lint、测试或检查命令。

ObservationPack / 观察句柄

大文本结果存成稳定句柄，后续按页精确回取，而不是每次把整段结果重新放进上下文。

适合：重复查看的大日志、长 API 响应、目录或报告。

Evidence-Preserving Reducer

长诊断日志可压成紧凑 receipt，但保留原文归档，并要求保留的引用与源文匹配。

注意：可能把符合条件的日志发送给配置的 reducer model。

Online Context Compact

把完成的计划步骤变成 Pi 原生 compaction 的候选点；成功压缩后，Pi 会在新 turn 继续活动任务。

注意：取消运行或退出 Pi 不会触发自动续跑。

共同规则：没有配置文件时四项都不启用；SoL-Pi 使用 Pi 的认证、Provider URL、主模型和 shell 行为，不接管 Pi 的运行选择。

安装：锁住 Pi 版本，再装扩展

04

首次验收：每个开关都要有“输入—证据—回读”

不要只看 Pi 能否启动；要确认省下的是重复传输，而不是验证内容。

Action Fusion

给一个小文件做可预测编辑，并指定一个无副作用检查。验收：一次调用后能看到编辑结果与验证结果；验证失败不能被隐藏。

ObservationPack

制造一份可重复读取的长结果。验收：首次得到句柄，按页读取能回到指定区间；原始归档仍在本地 session 目录。

Reducer

只用不敏感的测试日志。验收：receipt 的引用可与归档原文对照；模型调用路由、费用和失败回退已记录。

Context Compact

使用可取消的短任务。验收：压缩前后的活动任务连续；退出 Pi 或取消后不把“自动继续”当作仍会发生。

05

存储与安全：本地归档不等于绝对不外发

四个机制的证据边界不同，尤其要审查 Reducer 的远程模型路径。

机制状态/原文位置风险与控制
ObservationPack<session-directory>/sol-pi/<session-id>/observation-pack/归档仍在本地，Pi session 结束时不会自动删除；按数据保留策略清理。
Evidence-Preserving Reducer.../evidence-preserving-reducer/可能把 eligible diagnostic-log 发给 reducer model；敏感日志保持关闭。
Online Context Compact状态写入 Pi session log成功后新 turn 继续；取消/退出不触发自动 continuation。
认证与 Provider由 Pi 管理SoL-Pi 不替你审查 Provider URL、权限、数据处理条款；启用远程能力前单独评估。
安全验收顺序：先用合成日志 → 确认本地 archive → 检查 reducer 配置/模型路由 → 再决定是否处理真实诊断日志。不要把“保留原文”误读成“永不离开本机”。
06

故障排查：按安装、配置、句柄、模型四层定位

每层只验证一个假设，避免把所有异常归咎于 token 优化。

现象先查再做
Pi 找不到扩展Node 版本、Pi 0.84.2、安装输出重新安装；确认是全局还是 project-local scope
开关没生效实际读取的是哪一个 sol-pi.json只保留一份测试配置，再逐个启用
长结果回取失败句柄、页码、session archive回看原始归档，不要只依赖摘要
Reducer 失败模型路由、认证、日志资格原结果应保持不变；敏感日志直接关闭远程 reducer
压缩后任务不连贯Pi session log 与取消/退出状态缩小任务，重新验证 compaction 前后上下文
07

适用边界、版本与许可证

SoL-Pi 是 Pi 的独立扩展，不是 Pi 官方发行版，也不是通用模型成本保证。

适合

长时间编码任务、重复验证、大日志读取和计划阶段较多的 Pi 工作流；团队愿意审查本地归档与模型调用。

不适合

不能接受任何远程 reducer、无法管理 session archive、或需要把所有上下文变化保持人工可见且不自动续跑的流程。

当前事实快照

NVlabs/SoL-Pi：TypeScript；main；GitHub API 约 1,584 Stars、113 Forks、38 Open Issues；无 Release、无 Tag。
