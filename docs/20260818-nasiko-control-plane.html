01
Section One

它是什么

Nasiko 是 Nasiko-Labs（GitHub: Nasiko-Labs）开源的单一控制面进程，面向 A2A 兼容的多 Agent 部署场景：一次部署，同时拥有代理路由、MCP 网关、LLM 密钥路由、可观测性和嵌入式镜像仓库。无需独立 gateway 或 sidecar 进程。

单进程控制面架构

单一 nasiko-server 进程承担全部控制职责：TLS 终止、认证、代理路由、可观测性收集。agents 从不被公网访问——所有 agent-to-agent 调用都经 server 内部回环代理。

A2A v1.0 严格兼容

硬编码 A2A-Version: 1.0 header，向下不兼容 0.2.x / 0.3.0 版本。任何实现 A2A v1.0 协议的 Agent（Python / Rust / Go / TypeScript）均可接入，无需专有格式。

MCP Gateway

单一永久 URL 为所有 agents 提供合并的、权限过滤后的 Composio toolkits 与自定义 MCP servers 视图，agent 无需持有凭证。

LLM Router（密钥保护）

Agent 获得 OPENAI_BASE_URL + 短期身份令牌，真实 API key 在服务端解析。API key 永不暴露给 Agent 或日志。

Flow Guards（防循环）

Redis 实现的 depth / fan-out / token budget / timeout / cycle detection 限流，防止失控 Agent 循环调用和资源耗尽。

OTel 全链路追踪

每条 dispatch 和代理跳发出实时 OTel span，端到端追踪。Token 用量与成本从 gen_ai.* 属性自动采集。

02
Section Two

核心架构组件

nasiko-server 内部划分 10 个功能模块，共同构成单进程控制面。

🔐 AUTH

身份 · TLS · 限流

Session JWT + TLS + rate limit + ACL 共同鉴权每条请求。

🔄 PROXY

A2A 反向代理

通用 Agent 反向代理——绕过路由引擎，直接通过 server 内部回环转发 A2A 消息。

🧭 ROUTE

智能路由引擎

三阶段：embedding 相似度初筛 → 对话上下文重排 → LLM 终选。调用方无需了解 Agent 集群。

🛠 MCP

MCP 网关

tools/list + tools/call + OAuth，支持 Composio 与自定义 MCP server 合并视图。

🤖 LLM

LLM 路由

OPENAI_BASE_URL + 短期令牌，provider/key 在服务端解析，无 key 泄漏。

📦 OCI

嵌入式 OCI Registry

S3 后端 + 层去重，nasiko push / deploy 无需外部 registry。

⏱ FLOW

Flow Guards

depth / fan-out / token budget / timeout / cycle detection，Redis 状态后端。

🔑 SECRETS

密钥引擎

AES-256-GCM 静态加密，部署时注入，Postgres 持久化。

🔌 OIDC

OIDC 单点登录

企业级 SSO 支持，OIDC 客户端集成。

后端基础设施（Docker 运行时）

Postgres（持久状态） Redis（Flow Guards） S3 / RustFS（OCI 镜像） OTel Collector（追踪） Tempo（分布式追踪） Loki（日志聚合） Docker Engine + Compose V2 Rust 1.85+（本地开发）
03
Section Three

快速部署（Docker，无需 Rust）

Docker-only 路径只需 Docker Engine + Compose V2，三步启动完整 Nasiko 平台。

Step 1：克隆并配置

# 克隆仓库 git clone https://github.com/Nasiko-Labs/nasiko.git cd nasiko # 复制环境变量模板 cp .env.example .env # 必填配置（编辑 .env） OPENAI_API_KEY=sk-... # 路由引擎 + Agent 注入用 ADMIN_PASSWORD=your-secure-password # Bootstrap 管理员密码

Step 2：启动完整平台

# 启动全部组件（首次构建需几分钟） docker compose up -d # 跟随 server 日志 docker compose logs -f server # 停止平台 docker compose down

Step 3：访问 Dashboard

# 打开 Dashboard http://localhost:8080 # 默认登录凭证（首次使用后立即修改） Username: admin Password: changeme # 或 ADMIN_PASSWORD 指定值

CLI 命令（Rust 路径）

本地开发需要 Rust 1.85+：

nasiko new # 创建新 Agent nasiko run # 运行 Agent nasiko chat # 交互式 Chat nasiko deploy # 构建 + 推送 + 运行 nasiko push # 推送到内置 OCI Registry

Bring Your Own Agent

接入任意 A2A v1.0 兼容 Agent，无需专有格式：

# 通过 API 注册 Agent curl -X POST http://localhost:8080/api/v1/agents \ -H "Authorization: Bearer $TOKEN" \ -H "Content-Type: application/json" \ -d '{"name":"my-agent","a2a_url":"http://my-agent:8080"}'

Section Four

X 帖子叙事：Multi-Agent Control Plane Pattern

monokern @x.com（X Article，2026-08-11，4.8 万浏览）提出"分布式 multi-agent pipeline 失败 → 单 Agent 控制面替换"的架构叙事。Nasiko 是该模式的开源实现路径之一，但两者不等同。

⚠ 证据分层边界（必读）

  • Nasiko 官方事实（已核验）：README · LICENSE · GitHub API 元数据
  • A2A 生态规范（已核验）：A2A protocol v1.0，Linux Foundation
  • X 帖子叙事（仅作架构观点背景）："Single-Agent Control Plane Pattern"三柱框架、50+ turns / 30 minutes / 18% TRX drop 等案例数字——这些是 monokern 的观点，不是 Nasiko 项目的实际性能数据
  • 未核验：ZS Associates 商用 pharma 案例（公司未公开具体实现，无法一手核验）

monokern X Article 三柱框架

X Article 叙事（非 Nasiko 内置功能）：

  • Pillar 1 — Deterministic Signal Queue：统计异常检测脱离 LLM，用 SQL/Python window functions + Z-score 做前置过滤，LLM 只处理已确认的信号事件
  • Pillar 2 — Centralized Reasoning：单一主 Agent 拥有端到端诊断生命周期；子 Agent 仅做隔离数据获取，不被授予判断权
  • Pillar 3 — Knowledge Graph Control Plane：Domain expert 构建知识图谱，约束 Agent 推理路径，防止无效 SQL 和幻觉关联

Nasiko 的实际实现范围

Nasiko 专注Agent 运行时控制，不内置知识图谱推理：

  • ✅ A2A v1.0 代理路由（单进程 Proxy）
  • ✅ MCP Gateway（工具聚合与鉴权）
  • ✅ LLM Router（密钥保护与模型路由）
  • ✅ Flow Guards（循环检测 + 限流）
  • ✅ OTel 全链路追踪
  • ✅ OCI 镜像管理
  • ❌ Knowledge Graph 控制面（非内置，需外部实现）
  • ❌ Deterministic Signal Queue（非内置）

Bounded Investigation Loop（X 帖子叙事）

STEP 1Neighborhood Discovery：从 KG 查询信号节点邻域
STEP 2Hypothesis via Edges：每条边 = 可操作假设路径
STEP 3Data Verification：直接 SQL / API 检查底层数据证据
STEP 4Evaluate & Traverse：符合阈值则深入，否则剪枝
STEP 5Termination：50+ 轮迭代，直到根因定位或路径耗尽

Section Five

风险与限制

⚠

A2A 版本硬性要求

Nasiko 硬编码 A2A v1.0，向下不兼容旧版 agents（0.2.x / 0.3.0）。错误码 -32009 VersionNotSupported 会在不兼容时立即出现。

!

基础设施依赖

完整平台依赖 Postgres + Redis + S3 + OTel Collector + Tempo + Loki。自托管需额外运维工作，不适合轻量单 Agent 场景。

89

Open Issues

截至 2026-08-17 仍有 89 个 open issues（GitHub API）。活跃开发中，部分 API 或有 breaking change。

📊

缺少量化吞吐数据

README 未提供 agent 并发数、延迟 P99 或 token 吞吐实测数据。生产部署前建议自行压测。

🔑

密钥注入机制

Secrets 以 AES-256-GCM 加密存储，但密钥管理方案（部署时注入）需配合安全 CI/CD 流程，否则部署节点仍有泄漏风险。

KG

Knowledge Graph 非内置

monokern X Article 的 KG 控制面模式不在 Nasiko 内置功能范围内。如需该能力，需在 Nasiko 之上自行集成 Neo4j / NetworkX 等图数据库。
