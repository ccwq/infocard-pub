02 · ONE SMALL CLIP

第一次只做三件事：导入、裁剪、调音量

用约 30 秒、你拥有使用权的视频副本练习。先选择常见 MP4 素材；README 列出 MP4、MOV、WebM、MKV、MP3、WAV、PNG 导入，但扩展名在列表里不代表任意内部编码都能解码。

  1. 导入并放到时间线：确认预览能播放，音频有声，素材时长符合预期。先不要叠加其他媒体。
  2. 裁掉头尾：以保留中间约 10 秒为练习目标，调整片段边界；播放开头和结尾，确认没切掉要保留的内容。
  3. 调整片段音量：从原音量开始试听，再适度降低；是否有百分比、dB 或其他单位以当前界面为准，不照抄未经核对的默认值。
  4. 尝试撤销/重做：文档声明支持 undo/redo，可用一次小改动验证能否回退；不要依赖未验证的快捷键。

这一轮先不加滤镜和动画。这样导出失败时，能区分基础媒体问题与效果叠加问题；原素材副本始终保留。

03 · ACCEPTANCE BEFORE SCALE

“导出完成”不是验收完成

若当前导出界面提供 H.264，先以它完成小样；优先保持素材原分辨率和帧率，暂不做升采样。README 也列出 ProRes，但本页未验证各平台编码器、封装格式组合或导出预设。

导出前：范围

确认目标是裁后的约 10 秒，而非整段素材；核对输出位置，避免覆盖原文件。

导出时：记录

记录应用版本、所选编码/分辨率/帧率和错误提示；不要把某种扩展名当成编码器名称。

导出后：独立播放

在外部播放器打开文件，不只看编辑器预览；至少播放首帧、中段和末尾。

  • 时长：是否与保留范围一致，有没有多余黑场或尾部截断？
  • 音画：有没有失声、爆音、明显不同步或掉帧？
  • 画面：文字是否裁切，比例是否拉伸，头尾是否完整？
  • 水印：项目声明无水印；检查你的实际输出，不能用本页代替确认。
全部通过后，再加一条音轨或一段文字叠加，并重新验收。重要交付前，必须用自己的目标素材和目标播放设备做第二轮测试。

04 · FEATURES → ENGINE

能做什么，底层各自负责什么

以下为 README 的能力范围，不是本页对功能完整度的实测评分。

剪辑

多轨时间线

多层轨道、帧级裁剪与撤销/重做。先验证单轨，再测试你的多轨组合。

声音

波形与片段音量

peak + RMS 波形、音画同步与音量控制。不据此推断已具备专业混音全套功能。

画面

文字、叠加、滤镜

自定义文字样式、动画叠加、滤镜和实时画布预览；复杂效果兼容性仍需验证。

React 19 / TypeScript
  时间线 UI · 预览 Canvas · Filmstrip 缓存
                  ↓ Tauri IPC
Rust / FFmpeg
  解码池（LRU 缓存）→ 帧解码 / 导出管线

React 管交互和预览界面，Tauri 连接前端与原生 Rust 核心，FFmpeg 参与媒体处理。有硬件加速路径 ≠ 每个 GPU、驱动与编码都能成功加速；卡顿时要连同机器信息和素材编码一起查。

05 · PERFORMANCE & PRIVACY

低延迟是项目宣称，遥测是明确边界

README 宣称 sub-10ms 解码并面向流畅 60 FPS 播放。本页没有安装、采样或跑性能基准；这不是对任意分辨率、编码、轨道数量和硬件组合的承诺。

文档明示收集

production 性能遥测：decode/compose 时延、P95 seek、掉帧数、OS 类别、GPU 厂商和型号。

项目声称不收集

视频帧、媒体素材、工程标题、文件路径和个人身份信息。此处转述 README，未独立审计实现。

尚未证实

退出开关、端点、保留期限和离线行为。本页不提供虚构的关闭选项，也不写“零遥测”。

README 还写了自适应采样：流畅播放时 1%，掉帧超过 5% 或驱动回退时 100%。不要把“本地编辑”理解成“完全不联网”。处理客户、保密或受监管素材前，先审阅 遥测说明 与你的组织政策；无法接受或确认时，先不导入。

06 · FOR DEVELOPERS

用安装包试用，和从源码开发，是两条路

只想剪视频：先走 Release 安装包，不必从源码编译。准备贡献代码：阅读 贡献指南，再沿 Development 核对环境。

  • 源码入口：默认分支是 master；src/ 为 React/TypeScript 前端，src-tauri/ 为 Rust 原生后端。
  • README 最低说明：Node.js 18+、Rust 1.70+、FFmpeg 6+ 及开发头文件；这不是当前依赖组合的充分兼容保证。
  • 依赖先核对：package 使用 Vite 7，实际 Node 要求可能更高；先查依赖和平台构建前提，不要盲装旧版本。
  • 开发入口：npm run tauri dev；先完成项目依赖、原生库和 sidecar 配置。环境样例是否存在需另查，本页不教复制未经确认的文件。
  • 验证入口：package 列有 npm run typecheck、npm test；README 列有 Rust cargo test。命令存在不代表本页已经跑通。
版本分开看：保存的 master package 写 1.6.0；主线程 Release API 快照返回 v1.2.2。源码版本不等于正式发布版本，下载和报告问题时以所用安装包的发布标签为准。

07 · WHEN THE FIRST TEST FAILS

先缩小问题，再报一个能复现的故障

现象第一项检查下一步
装不上 / 打不开系统、架构、安装包来源及安全提示Mac Intel 不拿 aarch64 包试；签名不明先核对，不绕过安全防护。
导入失败 / 黑屏文件是否完整；实际视频/音频编码，不只看扩展名换一段已知可播放的小素材对照；仍失败，记录提示和编码信息。
播放卡顿 / 拖动慢分辨率、帧率、轨道与效果数量、GPU 驱动回到单轨无效果小样；不要用 sub-10ms 宣传值判定你的机器必然正常。
导出报错 / 音画异常范围、编码器、封装格式、输出目录与空间若可选，回到常见 H.264 输出；用外部播放器区分预览和文件问题。

到 官方 Issues 报告时，附系统与 CPU/GPU、应用发布标签、素材编码/分辨率/帧率、最短复现步骤和原始错误。可共享时只用非敏感小样；提交截图和日志前，清理路径、标题等敏感信息。

08 · BOUNDARIES & SOURCES

把“开源承诺”与“可交付证明”分开

“无水印、无付费墙、无订阅、无功能限制”是项目 README 的声明。本页未独立验证收费策略、安装体验或长期稳定性，也不依据推文断言十月发布频率。先做自己的导出验收，再判断是否适合正式使用。

许可：保存的 LICENSE 为 MIT，可使用、修改和分发，但要保留版权与许可声明，且软件按现状提供。README 另注明 FFmpeg 依赖为 LGPL v2.1+；重新打包或分发前，需核对具体组件、构建选项和适用义务，不能只看主项目 MIT。

  • 官方仓库 / master README：身份、功能、平台、架构和遥测声明。
  • Releases 与 Assets：下载时按实际发布说明、系统和架构选择；已核对资产所属发布页 仅作快照来源。
  • package.json / LICENSE：源码版本、依赖、脚本与许可。
  • 发现这款工具的推文：发现入口，不作为性能、发布频率或移动端可安装性的证明。

证据范围：读取仓库文档与主线程提供的 Release API 核对记录；未运行 Clypra。界面路径、签名、遥测实现和目标素材兼容性仍待验证。
