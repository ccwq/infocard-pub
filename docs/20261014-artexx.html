ARTEX.

AI 自主渗透测试系统：Go 单体后端（go:embed 内嵌 Next.js 前端）+ PostgreSQL，agent 能力由 norma SDK 提供。核心是双图架构与围绕它的两条自主性机制。

这套系统在架构上最值得读的一点：把「目标是什么」和「测到了什么程度」拆成两张图——全局共享的资产图负责真值，每任务独立的探索图负责推理链，两者用锚点相连。planner 只在有未覆盖的新方向时派意图，worker 领一条意图、用真实工具执行、写回后即停。

03ORCHESTRATION

编排层是全卡唯一的饱和区。职责分工很硬：planner 只派意图，worker 只执行一条。

plannerLoop（每任务一个）· 只派意图

读探索图态势、判目标，只在有未覆盖的新方向时把意图派进 frontier。planner 是事件驱动的，每次唤醒都是全新会话。

意图派发事件驱动无状态会话
worker（每任务 N 个 goroutine）· 只执行一条

领一条意图、用真实工具执行、把新资产/事实/漏洞写回两图后即停。并发数 = 每个任务的 work agent 数（系统设置，默认 3）。

一条意图写回即停默认 3 并发
engine · 生命周期与调度

Manager 托管任务、引擎、DB store 生命周期；engine 负责意图领取、超时、暂停、drain。

Manager超时/暂停drain
agent · goals / planner / worker / mainagent

ToolSet 把双图暴露成 LLM 工具，agent 通过工具读写，而不是直接改数据库。能力由 norma SDK 提供：agentcore / tool / permission / harness / memory / transcript。

ToolSetnorma SDKpermission
图变 ⇢ 触发 唤醒 planner ↓ 调用 派意图进 frontier ⇢ 触发 worker 执行并写回 ↓ 调用 prove_goal

事件驱动闭环：图一变就唤醒 planner，planner 派意图，worker 领意图执行并写回，写回又触发下一轮，直到目标被证明（prove_goal）。大多数唤醒派 0 个意图——无新方向即结束。

04AUTONOMY

两条自主性机制，分别解决「信息不对称」和「无状态会话下的链路稳定性」。以下口径来自 README，未做行为实测。

worker 间过程级信息交换

search_all_worker_traces(q) 在本任务其他 work 的执行过程里按关键字检索（自动排除自己这条意图的步骤），命中项带 intent_id；list_worker_traces / get_worker_trace(intent_id, step_ids=[…]) 先看有哪些 work 跑过，再取某个 work 具体几步的完整内容做细节交换。

为什么重要：即便探索图上还没有对应 fact，后续 worker 也能复用他人过程中的观察。信息以「执行过程」为粒度在 worker 间流动，边界不变——每个 worker 仍只做自己领到的那条意图。

粒度 = 执行过程自动排除自身未行为实测
planner 跨唤醒共享 todolist

planner 持有按任务保留、跨唤醒共享的规划待办（todolist）。planner 是事件驱动的，每次唤醒都是全新会话——共享 todolist 让它把一条串行利用链记录一次，再在后续多轮里按依赖逐步派意图，而不是一轮全前置展开。

每轮只对「前置步骤已完成、其依赖的 fact 已存在」的下一步派意图，并随进展更新清单。于是攻击链在「事件驱动 + 无状态会话」下依然稳定推进、不重复、不错序。

跨唤醒共享按依赖派发未行为实测
05AGENT STACK

自上而下的运行栈：前端内嵌进单二进制，server 托管生命周期，engine 跑 agent，双图落在 Postgres。

前端
Next.js 静态导出，go:embed 内嵌进单二进制；可视化任务 / 资产 / 探索链路 / 覆盖图，人在环路对话。
server
net/http 路由 + JWT 鉴权 + SSE；Manager 托管任务、引擎、DB store 生命周期。
engine
每任务一个 plannerLoop + N 个 worker goroutine；意图领取、超时/暂停/drain。
agent
goals / planner / worker / mainagent，ToolSet 把双图暴露成 LLM 工具。
db
双图的 Postgres 落地（pgx）；schema 随 go:embed 每次启动幂等建表。
支撑
记录型 MITM 代理、审批门、异步补全（DNS/HTTP）、MCP / 技能 / 记忆 / 报告。

05已知限制与边界

08OPS PITFALLS

运维坑（五条，逐条单列）

  1. 升级只换程序、不动数据。Postgres 数据卷 pgdata、./data（jwt.key / SQLite 等）、./skills 都保留。数据库迁移无需手动执行——artex 每次启动幂等重跑 schema.sql（含 ADD COLUMN / CREATE INDEX IF NOT EXISTS），即「重启即迁移」。升级前建议先备份 ./data 与数据库。
  2. 页面一键更新的流程是五步。系统配置页（/system/settings）的「版本与更新」卡片：下载对应平台发布包 → 比对 Release 的 SHA256SUMS → 用 -h 冒烟测试新二进制 → 暂存为 artex.new → 退出后由 start.sh / start.bat 重新拉起完成换装。校验或冒烟不通过就丢弃暂存件继续跑当前版本；新版连续 3 次启动失败会自动回滚到 artex.old（失败件留作 artex.failed）。可回滚到上一版本，但数据库结构不会回退；更新会中断正在运行的任务；版本号是 dev 或 git describe 带后缀时禁用更新。
  3. Docker 下更新不带镜像内工具链。更新只换程序不换镜像，镜像里的 playwright / nmap 等工具链不会跟着升级，docker compose up -d 重建容器后会退回镜像自带版本；要连镜像一起升级须用 docker compose pull artex && docker compose up -d artex。
  4. 反代必须关闭缓冲，否则 SSE 收不到事件。SSE 是长连接持续推送，反代若不关缓冲，浏览器连上却收不到事件（活动流一直转圈）。Nginx 需 proxy_buffering off、proxy_cache off、proxy_read_timeout 3600s、proxy_http_version 1.1、proxy_set_header Connection ""。公网只开放 443、把 8787 留内网即可。NEXT_PUBLIC_SSE_BASE 只在构建期生效（next build 时固化进静态包，容器运行时再设无效）。
  5. 复测历史不纳入导出。复测历史记录暂未纳入漏洞报告导出或任务归档包，也未自动关联流量包。

另有更新脚本 ./update.sh：可选 git pull，再选 ① Docker 更新（可指定 ARTEX_TAG，缺省 latest）或 ② 本地编译更新。
