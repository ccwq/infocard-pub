问题定义

为什么热路径不能学习？
热路径
用户等待中
Agent 执行任务时，用户正在等待响应。任何额外计算都会直接增加延迟。
→ 必须极简：廉价抓取原始痕迹，然后继续
冷路径
空闲时学习
昂贵的提炼过程完全在热路径之外运行，让明天的 Agent 比今天更好。
→ 定时节奏 + 容量阈值触发

核心机制：G → R → C 管道

G
Generator 生成器
从执行痕迹中提炼经验教训，提出更新建议候选
R
Reflector 反思器
批评验证——提议的教训是真的？和已知知识相容？值得保留？
C
Curator 管理器
决定最终写入存储，增量写入，持久积累，不重复覆盖

触发机制

⏰
定时节奏
每几小时自动触发一次，按组织/团队/个人三层各自节奏运行
📊
容量阈值
当未处理的执行痕迹积压超过阈值时立即触发，避免知识流失

设计原则

积累与呈现分离
存储层
持久积累
执行痕迹、学习成果、经验教训持久积累，不断丰富知识库。
呈现层
可替换
Prompt 优化方法、检索策略、知识组织方式均可独立演进，不影响底层存储。
生物类比
白天行动 · 晚上学习
生物记忆巩固机制：白天积累经验，夜间睡眠时整合强化，两者互不干扰。

热路径 vs 冷路径对比

🔥
热路径（Hot Path）
时机：用户等待中
目标：极低延迟响应
操作：廉价抓取原始痕迹（检索了什么、尝试了什么、哪里出错了）
原则：不做任何学习/提炼/优化操作
❄️
冷路径（Cold Path）
时机：空闲计算时
目标：让 Agent 持续进化
操作：G→R→C 三阶段管道处理痕迹
原则：今天没有任何任务变慢，明天变得更好

适用场景

🤖
Agent 产品
需要持续学习和优化的 AI Agent，在每次交互中积累经验，不断提升回答质量和任务成功率。
📋
长任务场景
复杂多步骤任务执行，过程中产生大量中间状态和尝试路径，需要在任务间隙进行知识沉淀。
🔄
多 Agent 协作
组织/团队/个人三层并行运行，各自在空闲时进行知识巩固，集体智慧持续增长。
⏱️
延迟敏感系统
对响应时间有严格要求的系统，必须将学习过程完全剥离热路径，保证用户体验不受影响。
