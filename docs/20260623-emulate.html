EMULATE · LOCAL API · CI READY

把第三方 API 变成本地、确定、零依赖的模拟层

emulate.dev 面向 dev 与 CI：为 GitHub、Stripe 等第三方服务提供本地 API emulation，状态可控、协议真实、无需外网，适合让 Agent Loop 在沙盒里零成本反复跑。

01
WHY IT MATTERS

对 Agent Loop 来说，外部 API 是最贵的随机变量

真实依赖会引入网络、配额、时延、权限和不确定状态；本地模拟把这些都压平了。

零成本

重复测试不再消耗真实 Stripe / GitHub 调用额度。

零依赖

离线或 CI 环境也能完整跑通依赖链。

可重置

每个测试都能从干净状态开始，结果可复现。

02
WHAT IT GIVES YOU

状态、协议、配置：都尽量像真的

它不是简单 mock JSON，而是更像一个可管理的本地服务层。

Stateful

有状态模拟

可保存 / 重置 / 复用测试状态。

Real protocols

协议尽量真实

让 SDK 和集成层改动更少。

Zero config

开箱即用

减少搭建本地测试环境的摩擦。

Offline & CI

天然适合流水线

在 CI / 沙盒里更稳定地跑 agent loop。

03
ENTRY POINTS

三种接入方式

同一份模拟能力，按场景分别用 CLI、程序化 API 或前端适配器接入。

CLI

npx emulate --service github,stripe，最适合在脚本和 CI 里快速起服务。

命令行快速启动

程序化 API

通过 createEmulator 在代码里创建、重置、关闭模拟器，适合测试框架或集成层。

reset()close()typed API

Next.js 适配器

给前端 / 全栈仓库提供更贴近项目结构的集成方式，减少手工 glue code。

04
TRADE-OFFS

它的定位是“本地基础设施”，不是“云 API 的替身”

适合开发、测试、CI、沙盒和 Agent Loop；不适合替代真实第三方服务的生产语义。

1

更快

没有外网往返和真实服务排队。

2

更稳

状态可重置，结果更确定。

3

更便宜

测试频繁跑也不消耗外部额度。

一句话：emulate.dev 把“外部 API 依赖”压成了一个可本地管理的状态层，Agent Loop 由此可以更快、更便宜、更确定。
