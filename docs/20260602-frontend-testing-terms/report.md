# 前端测试术语快速了解报告

## 结论
前端测试不要先问“哪种最强”，要先问“你要拦住哪一种失败”。

- **单元测试**：守住最小逻辑正确性。
- **集成测试**：守住模块、组件、接口之间的协作。
- **E2E 测试**：守住用户从入口到关键结果的完整路径。
- **冒烟测试**：守住上线后最基本的可用性。
- **回归测试**：守住旧 bug 不要因为新改动再次出现。
- **Mock / Stub / Fake / Spy / Snapshot**：是测试替身或快照手段，不是测试层级本身。

## 最实用的选择顺序
1. 先判断你在担心**逻辑**、**协作**、**路径**、**上线**还是**复发**。
2. 再决定测试层级，不要反过来按名词选。
3. 默认优先级通常是：**单元 > 集成 > E2E > 冒烟 > 回归补位**。

## 术语速查
- **单元测试**：验证一个函数、一个组件片段、一个纯逻辑块的输入输出。
- **集成测试**：验证多个模块拼在一起后，状态流转和边界是否正常。
- **E2E 测试**：从浏览器或真实用户路径出发，检查整个链路是否可完成。
- **冒烟测试**：发布后先查“能不能活着”，例如首页、登录、核心接口、关键按钮。
- **回归测试**：修复一个 bug 后，重新覆盖相关旧路径，防止老问题复发。
- **Mock**：预设交互期望，验证“有没有按预期调用”。
- **Stub**：给依赖一个固定返回值，专注于当前测试对象本身。
- **Fake**：用一个轻量但能工作的替身实现，常见于内存仓库、假服务、假数据库。
- **Spy**：记录调用次数、参数和顺序，观察行为而不一定强行控制返回值。
- **Snapshot**：保存渲染结果做差异对比，适合结构稳定的 UI，不适合高波动文案。

## 常见混淆
- **Smoke ≠ Regression**：冒烟是“上线先查活着没”，回归是“旧问题别回来”。
- **Mock ≠ Unit**：Mock 是手段，单元测试是层级。
- **E2E ≠ 全量测试**：E2E 只保关键路径，不是把所有分支都跑一遍。
- **Snapshot ≠ 截图**：它更像结构快照，不是视觉图片本身。

## 什么时候用哪一种
- **函数规则、输入输出明确** → 单元测试
- **组件 + 状态 + 请求一起跑** → 集成测试
- **登录、下单、提交、跳转这类主路径** → E2E
- **部署后快速确认核心功能正常** → 冒烟测试
- **修 bug 之后验证旧路径还在** → 回归测试
- **依赖太重、无法直接测本体** → Mock / Stub / Fake / Spy

## 一句话总结
前端测试的核心不是把名词记全，而是把每一层放在它最该负责的失败模式上：

**单元管逻辑，集成管协作，E2E 管路径，冒烟管上线，回归管复发。**
