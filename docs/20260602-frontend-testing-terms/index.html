前端测试术语快速了解报告：先分层，再选方法

01 / 核心判断

判断
一句话结论

前端测试不要先问“哪种最强”，要先问“你要拦住哪一种失败”。单元管逻辑，集成管协作，E2E 管路径，冒烟管上线，回归管复发。

最实用的选择顺序

  1. 先定目标：逻辑、协作、路径、上线、复发，五选一或组合。
  2. 再选层级：单元 / 集成 / E2E / 冒烟 / 回归。
  3. 最后补替身：如果依赖太重，再考虑 mock、stub、fake、spy。

怎么读这张卡

把它当作“测试术语决策树”：不是先记名词，而是先认场景。你越清楚自己要挡住什么风险，就越不会把测试写成成本很高但价值很低的仪式。

主线

单元、集成、E2E、冒烟、回归是不同的失败防线，不是同一件事的不同叫法。

定位

这是一张给前端开发者的术语速查卡，不是测试理论课。

边界

不要拿 snapshot 代替所有 UI 验证，也不要让 E2E 负责所有逻辑。

02 / 5 个测试层级

分层

这个流程图不是执行顺序，而是责任分层：你可以先写单元，再补集成，再用 E2E 保关键路径；冒烟和回归则负责发布后与修复后的门禁。

Unit Test单元测试

验证一个函数、一个组件片段、一个纯逻辑块的输入输出。它追求速度和定位精度，最适合把边界条件、分支判断和小逻辑先压稳。

关键词：快、准、颗粒度小。

Integration Test集成测试

验证多个模块拼在一起后，状态流转、数据传递、请求边界和组件协作是否正常。它负责补单元测试看不到的“拼起来会不会坏”。

关键词：协作、边界、联动。

E2E Test端到端测试

从浏览器或真实用户路径出发，检查从入口到结果的完整链路能否完成。它只保关键路径，不承担所有分支覆盖。

关键词：主路径、真实链路、成本高。

Smoke Test冒烟测试

发布后先查“能不能活着”：首页、登录、核心接口、关键按钮、基础跳转，先确认最小可用面没有崩。

关键词：上线门禁、快速探活。

Regression Test回归测试

修复一个 bug 或改动一个功能之后，重新覆盖相关旧路径，防止老问题再次出现。它关注的是“改完有没有把以前弄坏”。

关键词：复发、旧路径、保险栓。

选择原则按风险选，不按名词选

逻辑问题先单元，模块联动先集成，业务路径先 E2E，上线检查先冒烟，修复后确认先回归。层级不是越高越好，而是责任刚好对上风险。

关键词：风险匹配、职责分离。

03 / 5 个常见替身术语

替身
Mock模拟对象

预设交互期望，验证“有没有按预期调用”。它更关心行为合同，而不是把真实依赖完整跑起来。

适合：验证调用、参数、次数、顺序。

Stub桩

给依赖一个固定返回值，专注于当前测试对象本身。它的作用是把外部不确定性先压平。

适合：固定数据、简化依赖。

Fake假实现

用一个轻量但能工作的替身实现，比如内存仓库、假服务、假数据库。它比 stub 更像真的，但仍然是可控的。

适合：需要“能跑”的轻量环境。

Spy间谍 / 观察器

记录调用次数、参数和顺序，观察行为而不一定强行控制返回值。它更像埋点，而不是替换。

适合：检查调用轨迹。

Snapshot快照测试

保存渲染结果做差异对比，适合结构稳定的 UI、文案变化少的场景。它不是截图万能药，更不适合高波动页面。

适合：结构回归，不适合：频繁变文案。

关键提醒替身不是层级

Mock、Stub、Fake、Spy 是“怎么隔离依赖”，不是“测试是哪一层”。一条测试可以同时用替身，也可以不用替身。

记法：层级管范围，替身管依赖。

04 / 最容易混淆的地方

误区

四个常见误会

  • Smoke ≠ Regression：一个查“能不能活”，一个查“旧 bug 回不回来”。
  • Mock ≠ Unit：Mock 是手段，单元测试是范围。
  • E2E ≠ 全量测试：E2E 只保关键用户路径，不负责所有分支。
  • Snapshot ≠ 截图：它保存的是结构对比，不是视觉图片本身。

什么时候你该停一下

如果你发现自己在给所有东西都加 E2E，或者把 snapshot 当成“UI 保险”，那通常说明你不是在设计测试策略，而是在用名词填空。此时应先回到失败模式，再回到测试层级。

发布前

先 smoke，避免上线后才知道基础功能坏了。

修复后

再 regression，确认旧路径没被新改动破坏。

结构稳定时

snapshot 才有更高性价比。

05 / 速查结论

总结
最稳定的取舍：单元做大多数逻辑，集成补接口协作，E2E 只保关键路径，冒烟守发布门槛，回归守 bug 不复发。替身术语则用来隔离依赖，不用来替代测试层级。
  • 用途不是“记住名词”，而是快速决定：这一层到底该拦什么风险。
