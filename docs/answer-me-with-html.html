HOW IT WORKS · 工作原理

模型只写内容，CLI 完成所有渲染

Agent 写一段短 Markdown，CLI 负责 HTML/CSS/SVG 渲染。模型把精力放在「讲什么」而不是「怎么排版」。

序列图、状态图、对比表格、流程图——全用 Markdown 语法描述，不需要写 HTML/CSS。

## Three-way handshake
```sequence
Client -> Server: SYN
Server -> Client: SYN-ACK
Client -> Server: ACK
```
> 客户端发送 SYN 请求建立连接。
CLI renders

CLI 渲染为可读页面

蓝图风格（默认）：格纸背景、字母编号、渐变线条。支持 shadcn 风格和亮/暗模式。

不需要安装任何依赖，CLI 已打包进 skill，安装即用。

03
VIDEO · 讲解视频

am video：3Blue1Brown 风格的逐帧动画

在 Markdown 中加入「旁白行」，am video 将其渲染为带动画和声音的播放器页面。

Blueprint 风格3Blue1Brown 风格

两种视觉主题

  • blueprint（默认）：格纸背景、字母编号、渐变线条
  • theme: 3b1b：深色背景、3Blue1Brown 风格
  • mode: dark / light：切换明暗模式

视频与页面共享同一绘图风格，生成体验一致。

声音支持

旁白生成

  • ElevenLabs（需设置 ELEVENLABS_API_KEY）
  • macOS 系统 TTS：中文用 Tingting，英文用 Samantha
  • 纯字幕（无语音时）

音频嵌入页面，离线可播；加 --mp4 导出 1080p 视频（需 Chrome + ffmpeg + Node.js 22+）。

## 旁白行语法示例
```sequence
Client -> Server: SYN
Server -> Client: SYN-ACK
```
> [Server] 收到 SYN 后返回 SYN-ACK。
> [Client] 发送最后的 ACK，连接建立。

# am video 关键参数
am video examples/video-tcp.en.md        # 生成播放器页面
am video examples/video-tcp.en.md --mp4  # 导出 MP4 视频
# [Server] 触发相机聚焦和高亮节点
# 音频与字幕同步，beat = 一段旁白 = 一个动画步骤
04
ALWAYS-ON · 常驻模式

每次结论自动生成页面，不弹窗打扰

开启后，Agent 每次给出结论、总结、比较或计划时，自动生成 2-4 面板页面，路径附在回复末尾，不自动打开。

1

仅结论触发

闲聊和无结论回复不生成页面。约 90 tokens 的提示词规则写入 Agent 自身规则文件。

2

不弹窗打扰

always-on 模式下页面不自动打开，只在回复末尾附上路径，不中断工作流。

3

Claude Code 插件

安装 answer-me-with-html-always 插件即可开启；用 /answer-me-with-html:config always off 暂停。

DESIGN · 设计理念

ASD-STE100 原则：用最少的词把事情讲明白

源自特殊教育简化沟通理论（ASD-STE100），指导模型在最少输出中达到最大理解效果。

1

ASD-STE100 原则

用最少的词把事情讲明白——不是简化内容，是精炼表达。模型不需要写 HTML/CSS，只写核心信息。

2

Karpathy Ladder 第 4 层

Karpathy 的 LLM 输出理解阶梯：Text → Markdown → HTML → 可视化解释页面。answer-me-with-html 让 Agent 到达第 4 层。

3

Token 节省的本质

输出 token 是「你等待的成本」。Token 节省 7.4× = 等待时间减少 3.6×；费用基本不变，因为模型多了两步短调用。

为什么不用直接输出 HTML？模型现在能写出不错的 HTML。问题是它要手写每一行 CSS、每个 wrapper div 和每个 SVG 坐标——这些都是输出 token，而你就在屏幕前等着。
