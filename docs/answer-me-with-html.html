---
title: TCP three-way handshake
subtitle: How two hosts agree to talk, and how they stop
cols: 3
source: RFC 9293
---
TCP opens a connection with three messages and closes it with four.

## A Three-way handshake {span=2 meta="open"}
```sequence num
participants: Client, Server
note Server: LISTEN
Client -> Server: SYN, seq=x
note Client: SYN_SENT
Server -> Client: SYN+ACK, seq=y, ack=x+1
Client -> Server: ACK, ack=y+1
note Client, Server: ESTABLISHED
```

## B Why three messages
1. The server learns that the client can send.
2. The client learns that the server can send and receive.
3. The server learns that the client can receive.

## C State changes {span=2 meta="simplified"}
```flow LR
(CLOSED) -> LISTEN: passive open
LISTEN -> SYN_RCVD: get SYN / send SYN+ACK
(CLOSED) --> SYN_SENT: active open / send SYN
SYN_SENT -> *ESTABLISHED: get SYN+ACK / send ACK
SYN_RCVD -> *ESTABLISHED: get ACK
```

## D Flags
| Flag | Job | In handshake |
|---|---|---|
| SYN | Start a connection | ok steps 1, 2 |
| ACK | Confirm receipt | ok steps 2, 3 |
| FIN | Stop sending | no not used |
| RST | Reset at once | warn on error |
Model writes

模型负责的部分

  • 决定讲什么、分几个面板
  • 写关系、数据和说明文字
  • 用 Markdown 语法描述图表（序列图、流程图、树图）
  • 写旁白行（用于视频生成）

CLI renders

依赖：marked（解析 Markdown）+ dagre（图形布局），均打包进 am.mjs。

04
COMPONENTS · 全部 8 种组件

Agent 根据信息形态自动选择组件，完整对照表

每个组件对应一种信息结构。Agent 根据 Markdown 中的图表语法识别类型，CLI 自动选择对应组件渲染。也可以用 am list 查看完整列表。

flow架构/流程

flow · 流程图

```flow LR
A -> B: label
A --> B: dashed
A -.-> B: dotted
```

支持：分组（group）、决策节点（diamond）、数据库（cylinder）。dagre 自动计算节点坐标和连线走向。

sequence时序/协议

sequence · 序列图

```sequence num
Client -> Server: SYN
Server -> Client: SYN+ACK
```

支持：参与者声明（participants）、note 标注、带括号的序列号。自动换行对齐标签。

tree结构/层级

tree · 树状图

```tree
A | 标签文字
  B | 子节点
  C | 子节点
```

适合：文件夹树、模块结构、分类体系。文件树可加 list 修饰。

timeline历史/阶段

timeline · 时间轴

```timeline
1979 | AECMA starts work
1986 | First guide published
2005 | ASD-STE100 released
```

用于：技术历史、版本发布节点、阶段划分。关键节点可用 * 标记。

limits限制/边界

limits · 限额表

```limits
Request size | max 1 | MB
Timeout | max 30 | seconds
Retries | max 3 | attempts
```

用「值 + max/min + 限额 + 单位」格式，直观展示参数边界。

annot逐词标注

annot · 逐词批注

```annot
The valve [must be closed]{!} prior to operation.
# must=Approved verb; prior to=NOT approved → BEFORE
```

适合：语法批改、代码注释、文本校对。错误部分高亮，右侧给出修正。

kv元数据

kv · 标题块

```kv
* Title: TCP Handshake
Version: RFC 9293
Date: 2022
```

用于：文档元信息、规格说明、配置清单。模拟工程图纸标题栏。

callout重点提示

callout · 提示框

```callout warn Two is not enough
An old duplicate SYN arrives late.
```

类型：ok（成功）、warn（警告）、error（错误）、info（信息）。放在任意面板内。

i 表格式对比

多方案对比用 Markdown 表格，单元格写 ok → ✓，no → ✗，warn → !，自动渲染为对应符号。

05
DRAFT SYNTAX · 稿件格式详解

frontmatter / 面板 / span / rows / bare / template · 完整语法

Markdown 稿件是唯一输入格式。即使不用 Agent，也可以手写稿件用 CLI 直接渲染。

frontmatter · 文件头

---
template: sheet        # sheet = 网格面板（默认）, doc = 单栏目录
theme: blueprint       # blueprint（默认）或 shadcn
title: TCP three-way handshake
subtitle: How two hosts agree to talk, and how they stop
cols: 3               # sheet 模式的列数（默认 3）
source: RFC 9293       # 任意自定义字段，显示在标题下方
lang: zh-CN           # 强制语言，可不写自动检测
---

template: doc 生成单栏长页面，适合文档类内容；template: sheet 生成网格面板，适合对比和图解。

面板语法 · ## 标题 + 修饰符

## A 面板标题 {span=2 meta="副标题"}
正文内容，支持 Markdown 列表、表格、代码块。
所有图表语法写在 ``` 代码块中。

{span=2}   → 跨越 2 列（默认 1 列）
{rows=2}   → 跨越 2 行
{bare}     → 无标题栏（纯内容面板）
{meta="x"} → 面板右上角副标题文字

面板字母（A/B/C…）可省略，CLI 自动添加。面板顺序决定网格布局排列。

raw HTML/SVG 嵌入

当内置组件不满足时，可直接嵌入原始 HTML 或 SVG：

```html
<div class="my-custom">
  <h2>Custom</h2>
</div>
```

```svg
<svg viewBox="0 0 100 100">
  <circle cx="50" cy="50" r="40"/>
</svg>
```

language detection · 语言检测

CLI 自动检测语言，作用于写作检查规则和页面 lang 属性：

  • 检测到假名（かな/カナ）→ 日语，页面按钮和 lang="ja"
  • 检测到中文 → 中文规则
  • 其余 → 英语 ASD-STE100 规则

强制设语言：在 frontmatter 写 lang: ja

VIDEO · 讲解视频

am video：3Blue1Brown 风格的逐帧动画

在 Markdown 中加入「旁白行」（以 > 开头），am video 将其渲染为带动画和声音的播放器页面。支持 blueprint 和 3b1b 两种视觉主题。

旁白行语法 · video-tcp.en.md 示例

## Both sides wait
```sequence
Client -> Server: SYN
Server -> Client: SYN-ACK
Client -> Server: ACK
note Client, Server: ESTABLISHED
```
> The client sends a SYN to ask for a connection.
> The [Server] answers with a SYN-ACK.
> The client replies with an ACK.
> Now both sides are in the ESTABLISHED state.

## What each step proves
```flow LR
Client -> Server: 1st: client can send
Server -> Client: 2nd: server can send and receive
Client -> *Both confirmed: 3rd: client can receive
```
> After the first step, the server knows the client can send.
> After the second step, the client knows the server works both ways.
> Only the third step proves that the [client can receive].
1

步进动画

第 N 段旁白播放时，第 N 步图解出现。箭头自己画出，相机聚焦当前节点。

2

相机聚焦

[Server] 旁白触发相机聚焦该节点并高亮。节点不出框。

3

对象保持

下一场景中同名节点滑动到新位置，不切断切换。

旁白生成

每 beat 时长 = 音频时长，音画自动同步。

08
STE WRITING CHECK · 受控写作检查

ASD-STE100：航空维修手册的写作规范，LLM 也适用

ASD-STE100（简化技术英语）是一套可机器检查的写作规则，Karpathy 指出让 LLM 遵循这些规则能大幅提升可读性。answer-me-with-html 将其实现为每次渲染前的写作检查，分警告和严格两种模式。

ASD-STE100 背景

  • 1979 年：AECMA 启动航空业受控英语研究
  • 1986 年：AECMA 简化英语指南第一版
  • 2004 年：AECMA 加入 ASD
  • 2005 年：ASD-STE100 正式发布
  • 现由 STEMG（简化技术英语维护组）维护
  • 约 900 个批准词，每个词只有一个词性和含义

现在也用于国防、铁路、工业设备文档。

规则层级

严格度效果
style: off关闭检查
style: 80（默认）警告，但不阻止渲染
style: strict拒绝渲染，直到问题修复

通过 /answer-me-with-html:config style strict 或 frontmatter 中的 style: strict 设置。

英语规则 · English Rules

类别规则示例
步骤句子最多 20 词Open the valve. ✓ / Close the inlet valve before starting the pump. ✗（23词）
描述句子最多 25 词The pump supplies fuel. ✓
段落最多 6 句一个主题一段，段内不超过 6 句
名词短语最多 3 词hydraulic reservoir ✓ / the large red hydraulic reservoir tank ✗
动词形式限批准形式Close the valve. ✓ / The valve is being closed. ✗（被动进行时）
词汇选择用常见词use ✓ / utilize ✗；before ✓ / prior to ✗
主动语态程序中用主动Close the valve. ✓ / The valve must be closed. ✗
词义唯一一词一义close（v）= 合拢；close（adj）= 接近 ✗

中文规则 · Chinese Rules

类别规则示例
步骤句子最多 35 字符关闭阀门。✓ / 在启动泵之前先关闭入口阀门。✗（超过35字）
描述句子最多 45 字符泵为发动机供油。✓
段落最多 6 句一个主题一段
空动词去掉进行优化 ✓ → 优化 ✓；进行评估 → 评估 ✓
被动语态标记警告阀门被关闭了 ✗（中文被动句）
连续「的」一句不超过 2 个一个关于系统架构设计的文档的说明 ✗（3个）
模板词组标记警告赋能 ✗ / 闭环 ✗ / 打通 ✗ / 抓手 ✗ / 拉齐 ✗
⚠ 词汇对比示例

利用 → 使用（use）✓；利用 ✗｜进行优化 → 优化 ✓｜prior to → before ✓｜utilize → use ✓｜ensure → make sure ✓｜commence → start ✓

ALWAYS-ON · 常驻模式

每次结论自动生成页面，不弹窗打扰工作流

开启后，Agent 每次给出结论、总结、计划、比较或解释时，自动生成 2-4 面板页面，路径附在回复末尾，不自动打开。约 90 tokens 的提示词规则写入 Agent 自身规则文件。

仅结论触发

不弹窗打扰

always-on 模式下页面不自动打开，只在回复末尾附路径，不中断工作流。

Claude Code 专用插件

ERROR HANDLING · 出错处理

CLI 返回错误行号 + 组件名 + 正确示例，Agent 一次修复

稿件语法错误时，CLI 输出错误位置、问题组件和正确写法的对比示例。Agent 根据示例修正后，通常一次渲染成功。

错误处理流程

模型 → am: render 稿件
am --> 模型: ✗ L14 [flow] 缺少节点标签 + 正确示例
模型 → 模型: 按示例修正 flow 图表语法

am --> 模型: ✓ 页面路径 ~/.answer-me-with-html/pages/xxx.html
⚠ 常见错误类型

DESIGN · 设计理念

Karpathy Ladder 第 4 层 + Token 节省的本质

answer-me-with-html 的出现有清晰的逻辑链：LLM 能生成可读输出 → 但输出本身成为新的等待成本 → 分离内容与渲染 → 模型只写核心信息，CLI 完成布局和画图。

Karpathy Ladder · LLM 输出理解阶梯

  • Level 1: Text · 纯文本，最原始形式
  • Level 2: Markdown · 结构化，但仍是文本
  • Level 3: HTML · 可渲染，但模型要写 CSS/SVG
  • Level 4: 可视化解释页面 · answer-me-with-html 让 Agent 到达这一层

Karpathy 在推文中指出：随着 LLM 承担更多工作，理解其输出成为瓶颈。图解或网页比长文本更易理解。

Token 节省的本质

  • 直接要 HTML → 模型写 HTML 标签、CSS 样式、SVG 坐标 → 全部是输出 token
  • 用 answer-me-with-html → 模型只写 Markdown 内容（~900 token）
  • CLI 写 CSS/布局/SVG（本地执行，不计入输出 token）

省的是等待时间，不是钱。因为多了两步短调用（加载 skill + 运行 CLI），每步都重读上下文，账单基本不变。

✓ 单文件无依赖

每页输出为单个 .html 文件，无 CDN 链接、无 web fonts、无外部依赖。离线可开，易于分享。页面底部嵌入原始 Markdown 源码，点击「Copy source」可导出。

COMPARISON · 与同类工具对比

直接输出 HTML vs Mermaid vs D2 vs answer-me-with-html

市面上有多种让 Agent 输出可读图表的方式。以下对比各自取舍。

工具输出形式模型工作量Token 消耗维护方适合场景
直接输出 HTMLHTML 文件写 HTML + CSS + SVG高（6,000-9,000 token/页）模型自己自定义样式强需求
Mermaid / PlantUML图表代码写图表 DSL中（~500 token）Mermaid 社区简单流程/时序图
D2（Terrastruct）图表代码写 D2 语言中（~400 token）D2 社区架构图、依赖图
answer-me-with-html可读页面 + 图表写 Markdown 内容低（~900 token/页）项目维护者复杂解释、多组件、需要写作检查

Mermaid 的局限

  • 支持：流程图、时序图、ER 图、甘特图
  • 不支持：文件夹树、状态图、limits、annot
  • 渲染依赖 CDN（不独立）
  • 无写作检查机制

D2 的局限

  • 强于架构图和依赖关系
  • 时序图能力弱于 Mermaid
  • 需要本地安装 D2 二进制
  • Agent 仍要学 D2 语法

answer-me-with-html 的取舍

  • ✓ Token 消耗最低（7.4× 减少）
  • ✓ 内置 8 种组件，覆盖常用场景
  • ✓ STE 写作检查（其他工具无）
  • ✗ 组件类型固定，不能完全自定义
  • ✗ 需通过 Agent 使用
