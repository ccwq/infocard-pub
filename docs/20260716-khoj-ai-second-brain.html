Khoj：把你读过的东西
重新找回来别让笔记、PDF 和旧想法只在硬盘里“死”着

把 Markdown、PDF、Word、Notion 等资料交给 Khoj，它可以在你的文档上做问答、语义搜索与研究辅助。真正的价值不是“又一个聊天框”，而是让 AI 终于知道你过去积累过什么。

01核心定位

  • 从“存过”到“找得到”
    不靠文件名回忆，直接用自然语言描述你要找的内容。
  • 从零散资料到研究搭子
    在你的文档与互联网内容上对话，辅助整理、回顾与研究。
  • 从单一模型到自由组合
    README 明确列出 llama3、qwen、gemma、mistral，以及 GPT、Claude、Gemini、DeepSeek 等模型。

02资料如何进入系统

  • 本地文件
    PDF、Markdown、Word、org-mode 等文档可作为知识来源。
  • 知识入口
    浏览器、Obsidian、Emacs、桌面端、手机和 WhatsApp 均列在官方 README 的访问方式中。
  • 自托管
    可以在自己的电脑上私有运行，也可以使用官方云端应用。

03三步半上手路径

① 集中资料把 Obsidian 笔记、Markdown、PDF 和旧文档整理到可管理的位置。
② 选择部署按官方 setup 文档选择桌面端、自托管或云端体验。
③ 接入模型选择在线模型或本地模型；隐私敏感资料优先评估本地方案。
½ 开始提问用自然语言找资料、追问关联、生成研究线索。

04能力地图：别把它只当聊天框

能力你可以怎么用证据口径
语义搜索问“我以前在哪看过关于本地推理的内容？”，让系统按意义而不是关键词找资料。README 明确写 advanced semantic search。
文档问答围绕自己的 PDF、Markdown 或其他文档继续追问。README 明确列出 docs 与多种文件格式。
自定义 Agent配置自定义知识、persona、聊天模型和工具，做特定研究角色。README 明确列出 custom knowledge / persona / tools。
自动化研究把重复研究、个人 newsletter 和智能通知交给工作流。README 明确列出相关能力，具体配置以官方文档为准。

05适合谁

  • 长期积累资料的人：笔记多，但经常忘记自己写过什么。
  • 研究型工作者：需要把旧文档、论文和新问题串起来。
  • 隐私敏感用户：希望掌握部署位置与模型选择权。

06先看清边界

不要直接照抄传播文案里的环境细节。
“pip install khoj”“localhost:42110”以及“Obsidian 自动同步”等说法需要按当前版本官方文档核对；本卡只把 README/API 已确认的能力写成确定事实。部署前还应评估模型服务、索引数据与隐私边界。

07快速行动清单

先试用打开 app.khoj.dev，确认它是否适合你的资料问答习惯。
再自托管阅读 官方 setup 文档，按当前版本选择安装路径。
最后接入从一小批非敏感资料开始，验证召回质量、模型成本与隐私边界，再扩大资料范围。
