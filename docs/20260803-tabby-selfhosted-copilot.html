01

定位：为什么需要 Tabby？

Tabby 是开源的自托管代码补全引擎，提供与 GitHub Copilot 类似的实时代码补全体验，所有数据处理在自有服务器完成，满足数据合规要求。

核心价值

企业/团队无需将代码发送给第三方 API → 代码不离开内网，同时获得 AI 辅助编码能力。

适用场景

  • ✅ 企业内网，禁止代码出境
  • ✅ 金融/医疗/政务等高合规行业
  • ✅ 团队想私有化部署定制模型
  • ✅ 想节省 Copilot 订阅费

不适用的场景

  • ❌ 个人用户（直接用 Copilot/Cursor）
  • ❌ 需要最顶级模型效果
  • ❌ 没有 GPU/服务器资源

04

部署：从 Docker 到生产级

Docker 单机部署（5 分钟）

# 拉取镜像 docker pull tabbyml/tabby # 启动（使用 StarCoder 1B，CPU 即可） docker run -it \ --publish 8080:8080 \ --volume ~/.tabby:/tabby \ tabbyml/tabby \ serve --model StarCoder-1B # 浏览器打开 http://localhost:8080 配置

GPU 部署（推荐）

docker run --gpus all \ --publish 8080:8080 \ --volume ~/.tabby:/tabby \ tabbyml/tabby \ serve --model TabbyML/DeepSeek-Coder-1.3B

Kubernetes Helm

helm install tabby tabbyml/tabby \ --set model.repository=TabbyML/DeepSeek-Coder-1.3B
05

IDE 接入与推荐组合

VSCode

code --install-extension tabbyml.tabby # Settings → Tabby → Endpoint + API Key

JetBrains

Settings → Plugins → 搜索 Tabby # 配置 Endpoint + API Key

Neovim

use { "TabbyML/tabby.nvim" }

推荐组合

  • ✅ Tabby（补全）+ Ollama 本地 LLM
  • ✅ = 完全免费、合规的 Copilot 替代
  • ✅ 支持 OpenAI 兼容 API，灵活切换后端
OpenAI 兼容：Tabby 支持任何 OpenAI 兼容 API（Ollama / vLLM / Azure OpenAI），只需修改 Endpoint。
⚠️ 注意事项
🤖 模型质量
自托管模型与 GPT-4 存在明显差距，补全准确率约为 Copilot 的 70-80%。
💻 硬件要求
1B 模型最低 4GB VRAM，7B+ 模型建议 16GB+ VRAM。无 GPU 时 CPU 推理体验较差。
🔧 运维成本
需要维护 GPU 服务器和 Tabby 实例。
