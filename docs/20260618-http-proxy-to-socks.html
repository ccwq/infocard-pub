SOCKS → HTTP bridge manual

hpts 把 SOCKS 代理翻译成 HTTP 入口

这是一个极小但实用的 Node.js 桥接器：上游吃 SOCKS5，下游对外暴露 HTTP proxy。当 npm、Docker、系统代理或只认 HTTP 代理的客户端无法直接接入 SOCKS 时，它就是最短路径。

npm install -g http-proxy-to-socks
CLI 命令：hpts 默认监听：127.0.0.1:8080 默认上游：127.0.0.1:1080
proxy route mapv1.1.5

定位

不是代理客户端，而是协议翻译层

它不负责给你建立加密隧道，也不负责节点管理。它做的事情更窄：把“只会配 HTTP 代理”的客户端流量，转交给已经存在的 SOCKS 代理服务。

npmdockerapmsystem proxyios proxy
能力

同时覆盖普通 HTTP 请求和 HTTPS CONNECT

源码里既有 requestListener，也有 connectListener。前者处理普通 HTTP 请求，后者通过 SOCKS 建立 CONNECT 隧道，适配 HTTPS 代理流量。

  • requesthttp.request + socks-proxy-agent
  • connectSocksClient.createConnection
  • logswinston + info/error 两级
边界

默认很克制，配置面也很小

CLI 真正暴露给用户的参数并不多：上游 SOCKS、监听端口、监听地址、配置文件、日志级别。优点是上手快，缺点是高级策略很少，适合做“桥”而不是做“网关”。

上手方式

至少 4 种常见使用法

01

最小启动： hpts -s 127.0.0.1:1080 -p 8080。本地开一个 HTTP 代理，转发到本地 SOCKS。

02

自定义绑定地址： hpts -s 127.0.0.1:1080 -p 8080 -l 0.0.0.0。把 HTTP 代理暴露给局域网其他设备。

03

配置文件模式： 用 -c config.json 把常驻参数落盘，适合长期运行或配合守护进程。

04

程序化调用： 作为库引入 createServer(options)，在 Node 服务里内嵌代理桥。

典型命令
# 安装
npm install -g http-proxy-to-socks

# 最小示例
hpts -s 127.0.0.1:1080 -p 8080

# 绑定所有网卡
hpts -s 127.0.0.1:1080 -p 8080 -l 0.0.0.0

# 使用配置文件
hpts -c ./hpts.config.json

# 显示详细日志
hpts -s 127.0.0.1:1080 -p 8080 --level info
启动输出源码中的启动提示是：SOCKS: ... 和 http-proxy listening: host:port，可直接用于肉眼确认绑定是否正确。
参数手册

CLI 参数与默认值

参数默认值作用示例
-s, --socks127.0.0.1:1080指定上游 SOCKS 代理地址。源码解析支持 host:port，也支持 host:port:user:pass 四段格式。-s 10.0.0.2:1080
-s 10.0.0.2:1080:alice:secret
-p, --port8080指定对外暴露的 HTTP 代理监听端口。-p 7890
-l, --host127.0.0.1指定 HTTP 代理监听地址。默认只本机可用；改为 0.0.0.0 可供局域网访问。-l 0.0.0.0
-c, --config无从 JSON 文件读取配置，适合常驻部署。CLI 先读命令行，再用文件对象覆盖。-c ./hpts.config.json
--level默认 logger 为 warn；可切到 info/error控制日志级别。源码帮助文本写明允许值是 info 与 error。--level info
-V, --version无输出版本号。hpts -V
-h, --help无输出帮助。hpts --help
阅读方式桌面端应尽量一次看全参数矩阵；移动端则允许表格容器独立横向滚动，但不能通过缩小整页来伪装适配通过。
配置文件

JSON 方式适合守护运行

{
  "socks": "127.0.0.1:1080",
  "port": 8080,
  "host": "127.0.0.1",
  "level": "info"
}
覆盖顺序CLI 会先收集命令行参数，然后在检测到 config 后读取文件对象并 Object.assign(options, fileConfig)。也就是：配置文件会覆盖同名命令行值。
程序化 API

不仅是 CLI，也能被 Node 代码直接调用

包的 main 指向 lib/server.js，导出 createServer。如果你想把它嵌进自己的服务，可以直接在 Node 里起桥接器。

const { createServer } = require('http-proxy-to-socks');

createServer({
  socks: '127.0.0.1:1080',
  port: 8080,
  host: '127.0.0.1',
  level: 'info'
});
源码细节

库模式比 CLI 多一个代理列表维度

底层 ProxyServer 还支持 socksList 和 proxyListReloadTimeout：可以从文件加载多个 SOCKS 条目，并按间隔重载。不过这组能力并未直接暴露为 CLI 参数，更适合二次封装。

  • socksList代理列表文件
  • proxyListReloadTimeout默认 60 秒重载一次
  • randomElement请求时随机选择一个上游代理
风险提醒

局域网暴露要自己补安全边界

如果你把监听地址放到 0.0.0.0，这就是一个可被局域网访问的 HTTP 代理入口。工具本身没有额外鉴权、ACL 或配额控制，适合可信环境，不适合裸奔公网。

何时该用

最适合“上游已有 SOCKS、下游只认 HTTP”的缝合场景

A

本机已有 Shadowsocks / SOCKS5 服务，但 npm、Docker、某些桌面工具只支持 HTTP 代理。

B

你不想换客户端，也不想写一层自定义代理，只想把协议翻译打通。

C

你需要一个足够轻的桥，方便临时开、快速关、脚本里直接调用。

一句话结论
结论hpts 不是功能复杂的代理平台，而是一个很纯粹的协议桥：SOCKS in the back, HTTP in the front。如果你要的是“让旧客户端立刻吃上 SOCKS 能力”，它的性价比很高。
