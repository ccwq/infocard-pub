微软正式把 Agent Skills 的 Python API 推入生产级——可以用标准 API 给 Python agent 加载按需领域知识包，不再是实验性功能。

生产级 按需加载 标准 API
01
四阶段加载流程

渐进式加载：按需注入领域知识

agent 只在需要时才加载完整指令，上下文字段始终保持精简。

Step 1

advertise name

声明 Skill 名称与能力描述，agent 感知可用性。

按需发现，无需全量注册。

Step 2

load instructions

加载 Skill 指令集（SKILL.md 内容）。

仅在 agent 判定需要时触发。

Step 3

read resources

读取参考资料（文档、数据文件等）。

支持多资源并行按需加载。

Step 4

run scripts

执行业务脚本，完成特定任务。

最后一步，完成端到端 Skill 调用。

02
三种定义方式

灵活定义：文件型 / 代码型 / YAML 声明

适应不同场景：跨团队维护、动态生成、框架专属配置。

文件型

SKILL.md + 脚本 + 资料

以 Markdown 文件为核心，可附加脚本和参考资料。适合跨团队维护的标准化 Skill 包。

  • SKILL.md：主指令文档
  • 可选脚本：业务逻辑
  • 参考资料：数据/文档
代码定义

直接在 Python 代码中创建

通过 Python API 动态构造 Skill 实例，适合需要动态生成或上下文敏感的 Skill 场景。

  • 动态构造，无需磁盘文件
  • 适合运行时生成
  • 可注入上下文变量
YAML 声明

Agent Framework 专属配置

使用 YAML 声明 Skill 元数据，由框架解析并挂载到 agent。适合框架原生的标准化场景。

  • 声明式配置
  • 框架解析挂载
  • 适合工程化管理
03
HiTL 审批机制

Human-in-the-Loop：内置审批，无隐性自动执行

三种工具调用均默认需要人工审批，无隐性自动执行风险。

1

load_skill

加载 Skill 指令集——默认触发人工审批，agent 无法绕过。

2

read_skill_resource

读取 Skill 资源文件——默认需要审批，防止静默访问敏感数据。

3

run_skill_script

执行业务脚本——最后一道关卡，审批后才能执行外部操作。

关键设计原则：没有隐性自动执行——每一步都需要显式审批，确保 agent 的 Skill 调用始终在人类监督下进行。
