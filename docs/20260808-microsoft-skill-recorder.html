01 · 定位
WHY

它解决的是“示范到抽象”

传统屏幕录制留下的是视频，宏工具留下的是脆弱的点击坐标，而 Skill Recorder 试图保留任务的目的、顺序和判断。你做一次“把网页资料整理进表格”的工作，分析器应将它理解为一类可泛化的知识工作，而不是只能回放同一页面。

不是坐标宏

输出优先使用 Agent 的原生能力，例如 gh CLI、web_fetch 或本机工具，而不是强依赖 Playwright 点击。

不是黑盒生成

Analyze 产生的描述可以先阅读、编辑、拒绝；Create 发生在批准之后。

02 · 工作流
LOOP

四步闭环，先示范再复用

01
Record · 录制从一个可控、低风险、能代表日常工作的任务开始。全局快捷键为 macOS 的 ⌘⇧R、Windows 的 Ctrl+Shift+R。
02
Control · 控制录制期间通过置顶控制条查看状态、切换麦克风、结束或放弃本次录制。
03
Analyze · 分析Copilot 根据事件时间线、必要的画面和可选旁白，重构总体意图与有序步骤。
04
Create · 创建确认分析正确后，生成 SKILL.md 或 automation.json；不要跳过人工审阅。
03 · 产物
OUTPUT

两个结果，两个使用方式

Skill · 按需调用

SKILL.md 描述一套 Agent 可按需执行的程序。适合重复但不一定定时的流程，例如查资料、整理记录、处理一类表单。

Automation · 定时或触发

automation.json 表达同一套流程的自动化版本，适合计划任务或触发式执行；仍应审查权限、输入和失败回退。

平台边界

README 当前列出 Scout Skill、Copilot Cowork Skill、Scout Automation；Copilot Studio 标注为 Coming soon，不能当作当前可用输出。

04 · 获取与安装
SOURCE

源码安装：先锁定 Release commit

Skill Recorder 发布的是 source release。安装命令要求使用最新 Release 提供的完整 40 位 commit SHA；同一个 SHA 同时固定安装脚本和被构建的源码。不要把 main、master、分支名或未经核验的 tag 当作版本。

# macOS / Ubuntu（把占位符替换为 latest release 的完整 SHA） commit="<40-character-release-commit>"; curl -fsSL \ "https://raw.githubusercontent.com/microsoft/skill-recorder/$commit/install.sh" \ | SKILL_RECORDER_COMMIT="$commit" bash # Windows 11 x64 / ARM64 $commit="<40-character-release-commit>"; \ $env:SKILL_RECORDER_COMMIT=$commit; \ irm "https://raw.githubusercontent.com/microsoft/skill-recorder/$commit/install.ps1" | iex

安装器会下载 Node.js 24、取回精确源码、执行依赖与许可证检查、构建本机版本，并创建启动入口；不需要全局安装 Node.js 或 Copilot CLI。

05 · 第一次使用
FIRST RUN

用“低风险任务”验证闭环

Step 1 · 准备清空桌面、浏览器和剪贴板中的秘密；macOS 首次启动授予屏幕录制权限。
Step 2 · 示范录制一个可重复任务，例如从公开页面摘取资料并整理到测试表格。
Step 3 · 审阅检查总体意图、步骤顺序、应用归属、遗漏和是否把无关动作当成任务。
Step 4 · 复现用相邻输入再次运行生成的 Skill；不泛化就退回修改，而不是直接排程。

07 · 数据流与隐私
GOVERNANCE

“本地录制”不等于“全流程离线”

官方说明将边界拆成两个时刻：录制期间，录制、存储、帧提取和可选旁白转录在你的电脑上完成；只有你主动点击 Analyze 后，分析所需的数据才会发送到 GitHub 云端，由 Copilot 处理。这个差异是企业试用前必须向安全和合规团队说明的事实。

窗口追踪活动应用与窗口切换
浏览器 URLmacOS 页面地址
屏幕图像画面变化时的低帧率快照
剪贴板用于串联步骤的短预览

安全底线

不要在录制中展示、输入、粘贴、复制或口述密码、访问令牌、API Key、登录凭据、客户资料或其他机密。录制前先切换到合成数据；如果一次录制已经接触秘密，应丢弃而不是点击 Analyze。

08 · 评测
EVALS

测“还原正确”，不是测视频好看

仓库提供 fixture-based eval：将固定的合成事件流喂给真实 describer，隔离屏幕捕获的不稳定性。评分关注意图关键词、步骤数量、预期应用、动作顺序、必须提及的实体，以及是否误把录制器、权限弹窗或无关网页当成任务。

Describer eval

npm run eval 跑全部场景；可用 --only 选单场景，也可用 --judge 增加语义评审。

Builder eval

npm run eval:builder 固定一份已批准分析，再检查生成步骤是否优先使用本机原生工具，并能在 macOS/Windows 之间保持合理泛化。

09 · 适用性
FIT

什么时候值得用？

+
适合重复出现、步骤可解释、输入变化有限但不完全固定，并且可以用非敏感数据示范的知识工作。
+
适合团队希望把“专家知道怎么做”的隐性流程先写成可审阅草稿，再交给 Agent 维护和复用。
−
不适合高度依赖一次性页面状态、精确坐标、私密系统、不可逆提交，或无法脱敏的流程。
−
不适合把源代码安装器误当成预编译企业发行版，或要求完全离线分析的环境。
10 · 上线前检查
CHECKLIST

从 Demo 走向自动化

01
输入治理录制前清理秘密，确认窗口、URL、剪贴板和旁白的采集边界。
02
结果治理逐步审核生成的 Skill，明确它能读什么、写什么、提交什么。
03
泛化评测至少用多个脱敏样本验证顺序、异常路径、无关动作过滤和工具选择。
04
运行回退为失败、权限不足、页面变化和过期凭据设计人工接管，不让 Automation 静默扩大权限。
DECISION SUMMARY

推荐的最小试验路径

公开数据 → 一次短任务 → Analyze → 人工编辑 → 相邻任务复现 → 再决定是否 Create Automation。 这条路径同时验证了产品的核心承诺：它能否把一次具体操作抽象成稳定意图，能否优先选择本机原生工具，以及组织是否接受 Analyze 的云端数据边界。
