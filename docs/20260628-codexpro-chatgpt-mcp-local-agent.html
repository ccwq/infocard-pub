一句话定位
CodexPro 是一个MCP 中转工具：把 ChatGPT Plus/Pro 网页版的 Developer Mode（官方合规通道）桥接到本地仓库，让 GPT-4o / 5.5 级模型通过 MCP 协议操作本地代码文件——不是 API 替代品，而是用你已有的 Plus 订阅富余额度做本地代码代理。
技术架构
🤖
ChatGPT Plus/Pro
网页版 Developer Mode
🔌
MCP 中转协议
codexpro start + tunnel
💻
本地仓库
文件读写 + bash 验证
核心区别于反代：CodexPro 不绕过、不提升、不合并、不转售任何限制。它走的是 ChatGPT 官方 Developer Mode App 路径，所有请求通过你自己的 ChatGPT 会话，完全合规，OpenAI 官方认可。
前提条件
⚠️ 必须条件：拥有 ChatGPT Plus 或 Pro 账号，且账号必须能访问 Settings → Apps → Advanced settings → Developer mode。Free / Go 账号当前测试不支持此流程。
账号类型 支持状态 说明
ChatGPT Plus ✅ 支持 标准订阅，可正常使用 Developer Mode
ChatGPT Pro ✅ 完全支持 最高权限，含 o 系列推理模型
ChatGPT Free ❌ 不支持 当前测试不支持 App 创建流程
ChatGPT Go ❌ 不支持 当前测试不支持 App 创建流程
三种运行模式
🔧 Normal Coding
默认模式，ChatGPT 直接读写文件 + bash
codexpro start
📋 Handoff
ChatGPT 只写计划，本地执行器执行
codexpro start --mode handoff
🔒 Safe Bash
禁止 bash，仅读写文件，防止误执行
codexpro start --no-bash
💡 模式切换：Normal 模式下也可用 --bash-session main --require-bash-session 要求 ChatGPT 的 bash 调用必须带上 session_id: "main"，避免误触发到其他终端。

详细配置步骤（7 步）
① 安装 CodexPro CLI
需要 Node.js ≥20。推荐全局安装一次，之后每个仓库直接用 codexpro start。
npm install -g codexpro # 验证安装 codexpro --version # 期望输出类似: 0.28.5
② 进入本地仓库，运行初始化向导
进入你要让 ChatGPT 操作的本地项目目录，运行 setup。CodexPro 会引导你配置 tunnel 类型并自动复制 Server URL。
# 进入目标仓库 cd /path/to/your/project # 初始化设置（首次运行） codexpro setup # 交互式向导会问： # → 选择 tunnel：Cloudflare quick（快速demo）/ ngrok（稳定URL）/ Cloudflare named（自定义域名） # → 如果选 ngrok：输入你的 ngrok free dev domain # → 自动复制 Server URL 到剪贴板
③ ChatGPT 网页端开启 Developer Mode
在 ChatGPT 网页版（chatgpt.com）中依次打开以下设置路径。注意：Free 账号看不到这个路径。
ChatGPT Settings（设置） └── Apps（应用） └── Advanced settings（高级设置） └── Developer mode: ON ✅ └── Enforce CSP in developer mode: ON ✅
CSP（Content Security Policy）必须保持开启。CodexPro 的卡片和小组件按 CSP 开启的路径设计，不需要远程脚本或外部字体。
④ 在 ChatGPT 中创建 CodexPro App
在 Developer Mode 开启后，点击 Create app，填写连接信息，把 CodexPro 的 Server URL 粘贴进去。
# Create App 页面填写： Name: CodexPro Description: Local workspace bridge for ChatGPT coding Connection: Server URL Server URL: 粘贴第②步复制的 URL（含 codexpro_token） Authentication: No Authentication / None
⑤ 启动 CodexPro 进程
保持 CodexPro 进程运行，ChatGPT 才能连接本地仓库。停止进程后连接自动断开。
# 标准启动（Normal Coding 模式） codexpro start # 安全模式（禁止 bash，仅读写） codexpro start --no-bash # Handoff 模式（ChatGPT 只写计划，本地决定是否执行） codexpro start --mode handoff --no-bash # 查看帮助和常用命令 codexpro doctor codexpro settings
⚠️ 重要：停止 codexpro start 进程后，ChatGPT 立即失去本地仓库访问权限。Cloudflare quick tunnel 每次重启 URL 会变，需要重新粘贴到 ChatGPT App 设置。
⑥ 每日复用（稳定 URL 配置）
用 ngrok free dev domain 固定 URL，避免每次重启手动改 ChatGPT App 设置。
# 先在 ngrok 注册免费账号，创建 free dev domain（如 your-name.ngrok-free.dev） # 然后在 setup 时选择 ngrok，输入你的 dev domain codexpro setup # → 选择 ngrok → 输入 your-name.ngrok-free.dev # 之后每日启动只需： codexpro start # Server URL 不变，ChatGPT App 无需重新配置
⑦ 验证连接是否正常
启动后在 ChatGPT 中确认 MCP 工具已加载，尝试让 AI 读取一个本地文件。
# 在 ChatGPT 对话中测试： # "请读取当前仓库的 package.json 文件" # "请列出当前目录的文件结构" # "请运行 git status" # 如果工具不可见，检查： # 1. CodexPro 进程是否还在运行 # 2. ChatGPT App 的 Server URL 是否最新（quick tunnel 每次变） # 3. Developer Mode 是否开启 codexpro doctor # 诊断常见连接问题
工具暴露级别
级别 启动参数 暴露工具数 适合场景
standard（默认） 无额外参数 少量高信号 日常编码，平衡稳定性
minimal --tool-mode minimal 极少 演示 / 教学，避免 ChatGPT 误用
full --tool-mode full 完整工具集 需要完整 Codex 兼容性的场景
💡 设计理念：CodexPro 默认故意暴露少量工具。ChatGPT 面对少量高信号工具时更稳定，输出质量更高。如果需要完整兼容，用 --tool-mode full。
与本地 Agent 协同（Handoff 模式）
🤖 Hermes + CodexPro 的典型工作流
CodexPro 的 Handoff 模式非常适合与 Hermes Agent、Claude Code、Codex CLI 协同：ChatGPT 负责高上下文规划和审查，本地 Agent 负责实际执行。
# 启动 Handoff 模式，ChatGPT 只写计划不执行 codexpro start --mode handoff --no-bash # ChatGPT 会把计划写入 .ai-bridge/current-plan.md # 本地 Agent（如 Hermes / Codex CLI）读取计划并执行 # 本地 Agent 执行后，将结果写回 ChatGPT codexpro execute-handoff --agent opencode --model provider/model --dry-run codexpro execute-handoff --agent opencode --model provider/model # 或启动监听器，仓库计划变更后自动执行 codexpro watch-handoff --agent opencode --model provider/model --yes
💡 最佳实践：ChatGPT 负责高层面架构设计、代码审查、计划制定；Codex CLI / OpenCode / Hermes Agent 在终端执行 git 操作、运行构建命令、写业务逻辑。两者互补，不重复消耗 Plus 额度。
