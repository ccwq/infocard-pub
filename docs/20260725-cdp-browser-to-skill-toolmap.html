一句话回答
是否有"探索网站 → 直接沉淀为 skill"的现成端到端工具？

没有——目前任何单一项目都不能把一段 CDP 浏览器操作录像自动转写为可重用 skill 脚本。最接近的链路仍需要"人跑一遍 + 写一段"。现有工具的边界很清晰：

  • CDP 操作端 已经成熟：BrowserStack、Steel、agent-browser、Playwright MCP 可以以毫秒级精度操控浏览器。
  • 任务级 Agent 已经成熟：OpenHands、Devin、Stagehand、browser-use 让 LLM 能"完成任务"。
  • 沉淀为可复用 skill 仍是空白：Chrome DevTools Recorder + Anthropic skill-creator + Hermes SKILL.md 三件套拼起来才近似"端到端"。
Hermes Agent 实际产出过的"操作手册型 skill"——xhs-cdp-extract、grok-imagine-cdp、chrome-automation-keyring-fix——都不是"自动从录像生成"，而是"人走一遍 + browser_* 工具 + 总结成 markdown"。

三段路径：探索 · 操作 · 沉淀
1
探索 Discovery：通过 browser_navigate + browser_snapshot / browser_vision / browser_console 把站点结构、登录态、表单字段一次性摸清。本机已有 Hermes browser_* 工具集可用，无需装新工具。常见替代品：Stagehand observe()、OpenHands Web Browsing、browser-use high-level task。
2
操作 Operation：通过 CDP（Chrome DevTools Protocol）对已登录的 Chrome 实例发起 navigate / click / type / select / eval / upload。底层走 agent-browser CLI 或 Hermes browser_cdp + Input.dispatchMouseEvent。要点：单 tab 独立、不要覆盖活动页（tab new 而不是 tab close --all）。
3
沉淀 Crystallize：把操作经验和踩坑点写成 ~/.hermes/skills/<category>/<name>/SKILL.md。结构上必须含：目标、适用边界、URL 校验、防 Cookie 弹窗、坐标偏移兜底、验收清单、版本历史。Hermes 的"学习循环"会把它固化为下次复用。
缺失的"端到端"环节正是把步骤 2 的 CDP 调用直接编译为步骤 3 的 skill 文档。目前这一步必须人写。即使 Chrome DevTools Recorder 导出 Puppeteer JSON，也不能直接产出可在 Hermes / Claude / Codex 复用的 SKILL.md。

深度拆解：5 个最契合"探索 → 沉淀"工作流的方案
1 · Hermes Agent + browser_* + skill_manage

路径：Hermes 内置 browser_navigate / browser_snapshot / browser_click / browser_type / browser_press / browser_vision / browser_console / browser_cdp 工具集 + skill_manage 元技能 → 在同一会话里把操作总结为 SKILL.md。

已验证的产出（本机）：

  • xhs-cdp-extract：小红书轮播图抽取、OCR、整理为 summary.md。
  • grok-imagine-cdp：grok.com/imagine 写 prompt、点生成、下载 CDN URL。
  • chrome-automation-keyring-fix：CDP 启动 Chrome + GNOME Keyring 拦截排错。

沉淀格式：~/.hermes/skills/<category>/<name>/SKILL.md（YAML frontmatter + Markdown body）。

2 · agent-browser（vercel-labs · 39k ★）

定位："AI agent 的浏览器原子操作 CLI"。原子到 click/type/fill/press/select/upload/scrollintoview/eval/drag 全部一行命令。

CDP 协议路径：agent-browser --cdp 9222 tab new <URL> 直接接管已登录 Chrome，比启动新 Chrome 快 5-20 倍。

沉淀能力：本身不沉淀，但它的 snapshot 命令可输出完整可访问树（refs 引用），用于回放与对照。其命令式风格是"自动生成 skill"的天然素材。

缺点：原子粒度过细，单个任务要写一长串，缺高级 API（不能直接说"打开微博热搜"）。

3 · browser-use（106k ★）

定位："python -m browser-use '在 Hacker News 抓前 5 条新闻'"。LLM 解读 DOM，直接完成任务。

CDP 路径：底层走 Playwright，但 agent-browser 不直接调用 CDP——它走的是 Python 封装 + DOM 解析。

沉淀能力：单条指令一次跑完，不沉淀步骤。要复现同一流程必须重新提示。

缺点：对登录态、强反爬站点（小红书、TikTok、抖音视频号）容易撞验证码或 IP 风控；缺乏"已登录 tab"复用入口。

4 · Stagehand（Browserbase · 23k ★）

定位："AI 原生浏览器自动化 SDK"。四种原语：

  • act('点击"登录"按钮') — LLM 动作
  • extract('返回 title、点赞数') — 结构化抽取
  • observe() — 自主规划观察
  • agent('完成 X') — 链式多步

沉淀能力：cache() 可保存某一步返回的 DOM 状态，配合 act("click X") 可在多次执行间复用同一缓存。仍然不能让脚本自动转 SKILL.md。

配套：Stagehand + Browserbase（云端 Chrome，session replay + stealth mode）；云端付费、本地自托管免费。

5 · Chrome DevTools Recorder（Google 内置）

定位："浏览器自带操作录像机"。DevTools → Recorder → Start recording → 操作完成 → Stop。导出格式：@puppeteer/replay JSON 序列。

CDP 路径：直接录制 DOM/CDP 事件流；不会自动转写为 LLM 友好的 skill。

沉淀能力：JSON 可被 chrome-recorder-puppeteer 转换为 puppeteer.launch() 脚本；与 SKILL.md 之间还有写作间隔。

最佳组合：Recorder 录像 → chrome-recorder-puppeteer 转脚本 → Hermes 内手动总结 → SKILL.md。这条路径目前最接近"端到端"。

每个方案的优缺点
浏览器 SDK · 原子层

agent-browser：CLI 原子粒度，直接吃 CDP，不启动新浏览器，复用现有 Chrome 登录态。Apache-2.0 可商用。

Playwright MCP：官方 MCP 服务器，accessibility-snapshot 而非截图，速度与稳定性都远胜视觉方案。

Chrome DevTools Recorder：浏览器自带录像机，零安装门槛，导出 JSON 可回放可重构。

Playwright codegen：录制 → 直接生成 *.spec.ts；测试场景下几乎是同类最佳。

浏览器 SDK · 痛点

多数 SDK 只解决"操作"环节，沉淀为 skill 仍要人写。

对登录态、强反爬站点无内置方案。

SVG / Shadow DOM 路由复杂。

跨域 cookie、HttpOnly cookie 无法在 terminal 端伪造（已被 Cloudflare 等平台利用）。

任务级 Agent

browser-use：自然语言驱动的端到端 task；学习曲线最低；浏览器操作高手级 demo（WebArena 榜首）。

Stagehand：act / extract / observe / agent 四种原语分明，JS/TS 友好，Browserbase 配套最完整。

OpenHands：完整 GUI（含 terminal + 编辑器 + 浏览器），适合复杂多步任务（SWE-bench 强项）。

Skyvern：视觉路线对 shadow DOM 友好，workflow.yaml 可固化。

任务级 Agent · 痛点

不沉淀。同一条 task 不同次跑的步骤可能不同，难以审核。

依赖 LLM 决策，成本高（一次多步任务可能 5-50 美分）。

黑盒不可复用：失败时定位很慢。

Devin、Anchor 闭源，踩坑无法回退。

视觉 / RPA / 沉淀路径

Midscene：视觉坐标点击，对 shadow DOM 友好（抖音视频号后台的 wujie 结构）。

Automa / reBrowser：浏览器扩展层录制操作流，可视化工作流。

Hermes Agent skill_manage：把任意已跑通流程沉淀为 SKILL.md，下次由同一 Hermes 会话自动加载。

Anthropic skill-creator：5 步标准化流程创建 Skill，对"已有流程生成 SKILL.md"友好。

视觉 / RPA · 痛点

视觉坐标对窗口缩放、字体大小、高 DPR 屏幕敏感。

浏览器扩展 layer 在企业限制、零扩展环境下不可用。

国内 RPA 工具链（云扩/UiBot）闭源、与现代 LLM 弱对接。

沉淀格式互不相通——Hermes / Claude / Codex / 千问 / Hermes 各自一套。

"陷阱与排查"段落必须含：Cookie 弹窗、SVG 按钮拦截、临时签名 URL、TipTap 段落、键盘弹起导致的坐标偏移

高频陷阱 · 在所有方案中都会遇到
Cookie 弹窗遮挡 → 必须先关闭（grok.com 是典型案例）
SVG 按钮被内部元素拦截 → CDP 坐标点击失效，改 dispatchEvent
临时签名 URL 过期（Cloudflare 等） → 30 秒内下载，否则 403
TipTap / 编辑器刷新 DOM → 写入前必须重新 querySelector
键盘弹起导致坐标偏移 → 用 elementFromPoint 重新定位
CDP 浏览器共享 tab，命中上一个会话的登录态 → 显式 tab new
shadow DOM 里 atomNotVisible → 必须切换到视觉路线
HttpOnly cookie 不可被 terminal 伪造 → 必须走浏览器下载
验证清单 / 失败兜底
必须满足

URL 校验：每次 navigate 后立即 window.location.href，确认进入目标站而非上一个 tab 的页面。

专属 tab：使用 tab new，关闭时只关自己的 tab，禁止 close --all。

关键数据分层：页面 / DOM / 截图 / OCR / 网络补充分别落到不同文件，不混为单一事实。

临时清理：/tmp/*-extract 等路径用完即删；保留用户要的最终产物即可。

停止并报告（不替用户决策）

滑块 / 验证码 / 人脸验证

账号私有 / 删除 / 无权访问

页面只显示占位骨架且等待后仍无正文

CDP 浏览器共享状态污染：用 browser_navigate('about:blank') 清场后重试
