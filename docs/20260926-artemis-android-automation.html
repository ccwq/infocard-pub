02推文没讲的三个关键设计

APro 档的"事故"恢复模型——动作被阻塞或失败时开一个 execution incident，留在 Operator 上下文里直到后续动作成功——恢复由 Operator 自己做，没有单独的修复 agent。对比常见"失败就换修复 agent"的两段式，这是把恢复当连续谱而不是切换。
BExplorer 档位是用户配置，不是 agent 自选——Operator 的感知子层 Explorer 有 flash/pro/ultra 三档，README 用了加粗强调："never chosen by the agent"，在 config/artemis.jsonc 或 --explorer-pro-mode 里由人定。默认模型 gemini-3.8-flash（fallback 3.7-flash），多模型引擎支持 Claude/GPT-4o/OpenRouter/Vertex。
C历史压缩换无限步数——Flash 默认不限步数（max_turns=0），靠把旧截图折叠成视觉摘要、已完成步骤压成可检索的 era 块（search_history/replay_steps）控制上下文，还接 video_analyzer 查会话录像。瞬时 UI（自动消失的控制条、toast）用 click_sequence 连点处理。

03上手：三行命令到真机（Quick Start 照录）

前置：一台开了 USB Debugging 的 Android 真机或模拟器。一键脚本自动装 ADB、scrcpy、FFmpeg 和 Python（uv）依赖，并提示把全局 MCP 配置和"Mobile Testing Mindset"规则文件装进检测到的 IDE：

git clone https://github.com/google/artemis.git && cd artemis
./start.sh          # macOS / Linux（Windows 用 .\start.bat）
# 浏览器打开 http://localhost:8000：设备连接向导+实时投屏+prompt 沙箱+执行回放

四种用法按场景选：Web 控制台（uv run artemis ui，实时推理遥测/动作轨迹/回放，artemis restart/stop/status 管生命周期）；MCP server（IDE 里直接驱真机）；CLI（uv run artemis run "打开设置找到电池告诉我电量" --profile flash）；Python SDK（artemis-client 零运行时依赖，Pydantic 强类型输出，进 pytest/CI）。

MCP 里的 5 个工具（IDE agent 的全部界面）

工具作用
mobile_run_task异步启动任务（Flash/Pro），可带 device_serial；Pro 可调 verification_level（off/final/checkpoints/strict）和 explorer_mode
mobile_manage_task任务生命周期：status/stop/inject_instruction；结束 [Loop:continuous] 监控任务必须用 release_loop=True 显式信号，说"请停止"不算
mobile_get_device_state实时观察：screenshot 或 OCR+XML hierarchy
mobile_inspect_trace细粒度 trace：视觉动作叠加、agent 推理回放
mobile_diagnoseIDE 里的环境医生：返回 verdict（ready/degraded/blocked）+ 可执行的 next_steps；深查项 verify_credentials（约 12s）/ probe_device（约 20s）/ launch_avd；attempt_fix=true 自动再生 ADB 密钥、重启 ADB、清崩溃残留锁

异步任务跑在 detached 后台进程，完成/失败时全通道通知：Antigravity 里直接 agentapi send-message 唤醒会话；Cursor/Windsurf/VS Code/Cline/Roo 默认弹系统 toast + 审计文件。多设备并行：显式 device_serial 按设备执行锁并行，缺省自动选就绪设备。

04Flash vs Pro 怎么选（官方边界照录）

Flash（3–5s/步）Pro（15–40s/步）
形态单模型 observe-think-act 反应式循环，无图编排多 agent 图：Planner + Operator + 只读 Checker
计划无任务计划/笔记活 Markdown 计划，里程碑带 verify/assert 检查项
安全网无预执行校验每个动作过 Safety Net（XML 优先、像素兜底）
核验无 checkpoint/最终报告、无 ADB shellChecker 四档核验（off/final默认/checkpoints/strict）+ 可选书面报告
适用常规确定性 UI 任务；上下文靠压缩不设上限100+ 步长流程、[Loop:continuous] 监控、稳定性测试

Agent 侧还配了一份 rules.md（Mobile Testing Mindset，五章）：核心是"Runnable Code Principle"——不许猜不许幻觉 UI 跳转，动手前先探索；加上 Flash/Pro 路由策略、延迟与时序补偿、"Dynamic-First, Coordinate-Fallback"定位哲学。README 特别提醒 Claude Code 用户：规则装到 ~/.claude/rules/artemis.md 一个位置就够——Claude Code 同时加载 CLAUDE.md 和 rules/*.md，重复装浪费上下文。

05冷静面与判断

四个折扣点：① 99%+ 是官方自述，AndroidWorld 官方榜单页暂无 artemis 条目（榜单上另有团队刷到 100%，说明该基准头部已卷满，99% 是第一梯队而非断崖领先）；② 仓库 2026-08-13 才创建、无 release/tag，API 与配置仍在快速变动（pushed 09-12）；③ 仅 Android，iOS 在 Roadmap；④ 包含第三方 Minitap mobile-use 源码，审计时别只看 google org 就当纯 Google 血统。

判断：这是"AI 编码 agent × 真机测试"交汇处目前工程完成度最高的开源方案——五种用法覆盖从手工到 CI，MCP 五工具+环境医生+自愈把"IDE 里使唤手机"做成了闭环；读屏助手的隐私交代（本地监听、可卸载、可换后端）在同类项目里罕见地诚实。做 Android 研发/测试流水线的团队值得现在就试 Flash 档；想把它当通用手机 agent 用的，等 release 节奏稳定再上生产。
