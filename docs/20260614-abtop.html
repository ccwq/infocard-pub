它到底在看什么：五类最关键的监控面板

abtop 的重点不是“漂亮图表”，而是把最容易失控的 AI 编码工作流指标放在一起：会话、限额、上下文、子进程和端口。

tokensstatus

03

快速开始与使用边界

abtop 的入口很轻，真正的重点是：先看总览，再做细分排障，不要把它当成要改系统状态的管理器。

安装 / 运行

curl --proto '=https' --tlsv1.2 -LsSf \
  https://github.com/graykode/abtop/releases/latest/download/abtop-installer.sh | sh

cargo install abtop

abtop                 # 进入 TUI
abtop --once          # 打印快照后退出
abtop --json          # 输出 JSON 快照

常用快捷键

截图里的交互逻辑非常清晰：`r` 刷新、`s` 排序、`f` 过滤、`?` 帮助、`q` 退出。它更像一个可操作的观察面板。

r refreshs sortf filter? helpq quit

适合谁，不适合谁

  • 适合：同时开多个 AI coding agents、又要盯 token / context / 端口 / 子进程的人。
  • 适合：需要本地只读监控，不想把数据送到外部服务的人。
  • 不适合：只想要单一模型聊天窗口、没有多会话管理需求的人。
  • 不适合：希望它自动替你改配置、杀进程、提交代码的人——它本质上是看板，不是管家。
边界一句话：abtop 解决的是“看见并管理 AI Agent 的运行态”，不是“替你执行工作流”。它的强项是可视化和本地观测；你仍然需要自己决定该暂停、排序、过滤，还是继续让某个 session 跑下去。
