anything2explainer：把一个主题变成一条可验收的解释视频

它不是“输入一句话就自动出片”的 CLI，而是一套给 Claude Code / Codex 使用的 Remotion 生产方法：研究事实，写旁白，做逐镜头分镜，生成配音与字幕时间线，并行写镜头组件，渲染后按量化指标与章节逐轮 QC。

一条片子到底怎么出来？

把“解释一个主题”拆成可以并行、可以复查、可以重新渲染的工程流水线。

01 · evidence

先记住 3 个判断

适合解释机制，不适合复制既有视频或做真人主持。

固定规格

1280×720 / 30fps / H.264；横屏安全区规则写死在模板。

质量闭环

研究来源、分镜、镜头代码、渲染帧、QC 报告和 delivery notes 全部留痕。

关键代价

旁白锁定后改一句话会重新计时；并行构建至少预留约 5GB 磁盘。

01
IDENTITY · 它是什么

不是视频模型，而是“研究到成片”的 Agent 工程协议

仓库交付的是一套可编译的 Remotion 模板、动画原语和灯光库、语音/分镜/渲染/QC 工具、书面风格规范、多 Agent 分工协议，以及一部完整参考片。每一帧由 React + TypeScript 代码绘制，不依赖库存素材，也不调用生成式视频模型。

输入

一个主题（如“解释向量数据库”），或者一篇文章/文档；用户要先选择语言与片长。

topicdocument2–8 min

输出

1280×720 H.264 MP4，含同步旁白、按词边界对齐字幕、章节卡、顶部 HUD、底部章节进度条，以及完整研究和 QC 纸迹。

MP4subtitleschapters

核心区别

它把“好不好看”拆成可修改的 shot 文件，把“说得对不对”绑定到研究 URL，把“是否交付”交给渲染指标和章节 QC。

确定性代码，不是一次性像素。

先把运行环境和声音路径想清楚

仓库在 macOS 上开发与验证，Linux 理论上可用，Windows 未测试。不要把“能安装”误读成“所有平台都经过验证”。

03
PIPELINE · 九阶段

每一阶段的输入、交付物和停止点

渐进式使用不是“跑一个命令等结果”，而是四次人类检查点把成本放在最便宜的位置。

01–02

搭脚手架 → 研究

从 template 建项目；研究 Agent 输出带 URL 的调研文档，并列出数字与类比的来源。

没有来源的数字不上屏。
03–04

旁白 → 分镜

旁白先定稿，再生成 TTS、逐词边界、字幕表和一行一镜的 storyboard。

旁白改一个词，后续帧都会重排。
05–07

叠层 → 试片 → 并行构建

写标题、章节卡、HUD 和图标；先做首组与 30 秒 cut，再按每个 Agent 5–7 镜头并行。

先审 30 秒，别等全片。
08–09

渲染 → QC 修复

完整渲染，跑 frame metrics；每章配 QC Agent，修复后重验并交付 notes。

交付的是影片+纸迹。

检查点 1

片长与语言：决定行数、镜头数、并行 Agent 数。

检查点 2

旁白签字：声音生成前锁住文字和时间预算。

检查点 3

声音选择：默认中文 edge-tts，英文 kokoro；也可交自己的成品音频。

检查点 4

首 30 秒：先判断风格，避免全片完成后返工所有镜头。

配置不是装饰项：它会改变叙事预算、镜头数量、TTS、字幕策略和并行规模。

配置开关

  • lang: 'zh' | 'en'：切换字体、字幕预算、节奏和默认声音。
  • bg: 'stars' | 'dots'：两种背景；不是完整换主题。
  • 中文默认 zh-CN-YunxiNeural；英文默认 kokoro-82m am_liam。
  • 自定义音频放入 public/assets/<slug>/audio.wav，手填 timeline 与 subs。
  • 模板固定横屏 1280×720，当前没有 9:16 竖屏安全区。

05
FIRST RUN · 首次使用

用一个真实主题跑最小闭环

不要一上来做 8 分钟长片。先用 2–3 分钟、一个明确机制、两到三个章节完成一次可验收的试片。

最小输入

例如：“解释向量数据库，面向第一次接触 RAG 的前端工程师”。同时给语言、片长、受众和不应声称的边界。

人工动作

  1. 在检查点 1 选中文、2–3 分钟。
  2. 检查研究文档的 URL 与数字。
  3. 在检查点 2 锁定旁白。
  4. 看 30 秒 cut，再决定是否扩展。

成功定义

MP4 能播放；旁白、字幕和镜头同拍；章节进度与章节数一致；每个屏幕数字能回溯到研究 URL；QC 报告没有未处理项。

template/scripts/new_project.sh ~/work/my-video myslug
cd ~/work/my-video
python3 scripts/tts_build.py
python3 scripts/render_storyboard.py
scripts/preview.sh 30
VER=v1 scripts/render.sh
python3 scripts/frame_metrics.py
06
VERIFY · 验证与排障

把“看起来完成”拆成六项证据

这个项目本身把 QC 当成产物的一部分；使用者也应把它当作验收表，而不是最后看一眼 MP4。

验证清单

  • 研究 doc 为每个数字、年份、组织和英文术语提供 URL。
  • 旁白字数与片长档位匹配，字幕没有超预算。
  • 每个 shot 有 frame range、beat、visuals、motion、hero element、lighting。
  • 30 秒 pilot 通过后才并行构建其余镜头。
  • frame_metrics 与章节 QC 都有报告，修复后重新验证。
  • 交付 notes 记录版本、音频路径、渲染参数和已知边界。

常见失败

  • 旁白后改稿：帧号硬编码，整部片重计时；把修改前置到检查点 2。
  • 磁盘不够：并行 Agent 会同时打包 Remotion，至少预留约 5GB。
  • tmux pane 不够：超过约 12 个并行 Agent 要分波次。
  • 英语 TTS 失败：确认 kokoro、soundfile 和 espeak-ng；否则交 finished audio。
  • 字幕难读：中文/英文各有字幕预算，不能只缩字体解决。
  • 想做竖屏：当前模板所有 safe-area 假设横屏，不要把 16:9 CSS 硬裁成 9:16。
07
BOUNDARIES · 许可与边界

能做什么，不能把什么当成承诺

安装成功不等于适合生产；尤其要把 toolkit 许可、生成视频版权和 Remotion 自身许可分开看。

A

工具许可

anything2explainer 是 PolyForm Noncommercial 1.0.0：非商业免费，商业使用需作者事先授权。仓库 bundled fonts 另按 SIL OFL 1.1。

B

成片归属

README 表述“用它制作的视频属于你”，但片中使用的 Remotion 及其他字体/音频服务仍有各自条款，不能合并成一份许可。

C

事实与素材

每个屏幕事实必须能追溯；项目不鼓励复制既有视频，也不适合真人主持或以实拍为主的片子。致敬视觉语言不等于复用素材。

最终判断：如果你需要“解释机制并留下证据链”，它比一条 prompt-to-video 更可审计；如果你只要一次性广告片、竖屏短视频或全自动无检查点生产，它不是当前合适的工具。
