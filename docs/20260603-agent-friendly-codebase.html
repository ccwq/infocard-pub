01 · 可读真相源
Source of Truth
01

Readable Source of Truth

把关键信息放在代码里，而不是放在 Agent 读不到的地方。README、API 文档、架构决策应该与代码同在。

  • README 需要真的能让人跑起来
  • 架构图随代码更新（用 Mermaid 等工具）
  • API 文档内嵌或自动生成
实践：所有知识先写进代码/文档，再考虑其他传播渠道。
02

Self-Verification Loop

让 Agent 能够验证自己的输出。测试覆盖、类型检查、lint 不是负担，是 Agent 的感官系统。

  • 在 CI 中加入 PR 阶段测试
  • 用类型系统捕获推理错误
  • 让 Agent 自己看测试结果
实践：没有验证环路的代码库，对 Agent 来说是盲区。

03

Compressed Context

AGENTS.md 不是 README 的复制，它是 Agent 的" onboarding 指南"，只包含 Agent 需要知道的关键决策。

  • 为什么这样构建（非事实描述）
  • 关键的 5–10 个决策
  • 不要把所有细节都塞进去
原则：AGENTS.md 的价值在于压缩，而非详尽。
04

Always-On Automation

把重复性工作交给后台自动化。Agent 可以触发工作流，但工作流本身应该在后台静默运行。

  • 用 GitHub Actions 做 CI/CD
  • 用工作流引擎处理长时任务
  • Agent 负责决策，自动化负责执行
效果：Lee 迁移 CMS 后，用 25h 自动化节约替代了 344 个组件的人工操作。
