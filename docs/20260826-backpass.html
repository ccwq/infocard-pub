backpass

把 AGENTS.md 从“手工维护的规则文件”变成可用真实会话持续校准的 Agent 记忆层
一次 backward pass：采样会话 → 提炼 loss → 聚合证据 → 提出小步编辑 → 人工接受或拒绝

2提炼

4建议

MITNode ≥22.5Local-first

它解决什么问题？

Agent 犯错后，团队通常靠“记得这次教训”手工修改 AGENTS.md。backpass 直接读取真实项目会话，从 transcript 中提取违反规则、缺失规则和有效规则的证据。

核心隐喻Gradient descent

AGENTS.md 是权重

每次 Agent session 是 forward pass；会话留下的操作轨迹是 loss signal；backpass 只提出证据绑定的小步更新，不把记忆文件当百科全书无限堆长。

5,000默认 token budget
2+新规则所需会话证据
5单次最多编辑数
输入真实 transcript

从哪些会话取样？

  • 支持 Claude、Codex、Pi、OpenCode、Grok、Cursor CLI 与 Hermes 等本地 transcript store。
  • 优先按项目 cwd 或 Git remote 做确定性归属；删除 worktree 后仍可用远端信息追溯。
  • 分析结果缓存，并对旧会话使用按新鲜度加权的采样，避免每次重跑全部历史。
第一层Distillation

先把噪声压掉

工具调用压缩为一行，保留用户/助手关键原文，截断无关输出并脱敏。README 给出的典型压缩幅度是 96–99%。

第二层Loss analysis

每条结论都要引文

模型只能提交带逐字证据的“帮助 / 违反 / 缺口”判断；没有引文的结论会在代码层丢弃，降低凭空归因风险。

第三层Aggregate gradients

为什么不会一轮重写？

缺口需要跨至少两个独立 session 才能进入提案；一次最多五个编辑；文件超出预算时，新增内容必须由删除或抽取到 Skill 来支付。

人工门禁：分析阶段不写仓库。只有 backpass apply 才会展示 diff、证据与预算，并由人逐项接受或拒绝。
安装npm / npx

初步使用

npm install -g backpass
# 或不安装
npx backpass

cd your-repo
backpass init
backpass scan --since 7d --strict
backpass                 # 只分析并提出建议，不写入
backpass apply --no-ui   # 人工审核后才写入
适合

已经积累多轮 Agent 协作、希望用可追溯证据维护项目规则、并愿意保留人工审核的团队。

边界

它不是自动“训练模型”，也不是无条件自动改写 AGENTS.md；归因仍然困难，作者明确建议阅读证据而不是只看提案标题。
