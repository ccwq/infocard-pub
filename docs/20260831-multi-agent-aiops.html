源码里的职责由算法、状态和门控限定。Agent 是节点包装与协作边界，确定性逻辑仍由代码承担。

02

Orchestrator 才是工程主角

默认 Python 工作流按 Monitor → RCA → Heal → Change 执行；每个节点有条件、状态和重试计数，完成后保存 checkpoint。

01

Monitor 始终执行

没有外部指标时生成 Demo 告警；真实指标进入多算法投票。

02

有 Alert 才进入 RCA

条件路由避免没有告警证据时继续推理。

03

RCA 置信度 ≥ 0.3 才 Heal

自愈入口有显式阈值，不由自然语言临时决定。

04

有 HealEvent 才进入 Change

变更审批接收结构化修复建议、等级与爆炸半径。

重试`max_retries = 3`；节点失败后循环重试并记录状态。
Checkpoint当前 Python 实现保存在进程内字典，适合 Demo；并非持久化恢复系统。
LangGraph-style源码明确说明是简化图编排，不强依赖 LangGraph。
人工边界L1/L2 或高风险动作进入 oncall / tech lead 审批，不应伪装成全自动。
03

确定性代码与 Agent 的分工

这个项目最值得学习的不是“多 Agent”标签，而是哪些判断必须可计算、可审计、可停止。

决策源码实现为什么不交给自由生成
是否异常算法投票 + 阈值可复现，可校准误报率
是否自愈RCA 置信度、Playbook、爆炸半径可阻断高风险动作
是否审批风险评分 + L0/L1/L2责任边界明确
如何流转状态机、条件路由、重试失败路径可观察
如何解释Agent 组织证据和建议动作适合处理非结构化上下文

证据边界

RCA：Python 代码使用 `MOCK_SERVICE_TOPOLOGY` 和预设故障模式；生产环境需接真实 Neo4j、日志和变更数据。

Heal：`_execute_remediation()` 返回模拟成功文本；接入真实集群前必须增加 RBAC、命令白名单、幂等与回滚验证。

Audit / checkpoint：当前为内存列表和字典，不等价于不可篡改审计或服务重启后的持久化恢复。

许可证：GitHub API 返回 `license: null`，根目录未显示 LICENSE；使用前应向项目维护者确认。
