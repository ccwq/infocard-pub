01 项目定位

Maka 是一个本地优先（local-first）的桌面 AI 工作台，目标是在用户自己的电脑上运行一个可观察、可控、可持续恢复的 Agent。它把模型连接、会话管理、工具权限、文件读写、终端执行、联网搜索、Bot 入口和运行恢复全部集成在一个 Electron 应用里。

当前核心能力包括：桌面会话管理（创建、切换、归档、搜索、重命名、停止、重试、分支）、基于 Vercel AI SDK 的模型运行时、本地工具集（Read/Write/Edit/Bash/Glob/Grep）、权限策略引擎、Settings 中心（模型/账号/统计/记忆/搜索/Bot 网关）、本地记忆管理（MEMORY.md）、Tavily 联网搜索、多平台 Bot 入口（TG/飞书/企微/Discord/钉钉/QQ）、本地 HTTP/SSE 网关、Office 文档工作流（officecli）等。

核心设计判断：DeepSeek 成本运行线不应新建一条 agent flow，而应沿用已有的 SessionManager → RuntimeKernel → AgentRun → RuntimeRunner → AiSdkFlow → ModelAdapter/ToolRuntime 主线，把 provider-visible request 的成本纪律安装到现有边界上。

03 Self-Check 机制 · 两轮迭代

Maka Agent 的 Self-Check 机制受 Claude Code 启发，是其 Terminal-Bench 高分（0.8）的关键所在。整体设计分为两个阶段：

阶段一：Plan（计划提交）

Agent 在任务执行前通过 self_check_plan_submit 工具提交公开计划：

finalArtifacts
声明最终产物路径及用途，证明对任务的完整理解
selfCheckScratch
自检用的临时目录（默认 /tmp/maka-self-check/）及预期生成路径，防止污染工作区
workspaceGuardPlan
声明哪些路径会被检查/修改，防止意外副作用扩散

阶段二：Submit（证据提交）

Agent 在任务执行后通过 self_check_submit 提交语义自检证据：

status
pass | fail | inconclusive
commandEvidence
执行命令、退出码、超时标记、输出片段、产物路径引用（最多 25 条）
artifactEvidence
产物文件存在性、大小、哈希、元数据（最多 25 条）
executionHygiene
sandbox 执行记录、scratch 使用情况、清理状态、工作区副作用（added/modified/removed paths）

Gate 机制（两轮迭代关键）

heavy-task-self-check-gate.ts 评估每轮提交，决定三个动作之一：

allow_finalize / repair_prompt / allow_official_verifier

repair_prompt 返回带有 acceptance checklist 的修复提示，触发第二轮迭代。第一轮提交缺失证据 → Gate 拒绝 → Agent 收到修复提示 → 第二轮补全证据 → Gate 通过 → 提交官方验证器。

Source Guard（防作弊）

所有证据字符串经过 source guard 检查，拒绝引用以下内容：hidden_tests、hidden_thresholds、private_scoring_criteria、pytest_assertions、official_verifier_artifacts、non_public_evaluator_files 等。这确保 Agent 自检依赖的是公开任务指令，而非评测集内部信息。

04 Terminal-Bench 评测细节

Terminal-Bench 是由斯坦福等机构主导的权威 Agent 评测基准，给 AI Agent 提供一个具备执行权限的 Linux 终端环境（隔离 Docker 容器），模型不仅要写代码，还要精通系统运维、网络配置和 Shell 脚本。验证机制极为严格：无论推理过程多精彩，只要最终服务没跑起来/端口没通，直接记 0 分（Pass@1 Sandbox Execution）。

05 Harness Engineering · 工程化方法论

Harness Engineering 是 2026 年 AI Agent 领域的关键工程范式——Agent = Model + Harness。模型负责推理，剩下的全部是工程：工具系统、上下文管理、权限控制、反馈回路。实验证明：同一模型换 Harness，性能可差 10 倍（Trivedy 2026: 固定 GPT-5.2-Codex，仅靠 harness 改进，Terminal-Bench 2.0 从 52.8% 拉到 66.5%，+13.7 个百分点）。

关键工程洞察

"Context 利用率保持在 40% 以下。更多 token 不等于更好结果。" —Maka 设计原则。DeepSeek 成本纪律第一目标不是压缩 prompt，而是让系统能稳定回答：Provider 看到了什么 request？哪些 token 是 cache hit/miss？成本变化的原因是什么？

06 两轮迭代实践 · 复盘

两轮 Self-Check 迭代是将"做完了"变成"验证通过了"的关键机制。第一轮 Agent 执行任务 → 提交自检证据 → Gate 评估 → 如果证据不足或不符合 acceptance checklist，触发 repair_prompt，附带详细修复指令；第二轮 Agent 根据修复提示重新执行 → 补充证据 → Gate 通过 → 提交官方 Terminal-Bench 验证。

维度第一轮第二轮
目标完成任务执行，提交初步自检证据补充缺失证据，完成 acceptance checklist
Gate 决策可能返回 repair_prompt返回 allow_finalize 或 allow_official_verifier
Evidence 质量可能缺少 sandbox 执行证据 / workspace hygiene补全 commandEvidence + executionHygiene.sandbox + workspaceGuard
Source Guard必须通过，拒绝引用 hidden/private/evaluator 材料同上，所有新增证据仍需通过 guard 检查

这一设计的核心价值在于：把模型能力的上限从"执行"提升到"验证"。在没有 Self-Check 机制的情况下，Agent 可能在错误的路径上走得很远，最终被验证器一票否决。两轮迭代确保 Agent 在提交正式评测前，先完成自我审视。
