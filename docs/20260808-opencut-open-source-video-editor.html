01IDENTITY

不是“已经完成的 Rust 编辑器”

官方定位主仓库称 OpenCut 为 open-source CapCut alternative，许可证为 MIT。
当前产品线README 指向 opencut-app/opencut-classic，且明确说 opencut.app 仍运行 classic。
新版入口重写版在 new.opencut.app 迭代，准备就绪后才会接替 classic。
02WHAT WORKS

可用的是 classic，不是愿景清单

网页版本官网当前运行 classic；它是读者今天可优先评估的版本。
开发入口主仓库已包含 web、API、desktop 的开发命令与项目结构，但不等于每个终端用户能力已正式交付。
贡献边界官方 README 说明重写架构仍在设计，暂未准备好接收外部贡献。
03WHAT IS NEXT

路线图要逐项降级阅读

Rust core计划用一个 Rust core 覆盖 desktop、mobile、browser；目前是重写方向。
Editor API / 插件plugin-first architecture 和第三方插件属于 coming。
Headless / scripting自动化批渲染与编辑器内脚本标签也在路线图，不是现在可承诺的能力。
04STATUS MATRIX

官方、classic、社区扩展：三者不能混写

今天可验证

MIT 主仓库、classic 在线运行、公开开发仓库、80K+ Star 社区规模。

正在建设

Rust 重写、桌面、移动、统一 core、Editor API、插件、headless 与 scripting。

不能冒充官方

官方 MCP server 尚未发布。搜索到的 OpenCut MCP 若非 OpenCut-app 组织发布，应视为第三方项目。

对用户的含义

想立刻剪辑：先评估 classic；想押注自动化/插件/Agent 集成：跟踪重写里程碑，而不是按路线图购买确定性。

05DECISION

适合谁

适合希望使用或研究开源网页视频编辑器、关注 MIT 协议与创作工具自主性的用户。
谨慎需要稳定桌面编辑、移动端正式支持、企业插件 API 或 Agent 自动化的团队。
第一步区分 classic 与 rewrite；用实际项目测试当前 classic，而非只看 Star 数与愿景。
06RISK

最大的风险是版本错配

不要把“路线图”读成“能力清单”
官方 README 将 MCP、headless、scripting、插件、跨端 Rust core 都列在重写的 coming 项中。它们不应进入当前交付承诺。
Stars 的含义Star 数反映社区关注，不等同于新版重写完成度、商业级稳定性或某项路线图功能已经可用。
