📖 为什么值得看

很多好的 skill 都因为缺少分发渠道而不被人知道。LoopFlow 就是这样一个案例：工程质量极高，目前才 3 ⭐，但它的思路干净利落，值得所有做 Claude Code 自动化的人抄作业。

MIT 协议，约 600 行 TypeScript，用一个 YAML 文件把"写代码 → 验证 → 重跑"这件事彻底管起来了。

一句话

裸写一个自动循环，必踩三个坑——LoopFlow 的解法干净又完整：用 YAML 定义目标、串起带 persona 的 step、用一道独立人格的 gate 把验收关，没有 VERDICT: PASS 就不放行。

⚠️ 裸写自动循环，必踩的三个坑
坑 1 Agent 自己改自己批
自己写的代码自己审，模型会很开心地说"通过"。
→Gate：一道闸用独立人格的 agent 来审，必须 VERDICT: PASS 才放行。
没给裁决，一律算 FAIL。
因为「没验证的通过，不算通过」。
坑 2 没人盯着的循环 = 没人盯着的烧钱
一个循环跑起来，agent 每步都在花 token，没人看着就一路烧下去。
→Budget：硬性美元上限，runner 和 Claude Code 的 --max-budget-usd 双重锁。
任何一个触达上限，循环立即停。
坑 3 Agent 跑完就失忆
每次 Claude Code 启动都是一个全新上下文，上一轮学到的东西全丢了。
→Memory：每个循环一个 Markdown 文件，每轮追加结果、每次注入到 prompt。
agent 会忘记，repo 不会。
加餐：Worktree 隔离（多循环互不抢分支）+ 每步留 session id（claude --resume <id> 随时回放）。
fixer 写，skeptical reviewer 审，FAIL 就把反馈塞回去重跑。
⚙️ 底层原理
运行模型
# 每次迭代（≤ max_iterations） memory ──▶ step: fix ──▶ step: review (gate) ──┐ ▲ │ │ │ └── reviewer feedback ◀────────────── FAIL ┤ └───────────────── run record ◀─────────────────┘ PASS → success
  • 每步是一次独立的 Claude Code 静默调用（claude -p），不是 API 调。
  • Gate 必须以 VERDICT: PASS 或 VERDICT: FAIL 结尾；无 verdict 视同 FAIL。
  • FAIL 时，下一轮把 gate 反馈注入所有 prompt 的 system prompt 上下文。
  • 每次运行结果（outcome / cost / summary）追加写入 .loopflow/memory/<loop>.md，下次读取。
  • 无守护进程、无云服务、无额外 API key；本地 Claude Code 能跑，LoopFlow 就能跑。
📦 安装
前置条件
  • Node.js ≥ 18
  • Claude Code 已安装并完成认证（claude.com/claude-code）
npm 安装
npm install -g @loopflow/cli   # 或
npx @loopflow/cli
🔧 使用流程
初始化
cd your-project
loopflow init

生成 .loopflow/ 目录，内含三条 starter loops：

  • test-and-fix：修复 + gate 验收
  • debt-audit：代码债务发现循环
  • docs-sync：文档与代码一致性验证
运行循环
# 预览（不实际调用）
loopflow run test-and-fix --dry-run

# 正式运行
loopflow run test-and-fix
推荐先用 --dry-run 确认 prompt 组合正确，再真正执行。
📋 Loop 配置结构
# .loopflow/loops/test-and-fix.yaml
name: test-and-fix
description: Run the test suite, fix failures, verify the fix.

budget:
  max_usd: 2.00        # 全局美元硬上限
  max_iterations: 3    # gate 可拒绝的最大次数

worktree: false        # true = git worktree 隔离运行

defaults:
  permission_mode: acceptEdits

steps:
  - id: fix
    role: >
      You are a careful maintainer. You make the smallest change
      that fixes the problem, and you never weaken a test to
      make it pass.
    prompt: |
      Run this project's test suite. Diagnose and fix the root
      cause of any failure. Re-run to confirm. Summarize what
      you changed and why.

  - id: review
    gate: true          # ← 必须 VERDICT: PASS 才能结束循环
    role: >
      You are a skeptical senior engineer reviewing a change
      you did not write. You trust nothing without evidence.
    prompt: |
      A previous agent claims to have fixed failing tests.
      Inspect the diff, re-run the suite yourself, and check
      no test was weakened or deleted.
Gate 步的 role 必须独立于 Fix 步，避免同一模型自我放行。
⌨️ CLI 参考
命令说明
loopflow init [--force]初始化 .loopflow/ 目录
loopflow list列出所有 loops（步骤数 / gate 数 / 预算）
loopflow validate [name]校验 loop 定义合法性
loopflow run <name>运行指定 loop
--dry-run打印所有合成后的 prompt，不实际调用
-i, --iterations <n>覆盖 max_iterations
-b, --budget <usd>覆盖 max_usd
-v, --verbose打印完整步骤输出
Exit Codes
0
成功 — gate 通过
1
循环失败 — gate 耗尽 / 超预算 / 异常
2
配置错误
Programmatic API
import { loadLoop, runLoop } from "@loopflow/cli";

const loop = loadLoop(process.cwd(), "test-and-fix");
const result = await runLoop(loop, { root: process.cwd() });
console.log(result.outcome, result.costUsd);
⏰ 调度方式

LoopFlow 不内置守护进程，配 cron 或 CI 就能定时跑：

# Linux/macOS — 每周一 9 点跑债务审计
0 9 * * 1  cd /path/to/project && loopflow run debt-audit

# CI — GitHub Action 每周运行 docs-sync 并开 PR
有意为之的设计：无状态 CLI + 外部调度 = 不需要额外的后台进程或云依赖。
📌 边界与路线图
当前能力边界
  • 仅支持 Claude Code（不支持 Codex CLI 等其他 headless agent）
  • Step 之间为串行，非并行
  • Gate verdict 仅支持纯文本判断，尚无 --json-schema 结构化输出
  • 无内置历史日志查看器（loopflow logs 规划中）
Roadmap
  • 🔜 loopflow daemon — 内置调度器，支持 cron 表达式
  • 🔜 Parallel steps — fan-out across worktrees
  • 🔜 Structured gate verdicts via --json-schema
  • 🔜 loopflow logs — 循环运行历史
  • 🔜 其他 headless agent 适配器（Codex CLI 等）
