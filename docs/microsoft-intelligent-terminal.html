01
What it is

它是什么：Windows Terminal 的实验分支，AI Agent 原生集成

核心不是“加一个聊天框”，而是把 Agent 面板、错误检测、协议适配与终端输出联动起来，让 AI 直接围绕 Shell 工作。

官方出品MIT

微软官方仓库

仓库为 microsoft/intelligent-terminal，属于 Microsoft 官方项目。

实验性质

v0.1.0

Build 2026 发布，当前仍是实验分支，适合开发者和重度终端用户试用。

Windows Terminal 分支

不是新终端

它基于 Windows Terminal 继续演进，不要误认成 Copilot Chat、PowerToys 或其他微软工具集。

02
Core capabilities

关键能力：ACP、默认 Agent、上下文面板、错误检测

Intelligent Terminal 支持任何 ACP 兼容的 Agent CLI，并把这些 Agent 的能力嵌进终端工作流，而不是把用户赶去单独的聊天界面。

Agent 面板

  • 停靠式上下文面板，读取 Shell 输出。
  • Ctrl+Shift+.：唤起 Agent 面板。
  • Ctrl+Shift+I：切换 Agent 面板焦点。

错误上下文

  • 命令失败时可直接把错误上下文交给 Agent。
  • Ctrl+Alt+.：打开错误上下文。
  • 更适合修复命令报错和解释日志。

协议兼容

  • 支持 Agent Client Protocol（ACP）。
  • 兼容 Copilot / Claude Code / Codex / Gemini CLI。
  • 也支持本地或自建的 Agent CLI。

默认 Agent 策略

  • 默认 GitHub Copilot CLI。
  • 未检测到时会自动安装。
  • 复杂任务可在独立 Tab 中运行，不阻塞主 Shell。

04
Do not confuse

禁止混淆对象

下面这些都不能和 Microsoft Intelligent Terminal 混为一谈：它们要么是底层父项目，要么是默认 Agent，要么是协议/工具生态中的其他实体。

Windows Terminal

Intelligent Terminal 是其实验分支，不是同一个产品。

GitHub Copilot CLI

只是默认 Agent，不等于产品本身。

Microsoft Copilot Chat

VS Code 内置的独立产品，无直接等同关系。

PowerToys

微软另一工具集，别混淆。

Zed Editor

ACP 协议的主导方之一，但它是独立编辑器。

MCP / OpenClaw / AgentUnion ACP

MCP 与 ACP 不是同一标准；OpenClaw、AgentUnion ACP 也不是这个项目。

05
Why it matters

为什么这张卡值得关注

它体现了微软把 AI Agent 入口前移到终端的产品方向：把 Shell、协议、Agent CLI 和错误修复串成一条链，而不是让开发者在多个窗口之间来回跳转。

对开发者

更快把报错交给 Agent 处理，减少上下文切换。

对工具链

ACP 让接入不同 Agent CLI 的成本更低。

对微软生态

Build 2026 之后，终端成为 AI 工作台入口之一。
