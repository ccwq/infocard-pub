Opik：自愈式 AI Agent 可观测性平台

核心问题：当前所有 agent 可观测性平台只能告诉你"发生了什么"，没有一个能告诉你"为什么坏了"、"该改什么"、"下次不会再坏"。

真正的瓶颈：trace 到了屏幕上之后必须发生的所有事——为什么发生、这是修复、不会再坏了——全靠人工。

只记录发生了什么 不解释为什么 不给出修复 不保证不再坏

02
OLLIE · 核心创新

内置 coding agent：读 span 树、找根因、提 diff

Ollie 是 Opik 的核心创新——它不只记录问题，而是读源码、定位问题行、提出修复 diff。

01 / 读 span 树

遍历完整调用链

问"为什么最终回答忽略了检索到的上下文？"→ 遍历完整 span 树浮现根因

跨 LLM 调用解释因果链，识别失败模式。

02 / 读源码

定位问题代码行

opik connect 升级到完整代码修复模式：读源文件、定位问题代码行

不再只给你 trace，而是直接定位到需要改的代码。

03 / 提出 diff

生成修复补丁

提出 diff，批准后用原失败 trace 的精确输入重新运行 agent

实时流式生成新 trace 并排对比，验证修复效果。

04 / 回归锁定

坏 trace → 回归测试

坏 trace → 根因 → diff → 批准 → 重新运行 → 回归锁定

每个修复自动变成回归测试，防止相同问题再次发生。

关键创新：Ollie 把"人工分析 trace → 手动修复 → 手动测试"的循环，变成"AI 读 trace/源码 → AI 提 diff → AI 重新运行验证 → 自动锁定回归测试"的自动化闭环。
03
TEST SUITE · 测试套件

用自然语言断言替代传统数值指标

每个调试过的失败 trace 自动变成新测试用例，套件从真实生产失败中生长。

自然语言断言

语义级验证

用自然语言描述预期行为，而不是写死数值指标。AI 自动判断是否满足语义要求。

  • "回答应该包含关键上下文"
  • "不应该出现幻觉内容"
  • "调用顺序应该符合预期"
真实失败驱动

从生产中生长

测试套件从真实生产失败中生长，而非提前写的合成场景。每个失败都是新测试的来源。

  • 真实用户请求
  • 真实失败 trace
  • 真实修复验证

Opik 的核心价值

Opik 不只是另一个可观测性平台——它是第一个把"从失败到修复"变成自动化闭环的系统。当其他平台还在告诉你"发生了什么"的时候，Opik 已经帮你解决了"为什么"和"怎么修"。

  • 四层闭环：从追踪到回归测试的全链路自动化
  • Ollie：读 span 树、找根因、提 diff、重新运行验证
  • 自然语言断言：从真实生产失败中生长测试套件
  • 沙箱安全测试：非开发者也可验证配置变更

适用场景：LLM 应用开发、AI Agent 生产运维、复杂 Agent 调试与回归测试
