01
核心痛点：为什么需要 OpenSpec
传统 AI 编程有三个致命缺陷：缺乏上下文（只修表面漏洞）、跨对话碎片化（建议互相冲突）、无法适配既有系统（风格不一致）。OpenSpec 将软件工程最佳实践固化为规范驱动开发（Specification-Driven Development），让 AI 每次修改都有据可查、有规范可循。
缺上下文
只修表面，不溯根源
碎片化
跨对话建议互相冲突
不适配
无法适配既有代码风格
02
SDD 5 阶段详解
阶段命令产出物
探索 Explore /opsex:explore 编辑器内头脑风暴，梳理方案思路
规划 Plan /opsex:expose 四份文档：proposal.md + specs/ + design.md + tasks.md
实施 Apply /opsex:apply AI 严格按照 tasks.md 编写与修改代码
校验 Verify /opsex:verify 检查代码实现是否完全匹配规范要求
归档 Archive /opsex:archive 清理工作区 + 更新全局规范沉淀上下文
proposal.md — 阐述修改根本原因 specs/ — 需求目录，定义边界与异常 design.md — 确定架构与技术方案 tasks.md — 带路径和验证步骤的清单
03
命令体系：编辑器斜杠 + 终端 CLI
编辑器斜杠命令
  • /opsex:explore 探索对话
  • /opsex:expose 规划产出
  • /opsex:propose 提案生成
  • /opsex:apply 实施变更
  • /opsex:verify 校验实现
  • /opsex:archive 归档清理
用于高层对谈、文档生成与决策记录
终端 CLI 命令
  • openspec validate all strict 严格校验
  • openspec change greater than Jason delta's only 差异查看
  • openspec instructions 上下文生成
  • opsexhouse sync 命令同步
  • obsex new / continue / bark 扩展工作流
用于精确执行、验证与批处理
# 安装与基本使用
npm install -g @fission-ai/openspec@latest

# 新建变更提案
openspec change propose

# 严格校验所有规范
openspec validate all strict

# 查看与主分支的差异
openspec change delta only

# 生成当前上下文注入
openspec instructions > context.md
04
目录结构与规范体系
openspec/
├── specs/                  # 当前系统行为规范（事实来源）
│   ├── api-contract.md
│   └── error-handling.md
├── changes/                # 变更提案（四件套）
│   ├── proposal.md         # 阐述修改根本原因
│   ├── specs/              # 需求规格（边界 + 异常场景）
│   ├── design.md           # 架构与技术方案
│   └── tasks.md            # 任务清单（路径 + 验证步骤）
└── config.yaml             # 项目配置与上下文注入

.claude/commands/openspec/  # AI 斜杠命令规范文件
    ├── apply.md            # 实施规范
    ├── archive.md          # 归档规范
    └── proposal.md         # 提案规范
openspec/specs/ — 事实来源（只读） openspec/changes/ — 变更记录（追加） .claude/commands/ — AI 行为规范

06
AI 工具兼容与适用场景
✅ 适合场景
  • 大型代码库多轮迭代开发
  • 团队协作保持代码风格一致
  • 需要可追溯的变更记录
  • 微服务架构共享规范
  • AI 辅助代码审查与验证
❌ 不适合场景
  • 一次性简单脚本生成
  • 无本地 Node.js 环境
  • 已有成熟 CI/CD 质量门禁
  • 强离线隐私要求（需联网）
兼容工具： Claude Code Cursor OpenCode GitHub Copilot 无需 API 密钥
