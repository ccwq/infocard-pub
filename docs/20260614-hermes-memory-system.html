记忆系统

Hermes 有 6 层记忆/知识系统，分层分工。用对地方，省 token；用错地方，占满 memory。本卡说清楚每层的定位、触发口令、存取方式和典型场景。

"memory 是宪法，fact_store 是档案馆，skill 是操作手册，session_search 是历史记录，llm-wiki 是知识库。"

每套系统解决不同问题。不要把知识库塞进宪法，也不要把操作手册写成聊天记录。
六层架构图
layers
① 内置 memory

宪法级规则，每轮自动注入。容量 2,200 chars，只存全局硬规则。

② user memory

用户偏好，每轮注入。容量 1,375 chars，沟通风格和稳定偏好。

③ fact_store

档案馆，9 种检索动作，不占 prompt，按需查询，适合长期事实与项目约定。

④ skill

操作手册，可复用工作流和 SOP。按任务类型加载，不自动注入。

⑤ session_search

历史会话搜索，FTS5 全文，不改写历史，可恢复上下文。

⑥ llm-wiki

知识库，Markdown 文件互链，适合大型知识沉淀、调查报告、专题整理。

写入路由表
write routing
"记住硬规则 / 永远遵守"

→ memory(action=add, target=memory)

"记住我的偏好"

→ memory(action=add, target=user)

"沉淀项目事实 / 工具知识"

→ fact_store(action=add)

"固化操作流程 / 踩坑经验"

→ skill_manage(action=create)

"查一下上次怎么做的"

→ session_search(query="...")

"把调查报告 / 长期研究写进去"

→ 写 Markdown 到 ~/wiki，更新 index + log

系统 容量 注入方式 适合存什么 不适合存什么
memory ≤ 2,200 chars 每轮自动注入 全局硬规则、环境事实 项目知识、操作流程
user ≤ 1,375 chars 每轮自动注入 沟通偏好、语言风格 技术细节、长期事实
fact_store 无硬性上限 按需检索 项目约定、工具事实、长期结论 每轮都要知道的硬规则
skill 无上限 按任务类型加载 可复用流程、SOP、踩坑笔记 一次性进度、历史会话
session_search 完整历史 FTS5 全文搜索 历史进度、临时上下文 应固化的稳定结论
llm-wiki 无上限 读取 Markdown 文件 调查报告、专题研究、知识库 短偏好、硬规则
每层怎么触发？
trigger examples
memory：硬规则

触发语："以后都要遵守这个规则" / "这是全局边界"。例："磁盘日报永远跳过 /home/ccwq/qbox"。

user memory：用户偏好

触发语："记住我的偏好" / "以后用这种风格回复"。例："中文、直接、先给结论"。

fact_store：事实档案

触发语："把这个事实存起来" / "以后能查到这个项目约定"。例："CheatSheet 项目路径和 Pages 地址"。

skill：流程手册

触发语："把这个流程固化成 skill" / "下次同类任务按这个 SOP"。例："daily-disk-report 的扫描、对比、输出步骤"。

session_search：历史回溯

触发语："上次怎么做的" / "找一下我们聊过的 X"。例："找上次 qbox 不计入磁盘日报的会话"。

llm-wiki：知识库

触发语："把这份报告沉淀到 wiki" / "整理成长期知识页"。例："Hermes 记忆系统分层使用手册"。

✗ 用错地方的例子

把"项目有哪些坑"写入 memory → 2,200 chars 快速满载
把"我的偏好"写入 skill → 每轮加载浪费 token
把"调查结论"塞进 session → 结论无法复用

✓ 用对地方的例子

硬规则写 memory → "磁盘日报跳过 /qbox"
项目事实写 fact_store → 工具参数、平台事实
操作流程写 skill → daily-disk-report SOP
调查报告写 llm-wiki → 持续积累的知识库

常用存取指令
quick commands
# 写 memory（全局硬规则） memory(action="add", content="磁盘日报排除 /home/ccwq/qbox", target="memory") # 写 memory（用户偏好） memory(action="add", content="用户偏好中文回复", target="user") # 写 fact_store（长期事实） fact_store(action="add", content="CheatSheet 项目路径...", entity="cheatsheet") # 查 fact_store（按关键词） fact_store(action="search", query="infocard 发布") # 查 fact_store（按实体） fact_store(action="probe", entity="MiniMax") # 写 skill skill_manage(action="create", name="daily-disk-report", content="...") # 查历史会话 session_search(query="磁盘日报 qbox", limit=3) # 存 llm-wiki：写 Markdown + 更新 index.md + log.md
实操建议：如果发现 memory 经常满载，先把项目事实迁到 fact_store，把操作流程写成 skill。memory 只保留"宪法级规则"，这样才能腾出空间给真正需要每轮注入的内容。
