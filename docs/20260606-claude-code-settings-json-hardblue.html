01
SETTINGS.JSON

settings.json 是什么：4 大字段 + 4 层 scope

.claude/settings.json 是 Claude Code 官方 JSON 配置文件，每次启动会话都读它。100+ 字段，日常用得最多 4 个：permissions / hooks / env / statusLine。

权限

permissions

allow / deny / ask，决定 Claude 能用什么命令、禁止什么。核心控制层。

钩子

hooks

beforeEveryStdout / afterEveryCommand 等 10 个钩子，100% 触发，稳定自动化工作流。

环境

env

注入环境变量，hot-reload 无需重启会话。

状态栏

statusLine

底部状态栏自定义显示内容，实时展示会话状态。

4 层 scope 加载优先级（数组类跨 scope 合并，标量类取最高优先级）
优先级 scope 说明
最高 Managed 企业管控，团队统一策略
2 CLI 参数 命令行 --dangerously-skip-permissions 等
3 Local 项目级 .claude/settings.local.json
4 Project 项目级 settings.json
最低 User ~/.claude/settings.json（用户全局）
02
THREE MECHANISMS · 三种机制

auto mode / bypass / 手动 permissions：机制对比

三者不是替代，是配合。了解各自的真实边界才能正确组合。

AI 实时判断auto mode

auto mode 真实门槛（5 个）

  • 只支持 Claude Sonnet 4.6 / Opus 4.6 / Opus 4.7
  • 必须直连 Anthropic API（Bedrock/Vertex/Foundry 不可用）
  • Team/Enterprise 需管理员开启
  • 公司内部资源（GitHub org / S3 / 内部域名）被当外部，需额外配置
  • 进入时宽 allow 规则（Bash(*) 等）全部失效
  • 连续 block 3 次或总计 20 次自动退弹窗
⚠ 裸奔模式bypassPermissions

bypass 在本机 = 裸奔

  • 受保护路径（.git / .bashrc / .ssh / .gitconfig）全部可写
  • 无 prompt injection 保护（恶意 README 可骗私钥）
  • 唯一保留核选项 rm -rf /
  • 官方明确：只在隔离容器 / VM / dev container 里用
  • 本机日常绝对不要碰
静态规则手动 permissions

手写 permissions 优势

  • 字符串匹配，规则可读、可审计
  • 可 git commit 给团队共享
  • allow 写死高频白名单，省 classifier token
  • deny 写死红线，任何模式都生效
  • defaultMode: "acceptEdits" 让文件编辑直通
03
PERMISSIONS · 权限模式

6 个权限模式速查 + permissions 配置语法

Shift+Tab 在 default / acceptEdits / plan 三者切换。auto 和 bypass 不在默认循环，需要专门启用。

6 个权限模式
模式行为
default每次问确认
acceptEdits文件编辑免确认
plan只规划不执行
autoAI 实时判断
dontAsk禁止提问
bypassPermissions全部直通（危险）
permissions 语法速查
优先级：deny > ask > allow
allow：免审批列表
deny：禁止列表
ask：每次都问
additionalDirectories：扩展读写目录
// 基础 permissions 配置示例
// ~/.claude/settings.json
{
  "permissions": {
    "defaultMode": "acceptEdits",
    "allow": [
      "Bash(npm test *)",
      "Bash(npm run *)",
      "Bash(git diff *)",
      "Bash(git log *)"
    ],
    "deny": [
      "Bash(rm -rf / *)",
      "Bash(chmod -R 777 *)",
      "Edit(~/**)"
    ]
  }
}
04
WHY WRITE SETTINGS.JSON

为什么 settings.json 值得好好写

新手最常犯的错：把它当"可有可无的偏好设置"。事实正好相反。

原因 1
免弹窗

直接允许所有无关痛痒的操作，避免每次按 yes，手指发麻。

原因 2
守住红线

拒绝所有高风险操作，防止 Claude Code 造成重大安全隐患。

原因 3
自动化

设置 100% 触发的 hook，稳定自动化重复工作流。

⚠ bypassPermissions 在本机 = 裸奔

受保护路径全部可写，无 prompt injection 保护。官方明确：只在隔离容器 / VM / dev container 里用。

05
WORKFLOW · 配置实战

配置实战：按字段顺序配置

按 permissions → hooks → env → statusLine 顺序配置，每步给可复制 JSON。

1

permissions · 权限

defaultMode: "acceptEdits" + allow 高频命令 + deny 危险命令 + additionalDirectories 扩展目录。

2

hooks · 钩子

beforeEveryCommand / afterEveryStdout 等 10 个钩子，100% 触发，稳定自动化工作流。

3

env + statusLine

注入环境变量（hot-reload）+ 底部状态栏显示内容实时展示会话状态。

核心结论

写好 permissions 是基础，auto mode 是补充，bypass 是隔离环境特例。三者实际是配合，不是替代。

  • deny 写死红线：任何模式都生效，包括 auto
  • allow 写死高频白名单：不浪费 classifier token
  • defaultMode: "acceptEdits"：文件编辑直通，减少弹窗
  • bypassPermissions：本机日常绝对不要用，只在隔离容器里
