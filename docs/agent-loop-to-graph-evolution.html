从 Loop 到 Graph，再到 Grounding

单一 Loop 只能看见被要求优化的目标，多个 Graph 节点之间相互监督、约束与纠偏，但真正的可靠性来自与真实世界的锚定——这才是 Agent 架构进化的完整路径。

作者：Avrilyn Li · 174 Like · 33 转发 · 249 收藏
"Are we still discussing Loop, or have we already shifted to Graph?" — 单一 Agent 在 Loop 中反复「规划—执行—观察—反思」，而多个 Loop 连接形成的 Graph，则实现了节点之间的相互监督、约束与纠偏。

一、为什么 Loop 是 Agent 的第一个主流架构

Loop 包含四个基本动作：设定目标、测量现实与目标的差距、采取行动缩小差距、重复这一过程。温控器、A/B 测试、模型评估、OKR、复盘乃至机器学习训练，本质上都是 Loop。

Loop 的优势在于结构简单、成本低、早期效果显著。因此它自然成为 Agent 的第一个主流架构。

二、单一 Loop 的四个根本问题

Metric 优化到失真

例：客服 Agent 的目标是提升「工单解决率」，它可能通过减少追问、快速关闭对话、甚至把用户放弃的问题标记为已解决来达成指标——数字好看，但用户留存率却在悄悄下滑。

综合来看，单一 Loop 存在四类典型问题：

  • 优化目标到 Metric 失真的程度
  • 无法质疑最初设定的目标本身是否正确
  • 不同 Loop 之间可能相互冲突
  • 没有人知道负责测量的系统本身是否已经失准

三、Graph 架构的关键转变

Graph 的核心是让不同功能、不同速率的多个 Loop 连接协作：有的负责执行、有的负责审查、有的负责测试、有的可以否决、有的负责重置下级 Loop 的目标。

并行与局部重跑

某个节点失败时，只需在该节点局部重新执行，无需从零重启整个流程。

节点关系决定可靠性

真正的可靠性不只来自每个节点本身，更来自节点之间的关系：谁监督谁、谁能否决谁、谁向谁反馈、如何处理冲突。

四、Graph 的局限性

如果 Graph 中所有 Agent 读取的是同一批数据、同一份报告、同样的错误指标，它们最终可能只是在相互印证「正确性」——系统结构越来越复杂，每个节点都显示绿灯，却与现实完全脱节。

五、Grounding：最后的锚点

真正重要的是系统是否具备 Grounding——即是否始终与真实世界保持接触。

  • 实际到账的收入，而非报告中的数字
  • 真正执行过的测试，而非测试计划
  • 真正留住的客户，而非工单关闭率
  • 独立于优化系统的物理世界测量与审计数据

有些规则必须被冻结，不允许 Agent 为提升分数而修改评估标准。

更根本的问题是：「什么才算更好」这个价值判断，无法仅由 Loop 或 Graph 计算。系统可以优化目标、调整参数、甚至重组工作流程，但最基础的价值判断仍然来自人类。
