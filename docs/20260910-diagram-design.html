Boundary

语义先于皮肤

How it works

从关系到可验收图表

使用时先写清读者要追踪的关系，再让 Agent 选择 layout grammar。这样失败时能知道是语义、布局、内容删减还是 SVG 渲染出了问题。

01

理解内容：架构、时序、状态、流程、数据还是治理？

02

收敛输出：冻结 type、size、detail、audience 四个旋钮。

03

生成产物：输出自包含 HTML + SVG，并记录合并/折叠内容。

04

浏览器验收：检查裁切、对比度、键盘、屏幕阅读器和离线打开。

选择与导入

架构关系用 Architecture，时间顺序用 Sequence，分支决策用 Flowchart，实体与字段用 ER，角色交接用 Swimlane，依赖路径用 Dependency graph。导入 Mermaid 或 draw.io 时检查 fidelity ledger：哪些节点合并、哪些注释折叠、哪些关系丢失。

生产验收清单

  • 内容语义正确：图表类型匹配读者要理解的关系。
  • 结构完整：主路径、异常分支、关键依赖和方向没有被过度简化。
  • 文件独立：HTML/SVG 在无网络、无构建环境下可以打开。
  • SVG 不裁切：检查 stroke、marker、clip-path 和外层容器。
  • 可访问：有 title/desc 或等价命名，键盘路径清楚，reduced-motion 显示静态帧。
  • 导出干净：SVG/PNG 只包含图表，不误带页面说明或外部资源。
  • 可维护：来源、版本、导入损失和自定义 token 有记录。
适用边界如果只有一个框和一句话，普通段落更好；如果领域模型本身不清晰，Diagram Design 不能替你发明正确关系；如果要复杂可编辑设计文件，它也不是 Figma 替代品。
