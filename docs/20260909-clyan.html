01核心哲学：磁盘是 AI 的身体

Clyan 解决什么问题？当 AI Agent 在 Windows 上运行时，磁盘空间管理是一个盲区——它不知道 C 盘还剩多少空间、不知道哪些缓存可以清理、不知道哪个项目目录正在吃掉大量空间。传统的做法是让 AI 自己调用外部命令查磁盘，这引入了额外的延迟和不可靠性。Clyan 让 Agent 拥有真实的磁盘感知能力。

不替 AI 判断

只汇报客观状态（磁盘大小、文件体积、缓存年龄），不替 AI 做"该不该删"的决策。决策权始终在 Agent。

不按阈值决定

不根据"磁盘使用率 > 80%"这类阈值自动触发清理。Agent 可以自己定义策略，Clyan 只执行操作。

不给 AI「加工」过的数据

汇报原始文件列表、大小、修改时间，不做摘要压缩。Agent 拿到的是未经阉割的磁盘视图。

安全层机制

干运行（dry-run）模式：先预览会删除什么、不实际删除；白名单/黑名单路径；不会碰系统关键目录；删除前计算可释放空间。

汇报层格式

report.py 输出结构化 JSON：{path, size, category, last_modified, safe_to_delete}，Agent 直接解析使用，不需要正则解析。

05快速上手
$ pip install clyan
$ clyan pulse # 磁盘状态毫秒级脉冲（缓存后 <1ms）
$ clyan scan quick --path C:\Users # 快速扫描用户目录
$ clyan auto-clear --dry-run # 干运行预览（不实际删除）
$ clyan reclaim # 全量回收（确认后执行）
$ clyan report # 输出结构化 JSON 报告

在 AI Agent 中使用 MCP：配置 Claude Code / Codex 等 MCP 客户端，连接 Clyan 的 7 个工具。Agent 在需要时直接调用 check_disk_pulse 查询磁盘状态，或在写文件前调用 auto_clear_safe 清理目标路径。

07安全设计
干运行模式

所有危险操作（reclaim / auto-clear）默认先干运行，只报告将要删除的文件列表，不实际删除，等待 Agent 确认。

白名单保护

系统关键目录（Windows/System32 等）永久在白名单里，任何规则都不会碰。C:/Users 下可配置排除特定项目目录。

规则沙盒

Winapp2 规则逐条审核后才能启用；自定义 Provider 规则在干运行模式下验证效果，防止误删。

免责声明：Clyan 按原样提供清理功能。操作前请确认目标文件可删除；对于关键数据，建议使用版本控制系统或备份工具进行保护。
