Key Reference

关键前置参考：PAL 框架

Program-Aided Language Models，Ornis 诞生的重要理论基础

提出者
Google / OpenAI + UCLA
2022 年联合发表，开创了将代码执行引入 LLM 推理的先河
核心机制
利用外部 Python 解释器严格验证模型生成的代码
通过确定性执行环境对 LLM 输出进行闭环验证，避免幻觉传播
局限与 Ornis 的超越
PAL 解决了「验证问题」，但未解决「生成问题」—— 模型依然被动等待人类指令。 Ornis 在此基础上，引入 selfing RL 让模型能够自主生成、重写编排逻辑， 实现了从「验证」到「生成+验证」的完整闭环。
⚠️ PAL 局限：PAL 仅解决「代码执行验证」，未改变模型被动等待人类指令的本质。

FAQ

常见问题

什么是 Self-Scaffolding？
Self-Scaffolding（自我构建脚手架）是一种通过 selfing RL（自我增强强化学习）训练的技术范式， 使模型能够在运行过程中自主生成、重写并优化自身的编排系统和动态执行脚手架， 无需人工预定义完整工作流程。
Mac Mini M4 真的能跑 9B 模型吗？
可以。Ornis 9B 版本针对 Apple Silicon 进行了深度优化，16GB 统一内存的 Mac Mini M4 足以流畅运行。在 Terminal Bench 2.1 评测中，9B 以小博大，部分场景超过传统 35B 云端模型， 性价比极高，是理想的入门选择。
Ornis 397B 和 Claude 4.7 比，哪个更强？
在 AG Coding 综合评测中，Ornis 397B 旗舰版已实现对 Claude 4.7 和 OpenAI GPT-4.7 的反超。 这意味着对于企业级核心算法和复杂编程任务，本地部署的 Ornis 397B 可以完全替代 昂贵的云端商业模型，同时保障数据隐私。
PAL 框架和 Ornis 有什么关系？
PAL（Program-Aided Language Models）是 2022 年 Google/OpenAI + UCLA 提出的框架， 开创了用外部 Python 解释器验证 LLM 代码的先河。Ornis 在 PAL 基础上进行了质的飞跃： PAL 只解决了「验证问题」，而 Ornis 通过 selfing RL 进一步解决了「生成问题」， 让模型能够自主生成和优化编排逻辑。
本地部署相比云端 API 有哪些优势？
① 成本：一次性硬件投入，长期零代币消耗；② 隐私：代码和数据不离开本地局域网；③ 可控性：完全掌控模型版本和配置；④ 延迟：内网访问，延迟极低；⑤ 定制：可针对团队场景微调模型。
Mac Studio 32GB 能跑 35B 吗？
可以。Ornis 35B 是目前主力推荐的版本，Mac Studio 32GB 统一内存（推荐 64GB 效果更佳） 可以流畅运行。该版本在复杂前端构建、空间视觉推理、主动 Debug 打印日志等场景 表现极为强劲，是大多数开发团队的高性价比选择。
