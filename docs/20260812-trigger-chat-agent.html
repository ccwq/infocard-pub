一句话定位

每个对话是一台状态机：变量、缓存、子 agent 全部留在内存；无人输入时休眠，回来时从上次位置继续；刷新或崩溃后流式输出自动恢复。

状态持久 无超时 流式恢复 后端即代码
01
CORE FEATURES

核心特性

chat agent 把 AI 聊天体验变成真正的持久状态机，所有传统方案中的状态丢失问题都被结构性解决。

持久化核心

回合状态不过期

变量、缓存、四个问题前派生的子 agent，全部留在内存。关闭浏览器几天后回来，从上次停下的地方继续。

  • 无需手动序列化 context
  • 无需外部 KV 存储状态
  • 刷新页面 → 流式继续
休眠/醒来弹性

机器休眠自动检测

无人打字时，底层 task 休眠，不消耗资源；用户回来时自动唤醒，从上次停下的位置继续流式输出。

  • 按需启动/休眠
  • 无超时限制
  • 流式恢复无需重试
无 API简化

后端即一段代码

不需要 API Route，不需要 /api/chat，不需要维护连接。整个后端就是一段 task 函数，useChat 直接指向它。

  • 零后端基础设施
  • 零连接管理
  • 零状态序列化

CODE EXAMPLE

最小示例

整个后端就是这段代码——声明 tools、定义 chat.agent、useChat 直接指向它。

// chat-agent-example.ts
import { chat } from "@trigger.dev/sdk";
import { anthropic } from "@ai-sdk/anthropic";
import { streamText } from "ai";

// 声明工具（typed, declared once）
const tools = {
  searchDocs: tool({
    description: "Search the product docs",
    inputSchema: z.object({ query: z.string() }),
    execute: async ({ query }) => searchIndex(query),
  }),
  refundOrder: tool({
    description: "Refund an order",
    inputSchema: z.object({ orderId: z.string() }),
    needsApproval: true,  // Human-in-the-loop: 暂停等审批
    execute: async ({ orderId }) => payments.refund(orderId),
  }),
};

// 定义 chat agent
export const supportAgent = chat.agent({
  id: "support-agent",
  tools,
  run: async ({ messages, tools, signal }) =>
    streamText({
      ...chat.toStreamTextOptions({ tools }),
      model: anthropic("claude-sonnet-4-5"),
      messages,
      abortSignal: signal,
      stopWhen: stepCountIs(15),
    }),
});

VS TRADITIONAL

vs 传统 API Route 方案

对比三种方案：传统 API Route、Session 存储方案、chat agent。

维度 API Route + SSE Session 存储方案 chat.agent（推荐）
状态持久 ❌ 需外部存储 ✅ 依赖 KV/DB ✅ 内存原生
刷新恢复 ❌ 需重新拉取 ⚠️ 依赖存储延迟 ✅ 自动流式恢复
超时限制 ⚠️ Vercel 10s/60s ⚠️ 云函数限制 ✅ 无限制
代码量 Route + SSE + 序列化 Route + Storage SDK 零后端基础设施
状态一致性 ⚠️ 序列化/反序列化 ⚠️ 存储延迟风险 ✅ 零序列，原生内存
Human-in-loop 需自行实现 需自行实现 ✅ 内置 needsApproval

USE CASES

适用场景

chat agent 适合所有需要长时间多轮对话、AI 判断、可审批工具调用的场景。

场景 1

客服助手

跨多步的订单查询/退换货，需人工审批高风险操作。

场景 2

数据分析师

长思维链任务：查数据 → 写代码 → 执行 → 出报告，用户离开可继续。

场景 3

复杂 Agent

子 agent 协作、树形推理、中途停止后续恢复。

场景 4

教育辅导

长时间解题会话，学生关闭标签页后再回来状态完整。

适用读者

想构建持久 AI 聊天体验的前端工程师、AI Agent 开发者、TypeScript 开发者。

  • 使用 Vercel/Netlify 等 Serverless 平台，想突破超时限制的团队
  • 需要多轮复杂推理且中途可暂停等用户确认的工作流
  • 想用纯 TypeScript 代码替代 API Route + SSE + 状态存储的开发者
