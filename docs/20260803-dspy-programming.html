01

核心范式：从 Prompt 工程到编程

DSPy（Declarative Self-improving Python）将 LLM 调用从"写 Prompt"转变为"写程序"。用户声明 Signature（输入/输出签名），框架自动决定内部 Prompt 和推理策略。

核心理念

将 prompt 视为可优化的参数，而非静态字符串。框架通过编译器（Compiler）自动搜索最优 Prompt 组合。

传统方式

  • ❌ 手工编写长 Prompt
  • ❌ 复制粘贴调整，版本混乱
  • ❌ 模型换代后全部重写
  • ❌ 无法自动测试质量

DSPy 方式

  • ✅ 声明式 Signature
  • ✅ Modules 组合调用
  • ✅ Teleprompter 自动优化
  • ✅ Benchmark 驱动编译
02

Signature：模块的核心契约

Signature 是 DSPy 模块的输入输出规范，用自然语言描述任务，无需手工写 Prompt。

# BasicQA — 输入问题，输出答案 signature = "question: str -> answer: str" # 生成一个问答模块 cot = dspy.ChainOfThought("question -> answer") result = cot(question="什么是 DSPy?") print(result.answer)
Signature 示例：context: list[str], question: str -> answer: str, thought: str
字段类型说明示例
: str单字符串question: str
: list[str]字符串列表context: list[str]
-> answer: str输出字段（LM 填充）LM 必须填充
03

Modules：可组合的 LM 构件

DSPy 提供 6 大内置模块，通过 dspy.Module 基类统一封装，可自由组合。

ChainOfThought
链式思考：强制 LM 输出 thought 再输出 answer，显著提升复杂推理质量。
ProgramOfThought
思维编程：让 LM 生成 Python 代码执行，结果回传后输出最终答案。
MultiChainComparison
多路径对比：并行执行多条 CoT，取最优或投票决定答案。
BootstrapFewShot
少样本引导：从少量标注数据中自动生成高质量示例。
Regression
回归模块：用 LM 生成候选答案后，通过训练权重回归出最优组合。
Ensemble
集成模块：组合多个不同 teleprompter 的模块，取多数投票或加权融合。
# RAG 示例 class RAG(dspy.Module): def __init__(self): self.retrieve = dspy.Retrieve("passage") self.cot = dspy.ChainOfThought("context, question -> answer") def forward(self, question): context = self.retrieve(question).passages return self.cot(context=context, question=question)
04

Teleprompter：自动 Prompt 优化器

Teleprompter 是 DSPy 的编译器组件，输入任务描述（Metric）和少量示例，自动搜索最优 Prompt + Modules 配置。

Teleprompter原理适用场景成本
BootstrapFewShot从少量标注生成示例数据稀缺、快速启动低
MIPRO贝叶斯优化搜索组合最佳质量与效率平衡中高
BOHBBayesian + Hyperband大搜索空间、算力充足高
RandomSearch随机采样配置基准对比、快速实验中
EnsembleOptimized多模块集成联合优化多模型协作高
# MIPRO 优化 teleprompter = dspy.MIPRO("answer: str", metric=accuracy_metric) compiled = teleprompter.compile(RAG(), trainset=train_set, max_bootstrapped_demos=4)
05

DSPy vs 传统 Prompt 工程

维度传统 PromptDSPy
代码组织字符串拼接，易碎Python 类/模块，可版本控制
Prompt 管理分散在代码各处集中声明，编译器管理
模型迁移需全部重写只需改一行配置
质量保证依赖人工测试Benchmark 驱动自动优化
适用规模单任务、少量场景多任务、管线化生产
选型建议

个人实验 / 单次任务 → 直接写 Prompt。
多任务系统 / 生产管线 / 模型频繁切换 → DSPy 模块化架构。

⚠️ 使用注意事项
⚡ 优化成本
MIPRO/BOHB 需要在训练集上多次调用 LM，单次编译可能消耗数百美元算力。
🔒 数据隐私

📦 依赖版本
DSPy 处于快速迭代期，v2/v3 API 有变化，生产环境建议锁定版本。
