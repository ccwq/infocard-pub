WORKFLOW 怎么用

交代任务，bot 在后台干，卡住了来找你

给 bot 一份长期任务，它自己开工；只有缺信息、要拍板或要授权时才回来。碰到验证码、人机验证这类过不去的坎，它会主动停下来请人接手。想自己上？点「Take control」接管屏幕，操作完交还给它继续——接管/观看走两条可独立撤销的 websocket 能力通道，桌面释放前会先断开客户端。

COMPUTER · 电脑机制
PAGE 02

COMPUTER 电脑机制

Team 电脑共享干活，私有电脑隔离隐私

01
Team Computer（默认）

每个工作区一台，bot 共享文件与工具。Team bot 起始于 bots/<bot-id>/、共享件放 shared/——文档原话：这些文件夹「组织工作但不是安全边界」，每个 Team bot 都能访问整个工作区。

02
Private Computer

整个工作区就是它的 home；涉隐私的活（私人邮箱/账务）文档建议单独配。

浏览器持久化：每个活跃 bot 独立 X display + Chrome 进程 + 按 bot 身份隔离的持久 profile——登录、cookie、历史互不可见，不克隆不合并；重开 bot 沿用原 profile。并发靠 per-bot 数据库租约：多 bot 可同时干活，一个 bot 同时只有一个 driver。单机可承载 100+ bot profiles。

SECURITY · 边界
PAGE 03

SECURITY 边界

默认全通，敏感场景要手动收紧

Docker 电脑默认全出站：公网 + Docker 宿主地址 + 局域网 + 云厂商的链路本地元数据端点（link-local metadata endpoint）——最后这条在云 VM 上等于把实例凭证暴露给 bot 跑的任何东西。

Restricted 模式（opt-in）：保留公网出站（浏览/DNS/apt/git over SSH），切断所有非公网目的地与主机流量。

资源上限每台默认 2g 内存 / 2 CPU / 2048 PIDs，可调可解除；配错了启动时就报错，不会变成 bot 跑着跑着才炸。

INSTALL · 四条命令
PAGE 07

INSTALL 四条命令

装好 Docker 就够了，不用 clone 不用 Node

mkdir -p rakazo && cd rakazo && curl -fsSLO https://raw.githubusercontent.com/elie222/rakazo/main/infra/compose/install-images.sh && bash install-images.sh

安装脚本下载 Compose 文件、生成带随机密钥的 .env（重跑保留已有配置）、启动服务。前置只有 Docker Engine + Compose 插件 + curl + OpenSSL。打开 http://127.0.0.1:5173 注册账号、连模型即用；本地 Docker 电脑默认开启。

源码开发路线才需要 Node 22.22+/24.x/26+（23/25 不支持）+ pnpm 9 + Postgres。镜像默认 tag edge，amd64+arm64 双架构。

SERVER · 24 小时在线
PAGE 08

SERVER 24 小时在线

bot 要常驻，后端就得在服务器上

同一脚本三步变生产部署：--prepare-only 生成配置 → 编辑 .env（SANDBOX_PROVIDER、RAKAZO_HOST=你的域名）→ 正式启动。桌面/手机端选 Existing instance 填 https 地址连回去。

硬要求：公网服务必须 HTTPS（文档给了 Caddy 配置与主机加固清单），HTTP 只接受本机回环与私网地址。备份一条命令 ./scripts/backup.sh（pg_dump + data/ 归档，失败即非零）；升级按 tag 拉镜像 up -d --wait。警告：docker compose down -v 会删光全部 Postgres 状态。

BETA · 边界
PAGE 09

BETA 边界

上生产前要知道的四件事

① Beta 阶段，官方托管云未上线，只能自己部署；② Team 电脑的文件夹分工不是隔离，每个 bot 都能读整个团队工作区——隐私任务配 Private Computer；③ Docker 电脑默认出站全开（含云厂商链路本地元数据端点 = 实例凭证风险），云 VM 上建议开 Restricted egress；④ 桌面版独有 SANDBOX_PROVIDER=desktop：bot 命令直接跑在你 OS 账户下，权限等于你自己，慎开。
