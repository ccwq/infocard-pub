03推文没讲的三个关键设计

A段间引导（运动续拍）——多段生成时把上一段末尾运动帧"钉入"下一段采样再裁掉前缀，上下文帧数 5/22/39/56 可选（默认推荐 22）。这是长视频不"跳戏"的关键；思路致谢 ComfyUI-H3-Motion-Context。
B三个外接口 = 三级画质引擎——semantic_bridge（student MLP 改写官方 cond token：原版桥偏构图/空间/计数，BUNNY 桥偏动作归属/多人场景，权重自放 models/semantic_bridge/，插件不分发）；selflift（低清前缀+3D lift+高清收尾的渐进一采）；refine（refine 同分辨率精修 / upscale 先放大再二采 / latent_upscale 只放大 latent，passes 默认 1 最多 9999，upscale 默认 h3_latent 3D 权重，也可 lanczos+RealESRGAN 或 NVIDIA RTX VSR）。三口都不接 = 官方原链路，接哪个升哪级。
C工程细节控——导演包 .mmxpack.zip（timeline.json 无损往返 + 素材目录全 ASCII 防路径编码坑）；音频槽选视频会立即抽首轨存 FLAC；同名素材沿用 ComfyUI 上传规则不覆盖；confirm_first_pass 首跑只出一采阻断下游，二次 Queue 命中缓存完成二采；fl2v 默认跳过二采保护钉死的首尾帧。

04上手：四步出片（含模型清单）

  1. 升级 ComfyUI ≥ 0.30.0（含官方 H3 节点）。
  2. 装插件：Manager "Install via Git URL" 填仓库地址，或 git clone 进 custom_nodes + pip install -r requirements.txt（可选 scenedetect 智能分割 / opencv 源视频解码 / imageio-ffmpeg 抽音轨）。
  3. 下模型（完整包在 comfyit.cn/article/506，或 HF Comfy-Org/MiniMax-H3）：minimax_h3_fl2va/ref2va_pruned_int8_convrot 双 UNET → diffusion_models；qwen3vl_32b_minimax_h3_nvfp4_awq CLIP → text_encoders；video_vae_fp16 + audio_vae_fp32 → vae。
  4. 拖入 9 个示例工作流之一（t2v/fl2v/r2v/v2v/rv2v/外部多组×2/二采加速），连好 UNET/CLIP/双 VAE，在导演台 UI 里切段时间轴写提示词，Queue。默认出片 0.4MP 16:9（864×480）、5 秒/124 帧@24fps、25 steps、CFG 1.0、sigma shift video 12/audio 3。

B 站有作者视频教程合集（space.bilibili.com/1997403556）。

05冷静面与判断

四个折扣点：① 强依赖 ComfyUI 官方 H3 节点（≥0.30.0），官方链路变动它会跟着断；② Semantic Bridge/SelfLift 权重需自行从第三方 HF 仓库获取，插件不分发，"桥不要串"（原版与 BUNNY 二选一）；③ r2v/v2v/rv2v 对 Semantic Bridge 为"强制兼容"，作者自己都标注"请谨慎使用"；④ 无 release/tag，8 月初建仓，迭代快（README 大量细则说明边界仍在移动）。

判断：这是"官方模型能力 + 社区工程化"的教科书案例——MiniMax H3 官方节点只给单段生成，这个插件在其上补齐了长视频工业化的全部缺口（分段、续拍、精修、放大、打包）。做 AI 短视频/短剧的 ComfyUI 用户值得直接装；只在意的不是"能不能用"而是"官方节点升级后兼容窗口有多长"。适合愿意读 README 的进阶玩家；纯新手先跑通官方 t2v 再上导演台。
