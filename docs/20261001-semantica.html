它是什么
what is it

Semantica 自我定位是 Graph-Native Infrastructure for Context and Accountable AI Systems——图原生的上下文与可问责 AI 基础设施。官方明确它面向高风险、强监管领域：医疗、金融风控、合规、安全运营。对比昂贵的企业级平台，走开发者优先路线：Python 库 + CLI + REST + MCP server，MIT 协议。

你给它什么input

  • 散落各处的数据源：文件/网页/数据库/Kafka/邮件/Git/数仓
  • 你的业务规则（推理规则、本体 ontology）
  • 可选的大模型 API key（不给也能跑）

它还你什么output

  • 可查询的上下文图谱与知识图谱
  • 带完整出处的决策记录与因果链
  • PROV-O 审计轨迹（JSON/CSV/RDF）

数据管线：从散落数据到知识图谱
pipeline
01 · 摄入Ingest

FileIngestor 收 PDF/DOCX/HTML/JSON/CSV/XLSX/PPTX/Parquet/XML 与整个目录；WebIngestor 遵守 robots.txt 抓网页；DBIngestor 连 SQL 库；企业级有 Databricks/Snowflake/SAP OData 专用连接器。

02 · 解析Parse

DocumentParser 返回 full_text + metadata；复杂表格版式换 DoclingParser（pip install semantica[parse-docling]），能出结构化表格数据。

03 · 抽取Extract

NERExtractor + RelationExtractor 双模式：method="pattern" 零 API key 开箱即跑（confidence 0.7 起步）；method="llm" 接 Groq/OpenAI 等换更高精度。

04 · 建图Build

GraphBuilder(merge_entities=True) 自动合并 "Apple"/"Apple Inc."/"AAPL" 同义实体，无需手工去重；输出 nodes + edges 的图字典。

05 · 出图/导出Deliver

KGVisualizer 三种布局（force/hierarchical/circular）生成可交互 HTML；RDFExporter 出 turtle/json-ld/nt；ParquetExporter 直通 Spark/BigQuery；ArangoAQLExporter 生成 AQL 插入语句。

批注：整条管线不依赖任何大模型——pattern 抽取 + 规则推理即可完整跑通；LLM 只是精度增强的可选项，这是它与「先把数据发给模型再说」类工具的本质差别。
确定性推理八模式
reasoning modes

推理与检索的区别：检索找回已有信息；推理用逻辑规则推出数据里没写的结论。文档分别写了「APT29 用 SUNBURST」和「SUNBURST 利用 CVE-2020-10148」，推理自动得出「APT29 可利用 CVE-2020-10148」。

前向链式forward_chain

从已知事实出发推出全部隐含事实——全量物化。

反向链式backward_chain

证明一个具体目标，给出最小证据链——给合规看就靠它。

Datalog递归推理

任意深度递归遍历：供应链传导、组织架构穿透。

SPARQL模式查询

在增强后的工作记忆上跑图模式匹配。

后四模式与官方红线
modes + caveat
RETE 网络ReteEngine

100+ 规则大集用：alpha/beta 节点网络做增量传播，新事实不来就不重算。推文提到它的条件匹配当前还比较简单——README 同样披露，上合规生产前先自验。

时序推理Temporal

Allen 区间关系：时间窗之间的 before/overlaps/contains。

LLM 图推理GraphReasoner

留给大家口：对图上下文做自然语言自由查询。

自然语言解释ExplanationGenerator

把推理结果翻译成人话——「为什么得出这个结论」的一键答案。

选型速记： 全量物化 → forward_chain 给合规证据 → backward_chain 深层传导 → Datalog 百条规则流 → RETE 说不清why → ExplanationGenerator
出处追踪：每条事实带身份证 + 防篡改封条
provenance & audit
A · 记出处Track

ProvenanceManager(storage_path="audit.db")；track_entity() 记录每个实体的来源文件、抽取器、时间戳。文档切块后每块也有出处，父子关系保留。

B · 封校验和Seal

每条 ProvenanceEntry 写入时算 SHA-256 checksum；事后任何字段被改——误配置、迁移、蓄意篡改——重算对不上，状态变 TAMPERED。

C · 追血缘Trace

trace_lineage() 沿 parent 链上溯：这个实体从哪来、被谁加工、经过哪些版本。合规审计的核心动作就这一个调用。

D · 交合规Export

PROV-O 字段一对一映射（entity/activity/agent/role/wasDerivedFrom），role 支持 generator/approver/reviewer——四眼流程直接建模。导出 JSON/CSV/RDF。

TAMPERED 状态 = 记录在写入后被改过，合规使用前必须先查清楚。
README「Verifying integrity」原意；医疗审计 recipe：药物相互作用决策链 → add_causal_relationship(CAUSED) → to_kg_dict() → audit_trail.ttl
决策即节点
decision intelligence

一段代码记录一个可审计决策core api

context = AgentContext( vector_store=VectorStore(backend="faiss", dimension=768), knowledge_graph=ContextGraph(advanced_analytics=True), decision_tracking=True, ) decision_id = context.record_decision( category="model_selection", scenario="为生产推理管线选 LLM", reasoning="GPT-4 基准优势证明 3x 成本合理", outcome="selected_gpt4", confidence=0.91, ) context.find_precedents("model selection", limit=5) context.analyze_decision_influence(decision_id)
批注：find_precedents 防止同一团队在不同会话里对同类问题做出不一致选择——决策历史变成可检索资产，不是聊天记录里的流水。
因果链与信任分级
causality & trust tiers
1
三种因果关系

add_causal_relationship 只允许 CAUSED / INFLUENCED / PRECEDENT_FOR 三种类型——枚举约束保证图语义干净。

2
信任四级

v0.7.0 起图事实带 corroboration 信任档：quarantine → bronze → silver → gold，按证据佐证度升降。

3
真值维护

TruthMaintenanceSession 追踪事实的支持与撤回（非递归规则），ContextRetriever 可按「当前被支持的事实」过滤检索上下文。

4
Schema 校验

SchemaValidator 拿领域本体校验抽取输出；bootstrap_schema 能从已抽数据自举一份草稿本体供人工批改。

接进你的 AI 助手：MCP server 15 件工具
mcp server
01 · 启动semantica-mcp

stdio 传输：不是 REST 服务，无端口无 API key——AI 客户端把它作为本地子进程拉起，输入输出走 stdin/stdout，天然继承你的本地文件权限。

02 · 持久化KG_PATH

设 SEMANTICA_KG_PATH=/data/graph.json 图才跨重启存活；不设则是内存图，进程退出即清空——官方 Info 框原话提醒。

03 · 接客户端Claude 系

Claude Desktop 配置文件加一条 mcpServers（macOS 在 ~/Library/Application Support/Claude/）；Cursor、Windsurf 同理——任何兼容 MCP 的客户端都能接。

04 · 对话即用图15 tools

extract_entities / extract_relations / add_entity / add_relationship / query_graph（节点邻居最多 5 跳）/ update_node / delete_node 等 15 件工具 + 3 个只读资源；agent 自己编排调用顺序。

批注：这一步的实际意义——分析师在 Claude Desktop 里贴一份 OSINT 报告，agent 自动抽实体、入图、跑查询、录决策；图和审计留在你本机，不出域。

边界与红线：什么时候别用它
boundaries
✓ 适合Good fit

强监管域的 AI 决策留痕；多源数据织图；需要确定性推理而非概率回答；agent 记忆与决策复盘；合规审计导出。

✗ 慎用Not fit

纯语义相似度检索（用向量库就够）；轻量聊天机器人记忆（杀鸡用牛刀）；无规则可写的纯直觉任务。

⚠ 红线Official caveat

RETE 引擎条件匹配当前较简单（官方与推文双重确认）；上合规生产前必须用自己的数据验证结果——这句是官方 README 原话，不是保守套话。

词汇表
glossary
Context Graph 上下文图谱vs KG

agent 的「知道+决定+推理」总账本；知识图谱（KG）偏世界事实，上下文图谱偏过程记录。

PROV-OW3C 标准

出处描述的本体词汇表：Entity/Activity/Agent 三元骨架，合规导出的目标格式。

RETE算法名

1980 年代的高效规则匹配算法：用 alpha/beta 网络避免重复求值，规则多时的增量引擎。

GraphRAG检索增强

把 RAG 的向量检索升级成图检索：社区分层摘要 + 全局 Map-Reduce，答「整体性问题」更稳。

SHACL / OWL / SKOS本体三件套

约束校验 / 形式化类与属性 / 词表映射——治理层的三个 W3C 标准，Semantica 内建支持。
