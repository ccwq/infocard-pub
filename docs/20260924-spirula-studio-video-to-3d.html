为什么它省事：传统 3DGS 三座大山，逐个拆

做过三维高斯泼溅的都懂：环境是第一道墙。Spirula 的解法不是「打包得更优雅」，而是把训练引擎整个用 Vulkan compute 重写——底层是其作者一作、发表于 Eurographics 2026 的 VkSplat 论文，号称首个达到 SOTA 性能的全 Vulkan 3DGS 训练管线。

环境依赖清零

传统流程：COLMAP 算位姿 + Python/PyTorch 环境 + CUDA 工具链，配一趟三小时起步。Spirula 解压即用：Windows 包 33-39MB，macOS DMG 45-55MB，双击开 GUI；云端训练走 CLI（spirula train 自带 HTTP 查看器，SSH 端口转发即可盯进度）。

显卡解锁

CUDA 生态把 AMD/Intel/苹果用户挡在门外；Vulkan 后端全厂商通吃，macOS 经 MoltenVK 静态链接、零依赖运行。代价也有：论文实测同场景 RTX 3090 跑 575 秒、RX 7800 XT 跑 1201 秒——AMD 慢约 2.1 倍，最大瓶颈在主机→显卡的 loss 数据传输（24s vs 303s）。

【v2 扩充】初学者完整指南：从一部手机视频到可分享的 3D 模型

以下内容全部取自官方 docs/datasets.md（4.9 万字符的官方拍摄指南）、VkSplat 论文 Table 1、以及 issue 区作者亲自回复——每一条都能在仓库里对到原文。目标读者：第一次碰 3DGS 的人。

先搞懂 5 个词：3DGS 黑话速查

术语人话解释
高斯点 / Splat场景由几百万个带颜色、带透明度、带朝向的半透明椭球「点云团」拼出来。渲染时像泼颜料一样把每个椭球「泼」到屏幕上——所以叫 splatting（泼溅）。Spirula 的 .ply 产物就是一堆这种椭球的参数。
SH3（三阶球谐）每个椭球存 48 个系数描述「从任何角度看是什么颜色」（含高光随视角变化）。SH3 = 最高质量档，也是显存大头——8GB 训 1000 万个指的就是它。
SfM（运动恢复结构）从一堆照片反推「每张照片是在哪、朝哪个方向拍的」+ 一份稀疏点云。传统上由 COLMAP 干，Spirula 内置了自己的实现，还能选 LoMa 特征匹配对付难拍的场景。
PSNR / SSIM / LPIPS三个「重建得像不像」的打分：PSNR 越高越好（dB），SSIM 越接近 1 越好，LPIPS 越接近 0 越好。VkSplat 论文 Table 1 实测三者与 CUDA 基线打平。
Floater（漂浮物）悬空半透明「脏斑点」，训练不充分或素材质量差时的典型瑕疵。Spirula 的 MCMC/IGS+/MRNF 混合策略主打「更锐利、更少 floater」。

拍素材：官方指南里的硬规则（决定成败的一步）

3DGS 成品质量七分靠素材。以下全部出自官方 docs/datasets.md 与作者在 issue 区的回复：

规则为什么 + 官方依据
动相机，别只原地转视差（近处物体相对远处移动）是三角测量的原料。原地旋转拍 360° 视频对普通相机模式几乎无效——自适应抽帧系统对「纯旋转」的代价打分为 0（球面上转向免费），几乎不抽帧。正确做法：围绕主体或沿路径平稳移动拍摄。
相邻画面保持足够重叠SfM 靠重叠区域匹配特征。issue #69（中文用户）两次遇到「重叠少/镜头模型不对」重建失败，作者建议升级 v2026.9.13 后重试——新版本支持取消后改参数从特征匹配阶段重跑，不用从头再来。
手持抖动不用怕自适应抽帧用仿射合成消除「抖回来」的动作：实测合成后典型窗口降到求和的 0.65–0.70，最抖的 10% 降到 0.0–0.4——抖腕不再白耗抽帧预算。但大范围快速甩动仍然要避免。
分辨率不用执着运动分析前所有画面统一缩到灰度小帧，实测 3840px 与 1920px 的代价打分差 0.0005（约 2% 以内）——4K 素材对抽帧决策没有优势，反而拖慢扫描（1080p 13 分钟视频扫描约 165 帧/秒）。
360 全景是特殊赛道GoPro MAX 的 .360 文件 = 双 HEVC 轨道的 EAC 3×2 立方体映射，Spirula 原生拆成 10 个视图（cam0–cam9）作为一组 rig。全景旋转不花钱、只有位移算钱——拍 360 时要「走」不要「转」。
别混拍普通相机 + 全景issue #53：360 相机 + 普通相机混用导致重建结果倾斜。v2026.9.13 的「从遥测元数据恢复真实尺度与朝向」就是治这一族问题——更新到新版再用混合素材。

GUI 五步流水线（每步会发生什么 + 可调什么）

步骤后台在干什么你能调的参数（官方文档确认）
① 导入素材识别输入类型：视频 / 照片 / 已完成的 COLMAP 数据集（自动检测顺序 Nerfstudio → COLMAP → Metashape 三种布局）每个视频单独设抽帧率（v2026.9.24 起 per-video rate）；多段素材共享一个自适应预算
② 建数据集GPU 解码抽帧（开 PATENTED 比外调 ffmpeg 快约 15×）→ 运动分析定自适应帧距 → SAM 抠前景遮罩 → 内置 SfM 算位姿镜头模型选错可「取消 → 改模型 → 重建数据集」，从特征匹配阶段续跑；alpha 通道的透明素材自动变成遮罩
③ 训练Vulkan 引擎跑 3DGS：量化训练压显存，MCMC/IGS+/MRNF 混合致密化，PPISP + 双边网格做曝光/白平衡校正train_resolution_divisor＝「调小分辨率换速度」旋钮（2 = 边长减半）；eval_mode 选 all/fraction/interval/filename 留验证集
④ 检查内置预览视图：Motion 视图逐条素材画「画面变化曲线 + 实际抽帧率」，一个比例尺，谁动得多谁被抽得密一目了然训练中途的 splat 已可在 Web Viewer 里看；seed 点可设 auto/always/never 随机初始化
⑤ 导出v2026.9.24 起支持编辑 3DGS/稀疏重建/网格 + 导出图像/视频渲染；带贴图网格（meshing）用 Delaunay 四面体剖分meshing 是最重的一步：issue #73 在 RTX 4060 Ti 16GB 上 1.87 亿四面体剖分失败——大场景先降分辨率再 mesh

三个官方实测案例：参数怎么影响速度和显存

下面数字全部来自官方 datasets.md 在 RTX 5070 笔记本上的实测，帮你建立「改参数 → 多大后果」的直觉：

实验设置 A设置 B结论
1000×1500 鱼眼（108°–162° 视场）uniform 面片 5×548²，1 pass：27.6s / 804 MiBper-face 3 passes：31.1s / 692 MiBper-face 省 14% 显存、慢 13%——显存不够时的逃生门
960×960 鱼眼（~200° 视场）uniform：32.3s / 818 MiBper-face：35.4s / 858 MiB反例：边带全满时 per-face 反而更慢更吃显存——不是万能开关

新手最容易踩的 6 个坑（含官方补救法）

坑症状 → 官方给的出路
① 镜头模型选错重建失败或畸变离谱 → v2026.9.13 起：点 Cancel → 改对模型 → Create/Update Dataset，从特征匹配阶段续跑，不必全重头（issue #69 作者回复）
② 竖拍素材横躺EXIF 方向标签默认不被读取 → 视频抽帧默认已自动转正（auto_rotate）；照片重编码时烘焙方向；--exif-orientation 的 orient/apply/none 三档在 sfm 和 train 两步必须一致
③ 重建结果太大/太小/倾斜SfM 没有绝对尺度 → v2026.9.13 从视频/照片遥测元数据（GPS/IMU）恢复真实尺度与朝向；EXIF GPS 版本 9.8 已上
④ Windows 杀毒报毒issue #92：v2026.9.20 被 Defender 报 Wacatac——作者定性误报并已提交微软分析。从官方 Releases 页下载 + 校验来源，别下第三方转载包
⑤ mesh 导出卡死/报错issue #73：四面体数量上亿时显存吃紧 → 先用 train_resolution_divisor 降分辨率训练再 mesh，或砍掉场景边缘（离主机位远的区域四面体爆炸）
⑥ 想接自动化（API/MCP）issue #94 已有人提、官方尚未实现——目前只有 GUI/CLI 两条路；CLI 的 spirula train 自带 HTTP viewer 可远程盯进度，服务端场景够用

进阶：两条许可证红线与三条求救路径

许可证红线（商用前必读）

  • 本体 GPLv3：自用/研究零障碍；做成产品分发需开源同协议。想闭源集成？联系作者商业授权是唯一正道。
  • -DSS_ENABLE_PATENTED=ON：启用 GPU 视频解码（抽帧快 15×）但 AVC/HEVC 解码器有专利授权费问题——官方文档原话「你需要自己确保符合当地专利法」。默认 OFF，自编译者自行抉择。
  • SAM 遮罩模型：永不打包。SAM 2.1 = Apache-2.0 友好；SAM 3 = Meta 自家非标准许可证。GUI 首次使用先展示条款再下载，选哪个看你的使用场景。
