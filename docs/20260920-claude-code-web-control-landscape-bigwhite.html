Claude Code Web 控制方案全景

让 Web 页面接上 Claude Code，不是“把终端塞进网页”这一件事，而是三条不同的路线：官方 Remote Control 接管已有会话，PTY/WebSocket 复用终端进程，Agent SDK Web UI 重建控制面。先确定“谁拥有会话”，再选 Web UI。

SESSION 层Remote Control / Agent SDK：控制 Claude 会话与消息。
TTY 层PTY + WebSocket：控制终端进程的画面与按键。
平台现实没有成熟方案可无条件 attach 任意已打开的 Windows Terminal。

ROUTES · 路线辨析
PAGE 02

三条路线控制的东西不同

A
Remote Control

接管已有 Claude 会话：浏览器与本地终端共享同一 session、权限提示与任务状态；本机不开放入站端口。

B
PTY / WebSocket

接管终端进程：xterm.js 只负责渲染，node-pty / ConPTY / tmux 才是执行边界；等价于把 stdin 交给浏览器。

C
Agent SDK Web UI

用 @anthropic-ai/claude-agent-sdk 的 query() 重建控制面：结构化事件流、权限与计划审批，不显示原始终端。

OFFICIAL · 官方入口
PAGE 03

Remote Control：默认首选

# 服务器模式：托管多个会话
claude remote-control

# 已有交互式会话内
/remote-control

工作方式：本机 Claude Code 只发起出站 HTTPS，经 Anthropic API 转发；浏览器在 claude.ai/code 打开同一会话。本地文件、MCP、工具、项目配置保持可用。

边界：需 claude.ai 登录，不支持纯 API Key；Bedrock / Vertex / Foundry 与自定义 ANTHROPIC_BASE_URL 场景不可用；部分终端专属命令（如 /plugin、/resume）仍需本地 CLI；本地进程退出后会话离线。

ARCH · 官方链路
PAGE 04

会话层：官方托管转发

# 浏览器看到的是结构化会话，
# 不是终端画面
claude.ai/code  ─┐
Claude 手机 App ─┤  Anthropic API (TLS)
                 ▼
        本机 Claude Code 进程
                 ▼
     本地文件 / MCP / 工具 / 配置

本机不开放入站端口；transcript 在 Remote Control 期间同步到 Anthropic 服务端以支持多设备与断线恢复，保留策略遵循其数据条款。协议细节（握手、token 语义、多端写入策略）未完整公开，不应自行假设。

ARCH · 自建链路
PAGE 05

TTY 层：PTY Broker 是执行边界

# 浏览器永远只连 Broker，
# 不直连 PTY 或 tmux socket
xterm.js ── WebSocket ── Auth Broker
                          ├─ node-pty / ConPTY
                          ├─ tmux / psmux
                          └─ claude / claude --resume

xterm.js 官方定位是终端渲染组件，不是 shell。谁持有 PTY，谁就拥有命令执行权。Broker 必须承担：认证、Origin 校验、会话注册表、单 writer、断线重连与输出缓冲。

RISK · 安全底线
PAGE 06

WebSocket 可写 ≈ 远程终端输入

PTY Web UI 一旦被未授权访问，等价于远程命令执行入口。基线：

· 默认只监听 127.0.0.1，远程用 Tailscale / WireGuard / SSH 隧道；
· WebSocket 校验精确 Origin + CSRF / 一次性配对 token；
· 每个 session 默认单 writer，其余连接只读 observer；
· 限制连接数、消息大小与 PTY 数量，记录审计日志；
· 凭证、环境变量、.env 永不进浏览器。

SDK · 路线 C 备注
PAGE 08

fafawlf/claude-code-web 不是 PTY

与 vultuk 同名不同物：它基于 @anthropic-ai/claude-agent-sdk 的 query()，用 Fastify WebSocket 驱动 SDK 管理的会话，提供 cwd / resume / permissionMode / 事件重放。控制的是 Agent 能力面，不 attach 现有终端、不显示 TUI 画面。默认 loopback + token，单用户定位。

“接管已有 TUI”要拆开看

方案接管对象是否显示原始终端能否接任意已开窗口
Remote ControlClaude 会话层否，结构化 UI按官方会话语义，非任意终端
PTY 项目终端进程层是通常仅限自家托管的 PTY/tmux
Agent SDK UIAgent 生命周期否否，新建/恢复 SDK 会话
BOTTOM LINE
托管
优先

没有方案能无条件抓取任意已打开的终端窗口。可靠的模型始终是：Broker 托管 ConPTY / psmux / tmux 会话，已有对话用 claude --resume <session-id> 恢复，而不是直接抓取窗口。
