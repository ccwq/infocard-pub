AI AGENT SYSTEM · ARCHITECTURE MANUAL

AI智能体系统：不是“有脑子”，而是会循环的应用架构

把用户素材拆成一条可工程化链路：Message数组承载对话，后台把历史打包成上下文载荷，System Prompt设定最高规则，模型只“预测下一段文本”，工具调用/RAG/ReAct/多智能体都由外层代码协议接管。

核心：自回归续写载荷：JSON Message数组控制：System Prompt外循环：ReActRAG ≠ 灌进大脑
一句话定位

AI智能体系统 = 无状态大模型 + 有状态应用层 + 可解析工具协议 + 检索证据 + 循环调度 + 人类审核边界。

01
FOUNDATION

消息交互：统一 Message数组 是智能体的“短期工作台”

多数聊天/Agent API 都把对话组织为角色化消息列表。模型没有真的看见过去，只看见本次请求塞进上下文窗口的内容。

数据结构

JSON Message数组

历史记录以 User / Assistant 等角色消息排列；后台按顺序把系统规则、历史对话、检索片段和工具说明拼成一次请求。

运行机制

概率续写，不是数据库查询

大模型阅读消息数组后预测下一句话/下一段结构化文本。智能感来自训练统计与上下文提示，不等于内部存在稳定记忆对象。

工程含义

应用层负责状态

“记住你刚才说过”其实是应用把历史再次放进 payload；如果没放进去，模型就像全新开始。

02
PIPELINE

从 Prompt 到行动：七段式架构链路

这条链路表达本卡主线：消息数组 → 上下文载荷 → 系统提示词 → 工具协议 → RAG → ReAct外循环 → 多Agent编排。

1 Message数组User / Assistant 历史记录与当前问题，形成可读上下文。
2 Payload打包后台选择、裁剪、摘要并注入历史，平衡窗口与成本。
3 System Prompt位于数组顶部，设定人设、边界、输出规则与优先级。
4 Tool Protocol模型输出规范化指令；代码解析并真正调用 API / 文件 / 浏览器。
5 RAG证据先检索向量库/知识库，再把证据拼入 Prompt，像开卷考试。
6 ReAct循环Thought → Action → Observation 由外层代码轮询推进。
7 多Agent总控Agent拆解任务，垂直Agent执行，汇总后验收。
03
PROMPTING

提示词工程：控制方向，不是给模型装插件

System Prompt、CoT、Few-Shot、Pre-fill 是“让输出更可控”的工程手段；它们不改变模型无状态和概率生成的底层性质。

人设控制System Prompt

最高行为准则放在顶部

  • 定义角色、任务、禁区、格式与优先级。
  • 对话越长，越需要定期重申关键约束。
  • 系统提示词不是安全银弹，仍会被上下文噪声和攻击影响。
格式锁定Few-Shot / Pre-fill

用示例与开头前缀压住跑偏

  • Few-Shot 给真实输入/输出样例，降低格式自由度。
  • Pre-fill 在 AI 开口前写入“{”等前缀，让解析器更容易拿到纯净 JSON。
  • 非必要不引入多层嵌套，标准解析器稳定性优先。
逻辑推理CoT

把中间步骤转成线索

“一步一步计算”能提升复杂问题的可控性；生产系统更常把推理压缩为可审计摘要或隐藏 scratchpad，避免泄露与冗余。

输出约束

让机器读，而不只是让人看

智能体系统的核心交付常常不是一段漂亮话，而是可解析的 JSON、函数参数、状态枚举或下一步计划。

04
TOOLS & STOPPING

工具调用与阻断：AI 输出“指令”，代码完成“行动”

工具调用的关键不是模型真的拥有工具，而是它学会按协议生成工具名和参数；执行权始终在应用代码。

运行协议

模型输出类似 {"tool":"search","query":"..."} 的规范化文本；应用层校验 schema、权限和参数后再执行。

停止序列

设置 Observation 等阻断词，相当于在 Action 后强行踩刹车，把控制权交还代码，等待真实工具结果。

安全边界

工具执行前必须做 allowlist、参数校验、审计日志与高风险人工确认；不能把模型输出直接当 shell 命令信任。

05
KNOWLEDGE & MEMORY

记忆管理与 RAG：把“遗忘”变成可控的数据管线

大模型单次请求间天然无状态；Agent 的记忆来自应用层持久化、检索、摘要与重注入。

无状态特征

每次请求都是新开始

模型权重不会因为某次对话即时写入长期记忆；所谓上下文记忆，是服务端把相关历史重新拼回本轮 payload。

RAG

开卷考试，不是灌输给大脑

程序先从向量数据库/搜索索引检索私有数据，再拼接进 Prompt。模型依据这些材料回答，但材料本身不会自动变成模型权重。

层做什么典型风险最佳实践
上下文窗口承载当前可见材料过小遗忘；过大成本高且注意力分散摘要、裁剪、分层检索，保留任务关键变量
短期状态记录当前任务进度、工具结果Observation 污染后续推理结构化存储，不把噪声全塞回 Prompt
长期记忆跨会话保存偏好、事实、项目知识过期、冲突、来源不可追溯带时间戳、来源、可删除与人工校正机制
RAG证据补充私有知识与实时资料召回错误、片段断章取义多源交叉、引用出处、高风险人工审核
06
ORCHESTRATION

多智能体编排：像职场分工一样拆解、执行、汇总

多Agent不是魔法叠加，而是把复杂任务按角色、上下文与验收标准切开，降低单个上下文的认知负担。

包工头 Agent

拆任务 / 定接口

把目标拆成研究、实现、测试、审计等子任务，明确输入、输出、验收标准和合并规则。

垂直小弟 Agent

专注执行

每个 Agent 只拿必要上下文，专注一个领域，减少互相污染；完成后交付证据而非只交付结论。

验收 / 汇总

回到主控闭环

主控汇总结果、检查冲突、运行测试，并在高风险节点引入人工审核。

07
GUARDRAILS

约束与最佳实践：承认幻觉，然后工程化压制

幻觉来自自回归生成机制的底层特性，无法彻底消除；可靠系统靠证据、解析、权限与人工闸门降低损失。

上下文平衡

窗口过小会忘记，过大则成本高、注意力分散。做法是把“必须记住的状态”结构化，把“可检索资料”放 RAG，把“临时噪声”及时丢弃。

幻觉压制策略

RAG 提供依据；工具返回真实 Observation；输出必须能被解析器校验；涉及金融、医疗、权限、发布等高风险节点，加入人工审核。
