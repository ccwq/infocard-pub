不是普通 code review

这是一个极严格的可维护性审查技能，关注抽象质量、巨型文件、分支复杂度和代码库健康，而不只检查功能是否通过。

核心动作Code Judo

优先删除复杂度

审查的关键问题是：能否通过重构让整段分支、helper、mode 或条件判断直接消失，而不是把同一套复杂度换个位置。

审查范围可维护性

它具体盯什么？

  • 结构性回归：模块是否更耦合、更难扫描。
  • 分支与特殊情况：是否把一次性 if 继续塞进忙碌流程。
  • 边界与契约：是否滥用 any、unknown、cast、可选参数掩盖真实不变量。
  • 文件规模：没有充分理由，不应把文件从 1,000 行以下推过 1,000 行。
  • 层次归属：逻辑应放在真正拥有该概念的 canonical layer。
硬门槛

不因“能工作”就批准

通过测试只是起点。若实现保留了明显的偶然复杂度、特殊分支或薄包装，仍应要求结构性改写。

输出优先级

先结构，后细节

先看结构回归与简化机会，再看分支、边界、拆分、模块化和可读性，避免被低价值命名建议淹没。

使用边界：该技能在官方 SKILL.md 中标记为 disable-model-invocation: true。它适合显式发起的严格审查，不应被模型自动触发。

# 适用请求
对当前分支做一次严格的可维护性审查：
- 找结构性回归
- 找能删除复杂度的 code-judo 重构
- 检查 1k-line、spaghetti、边界与层次问题
- 不因测试通过而降低批准标准
适合

合并前的分支审查、复杂重构、代码质量专项、担心文件膨胀或特殊分支失控的项目。

不适合

只想快速确认语法、格式或单个运行时错误时，不需要使用这套高强度维护性门禁。
