herdr：Agent 感知的终端工作区管理器

为 AI 编程代理设计的终端复用工具：在同一个工作区里并排运行 Claude Code / Codex / OpenCode，自动识别每个 pane 里的 Agent 状态（working / blocked / done / idle），让"多 Agent 协作"从脚本拼接到可视化工作台。

开源 CLI Agent 检测 Workspace 编排 tmux 进化版
GitHub ≈ 27k stars 500+ 社区插件 YC 项目 Windows Beta
核心定位：不是又一个 tmux，而是"认识 Agent"的终端工作区

普通终端复用器只知道 pane 里有个进程；herdr 能识别 pane 里跑的是哪个 Agent、处于什么状态，并把多 Agent 的工作区状态聚合到一个界面。安装、配置、极简工作流与检测机制都在下面。

01
POSITIONING

它解决什么问题

多 Agent 并行开发时，终端窗口一多就失去秩序；herdr 把"窗口管理"升级为"工作区 + Agent 状态管理"。

是什么定位

Agent 感知型工作区管理器

在终端复用（tmux/screen 类能力）之上，增加对 AI 编程代理的语义识别：知道每个 pane 在跑什么 Agent、处于什么状态。

  • workspace / tab / pane 三级结构
  • pane 是真实终端进程载体
  • 状态：working / blocked / done / idle
不是什么边界

不是普通终端复用器

如果只是分屏、跳转、持久会话，tmux 已经够用。herdr 的差异在"Agent 语义层"：状态检测、生命周期 hooks、多 Agent 协作界面。

  • 不是 tmux 皮肤
  • 不是 CI / 任务调度器
  • Agent 状态≠进程是否存活
适用场景

谁最需要它

同时跑多个 AI 编码代理的开发者、需要"一项目一工作区"的团队、想在终端里可视化多 Agent 进度的用户。

  • Claude Code + Codex 并行改代码
  • 前端 / 后端 Agent 分工同一仓库
  • 长任务 detach 后继续跑

INSTALL

安装与更新

官方文档提供脚本、包管理器与手工二进制三种路径；Windows 为 Beta 支持。

// Linux / macOS（官方脚本）
curl -fsSL https://herdr.dev/install.sh | sh
// Windows（Beta，PowerShell）
powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"
// 包管理器
brew install herdr
mise use -g herdr
nix run github:herdrdev/herdr/v0.x.y
Linux x86_64
herdr-linux-x86_64
Linux aarch64
herdr-linux-aarch64
macOS
herdr-macos-x86_64 / aarch64
Windows (Beta)
herdr-windows-x86_64.zip
更新：直接运行 herdr update，官方脚本安装的版本支持自更新。
03
QUICK WORKFLOW

极简工作流：5 步跑通

从安装到多 Agent 并行，最小可用路径。

// 第 1–2 步：启动 + 跑 Agent
herdr                          # 进入工作区
# 在一个 pane 里运行任意受支持的 Agent
claude                         # 或 codex / opencode
// 第 3 步：pane 操作快捷键
Ctrl+b v   垂直分屏
Ctrl+b -   水平分屏
Ctrl+b c   新建 pane
Ctrl+b w   切换 workspace
Ctrl+b q   退出当前 pane
// 第 4–5 步：后台与停止
# detach 后任务继续跑，重进即可恢复
herdr

# 停止会话 / 重载配置
herdr server stop
herdr server reload-config
建议约定

一项目一 workspace

官方推荐按项目划分 workspace：每个项目一个工作区，内部用 tab / pane 组织不同 Agent 或任务。

  • workspace = 项目边界
  • tab = 任务组
  • pane = 单个终端进程（Agent）
  • session = 可 detach 的持久会话

01 / 状态

working

Agent 正在执行任务

前台进程 + 输出特征联合判断。

02 / 状态

blocked

Agent 卡住 / 等待输入

需要人类介入的信号。

03 / 状态

done / idle

任务结束或空闲

用于工作区总览排序。

04 / 来源

检测层级

foreground process

screen manifest + lifecycle hooks / plugin 三层。

检测机制：herdr 通过前台进程识别判断 pane 里跑的是什么；screen manifest 描述工作区结构；lifecycle hooks / 插件 上报 Agent 生命周期事件。外层 wrapper 或嵌套 tmux 会干扰识别，官方建议直接裸跑 Agent。

配置与常用命令

06
LIMITS & RISKS

限制与注意点

上手前值得知道的边界。

1

Windows 仍为 Beta

官方将 Windows 标为 Beta 支持，生产环境优先 Linux/macOS；部分 Agent 状态检测在 Windows 上表现可能不完整。

2

外层 wrapper / 嵌套 tmux

在 tmux 里再套 herdr，或给 Agent 包一层 wrapper 脚本，会干扰前台进程识别与状态检测。建议直接裸跑 Agent。

3

规模数字随时间变化

GitHub stars、插件数与下载量为抓取时快照（约 25k–27k stars、500+ 插件、340k downloads），发布时以仓库实时数据为准。

收口：什么情况下选 herdr

当你同时在终端里跑多个 AI 编码 Agent、需要"一项目一工作区"的结构化编排、并想一眼看到每个 Agent 是 working 还是 blocked 时，herdr 是 tmux 的语义升级版。

  • 核心价值：Agent 状态聚合 + 工作区编排，不是单纯终端复用
  • 上手成本：一条命令安装，5 步跑通，配置是单文件 TOML
  • 边界：Windows Beta、嵌套终端影响识别、生态数字随时间变化
