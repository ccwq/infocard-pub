核心定位

它做的不是“再搜一遍仓库”，而是先把仓库变成图，再让你问图

README 的开头已经把定位说透了：只要在 AI coding assistant 里输入 `/graphify .`，Graphify 就会把当前项目映射成知识图，然后产出 `graph.html`、`GRAPH_REPORT.md` 和 `graph.json` 三个结果文件。重点不在报告本身，而在于它后续可查询、可继续复用，而不是一次性浏览。

  • graph.html浏览器里点节点、筛选、搜索
  • GRAPH_REPORT.md项目亮点、意外连接、建议问题
  • graph.json真正的图数据底座，后续可以 query / path / explain

怎么工作

从文件夹 → 抽取 → 图谱 → 查询 → 助手工作流

Graphify 的真正主线不是“做 HTML 图”，而是“把所有输入压成一个可以复用的查询层，再让助手总是先查图而不是直接读全仓”。这一点让它更像 memory / graph context layer，而不是一次性知识整理器。

01

你对当前项目运行 `/graphify .`，它开始抽取代码、文档、媒体和配置。

02

产出 `graph.html`、`GRAPH_REPORT.md`、`graph.json`，前者给人看，后者给助手继续查询。

03

再运行 `graphify install`，把“优先查图”这条规则写入 Claude Code / Codex / Cursor / Hermes / OpenClaw 等平台的工作流里。

04

之后助手就会用 `query` / `path` / `explain` 方式先向图提问，而不是从零扫文件。

为什么这对 AI coding assistant 有用

当项目包含代码、数据库、基础设施、文档、图片和研究材料时，普通搜索只能一块块找；Graphify 试图先做实体、关系和路径层，把“局部问题”提升成“图上的连接问题”。

Path

查两个节点之间怎么连起来：`graphify path "UserService" "DatabasePool"`

Query

直接问图：`graphify query "what connects auth to the database?"`

Serve

把 graph.json 暴露成 MCP / server，供一整个团队或多个 agent 消费。

安装与接入

真正上手门槛不高，但要注意它的包名和命令名不是同一个

README 专门强调：PyPI 包是 graphifyy（双 y），但 CLI 命令仍然是 graphify。这类细节如果不写进卡里，读者很容易装错包或误以为命令不可用。

  • 推荐安装uv tool install graphifyy
  • 替代方案pipx install graphifyy
  • 接入助手graphify install
  • 项目内安装graphify install --project

边界与取舍

它不是零成本黑箱：图谱质量仍取决于抽取范围、后端和依赖环境

Graphify 很强，但不是魔法：要启用 PDF、Office、Google Workspace、video、neo4j、terraform、dm 等能力，还需要额外 extras。它的价值在于把这些能力整合进同一图，而不是承诺“默认全开、零配置”。
