Ghost-Downloader-3

一个应用接管六种协议：HTTP、磁力 / BT、FTP、M3U8、MPEG-DASH、eD2k。桌面端负责下载，浏览器扩展只负责嗅探，并把任务交给桌面端。

01先做这一步get started

STEP 0-1
装桌面端

从 releases 页下载对应平台的安装包并安装。Windows 10+、macOS 13.0+、Linux glibc 2.35+、Android 11.0+。

STEP 0-2
配对浏览器扩展

安装浏览器扩展，把扩展连接到桌面端。扩展只做嗅探与转发，下载由桌面端执行。

STEP 0-3
第一次下载

在浏览器点击下载链接，GD 自动接管任务；链接不用复制，也不需要手动粘贴到客户端。

02核心机制how it works

合而不同

一个应用，六种协议

官方定位是「下载器的集大成者」（README 英文版：The only downloader you need）。六种协议不拆成六个客户端：

HTTP 磁力 / BT FTP M3U8 MPEG-DASH eD2k

站点专属能力：YouTube 与 Bilibili 支持框选片段、任意画质与字幕、播放列表与合集分 P；GitHub 与 HuggingFace 走镜像加速。

快在刀刃
  • 智能分块，无需合并文件
  • 自动适配带宽
  • 使用真实浏览器 TLS 指纹，不触发风控
尽在掌控
  • 兼容 aria2 RPC API，第三方工具可直接推送任务
  • 下载途中可改链接、改请求头、改代理
  • 改动过程进度不丢失
一触即发

下载按钮跟随视频，扩展只负责嗅探

下载按钮跟随视频画面出现。扩展窗口列出当前页面上所有媒体资源，在扩展里点击，或者照常点击下载，桌面端都会无缝接管。链接不用复制，任务还带着验证状态。

扩展嗅探→ 桌面端
下载执行桌面端
同一软件覆盖四个系统

各平台原生体验。上游组件包括 Kelpie（eD2k 引擎）、N_m3u8DL-RE（DASH/HLS/MSS，支撑 M3U8 支持）、libtorrent、yt-dlp、wreq（TLS 指纹模拟）、PyQt-Fluent-Widgets / PySide6 等。

口径纠正 · 平台架构

推文写「Windows、macOS、Linux、安卓四个平台都装，x86_64 和 arm64 都支持」，不准确。README 平台表里只有前三者同时提供 x86_64 与 arm64；Android 11.0+ 只有 arm64-v8a，没有 x86_64 构建。装之前先确认设备架构。

05已知限制与边界limits

  • CPU 指令集：Qt 6.6+ 已不再支持不支持 AVX 指令集的 CPU。老机器装不上或跑不起来。
  • Android 架构：11.0+ 仅 arm64-v8a，没有 x86_64 构建。
  • 插件 API 尚未公开：功能包（Feature Packs）体系已运作，作者自述 API 仍在稳定中；面向外部开发者公开插件 API 仍在路线图上。
  • 许可约束：GPL-3.0。基于它做衍生作品，需要同样开源。
  • 路线图另一项：更强大的任务编辑功能（一个任务绑定多个 Sessions 等），尚未落地。
未核验

推文里「网页里的视频得先装个嗅探插件」等使用场景描述属作者主观体验，本卡未做实测。README 未给出下载速度的量化对比；文档站有 2026-07-30 的单次实测记录页，本卡未逐项核对。
