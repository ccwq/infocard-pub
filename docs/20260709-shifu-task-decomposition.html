让贵的模型只做"规划"，让便宜的模型执行——双模型分工协作大幅降本

Shifu 是一个 Agent Skill（技能文件），将复杂任务拆解为自包含的规格说明（spec），交给便宜的模型执行，贵模型只负责理解全局、判断边界、写无歧义规格。最终 reconcile 由贵模型审查便宜模型的修改，直到通过。灵感来自 shadcn 的 improve，但更简单通用。

# Shifu 自动：分析 → 拆解 → 写 plans/ → 派发便宜模型 → 审查结果

核心理念：规格是产品，实现交给执行者。Shifu 本身不写一行代码——它只是写规格说明（spec）的机器。 便宜模型拿到规格后独立执行，贵模型最终 reconcile 审查，直到通过。

02 Two Modes · 两种运行模式
🤖 自动模式（推荐）
  • Claude Code / Cursor / Codex / Claude Code 等现代 Agent 原生支持 subagent
  • 在同一个会话内完成：规划 → 派发 → 审查完整循环
  • 无需切换窗口，发送一条指令自动跑完
  • 适合：大型 feature、分支并行的复杂重构
🖥️ 手动模式
  • Agent 不支持 subagent，或需要更精准的控制
  • 逐条执行 /shifu 指令，人工控制每一步
  • 步骤：规划 → 确认规格 → 手动派发给便宜模型 → 人工 reconcile
  • 适合：精确控制、调试阶段、小团队流程把控
03 Command Reference · 指令参考
指令 说明
/shifu <description> 标准分析：理解任务 → 拆解边界 → 生成规格文件到 plans/ 目录
/shifu quick <description> 轻量版：子任务更少、分析更浅，适合简单功能
/shifu deep <description> 深度版：细粒度拆解，分析更彻底，适合大型重构
/shifu execute <plan-id> 派发单个规格给 worker 模型执行（默认用便宜模型）
/shifu execute <plan-id> --model <model> 指定 worker 模型执行某个规格
/shifu execute all 按依赖顺序派发所有就绪规格给 worker
/shifu review <plan-id> 贵模型审查已有规格，优化收紧（reconcile 前置步骤）
/shifu status 查看所有 plans 的当前状态（pending / running / done / blocked）
/shifu reconcile 全局审查：验证完成项、解除阻塞、更新状态，让贵模型介入修改直到通过
04 vs improve · 与 shadcn improve 对比

Shifu 更简单

只写规格说明（markdown），任何 Agent / 人类都能读取执行，无需理解内部实现。

Shifu 更通用

不绑定特定 Agent，支持 Claude Code / Cursor / Codex / OpenCode / Gemini 等所有 skills.sh 兼容平台。

双模型协作原生

内置 execute / reconcile 机制，便宜模型执行 + 贵模型审查形成闭环，improve 没有这一层。

规格即产品

Shifu 本身零实现——它只输出规格文件，交付物清晰、可复用、可版本化追踪。

05 Hard Rules · 硬规则

Shifu 的 5 条不可违背原则：

规格是产品 Shifu 不写代码，只写规格。实现是执行者的事，不是规划者的事。
规划者不实现 贵模型只负责理解全局、拆解边界、写无歧义规格，绝不直接改代码。
规格自包含 每个 plans/*.md 独立可执行，包含上下文、验收标准、边界条件，无需额外信息。
Reconcile 强制通过 便宜模型的修改必须经过贵模型 reconcile 审查，不合格就打回，直到最终通过。
小 feature 不用 一行能搞定的事不要启动 Shifu，工具开销大于收益时不要用。
