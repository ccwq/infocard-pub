01 · 一句话判断
Core Take
core definition

把"如何写一个好 skill"从手工经验变成可优化流程：优化器模型先根据打分轨迹提出 bounded 的 add / delete / replace 编辑，再用持出验证集严格门控，只有真正提升才接受。这样得到的 skill 可以在不同模型、不同 harness 之间迁移。

SkillOpt 解决什么问题
把 skill 文档看成"冻结 agent 的可训练状态"，validation gate 看成"编辑是否进入模型"的硬阀门。训练期产出一串 skill snapshot、step patch、slow update、meta skill，最终收敛到一个可直接部署的 Markdown 工件。
关键判断：SkillOpt 的价值不在于生成更多文本，而在于让 skill 的改进过程像训练神经网络一样可复现、可比较、可回滚。
你可以怎么理解它
它训练的不是模型权重，而是 best_skill.md 文档本身。部署时零推理开销，只挂到未改动的 target model 上。
文档级优化 验证门控 可部署 artifact 跨 harness 迁移 零推理开销
02 · 训练闭环架构
Loop Architecture
skillopt loop · rollout → reflect → gate → update
current_skill.md
初始 skill + 历史片段 + epoch 更新 + 拒绝编辑缓冲SKILL
↓ 作为系统提示 + 行为规范输入
ROLL OUT
跑 harness 收集分
REFLECT
bounded edits
↓ 生成候选 patch
VALIDATION GATE hard
SLOW UPDATE
epoch 边界
↓ 输出
best_skill.md
300–2,000 tokens · 直接挂载到 target model
rejected-edit buffer
每轮被验证拒绝的编辑进入 buffer，被接受的更新保存到 skills/skill_vXXXX.md。通过检查 skills/ 目录可以看到演变历史，随时回滚。
关键不是「多写几轮」
而是「每轮都比上一轮更严格」：训练数据来自 rollouts，编辑来自 reflect，接收来自 validation gate，稳定性来自 slow-update 和 rejected-edit buffer。
03 · Validation Gate 三型
Gate Types
hard gate default
候选 skill 必须在 held-out split 上每个样本都优于或等于当前 best，否则直接拒绝。零妥协，适合最终收敛。
soft gate
看平均分是否提升，允许少量样本暂时落后。适合训练早期探索，不容易卡在局部最优。
mixed gate
前 N 轮用 soft，后期切换 hard。兼顾探索效率和最终质量，是 ckpt 快照默认方案。
gate_metric: hard # hard | soft | mixed gate_threshold: 0.0 # soft 模式最小提升量
04 · Cookbook ① 最短训练路径
Train
最小命令
python scripts/train.py \ --config configs/searchqa/default.yaml \ --split_dir /path/to/searchqa_split \ --azure_openai_endpoint https://your-resource.openai.azure.com/ \ --optimizer_model gpt-5.5 \ --target_model gpt-5.5
这条命令在做什么
1
读 configbenchmark、batch、epoch、gate、skill_init 都从 YAML 拉起。
2
跑 rollout把 current skill 喂给 target model，拿到预测与分数。
3
反思 + 过滤optimizer 只建议 bounded edit，validate 后再接受。
epochs
训练轮数：默认 4
太少学不够，太多容易在无效编辑上打转。
batch
rollout batch：默认 40
轨迹太少 gate 不稳，太多则优化器成本飙升。
learning rate
文本学习率：默认 4
控制每次文档改动幅度，不是模型参数学习率。
05 · SkillOpt-Sleep 夜间进化（2026-06-15 新增）
SkillOpt-Sleep 😴 · Preview
SkillOpt-Sleep 是什么
把 SkillOpt 的 discipline 应用到你自己的日常使用。给本地 coding agent 一个夜间睡眠周期：回顾过去会话、重放循环任务、在持出任务上验证、把学到的东西整理成经过验证的长期记忆和 skill——全程在 held-out gate 后面分级，推给你审阅后再采用。越用越强，零权重训练、零推理时额外开销。
🌙 夜间执行 🧠 Claude Code / Codex / Copilot 🔒 Held-out Gate 📦 skillopt_sleep 独立包
One "Night" 流程
harvest Claude Code / Codex transcripts → mine recurring tasks → replay offline → consolidate (reflect → bounded edit → GATE) → stage proposal → (you) adopt

可选机制：Experience Replay & Dream Rollouts （默认关闭）
dream_rollouts
每个任务跑 K 次 → 从好坏对比中学习（对比反思）。默认 1（关闭）。
recall_k
关联回想法 — 从持久化存档中拉取 K 个最相似的过去任务，加入今晚的 dream。默认 0（关闭）。
dream_factor
为每个任务添加 N 个轻量合成变体。默认 0（关闭）。

18-Cell Deployment Sweep：Dream 多样性修复是关键
引擎配置mean Δ最差 cell Δcells > +0.5cells < −0.5
单样本反思（降级）−2.66−52.87 / 185 / 18

多样化 rollouts 从根源消除了 −52.8 灾难；recall 提升网格均值并收紧最坏情况。这是纵深防御，每层均可测量。
诚实范围：增益适用于「任务重复出现且有可验证正确性信号」的场景。对于饱和基准或强模型，收益在运行噪声范围内持平。Gate 默认开启，这是最坏情况有界的关键。

10 · 适合谁 / 不适合谁
Boundary
✅ 适合
1
想把 skill 变成可优化资产而不是每次靠手写 prompt 祈祷。
2
想复现论文结果 / 做 ablation需要严谨比较不同 gate、不同 harness、不同模型。
3
想要可部署、低推理成本的技能训练期复杂，部署期干净，适合生产化技能资产。
4
想让本地 agent 越用越强用 SkillOpt-Sleep 做夜间自动进化，不需要每次手动整理。
❌ 不适合
1
只想要一次性 prompt 模板那不需要这套优化器闭环。
2
不想准备验证集 / split没有 hold-out gate，SkillOpt 的核心价值会塌掉。
3
想让模型权重自己学会一切这套方法明确训练的是文本资产，不是参数。
