SkillOpt Cookbook：把技能训练成可部署工件

SkillOpt 不是在训练模型权重，而是在训练skill.md 文档本身：用 epoch、mini-batch、learning rate、validation gate 和 rejected-edit buffer，把可复用的自然语言技能做成能跨模型、跨 harness 迁移的最优版本。

先钉死边界：SkillOpt 训练的是“技能文档”而不是模型参数；部署时零额外推理开销，只有一个更好的 best_skill.md。它的核心是 validation-gated edits，不是自我陶醉式重写。

一句话判断

core take

SkillOpt 解决什么问题

它把“如何写一个好 skill”从手工经验变成可优化流程：优化器模型先根据打分轨迹提出 bounded 的 add / delete / replace 编辑，再用持出验证集严格门控，只有真正提升才接受。这样得到的 skill 可以在不同模型、不同 harness 之间迁移。

关键判断：SkillOpt 的价值不在于生成更多文本，而在于让 skill 的改进过程像训练神经网络一样可复现、可比较、可回滚。

你可以怎么理解它

把 skill 文档看成“冻结 agent 的可训练状态”，把 validation gate 看成“编辑是否进入模型”的硬阀门。训练期会产出一串 skill snapshot、step patch、slow update、meta skill，最终收敛到一个可直接部署的 Markdown 工件。

✓ 不是 weight tuning ✓ 文档级优化 ✓ 验证门控 ✓ 可部署 artifact

训练闭环：它怎么把 skill 越训越好

architecture
skillopt looprollout → reflect → gate → update
Skill 文档 / current_skill.md
初始 skill、历史片段、epoch 更新与拒绝编辑缓冲共同构成可训练状态
↓ 作为系统提示 + 行为规范输入
Rollout
用当前 skill 跑 benchmark / harness，收集预测、硬分、软分和失败样本
Reflect
优化器模型把轨迹转成 bounded edits：add / delete / replace
↓ 生成候选 patch
Validation Gate
候选 skill 只有在 held-out split 上严格更优才被接收；默认 hard gate，可切 soft / mixed
Slow / Meta Update
epoch 边界做慢更新，产生更稳的 meta guidance；可 force-accept 或 gated
↓ 输出
best_skill.md
最终可部署工件，通常 300–2,000 tokens，直接挂到未改动的 target model 上
这条 loop 的关键不是“多写几轮”，而是“每轮都比上一轮更严格”：训练数据来自 rollouts，编辑来自 reflect，接收来自 validation gate，稳定性来自 slow-update 和 rejected-edit buffer。

Cookbook ①：最短训练路径

train

最小命令

python scripts/train.py \
  --config configs/searchqa/default.yaml \
  --split_dir /path/to/searchqa_split \
  --azure_openai_endpoint https://your-resource.openai.azure.com/ \
  --optimizer_model gpt-5.5 \
  --target_model gpt-5.5

这条命令在做什么

1
读 configbenchmark 选择、batch、epoch、gate 和 skill_init 都从 YAML 拉起。
2
跑 rollout把 current skill 喂给 target model，拿到预测与分数。
3
反思 + 过滤optimizer 只建议 bounded edit，validate 后再接受。

训练时最该盯的三个变量

epochs

训练轮数

默认 4 轮；太少学不够，太多容易在无效编辑上打转。

batch

rollout batch 40

轨迹太少 gate 不稳，太多则优化器成本飙升。

learning rate

文本学习率 4

控制每次文档改动幅度，不是模型参数学习率。

Cookbook ②：只做评估，不重新训练

eval-only

评估已有 skill

python scripts/eval_only.py \
  --config configs/searchqa/default.yaml \
  --skill ckpt/searchqa/gpt5.5_skill.md \
  --split valid_unseen \
  --split_dir /path/to/searchqa_split \
  --azure_openai_endpoint https://your-resource.openai.azure.com/

什么时候用它

A
想复核论文里的结果直接评估 ckpt/ 里已清洗好的 GPT-5.5 技能。
B
想对比自己训出的 skill把 `--skill` 换成 `outputs/.../best_skill.md` 即可。
C
想看 skill 的迁移性同一个 skill 可以在不同 split、不同 harness 下复测。

常见 split 语义

valid_unseen

测试集

论文与评估常用目标。

valid_seen

验证集

选技能、做门控的持出集。

all

全量评估

训练/验证/测试一起看。

Cookbook ③：加一个新 backend / 新 benchmark

extend

加新 backend 的最小动作

1
新建 `skillopt/model/your_backend.py`实现 `generate()` / `generate_with_tools()` 等接口。
2
注册到 `skillopt/model/__init__.py`把 backend 放进 registry，才会被路由选到。
3
用环境变量塞凭据README 推荐通过 `.env` / `export` 管理 API key。

加新 benchmark 的四件套

1
SplitDataLoader负责从 train / val / test 目录加载 item。
2
rollout helper跑 target model 并打分，输出 hard / soft。
3
EnvAdapter接入 SkillOpt 生命周期：build、rollout、reflect、get_task_types。
4
YAML config把 benchmark 接到默认训练协议上。

官方文档给出的两个最值得记的入口

backend guide

docs/guide/new-backend.md

模板是：先实现 backend，再注册 registry，再用 YAML 选择。

benchmark guide

docs/guide/new-benchmark.md

模板是：loader → rollout → adapter → config，一条线接进去。

关键配置：你最容易踩的坑

config
参数作用默认/要点
slow_update_gate_with_selectionepoch 边界的慢更新是否走验证门控false 是当前 main；true 对齐论文 / ckpt
gate_metric验证门控使用的分数类型hard / soft / mixed
learning_rate文本编辑步长默认 4，不是模型参数 LR
minibatch_size反思阶段每批处理的样本数默认 8
skill_init训练起点 skill 文件可以是空 skill，也可以是种子文档
如果你只是“觉得 skill 写得还行”就扩大编辑，通常会把验证集冲坏。SkillOpt 的 cookbook 不是“多写点”，而是“每次改动都要过门”。

输出物与复核方法

artifact

训练目录里最重要的文件

outputs/<run_name>/
├── config.json
├── history.json
├── runtime_state.json
├── best_skill.md
├── skills/skill_vXXXX.md
├── steps/step_XXXX/

如何判断有没有真提升

✓
看 best_skill.md 而不是只看日志真正要部署的是最终技能文件，不是训练历史。
✓
看 held-out score 是否严格更高gate 不通过，编辑就不算有效。
✓
看跨模型 / 跨 harness 迁移论文强调 SkillOpt 的技能能从 Codex 迁到 Claude Code 等执行面。

适合谁 / 不适合谁

boundary

适合

1
想把 skill 变成可优化资产而不是每次靠手写 prompt 祈祷。
2
想复现论文结果 / 做 ablation需要严谨比较不同 gate、不同 harness、不同模型。
3
想要可部署、低推理成本的技能训练期复杂，部署期干净，适合生产化技能资产。

不适合

1
只想要一次性 prompt 模板那不需要这套优化器闭环。
2
不想准备验证集 / split没有 hold-out gate，SkillOpt 的核心价值会塌掉。
3
想让模型权重自己学会一切这套方法明确训练的是文本资产，不是参数。

最终结论

SkillOpt 的 cookbook 本质上是一套“把自然语言技能做成可训练、可验证、可部署工件”的操作手册。它把文档、轨迹、门控、慢更新和输出 artifact 统一成一条闭环，适合做高复用 agent 技能资产。

你会用到的三条主线

  • 训练：scripts/train.py
  • 评估：scripts/eval_only.py
  • 扩展：backend / benchmark guide
