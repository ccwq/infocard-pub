01WHAT LOOP ENGINEERING IS

Loop engineering 不是“更会 prompt”。它是把自己从“持续手动提示 Agent 的人”升级成“设计系统的人”。

核心判断：当工作可以递归地被定义为“设定目标 → 迭代 → 检查 → 记录 → 决定下一步”时，真正的接口不再是对话框，而是循环本身。

为什么这件事现在重要

  • 过去两年：你输入一句，Agent 回一句，你再接一句。
  • 现在：你设计一个小系统，让它自动发现工作、分发工作、检查工作、写下状态并继续前进。
  • 这比“写更好的 prompt”更接近真实工程。

03HOW THE LOOP RUNS IN PRACTICE

Automations = heartbeat

按计划跑：daily triage、CI 摘要、commit briefing、bug hunting。好的自动化不是“多跑一次”，而是只把有价值的发现送出来。

Worktrees = parallel lanes

两个 agent 同时开工时，worktree 让彼此不会踩掉对方的未提交工作。循环一旦并行，隔离就变成必要条件。

Skills = reusable doctrine

Recurring work 不该每次都重新讲。把流程写成 skill，循环就会从临时脚本升级成可维护的工程资产。

Connectors = existing tools

把 agent 接到你已经在用的工具里：issue tracker、CI、repo、任务系统，而不是引入孤立的新世界。

Sub-agents = split cognition

不要让同一个 agent 同时负责构思和验收。把“想”和“查”拆开，质量更稳，幻觉更少。

Memory = durable state

循环要跨越单次会话，就必须把“做完了什么、接下来是什么”落盘。否则每次开跑都像失忆。

04PRODUCT / RISK / QUALITY

好的循环会做什么

  • 自动发现要做的事。
  • 把工作分给多个 agent。
  • 记录完成状态与下一步。
  • 持续收集反馈并修正。

必须盯住的风险

  • token 成本可能剧烈波动。
  • 质量如果失控，循环会放大 slop。
  • 工具越强，越要保留人工审查节点。
Define purpose, not prompts
Automate discovery first
Isolate parallel work
Keep memory on disk
