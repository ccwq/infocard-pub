### 核心方法（来自论文摘要，已核验）

RESOURCE2SKILL 框架将**教程视频、代码仓库、文章、参考制品**四种多模态资源作为输入，通过蒸馏操作器生成可执行技能，并以**分层多模态 Skill Wiki** 组织。

每个技能词条包含：
- **结构化文本**（说明 + 操作步骤）
- **可执行代码片段**
- **视觉示例**
- **元数据**
- **来源溯源（provenance）**

各模态互补信号：视频捕捉时序操作与视觉效果，代码捕获可执行工具模式，文章/制品提供概念与风格锚定。

推理时 Agent 从 Wiki 检索并组合相关技能；覆盖不足时同一蒸馏操作器可**在线获取新技能**。

### 实验指标（论文自报，未经独立复现）

| 指标 | 数值 | 说明 |
|------|------|------|
| 平均 overall score 提升 | **+11.9pp** | vs 无技能 Agent，7个 authoring domains 平均 |
| 胜出单元比例 | **26/28** | 主聚合模型-领域单元中胜出 |
| 评估领域数 | **7个** | practical authoring domains |
| 资源类型 | **4种** | 视频、仓库、文章、制品 |

### Ablation 消融结论（论文自报）

1. 多模态技能格式优于单模态
2. 分层组织优于扁平列表
3. 来源多样性（多类型资源混合）优于单一来源
4. 选择策略影响最终 Agent 表现
5. 在线获取机制扩展静态 Wiki 覆盖边界

## 适用边界

**适用场景：** 软件 Agent 需要复用操作知识的场景——工具调用、代码生成、自动化工作流构建、跨仓库任务规划。

**不适用场景：** 需要实时感知环境（摄像头/麦克风输入）、需要完全零样本泛化、或资源本身质量低下的场景。

---

## 风险与局限

- **资源质量依赖：** 输入多模态资源质量直接影响蒸馏技能质量
- **模态缺失时性能退化：** 若某资源类型缺失，相关信号无法补全
- **在线获取延迟：** 覆盖不足时实时获取新技能可能引入延迟
- **论文自报指标：** 所有数值（+11.9pp、26/28 胜出）均为论文 v4 中作者报告的结果，未经第三方独立复现验证
