01

先理解仓库结构：组件、工具和安装方式是三条路径

不要把“有 165+ 组件”理解成一个需要整体安装的大型运行时。

组件库

官方 README 将内容分为文字动画、动画、组件和背景；每个组件页面提供代码与技术选项，目标是复制到现代 React 项目。

创意工具

Background Studio、Shape Magic、Texture Lab 用于探索背景、形状圆角和图像/视频纹理，并可导出视频、图片、SVG、React 或 clip-path 代码。

技术变体

同一组件提供 JS-CSS、JS-TW、TS-CSS、TS-TW 四种变体；先按项目已有 TypeScript/Tailwind 组合选择，不要盲目引入新栈。

事实边界：“165+”来自当前 README 文案，是会增长的仓库快照；它不是本次逐项统计，也不是所有组件在同一依赖和浏览器环境下都已实测。
02

安装：先读组件页，再选择 shadcn、jsrepo 或手动复制

最小目标不是装完整网站，而是把一个组件放进你的真实页面。

01

确认项目

确认 React、CSS/Tailwind、TypeScript 与现有构建工具。

02

选变体

JS/TS 与 CSS/Tailwind 组合要匹配项目。

03

安装/复制

CLI 或手动源码二选一，记录新增依赖。

04

真实页面验收

检查加载、交互、键盘、移动端和 reduced motion。

# 官方 README 示例：通过 shadcn 添加组件 npx shadcn@latest add @react-bits/BlurText-TS-TW # 然后在真实页面确认： # 1. 组件依赖是否已写入项目 # 2. Tailwind/CSS 配置是否生效 # 3. 动画是否在移动端和 reduced-motion 下可接受
不要直接复制：组件页面是选择入口，实际命令和依赖以该组件的当前页面为准；README 的单个示例不能代表所有组件都使用同一安装命令。
03

第一次使用：用一个短文本组件跑通“复制—改参数—验收”

先从 BlurText 这类可见、可回退的组件开始，不要先改整页背景。

复制前

记录组件页、变体、依赖和默认 props；确认项目已有路由、字体和 Tailwind 配置。

复制后

只改一个参数：出现/延迟/分段/触发方式等。保留一份原始版本，方便比较和回退。

验收时

桌面与移动各看一次；键盘可操作；开启系统 reduced motion 后不会制造不可用的延迟或闪烁。

// 验收记录模板（示意） component: BlurText variant: TS-TW source_page: <component-page> changed_prop: <one-prop-only> keyboard: pass / fail reduced_motion: pass / fail mobile_390: pass / fail bundle_or_dependency_change: <record>
04

怎么选：动效价值要超过它带来的认知和性能成本

视觉“高级感”不是单一参数，必须在页面任务里证明它有帮助。

需求优先选什么验收重点不要忽略
首屏标题吸引注意Text animations首屏可读、延迟合理、静态 fallback长标题和 reduced motion
背景氛围Backgrounds / Background Studio内容对比度、GPU开销、低端机动效不能压过正文
产品交互差异Interactive components状态反馈、键盘、触摸目标焦点与错误状态
图片/视频质感Texture Lab导出质量、文件大小、版权不要把处理结果当原创素材
形状与布局表达Shape MagicSVG/clip-path兼容、响应式导出代码的维护成本
决策规则：如果一个静态标题已经清楚表达任务，而动效只增加等待、眩晕或低端设备负担，就不要为了“高级感”加入它。
05

常见故障：先分清组件代码、项目配置和运行时问题

组件库只负责提供起点；出现问题时按层定位。

样式不生效

查选错变体、Tailwind content 扫描、CSS导入和项目版本；先用组件最小示例复现。

动画卡顿

查高频 layout、图片/视频大小、阴影/滤镜、列表数量和低端设备；不要只提高硬件要求。

交互不可用

查鼠标触发是否有键盘替代、焦点是否可见、触摸目标是否足够大、动画是否可关闭。

# 一个组件接入后的回归清单 npm run lint npm run build # 用浏览器检查桌面 + 390px 移动端 # 开启 prefers-reduced-motion 再检查一次 # 对新增依赖和 LICENSE.md 做人工审查
06

许可证、动态事实与适用边界

仓库 README 写明 MIT + Commons Clause；GitHub API license 字段当前为 Other/NOASSERTION，使用前应阅读仓库 LICENSE.md。

当前快照

GitHub API：约 47,122 Stars、2,279 Forks、4 Open Issues；主要语言 JavaScript；默认分支 main。README 当前写 165+ 组件。

许可证

README 链接 MIT + Commons Clause，并写“free for personal and commercial use”；API 结构化 license 是 Other/NOASSERTION。商业项目应直接核对 LICENSE.md 与组件来源。

适合 / 不适合

适合 React 页面快速建立动效基线；不适合未经审查地批量复制、把组件当完整设计系统，或忽视性能、无障碍与依赖许可。

下一步只做一件事

选一个真实页面和一个组件 → 选择匹配的 TS/CSS 或 Tailwind 变体 → 按官方组件页安装/复制 → 跑 lint/build → 在桌面、390px 和 reduced-motion 下验收 → 再决定是否扩大使用。
