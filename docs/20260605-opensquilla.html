01

核心定位：微内核 AI Agent 运行时

OpenSquilla 是一个 token 高效的微内核 AI Agent。核心设计原则：每个入口（CLI/Web/IM）共享同一 Turn Loop，工具调度、重试和决策日志行为完全一致。

🧠 本地模型路由

SquillaRouter 根据任务复杂度自动选择合适模型层级，简单任务用便宜模型，复杂推理保留给高端模型。

推荐路由 OpenRouter Mix

🔧 工具压缩

大型工具输出（命令日志、JSON、网页、搜索结果）不会耗尽上下文窗口。保留原始结果的同时，向模型发送压缩预览。

截断 语义摘要 结构投影

⚡ MetaSkills

将重复性多步骤工作封装为可复用、可检查的工作流。例如：竞争情报分析、合同决策、职位搜索、论文写作。

元技能 工作流复用

🛡️ 分层沙箱

文件、Shell、Web、Memory、Git、Artifact、Media、Channel 工具均在策略层和审批面之后运行，支持 E2B Cloud Sandbox 或 Docker Sandbox。

E2B Docker
02

SquillaRouter：本地模型智能路由

本地 on-device 模型路由器，根据任务难度自动分派到最便宜的可用模型，避免简单任务用高端模型浪费成本。

推荐模式

R1
开启方式

首次运行向导推荐安装路径：opensquilla onboard --router recommended

适用场景

日常对话 / 编辑 / 摘要 / 常规工具调用→ 自动路由到低费用模型 tier；复杂推理保留高端模型。

OpenRouter Mix

R2
开启方式

opensquilla configure router --router openrouter-mix 使用 OpenRouter 混合默认模型池。

适用场景

需要跨多个模型质量层：OpenRouter 作为统一入口，支持 OpenAI、Anthropic、DeepSeek、Gemini 等多厂商混合路由。

直接模式（关闭路由）

R3
开启方式

opensquilla configure router --router disabled 完全禁用路由，使用固定单一模型。

适用场景

测试 / 调试 / 已知任务复杂度：跳过路由判断，直接使用配置的 provider/model，适合 CI 环境或精确控制场景。

03

工具压缩：保持上下文高效

工具调用会产生大型输出（命令日志、JSON、网页、diff）。工具压缩在不改变原始结果的前提下，让模型看到压缩预览，保护活跃上下文窗口。

🔪 Truncate 模式

快速确定性预览：将长输出截断到固定 token 阈值。速度最快，适合日志、diff 等结构化输出。

  • 适用：命令日志、文件 diff、表格数据
  • 取舍：可能遗漏中间有用部分

🧩 语义摘要模式

用模型理解内容后生成语义压缩摘要。速度较慢但保留关键信息，适合背景工作流。

  • 适用：长文档、网页内容、搜索结果
  • 取舍：需要额外模型调用，应设为 opt-in

📐 结构投影模式

针对已知工具输出形状（JSON、表格、日志）使用结构化降维器。效果取决于该类型是否有 reducer 覆盖。

  • 适用：已知 schema 的 JSON / API 响应
  • 取舍：依赖 reducer 覆盖范围
关键设计原则：原始结果始终可查（通过文件、Session 导出、诊断工具），模型看到的只是保护上下文窗口的预览。 OpenSquilla 分离两个视图：Runtime View（持久结果可检视/导出）和 Provider View（下一个推理步骤的边界文本）
04

MetaSkills：将多步骤工作变成可复用工作流

MetaSkill 将重复性多步骤工作封装为可复用、可检查的工作流。与普通 Skill（单任务指令包）不同，MetaSkill 可以组合多个 Skill、检查点、输出和最终合成。

🗺️ 内置 MetaSkills 目录

v0.3.0 稳定功能

  • meta-competitive-intel：账户或竞品信号 → 销售/BD/竞情简报
  • meta-daily-operator-brief：今日任务 + 上下文 + 约束 → 运营简报
  • meta-document-to-decision：合同/报价/续约/通知 → 签署/拒绝/谈判决策
  • meta-job-search-pipeline：JD + 简历 + 申请目标 → 申请包 + 面试准备
  • meta-paper-write：学术草稿 → 手稿结构 + 引用规划 + LaTeX/PDF 路径
  • meta-web-research-to-report：源研究需求 → 报告/简报/决策备忘录
  • meta-skill-creator：重复多技能协作模式 → 新 MetaSkill 提案
  • meta-kid-project-planner：学校项目 → 安全适龄计划

⚙️ Skill vs MetaSkill 区分

设计原则

  • Skill：单一聚焦任务模式、指令集、脚本或工具辅助。例如："总结这篇文档"。
  • MetaSkill：由多个步骤、Skill、检查点或最终合成组成的可复用工作流。例如："把合同+报价+邮件变成签署/拒绝/谈判建议（附风险和下一步）"。
Skill = 单任务 MetaSkill = 多步骤工作流
05

持久记忆与 Skills 系统

OpenSquilla 的 Memory（存储事实）和 Skills（存储方法）分离设计：Memory 让 Agent 跨 Session 记住偏好、项目规范和重要决策；Skills 让 Agent 学习如何执行任务。

🧠 Memory · 记忆系统

持久存储跨会话事实：用户偏好、项目规范、仓库名称、决策记录。可通过自然对话"记住 X"触发写入，也可显式 flush session 到记忆。

  • opensquilla memory status [--deep]
  • opensquilla memory index / list / search
  • opensquilla memory flush-session <key>

🛠️ Skills · 技能系统

任务专用指令包和脚本，只在需要时加载。覆盖：深度研究、GitHub/PR 工作流、文档生成、网页搜索、天气查询、终端监控、子 Agent 委托等。

  • opensquilla skills list / view <name>
  • opensquilla skills search <keyword>
  • opensquilla skills install / update / uninstall
  • opensquilla skills tap add <owner/repo>

📦 压缩与缓存

长会话自动压缩（compaction）保持上下文连续性。Session 历史可导出为精确记录，Memory 保留有用回顾。Prompt Cache 支持跨 turn 复用。

  • 会话导出：sessions export <key>
  • 压缩触发：自动基于 turn 数或 token 阈值
  • 诊断工具：diagnostics + replay

架构总览与入口点

OpenSquilla 的统一运行时路径：所有入口共享同一 Loop、工具、记忆、审批和用量核算。

🏗️ 统一运行时路径

  • Turn Loop：单一共享循环，所有入口（CLI / Web UI / IM Channels）均经过此路径
  • SquillaRouter：本地 on-device 模型路由器，按任务难度选择模型 tier
  • Persistent Memory：跨会话事实存储（用户偏好、项目规范、重要决策）
  • Layered Sandbox：E2B Cloud / Docker 沙箱，工具执行后文件同步回持久存储
  • Tool Compression：大输出压缩预览，保护活跃上下文窗口
  • Built-in Web Search：集成搜索工具，支持 Brave 等搜索提供商
  • On-device Embeddings：本地向量嵌入，支持语义搜索

🔌 入口点

  • Web UI：本地 Web 界面（http://127.0.0.1:18791/control/）
  • CLI：opensquilla gateway run / opensquilla onboard / configure / skills / memory / sessions
  • Chat Channels：Telegram / Discord / Slack 机器人绑定
  • Gateway RPC：OpenAI 兼容 API（/v1/chat/completions 流式）
  • MCP Server：MCP 协议桥接，支持 MCP 客户端接入

🛡️ 安全与审批

  • Policy Layer：文件/Shell/Web/Memory/Git/Artifact/Media/Channel 工具均受策略层管控
  • Approval Surfaces：审批面，支持权限配置文件（approvals-and-permissions.md）
  • Write Policy：写操作受沙箱边界和 workspace 隔离约束
  • Migration Support：支持从 OpenClaw 或 Hermes Agent 迁移（opensquilla migrate openclaw/hermes）

快速安装路径

支持 Windows 便携 / 快速终端安装（推荐）/ 从源码安装 / 开发者源码四种路径。

💻 快速终端安装（推荐）

任意 OS，uv 自动安装推荐配置（含 SquillaRouter + 模型资产）

uv tool install --python 3.12 \
  "opensquilla[recommended] @ https://github.com/opensquilla/opensquilla/releases/download/v0.3.1/opensquilla-0.3.1-py3-none-any.whl"

🪟 Windows 便携版（无需 Python）

下载 zip 包，自带 CPython 运行时，最快上手

# 下载 releases/latest/download/opensquilla-*-win-portable.zip
# 解压后运行 opensquilla.exe

🔧 首次配置向导

安装后运行 onboard 完成首次配置，支持最小化/仅 provider/完整交互模式

opensquilla onboard                  # 完整交互
opensquilla onboard --if-needed    # 幂等，安全用于脚本
opensquilla onboard --minimal      # 仅 provider
opensquilla onboard status         # 仅检查，不写入

🌐 Web 控制台

启动后访问本地 Web UI，管理 Agent、Model、Skills、Users、API Keys

opensquilla gateway run
# 打开 http://127.0.0.1:18791/control/
