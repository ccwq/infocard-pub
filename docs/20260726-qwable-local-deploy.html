03Windows 部署流程
07

LM Studio（推荐桌面 GUI 方案） 🖥️

适用场景：无命令行经验者、快速验证、GUI 操作、局域网 API
步骤：
1. 下载安装：lmstudio.ai/download（Windows .exe）
2. 在 LM Studio 内置模型搜索框搜索 lordx64/Qwable-v1-GGUF，选择量化版本（推荐 Q4_K_M 或 IQ4_XS）
3. 下载完成后，在"Local Server"标签页启动 OpenAI-Compatible API（默认端口 1234）
4. 设置 GPU offload（n_layers 设为最大或自动）
5. context length 默认 4096，可在设置中调整
6. 用 curl http://localhost:1234/v1/chat/completions 测试 API
Windows 特有问题：首次启动若遇显卡驱动提示，需安装 NVIDIA Driver 537+；显存不足时 LM Studio 会提示，降低量化级别或关闭部分 offload 层

LM StudioGUIOpenAI APIWindows

llama.cpp（Windows 命令行方案） ⬇️

适用场景：高可控、轻量服务、自动化脚本、Docker 集成
步骤：
1. 下载 llama.cpp Windows 预编译包（github.com/ggerganov/llama.cpp/releases，寻找包含 win 的 llama-server.exe）
2. 下载 GGUF 文件（HF：lordx64/Qwable-v1-GGUF，选择量化版本）
3. 用 PowerShell 或 CMD 启动（不要在 WSL 中运行，需要本地 NVIDIA 驱动）：

.\llama-server.exe -m Qwable-v1.Q4_K_M.gguf --host 127.0.0.1 --port 18081 -c 32768 -fa on --cache-type-k q8_0 --cache-type-v turbo4

4. -c 32768：context length（设为 32768 注意显存，4096 为安全默认值）
5. -fa on：flash attention（加速但需要足够显存）
6. 用 curl 或浏览器访问 http://127.0.0.1:18081 验证
Windows 特有问题：CUDA DLL 缺失 → 安装 NVIDIA Driver + CUDA Toolkit；PowerShell 执行策略限制 → 用 Bypass 策略运行

NVIDIA CUDA（主流 GPU 方案） 🐧

前置检查：

nvidia-smi  # 查看 GPU 与驱动
nvcc --version  # 验证 CUDA 版本（建议 12.1+）
llama-server 部署：
# 下载 llama-server（CUDA 编译版）
wget https://github.com/ggerganov/llama.cpp/releases/latest/download/llama-server-linux-x64-cuda12.1.tar.gz
tar -xzf llama-server-linux-x64-cuda12.1.tar.gz

# 下载 GGUF
huggingface-cli download lordx64/Qwable-v1-GGUF Qwable-v1.Q4_K_M.gguf

# 启动服务
./llama-server -m Qwable-v1.Q4_K_M.gguf --host 0.0.0.0 --port 8080 -c 32768 -fa on --n-gpu-layers 999
systemd 服务（后台常驻）：
sudo tee /etc/systemd/system/qwable.service >/dev/null <<'EOF'
[Unit]
Description=Qwable-v1 llama-server
After=network.target

[Service]
ExecStart=/opt/llama.cpp/llama-server -m /data/models/Qwable-v1.Q4_K_M.gguf --host 0.0.0.0 --port 8080 -fa on --n-gpu-layers 999
Restart=always
User=ubuntu

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now qwable
journalctl -u qwable -f  # 查看日志
显存不足排查：nvidia-smi 查看占用；降量化（Q4_K_M → IQ4_XS）；减少 -c context；减少 --n-gpu-layers

Ollama / vLLM（高级方案） 🚀

Ollama 适用场景：低门槛本地 API、Agent 工具接入（如 OpenClaw / n8n）
Ollama 局限性：Qwable-v1 需要先转换为 Ollama Modelfile；GGUF 格式支持；工具透明度相对较低；复杂量化控制不如 llama.cpp 细粒度
vLLM 适用场景：Linux + NVIDIA 高并发吞吐、生产服务、需要 PagedAttention 和批量推理
vLLM 局限性：配置复杂；需要足够显存（建议 24GB+ GPU）；不支持 Mac；不支持 Windows 原生
选型决策：桌面快速验证 → LM Studio；自动化脚本 / Agent → llama.cpp；生产高吞吐服务 → vLLM

已知局限与风险边界 ⚠️

🚧 官方评测未完成：SWE-bench Lite / HumanEval / MMLU-Pro 等 benchmark 均为"进行中"状态，任何以"Qwable 质量超过 X"为结论的描述均为 L4 未证实说法。

蒸馏数据范围极窄：Fable-5 数据来自一位开发者的 Claude Code 一周会话（5000 轮，81% 工具调用结尾），领域集中在 web/Three.js / 游戏 / Express 服务器 / Fluid 模拟 / Transformer 训练脚本；窄分布意味着对其他领域（金融、医疗、法律、复杂 Agent 规划）的泛化能力未知。

不适合的场景：· 需要 4096+ 超长上下文（当前最大 4096 tokens，KV cache 随长度线性增长显存）；· 需要严格质量保证的生产代码（评测未完成）；· AGPL 合规成本高于云 API 节省；· Mac 16GB 统一内存（不足以运行 Q4_K_M 及以上量化）。
