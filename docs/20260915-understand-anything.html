UNDERSTAND ANYTHING / CODEBASE MAPGRAPH · SEARCH · ASK · IMPACT
MULTI-AGENT ANALYSIS · TREE-SITTER + LLM · MIT

先把陌生代码库变成地图，再决定改哪一行

Understand Anything 把代码库、知识库或文档转换成可探索、可搜索、可提问的交互知识图谱。它不是把整个项目“自动读懂”后交付一个绝对答案，而是先用 Tree-sitter 抽取结构事实，再用 LLM 补充摘要、架构层、业务域和学习路径，最后把结果落在可回溯的数据目录和 Dashboard 中。

先问三个问题

你缺的是搜索，还是系统结构？

陌生项目：先得到文件、函数、类和依赖的地图，再沿依赖顺序学习。
准备改动：先跑 diff impact，查看可能受影响的区域。
数据边界：初次分析会调用 LLM；大仓库先评估 token、Provider 和源码外发政策。
01

它做什么：把结构事实和语义解释分开

图谱不是装饰，它应该能回答“这个节点是什么、连接到哪里、证据来自什么”。

结构层 / Tree-sitter

确定性解析 imports、exports、函数、类、调用点和继承关系；同样输入得到同样结构边。

语义层 / LLM

补充自然语言摘要、架构层、业务域、guided tours 和 language concepts；这些结果要按模型与版本看待。

呈现层 / Dashboard

节点可点击、可搜索、可查看关系与解释；结构图服务导航，不替代源码阅读和测试。

核心判断：它适合降低“从哪里开始读”的成本，不应被表述成无需工程师验证的自动代码审计。

第一次安装：按你的 Agent 平台选择适配器

Claude Code 是原生插件；其他平台通过官方 install.sh / install.ps1 或各自插件发现机制接入。

01

确认平台

Claude、Codex、Cursor、Copilot、Gemini CLI、Pi、Hermes 等路径不同。

02

安装插件

Claude 用 marketplace；macOS/Linux 用 install.sh；Windows 用 install.ps1。

03

重启工具

安装器会创建目录/链接；重启 CLI 或 IDE 让 skill 生效。

04

分析小项目

先在可控、已授权的项目跑通，不要从超大 monorepo 开始。

05

看图再提问

先确认 .ua 数据目录与 Dashboard 有结果，再使用语义命令。

安装边界：官方安装器默认把仓库放在 ~/.understand-anything/repo，并创建对应平台的 skill/plugin 链接；安装前应读脚本并确认目标目录。
03

最小可验证路径：分析 → 打开 Dashboard → 问一个具体问题

不要先追求完整图谱；先让一个小项目产生可检查的节点、边和摘要。

# 在目标项目中（以平台实际前缀为准） /understand /understand-dashboard /understand-chat How does the payment flow work? /understand-explain src/auth/login.ts /understand-diff /understand-onboard # Codex 的调用前缀是 $ $understand $understand-dashboard

第一验收

`.ua/knowledge-graph.json` 或兼容的 legacy 数据目录生成，Dashboard 能打开并显示节点。

第二验收

搜索一个明确目标，例如 auth/login；结果能落到文件、函数或关系，而不是只返回泛化摘要。

第三验收

对一个当前改动运行 diff impact；把结果作为待检查清单，不是自动批准或阻止提交。

04

数据目录与增量更新：图谱要跟着代码一起变化

v2.9.0 将新数据目录命名为 `.ua/`；已有 `.understand-anything/` 项目保持兼容。

动作官方路径判断
初次分析/understand全库分析，可能消耗较多 token；大项目先评估成本
增量重跑/understand默认只重新分析变化文件，减少重复消耗
自动更新/understand --auto-updatepost-commit hook 增量修补图谱；先审查生成内容
分享图谱提交 `.ua/`，排除 intermediate 与 diff-overlay团队可跳过初始化，但需同步图谱版本
大型图谱10 MB+ 使用 git-lfs评估仓库体积和访问权限
# 只启动已提交图谱的本地只读 viewer npx https://github.com/Egonex-AI/Understand-Anything/releases/latest/download/understand-anything-viewer.tgz /path/to/analyzed/project # 该路径只需 Node.js >= 18，不需要 Claude Code、LLM 或 API key # 项目目录必须已有 .ua/ 或 legacy .understand-anything/
05

多 Agent 管线：每个 Agent 的结果都要知道用途

官方 README 当前描述初次 understand 使用 5 个专用 Agent，domain/knowledge 模式会增加分析角色。

project-scanner

发现文件、语言和框架，为后续扫描定范围。

file-analyzer

抽取函数、类、imports，生成图谱节点和边。

architecture / tour

识别架构层并按依赖顺序生成 guided tour。

graph-reviewer

检查图谱完整性与引用完整性；默认 inline，也可用 full review。

domain-analyzer

/understand-domain 提取业务域、流程和步骤。

article-analyzer

/understand-knowledge 分析知识库实体、claim 和隐含关系。

并发与可重复性：文件分析器最多 5 个并发 worker，每批 20–30 个文件；结构侧更确定，LLM 语义侧仍受模型、上下文和 Provider 影响。

常见故障：先分清安装、权限、Provider 和图谱质量

“没有结果”不一定是模型不行，也可能是平台前缀、数据目录或权限错误。

现象第一检查下一动作
命令不认识平台调用前缀与 skill/plugin 是否已发现Claude 用 slash；Codex 用 `$`；重启后复试
初次运行很贵项目规模、模型、Provider、是否全库扫描小目录试跑；考虑本地模型或 token plan
图谱不完整merge-report、语言支持、忽略规则、解析错误查看 phase report，修复后增量重跑
旧目录冲突`.ua/` 与 `.understand-anything/` 是否同时存在遵循项目的 legacy 优先/兼容规则，不手动迁移
Dashboard打不开数据目录、Node.js 版本、tokenized local URL用 viewer 路径在本地只读打开
语义答案偏差源码证据、模型、上下文、增量状态回到节点/文件/关系核对，不把摘要当证明

许可证、动态快照与适用边界

仓库当前 API 与 README 的许可证/统计/版本信息要分开记录。

当前快照

GitHub API：约 82,544 Stars、6,944 Forks、302 Open Issues；主要语言 TypeScript；默认分支 main；最新 Release v2.9.0。

许可证

仓库 package.json 与 LICENSE 声明 MIT；README 末尾也写 MIT。第三方模型、Provider、源码和团队数据政策仍需另行确认。

适合 / 不适合

适合大型/陌生代码库 onboarding、架构导航、语义检索和变更影响初筛；不适合替代测试、代码审查、动态安全分析或未经授权的源码外发。

下一步只做一件事

在一个已授权的小项目中安装对应平台适配器 → 跑一次 understand → 打开 Dashboard → 用一个具体问题检索 → 查看 diff impact → 再决定是否启用 auto-update 或提交 .ua 图谱。
