它真正比普通 AI 视频工具多了什么

why it matters

不是单 clip，而是完整 production pipeline

大多数 AI 视频产品只生成一个片段；OpenMontage 把 research → proposal → script → scene_plan → assets → edit → compose 串成完整生产链。

不是只会“动几张图”，还能走真实素材路径

它支持 documentary montage：从 Archive.org、NASA、Wikimedia、Pexels、Unsplash 等公开素材库建 corpus，再按 CLIP 语义检索和剪成真实 motion video。

不是黑盒 orchestration，而是 agent-first 架构

真正的 orchestrator 不是隐藏在后端的 workflow engine，而是你的 AI coding assistant 本身：它读 pipeline manifest、读 stage skill、调用 tool registry、自审并 checkpoint。

不是“能生成就算完成”，而是带质量门控

README 明确写了 pre-compose validation、delivery promise enforcement、ffprobe / frame extraction / audio analysis 这类自审链路，避免把 slideshow 或坏 render 当成成片交付。

最小上手路径

install path

1. 装基础依赖

Python 3.10+、FFmpeg、Node.js 18+，再选一个 AI coding assistant（Claude Code / Cursor / Copilot / Windsurf / Codex）。

2. clone + setup

`git clone` → `cd OpenMontage` → `make setup`。没有 `make` 也可手动装 requirements、remotion-composer 依赖、Piper TTS 并复制 `.env.example`。

3. 直接用自然语言下视频需求

例如做 60 秒 explainers、documentary montage、product teaser，或先给一个 YouTube / TikTok 参考视频，让系统反推 pacing、hook 和风格。

边界与取舍

what to watch

AGPL-3.0 不是宽松许可

这类许可证适合开源协作和二次研究，但如果你要把它深度嵌入闭源商业工作流，需要先看清 license 影响。

README 的“500+ skills”与可见目录规模要区分

宣传口径讲的是全系统 capability；真正落地时仍需按你配置的 provider、GPU、本地工具链和 pipeline 选择去看哪些能力现在能跑。

“一句话拍大片”并不等于完全免审

OpenMontage 的设计本身也假设你要做人类审批：proposal、cost estimates、quality gates 都在提醒你，这仍是一套需要控制的 production system。

为什么值得发这张卡：OpenMontage 把“AI 视频生成”从一个 prompt 工具，往前推进成了带 pipeline、tooling、skills、quality gate、budget governance 的生产系统。对于已经在用 Claude Code / Cursor / Copilot 的人，它提供的不是另一个模型入口，而是一套更完整的视频生产工作台。

最适合谁：想把 Agent 扩展到视频工作流的人；想要真实素材 documentary path、而不是只做图片转场视频的人；想比较本地/免费路径和云端 provider 混合生产的人。
