02
Mechanism

它怎么工作

把仓库或帖子背后的工作流拆成可复用步骤，而不是只说“很强”。

STEP 1

文件结构

顶层是 YAML front matter，下面是 Markdown body。

STEP 2

分段约束

Sections 必须按 spec 顺序出现，未知内容保留但不报错。

STEP 3

行为契约

它告诉 agent 该如何理解设计系统，而不是直接决定视觉长什么样。

STEP 4

输出

lint / diff 两类命令都返回结构化数据，方便脚本消费。

03
Fit & Boundaries

适合谁 / 不适合谁

把边界说出来，卡片才像决策辅助页，而不是宣传页。

适合

适合

  • 设计系统文档
  • AI 驱动 UI 生成
  • 需要长期稳定视觉身份的项目
不适合

不适合

  • 只想要一个 CSS 主题
  • 没有 token 规范的随手页面
