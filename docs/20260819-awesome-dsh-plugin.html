核心定位

为什么需要这个列表？

痛点
插件分散在各作者仓库，安装方式不统一，质量参差不齐
有了这个列表，就有了统一的入口和安装标准
收录标准
能通过 dsh plugin add 安装、有 dsh.bundle manifest、经人工核查描述属实
不是所有 GitHub 仓库都能装就能上这个列表
生态位置

在 DSH 生态中扮演什么角色？

官方定位
DeepSeek 官方开源的 Coding Agent 框架（Harness = "马具/驾驭）
Harness 本身是框架，插件是扩展手段，列表是发现层
配合使用
dsh-market（内置插件市场，一键安装升级换主题）
在 DSH Settings 里点击即装，不需要找仓库
安全说明

⚠️ 安装第三方插件有风险

警告
插件运行在本地，拥有你的文件和凭证，Tool Approvals 不会隔离插件代码
列表不是安全审查，上插件前先读源码
排除标准
仓库消失、停止维护、或发现实际不可用 → 从列表移除
动态维护，保持可用性

安装方式 · 三种任选
CLI 安装（推荐）
# 最简方式，直接从列表安装
dsh plugin add <owner/repo>

# 示例：安装 dsh-market（内置插件市场）
dsh plugin --profile web add dsh-market

# 安装插件发现工具（会话内搜索 GitHub）
dsh plugin --profile web add dsh-find-plugin

3. 仓库必须带有 dsh-plugin topic
4. 描述必须与实际功能完全匹配
