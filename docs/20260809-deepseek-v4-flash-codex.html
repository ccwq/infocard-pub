01
01 / OFFICIAL PATH

官方脚本实际替你处理什么

DeepSeek 官方文档给出的重点是可恢复性和兼容性。

备份

把 ~/.codex/config.toml 备份到 backup-deepseek，便于回滚。

模型目录

写入 ~/.codex/models.json，声明上下文、reasoning effort、tool call 等元数据。

provider

在 config.toml 中增加 [model_providers.deepseek]，并尽量保留现有 MCP servers 与项目 trust 设置。

02
02 / COMPATIBILITY

为什么不能只填 base_url

Codex 需要知道模型如何被调用，而不只是请求发往哪里。

当前支持

官方文档写明目前 deepseek-v4-flash 支持 Codex 集成；v4-pro 的支持时间以最新官方文档为准。

Responses API

V4-Flash 支持 DeepSeek Responses API 形式，Codex 配置使用官方 base_url。

能力边界

文档同时列出不支持的状态字段与内置工具类型；兼容不等于所有 OpenAI Responses 能力都可用。

03
03 / RECOVERY

最小可恢复试用法

把“能跑”升级成“出了问题能撤回”。

先备份

复制现有 ~/.codex/config.toml，并记录当前模型和 provider。

跑官方脚本

让脚本负责生成 models.json、修改 provider，并在写入前做语法校验。

验收

重新启动 Codex，确认模型可选、一次简单请求成功；失败就恢复备份，不要继续叠加手改。
