01 / CURRENT STATE

先把“支持 MCP”拆成四个问题

项目层面的支持状态，不能用一个标题概括。

WebUI 客户端

PR #18655 已合并，覆盖 Tools、Resources、Prompts 与 Agentic Loop。

Server 端

PR #25736 的目标是让 llama-server 通过 stdio 连接外部 MCP server；公开资料显示它仍标为 experimental。

传输方式

此前路径偏 HTTP(S)，stdio 路径意味着 llama-server 可直接拉起本地子进程。

02
02 / IMPLEMENTATION

配置面与运行时行为

真正影响部署的是进程生命周期、工具暴露和 slot 关系。

配置入口

PR 描述了 Cursor-compatible JSON，并提供 --mcp-servers-config 与 --mcp-servers-json。

懒加载

启动时做工具发现；实例在首次调用时懒启动，并在 server 进程生命周期内保持。

关键限制

MCP 实例是 global 而非 per-slot；/tools 没有 slot binding，状态型 server 需要谨慎评估。

03
03 / SECURITY

本地能力越强，信任边界越重要

stdio MCP 的价值是本地可组合，风险也是本地进程执行。

进程执行

启用后会 spawn 任意本地进程；不应在不受信环境直接打开。

跨平台坑

PR 讨论涉及 Windows 参数 quoting、stderr/stdout 混流、并发与路径空格。

建议

先在隔离目录和低权限账户测试，再接入真实文件、浏览器或系统控制工具。
