LOOP ENGINEERING / APACHE-2.0

loop.js

给 Agent 一个目标和完成标准，让它一轮轮执行；每轮清空上下文、把笔记落盘，直到独立且只读的 Verify Agent 判定达标。

来源：github.com/loop-js/loop.js

GOAL
要达成什么
↓ fresh session
EXECUTE WORKER
可读写，完成任务并交接笔记
↓ independent read-only check
VERIFY AGENT
只读判定：ok / impossible / continue

三种 prompt，同一种形状

goal、execute、verify 都接受同一种 Prompt：字符串、文件引用或函数。目标、干活和验收因此可以复用同一套表达方式，但职责仍然分离。

goalexecuteverify

Worker 无自判权

Execute Worker 默认是 auto，可以改工作区；Verify Agent 默认是 read，禁用写操作。循环是否收尾只看 Verify 的 Verdict。

每轮从零开始

Execute 每轮使用 fresh session，不 resume 上一轮上下文。跨轮连续性来自磁盘，而不是越来越长的聊天记录。

把记忆写进文件

Handoff 将笔记写入 rounds/XXXXK-<slug>.md，并投影到 .loop/index.md；下一轮再读回来继续。

最小运行路径

npm create @loop.js@latest # 或 npm install @loop.js/core export ANTHROPIC_API_KEY=... loop run

要求 Node.js >= 22.18.0。默认执行模型为 Claude Opus，Verify 使用更便宜的 Claude Haiku。

Guard 不是完成标准

rounds、usd、timeout 只是防跑飞护卫。即使达到轮数，只要最后的 Verify 返回 ok，Loop 仍然可以 settled。

不要混淆

loop.js ≠ Claude Code /loop loop.js ≠ while(true) Verify Agent ≠ Execute Worker Agent.run() ≠ Loop.run() package 0.2.0-beta ≠ Release v0.1.0-beta
