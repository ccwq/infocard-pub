ui-ux-pro-max149,946 ★（11-16）
github.com/nextlevelbuilder/ui-ux-pro-max-skill
原帖称「设计类的绝对一哥」。README 给两条路：Claude Code 插件市场，或 npm 装 CLI。注意官方 README 提示旧包 uipro-cli 已过期，要用 ui-ux-pro-max-cli。
官方 README 安装命令 
# 方式 A：Claude Code 插件
/plugin marketplace add nextlevelbuilder/ui-ux-pro-max-skill
/plugin install ui-ux-pro-max@ui-ux-pro-max-skill

# 方式 B：CLI（装的是 uipro 命令）
npm install -g ui-ux-pro-max-cli
uipro init --ai claude            # 当前项目
uipro init --ai claude --global   # 装到 ~/.claude/skills/

05 怎么装 · Claude Code 与豆包
动手
路径 A · Claude Code / Codex / Cursor 系
01挑 1 个头部 + 1 个品味类 02进 agent 会话粘贴命令 03/plugin 或 npx skills 04重启会话，发需求验证
三种通用装法（以上表命令为准） 
# 1) Claude Code 插件市场（ui-ux-pro-max / taste-skill / scroll-world 可用；designer-skills 与 design-os 两个候选仓库各自也支持）
/plugin marketplace add <owner>/<repo>
/plugin install <plugin>@<marketplace>

# 2) 跨 agent 的 skills CLI（huashu-design / taste-skill / scroll-world / emilkowalski / make-interfaces-feel-better 可用）
npx skills add <owner>/<repo>        # 交互式选目标 agent，-a codex 直装 Codex

# 3) 手动放置：把仓库克隆进 skills 目录
git clone https://github.com/<owner>/<repo>.git ~/.claude/skills/<name>
路径 B · 豆包（不装插件）
原帖作者的做法（作者自述，本卡未实测）：去 GitHub 把 Skill 仓库的说明文件（SKILL.md / README）下载下来，直接发给豆包让它照着执行，同一个聊天里接着说需求。作者称把 ui-ux-pro-max 的规则文件喂给豆包做小程序界面后，「配色和间距明显不像以前那么毛坯」。此说法是作者的个人体验，没有可复核的对照证据；按 04 节找到仓库、下载说明文件即可自行验证。
原帖的判断值得记住：Skill 就是一份「怎么干活的说明书」，Claude、豆包、智谱清言还是别的 Agent，谁看得懂说明书，谁就涨本事。
06 边界与行动
先读再装
作者建议（原文观点）
别全装：装一个头部 + 一个品味类就够，规则塞太多 AI 反而打架。作者自己的组合是 ui-ux-pro-max 打底、taste-skill 纠偏。他把效果描述为「朋友都问是不是花钱请了设计」——这是作者的主观评价，不是可复核的结论。
行动顺序：按 01 表选仓库 → 用 02/03 节的官方命令安装 → 给 agent 发一个真实需求（例如一个落地页）对比装前装后 → 不合适就 /plugin 卸载，成本很低。
时效与归因
星标时效：原帖数值是 2026-10-31，本表复核是 2026-11-16，两列都只是单时点读数。判断「活不活跃」看仓库最近的 commit 与 release，别只看星标。
未核验项：豆包路径为原文自述；designer-skills 与 Design OS 两名各有多个同名仓库，原帖未指明对应哪一个，本卡并列候选；候选 A（buildermethods）Design OS 安装细节在外部文档；「秒变设计总监」是标题修辞，本卡不为其背书。
