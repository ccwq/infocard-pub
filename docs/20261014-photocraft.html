01

先判断：你要编辑图片，还是替代生产工具？

PhotoCraft 用纯 Rust 实现文档模型与命令引擎，egui 提供原生界面，wgpu 合成画布；另有 CPU 合成器作为对照。可处理图层、蒙版、文字、矢量、画笔与 PSD，不是 Adobe 产品，也不依赖 Photoshop 插件生态。

可以从这里开始

测试小型分层 PSD；做可撤销的曲线调整；探索批量处理、CLI 或 agent 对现有图像的操作。

先不要拿它交付

关键客户原稿、复杂字体排版、强依赖插件或生成式 AI 的项目。官方明确列出 AI/生成功能、15 个工具、字体与专业流程深度、插件兼容等缺口。

“67 个工具 / 500+ 命令”应该怎样理解？

README 列出 67 个工具，并称 500+ 命令共享 UI、CLI、JSON 控制与 MCP 入口。这是官方描述，不是本次逐项运行结果。菜单接到命令只说明入口已连通，不代表每个工具行为与 Photoshop 完整一致。

02

安装：先选系统，再选 CPU

普通用户先用发行包，不必先装 Rust。打开 GitHub Releases 或 官方下载页；下面是 README 声明的包类型，不代表本轮已逐一核验资产。

系统包与架构选择动作
Windowsx64 / arm64 / x86；MSI 与 portable ZIP常规 Intel/AMD 64 位选 x64；ARM PC 选 arm64；32 位系统才选 x86。
macOSUniversal DMG；CLI 单独 Universal ZIPDMG 同时面向 Apple silicon 与 Intel；要用命令行，再下载 CLI 包。
Linuxx86_64 / aarch64；AppImage、deb、rpm、Flatpak、tarIntel/AMD 通常选 x86_64，ARM64 选 aarch64；格式按发行版或隔离需求选择。

下载后对照该 release 的 SHA256SUMS.txt 检查包；首次启动用 File › Open 打开 PSD 副本。Linux Wayland 暂不支持把文件拖进窗口：用 File › Open，或在文件管理器复制图片后按 Ctrl+V。

Linux 安装示例与首次启动副作用

<version> 是占位符，必须换成你实际下载的版本；架构也要对应机器。Flatpak 会提示安装所需 freedesktop runtime。

flatpak install --user photocraft-<version>-linux-x86_64.flatpak
flatpak run ai.storyteller.photocraft

AppImage 不需传统安装，但首次运行会在 ~/.local/share 注册图标与菜单入口，并非完全无副作用。若不需要桌面集成：

chmod +x photocraft-<version>-linux-x86_64.AppImage
PHOTOCRAFT_NO_DESKTOP_INTEGRATION=1 ./photocraft-<version>-linux-x86_64.AppImage

上面 chmod 与环境变量启动是按发行文件名组织的操作示例，未实测。撤销桌面集成参见官方 releasing 文档。

源码运行是开发路线，不是安装前提

需要 Rust 工具链与源码目录。README 的桌面启动命令如下；此处不声称它在你的平台一定编译成功。

cargo run --release -p photocraft -- image.psd

发行版包含可选 craft-fonts 构建输入；没有它的源码构建会使用系统 CJK 字体。文字验收仍应检查原稿所需字体是否存在。

03

第一个任务：PSD 打开 → 另存 → 再打开

建议小样：选一份含背景、可编辑文字、蒙版与调整层的小 PSD。先备份原稿；不要用唯一一份客户文件做实验。

  1. 留基准：在原编辑器中记录画面、图层顺序、字体和关键位置，保留基准截图或平面预览。
  2. 打开副本：逐项检查文字内容与可编辑性、蒙版边缘、调整层效果、位置与颜色；阅读任何导入警告。
  3. 微改并另存：只做一次小改动，保存为新的 PSD 文件名。若使用原生工程，可另留 .pcraft，不要把它当成 PSD 互通证明。
  4. 重新打开：关闭后在 PhotoCraft 再开新 PSD；若需交给 Photoshop，就再用 Photoshop 打开，重复同一检查。
  5. 最后才导出：PNG/JPEG 用于预览或交付平面图；它们不保留可编辑图层，不能代替工程备份。

通过标准是你的小样通过，不是软件“完全兼容”。若文字替换、蒙版失效、颜色改变或导入警告未消除，停止扩大使用，保留原稿与问题样本。

307 / 309 的测试结果，能证明什么？

作者报告：在 psd-tools 测试集合中，307 个文件在打开并重存后渲染一致，总数为 309。这只是该测试集合的结果，不是所有 PSD 的通用兼容率，也不是重存文件的二进制相同。

PhotoCraft 会重写资源、图层记录与合成图。README 另述独立 photocraft-psd crate 在不经过文档模型的解析/写回路径中可逐字节复现可解析语料；这不能套用到桌面应用编辑后保存。

04

第二个任务：用调整层与蒙版做局部修改

把“改原像素”改为“加一层可关闭的效果”。官方说明支持 Curves、Levels、Vibrance、Hue/Saturation 等调整层，可重排、禁用并用蒙版限制区域。下面是建议练习流程，具体入口以安装版本为准。

选中目标
→
新增调整层
→
限制蒙版
→
开关验收
  1. 打开已通过初步验收的副本，先确认当前选中的图层，而不是直接在原图上刷颜色。
  2. 新增 Curves 调整层，只做轻微亮度变化；开关该层，确认画面恢复与变化均符合预期。
  3. 用选区转蒙版，或在蒙版上限制效果：白色显示、黑色隐藏，灰色提供过渡；确认编辑目标是蒙版，不是图像缩略图。
  4. 放大检查边缘、半透明区和文字；切换调整层与蒙版，确认只影响目标区域。
  5. 另存工程并重开，检查调整参数、蒙版和图层顺序是否仍可继续编辑。
常见失败：为什么“局部调整”影响了整张图？
  • 没有有效蒙版：先查看调整层是否带有蒙版，再看蒙版是否几乎全白。
  • 编辑错对象：画笔可能落在像素图层上，先撤销，再确认蒙版被选中。
  • 保存后不再可编辑：检查是否导出了 PNG/JPEG，而非保存工程；平面导出不保留调整层。

以上是通用排查方法，不是已验证的 PhotoCraft 缺陷清单。若重开后变化无法解释，停止覆盖保存并报告样本。

05

CLI：先跑单文件，再考虑批量

先确认 photocraft-cli 已可调用，且当前目录有你自己的 wave.psd 副本。以下是 README 的真实示例，不是本轮运行记录；续行写法面向 POSIX shell。

photocraft-cli run wave.psd \
  --cmd filter.sharpen.smartSharpen     --params '{"amount":80}' \
  --cmd layer.newAdjustmentLayer.curves --params '{"points":[[0,0],[64,48],[192,212],[255,255]]}' \
  --out wave-final.png
参数本例作用验收动作
--cmd按顺序执行智能锐化与新增曲线调整层命令先在副本上看效果，不把命令存在理解为效果与 Photoshop 完全等价。
--params每个命令后传 JSON；本例 amount=80 与四个曲线点这些是示例值，不是默认值或适合所有图片的推荐值。
--out输出 wave-final.png确认新文件能打开，画面变化正确；PNG 不保留新增调整层。
批量命令：先查帮助，不编造动作文件
photocraft-cli batch --help
photocraft-cli batch --actions grade.json --in ./raw --out ./graded

grade.json 是 README 示例中的动作文件，不是随卡提供的成品。它的 schema 本轮未核验；请按你所装版本的帮助和官方文档准备，不要猜字段。先用 1–2 个输入副本与独立输出目录试跑，再检查是否有失败或异常产物。

若遇到 command not found，先确认 CLI 包、解压路径和可执行文件位置；若输入打不开，先用 GUI 打开同一副本。不要用扩大批量规模代替诊断。

06

MCP 与控制通道：自动化入口，不是生成式 AI

无头 MCP 入口

photocraft-cli mcp

README 描述可无头运行或桥接正在运行的桌面应用。它让 agent 通过结构化命令操作现有像素、图层与文档；不等于内置 AI 生图、生成式填充或自动替你做审美判断。

桌面控制入口

photocraft --control

官方说明这是需认证、仅 loopback 的控制通道，可读取 UI 状态、驱动指针与截图。不是向公网开放的远程编辑服务。

最小授权：只交给 agent 一个测试目录与副本，输出到新位置。不要公开令牌、贴入截图或日志，不要把控制端口通过反向代理暴露到公网。

接入 agent 前的四项检查
  1. 先读 控制协议 与所用客户端的 MCP 接入说明；本卡未提供未经核验的配置 JSON、端口或令牌字段。
  2. 区分“软件本地处理”和“agent 在哪里运行”：云端 agent 仍可能读取文件、上传内容或调用计费模型。
  3. 让 agent 先描述计划与输出路径，再授权写文件、批处理或覆盖；生产原稿不放入测试目录。
  4. 检查实际产物与变更，不只读 agent 的“成功”回复；结束后关闭不需要的控制入口。

本地运行不意味着“零 token 保证”，MCP 也不是沙箱。文件权限、客户端配置与模型费用需单独管理。

07

性能与格式：看具体任务，不看“全兼容”口号

wgpu GPU 合成器、CPU 对照合成器、写时复制的 256² 稀疏瓦片与多线程滤镜是 README 描述的设计。它们不是本轮性能测试；大 PSD、图层数量、位深、GPU 驱动与字体都会改变体验。

建议验收顺序：先小样，再换到你的典型尺寸与图层数；分别观察打开、缩放、一次滤镜、撤销、保存与重开。出现问题时记录系统、文档尺寸、图层数和截图，不要只报告“很慢”。

格式速查：读写能力不能混为一谈
格式官方边界工作流建议
PSD / PSB / .pcraft支持分层工程；PSD 仍需逐文件来回验收保留原稿，另存后重开；不能用 PNG 成功替代 PSD 验收。
PNG / JPEG平面输出；PNG 可保留 8/16 位样本，JPEG 降为 8 位用于预览或平面交付，另保留可编辑工程。
HEIC只读；官方构建包含，源码为可选 heif feature可尝试导入手机照片，不要规划 HEIC 回写。
AVIF / JPEG XLAVIF 仅可选构建写入，不支持解码；JPEG XL 不可用不要假设现成 AVIF 可打开，也不要选择 JXL 导出。
Affinity 文档只读；不支持部分会有警告，不能导出 Affinity检查效果与调整层警告，不作为无损来回编辑方案。

README 还列出分层 TIFF、OpenRaster 读写，PDN3 与 Krita .kra 读取等。需核对“读取 / 写入 / 图层 / 位深”四个维度，不应概括成所有设计格式全兼容。输出色彩关键时，用实际目标软件、嵌入色彩配置和样本验收。
