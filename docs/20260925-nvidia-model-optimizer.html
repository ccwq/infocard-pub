02 / 五种手段怎么选：一张决策表
手段做什么什么时候用
PTQ 量化训练后直接压权重（FP8/NVFP4 等），无需重训，2–4× 体积缩减所有人的第一步。显存差一口气时的首选；拿校准集跑一遍前向即可
QAT / 量化感知蒸馏量化后再用少量训练步骤把精度找回来PTQ 后精度掉太多、且你有算力做短训时——官方称 NVFP4 W4A4 + QAD 在 Qwen3.6-35B 上恢复所失精度
剪枝 Pruning按深度（砍整层）或宽度（砍隐藏维）删参数需要"小一号的同款模型"而非低精度版；配合蒸馏使用（Minitron 范式）
蒸馏 Distillation让小模型学大模型的行为（logits 级）剪枝后恢复精度；或干脆造一个全新小模型
推测解码 / 稀疏化 / NAS draft 模型加速解码 / 结构化稀疏 / 自动搜结构推理延迟敏感；Puzzletron（2026-05 新算法）做异构剪枝与 NAS

官方组合拳参考：剪枝 + 两阶段蒸馏 + FP8 = Nemotron-3-Nano-30B 案例（2.6× 吞吐、2.6× 内存）；W4A4 NVFP4 + 量化感知蒸馏 = Qwen3.6-35B 案例（1.30× vLLM 吞吐、检查点小 3.1×）；NVFP4 PTQ = Nemotron 3 Ultra 550B 案例（decode-heavy 吞吐达 GLM-5.1 754B FP4 的 5.9×，精度持平 BF16）。

03 / 三行代码上手 PTQ（官方 hf_ptq 范式）
# 安装 pip install -U nvidia-modelopt[all] # 量化核心就一步 import modelopt.torch.quantization as mtq model = AutoModelForCausalLM.from_pretrained("你的模型") calib_set = get_dataloader(num_samples=calib_size) # 校准集 def forward_loop(model): for batch in calib_set: model(batch) model = mtq.quantize(model, mtq.NVFP4_DEFAULT_CFG, forward_loop) # 导出统一 HF 检查点（vLLM/SGLang/TensorRT-LLM 直接认） from modelopt.torch.export import export_hf_checkpoint

关键细节（官方 hf_ptq 文档）：校准集默认混用 cnn_dailymail 与英伟达自家 Nemotron-Post-Training-Dataset-v2。NVFP4 精度敏感的模型别用 DEFAULT 配置——改用 NVFP4_MLP_ONLY_CFG（只压 MLP/MoE）、NVFP4_EXPERTS_ONLY_CFG（只压专家层）或 NVFP4_OMLP_ONLY_CFG，保住注意力 QKV 不量化，压缩照做、精度少掉。

不想自己压？三个现成检查点直接下：DeepSeek-R1-NVFP4、Llama-3.3-70B-Instruct-NVFP4（28 万次下载最多）、Llama-3.1-405B-Instruct-NVFP4——统一 HF 格式，vLLM 一行加载。另外三条路：nvcr.io 容器镜像预装；问 Claude Code/Codex 里装好的 modelopt 技能；或看 HF nvidia 主页整列现成量化模型。

04 / 三个官方案例：压缩的真实成本与收益
案例手段结果代价（诚实披露）
Nemotron 3 Ultra 550B（英伟达自产）NVFP4 PTQdecode-heavy 吞吐 5.9× 于 GLM-5.1 754B FP4；精度匹配 BF16需前向校准；对照物是别家 754B 模型，比较口径由英伟达定
Domyn-Large 263B（意大利主权 AI）Minitron 深度+宽度剪枝 → logits 蒸馏355B → 263B，关键基准平均降 3.2pp；上下文扩到 64K（评测 128K）探索过"两轮轻剪枝"路线，没有比单次剪枝更好；更激进的剪枝蒸馏也救不回来
Bielik Minitron 7B（波兰语模型）Minitron 剪枝 + 蒸馏体积 -33%、速度 +50%、保 90% 质量10% 质量让渡换部署成本，适合语种专用场景

读表须知：三个案例都没说"无损"。NVFP4 案例的对照基线是别家模型而非自家 BF16（后者另说"匹配精度"）；剪枝案例明确存在 3.2pp 下滑与"多剪必崩"的边界——hidden 65,920 / 90 层这个配置是实验出来的甜点，不是普适公式。压缩是工程权衡，不是免费午餐。

05 / 新手常见 4 问
PTQ 掉精度怎么办？
第一步换敏感层配置（MLP_ONLY / EXPERTS_ONLY / OMLP_ONLY，保 QKV）
第二步换校准集（换成本任务领域数据）
第三步上 QAT/量化感知蒸馏（需要训练算力）
压完的模型怎么部署？
导出export_hf_checkpoint 出统一 HF 检查点
目标vLLM / SGLang / TensorRT-LLM（PyTorch 与 C++ 后端都认）
注意旧式 TRT-LLM 专用检查点只剩 C++ 后端可用（legacy）
Claude Code 里的技能有什么用？
作用装好后直接问"这个模型该怎么量化"——技能内置 ModelOpt 方法学
安装claude plugin install modelopt@modelopt / Codex 同理
和 GGUF/llama.cpp 什么关系？
赛道不同：ModelOpt 面向 vLLM/TensorRT-LLM 级服务端推理
格式NVFP4/FP8 是 NVIDIA 硬件生态格式
不适合AMD/消费卡用户；本地聊天级需求不是本工具目标人群
06 / 判断

值得用：如果你在 vLLM/TensorRT-LLM 上部署、显存刚好差一口气，PTQ 三行代码 + 现成 NVFP4 检查点是当下性价比最高的路径；多节点大模型想"瘦身保精度"，Minitron 剪枝+蒸馏有 Domyn/Bielik 两个非 Meta 产出的独立案例背书。

想清楚：① NVFP4/FP8 是 NVIDIA 硬件生态格式，AMD/消费卡用户先确认硬件支持；② "压缩后精度持平"都附带基准口径，自己的业务集必须重测；③ 剪枝+蒸馏是重活（Domyn 是 DGX Cloud + NeMo 级投入），个人用户止步 PTQ 即可。
