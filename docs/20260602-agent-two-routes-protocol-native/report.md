# Agent 正在分叉成两条路线：Harness 只是第一阶段，协议才是下一层

## 结论

这条 X 帖的核心判断很明确：**Agent 的主线正在从 Harness 式多 Agent 编排，转向 Protocol-Native 的身份型 Agent 社会。**

前者仍然是软件工程问题，靠上下文共享、任务路由、工具调用、规划和记忆把多个子角色组织起来；后者则要求 Agent 真正成为“身份实体”，让权限、信任、委托、激励、声誉和价值交换都通过协议来处理。

## 这条帖到底说了什么

- 第一条路线：Harness 式多 Agent 系统。
  - 本质是 Workflow Engine + 更灵活的 ontology。
  - Agent 更像可调用函数、工具节点、带人格的任务节点。
  - 关键能力仍然是 Prompt Engineering、Context Management、Task Routing、Tool Calling、Planning、Memory、Workflow。
- 第二条路线：Protocol-Native Agent System。
  - 每个人拥有自己的 Personal Agent，甚至是专属无人公司。
  - Agent 从 task-scoped 变成 identity-scoped。
  - 关系网络、历史、偏好、权限、利益边界都被长期保留。
  - 交互从 API Call 变成制度性交互。

## 为什么这条判断值得单独做卡

这不是一般的“多 Agent 趋势判断”，而是在把 Agent 的层级重新划线：

1. **第一层是调度问题**：怎样让多个角色更高效地协作。
2. **第二层是身份问题**：当 Agent 真的代表“你”，协议必须接管协作基础设施。
3. **第三层是组织问题**：协议不再只是通信格式，而是组织关系本身。

这就是帖里“协议即组织”的意义。
