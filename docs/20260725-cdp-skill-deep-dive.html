方案 1 · Stagehand v3（browserbase/stagehand）
Stagehand v3 · 23.6k ★ · MIT 2026-07-25 当天 commit

核心突破：2026-05/06，Stagehand v3 引入「CUA → deterministic scripts」机制——AI 决策路径自动固化为可重放脚本，真正实现了"操作录像→可复用 skill"的转化。官方称之为「Action caching + CUA 确定性脚本」。

四种原语：act() / extract() / observe() / agent()，每个都支持缓存和脚本化。

v3 新增：deterministic scripts
// 原来：每次 act('click X') 都是 LLM 决策 await stagehand.act('click the submit button'); // v3：第一次跑通后，缓存为确定性脚本 // 第二次直接回放，无 LLM 开销 const cached = await stagehand.act('click submit', { cache: true, deterministic: true, // 输出 .ts 脚本，可被外层消费 }); // cached.actionSequence → 可序列化为 SKILL.md 操作步骤

CDP 支持：底层即 Playwright/Puppeteer/CDP，原生支持。

Shadow DOM：v3 专门加入了 shadow root pierce 支持，不需额外 selector 兜底。

Browserbase 配套：云端 stealth mode Chrome，session replay + 无限并发（需付费）；本地自托管免费。

与 Hermes 组合：Stagehand 生成的 .ts 脚本 + Hermes skill_manage → 完整的 SKILL.md。Stagehand 管"操作层"，Hermes 管"知识层"。

方案 2 · Midscene.js v1.6（web-infra-dev/midscene）
Midscene.js · 14.2k ★ · MIT 2026-07-24 当天 commit · v1.6 新增 CDP

核心突破：v1.6 正式引入「CDP browser connect mode」，支持直接接入 Playwright / Puppeteer 的 CDP 端点，不再依赖 Midscene 自家的 browser runner。这意味着 Midscene 可以接 Hermes 的 agent-browser --cdp 9222 已有登录态。

v1.6 CDP connect 模式
import { Midscene } from '@midscene/web'; // 方式1：接 Hermes 已有 Chrome CDP 9222 const ms = new Midscene({ browser: 'cdp', cdpEndpoint: 'ws://127.0.0.1:9222/devtools/page/...', // 复用已登录态，无需重新登录 }); // 方式2：接 Playwright 实例 const ms2 = new Midscene({ browser: 'playwright' }); // 视觉坐标操作（对 shadow DOM / wujie 友好） await ms.aiQuery('点击"发布"按钮', { mode: 'visual' }); // 自动生成 ai-query-report.json（可视化回放报告）

Midscene Skills DSL：2026 路线图明确要做"Midscene Skills"，即把操作流程固化为 YAML skill 文件，可被 Midscene agent 直接复用。

可视化回放：ai-query-report.json 包含每一步的 screenshot + action + LLM reasoning，可直接转为 SKILL.md 的"陷阱与排查"段落。

多模态 LLM：视觉路线，对抖音视频号后台、wujie 结构等 shadow DOM 友好的场景，是 Stagehand 之外的最佳选择。

方案 3 · Chrome DevTools MCP（ChromeDevTools/chrome-devtools-mcp）
Chrome DevTools MCP · Apache-2.0 2026-07 月快速迭代 · 替代 Chrome DevTools Recorder

关键背景：Chrome 148 之后，Chrome DevTools Recorder 被官方淡出，取而代之的是「Chrome DevTools MCP」——把 CDP 完整包成 MCP server，给 AI 编码助手直连 Chrome。

Chrome DevTools MCP 的核心价值

Chrome DevTools MCP 让 LLM agent（Claude / Codex / Hermes）直接通过 MCP 协议操作 Chrome：

  • 原生 CDP：直接暴露 Page / Runtime / Input / Network 所有 CDP 方法
  • MCP 协议：标准化的工具定义，AI 每次调用都是可追溯的 JSON-RPC，有日志可导出为 skill
  • vs Recorder：Recorder 只做录像回放；MCP 让 AI 在录制过程中实时参与决策
  • 与 skill_manage 联动：MCP call log → JSON → 人工总结 → SKILL.md（比 Recorder 多了"AI 决策推理"）

典型场景：用 Claude Code / Codex 写完一个 task → 让 Chrome DevTools MCP 执行 → 导出 call log → 总结为 SKILL.md。下次同类 task 加载 skill 即可跳过 MCP 调试。

限制：依赖 Chrome 实例本地运行；MCP 客户端需支持 MCP 协议（Claude Desktop / Codex CLI 已支持，Hermes 通过 mcp__browser_* 工具集部分实现）

方案 4 · Computer-Use-Hub（trycua/cua）
Computer-Use-Hub · 20.6k ★ · MIT 2026-07-25 当天 commit · macOS 沙箱优先

定位：Computer Use 场景的 benchmark + driver hub。聚合多个 CUA 实现（Anthropic Claude CUA / OpenAI CUA / Google Gemini CUA），统一接口，并自带 skill 导出机制。

Computer-Use-Hub 技能导出能力
# hub 内置 benchmark + drivers # 每次 CUA 执行都会记录 action sequence # 可导出为 standardized skill format from cua import ComputerUseAgent agent = ComputerUseAgent(provider='anthropic') result = agent.run('在飞书完成周报发布') # 导出 skill skill = result.export_skill( name='feishu-weekly-report', format='skmd', # SKILL.md 兼容格式 ) # skill.content → 直接写入 ~/.hermes/skills/...

Skill 格式：输出 .skmd 文件（与 SKILL.md 格式兼容），可直接写入 ~/.hermes/skills/<category>/<name>/SKILL.md。

适用场景：多 CUA 方案横向对比评估、标准化 skill 导出、macOS 桌面自动化（文件操作 + 浏览器 + 终端）。

限制：Linux/Windows 支持仍在完善中；偏沙箱评测，落地生产需额外适配。

方案 5 · CUA → Deterministic Scripts（跨框架趋势）
CUA 确定性化 · 2026 年跨框架趋势 Stagehand v3 首发，其他框架跟进中

背景：传统 CUA（Computer Use Agent）的核心问题是"不稳定性"——同一条 task 每次跑步骤可能不同，LLM 成本高，失败时难以定位。2026 年的突破方向是"确定性化"：让 AI 决策固化为一组可验证、可回放的脚本。

各框架进展：

  • Stagehand v3：deterministic: true + cache: true → 输出 .ts 可重放脚本
  • Midscene v1.6：ai-query-report.json 含每步 screenshot + reasoning + action
  • Computer-Use-Hub：内置 export_skill(format='skmd')
  • Skyvern：workflow.yaml 已是确定性 DSL，参数化后可复用
  • browser-use：trajectory 可导出，screenshot + actions JSON 可被外层脚本消费
  • OpenHands：trajectory log 可导出为 .agents/skills/ 目录
"CUA → skill" 全链路示意
操作者运行 CUA（Stagehand/Midscene/CUA-Hub）
↓
执行 log（action sequence + screenshot + reasoning）
↓
确定性脚本（.ts / .yaml / .skmd / JSON）
↓
人工审查 + 补充陷阱段
↓
SKILL.md（~/.hermes/skills/...）
↓
下次同场景 → 加载 skill → 直接运行确定性脚本（无 LLM 决策）
↓
验收清单 + 失败兜底（遇到异常回退到 CUA 模式）
