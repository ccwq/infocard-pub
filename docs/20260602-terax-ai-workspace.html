核心判断：Terax 不是“再做一个终端”，而是把 PTY、WebGL 渲染、AI 侧栏、代码编辑、git graph、Web preview 做成一个本地优先的开发工作台。它的强项是把终端上下文和 AI 工作流拧在一起。
01 · 一句话判断
Core Take
Terax 的定位
轻量、terminal-first、AI-native 的桌面开发工作台。基于 Tauri 2 + Rust + React 19，提供原生 PTY backend、WebGL renderer、AI side-panel、代码编辑器、文件树、source control、Web preview。
关键判断它的卖点不是“AI 功能很多”，而是开发上下文全在一个桌面壳里闭环：终端、编辑器、git、预览、AI 互相联动。
一句话总结
如果你需要一个本地可控、低体积、无账号依赖的 AI 开发工作台，Terax 的组合拳很完整：终端优先、AI 侧栏、文件与 git 一体化、跨平台桌面发布。

02 · 能力矩阵
Capabilities
Terminal
xterm.js + WebGL renderer，多标签页、后台流式输出、分屏、搜索、链接识别、真彩色、Windows tab workspace。
Code editor
CodeMirror 6，支持主流语言；内联 AI autocomplete、逐 hunk 接受/拒绝、Vim mode、十套内置主题。
AI side-panel
BYOK providers + local/offline；支持 plans、sub-agents、project memory、file read/write/edit/multi-edit/grep/glob、bash approval gating。
Source control
stage / unstage hunks、commit、push、branch display、real commit graph、commit search，直接跳远程提交页。
File explorer
Catppuccin 图标、模糊搜索、键盘导航、inline rename、context actions，支持直接 attach 到 AI 侧栏。
Web preview
自动发现本地 dev server 并预览，外部 URL 也可通过 native child webview 打开。

04 · AI 与模型策略
AI
支持哪些模型
BYOK：OpenAI、Anthropic、Google Gemini、Groq、xAI Grok、Cerebras、OpenRouter、DeepSeek、Mistral，以及任意 OpenAI-compatible endpoint。
本地 / 离线：LM Studio、MLX、Ollama。
Agentic workflow
plans、sub-agents、project memory via TERAX.md、file read/write/edit/multi-edit/grep/glob、bash 以及 approval gating、background processes。
custom agents slash commands voice input #handle / @path
Composer
通过 `#handle` 引入片段，通过 `@path` 引入文件，支持 attach-to-agent。
Plan mode
多步骤任务先生成并确认计划，再执行，减少误操作。
Keys
API key 写入 OS keychain via keyring，不落盘 / 不进 localStorage。

06 · 适合谁 / 不适合谁
Boundary
适合
1
终端即工作台希望 terminal、edit、git、preview、AI 在同一个界面里协同。
2
本地优先想减少云账号、遥测和隐私顾虑。
3
轻量但完整要桌面壳的完整性，但不想要重量级 IDE。
不适合
1
只想要纯终端工具如果不需要编辑器 / git / preview / AI 一体化，收益有限。
2
完全离线且无外部模型虽然支持本地模型，但若完全不配 AI，核心卖点会弱很多。
3
重度 IDE 深度插件依赖如果依赖特定 IDE 插件生态，Terax 不是那类产品。
