02 / 逐个说清楚：它是什么、怎么装、坑在哪

1. Awesome（510,244★）—— 不是导航站，是"列表的列表"

本体是 CC0 协议的元清单：几百个主题 awesome-* 列表的入口。正确用法是把它当目录索引，顺着进 awesome-llm、awesome-mcp-servers 这类子列表；常见误用是把它当收藏夹通读。注意 README 顶部注明 PR 暂停处理——维护者自己都快跟不上了，别指望它是实时更新的。

2. Public APIs（483,088★）—— 1,922 个 API 条目、52 类

机器数了README 表格：1,922 个条目、52 个分类，每条标注认证方式（无/ApiKey/OAuth）与 HTTPS/CORS 支持——选数据源时先看这两列，CORS 缺失意味着浏览器直连不可行。新增 MCP Servers 章节，方向已经在转。坑：顶部有 APILayer 商业推广位，免费清单里混着广告，别照单全收。

3. Scrapling（83,610★）—— 自适应爬虫，但注意安装分两步

亮点是"自适应"：页面结构变了，解析器能自动重新定位元素；fetcher 开箱绕 Cloudflare Turnstile；还有 MCP server 可以直接挂给 Agent 用。两个安装细节（README 加粗强调）：pip install scrapling 只装解析引擎，用 fetcher 必须再跑 scrapling install（下载浏览器和指纹依赖）；Python 要求 3.10+。典型用法 StealthyFetcher.fetch(url, headless=True, auto_save=True)。作者 Karim Shoair（D4Vinci）。合规提醒：绕反爬能力越强，越要确认目标站点的 robots 与服务条款。

4. Free for Dev（138,424★）—— 57 大类免费资源清单

约 1,370 个出链、57 个分类（云、CI/CD、DNS、监控、邮件……），做 MVP 前先来这里扫一遍能省真金白银。两个注意：仓库 API 里没有 LICENSE 文件（内容版权状态模糊，引用需注明来源）；免费额度变动频繁，用之前去服务商官网核对当前额度，清单有滞后。

5. Ollama（181,684★）—— MIT，本机跑模型的事实标准

ollama run gemma4 一条命令跑起来；REST API 在 localhost:11434/api/chat；新还加了 ollama launch openclaw（把 Ollama 变成 WhatsApp/Telegram/Slack/Discord 上的个人助手）。"省 90% API 成本"取决于你的硬件——电费+显存就是成本，只是不按 token 计费。真·隐性成本是质量差距：本地小模型和旗舰 API 的能力差，在复杂任务里会以返工时间的形式收回去。

6. Open WebUI（153,142★）—— 本地模型的前端，但许可证有品牌条款

Ollama 在本机时一条命令接入：docker run -d -p 3000:8080 --add-host=host.docker.internal:host-gateway -v open-webui:/app/backend/data --name open-webui --restart always ghcr.io/open-webui/open-webui:main；远程 Ollama 加 -e OLLAMA_BASE_URL=...；有 :cuda 镜像。许可证重点：不是标准 BSD——附加条款禁止移除/遮蔽/替换 "Open WebUI" 品牌标识，想改皮做商业分发需要联系官方（企业版路径）。

7. Dify（157,180★）—— 最快的 Agent/工作流 MVP 路径，但 SaaS 要买授权

安装：cd dify/docker && cp .env.example .env && docker compose up -d（要求 Docker Compose v2.24.0+），浏览器开 localhost/install 初始化。可视化编排 Agent、知识库、工作流，确实是"几小时出 MVP"级。许可证重点：魔改 Apache-2.0——多租户（一个 workspace 一个租户）环境必须取得商业授权，去掉品牌/logo 同样触发商用条款。自用、单租户内部工具没问题；拿它做对外 SaaS 前先读 LICENSE。

03 / 组合链路：这 7 个怎么串成一条"搞钱流水线"

推文说"覆盖完整链路"是对的，但没说怎么串。一条已验证可行的最小链路：

# 1. 数据面：Scrapling 抓行业信息（注意合规）
pip install "scrapling[fetchers]" && scrapling install

# 2. 模型面：Ollama 本地跑开源模型
ollama run gemma4          # 或任何适合任务的模型

# 3. 交互面：Open WebUI 套壳，团队可直接用
docker run -d -p 3000:8080 --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data --name open-webui \
  --restart always ghcr.io/open-webui/open-webui:main

# 4. 产品面：需要工作流/知识库/多角色编排时上 Dify
cd dify/docker && cp .env.example .env && docker compose up -d

# 5. 数据源与省钱：Public APIs 找接口，Free for Dev 找免费额度
#    Awesome 用于扩列表（MCP servers / LLM 资源等子清单）

链路顺序即成本顺序：先 Scrapling/Public APIs 解决"有没有料"，再 Ollama 解决"跑不跑得起"，然后 Open WebUI 解决"能不能给人用"，最后 Dify 解决"能不能编排出产品"。跳步的直接代价：没有 1-2 就上 4，Dify 编排的是空转的工作流。

04 / 判断

清单本身是及格的：7 个全部真实存在、全部活跃（6 个一周内有推送）、星数全部对得上。作为"AI 独立开发起步包"，这 7 个的选择确实覆盖了资源→数据→模型→界面→编排的最短路径，没有混入广告位项目。

两处要泼冷水：① 推文体量的百分比收益（10 倍/5 倍/90%）无一可溯源——这套话术是流量写法的标准件；② 许可证差异被完全略过：Dify 多租户商用需授权、Open WebUI 禁改品牌、Free for Dev 无 LICENSE——"拿开源拼个产品卖"之前，这三个文件必须先读。星数是热度的证据，不是你赚钱的证据；真正的验证只有一个：用你自己的场景跑一遍，看它省的是不是你的时间。
