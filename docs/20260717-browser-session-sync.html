BROWSER AUTOMATION · AUTH STATE

双浏览器登录态同步

把同一网站的 Cookies、localStorage 与 sessionStorage 从浏览器 A 定向迁移到浏览器 B。重点不是“复制 Profile”，而是建立一个可过滤、可验证、可回滚的状态搬运链路。

CDP 首选Cookie + Web Storage单向先行不打印 Token
一句话结论

CDP 原生覆盖 Cookie 与 DOM Storage；用两个浏览器 CDP 端点实现“读取 A → 写入 B → 刷新验证”，比复制 Profile、依赖浏览器 Sync 或只导出 Cookie 更可控。

RECOMMENDED PIPELINE

状态快照 → 定向恢复

控制范围、保留证据、避免把登录凭证变成长期明文文件。

01
SCOPE · MODEL

先定义“登录态”是什么

Cookies 和 Web Storage 只是常见组成部分；站点可能还依赖 IndexedDB、Service Worker、设备绑定或风险控制。

Cookies含 HttpOnly / Secure / SameSite
localStorageorigin 级持久键值
sessionStoragetab + frame + origin 作用域
其他状态IndexedDB / WebAuthn / 风控
关键区别

localStorage ≠ sessionStorage

localStorage 跨页面会话持久存在；sessionStorage 通常绑定当前顶层 browsing context，不能像普通 Cookie 一样“写入浏览器后自动覆盖所有 Tab”。目标 Tab 必须打开正确 origin，必要时还要处理 frame。

事实边界

复制成功 ≠ 登录一定成功

服务端可能把 token 与 IP、设备指纹、User-Agent、刷新轮换、CSRF、WebAuthn 或 IndexedDB 状态绑定。卡片中的方案是状态迁移能力，不是绕过站点认证或风控的保证。

02
CDP · NATIVE SURFACE

CDP 能直接做什么

Chrome DevTools Protocol 是控制接口，不是现成的“同步按钮”。同步器负责把两个端点串成一个安全流程。

Network

Cookies

使用 Network.getAllCookies 读取，目标端使用 Network.setCookies 批量恢复；也可用 setCookie 做单项更新。

  • 保留 domain/path/secure/httpOnly/sameSite
  • 注意 partitionKey 等分区 Cookie
  • 按目标 origin 或域名白名单过滤
DOMStorage

localStorage

使用 DOMStorage.getDOMStorageItems 读取，以 isLocalStorage: true 定位；用 setDOMStorageItem 写入。

  • 按 securityOrigin 精确定位
  • 只迁移声明过的 key 更安全
  • 写入后触发站点初始化或 reload
Tab / Frame

sessionStorage

用 isLocalStorage: false 读取/写入当前目标上下文；也可以在目标页面通过 Runtime.evaluate 操作 JS 对象。

  • 目标页面必须已打开
  • 关注顶层 frame 与 iframe
  • 不能假定新 Tab 自动继承
// 概念性 CDP 调用：不要把真实 token 打入日志 Network.getAllCookies() DOMStorage.getDOMStorageItems({ storageId: { securityOrigin: "https://example.com", isLocalStorage: true } }) DOMStorage.getDOMStorageItems({ storageId: { securityOrigin: "https://example.com", isLocalStorage: false } }) Network.setCookies({ cookies: filteredCookies })
03
IMPLEMENTATION · TWO ENDPOINTS

推荐的最小可行架构

第一版只做“单网站、单向、一次性同步”，先验证可控性，再考虑实时双向。

Source

浏览器 A：读取快照

  1. 通过 CDP 连接并枚举 targets。
  2. 确认目标 Tab 的 URL、origin 和 frame。
  3. 读取 Cookies、localStorage、sessionStorage。
  4. 在内存中按 origin / key 白名单过滤。
Target

浏览器 B：恢复并验证

  1. 通过另一个 CDP 端口连接。
  2. 打开同一 origin 的目标页面。
  3. 写入 Cookies 与两类 Web Storage。
  4. reload，检查页面登录标记或受保护 API。
步骤输入动作验收证据
发现CDP target 列表选择指定 origin 的 page/frameURL 与 origin 匹配
读取A 的状态Cookies + 两类 Storage只输出数量、key、域名摘要
恢复过滤后的快照B 写入并刷新无 API 错误、无跨域写入
验证登录标记DOM / API / 页面导航检查明确 PASS 或失败原因

OPTIONS · MATURITY

现成方案怎么选

没有一个成熟工具能无条件把两个现有浏览器的完整登录态实时镜像；要按运行环境和完整度取舍。

方案CookieslocalStoragesessionStorage现有浏览器判断
CDP 双端点同步器强强强，但依赖目标 Tab强最推荐
Playwright storageState强强需自定义脚本偏新建 Context适合测试/自动化
Cookie Editor 扩展强弱弱强适合手工排障
自定义 Chrome 扩展强可行可行但依赖注入强适合长期产品化
浏览器账号 Sync不完整不保证不适合有限不要依赖
复制 Profile表面完整表面完整不可控弱不推荐

Playwright 的位置

storageState 是成熟的 Cookie + localStorage 固化机制，适合测试账号复用和新建 BrowserContext。它不是现有两个浏览器 Tab 的完整同步器，sessionStorage 需额外在页面上下文读取/恢复。

扩展的长期价值

扩展可以用 chrome.cookies 监听和修改 Cookie，再用脚本注入读取 Web Storage；但需要 host permissions、中继服务、权限审计和跨浏览器适配，开发成本高于一次性 CDP 工具。

05
SECURITY · FAILURE MODES

安全边界与常见失败

登录态材料的敏感级别接近密码。同步器必须默认“最小权限、短生命周期、不落盘”。

高风险材料

  • session_id、access_token、refresh_token、id_token
  • HttpOnly Cookie 与 CSRF token
  • 任何可直接重放的认证凭证

禁止写日志、进 Git、通过公开 HTTP 传输或长期明文保存。

推荐的安全默认值

  • 仅允许显式 origin 白名单。
  • 内存传输；如必须落盘，使用 0600 且同步后立即删除。
  • 本机 Unix socket / 受限 localhost，不暴露公网。
  • 日志只记录数量、key 名、域名和结果，不记录 value。
  • 先做 A→B，失败时保留 B 的原状态快照或不覆盖写入。
失败 01

端口或 Profile 冲突

两个浏览器必须使用不同 CDP 端口和不同 user-data-dir。不要让两个进程并发写同一运行中的 Profile。

失败 02

写入了但仍未登录

检查 token 轮换、设备绑定、IndexedDB、Service Worker、CSRF、IP 和风险控制；不要无限重试或扩大复制范围。

失败 03

sessionStorage 不生效

确认目标 Tab、origin、frame 和写入时机；必要时先导航到目标页面，再在该页面上下文执行。

06
BUILD · DECISION

落地路线：先工具，后产品

把同步能力拆成可验证的阶段，避免一开始做实时双向和全存储复制。

MVP

一次性单向同步

一个 origin、A→B、内存快照、Cookie + 两类 Storage、刷新后检查登录标志。失败就报告具体层级，不自动扩大范围。

第二阶段

可审计的状态策略

加入 key/domain 白名单、冲突策略、dry-run、diff 摘要、失败回滚和按站点配置；仍不记录 secret value。

第三阶段

扩展或本地代理

只有确定需要按钮、监听变化、多用户或跨浏览器长期使用时，才做扩展 + 本地中继；同时做权限和密钥生命周期设计。

sync-config.yaml source: http://127.0.0.1:9222 target: http://127.0.0.1:9223 origins: ["https://example.com"] storage: [cookies, localStorage, sessionStorage] direction: A-to-B mode: one-shot log_values: false verify: [logged_in_dom_marker, protected_api_status]
