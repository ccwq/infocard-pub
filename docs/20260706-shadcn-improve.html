01 核心理念
核心洞察：把智能会累积的部分（理解代码库、判断什么值得做、写规格）交给最强模型；执行交给便宜的模型。Skill 自己从来不实现任何东西，计划才是产品。
智能分层：最强模型做审计、规划、判断；便宜模型只执行
永不越界：唯一的写入是 plans/，从不修改源代码
Worktree 隔离：执行器在一次性 Worktree 中编辑，不污染主分支
用户决策：合并始终由用户决定，Skill 只负责计划和审查
02 核心命令
/improve 全局审计 → 优先级排序的发现 → 计划 完整流程：勘查 → 审计 → 审查 → 排序 → 计划化
/improve quick 快速模式：热点 + 最高优先级发现 适合日常巡检，快速拿到 Top 发现
/improve deep 详尽模式：每个包、每个类别都过一遍 适合全面审计，不遗漏任何角落
/improve security 安全审计：专注安全，也覆盖 perf/tests/bugs 聚焦安全问题，附带其他类别发现
/improve branch 增量审计：只看当前分支改动的部分 适合 Code Review 场景
/improve next 产品方向：给出下一步产品方向建议 超越技术审计，提供战略视角
/improve plan <描述> 跳过审计，直接起草计划 直接进入计划阶段
/improve review-plan <文件> 批判收紧：审查并收紧已有计划 完善现有计划，提高可执行性
/improve execute <计划> 执行计划：派便宜执行器执行 隔离 Worktree + Tech Lead 审查
/improve reconcile 刷新 Backlog：验证、解锁、退役计划 保持计划列表与代码库同步

04 计划可执行特性
自包含：所有上下文内联，精确文件路径、代码摘录、规范示例、已验证命令
验证门：每步以命令及预期输出结束，完成标准机器可检查
硬边界：明确范围外列表，STOP 条件
05 闭环执行

execute 执行器

  • 在隔离 git worktree 中执行
  • 按计划执行每一步
  • 重跑每个完成标准
  • 检查范围合规
  • 读 diff 对意图

审查结果

  • ✅ 通过 → 批准（合并由用户决定）
  • 🔄 退回修改（最多 2 轮）
  • ⛔ 阻塞 → 精炼计划

reconcile 刷新 Backlog

  • 验证 DONE 计划是否仍成立
  • 调查 BLOCKED 计划并绕过障碍
  • 刷新漂移的计划
  • 退役独立修复了的发现

--issues 发布选项

  • 将计划发布为 GitHub Issues
  • 自动创建带标签的 Issue
  • 便于团队协作追踪
06 硬规则
🚫从不修改源代码，唯一的写入到 plans/
🛡️执行器只在一次性 worktree 中编辑
👤合并始终由用户决定
💥从不运行会破坏工作树的命令
🔐从不复现密钥值
📋被要求实现？拒绝并指向计划
