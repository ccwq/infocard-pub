Loop ≠ 传统指令
传统指令

"修复所有 lint 错误" —— 一次性命令，AI 可能修一半就停。

Loop 循环

执行 lint → 修复最小 diff → 再次 lint → 直到干净。闭环自动迭代到目标达成。

不是你持续提示 AI，而是你设计一个循环让它自己跑到终点。

Loop 的核心：给 AI 一个可验证的目标 + 一个检查命令 + 一个最大迭代次数，然后让它自己跑。你只需在必要时介入。
01 · 执行Run Check

运行检查命令（如 npm test），获取当前状态。

02 · 检查Verify

判断是否通过。通过则结束，未通过则分析失败原因。

03 · 修复Fix Root

修复最小根因，不做大范围改动，确保可追溯。

04 · 重复Repeat

迭代次数 +1，回到第 1 步。达到最大次数则提示人工介入。

核心概念与原则
concepts

Loop 五要素core

  • 目标 (Goal) — Loop 要达成的最终状态
  • 检查命令 (Check) — 验证目标是否达成
  • 最大迭代次数 — 防止无限循环
  • 退出条件 — 通常指检查命令返回成功
  • 执行步骤 — 每一轮的具体操作
1
目标清晰

必须有一个可验证的目标，不是模糊描述。

2
检查命令明确

必须有一个命令能判断是否达成目标。

3
可迭代修复

每次失败后都能进行小步修复，不伤整体。

4
有退出条件

避免无限循环，达上限时人工介入。

5
保持最小化

每个 Loop 只负责一个职责，不混合。

创建自己的 Loop

三步创建3 steps

  • 复制 prompts/zh/test-until-green.md
  • 重命名为 prompts/zh/my-loop.md
  • 修改标题、目标、检查命令、步骤

Loop 文件模板template

--- name: "my-custom-loop" description: "你的 Loop 目标" --- # 你的 Loop 标题 **分类:** 自定义 **最大迭代次数:** 5 ## 目标 描述 Loop 要达成的最终状态 ## 检查命令 npm run your-check-command ## 退出条件 检查命令返回成功 ## 执行步骤 Step 1: 运行检查命令 Step 2: 如果失败，修复最小根因 Step 3: 重复直到退出条件满足
最佳实践
best practices
A
运行前提交

运行 Loop 前最好先 git commit 当前工作，Loop 会修改代码。

B
每次只修最小根因

不做大范围重构，每次修改后必须运行检查命令验证。

C
设最大迭代次数

达到上限时人工介入，避免无限循环烧 token。

D
与 Git 工作流结合

功能分支 → Loop TDD → Loop 自审 → push → Loop 修 CI。

# Git + Loop 工作流 git checkout -b feature/new-stuff /loops autoloop-tdd # TDD 实现功能 /loops pr-self-review # 自我审查 git commit -am "feat: add new stuff" git push origin feature/new-stuff /loops fix-ci-until-green # 修 CI 到绿
