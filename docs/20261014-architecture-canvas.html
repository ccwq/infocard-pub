Architecture Canvas：用对话画架构图

weike-zhang/architecture-canvas · Apache-2.0 · 本机单用户 · Excalidraw 画布
从零到第一张图：6 步，先不配密钥

它是什么：一个跑在你本机的架构图工具。你上传需求文档，配一个能调工具的模型，然后用对话让它生成架构图；画布本身用的是 Excalidraw。作者在 README 里把当前状态写成「本机运行的 Alpha 版本」。

第一步

git clone https://github.com/weike-zhang/architecture-canvas
cd architecture-canvas
python3 start.py

首次运行会自动建 venv、装锁定版本的 npm 依赖并构建页面，耗时比第二次长。第二次直接复用，README「快速开始」是这么写的。

前置条件三个：Python 3.10+、Node.js 22.12+、npm。缺了就先 python3 start.py --check，它专门用来查依赖。

启动与依赖检查：端口和密钥

两个端口口径，原样照写

README 里出现两个端口，不要当成笔误去替作者统一：

方式命令端口
默认python3 start.py127.0.0.1:5093
换端口python3 start.py --port 5096你指定的值
README 另给PORT=5096 node harness/workspace.mjs环境变量指定

服务只监听本机回环地址，没有对外暴露的选项。

密钥的三个存放口径

① 页面里填填模型地址、模型名、API Key。密钥只在服务进程内存里，重启服务要重填。README「模型配置」是这么说的。
② llm.env 文件cp llm.env.example llm.env。这个文件不纳入版本管理，可以留着复用。重启后不用重填。
③ Tavily 搜索密钥联网搜索是可选模块。密钥只在进程内存，不进会话备份，运行中可以换或停用，不用重启 Harness。
不需要密钥的部分手动新建形状、拖动改字、导出 SVG/PNG、导入导出会话备份，都在本地完成。

模型要求：推文说得松了

推文 @GitHub_Daily 的说法是「模型不绑定，填兼容接口的地址和 Key 就能用」。准确的条件更窄一点，必须写成这样：

  • 需要兼容 Chat Completions 且支持工具调用（tool calling）的模型接口。填普通聊天接口不一定能跑通。
  • 要让模型「看图」（比如对着已有架构图提问），还需要支持视觉输入的模型，并在页面上勾选对应选项。

不是 OpenAI 专用。地址、名称、Key 都是你自己填。

边界提醒：README「当前边界」写明这是仅本机、单用户的 Alpha 版本：没有多用户账号，没有多人协作，没有生产部署说明。不要按团队平台来评估它。
数据放在哪：会话数据存在 .workspace/。换路径用环境变量 ARCH_DATA_DIR。这意味着它跟本机文件系统一样，需要你自己管权限和备份。
不配密钥，先把编辑和导出走通

无密钥体验

README 给了 demo.py，生成一份会话备份：

python3 demo.py --output demo-session.json

然后在页面的「上下文 → 导入会话备份」里导入它，就能看到一张示例图。这份示例是手工编写的知识助手结构，不调模型，也不搜索——它证明的是编辑和导出链路，不是生成质量。

导入后你可以拖动改字，然后导出 SVG 或 PNG。这条链路全程离线。

上传资料：支持什么，读到什么程度

资料类型

文本类：TXT、Markdown、CSV、JSON、YAML、XML、HTML、代码文本。文档类：DOCX、XLSX、PPTX、PDF。图片类：常见格式。

读法分两种。文档由本机解析，按行读取；图片作为视觉输入发给模型。

图片发送前最长边会压到 2048 像素。

不支持的

  • 旧版 DOC / XLS / PPT，需要自己先转换。
  • Office 内嵌图片。
  • 表格公式重算。
  • 音视频内容。

扫描版 PDF 与 OCR：可选依赖，不是自动能力

扫描件要出文字，需要额外装 Tesseract，而且中文需要 chi_sim 语言包。不装的话，页面会提示「无法识别」，不会假装已经读过。这一条推文完全没提，是决定能不能用它读合同/扫描需求文档的关键。

上限（README「限制」章节）

对象上限
每会话资料数20 份
单文件大小25MB
正文长度30 万字符
PDF 页数100 页

触到边界会给出提示，不会静默截断。会话保存消息、资料、当前图和最近 12 次生成历史。

一次真实工作流（作者建议，未实测）

下面这条路径按 README 的功能串起来，我没有克隆、启动或生成过任何架构图，以下未实测。它的作用是告诉你各功能按什么顺序用。

1导入备份
2配模型
3上传需求
4出首稿
5对话改
6导出
  1. 「上下文 → 导入会话备份」导入 demo.py 产出的 demo-session.json，先把界面认熟。
  2. 填模型地址、模型名、API Key。要看图再勾视觉输入选项。
  3. 上传需求文档。有扫描页就按上一节先把 Tesseract 和 chi_sim 装好。
  4. 让它出第一稿。首次生成直接显示，不走确认。
  5. 对话改。可以固定某个组件的位置，也可以限定只改选区。
  6. 导出 SVG、PNG，或者含图片的可编辑文件。

上下文面板能做什么

  • 备份或导入整个会话。
  • 删除会话或单份资料。
  • 看每个组件的来源。
  • 预览资料原文、启用或停用某个文件。
  • 填写需要跨会话保留的需求摘要。
  • 开启新上下文：画布和已选文件保留，旧对话还能看。

长会话怎么处理

重放正文以 12 万字符为预算。README 说明这是正文预算，不是模型的 token 用量。撞到上限要你手填摘要，再开新上下文。

图片在同一个运行时里只发第一次；闲置 15 分钟运行时会释放，之后重建运行时需要重新附图。重启后它用持久化的消息和需求摘要来重建上下文——这不是模型 SDK 原生的工具日志恢复，是它自己的做法。

为什么修改要你点一下「应用」

先列变更，再生效

首次生成直接显示，后续修改会先列出这次要改什么，你点「应用修改」才落到画布上，可以放弃。这多一步是有理由的：AI 改图常常顺手把没关系的部分一起挪了，让人失去对版面的控制。

它怎么保护你的手工调整

  • 可以固定选中的组件，让 AI 改别处时它不动。
  • 可以限定只改某个选区。
  • AI 修改尽量保留你手动摆的位置和样式。
  • 支持停止请求、失败反馈与重试。

语义结构只认该认的东西

你手动新建的带文字形状和两端都绑定了的箭头会同步进语义结构，AI 后续能理解它们。自由线条、没绑定的箭头、纯装饰元素不算架构关系，不会被拿去当组件编辑。

代价：新增节点之后可能需要你手工排版。复杂的多列布局，它只展示相邻模块之间的少量主关系，完整细节留在结构数据里——图上不会全画出来。
图标和导出为什么能离线

图标

统一用 Lucide 0.468.0。引擎内置 32 个常用图标，按语义自动匹配；遇到不认识的名字回退到通用组件图标。图标以 SVG 形式随图一起嵌入，所以导出文件和离线打开都不请求 CDN。中文节点会保留图标并预留文字空间。

要更新图标跑 python3 sync_icons.py。这和推文说的「内置 32 个常用图标自动匹配」一致。

导出

SVG PNG 含图片的可编辑文件 离线可用

三种都是本地生成，不调外部服务。

可插拔边界：SDK、MCP、搜索
接入方式怎么用边界
Python SDKdiagram_sdk.render(ir)、diagram_sdk.read_document(path)无状态渲染
MCP 服务python3 mcp_server.py --root /授权目录协议 2024-11-05；不传 --root 时只给渲染工具，不读文件
Harness 插件harness/plugin.mjs注册 read_diagram、create_diagram、update_diagram、list_documents、read_document
架构 Agent—不开放 shell

--root 传哪个目录，它就只能读哪个目录。不传就等于关掉读文件能力。这是个有意的设计，不是 bug。

MCP 侧不修改你正在编辑的那张图。

联网搜索是可选模块

填自己的 Tavily API Key 并勾选「联网搜索」后，支持搜索、正文阅读、会话快照和组件来源引用。密钥只存进程内存，不进备份，运行中可启停换密钥，不用重启 Harness 会话。

想单独打包这个模块：python3 manage.py bundle-search --output /tmp/architecture-tavily-module.zip。

不填 Key，搜索关掉，其余功能照用。

隐私边界（README「隐私」章节）

分两句读：

  • 上传的内容存在你本机，不上传到作者的服务器。
  • 但：启用的图片、被工具读到的文件片段、对话内容和架构结构，会发给你自己配置的那个模型服务。你选哪个模型端点，就等于你把内容交给了谁。

还有一个容易漏的点：移除文件只是阻止后续读取，它对已有对话的影响不会自动消失。要清干净，得开一个新上下文。

推文没说的五件事：当前是 Alpha、仅本机单用户、时序图和 ER 图不支持、组件上限 22、不给 --root 的 MCP 不读文件。另外还有资料与正文上限，以及扫描 PDF 文字识别需可选装 Tesseract 且中文要 chi_sim，没有 OCR 时页面会提示而不会假装已读。
建议的试做规模与验收方法（未实测）

想试的话，别一上来喂一整个代码库。README「限制」写着正文最多 30 万字符、每会话 20 份资料，但一次塞满只会让上限和噪音同时出现。

  1. 拿一份真实需求文档跑首稿——一份就够，最好是分层清楚的那种。
  2. 对照原文档核两件事：层级划分对不对，组件命名是不是你自己的叫法。这两项错了，后面改得越多越乱。
  3. 锁定关键组件再改一轮：用「固定选中组件 + 只改选区」把重点区域调准，同时确认它有没有动到你手动摆过的位置。
  4. 检查导出：把导出的 SVG 断网打开，看图标有没有变方块（SVG 没嵌入）、连线有没有丢。
  5. 有扫描页就单独验 OCR：装 Tesseract 和 chi_sim，对同一页分别看「装了」和「没装」时的提示差别，确认它没有替你编内容。

这几步是我按 README 功能编排的验收路径，未实测。如果你跑下来哪一步和文档说的不一样，以你看到的为准。
