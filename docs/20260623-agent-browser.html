01
WHY IT MATTERS

先看结果，再看命令

在 UI 任务里，Agent 最缺的不是“会不会发请求”，而是“能不能确认自己真的做对了”。

可验证

页面可见状态、录屏、截图、网络流、Profiler 都能直接纳入验证，而不必依赖模型自说自话。

可复现

refs、sessions、profiles 与 native mode 让多轮 agent loop 具备复现能力。

可嵌入

任何 shell agent 都可接；不仅仅是某一家的模型或 IDE。

02
FEATURE MATRIX

功能矩阵：浏览、调试、录屏、性能一条龙

如果你在做前端回归、支付流程、表单填写、登录检查、或需要把 UI bug 再现给 agent，这类能力非常关键。

Observe

快照 / 截图 / 录屏

从人类可读的 snapshot 到可归档视频，证据链完整。

Act

点击 / 输入 / 导航

按 ref 交互，避免脆弱 selector。

Inspect

Network / Debugging

直接看请求响应和调试输出，快速定位失败点。

Measure

Profiler / Web Vitals

不仅看“能不能过”，也能看“过得快不快”。

03
TRADE-OFFS

为什么它比“裸 Playwright”更像 Agent 工具

重点不是浏览器本身，而是为 agent 设计的输出格式、状态持久化和调试视角。

1

更少 token

紧凑文本输出直接降低上下文消耗，适合 loop 里反复读写。

2

更稳 ref

snapshot refs 比纯 selector 更适合 LLM 选择目标。

3

更强证据

录屏、网络、Profiler、Vite / React Web Vitals 让验收不止靠截图。

一句话：它把“浏览器自动化”变成了“Agent 可验证、可复现、可调试的 UI 闭环基础设施”。
