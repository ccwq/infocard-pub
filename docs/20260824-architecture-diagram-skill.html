Architecture Diagram Skill

把系统架构、RAG 流程、数据管道或微服务调用，生成可点击、可播放、可离线打开的单文件 HTML。让读者沿着数据包和请求路径观看系统如何工作，而不是只读静态框和箭头。

这条推文分享了什么

Indie Fox 分享了一个“会动”的架构图 Skill。它可以根据项目说明生成可交互 HTML：节点可点击，右侧面板展示当前步骤详情，动画数据包沿连线播放。

推文称它比静态架构图更适合阅读新项目：先看核心节点和调用流程，再展开每个节点的说明。

它解决的痛点

  • 静态架构图无法演示请求和数据如何流动。
  • 系统说明、RAG、认证和微服务流程不容易一次讲清。
  • 设计评审或 onboarding 需要可点击、可逐步播放的解释材料。
  • 单文件 HTML 无构建步骤，便于邮件、托管或本地打开。

交互能力

01

Named Flows

用场景标签切换 RAG Query、Login、Ingest 等流程。

02

动画数据包

数据包沿服务之间的曲线连线移动，按步骤点亮路径。

03

节点与侧栏

节点可拖动；侧栏显示 payload、描述、延迟、鉴权和端口。

04

模式切换

支持 offline/online、dev/prod、v1/v2 等模式切换。

05

演示控制

播放、暂停、单步、进度条、键盘快捷键、全屏与主题切换。

支持场景与边界

  • 系统架构：服务、数据库、队列、外部 API。
  • 数据管道 / ETL：从摄取、转换到存储的数据路径。
  • Agent / RAG：LLM 链路、工具调用、检索增强和多 Agent 编排。
  • 微服务、CI/CD、认证安全、onboarding 和设计评审。
  • GitHub：konraddzbik/architecture-diagram-skill · MIT
  • 来源推文 · @indie_maker_fox

边界：它是教学与设计沟通工具，不是实时监控面板；单张图建议控制在约 12 个节点以内，默认产出 HTML 与 Markdown 两个文件。
