WHAT IS PENPOT?

Penpot 是什么：开源设计平台

它服务于需要规模化协作的数字产品团队，重点解决设计与代码之间的交付断层，而不是承诺“完全替代所有工具”。

定位Open Source

团队设计平台

为产品、设计与开发提供共同的协作空间，支持从探索到交付。

问题Handoff

减少交付断层

让设计规则、可检查代码和工程语境更早进入同一条链路。

形态Web

浏览器优先

官方文档同时记录浏览器使用与自托管路径，团队可按治理要求部署。

许可MPL-2.0

开放许可

官方仓库采用 MPL-2.0；使用前仍应结合组织的合规与分发规则评估。

开放标准：设计文件更接近 Web

Penpot 强调 SVG、CSS、HTML 与 JSON；这使设计交付不必被封闭格式单独解释。

01 / SVG

矢量图形

可读、可编辑、适合进入 Web 语境。

02 / CSS

样式与布局

把视觉规则连接到真实前端语义。

可与 Grid、Flex Layout 等 Web 布局概念衔接。

03 / HTML

页面结构

让交付讨论不只停留在截图。

Inspect 输出帮助开发者理解结构与实现起点。

04 / JSON

数据交换

更适合自动化、工具链与扩展。

开放的数据语境为 API、插件和协作流程留下空间。

Design SystemReusable

三件套：Tokens / Components / Variants

  • Design Tokens：集中管理颜色、间距等规则
  • Components：沉淀可复用的界面部件
  • Variants：表达状态、尺寸与组合变化

它们共同降低重复劳动，让团队讨论从“这张图”上升到“这套系统”。

04
COLLABORATE + EXTEND

实时协作与扩展：从团队到工具链

协作不止是多人同时打开页面，也包括让外部系统能够观察、调用和扩展设计工作。

1

实时协作

产品、设计、开发围绕同一份材料同步讨论，减少版本和语境错位。

2

插件生态

插件为团队工作流提供扩展入口，适合把重复动作接入组织流程。

3

Open API / Webhooks

开放 API 与 Webhooks 让自动化、通知和外部系统连接成为可能。

4

MCP server

README 记录 MCP server；可作为探索 AI 辅助设计与工具调用的接口。

5

Web 布局能力

CSS Grid 与 Flex Layout 支持让设计语境更贴近真实 Web 实现。

6

协作边界

开放接口不等于自动完成治理；权限、审计和组织流程仍需自行设计。

✓ 更适合

  • 希望设计与开发共享 Web 标准语境的产品团队
  • 需要 Tokens、Components、Variants 的设计系统团队
  • 希望保留 SaaS 与自托管选择的组织
  • 愿意通过 API、Webhooks、插件或 MCP 连接工具链的团队

✗ 不适合的期待

  • 期待零迁移成本、零治理成本的“一键替代”
  • 只需要静态截图、不关心可复用系统或代码交付
  • 无法投入权限、备份、升级与自托管运维资源
  • 把原帖的宣传性表述当作未经核验的项目事实
