01
PROBLEM · 痛点

云端 Agent 的登录墙：第一件正经活就撞上

问题根源

Grok Bot 和 Muse 都在自己的云端浏览器上跑，Chrome 是全新的，什么都没登录。

  • 你把账号交给它，第一件正经活就撞登录墙
  • 绕过登录墙需要凭据，但云端浏览器什么都没有
  • Provider 的 MCP / 插件只能覆盖 Google/Meta/X，其他站点无法覆盖
  • 每次新建会话，登录状态重置

传统方案的问题

  • 直接给密码：密码在网络上传输，违反安全实践
  • 截图/OCR：无法真正登录，无法操作后台
  • Provider 官方 MCP：仅覆盖 Google/Meta/X，Canva/CRM/工单/Stripe 均不支持
  • 手动操作：每次会话都要重做，无法自动化
✓ 解法思路

Chrome 浏览器已持有所有已登录站点的 session cookie。session cookie 证明身份但不暴露密码。把这些 cookie 同步到云端浏览器，Agent 就能以登录状态工作——不需要密码，不需要账号密码管理器。

SYNC MODES · 同步模式

定时（15 分钟）/ 即时（约 1 分钟）/ 手动，三种触发方式

定时同步

默认每 15 分钟运行一次。alarm API 触发，扩展后台脚本执行。

可调整间隔（修改扩展设置）。

即时同步

检测到登录 cookie 变更后约 1 分钟内导出。默认开启，防止新建登录要等 15 分钟。

两次即时同步最短间隔 2 分钟。

手动触发

点击扩展图标，或运行脚本：

  • Request-Sync.ps1（Windows）
  • request-sync.sh（macOS/Linux）

同步文件夹内容

文件内容位置

04
FILTERING · 站点过滤

三种规则 + 近期站点筛选 + 三大平台默认隔离

三种过滤规则

  • 所有已登录站点：导出 Chrome 中所有有 session cookie 的站点
  • 仅选中站点：只导出你手动勾选的站点
  • 排除选中站点：导出除勾选站点外的所有站点

切换规则实时生效，下次导出按新规则执行。

近期站点筛选

  • Chrome 不记录 cookie 创建时间，所以用两个来源判定：
  • ① 扩展读取的浏览历史（首次选择窗口时申请一次权限，仅本地读取）
  • ② 扩展安装后观察到的 cookie 变更记录
  • 可选范围：Today / 7d / 30d / 90d / any time

默认隔离的平台（不可关闭）

平台为何隔离官方支持方式
Google云浏览器出现在 Gmail/Drive/Ads/YouTube 触发风控，代价：安全警告/账号锁定/广告账户被停MCP Server / 官方 API
MetaFacebook/Instagram/WhatsApp/Meta Ads Manager 均检测云浏览器，代价同上MCP Server / 官方 API
X（Twitter）Cloud browser on x.com 是 X 风控的明确目标，代价同上MCP Server / 官方 API
⚠ 安全红线（不可绕过的设计）

扩展设置页面有一个默认开启的独立开关，会强制隔离 Google、Meta 和 X——无论其他规则如何设置。这不是可选建议，是内置防线。

Then set a recurring sync every 15 minutes from the cookie export folder to your computer, inject those cookies into your Chrome via CDP after each pull (see agent/inject-cookies.py), and support on-demand sync with Request-Sync.ps1 / request-sync.sh. Do not use these cookies to sign in to any Google, Meta or X account, as that can trigger a security warning on my account; use your own MCP or plugin for those.

06
INJECT SCRIPT · Cookie 注入

agent/inject-cookies.py：DevTools Protocol + Storage.setCookies

Bot 每次拉取同步文件夹后，必须运行此脚本将 Cookie 注入自己的 Chrome（需开启 --remote-debugging-port）。Grok Bot 和 Muse 默认已开启此参数。

inject-cookies.py 关键设计

  • 使用 Chrome DevTools Network.setCookies API（CDP）
  • 从不打印 Cookie 值（安全设计：日志不泄漏凭证）
  • 需要 --remote-debugging-port 启动的 Chrome
  • 读取 cookies.json 中的完整 Cookie 对象（name/value/domain/path/expiry 等）
  • 注入后需手动 reload 站点（或 Bot 自动 reload）

同步文件夹的 Bot 侧配置

  • Bot 负责将 %LOCALAPPDATA%\AgentCookieSync 或 ~/.agentcookiesync 同步到自己的机器
  • 可使用 rsync / scp / 云盘 / MCP filesystem 工具
  • 同步完成后运行 inject-cookies.py
  • on-demand：运行 Request-Sync.ps1 或 request-sync.sh 触发即时导出
✓ 完整同步流程（Bot 侧伪代码）
# 1. 拉取同步文件夹（每 15 分钟 / on-demand）
rsync -av user@local:/path/to/.agentcookiesync/ /bot/.agentcookiesync/

# 2. 检查是否需要更新
diff old/cookies.json new/cookies.json || continue

# 3. 注入 Cookie
python3 agent/inject-cookies.py

# 4. 重新加载目标站点
navigate("https://target-site.com/dashboard")

SECURITY · 安全说明

密码不落地 / 扩展零网络 / 撤销三步 / 工作 profile

✓ 安全设计

  • 密码不落地：只同步 session cookie，密码始终在密码管理器中
  • 扩展零网络：Chrome 扩展和 Native Host 均不发起任何网络请求
  • Meta.json 记录规则：Bot 可看到本次同步应用的过滤规则
  • CDP 不打印值：inject-cookies.py 日志不含 Cookie 明文
  • MIT 协议：代码可审计，无隐藏行为

⚠ 安全红线

  • cookies.json = 钥匙：持有此文件即可登录你的所有同步站点，像密码库一样对待
  • 同账号 Bot 共享所有登录：一个 Bot 拿到登录，该账号下所有 Bot 都能用
  • 用工作 profile：不要用私人 Chrome profile，单独建一个专门给 Agent 用的
  • Google/Meta/X 走官方 API：这些平台的风控系统专门检测云浏览器，后果严重
撤销三步

① 移除 Chrome 扩展 → ② 删除同步文件夹（%LOCALAPPDATA%\AgentCookieSync 或 ~/.agentcookiesync）→ ③ 在被同步站点上改密码。任何一项均可单独执行，组合执行即完全撤销。

FAQ · 常见问题

8 个关键问答，覆盖安全 / 兼容 / 同步细节

问题回答
Cookie 是否发送到任何服务器？不。扩展和 Native Host 零网络请求。同步到 Bot 是 Bot 自己拉取的行为，与本项目无关。
除了 Grok Bot / Muse 还能用吗？任何在非本地机器上运行、能同步文件夹、能通过 --remote-debugging-port 注入 Cookie 的 Agent 均可。
本机 Agent 需要这个工具吗？不需要。本机 Agent 已经可以使用你的浏览器，不需要同步 Cookie。
同步了但 Bot 仍在登录页？同步文件夹 ≠ 登录。Bot 必须运行 inject-cookies.py，然后 reload 站点。详见 FAQ。
可以让 Bot 登录 Gmail / Facebook / X 吗？绝对不要。这三家风控会检测云浏览器，后果是安全警告、账号锁定或广告账户被停。用各自的 MCP 或官方 API。
可以只同步部分站点吗？可以。设置页面选「仅选中站点」，勾选需要的网站。下次导出只包含这些站点。
新建登录后 Bot 多久能用到？即时同步开启时，约 1 分钟内。Bot 在下一次拉取后注入即可。
可以给客户用吗？可以，MIT 协议。只是不要用 Agent Ops Club 的名义分发。
