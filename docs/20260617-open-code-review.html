01
Core Diagnosis

通用 Agent 做 review 的三类漂移，它用工程约束先堵住

README 直接点名了通用 agents 的痛点：大改动时漏看文件、评论位置漂移、质量随 prompt 细节波动。Open Code Review 的解法是 hybrid architecture：硬约束归工程逻辑，动态判断交给 agent。

Coverage

不让模型决定“看哪些文件”

确定性文件选择与过滤先划定审查范围，避免大 changeset 中 agent 偷懒只看一部分。

Position

定位不靠自然语言猜

外置 comment-positioning 模块系统性提升行级评论的位置准确性，减少文件/行号漂移。

Quality

规则匹配模板化

用 template-engine-based rule matching 给不同文件分配规则，减少纯自然语言规则带来的不稳定。

02
Hybrid Architecture

确定性流水线负责“不能错”，Agent 负责“需要理解”

这是一张监控台式架构图：左侧是稳定管线，右侧是可检索上下文的 agent。两者分工明确，避免把所有控制权交给 LLM。

03
Review Modes

CLI、本地 Agent、CI/CD 都能进同一条审查链

OCR 可以作为独立 CLI 使用，也能作为 Claude Code / Codex plugin 或 skill 进入 agent workflow；CI 中输出 JSON，适合 PR/MR 自动化。

ocr review
Workspace mode：审查 staged、unstaged、untracked changes。
--from main --to branch
Branch range：对比两个 ref，适合功能分支 review。
--commit abc123
Single commit：按单个提交审查，并可从 commit message 自动填充背景。
--format json --audience agent
Agent / CI 模式：输出机器可解析结果，减少进度噪声，适合自动修复链路。
04
Built-in Rules

规则层不是装饰，而是把模型注意力压到风险点

README 强调内置 fine-tuned ruleset，覆盖 NPE、thread-safety、XSS、SQL injection 等。规则采用四层优先级：CLI 指定、项目配置、全局配置、系统默认。

Priority Chain

规则来源有明确优先级

  • 1. `--rule` 用户显式覆盖
  • 2. `/.opencodereview/rule.json` 项目规则
  • 3. `~/.opencodereview/rule.json` 全局规则
  • 4. embedded system_rules.json 默认规则
Filter Safety

include / exclude 控制审查范围

二进制、用户排除、非支持扩展名、include bypass、默认测试排除等都有确定性流程；`exclude` 永远优先于 `include`。

05
Adoption

它更像 code review harness，不只是 CLI

仓库同时提供 npm 安装、GitHub release binary、源码构建、Claude Code plugin、Codex plugin、skills registry 与 CI 示例。适合把 AI review 变成团队里的可重复门禁。

CLI

独立运行

`ocr config provider` / `ocr config model` 后即可对工作区、分支或提交进行 review。

Agent

进入编码代理

支持 `npx skills add alibaba/open-code-review --skill open-code-review`，也提供 Claude Code 与 Codex plugin。

CI/CD

自动化 PR/MR 审查

`ocr review --from origin/main --to <commit_sha> --format json` 可接入 GitHub Actions / GitLab CI。

安全注意：viewer 会通过 HTTP 暴露 session JSONL，包括 LLM request messages 与 responses；README 说明它有 Host-header allowlist，非 loopback host 需要显式配置 `OCR_VIEWER_ALLOWED_HOSTS`。
