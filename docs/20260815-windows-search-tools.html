1
DocFetcher — 首选，最省事
适用场景：需要零配置、只索引指定项目目录、支持中文和 Office 的日常文档检索。
许可证
EPL（Eclipse Public License）—— 免费商用，无限制
中文支持
完全支持。示例：目录 新能源汽车动力电池管理系统 → 搜索 动力电池 命中
项目目录索引
右键「搜索范围」→「选择目录」→ 弹出「索引配置」窗口 → 选「索引目录 = 你选择的项目目录」→ 完成后左下角显示 ☑ 项目名
命令行启动
$Exe = Get-ChildItem ".\DocFetcher" -Recurse -File -Filter "DocFetcher.exe" | Select-Object -First 1
# 正常输出：FOUND: C:\...\DocFetcher.exe
已知缺点
基于 JVM，大型索引时内存占用显著（已有案例：130GB 提交内存导致 JVM 被 OS 终止）。可调低 JVM 堆内存参数缓解。
2
Recoll — 首选，偏工程化
适用场景：需要 CLI 自动化、项目索引独立随项目走、或者追求更高搜索性能的进阶用户。
许可证
GPL。Windows 二进制需通过第三方渠道获取（略绕但可行）。
独立项目索引
每个项目独立配置目录，索引随项目走，不污染全局：
# 为项目 A 创建独立索引
recollindex -c "D:\Projects\ProjectA\.recoll"

# 查询项目 A
recoll -t -c "D:\Projects\ProjectA\.recoll" -q "新能源汽车"
recollq -c "D:\Projects\ProjectA\.recoll" "新能源汽车"
CLI 自动化
# PowerShell 封装示例：search-docs.ps1
search_project_documents("报价")
为什么没排第一
Windows 二进制获取路径对普通用户不够直观；GUI 体验略逊于 DocFetcher。
3
索引必须跟着项目一起走
① Recoll：最规范
ProjectA\.recoll\ → 纳入版本控制或 .gitignore 排除均可。完全独立，随项目走。
② DocFetcher Portable：最方便
下载 Portable 版到项目根目录，无需安装。索引文件在 ProjectA\ 下。
③ Tika + 自建索引：自由度最高
ProjectA\index\ 下自行管理索引，支持 docx / xlsx / pptx / pdf 等全部格式。需要一定开发能力，Apache 2.0 许可证。
4
其他方案为什么不主推
Windows Search
依赖 IFilter 解析 Office，IFilter 缺失或损坏则无法搜索。索引是全局的，无法隔离到单个项目。系统自带是优点，但独立性弱。
结论：备选方案。
ripgrep-all
CLI 强大，但 Office 支持不完整（依赖外部转换工具），且不是真正的倒排索引，性能不如专业方案。
结论：本需求不推荐。
★
最终建议
⭐ 日常使用 → DocFetcher：零配置、GUI 友好、Office 支持完整、中文无问题、EPL 商用免费。JVM 内存问题可通过调参解决。

⚙ 自动化 / 工程化 → Recoll：独立索引随项目走、CLI 强大、查询速度快。适合有脚本能力的用户或 AI Agent 集成。
