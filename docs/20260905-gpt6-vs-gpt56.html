01
DECISION

先别问谁“更聪明”，先问任务值不值溢价

这是一个官方参数与供应方评测的决策卡，不是本机 benchmark。GPT-6 Astra 的主要卖点是更强的端到端复杂任务表现；GPT-5.6 家族提供 Sol、Terra、Luna 三个能力—成本层级。

Astra：复杂任务优先

适合深度研究、计算机使用、复杂软件工程、科学分析和需要连续决策的 Agent。官方定位是“为最困难的端到端工作打造”。

Sol：旗舰成本基线

适合专业编码、知识工作、工具调用和长上下文分析。官方 API 价格低于 Astra，且上下文与最大输出上限相同。

Terra / Luna：分层降本

Terra 平衡智能与成本；Luna 面向成本敏感、高流量工作负载。不要把“便宜”理解成不能推理或不能调用工具。

建议：把 Astra 留给失败代价高、人工复核贵、需要多轮工具闭环的任务；把 Sol/Terra/Luna 用作日常生产与批量工作，再用代表任务测算成功率—成本曲线。

超过 272K 输入

官方模型页说明：输入超过 272K tokens 时，整次请求的 input 与 cache rate 按 2 倍，output 按 1.5 倍计价。不能只把超出的那一段乘倍数。

缓存与处理模式

Cache writes 按未缓存输入价的 1.25 倍；Batch 与 Flex 为标准价格的 50%；Fast mode 为适用价格的 2 倍。实际预算必须把这些路径拆开。

04
CAPABILITY LAYERS

上下文和输出没有变，变化在“怎么使用这 100 万 token”

更大的上下文不是自动更好的答案；关键是检索、压缩、工具调用、推理投入和验证闭环。

Context

两代代表模型都达到 1.05M context。可装下大型代码库、长合同或知识库，但仍需处理噪声、相关性和成本。

Output

两者最大输出均为 128K。它限制单次生成长度，不等于模型会稳定产出十万字可用内容。

Reasoning

Astra 从 low 起；Sol/Luna 支持 none 到 max。推理档位会影响延迟、token 消耗与任务成功率。

Tools

工具能力不能只看模型名。Responses API 的工具、宿主实现、权限、审批和 Harness 同样决定最终效果。

正确理解：GPT-6 Astra 的潜在优势不是“塞更多内容”，而是更可能在长上下文中找出隐含依赖、规划多步骤动作、使用电脑或工具完成闭环。这个判断需要用你的真实任务验证。
05
AGENT WORKFLOW

从“顾问”到“交付负责人”是工作流差异，不是 API 魔法

两代模型都可以接工具；差异应该落在任务分解、并行、记忆、权限、验证和失败恢复上。

GPT-5.6 的有效用法

  • 用 Responses API 连接工具和状态。
  • 用 Programmatic Tool Calling 处理大批中间结果。
  • 用 multi-agent beta 并行子任务，再由根 Agent 汇总。
  • 把 Sol 用在高价值主任务，把 Terra/Luna 用在分类、提取、批量检查。

GPT-6 Astra 的有效用法

  • 把复杂目标拆成研究、执行、检查、修复四段。
  • 让模型在明确权限边界内使用 computer use、shell、patch 和搜索。
  • 把关键决策保留人工批准，尤其是外部写入、支付、删除和安全动作。
  • 用轨迹、产物和验收结果评估，而不是只看回答风格。
Agent 层最低设计要求验收问题
规划目标、假设、依赖与停止条件显式化。模型是否知道什么时候该继续、询问或停止？
工具工具 schema、权限、超时、重试和输出上限统一管理。失败能否重试而不重复破坏性动作？
状态任务状态、文件变更、证据和人工决策可追踪。中断后能否从状态继续，而不是重新猜？
验证测试、截图、diff、引用和公网状态成为完成条件。系统是否把“生成了”误报成“完成了”？
06
EVIDENCE

官方 benchmark 有价值，但不能替代你的评测

供应方公布的分数用于观察能力方向；它们依赖数据集、工具、推理档位、时间限制和成本模拟。

GPT-6 Astra 官方报告的方向

官方公告报告了计算机使用、专业任务、代码、科学与长上下文评测的提升，也报告了更强的安全边界和授权范围遵循。

GPT-5.6 官方报告的方向

GPT-5.6 Sol 强调智能效率、代码 Agent、长周期专业工作和多 Agent；Terra/Luna 强调价格—性能曲线。

不能直接推出的结论

不能从单个 benchmark 推出你的仓库一定更快、一定少用 token、一定不需要人工，或一定能安全完成任意 Agent 任务。

评测最小闭环

准备 20—50 个与你真实工作相似的任务，固定 prompt、工具权限、模型档位和停止条件；记录成功率、人工修复次数、输入/输出 token、墙钟时间、工具失败、越权尝试和最终可交付性。再比较 Astra、Sol、Terra、Luna 的总成本，而不是只比较单次回答。

07
ROUTING

按你的工作流选：高复杂度上探，常规任务分层降本

以下是基于官方能力定位和任务形状的建议，不是针对你本机的实测结论。

Deep Investigation

优先试 Astra，Sol 做成本对照。重点观察来源整合、反证、长链推理、未知项表达和最终决策质量。

Skill / SOP 设计

Astra 适合复杂流程建模；Sol 适合日常迭代。必须把工具边界、验收和异常恢复纳入评测。

大型代码 Agent

Astra 与 Sol 都应进入候选。比较真实仓库的修改正确率、测试通过率、返工轮数和总 token。

批量提取 / 分类

优先 Luna，必要时升 Terra。这类任务的价值来自吞吐和单位成本，不一定需要旗舰模型。

普通聊天 / 翻译

GPT-5.6 低成本层通常足够。把 Astra 留给确实能减少人工复核的工作。

高风险外部动作

模型升级不等于授权升级。无论使用哪一代，都要保留审批、沙箱、日志和回滚。
