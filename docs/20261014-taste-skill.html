先搞清它管什么、不管什么

01 · scope

最常见的误解是把它当 UI 框架。它不是：没有组件、没有样式导出、装完不会给你一个新按钮。它是喂给 agent 的设计判断规则，让模型少产出「一眼 AI」的东西。

默认 skill 的适用范围in scope

  • 落地页、营销站
  • 作品集
  • 产品页

明确不适合out of scope

  • dashboard
  • 应用界面（产品 UI）——这类改用 minimalist-ui 或 high-end-visual-design 的 soft 路线
为什么这层边界重要：拿营销页规则去做数据密集界面，得到的会是「好看的表格页」，不是能用的工具。作者自己把这条线画在 README 里。

挑哪个 skill：一张决策表

03 · which skill

仓库里 11 个 skill，只有 design-taste-frontend 是 v2 的默认项，也是上面所有命令装的那一个。其余按场景选。

skill用途什么时候选它
design-taste-frontendv2 默认；落地页 / 营销站 / 作品集 / 产品页不确定时选它。绝大多数展示型页面从这儿开始。
redesign-existing-projects先审计现有 UI 再动手手上是已有项目，要改版不想推倒重来。
image-to-code生成参考 → 分析 → 实现已有目标视觉，需要把它拆成代码。
gpt-taste给 GPT / Codex 更严的变体，布局变化更大觉得默认约束对你还是太松。
high-end-visual-designsoft 对比 / 留白 / 弹簧动效要产品 UI 或高端感，不要硬对比。
minimalist-ui编辑式产品 UIdashboard、应用界面的首选替代。
industrial-brutalist-ui瑞士字体 + 硬对比要工业 / 野兽派气质。
stitch-design-tasteGoogle Stitch 规则，可导出 DESIGN.md你要把设计约束沉淀成 DESIGN.md 给团队。
full-output-enforcement禁止半成品与占位注释代理爱交半截代码时叠上去。
imagegen-frontend-web / -mobile / brandkit只出设计图，不出代码先要视觉稿，代码后面再说。
组合方式：后三类是「叠上去」而不是「换掉」——比如 minimalist-ui 管产品 UI，full-output-enforcement 管交付完整性。

v2 的六步，和 v1 的差别

04 · workflow

v2 的核心是把选择提前：方向、素材、验收都在写代码之前定。六步里只有第四步在写页面，其余五步都在缩小搜索空间。

step 01读 brief，列客户独有信息

先把客户特有的东西列出来，后面所有判断都拿它当基准。

step 02抽方向

脚本从 20 个调研方向里发 3 张牌，agent 选 1 张。

step 03找 idea

用一句话把客户素材和选中的方向绑在一起。

step 04用真实图片构建

走开放档案，页面上标注 credits。这步才产出页面。

step 05三宽度真浏览器自检

在真实浏览器里检查三种宽度，对 slop 判定失败。

step 06看自己的截图修 top3

对着截图挑出最该修的三个问题，最多三轮。

v2 相对 v1 少掉的东西removed

v1 的三个 dial 在 v2 里没有了：DESIGN_VARIANCE、MOTION_INTENSITY、VISUAL_DENSITY。也就是说你不再手动调这三根滑杆，方向由步骤 02 的抽牌决定。

素材规则assets

图片来自 Wikimedia Commons、Openverse、Met，只提供 public domain、CC0、CC BY、CC BY-SA 四类，页面必须标注 credits。你可以换成自己的素材——这一步不受来源限制。

step 02 的实际形态（作者口径）： 20 个调研方向 → 脚本发 3 张牌 → agent 选 1 选定方向 = 后面所有布局决定的根，不再回头改 step 05 的三种宽度：作者只说「三种宽度」， 未公开具体数值（README 未列，本轮未实测）

一次小规模试做：先别整套上

05 · pilot

下面这套是作者的建议路径，不是实测结论 作者建议 · 未实测。理由很直接：默认 skill 的单次口径是 30–45 分钟和几十万 tokens，直接丢给真项目做一次全量试错，代价太大。

小规模试做四步pilot

  1. 只做一个单页 landing，别开多页。
  2. 只选一个方向，看它抽出来的牌是否贴合你手上这个客户。
  3. 看三种宽度的截图——这一步是全部价值所在，别跳过。
  4. 截图过了，再决定要不要整套用；没过，先判断是方向抽错还是素材不对。

判断点很清楚：方向是否配客户。配得上，后面的问题多是执行细节；配不上，后面每一步都在错的基础上加细节。

替换成自己的素材swap in

开放档案只是兜底。你的品牌图、截图、产品照片直接替上去，比从 Commons 找图更省事，也不用担心授权。

成本与预期

06 · cost

单次构建official

30–45 分钟，几十万 tokens。这是官方口径，本轮未复现。一次不是 30 秒出图，是一轮带自检的完整流程。

重跑的成本iterate

step 06 最多三轮。三轮用满仍不理想，该换的是方向或素材，不是继续加轮数。

它便宜在哪free

没有 API key、没有付费依赖、没有 token/币模型。成本就是你自己的模型额度 + 时间。

预期管理：如果你要的是「一次调用出一个漂亮首页」，它不解决这个。它解决的是「第一次就交出去的东西不至于像模板」。

五种翻车姿势

07 · failure modes
方向抽到不合客户step 02

脚本只发牌，牌配不配客户它不管。这是六步里唯一会污染后面全部产出的一步。

素材授权踩线step 04

只用 README 允许的四类许可，并且要在页面上标 credits。标漏了就是合规问题，不是审美问题。

图片下载失败step 04

找图是唯一需要联网的环节。源站挂图、限流、改 URL 都会断。断网时这一步直接卡住，没有兜底。

产出仍然像模板step 05

三宽度自检是拦截点，跳过它等于放弃整套流程里最贵的一环。截图必须自己看。

v1 / v2 混用全局

还在调 DESIGN_VARIANCE、MOTION_INTENSITY、VISUAL_DENSITY，说明在用 v1 口径。v2 没有这三个 dial。
