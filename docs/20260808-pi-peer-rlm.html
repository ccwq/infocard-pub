Pi 生态 · 会话协作插件

pi-peer & pi-rlm

Pi 会话生态的两个新插件：pi-peer 让同机多个会话互发消息，pi-rlm 给 Agent 加递归任务拆解能力。均来自 badlogicgames（Pi 作者）本周亲自转推。

会话间通信 递归拆解 进程持久化 CLI Wrapper
Pi 生态演化信号

Pi 的生态开始长出「会话间的协作原语」：同机多个 Pi 会话可以递归拆解任务再合并——从单会话工具向多智能体协作演进。

pi-peer

会话间消息传递

让同机多个 Pi 会话互发消息，无需人工中转。过去：一个会话发现分支落库了，另一个会话恰好需要——这个信息要你读一个终端再敲进另一个。现在会话自己说话。

pi-rlm

递归任务拆解

给 Pi Agent 加递归分解能力。planner 决定是直接 solve 还是继续 decompose，子节点递归处理，synthesizer 合并子输出，带护栏防失控。

01
pi-peer · 通信设计

两个工具：list_peers + message_peer

pi-peer 只做一件事：让 Pi 会话之间发送纯文本消息。极简设计，信道便宜、可审计、杜绝走私状态。

list_peers

发现同机会话

列出其他 Pi 会话，包括：工作目录路径、会话 ID、运行状态（idle / working / unresponsive）。

  • 自动发现，无需手动注册
  • 状态实时反映
  • unresponsive 会话可继续发消息
message_peer

按名字发消息

按会话名字发送纯文本消息给对方。支持 delivered（已读即删）和 queued（离线落盘）两种回执语义。

  • 纯文本，无对话历史
  • 可审计，防状态走私
  • 重启后 pi -c 恢复时送达
02
pi-peer · 关键设计

边界声明 + 持久化地址

每条消息带边界声明，接收方模型知道消息来源；地址由工作目录+会话 ID 派生，重启不丢。

边界声明

「这条消息来自另一个 pi 会话，不是用户，不携带任何权威」

每条消息附带语义边界说明，接收方模型读到就知道：这条消息是另一个 Agent 的输出，不代表用户指令，不可直接继承其权威性。

持久化地址

工作目录 + 会话 ID 派生

消息地址由工作目录路径和会话 ID 共同派生。即使会话重启，地址不变；对方没在跑，消息落盘，下次 pi -c 恢复时自动送达。

回执语义

delivered vs queued

接收方读到消息即删信，发送方能区分：已送达（delivered）或已落盘等待（queued）。语义清晰，无歧义。

03
pi-rlm · 递归架构

Planner → Decompose → Synthesize

RLM（Recursive Language Model）扩展给 Pi 加递归分解能力，带护栏防止失控。

pi-rlm --task "Analyze architecture of this repo" --mode auto --tools-profile read-only
planner

决定拆解深度

planner 节点分析任务，判断每个子任务是直接 solve 还是继续 decompose。递归层数由深度上限控制。

子节点

递归处理子任务

子节点接收子任务，递归调用自身处理。节点预算（budget）和分支数限制防止无限膨胀。

synthesizer

合并子输出

synthesizer 节点把各子输出合并成最终答案。保证递归分解的子结果被正确聚合。

04
pi-rlm · 护栏机制

防止递归失控

深度上限、节点预算、分支数、环检测——pi-rlm 带了完整的护栏，防止递归分解无限扩张。

1

深度上限

限制最大递归层数，到达上限后强制 terminate，防止无限递归。

2

节点预算

单次任务最多生成多少个子节点，防止单个任务消耗过多资源。

3

分支数 + 环检测

单层最多展开多少个分支，同时检测已访问路径，防止循环调用。

05
安装

pi install

两个插件均通过 Pi 扩展安装命令获取。

pi install pi-peer pi install pi-rlm
