01
核心定位

它不是"又一个 Agent 教程"，而是一套可持久的设计骨架

README 明确说"这个课程是给你骨架的，你的 Agent 会帮你填肌肉"——这不是修辞，而是设计哲学：框架无关、模式优先、AI 伙伴全程陪学。

是什么

22章骨架课程

覆盖从工具调用到自进化 Agent 的完整知识图谱，每章都有 TL;DR / Why it matters / 核心概念 / 真实系统笔记 / AI 配学提示。

  • 负载承重的主题与权衡
  • 架构模式，不绑定 SDK
  • 文件对（course + AGENTS.md）
怎么学

用 Agent 陪学

每章都有"与你的 Agent 配学"提示：问三个真实案例、模拟面试、问"该问但没问的问题"、把模式翻译成最小可用代码。

  • 不要求看完才动手
  • 第一条命令就是"开始"
  • 最快路径：Ch.22 设计画布
边界

不是步进教程

没有完整演示项目、不绑定 LangChain 或 Pydantic AI、不给精确 API 签名。需要这些时，让你的 Agent 去读文档或搜索。

  • 骨架优先，肌肉靠 Agent
  • 框架中立，模式通用
  • 参考系统可选，非必需
内置技能

agentic-system-reviewer

内置 Skill，可对任何 Agent 系统做基于课程的评审：PRD、设计文档、实现计划或 Agent 代码，先校准范围再出报告。

  • 严重级别 + 证据 + 章节引用
  • 具体修复建议
  • 非泛化"looks good"评价
02
章节结构

22章分5组递进：基础 → 记忆 → 协调 → 外部表面 → 生产规模

每章只依赖前面章节的知识；按项目类型走不同的学习路径，而不是从头读到尾。

Foundations 基础

1
Ch.01–04 · 理论

从"单次工具调用"到"Agent 循环"，再深入"工具作为合约"、"提示与缓存"的设计含义。Ch.02 讲清楚 Agent loop 是什么，Ch.03 讲工具注册的本质。

适用场景

场景A：刚接触 Agent 的开发者，先跑通 loop 再谈记忆。
场景B：想理解为什么工具 schema 设计会影响召回质量。
场景C：调试"Agent 总是忘记之前行为"的根因——Ch.04 的 prompt/缓存边界。

Memory 记忆与状态

2
Ch.05–08 · 理论

短时记忆 → 长时检索 → 撰写与策展 → 持久化。Ch.05 讲清楚压缩(compaction)和延续(continuation)的二元性；Ch.07 讲 curator lifecycle。

适用场景

场景A：做个人助手时"历史上下文爆炸"的根因分析。
场景B：设计"什么时候该压缩、什么时候该继续"的决策边界。
场景C：理解 Hermes Agent 的 memory 模式在 Ch.05–07 的对应位置。

Coordination 协调

3
Ch.09–11 · 理论

规划模式 → 多 Agent 委托 → harness 作为组合工具。Ch.11 的 harness 设计是课程核心：不是用代码把 Agent 串起来，而是用 harness 统一管理上下文和工具分发。

适用场景

场景A：需要多个专业 Agent 协同工作时的角色分配问题。
场景B：理解为什么"把所有 Agent 放同一个上下文"是错的。
场景C：用 harness 统一管理工具分发和多轮状态。

External Surface 外部表面

4
Ch.12–14 · 理论

人机协同 → 连接器与 MCP 协议 → 技能/MCP/子 Agent 作为最小执行单元。Ch.13 讲清楚 channels（输入）和 skills（能力）的区分；Ch.14 讲 MCP 如何作为标准接口层。

适用场景

场景A：设计"什么时候用 human-in-the-loop 暂停"的判断标准。
场景B：想理解 OpenClaw 的 channel adapter 架构如何对应 Ch.13。
场景C：MCP server 接入时的命名空间和权限设计。

Production Scale 生产与运营

5
Ch.15–19 · 理论

后端基础设施 → 可观测性 → 成本/延迟/模型策略 → 安全与对抗输入 → 运营与 forward-deployed。Ch.17 的模型策略是很多项目后期才踩的坑：什么时候用大模型，什么时候用小模型，什么时候用本地。

适用场景

场景A：Agent 上线后发现成本失控——Ch.17 的模型分层策略。
场景B：需要给 Agent 加可观测性时的 trace/log/metric 结构。
场景C：理解对抗输入的防御边界（Ch.18）和 Paperclip 的 durable state 模式。

Agency + Canvas 自主与设计

6
Ch.20–22 · 理论

主动 Agent → 自进化 Agent → Ch.22 设计画布。Ch.22 是整个课程的应用出口：把"我有个想法"翻译成最小可行规格（spec），用设计画布对齐需求与架构选择。

适用场景

场景A：从零开始设计自己的 Agent——Ch.22 设计画布是入口。
场景B：理解"主动 Agent"和"自进化 Agent"的边界在哪里。
场景C：Ch.20 的"proactive"如何对应 Hermes Agent 的 RL 个性化模式。

03
学习路径

5条学习路径，按你想做的项目类型选，不是从头读到尾

课程故意把路径设计成可跳读的——有清晰项目时，跳过不相关的章节，专注你需要的架构层。

路径 A

探索型 · Just Exploring

Ch.00 → Ch.01 → Ch.02，按顺序打基础。跳到 Ch.04 后可以随便逛。无需克隆参考系统。

路径 B

编码 Agent · Coding Agent

Ch.00, Ch.22, Ch.01–04, Ch.05, Ch.08, Ch.12, Ch.16–17, Ch.18。参考系统首选 OpenCode。

路径 C

个人助手 · Personal Assistant

Ch.00, Ch.22, Ch.01–02, Ch.05–07, Ch.13, Ch.16, Ch.19, Ch.20–21。参考系统：Hermes Agent + OpenClaw。

路径 D

多租户工具 · Multi-Tenant

Ch.00, Ch.22, Ch.11, Ch.13, Ch.15, Ch.12, Ch.18–19。参考系统首选 Paperclip。

路径 E

研究/知识 Agent

Ch.00, Ch.22, Ch.04–07, Ch.16, Ch.21。参考系统：Hermes Agent 记忆模式 + OpenCode 压缩。

04
参考系统

4个开源参考系统，按需克隆，不是启动必需品

课程设计为章节自带概念；当你想看"这在代码里实际怎么实现"时，才触发克隆。运行一次 ./setup.sh 可以拉全部4个。

OpenCode

Ref 1
参考章节

编码 Agent，terminal 优先，带类型化工具、会话管理和上下文压缩。强参考：Ch.02, Ch.03, Ch.04, Ch.08, Ch.11, Ch.17。

何时克隆

场景A：问"OpenCode 如何处理上下文压缩"时。
场景B：想看 typed tools 的实现样本。
场景C：做编码 Agent 项目时的实现参考。

Hermes Agent

Ref 2
参考章节

个人助手，含记忆、技能、cron、channels、背景策展和 RL 个性化。强参考：Ch.05–07, Ch.13, Ch.20–21。

何时克隆

场景A：做个人助手项目，想看 memory 实现的具体模式。
场景B：问"Hermes Agent 的 RL 个性化对应哪个章节"。
场景C：设计 skills 和 cron 调度时的参考实现。

OpenClaw

Ref 3
参考章节

自托管个人助手网关，多 channel 适配器。强参考：Ch.13, Ch.19, Ch.20。

何时克隆

场景A：需要 channel adapter 架构的实际代码。
场景B：设计多平台（微信/飞书/Telegram）接入时。
场景C：Ch.19 forward-deployed 运营模式的实现参考。

Paperclip

Ref 4
参考章节

工作流控制平面，多 Agent 编排、治理、持久化 Postgres 状态。强参考：Ch.08, Ch.12, Ch.15, Ch.19。

何时克隆

场景A：设计多租户 Agent 系统时需要 Postgres durable state 模式。
场景B：想看 Ch.08 curator/持久化在生产系统的实现。
场景C：做 Ch.12 human-in-the-loop 治理的实际代码参考。

05
仓库结构

每个目录都是为特定角色设计的，不要跨边界使用

course/ 只读，docs/ 需要学生显式要求才写，questions/ 自动追加每日日志，workspace/ 用于构建和运行。

只读

course/

22章骨架内容，只读不修改。课程本身是持久制品，携带随时间缓慢老化的架构模式，而非框架细节。

AI产出

docs/ & questions/

docs/ 存放学生显式要求的交付物；questions/ 是每日学习日志，自动追加，一对 Q&A 一个 entry，用 XML 标签包裹。

构建区

workspace/

代码、练习、项目实现。单次练习直接在根目录，项目多文件放 workspace/<project-name>/ 子目录。

按需

references/

4个参考系统的克隆位置。按需触发——不是启动必需品，需要时才 clone one-by-one。

06
适合谁

最值得看的判断：它解决的是"我没有架构框架"，而不是"我不会写代码"

这个课程的价值是让"有想法但不知道从哪里开始设计 Agent 系统"的人有一个结构化的起点。

值得

应该读

  • 有明确 Agent 项目想法，但不知道从哪里开始设计
  • 已经跑过一些 demo，想系统化理解架构模式
  • 在选型 LangChain / LlamaIndex / PydanticAI，不知道怎么比较
  • 需要给团队建立 Agent 设计共识
  • 想理解 OpenCode / Hermes Agent / OpenClaw 的架构逻辑
不值得

可以跳过

  • 想要一个手把手带做完整项目的教程
  • 只需要 API 签名和代码片段，不需要架构思维
  • 已经有很深的 Agent 系统经验，想要源码级别的细节
  • 只是临时用 Agent 做单次任务，不需要持久设计

一句话判断：它解决的是"我不知道这个 Agent 系统该怎么设计"，而不是"我不会写代码"。如果你是前者，这套课程值得投入；如果你是后者，先去看 SDK 文档和示例代码更高效。
