LAYER 2

LAYER 3

LAYER 4

Loop Engineering

单 Agent 长程循环、机械验证与回滚；但目标会漂移。

LAYER 5

Graph Engineering

Agent、工具和人作为节点，状态、边和策略显式化。

02
FAILURE MODES

Loop 为什么会失效

复杂任务的难点是控制与恢复，不是让循环更长。

01

目标失明

长程循环会逐渐偏离原目标；局部指标不能替代真实用户目标。

02

状态不可观测

状态塞进上下文，外部难以干预、调试、暂停或恢复。

03

上下文腐烂

历史积累带来成本与错误记忆；关键决策被后续噪音稀释。

04

权限失控

单一 Agent 持有全部工具权限，错误调用的影响面过大。

05

无介入点

没有 checkpoint / 审批节点，企业无法接受全自动黑盒。

03
TOPOLOGY

图的四要素与三种拓扑

节点、边、状态、策略定义结构；拓扑决定协作方式。

STRUCTURE

节点 + 边

节点可为 Agent、工具、LLM 调用或人工审阅；边是条件、顺序或并行路由契约。

BEHAVIOR

状态 + 策略

状态由 reducer 合并更新；策略可来自规则、LLM 判断、投票或 supervisor。

DIAMOND

菱形

一个输入扇出到多个并行 Agent，再汇聚综合，适合多视角验证。

SUPERVISOR

主管

中央节点动态决定下一个子 Agent，适合开放式任务分解。

PIPELINE

流水线

线性或分支 DAG，把上一步输出交给下一步，适合 ETL 和批处理。

04
WORKFLOW MAP

Anthropic 五种工作流模式

Graph 不是凭空发明，而是将常见模式抽象为节点、边和共享状态。

01

Prompt Chaining

固定序列调用，适合明确线性流程。

02

Routing

分类后进入专用子流程，适合多领域分流。

03

Parallelization

投票或任务拆块后并行聚合。

04

Orchestrator-Workers

Orchestrator 动态分解、分发 worker、汇总结果。

05

Evaluator-Optimizer

生成器与评估器循环迭代，直到满足标准。

05
TRADE-OFF

Loop 与 Graph 的取舍

Graph 不是默认答案；复杂度必须由真实瓶颈证明。
