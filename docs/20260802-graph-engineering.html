02
FIVE LAYERS

AI 工程五层演进路径

从单次 prompt 到可观测系统

Layer 1

提示词工程

单轮 LLM 调用的优化：system prompt、few-shot、formatting。单点能力但无状态、无工具。

Layer 2

工作流编排

确定性脚本串联多个 LLM 调用：固定 DAG、if/else 分支、序列化执行。可控但缺乏智能。

Layer 3

ReAct 推理

Thought → Action → Observation 三段循环。模型自主决定下一步行动，但仍是单智能体内循环。

Layer 4

Loop Engineering

Karpathy autoresearch 为代表：单智能体长程循环 + 机械验证 + git 回滚。可执行长任务，但目标失明。

Layer 5

Graph Engineering

多智能体 + 工具 + 人组成的有向图。节点是 Agent，边是契约，状态可观测、可恢复、可扩展。

关键拐点

确定性来源的转移

从「prompt 写得准」转到「验证器写得严」。Graph 本身不创造智能，而是把智能的输出绑定到现实锚点。

03
LOOP · 5 DEFECTS

Loop 的五大结构性缺陷

为什么单智能体循环撑不住复杂任务

1

目标失明

智能体在长程循环中逐渐偏离原始目标，迭代越深偏离越严重。机械验证指标 ≠ 真实用户目标。

2

状态不可观测

循环内部状态全部塞进上下文窗口，外部系统无法干预、调试、暂停。出了错只有「重启」一招。

3

上下文腐烂

长对话累积历史，token 成本失控；早期关键决策被新数据稀释；agent 自己引用错误的早期记忆。

4

工具调用失控

单一智能体持有全部工具权限，缺少隔离；一个错误调用可能清空数据库 / 发送错误邮件 / 删库。

5

无人类介入点

循环一旦启动就跑到底，没有 checkpoint / 暂停 / 审批节点。企业场景无法容忍这种「全自动黑盒」。

04
GRAPH · 4 ELEMENTS

Graph 四要素

节点 · 边 · 状态 · 策略

静态结构

节点 + 边

节点（Node）：Agent / 工具 / LLM 调用 / 人工审阅节点。每个节点有明确的输入输出契约。

边（Edge）：节点之间的契约路由。条件边（conditional）、顺序边、并行边决定图的控制流。

动态行为

状态 + 策略

状态（State）：图执行过程中的全局可观测状态，由 reducer 决定如何合并更新。

策略（Policy）：决定路由走向的决策函数，可以是 LLM 判断 / 规则 / 投票 / 主管 agent。

05
3 TOPOLOGIES

三种经典拓扑

菱形 · 主管 · 流水线

菱形

Diamond Pattern

一个输入扇出到多个并行 agent，结果汇聚到一个综合节点。适合「多视角验证」「ensemble 决策」。

例：3 个 agent 并行写代码，1 个 agent 选最好的。

主管

Supervisor Pattern

中央 supervisor 节点动态决定下一个执行的子 agent。subagent 协作是这张图的灵魂。

例：AutoGen、LangGraph supervisor、CrewAI 的核心范式。

流水线

Pipeline Pattern

线性 / 分支 DAG，每一步输出是下一步输入。适合数据 ETL、文档处理、批处理。

例：LangChain LCEL、Airflow + LLM、Prefect + Agent。

06
ANTHROPIC · 5 PATTERNS

Anthropic 官方五种工作流模式

来自 Anthropic 2024 Building Effective Agents 博文

Prompt Chaining
将任务拆成固定序列的 LLM 调用，前一步输出作为后一步输入。适合有清晰线性流程的任务。
Routing
由分类步骤决定把请求分发给哪个专用子流程。多领域分流、跨模型路由的标配。
Parallelization
同一任务并行多个独立 agent（投票 / ensemble），或把任务拆块并行处理再聚合。
Orchestrator-Workers
中央 orchestrator 动态分解任务，分发给 worker agent，收集结果聚合。主管拓扑的工程化版本。
Evaluator-Optimizer
一个 agent 生成输出，另一个 agent 评估反馈，反复迭代直到满足标准。Loop + 验证器。

注：Anthropic 官方博文中这 5 种模式与 Graph Engineering 的拓扑高度重合——Graph 不是凭空发明，是把这 5 种模式抽象成「任意节点 + 任意边 + 共享状态」的统一框架。

09
RISK · BOUNDARY

风险与边界

Graph 不是银弹

1

过度工程化

简单任务用 Graph 会让架构复杂度远超业务复杂度。先 Loop 后 Graph，根据实际瓶颈升级。

2

协调开销

多智能体通讯 / 状态同步 / 冲突解决本身有成本。3 个慢 agent 串联可能比 1 个慢 agent 更慢。

3

验证器依赖

Graph 的确定性寄托在 verifier 节点。verifier 写不好，整个图垮得比 Loop 还快——只是垮得更有结构感。
