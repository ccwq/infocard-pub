选型决策树

3 步找到适合你的模型

Q1.素材是"视频"还是"单张照片"？
└─ 只有单张照片→ SadTalker（3DMM）
└─ 有视频→ Q2
Q2.需要实时对话 / 直播 / 批量处理吗？
└─ 是（客服/直播/批量）→ MuseTalk（单步 Inpainting，30fps+）
└─ 否（追求最高质量）→ Q3
Q3.画面是大特写 / 重要精修吗？
└─ 是（配音/特写/精修）→ LatentSync（Diffusion，512px）
└─ 否（轻量验证/研究）→ Wav2Lip（OSS 不可商用！）
⚠ 通用前提：无论选哪个模型，商业使用务必确认已获得被生成人物的有效授权（肖像权 + 声音权），这是独立于模型许可的法律问题。
核心技术原理

🎙 MuseTalk — Latent Inpainting

在 VAE 潜空间内完成单步修复。音频由 Whisper-tiny 编码为特征向量，图像由冻结的 ft-mse-vae 编码为潜向量，U-Net 在潜空间内融合音视频特征后直接输出 256×256 修复结果。非扩散模型，无需迭代，去噪开销为零。

SIS（信息性帧采样）：选择与目标头部姿势最接近的参考帧，减少冗余信息干扰。AAM（动态边界采样）：动态调整唇音同步损失的有效范围，平衡画面质量与同步精度。

👄 Wav2Lip — GAN

基于 GAN 的唇形同步。生成器接收音频特征（Log-Mel）和随机噪声，直接在像素空间输出唇形区域。判别器（SyncNet）在 96×96 分辨率上训练，专门评估音频-视觉同步置信度（LSE-C），驱动生成器优先保证同步精度。

局限：训练在低分辨率（96×96）上完成，生成结果模糊。SyncNet 的 LSE-C 指标本身在低分辨率上有优势——这解释了为什么 Wav2Lip 的 LSE-C 最高但 FID 最差。

🧠 LatentSync — Latent Diffusion

在 Stable Diffusion 的潜空间内执行扩散过程。音频embedding注入 U-Net 进行跨注意力融合，对 256/512 人脸区域进行 20-50 步迭代去噪生成。质量最高，但每段需数秒到数分钟。

LatentSync 训练了自己的 SyncNet（参数量约为 Wav2Lip SyncNet 的 10 倍），在 256×256 分辨率上评估 LSE-C，解决了 Wav2Lip 评分"低分≠低质量"的问题。

📐 SadTalker — 3DMM

从单张静态照片重建 3D 人脸头部模型（3DMM）。音频驱动提取头部运动系数（pitch/roll/yaw + 眼球凝视），系数经映射网络转换为驱动信号，控制 3D 渲染器输出说话头部视频。

唯一能从单张照片生成说话视频的开源方案，适合没有视频素材的场景。视频自然度略低于前几种方案。

快速启动
# 1. 环境准备（Ubuntu 22.04 / CUDA 12.8） conda create -n livetalking python=3.12 && conda activate livetalking pip install torch==2.9.1 torchvision==0.24.1 torchaudio==2.9.1 \ --index-url https://download.pytorch.org/whl/cu128 pip install -r requirements.txt # 2. 下载模型（夸克云盘 或 Google Drive） # wav2lip256.pth → models/wav2lip.pth # wav2lip256_avatar1.tar.gz → data/avatars/wav2lip256_avatar1/ # 3. 启动服务（WebRTC 模式） python app.py --transport webrtc --model wav2lip --avatar_id wav2lip256_avatar1 # 4. 浏览器打开 → http://serverip:8010/index.html
核心 API
方法端点说明
POST/human文本驱动，支持 echo（直接复读）和 chat（LLM 对话）两种模式；返回 sessionid 用于后续音频驱动
POST/humanaudio音频文件直接播放，数字人朗读给定音频内容，无需文本转换
POST/human/stream流式响应，支持打字机效果实时输出 TTS，数字人口型同步跟进
GET/human/{sessionid}/status查询会话状态，判断当前数字人是否正在播报或处于空闲
POST/human/interrupt强制打断当前播报，用于观众提问打断场景，立即停止当前 TTS + 口型推理
GET/admin/stats全局监控：当前并发会话数、GPU 推理 FPS（inferfps）、推流 FPS（finalfps）
系统架构分层
层级组件说明
接入层WebRTC / RTMP / 虚拟摄像头多协议输出，WebRTC 延迟 <200ms；RTMP 支持抖音/B站/YouTube 推流
API 层/human · /humanaudio · /human/stream · /human/interruptHTTP REST，接入简单；每个连接分配唯一 sessionid，支持多用户并发
逻辑层LLM 引擎（Qwen 等）· TTS（EdgeTTS / GPT-SoVITS / CosyVoice / 腾讯云）模块化插拔，新增 TTS 服务只需修改 registry.py；支持声音克隆
推理层Wav2Lip · MuseTalk · ER-NeRF · UltralightGPU 推理，inferfps ≥ 25 才算实时；插件机制 via registry.py 可扩展新模型
渲染层Mel 频谱提取 → 口型推理 → 视频贴回音频特征同步提取，口型区域平滑贴回原始高清视频
