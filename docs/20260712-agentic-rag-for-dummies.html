四阶段查询处理流程

对话理解→查询改写→查询澄清→并发推理→聚合回答
Stage 1

对话理解

维护滚动摘要 + 最近对话历史，保留连续性而不无限膨胀上下文。

Stage 2

查询改写

将指代（如"那个问题"）和省略还原为完整查询语句。

Stage 3

查询澄清

检测歧义查询，暂停询问用户细节——人类介入机制。

Stage 4

并发推理

LangGraph 协调多路 Agent 并行处理子任务，聚合结果后回答。

对话记忆：上下文压缩只留干货

滚动摘要

长期对话不膨胀

维护一个 rolling summary，保留对话核心意图，不随对话轮次线性增长 token 消耗。

最近历史

近 N 轮完整保留

保留最近几轮完整对话记录，确保即时上下文不丢失。

防爆机制：拒绝无限死循环

最大迭代次数

内置上限，自动停止

LangGraph 内置 max_iterations 限制，Agent 不会陷入无限检索循环。查不到资料自己停，绝不乱烧 Token。

回退机制

优雅降级

当检索失败或超过限制时，系统回退到预设策略（如直接回答"信息不足"），而不是重试到 Token 耗尽。

Human-in-the-loop：查询澄清

Agent 检测到歧义查询时，暂停并向用户请求澄清——不是猜一个方向硬做，而是让人类确认意图后再继续。这避免了因查询歧义导致的答非所问。

歧义检测

Agent 自动识别指代不明、多义、缺省信息的查询。

用户确认

Agent 暂停，向用户提问澄清，确认后继续处理。

多路并发：分身处理复杂任务

LangGraph 协调多个子 Agent 并行处理子任务。复杂长问题拆分为多个子任务并发秒回，再聚合为最终答案。

安装与体验

Google Colab

免配置，一键跑

打开 notebooks/agentic_rag.ipynb，点击 Colab badge，无需安装任何依赖，浏览器里直接跑完整示例。

本地安装

pip install + docker

Python 3.11+：pip install 后启动 Qdrant（Docker），配置 Ollama，即可本地运行完整 Agentic RAG 系统。

使用边界：3,644 Stars 为 GitHub API 实时检索值。所有 LLM 提供商均需自行配置 API key（Ollama 除外）。分层索引效果依赖文档 Markdown 结构质量，无结构化标题的 PDF 效果会打折扣。reranker 为可选模块。
