Design guidance for AI coding agents

Impeccable：让 AI 写出不像 AI 的前端

1 个 skill、24 条命令、live browser 实时迭代、61 条确定性检测规则。从 Anthropic frontend-design skill 进化而来，Apache-2.0，一套设计词汇装进所有主流 AI 编码工具。

1

init 建档

PRODUCT.MD

/impeccable init 记录产品真相：受众、目的、语境、约束、voice，后续命令不再重复问。

2

词汇共通

24 COMMANDS

polish/audit/critique/bolder/quieter——你说人话，AI 做设计，共享一套设计动词表。

3

确定性检测

61 RULES · NO LLM

CLI 与浏览器扩展零 LLM 零 API key 跑规则；glow、卡片套卡、过气字体全部现形。

4

装进你的工具

13+ HARNESSES

Claude Code、Cursor、Codex、Gemini CLI、Hermes、Grok、Veto、Trae 等全支持。

官方判断：每个模型都在同一批 SaaS 模板上训练——跳过设计指导，产出就是同一把「AI 味」标志牌。

五步安装

推荐 npx impeccable install：自动探测 ~/.claude、~/.codex、~/.hermes、.cursor 等，装完全家桶后 reload。

init 建档

/impeccable init 检查项目，只问实质缺口，写 PRODUCT.md 记录产品真相。

live 迭代

/impeccable live 进浏览器实时改元素，generate 自动生成变体，不用手工挑选。

一套设计动词表

24

命令全景

THE COMMAND TABLE

全部走 /impeccable <command> <target> 调用；pin <command> 可造独立快捷命令（pin audit → /audit）。SKILL.md 按官方四类分组：Build 建造、Evaluate 评估、Refine 精修、Iterate 迭代。

B

Build 建造

SHAPE THE WORK

shape 先规划 UX/UI 再写码；init 产品建档；document 从现有代码生成 DESIGN.md；extract 抽取组件与 token 进设计系统；craft 已弃用（普通 new-work 即可）。

E

Evaluate 评估

JUDGE THE WORK

critique UX 设计评审（层级/清晰度/情绪共鸣）；audit 技术质量检查（a11y/性能/响应式）；polish 出货前终检 + 设计系统对齐。

R

Refine 精修

PUSH EITHER WAY

bolder 放大无聊设计 / quieter 压制过火设计——双向旋钮；distill 剥到本质；harden 错误处理/i18n/溢出/边界；onboard 首跑流程与空态；clarify UX 文案；typeset 字体层级；layout 间距节奏；colorize 战略用色；animate 有目的的动效；delight 愉悦时刻；overdrive 技术级特效；adapt 多设备适配；optimize 性能。

I

Iterate 迭代

LIVE BROWSER

live 视觉变体模式：在浏览器里对元素实时迭代；generate 对命名元素自动生成变体，免手工挑选。

别万物皆卡

不要把一切包进卡片，更不要卡片套卡片——AI 味第一标志。

别紫蓝渐变

零位移彩色光晕（dark-glow）是 detector 明文规则，category=slop。

别过气字体

Arial、Inter、系统默认都在过用清单里；彩底灰字、纯黑纯灰同样禁止（总要带色调）。

别土味缓动

bounce/elastic 缓动显得过时；动效要有目的，不做装饰。

别无穹自检

官方 SKILL：有界验证——建完批量查一次（桌面+移动），一批修完，至多再确认一轮就停。

推文说的「血脉喷张」，官方叫 template slop：61 条确定性规则 + 851 个 golden 基线测试逐条抓这些标志牌（glow / oversized-h1 / icon-tile-stack / kicker-above-heading…）。

按 surface 定模式

4

设计模式

PERSUADE · OPERATE · READ · EXPERIENCE

模式描述「访客在这个页面上成功是什么样子」。按 surface 而非产品判定：工具的落地页仍是 Persuade，时尚品牌的文档仍是 Read。

P

Persuade

EARN ACTION

落地页、营销、定价页——设计即产品，赢取注意与行动；brief 需要真图就上真图。

O

Operate

COMPLETE TASKS

应用 UI、仪表盘、编辑器、设置——可扫读、一致性、平台习惯优先，品牌活在精确细节里。

R

Read

BUILD UNDERSTANDING

文档、文章、指南、changelog——先为理解结构化，再让阅读体验值得停留。

E

Experience

INSIDE THE WORK

作品集、画廊、展示——让作品从首屏开始主导，界面退后。

How to design 三铁律

The brief wins：用户钉死的审美、年代、材质、字体、配色，即使与饱和模式警告冲突也要遵守——把明确 brief 拉向自己的口味即是失败。Refinement preserves, redesign replaces：精修保留既有身份、行为、文案；重设计保留产品真相但把旧视觉当证据与反参照，绝不折中。视觉权威是证据而非文件名：没有 DESIGN.md 不等于 greenfield。

① CLI 安装

项目根目录 npx impeccable install；探测已装的 harness，选择 project 或 global。脚本化用 --providers=claude,codex,cursor,grok,hermes,veto 与 --scope=project|global。

② 或 submodule

团队 vendored：git submodule add + npx impeccable link --source=.impeccable --providers=claude,cursor；更新走 submodule update --remote 再 link。

③ 无运行时

引擎是自包含二进制：launcher 旁或首跑下载进 ~/.impeccable/bin；只有 npx 安装器需要 Node，手动/submodule 全程零 Node。

④ hook 信任

Claude/Cursor/Codex/Copilot/Grok 自动装 provider-native hook；Codex 要 /hooks 批准，Grok 要文件夹信任——更新改 hooks.json 后 Codex 要重新批准。

⑤ 首跑三连

/impeccable init 写 PRODUCT.md → /impeccable document 生成 DESIGN.md → 需要精修的页面跑 /impeccable polish 或 /impeccable audit。

给新项目

init → document → shape 新页面 → live 迭代 → polish 收尾。前两条只跑一次。

接手旧项目

document 先生成 DESIGN.md 摸清既有视觉，再 extract 抽组件；别急着 redesign。

调品味方向

太平淡 bolder，太吵 quieter，要本质 distill；单页走 polish，全站走 audit。

日常直说

也支持自然语言：/impeccable redo this hero section——描述需求，不必记命令名。

为什么它敢说「让 AI 学好设计」？

WHY IT HOLDS UP

  • 确定性优先：61 条规则零 LLM 零 API key 跑在 CLI 与浏览器扩展上，同一结果可复现；LLM 只负责 critique 类主观判断——设计底线交给规则，品味提升交给模型。
  • 验证有纪律：官方 SKILL 明文「open-ended self-QA burns the user's money」——建完一次批量检查、一批修完、至多一轮确认即停，这套节流纪律本身就是给 agent 的行为规范。
  • 跨 harness 一份真相：同一设计词汇编译成 13+ 工具的原生格式（含 hook manifest），不维护多套 prompt；PRODUCT.md 记产品真相、DESIGN.md 记视觉系统，事实与品味分层。
  • 作者可信：Paul Bakaus 是 jQuery UI 创作者、前 Google Chrome DevRel——推文选他不是偶然，他见过「模板如何变平庸」的完整历史。
  • 模式先于像素：Persuade/Operate/Read/Experience 四模式逼 agent 先回答「这页面为谁成功」，再谈视觉——这正是「加极简高级现代科技感」口号式调参失败的解药。
