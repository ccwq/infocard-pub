AG雷达 · 苏茶插件选型笔记

57 个 DSH 插件，
先选任务，再查边界

把苏茶的清单当作候选库：先确认宿主与 profile，再为当前瓶颈装一个插件，用可检查的结果决定是否留下。

  • 上下文先查组成：用 /context 看 system、tools、messages，再决定是否压缩或加记忆。
  • 工作台先配版本：better-sidebar 与宿主各自更新，两个 latest 不代表兼容。
  • 任务完成看记录：看板 Done 只是一列，执行历史和会话才是运行依据。
  • 远程与视觉先管数据：SSH 能触及宿主文件；免 Key 视觉仍可能上传云端。

安装前的四个问题

这四项比下载量更能决定装完是否可用。

装在哪里

web 是目标 profile；桌面应用走自身 Settings → Plugins。

支持哪个版本

核对宿主门槛、固定版本和作者，不靠同名包猜。

怎样算成功

页面出现只说明加载；结果、会话、退出状态要另查。

交出什么权限

插件是第三方代码；工具审批不是插件沙箱。

使用方式
1 → 验证 → 留下

建议每次只增加一个变量；先完成小任务，再考虑叠加。

可行动速览：只想改善当前会话，先用 dsh-context；需要工作台，先对照 better-sidebar 版本表；需要定时或 SSH，先做只读试跑并核对记录。暂时没有对应瓶颈，就先不装。

01
DSH FIELD GUIDE

先装对入口：仓库链接不是包名

下面的命令只针对已经在用的 web profile；不要照搬到桌面应用。

dshmarket：先确认宿主门槛

市场文档要求 dsh web 0.1.0-rc.6+。在已有 Web 环境使用：

dsh plugin --profile web add dshmarket

重启 dsh web，进入 Settings → Plugin Market。0.2.1 起 Settings 在账号菜单，不在侧栏。其他 profile 要替换 web；官方桌面版从应用自身 Settings → Plugins 安装，不要在应用运行时用 CLI 改它的 profile。

目录发现与安装要分开

0.2.1+ 的内建发现入口为 Plugins → Discover → Index sources，可添加：

https://cdn.jsdelivr.net/npm/dsh-plugin-catalog/index.json

索引覆盖有已知 npm 版本的条目；GitHub-only 仓库不等于能在索引直接安装。用市场显示的准确包名，不把仓库地址直接塞给 pnpm。

dsh-market 文档 · 插件目录

少装一步，也少一个排障变量。苏茶提醒 dsh-web-all 不要与其中组件重复安装；dsh-pet、dsh-code-review 各有不同作者版本。先认仓库作者，再认名字。
02
DSH FIELD GUIDE

上下文：先找到占用，再决定怎么减

诊断、压缩和长期记忆解决不同问题，不必一上来全装。

dsh-context：用 /context 开始

dsh plugin --profile web add dsh-context

也可在 Add plugin 输入 dsh-context 后安装。在聊天里输入 /context 查看当前组成，再到 Context 页面检查 system、tools、messages 的占用和压缩事件。Context Insights 提供跨会话概览；Fleet 可查看当前、父与子 Agent。

建议检查：用同一任务记录“工具定义多”还是“历史消息长”。前者先检查不需要的工具或注入，后者再评估压缩。费用是价表估算，不是账单核对。

dsh-context 文档

billion-context：评估压缩，不许诺倍率

项目文档描述分层、增量压缩与按需解压，并尽量维持前缀缓存。它面向长会话的上下文管理，不能替代“哪些事实值得长期记住”的选择。

先选一个允许丢弃的测试会话，保留关键约束清单；压缩后检查这些约束还能否正确取回，再决定是否继续使用。不要把单次回答更短当作记忆完整。

维护者宣称“5× fewer tokens”，本次未复现；项目位于个人账号下，没有据此称其为官方插件的依据。长期记忆另看 hindsight、dsh-mnemon、OpenViking，先确认服务端与存储边界。

04
DSH FIELD GUIDE

任务看板：Done 不等于执行过

适合需要真实会话、执行历史与 cron 调度的人；先验证手动运行，再打开定时。

第一次，只跑只读任务

文档标注 DSH ≥0.2.1-rc.2，安装后需重启 dsh web。先创建任务：“检查项目测试说明并列出建议，不修改文件。”手动运行一次，在执行历史打开对应会话，核对是否真的读取了目标、给出了结果。

检查项是 execution record + 对应 transcript。手动把卡片拖到 Done 或 Failed 只改列，不创建执行记录；不能据此判断自动任务成功。

先核实包名，再启用 cron

README 徽章写 @linxin666/dsh-task-board，安装段却写 @linxin666/dsh-client-ui-task-board。两处口径不一致，这里不提供安装命令；先在市场实际条目或包清单核实。

浏览器关闭不等于 Host 停止，定时任务的运行位置要核对。高于默认权限的绑定需要用户确认，不能让 Agent 代为确认授权。

05
DSH FIELD GUIDE

远程和视觉：能力开通前，先画出数据边界

SSH 管主机与本地路径；视觉管图片和请求去向。二者都不适合拿真实机密做首次试跑。

SSH：先列主机，再执行只读命令

dsh plugin --profile web add @linxin666/dsh-ssh@latest

文档要求 DSH ≥0.2.1-rc.2，重启后侧栏出现 SSH。先在 GUI 配置主机，或导入 ~/.ssh/config。建议先配置测试机，再要求：“列出主机，仅在指定测试机运行 uname -a，不写文件。”

用 ssh_list 核对别名，再查 ssh_exec 的 stdout、stderr 与退出状态。SFTP、端口转发和集群执行先不要一起开启。

视觉：免 Key 不是本地处理

dsh-vision-router 安装到现有 Web profile 后，在输入框旁开启“👁 Vision”，看到“👁 Vision ✓”再发送图片。首次建议用无敏感内容的报错截图，核对识别文字或按钮位置。

默认匿名 OVHcloud 回退会向云端发送图片或裁切图、提示词及请求元数据。免费、免 Key 只说明接入方式，不表示离线或保密；内部文档、凭据与客户截图不要直接输入。

0600 不是加密

密码、私钥口令明文保存在 ~/.dsh/dsh-ssh.json，权限为 0600。ssh-agent 认证不存私钥；agent forwarding 默认关闭，仅对信任主机启用。

宿主权限不是 bash 沙箱

SSH 上传、下载能按宿主进程权限访问任意本地路径，不受 bash 沙箱约束。目录收录、工具审批都不能替代插件代码的安全检查。

断线后先查结果

exec 断线可重试，非幂等命令可能再次执行。付款、写库、部署等操作不能盲目重试；先核对远端状态。不要承诺主机描述默认自动注入，文档表述不一致。

搜索也要查前提：dsh-free-search 可配置引擎开关与回退顺序，付费引擎缺 Key 会报错，原帖“7 个”不当作固定现行规格。modsearch 提供结构化引用证据，但社交平台 X 搜索要求安装 Grok Build；默认 keyless 服务仍有额度，不能按无限检索安排任务。
