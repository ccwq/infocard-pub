面向自改进的
Harness 工程

Harness 是 AI 部署的重要组成部分，编码 agent 产品如 Claude Code 和 Codex 的成功就是例证。Harness 不是 prompt 模板，而是运行时和软件系统设计。

LLM Harness Self-Improvement RSI Meta-Harness Self-Harness
核心洞察：2026 年 AI Agent 竞争的核心不在模型本身，而在围绕模型的 harness

递归自改进（RSI）的近期路径不太可能是模型直接重写自身权重。更务实的方向是：模型改进训练流程和部署系统（即 harness），这反过来使更好的后继模型能产生。

RSI — 递归自改进

I. J. Good (1965) 的"超智能机器"

一个在所有智力活动中超越人类并能设计更好机器来自我改进的系统。现代 AI 中，这个反馈循环意味着模型改进训练流程和部署系统，反过来使更好的后继模型产生。

Harness 是什么

围绕基础模型的系统：编排执行，决定模型如何思考与规划、调用工具与行动、感知与管理上下文、存储制品、评估结果。比早期 agent 框架多出工作流设计、评估、权限控制与持久状态管理。

Harness 工程聚焦

不在 prompt 模板，而在运行时和软件系统设计。应刻意简单通用以促进泛化，参考现有软件工程实践以受益于预训练知识。与操作系统有强烈类比关系。

核心优化演进路径

指令 prompt → 结构化上下文 → 工作流 → harness 代码 → 优化器代码
模型越强 → 目标越复杂 → 方法越通用

PATTERN 1 · 工作流自动化
PAGE 01

设计模式一：工作流自动化

定义一个模型可以在其中操作、测试和迭代的工作流是自动化的关键设计。Karpathy 的 autoresearch repo 是一个简洁的例子。

目标导向循环
规划 → 执行 → 观察/测试 → 改进 → 再次执行

循环直到目标达成。设计应刻意简单和通用以促进泛化。

PATTERN 2 · 文件系统持久记忆
PAGE 02

设计模式二：文件系统作为持久记忆

Harness 不应在上下文中携带整个工作流和所有日志；应将持久状态保留在文件中。

实验日志 / 代码 diff
跨 session 保留，可中断后恢复
论文摘要 / 错误踪迹
通常比训练上下文窗口长得多
Rollout 轨迹数据
学会读、写和编辑文件系统是 LLM 的基础技能

以文件形式管理持久记忆，自然受益于核心模型能力的提升。

PATTERN 3 · 子 Agent 体系
PAGE 03

设计模式三：子 Agent 和后端任务

Harness 可以生成多个子 agent 并行执行并监控后端任务。父 agent 需要一个小的进程管理器：

启动任务 → 检查日志 → 取消失败运行 → 合并结果
关键设计

并行应变得显式和可检查：子 agent 输出存为文件/日志/状态记录，而非只存在于聊天上下文。中断后模型可恢复并推理执行历史。

CONTEXT ENGINEERING · 上下文工程
PAGE 05

上下文管理三阶段演进

ACE — Agentic Context Engineering
将上下文视为不断演化的 playbook。三个组件：
Generator 生成任务轨迹 → Reflector 从成功/失败中提取洞见 → Curator 用增量条目更新结构化上下文（而非重写完整 prompt blob）
MCE — Meta Context Engineering
将机制（如何管理上下文）与制品内容（上下文中有什么）分离
元优化层面运行 skill 进化，基础层面运行上下文优化。用自由形式的 skill 存储任务最重要知识，迭代同时进化 skill 和 skill 条件化的上下文。
⚠ 关键数据：性能差距 6 倍
同一模型，仅因 Harness 不同，性能差距可达6 倍。这是 2026 年 Agent 竞争核心转向 harness 的量化依据。
Meta-Harness（Stanford）
不再只优化单条 prompt，而是把完整 harness 程序作为优化对象。文本分类：40.9% → 48.6%，上下文开销：50.8K → 11.4K tokens
Anthropic 三层虚拟化
Session（外置记忆体）→ Sandbox（执行隔离）→ Harness（推理确定性部分）。设计哲学：从"宠物架构"到"牲畜架构"，接口比实现活得更久。
WORKFLOW DESIGN · 工作流设计
PAGE 06

自动工作流发现

ADAS — Agent Design as Search
将 agent 设计本身公式化为优化问题。元 agent 提出新的 agent 工作流设计，所有新 agent 用代码编写。
AFlow — 图驱动工作流优化
将 agent 工作流表示为图：节点 = LLM 调用动作，边 = 用代码实现的逻辑操作。基于 MCTS（蒙特卡洛树搜索）优化。
AI Scientist
提出想法 → 写代码 → 跑实验 → 分析结果 → 写论文 → 同行评审。每条声明（引用/数值/方法论/结论）必须追溯到证据源。可验证性作为中心设计约束。
SELF-IMPROVEMENT · 自改进 Harness
PAGE 07

自改进 harness 三种方案

STOP — Self-Taught Optimizer
种子改进器拿到初始解决方案 + 效用函数 + 黑盒模型 → 返回改进后的解决方案。目标不是改进解决方案，而是改进改进器本身。
发现的策略：遗传算法 / 分解改善 / 多臂 bandit / 模拟退火 / 波束/树搜索
⚠ 仅递归结构不够：基础模型必须足够有能力来改进机制（GPT-4 有效，GPT-3.5/Mixtral 退化）
Self-Harness — 自优化 Harness
使用 propose-evaluate-accept 循环：弱点挖掘 → harness 提案 → 提案验证。在 MiniMax M2.5 / Qwen3.5-35B / GLM-5 上学到模型特定的 harness 指令。
DGM — Darwin Gödel Machine
基于 LLM 的编码 agent 修改自己的 harness 代码库。Claude 3.5 Sonnet + 简单初始 harness → SWE-Bench Verified: 20% → 50%，Polyglot: 14.2% → 30.7%
EVOLUTIONARY SEARCH · 进化搜索
PAGE 08

进化搜索：Harness 的 Pareto 前沿

适用场景：搜索空间巨大或形状古怪；难以用梯度优化但易于评估解决方案。Harness 搜索非常匹配。

AlphaEvolve
候选程序和 prompts 存储在池中，冻结 LLM 生成 diff 改进。在池中反复评估子程序并保留成功者。
Darwin Gödel Machine
从池中选父代 → 检查基准评估日志 → 提出对自身 harness 代码库的改进来生成新版本 agent。明确的自我修改能力。

HARNESS VS CORE INTELLIGENCE · Harness 与核心智能
PAGE 11
实用近期预测
1. 元方法论方向
Harness 工程将朝元方法论方向演进——改进获得更好答案的机制，而不仅仅是改进答案本身。
2. 自动研究闭环
成熟的 harness 使自动研究成为可能。更智能的模型防止 harness 过度工程化。
3. 内化 vs 接口
许多 harness 改进可能被"内化"到核心模型行为中，但与外部上下文和工具的接口应保留。
