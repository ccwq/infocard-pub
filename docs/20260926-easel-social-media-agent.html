Easel：浙大开源的社媒运营 Agent

浙大 REAL Lab × 北大 × OpenDCAI 的开源内容工作台，OpenClaw 驱动。主张"Agent 不只回答该怎么做，而是直接把内容做出来"：发现→策划→创作→发布→归因五层闭环，git 实测 114 个 SKILL.md，七平台真实发布。1,442★（09-26 实测），v0.2.1 刚发布。

01它是什么：一条五层流水线，不是聊天包装

层干什么（README 能力表精选）
发现全网热搜聚合（微博/抖音/知乎/B站/百度/头条热榜）、垂类趋势、内容缺口分析、节日事件日历、平台算法动态、竞品分析、RSS、UGC 发现
策划账号定位分析、受众画像、人设声音、选题矩阵与评分、标题与 Hook、分镜脚本、内容日历、跨平台复用、直播/商单方案
创作文案、小红书笔记、去 AI 感改写、风格迁移、论文解读、金句卡/知识卡/海报/信息图/思维导图、TTS 与多角色配音、声音克隆、AI 音乐、视频剪辑/切片/高光/绿幕/横竖转换、AI 短剧
发布按平台适配标题/正文/画幅/媒体要求；质量门禁+敏感版权检查+发布 Checklist；七平台登录与发布
归因读播放/互动/评论数据，把有效结构和偏好沉淀回账号画像（ROI 计算、内容复盘、画像记忆）

关键区分：技能是真执行——图片、配音、字幕、剪辑、发布技能都配可运行脚本，成品写入 outputs/ 按项目归档，不是"给你一个建议清单"。同一母版内容可改写成小红书卡片、短视频、知乎长文，遵循各平台格式与字数。

02账号画像：六个维度决定 Agent 的"人设记忆"

画像对应 profiles/<名字>/ 目录：定位、风格、受众、平台、偏好与红线、长期记忆。一份画像跨多个平台和会话持续使用；归因层把"什么有效"写回记忆，下次创作自动贴合。官方一句话："会记住你的内容搭档"。

cp -r profiles/_template "profiles/我的账号"   # 或在 Web「画像」页直接建
easel skill quality-gate -i "这是待发布文案" -p 科技数码达人

-p 参数指定画像；所有技能由 Agent 读 SKILL.md 调脚本执行。发布前两道把关：skill-quality-gate 一次查两类——合规风险（敏感词、绝对化用语、平台规则）+ 产物质量（完整性、可读性、平台适配）；skill-seo-quality 再做平台搜索优化（标题/正文关键词布局、话题标签权重、封面首帧文字，覆盖小红书/抖音/知乎/公众号）。

03上手：三条命令跑通（setup.sh 可重复执行）

  1. 安装（Linux/macOS/Win10+，Python 3.10+）：
    git clone https://github.com/ZJU-REAL/Easel.git && cd Easel
bash setup.sh          # Windows PowerShell 原生：.\setup.ps1（免 WSL）
    安装器引导式、可重复运行：查依赖（缺 FFmpeg 走系统包管理器，Windows 用 winget 自动补）→ 建 .venv → 装独立 easel OpenClaw profile（不覆盖本机已有 ~/.openclaw/）→ 构建前端 + Playwright Chromium → 引导配 LLM Key（不回显）→ 同步 skills 启动 gateway。任一步失败即停，不会回退成不完整安装。
  2. 最小配置：项目根 .env 一个能用的 LLM 即可（ANTHROPIC_API_KEY 或 OPENAI_API_KEY+BASE_URL，也支持 Anthropic-compatible 端点）。聊天 API 不带向量模型时配 EASEL_EMBEDDING_*，否则 Easel 显式降级为关键词记忆检索（不会反复打聊天端点要 embedding）。视频/音乐/配音模型按需在 Web 技能库填，没配的媒体技能不影响文本创作。
  3. 验证与启动：
    source .venv/bin/activate
easel doctor     # 查 Python/Node/OpenClaw/关键配置
easel ping       # 实测 gateway 与 Agent 连通
easel web        # Web 工作台 http://localhost:7860（gateway 18789）
    推荐 Web 前端：会话/素材/账号/画像/内容库/发布管理都比 CLI 全。

04三个容易被忽略的诚实细节

A小红书风控警告写在 README——"小红书平台可能检测自动化操作，存在验证、限流或账号风控风险；建议使用预览与发布前检查，并由用户确认后手动发布"。其他平台正常。这是对自动化社媒工具最实际的一条免责边界。
Bknown-issues 文档像事故报告——CLI 的 ask_user 重复显示问题，文档追到上游 OpenClaw 的 session projection 根因、给出上游 PR 号（openclaw#144730/#144892）和四层修复策略，并注明"Web 后端从原始事件流自行渲染，不受影响"；第三方代理超时问题连 baseUrl: expected string 的报错原文都写了。easel doctor 内置 OpenClaw 最低版本检查（≥2026.6.11）。
C数字对不上，但偏向诚实——README 徽章写 113 Skills，能力地图与 git 实测均为 114 个 SKILL.md（我数了）。产物实证也扎实：README 直接挂出 6 篇论文解读卡、4 篇小说、多条视频成片，全部来自真实工作流而非示意图。

05判断

值得用的：内容团队/个人创作者想用 Agent 跑"热点→成片→发布→复盘"全链路，且主力平台在中文社媒（七平台支持是国内开源里罕见的完整度）；做社媒 Agent 研究的人——README 明说这是"研究成果应用到真实场景的实践"，后续方向是社媒场景的社交智能。

要斟酌的：发布能力依赖浏览器登录真实账号（Playwright Chromium），平台风控是长期猫鼠游戏（官方只对小红书发了警告，其他平台同样存在）；项目 8 月底才建、v0.x 阶段，API 和技能结构还会变；Roadmap 第一条就是 Windows 原生全链路适配——现在 Windows 用户走 setup.ps1 但兼容性仍在打磨；OpenClaw 单一 harness 依赖（Claude Code/DeepSeek/Codex harness 支持在 Roadmap）。
