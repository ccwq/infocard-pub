avante.nvim

01

先做这一步

最小可用配置就是下面这段。装之前先记住两条硬要求：build 字段必须写（README 用三个感叹号强调，不写会装上但跑不起来），version 不能设成 "*"（README 原话：Never set this value to "*"! Never!）。

{
  "avante-corp/avante.nvim",
  -- build 字段必须设置（README 用三个感叹号强调）
  -- 不设：插件装上了，但二进制/依赖没构建，跑不起来
  build = "make",
  -- 从源码构建才用它，需要 cargo：
  -- build = "make BUILD_FROM_SOURCE=true"
  -- Windows：
  -- build = "powershell -ExecutionPolicy Bypass -File Build.ps1 -BuildFromSource false"

  -- version 不要写 "*"：README 明确禁止
  -- version = "*"   -- 错了，别这么写

  dependencies = {
    "nvim-lua/plenary.nvim",
    "MunifTanjim/nui.nvim",
    "ColinKennedy/mega.cmdparse",
    "ColinKennedy/mega.logging",
  },
}
安装方式
lazy.nvim，README 首推。示例即上面这段。
预编译产物依赖
需要 curl 与 tar 拉取预编译二进制；只有从源码构建时才需要 cargo。
四个依赖插件
plenary.nvim、nui.nvim、mega.cmdparse、mega.logging。
项目专属指令
instructions_file = "avante.md"，放在项目里，只对该项目生效。
踩坑对照：漏写 build → 插件加载了但功能不可用；version 写 "*" → README 明确点名禁止的写法。这两条是最容易出错的地方。
02

核心机制

它做两件事：在编辑器侧边栏里跟你对话；以及改你选中的代码块。区别在于「谁动手」——agentic 模式自己动手，legacy 模式等你批准。

agentic 模式 默认
AI 可用工具，自动生成并应用代码改动：文件操作、bash、网页搜索等。
legacy 模式
传统规划模式，不做自动工具执行，所有动作需人工批准。

关工具：disable_tools 与 disabled_tools 不是一回事

配置项作用范围什么时候用
disable_tools = trueprovider 下设，整体关掉工具部分模型不支持工具调用
disabled_tools = { "python" }只禁指定工具模型过度使用某个工具，单独掐掉

一个整体开关，一个白名单式剔除；混用会把该留的工具一起关掉。

工具清单（agentic 模式下可被调用）

rag_searchpythongit_diffgit_commitglobsearch_keywordread_file_toplevel_symbolsread_filecreate_filemove_pathcopy_pathdelete_pathcreate_dirbashweb_search_tavily

可用的网页搜索后端：Tavily、SerpApi、SearchAPI、Google Programmable Search Engine、Kagi、Brave Search、Firecrawl、SearXNG。

ACP：把外部 agent 接进来

ACP 指 Agent Client Protocol（文档 agentclientprotocol.com），目的是让遵循该协议的 AI agent 与开发环境用统一协议交互，覆盖代码编辑、文件操作与工具执行。插件默认内置三个 provider：codex、gemini、claude-code。要自建 provider 就写配置里的 acp_providers 段，细节看 :h avante-acp 与 wiki 的 Custom providers 页。

03

可执行步骤

A. 安装

1
先确认环境
机器上有 curl 和 tar（取预编译二进制用）。只有走源码构建才需要 cargo。
2
写进 lazy.nvim 配置
照 01 先做这一步里那段骨架：build 字段必设，version 不写 "*"，四个依赖列全。
3
Unix 用 make，Windows 用 Build.ps1
build = "make"；要从源码构建改成 "make BUILD_FROM_SOURCE=true"。Windows 用 powershell -ExecutionPolicy Bypass -File Build.ps1 -BuildFromSource false。

B. 认证

Claude Pro / Max 订阅

把 claude provider 的 auth_type 设为 "max"，重开 Neovim 后走浏览器授权，登录后把页面上显示的 code 粘回 Neovim 的提示框。

前置 如果之前选过别的 provider，先执行 :AvanteSwitchProvider claude。

自己的 API key

环境变量加 AVANTE_ 前缀可与其它应用隔离，例如 AVANTE_ANTHROPIC_API_KEY、AVANTE_OPENAI_API_KEY、AVANTE_GEMINI_API_KEY。

不设环境变量时，Avante 启动会提示输入 API key。README 建议把环境变量写进 shell 配置，保持跨会话一致。

C. 常用命令

命令作用
:AvanteAsk [question] [position]就代码提问，position 设窗口位置
:AvanteChat就整个代码库开始对话会话（默认 ask=false）
:AvanteChatNew开新会话；旧会话可用会话选择器重新打开
:AvanteEdit编辑选中的代码块
:AvanteHistory打开历史会话选择器
:AvanteBuild构建项目依赖
:AvanteFocus在侧边栏与主窗口间切换焦点
:AvanteRefresh刷新所有 Avante 窗口
:AvanteClear清空当前会话聊天记录
:Avante acp modes切换 ACP 模式（:AvanteACPModes 是废弃别名）
:Avante acp sessions列出当前 ACP agent 的会话（含它 CLI 里开的）并恢复选中项
:Avante rag start | stop | status管理 RAG 服务
:Avante rag query How does authentication work?查询当前项目

D. 可选：RAG 与 MCP

RAG 默认不启用，且要单独装 rag service。安装二选一：

# 方式一：nix
nix build .#ragService

# 方式二：uv
uv venv && source .venv/bin/activate && uv pip install --editable py/rag-service

然后配 rag_service 段：enabled、url（默认 http://localhost:20250）、runner（docker 或 native）、llm（provider / endpoint / api_key / model，示例用 openai + gpt-4o-mini）、embed（示例用 text-embedding-3-large，max_embedding_tokens 512）。

MCP 不走本插件：通过 mcphub.nvim 接入，需额外安装。

04

预期现象

装好之后：侧边栏出现对话面板，选中代码后它能给改动建议，agentic 模式下改动可以直接落到文件里。

侧边栏里能看到的
对话记录、改动内容，以及 apply all / apply cursor 这类应用按钮——决定把哪些改动写回文件。
选中代码块之后
用 :AvanteEdit 直接编辑选中的块，不用把代码复制到别处。
RAG 开启之后
服务起来后可以用 :Avante rag query <问题> 查询当前项目，例如「How does authentication work?」。

作者怎么用它日更（推文侧信息）

这一段来自 推文原文，不是 README 内容。推文未点名仓库，本卡按作者 yetone 高置信度匹配到 avante-corp/avante.nvim（18,189 star，2026-10-14），此匹配关系属推断。

推文称作者在 Claude Code 里用 /loop 定时命令挂了 3 条提示词，每隔一阵自动重跑：

  1. 盯 GitHub issue 与 PR——别人的 PR 先拉下来跑一遍再合并；
  2. 盯推特反馈——能复现的 bug 修好就上线，再回复网友；
  3. 定期清理屎山代码，把踩过的坑写进经验文件。
关键边界 · /loop 不是常驻后台

/loop 是 Claude Code 内置的会话内定时能力：/loop [interval] 让一条 prompt 或 slash command 按间隔重复执行，最小粒度 1 分钟，支持 Ns / Nm / Nh / Nd 写法。官方文档：code.claude.com/docs/en/scheduled-tasks。

官方文档说明这类定时任务 session-scoped（会话内生效），依赖 Claude Code 会话处于活动状态，不是常驻后台服务。所以推文那句「每隔一阵自动重跑」不等于常驻自动化——会话关掉就不跑了。
