为什么它像“计划控制平面”
technical analysis
Plannotator 不是单纯的评论工具。它把“计划生成 → 人工/AI 标注 → 评审 diff → 回传反馈 → 团队共享”串成闭环，解决 agent 开发里最容易断裂的那段：人类读计划、agent 改代码、双方失联。
Plan mode HTML artifacts Feedback loop Encrypted share
代码层面，它是一个 monorepo：apps/* + packages/*，命令上同时支持 codex、Claude Code、OpenCode、Copilot CLI 等环境。
它的接口面也很清晰：本地标注、diff 审查、PR/MR 审查、HTML 产物审查、会话回看、团队共享。
输入计划 / spec / markdown / HTML / URL / diff
输出结构化注释、评审意见、回传 agent 的反馈
协作加密 review link、团队共享、跨工具统一收口
风险点安装链路偏“最新即用”，需注意版本可验证性

一句话判断

这是一个把“计划审查”产品化的 agent 评审中枢，而不是单一的 diff viewer。

生命周期 / 工作流
plan → annotate → review → feedback → share
1
计划进入

把 plan、spec、README 或 URL 放进标注面板。

2
逐段标注

在 markdown / HTML / 代码文件上写批注，收口观点。

3
代码评审

对 uncommitted changes / PR / MR 做审查和建议。

4
回传 agent

将结构化反馈直接发回 agent，形成下一轮修正。

5
团队共享

加密 review link / 历史会话 / 评审结果，团队协同。
