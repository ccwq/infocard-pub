Core Mechanism

Zone of Proximal Development

ZPD

最近发展区

每次教学都在用户"刚好够得着"的挑战区间：通过 learning records 了解当前水平，再推送刚好超出其现有能力的 lesson。

LR

Learning Records

教学 ADR：序号递增，只记录非显而易见的事。覆盖而非删除旧记录，保持理解演化历史。

MISSION 驱动

所有教学决策回溯到 MISSION.md。如果用户不清晰，先问"Why"——抽象目标比具体任务更危险。

Learning Science

Fluency vs Storage

Fluency Strength

即时提取能力

感觉"掌握了"≠真正记住。快速访问、提示、模板让用户能立刻上手，但不能替代长期记忆。

Storage Strength

长期保留能力

费力检索才是真正构建记忆的方式。三大工具：检索练习、间隔重复、交叉训练。

Quiz Design

选项字数相同

每个答案选项必须字数、字符数完全一致——不能通过格式差异给用户线索。Tight feedback loops，即时反馈是关键。

Reference vs Lessons

两种输出形态

Lessons：单次访问，追求完成感（Tufte 设计）。Reference：反复查阅，追求快速检索。Reference 是压缩的精华。

File Formats

格式纪律

MISSION.md

Concrete over abstract。"跑半马"比"变健康"好。推动所有决策；Mission 变了 → 更新文件 + 写 LR。

GLOSSARY.md

只收录已理解的术语——压缩理解，不是增加阅读量。分组 + 排除词 + 简洁定义。用自己术语互相定义。

Learning Records

ADR 风格。触发条件：真正的理解、新认知、mission 变化。覆盖而非删除：Status: superseded by LR-NNNN。

RESOURCES.md

高信任资源。知识（来源）+ 智慧（社区）。每个链接必须注释"何时使用"。发现空白 → 显式列出 Gaps。

Lessons

单个 HTML 文件，保存到 ./lessons/0001-dash-case.html。简短、可打印（Tufte）、有具体小成果、推荐一手源。

关联技能 角色 说明
/grill-me pre-teach · 需求澄清 上课前的需求捕获：让 agent 问详细问题，确保理解用户真正想要的。不是教学，是需求收集。
/write-a-skill output · 压缩经验 把经验和流程写成可复用的 skill 文件。teach 的输出可以被写成 skill，形成知识沉淀闭环。
/handoff context · 上下文交接 把当前状态（mission、进度、关键决策）完整传递给下一个 agent。教学 session 的状态迁移。
/caveman output · 简化表达 用粗体和层级结构让 agent 输出更容易扫描。teach 的 lessons 也需要保持可读性。
