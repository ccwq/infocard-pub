01
Core Mechanism

状态化教学空间

从"一次问答"变成"多轮教学系统"，每次会话都积累可参考的资产。

TRIGGER · /teach

当用户说"教我 X"或"我想学 Y"，/teach 激活工作台模式：在当前目录下构建完整的教学环境，追踪用户的学习轨迹，而非仅回答当前问题。

MISSION.md · 学习锚点

每个工作台必须有且仅有一个 MISSION.md。它回答"为什么学"而不是"学什么"。所有教学决策都回溯到它——如果不清晰，先问用户。

  • Why：学了这个能改变什么现实？
  • Success looks like：学成后能做什么具体的事？
  • Constraints：时间 / 预算 / 偏好
  • Out of scope：明确不教的，保护 ZPD

Zone of Proximal Development

每次教学都在用户"刚好够得着"的挑战区间：通过 learning records 了解用户当前水平，再推送刚好超出其现有能力的 lesson。

← 已知区域 ZPD（教学区） → 未知区域

判断 ZPD：读 learning-records → 估算水平 → 教最相关的刚好超出部分

Learning Records · 教学 ADRs

每次用户展示了真正的理解（不只是了解），就写一条 learning record。格式极简：一个标题 + 1-3 句。它和软件架构中的 ADR 一样：记录非显而易见的决策，驱动后续教学。

# 用户理解了"检索练习"优于"重复阅读" 理解意味着：能解释为什么在空白状态下回忆比再看一遍更有效。 这解锁了：可以在 lesson 中加入主动回忆而非被动复看。

Teaching Trinity

知识 → 技能 → 智慧

深度学习需要三者同时存在：获取知识、构建技能、追求智慧。

Wisdom
在真实社区中检验技能的现实智慧。

Knowledge · 获取

从高信任资源中提取：优先一手源、专家、同行评审。不要信任参数记忆。

难度是敌人 — 复杂资源会消耗工作记忆，阻碍理解。

Primary sources Annotated links

Skills · 构建

设计有反馈的练习：测验、交互式任务、实时验证。难度是工具 — 费力检索才是真正构建记忆的方式。

设计原则：检索练习、间隔重复、交叉训练。

Retrieval practice Spaced repetition Interleaving

Wisdom · 检验

在真实社区中测试技能：论坛、线下课、本地小组。真实世界的互动才是智慧来源。

当用户问需要智慧的问题时，默认推荐社区，同时尊重其偏好。

Community first
03
Workspace Assets

核心文件格式

每个文件都有精确的用途和格式规范，不能互换。

⚠️ 格式纪律

GLOSSARY 不等于字典（只收录已理解的术语）；learning record 不是日志（只记录非显而易见）；MISSION 短于一张屏幕（否则变成了计划而不是指南针）。

MISSION.md

学习目的。Concrete over abstract。推动所有后续决策。Mission 变了 → 更新文件 + 写 learning record。

锚点每次决策回溯

GLOSSARY.md

术语规范。只收录用户已理解的术语——压缩理解，不是增加阅读量。分组 + 排除词 + 简洁定义。

压缩理解不是字典

Learning Records

教学 ADR。序号递增。只记非显而易见的事：真正的理解、新认知、mission 变化。覆盖而非删除旧记录。

ADR stylesupersede, don't delete

RESOURCES.md

高信任资源。知识（来源）+ 智慧（社区）。每个链接必须注释"何时使用"。发现空白 → 显式列出。

KnowledgeWisdom

Lessons · 自包含 HTML 教学单元

每个 lesson 是一个独立的 HTML 文件，保存在 ./lessons/0001-dash-case.html。设计原则：

  • 简短：工作记忆很小，必须在容量内完成
  • 可打印：用户会回来看，视觉要优雅（参考 Tufte 设计）
  • 可完成：每个 lesson 有一个具体的小成果，用户能立刻用上
  • 引用源：每个 lesson 必须推荐一个高质量一手来源
  • 关联锚点：通过 HTML 锚点连接到其他 lessons 和 reference 文档
  • 反馈提示：在 lesson 结尾提示用户可以向 agent 追问
04
Reference Docs

Reference · 压缩知识单元

Reference 文档是 lessons 的原材料，也是长期可用的快速参考。

Reference 用途

Lessons 很少重访，Reference 会反复被查阅。它是 lesson 的压缩本质，设计用于快速参考和打印。Topics that lend themselves to reference docs:

  • Glossaries / 术语表
  • Syntax references / 语法速查
  • Cheat sheets / 速查卡
  • Algorithms / 算法速查
  • Yoga poses / 身体姿势图解

Reference vs Lessons

LessonsReference
频率单次访问反复查阅
设计学习过程快速检索
形态可打印、优雅紧凑、信息密集
目标完成感 + 小成果随时查、快速用
Lessons should be beautiful — clean, readable typography and layout — since the user will return to these later to review. Think Tufte.

— Matt Pocock, SKILL.md

05
Fluency vs Storage

两种学习力量

教学设计必须区分"当下提取"和"长期记忆"，二者有相反的最优策略。

Fluency StrengthStorage Strength
定义当下即时检索长期保留
错觉感觉掌握了 = 实际没记住难度高时感觉没学会
策略快速访问、提示、模板费力检索、间隔、交叉训练
敌人遗忘提示词轻松重复（假学习）
教学重点让用户能快速上手通过反馈循环建立持久记忆

Quiz 设计原则（构建 Storage Strength）

每个答案选项必须字数和字符数完全相同——不能通过格式差异给用户线索。设计 tight feedback loops，即时反馈是关键。

❌ 错误：选项长度不同 A. Python B. 这是 JavaScript C. Rust ✓ 正确：选项长度一致 A. Python B. Ruby C. Rust
