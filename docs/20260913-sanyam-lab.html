01

先从“它在验证什么”开始，不要按作品集顺序扫

官网共有 31 个实验；每个项目的描述更像一个交互命题，而不是一句技术栈标签。

物理

Spring Image / Shelf Drop

拖动、释放、坠落、回弹和遮挡关系成为观察对象；重点不是“用了动画库”，而是运动结果是否保持连续。

状态

Discount Code / Multi Step Form

一个按钮如何变成输入框，表单步骤如何换高低而不跳布局；适合检查状态机和过渡是否被写清。

空间

Radial Menu / File Tree

菜单从触发点展开、文件树折叠；观察位置、层级、焦点和撤销路径是否与用户动作一致。

阅读方法：先操作，再回看描述。实验的价值在于把“感觉顺不顺”变成可复现的输入、状态和反馈。

03

四个实验，足够开始一次有效浏览

不要从 31 个入口平均分配注意力，先选能回答你当前问题的四个。

Crack Button

连续按压让按钮从裂纹到解体；修复时裂纹回到来源点，适合看“同一动作的累积状态”和恢复逻辑。

入口：/lab/crack-button

Radial Menu

拖动文件到格式轮盘的扇区完成转换；放回中心或扇区外则保持不变，适合看成功条件与撤销路径。

入口：/lab/radial-menu

Event Stacking

日历卡片拖到同一格会形成堆叠，前卡点击后换到后面；适合看空间拥挤时信息是否仍可识别。

入口：/lab/event-stacking

Discount Code Input

按钮到输入框经历 idle、editing、loading、applied 四个状态；适合看状态机是否比“加几个 CSS 动画”更清楚。

入口：/lab/discount-code-input

05

如何判断“手感”而不是被视觉效果带走

把一次浏览变成五个可观察问题。

观察问题通过信号失败信号
触发是否有来源反馈从点击/拖动/游标位置开始动画突然出现，用户不知道为何发生
中间态是否成立半开、半拖、半翻时仍能理解并继续操作只设计了 idle 与完成态
失败能否恢复放错位置、按遮罩、Escape 或修复动作有明确回路失败后只能刷新页面
信息是否仍可识别动效改变形态，但名称、状态和焦点不丢动画抢走对象身份
动作是否值得机制让理解更快或反馈更准确只是为了“看起来酷”增加等待
