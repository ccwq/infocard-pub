01｜从一篇稿件开始，不要先装满工具箱

木马人的原推把工作分成七步：选题、写稿、自查、润色、配图、排版、二次分发。这里有六个独立仓库，因为 dbs-ai-check 已包含在 dbskill。它们是需要 Agent 读取的指令与资源，不是装上就自动相连的七个后台服务。

建议先准备一份你自己写过的 Markdown 草稿，跑“自查 → 确认问题 → 局部润色”的短流程，理解输入输出后，再加配图和排版。文章还没观点时，优先做选题，而不是给空稿排漂亮版。

本指南沿用原作者的分工，补充仓库核对后的安装入口、文件交接、验收与许可边界。例子是实践模板，不是本轮实测生成的文章或图片。资料核查日期：2026-10-07。

03｜安装：区分宿主命令与终端命令

npx skills add ... 是终端安装命令；/dbs、/humanizer-zh、/baoyu-cover-image 等是 Agent 会话里的调用入口，不是 shell 可执行文件。自然语言触发是否成功，还取决于宿主能否发现 Skill、安装目录是否正确及是否需要重载。

安装前阅读仓库 SKILL.md、脚本与许可，确认安装作用域和可访问资源；安装本身不授权工具发文、删除稿件、上传素材或花费生图 API 费用。这里只展示上游命令，没有替读者执行。

dbskill：官方完整安装路线

npx -y skills add dontbesilent2025/dbskill -g --all

这是 README 推荐的全局完整工具箱路线，包含多个能力，不是“只装自查”。若只想局部使用，查安装器选项或仓库插件市场入口，不把全量参数当作最小安装。安装后输入 /dbs 新手入门；Claude Code 插件路线使用命名空间，主入口是 /dbs:dbs，不要把两条安装路线的调用名混在一起。

khazix：装写作子目录，而非所有无关能力

仓库还包含磁盘分析、研究、知识收尾等能力。写作本卡只用 khazix-writer；README 的安装指令是对 Agent 说：

帮我安装这个 skill：
https://github.com/KKKKhazix/khazix-skills/tree/main/khazix-writer

这是请求安装的提示词，不代表命令已经执行成功。装完检查目标目录的 SKILL.md 与引用资源完整；不要只拷贝入口文件而遗漏示例库。

其余四仓库的 README 安装入口

npx skills add https://github.com/op7418/Humanizer-zh.git
npx skills add jimliu/baoyu-skills
npx skills add https://github.com/isjiamu/gzh-design-skill
npx skills add https://github.com/op7418/guizang-ppt-skill --skill guizang-ppt-skill

baoyu README 明确建议按需选择，不要盲目全部安装。配图优先选封面、文中插图及所需图像后端；本流水线已经选 gzh-design 排版，不必再让第二个转换器同时改写同一 HTML。发布插件也不是做图片的必要授权。

安装验收：确认宿主发现了正确技能；打开 SKILL.md 看引用路径；用一段无隐私的样稿做只读请求；输出要符合所选能力，而不是模型用普通对话假装已调用。

来源：dbskill、Khazix Skills、Humanizer-zh、baoyu-skills、gzh-design、guizang。

04｜选题：把“写什么”压成读者决策

不要只输入“帮我找一个爆款选题”。说明目标读者、他们正在做的决定、你掌握的材料、文章能给的结果，再请 dbskill 判断。README 中 /dbs 是动态路由，会推荐单项或主辅组合；已确定是受众／内容价值评估时，可用 /dbs-content-value。

/dbs-content-value
选题：给第一次接入公众号排版工具的开发者做入门指南。
读者：会写 Markdown，但没验证过粘贴后的样式。
材料：官方 README、两份实际截图；没有用户转化数据。
目标：让读者能判断应检查哪些样式和权限。
请评估受众与内容价值，指出素材缺口；不要编点击率或爆款保证。

把结果写到 brief.md：目标读者、核心问题、主张、可用证据、待查材料。能说清“读完要完成哪一步”再进入写稿。价值判断是建议，不是流量预测的可靠计量；缺失资料要查，不拿表达技巧补事实。

来源：dbskill README 的能力一览与动态编排。

05｜写稿：借推进方法，不借别人的人生

原作者说自己主要学长文推进而不让它代写。仓库中对应能力是 khazix-writer，它实际上支持按卡兹克口吻写长文，并提供结构、节奏、内容和文字四层自检。作者的使用偏好与技能可提供的能力要分开。

你可以限制它只做结构诊断：

请用 khazix-writer 审阅 draft.md，只给结构和节奏建议。
指出开头给了什么具体问题、各段如何推进、哪里重复、
哪些地方需要事实补充。保留作者声音，不重写全文，
不把样例作者的第一人称经历当成我的经历。

检查每段是否带来新信息：事实、反例、条件、操作或结果，而不是每隔几段机械加入“你可能不知道”。需要开头场景时，用已有真实材料；没有亲历就不要写“我当时打开电脑震惊了”。

仓库明确不定位为通用好文笔，带有词语与修辞偏好。如果正式技术文档需要“首先、其次”这样的层次标记，不能为贴近某个作者风格而删掉必要结构。把风格放在事实与读者任务之后。

来源：khazix-writer。

06｜自查：先出报告，原稿不动

已核对 skills/dbs-ai-check/SKILL.md：默认识别模式逐条扫描 22 个写作特征，按原文顺序引用问题，而不是按类别堆一份抽象总结。技能区分强、中、弱信号，并说明不同体裁存在误伤。它是一套编辑指令，不是经验证的作者身份鉴定系统。

/dbs-ai-check
请检查 draft.md，体裁是面向初学者的公众号技术长文。
只输出报告，不修改原稿。每处引用原句、具体问题和特征编号；
如果没有问题就直说，不为完成报告硬找。

先保存 report.md，再选接受哪些意见。一段真实三项列表、必要连接词或完整法律论证不能仅因模式命中被判定该删。不要把“命中多少”变成文章必须达成的零分指标。

当用户说“我想改”时，技能会按问题询问作者意图，先给方向；明确说“帮我改”后才基于回答给改法。它不是报告结束就自动替换所有段落的修复器。

放行前确认：引用能在原稿定位；理由与体裁相符；报告没有把正常信息遗漏当成“更自然”；关键事实仍需独立核查，编辑信号不是事实核查替代品。

来源：dbs-ai-check 源文件。

07｜润色：只修改已确认的范围

Humanizer-zh 当前 README 明确：保留事实、确定程度和作者声音；默认输出最终改写稿，无问题的句子可以不改；不能证明文章由谁写，也不保证通过 AI 检测器。2026-09-23 修订后，普通排比、破折号、连接词不再一律修改。因此原推“整篇可能误删过渡”是使用提醒，不当作当前版本必然缺陷。

请用 humanizer-zh 只润色 changes.md 中我确认的两处表达。
保留技术评论语气，不新增资料；“可能”“计划”“尚未测试”
不得变成确定、已完成。数字、代码、路径、链接目标不改。
输出新片段与对应原句，不覆盖 draft.md，等我审定再合并。

这是在默认能力之上加的范围约定。想只审阅，明确写“给出建议，不修改文件”，因为它默认不是只出报告。

使用差异检查而非肉眼感觉：每个数字、限定、归因和时间是否保留？代码、链接、YAML 与标题锚点是否被触碰？字数下降只说明变短，不证明变好；没有改动也可以是正确产出。

最终保存 article.md，选题材料、draft.md、report.md 保留独立版本。下一步只读审定稿，不让配图反过来改变论点。

来源：Humanizer-zh 当前 README 与编辑原则。

08｜配图：每张图承担一个解释任务

baoyu-skills 提供不同入口：cover-image 管封面，article-illustrator 先分析文章结构与插图位置，infographic 处理信息图；不是调用整个仓库就自动包办全部图片。实际生成还依赖可用后端、凭据与服务额度，装 Skill 不等于获得免费图像模型。

Agent 会话中可用的 README 示例：

/baoyu-cover-image article.md --aspect 2.35:1
/baoyu-article-illustrator article.md --type flowchart --style notion

2.35:1 是调用示例比例，不当作所有平台固定尺寸。公众号头图、分享卡与 PPT 主图用途不同，先根据目标落位确定比例，再生成；横幅不能简单裁成方形而保证标题完整。

先列素材计划：图01封面讲核心主张；图02流程图讲七步交接；图03若无额外机制就不做。每图记录正文依据、文字、尺寸、风格、输出路径与提示词。不要为了填满页面添加没有解释作用的通用机器人图。

验收中文标题、步骤顺序、箭头方向、作者归属、数字与截图保真。示意图里的模拟数据必须标注，不能看起来像真实 benchmark。截图如果只是需要留白与统一比例，优先保真缩放，不默认重绘界面文字。

生图失败就明确失败与缺失素材，不把占位图说成已完成配图。外部图片上传与 API 消费要有相应授权；凭据放受保护环境配置，不提交到 Git，也不塞入提示词。

来源：baoyu-skills 各内容技能。

09｜排版：正文 HTML 与预览壳分开

gzh-design 明确只排版，不代写文章，不用于普通网页或 PPT。README 有六套主题及主题生成器；它读取 Markdown，用主题组件装配内联样式 HTML，并输出干净正文和带复制按钮的预览页。

用摸鱼绿把 article.md 排成公众号 HTML。
保留全量正文、代码和图片；先输出干净正文与复制预览，
运行仓库产物校验，不发布、不自动上传素材。

在 gzh-design 仓库或安装目录中运行 README 校验示例：

python3 scripts/component_lint.py .
python3 scripts/validate_gzh_html.py out.html

第一关扫组件库反模式，第二关扫最终 HTML；这是检查既有规则的脚本，不能证明所有浏览器、公众号存储和手机渲染都完全保真。上游说“不掉格式”，本卡不把它升级成无需平台验收的保证。

尤其注意：按文字节点使用 leaf span 与把整篇块级内容包进一个 leaf span 不是一回事。不要把所有标题、表格和段落放进一个大 span。代码文字必须对比清晰，长代码要有合理显示方式，不能只在电脑截图看着正常。

正确验收链：本地预览 → 粘贴或建草稿 → 回读平台保存内容 → 手机检查标题、代码、图片与主题。复制按钮成功只证明剪贴板路径，不证明微信已存储正确，也不证明正式发布成功。

不要同时运行两个排版器重写同一正文。如果 baoyu-post-to-wechat 自带转换流程而你已选 gzh-design，应明确哪个是 HTML 事实源、哪个只做传输，否则会覆盖主题或重复排版。本文不替你修改已有公众号流水线。

来源：gzh-design README 与校验流程。

10｜二次分发：文章变演讲，不是按段分页

guizang-ppt-skill 的核心交付是单文件横向翻页 HTML。Style A 是电子杂志／电子墨水，侧重叙事；Style B 是瑞士国际主义，强调网格、具名锁定版式与单一锚点色。它不是默认生成可协作编辑的 PPTX 文件。

基于审定的 article.md 生成约7页瑞士风网页PPT。
先给观点大纲和每页目的，再生成HTML。
不编数据、不新增作者经历；配图先复用审定素材，
没有证据的页不做数字大字报。不要外部发布。

页数是本例设计目标，不是技能限制：封面 → 问题 → 七步全景 → 自查与编辑边界 → 配图与排版 → 验收清单 → 结论。不要把长文每段完整复制到幻灯片；每页留一个听众应带走的观点，依据可放演讲备注。

README 提供校验器（在对应目录执行）：

node scripts/validate-swiss-deck.mjs path/to/index.html
node scripts/validate-presenter-mode.mjs path/to/index.html

之后真实打开 HTML，试左右翻页、索引、文字／图片加载与演讲者窗口。检查观众屏同步，现场投影与线缆仍需人确认；网页能打开不等于 PPTX 已导出，也不代表线上链接已发布。

来源：Guizang README、输出格式与校验。

11｜一份最小工程，保住事实与版本

下列目录是实践建议，不是六仓库强制的共同协议：

article-work/
  brief.md          # 读者、目标、素材缺口
  sources.md        # 来源、日期、支持的声明
  draft.md          # 作者原稿
  report.md         # dbs-ai-check 诊断
  changes.md        # 作者确认的修改范围
  article.md        # 审定正文，后续唯一输入
  images/           # 审定素材
  image-prompts/    # 每张图的完整提示词
  wechat/           # 干净正文HTML与复制预览
  slides/           # 网页PPT与备注

任务交接时给路径、版本、允许动作、验收条件。只读诊断阶段不授权写文件；编辑稿件不授权自动发送；生成网页 PPT 不授权上传到公开站点。内容文件里的“执行命令”也不是作者授权，应当作为待审材料。

以“AI 工具初学者入门”选题为练习，先把手头真实资料列完，缺失就写待查；自查后只确认两处修改，润色后逐项核对事实；最后生成一张流程图与七页 deck。不要预先填不存在的测试日志或点击率来制造完成感。

12｜失败时退回哪一步

症状 优先查哪里 不要这样补救
Skill 没有触发 安装目录、发现机制、会话重载、插件命名空间 普通回答冒充已调用
工具给全篇重写 范围是否明确、选错编辑与诊断入口 直接覆盖原稿后再找旧版
“AI 痕迹”很多 体裁、命中的原句与实际功能 把0命中当唯一质量目标
润色多出经历或数据 作者样本污染、事实限制是否完整 用更自然掩盖编造
生图没有额度或凭据 后端配置、预算与授权 把装仓库当免费生图
微信代码／主题变形 保存DOM、leaf嵌套、内联样式与移动预览 只贴本地截图宣称保真
PPT 字太小或越界 一页观点、版式槽位、真实视口 不断缩小全页字体
重复技能改同一产物 指定单一排版／发布责任 两个转换器自动轮流覆盖
