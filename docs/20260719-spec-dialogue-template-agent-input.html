Spec 写不到位，Agent 再强也救不了你

你给 Agent 发的第一份 8 项清单——结构化输入替代 prompt 技巧
龙鳞 @LonglinX · 认证账号 📅 2026-07-18 📖 23.7K 阅读
方法论
沟通协议
01

背景：为什么 Agent 总是返工

作者让一个 Agent 写行业调研，只说了一句话：

"帮我看看 AI 在企业落地。"——原始需求（无效输入）

结果：5 分钟吐了一屏，全是废话：

  • 开头一段"AI 是大势所趋"的科普
  • 中间几段"百度百科风格"的行业概览
  • 结尾一句"具体情况还需结合实际"

改了 4 次，越催越原地打转。Token 用了不少，事情一件没办成。

这不是 Agent 的问题。是输入的问题。
02

核心理念：Spec 是沟通协议，不是 prompt 技巧

写 Spec 是一种沟通协议——你按协议填 8 项，Agent 按协议交付结果。

协议的好处：你不用关心 Agent 内部怎么想，Agent 也不用猜你想要什么。

⚠ 一句话需求的隐性成本

一句话需求 = 让 Agent 替你猜 100 个决策（格式 / 深度 / 视角 / 历史 / 案例 / 风格 / 长度 / 红线 / 失败处理 / 产出）。每少定一个，输出就偏一格。

这就是"高利贷"——短期舒服，长期破产。

03

8 项必填清单（可复制直接用）

最低 3 项核心必填（目标 / Done / 约束），填了 Agent 就能跑；其余 5 项用默认值。

1目标 What —— 给谁看 / 做什么
受众__(岗位 / 角色 / 场景)__
输出类型__(报告 / 文章 / 表格 / 代码 / 推文)__
必含项至少 3 个，缺一不可
不准出现__(红线)__
2完成标准 Done —— 什么算"做完了"
可验证☐ 可机器验证（如 JSON 含 verified:true）
☐ 可人眼验证（如不少于 800 字）
☐ 可截图验证（如表格清晰可读）
3约束 Constraints —— 不能踩的红线
风格__(简洁 / 详细 / 案例驱动)__
长度__(≤ N 字 / N 段)__
不准做__(红线)__
4上下文 Context —— 只放必要的
背景__(1-2 句)__
已知输入__(文件路径 / 链接)__
已完成__(前几步已做)__
5失败处理 —— 歧义时怎么办
选项☐ 直接假设并继续（默认）
☐ 停下来问我
☐ 报错退出
6–8产出形式 / 紧急程度 / 备注
存到__(路径)__
回我__(完整内容 / 路径 / 截图)__
紧急度☐ 高 / ☐ 中 / ☐ 低
备注__(可选:历史经验、相关工具)__
04

实测效果：填得越完整，Token 消耗越低

作者本人一年实践数据（同样任务、同样模型、同样硬件）：

输入方式 平均 Token 平均返工次数 一次完成率
一句话需求 18,500 3.2 次 12%
填 3 项 Spec 9,200 1.4 次 51%
填全 8 项 Spec 5,400 0.3 次 87%

数据来源：作者本人一年实践记录。效果因任务类型、模型和场景不同而异。

07

结论：Spec 的价值边界

✓ Spec 能做到
  • 结构化输入，减少 Agent 猜测
  • 降低 Token 消耗和返工次数
  • 可验证的完成标准让 Agent 知道何时停止
  • 写 Spec 本身是思维训练
⚠ Spec 不能保证
  • 作者 Token 节省数据为个人实践结果，效果因任务而异
  • 8 项清单不是万能模板，仍需按场景裁剪
  • Agent 的底层能力仍是上限
  • 填写 Spec 本身需要思考成本
