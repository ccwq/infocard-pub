OpenSpec 是 GitHub 增长最快的 AI 编程规范框架。它将软件工程最佳实践固化为 Spec-Driven Development（SDD）——让 AI 编程从「昂贵的随机数生成器」变成可追溯、可验证、可复用的工程流程。Y Combinator 入选项目。

01核心痛点：AI 编程为什么需要规范
❌ 传统 AI Coding 缺陷
  • 上下文丢失 — 每次新会话从零开始
  • 跨对话冲突 — 不同建议相互矛盾
  • 风格不一致 — 无法适配既有代码库
  • 无法追溯 — 谁改了什么、为什么改，全靠猜
✅ OpenSpec 解法
  • 持久化上下文 — 规范存储在项目内
  • 四件套文档 — proposal / specs / design / tasks
  • 版本化变更 — 每次改动都是可追溯的 commit
  • 严格校验 — verify 命令确保实现匹配规范
Vibe Coding → SDD 随机数生成器 → 工程流程 proposal.md 提案文档 tasks.md 任务清单
02SDD 5 阶段详解
阶段斜杠命令核心产出
探索 Explore /opsex:explore 编辑器内头脑风暴，梳理技术方案思路
规划 Plan /opsex:expose 四份文档：proposal + specs + design + tasks
实施 Apply /opsex:apply AI 严格按照 tasks.md 执行代码编写
校验 Verify /opsex:verify 逐项检查实现与规范的一致性
归档 Archive /opsex:archive 清理工作区 + 更新全局规范沉淀上下文
proposal.md — 阐述修改根本原因 specs/ — 边界与异常场景定义 design.md — 架构与技术方案 tasks.md — 带路径和验证步骤
03目录结构与规范体系
openspec/
├── specs/          # 当前系统行为规范（只读事实来源）
│   ├── api-contract.md
│   └── error-handling.md
├── changes/        # 变更提案（四件套）
│   └── [change-name]/
│       ├── proposal.md   # 为什么改
│       ├── specs/        # 怎么改（边界+异常）
│       ├── design.md     # 架构方案
│       └── tasks.md      # 谁来干（带路径）
└── config.yaml     # 项目上下文配置

.claude/commands/openspec/
├── apply.md
├── archive.md
└── proposal.md
openspec/specs/ — 事实来源（只读） openspec/changes/ — 变更记录（追加） .claude/commands/ — AI 行为规范
04命令体系：编辑器斜杠 + 终端 CLI
编辑器斜杠命令
  • /opsex:explore 探索对话
  • /opsex:expose 规划产出
  • /opsex:propose 提案生成
  • /opsex:apply 实施变更
  • /opsex:verify 校验实现
  • /opsex:archive 归档清理
用于高层对话、文档生成与决策记录
终端 CLI 命令
  • openspec validate all strict 严格校验
  • openspec change propose 新建提案
  • openspec change delta 查看差异
  • openspec instructions 上下文生成
  • openspec stores pull 拉取规范
  • openspec workspaces sync 工作区同步
用于精确执行、验证与批处理
# 安装（Node.js ≥ 20.19.0）
npm install -g @fission-ai/openspec@latest
openspec --version

# 项目初始化（自动检测 AI 工具）
cd your-project && openspec init

# 新建变更提案
openspec change propose

# 严格校验所有规范
openspec validate all strict
05AI 工具兼容与适用场景
✅ 强烈推荐场景
  • 大型代码库多轮迭代开发
  • 团队协作保持代码风格一致
  • 需要可追溯的变更记录
  • 微服务架构共享工程规范
  • AI 辅助代码审查与验收
❌ 不适合场景
  • 一次性简单脚本生成
  • 无本地 Node.js 环境
  • 已有成熟 CI/CD 质量门禁
  • 强离线隐私要求（需联网）

06v1.5.0 新功能：Stores 跨仓库规范管理

  • 独立规范仓库 + 配置文件引用
  • 多仓库微服务共享同一套工程规范
  • 按需精准获取，无需重复定义
配套功能
  • Workspaces（beta） — 多仓库本地视图
  • Context Store（beta） — 持久化上下文管理
  • OpenSpec-cn — 官方中文版发布
stores pull/push — 规范拉取推送 workspaces sync — 工作区同步 context-store — 上下文持久化 无需 API 密钥
