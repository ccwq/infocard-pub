🔍第二层 · 核实：三个条件满足其一才叫醒 Agent
  • 触发一厂商自己的账号说了。
  • 触发二有两个不同的来源都在说。
  • 触发三帖子里直接链了厂商自己的页面。
  • 反例只有一个社区帖子孤零零在说的，先放着不管，等第二个来源。雷达找到的只是线索，线索不等于羊毛。
反假官网路径

核实 Agent 只认厂商自己的页面，还得确认这个页面真是这家厂商的——假官网上的活动页真不少。所以它必须从厂商官网的首页、或者它的官方账号出发，一路点到这个活动页，确认是真的才可以。

再过一关：「值得领」

以下直接毙掉（作者原话：都是踩坑踩出来的血泪经验）：

  • 只能用很老的模型，比如 GLM-4.7、DeepSeek v3 之类——没意义。
  • 营销合并数字：很多营销文章把「每个模型各送 100 万 Token」加在一起写成「送 7000 万 Token」，核实的 Agent 直接毙掉。
  • 各种返利和邀请链接、API 中转站、二手积分、共享账号、接码多开。
  • 只给付费用户的、要先充值才送的——大家领不到。
🛠️第三层 · 巡查：原话对照，每天两遍

羊毛上架以后，厂商随时可能改规则、提前结束，或者额度早就被领完了。所以每一条都要有人盯着——这部分基本全是 Agent 自动化在跑。

  • 上架时，从厂商页面上照抄一到三句原话：送多少、怎么领、到哪天。
  • 专门有个脚本每天拿原话去对照两次。
  • 原话连着两次都找不到了，或者页面上新冒出来「暂停」「结束」这一类字眼，马上派一个 Agent 去复查。
  • 每天晚上，一个 Agent 照着一本巡检手册，把页面上的每一条 Token羊毛都重新过一遍。
  • 第二天早上，新上架的和换了链接的，列成一张单子发给作者和另一个 Agent 确认——作者每天就像批奏折一样扫一眼那张单子。
💡理念与边界：新闻的噪声，正是需求的福利

过去：新闻视角

  • 厂商发福利＝广告＝噪声
  • 绝对不该出现在精选列表里
  • 为了剔除这些广告，花了很多力气做剔除规则

现在：需求视角

  • 这正是很多人每天在群里互相提醒着找的东西
  • 把剔除规则反过来＝「什么样的资讯是福利公告」的识别器
  • 于是有了 Token羊毛
