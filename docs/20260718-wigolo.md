# Wigolo：本地优先 Web Intelligence MCP 使用指南

> **来源边界**：仅依据 Wigolo 官方仓库本地副本的 `README.md`、`mcp.json`、`package.json`、`SECURITY.md` 与 `src/` 源码整理。项目 README 标记为 **public beta**；许可徽章标记为 **AGPL-3.0**。

## 它是什么

Wigolo 是给 AI 编程代理使用的本地优先 Web Intelligence MCP Server。官方 README 将其能力概括为：搜索、获取网页、爬取、内容提取、缓存、发现相似内容、研究与自治收集循环。

- 要求：**Node ≥ 20**、约 **1.5 GB** 可用磁盘；支持 macOS、Linux、Windows。
- README 表述：核心工具无需 API key，工具触及的内容留在 `~/.wigolo/`。
- 这不代表“完全离线”：抓取 URL 会访问相应站点；启用可选云端 LLM 合成时会使用你配置的 provider。

## 快速接入

```bash
# 给一个或多个受支持 agent 执行无人值守完整初始化
npx wigolo init --agents=claude-code,codex

# 健康检查
npx wigolo doctor
```

`init` 默认下载浏览器引擎与设备端模型、执行健康检查并输出组件状态。若要延后下载，可加 `--no-warmup`；README 说明组件下载失败不阻断 MCP 接线，未就绪组件会在首次使用时重试。

### 内置支持的 agent

`--agents` 支持逗号分隔的：

- `claude-code`
- `cursor`
- `codex`
- `gemini-cli`
- `vscode`
- `windsurf`
- `zed`
- `antigravity`

## 直接使用 MCP

对其他 MCP 客户端，先初始化本地引擎：

```bash
npx wigolo init
```

再将 MCP 命令指向：

```bash
npx wigolo mcp
```

官方 `mcp.json` 给出的通用 JSON：

```json
{
  "mcpServers": {
    "wigolo": {
      "command": "npx",
      "args": ["-y", "wigolo"]
    }
  }
}
```

README 说明不带子命令的 `wigolo` 默认也启动 MCP stdio server；源码 `src/cli/mcp.ts` 则确认 `wigolo mcp` 启动 MCP stdio 路径。配置键与文件位置会随客户端不同而变化：例如 VS Code 用 `servers`，Zed 用 `context_servers`，Codex 用 TOML。请以 README 的 **Manual MCP setup** 表格为准。

## MCP 工具

`src/server.ts` 注册了这些工具：

| 工具 | 用途 |
|---|---|
| `search` | 网页搜索 |
| `fetch` | 获取单网页 |
| `crawl` | 爬取 |
| `cache` | 缓存操作 |
| `extract` | 内容提取 |
| `find_similar` | 查找相似内容 |
| `research` | 研究工作流 |
| `agent` | 自治收集循环 |
| `diff` | 内容差异 |
| `watch` | 监视 |

README 将 `search`、`fetch`、`crawl`、`extract`、`cache`、`find_similar` 列为无需 API key 的核心工具。

## 配置与生命周期

- `research`、`agent` 和 `search format=answer` 若要撰写最终答案，需配置可选 LLM provider：`WIGOLO_LLM_PROVIDER` 与对应的 key。应通过私有 shell/MCP 环境变量提供，避免写进公开仓库。
- 检查环境：`npx wigolo doctor`。
- 清除设置：`npx wigolo config --uninstall --yes`。
- `serve` 是不同于 stdio MCP 的 HTTP 服务模式。官方 README 表示：若绑定到非 loopback 地址，须设置 token；更硬化的部署可使用 `WIGOLO_API_TOKEN_FILE`，避免 token 出现在进程环境中。

## 隐私、网络与安全边界

### 本地优先不等于没有网络

README 的 `~/.wigolo/` 声明描述本地缓存 / 数据定位；但 fetch、crawl 等访问给定 URL，必然向目标站点发起网络请求。配置外部 LLM 合成时，也会按 provider 配置发送必要请求。

### SSRF 与远程内容

`SECURITY.md` 将下列范围列为特别关注：

1. 可选 watch/webhook 子系统的 SSRF 防护与 URL 验证；
2. 可选云 LLM key 的凭据处理（OS keychain / 加密文件）；
3. 抓取或爬取的远程内容影响宿主机的路径。

源码 `src/daemon/rest/target-guard.ts` 显示：在非 loopback 地址绑定的 serve 模式，默认拒绝 `localhost`、`127.x.x.x`、`::1` 等 literal loopback 目标，除非设置 `WIGOLO_SERVE_ALLOW_LOCAL_TARGETS=1`。源码注释明确这一检查不宣称覆盖 DNS rebinding。

### 漏洞报告

不要公开开 issue。请使用仓库 Security 标签页的 **Report a vulnerability** 私密提交：<https://github.com/KnockOutEZ/wigolo/security/advisories/new>。官方安全策略说明：public beta 期间，安全修复针对最新已发布版本。

## 排错

1. **初始化 / 组件失败**：确认 Node ≥ 20 与约 1.5 GB 可用磁盘，执行 `npx wigolo doctor`，按初始化输出的具体组件提示处理；网络受限时可使用 `--no-warmup` 延后下载。
2. **Agent 没有工具**：核对 agent 是否在内置列表；否则按手工 MCP 配置接入。核对 `npx wigolo mcp` 与客户端特定的配置文件、键名。
3. **研究或答案合成无法工作**：核心检索无需 key；但最终答案合成需要正确设置 `WIGOLO_LLM_PROVIDER` 与对应私有 key。
4. **serve / watch 涉及安全问题**：不要将服务暴露到非 loopback 地址而不设置 token；不要为图方便放宽本地目标或私网访问限制；疑似漏洞走私密 Security Advisory。
