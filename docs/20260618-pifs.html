πfs：把文件映射到 π 的 FUSE 实验

它不是“100% 压缩”的严肃文件系统，而是一个技术上可运行、概念上极具反讽的实验：用元数据目录记住索引，用 BBP 算法生成 π 的十六进制位，把“所有可能的文件都存在 π 里”做成一个可挂载的系统。

Core定位

它是“数据自由”的反讽系统

README 的核心句不是“提高性能”，而是“Never worry about data again”。仓库把极限命题做成一个可挂载的文件系统实验，技术价值在于把概念玩笑变成了真实的系统结构。

Build / Use

构建路径很朴素，使用接口更朴素

安装依赖后按 `./autogen.sh → ./configure → make → make install` 走；挂载时只要给元数据目录和 mountpoint，真正的数据则通过 π 的位序列去“查”。

Technical core

两个模块各司其职

`src/πfs.c` 负责 FUSE 回调、路径映射和元数据目录；`src/piqpr8.c` 实现 BBP 算法，生成 π 的十六进制数字字节流。一个管文件系统边界，一个管“π 里有什么”。

Why it works

逻辑依赖的是 π 的“全覆盖”假说

README 明确把论证建立在 π 可能是 normal / disjunctive sequence 的假说上：若十六进制位足够均匀，那么所有有限文件都能在 π 中找到。技术上这不是证明，而是一个把数学命题转成工程叙事的思路。

Implementation detail

读取不是“解压”，而是按字节查找

README 写得很直白：为了性能，每个字节分别去 π 里查找，而不是试图一次性匹配长文件。这也暴露了系统的本质——它不是高效存储，而是一个极端概念验证。

Reality check

真正的价值在概念，不在可用性

仓库当前语言以 C 为主，辅以 M4 / Shell / Makefile，说明它是经典 FUSE 工程；但 README 还专门提示最新方向在 `philipl/inferencefs/`，意味着 pifs 更像里程碑式实验，而不是终局产品。
