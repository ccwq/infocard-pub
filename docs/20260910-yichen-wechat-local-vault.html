yichen-wechat-local-vault：把微信本地数据变成可查询的私有资料库

它不是“把微信上传给 AI”，而是一套在本机处理已授权数据的 Skill：Mac 4.x 全量/增量解析，统一查询聊天记录、联系人、群聊、朋友圈、收藏夹和附件索引；Windows 只接受已解密的离线明文快照，并且仍处于实验性兼容阶段。

隐私提醒：本卡讨论的是高敏感本地通信数据。只处理你有权访问的内容；密钥、明文库、完整 wxid 和未脱敏导出不得进入项目目录、网盘或聊天窗口。

01

先判断：你要处理哪一种数据来源？

ROUTE
A

Mac 当前账号

本机微信数据库、密钥、全量解密或增量刷新。支持朋友圈、收藏夹、群聊和导出。

B

Windows 快照

用户提供已授权的离线明文快照；先 validate，再 chats，最后 history/search/export。

C

不做的事

不自动点击微信界面，不处理第二微信容器，不把 Mac 流程猜测套到 Windows。

D

安全底线

密钥、明文库、manifest 和导出报告留在本机私有目录，不复制进项目或聊天。

授权边界：只处理你有权访问的数据。联系人、群聊、朋友圈和收藏内容都包含第三方隐私；“本地”不等于“可以任意分析或分享”。
02

安装后的第一条路径：先检查，再解密，再查询

MAC FIRST RUN

日常使用优先走 vault_cli.py；它默认 JSON 输出，适合被 Agent 调用，加 --format text 才适合人工查看。首次运行不要直接全量抓取，先检查本机有哪些库。

# 1. 只列数据库，不启动微信界面 python3 scripts/extract_keys.py --list-dbs # 2. 已有抓取日志时，先尝试复用 key python3 scripts/extract_keys.py --match-only --targets all --reuse-log # 3. 只有复用失败或缺库时才抓新 key python3 scripts/extract_keys.py --targets all --duration 240 # 4. 首次建立私密明文 vault python3 scripts/decrypt_all_dbs.py --mode full # 5. 之后日常只做增量 python3 scripts/decrypt_all_dbs.py --mode incremental
验证标准：全量/增量命令结束后，要看 manifest 的解密数量与失败项；“命令退出 0”不能单独证明目标数据库都已经可用。

04

四个可执行场景：查、导出、复盘、沉淀

USE CASES

业务沟通前

先用 history/search 检索与某个联系人或客户的历史沟通，再基于时间范围复盘合作痛点。只引用必要片段，不默认输出整段私聊。

大群日报

先用 digest-source 落地 sources/*.json 与 sources/*.md，再写日报；不要把几百上千条原始消息直接塞进对话。

收藏夹找资料

用 favorites 按类型与关键词定位文章、文件、卡片或视频，导出到用户指定目录，避免把整个收藏库复制到项目。

朋友/朋友圈想法

用 moments 按联系人、时间、关键词读取；输出内容素材时保留来源和授权边界，不把第三方碎片直接当作可公开素材。

群聊精华的正确顺序：增量刷新 → 确认唯一群聊 → digest-source → 读取素材 → 写摘要 → 确认完成后更新 history。素材包不会自动更新 history，避免半成品成为下一次“从上次继续”的锚点。
05

群聊素材包：为什么要先落文件？

DIGEST SOURCE

digest-source 会在 {data_root}/{group_id}-{group_name}/ 下创建可复核的素材目录：

sources/*.json机器可读消息、统计和路径
sources/*.md人工可读素材稿
profiles/普通版群友画像
profiles-roast/毒舌版画像，必须分开
imgs/*.txt图片说明扩展点；无文件就不能编造画面
python3 scripts/vault_cli.py digest-source "群名" --start "2026-05-01" --end "2026-05-14" --format text python3 scripts/vault_cli.py digest-source "群名" --since-last --data-root ~/Documents/wechat-digests --format text

“图片内容不可见，根据上下文推断到这里围绕一张图片讨论”是允许的证据边界；把不存在的图片描述写成确定事实是不允许的。

06

Windows 路径：只读快照，不走 Mac 解密链

EXPERIMENTAL

Windows 模式使用同一入口，但它接受的是用户提供的、已授权的离线明文快照。它不访问 Mac 配置、不抓 key、不解密、不做增量刷新，只接受验证器支持的明文结构。

python3 scripts/vault_cli.py snapshot --snapshot /path/to/authorized-snapshot validate python3 scripts/vault_cli.py snapshot --snapshot /path/to/authorized-snapshot chats # 选出精确 chat_id 后再查询 python3 scripts/vault_cli.py snapshot --snapshot /path/to/authorized-snapshot history --chat-id "精确ID" python3 scripts/vault_cli.py snapshot --snapshot /path/to/authorized-snapshot search --query "关键词" python3 scripts/vault_cli.py snapshot --snapshot /path/to/authorized-snapshot export --chat-id "精确ID" --format markdown
兼容性仍是实验性：缺快照、schema 不兼容或存在 WAL/SHM 时停止；不要因为当前运行在 Mac 就猜测 Windows 版本一定可用。
07

排障、隐私与许可：上线前必须看

BOUNDARIES
  • key 问题：先 list-dbs，再 match-only/reuse-log；不要一上来启动界面或抓全量。
  • 性能/规模：大群先落素材文件；不要把长时间范围原文全部塞进 Agent 上下文。
  • 明文边界：数据库、keys、manifest、增量状态、导出报告均放私有目录；不要同步、分享、复制到项目工作区。
  • 第三方隐私：联系人、群成员、朋友圈内容不是“你自己的数据”；分析和公开发布都需有相应授权。
  • 第二容器：默认只处理官方第一个 com.tencent.xinWeChat，不自动处理双开/第二微信。
  • 许可：仓库使用 Personal Learning and Non-Commercial Use License；个人学习、研究和非商业个人工作流可用，商业/客户交付/付费服务/企业内部工具包等需作者书面授权。
  • 第三方 notices：仓库另有 THIRD_PARTY_NOTICES.md；不能把整个仓库简单称为 MIT 或完全自由商用。
安全判断：这类工具的价值是本地查询，不是绕过第三方控制。只对自己有权访问的账号、数据库和快照操作；不输出密钥、完整 wxid、原始私聊库或客户数据。
08

四个上手玩法：先查、再提炼、最后导出

PRACTICAL ROUTES

新增来源帖把这个 Skill 的价值压缩成四类任务。它们都应从已授权、已解密的本地 vault开始；“让 AI 读微信”不是授权绕过，也不是把整库默认交给模型。

① 客户沟通前

先用 history 或 search 限定联系人、关键词和时间范围，提炼合作痛点或待办。只带必要片段进入下一步，不要把半年完整私聊复制给 Agent。

② 大群日报

先增量刷新，再用 digest-source 生成 sources/*.json 与 sources/*.md。先确认群名对应唯一会话，再写摘要；历史锚点要在人工确认后更新。

③ 收藏夹找资料

按类型和关键词查文章、文件、卡片或视频：

python3 scripts/vault_cli.py favorites --type article --query "关键词" --format text

找到目标后再导出到用户指定目录。

④ 朋友圈/想法提取

用 moments 限定联系人、时间和关键词，输出时保留“素材来源”和“不可公开”标记。第三方发言、图片和群文件不能因为已在本机就自动获得公开许可。

推荐顺序：status → sessions/contacts 确认目标 → 时间/关键词过滤 → 只读查询或素材包 → 人工检查 → 指定目录导出。任何一步目标不唯一，就先停下来确认，不要扩大读取范围。
