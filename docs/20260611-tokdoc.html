§01
核心定位

本地私密文档管理器，无需联网

上传 HTML / PDF / Word，自动生成本地短 URL，全部数据存储在本地 SQLite，无需外部依赖

📝 HTML 实时编辑

访问 /f812c6?edit=1 直接在页面中修改标题、段落、表格，600ms 防抖自动保存，自动生成版本快照

📖 PDF / Word 阅读

PDF 以阅读器方式打开；Word (.doc/.docx) 自动转 PDF 再阅读，Docker 内置 LibreOffice + Noto CJK 字体

📁 目录批量导入

浏览器批量导入目录，自动同步 CSS/JS/图片等相对路径附件，写入 /page-assets/<uploadId>/...

§02
安装入口

Docker 一键部署，本机 Node 也支持

依赖 espeak-ng 和 ffmpeg，pip 或 Docker 两种启动方式

# Docker 启动（推荐，默认端口 18082） git clone https://github.com/yaojingang/yao-open-tools cd yao-open-tools/tools/TokDoc cp .env.example .env docker compose up -d --build # 自定义端口 TOKDOC_HOST_PORT=8088 docker compose up -d --build # 本机 Node 启动 npm install && npm run dev

默认访问地址

http://127.0.0.1:18082/ 文档索引页

http://127.0.0.1:18082/admin 后台管理

http://127.0.0.1:18082/healthz 健康检查

默认登录

用户名：admin

密码：tokdoc

可通过 .env 修改初始账号：TOKDOC_INITIAL_USERNAME / TOKDOC_INITIAL_PASSWORD

§03
核心功能

文档全生命周期管理

从上传到版本回溯，完整功能覆盖

🔔 目录监听

在"设置"填入容器可访问目录（如 /watch/html-inbox），保存后自动持久化监听并扫描入库

📊 访问统计

访问 /<slug> 自动统计访问次数，列表页显示目录名称后的访问计数

🗑️ 回收站

删除移入回收站，文件移至 data/trash/；可在回收站一键恢复，重新展示文档

📈 统计注入

在"设置"填入统计脚本，新上传文档自动注入该代码，用 TokDoc 标记包裹

🔄 版本快照

每次保存自动生成版本快照，存于 data/versions/，可通过 API 随时恢复任意历史版本

☁️ 线上同步

在"设置"的"线上绑定"填入同类程序 API 地址后，页面列表可一键上传 HTML 到线上，PDF/Word 暂不支持

§04
API 摘要

REST API 完整覆盖

文档 CRUD / 版本管理 / 监听目录 / 公开列表

文档管理

  • GET /admin/api/pages — 文档列表
  • POST /admin/api/pages/upload — 上传文件
  • PATCH /admin/api/pages/:id/content — 更新内容
  • DELETE /admin/api/pages/:id — 删除文档
  • GET /:slug?edit=1 — 编辑文档

版本与监听

  • GET /admin/api/pages/:id/versions — 版本列表
  • POST /admin/api/pages/:id/restore/:versionId — 恢复版本
  • GET /admin/api/watch-dirs — 监听目录列表
  • POST /admin/api/watch-dirs/:id/rescan — 重新扫描
  • GET /public/api/pages — 公开列表 API
§05
数据目录

本地文件系统存储结构

全部数据在本地，无需外部数据库

data/tokdoc.db

SQLite 数据库：文档元数据、账号、版本快照

data/pages/

生成后的本地页面，文件名含日期、短码

data/uploads/

上传源文件副本：HTML/PDF/Word + 附件

data/versions/

自动保存的版本快照，支持随时恢复

data/trash/

回收站文件，已移出可访问路径

html-inbox/

本地默认监听目录

§06
适合 / 不适合

本地私密文档 vs 需要协作的场景

yaojingang/yao-open-tools 工具集成员 · MIT License

✅ 适合

  • 个人笔记整理、内部私密文档分享
  • 小团队知识库、需要离线/内网部署
  • 需要版本快照和历史恢复的文档管理
  • Word 文件转 PDF 阅读

⛔ 不适合

  • 需要公网访问和多用户协作的文档平台
  • 大规模内容管理和复杂权限控制
  • 实时协同编辑场景
