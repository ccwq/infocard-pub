日常流程 · 四步出稿
PAGE 01

四步，从原稿到可粘贴的正文

1
粘贴文章第一行写标题，后面写正文；首次打开会显示一篇含图片的灰色示例，点一下编辑区才清空进入输入状态，示例不会被复制或导出。
2
选模板并调整在“更多模板”里挑一款，用工具栏加章节、图片、来源和列表；也能直接在预览里改字，改动会写回原稿，支持撤回重做。换模板不改原文。
3
检查预览可切网页版 / iPhone / Android 三种预览。点“复制排版”时，必须修正的问题会阻止复制，普通提示可检查后继续。
4
复制并粘贴到后台剪贴板只带正文 HTML 和纯文本，标题不包含在内；到公众号后台单独填标题、检查图片与排版后自己发布。

刷新就没了，先导出再动手

文章和本地图片只在当前页面内存里暂存，刷新、关闭或重新打开都会回到内置示例，没有账户也没有文章库。需要留底就先“复制正文”或下载 .wedraft.zip 文章包。

数据边界 · 文章不上传
PAGE 03

不注册、不绑号、不传稿

无账号无云同步不提供账号、云同步或文章上传服务；不请求 AppID / AppSecret / Token，也不需要公网 IP。
统计默认关闭0.2.0（2026-09-27 候选）新增默认关闭的网页操作与内容特征统计：用户主动允许才开启，可随时撤回，不采集文章原文。
只记模板偏好Cookie 里只有默认模板，不含文章内容；新版不读取、不迁移旧候选写入的 IndexedDB 草稿，也不碰 Mac 应用数据库。
外链图片仍会外连远程图片由浏览器向来源站点请求，CLI / MCP 不下载；用外部 AI 时稿件按该 AI 产品的数据政策处理。
Mac / CLI / MCP 无遥测本期不新增远程统计，也没有公开的 Mac 下载指标；Mac 应用离线可用，编辑、预览、复制都不依赖网络。
接入 AI · 两条路径
PAGE 04

先用 AI 整理，或者让 AI 直接排版

手工整理（不用装东西）

在网站「接入 AI」页复制产品的 Markdown 格式规则，连同原文交给任意 AI，让它保真整理格式，再把结果放回网页选模板、复制正文。整理结果需要自己核对。

自动排版（装一次）

接入 Skill / MCP 或 CLI 后，把已有 Markdown 交给 AI，一句话让它调用同行排版核心，产出 preview.html 与文章包，打开预览即可复制正文。

A
网页与 AI 共用一套模板同一版本的 CLI / MCP / 网页读同一份模板目录，AI 用「青岚」排出来的样式，与你在网页选「青岚」一致；改模板版本时文章包会明确拒绝不兼容版本。
B
一句话就够例：「用 WeDraft 的青岚模板排版这篇 Markdown，保留原文、链接和图片来源，给我可以复制富文本的预览。」
C
边界在哪WeDraft 的本地 MCP 不控制微信、不发布文章；有浏览器或剪贴板能力的宿主 Agent，才会在你授权后继续粘贴到指定草稿。
一键接入 · 一条命令
PAGE 05

把 CLI、Skill 和本地 MCP 一次装好

适合 macOS / Linux。Node 22.12+ 可用就直接用；缺失时安装器准备一份专用 Node 24 运行时，不要求 sudo、pnpm，也不拉源码仓库。

curl -fsSL 'https://wedraft.xiaoha.org/integrations/install.sh' | sh -s -- 'https://wedraft.xiaoha.org/integrations/'
只从 HTTPS 或 localhost 装安装器拒绝明文 HTTP 来源，并对 installer.mjs 做 SHA-256 校验；下载 Node 运行时同样核对官方 SHASUMS256。
写在哪工具进 ~/.local/share/wedraft/，Skill 进 ~/.agents/skills/format-with-wedraft/，并在 ~/.codex/config.toml 里登记名为 wedraft 的 stdio MCP 条目——改动前先备份，遇到冲突文件会停下而不是覆盖。
谁被自动登记目前只自动登记 Codex；其他本地 stdio 客户端用安装器生成的 mcp-client.json（命令与参数）自行配置。
装完立刻可用CLI 马上能用；已经在跑的 AI 会话需要重新加载工具才能看到 MCP 工具。安装器会打印可用命令，Skill 里带完整可执行路径。
装上之后 · 查状态 / 升级 / 卸载
PAGE 06

用 manage.sh 收口，不做黑箱安装

1
查状态sh "$HOME/.local/share/wedraft/manage.sh" status —— 离线只读，输出 JSON：release.version、sourceCommit、sourceDirty。版本号可能覆盖多个提交，要连源码提交一起比对。
2
升级manage.sh upgrade 复用记录的来源；换镜像站用 --base-url。升级写入失败可回滚，不会动你的文章。
3
卸载manage.sh uninstall 是保守卸载：导出目录、其他 MCP 配置和你自己的本地改动都保留。

localhost 只对同一台电脑有效

本地预览地址不能被云端 AI 访问，MCP 也只走 stdio、不开 HTTP 端口；正式网站的接入页提供公共安装入口。早期安装若没有 manage.sh，需要用原始命令带原来的自定义路径重跑——不要猜路径，也不要删掉记录来绕过冲突。

CLI · 三个子命令
PAGE 07

不想装 MCP，就用命令行

命令做什么关键参数
wedraft templates列出七款模板的标识与名称，判断 AI 该用哪个 ID--json
wedraft validate只做检查、不改内容：能不能直接复制、有没有必须先修的问题--input <article.json>、--json
wedraft render生成可复制正文、纯文本预览与文章包--input、--out <dir>、--template <id>
退出码当成判断条件0 可以直接复制、2 被内容问题阻断、1 输入本身不合法。把这三档接进脚本，AI 就不用「猜」排版能不能用。
管道友好--input - 从标准输入读取 ArticleInput JSON，便于和别的命令串联；加 --json 得到机器可读报告。
本地图片要重定位图片是 http(s) 链接时原样保留，复制后你手动重传；用本地相对路径时需配合 --asset-root，否则会被判为阻断问题。
render 产出 · 四个文件
PAGE 08

一次渲染，拿走四样东西

01
article.wedraft.zip文章包，记录 schemaVersion / engineVersion / templateVersion，可再导入网页或交给宿主继续处理；版本不兼容会被明确拒绝。
02
preview.html本地预览页。打开后点「复制正文排版」，粘贴到公众号后台即可——与网页版同一条复制路径。
03
report.json检查报告，写清哪些问题会阻断复制、哪些只是提示，便于 AI 或脚本决定要不要改稿。
04
body.html / body.txt正文 HTML 与纯文本，给需要自己处理剪贴板或二次加工的流程用。

没有文章仓库

网页端文章只在当前页面内存存活，刷新即回到示例；网页不保存也不托管你的文章，需要留存就靠文章包或 Mac 应用的历史记录——两者各自独立、互不同步。

本地 MCP · 四个工具
PAGE 09

给 AI 的接口，只有这些

工具作用是否写盘
list_templates读取当前模板清单与标识否
validate_article检查 Markdown 与图片来源是否会被阻断否
render_article排版并产出预览与文章包否
export_article把结果写到指定输出目录是，且需启动时传 --output-dir
默认不开放写盘没传 --output-dir 时 export_article 根本不注册，避免让 AI 往任意路径写文件；前三个工具全程无副作用。
只有 stdio，没有端口服务不监听 HTTP，也不提供远程接入；本机调用、本机结束。已用 MCP SDK 1.26.0 验证过真实子进程连接。

内容上限 · 会被拦住的写法
PAGE 12

卡住复制的，通常是这几类

篇幅与图片正文上限约 100 万字符；单张图片 ≤10 MiB 且 ≤4000 万像素；单篇 ≤64 个图片资产、合计 ≤40 MiB。
不支持的 Markdown嵌套列表与任务列表、原始 HTML、删除线、脚注、引用式链接会被判为问题——微信后台对它们的支持本就不可靠。
图片是外链时会怎样渲染时原样保留外链，复制到后台后通常需要重新上传；本地图片走 CLI 时要重新指定资源根目录。
复制了但样式不对先用同一浏览器的无痕窗口试一次：扩展拦截剪贴板、页面被翻译插件改写 HTML，都会让样式丢失，而不是模板的问题。

上手自检 · 八步走完
PAGE 18

第一次用，照这个顺序别踩坑

01
先点编辑区打开站点会看到灰色示例稿，点一下才进入输入状态；示例不会被复制，也不会被导出。
02
第一行写标题Markdown 第一行当标题用，但复制时不会带进剪贴板——到公众号后台要单独填。
03
选模板再改文案换模板不动原文，先把样式定下来，再回头改字更省事；经常用的模板可以「设为默认并使用」。
04
三个视口各看一遍网页 / iPhone / Android 依次切换，重点看表格、代码块和长链接有没有溢出。
05
修完阻断项再复制点「复制排版」时被拦下，就按提示改掉不支持语法；只是提示的项可以判断后继续。
06
后台粘贴后四查查图片是否要重传、查链接、查公式与代码块、用手机在微信里再看一遍，然后才发布。
07
导出文章包留底网页不会自动保存，刷新即清空；要留着改就先导出 .wedraft.zip，下次导入继续编辑。
08
再决定要不要接 AI稿量大、格式重复，再接 Skill / MCP；只偶尔发一篇，网页版 + 手工整理已经够用。
工程视角 · 一套核心四种外壳
PAGE 13

排版核心只有一份，外壳有四个

·
packages/wechat-renderer微信 HTML 渲染与七款模板的唯一定义处——网页、CLI、MCP 都从这里取模板，避免"三份名单对不上"。
·
apps/：web · desktop · monitorVite 静态网页；Tauri + Rust 的 Mac 应用；可选的 Cloudflare Worker 监控。只有构建 Mac 版才需要 Rust 与 Xcode 命令行工具，跑网页和 AI 工具不需要。
·
packages/ 十个包core、wechat-renderer、editor-ui、article-model、article-parser、cli、mcp、shared-types、validation、telemetry——模板与渲染规则只有一份，网页、CLI、MCP 都取同一份；技能包在 skills/format-with-wedraft。
·
integrations 与 deployment安装器（install.sh / installer.mjs）、接入说明与示例文章；部署清单在 deployment/，仓库用 pnpm workspace 管理（Node ≥22.12）。
本地跑一遍git clone → pnpm install --frozen-lockfile → pnpm dev:web；./scripts/verify 一次跑完检查、类型、测试与构建。
想离线读源码只看排版规则的话，packages/wechat-renderer 与 templates/ 两处就够；README 里给了每个构建命令的用途。
适用判断 · 先看这里
PAGE 14

什么时候用它，什么时候先别用

合适

稿子以 Markdown 为主；想固定一套视觉风格反复出稿；不愿把未发布内容上传到任何云；想让 AI 按同一套模板批量排版；能接受"复制到后台"这一步手工操作。

先别用

需要多端同步或云端草稿库（它不做文章仓库）；要支持 Windows 一键接入（当前只做 macOS / Linux）；必须保证 Safari、Firefox 全流程；原稿重度依赖原始 HTML、脚注或嵌套列表。

它替你省的是排版，不是校对

模板解决的是标题层级、行距、颜色与配图位置这类重复劳动；错别字、事实错误、图片版权、后台最终呈现，仍然要你自己过一遍——验收文档也把"真实微信环境"列为未完成项。

贡献一款模板 · 数据驱动
PAGE 15

想加第八款模板，路径是公开的

1
按数据模型写样式模板是数据 + 独立样式目录，不掺业务逻辑；先读仓库里的模板贡献指南，照现有七款的结构来。
2
注册进模板名单在 packages/wechat-renderer/src/index.ts 注册后，网页、CLI、MCP 会同时看到它——不需要改三处。
3
过白名单清洗微信渲染走白名单机制：不允许网络请求、远程字体和追踪代码，只留下微信能安全承载的内联样式与结构。
4
保持 ID 稳定并抬版本模板 ID 一旦发布就要稳定；改动会影响已保存的文章包，需要同步提升模板版本号，让不兼容被明确拒绝而不是静默变形。
合入之后模板随版本同时提供给网页和 AI 工具，不需要用户单独安装。
提交之前仓库走 ./scripts/verify；提 PR 前先读贡献指南与维护规则，模板类改动最好附上实际文章的截图对照。
