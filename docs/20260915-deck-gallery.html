A RESEARCH TOOL FOR PRESENTATION DESIGN

别从空白页憋布局，先用真实演示页建立版式参考库

Deck.gallery 把来自真实演示文稿的单页按页面角色组织起来：封面、议程、品牌系统、数据页、解决方案、团队介绍等。它最有用的地方不是让你“抄一页”，而是让你在卡住时快速比较同类页面如何处理信息密度与阅读路径。

1

搜索任务

SEARCH BY INTENT

先找 agenda、solution、how it works 等页面目的。

2

观察结构

READ THE COMPOSITION

看标题、证据、图表和留白如何形成顺序。

3

比较邻居

COMPARE NEARBY SLIDES

同类页面并排看，比单独收藏一张更容易提炼规则。

4

重建自己的页

REBUILD, DON'T TRACE

保留问题结构，替换成自己的事实、图表和品牌系统。

5

回到版权边界

CHECK THE SOURCE

参考库中的品牌页面仍属于其权利人；研究参考不等于获得复制和商用授权。

核心判断：先搜“这页要完成什么任务”，再搜“我喜欢什么风格”。

1. 定义页面任务

是封面、议程、方案、数据证据，还是结论页？先确定读者要带走什么。

2. 读信息层级

不要先看颜色；先拆标题、主证据、辅助说明、页码和行动指向。

3. 用自己的内容回归

把参考页转成结构草图，再用自己的数据和素材重建并检查可读性。

01 / FIND THE RIGHT REFERENCE

平台怎么找：搜索、筛选和无限画布各自解决什么

官网页面提供 Search、Category、Type、Industry 等过滤入口；不要只靠漫无目的拖动画布。

SEARCH

用页面角色搜

在搜索框输入结构意图，优先使用 agenda、solution、how it works、team、vision 等词，再观察结果的 page role 和 deck 来源。

FILTER

用筛选缩小范围

Category 区分 Pitch、Guideline、Report 等；Type 区分 Cover、Section、Finding 等；Industry 可帮助你避开与当前任务无关的样本。

CANVAS

画布用来发现，不用来定案

Slides 页面是可拖拽、可滚动、可用方向键探索的无限循环画布；发现候选后应进入单页详情，再记录结构。

# 一个可复用的检索记录
intent: "how it works"
filter: "Report"
observe: [headline, evidence, sequence, chart, source_deck]
keep: "结构关系，而不是原页面的品牌装饰"
verify: "打开单页详情，确认标题、来源和页面角色"
02 / READ A SLIDE

一张参考页应该拆成哪些可迁移结构

真正能迁移的是信息组织，不是某个品牌的字体、照片、图表或装饰。

观察层要问的问题迁移时怎么做
页面任务这一页要让读者理解、相信、比较还是行动？先写一句页面结论，再决定版式。
阅读顺序视线先到标题、数字、图表还是人物？把主信息放在最短路径，辅助事实降级。
网格内容是单栏、双栏、三栏还是大图+说明？提取列关系和对齐线，不复制具体尺寸。
证据密度一页承载几个事实？哪些被合并成一个视觉单元？控制自己的字数和图表数量，保留可读留白。
语气是报告、品牌指南、投资叙事还是产品说明？只迁移适合自己受众的语气，不把名牌视觉当成内容质量。
实用规则：收藏一张页面时至少写下“页面任务、主结论、证据类型、网格关系、可迁移部分、不可复制部分”六项；否则收藏很快会退化成图片堆。
03 / TEN-MINUTE EXERCISE

十分钟练习：从“数据页卡住”到自己的版式草图

练习目标不是做出与参考页一样的页面，而是证明你能提炼结构并换入自己的内容。

第 1–2 分钟：写结论

把数据页要表达的结论写成一句话，例如“激活率上升，但留存仍是瓶颈”。不要先打开设计软件。

第 3–5 分钟：搜同类页面

用 finding、traction、report 或行业筛选找到 3–5 张候选，记录它们的标题—证据—结论结构。

第 6–8 分钟：抽象成线框

只画矩形、线条和文字占位符：标题区、主图表区、解释区、脚注区。暂时不要复制品牌颜色和素材。

page_job: "让读者相信一个变化，并知道下一步"
headline: "激活率上升，但留存仍是瓶颈"
evidence: "两条时间序列 + 一个对照数字"
layout: "结论标题 / 主图表 / 解释卡 / 来源脚注"
source_note: "数据口径、时间窗、样本范围"
acceptance: "3 秒知道结论，30 秒能找到证据，不能误读口径"
04 / REFERENCE ≠ LICENSE

版权和平台边界：把“看到”与“可以使用”分开

Deck.gallery 的价值是参考与研究；它不会自动替你获得原演示文稿的复制、改编或商用权利。

页面来源仍归原作者

品牌指南、报告和 Pitch Deck 可能包含商标、摄影、字体、图表和客户数据。平台收录不等于内容进入公共领域。

只迁移抽象结构

可以学习“标题—证据—解释”的关系；不要直接复制原图、文案、数据、logo、照片或独特插画。

阅读 robots 信号

官方 robots.txt 标明允许 search/reference，禁止 ai-train；不要把站内内容批量送入模型或构建训练集。

发布前确认：自己的数据来源、图片/字体许可、品牌使用权、外部引用标注和客户保密边界。即使只是“参考”，也不要把未公开材料上传到第三方服务。

06 / WHEN NOT TO USE IT

什么时候不要打开 Deck.gallery

不是所有 PPT 问题都需要更多参考；有时你缺的是结论、数据或模板约束。

你还没有结论

如果连这一页要表达什么都没写清，继续浏览只会积累风格焦虑。先写 page job 和一句 headline。

你需要严格品牌模板

若公司有固定母版、字体、色板和无障碍规范，先遵守内部系统；参考站不能替代品牌治理。

你要找可商用素材

这里不是素材授权市场。需要图片、图标、字体或可编辑模板时，去相应的许可来源核验。

07 / SELF-CHECK

发布前自检：我是在参考结构，还是在复制页面

把下面的问题交给自己或团队 reviewer，不要交给“看起来很像”这个感觉。

问题通过标准
页面任务一句话说清这页改变读者什么认知。
结构迁移能解释采用的是哪种阅读顺序和网格关系。
内容替换标题、数据、图表、图片和文案均来自自己的可核验来源。
视觉独立没有直接复制 logo、品牌文案、图片、独特插画或原页截图。
可读性桌面和移动端都能读；图表有单位、时间窗和来源。
许可证对外发布前已分别核验字体、图片、图标、数据和引用许可。

最短可验证路径

SEARCH → CLASSIFY → ABSTRACT → REBUILD → CHECK RIGHTS

  • 打开 Slides 页面，先搜一个页面任务，而不是漫游。
  • 选 3 张同类 slide，记录任务、结论、证据和网格。
  • 用自己的内容画一张黑白线框，再决定视觉系统。
  • 回看来源、版权、数据口径和移动端可读性。
