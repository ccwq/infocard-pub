03 / 最值得精读的 4 份 SKILL.md（附可抄的设计模式）

3.1 wide-research：并行研究的"经理-工人"契约

处理"帮我把这 50 家公司都查一遍"式任务。核心设计：全局只允许一个 manager 子代理（禁止平级多开），输入四件套 operation_brief / inputs / output_schema / worker_prompt_template，输出强制七字段 JSON（total / success_count / failure_count / results / failures / notes）。七条操作规则里最值得抄的三条：先去重再派发；失败的只重试一次；最终回复必须报告覆盖率（success/total）与未解决缺口——不让静默失败蒙混过关。

3.2 forget：把"遗忘"当全库清理工程

正面回答了"Agent 记忆删不干净"这个行业难题（对照 MemoryAgentBench 里 Cognee 2.3/100 的遗忘分）。设计：forget.plan → 人工确认 → forget.confirm 三段式。规划器是只读子代理，检查四类残留：原位置与同义副本、从记忆生成的摘要、会把它写回来的提醒/定时任务、以及" Muse 无法删除的外部副本"。两条规则很有分寸感：对用户只说"记忆/提醒/备份"，不暴露内部表名；沉默、含糊、部分同意都不算确认。执行器找不到明确计划+批准时必须拒绝动手。

3.3 skill-creator：官方版 SKILL.md 写作规范

几乎可以直接套用到任何 Agent 的技能编写（包括 Claude Code skills）。要点：一个技能一个窄任务；SKILL.md 只留操作核心，大文档进 references/ 按需加载；Auth 必须独立成节；连接器凭据走 credentials.request_api_access 工具而非手写文件；还有两条实战血泪——"401/403 先查凭据有没有附上，再查 key 对不对"（没带凭据的请求和错 key 症状一模一样）；写完 Python CLI 必须 python3 -m py_compile 自检才能报成功。

3.4 goals：防"重复 intake"的状态机

区分"首次建目标"与"跟进既有目标"两条路径：Goals 标签页的创建回合由运行时注入完整创建契约（含安全节），此时 Agent 禁止再读 skills/goals/ 下的文件——避免同回合双份指导互相打架。还要跟踪用户承诺、在期限到期时判断"完成还是延期"、完成后触发复盘。这是"目标管理"从口号落到机制的样本。

其他值得看的：artifacts/testing（"生成成功"与"交付可用"分开验收）、travel-planning（行程研究与实时可订/交易分开路由）、magic-moment（事实素材→叙事→视觉→时间线→渲染前审阅的视频流水线）、gmail（正文+方法级 manifest+评测场景三位一体的阅读样本）。

05 / 架构与安全：可信度边界画在哪里

架构（自述 + 文档交叉还原）

Hatch daemon 为核心

用户 → Hatch Agent daemon → Skills/连接器 manifest + 执行服务 → PostgreSQL（应用状态）→ 凭据代理/网络出口 → 外部服务。隔离用 systemd-nspawn + openat2 fd 锚定路径限制。聊天只是入口之一，后台研究/记忆整理/建议生成才是常态负载。

安全审计（随包历史材料）

结论 Clean，但范围有限

无反弹 shell/数据外传/凭据收割/混淆载荷/持久化后门。但注意：29MB 主二进制只做了 metadata + strings 检查，未完整反汇编；muse-mail 与 auth 工具共享同一硬链接镜像，字符串不能直接归因。这是"未发现恶意"不是"证明安全"。

三个一致性瑕疵（PROJECT_ANALYSIS 指出）：Web Artifact README 引用的 build.mjs/sdk//space-sdk.tgz 不在快照里；评测 YAML 引用的 spawn-eval-instructions.md 缺失；runtime-cell.kdl 引用的 run-execd.sh 缺失。加上零字节的 gws——这份快照是"搬走了一部分东西"的状态，不是全量镜像。

07 / 判断

这份档案的真正价值不在"吃瓜 Meta"，而在它是目前公开可见的、量产级个人 Agent 的完整运行文档样本：多数开源 Agent 项目的 SKILL.md 只有"怎么调用"，这里多了三样行业稀缺品——方法级权限声明、行为评测场景、以及 forget/goals 这类把脏活（删除、承诺跟踪）工程化的流程文本。68 个技能覆盖的"确认语义"（沉默不算确认）、"覆盖率汇报"、"生成与交付分开验收"，都是可以直接搬进自己 Agent 设计的模式。

两点克制：① "泄露"来源未验证，传播时请用"非官方存档"这个仓库自称；② 该快照无法启动、不含源码，别把它当 Meta 的技术能力上限——它只暴露了"文档层 + 二进制黑盒"，真正的执行质量看不见。做 Agent 的人，读 Skills 目录的 2 小时收益远超读 100 篇 Agent 方法论推文。
