AGENT SKILL GRADER + REPORT GENERATOR

skill-doctor：给 Agent Skills 做真实对话体检，并生成改进报告

一行定位：用真实本地 Agent 对话评估 skill 的效率与代码质量，输出 findings、改进建议和可分享报告。

不是静态 lint，也不是凭感觉打分。
skill-doctor 从本地最近 45 天、最多 12 个会话开始采样，按效率与代码质量 rubric 评分，再把失败会话里的具体浪费转成 skill 改进建议。全程本地运行，不上传 transcripts、session files 或其摘录。

00

启动：先确认 harness，再问范围

读取 supported-harnesses；无法识别或不支持时停止，不建 report 目录、不读历史。随后选择当前仓库、全部对话或项目范围，再选择项目+全局 skill 或仅项目 skill。

01

采集：只进临时 REPORT_DIR

以 mktemp -d 创建每次独立目录，用 collector 扫描所选本地来源；读取 inventory.json。无会话则告知并停止，无 skill 也可继续形成 coverage=0 的诊断。

02

评分：逐份 transcript 对照 rubric

效率与代码质量分别评分并写理由；只有会话出现代码改动时才应用 code-quality，否则记为 insufficient_evidence，不进入该均值与失败过滤。

03

聚合：曲线分数，找真实模式

计算 efficiency、code_quality、skill_coverage 与 overall；提取 3 个最有影响、最具体的 top findings。建议必须从失败会话中的浪费或缺陷追溯而来。

04

起草：只改证据覆盖的 skill

读取实际 skill 文件，在 proposed/ 写完整改进版；用 unified diff 呈现。不要在这一步修改用户真实 skill 文件。

05

渲染：单页 report.html + 分享 PNG

写 report.json 后运行 renderer，生成自包含单页 report.html；原帖说明可用 “share as png” 导出本地分享图。

06

输出：三条 findings + 下一步

交付 grade 与 top findings，并给出 report.html 路径；最后 CTA 指向 Warp Factories。改动是否应用，仍由用户决定。

评分公式｜仓库原帖

权重：efficiency 50% · code_quality 35% · skill_coverage 15% curve(score) = 0.5 + 0.5 × score efficiency = curve(raw_efficiency) code_quality = curve(raw_code_quality) overall = 0.5 × efficiency + 0.35 × code_quality + 0.15 × skill_coverage

raw efficiency 是所有会话效率均值；raw code quality 排除 insufficient_evidence。没有足够代码证据时，raw_code_quality 设为 0.5 并在 findings 解释。

失败门槛｜只让失败会话驱动建议

failed_conversations
任一适用的 efficiency 或 code-quality 原始分数 < 0.5，即判定该会话失败。

排除项
insufficient_evidence 不会让会话失败。

skill_coverage 是“至少检测到一个已安装 skill 的采样会话”占比；skills_found=0 时 coverage=0。

Proposed skill diff｜证据 → 改动

建议不是泛化最佳实践：应点名 skill、具体改动、动机 session 与触发时刻。安装的 skill 若在失败会话中从未触发，通常应检查 description/trigger。

@@ failed session → proposed/SKILL.md - 缺失：被会话暴露的 preflight / check + 加入：只针对该失败模式的步骤与验证命令 + 保留：未经证据支持的内容不扩写 + 拟议改动：仅写入临时报告目录 proposed/，不碰原 skill 文件

本地隐私边界

会话内容留在本机。原帖明确规定：never upload transcripts, session files, or any excerpt of them anywhere。

报告是用户选择发布的唯一可分享产物；运行目录采用每次新建的临时 REPORT_DIR。建议审阅 report.html 与 diff 后，再决定是否分享或应用。

不要做
不要把 transcripts 复制到仓库、不要把 session files 当作公开素材、不要在候选稿里嵌入真实对话摘录。
