PORTLESS · .LOCALHOST · WORKTREE

把端口号从开发流程里拿掉

portless.sh 把 localhost:3000 这类数字端口换成稳定命名的 .localhost URL，支持 HTTPS/HTTP2、自动 CA、子域名、custom TLD，还能和 git worktrees 一起工作。

Named localhost URLsHTTPS 默认开启git worktrees端口冲突消失
更适合人和 Agent 一起开发

同一个项目不必再记 3000 / 3001 / 5173；Agent 直接拿稳定命名 URL，减少“端口对不上”的无效回合。

.localhostauto CAsubdomainsworktrees
01
WHY IT EXISTS

解决端口冲突，也解决“环境理解负担”

当一个仓库要同时开多个前端、多个 worktree、多个 agent，数字端口会变成不稳定的认知噪音。

稳定

名字比端口更稳定，适合长时间开发与多人协作。

可读

命名 URL 更容易记住，也更适合在文档/脚本/Agent 输出里传递。

兼容

Next.js / Express / Nuxt 等多数框架都能直接工作。

02
HOW IT FITS

git worktrees 是它特别亮眼的组合拳

你可以在多个 worktree 里同时开不同分支，每个 worktree 有自己的命名子域，不打架。

Worktree 友好

把不同分支映射到不同的子域名，避免端口和目录双重冲突。

branch → subdomainworktree routing

Custom TLD / 子域名

支持更灵活的本地域名映射，让开发环境更接近真实线上分层。

.localhostcustom tldhttps
03
INSTALL & RUN

保持脚本清爽，只在入口层加一层代理

它读取 package.json 的 dev 脚本，把原有启动命令代理成命名 URL，不逼你重写开发习惯。

Install

安装很轻

直接按 docs 装即可，核心思路是让开发脚本保持原样。

Run

用 portless 包住 dev

portless myapp next dev 这类方式就能把入口转成命名域名。

HTTPS

默认有本地 CA

首次运行会生成并信任本地 CA，默认可用 HTTPS / HTTP2。

04
TRADE-OFFS

它的价值不是“多一个工具”，而是“少一类错误”

少掉端口冲突、少掉环境切换、少掉“我记错端口了”的沟通成本。

1

减少心智负担

不用再记多个端口号。

2

减少协作摩擦

不同人/不同 agent 访问统一命名入口。

3

更接近生产

命名域名 + HTTPS 更像真实部署环境。

一句话：portless 把“端口管理”从开发者脑子里挪到工具里，让 Agent Loop 少一类无意义故障。
