并行多模型 fanout + 合成回复——比单个前沿模型更好

不是所有推理都要在一个最贵模型里跑完一条长链。有些可以并行分散到更便宜的模型，再压缩成一个最终回复。

FUSION ≠ CHAIN

pi-fusion 是 pi 的复合模型面板扩展。在正常回合开始前，它运行一个可选的 discovery agent， 将 prompt 重写为互补角度，fanout 到多个 planner worker，然后将它们的笔记注入主线程做合成。 独立模型回复的组合在多个 benchmark 上超过单个前沿模型——因为独立路径产生有用分歧，合成模型可以复用这些分歧。

NO. PHASE WHAT HAPPENS
00 Recall 读取 .agents/learned/ — 加载已学规则（可选）
01 Discovery 加载共享上下文一次。可选步骤，由独立 discovery model 执行。
02 Prompt Rewrite 将原始 prompt 重写为互补角度的 worker 变体。可选步骤。
03 Workers (并行) 多个 planner worker 并行执行，每个有自己的 prompt 角度和工具权限。
04 Synthesis pi 主回合作为合成步骤，将所有 worker 输出压缩为一个最终回复。
05 Final Turn 一个最终回复，包含所有 worker 的有用分歧和共识。
CORE INSIGHT
为什么有效

独立模型回复的行为不同——它们在不同路径上探索问题空间。合成模型可以复用这些有用分歧，而不是把赌注全押在一条路径上。

在某些情况下，你可以用更好的价格和延迟，获得比前沿模型更好的表现。

RESEARCH BASIS

Compound AI Systems（Berkeley BAIR）— 多组件交互系统

"Are More LLM Calls All You Need?"（Chen et al.）— 聚合多次 LM 调用的 scaling law

Scaling Test-Time Compute（Snell et al.）— 推理时计算作为独立 scaling 轴

Mixture-of-Agents（Wang et al.）— 多 Agent 聚合提升答案质量

VS OPENROUTER FUSION

OpenRouter 有托管的 openrouter/fusion 路由。pi-fusion 类似，但运行本地 pi 子进程，对接你的工作树，把笔记交给已选的合成模型。你完全控制配置。

适合的场景
✓
"找 bug，但不确定在哪"
多个 worker 从不同角度探索代码库
✓
"动文件前先规划重构"
并行规划，合成最佳路径
✓
"审查陌生区域，建议最小安全改动"

✓
"比较几种实现路径再定"
每个 worker 走一条路径，合成对比
不适合的场景
✗
小改动
启动延迟比任务本身还贵
✗
带图片的 prompt

✗
非交互式运行
需要 stdout 进度输出的场景，pi-fusion 保持安静以免污染输出
