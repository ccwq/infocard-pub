SKILL.MD · Discovery 产物 · L1 核心产出
## SKILL.md (morning-triage) — 改三处就能用
---
name: morning-triage
trigger: invoked by daily automation

## Read (DISCOVERY 的输入源)
# 改:换成你项目真的能读到的源
- CI runs that failed since the last run          # gh run list --status failure
- issues opened in the last 24h                   # gh issue list --search "created:>=…"
- commits merged since yesterday                  # git log --since=yesterday
- the previous ./state/triage.md                  # 昨天 → 今天接力

## Judge (Discovery 设的天花板)
# 改:这条是 loop 能否自己挑的核心
For each candidate, decide:
  - is it actionable NOW, or noise?
  - does it block a release? → priority = P0
  - is it already being tracked? → skip
Keep only what is worth a worktree TODAY.

## Write (PERSISTENCE 的输出)
Append to ./state/triage.md:
  | finding | source | priority | status |
Commit the file so tomorrow can read it.

## Handoff (准备 L2 worktree)
For each kept finding, emit a task line:
  worktree=fix/<slug> goal=<stop-condition>

## Stop (明文写 loop 不能做的事)
# 改:这是你唯一需要自己想清楚的部分
Never merge. Never delete.
Anything you are less than confident about → ./inbox/ for a human.

# 核心原则: automation 触发的是 skill，不是粘进 cron 的 prompt
WORKTREE + EVALUATOR · L2/L3 核心代码
## L2: 每个 finding 独立 worktree (Handoff)
$ MAX_PARALLEL=3
$ findings=$(awk -F'|' 'NR>2 && $5 ~ /open/ {print $2}' state/triage.md | head -n $MAX_PARALLEL)
$ for finding in $findings; do
$   slug=$(echo "$finding" | tr ' ' '-' | tr -cd '[:alnum:]-')
$   git worktree add ../wt-$slug -b fix/$slug
$   claude --worktree ../wt-$slug --goal "tests pass and lint clean" "draft fix: $finding" &
$ done && wait
# 关键: worktree = 物理隔离。多个 agent 不碰同一文件。

## L3: Evaluator agent system prompt (Verification)
# .claude/agents/reviewer.md
ROLE: Adversarial code reviewer. ASSUME: this code is BROKEN until proven otherwise. DO NOT praise. Find what fails.

CHECK, in order:
  1. Does it run? (execute, don't read)
  2. Tests: run them, paste real output.
  3. Edge cases the author skipped.
  4. Does behavior match the ticket?

USE Playwright MCP: open the page, click, screenshot, inspect the DOM.
Judge behavior, not intent.

VERDICT: PASS only if every check holds. Otherwise REJECT + list each reason.

# 停止条件 — 由 fresh small model 判断，不是 generator 自己说"差不多了"
$ /goal all tests in test/auth pass and the lint step is clean

# 核心原则: maker 和 checker 必须是两个 agent。generator 永远不能给自己打分。
FIVE ANTI-PATTERNS · 砍掉哪一动作，就长哪一种 loop 病
Discovery 被砍

Blind Loop

人还在每天给 loop 派活。它只自动化了"做"，没自动化"挑"。

修：把 Judge 写进 SKILL.md，让 loop 自己挑
Handoff 被砍

Tangled Loop

多 agent 在同一目录改同一文件，merge 时一团乱。只在并行时才暴露。

修：每条 finding 独立 worktree
Verification 被砍

Nodding Loop

同一个 agent 写代码、夸自己，以机器的速度堆出看起来很对的错误。

修：generator ≠ evaluator，结构性分离
Persistence 被砍

Amnesiac Loop

结果只在 context 里，agent 怎么 forget 都不影响。明天从零开始。

修：state file 写在磁盘 markdown
Scheduling 被砍

Manual Loop

四个动作都漂亮，就是没装 cron。Demo 那天惊艳，之后就停了。

修：挂一个不依赖你记得的 trigger

KEY INSIGHT
最被低估的一条直觉

同一个 bug，四层代价不同

agent 看错了一个函数返回值——在 Prompt 层：人立刻重写。在 Context 层：看到答案就知道。在 Harness 层：diff 在那儿，shipping 前能拦住。在 Loop 层：错的判断写进 state 文件，明天早晨当既定事实读回来。

核心直觉

一个错误的代价 = 它在被发现前活过的轮数。loop 是构造上把"轮数"做大的机器——evaluator、人门、token cap 存在的理由都是一句话：缩短"错误发生"到"有人发现它"的距离。

KEY INSIGHT
Generator ≠ Evaluator 的结构性原因

为什么 agent 总在夸自己

代码写完时，agent 的 context 里塞满了"为什么这么写"的自我说服链。它看自己的输出时，看到的不是结果，是那条说服链。

解法：结构性分离

换一个 agent 进来，带着完全不同的指令从零看这段代码——它身上没有那条自我说服链。"Tuning a standalone evaluator to be skeptical is far more tractable than making a generator critical of its own work." — Prithvi Rajasekaran, Anthropic

银行业老规矩

汇钱的人和审钱的人必须不同。/goal 的核心就这一句。

KEY INSIGHT
Stay the Engineer

同一个 loop，两个人造出来

一个人用 loop 跑得更快，但读代码、有方向感，loop 放大的是他已经有的判断。

另一条路

另一个人用同一个 loop，只是为了再也不用理解一遍——六个月后，前者更强了，后者成了一台他读不懂的机器的看门人。

loop 是忠实的放大器

带理解它放大理解，带懒惰它放大懒惰。先决定你要被放大的是什么。

"So long as the human knows something the AI does not, human-in-the-loop is needed to inject that knowledge into the system." — 只要人知道一些 AI 不知道的东西（用户是谁、场景长什么样、什么才算好），human-in-the-loop 就是必要的。

— Andrew Ng, The Batch 2026-06 · "Three Loops for Building 0-to-1 Products"
