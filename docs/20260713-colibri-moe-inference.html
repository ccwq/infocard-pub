Colibri 是一个纯 C 语言、零外部依赖的 MoE 大模型推理引擎。通过磁盘流式读取专家（370GB 按需调度），只将 int4 量化的稠密部分常驻内存（≈9.9GB），实现无 GPU 消费级硬件上的大模型推理。

01 ARCH · 流式专家架构
💾 磁盘专家池

21,504 个路由专家存储于磁盘（NVMe/HDD），每专家约 19 MB（int4）。按需流式读取，内存永不存满整个专家集。

⚡ 稠密部分常驻

注意力层、共享专家、embeddings 等稠密部分以 int4 量化常驻 RAM（≈9.9GB），是推理的主要计算单元。

🧠 极低内存门槛

总 RAM 需求 ≈25 GB（稠密部分 + 专家缓存 + KV-cache 182 KB/token），消费级设备即可运行 744B MoE 模型。

02 FEATURES · 核心技术亮点
🦜 纯 C · 零依赖

不依赖任何外部库，编译即跑。可嵌入式部署，适合资源受限和定制化场景。

🔢 MLA 注意力

集成 Multi-head Latent Attention（MLA）机制，低秩联合压缩 key-value，显著降低推理时的显存占用。

🎯 MTP 投机解码

Multi-Token Prediction 投机解码，一次生成多个 token，加速推理吞吐量。

📦 INT4 量化

稠密部分 int4 量化存储，约 2.6 倍体积压缩，内存占用从 ≈38GB 降至 ≈9.9GB。

03 RUN · 快速上手
⚙️ 编译

git clone https://github.com/JustVugg/colibri
cd colibri
mkdir build && cd build
cmake .. && make

🚀 运行

./colibri --model /path/to/glm-model
--experts-disk /path/to/experts
--memory-limit 25GB

04 MEMORY · 内存布局
组件 存储位置 大小
路由专家（MoE） 磁盘（NVMe/HDD） ≈370 GB
稠密部分（注意力等） RAM 常驻 ≈9.9 GB
运行时 RAM 总计 RAM ≈25 GB
📊 KV-cache 开销

182 KB/token，取决于上下文长度。内存布局设计确保专家缓存与 KV-cache 不冲突。

🎯 适用场景

本地开发测试、嵌入式部署、学术研究、内存受限的服务器环境。
