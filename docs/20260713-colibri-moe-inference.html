02 FEATURES · 核心技术亮点
纯 C 引擎
单文件 c/glm.c（约 2,400 行），零外部依赖，AVX2 整数矩阵乘，编译即跑。
MLA 注意力
q/kv-LoRA + 交织 Partial RoPE，压缩 KV-cache 57×（576 float/token）。
MTP 投机解码
GLM-5.2 自带 MTP 头做草案验证，接受率 39–59%，实现 2.2–2.8 tokens/forward。
Grammar 约束
GBNF 语法约束草案（JSON/函数调用），强制 span 接受率 ~1.0，与 MTP 可组合。
int8/int4/int2 核
按 shape 自动选择最快核：int8 加速 1.4–2.5×（119 GFLOP/s 实测），int4 批量 1.8×。
DSA 稀疏注意力
GLM-5.2 的 lightning indexer，每层 top-2048 因果 key 选择，与稠密逐 token 相同。
KV 持久化
压缩 MLA KV-cache 持久化到 .coli_kv（182 KB/token），重启后零预填充恢复。
OpenAI 兼容 API
coli serve 提供 OpenAI 兼容 HTTP 接口，支持 SSE 流式、thinking 模式、JSON 响应。
03 RUN · 快速上手
# 编译（纯 C，零依赖） cd c && make glm
# 一键转换模型（python 仅用于转换，运行时无需） ./coli convert --model /nvme/glm52_i4
# 启动聊天 COLI_MODEL=/nvme/glm52_i4 ./coli chat
# 部署 OpenAI 兼容 API COLI_MODEL=/nvme/glm52_i4 COLI_API_KEY=local-secret ./coli serve --host 127.0.0.1 --port 8000

Windows 11 原生支持：MinGW-w64 编译，无需 WSL。make glm.exe 直接生成静态可执行文件。

04 MEMORY · 内存布局
组件 存储位置 大小 说明
路由专家（MoE） 磁盘（NVMe/HDD） ≈ 370 GB 21,504 个专家按需流式读取，每专家约 19 MB（int4）
稠密部分（注意力等） RAM 常驻 ≈ 9.9 GB int4 量化，包含 attention、共享专家、embeddings
运行时 RAM 总计 RAM ≈ 25 GB 稠密部分 + 专家缓存 + KV-cache（182 KB/token）

对比：传统方案需 756 GB 模型全量加载。Colibri 通过流式专家 + int4 量化，把消费级硬件变成 744B MoE 推理机。
