01 / ARCHITECTURE

Source-first 不是口号，而是一次修改的传播路径

源文件拥有几何与元数据；编译器负责规范化与导出；消费端只拿生成产物。

CANONICAL SOURCE

generator/src/*.icon.json

每个图标的名称、标题、分类、关键词和 shapes 都在这里。人类能读，Agent 能搜索，Git 能逐行 diff。

COMPILER

build-icons.mjs

读取 JSON，标准化 stroke、caps、corner 和 geometry，拒绝非法构造，并生成报告与下游文件。

GENERATED OUTPUT

不要手改 dist/

README 说明一次构建可产出 standalone SVG、React components、sprite、icons.json、预览画廊和 balance report。

为什么这样更适合 Agent：Agent 不需要猜一条最终 SVG path 是怎么来的；它可以在小型 JSON 语言里搜索邻居、复用 construction、运行确定性 check，并把每次改动留在可审计的源文件上。

03 / DRAWING LANGUAGE

24×24 画布里的规则：哪些是硬约束，哪些只是建议

这一区分决定了 Agent 应该自动修什么、把什么交给人眼。

层级规则如何验收
硬约束画布 24×24；安全区 2–22；点落在整数或半格网格；stroke 2、round caps。build-icons.mjs --check 通过；错误会指出图标、shape index 和违反的规则。
弧与旋转圆心/半径在半格；arc 角度为 45° 倍数；rotate 为 90° 倍数。先检查构造，再在实际尺寸预览；不要凭 SVG 大图判断。
间距平行轴对齐笔画中心距不得小于 3；圆角不超过短边 50%。机器 check 负责可计算约束；复杂视觉密度仍需 16px 对照。
基元line、polyline、rect、circle、arc、bend、quad、ellipse、dot、arrow、path、use 共 12 类。未知 primitive、零长度线、重名、文件名不匹配直接修复，不绕过 validator。
视觉建议墨量超过全套中位数 2.2 倍、中心偏移超过 1.25、包围盒小于 12 时提示。这些是建议而非错误；chevron 天生可能轻，不应为了分数改变 stroke width。
重要：“验证证明构造合法；视觉审查决定它是否属于这个家族。”这句话是贡献流程的核心分界线。
04 / AGENT WORKFLOW

给 Agent 的最短贡献闭环：找重 → 写源 → check → 看矩阵 → test

官方 generator/AGENTS.md 和 .dev/SKILL.md 都要求从源文件开始，禁止手改生成文件。

01

搜索已有项

先查 src/；build 后再用 dist/icons.json 搜名称、关键词和分类，避免重复造一个已有形状。

02

选邻居

按 shape 而非语义命名；找 construction 相近的图标作为邻居。不要从 Lucide、Tabler 等库拷贝 path。

03

写一个 JSON

保持最少 shapes；保留 name/title/categories/keywords；把旋转、mirror、nudge 当作明确 modifier。

04

生成矩阵

preview --matrix 对照 16/20/24/32px、不同 weight、outline/tonal、light/dark 和 controls/text rows。

05

全量 test

接受视觉结果后跑 pnpm test，让 catalog 与 package 重新生成，再提交 PR。

# 官方 workflow 的可复用形状
pnpm --dir generator check src/tool.icon.json
pnpm --dir generator preview tool eye layers --matrix
# 真实打开 dist/preview.html 看 16px 与邻居
pnpm test
# 贡献者指南：generator/AGENTS.md
05 / OUTPUTS

一次构建会改变哪些下游文件

统一源文件的价值，要在输出面而不是 README 口号里验收。

独立 SVG

outline 版本可直接复制；closed shape 的 filled/tonal 版本来自同一几何源，不需要手工维护两套 path。

React 与 sprite

README 说明计划中的 package 会包含 React components、TypeScript types、raw SVG、sprite 和 icons.json。

目录与报告

本地 gallery 可搜索图标、切换 size/theme/style；balance report 提醒墨量和中心偏移，但不代替视觉判断。

输出读者用途常见错误
svg/outline应用和设计工具直接消费直接改生成 SVG，下一次 build 被覆盖。
svg/filledclosed shape 的 tonal 变体另画一份 filled 图标，导致 outline/filled 几何漂移。
dist/preview.html搜索、切换尺寸/主题/风格、视觉观察只看生成截图不打开页面；官方 skill 明确要求真正看渲染结果。
dist/report.json读取 balance notes 与 path 等报告把建议项当成阻断错误，强行改变笔画宽度。
06 / DESIGN REVIEW AT 16PX

机器管合法性，人眼管家族感

图标大图看起来正确，缩到 16px 仍可能变成 blob、闭合或误读。

先看 counter

需要被读者看到的 slot、pupil、层间空隙，实用建议是约 4 units clear space；密集 glyph 仍需在各 weight 观察。

再看 stroke

视觉偏重/偏轻时移动质量，不要修改全局 stroke。曲线和斜线携带的墨量不同，几何跨度相等不代表视觉重量相等。

最后看语义

按形状命名、按关键词承载意义；一个 construction 可能读成另一个对象，必须和邻居并排比较。

复核问题：在 16px 下，counter 是否闭合？两条线是否合并？图标是否仍然读成预期对象？如果 check 通过但答案是否定的，回到 JSON 调 geometry，而不是绕过规则。
