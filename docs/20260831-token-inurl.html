01

先理解 BYOK：聚合配置，不是替你购买额度

你仍然需要向各家模型厂商申请并维护自己的 API Key。inurl 的作用是把这些 Key 放进统一的密钥库，再让本机代理按统一入口调用；“无限”“永远在线”等文章标题式表述，不应当当作服务保证。

✓ 官方站点 / 教程宣称

  • 浏览器端加密密钥，云端保存密文和目录
  • 厂商调用从本机 Agent 发起
  • 多个厂商统一成一个客户端入口
  • 支持流式传输与自动/分类路由

✗ 不能直接推出

  • 不能推出绝对零信任或绝对不可泄露
  • 不能保证每个厂商的免费额度长期有效
  • 不能保证 429 / 5xx 后一定有可用备用厂商
  • 不能跳过客户端、启动器和服务端代码审计

请求链路：客户端 → 本地代理 → 厂商 API

链路声明的边界“云端不中转、调用从本机发起”是官方产品页与教程的描述。使用前仍应查看当前版本的客户端、网页加密实现、本地代理启动器、服务器端 API 和第三方厂商条款。
03

核心能力：一个入口，多种路由

KEY VAULT

端到端加密密钥库

官方页面宣称使用浏览器端主密钥加密，并以 AES-256-GCM / PBKDF2 描述密钥保护；恢复密语需自行安全保存。

UNIFIED TOKEN

统一客户端配置

客户端使用统一令牌连接本机代理，厂商 Key 在密钥库中分别管理，减少重复改 Base URL 的操作。

STREAMING

流式调用

官方页面描述支持 SSE 流式透传；实际协议转换和错误处理应以当前代理版本验证。

Model 填值路由范围适用例子
inurl / inurl-text文本模型普通对话与文本生成
inurl-code代码模型代码补全、重构、调试
inurl-image图像模型图像生成（需对应厂商能力）
inurl-video / audio视频 / 音频按目录标签匹配可用厂商

05

配置流程：先审计，再接入

STEP A

注册并保存恢复信息

在官方控制台注册，保存统一令牌与恢复密语。不要把它们粘贴到信息卡、Issue、聊天记录或公共仓库。

STEP B

添加自己的厂商 Key

在密钥库中逐家添加，先用低权限/低额度测试 Key，确认加密、删除和恢复路径。

STEP C

启动本地代理

教程描述可从控制台下载启动器，运行前检查来源、文件内容、Node.js 依赖和本机权限。

STEP D

用单一模型做回归

先用一个已知可用的模型测试 /v1/models、普通请求、流式响应和错误处理，再启用自动路由。

06

免费模型与自动切换：便利伴随供应商约束

官方模型目录列出 Ollama、Groq、OpenRouter、Gemini、DeepSeek、OpenAI、Mistral、Claude、Qwen、MiniMax 等免费或付费来源。目录、额度、地区可用性和模型名称会变化，不能把当前目录快照当成长期承诺。

自动路由不是魔法当某厂商返回 429 或 5xx 时，系统是否切换、能切到哪家、模型能力是否等价，都取决于当前可用 Key、路由标签、上游状态和请求类型。重要任务应保留可重复的具体模型配置。
07

适合谁？不适合谁？

✓ 更适合

愿意维护多个厂商 Key、希望统一客户端配置、能运行本地代理并愿意自行审计密钥与请求链路的开发者。

✗ 不适合

不愿管理密钥、要求稳定 SLA/顶级模型质量、不能接受第三方服务风险，或希望“点开即用且无需任何审计”的用户。
