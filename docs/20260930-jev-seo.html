jev-seo：一条命令给你的网站做 SEO 体检

开源的网站 SEO 体检工具：给它一个首页网址，真实爬一遍你的站（robots.txt、sitemap、重定向、死链、结构化数据、JS-only 页），对照 Google Search Central 的 52 条硬规则逐项检查，Core Web Vitals 走 Google PageSpeed API，再把每个页面交给 TypeSafe 的 Jev 模型做类型化提问。代码打分排序，一次出 PDF / Excel / Markdown 三份报告。以下全部事实于 2026-09-30 从仓库源码与文档逐条核验。

52 + 14 · 规则体系实测

52 条硬规则（checks.py）+ 14 条 Jev 评分规则（score.py）

「52 条规则对照 Google 官方文档」逐字属实：checks.py 的 RULES 字典恰好 52 条确定性规则，每条带 (category, severity, title, fix, source-key, effort, heuristic) 七元组，source-key 挂 SRC 表里 39 个官方 URL（Google Search Central 为主，另有 web.dev、OGP、MDN、OWASP、llmstxt.org）。每条 finding 输出：规则名、受影响 URL、实测证据、改法、主要出处；标了 heuristic 的 5 处会明确说明是编辑约定而非搜索引擎要求。

  • crawl 爬取与索引 16robots/sitemap/HTTP 错误/重定向链/canonical/noindex/软 404
  • onpage 页面级 12title 缺失/重复/过长过短、meta description、hreflang、lang 属性
  • links 链接架构 6死链、经过重定向的内链、首页三次点击可达性
  • structured 结构化数据 6解析失败、缺 Google 富结果必需属性、OG 标签
  • security 5 + performance 3HTTPS/HSTS/安全头；TTFB>0.8s、HTML>500KB、图片缺宽高
  • content 2 + ai 2AI 爬虫准入（llms.txt）、主内容过少/重复正文
52 deterministic+14 jev-scored9 categories39 source URLs
Jev 在判什么（score.py 14 条） content 7 条（价值主张、helpfulness、specificity 等）· onpage 3 条（title/meta/H1 契合度）· ai 3 条（实体清晰度、answer-first、可引用性）· structured 1 条。页面级 13 问 + 站点级 5 问 + 竞争页配对；首页类型由代码定，不问模型。每答保留概率，落在决断带外的答案在所有格式里标「to verify」。
--full 模式再加 DataForSEO 排名关键词与位置、预估流量 ETV、竞品、referring domains 对比、关键词建议/缺口、实时 Google 结果（含 AI Overviews 是否引用你站）、AI 回答中的品牌提及。Jev 再过滤别家品牌词并把每个保留词映射到「该 owned 它的页面」或「需要新页」。约 $0.30/站，按次付费。
Setup · 上手五步

从 clone 到第一份报告

01

Python 3.10+；WeasyPrint 需要 Pango：Debian/Ubuntu sudo apt install libpango-1.0-0 libpangoft2-1.0-0，macOS brew install pango。

02

git clone https://github.com/AgriciDaniel/jev-seo.git && cd jev-seo && python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt

03

cp .env.example .env 填 TYPESAFE_API_KEY（唯一必填级；不填也能跑，Jev 区块标 not assessed、分数标 partial audit）。

04

bin/jevseo doctor 自检依赖与密钥（只报有无，永不打印值）。

05

bin/jevseo run https://example.com —— 体检 + 渲染一步到位；报告落 jev-seo-reports/<domain>-<stamp>/。可选 pip install playwright && playwright install chromium 渲染 JS-only 页面。

CLI · 五个子命令

会跑之后按需拆步

  • audit <url>爬取+规则+Jev+PageSpeed → audit.json + digest.md
  • render <dir>audit → report.pdf / .xlsx / .md（+html、charts/）
  • run <url>audit+render 一把梭，自动摘要，图快不求旁白
  • rescore <dir>离线重算分数与 digest，零网络零花费（改规则后用）
  • doctor依赖与密钥体检，永不出键值

Evaluation · 2026-09-22 实测记录

它对自己的可信度交了底

  • 规则与爬取事实独立重爬复核全对；字数误差 <5%
  • 复现性（推文说的 0.03）同 59 页跑两遍：分数平均移动 0.001–0.023；决断态页面类型 44/44 一致；0.03 是保守上限不是均值
  • 盲评第二裁判30 页 + 40 词，另一模型盲标：helpfulness/specificity 28/29、开头点题 23/23、下一步 16/16、关键词相关 27/30
  • PageSpeed独立重跑分数与字段值一致；但 lab 分数本身每次会波动
诚实边界（README「How far to trust it」原话） 盲评裁判是另一个模型不是人类——这只证明 Jev 一致且合理，不证明它「对」。决断带外的答案全部标「to verify」。作者的坦白：Jev 阈值还没对着人类标注调过；想当裁判用，先给每个判定族标约 100 条人工样本。
成本台账（写进报告的 ledger） 爬取/规则/打分/图表/PDF/XLSX/MD：本机，免费。JS 渲染：本机 Playwright Chromium，免费。Core Web Vitals：Google PageSpeed API，免费。Jev 判定：$0.042/M input tokens ≈ $0.00015/页（60 页跑一遍 ≈ $0.01）。--full 的 DataForSEO：≈ $0.30/站。两个付费 API 都有硬上限（--jev-budget 默认 0.25、--dfs-budget 默认 1.00 USD），每次请求前检查，每笔调用进报告花费台账。
Limits（README 不装的地方） 大站按 60 页上限抽样且报告会声明；Jev 阈值未对人类标注调优；PageSpeed lab 分数逐次波动、field data 只在有足够 Chrome 流量的站存在；DataForSEO 的量/难度/流量是估计；标 heuristic 的规则是编辑约定不是搜索引擎要求。定位原话：evidence tool，不是 rank tracker，替代不了 Search Console——不测流量、收入、跨时间排名。

Position · 什么时候别用它

适用与不适用

合适：给自己或客户的站做交付前体检（附一份 PDF 报告比嘴上说「SEO 做好了」有力）；改版后回归检查；把 Actions sheet 当整改进度表；用 Markdown 报告在团队仓库里持续追踪。

不合适：需要登录/私网站（爬虫设计上拒绝私网地址）；期待排名或流量预测（分数只排序工作项，报告明说不是 rank tracker）；替代 Search Console（不测跨时间数据）；单页迷你站跑 --full（DataForSEO 花费不值）。

注意：仓库 created 与 pushed 同为 2026-09-22（发布当日即首版），open_issues 1，迭代史短——规则集与 Jev 阈值仍在演化期，把 rescore 工作流用起来，规则更新后离线重算即可。
