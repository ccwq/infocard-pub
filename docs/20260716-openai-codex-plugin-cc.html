01核心定位

官方定义很直白：“Use Codex from inside Claude Code for code reviews or to delegate tasks to Codex.” 它不是在 Claude Code 里塞进一个新的模型，而是调用你机器上已有的 codex CLI 与 Codex app server。

CLAUDE CODE

主控与上下文

继续在熟悉的 Claude Code 会话、仓库和插件入口中工作。

CODEX PLUGIN

命令与调度层

把 review、challenge review、delegate、transfer、status 等能力变成 slash commands。

CODEX CLI

执行与会话

使用同一台机器的 Codex 登录态、配置、仓库 checkout 与环境。

02安装与启动

前置条件：ChatGPT 订阅（含 Free）或 OpenAI API Key；Node.js 18.18+。插件会使用本机 Codex 认证与额度。

在 Claude Code 中执行
/plugin marketplace add openai/codex-plugin-cc
/plugin install codex@openai-codex
/reload-plugins
/codex:setup
首次检查：/codex:setup 会确认 Codex 是否已安装并登录。若没有本机 Codex CLI，可自行执行 npm install -g @openai/codex，再用 !codex login 登录。

03命令地图

/codex:review

普通、只读的 Codex Review。可审当前未提交修改，或用 --base main 比对分支。

/codex:adversarial-review

可附带焦点文本的挑战式 Review：质疑设计取舍、隐藏假设、可靠性与替代方案。

/codex:rescue

把排障、尝试修复或延续任务委派给 Codex；支持 --background、--resume 与模型/effort 参数。

/codex:status · result · cancel

查看后台任务进度与结果，或取消运行中的任务。

/codex:transfer

把当前 Claude Code 会话转成可在 Codex 继续的持久线程，并提供 codex resume。

为什么比复制粘贴顺手？

  • Review、委派和后台状态都留在 Claude Code 的命令面内。
  • Codex 直接复用本机 CLI 的认证、配置与项目环境。
  • 结果可由 /codex:result 取回；需要深挖时可 codex resume。

04适合怎么用

SHIP 前

让第二个视角挑错

先在 Claude Code 完成实现，再执行 /codex:review --background；如果担心方案本身，改用 adversarial review 聚焦缓存、重试、并发或回滚风险。

卡住时

把排障包给 Codex

用 /codex:rescue --background 把 flaky test、CI 失败或局部修复委派出去，同时继续在 Claude Code 做其他工作。

要换场

转移上下文，不重讲一遍

在 Claude Code 中启动讨论后，用 /codex:transfer 生成可恢复的 Codex 线程，后续可在 Codex 侧继续。

长任务

让状态可见、可控

后台任务后用 /codex:status 查看进度、/codex:result 读取结果；不需要时用 /codex:cancel 终止。

05边界与提醒

Review 不等于自动修复。 /codex:review 与 /codex:adversarial-review 是只读命令；要委派调查或尝试修复，用 /codex:rescue。可选的 review gate 会在 Claude 停止时触发定向审查；官方明确警告它可能形成长时间 Claude/Codex 循环并快速消耗用量，应在主动监控时才开启。
