read first

它卖的不是“一个插件”，而是“Claude Code 的完整操作层”

原帖的核心信息很明确：Everything Claude Code 试图把日常会话里散落的规划、技能、命令、安全检查和审查流程，整理成一套可以直接装配的工具箱。它更像一套作战编制，而不是单点功能。

原帖金句： “No estás usando el 100% de Claude Code. Hasta que instalas esto.”
中文意思：你还没把 Claude Code 用到 100%，直到你装上这个工具箱。

为什么会吸引人

它给了用户一个非常具体的想象：不是“再学一个技巧”，而是把 Agent、Skill、Command、Review、Security 变成可复制的系统。对重度 Claude Code 用户来说，这意味着更少手工拼接，更少上下文噪音。

这套工具箱到底装了什么

what ships
packaging logic

把“使用 Claude Code”变成“运行 Claude Code 系统”

从帖子的表达看，这不是单纯罗列功能，而是把 Claude Code 的常见高频环节拆包：规划（planning）、开发（code review）、安全（AgentShield）和命令入口（commands）。这种设计最重要的价值，是降低“每次都从零开始搭流程”的重复劳动。

reader takeaway

你真正该盯住的不是数量，而是边界

30 / 64 / 33 只是入口，重点是这些组件怎么互相配合：agents 负责分工，skills 负责知识复用，commands 负责节奏，AgentShield 负责守门。若没有这个边界，工具再多也只是堆列表。

组件拆解

component notes
30 Agents
职责分离 / 任务分派
01
原帖定位

用多个 agent 承接不同阶段与角色，减少一个上下文里把所有事都塞满。

重点看

是否真的按职责拆开，而不是给同一个会话换个名字。

64 Skills
知识封装 / 复用单元
02
原帖定位

把可复用的工作方式、规范、经验封装成 skills，让 Claude 进入任务前先有“预热知识”。

重点看

Skills 是否覆盖真实工作流，而不是只堆概念名词。

33 Commands
快捷入口 / 操作层
03
原帖定位

把常用动作做成可直接触发的 command，减少记忆成本和重复输入。

重点看

是否真的能把“复杂操作”压缩成少数稳定指令。

AgentShield
安全护栏 / 测试约束
04
原帖定位

1,282 条安全测试是一个强信号：这不是“看起来很完整”，而是把风险控制也做成产品的一部分。

重点看

安全检查有没有真正嵌入流程，而不是只放在 README 里。

Planning / Code Review
主流程 / 持续校验
05
原帖定位

把计划与审查拉进系统里，意味着它不是“写完再看”，而是把执行和检查绑定到一起。

重点看

能否减少上下文漂移，让每次输出更稳定。

Open Source Toolkit
可看源 / 可迁移 / 可改造
06
原帖定位

开源的意义不是“免费”，而是让用户能看清它怎么组织系统、如何做默认选择。

重点看

哪些设计能直接移植到自己的 Claude Code 工作流里。

阅读时别忽略的一个边界

caveat

数量很强，但不等于“装上就自动更强”

这类工具箱最容易产生的误解，是把“组件齐全”直接等同于“结果更好”。实际上，真正值钱的是它的默认编排：谁先跑、谁来审、谁负责安全、谁适合复用。卡片里已经把这层逻辑提出来了，别只记住数字。

最值得记住的一句话

Everything Claude Code 的卖点不是“更多功能”，而是“把 Claude Code 从单点工具变成可运维、可审查、可复用的工作系统”。
