写 Prompt 的方法 02 Writing a prompt

说概念，不说画法

Prompt 是想法，不是绘画指令。「Explain how an LRU cache evicts entries」就够了，决定它画成书架是 Claude 的工作。

两个魔法词 Magic words

interactive WebGL 3D

interactive：响应鼠标拖动、按键。长图不加就是静止画。
WebGL：火焰、水、等离子体等 shader 效果。
3D：零件真正在深度旋转（耗时更长）。

尺寸分级 Size tiers

  • Figure：40~80 零件，30~90 分钟
  • Hero：80~150 零件，2~4 小时
  • Epic：整车/整栋，6 小时+，需确认
Claude 工作流 03 What Claude does
Step 1

定尺寸：Figure / Hero / Epic，预估时间

Step 2
Truth first

收集真实数字和行为，写成小模型，动画与读数都读它

Step 3
Invent the object

发明一台机制与概念一一对应的机器

Step 4

Step 5

Step 6
Paint back-to-front

质量 80% 在前四步决定，几何还没开始，质量已经定完。验证用截图、接触单、4 倍放大crop、双重自动检查。
等轴测图六规则 04 Anatomy of a figure
单一相机

等轴测，俯角 30°，无透视，平行线永不相交

实体遮挡

所有零件填色绘出，前后关系正确，无透明边线

四色分面

顶面最亮，侧面按受光程度分 4 级色调

一点高光

只有一处被照亮：读者应关注的那个零件

线终结于面

每条线止于面、另一条线或点，无引线、无气球、无箭头

4 倍细节

正常大小读为一台机器；4 倍放大仍有东西可发现

无图内文字 真实数字驱动读数 图 = 程序 无障碍：读数变化时播报屏幕阅读器
六台近距离 05 Six machines

Hash 冲突 Sorting desk

哈希映射把同桶的键堆在一起 → 邮政分拣台。编码机打印每个字母的桶号（hash mod 8），按 pigeonhole 归档。

布隆过滤器 Fruit machine

能确定说「绝对不是」，但只能说「可能是」→ 老虎机。三转盘 = 三个哈希函数，16 面旗帜 = 位数组；三个旗帜都竖起才吐币。

互斥锁 Tank and key

两写者同时读到旧值会误操作 → 双泵水箱。无联锁钥匙：两控制器读同水位，超量；有钥匙：持钥匙者才可读写。

TCP 握手 Mail ropeway

数据移动前双方确认对方在监听 → 两站间的邮件索道。SYN 桶、SYN+ACK 旗帜旗、ACK 桶划过绳索，各站信号旗显示连接状态。

温度采样 Roulette wheel

温度改变下一 token 概率分布不改 token 集合 → 轮盘。16 个口袋 = 最可能的下一 token，口袋宽 = 概率。

两台大机器 06 Two big machines

机械表机芯 Watch movement

  • 拖王冠↑上链：棘轮转动，发条盒动

安装与使用 08 Install & in your code

安装（两条路）

npx skills add wheresryan22/anatomy

或下载 anatomy.zip 解压到 ~/.claude/skills/

unzip anatomy.zip -d ~/.claude/skills

React 组件

npm install anatomy-figures
import {'{'} Watch {'}'} from "anatomy-figures"; <Watch theme="light" />

每张图独立导入，不互相拖累。5 个内置主题：dark / light / paper / blueprint / sepia，或传 --anatomy-* CSS 变量。

需要 React 吗？

不需要。产出无框架 TypeScript → SVG + HTML。也支持 React 组件或自定义元素（原生 HTML 可直接用）。

能改图吗？

能。零件、读数、动画都读同一模型，改一个数字全部联动。问 Claude 或直接改代码。

影响页面性能？

图滚出屏幕停止，只重绘移动的零件。shader 仅在效果激活可见时渲染。设备像素比上限 1.5。减弱动作模式下只绘一帧静止图。

无障碍？

键盘可聚焦，支持方向键。读数变化自动播报屏幕阅读器。减弱动作模式保持交互但动画静止。

局限与已知问题 09 Limits
做得好 ≠ 看起来对

Claude 很擅长构建这些，但不一定擅长发现错误。优化目标是「能跑」，一个零件每个数字都对但看起来可能不对。

解法：播放图，描述哪里感觉不对，说出来，再问一次。

好东西都慢

skill 要求每张图至少 40 个零件，不会为速度放弃细节。需要快就说，预期 Figure 而非 Hero。

3D 是 beta

每次转一个主体。密集图审计 15~20 分钟。仅在零件真的要在深度移动时才值得要求。

参考资料只用于氛围

给照片 → 取表面处理/材质/氛围，不取对象。忠实复制别人画作不是它的用途。

至少 40 个零件

这是硬性要求。如果图里零件太少，效果会很抽象或扁平。

好看 ≠ 对 慢 3D 是 beta 至少 40 零件 参考资料仅取氛围
