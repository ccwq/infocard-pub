Moli：给 AI Agent 的结构优先型 Rust 无头浏览器

Moli 是 Lexmount 开源的生产级 headless browser。它把原生 DOM 与样式状态作为事实来源：提取、查询和执行脚本默认不触发布局与绘制；只有截图、坐标输入等真正需要视觉的请求，才按需建立 layout 与 paint。

RustV8DOM-firstCDPWebDriver BiDiAI Agents
一句话判断：先读结构，后算像素

对 Agent 来说，大多数网页任务只需要内容、DOM、脚本和网络状态，不需要持续维护完整视觉世界。Moli 把昂贵的 layout / paint 从默认路径移出，换成“按需生成、用完即弃”的成本模型。

01
核心机制

把浏览器的“事实来源”放回 DOM 与样式

传统浏览器持续维护视觉状态，但 Agent 的主路径通常是抽取和操作结构。Moli 将两类请求拆开，避免为不需要的像素付费。

Structure first

默认不触发 layout / paint

HTML、Markdown、semantic tree、DOM 查询、JS 执行、网络与存储检查，直接读取浏览器运行时状态。

Pixels on demand

真正需要视觉时再渲染

截图、全页截图、PDF、坐标输入与命中测试可以显式开启 layout；视觉快照不是长期维护的负担。

Not a simulator

完整 runtime 仍在

V8、DOM、CSS cascade、Fetch/XHR/WebSocket、Cookies、WebCrypto、Worker 与存储能力共同构成真实浏览器内核。

02
能力矩阵

一套内核，三种自动化协议

同一个 Moli 服务端点同时暴露 CDP、WebDriver Classic 与 WebDriver BiDi；Playwright 可通过 connectOverCDP 直接接入。

03
快速上手

从安装到 Agent 接入，只保留必要的显式开关

README 提供 Linux / macOS / Windows 安装方式；服务端默认适合 DOM-first 工作负载，需要几何与视觉时再加参数。

InstallCross-platform

一条命令安装预构建二进制

# Linux / macOS curl --proto '=https' --tlsv1.2 -fsSL \ https://github.com/lexmount/moli/releases/latest/download/moli-installer.sh | sh # Windows PowerShell irm https://github.com/lexmount/moli/releases/latest/download/moli-installer.ps1 | iex
ServeExplicit cost

根据任务决定是否启用 layout

# DOM-first：默认路径 moli serve # 几何、坐标输入、截图 moli serve --layout # 额外加载图片、字体、音视频等资源 moli serve --layout --resource
接入判断：如果你的 Agent 主要抓取、抽取、搜索和评估网页结构，先从默认模式开始；如果任务需要坐标或截图，再把视觉能力作为显式预算打开。
04
适用场景与边界

最适合批量网页处理，不等于无条件替代 Chrome

Moli 的优势建立在“结构请求占多数”这一工作负载假设上；需要长期高保真视觉状态的场景，应保留完整浏览器方案作为对照。

爬虫 / 检索管线

大量页面只需要文本、DOM、脚本结果与网络状态，结构优先可以减少持续布局和绘制的资源消耗。

Browser-use Agent

需要真实 Web runtime 与主流协议兼容，但不希望每一步都维护完整视觉状态的自动化工作流。

评估 / RL 环境

批量网页处理和 Agent 行为评估可以把视觉输出变成按需生成的稀疏事件，控制计算成本与吞吐波动。
