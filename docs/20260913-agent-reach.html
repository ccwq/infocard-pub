给 Agent 装上互联网能力，但先看渠道与凭据边界

Agent Reach 不是把所有网站包成一个新 API，而是为每个渠道维护“首选 + 备选”的有序后端：负责选型、安装、体检和路由，实际读取仍由 Agent 调用上游工具完成。

16+ 渠道README 当前列出网页、视频、RSS、GitHub、X、Reddit、小红书等
doctor真实探测当前可用后端并给修复处方
MIT官方 LICENSE；当前 release v1.5.0
01

先判断：你要读公开内容，还是要调用登录态？

零配置、自动配置和登录态不是同一档能力；不要把“支持平台”读成“所有平台装好即用”。

装好即用

网页 / YouTube / RSS

README 将网页阅读、YouTube 字幕/搜索、RSS/Atom 阅读列为无需额外配置的渠道；GitHub 公开仓库读取也有直接路径。

需要配置

全网搜索 / X / GitHub 私有资源

搜索通过 MCP 接入 Exa；X 搜索/时间线、私有仓库、Issue/PR/Fork 等需要登录或进一步配置。

高风险

Cookie 登录平台

Twitter/X、小红书、Reddit、Facebook、Instagram 等涉及登录态；Cookie 等同于登录权限，建议专用小号和人工导出。

先做选择：只读公开网页时不必先配置 Cookie；要做平台搜索或时间线任务，再按渠道说明单独解锁。
02

安全安装：先预览，再决定是否允许改系统

当前 README 的安全口径是默认检查；显式 --system 才允许安装外部工具、写入配置或注册 Skill。

# 交给 Agent 的官方安装说明 帮我安装 Agent Reach：https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md # 只预览会做什么 agent-reach install --env=auto --dry-run # 默认检查环境，不主动改系统 agent-reach install --env=auto # 明确授权后才安装系统依赖与写入配置 agent-reach install --env=auto --system

OpenClaw 先查 exec

README 要求 OpenClaw 用户确认 exec 权限；否则 Agent 无法执行 pip install、mcporter 等命令。

本地 vs 服务器

README 称本地电脑不需要代理；服务器部署时代理可能产生额外成本，不能把“免费工具”理解为“零基础设施成本”。

安装后第一条命令

agent-reach doctor 检查渠道状态、当前后端和修复处方；它是验收入口，不是装饰信息。

04

一次真实任务：从安装到可验收输出

把“装好了”拆成环境状态、渠道路径、结果证据三层。

01安装前 dry-run，审查将要改什么
02执行安装并确认 Agent 能跑命令
03运行 doctor，看每个渠道状态
04用一个公开 URL 做最小读取
05记录来源、时间与失败原因
# 例：把一个公开网页交给 Agent 帮我看看这个链接：https://example.com/article # 例：让 Agent 检查环境 agent-reach doctor # 机器可读输出（v1.5.0 release 说明） agent-reach doctor --json
验收标准：不是“命令返回 0”就结束，而是知道这次读取用了哪个后端、返回内容来自哪里、登录态是否参与、失败时下一步如何修复。
05

版本变化提醒：渠道会退役，不能照抄旧文章

v1.4.2 的 release 明确移除抖音、微博、微信公众号，原因是上游停更、不可用或反爬加剧；README 当前口径也随之变化。

为什么需要版本核对

Agent Reach 的价值是能力层路由，不是固定工具清单；首选后端失效时可能切备选，渠道也可能被诚实下架。

更新后要做什么

先更新本体与上游工具，再运行 agent-reach doctor；不要只看 pip 版本或仓库 Star。

本卡采用版本

官方最新 release/API 交叉核验为 v1.5.0；X 帖是发现线索，不把帖子中的平台列表当成永久承诺。

06

凭据与卸载：把“能抓”与“该不该抓”分开

读取平台数据可能触发平台条款、封号和隐私风险；工具的能力不构成授权。

Cookie / Token

README 说明凭据保存在本地配置；不要把 Cookie、Token 写进卡片、日志、Issue 或共享脚本。本文不展示任何凭据值。

平台风险

需要登录态的平台可能检测脚本/API 调用；官方建议使用专用小号。遵守平台条款、访问权限和数据最小化原则。

卸载前预览

agent-reach uninstall --dry-run 先预览；正式卸载会涉及 ~/.agent-reach/、Skill 文件和 MCP 配置。

一句话：先用 dry-run 和 doctor 把“会改什么、现在通什么、实际走哪条路”看清楚，再给登录态和系统写入授权。
