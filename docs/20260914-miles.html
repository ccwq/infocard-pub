把大模型后训练变成工程流水线，但先从 8 张 GPU 的小实验开始

Miles 是 RadixArk 开源的 LLM/VLM 大规模后训练框架：SGLang 负责高吞吐 rollout，Megatron-LM 或 PyTorch FSDP2 负责训练，Ray 负责分布式编排。它能把 agentic RL、SFT、LoRA RL 和 on-policy distillation 放进同一套架构，但这不是“换上数据就能训”的轻量脚本。

实验卡 / 先读这一页

这不是推理服务，是训练闭环

Rollout

SGLang 在环境中生成轨迹：多轮对话、工具调用、终端任务和 sandbox 行为都发生在这里。

Score

奖励函数对轨迹打分；官方 quick start 用可检查答案的数学数据跑 GRPO。

Train

Megatron 或 FSDP2 消费轨迹，更新策略，再把新权重同步回 rollout 引擎。

Resume

checkpoint 不只是输出文件：官方 quick start 明确给出从最近 checkpoint 恢复的路径。

读者真正要做的选择

我只有一台 8-GPU 节点

先走 Docker + Qwen3-4B GRPO quick start，确认 GPU 可见、模型/数据可下载、reward 能上升、checkpoint 能恢复。

我要做 agentic RL

再确认环境 connector、sandbox、长上下文、异步 rollout 和 reward 设计；不要把聊天模型微调误称为 agentic RL。

我要上多节点/大模型

先核对 InfiniBand、RoCEv2 或 Slingshot 等高速互联，以及训练后端、权重同步和故障恢复方案。

本卡边界：没有在本机 GPU 上执行 Miles；所有命令是官方文档路径，示例日志和性能数字不是本次运行结果。
01

安装前置：Docker 不是可选的“美化层”，而是依赖封装

官方推荐 Docker，因为 Miles 固定了经过补丁处理的 SGLang、Megatron-LM 和 CUDA kernel 版本。

01

确认 GPU

NVIDIA GB300/GB200/B 系列、H200/H100、A100，或 AMD MI300X/MI325/MI350X/MI355X（ROCm）按官方状态表核对。

02

确认 Docker

Docker 能把 GPU 交给容器；NVIDIA 先用 docker run --rm --gpus all ... nvidia-smi 验收。

03

确认磁盘

官方 quick start 以 8 GPU 和至少 500 GB 可用磁盘为前置；模型、数据、转换权重和 checkpoint 都占空间。

04

确认互联

多节点训练需要高带宽互联；单节点可走 NVLink，不能把普通网络当作等价替代。

# NVIDIA Docker 路径（官方推荐） docker pull radixark/miles:latest docker run --rm \ --gpus all --ipc=host --shm-size=32g \ --ulimit memlock=-1 --ulimit stack=67108864 \ --network=host \ -it radixark/miles:latest /bin/bash # 容器内确认安装与 GPU python -c "import miles; print('Miles import OK')" nvidia-smi
依赖陷阱：官方安装文档明确提醒，自己安装错误 commit 的 SGLang/Megatron-LM 是常见 bug 来源；能用 Docker 就不要先手工拼环境。
02

最小可验证路径：Qwen3-4B + DAPO math + GRPO

先跑通一个可解释的 reward loop，再谈大模型、异步和 agent 环境。

03

读日志而不是看“启动成功”：四个指标告诉你训练到底发生了什么

官方示例日志中的键可以把 rollout、训练等待、actor 更新和 reward 分开观察。

perf 0: {'perf/rollout_time': 98.6, ...} rollout 0: {'rollout/raw_reward': 0.32, 'rollout/log_probs': -0.27, ...} step 0: {'train/loss': 0.0021, 'train/pg_loss': 0.0018, 'train/grad_norm': 0.62, ...} perf 0: {'perf/train_wait_time': 101.2, 'perf/actor_train_time': 41.3, ...}
问题指标/工具解释
策略在学习吗？rollout/raw_reward新鲜采样答案的平均奖励；要看趋势和方差，不要把单步上涨当成收敛。
瓶颈在哪？perf/rollout_time vs actor_train_time区分环境/推理慢，还是训练更新慢。
GPU 是否吃满？nvidia-smi dmon -s u结合通信和等待时间看，GPU 利用率高不代表 reward 设计正确。
Ray 是否有 worker 崩溃？~/.ray/session_latest/logs/worker-*.err不要只看主进程；分布式 worker 的错误可能先落在独立日志。
官方 quick start 的日志数值是 illustrative / abridged 示例；卡片不把它们冒充本次执行结果。
04

从 GRPO 到 agentic RL：变化的是环境与闭环，不只是换一个 flag

Agentic RL 让模型在真实或沙盒环境里多轮行动、调用工具并接受任务级反馈。

Rollout 层要增加什么

  • 多轮 session 与 token-in-token-out（TITO）
  • 工具执行与轨迹捕获
  • OpenEnv、Harbor、HUD、NeMo Gym、Verifiers 等 connector
  • AgentENV、Daytona、E2B 或 Modal 等 sandbox

训练层要重新验收什么

  • 奖励是否对应最终任务，而非只看文本相似度
  • on-policy / off-policy 调度是否符合实验设计
  • 长上下文、并发 session 和 KV cache 是否稳定
  • 失败环境能否重放、定位和恢复
不要混淆：SFT 是用标注数据拟合；agentic RL 是在环境中行动并依据奖励更新。Miles 同时支持二者，但它们的实验设计、数据和验收标准不同。
05

大规模训练的工程核心：权重同步、精度、故障恢复

这些机制决定“能跑一次”能否变成“可以长时间运行并复现”。

Weight sync / 权重同步

支持 colocated 与 disaggregated 拓扑；官方文档列出 broadcast、P2P RDMA 和 disk-delta 等传输路径。先确认拓扑再选 transport。

Precision / 低精度

README 列出 MXFP8、NVFP4、FP8、INT4 QAT、BF16、FP16；A100 对 FP8 功能有明确限制。

R3 / 路由回放

记录 rollout 时的 MoE expert routing，并在 trainer forward 中回放，针对大规模 MoE 的 rollout/training mismatch。

Fault tolerance / 容错

官方 README 声称 SGLang engine 崩溃时可恢复并原地续跑；上线前仍应模拟故障验证自己的集群和 checkpoint。

# 官方 quick start 的恢复原则 # 同一 launcher 重新启动，从最近 checkpoint 继续 python scripts/run_qwen3_dense.py --model-name Qwen3-4B # 观察训练/rollout/worker 日志 # 不要删除 /root/shared_data/checkpoints # 生产环境请把 --output-dir 指向持久化存储

08

适用边界、许可证与版本快照

这是一个高门槛训练基础设施，不是本地消费级微调工具。

适合

  • 有 GPU 集群、数据和奖励函数的研究/基础设施团队
  • 需要把 SGLang rollout 与训练后端接成闭环
  • 要做 agentic RL、LoRA RL、SFT 或 on-policy distillation
  • 愿意维护容器、Ray、通信、checkpoint 和 observability

不适合

  • 只有 CPU 或没有 GPU 直通权限
  • 希望一条命令在普通笔记本完成大模型训练
  • 没有可检查 reward、数据集或环境 sandbox
  • 把官方 case study 当成自己的成本/稳定性保证
当前快照：GitHub API 约 2,836 Stars、488 Forks、999 Open Issues；Python；默认分支 main；最新 release/tag 为 v0.1.0；Apache License 2.0。统计会变化，使用前回到官方仓库与文档。
