Planning with Files

Manus 风格持久规划 Skill，让 AI Agent 在 /clear、上下文丢失和崩溃后自动恢复任务状态。Benchmark 验证通过率 96.7%，A/B 盲测 3/3 胜出。

SKILL.md 标准 17+ IDE Hook v3.1.3 MIT 96.7% Benchmark
核心问题上下文窗口是 RAM，文件是磁盘

用文件系统作为 Agent 的持久化记忆层，上下文只保留当前轮次的引用和状态

Manus 原理文件即工作记忆，钩子即注意力锚点

3 个规划文件 + PreToolUse 钩子自动重读目标，Stop 钩子验证完成状态

L1 · 文件结构

3 文件模式

每个任务创建 3 个文件，构成完整上下文骨架：

  • task_plan.md — 阶段、状态、依赖链
  • findings.md — 研究/调查结果
  • progress.md — 会话日志、测试结果

初始化：./scripts/init-session.sh

L2 · 钩子系统

5 个生命周期钩子

Hook 自动注入规划，无需手动触发：

  • PreToolUse — 写/编辑/执行前重读任务计划
  • PostToolUse — 写完后提醒更新进度
  • Stop — 退出前验证所有阶段完成
  • PreCompact — 压缩前同步进度
  • SessionStart — 新会话/恢复时注入规划
L3 · 核心规则

5 条黄金规则

  • R1：无计划不开始，先建 task_plan.md
  • R2：每 2 次搜索/浏览后写 findings.md
  • R3：所有错误必须记录，避免重蹈覆辙
  • R4：不要重复失败，追踪尝试并改变方法
  • R5：完成后 Stop 钩子验证所有阶段完成
v3 模态选择：无 .mode = v2 行为（钩子仅提示，不强制）；--autonomous = 每轮仅注入一次（强模型减少 token 税）；--gated = 追加门控，阶段未完成时阻止退出（需 5 项条件同时满足）。门控宿主分级：硬拦截（Claude Code / Codex）→ 跟进注入（Cursor / Pi）→ 仅通知（OpenCode / Gemini CLI）。

L4 · v1→v2 迁移

向后兼容

v2.0.0 完全向后兼容。现有 task_plan.md 无需修改，Hook 自动降级处理缺失文件。

推荐更新状态格式：

  • v1: - [x] Phase 1 ✓
  • v2+: **Status:** in_progress

L5 · v2→v3 迁移

零破坏升级

v3.0.0 默认路径与 v2.43 字节完全相同。v3 新行为全为显式 opt-in：

  • 无 .mode → v2.43 行为
  • --autonomous → 减少复述 token
  • --gated → 完成门控（5 条件同时满足才阻止）
  • SHA 缓存移至 $XDG_CACHE_HOME/pwf-sha

门控安全：块计数器上限 20 stall 检测 + host stop_hook_active 后备。
