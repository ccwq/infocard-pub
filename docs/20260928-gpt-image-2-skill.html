GPT Image 2 Skill

它不只是一个“调用生图 API”的脚本，而是一套把生成、编辑、透明 PNG、历史记录和 Agent 输出协议统一起来的图像资产工具链。

gpt-image-2-core 负责 provider 路由、重试、凭据解析、SQLite history、结果存储和透明度质量门；CLI、桌面 App、Docker Web 与可安装 Skill 只是不同的入口。

01 · 先理解架构

四种入口，共用一套实现

01
ACLIRust binary，适合 Agent、CI 和脚本编排。
B桌面 AppTauri + React，通过 sidecar 调本地 CLI。
CDocker WebAxum + React，自托管 HTTP 服务。
D可安装 SkillNode wrapper 解析 binary，再转发参数。
ERust crate直接嵌入 gpt-image-2-core。
单一权威实现

core 不藏在 UI 里

provider、透明 PNG、config、history、keyring、OAuth refresh、retry 和 storage 都在 Rust core，而不是各入口各写一份。

数据目录分层

CLI jobs 不等于产品结果库

CLI/Skill 继续使用 $CODEX_HOME/gpt-image-2-skill/；桌面 App 和 Docker Web 把新结果写进自己的产品结果库，同时兼容读取旧 jobs。

调用边界

Agent 先看 envelope

成功与失败都能用 JSON 解析；进度事件独立走 stderr 的 JSONL，不把日志混进最终结果。

02 · PROVIDER 选择

同一套命令面，换的是上游凭据和协议

02
Provider入口与凭据能力边界
openaiOPENAI_API_KEY 或 --api-key；默认 gpt-image-2/images/generations、/images/edits multipart；支持 mask 等 OpenAI-only flags
openai-compatible--openai-api-base 或 config.json 命名 provider上游必须实现 generation 与 edit endpoints；不等于所有兼容站点都具备同样能力
codex~/.codex/auth.json；默认模型 gpt-5.4通过 image_generation 工具委派；401 自动 refresh 一次再重试
auto优先 config 的 default_provider没有默认配置时按 OpenAI → Codex fallback；实际命中 provider 可由 doctor 报告
03 · 透明 PNG 不靠运气

从“看起来透明”到“验证通过”

03
1Controlled matte先生成受控背景源图，而不是盲信 provider 原生透明参数。
2本地 extractchroma 处理单色底，dual 处理玻璃、光带和烟雾。
3Profile按 icon、product、glow 等素材类型选择质量门。
4Strict verify检查 alpha、残留、halo、边缘接触和棋盘格。
5交付只有 final PNG 过门禁，才作为可交付资产输出。
generate

端到端生成

transparent generate 组合生成 controlled matte、局部抠图和验证。

extract

受控输入的本地抠图

transparent extract --method chroma|dual 不是任意照片背景移除器，输入前提是受控源图。

verify

交付前最后一道门

transparent verify --strict --profile product 输出 alpha bounds、transparent ratio、partial pixels、stray pixels、halo 和 quality score。

04 · Agent 协议

stdout 给结果，stderr 给过程

04
JSON envelope

成功和失败都机器可读

成功返回 ok 与 data；失败返回 error.code、message 和可选 detail。常见码包括 auth_missing、refresh_failed、network_error、unsupported_option 和 transparent_verification_failed。

JSONL events

进度不污染最终结果

加 --json-events 后，multipart prepared、retry started 和 Codex SSE 增量等事件走 stderr，Agent 可以分别消费。

gpt-image-2-skill --json --json-events \
  transparent generate \
  --prompt "A red apple sticker, no text" \
  --out ./apple.png --size 2K --quality high

# doctor / auth / history / raw escape hatch
gpt-image-2-skill --json doctor
gpt-image-2-skill --json auth inspect
gpt-image-2-skill --json history list --limit 20
gpt-image-2-skill --json request create --request-operation generate \
  --body-file ./body.json --out-image ./out.png --expect-image
05 · 配置、密钥和历史

共享配置，但凭据来源可分层

05
config

$CODEX_HOME/gpt-image-2-skill/config.json

保存 default_provider、命名 provider、api base、模型和 credential source。$CODEX_HOME 默认是 ~/.codex/。

credentials

file / env / keychain

凭据可以来自文件、环境变量或 macOS Keychain、Linux Secret Service、Windows Credential Manager。

history

SQLite + result library

CLI history 使用 history.sqlite；桌面 App 和 Web 额外维护产品结果库，导出目录与内部 jobs 分离。

06 · 运行与存储

从本机命令到自托管产品面

06
CLI

安装后直接调用

cargo install、Homebrew、npm、cargo-binstall 都可提供 Rust CLI。

DESKTOP

Tauri + React

macOS、Windows、Linux 安装包；sidecar 使用同版本 CLI，默认导出到 ~/Downloads/GPT Image 2。

Origin / Archives

支持 local、S3、WebDAV、HTTP、SFTP；pipeline 可选 local_only、mirror、cloud_primary、cloud_archive_only。

07 · 安全边界

Relay 的任务不是“代存密钥”，而是缩小浏览器请求面

07
CLOUDFLARE WORKER

固定操作 + 公网校验

Relay 只拼接 /models、/images/generations、/images/edits 等固定路径，并校验公网 HTTPS、重定向和请求头。

REPLAY 防护

不重放不确定的生成 POST

浏览器先做无副作用 models 探测；生成或编辑状态不明确时，不自动切换通道重放，避免重复生成和重复扣费。

部署前要明确的事

Worker secret 需要 Turnstile keys 和至少 32 字节的 HMAC key；远程上传默认拒绝 loopback、private、link-local 目标。API key、provider 条款和远端对象生命周期仍由部署者承担。

08 · 限制与适用场景

它解决的是资产交付，不是所有图像问题

08

适合

Agent/CI 图像生成、参考图编辑、透明 icon/贴纸/产品图、自托管 Web、可追踪历史和统一错误处理。

不应误读

transparent extract 不是任意照片的通用抠图器；Codex 不应依赖 provider native transparent background。

验收方法

先 doctor 与 auth inspect，再生成；交付前使用对应 profile 的 transparent verify --strict。
