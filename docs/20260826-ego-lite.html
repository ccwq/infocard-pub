01 是什么 & 不是

ego lite 是一个 Chromium 浏览器，你和 AI Agent 同时使用、互不干扰。

✓ ego lite 是

  • 专为「人 Agent 并行」设计的浏览器
  • 每个 Agent 任务运行在独立 Space
  • 通过 ego-browser skill 暴露代码式 API
  • 迁移 Chrome 登录态/Cookie/密码/扩展
  • 压缩语义 Snapshot，token 效率高
  • kernel-level 定制，处理深层 iframe

✗ ego lite 不是

  • 非 browser-use / agent-browser 那类 automation library
  • 非 ChatGPT Atlas / Perplexity Comet 那类 AI Browser
  • 非 headless Chrome 或 offscreen rendering
  • 非云端浏览会话（数据留在本地）
  • 非给人类手工操作的 UI（面向 Agent）
  • 非 Playwright / Puppeteer 替代品

03 ego-browser 核心循环

ego-browser 是 Node.js heredoc runtime，面向 LLM Agent，非手工操作。

ego-browser nodejs — 典型 heredoc 示例
// Agent 写入完整 JS 流程，一次 stdin 交付 ego-browser nodejs await useOrCreateTaskSpace('search github issues') await openOrReuseTab('https://github.com/issues', { wait: true, timeout: 20 }) cliLog(await snapshotText()) // refs 来自 snapshotText() 输出的 [ref=N, loc=...] await click('@21', { label: 'check login state' }) await fillInput('@2', 'user@test.com') await waitForLoad() cliLog(await js(String.raw`(() => { return [...document.querySelectorAll('article')].map(e => e.innerText) })()`))
helpers: snapshotText · click · fillInput · typeText · wait · js · cdp · cliLog · useOrCreateTaskSpace · openOrReuseTab · captureScreenshot

核心步骤

  • ① useOrCreateTaskSpace(name) 复用或创建 Space
  • ② openOrReuseTab(url) 打开目标页面
  • ③ snapshotText() 读取语义快照（[ref=N, loc=...]）
  • ④ 用 @N 或 CSS selector 操作页面
  • ⑤ cliLog(...) 输出最终结果

注意事项

  • heredoc 内是 Node.js 上下文；js() 内是页面 DOM 上下文，勿混用
  • @N 只对最近一次 snapshotText() 的 refMap 有效
  • 跨快照引用元素请用 loc=... selector
  • 正则写在 js() 时双写反斜杠或用 String.raw
  • 不要 preflight：which ego-browser / node -v 仅在首次报错时执行

07 ego-browser 完整 Helper 参考

所有 Helper 无需 import，直接在 heredoc 中调用 camelCase 名称。以下是官方文档整理的完整 API 速查表。

Space 生命周期

  • listTaskSpaces() — 列出当前所有 Space
  • useOrCreateTaskSpace(name) — 复用或新建命名 Space
  • completeTaskSpace(name) — 任务完成，保留最后一个标签页
  • closeTaskSpace(name) — 关闭并销毁 Space

name 建议 3-6 词自然语言描述，不含占位符。

导航与 Tab 管理

  • listTabs() — 列出当前 Space 的所有 Tab
  • openOrReuseTab(url, { wait, timeout }) — 打开或复用 Tab
  • gotoAndWait(url, { timeout, settle }) — 导航并等待网络空闲
  • newTab(url) — 在当前 Space 新建 Tab
  • switchTab(tabId) — 切换到指定 Tab
  • currentTab() — 返回当前 Tab 信息
  • ensureRealTab() — Space 为空时确保至少有一个真实 Tab

观察与快照

  • snapshotText() — 完整页面语义快照（含 [ref=N, loc=...]）
  • snapshotText({ scope: 'only_within_viewport' }) — 仅视口内快照
  • captureScreenshot(file?) — 截图，可选保存文件名
  • drainEvents() — 消费导航 / 网络事件队列
  • pageInfo() — 返回当前页面基本信息

快照默认全页，200-400 token/页，远低于原始 HTML。

鼠标与滚动

  • click(target, { label? }) — 支持 @N / CSS selector / [x,y] 坐标
  • doubleClick(target) — 双击
  • hover(target) — 悬停
  • dragMouse([from, to]) — 拖拽
  • scrollBy(px) — 按像素垂直滚动
  • scroll({ dy: px }) — 同上，显式参数
  • scrollToBottomUntil(asyncFn, { step, wait, maxSteps }) — 滚动到底部条件

键盘与输入

  • typeText(text) — 逐字输入文本
  • fillInput(target, value) — 直接填充表单字段
  • pressKey(keyName) — 按键（如 'Enter', 'Escape'）
  • dispatchKey(keyEvent) — 分发原始键盘事件

等待与网络

  • wait(seconds) — 等待秒数（不含 Ms 的参数）
  • waitForLoad() — 等待页面 load 事件
  • waitForElement(target) — 等待元素出现
  • waitForNetworkIdle() — 等待网络请求结束
  • httpGet(url) — 在页面上下文发起 GET 请求

timeout 参数单位为秒，Ms 结尾才是毫秒。

浏览器执行层

  • js(source) — 页面 DOM 上下文执行 JS（不用传 function）
  • elementEval(target, fn) — 对单个元素执行 JS
  • cdp(domain.method, params) — 原始 CDP 调用
js() 正确写法
const items = await js(String.raw`(() => { return [...document.querySelectorAll('article')].map(e => e.innerText) })()`) // ❌ js(el => el.getBoundingClientRect()) // closure 丢失 await elementEval('@1', el => el.getBoundingClientRect())

Skill 工作区与环境变量

  • siteSkills() — 列出当前加载的 Site Experience
  • cliLog(value) — heredoc 内唯一输出通道
  • help(name) — 查询 Helper 用法
环境变量覆盖
# 指定 skill workspace 路径 EGO_BROWSER_AGENT_WORKSPACE=/path/to/ego-browser ego-browser nodejs <<'EOF' await cliLog(await siteSkills()) EOF
08 Snapshot 语义快照机制

kernel-level 定制快照，内置于 Chromium 引擎，处理深层 iframe / shadow DOM / 第三方 SDK，比 JS shim 快且可靠。

snapshotText() 输出示例 — 登录页
Page: Example - Log in URL: https://example.com/login @1 [heading] "Log in" @2 [form] @3 [input type="email"] placeholder="Email" @4 [input type="password"] placeholder="Password" @5 [button type="submit"] "Continue" @6 [link] "Forgot password?"

@N ref 工作原理

  • ref 来自元素的 CDP backendNodeId，同一元素通常跨快照保持相同编号
  • 每次 snapshotText() 重置 refMap，@N 只对最近一次快照有效
  • 元素滚动出视口 / DOM 重渲染后 @N 可能失效
  • 跨轮次稳定引用：用 loc=... selector 或 CSS selector

为什么比 HTML 更高效

  • 整页通常只需 200-400 token，远低于原始 HTML
  • Accessibility Tree 结构化输出，Agent 直接理解语义
  • 第三方 SDK（Stripe / Salesforce / Intercom / React Portal）可穿透
  • class 名轮转不破坏 @N 引用
Unknown ref 常见原因：① 元素已滚动出视口 ② DOM 重渲染后 ref 改变 ③ 上一轮用了 only_within_viewport 但本轮用了 full_page。处理方案：用 loc=... selector 替代 @N，或先滚动到目标元素再重取快照。

何时用 full_page vs viewport

  • full_page（默认）：长列表、整页表单、多步骤流程
  • only_within_viewport：仅需要当前可见区域时使用

跨轮次稳定选择器策略

  • 从快照中复制 loc=... 属性（推荐）
  • 手写 CSS selector：button.primary、input[name="email"]
  • 避免坐标点击：坐标在响应式页面不可靠

12 排错清单

Error 1: "command not found: ego-browser"

原因：skill 未正确安装，或 ego lite 未启动。

  • ① 确认 ego lite 应用已安装并运行中
  • ② 确认 skill 已写入 Agent 目录：ls ~/.agents/skills/ego-browser/
  • ③ 重新运行安装：npx skills add github:CitroLabs/ego-lite/skills/ego-browser
  • ④ 在 Agent 中输入 /ego-browser 激活 skill

Error 2: "Unknown ref @N"

原因：@N 只对最近一次 snapshotText() 有效，DOM 重渲染或滚动导致 ref 失效。

  • ① 重新调用 snapshotText() 获取最新 refMap
  • ② 用 loc=... selector 替代 @N（跨轮次稳定）
  • ③ 确认元素在当前视口内，必要时先 scrollBy(600)
  • ④ 如果上轮用了 only_within_viewport，本轮改用 full_page

Error 3: Agent 权限被拒绝

原因：Codex / Claude Code 需要 Full Access 权限才能启动本地应用。

  • ① 在 Agent 设置中查找权限选项
  • ② 将权限级别从"受限沙盒"切换为"Full Access"
  • ③ 重新尝试运行 /ego-browser 任务

Error 4: 页面加载超时

原因：timeout 默认值不足以应对慢速网络。

修复方式
// ❌ 默认 timeout: 20s 可能不够 await openOrReuseTab('https://slow-site.com', { wait: true, timeout: 60 }) // ✅ 用 settle 参数等网络空闲 await gotoAndWait('https://api-heavy-site.com', { timeout: 45, settle: 2 })

Error 5: js() 结果返回 undefined

原因：传入 function 而非字符串，closure 变量被 toString() 丢弃。

正确写法
// ❌ function 形式 closure 丢失 await js(el => el.getBoundingClientRect()) // ✅ 用 elementEval 对单个元素 await elementEval('@1', el => el.getBoundingClientRect()) // ✅ 字符串形式 + String.raw 避免转义 const result = await js(String.raw`document.querySelector('h1').innerText`)

Error 6: Space 内没有 Tab

原因：新建 Space 默认没有 Tab，直接调用 snapshot/click 会失败。

修复方式
// ✅ 先确保有真实 Tab await useOrCreateTaskSpace('my-task') await ensureRealTab() await openOrReuseTab('https://example.com', { wait: true })
13 性能对比 & Benchmark

官方内部 Benchmark，覆盖 4 个复杂浏览器自动化任务，对比对象为 Vercel agent-browser。

速度对比（官方数据）

官方测试集：4 个复杂浏览器自动化任务，ego lite 平均比 agent-browser 快 2.5×，困难任务差距更大。

  • 普通任务：~1.5-2× 提升
  • 复杂任务（多步流程、表单嵌套）：~2.5-3.45× 提升
  • 任务越难，ego lite 优势越大

Benchmark 方法：控制任务相同、模型相同，对比实际完成时间与 token 消耗。

Token 效率（官方数据）

语义快照压缩效果：整页 HTML → 语义快照，平均 token 减少约 70-85%。

  • 原始 HTML 快照：通常 2000-8000 token/页
  • 语义 Accessibility Tree：通常 200-400 token/页
  • Agent 每步工具调用减少（heredoc 内联多步）
Benchmark 局限性：官方自测，agent-browser 版本和任务复杂度会随时间变化。建议在真实任务中自行对比。ego lite 的 heredoc 模式对长流程任务（5+ 步骤）优势最明显；短任务（1-2 步骤）两者差距较小。

19 官方 FAQ

基于官方文档整理的高频问题解答。

Q: 与 Playwright / Puppeteer 有何不同？

Playwright/Puppeteer 是浏览器自动化库，ego-browser 是自动化运行时。后者专为 LLM Agent 设计，语义快照替代原始 HTML，heredoc 内联多步替代逐命令调用，无 SDK 集成，Model-agnostic。人类不应直接使用 ego-browser。

Q: Space 与 Chrome Profile 的区别？

Chrome Profile 是独立的浏览器配置文件，数据完全隔离。Space 是同一个 Chromium 进程内的逻辑隔离区，共享登录态、扩展、cookies，同时每个 Space 的 browsing context 完全独立。Space 比 Chrome Profile 更轻量且支持 Agent 动态切换。

Q: Windows 和 Linux 何时可用？

Windows 和 Linux 版本在官方路线图上，尚未发布。具体时间线以官方公告为准。可关注 GitHub Releases 或 Discord 社区获取最新进度。

Q: ego lite 会收集我的浏览数据吗？

不会。浏览数据（密码/cookies/历史/书签）永不离开本机。页面内容由你自己的 Agent 读取和操作。ego lite 仅在安装时记录用户是否选择了 Chrome 数据迁移，没有任何遥测或上传行为。

Q: 哪些站点 ego lite 无法处理？

① 需要硬件令牌（U2F key）的强双因素认证（不是手机 TOTP）② 复杂的 CAPTCHA（需人工解决）③ 高度动态的 SPA（每个操作都需要特殊等待逻辑）。对于①和③，ego lite 的 kernel-level snapshot 比 JS shim 工具更可靠。

Q: 可以同时运行多少个 Space？

取决于机器硬件配置。官方测试中常见 5-10 个并行 Space（16GB+ RAM 推荐）。Space 之间完全独立，共享内存极少。每个 Space 的资源占用与普通 Chrome Tab 相当。

Q: ego-browser 支持哪些操作系统？

ego-browser（Node.js CLI）与 ego lite（浏览器）共同工作：

  • ego lite macOS GA：正式可用
  • ego lite Windows：路线图
  • ego lite Linux：路线图
  • ego-browser Node.js CLI：跨平台（需要 ego lite macOS 运行）

Q: Experience 积累功能何时上线？

官方预告该功能即将到来（coming soon）。首次运行成功后，验证过的操作自动沉淀为 Site Experience，同域名下次任务可加载已验证方案，二次运行预期快 5×。具体上线时间以官方公告为准。

23 js() 上下文与 CDP 深度指南

js() 运行在页面 DOM 上下文，cdp() 直接调用 Chrome DevTools Protocol。两者是ego-browser 的底层扩展机制。

核心原则：heredoc 内（Node.js 上下文）与 js() / cdp() 内（浏览器上下文）是两个完全隔离的世界。不要把 heredoc 里的变量传入 js()（因为 js() 是 Runtime.evaluate 字符串）；也不要把 js() 里的变量当作 Node.js 变量。

js() 正确使用模式

✅ 正确：字符串 + String.raw

js() 标准写法
const titles = await js(String.raw`[...document.querySelectorAll('h2')].map(h => h.innerText)`) const links = await js(String.raw`([...document.links].map(a => ({ text: a.innerText, href: a.href })))`) const rect = await js(String.raw`document.querySelector('#target').getBoundingClientRect()`)

❌ 错误：function 形式

❌ 错误写法
// ❌ Closure 变量丢失，产生警告 await js(el => el.getBoundingClientRect()) // ❌ 参数无法传入（JSON.stringify 额外转义） await js('document.querySelector("' + selector + '").click()')

js() 复杂提取示例

js() 高级提取模式
// 提取表格数据（带类型推断） const tableData = await js(String.raw`(() => { const rows = [...document.querySelectorAll('table tbody tr')] return rows.map(row => { const cells = [...row.querySelectorAll('td')] return { col1: cells[0]?.innerText.trim(), col2: cells[1]?.innerText.trim(), col3: cells[2]?.innerText.trim(), col4: parseFloat(cells[3]?.innerText.replace(/[^\d.]/g, '')) || 0 } }) })()`) // 提取带图标的列表项（class 轮转时用 aria-label） const navItems = await js(String.raw`([...document.querySelectorAll('[role="navigation"] a')].map(a => ({ label: a.getAttribute('aria-label') || a.innerText.trim(), href: a.href })))`) // 提取 React 组件状态（如果页面是 React SPA） const reactState = await js(String.raw`(() => { const root = document.querySelector('#root') const keys = Object.keys(root || {}) return { hasRoot: !!root, childCount: root?.children.length } })()`)

elementEval：单元素 DOM 操作

elementEval vs js()

  • js(string)：全局页面上下文执行
  • elementEval(target, fn)：对特定元素执行，fn 参数是该元素
  • elementEval 自动注入元素引用，避免 querySelector
  • 适合测量单个元素、获取元素特有属性
elementEval 示例
await elementEval('@15', el => ({ tag: el.tagName, rect: el.getBoundingClientRect(), visible: el.offsetParent !== null, text: el.innerText })) await elementEval('img.avatar', img => ({ naturalWidth: img.naturalWidth, naturalHeight: img.naturalHeight, complete: img.complete }))

cdp() 原始 CDP 调用

当 Helper 不满足需求时，直接调用 Chrome DevTools Protocol。

cdp() 示例
// 截图（通过 CDP 获取二进制数据） const pngData = await cdp('Page.captureScreenshot', { format: 'png', quality: 100 }) // 获取所有 console 消息 await cdp('Log.enable') await openOrReuseTab(url) const logs = await cdp('Log.getEntries') // 获取网络请求记录 await cdp('Network.enable') await cdp('Network.getAllCookies')

24 Experience 积累 & Skill 开发

ego lite 的 Experience 积累机制让每次成功任务成为下一个任务的加速器，官方预告即将到来（coming soon）。

Experience 积累工作流

当 Experience 功能上线后，每个成功完成的任务会自动沉淀：

  • ① Agent 执行 heredoc，完成任务
  • ② ego-browser 将验证过的操作序列记录为 Artifact
  • ③ Artifact 按域名归档至 learnings/<domain>/
  • ④ 下次同域名任务，Agent 加载已验证 Artifact
  • ⑤ 二轮运行跳过试错，直接执行经验路径
  • ⑥ 官方测试显示：二轮运行快 5×

Experience vs Hardcoded Selector

硬编码 selector 的问题：

  • class 名在 React/Next.js HMR 中频繁变化
  • 第三方 UI 库（Material UI / Ant Design）class 名带 hash
  • 同一页面在不同时间点 DOM 结构不同

Experience 积累的价值：

  • Agent 在运行时动态学习 site-specific 的最优路径
  • artifact 记录的是语义层（"点击'登录'按钮"）而非 class 层
  • 跨 Site 泛化能力更强

26 工作原理解析

理解 ego lite 的底层工作原理，有助于在复杂场景下正确使用和排错。

三层架构

  • Layer 1 — Chromium 内核：ego lite 是基于 Chromium 的定制浏览器，与 Chrome 共享渲染引擎，但内置 kernel-level 快照处理。
  • Layer 2 — Space 隔离层：每个 Space 映射到一个独立的 BrowserContext（CDP 概念），共享主 Chromium 进程，不启动独立进程。
  • Layer 3 — ego-browser runtime：Node.js CLI，通过 CDP 与 ego lite 通信，将 heredoc 中的 JS 代码注入到目标 Space 的页面上下文。

快照生成流程

  • ① Agent 调用 snapshotText()
  • ② ego-browser 通过 CDP 向 Space 发送 Accessibility Tree 请求
  • ③ Chromium 内核返回页面的 Accessibility Node 树
  • ④ ego-browser 遍历节点，生成带 ref 标记的语义树
  • ⑤ 返回 200-400 token 的结构化文本给 Agent
为什么 kernel-level 比 JS shim 更可靠：JS shim（如 browser-use）通过注入脚本拦截 DOM 事件和 MutationObserver 来生成快照。但它们无法感知跨域 iframe（浏览器的安全边界）——脚本无法跨域注入。ego lite 的快照在内核层生成，Chromium 本身就拥有完整的跨域 DOM 视图，因此能穿透 iframe、shadow DOM 和动态加载的第三方组件（Stripe/Intercom/Salesforce 等）。
