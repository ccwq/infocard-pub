01
逐项安装与使用条件

01–06｜先决定动画如何表达

视频组件、网页动作、数学讲解和设计动画播放是不同入口。先选与你的内容匹配的一条，不要把六项理解成必须叠加的依赖。

01

Remotion

用 React 组件和网页技术编写、渲染视频。

适合把标题、图表、画面元素写成可重复渲染的视频组件。和网页动画库相比，它的目标是成片；已有 React 项目经验时更容易理解这一入口。

GitHub · remotion-dev/remotionREADME

安装／运行入口

这是新建视频项目的交互式入口，不是给现有项目随手加一个动画函数。先确定项目目录；包管理器与运行环境按仓库当前说明准备。

npx create-video@latest

别混淆：Remotion 采用专门的许可证条款，不能因仓库公开就当成所有团队、所有商业用途都免费。正式使用前阅读 LICENSE.md。

第一次先验：先渲染一个短镜头，核对画面尺寸、帧率、字体和输出文件，再添加配音与字幕。

02

Remotion Skills

给智能体提供 Remotion 项目的创作与实现规范。

它是规范包，和 01 的渲染工具不是一回事。可在让智能体编写 Remotion 视频时配合使用，但不承担视频渲染本身。

GitHub · remotion-dev/skillsREADME

安装／运行入口

下列两条是不同工具链的安装入口，选择与你使用的客户端匹配的一条；不是必须先后运行。安装规范包也不等于装好了 React、Remotion 与渲染依赖。

npx skills add remotion-dev/skills
gh skill install remotion-dev/skills

别混淆：原帖用一个总称收纳 20 项，容易让人误会所有仓库都能以同一种方式载入。此项才明确是供智能体使用的项目规范；其余多为库、引擎或桌面软件。

第一次先验：让客户端确认已读取项目规范，再检查生成的项目能否按 Remotion 自身流程渲染。

03

Anime.js

用 JavaScript 编排 CSS、SVG 和 DOM 动画。

适合网页里一组元素按时间关系运动的场景。原帖强调时间线编排；如果目标只是交互页面中的动作，不必先引入完整的视频制作框架。

GitHub · juliangarnier/animeREADME

安装／运行入口

包名 animejs 来自官方使用文档；材料中的 README 只有贡献者依赖安装，不能把贡献者的 npm i 与用户安装混为一谈。

npm install animejs

别混淆：网页里看起来流畅，不等于已经输出可交付的视频文件。若要成片，还需要单独确定录制或渲染路径。

第一次先验：在目标浏览器检查元素运动、时间线顺序与缩放后的布局，再决定如何捕获画面。

04

Motion

为 React、JavaScript 与 Vue 界面提供动画和布局过渡。

适合 UI 状态变化和布局移动。它与 Anime.js 有重叠，选择时先看当前界面技术和动作组织方式；不需要仅因两者都在清单上就同时引入。

GitHub · motiondivision/motionREADME

安装／运行入口

下列命令安装 motion 包。本文只确认安装入口，不假设各框架的导入写法相同，具体集成方式以仓库文档为准。

npm install motion

别混淆：界面动画与离线视频渲染是不同任务。不要把 UI 过渡能力直接解释为完整的剪辑、配音和导出系统。

第一次先验：用真实组件状态变化做一次过渡，观察布局变化时的位置与尺寸是否符合预期。

05

Manim

用代码制作数学公式、图表和讲解动画。

当重点是公式推导、几何关系或图表讲解时，这比通用场景工具更贴近内容。原帖把它放在动画层，不意味着它和网页 UI 库共用运行环境。

GitHub · ManimCommunity/manimREADME

安装／运行入口

材料将此命令追溯到官方安装文档。Python 包安装只是入口；系统依赖和具体渲染方式仍要按 Manim 文档准备。

pip install manim

别混淆：配图来自 README 的命令语法说明图，不是终端执行截图或本文渲染出的数学动画，也不能证明当前机器已经具备渲染环境。

第一次先验：先跑官方最小示例，确认生成的图形、文字和视频文件都正常，再加入长公式。

06

Lottie

在网页中播放从 After Effects 导出的动画 JSON。

适合把已有的设计动画作为网页素材播放。和用代码从头描述动画不同，这条路线要先有可供播放器读取的动画数据。

GitHub · airbnb/lottie-webREADME

安装／运行入口

npm 与 Bower 是不同安装路径，按项目现状选择一条；此处保留 README 中的两种写法，不要求一起执行。

npm install lottie-web
bower install bodymovin

别混淆：“体积很小”是原帖的概括，不是所有素材的体积保证。播放器安装也不包含动画制作文件、字体和导出设置。

第一次先验：把实际导出的动画 JSON 放进目标页面，检查图层、字体与播放结果；不要仅凭 README GIF 判断自己的素材兼容。

07

MCP for Blender

通过 MCP 让 AI 客户端操作 Blender 场景。

它连接的是客户端与 Blender 场景操作，不是替换 Blender 的建模、材质和渲染能力。原帖的“让 Claude 帮你搭和改”应理解为借助桥接工具控制场景。

GitHub · ahujasid/mcp-for-blenderREADME

安装／运行入口

此命令下载远程脚本并交给 shell 执行。保留来源写法供查阅；实际使用前先审查脚本内容、下载来源与权限范围，不建议未经检查直接粘贴。

curl -LsSf https://www.mcp-for-blender.com/install.sh | sh

别混淆：客户端、MCP 连接和 Blender 本体都属于前置条件。能安装桥接端，不等于场景已经连通，也不等于任何修改都安全。

第一次先验：在可丢弃的空场景里测试一个简单对象操作，确认连接、权限与保存位置后再打开正式工程。

08

Three.js

用 JavaScript 构建浏览器中的 3D 场景、相机与渲染。

它是这一组浏览器 3D 工具的基础入口。后面的后处理、粒子和调参需要围绕具体场景来接，而不是先把效果库装满再找用途。

GitHub · mrdoob/three.jsREADME

安装／运行入口

在自己的 JavaScript 项目中安装 three。相机、场景和渲染循环仍需你或智能体编写；一个依赖安装命令并不会生成完整作品。

npm install three

别混淆：Blender 场景操作与浏览器 3D 是两条不同路线。本文没有验证两者之间的模型导出、材质或动画数据交换。

第一次先验：先让一个简单场景在目标浏览器稳定显示，再增加纹理、灯光、模型与录制步骤。

09

Three GPU Pathtracer

在 GPU 上进行基于物理的路径追踪渲染。

README 介绍使用 three-mesh-bvh 与 WebGPU 计算着色器来加速渲染，并提供材质、光照与动画渲染示例。它解决的是画面形成方式，不是物体运动规律。

GitHub · gkjohnson/three-gpu-pathtracerREADME

安装／运行入口

注意：材料里的 npm install 是在下载或检出的本仓库根目录里安装本地示例依赖。它不是把路径追踪器加进任意项目的包名命令；README 另用 npm start 启动示例。

npm install

别混淆：真实感不等于固定帧率，也不意味着每台设备都能以同样速度输出。本文没有测 GPU 兼容性、收敛时间或视频渲染耗时。

第一次先验：先运行仓库的基础场景，观察目标设备的渲染结果，再选择是否为当前镜头引入路径追踪。

10

Jolt Physics

为游戏与 VR 提供刚体、碰撞检测等物理模拟。

README 明确列出刚体、约束、软体和其他模拟能力，并将用途限定在游戏或 VR 一类近似模拟场景。物理引擎算运动与碰撞，渲染器负责把结果画出来。

GitHub · jrouwe/JoltPhysicsREADME

安装／运行入口

下面逐字保留资料给出的源码构建片段，但它没有交代完整工作目录，且 -config 参数不能直接当作已验证的通用 CMake 写法。实际构建以仓库 Build/README.md 的平台步骤为准；本文不把它标为可连续执行的一键脚本。

git clone https://github.com/jrouwe/JoltPhysics.git
cmake -B Build -DCMAKE_BUILD_TYPE=Release
cmake --build Build -config Release

别混淆：它是 C++ / CMake 源码工程，不是 npm 或 pip 插件；浏览器使用还涉及独立的 WebAssembly 路线。配图是 README 引用的游戏封面，不是物理测试截图。

第一次先验：按官方构建文档生成并运行 Samples 或 HelloWorld，再判断如何把模拟结果接给自己的渲染场景。

11

postprocessing

为 Three.js 画面添加全屏后期处理效果。

原帖列举泛光、景深与调色。这类工具作用在渲染画面上，适合已有场景后补视觉风格；它不负责搭建模型，也不生成碰撞和刚体运动。

GitHub · pmndrs/postprocessingREADME

安装／运行入口

此命令同时列出 three 与 postprocessing。接入现有工程时还要核对依赖版本和渲染路径，不能把装包成功等同于效果已接入。

npm install three postprocessing

别混淆：后处理与路径追踪分属不同环节，不能仅凭两者都能改善画面就假设可以无条件叠加。本文没有做联合管线测试。

第一次先验：先只加一个效果，在同一镜头比较开关前后的画面、可读性和运行负担，再逐项增加。

12

Three.quarks

为 Three.js 场景提供粒子与实时特效系统。

当镜头需要粒子或动态特效时再考虑这一层。它与物理模拟的职责不同：看上去有运动的粒子，不自动意味着存在你需要的碰撞和物理行为。

GitHub · Alchemist0823/three.quarksREADME

安装／运行入口

材料给出 three.quarks 包安装入口。仍需依据仓库示例创建效果并挂接到场景，安装不会自动把特效写入现有镜头。

npm install three.quarks

别混淆：资料用“高性能”描述此项目，本文没有测粒子数量、设备负载或帧率上限；不要把 README 示例图当成自己设备的性能承诺。

第一次先验：在目标设备逐步增加特效复杂度，检查画面是否符合创作目标，再考虑录屏或离线输出。

13

Tweakpane

用轻量控制面板实时调参数并监控数值。

它适合把镜头参数暴露出来，让你在画面旁调数值。面板是调试和创作接口，不是另一套渲染器，也不会替你决定什么画面更好。

GitHub · cocopon/tweakpaneREADME

安装／运行入口

README 指向官方 Getting Started；材料按文档记录 tweakpane 的包安装命令。具体参数绑定要由项目实现。

npm install tweakpane

别混淆：面板里的临时调节值是否会被保存、能否随渲染复现，要看工程如何记录，不能假设拖过滑块就已经固化成作品参数。

第一次先验：把选定的参数写回工程配置，再重新打开或重渲染一次，确认不是仅在当前页面会话生效。

逐项安装与使用条件

14–17｜素材生成、旁白、分析和字幕分开做

先分清输入是什么：文字进配音系统，声音进识别或分析系统，生成工作流则依赖所选模型与节点。框架安装只是第一步。

14

ComfyUI

用节点连接图像、视频、音频等生成工作流。

在需要生成素材时，它可以承担独立的生成环节。不要把节点工作流与时间线剪辑混成一个概念：生成了素材，还要确定怎么进入后续镜头与声音流程。

GitHub · Comfy-Org/ComfyUIREADME

安装／运行入口

材料中的新版 README 推荐 comfy-cli。先安装管理工具，再运行 comfy install；模型、节点与设备支持需按选定工作流另行准备。

pip install comfy-cli
comfy install

别混淆：装好框架不等于模型权重已就绪，也不等于别人分享的工作流在本地可复现。第三方节点和模型各有来源、依赖和使用条款。

第一次先验：先用明确依赖的小工作流出一份素材，记录节点与模型版本，并核对生成文件能被后续工具读取。

15

CosyVoice

将文本合成为多语种、可控制的语音旁白。

它在这份清单里负责把稿子变成声音，与识别已有音频的 WhisperX 方向相反。README 提供模型与推理入口，环境安装后仍有模型下载步骤。

GitHub · QwenAudio/CosyVoiceREADME

安装／运行入口

克隆命令保留 README 使用的 FunAudioLLM 路径，仓库入口则沿用原帖的 QwenAudio 链接，二者不在此擅自改写。先完成克隆并进入 CosyVoice 目录，再执行 Conda 环境与 requirements 安装；本段原始命令列表省略了进入目录步骤。

git clone --recursive https://github.com/FunAudioLLM/CosyVoice.git
conda create -n cosyvoice -y python=3.10
conda activate cosyvoice
pip install -r requirements.txt

别混淆：下列 requirements 命令是材料记录的简化写法，README 对应位置带有镜像参数。本文没有运行推理或比较音质；模型条款、声音授权与被配音内容都要单独检查。

第一次先验：先用自己有权使用的文本和声音做短句，检查专有名词、数字读法与时长，再录入正式旁白。

16

librosa

在 Python 中分析音频与音乐信号。

原帖建议用它抓节拍，让画面随音乐运动。分析结果可以成为动画时间点的输入，但从分析数组到镜头动作仍需要你定义映射逻辑。

GitHub · librosa/librosaREADME

安装／运行入口

pip 与 Conda 是可选的安装路径，按现有 Python 环境选择一条。不要为照抄清单而在同一环境重复混装。

pip install librosa
conda install -c conda-forge librosa

别混淆：它负责音频分析，不是自动配乐或自动卡点剪辑成片工具。附图是 README 项目标识，不是频谱或节拍分析结果。

第一次先验：把检测到的时间点叠到自己的音频上试听，人工修正与创作节奏不一致的位置，再用于画面切换。

17

WhisperX

进行语音识别、逐词时间对齐与说话人分离。

它适合给已有音频建立文字和时间的对应关系。与配音工具相比，这是声音之后的整理环节，常用于字幕时间轴。

GitHub · m-bain/whisperXREADME

安装／运行入口

pip 是安装入口，uvx 是另一种运行入口；按自己的环境选择，不是强制连续两步。模型下载与说话人分离的额外要求按仓库说明配置。

pip install whisperx
uvx whisperx

别混淆：“逐词时间戳”不等于每个字都无需复核。字幕中的人名、术语、标点和说话人切换仍需听音核对，本文没有测识别准确率。

第一次先验：先转写一段有停顿与专有名词的音频，检查词语和时间位置，确认之后再批量生成字幕。

LosslessCut

快速剪切视频片段，尽量避免重新编码。

适合已经有视频后做快速取舍。若任务包含复杂的字幕合成、叠画或统一重新编码，仍要确定其他处理方式，不能把快剪工具当成完整的动效制作环境。

第一次先验：输出一小段，复核开头、结尾、音轨和目标播放器播放情况，再处理整段素材。

组合
编辑建议 · 未做联合运行测试

别从装齐 20 项开始，从一个短片任务开始

以下按功能分工提出组合。它们不是仓库共同发布的集成方案，接口、版本与素材交换仍需用你自己的项目验证。

讲解短片

画面先用 Remotion 或 Manim

以文字、图表和界面为主，可先试 Remotion；以公式和数学图形为主，可先试 Manim。二者是入口选择，不必同时采用。需要旁白时再接 CosyVoice，已有语音需要字幕时再看 WhisperX。

交接点：确定旁白时长与画面节奏，用一段短镜头检查字幕是否跟着声音走，最后再让 FFmpeg 处理需要的编码。

浏览器 3D

Three.js 先把场景跑起来

只在需求出现时加入 Three.quarks 粒子、postprocessing 后期或 Three GPU Pathtracer。参数需要边看边调时用 Tweakpane；需要物理行为时另行评估 Jolt 的接入路径。

交接点：先确认目标设备能稳定呈现镜头。实时录制可试 OBS；不要默认浏览器运行、物理模拟和最终编码已经共用同一时间基准。

已有素材剪短

录制、取段与转码分开验收

已有桌面演示可先用 OBS 录制，用 LosslessCut 取片段；需要换格式或统一编码再用 FFmpeg。只有需要生成新素材时才引入 ComfyUI。

交接点：先检查录下的音轨和画面，再核对切点与输出兼容性。没有新增需求时，不必把 3D 或生成模型一起装进来。

用一个可丢弃的短样片检查五个交接点

  1. 定输出。先写明横竖屏、画面尺寸、帧率、声音和字幕需求，避免最后才发现素材比例不合。
  2. 定时间。把旁白、节拍或字幕时间点映射到画面；这一步需要工程逻辑，不会因库都已安装而自动发生。
  3. 定素材。检查图像、模型、语音是否能被下一环节读取，同时保存来源与使用许可。
  4. 定参数。把调参结果、模型与节点版本记进项目；不要依赖某次页面会话里的临时状态。
  5. 看成片。播放真实输出文件，核对首尾、同步、缺字、音轨与目标播放器。能预览不等于能交付。

安装入口不等于完整脚本

npm / pip 依赖安装、项目脚手架、源码构建和桌面安装器是不同类型。Three GPU Pathtracer 的 npm install 有仓库目录前提；Jolt 的片段有待核验参数；CosyVoice 和 FFmpeg 的片段还涉及工作目录。

逐项字串在上文保留；有缺口的地方已标出，不能靠补一个看起来合理的命令冒充验证。

远程脚本和模型要单独审查

MCP for Blender 的命令会直接执行网络脚本，先检查内容与权限。生成工作流还涉及模型、节点、硬件与声音授权；安装框架本身并未解决这些条件。

制作前先用空工程和非敏感素材验证，不要把正式项目或私人录音当测试材料。

公开仓库不等于统一许可

Remotion 有专门许可证；ComfyUI、LosslessCut、FFmpeg 等各有不同条款。依赖、模型、字体、音乐和示例图也有自己的使用边界，不能用仓库代码许可证概括全部素材。
