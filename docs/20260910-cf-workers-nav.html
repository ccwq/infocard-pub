DEPLOY · 六步部署
PAGE 01

十分钟上线的完整路径

  1. 登录 Cloudflare创建一个 Worker；把仓库里 workers.js 的代码粘进去点部署——整个项目就这一个文件。
  2. 创建 KV 存储新建名为 CARD_ORDER 的 KV 命名空间，所有卡片数据都存这里。
  3. 配置两个环境变量ADMIN_PASSWORD（管理员密码）和 JWT_SECRET（随机字符串，用于签发登录 Token）。
  4. 绑定 KV 命名空间Worker 的变量名 CARD_ORDER 指向上一步创建的 KV。
  5. 绑定域名用 workers.dev 免费子域名，或绑自己的域名。
  6. 管理员登录用 ADMIN_PASSWORD 登录后进入编辑模式，开始建分类和卡片。

CONFIG REF · 变量与绑定速查
PAGE 06

照着填就行

配置项填什么作用
ADMIN_PASSWORD自定义强密码管理员登录，解锁编辑模式与私密链接
JWT_SECRET32+ 位随机字符串签发登录 Token；老版本升级必填，否则报错
CARD_ORDER（变量）指向同名 KV 命名空间所有分类/卡片数据落点
workers.js仓库根目录单文件全部业务逻辑；更新=替换此文件内容

表内变量名大小写敏感，与 README 保持一字不差；改完任何配置都要重新部署 Worker 才生效。

你的数据长什么样

→
浏览器 ↔ Worker访问导航页时 Worker 直接返回 HTML，卡片数据由前端向同域 API 请求。
→
Worker ↔ KV读：打开页面拉取 categories；写：管理员编辑/拖拽后写回，自动备份同源。
→

BOUNDRY · 边界与选用判断
PAGE 05

免费额度与你该知道的事

Cloudflare 免费额度边界：Workers 免费版每日 100,000 次请求；个人导航页通常用不完，但若做成团队共享入口或被爬虫扫到，量级会快速上涨，重度使用需评估付费套餐。KV 免费层另有每日写入限额（1,000 次/天），正常手动编辑用不到，自动化批量写入要留意。

配置细节：JWT_SECRET 只要求"随机字符串"，但它签发的是管理员登录态——泄露即可控你的导航页，建议 32 位以上并定期轮换；ADMIN_PASSWORD 输错无锁定机制（无验证码/限流），密码本身要够强。KV 命名空间绑定后改名需要重新部署，先在本地记好变量名再上手。

免费额度怎么算：导航页是低频写 + 高频读：每次打开主页读 KV 一次（读写都算 KV 操作，免费层读 10 万次/天），个人使用绰绰有余；若把导航页挂到公司内网给几十人共用，按人均日刷新几十次估算依然安全，但自动化脚本高频写 KV 会在免费层 1,000 写/天上限前先触顶。

数据迁移路径：导出的 JSON 即全量数据（categories 结构）。迁移到新 Worker = 新建 KV + 导入 JSON + 绑定同名变量，两分钟完成；这也是从免费版升付费或换账号的推荐路径。

项目活跃度：README 更新日志显示功能迭代集中在 2025 年（2025-12-10 为 UI 重构），仓库仅 99KB 单文件，属于"够用就好"的轻项目——别期待插件生态。
