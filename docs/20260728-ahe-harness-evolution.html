什么是 AHE

Agent Harness Evolution 的核心概念

★ 核心定义

AHE 让 Harness 具备自我演化能力

传统 Harness 是固定的评测基准，Agent 需要"适配"Harness。AHE 反转了这个范式——Harness 根据 Agent 行为数据自动调整，形成"Agent ⇄ Harness"双向协同进化闭环。

双向闭环 行为驱动 动态评测

① 收集Agent 行为数据
② 分析识别薄弱场景

↻ 持续循环

传统 Harness：固定评测集，Agent 适配基准
AHE：动态演化，Harness 适配 Agent

02

核心机制

AHE 实现自我演化的三大支柱

🗂 行为数据采集层

  • 记录 Agent 执行轨迹（思考链 / 工具调用 / 输出结果）
  • 采集任务完成率、耗时、错误类型分布
  • 建立 Agent 能力画像（擅长/薄弱的任务类型）

输入：真实 Agent 运行数据 → 输出：结构化行为日志

🧠 演化决策引擎

  • 对比历史 Harness 与当前 Agent 能力差距
  • 识别"过易"（Agent 100% 通过）和"过难"（Agent 接近 0%）的评测项
  • 自动生成下一轮 Harness 更新建议

输入：行为日志 → 输出：Harness 变更指令

⚙️ 自动更新执行层

  • 自动调整评测难度参数（上下文长度、约束条件、噪声干扰）
  • 自动生成新的测试用例补充薄弱区域
  • 版本化管理 Harness 演化历史，可回滚可审计

输入：变更指令 → 输出：v2.0 / v2.1 / … 新版 Harness

🔄 闭环验证

  • 新版 Harness 部署后立即触发新一轮 Agent 评测
  • 对比进化前后 Agent 得分曲线，验证改进效果
  • 如果退化，自动回滚到上一稳定版本

输入：新旧 Harness 评测结果 → 输出：确认改进或触发回滚

演化阶段

从静态评测到自我演化的演进路径

1
静态基准
手工构建固定评测集，Agent 单向适配
2
数据积累
大规模 Agent 运行数据采集，建立行为日志
3
分析挖掘
识别评测盲区和 Agent 薄弱环节
4
AHE 闭环
Harness 自动更新，持续协同进化
核心洞察：传统 Harness 是"考试"，AHE 是"学习系统"——考试题随学生水平自动调整，越考越精准。
04

为什么重要

AHE 对 Agent 工程的三层价值

评测层

静态 Harness 存在"适应性过拟合"——Agent 在固定基准上刷分，但实际能力未必提升。AHE 让评测始终与 Agent 真实水平对齐。

开发层

开发者可通过 AHE 自动发现 Agent 的真实短板，定向改进。无需手工设计测试集，系统自动找到"最值得改进的地方"。

生态层

当多个 Agent 共享同一 AHE 系统时，Harness 的演化会综合多 Agent 行为数据，形成更全面、更公平的评测标准。

前瞻

AHE 本质上是"让基准测试具备元学习能力"——这一思想可扩展到 RLHF、自动化 prompt 优化、Agent 能力评估等多个方向。
