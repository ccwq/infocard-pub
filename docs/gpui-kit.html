01 · 核心定位：开局界面不再手搓

Rust 桌面开发最磨人的地方不是写业务逻辑，是开局：窗口库选完之后，表格、下拉、弹层、表单校验全得自己来，等界面勉强能看，两周已经过去了。gpui-kit 给的就是这一套：75+ 个带文档的组件，表单、导航、浮层、数据展示、编辑器这些常用的都在里面，底座是 Zed 团队那套 GPUI 渲染引擎。

它不是玩具，背后是从 2019 年就在拿它打磨的商业桌面产品 Longbridge Pro（港美股交易终端），同码一份跑 macOS、Windows、Linux，还能编译到 WebAssembly 丢进浏览器。

04 · 四大核心能力深度解析

🗃 数据表格：数十万行稳得住

虚拟滚动只渲染可见区域，固定列、拖宽列、排序、按单元格选择，全部在几十万行数据下保持响应。解决了 Rust 桌面数据密集型应用的核心痛点。

⌨ 代码编辑器：20 万行不退

Rope 后端文本存储避免全量重排；Tree-sitter 语法高亮；LSP 补全、诊断、悬浮提示。官方标称扛得住 20 万行文件，配套 GPUI Kit 官网在线预览。

♿ 无障碍：AccessKit 内置测试覆盖

AccessKit 角色、名称、状态、关系和动作全部内置于交互层，且有测试覆盖。这在 Rust GUI 生态中极为罕见，大多数框架在这里留白。

🧪 UI 集成测试：头窗口真组件断言

gpui_kit::test + TestWindowExt 在头窗口中渲染真实组件，驱动指针和键盘输入，断言状态、焦点、布局和无障碍。不是 mock，是真组件。

05 · 快速开始（3 步到 Hello World）

1添加依赖
2编写窗口
3运行
[dependencies]
gpui-kit = "0.7"
gpui-kit-assets = "0.7"
use gpui_kit::component::button::*;
use gpui_kit::component::*;
use gpui_kit::*;

pub struct HelloWorld;
impl Render for HelloWorld {
    fn render(&mut self, _: &mut Window, _: &mut Context) -> impl IntoElement {
        div()
            .v_flex()
            .gap_2()
            .size_full()
            .items_center()
            .justify_center()
            .child("Hello, World!")
            .child(
                Button::new("ok")
                    .primary()
                    .label("Let's Go!")
                    .on_click(|_, _, _| println!("Clicked!")),
            )
    }
}

fn main() {
    gpui_kit::application()
        .with_assets(gpui_kit::assets::Assets)  // Lucide 图标
        .run(move |cx| {
            gpui_kit::init(cx);
            gpui_kit::open_window(WindowOptions::default(), cx, |_, cx| {
                cx.new(|_| HelloWorld)
            }).expect("Failed to open window");
        });
}

08 · 三层层级设计原则

核心理念：行为属于底层，呈现属于应用。gpui-base 处理困难的交互机制——焦点、浮层定位、虚拟化、无障碍。你的产品决定它们看起来和感觉如何。

对比 Web 生态更容易理解这层关系：

GPUI Kit 生态Web 生态对应
GPUI（渲染引擎）HTML + Tailwind CSS（底层）
gpui-base（无样式行为层）Base UI（语义行为库）
gpui-component（完整样式组件）shadcn 组件层

09 · gpui-shell：Rust 宿主 + JS 扩展

不同于大多数插件系统，gpui-shell 要求宿主程序完全用 Rust 编写，扩展用 JavaScript。能力逐个显式授权，脚本在同一进程中绘制真实界面，并支持保存即热重载（无需重启）。

import { Button, text } from "gpui";

Button.new("save")
  .on_click((_e, cx) => this.save(cx))
  .child(text("Save changes"))
前提条件：需要 gpui-shell 包（独立引入）和 gpui-component-shell（样式组件目录）。默认情况下 gpui-kit 不包含 JS 运行时，按需引入。

10 · 图标与资源

默认引入 gpui-kit-assets（含完整 Lucide 图标集），通过 gpui_kit::assets::Assets 注入。若需自定义 SVG 图标，文件名必须按 IconName 枚举中的定义命名，参考源码 crates/component/src/icon.rs。
