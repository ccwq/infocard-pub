影响使用方式 · 6 项

本窗口对「怎么用」影响最大的一组变化发生在 08-15：四个 PR 连击把跨技能调用从模糊的文字提及升级为显式工具调用，并封死了「技能自动调用 user-invoked 技能」这条被违反的不变量。机制：纯粹在正文里写「run the /grilling skill」不能可靠触发加载——这是 grill-with-docs 被报告最多的问题根源；显式 tool call 提高命中率，而去掉前导 / 也让指令不再假设 Claude Code 的触发语法。但 setup-matt-pocock-skills 等 user-invoked 技能被不变量禁止被任何其他技能调用，于是五处前置条件改为「让人类去运行」，diagnosing-bugs Phase 6 对 improve-codebase-architecture 的自动交接被整体删除（无人值守流程里没人能接住失败的调用）。

方法校正 · 为什么不能只读 CHANGELOG

1.2.0（08-05 发布）的 CHANGELOG 记入了 Codex 元数据、grilling round-by-round 轮次机制、YAGNI 探索裁剪、Claude Code 插件发布本身——但这四项在基准树（07-17）中全部已存在。它们由 release/v1.2 功能分支提前带入：作者日期早、合入 main 晚、发布日才记账。

若以 CHANGELOG 为准，会把这些当成窗口内变更而高估约 4 项；若只看提交日期，又会漏掉合入日才对 main 用户可见的部分。本卡的窗口归属一律以树级 diff（9c32629…c55ee46）为准——CHANGELOG 是当事方叙事，树状态是原始数据，两者冲突时以后者为准。

事实等级标注：本卡全部变更条目 = 已证实事实（可用 git diff 复现）；影响评估 = 高可信推断；skills.sh 服务端清单同步状态 = 当前未知。
