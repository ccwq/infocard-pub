AGENT SKILL · LONG-DOCUMENT PIPELINE

Translate Book
让 Agent 并行翻完整本书

把 PDF、DOCX 或 EPUB 交给 Codex、Claude Code 或 OpenClaw：先转换、拆块，再由多个独立 subagent 并行翻译，最后用 manifest 校验、合并并导出多种格式。

PDF / DOCX / EPUB默认 8 路并行可续跑MIT

FIRST DECISION

适合“整本书”
而不是一段文本

如果你要的是长文档的分块、术语一致性、断点恢复和可验收产物，它比一次性把整本书塞进一个上下文更有工程边界。

但它不是“按下按钮就保证出版级译文”：模型、术语表、版式和人工复核仍决定最终质量。

01 / IDENTITY

它解决的不是“翻译一句话”，而是管理一次整书翻译运行

输入

PDF、DOCX、EPUB。Calibre 负责进入 HTML/HTMLZ 路径，Pandoc 和 Python 工具继续处理结构。

执行

每个 chunk 由独立 fresh-context subagent 处理，默认每批 8 个并行翻译器，并可读取相邻 chunk 的短摘录。

交付

合并后可生成 Markdown、HTML、DOCX、EPUB 和 PDF；中间状态、hash 与产物关系有记录。

02 / FIRST RUN

先装依赖，再选 Agent 入口

PREREQUISITES准备 Codex、Claude Code 或 OpenClaw；安装 Calibre、Pandoc、Python 3。
INSTALL SKILL按官方 README 为对应 Agent 安装 translate-book Skill。
TRANSLATE输入书籍路径和目标语言，让 Skill 运行完整流水线。
VERIFY检查 chunk 一致性、空输出、manifest，再合并导出。

Codex

npx skills add deusyu/translate-book -a codex -g $translate-book Translate /path/to/book.pdf into Chinese.

Claude Code

npx skills add deusyu/translate-book -a claude-code -g /translate-book translate /path/to/book.pdf to Japanese

OpenClaw

openclaw skills install @deusyu/translate-book translate /path/to/book.pdf to Chinese
03 / PIPELINE

一条可检查的翻译流水线

阶段做什么留下什么证据
转换Calibre ebook-convert → HTMLZ → HTML → Markdown源指纹、输入缓存、可复现的转换路径
拆块按约 6000 字符切成 chunk0001.md 等文件manifest.json 记录每个 source chunk 的 SHA-256
翻译每个 chunk 由独立 subagent 翻译，分批控制 API 速率output_chunk*.md 与 per-chunk meta
校验检查 source/output 1:1、hash、空文件和源文件漂移manifest validation；失败时禁止静默合并
导出合并 → Pandoc HTML/TOC → Calibre 输出output.md、book.html、book.docx、book.epub、book.pdf
04 / CONSISTENCY

并行之后，靠三层状态把全书拉回一致

Glossary v2

先抽样构建术语表，再把与当前 chunk 相关的原文、别名和译文注入 prompt。术语表可手动修订。

Neighbor context

每个 chunk 可以看到前后 chunk 的短只读摘录，用来降低代词、实体和章节衔接漂移。

run_state

记录 glossary 版本、实体、source hash 和 output hash；术语表变更时可精确重译受影响 chunk。

核心取舍：并行减少“整本书单会话”带来的上下文堆积和输出截断，但不会自动解决术语歧义、跨章风格、表格布局或译文审校。
05 / CONFIGURATION

几个真正影响运行的参数

参数 / 文件作用边界
--olang zh指定目标语言。目标语言不等于术语风格已经确定，仍需检查 glossary。
--temp-root把 book_name_temp 放到指定父目录。保留叶子目录名；不要把临时产物散落到仓库根目录。
--cover向 EPUB 的 Calibre 步骤传入显式封面。封面兼容性取决于源文件和 Calibre 环境。
--export-name额外生成面向用户的导出别名，保留 canonical book.*。它是副本命名，不改变流水线内部产物契约。
glossary.json维护专有名词、别名、译法和证据。同一 surface form 不能无依据归入两个术语。
06 / OUTPUTS

先看 Markdown，再决定要不要生成出版格式

output.md

适合先做文本级检查：章节完整性、术语、标点、引用和空 chunk。

book.html

带浮动目录的网页版本，适合快速浏览和定位结构问题。

DOCX / EPUB / PDF

由 Calibre 输出，适合继续编辑、阅读或打印；版式仍需抽样复核。

07 / BOUNDARIES

什么时候值得用，什么时候不要直接上

适合

  • 整本技术书、教材、长报告。
  • 需要断点恢复和选择性重译。
  • 希望保留 Markdown/HTML/DOCX/EPUB/PDF 多种产物。
  • 愿意维护术语表并做抽样审校。

不适合直接交付

  • 法律、医疗、出版级内容且没有人工审校。
  • 强依赖复杂图表、公式、脚注和版式的书。
  • 没有 Calibre/Pandoc 或 Agent runtime 的环境。
  • 期待并行数直接等于质量或线性加速。

最小验收

  • 抽查首章、中章、末章和术语高频段。
  • 检查表格、脚注、链接、图片和目录。
  • 确认 source fingerprint、manifest、1:1 输出。
  • 记录模型、目标语言、术语表和人工修订。
证据边界：本卡核验了官方 README 和仓库元数据；本轮没有在本机安装 Calibre/Pandoc，也没有执行完整书籍翻译。因此“可运行流程”是官方说明，不是本机实测结果；吞吐、费用和译文质量应由你的书籍样本评测。
