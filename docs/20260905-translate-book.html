AGENT SKILL · LONG-DOCUMENT PIPELINE

Translate Book
让 Agent 并行翻完整本书

把 PDF、DOCX 或 EPUB 交给 Codex、Claude Code 或 OpenClaw：先转换、拆块，再由多个独立 subagent 并行翻译，最后用 manifest 校验、合并并导出多种格式。本版补齐从安装到验收的入门路径。

PDF / DOCX / EPUB默认 8 路并行可续跑MIT

FIRST DECISION

适合“整本书”
而不是一段文本

它解决的是长文档的分块、术语一致性、断点恢复和可验收产物。

它不是自动保证出版级译文的按钮：模型、术语表、版式和人工复核仍决定质量。

01 / IDENTITY

先理解它管理的是什么

输入

PDF、DOCX、EPUB。Calibre 负责进入 HTML/HTMLZ 路径，Pandoc 与 Python 工具继续处理结构。

执行

每个 chunk 由独立 fresh-context subagent 处理，默认每批 8 个并行翻译器，并可读取前后 chunk 的短摘录。

交付

合并后生成 Markdown、HTML、DOCX、EPUB 和 PDF；manifest、source fingerprint 与状态文件记录中间关系。

02 / FIRST RUN

新手第一次运行：按这 4 步走

01 · PREPARE准备 Agent runtime、Calibre、Pandoc、Python 3；先确认 `ebook-convert` 和 `pandoc` 在 PATH。
02 · INSTALL为 Codex、Claude Code 或 OpenClaw 安装 Skill，重启 Agent 让新 Skill 生效。
03 · TRANSLATE给出输入文件绝对路径、目标语言和必要的术语/语气要求。
04 · VERIFY先检查 chunk、manifest、术语和输出，再决定是否导出阅读/打印格式。

Claude Code

npx skills add deusyu/translate-book -a claude-code -g /translate-book translate /path/to/book.pdf to Chinese

Codex

npx skills add deusyu/translate-book -a codex -g $translate-book Translate /path/to/book.pdf into Chinese.

OpenClaw

openclaw skills install @deusyu/translate-book translate /path/to/book.pdf to Chinese

04 / PIPELINE

一条可检查的翻译流水线

阶段做什么证据 / 失败信号
转换Calibre ebook-convert → HTMLZ → HTML → Markdowninput、source_fingerprint；源文件替换后应中止
拆块约 6000 字符一块，生成 chunk0001.md…manifest.json 记录每个 source chunk SHA-256
术语表抽样首/末/中间 chunk，建立 glossary v2原文、别名、译文、类别、证据和频次
翻译每个 chunk 独立 fresh context，默认 8 路分批output_chunk*.md 与 meta；API 速率受批次约束
校验检查源/输出 1:1、hash、非空和状态有缺失或空输出时禁止静默合并
合并导出Markdown → Pandoc HTML/TOC → Calibre 格式output.md、book.html、book.docx、book.epub、book.pdf
05 / CONSISTENCY

并行之后，靠三层状态把全书拉回一致

Glossary v2

记录术语、别名、译法、类别、性别、置信度、证据和频次；同一 surface form 不能无依据归入两个术语。修改后只影响相关 chunk 的重译计划。

Neighbor context

每个 chunk 读取前后短摘录，帮助处理代词、实体和章节衔接；它是只读上下文，不应被复制进译文。

run_state

记录 glossary 版本、实体 hash、源 hash、输出 hash；可识别缺失/空输出、源漂移、术语变化并选择性重译。

关键判断：并行降低单会话上下文堆积和输出截断风险，但不会自动解决跨章风格、术语歧义、表格/脚注版式或人工审校问题。
06 / COMMANDS & CONFIG

真正会影响结果的参数

参数 / 文件什么时候用边界
--olang zh转换时指定目标语言语言不等于术语风格；仍需审阅 glossary
--temp-root /work把 book_name_temp 放到指定父目录保留叶子目录名，避免污染仓库根目录
--cover cover.jpg给 EPUB 导出显式封面最终效果受 Calibre 与源格式影响
--export-name给用户生成别名文件名不改变 canonical 的 book.* 产物
--cleanup完整成功后清理中间文件首次排错不要急着清理，保留 chunks 便于复核
glossary.json手工修正术语与别名改后用 run_state 规划受影响 chunk，不要盲目全书重译
07 / OUTPUT ACCEPTANCE

输出不是生成了就算完成

文本完整性

确认每个 source chunk 都有 output；输出非空；源 hash 未漂移；manifest 1:1 匹配。

术语一致性

抽查首章、中章、末章和高频术语；检查人名、专有名词、缩写和大小写是否统一。

版式完整性

抽查目录、标题层级、表格、脚注、链接、图片、代码和页码；HTML 与 PDF 不应只看首屏。

# 推荐的最小验收顺序 1. 检查 manifest 与 source_fingerprint 2. 检查缺失/空 output_chunk 3. 检查 glossary 与高频术语 4. 先读 output.md / book.html 5. 最后再打开 DOCX / EPUB / PDF 做版式抽查
08 / TROUBLESHOOTING

遇到错误，先按症状定位

症状优先检查处理
ebook-convert not foundCalibre 是否安装、PATH 是否包含命令安装 Calibre 或修正 PATH 后重新转换
Manifest validation failed源 chunk 是否被修改重新运行 convert，不要沿用过时输出
source bytes 不一致temp 目录是否来自另一份书换新的 temp-root 或删除旧 temp 目录
Blank / Empty output对应 subagent 输出是否空白定位 chunk，重跑该 chunk，最多按流程重试
术语前后不一致glossary、别名和 run_state修 glossary，再让 planner 精确重译受影响 chunk
改标题后产物没变旧 output.md / book.* 是否仍在 temp按 README 清理旧最终产物后重新 merge_and_build
09 / FIT & BOUNDARIES

适用边界和人工责任

适合

  • 整本技术书、教材、公开领域长报告
  • 需要可续跑、术语管理和多格式输出
  • 愿意做抽样审校并维护术语表

不适合直接交付

  • 法律、医疗、出版级内容且没有人工复核
  • 公式、图表、脚注和复杂版式要求极高的书
  • 含个人隐私、机密或未授权资料的输入

本轮证据边界

  • 核验了官方仓库、英文/中文 README 和元数据
  • 本机未安装依赖，未执行完整书籍翻译
  • 吞吐、费用和质量需用你的样本实测
安全提示：不要把含密码、API key、内部文件或个人隐私的书籍直接交给未评估的数据路径；输出发布前检查引用、版权和翻译许可。MIT 是仓库许可证，不代表输入书籍或输出译本自动获得再发布权。
