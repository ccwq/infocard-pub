01 / MAP先把工具分层，而不是一股脑收藏
最快上手

想把网页喂给 LLM：先试 Firecrawl 或 Crawl4AI；一个偏 API/服务化，一个偏 Python 本地管线。

规模爬虫

Python 生态选 Scrapy；Node/TS 生态选 Crawlee。它们更像工程框架，不只是“抓一个页面”。

复杂交互

遇到登录、表单、动态页面，用 browser-use 或 Crawlee + Playwright，但成本与合规压力同步上升。

补位组件

MarkItDown 做文件转 Markdown；curl-impersonate 处理 TLS/指纹；scrcpy 更适合 Android 设备控制，不是通用网页爬虫。

03 / PLAYBOOK怎么用：三套组合栈
个人知识库
  • Crawl4AI / Firecrawl 抓网页
  • MarkItDown 统一文档格式
  • 再进入 RAG / Wiki / Obsidian
生产爬虫
  • Scrapy 或 Crawlee 做队列与调度
  • Playwright 只处理少量动态页
  • 严格限速、缓存、去重、失败重试
难抓页面
  • 先用普通 HTTP 验证是否足够
  • 再上 browser-use / Crawlee 浏览器层
  • curl-impersonate 只做诊断与兼容测试
04 / LIMITS边界：能爬不等于该爬
实用判断：先看 robots.txt、服务条款、登录授权、个人信息与版权；优先公开数据、低频采集、可缓存内容。对需要绕过登录、验证码、付费墙或访问控制的场景，不要把“工具可行”误解成“合规可行”。
