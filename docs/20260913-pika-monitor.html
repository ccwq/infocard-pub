轻量监控多台 VPS，但先把数据、认证和告警边界配对

Pika 是一个 Go 探针监控系统：探针通过 WebSocket 与服务端通信，指标进入 VictoriaMetrics，配置与审计数据使用 SQLite 或 PostgreSQL。它适合统一看状态，但“轻量”不等于不需要数据库、权限和数据保留设计。

01

先判断：你要的是资源看板，还是服务与安全检查？

Pika 不只画 CPU 曲线；不同监控对象对应不同采集、存储和告警问题。

资源

主机健康

CPU、内存、磁盘、网络、GPU、温度；适合多台 VPS 的容量与异常初筛。

服务

端口与证书

HTTP/HTTPS 可检查状态码、响应时间、内容匹配和证书到期；TCP 与 ICMP/Ping 检查连通性和延迟/丢包。

安全

资产与防篡改

收集端口、进程、用户、SSH、Cron、服务和内核资产；监控受保护目录的文件变化与不可变属性。

选择边界：如果你只要单机指标，Pika 的服务监控、安全审计和数据库组件可能超出需要；如果你要统一管理多主机，先设计探针分组、权限和保留周期。

快速部署：SQLite 适合先跑通，PostgreSQL 适合长期运行

两种官方 Compose 路径都要求先改配置；不要把示例密码、JWT Secret 直接带进生产。

环境要求

Docker 20.10+ 与 Docker Compose 1.29+；本卡未在本机执行部署命令。

数据位置

SQLite：./data/pika.db；PostgreSQL：./data/postgresql；两者都用 ./data/vmdata 保存时序数据。

保留周期

官方 SQLite 部署文档写明 VictoriaMetrics 默认保留 7 天；容量规划时按主机数、采样频率和查询跨度复核。

05

安全审计与防篡改：先定义“谁能看、谁能改、改了如何留痕”

Pika 提供能力，但安全结论仍取决于采集范围、权限和部署边界。

认证选择

支持 Basic Auth、OIDC、GitHub OAuth；官方通用配置建议优先考虑第三方认证，并把数据库端口限制为内部访问。

防篡改机制

基于 fsnotify 监控受保护目录，巡检不可变属性，并记录文件变动与属性篡改告警。

审计数据

资产清单、风险分析和历史审计可查询/对比；不要把“检测到风险”读成“自动完成修复”。

最低安全动作：改管理员密码、改 JWT Secret、限制数据库/时序端口、使用 HTTPS 反向代理，并确认 config.yaml 不会进入公开仓库。
06

故障排查：从部署层逐层向上，不要先怀疑指标页面

官方文档已经给出常见路径，排障时先判断是容器、配置、数据库还是采集范围。

页面打不开

先看 docker-compose ps 和 Pika 日志，再确认端口映射；若 8080 被占用，修改宿主端口而不是容器端口。

数据库连接失败

PostgreSQL 的 hostname 应是 Compose 服务名；compose 密码与 config.yaml 必须一致；检查健康检查和容器日志。

数据不全

检查网卡过滤、磁盘 include、探针在线状态和 GeoIP 是否按需配置；多磁盘默认只采集根目录与 C 盘。
