LLM Wiki × Hermes 是什么？

不是另一个模型，而是一套把知识持续沉淀成 Markdown Wiki 的工作方式：Hermes 干活，Wiki 记账，知识越用越值钱。
v20260529
结论
值得结合；本机能装；现在缺的是目录与配置，不是机器条件。

LLM Wiki 负责把知识组织成可追溯、可链接、可持续更新的 Markdown 页面；Hermes 负责搜索、整理、更新、回答。

一句话理解

Hermes 是执行层，LLM Wiki 是沉淀层。
前者把资料吃进去，后者把结果留下来，形成长期知识资产。

低系统门槛
高长期复用价值
可安装当前机器状态

它到底是干嘛的

本质

一个目录式 Markdown Wiki，而不是数据库产品。

把网页、论文、调研、问答沉淀成 entities / concepts / comparisons / queries。

强调来源保留、交叉链接、可持续维护。

解决的问题

避免“每次重新搜、重新总结”。

避免结论散落在聊天记录里无法复用。

让知识从一次性问答变成持续积累的资产。

和 Hermes 的关系

Hermes 执行层

  • 搜索、抓取、读取资料
  • 做摘要、结构化整理
  • 更新页面与交叉链接
  • 回答问题与定期巡检

LLM Wiki 沉淀层

  • 保存原始资料与整理结果
  • 用 index / schema / log 维持秩序
  • 让页面可浏览、可追溯、可复用
  • 适合 Obsidian / VS Code / Git

结合后的提升

从“聊天里答过一次”升级为“以后还能直接用的知识结构”。它不是让回答更花哨，而是让知识不会每次从零开始。

最直接的收益

  • 减少重复劳动
  • 让证据与结论不脱节
  • 同主题可持续增量更新
  • 跨会话保留高价值调研成果

适合的场景

  • 长期技术调研
  • 公司 / 人物 / 赛道知识库
  • 项目文档与设计决策沉淀
  • 持续调查与主题跟踪

系统要求与本机核查

系统要求

最低要求很低：一个可读写目录 + Markdown 文件即可。可选增强包括 Obsidian、Git、Node.js 22+（若要 obsidian-headless 同步）。

本机状态

Linux / Python / Node / npm / git 均已具备。当前未设置 WIKI_PATH，且 ~/wiki 不存在，所以属于“未配置”，不是“不能安装”。

王记者判断

如果你想把 Hermes 从“即时回答器”升级成“研究与维护助手”，LLM Wiki 值得上；如果你只想临时问几个问题，它的收益就没那么大。对这台机器来说，启用它没有系统门槛，差的只是创建目录和配路径。

关键提醒

别把它当 RAG 替身

它更像“编译后的知识库”，不是每次临时检索一遍。强项是长期维护，不是一次性问答速度。

别让它变 Markdown 垃圾堆

要维护好 schema、index、log；否则它会从知识库退化成一堆无序文档。
