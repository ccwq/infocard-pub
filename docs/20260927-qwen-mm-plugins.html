01
9 个能力插件 · CAPABILITIES

每个能力独立安装：Skill（告诉 Agent）+ MCP Server（工具本身）

按需安装，不需要全量。core 是所有其他能力的基础

👁️

core（基础能力）

无需 API 密钥 ffmpeg 视频

动态分辨率读取本地图片和视频；可视化文档、代码、数据表、3D 模型、NIfTI 医学影像。不需要手动缩放文件。

☁️

api（DashScope 云端）

需要密钥 DashScope

视觉问答（VL/Omni）、OCR、目标定位、ASR 语音转文字、多说话人区分、字幕生成、视频事件分析。

🔍

search（联网搜索）

需要密钥 Serper/Exa/Tavily

网页搜索、页面内容提取、反向图片搜索。文本搜索按 Serper → Tavily → Exa 顺序自动回退。

🎬

video-memory（长视频记忆）

需要密钥 DashScope

构建长视频的分层记忆图谱，支持超长视频问答。ffmpeg/ffprobe 用于构建索引。

🎨

video-edit（视频编辑+生成）

需要密钥 DashScope + Node

图片、视频、音频生成与编辑工作流。需要 Chromium 截图和 ffmpeg 音视频处理。

🧊

blender（3D 建模）

需要密钥 Blender + Xvfb

驱动运行中的 Blender 实例，薄客户端 22 个工具：建模、材质、灯光、渲染。Linux 无头模式需要 Xvfb。

⚙️

freecad（参数化 CAD）

需要密钥 FreeCAD + CalculiX

驱动运行中的 FreeCAD，薄客户端 14 个工具：参数化建模、STEP/STL 导入导出、FEM 有限元分析。Linux 无头模式需要 Xvfb。

📚

edu-agent（教育视频）

纯 Skill，无需 MCP

将数学/理科问题或图片转换为分步讲解视频和互动页面。Node/Chromium + ffmpeg + DashScope（旁白视频）。

🤖

mhs（硬件控制）

无需 API 密钥 最独特能力

6 个固定工具操作摄像头、传感器、灯、机械臂。通过 MHS adapter（纯 HTTP 服务器）控制真实硬件，本地安全限制 + estop。

02
mhs 硬件控制 · MODEL HARDWARE STANDARD

6 个固定工具 → 控制任意硬件设备

Anthropic MHS 标准：设备专属逻辑封在 adapter 里，Agent 永远只用同一套 6 个工具接口

mhs_discover
发现所有设备：类型、状态、能力列表
→
mhs_meta_info
查询单个设备：能力参数、安全限制、拒绝条件
→
mhs_read
读取传感器值、相机帧、当前设置
→
mhs_write
发送命令——唯一改变物理世界的工具
→
mhs_health_check
检查设备是否存活（永不缓存）
→
mhs_reset
恢复安全状态，或 mode=estop 立即停止
核心设计理念MHS 架构
# adapter 属于硬件厂商，不属于本插件 # 厂商写自己的 adapter，Agent 永远用同样的 6 个工具 # 无需学习每个硬件的专有 API adapter = 纯 HTTP 服务器（任何语言均可） adapter 归属 = 硬件所有者 本插件内容 = 无任何硬件驱动 # mhs-devices.json 示例 { "adapters": [ { "name": "lab-cam", "url": "http://your-device-hostname.local:8800" }, { "name": "arm", "url": "https://arm.internal", "timeout": 30, "auth": { "type": "bearer", "token_env": "ARM_TOKEN" } } ] } # token 值永远不写入文件，只写环境变量名 # mhs_discover 每次重新加载此文件，设备列表永不缓存
⚠️ 安全机制（mhs_write 前必读）

adapter 声明的 safety_limits 由主机端强制执行，超出限制的指令在离开进程前被拦截，不会到达真实硬件。adapter 仍需在本地再次检查。mhs_write 操作真实物理设备；Agent 写 adapter 前需先读元数据、安全限制、紧急停止位置。

mhs_reset mode=estop
立即停止设备（最高优先级）
mhs_reset mode=soft
清除错误，恢复空闲状态
mhs_meta_info <device>
首次写操作前必读，了解安全限制
mhs_health_check
重试失败写入前必须调用

04
使用示例 · NATURAL FILE REFERENCES

自然语言引用文件，Agent 自动调用对应工具

无需指定工具名称，告诉 Agent 你要做什么，它自动选择最合适的 MCP 工具

@report.pdf

「总结第 3 页内容，并提取其中的表格数据」→ core 读取 PDF，api（如配置）做 OCR 提取

@meeting.mp4

「转录这个视频，标注每段话的说话人和时间戳」→ core 提取帧，api ASR 识别并标注说话人

@place.jpg

「识别这张照片的拍摄地点，并在网上验证」→ core 读取图片，search 反向图片搜索

@brain.nii.gz

「检查元数据并显示正交中心切片」→ core 读取 NIfTI 医学影像并可视化（本地只读，非临床诊断）

@lecture-2h.mp4

「列出主要论点并给出时间戳」→ video-memory 构建分层记忆，回答长视频内容问题

硬件设备

「你看到什么硬件？能操作摄像头吗？」→ mhs_discover 发现设备，mhs_read 读取画面

05
技术栈 · TECH STACK & DEPENDENCIES

uv（uvx）按需安装 Python 依赖，系统工具按能力按需安装

core 不需要任何 API 密钥；云端能力按需配置 DashScope / Serper / Exa / Tavily

uv（uvx 按需安装 Python 依赖） ffmpeg（视频/音频，必选） DashScope API（VL/Omni/ASR/视频，可选） Serper / Exa / Tavily（搜索，可选） Blender / FreeCAD（3D/CAD，可选） Xvfb（Linux 无头模式 3D，可选） Chromium（edu-agent 渲染，可选） LibreOffice（Office 文档可视化）
验证依赖安装状态自动检查
# 运行安装脚本的验证步骤，确认 API 密钥和系统工具 bash install.sh verify # 验证结果示例 ✅ DASHSCOPE_API_KEY: configured ✅ ffmpeg: installed (v6.x) ⚠️ blender: not found (for blender capability) ✅ libreoffice: installed # 手动安装检查 uvx qwen-mm-plugins-core --check-system uvx qwen-mm-plugins-api --check-system

命令参考 · COMMANDS

install / update / verify / uninstall + Claude Code 插件命令

bash install.sh

bash install.sh update
更新已安装 capability
bash install.sh local
指向本地 checkout 开发

恢复发布源
bash install.sh verify
检查 API 密钥和系统工具
claude plugin marketplace add
添加插件市场（Claude Code）
claude plugin install <name>@qwen-mm-plugins
安装单个 capability（Claude Code）
配置变量~/.qwen-mm-plugins/config
# 环境变量（优先级最高） DASHSCOPE_API_KEY # 云端视觉、ASR、视频理解（api / video-memory / video-edit） SERPER_API_KEY # Serper 搜索（search，优先于 Tavily/Exa） TAVILY_API_KEY # Tavily 搜索（search） EXA_API_KEY # Exa 搜索（search） QWEN_MM_SEARCH_BACKEND # auto | serper | tavily | exa（默认 auto，按序回退） QWEN_MM_MHS_DEVICES # mhs 设备注册文件路径（默认 ~/.qwen-mm-plugins/mhs-devices.json） QWEN_MM_MHS_CACHE_TTL # mhs 元数据缓存 TTL（默认 60s，discovery/reset 永缓存）
