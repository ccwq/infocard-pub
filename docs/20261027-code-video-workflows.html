核心要点

  1. 要做角色手绘短片：选 ClaudeAnimationBase；用 p5.js / p5.brush 编排镜头，再由 render.mjs 渲染。Node.js、Chrome、ffmpeg 是前置，水彩填充可能拖慢逐帧输出。
  2. 要学或复刻 MG 样片：选 mg-styles-15；它提供 15 部十秒样片、提示词和源码。需要 Node.js 22.12+、Chrome、ffmpeg、Python 3.11+；3D 样片另需 Blender，字体不随仓库。
  3. 要做真实产品页面宣传片：选 video-shotcraft；页面截取接入 Remotion 镜头、卡点与 SFX，输出 MP4，工作台可调，剪映工程可选。先备 Node/npm、ffmpeg/ffprobe，再查素材与 Remotion 许可。
  4. 别把选集当排名：原帖的“试过 20+、选三款”和“ClaudeAnimationBase 效果最好”均为作者自述或主观评价；没有三者同条件基准，也没有平台涨粉保证。

01
深度论证 · 对应要点 1

ClaudeAnimationBase：先设计角色表演，再渲染镜头

这是 p5.js + p5.brush 的手绘 2D 卡通动画起步工程，不是可直接安装的 npm 成片服务。[A]

输入 → 制作 → 产出

围绕角色与分镜组织代码

仓库提供 Clawd 角色、31 种情绪、角色设定图和动画指南。输入应是角色行动与镜头安排，而不是等待模型一次生成整条视频。

1. 让编码 agent 先读 ANIMATION_GUIDE.md，再写分镜。
2. 用 p5.js / p5.brush 按镜头构建动画，渲染接触表检查关键画面。
3. 用无头渲染器输出 out/video.mp4。

GitHub Stars：2,080 · 数据时间：2026-10-27 · GitHub 仓库 API 快照；不是质量评分。

前置与失败代价

先把一个镜头跑通

README 列出 Node.js、Google Chrome、ffmpeg。进入仓库并装好这些依赖后，文档给出的安装与渲染入口为：

npm install
node render.mjs --clip --out=out/video.mp4

限制：README 提醒，集成显卡下的水彩填充可能每帧耗时数秒。这不是本卡实测，也不能据此推算另一台机器的整片耗时。

建议：先检查接触表中的角色造型与动作，再渲染长片；否则修改镜头后还要重新付出逐帧渲染时间。项目使用 MIT；package.json 标记为 private，不应当作公开 npm 包安装。

依赖与流程：README · 动画指南

02
深度论证 · 对应要点 2

mg-styles-15：拿样片、提示词与源码对照学习

主要价值是可拆解的风格样本，不是统一的成片引擎接口。[B]

输入 → 制作 → 产出

先选一种风格，复现它的实现

项目公开 15 部十秒动效短片，画面由代码生成，音频由程序合成，并附提示词、风格说明与源码。

  1. 挑一部目标样片，对照它的提示词与风格说明。
  2. 读取对应源码，先按该样片的路径复现，再修改画面或节奏。
  3. 通常将网页交给无头 Chrome 逐帧渲染，再由 ffmpeg 合成；3D 样片的画面走 Blender。

建议：用“能否解释并改出目标风格”验收学习成果，而不是把样片集合当成任意输入都能自动套用的服务。

GitHub Stars：2,363 · 数据时间：2026-10-27 · GitHub 仓库 API 快照；不是质量评分。

前置与失败代价

版本、字体与 3D 路线分开检查

  • 基础环境：Node.js 22.12+、Chrome、ffmpeg、Python 3.11+。
  • 条件依赖：Blender 仅用于 3D 样片，不必给所有样片加上这项前置。
  • 素材缺口：字体不打包在仓库；复刻前需要另行准备并检查字体授权。

失败代价：建议先核对目标样片的字体和渲染路径；缺少字体或把 3D 流程误当网页流程，会让复刻目标无法完整落实，需要补环境或调整设计。

代码仓库为 MIT，但第三方素材仍遵循各自条款。仓库自述的两轮评审与 AI 评委分数不等于独立验证，本卡不将其用于三项目排名。

03
深度论证 · 对应要点 3

video-shotcraft：用真实页面素材编排产品镜头

给 Claude Code / Codex 使用的视频 Skill；README 明确说它不是视频生成模型。画面来自产品截图、文案与代码绘制。[C]

输入 → 制作 → 产出

保留可调整的镜头工程

1. 页面素材：从真实产品页面截取画面，配合产品文案；页面捕获使用 Puppeteer。
2. 镜头编排：使用 Remotion 模板、镜头配方与可复用组件组织画面。
3. 节奏与声音：加入 BGM 卡点和 SFX；BGM 节拍分析才需要 Python 工具链。
4. 交付：输出 MP4；用 Motion Workbench 调整镜头，剪映工程是可选导出。

“可编辑”指保留工作台与工程路径，并非 MP4 自身保存了全部可编辑图层。当前 README 描述 124 张配方卡、150 个镜头及配套画廊。

GitHub Stars：13,970 · 数据时间：2026-10-27 · GitHub 仓库 API 快照；不是质量评分。

前置与失败代价

先过渲染环境，再过许可

  • 基础环境：Node/npm、ffmpeg 与 ffprobe。
  • 页面捕获：Puppeteer；Linux 服务器渲染还需核对 Chromium / headless-shell 限制。
  • 条件环境：Python 用于 BGM 节拍分析，不是所有步骤的统一前置。

失败代价：建议先完成一次页面截取与短镜头渲染；否则可能在剪好镜头后才发现服务器浏览器不满足要求，需要补依赖或迁移渲染环境。

许可不能合并看：仓库是 Apache-2.0；内置音频各有许可。Remotion 另有许可，企业可能需要付费授权，不能用仓库许可证替代检查。

行动
边界与行动

先做一个可验收的小样，再决定是否扩片

下面是试用建议，不是本卡已经完成的运行结果。

A · 验收角色镜头

照 README 装依赖，先做一个角色动作镜头。检查接触表的造型、动作，再确认能导出 MP4；不能接受本机渲染耗时，就先缩小试片范围。

B · 验收样片复刻

先选定一部样片，记录字体与 3D 需求，再复现原流程。检查改动能否被源码解释，而非只得到一份无法继续修改的成片。

C · 验收真实页面链路

用目标页面完成捕获、一个镜头、一次导出；再测试工作台调整是否符合交付需要。对外使用前逐项查仓库、音频、Remotion 许可。

适用边界：本文按项目文档选择制作路线，未实跑三项目，也未做同条件性能测试。Stars 仅为各仓库在所标日期的动态快照；未来版本的依赖、功能和许可应以当时文档为准。
