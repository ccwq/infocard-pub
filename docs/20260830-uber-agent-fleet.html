★ 核心结论

用量涨不可怕，浪费涨才可怕。

Uber 的核心洞察不是"少用 AI"，而是"消灭 AI 浪费"：把零价值的废 Token 物理抹杀，用量可以疯涨，但账单死死按在原地。解决方案是从"人打开聊天框求 AI 帮一把"转变为"托管 Agent 舰队自动上班"，人变成抽查质检的厂长。

01 策略一：规划用大脑，干活全用便宜子 Agent

任务拆解交给顶级大模型（Claude/GPT-4o），具体执行全部默认切给轻量模型（GPT-4o-mini/Claude-haiku）。这一招是全厂杠杆最高的开关：顶级模型只做高判断价值的规划，重复执行交给廉价模型。

规划层

顶级大模型

任务理解、拆解、路由判断、架构设计——需要强推理能力的环节。

执行层

轻量子 Agent

代码补全、测试生成、CI 修复、文档更新——大量重复执行任务。

02 策略二：5 分钟缓存 → 1 小时，原价 1 折续上

工程师去倒杯水或开个会回来，上下文缓存依然有效。更狠的是强制写摘要压缩（40 万 token 强制压缩），历史对话不会无限复印。

40 万 token 强制摘要压缩：防止历史无限复制，把上下文总成本控制在可预测范围内。
03 策略三：1000+ MCP 工具按需挂载，不开局灌 7 万 token

Uber 有 1000+ 内部 MCP 工具，如果开局就把所有工具定义灌给模型，光工具描述就要消耗 7 万 token。改为：模型先搜索工具库，按需挂载，只加载本次任务相关的工具。

旧方案（已废弃）

开局全量灌入

启动时把所有工具定义一股脑塞给模型，token 消耗高且干扰上下文。

新方案

搜索 + 按需挂载

模型需要时搜索工具库，按需挂载，开局零工具 token 开销。

04 策略四：Code-mode 砍掉话痨轮询，单项 token 省 90%

跑 SQL 查询和批处理时，模型自己写脚本去执行，只交回最终结果。避免一问一答的无效 ping-pong 轮询。
