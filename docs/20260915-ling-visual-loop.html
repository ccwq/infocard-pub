01

不要把“Diff”误解成自动裁判

Diff 的职责是把感觉变成证据；模型的职责是提出可核验的原因和改动。

输入必须可比

目标图与浏览器截图使用同一尺寸；不要先缩放目标图、再拿不同视口的结果比较。

诊断必须落到 CSS

模型先回答：最大偏差在哪里？可能是哪个元素/属性？准备怎么改？回答完再动代码。

结果必须可回滚

每轮保存渲染图、Diff、诊断和提交点；如果下一轮退步，从历史最佳继续，不在坏版本上叠补丁。

02

五阶段闭环：每一轮都要有退出条件

闭环不是“让模型一直改”，而是每一步都能回答“凭什么进入下一步”。

01

锁定基线

记录视口、DPR、字体、动画状态、页面等待时间和目标图尺寸。

02

生成候选

让模型写出可运行页面；保存原始候选，不覆盖上一版。

03

浏览器渲染

在固定浏览器状态截图；检查是否加载完成、字体是否替换。

04

解释差异

把目标、渲染图、Diff 一起交给模型，先要诊断再要 patch。

05

保留最佳

重新渲染并比较；变差就回滚，变好才成为新基线。

# 伪命令：把每轮证据放进独立目录
mkdir -p runs/round-02
render --url http://localhost:4173/card.html --viewport 1440x900 --out runs/round-02/render.png
diff --target target.png --candidate runs/round-02/render.png --out runs/round-02/diff.png
agent diagnose --target target.png --render runs/round-02/render.png --diff runs/round-02/diff.png
# 只有重新渲染确认变好，才更新 best.json
03

三个最容易让模型走偏的输入问题

先修测量系统，再讨论模型能力。

问题为什么 Diff 会误导修正与验收
尺寸不一致整体偏移几像素就能产生大面积差异，模型会把全局误差拆成局部 CSS 问题。锁定 viewport、DPR 和目标原图尺寸；先叠加边界框，再看局部差异。
动画未冻结淡入中的透明内容可能“看起来更像背景”，像素分数反而变好。禁用动画或等待稳定帧；同时人工确认内容真的可见。
版本继续叠补丁坏版本上的新改动会继承旧误差，问题越来越难定位。每轮保存 commit/目录；退步就回到历史最佳，不默认最后一轮胜出。
字体未就绪字体替换改变字宽、换行和卡片高度，后续所有 Diff 都会漂移。等待 document.fonts.ready；记录字体加载状态和截图时机。
只看一个分数全局像素分数可能掩盖按钮不可读、对比度不足或元素透明。分区域看 hero、正文、按钮和列表；加人工可读性/交互检查。
04

把模型放在正确的位置：它是诊断助手，不是发布闸门

Ling-3.0-flash-VL 的官方定位包含视觉理解、推理、行动和验证；这不等于它会自动给出可靠 CSS patch。

适合交给模型

从截图和 Diff 中归纳候选原因；指出疑似元素；生成小范围 CSS 修改；解释视觉偏差。

不要交给模型独断

像素基线是否有效、动画是否已稳定、字体是否加载、结果是否可访问，以及最终是否发布。

最小反馈格式

提供目标图、当前渲染、Diff、视口、轮次、上轮最佳分数；要求模型先写诊断，再输出 patch。

安全边界：模型卡的本地部署示例使用 HF token 占位符；不要把真实 token 写入命令、日志、截图或仓库。图像/页面内容发往第三方推理服务前，也要先确认隐私、版权和数据保留条款。

06

一个可复用练习：修复一张“看起来差不多”的定价卡

从问题定义到停止条件，完整走一轮，而不是连续运行到“感觉满意”。

A. 建立 baseline

锁定 1440×900；等待字体；关闭随机动画；保存原图、当前图和 DOM 版本。验收：两次基线截图像素差异接近零。

B. 让模型写诊断

只给三类证据：边界/尺寸 Diff、字体与间距信息、当前源码片段。验收：输出包含具体选择器和改动理由。

C. 小步改动

先改卡片宽度和按钮 padding，再改阴影；每次只动一个问题簇。验收：局部 Diff 下降且正文/交互没有退化。

round 01  width +16px       score 0.62  keep? no
round 02  width fixed        score 0.84  BEST
round 03  shadow improved     score 0.80  rollback

stop rule:
- 连续两轮没有改善：停止自动修改，人工判断
- 影响可读性/交互：无论分数如何，回滚
- 目标图本身尺寸或版权不清：停止并先补授权/基线
07

选择路径与发布前自检

方法卡的终点不是“模型改完了”，而是你能解释为何接受这版。

检查必须回答通过标准
输入目标图尺寸、来源和使用授权是什么？尺寸固定，来源清楚，未把私人/受限页面直接发给外部模型。
环境视口、DPR、字体、动画、等待时间固定吗？同一基线重复渲染不会产生结构性漂移。
差异Diff 指向哪个元素和属性？模型诊断可映射到选择器，并能人工复核。
版本当前版本是历史最佳还是最后一轮？best 记录可回滚，退步轮次不覆盖最佳。
视觉页面是否真的可读、可访问、可交互？像素分数之外，人工/自动检查无遮挡、无溢出、无透明内容。
模型这是模型卡事实、作者实测，还是你的结果？三者分层；7 秒等个人调用记录不外推成速度承诺。

最短可验证路径

固定一张有授权的目标图 → 用同一 viewport 渲染当前页面 → 生成局部和全局 Diff → 让模型先写三问诊断 → 只改一个问题簇 → 重新渲染 → 与历史最佳比较 → 变差就回滚。
