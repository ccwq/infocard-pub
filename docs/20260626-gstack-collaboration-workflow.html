GSTACK · HUMAN IN THE LOOP · AGENTIC ENGINEERING

GStack
人机协作工作流方法论

Token 最大化、人置于环路、伪技能、代码密度、三角色分工与工具互补，连成一条可执行、可复盘、可持续迭代的 AI 编程工作流。

核心判断：让 AI 负责规模化脏活，让人类把握需求、价值与边界；把“写代码”升级为“构建高密度工作流”。
核心环节
5 步
CEO 审查 · 设计审查 · 状态建模 · 自动化测试 · 角色演练
主力工具
Cline + Codex
统筹规划与硬核攻坚分工，形成互补闭环。
方法论关键词
Token效率 · 自动化测试 · 状态机 · 多角色复盘 · 开源主权

一句话总结

INSIGHT

GStack 的本质不是“再多加几个 AI 工具”，而是把工具、角色、审查、测试和主权控制编织成一套工作流：AI 做规模化执行，人类做价值判断，最后把每一次协作都沉淀成可复用的流程资产。

核心理念

FRAME
⚡
Token 最大化
不吝啬算力，用更长的上下文和更多轮次换更完整的成果。
🧭
人置于环路
机器处理重复脏活，人类掌控目标、价值和最终责任。

伪技能
把自然语言意图写成可执行的 Markdown 清单，让 AI 知道做什么。

主权保障
基于开源工具搭建个人系统，数据、提示词和执行权都在自己手里。

五步协作工作流

FLOW
1
CEO 审查 · 目标对齐
先逼问“这件事解决什么问题、谁受益、为什么值得做”，把任务从一开始就对准价值。
2
设计审查 · 体验与工程同时过一遍
涉及 UI / 开发者调用时，先做体验、结构和实现可行性审查，避免返工。
3
状态建模 · 写码前先画状态机
让 AI 先建模数据流、用户动线、覆盖状态，再进入实现，减少无效往返。
4
自动化测试 · 给结果上保险
封装 Playwright 等自动化测试，把回归风险压下去，目标覆盖率保持在 80%~90% 的有效区间。
5
角色演练 · 多视角复盘
交付前让 AI 扮演 CEO、设计师、开发、测试等多角色，系统性找出盲区和逻辑缺口。

主力工具分工

TOOLS
Cline / Code
统筹规划 · 任务队列管理
  • 适合发散工作模式与任务拆解
  • 协调多个子智能体，跟踪优先级
  • 把流程变成队列而不是脑内记忆
Cursor / Codex
高智商 CTO · 硬核问题攻坚
  • 适合复杂 Bug 排查和架构设计
  • 做精准代码生成与重构
  • 在难题上承担最后一环判断

约束与最佳实践

RULES
明确确定性边界
把 LLM 负责的非确定性意图和传统代码负责的确定性执行分开：AI 负责理解与策略，API 负责执行与返回可靠结果。
不要吝啬 Token
算力便宜，人的时间贵。与其省 Token，不如把问题一次做完整，把成果密度做高。
基于开源构建专属系统
围绕 Claude Code、Codex、Playwright 等开源/可控工具搭建个人系统，避免平台锁定与数据主权风险。
