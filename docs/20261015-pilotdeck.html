03
THREE PILLARS

README 里篇幅最大的三支柱

README 把产品组织成三大支柱能力。推荐文只讲了其中一条半，白盒记忆整段缺失。

WorkSpace 级隔离与积累

每个项目拥有独立的文件系统、记忆库和 skill 集合。并行任务互不干扰，检索范围有边界，skill 随任务自然积累。

官方原话：Every project gets its own file system, memory store and skill set.

可追溯的白盒记忆

记忆的生成、抽取、存储、检索全程可见。内置 Dream Mode 在空闲窗口整合记忆，支持一键回滚到之前状态。

官方用五个维度对比黑盒 agent：可见、可控、可追溯、隔离、可回滚。

智能路由与成本优化

自动判断任务难度，复杂调用走旗舰模型，简单调用降到轻量模型。通过端云协同编排降低 token 开销。

官方举例主 agent 用 Claude 3.5 Sonnet / GPT-4o 级别模型，子 agent 用更轻的。

Always-on 后台执行

打破“你问它答”的循环：你签收后，agent 继续发现候选任务、跑长程监控，最终把交付物落成本地文件并附摘要报告。

官方原话：lands deliverables as local files with a summary report waiting for you. 原文未给耗时与成功率数据。

SKILLS

办公文档能力来自上游 skill，不是平台引擎

推荐文把三份 skill 文件的编写方法，说成了平台的“内置自检机制”。这两件事不是一回事。

仓库实际有什么

  • 32 个 SKILL.md 位于 skills/ 目录。
  • 办公相关的是 docx、spreadsheets、pptx。
  • 另有 pdf、frontend-slides 处理文档与演示。
  • 其余覆盖 GitHub、Notion、Obsidian、浏览器、终端、天气、音频转写等。

写作、表格、演示三份 SKILL.md 开头分别是 “Use three stages…”（docx）、“Use four stages…”（pptx）、“Use three stages…”（spreadsheets），后面都跟一句 “as a reasoning framework, not a fixed tool pipeline”。

为什么说来自上游

README 的 Acknowledgements 段落明确列出 Anthropic Skills（Agent skill framework and built-in skills）与 Vercel Labs Skills。三份办公 skill 的 description 字段写法与 Anthropic 官方 skill 一致，都强调“只用于 .docx / .pptx / .xlsx，不要用于控制运行中的 Office”。

Anthropic Skills Vercel Labs Skills frontend-slides
推论要说清边界：三份办公 skill 的阶段划分方法写在 skills/*/SKILL.md 文件里，是给模型读的提示词与工作流程。推荐文描述的“先理解需求，再动手，做完之后还会自己检查一遍”，对应的是这份文档里的阶段划分，不是 PilotDeck 平台层的检查回路。把 skill 的工作方式说成平台能力，会让人误判它的工程实现层次。

INSTALL

安装与运行：Node 版本是硬门槛

三条路径：一行安装、源码、Docker。README 对每条都给了完整命令和已知故障。

macOS / Linux 一行安装

curl -fsSL https://raw.githubusercontent.com/OpenBMB/PilotDeck/main/install.sh | bash

网络慢时可预设镜像：

PILOTDECK_NODE_DIST_MIRROR=https://npmmirror.com/mirrors/node \
NPM_CONFIG_REGISTRY=https://registry.npmmirror.com bash

Windows PowerShell

powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/OpenBMB/PilotDeck/main/install.ps1 | iex"

必须以普通用户运行，不要用管理员。安装路径 %USERPROFILE%\.pilotdeck，启动器 %USERPROFILE%\.pilotdeck\bin\pilotdeck.cmd。脚本不会自动打开浏览器。

Docker Compose

docker compose up -d --build

完整配置见仓库 README_DOCKER.md。

日常启动与状态

macOS / Linux 上再次打开时在终端跑 pilotdeck，然后访问命令打印出的 URL。若 shell 还没拿到 PATH 更新，开新终端或 source 一下 profile。

Windows 三个已知坑

  • npm.ps1 无法加载：Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned，或直接用 npm.cmd run dev。
  • node-gyp 编译失败：装 Visual Studio Build Tools（含 C++ workload）和 Python 后重跑安装脚本。原生依赖有 node-pty、better-sqlite3、bcrypt、sharp。
  • 下载 install.ps1 报 429：GitHub 对共享网络限流，等几分钟重试，或先下载到本地再 powershell -ExecutionPolicy Bypass -File .\install.ps1。

LICENSE & EXTENSION

二次开发前先读 AGPL 的网络条款

推荐文说“可以基于它做二次开发”，这句话对，但只说了一半。

A

AGPL-3.0 的网络条款

若你修改了 PilotDeck 并把它作为网络服务对外提供，需要按 AGPL 条款开源你的修改。这与 MIT 完全不同。商业闭源改造前请先读仓库 LICENSE 原文；本卡不给法律意见。

B

扩展协议四点

MCP servers：原生支持 Model Context Protocol。Tools & Skills：注册自定义工具，或经 ClawHub 拉社区 skill。Lifecycle Hooks：可拦截 PreToolUse、UserPromptSubmit 等事件。Custom Memory：可插入自己的记忆存储 provider。

C

157 个未关闭 issue

项目 5 月才开源，issue 数说明使用者多、迭代也快。使用前建议先扫一眼 Issues，看有没有踩到你打算用的功能。

09
FIT

适合谁，不适合谁

按 WorkSpace 模型和 AGPL 许可来判断，而不是按推荐文的描述。

适合
同时跑多个独立项目的个人

WorkSpace 把文件、记忆、skill 完全隔开，检索范围有边界，不会串味。

适合
愿意自己选模型的人

接云端商用模型，或用 Ollama 全本地，provider 配置是开放的。

适合
需要可审计记忆的团队

能查看、编辑、删除每条记忆，出错能定位到具体条目，Dream Mode 可回滚。

适合
愿意改代码做定制的人

扩展协议开放，接 MCP、自定义工具、生命周期钩子和记忆 provider。

不适合
要闭源改造再对外服务的团队

AGPL-3.0 的网络分发条款会要求开源修改，路线不成立。

不适合
以为文件天然不出本机的用户

默认接云端模型，文件内容随请求发出。只有配 Ollama 才真正本地。

不适合
只想换个 IDE 写代码的人

它面向通用办公与长程任务，不是编程 IDE。编程向工具可选 Claude Code 一类。

注意
Node 版本卡在 22.13–23

内建 SQLite runtime 有此要求，低于 22.13 或达到 23 都不行。
