01

先按目标选框架

不用先纠结谁更强，先看你要解决的核心问题。

1 想要自由可改造的 Coding Agent 工作台 优先看 Pi Agent。
2 要构建产品级 Agent 服务或后端 优先看 OpenAI Agents SDK。
3 要处理复杂状态流、持久化和人工中断 优先看 LangGraph。
4 要多角色协作，快速生产结果 优先看 CrewAI。
5 在微软生态构建企业级多 Agent 应用 优先看 Microsoft Agent Framework。
6 要结构化输出、类型安全、Python 业务集成 优先看 Pydantic AI。
7 要知识库、RAG、文档问答与数据工作流 优先看 LlamaIndex。

Pi Agent

极简、可自定义改造的终端 Coding Agent
01
定位：可控制的 Coding Agent 工作台
TypeScript / Node.js 支持多模型 ★ ★ ★ ★ ★

⭐ 核心特点

  • 双向核心，可扩展
  • Skills Extension 机制
  • 上下文工程支持
  • Session 树和分支
  • 可观测切换

🧰 关键能力

  • 终端交互
  • 代码理解与修改
  • 权限控制
  • 上下文注入
  • 会话管理

🎯 适合场景

  • 个人或团队 Coding
  • 开源贡献、研究
  • 自定义 Agent 工作台
类比：像一个黑客可控制的终端 IDE / tmux，给你自由度。

OpenAI Agents SDK

产品级 Agent SDK，后端复杂首选
02

  • Tools / Handoffs / MCP
  • Guardrails 和事件流
  • Tracing 和监控
  • Sandbox Agents

🧰 关键能力

  • 工具使用与权限控制

🎯 适合场景

LangGraph

低层编排引擎，长任务 / 状态机专家
03
定位：纯粹可靠、可暂停、可持久化的复杂工作流
Python / TypeScript 基于 LangChain ★ ★ ★ ★ ★

⭐ 核心特点

  • 状态机编排
  • Durable Execution
  • 人工中断 Human in the loop
  • 持久化和恢复

🧰 关键能力

  • 复杂状态流
  • 分支、重试、回滚
  • 长期运行工作流

🎯 适合场景

  • 长流程业务
  • 审批流、复杂编排
  • 需要可恢复的系统
类比：像 Apache Airflow 为 AI 工作流而生的状态机。

按场景快速记忆

把七个框架压缩成七个高频落点，方便后续做选型图或汇报页。

终端 Coding

Pi Agent 更像可改造的个人工作台，适合需要深度控制和自定义的人。

产品后端

OpenAI Agents SDK 更偏生产集成，适合把 Agent 放进真实业务链路。

复杂流程

LangGraph 适合状态机、恢复、暂停、人工确认和长时间运行流程。

多角色任务

CrewAI 适合用研究员、写作者、分析师等角色协同完成任务。

企业生态

Microsoft Agent Framework 适合 Azure、Copilot、Telemetry 和企业 IT 场景。

结构化接口

Pydantic AI 适合数据抽取、分类、校验和可信业务接口。

文档智能

LlamaIndex 适合知识库、RAG、文档问答和数据连接器工作流。

没有最好的框架，只有最适合的场景。
