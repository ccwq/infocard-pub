Free Claude Code
把 Claude Code 接到免费模型代理层

它不是“改 Claude Code 本体”，而是做一个透明代理：把 Claude Code / VSCode 发往 Anthropic 的请求，转到 NVIDIA NIM、OpenRouter 或 LM Studio，从而用 2 个环境变量完成替换。

NVIDIA NIM OpenRouter LM Studio Discord Bot Rate Limit Subagents
01 · 一句话结论
Free Claude Code 的定位很清晰：把 Claude Code 的 Anthropic API 流量，代理到免费的或本地可控的 OpenAI 兼容模型后端。 它的价值不在“再造一个聊天框”，而在“让 Claude Code 继续照常工作”。
核心卖点
NVIDIA NIM 提供 40 req/min 免费额度；OpenRouter 可切换大量免费模型；LM Studio 则能完全本地化。对于想保留 Claude Code 工作流的人来说，这是一层替换而不是改造。
你可以把它理解成
“Anthropic API 的翻译层 + 模型路由层 + 请求优化层 + 限流层”。它让 Claude Code 看到的仍像 Anthropic，但实际流量已被重定向。
02 · 关键能力矩阵
3 个后端
NVIDIA NIM、OpenRouter、LM Studio 三路并存；每个 Claude 模型都可单独映射到不同 provider，支持混搭。
2 个入口
CLI 用 ANTHROPIC_BASE_URL 与 ANTHROPIC_AUTH_TOKEN；VSCode 扩展同样只改环境变量即可接入。
多项优化
请求优化、思考 token 解析、heuristic tool parser、滚动窗口限流、429 回退、并发控制都已经内建。
zero config-ish drop-in replacement per-model routing local/offline
03 · 它怎么工作
1Claude Code发 Anthropic API 请求
2Proxy拦截并识别模型名
3Router按模型映射 provider
4ProviderNIM / OR / LM Studio
5Stream back翻译回 Anthropic SSE 格式
关键点：它会把一些“非常简单”的请求直接在本地拦截掉，减少模型调用次数；真正复杂请求才走外部模型。
04 · 适合谁，怎么用
适合的人
想继续使用 Claude Code / VSCode 工作流，但不想被单一 API key、单一 provider 或成本锁死的人。也适合需要混用本地模型与云端免费模型的开发者。
运行方式
先启动 proxy：uv run uvicorn server:app --host 0.0.0.0 --port 8082；再让 Claude Code 指向本地代理：ANTHROPIC_BASE_URL=http://localhost:8082。

05 · 架构与风险
优势
低成本、可替换、可混用、可本地化；对 Claude Code 用户来说，几乎不需要改使用习惯。它把“能不能用”变成了“你愿意选哪个后端”。
门槛
前提是你至少要能拿到一个 provider：NIM、OpenRouter 或本地 LM Studio。并且它更像开发者工具，不是面向普通用户的一键 SaaS。
