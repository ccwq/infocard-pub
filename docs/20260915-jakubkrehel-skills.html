01

先理解 Skill 的分工：不是六个同义词

README 的列表是入口地图；真正的使用效果取决于你把问题路由到正确的 Skill。

FOUNDATION

better-ui

处理 concentric radius、光学对齐、图标、hit area、按下缩放和动效细节。官方规则明确写出 scale(0.96)、图标过渡的 opacity + scale + blur 组合。

READABILITY

better-typography

处理 type scale、行高、字距、文本 measure、wrap、truncation 和 tabular numbers。它解决的是文字怎么稳定渲染，不是文案写什么。

MEANING

better-colors

把颜色按语义 token 管理，要求在真实背景上测对比度；不要因为某个值“看起来合适”就借用错误角色的 token。

INCLUSION

better-accessibility

覆盖键盘、焦点、ARIA、hit area、reduced motion 和状态反馈。颜色或动画不能成为唯一的意义载体。

STRUCTURE

better-layout

处理 grouping、alignment、reading order、breakpoint 和空间关系。移动端布局问题先归到这里，不要靠缩小字体掩盖。

VOICE

better-writing

检查按钮、空状态、错误、占位符和产品文案是否清楚、可恢复、与动作一致。它不替你决定产品策略。

关键判断：如果你只运行一个入口，优先选 better-interface 做跨领域审查；但它的结论仍应回到对应的 better-* 规则和项目代码中验证。

03

better-* 的具体规则：把审美判断变成数值与验收

原帖提到的几个数值不是宣传口号，而是可以在对应 Skill 文档中找到的设计约束；它们也不是无条件适用于所有产品。

问题官方规则示例应用时要验证
嵌套圆角外层 radius = 内层 radius + padding实际 padding、背景和边框是否形成同心关系；不要只套公式。
按下反馈按钮使用 scale(0.96)；低于 0.95 会显得夸张按钮是否有静态状态提示；键盘/触摸和 reduced motion 是否仍可用。
图标切换opacity 0→1、scale 0.25→1、blur 4px→0px两个状态是否都在 DOM 中；transition 只写变化的属性。
动效节制高频交互即时反馈或 ≤150ms 的 opacity/color 过渡是否保留 prefers-reduced-motion 路径；动画不是唯一反馈。
文字换行标题可用 text-wrap: balance；长链接用 overflow-wrap: break-word真实中文标题、窄屏、长 ID 和多语言是否仍可读。
颜色对比在实际渲染的前景/背景对上测量，不凭肉眼估算组件 token 的角色是否正确，颜色是否不是唯一状态信号。
04

break：把一个组件放进“所有状态和边界”的试验台

它不是全站审查，也不是猜测式代码 review；它要求一次只选一个组件，按真实可达场景渲染。

先限定一个组件

例如 Button、输入框或头像，不要把“设置页”当作一个组件。先读 props、slots、states 和数据形状。

只保留适用场景

长文本、空数据、loading、error、disabled、窄容器等只有在组件确实能接收这些输入时才加入。

一次看完再报告

在临时页面中一次渲染所有场景；只报告实际看见的 break，例如文字逃出容器、空状态无下一步。

# 组件压力测试的记录格式（示意）
component: Button
scenarios:
  - label: 60-character label
  - state: loading
  - state: disabled
  - container: 320px
observed:
  - long label wraps into an unreadable control
owner: better-typography
next: fix in the real component, then re-render
不要误用：break 观察的是“这个组件在真实可达状态下哪里坏了”；它不替代 interface-review 的改动审查，也不应该在临时 harness 里重新设计或换主题。
05

explain-interface：解释别人页面是怎么画出来的

它区分“站点整体前端”与“某一个视觉效果的图层栈”，不能用一张 token 表回答所有问题。

问站点怎么构建

读取 framework、rendering strategy、styling system、component library、tokens、字体、图片、motion 和 breakpoint。

问一个效果怎么实现

按 paint order 找 pseudo-element、gradient、blur、backdrop-filter、动画 idle 值和生成的 stop list。

区分证据层级

Measured 是读到的 computed value；Derived 是计算结果；Inferred 是对意图的判断，不能混写。

06

把规则接回自己的项目：三轮最短实践

目标不是机械复制作者的数值，而是建立“发现 → 定位 → 修复 → 回归”的闭环。

01

选一个痛点

例如按钮按下不自然、中文标题挤压或颜色不够清楚。

02

选一个 owner

UI、typography、colors、accessibility 或 layout。

03

记录基线

保留当前截图、视口、状态和对应源码位置。

04

小范围修改

一次只改一个问题簇，避免把多个变量混在一起。

05

回归所有状态

桌面、移动、hover、focus、active、loading 和 error 都要回看。

你看到的现象优先入口通过标准
整体质量说不清better-interface得到按领域分组的根因，而不是一堆主观形容词。
单个组件在空/长/窄状态崩坏break场景在临时页真实渲染，观察结果能回到真实组件修复。
想知道某个网页效果怎么做explain-interface说明使用了哪种浏览器/抓取路径，并分 measured/derived/inferred。
准备商用或发布人工与项目门禁许可证、来源、可访问性、性能、安全和回归测试全部独立验收。

最短可验证路径
