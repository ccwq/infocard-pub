API Anything — 把任意网站变成 Agent 可调用的 API

用 headless Chrome 学两遍，把真实请求提炼成带槽位模板，Agent 直接打 HTTP 拿 JSON，不再驱动浏览器跑完整个页面。

TypeScript / MIT MCP Server 自修复 / Replay 本地凭证存储 基准 1.5–2× 更快

①Agent 拿网站数据，为什么要「爬浏览器」？

现在 Agent 要从网站提取数据，标准做法是挂一个 Playwright MCP，让浏览器一点点打开页面、点击按钮、等待渲染，再从 DOM 里读内容。这种方式有三个根本问题：

  • 慢：每次操作都要等页面完整渲染，Google Flights 任务 Playwright MCP 平均 12.9 秒，5 个日期参数直接拉到 41.6 秒。
  • 贵：页面渲染占用大量 token，成本 $0.166（单次）→ $0.154（5次），而且 token 消耗还在随页面复杂度线性增长。
  • 不稳定：网站改一次 UI，CSS selector 失效，整个流程就断了，需要人重新配一遍。
核心矛盾 Agent 实际上只需要网站返回的数据（JSON / 结构化文本），但我们却让它把整个浏览器渲染流水线跑完——这是巨大的浪费。

API Anything 的解题思路

把网站学下来，存成可复用的 HTTP 操作集。下次 Agent 要数据，填参数直接打请求，跳过浏览器渲染，拿到的就是干净的 JSON。整个过程不需要 LLM 生成任何请求逻辑。

为什么不用 LLM 生成请求？

传统的 AI 驱动爬虫让 LLM「看」页面截图或 DOM 后「想象」请求该长什么样——LLM 生成的是猜测，与网站实际接口可能存在偏差（header 缺失、参数名错误、URL 格式不对）。API Anything 的 Learn 阶段直接抓真实流量：它观察的是用户真实发出去的 HTTP 请求，是网站实际在处理的请求，零猜测。

两个输入的魔法 Learn 阶段需要两个示例输入（如 query=sqlite 和 query=javascript），系统通过对比两个请求的差异，自动识别出「跟着输入变的参数」和「不变的固定部分」，从而提炼出带槽位的模板。这一步完全不依赖 LLM。

②API Anything 是什么

一句话定位：把网站当 API 调，不再叫浏览器。

API Anything（goodnight000/api-anything，502★ / MIT / TypeScript）是本地 CLI + MCP Server，核心能力是「教 Agent 认识一个网站」，之后 Agent 可以像调用 REST API 一样直接发 HTTP 请求拿到结构化数据，不再需要 Playwright 或任何浏览器驱动。

GitHub README 原文 "Turn any website into an API your agent can call. Learns from the site's own frontend, heals itself when the site changes."

③核心工作流：Learn → Call → Repair

Step 1 · Learn（学）

用 headless Chrome 对两个示例输入各跑一遍，记录其中「跟着输入变化」的请求段，自动提炼成带槽位的 HTTP 模板。全程不调用 LLM。

关键点：「不叫 LLM 生成」 传统方案让 LLM 看页面后「想象」请求长什么样。API Anything 直接抓真实流量——它观察的是用户真正发出去的 HTTP 请求，不是猜测。这确保了学到的模板与网站实际接口完全一致。 
# 添加一个站点 operation
api-anything add hn-demo links \
  --trigger 'https://news.ycombinator.com/from?site={domain}' \
  --example domain=github.com \
  --example2 domain=github.io

# 添加 Goodreads 搜索（无公开 API，自 2020 年起）
api-anything add goodreads searchBooks \
  --trigger 'https://www.goodreads.com/search?q={q}' \
  --example q=piranesi \
  --example2 q=harry+potter

Step 2 · Call（调）

填槽位发 fetch。如果被目标站 block（403 / captcha），退回 Chrome 页面内发请求。最后手段才是跑页面本身读响应。

# 直接打 HTTP 拿 JSON（示例）
api-anything call hacker-news search query=sqlite

# 读 Goodreads 书评
api-anything call goodreads searchBooks q=piranesi

# MCP 调用（Claude Code / Codex）
# 安装命令直接粘贴给 agent：
# Set up API Anything for me: <url>

Step 3 · Repair（修）

当请求失效时，自动 re-learn（重新跑一遍页面流程），replay（重放验证），通过才保存新版本。防止「修坏了」——错误的新模板不会被保存。

Repair 的局限 Repair 无法解 CAPTCHA。如果 re-learn 过程中遇到人机验证，流程会中断，需要人工介入。

Map from Intent（全自动流程）

通过 skill 驱动，Agent 可自动完成「问用户意图 → 提议操作等审批 → scout 各页面 → 构建并验证 operation」全流程，无需手动编写触发条件。

⑤MCP 接入：Claude Code / Codex 一条命令安装

Claude Code 和 Codex 支持直接接入 MCP Server。API Anything 提供 MCP 接入能力，把下面这条命令粘贴给 agent 即可完成安装：

# 直接发给 agent 的安装指令
Set up API Anything for me: <mcp-server-url>

# 之后 agent 即可直接调用：
api-anything call <operation-name> <param1>=<value1> <param2>=<value2>

CLI 命令速查

命令作用
api-anything add <name> <op>添加站点 operation（触发 Learn 流程）
api-anything call <name> <op>调用已有 operation，填参数发请求
api-anything mapMap from Intent：自动扫描页面构建 operation
MCP 协议 MCP（Model Context Protocol）是 Anthropic 推出的 Agent 与工具之间的通信协议，Claude Code / Codex 原生支持。API Anything 作为 MCP Server 接入后，Agent 无需额外配置即可调用。

⑥Sessions & Logins：跨会话复用登录态

很多网站需要登录才能访问数据。API Anything 支持 cookie / token 本地持久化，存在 ~/.api-anything/ 目录，跨会话复用登录态。

凭证存储机制 凭证以引用方式存储在 spec 中（不直接存明文值），后续请求自动带上 Cookie / Authorization header，无需每次重新登录。

与 Playwright MCP 的对比

  • Playwright MCP：每次任务都要重新走登录流程（或维护复杂 session 状态）
  • API Anything：学一次登录态，全局复用；新增 operation 时自动继承已有 session

已测试支持场景

  • Goodreads 搜索 / 书籍详情 / 作者 / 书评（4 个 operation）
  • Hacker News 搜索
  • Google Flights 查询

使用流程示例：Goodreads 搜索书籍

# 一次性学习（Learn）
api-anything add goodreads searchBooks \
  --trigger 'https://www.goodreads.com/search?q={q}' \
  --example q=piranesi \
  --example2 q=harry+potter

# 之后直接调用（Call），无需再开浏览器
api-anything call goodreads searchBooks q=piranesi
# → 返回 JSON：{hits: [{title, author, rating, ...}], nbHits: 12}
安全注意 凭证存于本地 ~/.api-anything/，请在使用前阅读各目标网站的服务条款。使用前读各站点服务条款。

⑦诚实清单：已知局限

README 自述的局限性，评估是否影响你的使用场景：

局限项说明影响评估
Repair 可能失败 re-learn 遇到 CAPTCHA 时无法自动解算，需人工介入 高（频繁改版的站点维护成本高）
无 CAPTCHA 解算 人机验证场景无法自动绕过 中（大多数数据查询站影响小）
写操作需 --allow-writes LinkedIn messaging 等写操作未充分测试，需显式开启 中（读操作不受影响）
HTTP 2xx ≠ 送达 请求返回 200 不代表消息真的送到了（如 LinkedIn 发送成功确认） 高（写操作需额外验证）
本地工具，非托管 API 使用你的机器/网络/会话，无第三方保障 低（纯本地使用无影响）
只知道你教过的 operation 不支持站点的所有功能，只能调用学过的那些 低（按需学习，按需使用）
凭证本地存储 ~/.api-anything 目录，需注意权限和备份 低（本地工具正常风险）

⑨术语表

术语含义
MCP Model Context Protocol，Anthropic 推出的 Agent 与工具之间的通信协议，让 Agent 可以调用外部工具（类似 Tool Use / Function Calling，但更标准化）
Learn API Anything 的第一步：用 headless Chrome 对两个示例输入各跑一遍，观察实际发出的 HTTP 请求，提炼出带槽位的模板
Template（模板） 从真实请求中提取的 HTTP 骨架，包含固定部分（URL 前缀、header）和可变部分（槽位）。模板是网站实际接口的忠实复制，不是 LLM 生成的猜测
Slot（槽位） 模板中用 {参数名} 表示的可变占位符。Call 时填入具体值，生成最终请求。如 --trigger 'https://hn.algolia.com/?q={query}' 中 {query} 即为槽位
Call API Anything 的第二步：填槽位发 fetch 请求，拿到 JSON 数据。被 block 时退回 Chrome 页面内发
Repair API Anything 的第三步：请求失效时自动 re-learn + replay 验证，通过才保存新模板，防止修坏
replay（重放） 用新学到的模板重新跑一遍请求，验证返回值是否正确。只有 replay 通过才保存，防止返回他人数据或空响应
headless Chrome 无头浏览器：没有可视化界面的 Chrome，可编程控制页面行为、捕获网络请求。API Anything 用 headless Chrome 来执行 Learn 流程中的页面操作
Sessions 本地存储 cookie / token 等会话凭证存于 ~/.api-anything/ 目录，跨会话复用登录态。以引用方式存储 spec，不直接存明文值
Map from Intent skill 驱动的全自动流程：Agent 问用户意图 → 提议操作等审批 → scout 各页面 → 构建并验证 operation，无需手动编写触发条件
