PIPELINE

四个识别器 + 一个行分类器

rec.onnx 管拉丁/西里尔/希腊与拉丁手写，rec_cjk 管中日韩，rec_rtl 管阿拉伯/波斯/希伯来等，rec_world 管天城文、泰文、高棉文等。行分类器把每行派给对应识别器；拿不准的行让主识别器也读一遍，置信度高者胜出。

输出不止文字：每行、每块都有框、标签和阅读顺序，数字版 PDF 优先读文字层，只对缺的部分 OCR。

02
MECHANISM

它怎么处理一页文档

每页产出一个 Page 对象。数字版 PDF 走文字层检查，扫描页走旋转矫正和 OCR，两条路在 auto 模式下自动切换。

输出结构Page 对象

每个字段都有明确用途

  • markdown：标题、段落、列表；表格输出为 HTML，页眉页脚默认剔除
  • lines：每行 box（像素坐标）、text、置信度，按阅读顺序
  • blocks：布局块 {label, bbox, text}，同样按阅读顺序
  • source：text / ocr / hybrid / error，一眼看出这页走了哪条路
  • rotation / skew / vertical / timings / note：矫正角度、竖排标记、分步耗时、路径原因

块标签共 10 种：Text、Section-Header、Page-Header、Page-Footer、List-Group、Table、Caption、Footnote、Table-Of-Contents、Form。

模式与矫正三种 mode

auto / ocr / text 三种模式

  • auto（默认）：文字层检查通过就直读，失败区域才 OCR，图内文字也做 OCR
  • ocr：完全忽略文字层；官方跑分里 OCR-only 综合 61.2，低于 auto 的 66.7
  • text：即使检查不过也强制用文字层
  • 横放、倒置页面按 90°/180° 转；≤45° 倾斜自动拉直；中日韩竖排按四分之一转读，框仍标在原页面上

文字层能力有专项数据：75 个语系 1,125 页检查中，各语系字符保留率不低于 98%，含阿拉伯文、希伯来文和 CJK。

01 / CJK

中文怎么读

简繁中文、日文假名与汉字、韩文各走 rec_cjk.onnx。

中文测试集 64.0 分，低于 PP-StructureV3 的 68.4 和 PP-OCRv5 mobile 的 65.4。粤语用字（嘅 咗 冇）不在识别器内。

02 / HANDWRITING

手写：能读，读不好

OmniParseBench 手写测试 25.2%，held-out 手写页约三分之一词正确。

连笔和淡铅笔最差。官方把高精度手写指向自家平台的 Chandra 模型。

03 / MATH

数学默认关闭

--math 时数学行输出行内 LaTeX，综合分 66.7 升到 71.4。

代价：表格分掉 1.5，4 核吞吐约降 30%，32 核约降 38%；数学模型另下载。

04 / TILT

歪页与暗底

横放、倒置、最大 45° 倾斜、浅字深底都可处理。

官方示例：30° 倾斜页检出 skew 后拉直，读取结果与正页一致。

03
HANDS-ON

上手：从安装到一次可核验的处理

命令与字段均来自官方 README。环境要求 Python 3.10+，Linux x86_64/aarch64（3.10–3.13）或 macOS Apple silicon。

CLI最短路径

安装与三种输出

# 安装；首跑从 Hugging Face 下载约 76 MB 模型并缓存
pip install indra-ocr

indra-ocr paper.pdf              # markdown 到 stdout
indra-ocr *.pdf --out results/   # 每个输入一个 .md，默认用满所有核
indra-ocr scan.png --format json # 行、框、布局块、置信度、耗时
indra-ocr paper.pdf --mode ocr --timings  # 忽略文字层强制 OCR
indra-ocr *.pdf --out results/ --cores 8  # 限制核数

常用开关：--dpi（默认 200）、--max-pages、--password（加密 PDF）、--keep-furniture（保留页眉页脚）、--math。支持的图片格式：PNG、JPEG、TIFF（每帧一页）、BMP、WebP。

PYTHON批量

Python API 与本地查看器

import indra_ocr

conv = indra_ocr.load(threads=4)
for i, page in conv.convert("paper.pdf"):
    print(page.source, page.timings["total_ms"])
    print(page.blocks)   # [{label, bbox, text}] 按阅读顺序

# 批量：每核一个单线程 worker；macOS/Windows 必须加
# if __name__ == "__main__": 保护，否则单进程退化
indra_ocr.convert_many(["a.pdf", "b.pdf"], cores=None)

查看器：indra-ocr-viewer 在 localhost:8765 起本地页面，叠加行框、块标签和阅读顺序，附逐行置信度与分步耗时；文件不出本机。想对照 Tesseract 需额外装 indra-ocr[tesseract]。

验证任务5 分钟

最小验证：确认它对你的文档真的可用

  • 拿一页典型扫描图跑 indra-ocr page.png --format json
  • 看 source 字段：ocr / hybrid 说明走了识别；text 说明读了文字层
  • 抽查 blocks 的 label 与 bbox 是否和版面一致，表格是否成了 Table 块
  • 开 indra-ocr-viewer 目检框和阅读顺序，比肉眼看 JSON 快得多
失败边界官方口径

出问题时的判断依据

  • 某文件读不了：CLI 跳过继续，全部跑完后以退出码 1 收场；Python 侧返回 InputError
  • source: error 的页看 note 字段，里面写了它为什么走这条路
  • 机器无法访问 Hugging Face：用 --model-dir 或环境变量 INDRA_OCR_MODEL_DIR 指向本地模型目录
  • 表格单元格串行、手写页大量错词、老旧扫描错字多：属于官方 Limitations 列明的边界，不是配置错误

BOUNDARY & LICENSE

边界与许可：官方写明的短板

README 的 Limitations 一节明确说它是为「干净的印刷体、要速度」设计的。以下三项是最常踩到的边界，均照官方原文转述。

1

复杂表格

合并或跨行列的单元格、折行的单元格文本、嵌套表头、无框线表格，可能把单元格归错行列。简单网格表读得好。

2

手写与退化扫描

手写测试 25.2%，held-out 手写页约三分之一词正确；老旧、褪色、低分辨率扫描 29.5%。连笔与淡铅笔最差。

3

列表外文字与小字

叙利亚文、藏文、蒙古文等只能走数字 PDF 文字层；部分多变音符拉丁语言有近音替换；超 1 亿像素的页会降 dpi 渲染，小字可能丢。

许可两层

代码 Apache-2.0，权重是修改版 OpenRAIL-M

  • 代码：Apache License 2.0，仓库 LICENSE 文件即此
  • 权重（Hugging Face datalab-to/indra-ocr）：AI PUBS OPEN RAIL-M LICENSE（修改版）
  • 免费对象：研究、个人使用、融资或营收低于 2000 万美元的初创
  • 限制条款：不得与 Datalab 的 API 竞争性使用；推文转述时漏掉了这一句
  • 解除 OpenRAIL 限制或更大范围商用，走 Datalab 的付费授权
利益相关读数前知道

发布方同时在卖替代品

README 明确把手写、数学、复杂表格和退化扫描这些短板场景导向自家托管平台的 Chandra 模型，并附每月约 5,000 页免费额度的注册入口。同一厂商既发布 Indra 跑分、又出售更高精度的付费替代，这组数字应带着这个口径读。

工程结论：清晰印刷体的批量解析可以直接用 Indra 起步；命中上面任一短板时，先用 viewer 对自己的真实文档做一轮抽查，再决定是否需要更大的模型或商业 API。
