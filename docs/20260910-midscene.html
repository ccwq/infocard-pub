让 AI 看着屏幕完成 UI 测试

Midscene.js 用截图和视觉语言模型理解界面，让你用自然语言描述操作和预期，而不是把测试绑死在 CSS 选择器和 DOM 结构上。

先做什么：先用 Playwright 在一个非敏感测试页上跑通“打开页面 → 搜索 → 视觉断言 → 生成报告”，再评估移动端或桌面端接入。
从意图到可追溯结果
01 · 自然语言描述目标
02 · 截图理解当前界面
03 · 定位并执行操作
04 · 等待可见状态
05 · 语义断言 + 回放报告
核心判断：视觉定位减少选择器维护，但模型决策是概率性的；关键副作用仍要叠加确定性校验。
01

它解决什么问题：从“元素在哪里”转向“用户看到了什么”

传统 E2E 测试通常使用 CSS selector、XPath 或 accessibility tree 定位元素。它们在页面结构稳定时非常可靠，但前端重构、class 改名、复杂自定义控件、纯图标按钮、Canvas、跨域 iframe 和原生 App 界面，会让定位器维护成本快速上升。测试代码开始描述实现细节，而不是用户真正想完成的任务。

Midscene.js 的核心路线是视觉驱动：它获取当前屏幕截图，让视觉语言模型判断控件的位置、含义和当前状态，然后执行点击、输入、滚动或断言。对读者而言，测试步骤可以更接近验收语言，例如“搜索耳机并把价格筛到 100 美元以下”，而不是先为搜索框、筛选器和结果列表分别编写定位器。

但这不是“视觉一定比 DOM 更可靠”。视觉模型会受到截图质量、遮挡、相似控件、页面动态变化和模型能力影响。更准确的理解是：它把脆弱的结构定位问题，换成了需要模型调用、截图证据和结果复核的另一种工程权衡。

适用信号：你的测试目标跨 Web、移动端或桌面端，且同一个用户流程在不同 UI 实现中都应成立。若元素结构稳定、测试量大且结果必须完全确定，传统 locator 仍然值得保留。
02

第一次上手：先用官方 Web 集成跑通最小测试

官方仓库支持 Playwright/Puppeteer 方向的 Web 自动化。初学者不应从完整电商流程开始，而应准备一个能控制的测试页：页面包含一个搜索输入框、几个可见按钮和一个结果状态。先验证模型能看懂页面，再增加滚动、筛选和断言。

  1. 准备 Node.js 项目和一个可访问的测试页面；不要使用含真实个人数据的生产账号。
  2. 按官方文档安装当前版本的 Midscene Web 集成和 Playwright。
  3. 选择一个当前官方文档支持的视觉语言模型，并通过环境变量提供凭据。
  4. 在测试中创建浏览器页面，先用一个简单的 aiAct 完成点击或输入。
  5. 加入 aiWaitFor 等待结果状态，再用 aiAssert 验证用户可见结果。
  6. 运行测试并打开生成的回放/报告，检查每一步截图、定位和断言结果。
npm install -D playwright @midscene/web

03

六个核心 API：什么时候用完整流程，什么时候拆成单步

API作用适合初学者的用法验收重点
aiAct根据自然语言自主执行一段多步操作描述一个有明确终点的用户任务检查每一步截图与最终页面
aiTap根据视觉目标完成单次点击关键按钮需要单独观察时确认没有点击相似控件
aiInput定位输入区域并填入文本搜索、登录测试或表单输入确认输入内容和提交状态
aiWaitFor等待可见条件出现替代猜测式 sleep设置合理超时并准备失败截图
aiAssert对用户可见状态做语义断言颜色、选中状态、文案和布局断言写成可观察事实
aiQuery从界面提取结构化信息读取商品名、状态或列表内容核对字段格式与空值情况

建议先使用 aiAct 验证完整意图，再在失败位置拆成 aiTap、aiInput 和 aiWaitFor。这样可以缩小失败范围。不要把所有操作都压成一个超长自然语言段落，否则报告很难定位是哪一步误判；也不要把每个像素变化都写成断言，否则测试会重新变得脆弱。

04

等待与断言：用“状态”代替固定睡眠

页面加载、接口请求和动画时长在不同机器上可能不同。固定写“等待 3 秒”会造成测试变慢，或者在慢机器上仍然不够。aiWaitFor 让模型周期性观察截图，等待一个有意义的视觉状态，例如“筛选后的结果列表已经显示”或“提交成功提示可见”。

aiAssert 也应描述用户能看见的事实，而不是内部实现。例如“选中的套餐有蓝色边框和勾选标记”是视觉断言；“DOM 节点的 class 等于 selected”不是视觉断言，应交给传统代码或 DOM 检查。两者可以并存：视觉断言确认用户看到的结果，确定性断言确认关键数据、URL、HTTP 状态或业务规则。

不推荐：sleep(3000)
推荐：aiWaitFor("加载完成，结果列表和总数已经出现")

视觉：aiAssert("提交按钮变为已完成状态")
确定性：expect(response.status()).toBe(200)
确定性：expect(await page.url()).toContain("/result")
安全规则：涉及付款、删除、发布、权限变更或外部消息发送时，不要只用视觉断言决定成功；增加业务接口校验、人工确认或测试环境隔离。
05

Web、Android、iOS、鸿蒙和桌面：同一意图，不是同一套前置条件

官方 README 说明 Midscene 可运行在浏览器、Android、iOS、HarmonyOS、桌面应用以及能够提供截图和操作接口的自定义界面。跨平台价值在于测试意图和核心 API 可以保持相似；平台差异仍由各自的 Agent 初始化方式、设备桥接和截图能力承担。

平台常见接入方向需要准备第一条测试建议
WebPlaywright / Puppeteer浏览器、测试地址、模型 provider先测搜索或表单流程
Android设备桥接与截图控制ADB/设备权限、稳定分辨率先测打开 App 和点击一个按钮
iOS官方移动端接入路径设备、签名/自动化工具链先测可见页面状态，不先做支付流程
HarmonyOS官方支持的设备路径当前文档要求和测试设备先确认截图和操作接口可用
桌面/自定义提供截图与输入适配器窗口权限、捕获和输入注入先实现一个可回放动作

“同一套 API”不代表复制 Web 项目配置就能运行到手机。先阅读对应平台的官方集成文档，确认设备可见、截图尺寸稳定、输入动作可注入、模型请求不会把敏感画面发送到不合适的服务。

06

模型与成本：把公众号里的数字放回评测上下文

官方 README 列出 Qwen3.x、Doubao-Seed、GLM-4.6V、gemini-3.5-flash 和 UI-TARS 等视觉语言模型方向，并提到部分开源或可自托管选项。模型名称、版本、价格和 UI 定位能力会变化，实际项目应以当前 provider 文档和 Midscene 配置说明为准。

来源文章引用了一项 60 任务评测：使用 Doubao Seed 2.1 Turbo，总费用 0.59 美元，其中 58 个任务通过。这个数字属于特定 benchmark 的来源方报告，本卡不把它改写成“每个项目都不到一美分”或稳定通过率保证。评测结果会受任务集合、截图、模型版本、重试策略、缓存、地区价格和失败判定影响。

预算项为什么会变化你应记录什么
视觉模型调用每个操作/等待/断言可能产生多次观察调用次数、输入图像、token 和重试
截图与报告失败回放可能保存大量图片保存期限、压缩策略和访问权限
设备运行移动设备、云设备或桌面 runner 另有成本设备时长、并发和失败重跑
人工复核关键流程仍需要人确认哪些断言允许自动通过

成本优化顺序应是：先缩短测试意图和等待范围，再使用缓存回放，最后按风险选择模型。不要为了省调用把所有断言删除；也不要把一次成功当作稳定性数据。

07

报告、缓存与调试：失败时必须能回答“模型看到了什么”

视觉测试最重要的工程资产不是一句自然语言，而是失败时可回放的证据。官方资料提到 HTML 报告、每步截图、元素定位、AI 决策以及操作和断言结果。运行一次失败用例后，先看截图是否处于预期页面，再看模型的动作目标，最后判断是页面问题、模型定位问题还是测试意图不清楚。

  1. 保存测试名称、时间、浏览器/设备、模型和配置版本。
  2. 检查失败步骤截图：页面是否加载、是否有遮罩、是否出现登录过期。
  3. 检查动作：模型是否点击了相似按钮，输入是否进入正确区域。
  4. 检查等待：条件是否真正可见，超时是否过短。
  5. 检查断言：描述是否能被不同人独立判断。
  6. 如果页面确实改变，更新测试意图；不要只增加随机 sleep。

缓存适合复用已经验证的步骤、降低重复调用和加快回归，但缓存不能掩盖页面已经变化。遇到 UI 大改、模型升级、浏览器升级或设备分辨率变化，应清理或重建相关缓存，并重新审查报告。

08

把视觉测试接进工程：YAML、TypeScript、Vitest 和 CI

官方 README 同时提到 JavaScript SDK、YAML、Playwright/Vitest 集成、Skills 和 MCP。初学者可按复杂度选择：一个小流程先写 TypeScript；多人维护的验收意图可用 YAML；需要进入现有测试流水线时接 Playwright/Vitest；需要让 Agent 调用 UI 能力时再评估 Skills/MCP。

形式优点风险适合
TypeScript SDK可组合、可复用、能混合确定性断言工程代码较多正式回归套件
YAML 意图阅读门槛低，流程和实现分离复杂准备/清理仍需代码节点产品验收和团队协作
Playwright/Vitest进入已有 CI、报告和测试管理需要理解 runner 生命周期Web 回归测试
Skills/MCP上层 Agent 可按自然语言使用 UI 能力权限和副作用边界更复杂受控的 Agent 操作

CI 中至少要固定浏览器版本、视口、时区、语言、模型配置、超时和报告保存策略。若模型服务不可用，不要把整个失败伪装成产品回归；把“环境失败、模型失败、页面失败、断言失败”分开标记。

09

常见失败模式：从“看不懂”定位到具体原因

选错了相似控件

截图中有多个同名按钮或图标。缩小目标描述，增加上下文位置或先用确定性定位限定区域。

页面还没稳定

模型看到骨架屏、动画中间态或遮罩。用 aiWaitFor 等待可见业务状态，不要只延长固定睡眠。

输入成功但业务未提交

输入框有文本不等于请求成功。加入提交后状态和接口/URL 的确定性校验。

报告难以复盘

步骤过长或没有截图证据。拆分流程，给关键动作独立名称，保留失败上下文。

模型升级后通过率变化

模型和视觉定位能力会变。锁定版本或记录模型快照，重新跑代表性任务。

截图包含敏感信息

报告和缓存可能保存账号、客户数据或内部页面。使用脱敏测试环境并限制保存与访问。

10

安全边界：视觉自动化不应直接拥有不可逆权限

Midscene.js 可以让 AI 点击、输入和检查界面，因此权限设计比普通断言库更重要。测试账号应与生产账号隔离；支付、删除、发布、权限授予、外部消息和数据导出等动作必须进入专门的测试环境，并设置明确的人工确认或二次校验。

  • 不要把真实 API keys、tokens、passwords、credentials 写入用例、截图、报告或公开仓库。
  • 模型请求前确认截图是否包含个人信息、客户信息、内部 URL 或会话内容。
  • 为测试域名、账号、设备和可执行动作设置白名单。
  • 把视觉断言与业务接口断言组合，避免“看起来成功”被当成真实成功。
  • 记录模型版本、提示词、截图和决策结果，便于审计和复现。
  • 对失败重试设置上限；重试不能让重复提交、重复购买或重复发送发生。
不要这样做：不要把视觉 Agent 当作绕过登录、验证码、访问控制或第三方安全措施的工具。本卡只讨论授权测试环境中的 UI 自动化。
11

30 分钟最小实践：做一个可以解释的测试

  1. 创建一个本地或专用测试页面，包含搜索框、按钮、结果区和成功提示。
  2. 固定浏览器视口和语言，准备 3 个可重复的测试数据。
  3. 用单个 aiAct 完成输入和提交，运行一次并查看截图。
  4. 把等待条件改成“结果区已经显示”，不要使用无意义的长 sleep。
  5. 加入一个 aiAssert，验证结果区的可见文案或选中状态。
  6. 再加入一个确定性断言，验证 URL、状态码或测试数据。
  7. 故意改一个按钮文案，观察报告能否说明失败原因。
  8. 恢复页面，保存报告、模型版本和测试环境信息。
测试目标：搜索“耳机”并展示结果
视觉动作：在搜索框输入耳机并提交
等待条件：搜索结果区域已经显示
视觉断言：结果区域显示耳机相关内容
确定性断言：结果路由包含 /search
失败证据：最后一张截图 + 模型决策 + 页面日志

完成这个小闭环后，你已经验证了意图描述、视觉定位、等待、断言和报告五个关键环节。接下来才值得接入真实 Web 流程、移动设备或 CI。

12

最终选择：什么时候用 Midscene，什么时候不用

你的需求推荐原因
页面结构经常重构，但用户流程稳定优先评估 Midscene减少 selector 漂移维护
跨 Web、移动和桌面复用验收意图优先评估 Midscene统一自然语言意图和视觉结果
支付/删除等不可逆流程混合方案视觉 + 确定性校验 + 人工确认
元素结构稳定、调用量极大传统自动化或混合稳定 locator 成本更低、更可预测
需要像素级回归专门视觉回归工具语义断言不替代像素差异检测
没有稳定截图或设备接口暂不适合视觉路线的前提是能获取和操作界面

Midscene.js 最适合成为现有 E2E 体系的视觉层，而不是把所有测试都改成模型调用。先用一个小流程衡量：维护时间是否下降、失败是否更容易解释、模型调用成本是否可接受、关键路径是否仍有确定性保障。只有这些问题都得到答案，才适合扩大覆盖面。

官方入口：GitHub 仓库 · 官方网站 · API 文档 · 示例项目。项目采用 MIT 许可；具体版本、模型和平台要求以官方最新文档为准。

让测试描述用户目标，但让工程保留最后一道保险

  • 先从一个非敏感测试页开始，跑通截图、动作、等待、断言和报告。
  • 视觉定位减少结构耦合，但不能消除概率性；关键结果要有确定性校验。
  • 模型、价格、平台适配和 benchmark 都要绑定来源与版本。
  • 可回放证据、权限隔离和失败分类，决定它能否进入真实工程。
