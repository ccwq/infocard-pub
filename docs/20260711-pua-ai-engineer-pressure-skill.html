01 / AI 编程 Agent 高能动性 Skill

AI 编程 Agent：什么时候触发

README 定义：连续失败 2 次、准备说“无法解决”、未验证就归因环境、反复微调同一处、权限/网络报错后放弃，或用户要求“再试试”时触发；也可手动 /pua。

02 / 三条铁律

不是口号，是动作约束

  1. 穷尽一切：方案未穷尽前不说无法解决。
  2. 先做后问：有工具先用；提问附诊断结果。
  3. 主动出击：端到端交付，不等用户推动。
03 / 主动性等级

修完一个点，还要检查同类问题

README 将高主动性描述为：查上下文、找同类问题、修复后检查同模式，并给出验证结果与风险。它是行为规范，不是独立效果保证。

04 / L1-L4 压力升级

失败次数不是重试计数，而是切换诊断深度

L1
第 2 次失败
切换本质不同方案
L2
第 3 次失败
搜索 + 读源码
L3
第 4 次失败
执行 7 项检查清单
L4
第 5 次以上
拼命模式
05 / 7 项检查清单

L3：停止猜测，开始取证

README 的 MCP 注册案例中，L3 要求逐字读错误、检查日志和注册方式，最终发现 CLI 注册与手改配置存在差异。该案例不保证适用于所有 MCP 故障。

06 / 五步调试方法论

把“再试一次”变成新信息

  1. 闻味道：列出尝试，找共同失败模式。
  2. 揪头发：读错误、搜索、读源码、验证环境。
  3. 照镜子：检查重复与简单假设。
  4. 执行：方案必须本质不同且可验证。
  5. 复盘：记录原因，检查关联问题。
07 / 使用边界

适合调试纪律，不等于万能解法

  • README 列出 Claude Code、Codex CLI 等多平台；不代表每个平台具备同等功能。
  • README 列出 14 种扩展包与效率叙事；本卡未将其当作独立验证的性能结论。
  • GitHub API 未识别许可证，根目录未见 LICENSE；因此只写“README 声明 MIT”。
适用判断：当你的 Agent 常在难题前过早停止、未搜索未读源码就归因环境、或修复后不验证时，这套机制值得试。它提升的是执行纪律；不能替代权限、环境、模型能力与正确需求。
