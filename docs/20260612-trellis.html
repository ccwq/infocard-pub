USAGE SOP

五步完整使用流程：从安装到团队协作

1

安装 Trellis

全局安装 npm 包，Node.js >= 18，Python >= 3.9

npm install -g @mindfoldhq/trellis@latest
2

初始化仓库

在项目目录运行 init，指定用户名和使用的平台

trellis init -u 你的名字 trellis init --cursor --opencode --codex -u 名字
3

自然语言描述需求

用自然语言告诉 AI 你想做什么，Trellis 自动触发 brainstorm

"实现一个用户认证 API"
4

AI 自动跑四阶段

Brainstorm → Implement → Check → 自动验证，过程中无需人工介入

/trellis:finish-work
5

归档并沉淀规范

finish-work 将任务归档，更新 journal，将新认知写回 spec 目录

.trellis/spec/ 自动更新
1
PLAN
trellis-brainstorm 逐题梳理需求写入 prd.md；调研项派发给 trellis-research 子代理。输出：精选 spec + research，编排进 implement.jsonl。
trellis-brainstorm
2
IMPLEMENT
trellis-implement 子代理依据 PRD 编写代码，上下文按 implement.jsonl 自动注入。不主动执行 git commit。
trellis-implement
3
VERIFY
trellis-check 子代理基于 diff 对照 spec 逐项核查，运行 lint、type-check 和测试，在能力范围内自动修复。
trellis-check
4
FINISH
最终检查后，trellis-update-spec 将本轮新认知沉淀回 .trellis/spec/，为下一次会话积累工程记忆。
/trellis:finish-work
CORE ARTIFACTS
持久化的工程记忆
1

.trellis/spec/

规范沉淀目录：写一次规范，Trellis 在每次会话中按任务自动注入相关上下文，无需反复说明。

2

.trellis/tasks/

任务目录：PRD、实现上下文、审查上下文与任务状态统一存放，AI 开发过程保持结构化、可追溯。

3

.trellis/workspace/

工作日志：Journal 保留上次会话脉络，每次新会话从真实上下文开始，而非从零理解。

KEY FEATURES
相对 CLAUDE.md 的增量

作用域明确的 Spec

规范按任务/模块拆分，而非大而全的全局文档，便于维护和版本化。

任务级 PRD

每个任务有独立的 PRD 文件，描述清晰、可审查、可累积经验。

工作流关卡

Plan → Implement → Verify → Finish 四个阶段形成闭环，自动调用对应子代理。

工作区记忆

workspace journals 按开发者独立维护，共享 spec 则进入仓库版本控制。

平台感知生成

同一套规范，Trellis 自动适配不同平台生成对应格式的上下文文件。

TEAM COLLABORATION · 团队协作指南

共享规范（Spec）

.trellis/spec/ 进入 Git 仓库，PR 评审规范变更。团队成员共享同一套工程标准，无需各自维护。

✓ 进入版本控制

个人工作日志（Journal）

.trellis/workspace/ 按开发者独立维护，不进入共享仓库，避免冲突。规范共享，私人记录隔离。

✓ 独立维护

任务追踪（Tasks）

.trellis/tasks/ 存放 PRD、审查记录、任务状态。团队成员可查看任意任务上下文，Review 有据可查。

✓ 可追溯审查

FAQ

常见问题解答

Q: Trellis 和 CLAUDE.md / AGENTS.md 有什么区别？
这些文件是有用的入口，但容易变得冗长臃肿。Trellis 在此之上补充了：作用域明确的 Spec、按任务划分的 PRD、工作流关卡、工作区记忆，以及按平台自动生成的适配文件。
Q: Trellis 只能用 Claude Code 吗？
不是。Trellis 是一个跨平台的 Agent 工作流框架，支持 16+ 个 Coding Agent 和 IDE（Claude Code、Cursor、Copilot、Windsurf、Codex CLI 等）。
Q: Trellis 适合个人开发者还是团队？
两者都适合。个人开发者用它管理记忆和可重复的工作流；团队获得更大的收益：共享规范、任务边界、可审查的上下文和平台可移植性。
Q: 需要手动写所有规范文件吗？
不需要。很多团队从让 AI 从现有代码中起草规范开始，然后手工收紧重要部分。Trellis 最好在保持高信号规则明确且版本化的同时工作。
Q: 团队使用时会产生规范冲突吗？
不会。个人 workspace journal 在每个开发者端独立维护，而共享的 spec 和 tasks 放在仓库里，可以像其他项目文件一样被 review 和改进。
Q: 规范变更如何在团队中推广？
通过标准 PR 流程。规范变更提交 PR，团队成员 review 通过后合并。Trellis 不强制任何人遵守规范，但它提供了规范的「注入」机制——只要文件在 spec 目录里，Agent 每次都会自动读取。

"AI 写代码很快，但它每次会话都从零开始理解项目，记不住你的规范，也记不住团队级别的需求。Trellis 会把规范、任务、记忆沉淀进仓库，让任意 Coding Agent 都按你的工程标准来实践。"
