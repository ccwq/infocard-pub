Trellis

把 AI 编程从一次性的聊天变成有结构、可积累、可复用的工程流程：Plan → Implement → Verify → Finish 四阶段循环，规范沉淀到 .trellis/spec/，让任意 Coding Agent 都能按团队标准工作。

4 相阶段循环 5 智能体技能 14+ 平台支持 AGPL-3.0 v0.5.19
WITHOUT TRELLIS
每次新会话，Agent 从零理解项目。
痛点

上下文每次清空

项目规范、团队约定靠口头传递，Agent 无法累积记忆。

痛点

规范难以结构化

CLAUDE.md / AGENTS.md 容易变成大而全的文档，缺少任务级上下文。

痛点

平台绑定工作流

在 Claude Code 里积累的流程，换到 Cursor 就得重来一遍。

痛点

验证靠人工兜底

AI 写的代码没有自动对照 spec 检查，容易带进不符合规范的实现。

WITH TRELLIS → 上下文持久化 · 规范版本化 · 跨平台复用
"AI capabilities grow like ivy — Trellis provides the structure to guide them along a disciplined path."
npm: @mindfoldhq/trellis v0.5.19 · Node.js >= 18 · Python >= 3.9 · 安装即用，初始化后自动生成 .trellis/ 工作区结构。
1
PLAN
trellis-brainstorm 逐题梳理需求写入 prd.md；调研项派发给 trellis-research 子代理。输出：精选 spec + research，编排进 implement.jsonl。
2
IMPLEMENT
trellis-implement 子代理依据 PRD 编写代码，上下文按 implement.jsonl 自动注入。不主动执行 git commit。
3
VERIFY
trellis-check 子代理基于 diff 对照 spec 逐项核查，运行 lint、type-check 和测试，在能力范围内自动修复。
4
FINISH
最终检查后，trellis-update-spec 将本轮新认知沉淀回 .trellis/spec/，为下一次会话积累工程记忆。
CORE ARTIFACTS
持久化的工程记忆
1

.trellis/spec/

规范沉淀目录：写一次规范，Trellis 在每次会话中按任务自动注入相关上下文，无需反复说明。

2

.trellis/tasks/

任务目录：PRD、实现上下文、审查上下文与任务状态统一存放，AI 开发过程保持结构化、可追溯。

3

.trellis/workspace/

工作日志：Journal 保留上次会话脉络，每次新会话从真实上下文开始，而非从零理解。

KEY FEATURES
相对 CLAUDE.md 的增量

作用域明确的 Spec

规范按任务/模块拆分，而非大而全的全局文档，便于维护和版本化。

任务级 PRD

每个任务有独立的 PRD 文件，描述清晰、可审查、可累积经验。

工作流关卡

Plan → Implement → Verify → Finish 四个阶段形成闭环，自动调用对应子代理。

工作区记忆

workspace journals 按开发者独立维护，共享 spec 则进入仓库版本控制。

平台感知生成

同一套规范，Trellis 自动适配不同平台生成对应格式的上下文文件。

问：Trellis 和 CLAUDE.md / AGENTS.md / .cursorrules 有什么区别？

这些文件是有用的入口，但容易变得冗长臃肿。Trellis 在此之上补充了：作用域明确的 Spec、按任务划分的 PRD、工作流关卡、工作区记忆，以及按平台自动生成的适配文件。
