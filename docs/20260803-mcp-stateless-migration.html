MCP 无状态化：从 Session 到显式句柄的迁移指南

2025-06-18 规范与 SEP-2567/2575 的核心变化：协议层移除隐式 Session，把状态、身份和恢复责任交还给每个请求与业务设计。

迁移重点：Session 依赖MCP Stateless先审计，再升级
一句话结论：不是所有 MCP 服务都要重写

多数只使用 SDK 路由样板、未把 session 当业务状态的服务，主要是升级与兼容矩阵验证；真正高风险的是 session 作为存储键、粘性路由或认证绑定的长尾实现。

01
WHAT CHANGED

这次到底改了什么

把“协议层状态”拆成可验证的请求级机制。

握手

移除强制初始化握手

SEP-2575 提议移除必须建立持久状态的 initialize 流程，把协议版本、能力和客户端信息拆到请求级机制中；不应把视频中的“server/discover”等表述直接当作所有实现的现行规范，需按当前版本文档核对。

会话

移除协议层 Session

SEP-2567 的核心是移除 Mcp-Session-Id 与协议级 session 语义。列表结果不再依赖连接/session；缓存与失效应按部署、授权主体和 TTL 等实际条件设计。

状态

显式句柄成为工具设计模式

购物车、浏览器上下文、事务等跨调用状态，由 create_* 返回 opaque ID，再由后续工具显式携带。句柄不是新的协议字段，而是普通工具结果和参数。

02
IMPACT TRIAGE

先判断你属于哪一类

不要因为“无状态”三个字就启动全员重写。

低影响

只用标准工具调用

应用层未读取 session ID，也未依赖连接生命周期；优先升级 SDK 并跑兼容矩阵。

中影响

样板映射或无效生成器

检查 SDK 路由样板、构造参数和自动生成代码，按官方 codemod/迁移指南修正。

高影响

Session 作为存储键

将购物车、浏览器、事务等状态绑定 session 的代码，需要改成显式句柄与每次授权校验。

高影响

粘性路由或认证绑定

审计网关路由、身份和状态的耦合；迁移期准备新旧协议兼容端点和回滚方案。

03
STATE HANDLE

显式句柄怎么设计

句柄解决的是状态寻址，不自动解决授权。

推荐模式

create → carry → operate

create_basket() → basket_id
add_item(basket_id, sku)
checkout(basket_id)
  • 句柄保持 opaque，不编码内部结构。
  • 创建工具说明有效期、清理方式和恢复方法。
  • 过期句柄返回可让模型重新创建的明确错误。
安全铁律

持有不等于授权

  • 认证服务每次校验 `(handle, auth_context)`。
  • 未认证服务中，句柄是 bearer token，应使用至少 128 bit 安全熵。
  • 加入短 TTL、防重放、防枚举和主体绑定。
  • requestState 等客户端往返数据视为敌意输入，使用 HMAC/AEAD 等完整性保护；签名不等于加密。
04
MIGRATION CHECKLIST

十分钟自查与测试矩阵

先 grep 定位，再决定排期。

A · 搜索

定位隐式依赖

Mcp-Session-Id、initialize、旧传输类、session 作为 Map/Redis/数据库 key、sticky routing、认证与 session 绑定。

B · 兼容

验证新旧组合

客户端/服务器分别升级；覆盖工具发现、错误响应、OAuth、请求取消、长任务、超时、负载均衡和旧客户端遇到新服务器的行为。

C · 观测

重审监控假设

多轮交互可能改变 request ID 关联与延迟统计；监控系统不能再默认“一次请求 = 一次完整操作”。

05
RISK REGISTER

容易踩坑的工程细节

视频中的社区案例作为线索，必须按项目版本复现。

1

生命周期重复进入

Lambda/Mangum 类适配器若把 app 构建放在模块级，热调用可能触发生命周期复用错误；先查具体运行时与 SDK issue，不能只凭视频结论改代码。

2

requestState 被篡改或重放

客户端会原样回显但不应信任；服务端必须验证完整性、主体和 TTL，失败直接拒绝。

3

缓存跨用户串接

cacheScope/public 等配置若误标，可能把用户 A 的工具目录发给用户 B。TTL 是新鲜度提示，不是安全承诺。

06
DECISION

现在该怎么排期

把协议升级与业务状态迁移拆成两个决策。

先做

第一周：审计与隔离

固定旧版本可回滚基线；grep 全仓 session 依赖；列出路由/认证/存储耦合；在测试环境验证 SDK 版本与传输协商。

再做

第二周：显式状态与双车道

将业务状态改成显式句柄；为句柄增加身份绑定、TTL、完整性保护和销毁接口；迁移期提供兼容旧客户端的端点，再逐步拆除旧车道。
