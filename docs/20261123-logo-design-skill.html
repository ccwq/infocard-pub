logo-design-skill：
交稿前先停一下的 Logo 设计师

这个仓库把真人设计师接活的套路写成了 agent 的硬性步骤：先问清需求，再翻 1400 多个真实 Logo 查行业惯例，写 8–12 个一句话创意、挑差异最大的 3 个画成黑白 SVG，机器审查之后才给你看——然后停在一个确认点，等你选方向。选完才出配色、组合、图标和品牌规范。

一句话直出 vs 走完整流程
一句话直出

收到需求就画，中间没有需求确认，没有行业惯例对照，画完直接交，小尺寸和单色场景没人检查。

走完整流程

问不清楚就列假设让你确认；概念先黑白过审，16px 和单色都测过才展示；方向没定不出成品。

出图前查惯例，出图后跑测试，交稿前停在确认点——三件事都写成了流程里的必经步骤。

工作量的大头（配色、组合、演示板、图标、品牌规范）只在方向确定之后开工，README 原话：kit 只对已批准的方向才有意义。
到这里已经够判断要不要装。往下是两道检查的真实输出、参考库的统计数字、各 agent 的安装方式和三条使用边界。
01 · Brief问清需求

反过来问你一堆问题；问不清楚就把假设列出来让你确认，不猜着画。

02 · Research查行业惯例

在自带的 Logo 库里检索同品类的构造、手法和排版惯例。

03 · 概念 → 审查3 个黑白 SVG 先过检

8–12 个一句话创意，挑差异最大的 3 个画成 SVG，先跑 audit 和测试页再给你看。

停04 · Checkpoint展示 + 推荐，然后停

3 个方案拼成一张总览图，标出推荐，等你选方向；想改就回概念阶段。

选完方向才进 Kit：配色、横竖组合、行业演示板、favicon 与 app 图标、一页纸品牌规范。这步占整个工作量的大头。

两道硬检查，真实输出
audit & test sheet
svg_audit.py · 同一品牌两个文件推荐方案 99/100，未推荐的 76/100

扣分项写得具体：374 个锚点，超过 95% 的同类参考 Logo（中位 53）；8 条直边偏离标准角度 0.3–3°；6 个子图形小于画布的 1/48，缩成 favicon 就消失。推荐那个 205 个锚点、单色、横版 3.5:1。

preview_sheet.py · 测试页小尺寸阶梯 + 场景模拟

方案并排 96/32px、单色、反白，再逐级缩到 16px；配眯眼模糊、镜像和真实使用场景模拟，最后混进同类真 Logo 做货架测试。

README 示例 · Maison Orvelle字标 32px 发糊，字母组合标撑住

结论落在用法上：奢侈品牌的字标要配一个小标志一起用。Kiln 的例子则在展示前就抓出了一条 60.8° 的斜线和偏离中心的符号。

怎么用最划算
use it well
新 Logo把简报写得像回事

行业、气质、禁用元素、使用场景、最小尺寸一次说清；出概念阶段先别急着上色。

已有 Logo先体检再决定要不要重做

用 svg_audit.py 审现有的 logo.svg，FAIL 和 WARN 逐条列出，哪些影响小尺寸一眼可见。

选方案可以直接不选推荐的

确认点就是为这个设计的：选完它会对你的选择继续做工艺修正，再进上色和交付。

边界与提醒
limits
用之前先对三条：
  • PNG/ICO 导出要本机有渲染器：cairosvg、rsvg-convert、Inkscape、Chrome 系浏览器、macOS 快速预览，有其一即可；Python 3.8+、只用标准库。
  • 最好配能看图的模型：它会把草稿渲染成 PNG 自查后再给你；模型看不了图，这一步就失效。
  • 商用前自己跑商标检索：库内 SVG 是各家商标，仅作学习参考、不在 MIT 协议内；示例里的品牌全是虚构 brief。
