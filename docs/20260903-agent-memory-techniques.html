01

先判断：记忆问题属于哪一层？

不要把所有历史消息都塞进向量库；不同问题需要不同机制。

短期上下文

对话缓存、滑动窗口、摘要与 Token 裁剪：解决当前会话的上下文预算。Notebook 01–05。

长期事实

实体、语义、程序记忆：保存跨会话仍然稳定的偏好、事实与操作方式。Notebook 06–11。

关系与事件

知识图谱、情景记忆、时间记忆：回答谁与谁有关、何时发生过什么。Notebook 08、09、18。

认知架构

工作记忆、分层、合并、压缩、反思、遗忘：管理记忆生命周期。Notebook 12–19。

召回与协作

混合检索、重排、跨会话、多 Agent 共享和工具化记忆。Notebook 20–23。

框架与生产

Graphiti、Mem0、Letta、Zep，以及评测、基准和部署模式。Notebook 24–30。

02

日常技术选型：先问三个问题

把"哪个框架最好"改成"哪个机制适合当前约束"。

Q1要记住原文、事实，还是事件关系？
Q2优先低延迟、低成本，还是高召回与可解释？
Q3Demo 验证，还是要权限、删除与审计？
输出确定候选路线，再选 Notebook
对话缓存向量检索知识图谱跨会话评测生产治理
03

选型矩阵：按约束而不是热度决策

工程判断框架，不是框架能力的独立排名。

你的约束优先看可先读必须验证
单轮或短对话窗口、摘要、Token 预算01–05、12上下文长度与成本
跨会话个性化实体/语义/跨会话记忆07、10、21、25更新、冲突与删除
复杂关系与时间图谱、事件、时间检索08、09、18、24、27事实新鲜度与可解释性
团队 Agent 协作共享存储、消息与协议17、22、23隔离、并发与权限
准备上线评测、基准、缓存、TTL、观测28–30延迟、失败、成本与合规
04

从 Notebook 到生产：不要跳过验证

"能运行"只是起点，不能直接推出"适合上线"。

建议的验证顺序

先用可控场景复现 → 替换模型与存储 → 记录召回命中、陈旧、矛盾、延迟与成本 → 再用长对话基准和真实业务样本复核。

上线前的治理项

明确谁能读写记忆；支持更正、删除与过期；隔离用户和项目；记录召回来源；为错误记忆、提示注入和敏感数据泄露准备回退方案。

边界：仓库是学习与选型资源，不是独立性能排名，也不是生产就绪证明。当前卡片未对全部 Notebook 做本地运行复测；实际结论应以你的模型、数据、依赖、评测集和业务约束为准。
05

渐进式阅读：先做小实验，再扩大记忆边界

不要一开始就搭完整记忆平台；每一步都要能验证、能回退。

Level 1 · 当前会话先用窗口或摘要解决上下文预算
Level 2 · 跨会话再加入事实、实体与可删除记录
Level 3 · 关系召回需要时间与关系时再引入图谱
Level 4 · 生产治理最后补齐评测、权限、TTL 与观测
最小闭环：选一个真实但低风险的场景，固定测试问题与预期答案；每次只改变一种记忆机制，记录召回质量、延迟、成本和错误记忆，再决定是否进入下一层。
