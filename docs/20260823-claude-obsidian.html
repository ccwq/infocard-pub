■ 核心概念：LLM Wiki 与 Karpathy 起源

什么是 LLM Wiki？

一种让 LLM 自主维护、扩展和查询本地知识库的架构模式。LLM 不是在对话中临时生成答案，而是把知识固化到可验证的 Markdown 页面，并维护可溯源的 Source & Claim Ledger。

Karpathy 的开创性

Andrej Karpathy 在 2022 年提出的 "LLM Wiki" 概念（见 karpathy/gist），核心思路：用 LLM 构建、管理、查询自建知识库，使 AI 成为真正的第二大脑，而非一次性聊天。

claude-obsidian 的工业级实现

在 Karpathy 原型基础上，claude-obsidian 加入了 Multi-Agent 事务机制（SHA-256 写验证）、Source & Claim Ledger（高风险声明双源）、BM25 回退语义检索、15+ Agent Skills、Obsidian Canvas 可视化面板。

本地优先存储

纯 Markdown + JSON 格式，所有内容存储在你的 Obsidian Vault 中。无插件缓存、无云数据库、无静默上传。JSON 用于事务元数据（Source Ledger、Claim Ledger、事务 ID），Markdown 用于知识页面本身。

■ Multi-Agent 事务提交（SHA-256 验证）

Step 1 · 读源

读取所有目标文件，预先记录每个文件的预期 SHA-256 哈希

Step 2 · Worker 并行

并行 workers 返回草稿和证据（不直接写 vault）

Step 3 · Merge

将完整变更合并为一个操作包（operation bundle）

Step 4 · 检查

检查操作包，SHA-256 验证变更前的文件哈希

Step 5 · Apply

一次性应用变更，写入 vault，报告操作 ID 和变更路径

事务保证：核心持有单一进程生命周期 vault 锁，日志化备份，原子替换。如果 apply 无法完成则回滚到之前状态。变更目标 = 冲突，从不静默覆盖。Git checkpoints、破坏性修复、出口流量、权威研究合并均为显式操作。
Source & Claim Ledger：每个声明记录权威性（Authority）、新鲜度（Freshness）、支持（Support）、矛盾（Contradiction）、置信度（Confidence）和审查状态（Review State）。高风险声明要求两个独立来源。

■ 15+ Agent Skills

wiki
初始化或接管 vault，诊断就绪状态，路由工作流
save
保存一个限定答案或洞察——从不自动转录
wiki-ingest
将捕获的源转换为链接页面和溯源记录
wiki-query
从相关 vault 证据中读取答案
wiki-lint
报告死链、孤儿、元数据缺口、过期索引、空段落
autoresearch
有界 Web 研究，有显式出口流量和独立权威合并
canvas
Wiki 范围的 Obsidian Canvas 创建与维护
defuddle
在摄入前清洗网页内容为可读文本
wiki-fold
操作日志的可追踪提取汇总
wiki-mode
通用、LYT、PARA 或 Zettelkasten 分类约定
wiki-retrieve
上下文前缀 + BM25 + 可选余弦重排
wiki-cli
Obsidian CLI 读取搜索 + 事务安全写入
obsidian-markdown
正确 Obsidian 风味 Markdown、链接、嵌入、callouts
obsidian-bases
原生 .base 表格、卡片、过滤器、公式、汇总
think
结构化观察→倾听→连接→创造→成长回顾循环
BM25 回退语义检索：当 embedding 或重排阶段无法信任时，模型检索自动回退到确定性 BM25。不依赖外部 embedding 服务。

■ Claude Code / Codex / Gemini 接入方式

Claude Code

claude --plugin-dir /absolute/path/to/claude-obsidian
进入 vault 后用命名空间调用：/claude-obsidian:wiki 初始化 → /claude-obsidian:wiki-ingest 摄入源 → /claude-obsidian:save 保存答案 → /claude-obsidian:wiki-query 查询。

Codex / OpenCode

bash bin/setup-multi-agent.sh --host codex bash bin/setup-multi-agent.sh --host codex --apply
预览并应用 portable skill links，参考 GEMINI.md 文档对 Gemini 主机执行相同流程。

Cursor / Windsurf

使用 workspace-local skill 发现机制，按 docs/install-guide.md 进行 marketplace 设置。所有支持主机的详细安装步骤均在该指南中。

Gemini

bash bin/setup-multi-agent.sh --host gemini --apply
参考仓库根目录 GEMINI.md 获取完整接入指南。

■ 安装与快速开始

1
克隆
2
初始化 Vault
3
打开 Obsidian

运行 Claude
git clone https://github.com/AgriciDaniel/claude-obsidian.git
cd claude-obsidian

初始化独立 Vault（推荐）

export GENERATED_AT="$(date -u +%Y-%m-%dT%H:%M:%SZ)"
export OPERATION_ID="init-reviewed"

# 预览操作计划
python3 scripts/claude-obsidian.py init "$HOME/Documents/MyKnowledgeVault" \
  --generated-at "$GENERATED_AT" --operation-id "$OPERATION_ID"

# 审查 JSON 计划，复制 approved_plan_sha256，然后应用
python3 scripts/claude-obsidian.py init "$HOME/Documents/MyKnowledgeVault" \
  --generated-at "$GENERATED_AT" --operation-id "$OPERATION_ID" \
  --approved-plan-sha256 "<sha256-from-the-plan>" --apply

启动 Claude Code

cd "$HOME/Documents/MyKnowledgeVault"
claude --plugin-dir /absolute/path/to/claude-obsidian
信任边界：产品从不将源代码 checkout、插件缓存或贡献者状态视为默认 vault。Vault 通过 CLAUDE_OBSIDIAN_VAULT、最近的 .claude-obsidian.json 或一个明确的初始化祖先目录来显式选择。Vault 选择不确定时，命令退出不写入。
平台要求：Python 3.11+（核心）；Obsidian（视觉体验，可选）；Bash（安装脚本和测试套件）；Git（仅用于开发/发布/显式知识检查点）。Native Windows 需 WSL 执行 vault 写入操作。
