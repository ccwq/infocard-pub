不是向量库 是文件系统 cat/grep 可翻
Brain 是 Perplexity Computer 的记忆核心——用文件系统 Markdown Wiki 替代向量数据库，让 agent 的工作记忆可追溯、可引用、可自我进化。

Brain 将 agent 的交互历史存储为标准 Markdown 文件（而非向量 embedding），通过三层目录结构（knowledge/notes/sessions）组织知识，支持 [[wikilinks]] 横向上下文链接和 [cite:N] 证据引用链。Dream 后台 agent 每晚自动 orient → summarize → attach → update 循环，用 Git commit 持久化。Memory Agent 子 agent 按需语义搜索并加载文件。30 天生产数据：答案正确性 +9.3pp（0.600→0.661），召回率 +8.9pp（0.573→0.625），Token -15%，成本 -10%，生成速度 +10%；最大增益出现在偏好问题（+10.2pp）、时间推理（+8.6pp）和活动细节提取（+6.9pp）。定位 Max（$200/月）和 Enterprise Max 订阅者，现为 Research Preview。

01
CORE ARCHITECTURE

不是向量库，是文件系统 Wiki

Brain 的核心创新：把记忆存在标准 Markdown 文件里，用 Git 追踪历史，用 cat/grep 浏览——完全不需要向量数据库。

为什么不用向量数据库？
embedding 是黑盒——你不知道记忆里有什么、怎么关联、结论从何而来。Brain 选择透明：记忆就是人类可读的文件，[[wikilinks]] 就是关联，[cite:N] 就是证据链。
向量数据库Brain

两种记忆范式对比

  • ✗ embedding 黑盒，不可解释
  • ✗ 相似性搜索，无法精确引用
  • ✗ 需要单独向量索引服务
  • ✓ 标准 Markdown，人类可读
  • ✓ Git 版本控制，可追溯历史
  • ✓ cat/grep 即可浏览，无需专有工具

02
WIKI LINKING

[[wikilinks]] 横向上下文 + [cite:N] 证据链

Brain 的两条核心链接语法：[[wikilinks]] 连接横向上下文（"还需要知道什么？"），[cite:N] 指向证据来源（"这个结论怎么来的？"）。

[[wikilinks]]横向上下文

回答"还需要知道什么？"

在 Markdown 文件中用 [[实体名]] 或 [[project/项目名]] 链接相关实体、概念、项目：

## Brain 架构概述 Brain 是 [[perplexity-computer]] 的记忆核心， 基于 [[knowledge-base]] 而非向量数据库。 参见 [[project/research-preview]] 了解最新进展。

链接目标可是 entity、concept、project、历史学习记录——形成横向上下文网络。

[cite:N]证据链

回答"结论从何而来？"

用 [cite:N] 指向原始 session 或 connector 来源，建立可验证的证据边：

## Brain 评估结论 Brain 在 30 天生产中[cite:1]提升答案正确性 +9.3pp（0.600→0.661），Token 消耗 -15%[cite:2]。 证据来源： [1] sessions/session_2026-08-01.md [2] sessions/session_2026-08-15.md

84% 的问题 agent 可验证地接触了绑定到黄金证据的来源。

[[wikilinks]]

横向上下文边——连接相关实体、概念、项目。

  • 用途：扩展上下文
  • 回答：还需要知道什么？
  • 位置：knowledge/ 下各文件
链接类型

证据边——向下连接到原始 session 或 connector 来源。

  • 用途：可验证的引用链
  • 回答：结论怎么来的？
  • 位置：结论性陈述后

cat / grep

03
DREAM & MEMORY AGENT

Dream 每晚整理 + Memory Agent 按需加载

Dream 是每晚运行的后台整理 agent，执行四阶段循环；Memory Agent 是按需触发的语义搜索子 agent，两者共同构成 Brain 的自动维护机制。

DreamNightly Agent

Dream：每晚四阶段整理循环

默认每晚自动执行（可配置间隔），完整四阶段：

Phase 1
Orient — 定位今日新增内容
Phase 2
Summarize — 总结新 session
Phase 3
Attach — 附加重要观察
Phase 4
Update — 更新 links & citations

通过确定性格式检查 + 语义证据验证后，用 git commit 提交更改。记忆进化由 Git 版本控制追踪。

Memory AgentOn-demand Subagent

Memory Agent：按需语义搜索

独立子 agent，在 agent 需要特定记忆时触发：

启动时: 预加载初始 map 运行中: Memory Agent 语义搜索 加载时: 按需补充文件 # 混合物化策略 preload_map = initial_context memory_agent.search(query) memory_agent.load(relevant_files)

Memory Agent 不是每次都全量搜索，而是结合预加载 initial map + 按需语义补充的混合物化策略，平衡速度与精度。

E

Enterprise Max

企业级部署，支持团队共享 Brain 记忆，支持更多 connector 和数据源。

RP

Research Preview

当前阶段，功能持续迭代中。部分用户可提前体验。

未来随功能完善可能调整定价和定位。

适用

Brain 最适合的场景

  • ✓ 多会话、长周期任务（需要跨时间上下文）
  • ✓ 需要可追溯证据链的专业查询
  • ✓ 偏好密集型任务（用户习惯影响答案质量）
  • ✓ 企业知识管理（团队共享 Brain）
不适合

Brain 暂不适用的场景

  • ✗ 一次性单次查询（启动成本不划算）
  • ✗ 完全独立的短任务（无跨会话价值）
  • ✗ 需要实时数据库的场景（Brain 是事后整理）
  • ✗ Max 订阅以下用户（暂未开放）
