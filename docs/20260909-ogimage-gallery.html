它解决什么问题

OG Image 是链接被分享到社交平台时展示的首张预览图。OGimage.gallery 把这类图像当作产品入口来收集：读者可以按类别浏览不同网站的分享图，观察标题、配色、信息密度和品牌识别如何在一张小海报里完成。

关键判断：落地页负责说服已经点进来的人，OG Image 负责争取信息流里的那一次点击。它不是截图归档，而是一组可供产品、设计和营销参考的公开样本。

怎么使用画廊

  • 打开画廊，从 All 或 Animated、App、Creative、SaaS 等分类开始浏览。
  • 按视觉方向筛选：大字号、强对比、插画、动态预览或极简品牌色。
  • 点进单个样本，查看原始网站与对应的 OG 图；把构图规律提炼成自己的分享图规范。
  • 把观察结果落回产品：标题长度、品牌色、产品类型标签和行动暗示要在缩略图尺寸下仍然成立。

观察一张 OG Image 时看什么

  • 信息层级：第一眼是否知道这是什么，第二眼是否知道它为什么值得点击。
  • 缩略图识别：缩小到信息流尺寸后，标题是否仍可读，主体是否仍突出。
  • 品牌一致性：字体、颜色、插画和产品界面是否与落地页形成连续印象。
  • 内容时效性：版本号、活动日期和产品状态是否会让图在几周后过期。
  • 可分享性：图像是否给出了足够上下文，同时没有把所有正文塞进一张图。

适合谁

  • 独立开发者：为产品首页、发布帖和更新日志建立一套稳定的分享图模板。
  • 设计师：收集真实案例，比较不同产品类别的视觉入口。
  • 内容团队：在发布文章、工具和教程前，先检查社交预览是否值得点击。
  • 品牌团队：把 OG Image 当作低成本的品牌触点，而不是发布前最后一张截图。

边界与建议

OGimage.gallery 是灵感与案例画廊，不是 OG 图生成器，也不替你判断哪张图一定带来更高点击率。真正落地时仍要用目标平台的预览工具检查裁切、缓存和移动端显示，并结合自己的受众做 A/B 测试。

先理解 OG Image：它是点击前的第一层产品界面

当一个链接出现在社交平台、聊天窗口、收藏列表或搜索分享卡片中，用户通常先看到标题、摘要和一张预览图。OG Image 不是落地页的缩略截图，而是一个独立的入口组件：它需要在很小的面积里告诉用户这是什么、为什么值得点、它和谁有关。

OGimage.gallery 的价值在于提供大量真实案例，让初学者从“我觉得好看”进一步走向“我能说出它为什么有效”。你可以观察不同类别的网站如何安排标题、品牌色、产品截图、人物、插画和留白，并把规律转化成自己的模板。

新手 10 分钟入门路径

  1. 打开画廊首页，先不要追求看完所有样本。选择 App、SaaS、Creative 或 Resources 中与你的项目接近的分类。
  2. 连续打开 6 到 10 张图，记录每张图的第一眼信息：产品名、功能、活动还是观点。
  3. 把样本按大字号、产品截图、插画、强品牌色和动态感分组。
  4. 选出 3 张最接近你目标的样本，比较标题长度、图像比例、色彩数量和信息密度。
  5. 写出自己的第一版规则：画幅、标题位置、品牌色、是否放产品截图、是否保留副标题。
  6. 用一个真实页面生成预览，分别在桌面和移动端检查，再根据实际裁切修正。

从零设计一张自己的分享图

  1. 确定用途：产品发布、文章分享、版本更新、教程或活动，不同用途不要共用同一句标题。
  2. 确定唯一主信息：一张图只强调一个动作或一个价值，不要把整段摘要搬进去。
  3. 确定安全区：把关键标题和主体放在中心区域，避免被平台裁切或被圆角遮挡。
  4. 先做黑白稿：如果没有颜色和图片时层级仍然成立，后续加色更容易控制。
  5. 加入品牌锚点：选择一到两个品牌色、固定 Logo 位置和固定字体组合。
  6. 导出多个比例并实测：至少检查桌面分享、移动信息流和聊天预览。
主标题：一句话说清产品或内容
副标题：补充对象、场景或收益，不超过一行
视觉主体：产品界面 / 插画 / 人物 / 抽象图形，四选一为主
品牌锚点：Logo + 1~2 个品牌色
安全区：四周预留，不把关键文字贴边

常见失败模式

信息太多

把文章标题、摘要、作者、日期、功能列表和按钮全部放进一张图，缩小后只剩噪音。修复：保留主标题和一个视觉主体，其余信息放页面正文。

像截图而不像入口

直接截取首屏，字体小、界面密、品牌重点不明确。修复：从页面中提炼一个动作或结果，重新编排成海报。

品牌色失控

同时使用多个高饱和颜色，导致产品类别和视觉气质不清楚。修复：主色、辅助色和强调色分层。

只在本地看过

设计稿在大屏清晰，但平台压缩或移动端裁切后不可读。修复：用真实分享链接或预览工具检查。

适合场景的模板选择

场景推荐结构避免
新产品发布产品名加核心承诺加单一主视觉把全部功能列表塞进图片
技术教程问题或结果加技术名加简洁示意只放代码截图
版本更新版本号加最大变化加产品界面只写更新了很多功能
设计作品集作品名加视觉主体加统一签名每张作品使用完全不同的品牌语言

发布前验收清单

  • 标题在 320px 左右的移动预览中仍然可读。
  • 关键文字没有贴近边缘，平台裁切后不会丢失。
  • 缩略图状态下仍能区分品牌、产品类别和主视觉。
  • 图片压缩后颜色和文字对比度仍足够。
  • 链接元数据中的标题、摘要和图片地址均可访问。
  • 桌面、移动端和聊天应用预览没有出现旧缓存或错误图片。
  • 图片不包含未经授权的第三方 Logo、人物或艺术作品。

进一步实践：建立自己的 OG 设计系统

看画廊的最终目的不是复制某一张图，而是总结一套可持续的规则。建议建立一个小型资产库：记录每次发布的图片、标题、平台、点击表现和复盘结论。一个月后回看，你会知道哪些标题长度更稳、哪些色彩在移动端更清晰、哪些视觉主体能带来更高的点击意愿。

  review-log.csv    # 日期、平台、版本、结果、改进点
