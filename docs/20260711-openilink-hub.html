01 / background
ClawBot / iLink 协议
2026 年 3 月的变化
微信推出 ClawBot 插件，底层是 iLink（智联）协议。这意味着程序化收发微信消息第一次拥有了官方可用的原始通道，但协议本身仍然只是“底层管道”，不是完整平台。
Hub 解决什么问题
把 context_token、消息追踪、窗口提醒、多 Bot 管理、跨平台分发和应用扩展统一封装，避免每个接入方都重新造轮子。
产品定位
不是单纯的 SDK，也不是一次性脚本，而是一个面向微信消息场景的 开源消息管理平台：后台、市场、SDK、服务发现、回调、自动回复一并提供。

02 / value
核心价值
Self-hosted
默认 SQLite，开箱即用；需要更强能力时可以切 PostgreSQL。部署在你自己的服务器，数据、权限、密钥和日志都在你手里。
App 市场
市场化扩展是它的核心卖点：飞书、Slack、GitHub、Notion、天气、记账、提醒、RSS 等 App 都能一键启用。
平台互通
不仅微信收发消息，还能把消息流、通知流、AI Tools 和第三方平台串起来，形成“微信 ↔ SaaS ↔ 本地服务”的互通层。
消息中枢 多 Bot 管理 App Registry Webhook / WebSocket / AI 一键扩展

05 / deploy
Docker 一键部署 · 9800 端口
Quick Start 
# 一键安装（Linux / macOS）
curl -fsSL https://raw.githubusercontent.com/openilink/openilink-hub/main/install.sh | sh

# 启动 CLI
oih

# Docker 一键部署（默认 9800 端口）
docker run -d -p 9800:9800 openilink/openilink-hub:latest
http://localhost:9800 第一个注册者自动管理员 SQLite 默认 可切 PostgreSQL
文档强调：默认用 SQLite，不用先装数据库；如果需要更强的持久化或现有基础设施集成，可通过 `DATABASE_URL` 切到 PostgreSQL。
06 / security
安全特性
Passkey / WebAuthn
支持 Passkey 登录，适合减少密码暴露面，并给管理后台提供更现代的身份验证体验。
SQLite 默认
默认数据库是 SQLite，单机零配置即可起步，降低了试用和私有部署门槛。
数据自控
所有消息、授权和 App 连接都可以自托管；你掌握存储位置、访问边界与迁移路径，而不是把状态散落在脚本里。
07 / compare
vs 传统微信自动化
维度 OpeniLink Hub 传统微信自动化
核心定位 平台化 消息管理中枢 + App 市场 脚本化 / 点对点自动化
扩展方式 标准 App 机制 + 7 种 SDK 手工接代码、改脚本、自己维护 glue code
互通能力 微信 ↔ 飞书 / Slack / Discord / 钉钉 / 企业微信 通常围绕单个业务场景展开
部署形态 Self-hosted，Docker 一键启动，默认 9800 端口 单机脚本、定时任务、临时进程
安全与控制 Passkey、SQLite 默认、数据自控、可切 PostgreSQL 状态分散、权限和数据边界常靠约定
维护成本 市场化复用、统一后台、统一日志与追踪 每个需求都重新接一次
