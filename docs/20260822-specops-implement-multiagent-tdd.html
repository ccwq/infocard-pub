Agent Team

6 个角色构成的开发机器

Lead 总指挥 Agent

读 spec.md、分解任务、协调一切。从不写代码，只做决策和调度。

"我从不写代码。我只读 spec，决定做什么，分配给谁。"

Explorer 代码库勘探 Agent

扫描代码库，报告模式、约定、集成点、依赖关系。为 Teammate 提供上下文。

"我来摸清代码库的脾性，告诉 Teammate 哪里能动，哪里不能动。"

Teammate TDD 执行 Agent（×N）

按 RED-GREEN-REFACTOR 干活：先写失败测试，再写实现代码，再重构。非阻塞任务并行执行。

"测试先行，实现次之，重构最后。我不能给自己写评价。"

Reviewer 两阶段验证 Agent

Stage 1：spec compliance——是否符合 plan。Stage 2：code quality——代码健康度。两者互相抓不同的 bug。

"第一阶段看对不对，第二阶段看好不好。两把刀，缺一不可。"

Fixer 问题修复 Agent

接收 Reviewer 发现的问题，逐一修复，然后重审。修复后再次提交 Review 闭环。

"我修一个问题，Reviewer 重新审一个问题，直到全部 green。"

Verify 集成验证

全量测试 + lint + 类型检查。所有 agent commit 后执行，确保整体可集成。

"每个人都说自己好了，最后我来跑全套验证。"

TDD Discipline

RED → GREEN → REFACTOR → 循环

RED 写一个失败测试 Teammate 先写测试
功能代码不存在
GREEN 让测试通过 用最小代码通过测试
不求完美，只求可用
REFACTOR 改善代码结构 测试保持 green
逐步消除重复
VERIFY 集成验证 全量测试 + lint
+ 类型检查

Use Cases

适用场景

复杂多文件功能

跨越多个文件、模块、边界的功能实现，需要 Explorer 预先扫描代码库拓扑。

长程任务

传统 agent 跑久了 context 膨胀、质量下降。specops 每个 agent 独立 session，维持质量。

多人协作代码库

需要遵守既有约定、集成点、测试规范的新功能，Explorer 确保不破坏现有结构。

TDD 纪律要求高的项目

强制 RED→GREEN，Reviewer 两阶段验证，确保测试覆盖率和不退化。

Usage Flow

完整使用流程

1
/interview
结构化提问 → 采集需求 → 生成 specs/<name>/spec.md
2
/implement
启动 agent team → Lead 读 spec → Explorer 扫描 → Teammate TDD → Reviewer 两阶段验证
3
RED-GREEN-REFACTOR
Teammate 强制 RED 先写测试 → 实现通过 → 重构优化，循环直到所有测试 green
4
Fixer 修复闭环
Reviewer 发现问题 → Fixer 逐一修复 → 重新 Review → 全部 green 后进入集成验证
5
集成验证
全量测试 + lint + 类型检查 → 通过后 agent team 汇报结果 → 你回来看完成结果
