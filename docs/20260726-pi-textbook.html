沿 15 个可运行 checkpoint，从一条离线 Agent 轨迹出发，亲手实现完整 Pi-style coding agent。

本课程将 Agent 工程拆解为一条清晰的技术链路：从 TypeScript 协议定义、流式模型接入、Provider 适配器，到工具调用、Agent Loop、会话树、Context Compaction、资源扩展，最后用独立评测验证全流程。每章由四部分闭环——教材正文 + 真实 commit + 聚焦测试 + 故障实验——课程代码不是伪代码，而是一条可以 checkout、运行和验证的 Git 历史。

02
Checkpoints 速览

15 个 Checkpoint 完整路径

从离线路径（CP 00）到完整 Pi-style agent（CP 14），沿同一 Agent 执行链逐层推进

部分 CP 章节 核心内容 阅读
序章 00 一次 README 读取走完 Agent 闭环 跟随一次 README 请求，把用户消息、两次模型调用、工具调用与结果、最终回答连成完整闭环 打开 →
I · 模型与协议 01 TypeScript 生存集 四个 DemoEvent 串起联合类型、运行时校验、Promise 与 ESM 测试 打开 →
02 EventStream 实现 EventStream，让事件先到与消费者先等两种时序都能交付过程项和最终结果 打开 →
03 消息 IR 把文本、工具调用和配对结果保存为统一消息，并从模型事件收束出完整 assistant message 打开 →
04 ScriptedModel 实现可重复播放预设回合的 ScriptedModel，保存请求快照并投影稳定事件流 打开 →
05 Provider 适配器 把课程消息写成 Provider 请求，再将 SSE 响应还原为统一模型事件 打开 →
II · 工具与循环 06 工具调用 让 echo 调用经过 schema、Registry 和 executor，返回沿用原 call id 的工具结果 打开 →
07 Agent Loop 实现两轮 Agent Loop：模型提出 read，工具结果写回后再生成最终回答 打开 →
08 编码工具 让 read、write、edit、bash 在同一 workspace 内完成受控的文件与进程操作 打开 →
III · 状态与历史 09 有状态 Agent 让同一个 Agent 保存跨运行消息，并管理订阅、取消、运行中指令、follow-up 与重入 打开 →
10 Session 树 把完成消息追加为带父指针的 JSONL 记录，再从指定叶子恢复当前对话路径 打开 →
11 Context Compaction 按完整工具交互切分历史，在 token 预算内保留后缀，并用结构化摘要补回早期事实 打开 →
IV · 扩展与验证 12 资源与扩展 发现项目规则、Skill 与模板，按需送入上下文，并让可信扩展原子注册工具与 hooks 打开 →
13 Runtime 组合 把 Agent、Session Store、上下文、资源与扩展接成 Runtime，让 prompt 在新消息被接受后完成 打开 →
14 评测 capstone 用全新 fixture 运行 Runtime，核对活动路径与文件结果，再输出稳定的分类和计数 打开 →
