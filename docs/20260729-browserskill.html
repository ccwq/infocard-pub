01
PROBLEM BACKGROUND

问题背景：headless 无登录态的痛点

现有的 agent 浏览器自动化方案都绕不开这两个障碍。

痛点 A

headless Chromium 无登录态

headless 模式是干净的浏览器环境，但所有登录 Cookie、Session Token 都不存在。agent 面对的是"未登录版"网页，很多功能根本不可用。

  • 无法访问需要登录的内容
  • 需要重新走一遍登录流程
  • 验证码、多因素认证难以绕过
痛点 B

Playwright 独立配置繁琐

Playwright 是强大的浏览器自动化工具，但每次新建项目都要：装浏览器、配置 launch参数、管理 context，agent 无法直接复用你已有的浏览器环境。

  • 配置与你的浏览器完全隔离
  • 无法复用已有的登录状态
  • 多 agent 场景下资源重复占用
02
SOLUTION ARCHITECTURE

解法架构：bsk CLI + daemon + 扩展隔离

BrowserSkill 的核心设计——让 agent 操作你已经在用的真实浏览器。

组件 1

bsk CLI

命令行工具，agent 通过它向本地 daemon 发送指令。不绑定任何模型或框架，所有 shell-capable agent 通用。

  • 一条命令安装：bsk install-skill
  • 通过 stdin/stdout 与 agent 通信
  • 轻量，无额外依赖
组件 2

本地 Daemon

常驻后台服务，接收 bsk CLI 请求、路由到正确的浏览器 tab。运行在用户本地，与浏览器扩展通信。

  • 保持浏览器环境完整性
  • 管理 agent 与浏览器间的消息
  • 支持多 agent 并发请求
组件 3

浏览器扩展 + Agent Window

扩展在浏览器中开辟隔离的 Agent Window，执行来自 daemon 的指令。隔离执行意味着：不影响你正常浏览的标签页。

  • 扩展安装到你的真实浏览器
  • Agent Window 完全隔离
  • 登录态、Cookie 全部保留

04
INSTALLATION & USE CASES

安装命令与使用场景

一条命令完成安装，多种场景无缝切入。

// 安装命令
# 一条命令安装 BrowserSkill
bsk install-skill

# 验证安装
bsk doctor
场景 1

社交媒体管理

agent 以你的身份操作 Twitter/X、小红书、LinkedIn，保留真实登录态，自动发布、回复、采集数据。

场景 2

Web 应用测试

在真实浏览器环境中测试需要登录的 Web 应用，agent 自动执行端到端测试流程，无需重复登录。

场景 3

数据采集与爬虫

突破需要登录才能访问的数据页面，agent 在你的真实浏览器中导航、提取、汇总数据。

场景 4

自动化工作流

将重复性的网页操作（填表、审批、配置）交给 agent，真实浏览器环境确保所有前置条件满足。

场景 5

研究与调查

agent 帮你浏览需要登录的资讯平台、数据库、学术网站，整理信息、生成报告。

场景 6

多平台同步发布

一次操作，多平台同步——agent 在你的真实浏览器中逐一登录各平台，执行发布或更新。
