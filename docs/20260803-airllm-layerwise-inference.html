AirLLM：4GB显存跑 2.8万亿参数模型

不量化、不蒸馏、不剪枝——通过分层推理（Layer-wise Inference）与按专家加载（Per-Expert Streaming），把显存需求与模型总参数量解耦。Kimi K3 在 3.72GB 显存中稳定运行。

核心逻辑：显存瓶颈不在模型大小，而在「一次加载多少」

推理时显存只保留当前一层的权重，用完即释放，下一层从磁盘动态加载。MoE 模型进一步按专家流式加载——每次只把 token 真正路由到的专家调入显存。

分层推理 Per-Expert Streaming 预取 v2.5 块级量化可选
显存需求由「单层参数大小」决定，而非「模型总参数量」——这是 AirLLM 与量化/蒸馏路线的本质区别。

传统大模型推理对显存的要求遵循简单逻辑：参数越多，显存越大。Llama 3.1 405B 全精度加载需超过 800GB 显存，即便 INT4 量化也需约 60–80GB，将绝大多数个人用户和研究机构拒之门外。AirLLM 作者 Gavin Li（高辉）从另一角度切入：显存瓶颈的本质不在于模型有多大，而在于一次把多少参数加载进显存。结合 MoE 稀疏架构「每个 token 只激活少数专家」的特性，AirLLM 实现了参数规模与显存需求的解耦——2.8 万亿参数的 Kimi K3，单卡 3.72GB 即可推理。

01
CORE MECHANISM

两大核心机制：分层推理 + 按专家加载

AirLLM 不依赖量化、蒸馏或模型剪枝，是原汁原味模型权重的推理结果。

机制 1Layer-wise

分层权重拆分

首次加载时，把 Hugging Face 格式的模型按层拆分为独立权重文件，写入缓存目录。拆分后的单层权重远小于完整模型。

  • 按层独立存储
  • 单层权重 ≪ 完整模型
机制 2Dynamic Load

动态按需加载

推理以前馈方式逐层处理 token。第 N 层完成计算后权重立即释放，第 N+1 层从磁盘加载，任意时刻显存只保留一层参数。

  • 算完即释放
  • 磁盘 ⇄ 显存流转
机制 3Per-Expert

按专家加载（MoE）

对 MoE 模型，每次只把 token 真正路由到的专家调入显存，而非整个层。稀疏激活使单次推理调用参数仅占总量的极小部分。

  • 只加载激活专家
  • 稀疏 MoE 架构红利

代表性模型显存占用对照

全部为未量化权重推理。显存需求与参数量不再线性相关——MoE 模型尤甚。

03
IMPLEMENTATION

技术实现：分层加载 + 预取并行

磁盘 I/O 成为新瓶颈后，AirLLM 用预取把等待时间藏进计算时间。

拆分

分层权重拆分

Hugging Face 格式模型按层拆为独立权重文件写入缓存，单层权重远小于完整模型。

加载

动态按需加载

第 N 层算完即释放，第 N+1 层从磁盘加载；任意时刻显存只保留一层参数。

预取

预取机制（v2.5）

当前层计算时异步预加载下一层，I/O 与计算重叠，实测约 10% 速度提升。

可选

块级量化

4bit/8bit 压缩存储阶段权重而非激活值，几乎不损失精度，进一步减少数据搬运。

04
KIMI K3 NOTES

Kimi K3 专项：实践中的关键细节

2.8 万亿参数开源模型的运行环境有若干特殊要求，官方文档专门标注。

依赖必装

额外依赖

必须安装：pip install compressed-tensors flash-attn。K3 模型代码强制要求 Flash Attention，无论是否显式请求。

版本

CUDA / Transformers 限制

flash-attn 当前仅提供 CUDA 12 预编译 wheel，CUDA 13 用户需源码编译或切换环境。K3 remote code 在 transformers 5.x 下无法加载，需 4.56.x。

实测数据 RTX 6000 Ada
单张 NVIDIA RTX 6000 Ada（48GB 显存）端到端实测：Kimi K3 的 VRAM 占用稳定在 3.72GB——比参数量仅为其千分之一的 Llama 3 8B 还要低。
05
CODE

一行加载任意大模型

核心接口统一为 AutoModel.from_pretrained()，适配主流架构。

// Python · AirLLM
from airllm import AutoModel
model = AutoModel.from_pretrained("Qwen/Qwen3-32B")
# Kimi K3
# model = AutoModel.from_pretrained("moonshotai/Kimi-K3")
# DeepSeek-V3
# model = AutoModel.from_pretrained("deepseek-ai/DeepSeek-V3")
input_text = ['What is the capital of United States?']
input_tokens = model.tokenizer(input_text, return_tensors="pt", return_attention_mask=False, truncation=True, max_length=128, padding=False)
generation_output = model.generate(input_tokens['input_ids'].cuda(), max_new_tokens=20, use_cache=True, return_dict_in_generate=True)
print(model.tokenizer.decode(generation_output.sequences[0]))
覆盖架构：Llama、Qwen、DeepSeek、Mistral、Phi、Gemma、ChatGLM、Baichuan、InternLM 等主流架构均已覆盖。
06
SECURITY VIEW

对安全行业的启示

从蓝队视角审视，AirLLM 带来两个层面的思考。

1

本地化推理的安全价值

大模型可在消费级硬件本地运行，金融、医疗、政府等数据敏感行业无需上传第三方 API 即可获得强大推理能力；私有化部署门槛大幅降低，数据泄露风险减少。

2

威胁检测的新战场

恶意软件作者可能利用本地大模型自动化生成钓鱼邮件、恶意代码或社会工程攻击。安全团队需为 AI 辅助攻击（AI-Assisted Attack）新范式准备检测规则与响应预案。

3

边界提示

本地推理解决「显存」与「隐私」，但速度、吞吐与多用户并发仍受磁盘 I/O 约束；生产环境需按场景权衡本地 vs 云端。
