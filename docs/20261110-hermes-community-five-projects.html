AG雷达 · Hermes 社区项目盘点

五个 Hermes 社区项目，
装哪个、先查什么

同一份推文点名了五个方向不同的项目：查账单、组开发队、回复出图、桌面机器人、手机客户端。每个的安装路径、版本门槛和数据边界都不一样，装之前逐项核对，比装完再卸省事。

  • 先对版本门槛：GenUI 与 Alado 都要求 Hermes Agent ≥ 0.22.5；SpendSense 的插件 manifest 写同一条，作者注明对更新版本的兼容待验证。
  • 形态不同：SpendSense 和 GenUI 是插件，fleet-apps 是复制进 profile 的角色模板，Nous-Girl 是机器人固件，Alado 是装在你服务器上的 PWA。
  • 数据边界各有口径：SpendSense 只记记账元数据、不上传；GenUI 抓图仅限 https 公网地址；Alado 手机端不存任何秘密。
  • 三处明示未验证：SpendSense 的新版兼容、fleet-apps 的非 Windows/Python 平台、Nous-Girl 在他人硬件上的运行。

采用前查五件事

这五项在 README 里都有答案；查不到本身就是信号。

装在哪里

插件进 Hermes profile；模板进你的多个 profile；固件进机器人；PWA 进你自己的服务器。

要求什么版本

GenUI 与 Alado 明确要求 ≥ 0.22.5；SpendSense manifest 同门槛，更新版待验证；fleet-apps 绑 Hermes Agent profile。

交出什么数据

记账元数据、公网图片请求、语音与摄像头（机器人）、服务器反代——逐项核对去向再放行。

怎样算装好

每个项目都有可观察的成功判据：validate 通过、新聊天出图、ready 音、--check 退出码 0。

许可与溯源

GPL-3.0 / MIT / MIT / MIT / MIT；SpendSense 含 Apache-2.0 上游署名；Nous-Girl 的 tribute 面部素材不在 MIT 内。

使用顺序
查 → 装 → 验

先核版本与平台，再按 README 命令装，最后跑一次验证入口；不过验证就先别扩权限。

可行动速览：关心成本先装 SpendSense（隔离 profile + 备份，validate 通过再用）；要组队先抄 fleet-apps 的 coordinator 和 coder 两个角色；要出图先关 tool search 再装 GenUI；要机器人先确认有 StackChan 硬件和一台能跑 Docker 的电脑；要在手机用先确认有一台 80/443 可达的 Linux 服务器。

01
SPENDSENSE · GPL-3.0 · 59 STARS

用量账单：花了多少、订阅值不值

Hermes 插件。记录用量并在本地计价，把订阅费、预付余额和 API 路由放进同一处对照。README 标注 Early access，正式发布和目录收录未完成。

它记录什么、不记录什么

经 Hermes 观察钩子拿到每次调用的记账元数据：提供方、模型、路由、token 分桶、结果与时间戳。提示词、回复、凭据不记录。无账号、无遥测、无上传；用量存进 profile 级 SQLite，计价先用 Hermes 本地 models.dev 缓存，缺失时用内置离线价目。可选的 Live Updates 默认关闭，开启后才经 HTTPS 拉取公开的模型动态与订阅计划数据。

读数口径也写明了：API 等价价格是比较用的参照价，不是账单；缓存节省是理论对比，缓存写入可能反而产生净成本；无法定价的用量单独标出，不会冒充零。

安装与验证

插件 manifest 要求 Hermes ≥ 0.22.5，作者注明更新版本的兼容尚待验证；建议在隔离 profile 评估，升级前备份插件数据。桌面端在应用内用仓库 URL 安装，目录收录前对话框会警告来源未验证，装前核对仓库地址：

https://github.com/WolfMark-Ltd/spendsense

服务器与无头环境用命令行：

hermes plugins install WolfMark-Ltd/spendsense
hermes plugins enable spend-sense

安装前建议先验证源码树并逐条复查警告：

git clone https://github.com/WolfMark-Ltd/spendsense.git
hermes plugins validate ./spendsense --install-deps

本地优先、不联网同步：多台机器各自记账，账本互不相通。桌面与后端两部分要一起测；来源为 WolfMark Ltd，派生自 AFei（IT-dreamer）的 Token & Cost Meter（Apache-2.0），合并发行采用 GPL-3.0。

spendsense 仓库

订阅判断是它的核心用法。订阅费、提供方报告的用量、API 等价价值和规则推算的消耗四类数字分开呈现，不合并成一个总数；续费、降级、退订前看这四列，比看任何单一仪表盘都有依据。
02
FLEET-APPS · MIT · 角色模板

七人舰队：一个协调员带六个专家

不是插件，是一套可以复制进自己 Hermes profile 的角色模板：每个角色一份 SOUL.md 加自己的 skills，无安装命令。

流程只设两道人工门

想法 → product 写规格 → 你批规格 → designer 出视觉方案 → 你批设计 → coder 带测试实现 → qa 独立检查 → media/docs 出视频与文档 → release。coordinator 只派活、验收和汇报，自己不实现。qa 永远不改代码，只跑构建、复现问题、写问题清单；测试绿了才允许合并。任何对外公开动作（push、打 tag、发帖）和任何凭据，永远停下来等人。

还有几条成文纪律：秘密不进聊天，Agent 只告诉你该填哪个文件哪个变量；项目状态存仓库不存记忆；上下文压缩两次就写交接文档停手，新会话从文件接着干。

采用方式与已验证范围

一个角色一个 Hermes profile，把对应目录里的 SOUL.md 和 skills/ 复制进去；分步说明在 docs/adopt.md，建议从 coordinator 和 coder 起步，下一步再加 qa。角色引用的第三方技能不在仓库里，需按 docs/third-party-skills.md 的清单另行安装。

作者验证过的范围只有一条：Windows 上、用 Python 写的桌面应用、命令行工具和小型本地 Web UI，从想法到安装包发布，单人驱动。macOS、Linux、带服务器或支付的在线服务、移动应用、非 Python 技术栈都没有人测过——README 原话是"角色可能可用，但没人验证"。仓库尚无发布版本。

验证建议：挑一个不太重要的小工具走完整条链，检查两道门是否真的停下等人、qa 是否产出独立的 QA-REPORT.md、合并是否被红测试挡住。

03
HERMES-GENUI · MIT · 23 STARS

生成式 UI：回答不止一段文字

Hermes Desktop 插件。模型按问题从图表、表格、行程、计算器、清单等组件里挑着拼回答；模型决定展示什么，插件决定长什么样。

项目自带示例：三只股票的对比回答渲染成价格卡、趋势线与涨跌图

图片来源：sagarmainkar/hermes-genui 仓库 README 截图（assets/screens/compare.png），仓库采用 MIT 许可。

安装：先关 tool search

需要 Hermes Agent ≥ 0.22.5 加 Hermes Desktop。三步命令加一个开关：

hermes plugins install sagarmainkar/hermes-genui --enable
hermes config set tools.tool_search.enabled off
hermes gateway restart

关 tool search 的原因 README 写得很具体：默认的搜索桥接要求模型把整块 UI 写成转义文本，大板经常失败，出现红色 Unnamed call。代价是每条消息都会带上全部工具定义，token 开销变大——README 建议给这个插件单独开一个 profile。装完在 Desktop 的 Capabilities → Plugins 里选中对应 profile，把插件的 Desktop 开关打开。Hermes 在服务器、Desktop 在笔记本这类分离部署，每台跑 Desktop 的机器都要用 Install from Git 再装一次绘图端。

数据边界与验证

行情数据来自 Yahoo Finance；照片默认来自 Wikimedia Commons 和 Openverse，不填 key 也能用，可选补 Unsplash、Pexels 或 Tavily 的 key（由 Hermes 保管，插件不存）。模型只发送结构化数据，不发送 HTML、脚本或 SVG，组件全部由插件自己渲染；图片仅从 https 公网地址抓取，DNS 固定防重绑定、每跳重定向复查、有大小和时限；计算器公式走无 eval 的小解析器；板的尺寸、深度、文本量和数量都有上限。无遥测、无账号，板子以 JSON 存在本地 profile 里。Telegram 和 CLI 渠道按设计回退为 Markdown 文本。

验证方法：重启 gateway 后开新聊天，问"Compare NVDA, AAPL and MSFT over the past year"看是否出图。出红色 Unnamed call 说明 tool search 没关；提示 Couldn't load this block 就再跑一次 gateway restart；模型作者实测 DeepSeek V4.1 Flash 效果好，本地小模型画大板可能直接回文本，README 的建议是换更强的模型。

NOUS-GIRL · MIT · BETA

桌面机器人：固件在你手里，服务器也在你手里

跑在 M5Stack StackChan K151（CoreS3，ESP32-S3）上的固件 v3.6.7-dj7；语音服务端用 Docker 跑在你自己的电脑上，固件不含内置服务器。

三种大脑，记忆差在哪

方案 A 是 Hermes 加任意模型：长期记忆、联网工具，机器人的表情、视线、跳舞等控制经 stackchan MCP server 下发，难度最高。方案 B 是 Hermes 加本地 Ollama：同样有长期记忆，可以全本地运行。方案 C 只接 Ollama，最简单，但没有记忆——每次对话从头开始。README 的原话是：想让机器人记住你，就需要 Hermes Agent；Hermes 配置与人格文件 SOUL.md 的写法在 docs/HERMES.md。

功能面覆盖表情口型、唤醒词、灯光舞蹈、音乐与 DJ 模式、五语种语音、摄像头识物与人脸跟随、邮件（读回确认后才发送）等；每项的开关与撤销步骤在 docs/FEATURES.md。

上手四步与未验证范围

先备份机器人，再按 VERSIONS.md 烧录固件（发布带 checksum 与回滚步骤）；在你的电脑上用 Docker 启动 xiaozhi-esp32-server 语音服务端并下载模型；机器人配网（热点 Xiaozhi-XXXX，页面 192.168.4.1）；长按屏幕 1.5 秒填服务器地址：

http://<你的电脑IP>:8003/xiaozhi/ota/

成功的判据：播放 ready 提示音且无报错，Settings → Server 显示所填地址，喊"Hey Nous-Girl"能得到应答。语音模型单独下载，其中多语言版 phonon-40m-multilingual 为 CC-BY-NC-4.0 且需接受条款，仅限非商用；英文回退版是 Apache-2.0。

未验证边界：一人维护的业余项目，只在作者自己的机器人上端到端跑通；公共固件虽带校验和回滚，README 明说还没有其他人在别的硬件上试过；服务端链路只有 macOS（Apple Silicon）测过。发日志或照片前，先抹掉 Wi-Fi 名、密码、服务器地址、token 和邮箱。

nous-girl-stackchan 仓库 · SELF-HOSTING.md

硬件与平台前提

需要 StackChan K151 硬件和一台能跑 Docker 的电脑；没有对应硬件时，这个项目只能读文档。

许可分层

代码与文档 MIT；三张 CC0 起始面部可自由使用；faces/tribute/ 下的致敬画作明确排除在 MIT 外；各模型与服务端组件另有自己的条款。

语音与摄像头

语音识别、合成在本地电脑运行；摄像头识物、人脸跟随经本地模型处理。开哪项功能，先看 docs/SETTINGS.md 里对应的默认值。

ALADO · MIT · 14 STARS

口袋客户端：把 Hermes 装进手机主屏

连接你自托管 Hermes 服务器的手机 PWA：聊天、群组、审批、推送、语音和例行任务在第一层，重度功能收在下一层。

安装：一条脚本管到底

前提：一台 Linux 服务器（Ubuntu 22.04/24.04 或 Debian 12/13）、sudo 权限、80/443 可达；作者在全新 Ubuntu 24.04 加 Hermes v0.22.5 上端到端测试过。

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
git clone https://github.com/gabogabucho/hermes-alado && cd hermes-alado
sudo bash provisioner/prepare.sh --all --domain your.domain

没有域名就换 --access sslip（公网 IP）或 --access tailscale。脚本先让你创建手机登录账号（密码只存哈希），然后无人值守完成：配置浏览器与桌面、以仅本机回环方式跑 hermes serve 并置于 Caddy 之后、签 HTTPS 证书、装推送插件和 alado-companion 技能、重启 Hermes。手机打开脚本输出的 URL 登录，加到主屏幕即可。

更新是 git pull 后重跑同一条脚本；发布包自动下载并校验，bot 改进过的技能不会被覆盖。

安全模型与验证

手机上不存秘密：会话 token 只在内存里，本地留的只有后端地址、主题、语言和 bot 名称头像缓存；客户端没有任何读取服务器环境变量的调用。登录凭据只走 Hermes 自带的 browser vault 流程——bot 打开页面，Alado 弹安全表单，vault 负责填入，bot 和聊天记录里都看不到密码。PWA 经同源 Caddy 反代访问 Hermes 网关，无第三方服务；任何公网暴露都要求配置 dashboard 认证，没配时 provisioner 会警告且 Hermes 默认拒绝。

验证方法：装完跑 sudo bash provisioner/prepare.sh --check，只读诊断所有模块，退出码 0 表示全部正常。开发侧另有 vitest 测试、tsc 类型检查和 oxlint。

边界与行动

装之前，把顺序走对

五个项目都是活跃的社区作品，更新快、口径以各自仓库为准。

01 · 对门槛

03 · 单个装、跑验证

04 · 再给权限
确认数据去向与凭据边界后，再扩大任务范围
