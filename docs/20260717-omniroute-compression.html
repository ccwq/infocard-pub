核心定位句

OmniRoute 在请求到达上游提供商前自动压缩上下文。节省比例取决于模式、内容类型和上游基准，非固定承诺。

双层决策：先选场景 → 再选模式 用户可配置 / 内部引擎只"了解即可"
01
决策总览 · 双层决策树

先识别场景 → 再匹配模式

所有 7 种模式按两个维度排列：内容类型（对话 / 工具输出 / 混合）+ 目标（安全 / 平衡 / 最大节省）。

你的会话类型 典型内容 推荐模式入口 节省量级 风险
普通对话 问答、头脑风暴、写作 Lite → Standard 15–30% 低
代码工具输出 git/build/test/shell 日志 RTK → Stacked 60–95% 中
混合上下文 对话 + 工具输出交叉 Stacked（RTK→Caveman） 78–95% 中
长会话 多轮对话、项目回顾 Aggressive → Ultra 50–75% 中高
上下文紧张 触达模型上下文上限 Ultra → Stacked 75–95% 高
调试 / 审计 需保留原始输出、精确复现 Off → Lite + Raw Output 0–15% 无
安全优先Always-On

Lite 模式

零语义变更，仅格式化清理。可作为默认全局设置。

  • 合并空白行、去除尾随空格
  • 去重系统提示词
  • 压缩工具结果中的冗余
  • <1ms 延迟增加
平衡Caveman

Standard 模式

去除填充词、冗长措辞，保持代码块 / URL / JSON 完整。

  • 去除 "please / actually / basically"
  • 30+ 正则规则针对编码提示词调优
  • 保留结构化数据和路径
最大节省RTK

Stacked 模式

RTK 先压工具输出，Caveman 再压剩余自然语言，叠加节省。

  • 公式：1-(1-RTK)×(1-Caveman)
  • 默认流水线：RTK → Caveman
  • 适合工具日志 + 人类指令混合
数字来源说明 官方标注的节省比例来自上游项目基准和 OmniRoute 组合计算：RTK 上游样本 ~80%（118,000→23,900 tokens）；Caveman 上游样本平均 ~46% 输入压缩；Stacked 为两者乘积区间 78–95%。实际节省取决于内容类型，不是固定承诺。

七种模式 · 原理 · 适用 · 代价

七种压缩模式详解

Off 到 Stacked，覆盖零干预到最大压缩的完整光谱。内部引擎 CCR/Headroom/Ionizer/Session Dedup/LLMLingua-2 仅供参考了解，不开放用户配置入口。

模式 引擎 原理 适用场景 节省量级 风险 操作入口
Off 无 完全不动，原样传递 调试、审计、需要精确复现 0% 无 Dashboard → Context & Cache → 全局设置
Lite Caveman 辅助 空白/格式清理，零语义变更 Always-On 安全模式 ~15% 低 Dashboard → Context & Cache → Caveman
Standard Caveman 去除填充词、冗长措辞、礼貌性绕圈 日常编码、对话、写作 ~30% 中低 Dashboard → Context & Cache → Caveman
Aggressive Caveman + 历史摘要 消息老化 + 工具结果摘要 + 上下文窗口感知 长会话、扩展调试、大型代码库 ~50% 中 Dashboard → Context & Cache → Caveman
Ultra Caveman + 剪枝辅助 启发式剪枝 + 代码块精简 + 二分截断找最优切点 反复触及上下文上限 ~75% 高 Dashboard → Context & Cache → Caveman
RTK RTK 命令感知过滤器：识别 git/build/test/shell 输出，去除 ANSI/进度条/重复行 Agent 会话含大量终端/工具日志 60–90% 中 Dashboard → Context & Cache → RTK
Stacked RTK → Caveman RTK 先压工具输出（60–90%），Caveman 再压剩余自然语言（~30%） 工具日志 + 人类指令混合，最大节省 78–95% 高 Combo 配置 + Compression Combos
了解即可 以下内部引擎不开放用户配置入口，仅作概念了解

CCR（Content-Compress-Retrieve）

大块重复文本用内容寻址引用替换，只发一次，后续引用。内部 H4 级别实现。

Headroom（SmartCrusher）

同类 JSON 数组列式压缩为 [N rows] 格式，H3+N5 级别实现。

Ionizer / Session Dedup

Ionizer 对大均匀块进行首/中/尾采样；Session Dedup 跨会话轮次去重。内部实现。

LLMLingua-2（语义剪枝）

小 ONNX token 分类器做语义剪枝，需 co-locate 可选依赖否则 fail-open。

03
场景决策 · 六种典型场景

按场景选择压缩模式

每个场景给出"默认推荐"和"激进选项"，并标注关键参数。

普通对话Q&A / 写作 / 头脑风暴

默认：Standard  |  激进：Aggressive

日常对话、问答和写作。Lite 可作为零风险默认，但 Standard 能在几乎无损的情况下多省 15%。

  • Dashboard → Context & Cache → Caveman → 模式选 Standard
  • 语言包：en / es / id / pt-BR 完整；de / fr / ja 仅有 context+filler+structural
  • 注意：de/fr/ja 的 ultra 强度等同于 full（无 dedup/ultra 规则）
代码工具输出git / build / test / shell

默认：RTK  |  激进：Stacked

Agent 会话含大量终端 / 构建 / 测试输出。RTK 用 49 个内置过滤器处理已知命令类。

  • Dashboard → Context & Cache → RTK → 模式选 RTK 或 Stacked
  • RTK 默认流水线：stripAnsi → filterStderr → replace → matchOutput → drop/include → truncate
  • 保留：错误类型、失败信息、摘要行、变更文件、尾部上下文
混合上下文对话 + 工具输出交叉

默认：Stacked（RTK→Caveman）

工具输出和人类指令交替出现时，Stacked 先压机器输出再压人类语言，乘积节省。

  • 在 Combo 的 compressionOverride 中设置 modePack: "stacked"
  • 或通过 Compression Combos 分配给路由 Combo
  • 公式：1-(1-RTK省省)×(1-Caveman省省)，范围 78–95%
长会话多轮对话 / 项目回顾

默认：Aggressive  |  激进：Ultra

Progressive Aging 按轮次老化：最近 3 轮完整，4–8 轮轻压，9–20 轮 Caveman，21+ 轮重度摘要或丢弃。

  • Dashboard → Context & Cache → Caveman → Aggressive 或 Ultra
  • Aggressive：包含消息老化、工具结果摘要、结构完整性保护
  • Ultra：额外启发式剪枝 + 代码块精简 + 二分截断
上下文紧张触及上下文上限

默认：Ultra  |  最大：Stacked

反复触发上下文上限时，Ultra 用启发式剪枝 + 二分截断找最优切点。仍不够时切换 Stacked。

  • Dashboard → Context & Cache → Caveman → Ultra
  • Ultra 包含 Aggressive 全部功能
  • 配合 Combo 的 compressionOverride 指定 stackedPipelines
调试 / 审计保留原始输出

默认：Off  |  轻量：Lite + Raw Output

需要精确复现原始输出或审计时，关闭压缩或只开 Lite。配合 Raw Output Recovery 保留原始数据。

  • 全局关闭：Dashboard → Context & Cache → 全局设置 → Off
  • Raw Output：在 Combo config 中设 rawOutput.enabled: true, maxBytes: 1048576
  • 恢复原始数据：通过 API /api/context/rtk/raw-output/[id]（需管理认证）
  • 注意：Raw Output 默认关闭，每天 1000 请求时存储 50–500MB/天，建议仅调试时开启

RTK / Caveman · 可操作参数

两大核心引擎的可配置参数

RTK 和 Caveman 是唯一开放用户配置的引擎。以下是每个引擎的主要可操作参数及其默认值。

RTK

RTK 引擎可操作参数

参数 默认值 说明
intensity "standard" 强度级别：minimal / standard / aggressive。aggressive 下仍保留错误和堆栈。
enableGrouping false 对相似行分组压缩，默认关闭以避免误判。
deduplicateThreshold 3 引擎级去重阈值，≥3 行相同连续行时折叠为 1 行。范围 2–100。
customFiltersEnabled true 是否加载用户/项目自定义过滤器。
trustProjectFilters false 信任项目过滤器（需 SHA-256 trust.json 或环境变量）。
rawOutput.enabled false 存储原始输出供后续恢复。调试专用，每天 1000 请求约 50–500MB。
rawOutput.maxBytes 1048576 单次原始输出存储上限，默认 1MB。
Caveman

Caveman 引擎可操作参数

参数 默认值 说明
mode "standard" 模式：off / lite / standard / aggressive / ultra。
languagePack "en" 语言包：en / es / id / pt-BR 完整；de / fr / ja 部分。
skipSystemPrompt true 跳过系统提示词压缩。
deterministicOnly true 仅使用确定性规则（非 LLM 辅助）。
outputMode "auto" 输出模式（caveman / auto），通过 Combo config 设置。
RTK 内置过滤器 49 个内置过滤器覆盖 8 大类别
类别 覆盖命令 / 输出类型 操作要点

testVitest / Jest / Pytest / Playwright / Go / Cargo保留失败用例，裁剪通过用例
buildTypeScript / ESLint / Biome / Prettier / Vite / Webpack保留错误和警告，裁剪进度条和编译详情
packagenpm install / audit / pip / uv / Poetry / Bundler保留安全警告，裁剪下载进度

全局设置 · Combo Override · 预览统计

全局设置、Combo Override 与预览回滚

全局设置是默认行为；Combo Override 让每个路由组合有自己的压缩策略；预览统计用于实时调参。

全局设置

全局压缩设置

OmniRoute 在请求到达上游前决定压缩模式，优先级：

  1. Combo Override → 使用 Combo 专属设置
  2. Auto-Trigger 阈值 → 使用自动模式
  3. 全局设置 → 使用默认模式
  4. Off → 跳过压缩

操作入口：Dashboard → Context & Cache 或 API /api/settings/compression

Combo Override

路由 Combo 专属压缩

每个路由 Combo 可指定独立的压缩模式、RTK 配置和保留规则。

JSON 配置示例 
{
  "id": "coding-combo",
  "strategy": "priority",
  "compressionOverride": {
    "mode": "aggressive",
    "stackedPipelines": ["rtk", "caveman"],
    "preserveToolDefinitions": true
  }
}
预览 / 统计 / 回滚

预览、统计与 Raw Output 回滚

预览：通过 /api/compression/preview 或 Dashboard Playground 测试任意模式效果。

统计：Dashboard → Context & Cache → Compression Combos 查看节省量、引擎分解、每模式 Token 节省。

Raw Output Recovery：开启 rawOutput.enabled: true 后，原始输出按 request_id 存储，通过 API /api/context/rtk/raw-output/[id] 恢复（需管理认证）。

已知限制

  • LLMLingua-2 依赖 co-locate：需 @atjsh/llmlingua-2 共置到 dist/node_modules，否则 fail-open 返回原文
  • de/fr/ja 语言包不完整：缺少 dedup.json 和 ultra.json，ultra 强度等同于 full
  • Stacked telemetry 盲区：0% 节省的引擎步骤返回 stats:null，无法区分"运行了但无节省"和"跳过了"
  • Raw Output 存储成本：开启后每 1000 请求/天约 50–500MB，建议仅调试期间启用

收口说明

OmniRoute Token 压缩通过 7 种模式（Off→Lite→Standard→Aggressive→Ultra→RTK→Stacked）覆盖从零干预到最大压缩的全场景。双层决策：先识别会话类型，再匹配模式强度。RTK 和 Caveman 是唯一开放用户配置的引擎；其他 CCR/Headroom/Ionizer/Session Dedup/LLMLingua-2 为内部实现，"了解即可"。所有节省数字均标注上游基准来源，不承诺固定收益。

  • 安全优先 → Lite / Standard；最大节省 → RTK / Stacked；调试审计 → Off + Raw Output
  • RTK 支持自定义过滤器（需 trust.json 或环境变量）和 Raw Output 恢复（需管理认证）
  • Stacked 默认流水线 RTK→Caveman，乘积节省 78–95%（基于上游基准的组合计算）
