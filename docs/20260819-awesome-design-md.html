一句话

把「描述设计系统」这件事，从每次对话的提示词，挪成一个仓库里可以反复引用的文件。

01

打开这张卡，先跑这三行

下面命令在本地终端执行。仓库是纯文档仓库，没有构建步骤，克隆下来就能读。

# 克隆并进入仓库 git clone https://github.com/VoltAgent/awesome-design-md.git cd awesome-design-md # 看 design-md/ 下有哪些站点目录 ls design-md/ # 看某个站点目录里有什么文件 ls design-md/linear.app/

↑ 第 2、3 行就是本卡的第一个动作

不用 npm install，没有依赖 → 读文件就够

02

核心机制：靠什么做到

靠的是把设计系统从「参考图 + 口头描述」换成 可被模型直接读取的纯文本 token 规范。

  • 按站点分目录。design-md/ 下以站点名分目录（linear.app、notion、vercel、airbnb、github、stripe 等数十家），每份文件写该站点的 design token 与使用规则。
  • token 覆盖四类。每个文件含 color / typography / spacing / elevation 等 design token，以及这些 token 该怎么用的规则。
  • 纯文本进上下文。规范写成 .md，Agent 直接读文件，不需要解析截图、组件源码或设计工具导出。
  • 面向工具链。用途是把 DESIGN.md 喂给 Claude Code、Cursor、v0 等 Agent，让它生成风格统一的界面，不用每次重新描述设计系统。

关键在「使用规则」，不是只有色号

03

可执行步骤：查看 / 安装 / 配置

三步分开做：先把文件看清楚，再决定要不要复制进自己的项目，最后按工具约定挂到规则里。

查看 — 先确认这份规范写了你关心的东西

# 列出全部 DESIGN.md 文件 find design-md -name '*.md' | sort # 读某一份规范的前 60 行 head -n 60 design-md/linear.app/*.md # 只看这个站点提供了哪些 token 类别 grep -E '^(#|##)' design-md/linear.app/*.md

安装 — 把选中的规范放进自己的项目根目录

# 复制成项目根目录的 DESIGN.md cp design-md/linear.app/*.md ./DESIGN.md # 确认它确实落在项目里 head -n 5 ./DESIGN.md

配置 — 按各工具的约定让它每次都被读到

# Claude Code：项目根 CLAUDE.md 里显式引用 printf '设计规范见 DESIGN.md，生成界面前先读取并遵循。\n' >> CLAUDE.md # Cursor：放进 .cursor/rules/ 并写清触发场景 mkdir -p .cursor/rules cp ./DESIGN.md .cursor/rules/design.md # v0：生成前把 DESIGN.md 作为附件/上下文贴给它

Cursor 的 .cursor/rules/ 与 Claude Code 的 CLAUDE.md 是这两个工具各自的约定，不是本仓库提供的能力。

引用比复制更重要 规范会更新，引用就不失效

04

预期现象：执行后看到什么

  • 目录层面：ls design-md/ 返回数十个以站点命名的目录，和 README 里能看到的站点列表对得上。
  • 文件层面：每个站点目录下是纯文本 .md，打开后能读到具体色值、字阶、间距与层级规则，不是链接跳转到官网。
  • 生成层面：让 Agent 按这份规范出界面，配色和字阶第一次就对得上那套设计系统，不必逐个组件返工。
  • 换风格层面：把 DESIGN.md 换成另一家站点的版本，产出的界面风格跟着换，提示词不用重写。
  • 不用重复讲的层面：后续改页面时不再需要「圆角用 8px、正文 14px/1.6」这类口头约定，文件里已经写了。

「不用每次重新描述」是这个仓库的卖点 覆盖 60+ 设计系统（作者观点）

「60+」来自推文作者口径，不是仓库官方数字；官方可核的是站点目录的实际数量。

05

已知限制与边界

把它当规范快照，不要当实现

  • 不含组件代码。只有 design token 与使用规则，没有可安装的组件库，也没有交互状态、动效、无障碍实现。
  • 是静态快照。站点视觉更新后文件不会自动跟着变；本卡数据取自 2026-10-14 的仓库快照。
  • 非官方规范。内容依据站点公开可见的视觉特征整理，与各公司内部设计系统的真实取值可能有出入。
  • 风格上限受 Agent 决定。规范约束 token 与规则，最终产出仍取决于模型能力和当次提示词质量。
  • 许可证覆盖代码而非商标。仓库是 MIT；把某站点的设计规范用于产出界面时，不等于获得该品牌的商标授权。
  • 「60+」不是官方数字。该表述来自推文作者观点，按作者口径标注。
