Hermes Agent Skills
技能系统使用指南

技能是 Agent 的可复用能力单元——内置或用户编写的标准操作流程，以 YAML+Markdown 文件存在于 skills/ 目录，被 Agent 在对话中动态加载与执行。

内置技能 用户技能 YAML + Markdown 动态加载 skill_manage
核心定位：技能 = 可复用的标准操作流程

技能不是提示词模板，而是 Agent 可直接执行的操作步骤。内置技能覆盖搜索、浏览器自动化、代码、数据库查询等高频场景；用户技能可自定义扩展，由 skill_manage 管理生命周期。

SKILL.md YAML frontmatter skill_view() skill_manage()
01
WHAT IS A SKILL

什么是 Skill：能力单元的结构定义

Skill 由 SKILL.md（YAML frontmatter + Markdown 正文）组成，被 Agent 在运行时通过 skill_view() 动态加载。

结构

SKILL.md 组成

每个技能文件包含 YAML frontmatter（name、description、category、tags 等）和 Markdown 正文（步骤、坑点、验收标准）。

  • frontmatter 是元数据，供搜索和加载
  • 正文是执行指令，供 Agent 读取执行
生命周期

管理操作：skill_manage

创建、修改、删除技能文件，由 skill_manage 工具完成。action 可选：create / patch / edit / delete。

  • patch：增量修改，适合修复步骤或坑点
  • delete：删除技能，需确认无下游引用
加载

加载方式：skill_view()

Agent 通过 skill_view(name) 读取技能内容，支持按 file_path 读取子文件（references/、templates/、scripts/）。

  • skill_view(name)：读取主 SKILL.md
  • skill_view(name, file_path)：读取子文件
# YAML frontmatter 示例 --- name: my-custom-skill description: 处理 X 场景的标准工作流 category: productivity tags: [custom, workflow] required_environment_variables: [] required_commands: [curl] --- # 正文：触发条件、步骤、坑点、验收 ## Trigger: 用户要求处理 X 时触发 ## Steps 1. 准备环境 2. 调用 API 3. 处理结果

03
HOW TO USE

技能使用方式：从对话触发到显式加载

技能加载有三种方式：对话自动匹配、显式调用 skill_view()、列表浏览 skills_list()。

自动匹配

对话触发（推荐）

用户以自然语言描述需求，Agent 自动识别匹配的技能并加载。触发词通常为技能名、场景关键词或工具名。

  • "帮我搜索 X 的相关信息" → searxng-search
  • "调查 GitHub 仓库 Y" → github-repo-research
  • "用 TDD 写这个功能" → tdd
自动加载 零配置
显式调用

显式加载（精确控制）

当自动匹配不够精确时，可显式调用 skill_view(name) 加载指定技能内容，Agent 按技能步骤执行。

  • skill_view(name)：加载完整 SKILL.md
  • skill_view(name, file_path)：加载子文件
  • skills_list(category)：按分类浏览
精准加载 可控
# 列出所有可用技能（按分类筛选） await skills_list(category="search") # 加载指定技能完整内容 await skill_view(name="searxng-search") # 加载技能子文件（模板、脚本、参考文档） await skill_view(name="searxng-search", file_path="references/api.md") # 管理操作示例 await skill_manage(action="patch", name="searxng-search", old_string="旧步骤", new_string="新步骤")
04
SKILL AUTHORING

编写技能规范：好技能的标准结构

一个可维护的技能应包含触发条件、编号步骤、坑点、验收步骤和子文件支撑（references/、templates/、scripts/）。

必须

触发条件

明确说明技能何时被激活，包括触发词、场景描述和前置要求。模糊的触发条件会导致技能无法自动匹配。

必须

编号步骤

用有序列表写出精确的操作步骤，包含命令示例和预期输出。步骤越具体，Agent 执行成功率越高。

建议

坑点与陷阱

记录执行中常见的错误、失败原因和应对方案。坑点是最有价值的隐性知识，不写则重复踩坑。

建议

验收步骤

提供可执行的验证命令或检查清单，确认技能执行结果符合预期。可自动化验收时给出命令脚本。

# SKILL.md 必填字段（YAML frontmatter） name: my-skill-name # 小写 + 连字符 description: 技能的简短描述，说明用途和适用场景 category: category-slug # 分类标签 tags: [tag1, tag2] required_environment_variables: [VAR_NAME] required_commands: [curl, jq] # 正文结构（Markdown） ## Trigger ## Steps ## Pitfalls (坑点) ## Verification (验收) ## Related

RISK & SAFETY

风险边界：技能执行的安全红线

某些技能涉及高风险操作（文件写入、网络访问、外部服务调用），需注意权限边界和安全配置。

✅ 低风险技能（可自动执行）

  • 只读搜索：searxng-search、arxiv、llm-wiki
  • 本地分析：code-review、jupyter-live-kernel（read-only）
  • 知识管理：obsidian、notion（读操作）
  • 创意生成：ascii-art、baoyu-article-illustrator
  • 元数据读取：skills_list、skill_view

⚠️ 中风险技能（建议显式确认）

  • 文件写入：创建/修改文件、写入笔记库
  • 浏览器操作：browser_vision、browser_click
  • API 调用：涉及外部服务写入
  • 定时任务：cron 调度、后台进程管理

🚫 高风险技能（需显式授权）

  • 系统级操作：terminal 删除文件、git push、ssh
  • 凭证写入：API key、token 写入环境变量
  • 外部发布：社交媒体发帖、邮件群发
  • 数据库写入：涉及数据修改的数据库操作
  • 权限提升：sudo、chmod、修改系统配置
安全原则

最小权限执行

每个技能只授予完成目标所需的最小工具集。Agent 不自动执行高风险操作，需用户显式确认。

  • 内置技能默认安全边界：只读为主
  • 用户编写技能需明确声明 required_tools
  • 凭证不写入提示词或日志
  • 高风险操作需二次确认机制
