Weave Router：给 Claude Code、Codex 和 Cursor 接上自动模型路由

把多个模型供应商放到一个兼容入口后，由本机 scorer 为每个 API action 选择模型；同时提供 BYOK、可观测性和客户端安装器。

AnthropicOpenAIGeminiDeepSeek / Kimi / QwenBYOK
官方 README 声称
<50ms 路由
40–70% 成本下降

这是项目方宣传/文档指标，不是本卡独立复测结论。成本结果取决于模型池、流量分布、缓存与实际计费。

00

它解决的不是“没有模型”，而是“不会选模型”

Weave Router 是一个面向 Agent 系统的模型路由器。客户端只对接一个 endpoint，路由器再把请求翻译并转发到已启用的模型与 provider。

统一入口

兼容 Anthropic Messages、OpenAI Chat Completions 和 Gemini native API。

按 action 决策

官方语义是按单个上游 API request / action 路由，而不是按 turn 或 session。

本地优先

README 描述 on-box embedder、BYOK 密钥加密存储和直连 provider 的部署模型。

01

路由架构：请求先被理解，再被转发

CLIENTClaude / Codex / Cursor沿用客户端已有调用方式。
GATEWAYRouter :8080/v1/messages、/v1/chat/completions、/v1/route。
SCORERCluster scorer用本机 embedder 分析 action。
PROVIDERProvider poolAnthropic、OpenAI、Gemini 或兼容端点。
client → Router :8080 → embed + score action → selected model/provider ├→ Postgres（配置、usage、加密 BYOK） ├→ /ui/dashboard（自托管监控） └→ OTLP collector（Honeycomb / Datadog / Grafana）
故障边界README 称 cluster scorer 不可用时返回 HTTP 503，而不是静默选择默认模型。生产部署应把 readiness、模型 artifact、provider 凭据和路由失败都纳入监控。
02

30 秒接入：先用 hosted，再决定 self-host

# Hosted router：安装器询问目标和 scope npx @workweave/router # 指定客户端 npx @workweave/router --claude npx @workweave/router --codex npx @workweave/router --opencode npx @workweave/router --pi # 项目级 / 本地 / 自定义 endpoint npx @workweave/router --scope project npx @workweave/router --local npx @workweave/router --base-url https://router.acme.internal

要求 Node ≥18；Claude Code、opencode、pi 路径还需要 jq。Cursor 可在 Settings → Models → Override OpenAI Base URL 中接入，官方标注为 early beta。

Claude Code

npx @workweave/router --claude 或自托管安装；支持 router-on/off/status/models。

Codex

安装器维护 model_providers.weave，不应覆盖其他配置；可使用 native skills 控制路由。

opencode / pi

分别写入 provider.weave 或 pi extension；重装和卸载只处理受管区块。

03

自托管：路由器、scorer、密钥和 dashboard 留在你的栈里

# .env.local 只放你自己的 provider key；示例为占位符 OPENROUTER_API_KEY=<your-provider-key> # 启动 Postgres + router，并生成 router key make full-setup # Anthropic-compatible request curl -sS http://localhost:8080/v1/messages \\ -H "Authorization: Bearer <router-key>" \\ -d '{"model":"claude-sonnet-4-5","max_tokens":256,"messages":[{"role":"user","content":"hi"}]}' # 只查看路由决策 curl -sS http://localhost:8080/v1/route \\ -H "Authorization: Bearer <router-key>" -d '<request>'
不要把 BYOK 等同于绝对隐私保证官方架构说明 provider key 可本地加密保存、prompt 直连配置的 provider；仍需自行核对部署拓扑、日志、OTLP collector、Postgres、第三方 provider 和管理员权限。

路由不是盲目追求“最强模型”：配置文档提供 provider/model exclusion、session pin、hard pin、sub-agent model 等控制项，适合按成本、能力和任务类型做组织级策略。

05

三个值得先读的配置参数

ROUTER_DEFAULT_STRATEGY

默认值：cluster。决定没有持久化策略时使用的路由策略。

ROUTER_CLUSTER_EMBED_TIMEOUT_MS

默认值：200。本机 ONNX embed timeout；慢机器需谨慎调整。

ROUTER_SESSION_PIN_ENABLED

默认值：true。让多轮会话保持首次路由模型的一致性。

ROUTER_STICKY_DECISION_TTL_MS

默认值：0，禁用。按 API key 复用路由决定的时间窗口。

ROUTER_HARD_PIN_MODEL

默认：无。强制模型并绕过 scorer，文档定位为 debugging only。

ROUTER_SUBAGENT_MODEL

默认：无。可把 Claude Code Task-tool sub-agent 指到独立 provider/model。

06

API 与可观测性：别只看“省了多少钱”

Endpoint作用
POST /v1/messagesAnthropic Messages 路由入口
POST /v1/chat/completionsOpenAI Chat Completions 路由入口
POST /v1beta/models/:actionGemini generateContent 路由入口
POST /v1/route只返回路由决定，不调用上游
GET /health /readyz /validate存活、依赖就绪和 key 检查
GET /v1/analytics/routing-decisions导出原始路由决策与 usage 相关数据

OTLP traces 可送入自有 collector；dashboard 可查看路由、usage 和策略。评估时至少同时看命中模型、失败率、延迟、输入输出 token、provider 价格和用户体验。

07

适合、不适合与许可边界

适合

同时使用多家模型、希望统一配置入口、按任务调度模型、需要 BYOK 和路由观测的 Agent 团队。

不适合

只用单一模型、不愿引入额外 gateway / Postgres / policy 组件，或需要未经审计的自动模型切换的场景。

许可

仓库 README 的 license badge 为 ELv2（Elastic License 2.0）。部署、再分发和商业使用前必须按当前仓库许可证核对。

原帖与官方文档的边界原帖称“只改一个接口地址即可降低 40–70% 成本”；官方 README 同样给出低于 50ms 和成本下降描述。本文保留这些宣传指标，但不把它们写成独立 benchmark 或账单保证。
