四家生图 API，真正不同在哪里？

OpenAI、Gemini、Grok、Qwen 的差异，不在“能不能生成图片”，而在请求协议、图片输入、输出承载、尺寸表达、批量语义、编辑方式、异步能力、区域部署与迁移成本。

02 / 四家逐项拆解

请求、参数、返回和限制
01 · OPENAI

控制粒度最完整

gpt-image-2.5-sunburst / flare
生成
POST /v1/images/generations；model、prompt 必填。
参数
n、size、quality、background、output_format、output_compression。
输出
示例读取 result.data[0].b64_json，应用侧自行解码。
编辑
POST /v1/images/edits；一/多图、prompt、mask，multipart。
尺寸
推荐 1024×1024、1536×1024、1024×1536；自定义尺寸通常要求边长为 16 的倍数，比例 1:3 至 3:1，总像素有限制。
REST · 生成
POST https://api.openai.com/v1/images/generations
Authorization: Bearer $OPENAI_API_KEY
Content-Type: application/json

{"model":"gpt-image-2.5-sunburst","prompt":"A premium product photo","size":"1536x1024","quality":"high","n":1}

工程判断：适合把质量、透明背景、格式压缩、编辑做成产品级配置；代价是能力矩阵较复杂。

02 · GEMINI

多模态交互原生

gemini-3.1-flash-image；另有 Pro/Lite/2.5
生成
POST /v1beta/interactions；model、input 为核心字段。
参数
response_format 可是 image 对象，也可为 text/image 数组；图像配置用 aspect_ratio、image_size。
输入
input 可为字符串或 text/image 内容数组，适合多图参考与连续编辑。
输出
output_image.data Base64；同时可有 output_text。
限制
输出数量不一定严格服从要求；生成图包含 SynthID 水印；输入图数量/保真随模型不同。
REST · 图像 + 文本
POST https://generativelanguage.googleapis.com/v1beta/interactions
x-goog-api-key: $GEMINI_API_KEY
Content-Type: application/json

{"model":"gemini-3.1-flash-image","input":"Generate a product hero image and explain it.","response_format":[{"type":"text"},{"type":"image"}]}

工程判断：适合“看图—理解—修改—继续对话”；单次 T2I 需单独适配输出对象。

03 · GROK / XAI

OpenAI 外形 + xAI 扩展

grok-imagine-image-2.0
生成
POST /v1/images/generations；官方提供 OpenAI Python/JS SDK 用法。
参数
n 1–10、aspect_ratio、resolution 1k/2k、quality auto/low/medium、response_format。
输出
默认 url，是临时托管地址；需长期保存时请求 b64_json 并落盘。
编辑
POST /v1/images/edits；URL/Base64 data URI；最多 5 张参考图。
审核
SDK 有 respect_moderation，且可读实际解析后的 model。
REST · 2K Base64
POST https://api.x.ai/v1/images/generations
Authorization: Bearer $XAI_API_KEY
Content-Type: application/json

{"model":"grok-imagine-image-2.0","prompt":"A cinematic greenhouse","n":2,"aspect_ratio":"16:9","resolution":"2k","quality":"medium","response_format":"b64_json"}

工程判断：迁移既有 OpenAI Images SDK 阻力低，但扩展字段在不同 SDK 中的传递方式不同。

04 · QWEN / ALIBABA CLOUD

区域与协议是第一风险

qwen-image-3.0-pro / qwen-image-3.0
路径
OpenAI-compatible 同步；DashScope 同步（推荐）；DashScope 异步。
兼容请求
顶层 model、prompt；I2I 另加 image 字符串/数组。
原生请求
input.messages[].content 放 text/image；parameters 放控制字段。
控制
prompt_extend、prompt_extend_mode、enable_thinking、n、size、negative_prompt、seed、watermark。
限制
3.0 输出总像素约 512×512 至 2048×2048，比例约 1:8 至 8:1；输入 1–3 张、单图最多 10 MB；区域、模型、key 必须匹配。
Compatible · I2I
POST https://{WorkspaceId}.us-east-1.maas.aliyuncs.com/compatible-mode/v1/images/generations
Authorization: Bearer $DASHSCOPE_API_KEY
Content-Type: application/json

{"model":"qwen-image-3.0-pro","prompt":"Put the product on a studio table","image":["https://example.com/product.png"],"size":"1536*1024","n":1,"prompt_extend":true}

工程判断：适合中文、图中文字、区域 endpoint、异步批处理；必须保留 Qwen 原生分支。

04 / 可落地的统一适配层

用内部规范隔离供应商差异
01

标准化输入

prompt_text、reference_images[]、aspect_ratio、pixel_level、quality_hint、count、edit_mode。

02

能力协商

查 provider/model 能力矩阵：I2I、mask、透明背景、seed、异步、中文区域。

03

发送映射

OpenAI/Grok 走 images；Gemini 组 input/response_format；Qwen 选择 sync/async。

04

统一结果

转为 assets[]、mime_type、remote_url、base64、request_id、moderation、task_status。

05 / 选型结论与风险边界

不是单一赢家，而是场景首选
产品级控制

OpenAI

透明背景、质量档位、格式压缩、编辑与成熟 SDK 语义更适合产品化配置。

对话式多模态

Gemini

连续看图、解释、改图时交互对象自然；不能只按传统 T2I API 评价。

OpenAI 迁移

Grok

既有 OpenAI Images 系统迁移阻力低；要处理临时 URL、扩展字段与审核元数据。

中文/区域/异步

Qwen

中文、图中文字、区域 endpoint、异步批处理突出；协议分叉与区域绑定也最明显。

高风险未知

必须 POC

真实限流、区域可用模型、URL 有效期、审核边界、I2I 保真、并发吞吐、失败重试、实际计费。

不推荐

只做一个 OpenAI JSON

会掩盖 Gemini 交互输出、Qwen 异步任务、Grok 扩展参数和各家不同的图片承载。

结构性评分 · 非实测 benchmark
控制粒度 · OpenAI9.5
多模态交互 · Gemini9.4
OpenAI 迁移 · Grok8.8
中文/区域/异步 · Qwen9.1

评分来自官方字段的结构性评价，不替代目标账号、地区、并发和成本的 L3 实测。
