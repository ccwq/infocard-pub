01先理解它解决什么问题

不要再对 AI 说“做得高级一点”

“高级感”可能来自字体、材质、动效、空间层次，也可能来自整个页面的节奏。ThreeUI 的价值不在于替你选一个万能风格，而是把这句模糊要求拆成可以浏览、比较、接入和继续修改的具体效果。

推荐首个动作：先按产品场景挑一个细节——例如 Hero 背景、按钮、文字动效或数据粒子场——接入并验证，再决定是否扩展到整页。

第 1 步：建立具体描述

不要说“更酷”。改成“深色 Hero 背景，低密度粒子，鼠标移动产生轻微视差，移动端关闭实时动画”。

第 2 步：先复制一个局部

把组件放进独立 route 或测试区，先看它与产品字体、间距、内容密度是否相容。

第 3 步：让 AI 做适配

明确框架、入口文件、容器尺寸、交互事件和降级条件；要求 AI 保留可读的配置边界。

第 4 步：再决定是否扩展

单个效果成立，不等于整页需要同一套动效。保留主次，避免首页比产品本身更忙。

04代表性选择 · 按产品目标路由
你的目标优先看接入提醒
让首屏有空间感Globe / Landscape / Structure Flow先限定相机、光照和动画速度，避免背景抢正文。
做一个有记忆点的 CTACircle Buttons / Rectangle Buttons / Shader Buttons保留键盘焦点、hover 之外的可操作反馈。
解释复杂系统或网络Constellation Field / Diagnostics Panel动画是辅助关系表达，不要让用户靠猜图例。
强化品牌标题Text Path Studies / Article Headings / Brand Orbs准备静态文字 fallback，避免字体加载失败时首屏消失。
做完整页面原型Sylva / Kage / Sketchbook 等模板先拆出信息架构，再替换视觉，不要原样照搬全部动效。
05接入时需要交给 AI 的边界
技术上下文框架与构建工具、入口组件、包管理器、目标容器尺寸、是否 SSR、是否允许 WebGL。
交互上下文触发方式、动画是否循环、鼠标/触摸行为、键盘操作、prefers-reduced-motion 策略。
产品上下文主标题、正文密度、品牌色、内容优先级、首屏目标和转化动作。
交付上下文需要返回哪些文件、如何启动、如何验证、失败时的静态 fallback 和回滚方式。
请把这个效果接入当前页面的 Hero 容器：保持现有标题和 CTA 的 DOM 不变；动画仅作用于背景层；支持键盘与 reduced-motion；移动端关闭高成本 WebGL；返回修改文件、启动命令和验证清单。
06性能、可访问性与安全边界
性能观察首屏脚本体积、纹理大小、帧率、GPU 占用和低端设备降级。不要把每个组件都设为常驻动画。
可访问性动效不能承担唯一信息表达；保留文本、焦点态、键盘路径和 reduced-motion 方案。
工程稳定明确客户端执行边界；检查 SSR hydration、容器销毁、路由切换和 WebGL context 丢失。
不适合：后台密集信息表、需要极短首屏时间的营销页、无法接受 GPU 差异的关键流程，以及没有静态降级内容的无障碍场景。
07免费与 PRO · 不要混淆授权
目录层官方浏览页同时展示普通条目与标记为 PRO 的条目。目录可用于发现方向，但具体可复制内容、源码和使用权要以条目页面说明为准。
PRO 层看到 PRO 标识时，不要默认可以直接复制到商业项目；先核对访问条件、授权文本、素材依赖和分发限制。
发布前清单：记录实际使用的条目名称、源码/资源来源、许可证或购买条款、第三方依赖和是否需要保留署名。
08一句话决策与官方入口

适合谁

想给 AI 一个可观察、可比较、可继续修改的前端视觉起点，并愿意自己负责产品适配、性能和授权核对的人。

不适合谁

只想一键得到完整成品、完全不想处理浏览器兼容与动画降级，或需要把所有目录内容当作同一许可证资源的人。
