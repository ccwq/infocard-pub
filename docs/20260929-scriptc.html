scriptc

同一份 TypeScript，编译成不用装 Node 的原生可执行文件：解析与类型检查交给 TypeScript 官方编译器，再经 typed IR → C → LLVM IR，落到原生汇编、对象、二进制与 WASM。静态构建里既没有 Node，也没有任何 JS 引擎。

TypeScript 进，机器码出 Apache-2.0 Node 24+ macOS / Linux / Windows / WASI 5,661★
scriptc ≠ 把 JS 引擎一起打包
bun build --compile / pkg 一类

产物里塞进了 JS 引擎，运行时仍然在解释执行 JavaScript，只是省掉了安装 Node 这一步。

scriptc 的做法

真的编译到机器码：静态可编译的部分编进小型原生运行时，编不了的代码被报成诊断，或用 --dynamic 显式嵌入 quickjs-ng。

不能静态编译的代码不是被忽略，而是被报成诊断。

scriptc coverage 会对每一个动态或不支持的调用点给出带错误码的诊断。网络 socket / fetch、子进程、OS 信号、文件系统监控这几类在 WASI Preview 1 上缺失的能力，会在链接前以 SC3002 失败，而不是留到运行时才炸。
01 · 写 TS保留类型系统

async/await、promise、generator、timers、stdin/readline 事件、回调与 promise 风格的文件系统 API 都在支持范围内。

02 · 解析 + 类型检查复用 TS 编译器

解析和类型检查直接用 TypeScript 自己的编译器，类型错误在编译期暴露，不拖到产物运行时。

03 · typed IR--emit=ir

只调 Node 就能产出 .scriptc/hello.ir.json，不拉起 clang、archiver 或链接器。

04 · C / LLVM--emit=c | llvm

继续降级为可读的 C 源码 hello.c 与文本 LLVM IR hello.ll，每一步都能人工审计。

05 · 汇编 / 对象 / 二进制--emit=asm | obj

hello.s、hello.o，直到 scriptc build hello.ts -o hello 产出独立可执行文件。

产出矩阵 · 五种中间态
emit matrix

--emit=ir只需 Node

typed IR JSON，落在 .scriptc/hello.ir.json；连链接器都不需要。

--emit=c · --emit=llvm可读中间产物

生成 hello.c 与 hello.ll。不同产出种类会累积在 .scriptc/ 里，同一种重建即覆盖。

--emit=asm · --emit=obj捆绑 helper

macOS 15+ arm64 上用 scriptc 自带的平台 helper 与预编译运行时包，不需要编译器、archiver、链接器或 SDK，产物部署目标是 arm64-apple-macosx14.0.0。

--emit=obj 的对象语义relocatable

写出的可重定位程序对象带未定义的 scr_* 运行时引用与必需的 scr_runtime_abi_v3 标记；需要自包含归档接口时走 scriptc build --lib --profile。

Node API · 覆盖率 · 动态兜底
runtime / coverage / dynamic

Node API 真编到原生运行时node:http

受支持的 Node API 会编译进原生运行时：node:http 的 createServer 写成服务后 scriptc build server.ts -o server，直接 ./server 监听 8080，不需要 Node 进程。

覆盖率是逐点诊断，不是百分比coverage

对每个动态或不支持的调用点给一条带码诊断，静态可达比例直接算给你看，方便决定是先改代码还是先上 --dynamic。

$ scriptc coverage hello.ts statements analyzed 2 compile statically 2 (100%) fully static — this program has no dynamic remainder. $ scriptc build hello.ts -o hello && ./hello ctate hello, ctate $ SCRIPTC_CC=zigcc SCRIPTC_TARGET=wasm32-wasi \ scriptc build hello.ts --no-keep-c -o hello.wasm $ file hello.wasm hello.wasm: WebAssembly (wasm) binary module version 0x1 (MVP)

--dynamic：显式嵌入 quickjs-ngnpm 包

给 --dynamic 后，npm 包的 JavaScript 会被嵌进可执行文件，运行时不读 node_modules。示例用 picocolors 上色，./cli 直接跑。

外部对象消费仍属实验--print=native-link-info

该开关会输出对象并打印一份带版本号的 JSON 配方：目标三元组、main 入口、精确的 @scriptc/runtime 源包、必需系统库、FFI 输入与 ABI 标记，配方里不含隐藏缓存路径。

安装 · 平台 · 边界
install / platforms / limits

安装成本npm 一行

  • npm install -g scriptc（编译器本身要 Node 24+）
  • --emit=ir|c|llvm 只需要 Node
  • 产出的可执行文件不需要 Node
边界一：实验项目Vercel Labs EXPERIMENT

定位是 Vercel Labs 实验项目，API 与行为可能变更，不要拿它编译生产环境的服务端。

边界二：WASI 能力缺口SC3002 链接前失败

网络 socket/fetch、子进程、OS 信号、文件系统监控在 WASI Preview 1 上于链接前报 SC3002；sanitizer 构建、原生 FFI、库模式归档在 WASI 上同为目标诊断。

边界三：构建依赖分层linker / C compiler

普通 LLVM 层可执行文件需要平台链接器与 SDK/sysroot（SCRIPTC_LINKER 可选择驱动），但用的是捆绑 helper + 预编译运行时包，不编译生成代码与运行时 C；显式 C 构建、LLVM 回退、--sanitize 才额外需要 C 编译器。
