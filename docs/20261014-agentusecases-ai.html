01先做这一步

如果你只做三件事，就按这个顺序：

  1. 打开 agentusecases.ai 首页。首页是一条滚动的新用例流，顶部显示总量与更新日期——快照时首页写的是 1273 use cases，Updated Oct 13, 2026，并标出当日 47 new use cases。
  2. 先用 topic 或 agent 把范围缩小到你自己的领域。topic 适合按场景选（例如 Money, Bills & Benefits 106 条），agent 适合按工具选（例如 Claude Code 167 条）。别从首页一条条往下翻。
  3. 点进条目，看 View prompt。条目里有可查看的提示词文本；上方是来源平台标注与日期。需要原始细节就沿来源链接回原帖。
本卡边界 写这张卡时没有注册该站点、没有订阅邮件、也没有提交过用例。以下内容全部来自站点公开页面的一次快照，加一条推文的逐条口径核对。所有计数都是 2026-10-14 的值，之后会变。

02核心机制

它不是聚合机器人自动抓的列表，而是一个人工审核的提交制目录：有人真的用 agent 做过某件事，把它交上来，审核通过才可能出现在站上。

谁在运营

站点由 Alex Finn 运营。他还写 Ship/It Weekly，并在 X（@AlexFinn）与 YouTube 上发布内容。

提交与审核流程

  • 任何人都可以从首页提交用例。
  • Alex Finn 逐条审核后才可能发布。
  • 通过审核的条目会在后续更新时对照来源核对并加入站点。
  • 未通过审核的，不会出现在站上。

3.3 怎么用 View prompt

  1. 从 topic 或 agent 列表进入条目页。
  2. 先看来源标注与日期：New · X、New · Reddit 这类标注说明贴在哪个平台，日期说明新旧。
  3. 点 View prompt 看提示词原文，直接抄或按自己的工具改写。
  4. 提示词里出现的第三方工具、账号、额度，回原帖核对——条目是转述。

3.4 跟进增量

想每天看新增就订阅站点 RSS feed；首页顶部的“当日新增数”也可以当作更新频率的观察点（快照日显示 47 new use cases，对应 Tue, Oct 13）。

05已知限制与边界

5.1 转述与原文的差

条目是站点用自己的话转述的原帖，不保证复现原帖全部细节。要复现，必须回原文核对；本卡里的 5 条样例也只是转述文本，没有回原帖逐条验证。

5.2 计数自相矛盾（并列，不抹平）

  • 首页：1273 use cases，Updated Oct 13, 2026；当日 47 new use cases。
  • agents 页：27 agents and 1,267 real use cases。
  • 两者相差 6 条，站点未解释是哪一边滞后或口径不同。

5.3 覆盖不均

提交制 + 人工审核意味着覆盖是提交热度的形状，不是 agent 能力排名：Claude Code 167 条，而 Hermes Agent 26 条。冷门 agent 的条目少，不代表它做不了事。

5.4 采集机制未公开

站点自述来源是 the open web、X、Reddit、Hacker News，首页按天显示更新与新增量；但没有公开自动采集的技术细节，因此无法据此判断扫描频率与去重规则。不要把它写成“每天扫描整个互联网”。

5.5 许可与版权

站点无开源许可声明；内容版权归站点与原作者。页脚有 Sponsor 与 Privacy 链接。

5.6 数字会变

内容量、分类计数、agent 计数都是 2026-10-14 的快照值，会随后续更新变化。
