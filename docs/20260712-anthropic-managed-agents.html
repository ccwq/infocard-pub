规模化 Managed Agents
把大脑和手解耦

Anthropic 工程博客（2026-04-08）：用操作系统抽象哲学设计 agent 系统——把 harness（大脑）、sandbox（手）和 session（记忆）解耦成独立接口。接口比任何具体实现都活得更久。

大脑手解耦 三个组件：session、harness、sandbox p50 TTFT 下降 60% 凭证不进入 sandbox

不要养宠物：耦合架构的代价

问题

session、harness、sandbox 全在一个容器里

容器挂了 → session 丢。容器无响应 → 手工护理恢复。工程师开 shell 调试 → 容器通常持有用户数据 → 本质上没有调试能力。

问题

harness 假设 Claude 工作的东西都住在容器里

客户要求连接到自己的 VPC 时，要么网络对等，要么在客户环境里跑 Anthropic 的 harness——两个都不理想。

三个组件解耦：虚拟化 agent 的每个部件

Session

只追加的事件 log

所有事件的 append-only 记录。harness 在外部，session 不会随 harness 或 sandbox 的重启而丢失。

Harness

调用 Claude 并路由工具

loop：调用 Claude + 把工具调用路由到对应基础设施。不在容器里，像调用任何工具一样调用 sandbox。

Sandbox

Claude 执行代码和编辑文件的执行环境

Claude 可以在里面运行代码、编辑文件。每个 sandbox 通过 execute(name, input) → string 接口暴露。

解耦：容器从宠物变成牲畜

Harness 离开容器

容器是 cattle，不是 pet

容器死了 → harness 捕获为工具调用错误，传回 Claude。Claude 决定重试时，用标准配方重新初始化新容器。没有任何东西需要"存活"。

Harness 失败恢复

wake(sessionId) 重启新 harness

session 在 harness 外部。harness 崩溃后，用 getSession(id) 取回事件 log，从最后的事件继续——不需要恢复任何内部状态。

安全边界：凭证永远不进入 sandbox

Git token 不泄露

初始化时克隆，不运行时传入

Git push/pull 在 sandbox 内工作，但 Claude agent 自己从不处理 token——仓库用 token 在初始化时克隆，token 不在 sandbox 内可达。

自定义工具

MCP 代理从 vault 取凭证

通过专用 MCP 代理调用，代理获取与该 session 关联的 token，从 vault 取对应凭证——harness 永远不知道任何凭证。

session 不是 Claude 的上下文窗口

压缩（compaction）和上下文修剪（pruning）都涉及不可逆决策。Managed Agents 中，session 提供与 REPL 上下文对象相同的好处，但上下文被持久化在 append-only log 中。getEvents() 允许大脑选择事件流的位置切片——从上次停下的地方继续、在某个时刻之前倒退、或者在某个操作之前重读上下文。

多大脑多手：架构扩展能力

多大脑

p50 TTFT 下降约 60%，p95 下降超 90%

容器只在工具调用时才配给，不需要容器的 session 不必等。一个大脑可以连接客户 VPC 中的资源，无需网络对等。

多只手

execute(name, input) → string

每个 sandbox 是一个工具。大脑之间可以传递手——一只手出问题，不影响其他手和大脑。Claude 需要推理多个执行环境并决定工作发到哪里。

元 harness 设计：带走什么

Managed Agents 是"元 harness"——对 Claude 将来需要什么具体 harness 没有意见，只是一组通用接口。

我们相信的

Claude 需要操控状态（session）的能力、需要执行计算（sandbox）的能力、需要扩展到许多大脑和许多只手的能力。

我们不做假设的

不假设大脑或手的数量。不假设位置。不假设背后运行什么具体实现。

使用边界：Managed Agents 的性能数据（TTFT 下降 60%/90%）来自 Anthropic 官方博客原文；p95 "超 90%" 是原文表述，尚未独立核验。sandbox 接口和安全边界机制（Git token vault、MCP 代理）是原文描述的系统设计决策，不代表所有 MCP 集成均默认满足同等安全约束。
