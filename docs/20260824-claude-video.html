为什么需要这个插件

Claude Code 原生不支持视频输入。你粘贴一个 YouTube 链接，它只能靠标题猜测内容，或拉取残缺的字幕。

claude-video 的解决思路：让 Claude 自己提取帧、获取字幕 / Whisper 转写，然后用多模态 Read 工具"看"每一帧。Claude 最终的回答是真正基于画面和音频的，不是靠猜。

yt-dlp 下载 ffmpeg 帧提取 原生字幕优先 Whisper 转写兜底 纯 stdlib Python
处理流程
步骤工具说明
1. 获取字幕 yt-dlp 优先拉取平台原生字幕（免费、精确），跳过视频下载
2. 下载视频 yt-dlp 无字幕 / 需要帧时，按需下载（macOS 自动 via Homebrew）
3. 提取帧 ffmpeg 场景感知采样（scene-change detection），默认 100 帧上限，512px 宽，Claude 兼容 JPEG
4. 转写音频 Whisper API 无字幕时提取 16kHz 单声道音频，发往 Groq（推荐，便宜快速）或 OpenAI Whisper-1
5. 多模态回答 Claude Read 帧路径 + 时间戳 + 字幕一起发给 Claude，Claude 像真实看过视频一样回答
命令行参数
--detail
transcript 仅字幕（无帧，免费快速）；efficient 快键帧（上限 50）；balanced 场景感知（上限 100，默认）；token-burner 不设上限。
--timestamps
指定时间点抓帧，格式 SS / MM:SS / HH:MM:SS，可多值逗号分隔。Claude 会优先关注这些关键时刻。
--start / --end
截取片段范围（自动调整采样密度），适合长视频局部分析。
--max-frames N
手动降低帧上限，控制 token 消耗。
--resolution W
帧宽（默认 512px）。需要读屏幕文字（PPT、终端、代码）时建议 --resolution 1024。
--whisper groq|openai
强制指定 Whisper 后端。两个 key 都配置时默认 Groq。
--no-whisper
完全禁用转写，仅靠字幕或帧回答。
--no-dedup
关闭帧去重（默认去掉视觉相似的连续帧）。
适用场景

适合 claude-video

  • Bug 屏幕录制：定位 UI 卡死瞬间（~1:14 的 X 按钮事件）
  • 长演讲 / 教程：提问"3:20 处讲了什么"
  • PM 发的 Loom 演示：提取功能需求点
  • 视频教程 QA：验证代码演示是否匹配字幕

局限性

  • 帧间隔内的事件不可见（1fps 采样 ≈ 每秒间隙）
  • Whisper 差 = 转写差 = 答案差（音乐/重叠人声场景）
  • 无流式 / 实时分析能力，全量处理后回答
  • 不支持直播 / RTSP 等非文件 URL
依赖与成本
功能依赖成本
下载 + 原生字幕 yt-dlp + ffmpeg 免费
Whisper 转写（推荐） Groq API Key（console.groq.com） 极低 — whisper-large-v3 按分钟计
Whisper 转写（备选） OpenAI API Key 标准定价
Claude Code 调用 Claude 订阅 帧数 × token 消耗（~50-100 帧 ≈ 50-80K input tokens）

API Key 存于 ~/.config/watch/.env（权限 0600），macOS 首次运行自动通过 Homebrew 安装 ffmpeg / yt-dlp。
