01
核心定位

不是另一个日志看板，而是把可观测性变成自动化行动

Superlog 的 README 把定位说得很清楚：开源 agentic telemetry 系统。不是"更漂亮的数据可视化"，而是把 telemetry 数据变成 Agent 可以理解和执行的东西。

Why it exists

传统可观测性工具告诉你"指标 spike 了"，然后你得自己去看日志、自己诊断、自己修。Superlog 的思路是：让 Agent 替你做这件事——摄取信号、聚合成 incidents、触发自愈。

agentic observability

可观测性不只是看数据，而是让 Agent 能读懂

Superlog 在摄取层就考虑了 Agent 的可用性：信号聚合、incidents 组织，都是为了给下游 Agent 提供可执行的上下文。

self-healing

把诊断变成动作，不只是发告警

社区版的 community agent runner 记录本地 incident 摘要；接入自定义 Agent runner 后可以把诊断变成修复动作。

local-first

可以完全本地部署，不需要云服务

Docker Compose 一键启动，Web + API + OTLP intake 全在本地跑，数据不出你的机器。

02
技术架构

TypeScript monorepo：apps/ + packages/ 双层结构

README 里明确列出了 monorepo 结构：4 个 app + 2 个 package。技术上用 Vite/React 做前端，Node.js 20+ 做后端，Postgres 做元数据，ClickHouse 做 telemetry 查询。

apps/packages/

Monorepo 完整结构

apps/webVite/React 前端
apps/apiHTTP API 服务
apps/proxyOTLP intake 代理
apps/worker后台 worker / Agent 编排
packages/dbDrizzle schema + migrations
packages/fingerprinttelemetry fingerprinting helpers
OpenTelemetryClickHousePostgres

数据层设计

  • OTLP proxy：接收任何 OTLP-compatible telemetry 数据。
  • Postgres：元数据、incidents、配置等结构化数据。
  • ClickHouse：海量 traces/logs/metrics 的时序查询。
03
安装与入口

用 skills 安装 / Docker Compose 本地起量 / 源码构建

Superlog 提供了很有趣的安装路径：不只是 Docker，还支持用 coding agent 的 skills 机制一键安装。这让它特别适合集成到 AI agent 工作流里。

npx skills add

用 Coding Agent 安装

在任意支持 skills 的 coding agent 里运行：`npx skills add superloglabs/skills --all`，即可把 Superlog 安装到你的项目。

docker compose

本地快速起量

只需要 Docker + pnpm，一条 `docker compose up -d` 即可启动全套本地栈。

source

源码构建

需要 Node.js 20+ 和 pnpm 9+。适合想深度定制或参与开发的人。

本地服务端口：Web → localhost:5173 · API → localhost:4100 · OTLP intake → localhost:4101

open-core

社区版 = 完整开源，不删功能

README 明确说明：社区版包含完整功能（Web + API + OTLP proxy + workers + agent runner）。Superlog Cloud 是可选的付费托管版，不是功能解锁付费。

05
Open-core 模型

社区版 vs Cloud 版：功能完整，区别在部署方式

Superlog 采取 open-core 模式：社区版是完全开源的完整版本，Superlog Cloud 提供托管服务（有免费层、按量计费和月包套餐）。这个模型适合愿意本地部署的用户。

社区版

完全免费，开源完整

  • Web + API + OTLP proxy + workers
  • Postgres + ClickHouse 本地存储
  • community agent runner
  • Apache 2.0，没有任何功能锁
Cloud 版

托管服务，按需付费

  • 不需要自己维护基础设施
  • 免费层可用
  • pay-as-you-go 或月包套餐
06
适合 / 不适合

适合把可观测性接入 AI agent 工作流，不适合只需要简单告警

Superlog 的设计从一开始就是为 Agent 准备的。如果你只是想要一个传统日志看板，它不是最轻的选择；但如果你想构建"观测 → Agent → 自愈"闭环，它是目前少有的开源路径。

适合

最合适的场景

  • 想用 AI Agent 做可观测性驱动的自动化运维。
  • 需要本地部署、不想数据上云的场景。
  • 已有 OpenTelemetry 数据，想接入可扩展的 agentic 平台。
  • 想自定义 Agent runner 的可观测性诊断逻辑。
不适合

不该硬用的场景

  • 只需要一个传统日志看板或 APM 工具。
  • 不想维护自己的基础设施。
  • 对 Agent 自愈能力没有需求，只需要简单告警。
