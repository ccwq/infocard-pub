一句话结论

能不能用，取决于两件事：你的显存落在哪一档，以及你能不能接受人脸识别权重只允许非商用研究。技术链路本身已经成熟，卡点多在许可与硬件，不在原理。

代码 Apache-2.0 权重仅限非商用研究 插件停止维护
PuLID 是字节跳动的零训练身份保持方案，配 ComfyUI 插件能跑，但许可归属和显存档位是安装前必须确认的两件事。

PuLID 由 ByteDance Inc 团队开发，论文 arXiv:2404.16022，官方 README 记录 2024.09.26 被 NeurIPS 2024 录用。它的做法是把同一个扩散过程拆成两条并行分支：一条注入身份条件，一条不注入，再用对比对齐把带条件分支的输出拉向不带条件的输出分布，从而减少身份信息对基座模型的污染。这也是它能在不训练、不微调的前提下换脸的原因。

GitHub 上有两个常被推荐的 ComfyUI 插件：cubiq 的原生实现和 balazik 的 FLUX 版。本卡核对后发现两处关键差异：cubiq 仓库在 2025.04.14 自己宣布进入 maintenance only；而真正的许可限制来自 InsightFace 的人脸权重，不是 PuLID 的代码，也不是插件自己写的。公众号文章把这条限制的归属说错了，本卡逐条纠正。

01
MODEL ZOO

四个官方权重，选错会白折腾

版本不是越高越好。底模和权重版本必须配对，官方 Model Zoo 明确写了一条例外。

版本底模发布日期官方原话要点适合场景
PuLID-v1SDXL论文同期 Model Zoo 标注为 Paper model 复现论文效果；用 SDXL-lightning-4step 底模时仍推荐它
PuLID-v1.1SDXL2024-10-31 兼容性、可编辑性、脸部自然度、相似度都更好；ID 相似度略升 社区底模（Juggernaut-XL、RealVisXL 等）上要跟提示词、要改表情视角
PuLID-FLUX-v0.9.0FLUX2024-09-12 提示词跟随与画质更好；官方注明对部分男性输入 ID 保真度不够 追求画质与提示词跟随，且参考图不是男性正脸
PuLID-FLUX-v0.9.1FLUX2024-10-31 ID 相似度提升约 5 个百分点，编辑性保持相近 FLUX 底模的默认选择；只要 v0.9.1

官方写明的例外：“The v1.1 model does not perform as well as v1 on the SDXL-lightning-4step base model, so if you want to use SDXL-lightning-4step as the base model, we still recommend using the v1 model.”

2025.08.01 起新增：官方 app_flux.py 支持 FLUX.1-Krea-dev，加参数 --name flux-krea-dev 即可。公众号文章成文时还没有这条。

01 / 官方列表

README 里的 ComfyUI 实现

官方 README “third-party implementations” 小节，ComfyUI 下只列两个。

cubiq 的原生实现，和 ZHO-ZHO-ZHO 的 diffusers 实现。别只听教程推的那一个。

02 / 差异

两种实现路线不同

官方原文：cubiq 是 “native ComfyUI implementation”，ZHO 是 “diffusers-based implementation”。

原生实现走 ComfyUI 自己的模型加载，diffusers 实现走 diffusers 管线，行为不完全一致。

03 / 时效

停止维护意味着什么

作者保留合并关键更新与 PR 的可能，但不承诺持续投入。

遇到 ComfyUI 版本升级导致的节点报错，不要指望上游快速修。ComfyUI-PuLID-ZHO 是另一个可评估的选项。

03
LICENSE WALL · 重点

许可边界在 InsightFace，不在 PuLID

这一节是全卡最需要纠正的部分。归属搞错，商用判断会整个反过来。

A

PuLID 代码：Apache-2.0

仓库根目录 LICENSE 文件为 Apache License 2.0，GitHub API 的 license 字段也是 Apache-2.0。HuggingFace 上 guozinan/PuLID 模型页的 cardData 同样标 apache-2.0。

B

人脸后端：只有 InsightFace 一条路

官方实现与 cubiq 插件都只走 InsightFace + AntelopeV2。文章所称“FaceNet + VGGFace2 商用路径”在代码里不存在。

C

InsightFace 权重：仅限非商用研究

InsightFace README 原文：代码 MIT，学术与商用“无限制”；但紧接一句训练数据与由此训练的模型“available for non-commercial research purposes only”，手动下载与自动下载的模型都适用。

// 核对方法：对官方仓库做全文 grep
$ git clone --depth 1 https://github.com/ToTheBeginning/PuLID
$ grep -rniE 'facenet|vggface|buffalo' . | wc -l
0   ← 零命中，文章所说的第二条路径在代码里不存在

$ grep -n antelopev2 pulid/pipeline_flux.py
70: snapshot_download('DIAMONIK7777/antelopev2', local_dir='models/antelopev2')
73: self.app = FaceAnalysis(name='antelopev2', root='.', providers=providers)

$ grep -c 'non-commercial' cubiq/README.md
0   ← 插件 README 里没有非商用字样，别把 InsightFace 的政策说成插件自己的
需要纠正的三种说法：① 说“README 自己标注 For Non-Commercial / Research Use”——那是 InsightFace 的权重政策，不是 PuLID 的；② 说“存在 FaceNet + VGGFace2 商用路径”——代码零命中；③ 说“插件自己声明非商用”——cubiq README 里没有。
需要同时避免的两个极端：不要下“绝不可商用”的结论，也不要说“可以商用”。正确表述是：代码可商用；人脸权重受 InsightFace 的非商用研究限制。是否落在限制内，取决于你的具体用途和 InsightFace 当前的授权渠道，本卡不替读者定性。

要做商用，先做这三步判断

  • 去你要用的权重仓库看 license 字段（HF 模型页 cardData / 仓库 LICENSE），把代码许可与权重许可分开记录。
  • 直接问权重提供方，包括 InsightFace 官方渠道：README 已写明 inswapper 系列需联系 contact@insightface.ai 获取授权与支持。
  • 如果这条链路谈不下来，评估许可允许商用的其他身份保持方案，不要在“反正代码是 Apache”这条推论上继续。
出处：PuLID 仓库 LICENSE、requirements.txt、pulid/pipeline_flux.py；InsightFace 仓库 README 的 License 小节；GitHub API 快照 2026-10-15。

VRAM WALL

显存：按官方五档实测选参数

这组数字来自官方 docs/pulid_for_flux.md 的实测峰值，不是文章，也不是本机实测。

显卡档位命令峰值显存官方备注
不指定python app_flux.pyunder 45GBnaive bf16
常规卸载--offloadunder 30GBbf16 + offload
16GB 卡--offload --fp8 --onnx_provider cpuunder 15GB官方指定给 16GB 显存卡的组合
24GB 卡--offload --fp8under 17GB官方单独给出的一档
12GB 卡--aggressive_offload --fp8 --onnx_provider cpu约 11GB官方警告：每个 timestep 都在 CPU/GPU 间搬内存，速度会非常慢

出处：PuLID 官方 docs/pulid_for_flux.md，本轮逐行核对原文。另 2025.08.01 起加 --name flux-krea-dev 支持 FLUX.1-Krea-dev。

文章口径

文章给的两个数字

“Flux + PuLID：FP8/8bit GGUF 版 ~12GB，32bit 原版 ~22GB”。这两个数字与官方文档的五档实测都不对应。

可能来自不同底模、不同量化方式或不同机器，不能直接套用。

该怎么做

先量自己的卡

  • 查 nvidia-smi 或系统设置里的显存总量，按上表找最接近的一档。
  • 留出系统和其它进程占用，不要按标称值卡线。
  • 显存不够先加 --offload，还不行再 --fp8，最后才考虑 --aggressive_offload。
不要忽略

慢是真实代价

aggressive offload 省的是显存，花的是时间。官方原话是“speed will be very slow”。

如果你要批量出图，12GB 档的可用性要按小时算，不是按“能跑起来”算。

05
PARAMETER WALL

参数：两个节点不是一回事

文章只讲了标准节点的 method，漏掉了 Advanced 节点的 projection + fidelity，而后者才是最容易踩坑的地方。

参数ApplyPulid（标准）ApplyPulidAdvanced
method / projection (["fidelity","style","neutral"],) 三选一 (["ortho_v2","ortho","none"],) 三选一，没有 method
weight FLOAT 默认 1.0，范围 -1.0～5.0，步长 0.05 同左：默认 1.0，范围 -1.0～5.0，步长 0.05
fidelity 无 INT 默认 8，范围 0～32，步长 1
noise 无 FLOAT 默认 0.0，范围 -1～1，步长 0.1
start_at FLOAT 默认 0.0，范围 0～1，步长 0.001 同左
end_at FLOAT 默认 1.0，范围 0～1，步长 0.001 同左
attn_mask optional 的 MASK 输入 同左

出处：cubiq/PuLID_ComfyUI 的 pulid.py，两个类的 INPUT_TYPES 逐项读取，本轮核对源码。

⚠ 与文章不一致：weight 步长是 0.05，不是 0.1

文章写“范围 -1～5，每次 0.1”。源码里两个节点的 weight 都是 {"default":1.0,"min":-1.0,"max":5.0,"step":0.05}。滑杆实际刻度是 0.05，文章差了一倍。

fidelity 数值越低越像参考图。
cubiq README 加粗原文：“Lower fidelity values grant higher resemblance to the reference image.” 默认值是 8，往下调更像，往上调更松。
两个节点的等价关系（README 原文）：
· Advanced 的 ortho_v2 + fidelity: 8 = 标准节点的 fidelity method
· ortho + fidelity: 16 = 标准节点的 style method
· neutral 在标准节点里不做归一化，README 建议同时把 weight 调低；换到 Advanced 就直接调高 fidelity
// 源码里的分支等价（pulid.py）
# method==fidelity 或 projection==ortho_v2 → 同一分支
# method==style    或 projection==ortho   → 另一分支
# 所以切换节点不会自动对齐观感，必须自己换算 fidelity 值
06
DEPENDENCY CHAIN

依赖链：版本被钉死，顺序不能乱

PuLID 官方 requirements 把 PyTorch 钉在 2.0.1，这一行决定了你的 ComfyUI 环境能不能同时跑别的节点。

// requirements.txt 与 requirements_fp8.txt 的关键差异
# requirements.txt（默认）
torch==2.0.1          torchvision==0.15.2
diffusers==0.25.0       transformers==4.43.3
facexlib / insightface / onnxruntime / onnxruntime-gpu / timm / einops ...

# requirements_fp8.txt（flux-fp8 用）
torch==2.4.1          torchvision==0.19.1
diffusers==0.30.0       transformers==4.43.3
optimum-quanto==0.2.4   ← 只在 fp8 版本里出现
版本冲突点

两套依赖不共存

torch 2.0.1 与 2.4.1、diffusers 0.25.0 与 0.30.0 是两条路。要 fp8 就整套换 fp8 版本，别混装。

自动下载

EVA02-CLIP-L-14-336

cubiq README：EVA CLIP 用的是 EVA02-CLIP-L-14-336，首次运行会自动下载，放在 huggingface 目录里。facexlib 的模型也是首次使用时下载。

手动放置

AntelopeV2

README 要求解压后直接放到 ComfyUI/models/insightface/models/antelopev2。源码里 FaceAnalysis(name="antelopev2", root=INSIGHTFACE_DIR, ...)，root 指向 models/insightface。

顺序建议：先在 ComfyUI Manager 里装插件 → 确认节点出现 → 放 PuLID 权重到 ComfyUI/models/pulid/ → 放 AntelopeV2 到 models/insightface/models/antelopev2 → 首次运行下载 EVA CLIP 与 facexlib 模型 → 再跑推理。反过来做，第 3 步的自动下载会失败，报错也更难读。

关于“嵌套两层目录”导致 'detection' not in self.models：这是社区常见故障的说法，本轮在 cubiq README 里只看到放置路径要求，未找到官方文档明确写这条，因此标为社区经验。
