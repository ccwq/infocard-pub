Tailcat：没有 Tailscale 的 Tailscale

⚙ 架构拆解：三层组件如何协作

Tailcat 复用 Tailscale 的三个核心组件，无控制平面依赖：

① WireGuard 用户态实现

不走内核 TUN/TAP 设备，不接管路由表，不改 DNS。Go 实现的 wireguard-go 在用户态完成 WireGuard 握手与加密，所有流量通过 magicsock 路由。系统只看到 DERP 的 TCP 或直连 UDP，不感知 VPN 接口。

② magicsock 传输层

Tailscale 自研传输层，多路复用直连 UDP 与 DERP 中继。通过 STUN 发现公网端点（IP:port），用 Disco 协议交换 call-me-maybe 消息执行 UDP hole-punchingNAT 穿透。穿透成功则升级为直连 peer-to-peer；失败则降级走 DERP，全程透明。

③ DERP 中继协议

Tailscale 的加密 relay 协议，端口 443。充当 NAT 穿透的 rendezvous 信道（双方通过它交换公网端点），也是直连失败后的 fallback 数据路径。Tailscale 托管的公共 DERP 有带宽限速；可自建 cmd/derper 绕过限制。

连接路径选择逻辑：启动 → DERP rendezvous → 双方交换 UDP 端点 → hole-punching 尝试 → 成功则直连（无中继），失败则走 DERP relay。路径切换全自动，无需用户干预。

⬡ Go Library：用代码接管连接

Tailcat 既是 CLI 工具，也是 Go 库（github.com/tailscale/tailcat）。零值 Server/Client 均开箱即用，支持深度定制：

服务端

// 最小化 TCP 服务器
import (
  "fmt"
  "log"
  "net"
  "github.com/tailscale/tailcat"
)

s := &tailcat.Server{
  OnTCP: func(port uint16) func(net.Conn) {
    return func(c net.Conn) {
      fmt.Fprintf(c, "hello from port %v\n", port)
      c.Close()
    }
  },
}
if err := s.Start(); err != nil {
  log.Fatal(err)
}
fmt.Println(s.ConnBlob())  // 打印 token，发给客户端
select{}

客户端

// 最小化客户端（懒建立隧道）
import "github.com/tailscale/tailcat"

conn, err := tailcat.NewClient(&tailcat.Client{
  Server: token,  // Server 字段填入对方的 ConnBlob
}).Dial(context.Background(), "tcp", ":8080")
defer conn.Close()

⬡ SOCKS5 代理：让任意程序走 WireGuard 隧道

Tailcat 内置 SOCKS5 代理模式，server 启动 SOCKS5 监听本地随机端口，并将请求通过 WireGuard 隧道转发给 client，client 充当出口节点：

# 机器 A（出口）：启动 SOCKS5 代理模式
$ tailcat serve --socks5
# 输出：SOCKS5 listening on 127.0.0.1:随机端口
# 同时输出 ConnBlob token，发给机器 B

# 机器 B（入口）：连接并代理
$ tailcat connect <TOKEN>
# 所有出口流量经 WireGuard 隧道到达 A，从 A 的 IP 发出

# 任意程序透明使用（Linux/macOS）
$ ALL_PROXY=socks5://127.0.0.1:随机端口 curl https://api.ip.sb/ip
# 返回的是机器 A 的公网 IP
透明代理原理：Tailcat 在 server 侧运行一个标准 SOCKS5 服务（RFC 1928），任何支持 ALL_PROXY 环境变量的程序（curl/wget/git/apt）均可无感使用。流量加密穿越 WireGuard 隧道，client 侧无需安装任何代理软件。

典型使用场景

跨境访问

在海外 VPS 上运行 tailcat serve --socks5，本地走隧道出口访问被地理限制的内容。

内网穿透测试

暴露本机 8080 端口给协作者，对方通过 SOCKS5 访问你的本地开发服务。

隐私出口

不想在公共 WiFi 直接发送流量时，通过隧道将所有 TCP 流量加密到可信机器再出口。

Git 加速

ALL_PROXY=socks5://... git clone 走海外出口，GitHub 访问速度提升。

⬡ SSH 内置模式：零配置远程 Shell

Tailcat Server 可选启动内置 SSH 服务器，客户端直接 ssh tailcat@... 进入，无需 OpenSSH 配置：

# 机器 A：启动 SSH 服务器（监听 22 端口）
$ tailcat serve --ssh
# 输出 ConnBlob token

# 机器 B：连接并获得 Shell
$ tailcat ssh <TOKEN>
# 直接进入机器 A 的 Shell，WireGuard 加密隧道
SSH 安全性：内置 SSH 使用 token 验证（无密码/密钥），隧道走 WireGuard 端到端加密。适合临时接入内网机器，不建议替代长期 SSH key 管理。

⬡ 自建 DERP：零信任中继方案

若对 Tailscale 托管的 DERP 中继存在零信任顾虑，可运行完全自托管的 DERP 服务器，Tailcat 支持指定自定义 DERP map：

# 部署自建 derper（需要域名 + TLS 证书）
$ go install tailscale.com/cmd/derper@latest
$ ./derper -a :443 -certs-dir /etc/ssl/derper/

# 构建自定义 DERP map JSON
$ cat > my-derp-map.json <<'EOF'
{
  "regions": [{
    "regionid": 9001,
    "regioncode": "myserver",
    "regionname": "My DERP",
    "nodes": [{
      "name": "a",
      "regionid": 9001,
      "hostname": "derp.example.com",
      "certname": "derp.example.com",
      "ipport": "derp.example.com:443"
    }]
  }]
}
EOF
# 启动 Tailcat Server 使用自建 DERP
$ tailcat serve --derp-map-url https://example.com/my-derp-map.json
DERP 自建优势：中继带宽完全自控，无第三方限速；日志可审计；可部署在低延迟机房改善传输质量。代价是需要维护一台有公网 IP 的服务器。

⬡ 诞生记：从 derpcat 到 Tailcat

Tailcat 并非凭空诞生。2023 年 9 月，Tailscale 工程师在一次跨大西洋航班（UA605 ORD→Ireland）上写下了第一个版本，命名为 derpcat（DERP + netcat）。最初代码位于 tailscale.com 仓库的 fork 中，随着上游代码演进多次 bitrot。

2026 年 8 月，Tailscale 将其重构为独立的 Go module（不再 fork tailscale.com，而是作为 regular client），正式以 Tailcat（Tail + netcat）之名在 TailscaleUp 大会上开源。ConnBlob 格式经过重新设计，token 交换机制从 base64 编码改为更紧凑的二进制格式。

从最初的航班随手项目到生产可用的库/CLI，开源版本已是第三个 major iteration，代码质量与 Tailscale 主线保持一致。

⬡ ConnBlob：token 格式解析

Server 启动后输出的 ConnBlob 是一个紧凑的二进制编码字符串，包含建立 WireGuard 隧道所需的全部信息，接收端不需要知道 server 的 IP：

ServerPublicWireGuard 公钥（用于建立隧道）
ServerDiscoPublicDisco 公钥（用于 NAT 穿透信令）
DERP Region中继区域信息（server 时指定 RegionID）

ConnBlob 格式经过 2026 开源版本重新设计，从早期 base64 编码改为更紧凑的二进制格式，token 长度更短，适合通过 IM/邮件传输。

⬡ Go 库进阶模式：生产用例

模式 1：HTTP 代理服务（暴露本地 API）

package main

import (
  "context"
  "log"
  "net"
  "net/http"
  "github.com/tailscale/tailcat"
)

func main() {
  // 启动本地 HTTP 服务
  go http.ListenAndServe(":8080", nil)

  // 通过 Tailcat 暴露它
  s := &tailcat.Server{}
  s.OnTCP = func(port uint16) func(net.Conn) {
    return func(c net.Conn) {
      // 将进入的连接转发到本地 8080
      // （实际使用应建立双向 pipe）
      c.Close()
    }
  }
  if err := s.Start(); err != nil {
    log.Fatal(err)
  }
  log.Printf("Token: %s", s.ConnBlob())
  select{}
}

模式 2：带日志的文件传输服务

import "github.com/tailscale/tailcat"

s := &tailcat.Server{
  Logf: func(fmt string, args ...any) {
    log.Printf("[tailcat] "+fmt, args...)
  },
  OnTCP: func(port uint16) func(net.Conn) {
    return func(c net.Conn) {
      buf := make([]byte, 1024)
      for {
        n, err := c.Read(buf)
        if err != nil { break }
        log.Printf("received %d bytes", n)
        c.Write(buf[:n])
      }
      c.Close()
    }
  },
}

模式 3：exit node 出口代理

// 客户端：作为出口代理
c := tailcat.NewClient(&tailcat.Client{Server: token})
conn, _ := c.Dial(context.Background(), "tcp", ":0")
// conn 是 WireGuard 隧道内的连接
