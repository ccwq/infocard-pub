解决了什么问题

会话日志记录了 Agent 做了什么，但不记录它如何理解任务：它认为仓库的哪些部分相关？在哪里先探索再行动？它的足迹是否匹配你预设的范围？逐行读原始 JSONL 什么都回答不了。

Mindwalk 的核心直觉：Agent 的工作范围和你以为的往往不一样。当它跑了 30 分钟，你以为它读遍了整个仓库——但地图可能告诉你它根本没碰到关键目录。

核心功能

  • Tree / Terrain 视图 — 仓库的径向树或矩阵地图；发光强度 ∝ 文件被触达的深度和频率
  • 四级文件触达状态 — 未访问（暗）、已查看（苔绿）、已读取（月白）、已编辑（暖琥珀）
  • 播放控制条 — 冷色（搜索/读取/执行）到暖色（编辑/验证）的光谱，直观看出编辑阶段
  • 时间轴标记 — ◇ 上下文压缩、○ 子 Agent 启动、› 用户输入；均可点击跳转
  • Inspector — 点击文件固定访问历史，点击访问行跳转到播放头的对应时刻
  • Session Evaluation — 调用本地 Claude / Codex CLI，让 Agent 评判会话轨迹，给出锚定到时间轴事件的评估报告

底层架构（三个分离的构件）

构件作用
Trace将会话日志归一化为有序的文件触达事件流（internal/adapter，每种 Agent 格式一个 adapter）
Citymap仓库的确定性布局（internal/citymap）；同一棵树始终生成同一张地图，保证不同会话可对比
ReportLLM Judge 的证据锚定发现（internal/judge）；Judge 只贡献发现，裁决始终由机械逻辑汇总，保证报告可比性

本地 Go 服务（internal/server）串联三者并提供 React/Three.js 前端（web）。schema/ 镜像导出的 JSON 合约。

隐私保护 — 数据不离机器

单个 Go 二进制，所有数据完全本地处理。查看会话时不发送任何内容到任何地方。

唯一的例外（需用户主动触发）：Session Evaluation 时，会将当前会话摘要（用户消息措辞、文件路径、事件摘要）发送到你的 claude 或 codex CLI 背后的模型。Judge 子进程以密封模式运行：无工具调用、无 MCP 服务器、无用户/项目设置、无会话持久化。

报告缓存在 ~/.mindwalk/reports，会话内容变化后自动失效（不会自动重跑）。

快速安装

curl -fsSL https://raw.githubusercontent.com/cosmtrek/mindwalk/master/scripts/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
mindwalk

安装程序校验二进制签名并安装到 ~/.local/bin（可用 INSTALL_DIR 覆盖，VERSION 固定版本）。Windows 在 GitHub Releases。源码构建：make setup && make build。

无参数启动：自动扫描 ~/.claude/projects 和 ~/.codex/sessions，在随机本地端口提供 UI 并打开浏览器。

什么时候用

  • 用 Claude Code / Codex 跑复杂任务，想检查它是否真的理解了任务范围
  • 任务跑了很久但结果不对，想诊断 Agent 在哪里「跑偏」
  • 想直观对比不同 prompt 或参数下的 Agent 行为差异
  • 团队 Code Review 时，用可视化会话轨迹代替逐行读 JSONL
