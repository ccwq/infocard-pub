01 / ARCHITECTURE

架构：像 Docker 一样理解 Paseo

daemon 跑在你的电脑/服务器/Docker 里，管理 Agent 生命周期；客户端只是遥控器。代码永远不离开你的机器。Provider 是 Paseo 与外部 CLI 的契约——怎么启动、怎么流式输出、怎么回传输入、支持什么模式，二进制本体就是你已认证安装的那个。

层是什么关键事实
Daemon本机服务，端口 6767，WebSocket API + 内置 MCP server桌面版自带 daemon 开箱即启；CLI npm i -g @getpaseo/cli；Docker 镜像 ghcr.io/getpaseo/paseo 自托管 Web UI
Provider 两级原生适配（Claude Code/Codex/OpenCode/Pi）+ ACP 通用目录ACP 覆盖 Cursor、Gemini、GitHub Copilot、Hermes、Kimi、Qwen Code 等 25+；也可在 ~/.paseo/config.json 自定义端点/别名/二进制
Workspace任务容器：多个 agent 会话 + 终端 + 浏览器 + diff 同住隔离二选一：local 直接用现有目录；worktree 创建受管 git worktree，最后一个 workspace 归档后自动删除
连接三通道SSH 隧道 / Paseo Relay / TailscaleRelay 默认关闭、扫码配对启用；Curve25519 ECDH 端到端加密，官方 relay 是开源 Elixir 服务（getpaseo/paseo-relay），设计为「不可信也可用」

隐私口径核实：README 原文 "no telemetry, tracking, or forced log-ins"；配对/中继全部显式 opt-in，不开 relay 时走直连 TCP/Tailscale/VPN。

02 / ORCHESTRATION SKILLS

三个内置编排模式：交接、顾问、委员会

官方 skills 一键安装（npx skills add getpaseo/paseo），装完在任何 Agent 对话里直接用斜杠命令。作者自己的用法就是推文那个场景：「和 Claude 规划，然后 handoff 给 Codex 实现」。

/paseo-handoff

交接

把任务连同上下文交给另一个 Agent 接着干。规划用 Claude（opus-4.6）、实现换 Codex（gpt-5.5）——CLI 原语：paseo run --provider codex --background + paseo send 追加指令。

/paseo-advisor

顾问

临时拉一个 Agent 只给第二意见，不交出工作本身。适合 diff 审查：「找出风险最高的改动」——worker 出现在 Subagents 轨道，完成时主 Agent 收通知，期间你还能继续对话。

/paseo-committee

委员会

两个思路相反的 Agent 凑一组，跳出来做根因分析并产出计划。用 provider 差异制造视角差——比如一个保守一个激进，交叉验证卡住的问题。

进阶机制（推文没讲）：MCP 工具注入默认关闭（Settings → Agents 手动开启），开启后 Agent 能直接启动/协调同机其他 Agent；agent profiles 把 provider+model+thinking 级别存成一键档案；schedules 定时跑 prompt、heartbeats 周期性催同一个 Agent 续任务；TypeScript SDK（@getpaseo/client）把整套编排暴露成十行代码的编程接口。

03 / BOUNDARIES

上手前想清楚的四件事

前提

Agent CLI 得自己装好

Paseo 不分发任何 Agent。五家 CLI 各自要装好、配好凭据；它只是启动与监督。没有 Claude/Codex 订阅的话，Paseo 本身帮不了你省 token。

成本

免费开源，作者靠赞助

Apache-2.0（LICENSE 实文；GitHub API 元数据误标 NOASSERTION）。Mohamed Boudra 一人开发（4,786/5,100+ commits），README 自述「built by one person and funded by the people who use it」。

体积

桌面端不小

Electron + daemon：deb 123MB、dmg 170MB。手机走 App Store/Play 或直连自托管 Web UI；服务器场景 Docker 更干净。VS Code 也有社区扩展 paseo-vscode。

安全边界

插件与工具注入是权限面

TS 插件能访问 daemon 所在机器；MCP 工具注入默认关。官方文档明说「只装你信任的代码」——编排能力越强，信任链越要自己管。

判断：编排层之战已经开打，Paseo 抢到了先手

Verdict & Next Actions

  • 定位稀缺：Agent 数量在涨、窗口切换成本在涨——Paseo 卡的是「跨 Agent 协作」这一层，且四端 + 自托管 + 无遥测的组合目前没有同级对手。
  • 数据说话：18K star 不是故事，330 万下载才是——已过「玩具期」，但 0.9.x 版本号提醒你 API 还在动，SDK 依赖别写死。
  • 风险认知：单人项目 + 众筹模式，企业级 SLA 别指望；插件与工具注入是真实权限面，装第三方 provider 插件前看代码。
  • 今天就能试：装桌面版 → npx skills add getpaseo/paseo → 拿一个规划+实现分离的任务跑一次 /paseo-handoff，再决定要不要接进日常流。
