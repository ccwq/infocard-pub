USAGE MODES · 三种运行模式
PAGE 06

文档里提到的三种模式怎么用？

目标模式（Goal mode）
给主 Agent 一个「最终目标」，LLM 自动拆分 + 规划 + 执行。
示例：「把这个前端项目迁移到新的设计系统。」
子代理模式（Sub-agent mode）
提前注册子代理角色（架构师 / 编码 / 测试），按任务阶段调度。
示例：架构代理规划 → 编码代理实现 → 测试代理验证
工作包模拟模式（Work package simulation）
只生成「任务拆解 + 执行计划」，不直接改代码，适合事先审核。
示例：先生成计划 → 审核 → 决定是否放权自动执行

HOW IT WORKS · 工作原理
PAGE 01

LLM 生成 JS 编排脚本

STEP 1

你只需要描述任务目标（用自然语言）

STEP 2

LLM 自动生成一段 JavaScript 编排脚本，包含：任务拆分、并行/串行逻辑、验证机制、收敛条件、错误处理

STEP 3

JS 脚本自动调度执行，主 Agent 只接收最终答案

KEY FEATURES · 核心特性
PAGE 02

为什么更省 token？

✓
中间结果隔离
子代理结果只存在 JS 变量里，主 Agent 上下文不膨胀。
⚔
对抗性验证
部分子代理专门找漏洞、互相反驳，提升结果质量。
↺
断点恢复
进度实时保存，中断了可从中断处继续。
BOTTOM LINE
PAGE 03

比 Claude Code 原生版本更省 token

传统方案里，所有中间结果都要塞进主 Agent 的上下文窗口。动态工作流通过 JS 变量做信息隔离，让主 Agent 只看到最终答案，从根本上降低 token 消耗。

COMPARISON · 三种模式对比
PAGE 04

为什么动态工作流更好？

模式 特点 问题
传统 Subagent 子代理之间无法直接通信，所有信息靠主 Agent 中转。 上下文爆炸，token 消耗大。
Agent Team 解决了子代理之间的通信问题。 最多跑 3-5 个实例，多了就乱；会话一断，状态全丢。
动态工作流 ✓ 中间结果只存在 JS 变量里，主 Agent 只看到最终答案；内置对抗性验证；进度实时保存，可断点恢复。 —
