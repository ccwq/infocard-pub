01
Problem

AI 算命瞎编的根源：幻觉 + 无算法根基

纯 LLM 做命理分析的通病——不是"不够聪明"，是从根本上就做不了这件事

幻觉问题

LLM 不知道正确的排盘规则

大语言模型没有内置天文历法知识。八字四柱需要精确的干支换算、闰月处理、节令判断；紫微斗数需要安命宫、起五行、演十二宫——任何一步算错，后续全盘失真。

  • 日柱天干错位（60 甲子口诀随机
  • 闰月生人命盘错位
  • 大运起运岁数算反
推理幻觉

"看起来对"不等于"算对了"

LLM 会用流畅的语言输出看似专业的分析，但推理链建立在错误排盘之上，结论是沙上之塔。引用古籍条文≠算法正确，置信度不等于准确率。

  • 用推理代替计算（置信度≠准确率）
  • 用文学性掩盖算法错误
  • 格局判断无确定性依据
无增量

任意 LLM + 任意工具 ≠ 本 Skill

网上大量"AI 算命"本质是套壳 Prompt：无算法根基、无交叉印证、无格局补层、无海报输出。换一个 Prompt 换一个说法，无系统性可言。

  • 无独立八字/紫微算法层
  • 无八字×紫微交叉对账
  • 无结构化 HTML 海报输出

⚠ 典型错误案例（LLM 幻觉示意）

错误类型
闰月 1990 年 6 月生，日柱算成"甲子"而非正确干支
错误类型
大运起运岁数直接按月龄均分，忽略节气节令
错误类型
把"身强"误判为"从强"，调候用神全部写反
错误类型
紫微盘命宫起错，整盘十二宫全部偏移

以上均为真实场景中 LLM 单独运作时的高频错误。根本解法：把排盘交给确定性算法，LLM 只做后端的分析与解读。

02
Solution

本地精准排盘：Yiqi + lunar-typescript 算法层

确定性算法负责排盘，LLM 负责分析——职责分离，从源头切断幻觉

排盘核心

Yiqi 算法库（MIT）

八字四柱、紫微十二宫、大运流年由开源项目 Yiqi（fdxuyq/Yiqi-BaZi-ZiWei）提供，经实测对齐权威排盘结果。

  • 八字：年柱、月柱、日柱、时柱精准换算
  • 紫微：安命宫、起五行、演十二宫
  • 大运流年：节令判断、起运岁数精确
农历换算

lunar-typescript（MIT）

农历 ↔ 公历双向精确换算，处理闰月、节气交接、真太阳时等边界条件。

  • 闰月生人正确归属月令
  • 节气精确到分钟级判断
  • 真太阳时（可选）
🧮
格局补层算法
旺衰判断、调候用神、刑冲合害、盖头截脚——喂给 LLM 做有依据的分析，而非让 LLM 自己猜
🔒
本地隐私优先
所有排盘在本地完成，无需联网。运行产物默认 gitignore，不留痕。
📦
零运维依赖
算法层仅一个 npm 依赖（lunar-typescript），无数据库、无外部服务。
# 排盘核心流程（纯本地） node dist/run-chart.js --year=2000 --month=1 --day=1 --hour=12 --minute=0 --gender=male # 输出 JSON → 文墨天机风文本盘 node dist/dump-text.js --input=chart.json --output=chart.txt # JSON + 分析 + 模板 → 单文件 HTML 海报 node dist/render.js --chart=chart.json --analysis=analysis.json --template=../templates/report-zonghe-poster.html --output=report.html --currentYear=2026
03
Play Modes

三种分析模式：八字 / 紫微 / 综合印证

按需选择深度，适合不同场景——轻量查询、学术分析、深度综合解读

Mode A八字独立

八字独立分析

纯八字体系：年柱、月柱、日柱、时柱 + 大运流年 + 格局旺衰 + 调候用神 + 刑冲合害。

  • 格局判断（正格/从格）
  • 旺衰分析
  • 调候用神
  • 刑冲合害
  • 大运流年断事

输出：Markdown 长文深度版

Mode B紫微独立

紫微斗数独立分析

纯紫微体系：紫微星入宫、十二宫配置、星曜组合（紫微/天机/太阳等）+ 大限流年。

  • 命宫主星判断
  • 十二宫配置解读
  • 星曜组合分析
  • 大限流年推演
  • 四化飞星（可选）

输出：Markdown 长文深度版

Mode C综合印证

八字 × 紫微 综合印证

两套体系结论交叉对账：主轴是否一致、人生窗口是否对齐、冲突时优先信哪套。

  • 主轴一致性判断
  • 人生窗口对齐校验
  • 冲突优先级决策
  • 两套结论互补输出

输出：长文版 + 水墨风 HTML 海报版

💡 综合印证的价值：为什么需要两套体系？

一致性高
八字格局与紫微命宫配置相互印证，结论置信度大幅提升
局部冲突
某一阶段两套体系指向不同方向，提示该阶段需更谨慎决策
深度冲突
八字与紫微结论完全相反，提示该阶段可能存在隐藏变量或特殊格局
增量洞察
紫微擅长性格与关系解读；八字擅长事业与财运判断——两者互补而非替代

这是本 Skill 区别于"任意 LLM + 任意排盘工具"的核心增量——不是两个结果，是一套交叉验证方法论。

06
Architecture

目录结构：算法层 + 提示词 + 模板三层分离

LLM 只负责"分析"，排盘和画 HTML 由确定性模块负责——三者各司其职

bazi-ziwei-skill/   ├── SKILL.md            # Skill 主入口（Agent 读这个）   ├── TEST-GUIDE.md         # 测试指南（5 条用户路径）   ├── calculator/            # 算法层   │  ├── run-chart.ts         # 排盘入口：生辰 → JSON   │  ├── dump-text.ts         # JSON → 文墨天机风文本盘   │  ├── render.ts           # JSON + 分析 + 模板 → HTML   │  ├── yiqi-core/           # 排盘核心算法（vendored from Yiqi, MIT）   │  └── bazi-enrich/          # 格局/旺衰/调候/刑冲合害 补层算法   ├── prompts/            # 提示词目录   │  ├── bazi-prompt.md       # 八字独立分析   │  ├── ziwei-prompt.md       # 紫微独立分析   │  ├── zonghe-yinzheng-prompt.md # 综合印证（长文）   │  └── zonghe-poster.md   # 综合印证（海报 JSON 输出）   ├── templates/           # HTML 模板   │  └── report-zonghe-poster.html # 综合印证海报模板   └── examples/           # 合成示例（2000-01-01 男，非真人）

🔑 关键设计原则

排盘
确定性算法，零随机性，零幻觉
分析
LLM 只负责解读，不负责计算
呈现
固定模板渲染，零 LLM 幻觉污染
补层
格局/旺衰/调候算法增强 LLM 推理依据

Quick Start

快速安装：三步上手

Node.js ≥ 18 即可运行，无其他系统依赖

# Step 1 · 克隆仓库 git clone https://github.com/dzcmemory-web/bazi-ziwei-skill.git
# Step 2 · 安装算法层依赖（仅 1 个 npm 依赖） cd bazi-ziwei-skill/calculator && npm install # 需要 Node.js >= 18
# Step 3 · 注册到 Agent（示例：Claude Code） mkdir -p ~/.claude/skills/bazi-ziwei/ cp -r /path/to/bazi-ziwei-skill/ ~/.claude/skills/bazi-ziwei/
# Step 4 · 开始使用（直接对 Agent 说） "我是 2000 年 1 月 1 日中午 12 点出生的男生，帮我看下命盘。"
# 验证安装（命令行直接排盘，不经 Agent） cd calculator node dist/run-chart.js --year=2000 --month=1 --day=1 --hour=12 --minute=0 --gender=male # ✓ 输出 chart.json 即成功
