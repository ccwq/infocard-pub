AGENT ENGINEERING / TECHNICAL GUIDE

Agent Skills：从能力封装到长期运行

把可复用的做事方法封装成清晰、可调用、可维护的能力单元，再把它放进更长周期的任务流程中。

核心判断：Skill 不只是“多一条指令”，而是把一类任务的知识、步骤、约束与验收方式组织起来，让 Agent 在重复场景中更稳定地行动。

01

一门约 2 小时的学习路线

从概念到可运行的能力单元
理解问题为什么 Agent 需要可复用的工作方法。
拆出能力把任务目标、步骤、边界与产出拆开。
写成 Skill用明确说明组织触发条件与执行方式。
组合调用让能力进入更大的任务流程。
持续运行为长任务提供阶段化、可恢复的支撑。
02

从零构建 Agent Skills

实践建议，不是额外事实
先定义

1｜写清“什么时候用”

先描述任务类型与触发场景，再写执行细节。一个好的 Skill 应让 Agent 知道何时应该调用它、何时不该调用它。

再组织

2｜把方法变成步骤

将目标、输入、操作顺序、判断点和输出格式排成可检查的路径，避免只留下宽泛的经验描述。

加边界

3｜明确约束与例外

说明不能做什么、缺少什么信息时如何处理，以及哪些情况需要停下来确认。

最后验收

4｜用结果检验能力

不要只检查“有没有执行”；还要检查产出是否符合格式、范围、可读性与任务目标。

03

预构建 Skills：拿来用，也要会判断

把现成能力当作可复用模块

适合直接使用的情况

任务边界清楚、目标与现成 Skill 的适用场景一致，并且输出要求不需要大幅改造时，可以先调用，再根据结果微调。

需要审查的地方

检查触发条件、依赖条件、输出格式和失败处理。预构建不等于自动适配当前任务。

实践建议：先读懂，再组合

将预构建 Skill 看作一份经过整理的工作方法。先确认它解决什么问题，再决定是直接使用、局部调整，还是与其他能力串联。

04

Skills、Tools、MCP、Subagents 怎么区分？

核心概念对照
对象核心作用更像什么在任务中的位置
Skills封装一类任务的方法、步骤、约束与验收。工作方法 / 操作手册指导“如何稳定完成一类事”。
Tools提供可执行的具体动作或接口。工具 / 扳手负责“实际做某个动作”。
MCP让模型与外部能力或资源建立统一连接方式。连接层 / 插座负责“把能力接进来”。
Subagents把任务分派给相对独立的 Agent 处理。协作者 / 工作小组负责“由谁来处理某个子任务”。

一句话记忆

Skill 定方法，Tool 做动作，MCP 接能力，Subagent 分工作。它们可以组合，但不是同一个层次的东西。

05

长时间运行任务中的 Skills

让过程可持续，而不是只追求一次完成

阶段化

把大任务切成若干阶段，每个阶段都有明确目标、输入、输出和完成信号，减少上下文混乱。

可恢复

为中断、失败和重新进入预留路径：记录当前状态，明确下一步，避免从头开始。

可观察

让过程留下可检查的中间结果与判断点，便于发现偏差，而不是等到最终输出才验收。

可复用

将重复出现的处理模式沉淀回 Skill，逐步减少每次长任务都重新设计流程的成本。

06

落地检查清单

实践建议
触发清楚

能否判断何时应该调用，何时应该绕开？

步骤可读

另一个执行者能否按顺序理解并复现？

边界明确

输入不足、冲突或失败时是否知道怎么处理？

输出可验

是否有格式、质量或完成标准可供检查？

适合组合

能否与工具、连接层或子任务协作而不混淆职责？

支持持续

长任务中断后，是否能从状态与下一步继续？

核心结论
Skills 的价值在于把能力变成可复用、可组合、可持续的工作方法。
