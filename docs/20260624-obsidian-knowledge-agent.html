Obsidian Knowledge Agent

自进化的 Obsidian 知识 Agent——把 PDF、论文、教学大纲、URL 等原始材料自动转化为教学级笔记。三档智能匹配深度，六阶段流水线，每次纠正自动变成下次的规则。支持 Claude Code / Codex / Cursor。

为什么值得看

大多数 AI 笔记工具每次都用同样的规则运行。这个不一样——它会自进化：你对笔记的每次纠正会被捕获为 markdown 规则差异（git diff），审批后自动应用到下次运行。不需要微调，不需要黑盒。它借鉴了 Hermes 的文件学习模型：Agent 重写自己的 markdown，而不是权重。

自进化循环

纠正 → 规则 → 自动应用

每次运行后反思，提出规则差异供你审批。审批后写入 .agents/learned/，下次自动召回。

Ingest → Compile → Distribute 六阶段流水线执行

01
智能匹配

三档高度——需要多少做多少

不强制每条输入走完整流水线。Agent 自动判断材料需要的深度，只在必要时升级。

高度适用场景产出
Capture一条链接、一个想法、一篇文章——"保存这个"一张干净的笔记，归档到正确位置
Small Collection少量相关来源、一个小主题几张笔记 + 轻量索引
Full Build教学大纲、一本书、大型论文集完整脚手架：索引、导航、质量审查、概念图谱画布
适配你的 Vault：不强制分类法。学术 Vault 的 School/、ML/、Quant/ 只是空 Vault 默认值；工作 Vault 的 Projects/ Meetings/ People/ 同样适用。Agent 读取你已有的文件夹结构、命名方式和 frontmatter，按你的习惯来。
02
核心差异

自进化——越用越懂你的 Vault

大多数 AI 笔记工具永远用同样的规则运行。这个会累积：用得越多，越匹配你 Vault 的品味。

① 约定学习

你的 Vault 风格纠正 → conventions.md。以 git diff 形式供你审批。

② 分类示例

如何分类你的输入类型 → examples.md。Few-shot，有上限，最近优先。

③ 技能剧本

全新来源类型的处理剧本 → skills/*.md。每种输入形状一个剧本。

④ 运行日志

每次运行的完整历史 → journal.md。只追加，永不重写。

两层自治：日志自由写入；规则变更始终以 diff 形式提交给你审批——它在学习，但不会悄悄漂移。
03
流水线

六阶段流水线：Recall → Reflect

从召回已学规则到反思并提出规则更新，完整覆盖知识摄入生命周期。

阶段步骤发生了什么
RecallStep 0加载 .agents/learned/ — 应用已学约定、few-shot 示例和匹配的技能剧本
Ingest0分类输入（课程/书/论文集/单一来源/主题构建），提取结构图，解析目标路径
Compile1–3搭建文件夹树 + 索引文件，写教学级内容/来源/概念笔记，构建概念图谱画布
Distribute4–5连接 prev/next 导航，验证每个 wikilink，运行并行教学质量审查
Commit6提交集合；在明确审批策略下清空 Inbox/
Reflect7追加日志条目；提出持久规则/剧本更新供你审查

轻量 Capture 和 Small Collection 只运行需要的阶段——不是每条输入都走完整流水线。

04
命令

11 条斜杠命令

Claude Code 中通过 /obsidian-knowledge: 前缀调用。也支持自然语言——"research X"、"organize my inbox"。

捕获 & 构建
# 保存一条快速笔记
/obsidian-knowledge:capture <url>

# 从 Inbox 构建笔记，自动选深度
/obsidian-knowledge:ingest

# 从网络研究主题并写教学笔记
/obsidian-knowledge:research how RoPE works

# 追加今日日志
/obsidian-knowledge:log shipped the parser
改进 & 维护
# 就地改进笔记
/obsidian-knowledge:polish ML/Transformers

# 安全重组并重连 wikilink
/obsidian-knowledge:refactor split the Transformers note

# 健康检查：断链/孤儿/缺 frontmatter
/obsidian-knowledge:doctor

# 提交笔记 + 清空 Inbox + push
/obsidian-knowledge:clean
学习
# 捕获最近工作的教训，提出规则更新
/obsidian-knowledge:reflect

# 审查并批准 Agent 的规则变更提案
/obsidian-knowledge:evolve

推荐首次流程：:setup → 放入来源 → :ingest → :polish → :reflect

06
笔记质量

什么让笔记"好"

不是把信息塞进模板就完了——笔记要像人愿意回看的东西。

教学笔记风格指南

  • 笔记读起来像人愿意回看的文字，机器藏在幕后
  • 深度 ML/Quant 笔记在真正有帮助时使用可运行代码块、LaTeX 公式、Mermaid 图
  • 不会为了填充而堆砌——不需要的图表就跳过

工程质量

  • 概念图谱画布 — 3+ 单元的集合自动生成 JSON-Canvas 概念关联图
  • 链接完整性 — Python 验证器在提交前检查断链，处理图片/PDF 嵌入、块引用、标题锚点
  • 并行工作者 — 笔记写作和质量审查可 fan-out 到多个 Agent 并行
07
边界

适合谁，不适合谁

了解工具的边界才能最大化收益。

✓

适合

Obsidian 用户 + AI 编程工具。需要把课程/论文/书籍整理成结构化笔记的学生和研究者。想要 AI 适配自己 Vault 习惯而不是反过来的人。知识工作者需要持续捕获和整理信息。

!

注意

124 stars 早期项目，功能仍在快速迭代。自进化规则需要你审批——不是全自动的。需要基本了解 Obsidian 的 Vault 和 wikilink 概念。

×

不适合

不用 Obsidian 的人（核心依赖 Obsidian Vault 结构）。需要离线/私有部署的知识管理（Agent 需要 LLM API）。非 markdown 工作流。
