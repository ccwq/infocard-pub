Yao Interpreter Skill

这不是一个“执行 Skill”的工具，而是一个“解读已有 Skill”的解释器：把本地 Skill 目录、单个 SKILL.md 或安全 zip 归档当作不可信输入，做静态分析、证据链评分、风险审查和使用指导，最后输出中文优先、可切中英的 HTML 审计报告。

输入对象本地 skill 目录、SKILL.md、或安全 zip 归档。
关键边界不执行目标脚本、不安装依赖、不访问目标外部服务。
主要产物HTML / JSON / findings / QA / summary 多文件证据包。
评分维度
9

把 Skill 变成可审计的“可读资产”

01
静态读取

读取目录、脚本、references、examples、schemas 和 manifest，但不把目标内容当成本轮指令执行。

核心定位
PAGE 03

它是 Skill 解释器，不是 Skill 运行器

Yao Interpreter Skill 最重要的边界是：目标 Skill 一律按不可信输入处理。它评估“这个 Skill 值不值得学、能不能用、风险在哪、如何改”，而不是帮你去跑目标 Skill 的脚本、安装器、测试或模型提示。

输入边界
PAGE 05

支持三类输入载体

A
Skill 目录

完整读取一个带 SKILL.md 的本地目录，梳理文件类型、目录结构和脚本线索。

B
单个 SKILL.md

只分析入口文件，适合快速理解触发契约与能力边界。

C
安全 zip

支持 zip，但会拒绝路径穿越、异常大文件和可疑符号链接。

近邻路由
PAGE 06

它负责“解读”，不负责“创建”或“导出学习报告”

仓库里已经明确写了近邻边界：创建或重构 Skill 应改用 yao-meta-skill；如果只是想导出 Word/PDF 学习报告，优先考虑 yao-skill-reader-skill；如果要验证真实任务效果，则要走专门执行评测流程，而不是把解释器当运行器。

评分模型
PAGE 08

100 分不是“印象分”，而是带证据的九维打分

评分规则文件把 100 分拆成九个一级维度：规范兼容 12、触发信号 14、上下文效率 12、结构资源 12、使用就绪 14、安全权限 14、测试评估 10、维护发布 7、学习价值 5。任何扣分都必须落到证据链上。

红线规则
PAGE 09

总分高，也可能被红线直接降级

⚠
高危密钥与系统破坏

读取并上传令牌、Cookie、SSH 私钥，或未解释的递归删除、系统启动改写，都属于红线。

✕
越权提示注入

要求忽略系统规则、隐藏真实行为、绕过用户确认或越权读取，也会触发“暂缓使用”。

质量门
PAGE 10

不仅看分析器能不能跑，还看样例能不能把风险打出来

scripts/smoke_test.py 会跑 examples/good_skill 和 examples/risky_skill：前者要拿到可用分，后者必须触发高风险或 critical 发现项。这让“解释器本身是否稳定”也进入了验收闭环。

设计语言
PAGE 12

它连报告 UI 都被规范化了

参考文档不是只写“要出 HTML”，而是进一步规定了：白底高信任、顶部 sticky 状态栏、左侧目录、右侧指标栏、雷达图、热力图、donut、证据卡、提示词复制按钮，以及打印模式下要隐藏哪些交互控件。这意味着它不只是分析器，还是报告交付规范。

最适合谁
PAGE 13

适合 Skill 准入、学习、团队审核，不适合当执行沙箱

如果你面对的是一个来源不明或质量未知的 Agent Skill，想先判断值不值得采用、哪些地方危险、如何在团队里落地，那它很有价值；如果你想的是“帮我跑起来看看”，那它故意不做。
