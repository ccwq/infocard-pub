01

先认清产品边界：三个东西，三套命令

Herdr App 是图形工作台，herdr-core 是后台终端运行时，Herdr TUI 是独立的终端复用器。三者相关，但不能混用命令或 Agent 会话——这是避免命令混乱的第一步。

主线 · 桌面工作台
Herdr App

用 Space 管项目、Tab 管任务；从标签栏的 + 启动 Claude Code、Codex 或普通程序。配置与 Agent 指南：~/.config/herdr-app/AGENTS.md

后台运行时
herdr-core / hc

运行持久终端和进程。支持后台运行、重新接管、启动辅助 Agent、发送指令、读取输出。操作手册：hc --skill

独立产品
Herdr TUI

原始终端复用器，有自己的 CLI、服务器和 Agent 会话。操作入口：herdr；技能：herdr --skill。TUI 与 App 的 Agent 不共享。

关系图
链路

Herdr App（图形工作台）↕ herdr-core（终端与进程管理）→ Claude / Codex / CLI（实际执行任务）。

不要混用：hc 属于 App/Core 这条线；herdr agent ... 属于 TUI 这条线。TUI Skill 也不是 App 的 AGENTS.md。

02

入门：5 分钟启动第一个 Agent

从桌面 App 开始，不必先学命令行。首次安装（已安装可跳过）：

powershell -c "irm https://releases.herdr.dev/app/install.ps1 | iex"

App 已构建在 herdr-core 之上，不要为了使用 App 而重复安装独立 Core。启动 Claude Code 四步：打开 Herdr App → 创建或选择一个 Space（项目工作区）→ 点击标签栏的 + 启动 Claude Code → 在 Agent 中读取 Herdr 指南：

Read ~/.config/herdr-app/AGENTS.md

推荐组织方式：一个 Space 对应一个代码仓库；一个 Tab 对应一个任务或工作流。先保持简单，任务变多后再增加 Tab 或 Agent。

03

让 Agent 学会操作 Herdr：三种材料

指南、Core 手册、可复用 Skill 是三种不同材料，别混。

1
App 必读 AGENTS.md — 告诉 Agent 如何读取和修改 Herdr App 的布局、设置、主题与 Mods。
Get-Content "$HOME\.config\herdr-app\AGENTS.md"
2
Core 手册 — hc --skill 向 Agent 提供 Core 的命令与协作说明，适合学习终端生命周期、后台任务和 Agent 间通信。
hc --skill
3
TUI 专用 Skill — 这是 Herdr TUI 的可复用技能，不是 App Skill，要求 Agent 在 TUI 管理的窗格内运行。
npx skills add herdrdev/herdr --skill herdr -g

App 推荐引导语：「先阅读 ~/.config/herdr-app/AGENTS.md，再阅读 hc --skill。先说明你能通过 Herdr App 和 Core 完成哪些操作、各自的边界；暂时不要修改配置或启动进程。」官方 App 入门路径是让 Agent 读取 App 内的 AGENTS.md；官方可安装的 herdr Skill 则面向 TUI，不要把 TUI Skill 当成 App 的通用接入插件。

04

Core 命令：从外部 PowerShell 操作后台终端

适合希望保留命令行习惯的用户。先在 PowerShell 用 Set-Location 进入目标项目目录，再执行 hc run。

# 在当前目录运行测试，并等待结束
hc run cargo test

# 后台启动开发服务器
hc run --bg --name web bun dev

# 查看 Core 管理的终端
hc ls

# 重新接管终端
hc attach web

启动由 Core 管理的 Claude Code：

Set-Location D:\projects\my-project

# 后台启动 Claude Code
hc run --bg --name claude-main claude

# 查看、接管
hc ls
hc attach claude-main

不要误判：普通 PowerShell 里直接启动的 Claude Code，不会因为安装了 Skill 就自动变成 Core 管理的进程。需要从 Herdr App 的 + 启动，或通过 hc run 启动。

05

Agent 协作：让一个 Agent 调度另一个 Agent

基础协作链路：启动 → 派活 → 等待 → 读取 → 追问。示例中的 codex 可换成 Claude 或其他可执行程序。

# 在项目目录启动审查 Agent
hc run --bg --name reviewer codex "Review the current diff"

# 等待它结束当前工作
hc wait reviewer

# 读取结果
hc read --lines 80 reviewer

# 继续追加任务
hc send reviewer "Also check the tests"

父子 Agent 回报：Core 文档示例使用父终端 ID 作为回报目标。PowerShell 中先检查环境变量：

$parent = $env:HC_TERMINAL_ID
$parent

# 有值时，可将它传给子 Agent 的任务说明
hc run --bg --name reviewer codex "Review src. When done, send findings to terminal $parent using hc send $parent ..."

如果变量为空，不要猜 ID。先用 hc ls 查看目标，再用 hc read 收集结果。

适合拆分的任务：代码审查、测试、文档检查、依赖调查、独立模块实现。避免让多个 Agent 同时无协调地修改同一组文件。

06

远程机器：把服务器纳入同一管理面

Core 可以通过 SSH 添加机器，远程终端会进入同一份 Core 列表。前提：SSH 登录可用，远端已具备兼容的 Herdr Core 环境。先验证 SSH，再添加机器。

# 添加可通过 SSH 访问的机器
hc machine add box@my-server

# 在远程机器启动 Claude Code
hc run --on my-server --bg claude

# 查看本机和远程终端
hc ls
07

定制工作台与项目隔离

1
布局 · Agent 状态看板 — 把 Agent 排成三列：需要你处理、正在工作、已经完成。适合同时运行多个任务。
Make me a layout where my agents are cards in columns: needs you, working, done.
2
工作流 · 一个 Issue 一个 Worktree — 为独立 Issue 创建 Git Worktree，再在对应分支启动 Agent，减少多个 Agent 修改同一工作目录的冲突。
Open a worktree for issue 42 and start Codex on it with the issue as its task.
3
扩展 · 安装已有 Layout / Mod — 先让 Agent 阅读 App 指南，再指定布局或 Mod 地址，让 Agent 先检查文件再安装。
Read ~/.config/herdr-app/AGENTS.md, then add this layout: herdr.dev/layouts/herdrdev/pasture

配置目录 ~/.config/herdr-app/ 下通常包含 settings.json、keys.json、layouts/、mods/、themes/。先备份，再让 Agent 修改；优先新增布局，不直接覆盖默认布局。

08

独立分支：如果你使用的是 Herdr TUI

仅在确认产品是 TUI 时使用本节。

# 启动 TUI
herdr

# 在 Herdr TUI 管理的窗格中启动 Claude
claude

# 全局安装官方 TUI Skill
npx skills add herdrdev/herdr --skill herdr -g

TUI Agent 命令示例（窗格 ID 以当前 TUI 返回为准）：

# 查看 Agent
herdr agent list

# 读取某个 Agent
herdr agent read w1:p2

# 给 Agent 派发提示
herdr agent prompt w1:p2 "Review this diff" --wait

# 等待 Agent 状态
herdr agent wait w1:p2

边界：TUI 的 herdr agent ... 与 App/Core 的 hc ... 是不同命令体系，两者不共享 Agent 会话。Skill 会检查 HERDR_ENV=1，不在 Herdr TUI 窗格中时它应停止操作。

09

状态、排障与安全边界

排障
Agent 没出现在列表

确认从 App 的 + 或 hc run 启动；确认没有放在 tmux 内层；检查 Agent 是否报告状态。

排障
没有工作状态

Herdr App 依赖 OSC 7501 状态协议显示工作、完成或等待。程序不支持时仍可运行，但状态可能不可见。

边界
关闭 App 后任务如何

关闭 App 不会停止 Core 中的终端。若 Core 停止或机器重启，进程会停止；恢复终端不等于自动恢复 Agent 对话。

安全
先验证，再自动化

命令示例以官方文档为依据，尚未在本机执行；执行前以本机 --help、hc --skill 和版本匹配文档为准。

推荐验收清单：App 中能启动 Claude Code；Claude Code 能读取 AGENTS.md；外部 PowerShell 执行 hc ls 能看到 Core 终端；hc run 能启动一个辅助 Agent；hc wait 与 hc read 能收集结果；确认 App 与 TUI 没有被当作同一会话。
