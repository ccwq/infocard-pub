Open WebUI 将本地与云端模型接到同一界面，并可加入文档检索；它是入口和管理层，不替代模型服务。

  • Ollama 等运行本地模型；云端连接需要服务地址和密钥。
  • 上传文件不等于检索成功，要用可核对的句子和引用验证。
  • 本地卷不是备份，外部模型、抽取、搜索与插件仍可能收到数据。
  • 插件可能在服务器执行代码，导入权限应限于可信管理员。
单机试用先准备 Docker 和可访问的模型服务：创建管理员，连接模型，验证普通对话，再测试文档。需要离线时逐项检查处理服务和网络出口。

到这里可以决定是否试用；继续阅读可获得具体命令、对照测试和分层排障方法。

数据流：上传 → 抽取 → 切分 → embedding 与索引 → 检索片段 → 聊天模型

01 先把界面接到一个模型

以下假设 Docker 已安装，Ollama 运行在同一台宿主机。先用 openssl rand -hex 32 生成一串随机密钥，安全保存，并把下方占位符替换为该值：

docker run -d -p 127.0.0.1:3000:8080 \
  --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data \
  -e WEBUI_SECRET_KEY=your-secret-key \
  --name open-webui --restart always \
  ghcr.io/open-webui/open-webui:main

打开 http://localhost:3000，创建的第一个账号是管理员。127.0.0.1:3000:8080 只把端口绑定到宿主回环地址，避免默认向全网开放；open-webui 卷存放聊天、用户与设置。重建容器时继续使用同一个卷和密钥；删除卷会删除其中的数据，更新前另做备份。:main 会滚动更新，稳定部署应选定具体版本。

进入头像 → Settings → Admin → Connections，在 Ollama 连接中检查 http://host.docker.internal:11434。容器内的 localhost 指容器自己，不是宿主机；上面的 --add-host 解决名称映射，但 Ollama 仍须监听容器可访问的地址。官方提示宿主 Ollama 在 Docker 场景需监听 0.0.0.0；这也可能扩大暴露范围；应只允许容器所需的来源访问，并通过防火墙限制其他访问。

想接云端或其他兼容服务，在同一页面找到 Manage OpenAI API Connections，点击旁边的 +，填服务商提供的 Base URL 和 API Key，保存。OpenAI 的地址示例是 https://api.openai.com/v1；其他服务用自己的地址。若服务不提供模型列表，在连接设置里填写 Model IDs。然后新建聊天，选择模型，先问一个简单问题，确认能正常回复。

不使用 Docker 时，官方 Python 安装是两条命令，不能粘成一条；官方当前支持 Python 3.11 和 3.12：

pip install open-webui
open-webui serve

默认访问 http://localhost:8080。无论哪种安装方式，都要另行接入聊天模型。

02 文档问答：先证明它真的找到那句话

常见流程是：上传文件 → 抽取正文 → 切成小块 → embedding 模型把文本转成向量并建立索引 → 对问题检索相关片段 → 把片段连同问题交给聊天模型。聊天模型因此可以依据文档回答，但这既不是训练模型，也不能保证每次都检索正确。

教学示例：

  1. 新建 test.txt，写入：设备巡检口令是：蓝鲸带着橘子散步。 用不含真实敏感信息的句子测试。
  2. 在 Workspace 的文档或知识库区域上传；在聊天中通过 # 选择该文件，确认输入框上方出现附件标识。界面名称可能随版本变化。
  3. 选择已连接的聊天模型，问：“设备巡检口令是什么？请给出依据。”预期回答包含“蓝鲸带着橘子散步”，并检查界面中可用的来源或引用，确认指向测试文件。
  4. 再开一个未附该文件的新对话问相同问题，作为对照；如果它也答对，不能仅凭答案证明检索成功。还要检查引用、实际送入的上下文或检索记录。

结果不对，先确认附件选中且有访问权限，再检查文档抽取预览、索引状态和 embedding 配置；更换 embedding 模型后，在 Admin → Documents 重新索引。扫描件需要适合的 OCR/抽取方式；上下文过短也可能丢掉检索片段。对于绑定到模型的知识库，启用原生工具调用时，模型可能需要主动调用检索工具，不能假定每次都会自动查。

03 本地存储，不等于所有数据都留在本机

卷保存的是 Open WebUI 的应用数据。若使用云端 embedding，文档文本可能发送给 embedding 服务；若使用云端聊天模型，问题和检索到的片段可能发送给模型服务商。外部 OCR、向量库、搜索与插件也各有自己的数据路径。

真正的离线部署需要预先准备模型和依赖，将聊天、抽取、embedding 与存储指向受控环境，关闭不需要的外部连接，并检查实际出口。官方还提示默认安装可能发起版本检查、OpenAI 模型列表请求以及 embedding 更新检查；不要把“装在内网”直接等同于“没有任何外联”。

04 连不上时，按层排查

  • 页面打不开：运行 docker logs -f open-webui 查看启动日志；若 3000 端口被占用，改映射左侧端口。
  • Ollama 没有模型：先在宿主执行 curl http://localhost:11434/api/tags 检查服务，再检查容器到 host.docker.internal:11434 的连通性、监听地址和防火墙；确认 Ollama 已有可用模型。
  • 云端列表为空或认证失败：检查 Base URL、密钥、服务商权限和 Model IDs；不要把密钥贴到日志或公开截图。
  • 回答没有依据：确认文件已附加、抽取内容不为空、索引完成，检查模型上下文与工具调用模式，而不是只换提示词。

多人部署时，先限制新用户和知识库权限。更重要的是，Tools、Functions、Filters、Pipes 等插件可能在服务器执行任意 Python；只给可信管理员导入权限，先审代码，并隔离运行环境。社区展示不等于安全审计。

主仓当前使用带品牌条件的 Open WebUI License，并非 MIT；具体部署、二次开发及分发应核对所用版本的许可。另有独立的桌面应用仓库：官方标为早期 Alpha，可选启用内置 llama.cpp，首次启动需要联网，不能把它等同于上述标准 Docker 镜像。
