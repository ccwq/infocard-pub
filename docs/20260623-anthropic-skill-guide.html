1
FUNDAMENTALS · 基础

Skill 是什么：一个文件夹，教 Claude 一次，受益每次

Skill 的文件结构

# 最小可用结构 your-skill-name/ ├── SKILL.md # 必需 - 主指令文件（Markdown + YAML frontmatter） ├── scripts/ # 可选 - 可执行代码（Python, Bash 等） ├── references/ # 可选 - 按需加载的文档 └── assets/ # 可选 - 模板、字体、图标等

SKILL.md 必须精确命名（大小写敏感），文件夹用 kebab-case，不能用空格、下划线或大写字母。

三层渐进式披露（Progressive Disclosure）

第一层 · 始终加载
YAML frontmatter — 进入系统提示词，让 Claude 知道"何时该用这个 Skill"
第二层 · 按需加载
SKILL.md 正文 — Claude 判断相关时才读取，包含完整指令和指导
第三层 · 深度探索
Linked files — references/ 等目录中的文件，Claude 仅在需要时才发现和读取

目标：最小化 token 消耗，同时保持专业化能力。SKILL.md 建议控制在 5000 字以内。

可组合性

Claude 可同时加载多个 Skill。你的 Skill 应假设它不是唯一能力，需要和其他 Skill 共存协作。

跨平台可移植

Skill 在 Claude.ai、Claude Code 和 API 上行为一致。创建一次，全平台通用（需环境支持依赖）。

厨房比喻：MCP 提供专业厨房（工具、食材、设备），Skill 提供菜谱（如何用这些工具做出有价值的东西）。MCP 解决"Claude 能做什么"，Skill 解决"Claude 应该怎么做"。

PLANNING & DESIGN · 规划与设计

三类用例 + YAML frontmatter 是最关键的部分

三种常见用例类别

类别 1
文档与资产创建 生成一致高质量输出：文档、演示、应用、设计、代码。代表：frontend-design skill
类别 2
工作流自动化 多步骤流程 + 一致方法论，跨多个 MCP 协调。代表：skill-creator skill
类别 3
MCP 增强 为 MCP 工具访问提供工作流指导。代表：sentry-code-review skill

YAML Frontmatter — 整个 Skill 最关键的部分

Frontmatter 决定 Claude 是否加载你的 Skill。写错 = Skill 永远不会被触发。

# 最小必需格式 --- name: your-skill-name description: What it does. Use when user asks to [specific phrases]. ---

name 规则：kebab-case，不能用空格/下划线/大写，不能用 "claude" 或 "anthropic" 前缀（保留词）。

description 规则：必须同时包含"做什么"+"何时用"（触发条件），1024 字符以内，不能含 XML 标签。

好描述 vs 坏描述

# ✅ 好 — 具体且可操作 description: Analyzes Figma design files and generates developer handoff documentation. Use when user uploads .fig files, asks for "design specs", "component documentation", or "design-to-code handoff". # ❌ 坏 — 太模糊 description: Helps with projects. # ❌ 坏 — 缺少触发条件 description: Creates sophisticated multi-page documentation systems.

成功指标（量化 + 定性）

  • 触发率：90% 相关查询应自动触发（跑 10-20 个测试查询验证）
  • 工具调用次数：对比有/无 Skill 的同一任务，统计 tool calls 和 token 消耗
  • API 失败率：目标 0 次失败调用/工作流
  • 定性：用户不需要提示下一步；工作流无需纠错即可完成；跨会话结果一致

TESTING & ITERATION · 测试与迭代

三层测试 + skill-creator 工具 + 基于反馈迭代

三层测试体系

触发测试
确保 Skill 在正确时机加载 — 测明显任务、改写请求、不相关话题
功能测试
验证输出正确 — 有效输出、API 调用成功、错误处理、边界情况
性能对比
证明 Skill 比基线更好 — 对比 token 消耗、失败率、交互轮次

skill-creator：官方 Skill 构建工具

内置在 Claude.ai 中，也可用于 Claude Code。可以从自然语言描述生成 SKILL.md，审查常见问题，建议触发短语和测试用例。

使用方式："Use the skill-creator skill to help me build a skill for [your use case]"

建议流程：先在单一挑战任务上迭代到 Claude 成功 → 提取成功方法 → 封装为 Skill → 再扩展测试覆盖。15-30 分钟可完成首个可用 Skill。

欠触发信号

  • Skill 该加载时不加载
  • 用户需要手动启用
  • 支持工单问"什么时候用"

解决：在 description 中补充关键词和细节

过触发信号

  • 不相关查询也加载
  • 用户禁用 Skill
  • 对用途产生困惑

解决：添加负面触发，缩小范围

DISTRIBUTION · 分发与共享

Skill 是开放标准，跨平台可移植

分发渠道

  • 个人用户：下载文件夹 → 压缩为 .zip → Claude.ai Settings > Capabilities > Skills 上传，或放入 Claude Code skills 目录
  • 组织级：管理员可部署到整个工作区（2025-12-18 上线），自动更新、集中管理
  • API：/v1/skills 端点管理，通过 container.skills 参数加入 Messages API 请求
  • GitHub：公开仓库托管 + README + 安装指南 + 截图示例
开放标准：Anthropic 已将 Agent Skills 作为开放标准发布。同一个 Skill 应在 Claude 和其他 AI 平台上都可使用。MCP 一样，Skills 也追求可移植性。

定位建议：讲结果，不讲功能

# ✅ 好 — 讲结果 "The ProjectHub skill enables teams to set up complete project workspaces in seconds — instead of spending 30 minutes on manual setup." # ❌ 坏 — 讲技术 "The ProjectHub skill is a folder containing YAML frontmatter and Markdown instructions that calls our MCP server tools."

PATTERNS · 5 种工作流模式

从早期采用者和内部团队中提炼的实战模式

模式 1：顺序工作流编排

多步骤有序执行验证门控

用户需要按特定顺序执行多步流程。每步有依赖关系，每阶段有验证，失败时有回滚指令。

例：客户入职 → 创建账户 → 设置支付 → 创建订阅 → 发送欢迎邮件

模式 2：多 MCP 协调

跨服务阶段分离数据传递

工作流跨多个服务。每个阶段使用不同 MCP，阶段间传递数据，进入下一阶段前验证。

例：设计到开发交接 → Figma MCP 导出 → Drive MCP 存储 → Linear MCP 建任务 → Slack MCP 通知

模式 3：迭代优化

质量循环验证脚本知道何时停止

输出质量随迭代提升。生成初稿 → 运行验证脚本 → 识别问题 → 修复 → 重新验证 → 直到达到质量阈值。

例：报告生成 → 获取数据 → 初稿 → 质量检查 → 修复循环 → 最终定稿

模式 4：上下文感知工具选择

决策树回退选项透明度

同一目标，根据上下文选择不同工具。用决策树判断，提供回退选项，向用户解释选择原因。

例：智能文件存储 → 大文件用云存储 → 协作文档用 Notion → 代码用 GitHub → 临时文件用本地

模式 5：领域专业知识

领域知识合规检查审计追踪

Skill 嵌入超越工具访问的专业知识。在行动前做合规检查，记录所有决策，生成审计报告。

例：支付处理 + 合规 → 获取交易 → 制裁名单检查 → 风险评估 → 合规通过则处理，否则标记审查

TROUBLESHOOTING · 排障速查

6 个高频问题与解决方案

Skill 无法上传
原因：文件未精确命名为 SKILL.md（大小写敏感）
修复：重命名为 SKILL.md，用 ls -la 验证
Skill 不触发
原因：description 太模糊或缺少触发短语
修复：补充用户实际会说的触发短语，问 Claude "When would you use this skill?" 来调试
Skill 触发太频繁
原因：范围太宽
修复：添加负面触发（Do NOT use for...），缩小 description 范围
指令不被遵循
原因：指令太冗长 / 关键信息被埋没 / 语言模糊
修复：精简指令用列表，关键指令放顶部加 ## Critical，用确定性代码替代模糊语言
MCP 连接失败
原因：MCP 服务器未连接 / API key 过期 / 工具名错误
修复：检查 Settings > Extensions 连接状态，验证 API key，独立测试 MCP
大上下文性能下降
原因：SKILL.md 太大 / 同时启用太多 Skill / 未用渐进式披露
修复：SKILL.md 控制在 5000 字以内，详细文档移到 references/，评估是否启用了 20-50+ 个 Skill
