01 / ARCHITECTURE

不要把“搜索”和“阅读网页”混成一个能力

01 · 发现Tavily / Exa / Brave / Serper
返回候选 URL、片段和排名。
02 · 提取Jina Reader / Firecrawl
把已知页面变成干净 Markdown。
03 · 研究Exa Deep Search / You.com Research
处理多轮检索与引用整理。
04 · 交叉GitHub API / 官方站点 / 浏览器
核对第一方来源和动态页面。
05 · 降级CDP 浏览器
处理登录态、JS 渲染和搜索页。
关键边界：搜索 API 返回结果，不等于已经阅读并验证了网页。对于新闻、价格、版本和安全声明，仍要抓取原文并记录来源。

03 / DECISION

按任务选工具，而不是按品牌选工具

通用 Agent 搜索

Tavily → Exa → Brave → CDP
先用 Tavily 获取 LLM 友好的结果，语义不够时切 Exa，实时性或独立索引要求升高时加 Brave。

GitHub / 开源项目

GitHub REST API → Exa → 浏览器
仓库、README、代码树优先使用 GitHub 一手接口；搜索只负责发现和补充。

技术文档 / 论文

Exa → Tavily → Jina Reader
Exa 负责语义发现，Tavily 做补充，Jina 将确定的 URL 转为可引用正文。

新闻 / 舆情 / 实时事件

Brave → Tavily → 浏览器
至少交叉两个来源；涉及事实核查时不能只采用模型生成的摘要。

04 / IMPLEMENTATION

第一版接入，先做这三件事

01

统一 Router 接口

把 query、时间范围、域名过滤、结果数、超时和来源元数据统一成一个内部协议。

02

区分搜索与提取

搜索结果只进入候选池；正文必须经过 Jina、Firecrawl 或浏览器提取后再喂给 Agent。

03

设置预算与降级

记录 provider、请求数、credits、429 和延迟；失败时自动切换，不允许无上限重试。

推荐起步栈： Tavily（默认搜索）+ Exa（技术研究）+ Jina Reader（正文提取）+ GitHub REST API（开源项目）+ CDP 浏览器（登录态与 JS 兜底）。

免费额度不是架构

FREE TIER IS NOT THE ARCHITECTURE

  • 先拆层：搜索发现、正文提取、研究合成和浏览器兜底各司其职。
  • 先做预算：credits、token、请求次数、并发和自动续费都要可观测。
  • 先做核验：搜索结果是线索，官方原文才是证据。
  • 先做降级：一个供应商的免费额度耗尽，不应让 Agent 失明。
