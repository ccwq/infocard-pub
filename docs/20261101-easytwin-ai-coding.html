01

场景先行：可视化编辑与 AI Coding 的分工

SCENE FIRST

可视化编辑器负责场景

模型导入、环境调整、镜头与动画配置、散点/标牌/围栏等数字要素绘制，都在编辑器中边操作边预览完成。需要直观操作的场景环节，不要交给 AI 在代码里硬调参数。

AI Coding 负责业务逻辑

根据告警状态控制区域显隐、业务事件触发镜头动画、外部数据更新设备状态等动态交互，通过自然语言描述需求，让 AI 基于 EasyTwin SDK 生成应用代码。

成熟引擎能力直接复用

EasyTwin 将场景编辑、动画控制、数字要素、镜头动画封装为产品功能，并通过 SDK 开放场景访问、对象控制、事件交互。关联场景后即可访问其中的模型、数字要素、相机和动画对象。

复用的真正前提

官方原文是“在满足场景对象与代码依赖条件的前提下”复用已有应用代码，未逐项列明条件。复用前先用 easytwin scene inspect 比对两个场景的对象树，确认被代码访问的对象存在且属性一致。

分工边界：“把所有三维开发都交给 AI”不是官方推荐用法。围栏绘制、材质颜色、标牌位置、漫游路线这类直观操作留在可视化编辑器；SDK + AI 只处理需要响应业务逻辑的部分。两种方式混用反而要在三维参数配置与业务代码之间反复切换。
02

创建应用并关联场景：Scene Key 与应用凭证

APP + SCENE
01
在 EasyTwin 中创建应用

应用是承载 SDK 代码的工程单元，与三维场景分离管理；创建应用时填写 Scene Key（场景标识）。

02
关联目标场景

把应用与已建好的三维场景关联，代码运行时访问的就是这个场景中的对象。

03
取得应用凭证

App ID 与 App Secret 在应用设置中取得，用于本地 DevKit 凭证配置。

04
保管好 AppSecret

密钥只进本地配置文件，该文件由 init 自动写入 gitignore，永不入库。

验收：在 EasyTwin 控制台中确认应用已创建并关联场景（Scene Key 已填写），并在应用设置中拿到 App ID 与 App Secret。缺任一项，后面的 init 与运行调试都无法进行。
03

安装 DevKit 并初始化：AppSecret 只留在本地

SETUP

全局安装 CLI

npm install -g @easytwin/devkit

也可作为库安装：npm i @easytwin/devkit。本文快照版本 0.1.21（2026-10-08 发布）。

项目目录执行 init

cd your-app-project easytwin init

生成 .easytwin/easytwin.config.json 与 gitignore，拉取场景列表摘要、场景快照与工作区代码。

配置文件结构

// .easytwin/easytwin.config.json { "appId": "你的 App ID", "appSecret": "必填,保密", "env": "prod", "scenes": [] // scene list 写入 }

环境变量优先

EASYTWIN_APP_ID EASYTWIN_APP_SECRET EASYTWIN_BASE_URL EASYTWIN_ENV

环境变量优先于配置文件，适合 CI 或多环境切换。

# 初始化后的常用命令 easytwin scene list # 列出凭据可见场景,写入配置 easytwin scene pull # 拉取场景 JSON 到 .easytwin/scenes/ easytwin scene inspect # 只读打印对象树(id/name/type),超200节点截断 easytwin upload # 工作区代码与远端全量对齐 easytwin skills sync # 同步 AI skills 七件套到项目(cursor/claude/codex/all) easytwin docs doctor --json # 检查 SDK 文档接口,无需 IDE 加载 MCP
密钥红线：easytwin.config.json 含 AppSecret，请求头带 x-app-id / x-app-secret 直连官方 API。init 会自动处理 gitignore，但如果你手动建仓或改动 gitignore，必须自行确认该文件从未被 git add。密钥一旦提交历史，仅删除文件不够，需要轮换密钥。
04

main.ts 写业务逻辑，.spec.ts 模拟外部输入

AI CODING

给 AI 什么上下文

DevKit 随包分发 skills 七件套与 AGENTS.md 常驻约定，easytwin skills sync 写入项目后，官方称其可帮助 Codex / Cursor / Claude Code / Qode / Workbuddy 理解 EasyTwin 开发规范与接口能力。也可通过 easytwin docs 系列命令以机器可读 JSON 查询 SDK 文档。

main.ts 承载业务逻辑

对象控制、镜头动画、交互响应、数据联动都在应用入口组织。官方示例需求：“点击设备后，镜头自动聚焦并高亮模型，同时展示设备运行数据”——该效果需在你的场景与环境中运行调试验证；AI 结合开发上下文生成对应交互逻辑。

.spec.ts 模拟外部输入

需要与外部业务页面联动的应用，通过测试文件模拟外部事件与参数输入。真实业务页面尚未接入时，也能提前验证场景逻辑。

先定义预期再写代码

外部联动类应用先把业务预期写成明确清单：什么事件触发、作用于场景中哪个对象、期望出现什么变化。清单确认后再交给 AI 生成代码，运行调试时逐项对照。

# 业务步骤与预期现象（示意，非接口代码；真实实现以官方文档与你的场景为准） 1. 外部业务页面发出“选中设备”事件，携带设备标识 2. 应用代码接收事件，在场景中定位对应设备对象 3. 镜头切换至该设备附近，模型进入高亮状态 4. 页面侧同步展示该设备的运行数据 预期现象：运行调试中，场景视角变化、模型高亮与页面数据更新按上述顺序出现
提示词要点：让 AI 写代码时，明确说明目标场景的对象结构（可用 easytwin scene inspect 的输出贴给 AI），而不是只描述“点击设备聚焦”。AI 拿不到真实对象树时，会按惯例猜测接口——这正是错误的常见来源。

运行调试：验证互动结果，而不是只看代码

VERIFY

验证层方式观察什么
在线开发浏览器中编辑并验证功能适合快速调整与小改动
本地开发获取应用工程，在本地 IDE 持续开发配合 easytwin upload 同步代码
运行调试在关联场景中执行代码模型状态、镜头动画、交互响应是否符合预期
外部输入模拟.spec.ts 测试文件业务页面未接入时事件与参数逻辑是否正确
代码生成只是开始：AI 生成的代码不保证正确。必须在关联场景中实际运行，逐项确认镜头走位、高亮时机、数据展示与事件回传。发现偏差后，把“实际看到什么 / 期望什么”反馈给 AI 继续调整，形成运行→验证→修正的闭环，而不是反复重新生成。
06

提交不等于发布：版本发布与业务集成

SHIP

提交：代码同步

开发调试完成后，将代码同步（easytwin upload）至 EasyTwin；同步后仍需发布正式版本，代码变更才进入交付流程。

发布：正式版本

在 EasyTwin 中发布正式应用版本；官方说明已发布的应用可接入 EasyV，或集成至企业自有 Web 业务系统。

接入 EasyV 容器

已发布应用可直接接入 EasyV 平台，作为应用容器中的数字孪生组件使用。

集成自有 Web 系统

通过应用交互接口，业务页面与三维场景双向联动：页面定位场景目标、更新设备状态；场景把点击选择信息回传业务页面。

典型集成示例（来自官方场景描述）：仓储运输管理系统中，业务页面根据运输任务定位场景中的目标车辆、更新设备状态；三维场景将对象点击和选择信息传递给外部页面，联动展示业务数据。
07

边界与风险：四个必须写进心里的提醒

BOUNDARY
① AI 不保证正确。AI 基于 SDK 开发上下文生成的代码可能调用不存在或已废弃的接口。生成前用 easytwin docs api 核对签名，生成后在真实场景实测。官方明确强调“运行调试验证实际效果”是流程的一部分，不是可选项。

② 官方示例需环境验证。官方示例与文档代码未在你的场景中运行过；你的场景对象 id、结构与组件版本可能与示例不同，直接照抄容易报错。采用任何示例前，先在关联场景中运行调试验证。

③ UNLICENSED 只表明未选择开源许可证。npm 上 @easytwin/devkit 的 license 字段是 UNLICENSED，仓库指向内网 GitLab。该字段不代表授权范围或价格；商用与使用条款请通过官方渠道确认，本文不掌握价格信息，也不构成任何授权。

④ 复用代码有前提条件。官方原文是“在满足场景对象与代码依赖条件的前提下”复用已有应用代码，未逐项列明条件。换场景复用前，先用 scene inspect 比对两个场景的对象树，确认被代码访问的对象存在且属性一致，再做决定。
