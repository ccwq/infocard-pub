01
核心结论

它把“数学曲线”变成了“动效语言”，而不是只做成一组漂亮图案

这个页面的关键不在于“好不好看”，而在于它把公式和视觉结果一一绑定：每个 loader 都是一个参数组合的直接结果。也就是说，视觉不是贴出来的，而是算出来的。

为什么它像一个“图库”

页面按家族排布：先是 custom rose trail，再是 rose curve、Lissajous、lemniscate、hypotrochoid / spirograph、butterfly、cardioid、heart wave、spiral 与 Fourier。你看到的是一组连续变化的视觉家谱。

为什么它适合做信息卡

它的可复用价值不是某个 SVG，而是“参数 → 形态”的映射方式。做 loading state、品牌动效或生成式 UI 时，这种结构比单张海报更值得抄。

02
家族图谱

21 个图形可以收敛成 8 个家族，比较才会真正有意义

如果只把它看成 21 张图，就会被数量淹没；如果把它拆成家族，你会更快看懂哪些参数控制花瓣数，哪些控制拖尾密度，哪些控制“像心”还是“像波”。

04
可复用建议

如果你想借它的思路，优先复用“参数系统”，不要只复制外观

最容易落地的做法是：先选一个家族，再让一个参数只负责一个变化维度。这样你不是在抄图，而是在搭一套可扩展的 motion system。

可以先抄什么

  • 玫瑰线：用 k 控制花瓣数。
  • 螺旋花：用滚动参数控制瓣数和密度。
  • 心形 / 波形：把情绪化轮廓和可读节奏分开。

不要直接抄什么

  • 不要只搬一张图，忽略参数变化逻辑。
  • 不要把“数学感”误当成“线条复杂”。
  • 不要把图库做成静态海报，失去加载动效语义。
