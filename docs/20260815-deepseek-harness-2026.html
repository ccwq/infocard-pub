02 · 核心概念

Agent = Model + Harness

Agent = Model + Harness
模型是 Agent 的灵魂，Harness 是 Agent 在现实环境中工作的保障
🎯 Model（模型）
权重 → 负责预测 Token。DeepSeek V4 Pro / V4 Flash / Anthropic / OpenAI 均可作为大脑接入。
⚙️ Harness（挽具层）
工具接入 · 文件系统 · Shell · 子代理编排 · 上下文存储 · 终止逻辑 · 会话管理

Harness 的本质是一个工具接入层与执行协调器：将原始模型从聊天助手升级为能实际操控环境的 Agent。Anthropic 在 2025 年末首先在 Claude Code 中推广这一概念，DeepSeek 则将其开源化、模块化。L1 官方

Cordis Kernel
管理插件的挂载、卸载与依赖解析。所有 Agent 能力以插件形式注册到 Cordis Context 中。
Every Run is Traceable
完整的事件流记录：系统提示 → 推理链 → 工具调用 → 子代理调度 → 上下文注入，可回放/分支/搜索。
🎯 战略意义：DeepSeek 不再只是模型供应商，正向产品层延伸。V4 Flash（MoE 284B 总参数 / 13B 活跃参数，1M token 上下文窗口）+ Harness = 完整的开源 Agent 堆栈。 L2 VentureBeat 2026-08-14
03 · 安装流程

3 步启动 · 零配置体验

  1. 1
    前置：安装 Node.js
    要求 Node.js ≥ 22.19（含 24、26 支持）。推荐使用 nodejs.org 官方安装包，或通过 nvm 安装。 
    node --version  # 要求 >= 22.19
  2. 2
    一行命令启动 Web UI 
    npx @deepseek-ai/dsh web

    首次运行自动下载依赖，启动后服务默认监听 http://127.0.0.1:3080。无需克隆仓库，无需手动构建。

  3. 3
    配置 API Key 并选择工作区
    打开浏览器访问 http://127.0.0.1:3080，进入 Settings → Models，填入 DeepSeek API Key，保存后选择工作区目录，即可开始任务。

    API Key 可从 platform.deepseek.com 获取。支持配置多个 Provider 和自定义 OpenAI 兼容端点。

从源码构建（可选）： 
git clone https://github.com/deepseek-ai/deepseek-harness
cd deepseek-harness
corepack enable
pnpm install
pnpm run build
pnpm dsh web
源码构建需要 pnpm ≥ 10，通过 corepack enable 启用。 L1 官方 README

标准 · 极简 · PTC（Code） · 创造

DeepSeek Harness 提供四种运行时模式，适用于从轻量评测到深度定制的不同场景。L1 官方文档

05 · 插件系统

一切皆插件 · 可替换可组合

DeepSeek Harness 的核心设计哲学：每个能力都是可插拔的插件——模型、工具、Skills、会话、沙箱、存储、循环、调度、UI，全部可以独立替换或扩展。L1 官方

插件类型
  • 🔧 工具插件（tools）
  • 🤖 模型插件（llm / providers）
  • 🧠 Agent Skills
  • 📦 子代理编排（agents）
  • 🗄️ 存储与会话（storage / sessions）
  • 🖥️ UI / Web 界面
安装命令
dsh plugin --profile web add "github:owner/repo#ref"

也支持 npm / local path / file: / link: 协议。插件需声明 dsh.bundle.patch 才能激活。

插件开发（创造模式）

创造模式（Creator）内置插件开发工作台，支持内存中测试 Cordis 插件并组合为新预设。

// scratch-plugin/src/my-plugin.ts
export default {
  name: 'hello',
  inject: ['tools'],
  apply(ctx) {
    ctx.tools.register({
      name: 'greet',
      description: 'Says hello',
      async execute() { return 'Hello from plugin!'; }
    });
    console.log('[hello-plugin] loaded');
  }
}

注册到 cordis.yml 并启动：

# scratch-plugin/cordis.yml
- insert:
    - id: hello
      name: '/absolute/path/to/scratch-plugin/src/my-plugin.ts'

pnpm dsh web --patch ./scratch-plugin/cordis.yml
🔍 插件发现：在 GitHub 仓库添加 dsh-plugin Topic 即可被社区发现。官方 Discord 和 GitHub Discussions 提供支持。 L1 官方

10 · 局限性与风险

Developer Preview · 谨慎用于生产

  • 破坏性变更预警：官方明确声明「THERE WILL BE COMPATIBILITY-BREAKING CHANGES」，插件 API 和核心接口尚不稳定，生产环境需谨慎评估升级路径。L1 官方
  • 数据口径风险：生态报告同时出现 1804 仓库、4000+ 商店收录、6000+ 商店宣传和 908 注册表等不同口径；它们不是同一个分母，不能直接拼成增长曲线。L2 handbook chapter 15
  • 工具错误静默：在使用 DeepSeek 作为 Claude Code 后端时，工具调用失败不会返回错误标记，模型会继续执行而非停止报告。「DeepSeek 无法识别图片输入」在某些集成场景下也是硬限制。L3 genaiunplugged 2026-08
  • 插件质量参差：仓库数量不等于可安装、可运行或安全审计通过。安装前应检查源码、许可证、版本兼容性、权限边界和最新测试状态。L2 handbook boundary
  • rc 版本风险：手册记录了依赖断裂、插件入口、waterfall 的 next()、类型导出、端口占用与 reasoning 序列化等踩坑；升级后要重新跑最小任务与插件 smoke test。L2 handbook chapter 6
  • 图像理解限制：V4 Flash / Pro 在某些 Claude Code 集成场景下不支持图片输入（截图、设计稿），视觉相关工作流可能受限。
  • 官方托管服务缺失：目前无 DeepSeek 托管的云端后台 Agent 服务（Claude Code 和 Codex 均提供），适合需要开箱即用的团队。
使用建议：当前阶段适合个人开发工具链、本地实验、教育学习和插件探索；Windows 团队与生产环境应先建立版本 pin、回滚和权限审计流程。
