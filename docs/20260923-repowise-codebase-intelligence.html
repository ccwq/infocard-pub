01 推文说了什么

核心推荐逻辑：作者在 django 仓库跑了 43 个问题做对比，Agent 工具调用从 7.2 次降到 3.8 次，输出少 31.6%，样本、方法和输掉的行全部公开在仓库里。

推文还点出三个差异化：① 改代码前算一份 0-10 风险分，按仓库近期提交分布排序，列出受波及的调用方、该跑的测试、以往总一起改的文件这次有没有漏；② 代码健康有 51 个检测器，缺陷风险/可维护性/性能分开打分，给出可直接丢给 Agent 执行的重构方案；③ 建图、算风险、查健康度、找死代码都不调用大模型，不用 API Key，索引留在自己机器上，支持 26 种语言，另有免费 PR 机器人。

03 10 个 MCP 工具：按任务设计，不是按数据实体

官方对比：多数 MCP 工具围绕数据实体（一个文件、一个 symbol）设计，把 Agent 逼进"长链路顺序调用"；repowise 的工具围绕任务——一次调用传多个目标，拿回完整上下文：

get_answer(question)
混合检索（全文+向量 RRF）、PageRank 偏置、1-hop 图扩展，一次往返返回带引用的答案 + 校准的 retrieval_quality。把"搜索→读→推理"折叠成一次调用。
get_context(targets, include?)
文件/模块/symbol 的分诊卡：摘要、签名、hotspot 标记、约束决策。include 打开调用方/被调方/归属/指标，可批量传多个目标。
get_risk(targets, changed_files?)
热点、依赖方、co-change 伙伴、归属、测试缺口、bug 历史。传 changed_files 进 PR 模式，返回 directive 块。
get_change_risk(revspec)
合并前风险分：这次 commit 让缺陷/可维护性/性能新恶化了什么、归因、触及的测试覆盖、diff 形状在近期提交中的排名。
get_why(query?, targets?)
架构决策及其原文证据，标注 exact / fuzzy / unverified 三级置信。没有决策记录时回退到 git 考古。
get_health / get_dead_code
51 个检测器分三路打分（缺陷/可维护性/性能）+ 按置信分级的死代码清单；include 可展开结构化重构方案直接交给 Agent。
还有 4 个：get_overview / search_codebase / get_symbol / list_repos
get_overview() 是接手陌生仓库的第一个调用（架构摘要+模块图+入口+git 健康）；workspace 模式自动增加 get_architecture / get_blast_radius 等跨仓工具；另有 4 个 opt-in（get_dependency_path 等）。VS Code 插件额外向 GitHub Copilot 暴露 6 个工具。
04 与竞品的关键差异（README 对比表实测行）
零 LLM 分析
图、风险、健康、测试、死代码、PR review 全部不调用大模型；生成 prose 是可选项。确定性结果 + 无 API Key + 索引不出机器。
Agent 主动性
Claude Code / Codex 有 hook 级拦截（Full tier）：自动注入决策与风险；VS Code/Cursor/OpenCode 是 Good tier（MCP + instructions 文件）。Hermes 也在支持列表。
自动生成指令文件
init 时自动写 CLAUDE.md（Claude Code）和托管 AGENTS.md（Codex），含架构/入口/热点/约定，随代码库变化保持更新——Agent 零调用先获得定向。

与编辑器内置索引的区别（官方 FAQ）：Cursor/Continue 的索引是临时的、单仓的、纯 embedding——按需重新嵌入然后忘掉。repowise 是持久的结构层，带健康分、git 历史、归属和架构决策，跨多仓 workspace，任何 MCP 客户端都能调。诚实项：如果你只需要调用图，CodeGraph 更快更省，官方明说"这是正确的取舍，你该选它"。

05 三步上手（官方 Quickstart）
// 一条命令装好，无需 API Key（首次建索引不调用 LLM）
pip install repowise
cd /path/to/your/repo
repowise init --no-prose -y   # 建图/git/决策/健康/死代码/结构 wiki
repowise serve                # init 已自动为 Claude Code 写好 .mcp.json

# 然后直接问 Agent：
#   "Use Repowise get_overview to summarize this repository"
#   "What breaks if I change src/auth.py?"
1
跑 repowise agents 确认接线；6 个支持目标：Claude Code / Codex（Full 级）、VS Code / Cursor / OpenCode / Hermes（Good 级）
2
想要模型润色的文档就去掉 --no-prose（默认 init 需要一个 LLM key 写 prose；结构层永远不需要）
3
装 Claude Code 插件可获得 6 个自动激活 skills + 18 个 slash commands + hook 上下文注入；装不上就跑 repowise doctor
06 评测判断
Overall推荐 ★★★★☆（大型仓库 / 多 Agent 团队）
证据质量罕见地公开方法+样本+输掉的行
隐私本地索引 · 无 API Key · AGPL-3.0
代价首索引最慢（366.8s @ django）；Claude 增益 15.9% 低于 Codex
适用大仓、多仓 workspace、高频 Agent 协作
不适用只要调用图（选 CodeGraph 更快）；小仓收益有限

一句话：它解决的不是"Agent 不会写代码"，而是"Agent 每个任务都要重新交一遍学费"。43 问基准的可贵之处不在 31.6% 这个数字，而在方法全公开——包括自己输掉的那一行。
