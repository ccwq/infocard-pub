01

两条流水线，不是一条

模板走 scripts/sync/sync_bundles.py，蓝图走 scripts/sync/sync_blueprints.py；蓝图还有独立的导入脚本 scripts/blueprints/import_blueprints.py 做命名归一化与元数据生成。

02

蓝图用 ComfyUI 原生子图格式

blueprint 不是自定义 DSL，而是原生 subgraph 结构：顶层 definitions.subgraphs 里带 id / name / inputs / outputs / nodes / links。

03

版本号只有一个来源

版本写在根 pyproject.toml；贡献流程的最后一步是“改根版本号后提 PR”，避免包版本与内容漂移。

04

提交前必须复跑同步

README 明确要求：sync_blueprints.py 必须不产出任何改动，否则说明包与蓝图不一致——这是一致性门禁，不只是格式化。

05

CI 六项校验

JSON 语法、schema 校验、bundle 一致性、manifest 同步、缩略图、ComfyUI 节点兼容性。其中节点兼容性只作为信息性 PR 评论，不阻断合并。

贡献一个蓝图要走完的 5 步README · Option 1: Import from External Source

从外部 JSON 接入

  • 把 blueprint JSON 放进 blueprints/，文件名用 snake_case，例如 text_to_image_flux.json

先分清角色

三类人，三条路：用模板 / 改模板 / 贡献模板

这个仓库不是普通的示例合集：它同时是 ComfyUI 的模板分发源、蓝图组件源、以及官网 comfy.org/workflows 的数据源。先判断自己属于哪一类，再决定读哪几节——多数人只需要第一类。

你的目标要不要碰仓库最短路径
只想用现成模板不用ComfyUI 自带模板包，直接在界面里的模板浏览器选；也可以在 comfy.org/workflows 网页上先挑。想单独装：pip install comfyui-workflow-templates
想改参数、另存自己的版本不用（本地改）模板本身就是标准 ComfyUI 工作流 JSON，在 ComfyUI 里打开 → 改 → 另存；不需要动仓库，也不会被 CI 校验
想加一个新模板或蓝图要（提 PR）走 README 的 13 步流程。真正的关卡只有两个：sync_bundles.py（模板）和 sync_blueprints.py（蓝图）必须跑到「无 diff」
先知道代价，再决定动手

这个仓库按 GitHub 记录是 4,478,986 KB（约 4.5 GB）——大量 webp 预览资产。全量克隆很慢，贡献时也只应改自己那一小块；官方把资产按媒体类型拆成 6 个 bundle＋多个 pip 包，正是为了别让用户下 4.5 GB。

04 · 主流程

贡献一个模板：把 README 的 13 步压成 6 个关卡

README 用 Wan 2.1 文生视频模板做完整演示。下面按「你会卡在哪」重排：每关都给命令、判据和最常见的错法。

关卡 1 — 准备一个能热加载模板的前端环境

  • 准备好 ComfyUI_frontend 的开发环境，然后在它的 .env 里加 DISABLE_TEMPLATES_PROXY=true，再 npm run dev
  • 把本仓库的 templates 文件夹整个拷进 ComfyUI_frontend/public
  • 目的：让前端直接读你本地的模板目录，改完刷新即可见，不用等发布

关卡 2 — 拿到工作流 JSON

  • 在 ComfyUI 里画好流程 → Save → Export；已有工作流也可以直接复用
  • 如果工作流藏在一张图里，可用 comfyui-embedded-workflow-editor 把 JSON 抽出来
  • 硬规则：导出/创建时用 --disable-all-custom-nodes 启动 ComfyUI，否则自定义扩展会往 JSON 里偷偷写入元数据

关卡 3 — 缩略图（内容类型 + 悬停效果 + 命名）

内容类型悬停效果（可选）命名与压缩
Image 静态图 / Video webp 动图 / Audio 音频控件Compare Slider（前后对比）、Hover Dissolve（渐变到第二张）、Hover Zoom（放大）、不加以保持默认文件名不含空格、点、特殊字符；缩略图用同名＋序号：你的模板名-1.webp；先转 webp 再压分辨率，官方建议 65% 质量损失压缩

关卡 4 — 归包并同步（最容易失败的一步）

# 1) 在 bundles.json 里给新模板登记 bundle（media-image / media-video / …）
# 2) 模板目录或 bundles.json 一改，就要跑同步并提交生成的清单
python scripts/sync/sync_bundles.py
#    或者用 Nx： npm run sync
这道门禁会卡住你：manifest 必须与内容一致

同步会重写 packages/core/src/comfyui_workflow_templates_core/manifest.json，这个文件必须和你的改动一起提交。CI 里两处会拿它对 SHA256：Validate Manifests（validate-manifests.yml）与 build-test.yml 的前置同步检查。两处都不会先自动同步——清单过期就是直接失败，不会「悄悄帮你生成」。

关卡 5 — 补元数据：index.json、模型信息、可选的版本钉住与文档节点

  • 在 templates/index.json 里加条目：name、description、mediaType、mediaSubtype、tutorialUrl、thumbnailVariant；新建分类要写 moduleName/title/type
  • JSON 一律用双引号 "——README 专门用警告块强调过这一点
  • 让用户「不用离开 ComfyUI 就能跑」：给加载模型的节点（VAELoader / CLIPLoader / UNETLoader…）加 properties.models[]，字段为 name、url、hash、hash_type: "SHA256"、directory；hash 可在 HuggingFace 页面查到或自行计算
  • 硬规则：下载链接里的文件名必须与节点的 widgets_values 完全一致，否则「能下载但加载不上」
  • 可选：节点加 cnr_id + ver 钉住版本（示例：Wan 2.1 需要 SaveWEBM，故标 comfy-core / 0.3.26）；再加一个 MarkdownNote 节点放官方教程链接

关卡 6 — 多语言同步 → bump 版本 → 提 PR

python3 scripts/sync/sync_data.py --templates-dir templates
# 该脚本会：把技术字段（models/date/size…）同步到各语言文件
#         检测未翻译的 title/description
#         把新模板登记进 scripts/data/i18n.json
#         生成 index.zh.json / index.ja.json 等语言文件
  • 想顺手翻译，就在 scripts/data/i18n.json 里补 title / description 的语言键，再跑一次同步
  • PR 前先用「新用户视角」实测：删掉模型和输入图，走一遍下载—生成流程，确认能一次跑出缩略图
  • 确认所有语言文件都已同步并提交，然后在根 pyproject.toml 里 bump 版本号，再提 PR
05 · 蓝图

贡献一个蓝图：让「一堆节点」变成一个可拖拽组件

蓝图把 CLIPTextEncode + KSampler + VAEDecode 这类固定组合，封装成节点面板里的「Text to Image」「Style Transfer」——它用的是 ComfyUI 原生子图格式，不是自定义 DSL。

路径做法命令
A 外部导入把现成的蓝图 JSON 放进 blueprints/（文件名用 snake_case，如 text_to_image_flux.json），由脚本归一化命名并生成元数据python scripts/blueprints/import_blueprints.py
B ComfyUI 内创建在 ComfyUI 里把流程存成子图，再按原生格式导出到 blueprints/—

原生子图 JSON 的关键字段

{
  "id": "78bdb6eb-…",          // 工作流 UUID
  "revision": 0,
  "version": 0.4,               // 格式版本
  "nodes": [ { "type": "82187329-…",
               "properties": { "proxyWidgets": [["-1","text"],["31","seed"]] } } ],
  "definitions": {
    "subgraphs": [ { "id": "82187329-…", "version": 1,
                     "name": "Text to Image (Flux.1 Dev)",
                     "inputs": [ … ], "outputs": [ … ],
                     "nodes": [ … ], "links": [ … ], "groups": [ … ] } ]
  }
}
  • proxyWidgets 决定哪些内部控件暴露到外层节点上（上例暴露 prompt 与 seed）
  • 同目录可放可选预览图 名字-1.webp
  • 同步落点：packages/core/src/comfyui_workflow_templates_core/blueprints_manifest.json ＋ packages/blueprints（发行包 comfyui-subgraph-blueprints）
一致性判据：再同步一次应当没有 diff

蓝图流程的收尾动作是 python scripts/sync/sync_blueprints.py；README 要求它「不产出任何改动」。若还有 diff，说明包内容与蓝图源不一致——这是内容一致性检查，不是格式化检查。

08 · 发布

标签决定要不要上 PyPI，版本号只有一个来源

这个仓库把「出 GitHub Release」和「发布 PyPI 包」拆开了：默认合并只发 Release，省构建与存储。

PR 合并方式产出用户能 pip 装到吗
合并到 main，不带 release 标签只创建 GitHub Release不能
合并到 main，带 release 标签Release ＋ 构建并发布到 PyPI能
事后补发：Actions → Publish to PyPI → 勾 Force publish绕过标签检查；仍只上传「本地版本与 PyPI 不同」的包（恢复模式）视包而定

版本策略三条（来自 Frozen legacy media bundles 文档摘要）

  1. 只改模板的 PR：根 pyproject.toml 不变 → 不自动 bump
  2. Release PR：作者 bump 根版本＋打 release 标签 → CI 自动 bump 非冻结子包并更新依赖引用
  3. 冻结包 media-{api,image,video,other}：永不自动 bump，固定在旧版本，直到有意为之的 legacy 发布

另外：只改 hub 侧信息（归档、元数据）不要动根版本号，除非你确实想发一个新 PyPI 版本。CI 里对应的辅助脚本包括 scripts/ci/check_frozen_policy.py、check_pypi_quota.py、ci_version_manager.py。

10 · 自检

提交前十条自检清单

每一条都能在上面的章节里找到出处；全部打勾再点 Create pull request。

  1. 生成模板时用 --disable-all-custom-nodes 启动 ComfyUI
  2. 模板文件名不含空格/点/特殊字符；缩略图命名 名字-1.webp、先转格式再压分辨率
  3. 改过 templates/ 或 bundles.json 后跑 sync_bundles.py，并把重生成的 manifest.json 一起提交
  4. 提交前再跑一次 sync_bundles.py / sync_blueprints.py，确认无 diff
  5. 所有 JSON 用双引号，不用单引号
  6. 模型节点的 url 文件名与 widgets_values 完全一致，hash_type 写 SHA256
  7. 依赖新版本 ComfyUI 或自定义节点时，加 cnr_id + ver
  8. 新分类补 title/type；有悬停效果就写 thumbnailVariant
  9. 跑 sync_data.py --templates-dir templates，把语言文件同步并提交
  10. PR 前 bump 根 pyproject.toml 版本；纯 hub 改动不要 bump
