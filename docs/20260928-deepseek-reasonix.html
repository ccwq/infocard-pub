DeepSeek-Reasonix

由配置与插件驱动的 Go coding-agent harness：同一套本地引擎覆盖终端、桌面端、浏览器和 ACP 编辑器接入。

它围绕 DeepSeek 的前缀缓存调优上下文维护：启动时注入稳定环境摘要，旧工具输出先 snip/prune，再进入 compaction。计划、权限、工作区沙箱与 checkpoint 让长时间自治运行保持可读、可撤销。

03 · CACHE-FRIENDLY CONTEXT

长会话成本控制：先保持稳定，再压缩历史

03
01稳定环境摘要启动时注入可复用的环境信息，减少前缀漂移。
02工具输出 snip / prune旧输出先裁剪，再进入摘要管线，不让噪音占满上下文。
03compaction把历史压成模型仍需知道的状态，而不是无限复制原始对话。
04继续运行保留可读、可回退的长任务工作区。
边界：

“前缀缓存友好”是架构目标，不是所有 provider 都保证同样收益；实际成本仍取决于 provider、模型、缓存策略和任务上下文稳定性。

04 · PLUGINS & EXTENSIONS

MCP 与 Extension Protocol v1 各自解决什么

04
MCP SERVER

把能力接进 Agent

MCP server 提供工具、提示词和资源；适合把外部能力作为 Agent 可调用的工具面接入。

EXTENSION PROTOCOL V1

把运行时本身扩展出去

Sidecar 可以拦截运行时事件、提供 Provider 和结构化 UI，并通过版本化插件包分发。

区别

工具 vs 运行时控制

MCP 更像能力入口；Sidecar 更靠近内核运行时生命周期。把二者混为一个“插件系统”会丢掉边界。

回归保护

schema 是契约

内置工具 schema 有文档和回归测试保护；工具输出进入 compaction 前还有 snip/prune 阶段。

密钥边界

README 的配置模型使用 api_key_env 注入密钥；不要把密钥硬编码进项目配置。

模型边界

07 · SAFETY & REVERSIBILITY

自治运行要可读、可暂停、可撤销

07
PERMISSIONS

权限不是默认放行

工具调用、工作区沙箱和 Agent 权限决定副作用半径；MCP/Sidecar 扩展也应纳入同一权限边界。

CHECKPOINTS

逐轮 checkpoint 与 rewind

长任务需要保留可回退节点；checkpoint 不是“自动正确”，而是降低错误变更的恢复成本。

模型费用边界

Reasonix 是本地 harness，不代表推理免费。请求仍由用户配置的 provider 执行并按其计费规则结算。

插件副作用边界

插件能提供工具、事件和 UI；安装前应审查 manifest、运行权限、工作区范围和网络访问。

09 · DECISION

谁该试，谁应该先看清边界

09

适合

希望在终端长期运行 coding agent；需要桌面或编辑器入口；想用配置/插件扩展能力；在意长会话的上下文成本、checkpoint 和恢复能力。

不适合

只想要一个无需配置、无需 provider、无需审查插件就能安全执行任意变更的“万能自动程序”。

当前快照

GitHub API：35,385 stars、2,360 forks、1,699 open issues；数据来自 2026-09-28 快照，不把星标数等同于稳定性。

结论

Reasonix 的核心卖点是 harness 结构：入口可换、provider 可配、工具可扩、上下文可压缩、长任务可回退。
