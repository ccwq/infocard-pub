02｜Auto-review：替换审核者，不改变沙箱

原来的路径是“执行 Agent → 请求越界 → 人工批准 → 继续”；现在是“执行 Agent → 请求越界 → 独立审核 Agent 判断 → 放行或拒绝”。主要 Agent 仍在相同的沙箱里，文件与网络限制没有因为自动审核而扩大。

它审的是本来会要求批准的动作，例如申请扩大 shell 权限、被沙箱拦截的网络请求、修改允许目录之外的文件，以及需要批准的 MCP／应用工具调用。已经允许的沙箱内操作不会逐项被重新审核。Computer Use 的应用级审批仍会直接交给用户，不能拿这个功能替代所有权限弹窗。

从界面开始

  1. 确认使用 ChatGPT 账户登录，而不是把 API key 的计费场景混为一谈。
  2. 打开 Settings → Permissions → Auto-review，检查账户实际出现的入口。
  3. 先在可丢弃的测试项目运行一个只读检查或测试任务；不要直接把生产凭据和整个主目录暴露给它。
  4. 阅读一次自动审核记录：申请的原命令、涉及路径／目标、批准或拒绝及理由。
  5. 保留沙箱与最小权限，不因为“审核免费”而设置无限制运行。

CLI 的文档配置示例（不是本轮修改你本机的配置）：

approval_policy = "on-request"
approvals_reviewer = "auto_review"

approval_policy = "never" 没有交互审批可转给审核者，因此不等于更强的自动审核。配置可用性还受客户端版本与组织管理设置约束。

什么情况必须停下

审核者关注私密数据或凭据外传、探查 cookie／token、持久削弱安全边界，以及有不可逆风险的破坏性动作。明确拒绝后不能换工具、换包装或间接执行来追求同一被拒结果；只有实质更安全的替代路径才有意义，否则请用户决定。

超时与拒绝不同：超时不是危险已证实，但动作仍不应当作已执行。当前开源实现还有拒绝熔断机制，防止 Agent 无限重试越界请求。适用时可以通过 TUI /approve 针对某一个被拒动作申请一次重试；它不是所有后续类似操作的通行证，审核仍可能拒绝。

免费究竟免费什么

官方帮助中心《Using Codex with your ChatGPT plan》已明确：ChatGPT 账户登录用户的 Auto-review 安全检查免费，且不计入套餐用量。这不意味着主任务的模型调用免费，也不意味着 API key 计费自动免除。旧的审批文档仍有“额外审核模型调用可能增加用量”的表述；新公告与旧页面可能处在更新过渡期，账户用量页才是个人计费的最终核对入口。

原文的“此前消耗 2%–10%”属于待核实的历史范围，不拿来估算你能省多少。内部评估中人工中断显著减少也不等于你每个项目都会少 200 倍等待，更不等于安全提升 200 倍。

验收建议：在相同任务和沙箱设置下记录审批次数、人工等待时长、误放行／误拒绝事件；不要只看“没有弹窗”就认为效果好。这是实践建议，不是官方性能承诺。

来源：ChatGPT 计划的 Auto-review 免费说明；Auto-review 官方机制；第二天公告社区转述。

03｜API 层级：容量门槛下降，不是模型降价

OpenAI 社区公告转述：五个付费层级简化为 Build、Launch、Grow；Grow 资格是累计 API 支付 500 美元，旧最高档为 1,000 美元；已有付费组织自动迁移，无须手动升级。

新档位 原文给出的累计支付门槛 本次证据状态
Build 5 美元 原文及二手报道有描述，公开开发者限速页仍显示旧表，需组织后台确认
Launch 100 美元 同上，不能凭本卡保证账户已迁移
Grow 500 美元 社区公告转述明确写出；具体组织限速仍看后台

核查时公开 Rate limits 指南仍展示 Tier 1–5 的旧表，故不伪装成所有文档已经同步。Build／Launch 数字保留原文归属；不据此发布未经确认的新 RPM／TPM 数字。社区所在域名本身也不能使每个用户帖子自动变成官方原始公告。

先判断你撞的是哪个上限

  • RPM：一分钟请求数。大量短请求也会触发，哪怕 token 很少。
  • TPM：一分钟 token 数。少量超长输入也能触发。
  • 组织／项目范围：不同项目或模型可能共享限制，不要只看某个 key。
  • 资金与月度限制：支付、预算、组织批准的月度上限和速率不是同一个数。

例如“小请求发得太快”与“长上下文耗尽 TPM”需要不同处理；升档前先读错误正文、请求响应头和 Limits 页，别用充值替代诊断。金额不是月费，也不是账户获赠余额。

升档前后的四步核对

  1. 登录对应组织，记录当前档位、模型 RPM／TPM、项目限额及月度控制。
  2. 确认组织迁移后的值；不要以搜索摘要里某模型表格代替本组织实际额度。
  3. 在有限预算内逐步增加并发，分别记录成功率、延迟与 429。
  4. 发生限速时优先遵循 Retry-After，使用有上限的退避和抖动；余额不足或配额问题不应无限重试。

公开文档指出突增流量也可能遇到 slow_down，即使没超过分钟总量。升到高档不等于可以瞬间打满所有容量。Spend alert 只发通知、流量继续；Hard spend limit 才会阻断对应请求。使用前检查自己的控制类型，而不是看到“预算”字样就认为绝不会超支。

验收建议：升级后比较同一组请求的吞吐、429 比例与延迟，不仅检查档位名称变了；具体模型价格另看 Pricing，不把“最高档门槛减半”改写为“模型半价”。

来源：变更公告社区转述；Rate limits 官方指南；组织 Limits。

04｜Meetings：录音、记录与后续行动分开确认

官方帮助页明确：macOS ChatGPT 桌面应用的所有 Pro／Business 计划可使用 beta；Enterprise 尚未普遍开放，部分客户参加 alpha，需联系账户经理。Windows／iOS／Android 支持是后续计划，不当作现在已经可用。

它通过 Mac 的麦克风和系统音频记录线上会议或线下交谈，无需机器人进入会议。随后使用转写、你手工补充的笔记，以及已授权连接应用的相关上下文，形成个性化摘要与建议事项，保存到 ChatGPT Space。

第一场会议如何开始

  1. Mac 桌面应用 → 侧栏 Plugins → 找到 Meetings → 安装并完成引导。
  2. 开放麦克风与系统音频权限。前者记录你及附近的人，后者记录电脑里其他参与者的声音。
  3. Business 管理员检查 Space 和 Meetings 都已启用；安装插件不等于自动取得邮件、日历或外部写入权限。
  4. 告知每一位参会者并取得同意，再点击 Take notes。应用内提醒只显示给你，不会替你通知其他人或收集同意。
  5. 结束时停止记录，等待上传与处理完成，检查同一会议页中的笔记、摘要与建议事项。

日历连接不是手动开始的前提。只有需要提醒与展示即将召开的会议时，再考虑授权 Google Calendar 或 Outlook Calendar，不为一场临时会议无谓扩大访问范围。

先审摘要，再启动行动

建议用一个可验证提示词：“列出会议中的决定、负责人与期限；每项指出对应的会议依据，没有明确负责人或日期就写未确定。先起草，不发送、不更新外部系统。”这个提示词是本卡的实践模板，不是内置保证。

逐项确认人名、数字、决定是否真的达成、负责人和日期。只有达成共识的事项才进入项目计划；讨论中的提案不要自动升级为承诺。再审阅或编辑建议事项，手动启动具体工作。

“生成跟进邮件草稿”与“发给客户”是不同授权；“更新计划建议”与“写入团队项目系统”也是不同副作用。外部动作还受连接账户、工作区政策和工具批准限制。

隐私与保留边界

会议页默认私密，你决定是否分享。官方说分享会议页后其他人可访问笔记，但不能访问转写；不要推断为整个私人聊天或记忆被共享。分享前检查页面里是否包含来自授权应用的敏感信息。

音频通过网络流向 OpenAI 处理；笔记完成后，音频从 Mac 与 OpenAI 服务器删除、不能重播。但离线或处理未完成时，音频可能暂存 Mac。音频删除也不代表笔记与转写一起删除。

自动停止可能由合上电脑、长时间无音频或达到四小时会话上限触发。处理可能在停止后再花几分钟。如果缺了远端参会者，先检查系统音频权限，而不是只提高麦克风音量。Meetings 与旧版 Record 是不同产品入口，套餐与工作流不能直接套用。

验收：用有同意的短测试会议，说出一个明确决定、一个负责人和一个期限；人工对照结果，检查私密状态、分享对象与一项仅草稿任务，先不要执行外部发送。

来源：Meetings 官方操作与数据说明；ChatGPT 发布说明。

05｜Decisions：先限定答案空间，再接业务路由

官方指南确认公共 beta，当前支持模型只有 gpt-6-luna，端点是 POST /v1/decisions。输入为文本、图像或两者；输出是应用可用的 typed answers，而不是开放式长篇聊天。先在 Playground 试问题和输入，再写应用接入。

问题类型 适合任务 主要返回 容易踩的坑
predicate 判断是否符合条件 probability，0–1 的模型估计 不是经现实校准的真值或法律认定
choice 在有限分类中选择 choice、选项概率及 confidence 类别要互斥，必须有 other 等兜底
score 按有序等级评分 等级索引概率加权平均及分布 分数可介于两级之间，不等于整数标签

请求含 model、共享证据 input 和 questions。每个 question 给唯一 name，在 answers 中按名字找结果，不假定数组顺序永远就是你的业务身份。

一个可以复制的文本分类请求

下例改写自官方投诉分流示例，只作调用模板；本轮没有调用付费 API，也没有虚构响应结果。

curl https://api.openai.com/v1/decisions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-6-luna",
    "input": "I was charged twice for my order.",
    "questions": [{
      "type": "choice",
      "name": "department",
      "instructions": "Which department should handle this complaint?",
      "choices": [
        {"value": "billing", "description": "Payments, invoices, refunds."},
        {"value": "technical", "description": "Problems using the product."},
        {"value": "shipping", "description": "Delivery and tracking."},
        {"value": "other", "description": "Requests outside these categories."}
      ]
    }]
  }'

把 key 放在服务端环境变量，不嵌进浏览器代码、信息卡或 Git。读取真实响应后先校验 answers、name、选项值与错误状态，再交给路由；billing 只决定送给账务队列，不应直接触发退款。

三个细节决定能否上线

图像输入：这个端点要求 inline base64 data URL；不支持普通 HTTP／HTTPS 图片 URL 或 file_id。用 user message 的 input_text 与 input_image 组合；不要把 Responses 的输入习惯原样照搬。

多问题：独立问题可以共享 input 一起问。后一题依赖前一题结果时，分成请求；不要假设同一数组是顺序执行的小程序。把“有损坏”与“谁负责赔付”拆开，后者还需要业务规则与授权。

概率与 confidence：predicate 是条件为真的估计，choice／score 还有类别分布与单独 confidence；不要用一个不经验证的统一阈值处理所有类型。score 为从 0 开始的等级索引的加权平均；它不是“第一个等级从 1 开始”的业务枚举。

速度与价格的准确口径

官方称 typed-answer 任务约比 Responses 快 10 倍。它针对该类有限答案接口，不是所有聊天、推理和工具链都固定加速 10 倍；本卡没有独立 benchmark。

/v1/decisions 使用 GPT-6 Luna 的基础输入价为每百万 token 0.10 美元，只收输入，不收输出、cache-read 或 cache-write。长上下文输入倍数与区域处理附加价仍适用。其他端点调用同一模型遵循自己的价格，不能把 Decisions 价表套给所有 Luna 请求。

如需自定义 JSON 对象、字段提取或书面解释，官方建议 Responses Structured Outputs；需要请求工具动作则选 function calling。Decisions 适合有限判断，不能替代整个 Agent。

来源：Decisions 官方指南、示例、定价；一般 API 定价。

06｜“ChatGPT 版 Jev”只是类比，不是产品同一性

用户原文借 Jev 表达“快速判断”。本卡不把它当 OpenAI 官方命名，也不把它与今天另一张 Jev-Mem 信息卡混为一谈：Jev-Mem 是记忆研究项目，Decisions 是有限答案决策 API。名字相近不是技术血缘证据。

没有双方同任务评测、错误率、硬件／服务条件和收费口径，就不能写“替代”“更快”“更便宜”或“内部使用同一架构”。合理的比较维度是输入类型、输出约束、延迟、成本、误判代价和隐私条件；实际结果应通过你自己的测试集获得。

07｜把四项放进一个可控业务链

以客户反馈会议为例：Meetings 得到记录 → 人审确认待处理反馈 → Decisions 分类到有限队列 → API Limits 支持逐步扩大的吞吐 → Codex 在沙箱内开发或修改工具，越界动作交 Auto-review 审核。

这是一条设计示意，不是四个产品已经自带的一键集成。会议内容可能含个人或商业数据，送到 API 前先脱敏；分类结果不直接作退款或删除依据；代码审核通过也不等于你授权上线。每一条边都需要数据访问与动作授权。

先用非敏感、有标签的小批输入试跑，只启用一项业务路由。记录正确分类、未知分类、误判、延迟及账单；预留人工队列。高后果任务优先人工确认，不要为了追求“全自动”删掉兜底。

08｜上线前逐项验收

  • Auto-review：界面／配置确实生效；审核的是越界请求；拒绝不会被绕过；用量核对以账户为准。
  • API：组织档位与实际模型限速有记录；预算与速率分开；429／503有有界处理，没有无限重试。
  • Meetings：计划、平台、管理员许可、双音频权限、参会者同意、摘要复核与分享对象全部确认。
  • Decisions：key 在服务端；问题有观测标准；other 队列存在；真实响应校验；阈值用标签数据调；高风险后续动作留人工。

以上清单是工程实践建议，不是 OpenAI 的安全保证。本次只核查公开页面并整理教程，未登录账户检查资格、未启用 Auto-review、未录会、未充值或调用付费 API。

09｜来源与未决项

可直接追溯的机制与操作来自官方开发者／帮助文档；Auto-review 免费已有官方帮助页明确说明，第二天时间线及三档变更另经社区转述交叉核查。公开限速页与公告尚有差异，Build／Launch 的账户具体资格应以后台为准。原文中历史额度 2%–10%、四项同日首发及“对标 Jev”不作为已证实事实。

核心变化不是“免费又更强”的口号，而是把审批者、账户容量、会议依据和有限答案分开管理。选择与你当前瓶颈相关的一项，完成一次有证据的小闭环，再增加自动化范围。
