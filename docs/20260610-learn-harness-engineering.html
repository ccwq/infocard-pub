learn-harness-engineering

把 AI coding agent 的 harness 做成可安装、可验证、可接续的技能

这个仓库不是单纯“写文档”，而是把 harness engineering 拆成一套可复用的技能包：为 agent 提供启动路径、当前状态、验证命令、作用域边界和 session handoff，让代码代理在仓库里更稳地开始、推进、收尾与续接。

01
核心定位

把 harness 从“经验”变成“可复制的最小系统”

README 把 harness 定义得很明确：帮助仓库给 coding agents 提供 instructions、state、verification、scope boundaries 和 lifecycle handoff 五项能力。它的目标不是堆一份超长手册，而是让 agent 真正能用、能接、能续。

Boundary

它明确不用于模型选择、单独的 prompt tuning、聊天 UI 设计或通用应用架构；项目事实要留在目标仓库，不要塞回 skill 自己。

instructions

启动路径

AGENTS.md / CLAUDE.md 负责告诉 agent：从哪开始、按什么规则做、什么算 done。

state

当前状态

feature_list.json 和 progress.md 用来记录当前功能、证据和下一步，避免只靠聊天上下文。

verification

可证据化完成

init.sh 或文档化命令让“做完”必须落到可执行检查，而不是口头宣告。

02
安装与使用

它本身就是一份可安装技能：装进去，再生成 harness

仓库 README 给出最直接的安装与使用路径：用 `skills add` 安装 skill，或者直接拷贝 skills 目录；然后通过脚本创建、验证并导出报告。逻辑很像“先装控制面，再生成控制面下游配置”。

installcopy path

两种安装方式

npx skills add walkinglabs/learn-harness-engineering --skill harness-creator

# 或直接复制
cp -R skills/harness-creator /path/to/skill/path
createvalidatebenchmark

三类脚本，一条工作流

node skills/harness-creator/scripts/create-harness.mjs --target /path/to/project
node skills/harness-creator/scripts/validate-harness.mjs --target /path/to/project
node skills/harness-creator/scripts/run-benchmark.mjs --target /path/to/project --html /path/to/report.html
built-in modules only

脚本约束

脚本只使用 Node.js 内置模块，方便复制到别的仓库后继续跑，不依赖复杂外部运行时。

multi-stack detection

自动识别常见技术栈

它能检测 Node/npm/pnpm/yarn/bun、Python、Go、Rust、Maven、Gradle、.NET 等常见项目栈的验证命令。

03
五个子系统

它不只是“写个 AGENTS”，而是五层一起补

核心模型非常清楚：Instructions、State、Verification、Scope、Lifecycle。这个分法的好处是，agent 不会只拿到规则，还能拿到状态、证据和续接信息。

SubsystemMinimal artifactPurpose
InstructionsAGENTS.md / CLAUDE.md启动路径与 done 定义
Statefeature_list.json / progress.md当前做什么、做到哪
Verificationinit.sh / 文档命令如何证明完成
Scope依赖与完成条件防止 overreach
Lifecyclesession-handoff.md下次可以接着做
minimal firstappend state

先最小可用，再逐步加厚

  • 先检查已有的 instruction / state / verify / docs / manifests。
  • 先补最小 harness，再考虑 memory、tool safety、multi-agent、benchmark。
  • 状态文件比聊天记录更可靠，任务结束也更容易交接。
  • 用证据而不是感觉判断完成度。
04
验证与审查

validate 不是验收全部，只是结构分数；但它能把底线先守住

`validate-harness.mjs` 会对五个子系统打结构分，说明 harness 有没有齐、是否连贯。README 也明确说：结构分不等于真实效果，但它至少能帮你先发现 harness 是否缺骨架。

5 subsystem scorestructural benchmark

它测的是“有没有骨架”

如果 instructions、state、verify、scope、lifecycle 任何一层缺失，agent 就会更容易跑偏、忘记状态或无法续接。

10 evalsHTML report

报告与 benchmark 也是交付的一部分

仓库提供 HTML assessment report 和 structural benchmark report，适合把 harness 质量变成可见、可比较的产物。

05
适合 / 不适合

它适合把 agent 工作流工程化，不适合拿来做泛化架构讨论

这个技能的边界很明确：它是 harness engineering，不是模型路由器，也不是 app architecture 代替品。它解决的是“让 agent 在仓库里做事更稳”的问题。

适合

最适合的场景

  • 给 AI coding agent 建 AGENTS/CLAUDE、状态文件和验证命令。
  • 想把“怎么开始、怎么证明、怎么接续”标准化。
  • 需要把 harness 打包成技能，方便跨仓库复用。
  • 需要结构化 benchmark 而不是只靠体验判断。
不适合

不该硬用的场景

  • 想做模型选择或 prompt tuning 的单独优化。
  • 想解决业务系统架构设计本身。
  • 想把项目事实写进 skill 里长期维护。
06
生命周期

这套技能最重要的产物，是让下一轮接手的人不会从零开始

harness 的价值，最后会落到一个问题：下一个 agent 或下一个人进来时，能不能在最短时间理解现状、继续推进、并且拿证据说话。这个仓库把这件事写成了可执行的模板。

1
Inspect

先看已有的 instructions、state、docs 和 package manifests。

2
Create

补最小 harness：启动、状态、验证、scope、handoff。

3
Validate

跑结构验证，确认五层都在、逻辑自洽。

4
Benchmark

导出 HTML 报告，把质量显性化。

5
Handoff

把状态写回文件，让下一次能接着做。
