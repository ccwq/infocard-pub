MiniMind 是 GitHub Trending 全球第一的超轻量开源 LLM 项目，主线最小版本仅 25.8M 参数（GPT-3 的 1/2700），可在单张消费级 GPU 上 2 小时完成 Pretrain + SFT 全流程训练，成本不足 3 元。项目以「大道至简」为理念，所有核心代码从 0 使用 PyTorch 原生实现，不依赖第三方高层封装，提供 Pretrain / SFT / DPO / GRPO / CISPO / Tool Use / Agentic RL / 模型蒸馏完整训练链路，并延伸 MiniMind-V 视觉多模态、MiniMind-O Omni 多模态等孪生项目。配套 PPTX 流程图，分词器训练代码手把手展示——造大模型的完整流程，从零复刻一遍，是目前最完整的 LLM 训练教学项目。

01 Tech Highlights · 技术亮点
PyTorch Native
🔥 核心创新
全链路从 0 实现
不依赖 transformers / trl / peft 等高层封装，所有核心算法（Attention、FFN、MoE、RoPE、Softmax）均为 PyTorch 手写实现，理解 LLM 本质的最优起点。
结构对齐 Qwen3 生态
MiniMind-3 主线 Dense ≈ 64M，MoE ≈ 198M-A64M，移除了 shared expert 设计，与 Qwen3 / Qwen3-MoE 结构兼容，可直接迁移预训练知识。
完整 RLHF 族算法
DPO · GRPO · CISPO · PPO（均从 0 原生实现）+ RLAIF + Agentic RL，覆盖从 SFT 到对齐的完整技术栈。
🧩 生态兼容
推理引擎：兼容 llama.cpp / vllm / ollama / Llama-Factory
训练框架：支持 transformers / trl / peft + DeepSpeed / DDP
可视化：wandb / swanlab（国内友好）
评测：C-Eval / C-MMLU / OpenBookQA
Server & WebUI
serve_openai_api.py 提供 OpenAI API 协议服务端（支持 reasoning_content / tool_calls），可接入 FastGPT / Open-WebUI。
web_demo.py 基于 Streamlit，支持思考展示、工具调用、多轮对话。
模型导出
scripts/convert_model.py 支持 LoRA 权重合并，导出完整模型权重供第三方推理。

03 Training Pipeline · 训练阶段详解
① Pretrain
② Tokenizer
③ SFT
④ DPO / GRPO
⑤ Tool Use / Agentic RL
⑥ 推理 & 部署
① Pretrain · 基座预训练
基座模型从随机初始化开始，在大规模语料上进行语言建模训练，学习通用世界知识和语言能力。
数据集：pretrain_t2t_mini.jsonl（精简版，单卡 2h 可复现）
硬件：单卡 NVIDIA RTX 3090 24GB
时长：约 2 小时（1 epoch SFT 阶段）
② Tokenizer · 分词器训练
MiniMind 项目同时开源了分词器的训练代码，支持 BPE + ByteLevel 词表构建。
模板标记：<tool_call> / <tool_response> / <tool_call>
思考标记：<tool_call> 完整支持
Buffer token：预留扩展空间
③ SFT · 监督微调
在预训练基座上，使用高质量对话数据微调，使模型学会遵循指令和对话能力。
数据集：sft_t2t_mini.jsonl（精简版）
Tool Call：已混入主线数据，基础 full_sft 即具备工具调用能力
Adaptive Thinking：chat_template 控制 <tool_call> 自适应开关
④ RLHF · 强化学习对齐
DPO：从 0 PyTorch 原生实现，离线偏好对齐
GRPO / CISPO：在线强化学习，基于 rewards 自适应优化
PPO：完整策略梯度算法原生实现
RLAIF：AI 反馈强化学习，rlaif-mini.jsonl 数据集
Agentic RL：train_agent.py，支持多轮 Tool-Use 场景 GRPO / CISPO

06 Scenarios · 适用场景
🎓 个人学习大模型训练
最适合 LLM 入门者的实战项目。不是调 API，不是微调现有模型，而是从随机初始化开始，真正训练一个语言模型。每行代码都有教育价值，理解 Attention、RoPE、MoE 的最好方式就是亲手实现一遍。
🔬 低成本实验研究
3 元成本 + 2 小时 = 完整训练循环。适合快速验证新算法想法（新注意力机制、新 tokenization 策略、新 RL 算法），在 MiniMind 上跑通后再迁移到 7B+ 大模型。
📱 嵌入式 / 边缘部署
26M 参数的 MiniMind2-Small 可以在 CPU 或移动端运行，适合离线场景、私有化部署、成本敏感的嵌入式产品。PyTorch 模型可直接导出为 ONNX / TFLite。
🏢 企业内部模型定制
基于 MiniMind 训练私有领域模型（医疗、法律、金融），提供 LoRA 微调 + 模型蒸馏完整流程。结合私有数据，用极低成本训练专属小模型。

08 Start Here · 初学者十分钟路径
先推理，再训练
先做哪件事？ 如果你只有一张消费级 GPU，先下载现成的 minimind-3 做一次推理，确认环境、权重和 tokenizer 都能工作；不要一上来就跑预训练。
顺序动作入口验收标准
1建立 Python 环境requirements.txtimport torch 成功；CUDA 环境再检查 torch.cuda.is_available()
2下载已训练权重ModelScope 或 Hugging Face模型目录含配置和权重文件
3跑 CLI 推理python eval_llm.py --load_from ./minimind-3能生成一轮回答；异常先看路径和权重格式
4再跑最小训练trainer/train_pretrain.py → train_full_sft.pyout/ 生成对应 checkpoint，loss 有日志
重要区分：推理是加载已有权重；SFT 是在基座上学会指令；Pretrain 才是从随机初始化学习语言模式。帖子里的“从零训练”不能被理解成“下载模型后微调”。

10 Data Contract · 数据与模型边界
预训练 JSONL
pretrain_t2t_mini.jsonl 的基本记录形态是 {"text":"..."}。它服务 next-token prediction；文件放入 dataset/，路径通过 --data_path 指定。
SFT 对话 JSONL
sft_t2t_mini.jsonl 使用 conversations 数组，按 role/content 表达多轮对话；Tool Call 样本还会带 tools / tool_calls 字段。
不要混用：把预训练样本直接交给 SFT 脚本，或把 SFT 对话当成预训练文本，通常会导致数据解析失败或训练目标错位。先看脚本的数据集类，再决定文件格式。
Tokenizer 取舍：当前主线使用自定义 minimind_tokenizer，词表约 6,400；README 不建议为追求兼容性随意重训 tokenizer，因为词表变化会同时影响权重、数据格式、推理接口和指标可比性。
11 Observe & Debug · 训练中怎么判断正常
现象优先检查处理动作
CUDA 不可用torch.cuda.is_available()、Torch/CUDA 版本先用 CPU/MPS 做代码验证；不要据此宣称可复现 2 小时结果
找不到权重--load_from、--weight、out/ 目录区分 Transformers 目录与 PyTorch *.pth 权重的加载方式
显存不够batch_size、max_seq_len、gradient accumulation先减 batch 或序列长度；不要直接删除梯度累积逻辑
训练中断checkpoints/ 是否有 resume 文件重跑同一入口并加 --from_resume 1
Tool Call 不工作SFT 数据是否含 tool_calls；chat template 是否正确先用 eval_toolcall.py 验证，再检查 Agent RL 数据
loss 下降但回答异常数据模板、tokenizer、评测样本用固定问题做回归；不要只看单个 loss 数字
bash · 断点续训
cd trainer
python train_pretrain.py --from_resume 1
python train_full_sft.py --from_resume 1
