Computer Repair Skill 把维修师傅的排障经验整理成按需加载的 Playbook：先确认平台与约束，读取系统证据，给出候选原因和最小变更计划，得到确认后才修改，最后验证并记录。

它不是“一键优化”，而是一套可审计的维修流程

你可以把“蓝屏、断网、C 盘爆满、软件崩溃、打印机离线”直接告诉支持 Agent Skills 的 Agent。Skill 负责路由和安全边界；真正的读取、命令执行与确认仍由宿主 Agent 提供。

01

先学会提问：平台 + 症状 + 约束 + 期望动作

描述越具体，路由越准确；把“先不要做什么”写进问题里。

Windows 断网

“Windows 11 最近经常断网，先只读检查网卡、DHCP、DNS、代理和 VPN，不要重置网络。”

Linux 磁盘满

“这台 Linux 服务器磁盘满了，先按挂载点和 inode 找原因，不要删除日志或容器数据。”

macOS 变慢

“Mac 越来越慢，先做健康基线和性能取证，修复前把发现的问题和预计影响列出来。”

提问验收：如果你的请求没有平台、症状或禁止动作，Agent 可能只能给泛化建议；先补齐这三类信息，再让它进入诊断。
02

安装：选择 CLI、仓库安装器或手动复制

项目本身是 Markdown/YAML Skill 资源，不需要配套桌面软件、额外模型或专用云端 API。

# Skills CLI：已安装 Node.js / npm 时 npx skills add 88lin/computer-repair-skill npx skills add 88lin/computer-repair-skill --global # macOS / Linux 仓库安装器 git clone https://github.com/88lin/computer-repair-skill.git cd computer-repair-skill ./scripts/install.sh --target codex # 安装后：重启或刷新 Agent 的 Skills 列表

CLI 适合谁

希望让 Skills CLI 选择安装范围和目标 Agent 的用户。首次运行会进入交互选择。

安装器适合谁

希望明确指定目标的用户：`codex`、`claude`、`agents` 或 `custom`；已有目标目录默认拒绝覆盖。

升级前置

旧版本更新需要显式 `--force` / `-Force`；安装器会先把旧版本备份到相邻备份目录。

03

核心协议：诊断和维修分成六个状态

安全性不来自“命令看起来熟悉”，而来自动作分级、确认点、回滚和验证。

01确认平台、症状、约束
02读取状态、日志、配置、硬件事实
03列候选原因，禁止凭症状猜结论
04给出最小变更、影响和回滚
05得到本次动作确认
06执行、验证、记录结果
动作类型默认策略你需要关注
读取/盘点/诊断可先做输出可能含敏感路径、账号或设备信息；要求脱敏。
安装/删除/清理先计划，后确认影响范围、备份、回滚、是否误删个人数据。
提权/重启/服务修改强确认停机窗口、权限、恢复方式和重启后的验证。
分区/原盘恢复/拆机升级给专业人员或现场技师先备份、加密状态、物理风险；不要把 Agent 当维修资质。

05

高风险场景：Agent 必须知道什么时候停手

这些边界不是“保守建议”，而是避免不可逆损失的操作前提。

BitLocker / PE / WinRE

进入离线环境前，在当前系统保存 BitLocker 状态、备份检查、命令清单和停工条件。不要假设 PE 里有网络或 Agent。

数据恢复

先成像、只读扫描、输出报告，再写入独立目标；原盘出现异常时立即停工，不要用实验命令覆盖源盘。

凭据与隐私

不输出密码、恢复密钥、私钥、token 或完整敏感路径；轮换凭据时只汇报状态与脱敏证据。

物理停工条件：冒烟、进液、异响、过热、电池鼓包、原盘物理故障或重要数据无法备份时，停止自动化操作并升级专业人员。
06

验证 Skill 本身：改动后运行仓库验证器

这不是维修用户电脑的命令，而是贡献者修改 Playbook 后检查仓库一致性的命令。

# macOS / Linux PYTHONUTF8=1 python tests/validate_skill.py # Windows PowerShell $env:PYTHONUTF8 = "1" python tests alidate_skill.py

验证器会检查 frontmatter、Agent 元数据、Playbook 描述、工具契约、路由索引、README 分类数量、Markdown 链接、许可证一致性、占位符与疑似凭据；官方 Actions 会在 Windows 与 Ubuntu 上重复验证。

先记住：先取证，再判断；先计划，再修改；每次变更都要能回滚并验证。

把它当作维修前的“安全操作系统”

Computer Repair Skill 最值得借鉴的不是覆盖了多少故障，而是把维修从“根据症状猜命令”改成“证据 → 候选 → 计划 → 确认 → 变更 → 验证”。
