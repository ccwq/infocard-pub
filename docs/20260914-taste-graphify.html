AGENT SKILLS / TWO BOTTLENECKSVISUAL QUALITY · CODE UNDERSTANDING
TASTE SKILL + GRAPHIFY

一个修正页面观感，一个读懂陌生代码

这两个 Skill 解决的不是同一个问题。Taste Skill 面向 AI 生成前端的审美落地：读 brief、推断设计语言，再调布局、动效和密度。Graphify 面向代码库、文档、PDF 与图片的结构理解：提取概念和关系，生成可查询图谱。先按瓶颈选，再决定是否串联。

页面功能对，样子不对？

选 Taste Skill：先审计，再修间距、层级、配色、字体和交互细节。

接手项目，不知道从哪读？

选 Graphify：扫描代码与资料，得到节点、边、god nodes、路径和可追问结构。

01

先做决策：两个 Skill 不要互相替代

一个改变界面输出，一个改变你理解代码的入口；把它们当成同一类“万能增强”会导致验证目标混乱。

Taste

输入是 brief，输出是前端实现

适合已有页面或新页面：先判断视觉语言，再落到代码、GSAP 骨架、响应式布局和 redesign audit。

Graphify

输入是文件与资料，输出是图谱

适合陌生代码库、论文、Markdown、PDF、截图和架构图；重点是关系与查询，不是改 UI。

组合顺序

先 Graphify，再 Taste

如果项目既陌生又需要改前端：先用图谱找到页面、组件和依赖，再让 Taste 审计具体界面，避免对错文件下手。

关键边界：GitHub Stars、README 里的“anti-slop”或“71.5x fewer tokens”是项目/案例声明，不等于你当前代码库的实测效果。
02

Taste Skill：把“有品味”拆成可执行的审计路径

它不是换一个颜色主题，而是先读上下文，再决定方差、动效和信息密度。

01读 brief 与目标用户
02推断设计语言与系统图
03调 VARIANCE / MOTION / DENSITY
04按组件与页面审计返工
05跑 pre-flight，再交付完整输出

v2 experimental

README 当前将默认 design-taste-frontend 标为 v2 experimental；如果依赖 v1 行为，可安装 design-taste-frontend-v1。

安装一个技能

npx skills add https://github.com/Leonxlnx/taste-skill --skill "design-taste-frontend"

不只实现技能

仓库还提供 redesign、image-to-code、soft、minimalist、brutalist 等不同用途的技能，不能把整个仓库当成单一提示词。

# 先安装默认 v2 npx skills add https://github.com/Leonxlnx/taste-skill --skill "design-taste-frontend" # 新会话中让 Agent 审计已有页面 # 给出页面路径、目标用户、已知问题和不接受的视觉结果
03

Graphify：从扫描输入到可查询图谱

它把“读完几万行代码”改成先问图谱：什么是高连接节点？两点之间是否存在路径？哪些关系只是推断？

01准备代码/文档/PDF/图片
02运行 AST + 概念抽取
03查看 graph.html / JSON
04query / path / explain
05更新变化，保留缓存
# PyPI 包名暂为 graphifyy，CLI 名仍是 graphify pip install graphifyy && graphify install # 在目标目录生成图谱 /graphify . # 具体查询 /graphify query "what connects attention to the optimizer?" /graphify path "DigestAuth" "Response" /graphify explain "SwinTransformer" # 增量更新 / 观察 / 输出 /graphify ./raw --update /graphify ./raw --watch /graphify ./raw --wiki

结果目录

graphify-out/ 可包含 interactive graph.html、Obsidian vault、wiki、GRAPH_REPORT.md、持久化 graph.json 和 SHA256 cache。

边的可信度

每条关系标为 EXTRACTED、INFERRED 或 AMBIGUOUS；查图时不能把推断边当作源码事实。

输入范围

代码、Markdown、文本、RST、PDF、PNG/JPG/WebP/GIF；代码使用 tree-sitter，图片和文档可用 Claude 视觉/抽取能力。

04

用同一个陌生项目验证 Graphify，而不是只看图好不好看

第一次运行的验收重点是可追溯：节点来自哪里，边是抽取还是推断，图谱能否回答具体问题。

验收问题通过信号失败信号下一步
能找到入口吗？GRAPH_REPORT 给出 god nodes 与建议问题只有一张图，没有文字解释用 explain 追一个节点
关系可信吗？边有 EXTRACTED/INFERRED/AMBIGUOUS 标签把所有连线当确定事实回到源文件核对命中位置
增量有效吗？--update 只处理变化文件并合并图每次全量重跑、旧边消失检查 cache 与 graph.json
问题能回答吗？path / query 返回可解释路径问题超出图谱信息或输入未收录补输入，再明确问题范围
案例边界：README 给出混合语料 token benchmark 和 worked examples；这些是官方示例，不能直接当作你的仓库收益保证。
05

组合工作流：先读懂，再修正，再复核

当页面问题来自陌生架构时，先建立关系地图，减少 Taste Skill 在错误组件上反复返工。

Step A / Graphify

扫描 src/、文档、配置和截图；用 god nodes 找共享壳、路由和高连接组件。

Step B / 人工定主任务

从图谱回到页面：确认用户、首要任务、关键状态和当前组件边界。图谱不能替你决定设计目标。

Step C / Taste

把真实 brief、页面路径和问题清单交给 Taste；修复后重新跑页面级视觉与交互验收。

下一步：如果你接手的是陌生前端，先运行 Graphify 的最小扫描；如果你已经知道要改哪个页面，直接从 Taste Skill 的审计路径开始。
