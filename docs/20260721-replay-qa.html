Replay QA

Autonomous App Testing

自主应用测试工具：指向任意 Web 应用 URL，它会自动探索用户旅程、生成 Playwright 测试、用 Replay Browser 捕获完整运行时录像，并借助时间穿越调试定位根因，给出修复建议——无需现有测试套件，无需手动复现步骤。

Playwright 测试生成 完整运行时录像 时间穿越调试 根因分析 + 修复建议
内置深度 React 支持

组件树检查、渲染追踪、Effect 分析，大幅提升 React 应用 Bug 报告的深度；开启 Source Maps 可将失败回溯至原始源代码，而非编译产物。

独立运行

Stand-alone

只需提供一个 URL，Replay QA 全程自动完成，无需任何现有测试套件、配置文件或手动操作。

  • 自主导航 Web 应用
  • 发现用户旅程
  • 生成 Playwright 测试
  • Replay Browser 执行录制
  • 时间穿越回溯 Bug 根因
  • 输出详细分析 + 修复建议
零配置

连接 GitHub

GitHub Repo

安装 GitHub App，授权仓库后，代码每次变更自动触发测试，无需 CI 配置或 Workflow 文件。

  • 自动监听代码变更
  • 每次合并前发现回归
  • 每个 PR 独立测试运行
  • 结果直接回写 PR 评论
  • 含完整根因分析 + 修复方案
CI-Free

交给 Coding Agent

REST API

通过 loop-qa.replay.io REST API（OpenAPI），Coding Agent 可驱动完整 QA 循环，自动修复 Bug 直到清零。

  • 通过 API 创建 QA 项目
  • 轮询项目状态（不自行触发）
  • 读取每个 Bug 的根因报告
  • 直接在代码库应用修复
  • 通过 API 标记为已修复
  • 循环直到无 Open Bug
loop-qa.replay.io
深度 React 支持

组件树检查、渲染追踪（render tracing）、Effect 分析——显著提升 React 应用的 Bug 报告深度。Source Maps 开启时，失败可直接回溯至原始源代码（而非编译产物），修复建议包含正确的文件名和行号。

CI 集成模式（Replay CI Agent）

安装 GitHub Bot，将现有 Playwright 测试套件接入 Replay录制。CI 每次失败后，CI Agent 时间穿越录像，在 PR 下发布：①通俗语言根因说明 ②症状→根因执行链 ③含文件和行号的代码修复建议。无需复现步骤，无需日志考古。

时间穿越引擎：确定性浏览器录制

1

确定性录制（Deterministic Recording）

不同于视频或快照，Replay 录制捕获完整浏览器运行时：每个 DOM 变更、每个网络请求、每行 JavaScript 执行。

2

时间穿越回溯（Time-Travel）

Bug 发生时，引擎从症状反向穿越录制，追踪至真正的根因——而非停留在表面报错。

3

修复建议（Suggested Fix）

每份报告包含通俗语言解释、执行链追踪，以及可直接应用的代码修复方案（含文件路径和行号）。

⚠ 风险 / 边界提示

Replay Test Suites 已于 2024 年 8 月停止服务（与当前 Replay QA 为不同产品线）；请勿混淆。

独立运行模式依赖可公开访问的 URL；若应用仅在本地运行（localhost），需启用反向代理（reverse proxy）才可连接。

React 支持和 Source Maps 增强功能需应用本身使用 React 框架且开启 Source Maps，非 React 应用无法享受此深度分析。

GitHub App 连接模式需要仓库管理员授权；私有仓库需额外配置访问权限。

Coding Agent API 模式（loop-qa.replay.io）需要 Bearer Token 认证，API 密钥需自行安全管理。
