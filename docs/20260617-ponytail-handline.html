Ponytail：把 AI Agent 调成最懒的 senior dev

它不是在鼓励偷懒，而是在把“先别写，先想想有没有现成答案”这件事，变成每一轮都自动生效的规则：先问需不需要存在，再走 stdlib、原生能力、现有依赖，最后才是自己写。

works with 13 agents MIT ruleset + hooks less code
README 里最重要的一句：Lazy means efficient, not careless。
也就是说：不乱加抽象、不乱上依赖，但 trust boundary、数据安全、无障碍、校准和错误处理不能省。
80-94%代码量减少
3-6×速度提升
47-77%成本降低

“He says nothing. He writes one line. It works.”

最新 README 不只是讲一个 YAGNI 规则包，而是把它做成跨 Claude Code、Codex、Copilot CLI、Gemini / Antigravity、OpenCode、OpenClaw 等入口的可复制规则层。重点不是说教，是把“能不用写就不用写”自动化。

决策阶梯
how ponytail thinks
1
这真的需要存在吗？

先过 YAGNI，能删就删。

→ stdlib 优先 → 原生平台能力 → 已安装依赖 → 一行方案
2
标准库能不能直接做？

能用内置，就别再造一个包装层。

3
浏览器 / 操作系统 / 运行时已经有了吗？

原生特性比新依赖更“懒”，也更稳。

4
项目里现成依赖能解决吗？

已有包优先，避免拉新包。

5
能不能只写一行？

一行足够就别拉成十行。

6
最后才是最小可行实现

只有前面都不够，才自己写。

边界不打折：输入校验、数据丢失防护、安全、无障碍、现实硬件校准和明确要求的功能，永远不在“省代码”的裁剪范围内。

OpenCode

Gemini / Antigravity

extension / plugin 方式安装，rules 会常驻每个 session。

OpenClaw

ClawHub / skills 双路径都支持，命令和 skill 同步暴露。

编辑器侧

Cursor、Windsurf、Cline、Aider、Kiro、Copilot（editor）直接复制 rules 文件即可。

默认模式可由 PONYTAIL_DEFAULT_MODE 或 ~/.config/ponytail/config.json 控制；README 里明确写了：插件会在每轮重新注入规则，所以单次很短的 prompt，开销有时会抵消收益。
