把 1800+ 个站点，收进一个桌面工作流

OmniGet 是一个 Windows、macOS、Linux 桌面应用：以 yt-dlp 为下载引擎，把课程、视频、音频、书籍和本地媒体库放进同一个队列与播放器。

先判断：它解决的是工具碎片化

你可以直接使用 yt-dlp 获得最强控制力，也可以用 OmniGet 把“装 Python、记参数、换单站点下载器、再找播放器”的链路压缩为一个桌面入口。它的核心价值不是让每个平台都拥有同样的边角能力，而是把下载后的内容继续组织起来。

一条链接之后，实际发生什么

01 / INPUT

粘贴或全局快捷键

可将链接粘贴到 omnibox；也可复制链接后按 Windows/Linux 的 Ctrl+Shift+D 或 macOS 的 Cmd+Shift+D，让后台队列接管。

02 / RESOLVE

预览真实格式

应用通过 yt-dlp 解析标题、质量、字幕和音频格式；可以选择 4K、1080p、仅音频，或设置视频起止时间。

03 / ORGANIZE

下载后继续使用

队列支持重试与断点续传；课程可在内置播放器中继续观看，PDF/EPUB 可在阅读器中整理，音乐进入本地库。

5 步跑通：先下载一段你有权保存的内容

选择发行版

Windows 直接选 `.exe` 或 `.msi`；macOS 选对应架构 `.dmg`；Debian/Ubuntu 优先 `.deb`，其他 Linux 可选 `.rpm` 或 `.AppImage`。

处理首次启动提示

项目没有付费代码签名证书。macOS Gatekeeper 可能需要：

xattr -cr /Applications/omniget.app
codesign --force --deep --sign - /Applications/omniget.app
粘贴链接并预览

先确认标题、来源和可用格式，再选择画质、音频、字幕或片段范围；不要把“能解析”误认为“有权保存”。

让队列完成合并

yt-dlp 与 FFmpeg 会自动管理；遇到未知大小或直播流时，ETA 可能不是固定值，观察真实下载与合并阶段。

在本地消费结果

下载课程、视频、音乐或书后，分别进入播放器、音乐库或 PDF/EPUB 阅读器；需要脚本化时再单独使用 `omniget-cli`。

进阶：从桌面应用走向可复现脚本

桌面应用不需要终端。若你要做 cron、批量任务或 dotfiles，可从源码构建 CLI：

git clone https://github.com/tonhowtf/omniget.git
cd omniget
pnpm install
cargo build --release -p omniget-cli

omniget info <url>
omniget download <url> -q 1080 -o ~/Videos
omniget batch links.txt -m 3
Linux 坑：Debian 12+ / Ubuntu 24.04+ 的 AppImage 可能缺 FUSE 2，可安装 `libfuse2`，或使用 `.deb`。README 还明确指出：Linux 发行版说明曾出现错误，下载前应以当前 Releases 的资产为准。

边界与责任

适合

  • 自己拥有或明确获授权的课程、视频和资料
  • 想把下载、阅读、播放放在一个本地工作区
  • 需要 Windows / macOS / Linux 跨平台桌面入口

不适合

  • 绕过付费、DRM 或访问控制
  • 把平台支持数当作永久保证
  • 未经授权批量复制他人内容
