01 / 核心判断

判断
一句话结论

这个仓库的作用不是“教模型更聪明”，而是用四个原则把 LLM 的常见坏习惯提前钉死：别瞎猜、别过度设计、别乱动无关代码、别不设成功标准就开工。

四原则一眼看懂

  • Think Before Coding：先显式确认假设和歧义。
  • Simplicity First：只做必要内容，拒绝虚构的灵活性。
  • Surgical Changes：只碰用户要求的地方，别顺手重构。
  • Goal-Driven Execution：先定义可验证的成功标准。

怎么读这张卡

这是一个行为约束文件，不是模型评测文档。它把 Karpathy 对 LLM 编程常见问题的观察，翻译成 Claude Code 可执行的工作规范。

主线

不是多写提示词，而是减少不必要的模型自由度。

核心收益

更少假设、更少过度抽象、更少无关改动。

评价标准

看变化是否可追溯到用户请求和可验证目标。

02 / 四原则怎么解决四类问题

矩阵

Think Before Coding

解决“模型替你做决定、但没确认”的问题：显式假设、明确歧义、必要时提问。

Simplicity First

解决“过度设计、抽象膨胀、为了兼容而兼容”的问题：最小实现、拒绝额外配置。

Surgical Changes

解决“顺手改无关代码”的问题：只改请求相关行，清理只属于自己引入的残留。

Goal-Driven Execution

解决“没目标就开工”的问题：先定义成功标准，再用测试或验证闭环收口。

03 / 落地方式

使用
最实用的安装方式：把它写进项目级 CLAUDE.md，或者作为 Cursor rule / Claude Code plugin 使用。核心不是安装姿势，而是让这些规则随项目长期生效。
  • Think Before Coding：先写清假设、再开始实现。
  • Simplicity First：没有被要求的功能，默认不要加。
  • Surgical Changes：只改与你的任务直接相关的内容。
  • Goal-Driven Execution：先定义可验证的结果，再动手。

04 / 它为什么有效

原因

Karpathy 原话对应的四个坑

  1. 错误假设不问就跑。
  2. 过度复杂化和抽象膨胀。
  3. 乱动没要求改的部分。
  4. 没目标、没验收、靠感觉做事。

效果信号

如果这套指南生效，你会看到：diff 更小、澄清更早、返工更少、验收更清楚。它的目标不是让模型更“会说”，而是让它更像一个受约束的工程助手。
