CODEX / MONTHLY REVIEW

别只让 Codex 干活。

每月跑一次复盘 prompt，让它回头检查你的 threads 和 projects：哪些任务在重复，哪些步骤该固定，哪些经验能沉淀成模板、skill 或自动化。

当你频繁使用 Codex，却总是在重新描述相似需求，问题可能不是执行能力，而是没有定期整理自己的工作流。

每月 1 次横向看 threads使用子代理沉淀工作流
核心判断：Codex 不只是执行器，也可以成为你的工作流审计员。

把一次性解决方案，转成下一次可以复用的模板、skill、脚本或自动化任务。

01
WHY THIS MATTERS

问题不是做完，而是做完后没有留下东西。

一个线程解决了任务，却没有变成下一次可调用的资产；于是相似问题再次出现，你又重新开线程、重新描述、重新试错。

线程被当成一次性聊天

任务结束后直接放置，决策、命令、排错路径和成功条件没有被整理出来。

一次性成果不可复用

相似需求不断重写

当项目变多，重复劳动会隐藏在不同标题、不同仓库和不同线程里。

隐性重复重新描述
复盘的目标不是“总结得更漂亮”，而是回答：下次遇到类似事情，我能不能少开一个线程、少写一段说明、少走一轮弯路？
02
THE PROMPT

把这段话交给 Codex。

原始 prompt 很短，但它把 Codex 的角色从“完成当前任务”切换成“检查整个工作方式”。

Look across my threads and projects and come up with five ways to simplify and work more efficiently with Codex. Use sub-agents.
中文意思：查看我最近的 Codex 线程和项目，帮我提出 5 个可以简化流程、提高效率的做法。使用子代理分头分析。
03
USE SUB-AGENTS

让不同子代理看不同切面。

“Use sub-agents”不是装饰语，它可以把跨线程复盘拆成几个相对独立的观察任务。

A
找重复任务

扫描近期 threads 和 projects，识别反复出现的目标、技术栈、故障类型和交付形式。

B
找重复步骤

比较你经常手动执行的搜索、检查、测试、部署、汇报和收尾动作。

C
找可沉淀资产

判断哪些内容适合变成 prompt 模板、skill、脚本、项目模板或自动化任务。

D
合并成五条建议

最后让主代理去重、排序，优先给出能立刻减少重复劳动的改动。

04
FROM INSIGHT TO SYSTEM

把“发现”变成下一次能调用的东西。

高质量复盘不止给建议，还应该指出建议落在哪里、下次如何触发、怎样判断它真的省了时间。

Prompt 模板

适合重复出现、输入结构相近但结果不同的任务。保存触发条件、输入字段和输出格式。

低成本

Skill / 工作流

适合已经稳定重复、包含多个步骤和验收标准的任务，把方法固化成可加载的流程。

可复用

自动化任务

适合定期发生、规则清楚、无需每次重新决策的检查、汇报、同步或提醒。

定期运行
05
MONTHLY CHECKLIST

每月一次，形成轻量闭环。

不需要每天记录，也不需要为复盘建立复杂系统。先从固定节奏开始，再逐步沉淀。

01
选定回顾范围指定最近一个月的 threads、projects 或某一类任务，不要一开始就扩大到全部历史。
02
运行复盘 prompt要求 Codex 使用子代理分头分析，并明确要求输出五条可执行建议。
03
只落地一到两条优先选择能减少重复描述、重复检查或重复配置的建议，避免复盘本身变成新负担。
04
下个月验证收益观察是否少开线程、少写上下文、少走弯路；有效的再升级为模板、skill 或自动化。
一句话带走：不要只让 Codex 帮你完成更多任务，也要让它定期帮你减少“完成任务的重复方式”。
