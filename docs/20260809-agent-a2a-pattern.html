01 / CONCEPT

MCP 与 A2A 解决的不是同一件事

这是最容易被营销文案混在一起的两层。

MCP

解决 Agent 与工具、资源、提示之间的连接，让 Agent 有“手”。

A2A

面向 Agent 之间的发现、协商和协作叙事，让 Agent 能找到并请求另一个 Agent。

不能过度外推

A2A 的存在不等于你的 Agent 已经具备可靠协商、身份治理或业务级幂等。

02 / PATTERN

更稳的 80%：中心编排 + 专家回传

社区工程文章反复出现的共同模式，是让一个 orchestrator 持有全局计划。

单一计划持有者

主 Agent 拆任务、选择专家、接收结构化结果并决定下一步。

窄输入窄输出

专家 Agent 不直接自由聊天，只接收明确输入，返回 schema 化结果或错误。

人工检查点

涉及发布、付款、删除、外部发送等不可逆动作时，保留人类授权门。

03
03 / FAILURE

没有边界的 Agent 对话会怎么坏

这里是值得做成监控指标的失败模式，而不是泛泛的“多 Agent 很强”。

循环

A 把任务退回 B，B 又要求 A 补上下文；没有 max depth 就会持续消耗。

漂移

中间 Agent 扩大任务范围，最后没人知道原始目标是什么。

归因丢失

只统计 Agent 调用次数，不统计有用产出，无法知道成本是否值得。
