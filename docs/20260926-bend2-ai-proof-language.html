01机制核查：LAWS.bend 到底是什么

README 的三段论：后 AGI 时代人类不再读写代码，但仍需要无歧义语言向 AI 传达意图——laws 让意图比自然语言精确，proofs 让"AI 做对了"可机械验证，fast compiler 让它跑满算力。落地为一个文件 + 一条命令：

  1. 声明法律：把 app 不可破坏的规则让 AI 形式化进 LAWS.bend。README 例："所有余额之和恒为零"、"玩家不能穿墙"、"array_set() 永不越界"、"winning is impossible"——"Anything you can spell can become a law"。
  2. 强制证明：AI 每次改代码后跑 bend PROOF.bend。证明由 AI 写（def Laws.you_cant_win(moves): ...），编译器机械验证。
  3. 合并被挡：官方游戏 demo——law 是"赢不可能"；让 Claude 加"棋盘环绕"特性，无 LAWS.bend 时玩家绕过边缘拿到旗（bug 被合并），有则 AI 只好加一堵墙（也可以移旗、让房间杀人，唯独不能提交 bug，因为破坏 law 在数学上不可能，编译器强制）。
# LAWS.bend
law you_cant_win:                           # "winning is impossible"
  for moves: List<Game.Move>                # any sequence of moves
  board = Game.replay(Game.start(), moves)  # replayed from the start
  {Game.is_won(board) == False{} : Bool}    # never leads to victory
定位判断：这不是又一个 Lean/Agda。Lean 的对手是数学家，Bend 的对手是"AI 合并了 bug"——它把定理证明从"学术技能"降维成"写一个配置文件 + 让 AI 交作业"。官方在线 lab 可直接改 demo 代码试破坏 you_cant_win 定律。

02语言速览：Python 语法 + 依赖类型 + 仿射

语法刻意贴 Python（def/match/缩进），类型系统是仿射依赖类型论（论文 BendTT）。三个正交维度靠符号标注：-A erased（运行时擦除）、#n affine（至多用一次）、+x reusable（要 A 是 Data）；~f 是编译期模板不占运行时。两段官方示例：

# 并行：2^d，一棵 d 层树，每叶一个计算单元
def pow2(+d: Nat) -> U32:
  match d:
    case 0n: 1
    case 1n+p:
      a b = pow2(p) pow2(p)
      (a + b : U32)

def main() -> IO(Unit):
  result = pow2!(20n)          # `!` = 上 GPU
  IO.print(U32.show(result))
# 定理==laws，证明==defs
law add_zero:
  for x: Nat
  {Nat.add(x, 0n) == x : Nat}

def add_zero(x):               # 归纳：每步一个 %rewrite
  match x:
    case 0n: {==}
    case 1n+xp:
      %add_zero(xp) : {1n+Nat.add(xp, 0n) == 1n+_ : Nat}
      {==}

并行无需线程/锁/kernel：pow2(20) 分治到每个 GPU 核（官方 demo 铺满 4,096 核）再折叠回来。编译目标 C / Metal / CUDA / JavaScript（JS 单核、无图形音频；Lua/Luau/Python 计划中）。

03上手：三条命令 + 四行 AGENTS.md

  1. 安装：
    curl -fsSL https://bend-lang.com/install.sh | sh
    README 特别提醒：这个安装版 bend 会忽略项目的 bunfig.toml 和 .env；从 checkout 里 bun bend2/main.ts 跑则会读它们——测不信任的代码用安装版。
  2. 告诉你的 agent 用 Bend：把四行加进 AGENTS.md：
    When using Bend:
- run `bend guide` to learn it
- use `LAWS.bend` to keep important rules
- run `bend PROOF.bend` before committing
- parallelize the code whenever possible
    然后对 AI 说"use Bend"即可。bend guide 打印 39 节教程，bend base 打印标准库。
  3. 跑起来：bend PROOF.bend 过了才能 commit；想快的让 AI 并行化。官方建议 Linux/macOS、后端场景。在线 lab：bend-lang.com/#lab。
双重自指（这张卡最有意思的发现）：README 教你往 AGENTS.md 写"用 Bend"的规矩；而仓库自己的 AGENTS.md 规定——bend.ts（parser/理论/checker）是人写的，禁止编辑；编译器其余部分 99% 由 AI 写成（README Limitations 原话）。也就是说：Bend 用证明体系管 AI 的第一个大型项目，是它自己的编译器，且人只守语言核心那一层。

03.5这个仓库如何开发它自己（AGENTS.md 精读）

仓库自身的 AGENTS.md 是"AI 参与的编译器开发"的活样本，三层控制：

  1. 人写的核心：bend.ts（parser/理论/checker）人写禁改；其余（comp.ts 单编译器出 C runtime+C emitter+JS emitter、main.ts CLI、base.bend 标准库）由 AI 在规矩内写。
  2. 四道门禁：gates/test.ts 每个测试是一个 Bend 文件、以它必须打印的 #| 行结尾（金标准输出即断言），在 mini 集群分片跑；gates/perf.ts 性能基准跑 48 台 mini 对照 pins 文件（三次运行取中位数）；gates/repo.ts 文件白名单 + ttok 上限；gates/ping.ts 每日验证安装器、编译产物与版本。
  3. 论文级理论：两篇论文（BendTT 仿射依赖类型论 / BendRT 并行运行时，Typst 源码在 bend2/docs/），核心机械化为 bend.lean（Lean），并用两台 Mac 的硬件 pins 记录性能基线（apple_m4 门禁线 / apple_m4_max 纪录）。

对想抄"AI 工程化"作业的团队：这套"金标准输出测试 + 硬件 pins 性能门 + 文件白名单 + 每日安装 ping"就是 LAWS.bend 哲学在仓库基建上的投影。

05Limitations 精选（README 自己列了 30+ 条，罕见的诚实）

用前必读：全量显式标注、零类型推断，代码冗长；无 type classes/traits/macros；值是仿射的——闭包和数组不能共享；递归必须终止（@unsafe 可关检查）；数字只有 Nat/U32/F32（Metal 无 f64），F32 是公理化的——浮点行为不可证明；字符串是字符链表，文本处理慢；无 TLS/HTTP/JSON/regex；单 C 文件无增量编译，原生编译慢（开发用 JS 目标）；错误信息简短、无调试器/profiler/REPL；Windows 仅 WSL；Lean 形式化与 bend.ts 存在不匹配，早期可能有一致性 bug；编译器 99% AI 写且未经完全审计。Bend 1 程序与 HVM 不兼容——这是全新语言。

判断：LAWS.bend 把"AI 别写 bug"从 prompt 祈祷变成编译器强制，方向击中当下 vibe coding 最大痛点；代价是一门刻意朴素、生态近零的新语言。适合：AI 重度 vibe coding 且核心规则能形式化的新项目（金融不变量、游戏规则、协议实现）。不适合：要 f64、要 HTTP 生态、要快速文本处理的现有业务。观察点：release 频率极高（三天三版）说明处于暴力迭代期；"proof-backed AGENTS.md"这个抽象如果被 Claude Code/Cursor 生态采纳，价值远大于语言本身。
