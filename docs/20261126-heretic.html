HERETIC · LLM RESEARCH TOOL

自动搜索 Abliteration 参数，在拒答压制与模型保持之间取平衡

Heretic 把 directional ablation 与 Optuna TPE 优化组合成命令行流水线。它不是“训练一个新模型”，而是在 Transformer 权重上搜索干预方向与分层强度，并用拒答数量和 KL divergence 共同评价结果。

Python · PyTorchAGPL-3.043,207 stars · 2026-11-26latest v2.1.0
先定边界

降低拒答并不自动提升真实性、可靠性或安全性。项目适合受控研究与本地评测；派生模型的许可、发布、部署和使用责任仍由操作者承担。

01
MECHANISM

它怎样改变模型

核心不是提示词技巧，而是对模型内部矩阵做参数化的 directional ablation。

从拒答相关的 residual direction 出发

README 描述的方向来自 harmful 与 harmless 示例提示在首 token residual 上的均值差。工具按层得到候选方向，再把相关矩阵对这些方向做正交化，抑制它们在乘法结果中的表达。

1收集 harmful / harmless 示例，计算各层 residual direction
2干预 attention out-projection 与 MLP down-projection 等组件
3搜索方向索引、分层权重核与组件独立参数
4以拒答和 KL divergence 共同给候选方案评分
方向可插值

direction_index 不限整数

非整数值可在线性插值后探索相邻层方向之间的空间，扩大可搜索方向集合。

组件分开调

Attention 与 MLP 独立参数

官方观察认为 MLP 干预往往更容易损伤模型，因此分别搜索可改善合规度与质量的权衡。

权重核

干预强度随层变化

max/min weight、位置与距离共同定义跨层的消融权重形状，不必对每层使用相同强度。

无需后训练

目标是自动化处理

官方定位是不做昂贵 post-training，也不要求使用者理解 Transformer 内部细节。

02
COMPATIBILITY & COST

兼容性和资源要求

是否能跑，主要取决于架构识别、模型规模、精度、显存和 PyTorch 特性。

维度官方说明选型时要核对
模型架构支持多数 dense 模型，以及若干多模态、MoE 与 Qwen3.5 一类混合模型纯 state-space 和部分研究架构并非开箱即用
环境Python 3.10+、PyTorch 2.2+具体模型可能要求更高 PyTorch；MXFP4 示例涉及 2.6 的 torch.accelerator
显存启动时会 benchmark 系统并选择 batch size；支持 bitsandbytes 量化bnb_4bit 可降低显存，但质量、速度和兼容性要实测
时间官方示例：RTX 3090 默认配置处理 Qwen3-4B-Instruct-2507 约 20–30 分钟该数字不能外推到其他模型与硬件
输出动作保存、上传 Hugging Face、聊天测试、运行 benchmark上传前单独检查基础模型许可、派生条款与风险说明
03
MINIMAL START

最小启动形态

以下只保留官方 README 的环境与入口，用于理解工具形态；具体模型依赖和配置必须按硬件重新核对。

# 先安装与硬件匹配的 PyTorch，再安装 Heretic
pip install -U heretic-llm

# 以 Hugging Face model id 启动
heretic --model Qwen/Qwen3-4B-Instruct-2507

# 查看所有配置；仓库也提供 config.default.toml
heretic --help

依赖管理

仓库提供 uv.lock。使用 uv run heretic 可尽量对齐开发者锁定的依赖版本。

量化选项

README 提到把 quantization 设为 bnb_4bit 可显著降低处理模型所需显存。

配置入口

默认无需配置即可运行；高级控制可通过 CLI 参数或 config.default.toml 调整。

OFFICIAL EVIDENCE

怎样阅读官方 benchmark

数字适合验证项目主张，不适合直接当成所有模型和硬件的保证。

Gemma 3 12B

拒答 3 / 100

README 示例中 Heretic 派生模型与两个人工 abliteration 都达到 3/100。

官方报告更低偏移

同表中两个对照派生模型为 1.04 与 0.45；原模型按定义为 0。

条件限定

PyTorch 2.8 · RTX 5090

官方明确提示结果依平台和硬件变化；本卡没有复现实验，不把该结果泛化到其他模型。

05
RESPONSIBILITY

研究价值与风险边界要一起看

工具能降低拒答，但不会替你完成真实性、安全性、许可和部署治理。

适合：受控研究

比较不同消融参数、研究 refusal direction、对派生模型做系统评测，并保留基础模型对照。

不要混同：能力提升

更少拒答不等于更准确、更聪明或更可靠；KL 较低也不能覆盖全部行为变化。

发布前：单独治理

检查基础模型和 AGPL-3.0 的要求、模型卡与风险披露、数据与部署政策，以及对滥用场景的防护。
