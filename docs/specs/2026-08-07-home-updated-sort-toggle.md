# 首页“按修改日期排序”切换规格

**状态：** 待执行
**创建时间：** 2026-08-07 22:02:44 CST
**范围：** `infocard-pub` 首页归档列表

## Problem Statement

首页当前固定按卡片的首发/业务日期降序排列。已有卡片被补充、修订或完成审计后，虽然元数据的 `updated` 会更新，但用户无法在首页直接按修改时间查看近期有实质变更的旧卡。

这导致“最新发布”和“最新维护”两类内容混在同一种排序语义下：首发时间保持历史真实性，但近期更新的旧卡不易被发现。

## Solution

在首页搜索区下方、现有“筛选”按钮旁增加一个双态排序按钮，允许用户在以下两种降序之间切换：

- **按首发日期**：默认模式，保持当前首页行为与历史预期。
- **按修改日期**：按卡片 `updated` 字段降序排列，缺失或无法解析时回退至 `date`，再回退到现有的索引时间兜底。

按钮文案展示“下一次点击将切换到的排序方式”：

| 当前模式 | 列表排序 | 按钮文案 |
|---|---|---|
| 首发日期（默认） | 首发日期降序 | 按修改日期 |
| 修改日期 | 修改日期降序 | 按首发日期 |

切换排序不改变卡片元数据、不改变单卡详情页的时间展示，也不改变 taxonomy 筛选语义。

## User Stories

1. 作为归档访问者，我希望首页默认仍按首发日期排序，以便延续既有的浏览预期。
2. 作为归档访问者，我希望在筛选按钮旁看到明确的排序切换入口，以便不需要进入额外菜单即可查看最近维护的卡片。
3. 作为归档访问者，我希望点击“按修改日期”后，近期更新的旧卡靠前显示，以便发现内容升级。
4. 作为归档访问者，我希望再次点击后恢复按首发日期排序，以便在两种时间视角之间快速切换。
5. 作为归档访问者，我希望列表状态文本明确写出当前排序依据，以便不会误解“最新”的含义。
6. 作为使用搜索的访问者，我希望搜索结果在当前排序模式下重新排列，以便搜索与时间视角同时生效。
7. 作为使用 taxonomy 筛选的访问者，我希望筛选结果数量与命中集合不因排序切换而变化，以便排序不破坏筛选。
8. 作为移动端访问者，我希望排序与筛选控件在窄屏下保持可点击、可读且不横向溢出。
9. 作为通过浏览器前进/后退返回首页的访问者，我希望恢复离开前的排序模式、筛选条件、搜索词、已加载数量与滚动位置。
10. 作为刷新首页的访问者，我希望普通刷新恢复默认的首发日期排序，以便页面始终有一致的初始状态。
11. 作为维护者，我希望未填写 `updated` 的历史卡仍正常参与“按修改日期”排序，以便无需批量补写历史元数据。
12. 作为无障碍用户，我希望排序按钮可通过键盘操作并表达当前状态，以便理解和控制当前排序模式。

## Implementation Decisions

- 首页采用一个仅客户端使用的双态排序状态：`published` 与 `updated`；不增加升序、多字段排序、下拉菜单或 URL 参数。
- 默认状态为 `published`，按卡片首发/业务日期降序；这与当前首页默认行为一致。
- `updated` 模式的主排序键优先使用可解析的 `updated`；若缺失或不可解析，则使用 `date`；仍缺失时复用现有索引时间/文件时间兜底，保证每张卡都有稳定位置。
- 相同排序键使用现有稳定的标题/标识回退顺序，避免点击或重渲染时同时间卡片随机跳动。
- 排序必须发生在全文检索和 taxonomy 条件过滤之前的完整归档集合上；筛选只决定命中集合，排序只决定命中集合的展示顺序。
- 切换排序后重置增量渲染数量，并复用现有自动填充、加载更多和 IntersectionObserver 机制；不得出现旧排序的残留条目。
- 排序状态纳入现有首页 sessionStorage 状态，仅在浏览器 back/forward 还原；普通刷新不恢复排序状态，仍使用默认首发日期模式。
- 排序按钮与筛选按钮属于同一控制组，桌面端并列显示；移动端以不压缩搜索输入、无横向滚动为前提进行换行或自适应布局。
- 按钮需使用明确可见文案、`type="button"`、`aria-pressed`，并提供当前排序依据的文本反馈。
- 静态资源修改后更新首页 JavaScript/CSS 的版本参数，避免 GitHub Pages 或浏览器缓存继续加载旧逻辑。
- 首页索引构建逻辑和卡片侧边栏的“提交”时间展示规则保持原样；本功能只改变首页列表的可选排序。

## Testing Decisions

### 行为测试

以外部可观察行为为准，不对 Vue 内部变量或实现细节做脆弱断言：

1. 默认进入首页时，卡片按首发日期降序。
2. 切换到修改日期后，`updated` 更晚的旧卡排在较早首发但未更新的卡片之前。
3. `updated` 缺失、为空或无法解析时，卡片回退至 `date`，不会被排除或产生 `NaN` 排序。
4. 两卡排序时间相同时，顺序稳定且可重复。
5. 搜索和任一 taxonomy 筛选条件下，切换排序不改变命中数量和命中集合，只改变展示顺序。
6. 切换排序后，首批渲染、加载更多和自动加载不重复、不遗漏、不混入旧顺序。
7. 浏览器 back/forward 可还原排序状态；普通刷新回到首发日期默认模式。
8. 390px 视口下控件可见、可点击，无横向溢出，卡片列表仍可正常增量加载。

### 既有测试边界与参考

- 首页时间元数据已有测试覆盖“显示首发日期而不是批量维护更新时间”；新增测试不得改变该展示语义。
- taxonomy 筛选已有索引校验与模拟匹配逻辑；新增排序测试应证明其不改变筛选匹配。
- 构建后的注入索引、首页 JS、CSS 应通过现有站点构建与索引验证。

## Out of Scope

- 批量修改任何历史卡的 `date` 或 `updated`。
- 修改单张信息卡详情页的“提交”时间展示。
- 增加升序、按标题排序、按热度排序、多字段排序或可配置排序优先级。
- 通过 URL 查询参数共享或持久化排序偏好。
- 重构 taxonomy 筛选结构、首页视觉主题或增量加载架构。
- 创建或发布新的信息卡。

## Further Notes

- `date` 表示卡片的历史首发/业务日期，应保持真实性；`updated` 用于表示后来实质维护的时间。两者不能互相覆盖。
- 本功能针对“旧卡补充后，希望首页可按修改时间发现”的需求，首发日期仍是默认视图。
- 实施前应从最新 `origin/main` 创建隔离 worktree，避免当前主工作目录中已有的无关修改与未跟踪文件混入变更或提交。
- 实施完成后，生成产物应与源文件同一次提交；外部推送和 Pages 核验遵循信息卡发布门禁。
