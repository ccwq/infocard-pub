AI 处理页面，不预测密码

模型的输入是提取后的 HTML，输出是表单元素选择器。错误反馈主要帮助修正定位失败的元素，不是根据网站报错动态猜下一组密码。

01 · 分清两段流程

减少手工找表单，不等于减少密码搜索空间

项目将工作拆成两个阶段。第一阶段用 LLM 分析页面，再用 Playwright 检查模型给出的元素定位是否能用；第二阶段消费已有的表单分析结果与凭据列表。理解这个分工，才能判断“AI 加持”改变了哪里、没有改变哪里。

分析段：AI 给出定位建议

A

浏览器加载页面，提取输入框、按钮、相关表单与标签，组成模型输入。提取失败时可能回退到截断 HTML。

B

模型返回用户名输入框、密码输入框和提交按钮的 CSS 选择器。浏览器验证元素存在、输入与交互是否可行。

C

定位失败时，把失败元素的信息送回模型重试；验证后取得失败页面参考并保存分析结果。

尝试段：按已有列表运行

凭据来源是用户传入的文件或列表，不是从目标行业推导出的 AI 字典。README 描述了组合尝试与密码喷洒两种模式，但没有提供可复核的密码预测模型或命中率实验。

不能把定位重试写成攻击策略学习

选择器不存在、输入失败等反馈用于修复页面定位。它与理解“账号不存在”“密码错误”并自适应改变密码候选，是不同能力。

依据：BruteForceCore.py 的 stage1、_analyze_with_llm、_analyze_with_llm_retry、_validate_selectors_with_details；CLI 的凭据文件参数与 _load_data。

03 · 技术组成

浏览器、模型和数据库各做什么

Playwright

承担页面加载、表单元素验证与浏览器交互。项目不是只发送 HTTP 请求的字典循环，因此不能直接拿传统命令行工具的吞吐经验推算性能。

Ollama / Groq

前者通过配置地址调用模型，默认地址指向本机；后者走云端服务。源码的 provider 分支只有这两种，兼容 API 的路径名不代表第三方服务已经接入。

SQLite 与日志

保存表单分析和凭据尝试。数据库不是脱敏统计报表：尝试表包含密码文本，终端输出及文件捕获也可能留下凭据。

README 列出的运行条件是 Python 3.8+、Playwright、requests、PyYAML 和 Chromium。它们是文档要求，不是本文在所有平台实测通过的兼容承诺。仓库 README 徽标与 version.txt 为 v1.0.0；没有将 README 的模型推荐当成当前服务可用性保证。

04 · 数据流比“本地优先”标签更重要

网页内容和凭据，会留在哪？

模型输入：可能带有敏感页面字段

发送给 Groq 的是提取后的表单相关 HTML，完整表单可能包含隐藏字段。该路径未见专门的令牌或敏感属性脱敏。不能说“只上传选择器名称”，也不能夸大为“每次上传完整网页”。

本地存储：明文密码不是成功后才保存

数据库含 password TEXT，写入路径直接保存密码值，包括失败尝试。终端可能打印用户名和密码，输出捕获还会写入文件。真实账号凭据不应进入演示材料、共享日志或公开仓库。

通知：成功判定可能触发外发

配置通知渠道后，通知内容可包含目标、用户名、密码与公网 IP。启用通知不是纯粹的“进度提醒”，需要单独评估数据接收方与保留期限。

本地模型：不是整个工具的离线保证

Ollama 地址可配置；程序还有自动更新检查和公网 IP 查询路径。只有实际部署、网络访问和输出渠道都得到约束，才能讨论具体的数据边界。

依据：create_database、_attempt_login、_save_brute_force_attempt、_extract_form_content、_groq_request、_send_success_notification、_get_external_ip；CLI 的 OutputCapture。

05 · 结果怎么验收

页面变化，不能单独证明登录成功

源码利用失败参考页面与当前页面的 DOM 长度差，或者固定成功 / 失败词的启发式统计，判断一次登录是否成功。这种信号只是工具推断：动态提示、错误页变化或跳转都可能改变页面，准确性需要在可控测试环境另行验证。

防守方的第一步：先定义证据，而不是先启动工具

把许可和目标授权分别确认；使用隔离环境与测试账号，记录服务端认证事件、会话是否真正建立，以及是否访问到约定的受保护资源。工具输出“成功”只能是待复核线索，不应直接作为漏洞结论。

  • 身份防线：检查 MFA 或通行密钥是否覆盖关键入口，避免仅靠密码保护管理端。这是防守建议，不是本项目已实现的保护。
  • 服务端控制：确认限速、账号锁定与异常登录监测的预期行为，检查安全措施是否会误伤合法用户；不以规避告警作为测试目标。
  • 测试数据：使用虚构测试凭据，限定数据库和日志访问权限，约定保留期限；模型外传和通知渠道需要单独审批。
  • 判定质量：分别记录工具判定、服务端事实与人工复核，保留误报和漏报，不只汇总“命中数量”。

没有授权的第三方登录页面、真实账号或不明确的漏洞赏金范围，不适合作为试验对象。本次没有安装或执行该工具，也没有向任何网站提交测试凭据。
