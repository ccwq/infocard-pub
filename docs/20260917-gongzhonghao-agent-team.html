01
背景 · Automation
公众号内容生产的自动化需求

人工运营的痛苦：

  • 选题高压：每日需追踪热点，人工筛选效率低、容易遗漏
  • 写作耗时：深度文章需2-4小时，碎片化内容同样消耗精力
  • 排版繁琐：配图筛选、格式调整、封面制作占用大量时间
  • 发布重复：8个公众号各自登录、切换、复制粘贴

8个垂直领域的规模挑战：

维度差异
内容方向AI科技/论文解读/投资/数码/游民/时尚/合规/军事，各有专业门槛
受众画像技术开发者/研究者/投资者/消费者/远程工作者/设计师/合规官/军事爱好者
写作风格严谨学术 vs 犀利评测 vs 中英双语合规 vs 数据驱动
更新节奏每日热点 vs 每周论文深度 vs 实时政策跟踪

现有方案的局限：

方案问题
RSS聚合质量参差、去重困难、无原创能力
AI写作平台缺乏垂直深度、风格单一、无法对接公众号
人工+AI混合流程割裂、无统一调度、发布仍需手动
单一脚本抓取无智能体协作、无质量控制、无法多账号并行
核心价值：一套系统覆盖8个垂直领域，全自动生产+发布。主编智能体自动发现热点 → 编辑智能体深度研究撰写 → MCP工具直连公众号草稿箱，全程无需人工介入。

调度脚本 · Scheduler
调度脚本设计

daily_ai_news.py核心结构：

#!/usr/bin/env python3
import argparse, schedule, time, subprocess
from datetime import datetime

def parse_args():
    p = argparse.ArgumentParser(description="AI科技资讯自动生成")
    p.add_argument("--now", action="store_true")
    p.add_argument("--count", type=int, default=1)
    p.add_argument("--time", nargs="+")
    p.add_argument("-v", "--verbose", action="store_true")
    return p.parse_args()

def run_claude_code(n, verbose):
    prompt = "生成" + str(n) + "篇AI科技资讯文章。"
    cmd = ["claude", "--print", prompt]
    if verbose:
        print("[" + datetime.now().isoformat() + "] 启动Claude Code...")
    return subprocess.run(cmd, capture_output=True, text=True).stdout

def main():
    args = parse_args()
    if args.now:
        run_claude_code(args.count, args.verbose); return
    for t in args.time or ["08:00", "20:00"]:
        schedule.every().day.at(t).do(run_claude_code, args.count, args.verbose)
    while True:
        schedule.run_pending(); time.sleep(60)

命令行参数：

参数说明
--now立即执行，不等待定时调度
--count N每次执行生成N篇文章
--time HH:MM设定每日执行时间（北京时间）
-v / --verbose输出详细日志

完整代码 · Full Code
调度脚本完整代码
#!/usr/bin/env python3
"""AI科技资讯调度脚本 - 完整版"""
import argparse, schedule, time, subprocess
from datetime import datetime
from pathlib import Path

SCRIPT_DIR = Path(__file__).parent
AGENT_DIR = SCRIPT_DIR  # Claude Code在同目录读取.claude/agents/

def parse_args():
    p = argparse.ArgumentParser(description="AI科技资讯自动生成")
    p.add_argument("--now", action="store_true", help="立即执行")
    p.add_argument("--count", type=int, default=1, help="生成文章数量")
    p.add_argument("--time", nargs="+", help="每日执行时间(BJT)")
    p.add_argument("-v", "--verbose", action="store_true")
    return p.parse_args()

def run_claude_code(topic_count, verbose=False):
    prompt = f"生成{topic_count}篇AI科技资讯文章。搜索当日AI领域热点，每篇800-1500字，包含相关图片(3-8张)，输出为Markdown格式。"
    cmd = ["claude", "--print", prompt]
    if verbose:
        print(f"[{datetime.now().isoformat()}] 启动Claude Code...")
    result = subprocess.run(
        cmd, capture_output=True, text=True,
        cwd=str(AGENT_DIR)  # 关键：cwd确保读取正确的.claude/agents/
    )
    if result.returncode != 0 and verbose:
        print(f"[ERROR] Claude Code failed: {result.stderr}")
    return result.stdout

def main():
    args = parse_args()
    if args.now:
        run_claude_code(args.count, args.verbose)
        return
    times = args.time or ["08:00", "20:00"]
    for t in times:
        schedule.every().day.at(t).do(run_claude_code, args.count, args.verbose)
    print(f"调度已设置: 每天 {', '.join(times)} 执行")
    while True:
        schedule.run_pending()
        time.sleep(60)

if __name__ == "__main__":
    main()

关键设计：cwd参数确保Claude Code在正确公众号目录执行（读取对应的.claude/agents/和.mcp.json）；subprocess返回码非0时记录日志，不阻塞后续调度。

局限与改进 · Limits
局限性与改进方向
局限影响缓解方案
人工审核门槛无法完全无人值守草稿箱审核仍是最后把关

改进方向：
