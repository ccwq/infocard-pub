01

结论：有三条可用路线

EXECUTIVE SUMMARY
推荐决策

要“看起来是同一个人”的多角度肖像：先用 GPT Image 或 Gemini 图像编辑做多照片锚定；要批量、可控、可私有部署：用 InstantID / PuLID + FLUX 或 SDXL；要追求可旋转的头部几何：先做 DECA/3DMM，再用生成模型补质感。

关键边界：侧脸、耳部、发际线遮挡区等未被照片覆盖的信息，模型会基于先验补全。输出应标记为“AI 合成视角”，不能当作证据照片、身份认证素材或法医级复原。
02

统一工作流：先锚定，再扩视角

PIPELINE
A / 采集

覆盖角度

正脸、左右 30–60°、轻侧脸；保留高分辨率原图。

B / 清洗

筛掉干扰

剔除强滤镜、极端表情、运动模糊；统一裁切但不要过度磨皮。

C / 身份锚定

参考图分角色

脸型与五官、发型、肤质分别明确为“必须保持”。

D / 生成

一次一个角度

固定镜头、焦距、光照与背景；按正→45°→侧脸递进。

E / 筛选

人脸相似度 + 人审

用人脸 embedding 仅作排序；最终检查局部特征与跨图连续性。

03

方案矩阵：按交付目标选模型

MODEL ROUTES
SaaS / 最快落地

GPT Image（gpt-image 系列）

OpenAI 官方图像指南明确：编辑时可用一张或多张图像作为参考。适合把多张人像作为共同约束，输出指定镜头角度与视觉风格。

  • 适合：少量成片、人工审稿、产品原型。
  • 做法：多图 edits / Responses 输入 + 明确“保留的身份特征”。
  • 限制：不是专门的 3D 身份模型；跨批次需建立“锚图”。
SaaS / 对话编辑

Gemini 图像（Nano Banana）

“Nano Banana”常指 Gemini 图像生成/编辑能力。适合多轮对话式修正：先做标准正脸锚图，再用该锚图扩展 45° 与侧脸。

  • 适合：快速迭代与自然语言细修。
  • 做法：一次只改角度；其它条件写成“保持不变”。
  • 限制：请以 Google 官方 Gemini API 文档为准，不信任同名第三方站点。
开源 / 零样本

InstantID

项目公开定位为零样本身份保持生成：用人脸 ID embedding、轻量适配器与空间控制结合，支持姿态与风格变化；项目页还展示 multi-reference。

  • 适合：不想为每人训练 LoRA、希望接 ControlNet 姿态控制。
  • 做法：选一张最标准的人脸作为主 ID，其余图用于多参考或筛选。
  • 限制：对遮挡、妆容、极端角度仍会漂移。
开源 / FLUX

PuLID（含 FLUX 路线）

PuLID 是面向身份定制的开源方案；官方仓库包含 FLUX 相关支持。适合 ComfyUI / 本地 GPU 工作流，将身份条件、姿态条件和文本场景分开控制。

  • 适合：批量生成、私有数据、可重复参数记录。
  • 做法：锁定 seed、ID 强度与姿态控制；每个角度出多张候选。
  • 限制：部署依赖模型权重与显存；需要技术调参。
04

推荐实现：两阶段多图锚定

PRACTICAL RECIPE

这条路线适合 GPT Image 或 Gemini：不要把“生成九宫格多视角”作为第一步。先产出一个稳定的基准肖像，再以它为主锚图逐角度编辑，能显著减少不同输出之间的身份漂移。

# 阶段 1：从多张来源图合成“身份锚图” 输入：6–15 张同一人照片（含正脸 + 左右 30–60°） 提示：基于所有参考图，生成一张中性表情、自然日光、85mm 人像、正面或轻微 15° 转头的身份锚图。 必须保持：脸型比例、眉形、眼距、鼻梁轮廓、唇形、下颌线、发际线；不要美颜，不要改变年龄或种族。 # 阶段 2：以锚图为主参考，按单角度扩展 输入：身份锚图 + 1–3 张原始侧角度图（若存在） 提示：保持人物身份与上述面部特征完全一致；仅将头部转为“左侧 45°”， 镜头高度、85mm 焦距、柔和日光、灰色背景、表情不变。输出单张写实头肩肖像。 # 阶段 3：针对失败图做局部而非全量重抽 提示：保留眼距、鼻尖形态、下颌宽度和发际线；仅修正右耳/颧骨/侧鼻轮廓。
05

质量控制：把“像”拆成可验收项

QA CHECKLIST
01 · 参考覆盖度

每侧至少有一张清晰 30–60° 照片。缺失角度越多，补全成分越高。

02 · 几何连续性

核查眉弓、鼻梁、颧骨、下颌与耳位在正脸—侧脸之间是否连续。

03 · 身份相似度排序

可用 ArcFace / InsightFace embedding 对候选排序；阈值不是“真实身份”的证明。

04 · 人工局部复核

优先看最不易被风格掩盖的细节：眼距、鼻翼、唇峰、发际线、痣/疤（如确有）。

05 · 批间稳定性

保留锚图、提示词、模型版本、seed / 强度。不要每张图都从原始多图重新开始。

06 · 标注输出性质

文件、元数据和展示页注明“AI 生成的多视角外观图”，避免与原始照片混用。

06

什么时候要走 3D 路线

GEOMETRY VS. APPEARANCE

需要“视觉成片”

选生成式路线。它更擅长肤质、光影、头发和摄影感，但对未观测部位的几何有不可见的不确定性。

需要“可旋转几何”

先用 DECA 等 3DMM 重建脸部形状与表情，再从多个视角渲染。纹理和头发通常还需生成式模型修复；这也不是精密扫描的替代品。

07

边界与风险

NON-NEGOTIABLE

授权与隐私

仅处理本人或已获得明确授权的人像；保留授权范围和数据删除机制。不要把输入照片上传到不明第三方“Nano Banana”站点。

真实性表达

生成图不能用于身份核验、门禁、人脸支付、证据采信或冒充。对外展示时，应保留合成标注和来源记录。

偏差来源

化妆、滤镜、年龄跨度、表情、镜头畸变与遮挡都会导致模型在不同角度“重写”身份特征。

可复现性

商业模型会升级；开源模型会依赖权重版本。需保存模型版本、输入清单、提示词和候选筛选标准。
