DeepSeek Harness 是什么？

DSH 核心概念

Architecture
"一切皆插件" 的 Agent 运行时
MIT

DeepSeek Harness（dsh）是 DeepSeek 官方 2026-08-13 开源的多模型 Agent 运行时。"一切皆插件"（Everything is a plugin）意味着模型、工具、UI、协议网关都是可插拔的模块，而非硬编码的 monolith。Workdsh 基于 DSH 构建，继承这一架构，同时增加了自己的桌面工作台界面。

插件加载顺序（四层覆盖机制）
重要

DSH 配置按优先级从低到高叠加：① 组合包基础层 → ② profile 用户层 → ③ home 级覆盖 → ④ 启动参数 overlay。后应用层覆盖前面的同名配置，这是插件系统的核心工作原理。

本地优先 · 隐私可控
Local

DSH 所有数据默认存储在本地目录（~/.dsh/），凭证单独存放在 ~/.dsh/.credentials.yaml（只写不可读）。这意味着即使用云端 API 付费模型，数据本身仍在本地。

DSH 架构概览Reference
# DSH 四层加载顺序（优先级从低到高） # ① 组合包层（bundles）— 基础能力 @deepseek-ai/dsh-base ← 核心运行时 @deepseek-ai/dsh-web-app ← Web UI 界面 workdsh-plugin ← Workdsh 工作台插件 # ② profile 层 — 用户自定义配置 ~/.dsh/profiles/web/cordis.patch.yml # ③ home 级覆盖 — 多 profile 共享 ~/.dsh/cordis.patch.yml # ④ 启动参数 overlay — 命令行即时生效 dsh --profile web --patch extra.yml # 数据存储路径 ~/.dsh/ ← DSH home（默认） ~/.dsh/profiles/ ← 各 profile 配置 ~/.dsh/.credentials.yaml ← 密钥（0600，仅写权限） ~/.dsh/settings.yaml ← 全局设置 ~/.dsh/cache/ ← 模型列表缓存
初学者指南

5 步跑通第一个任务

1

安装 Workdsh

从 GitHub 下载对应平台的安装包（Windows / macOS / Linux）。桌面端下载后双击运行，无需额外配置 Node.js 环境。
前置条件（可选，CLI 模式）：Node.js ≥ 22.19。如果用桌面安装包则不需要。
2

配置模型 API

打开设置 → 模型，填入 DeepSeek API Key（或添加其他提供商）。密钥存入 ~/.dsh/.credentials.yaml，不在会话日志中明文出现。
DeepSeek API 申请：前往 platform.deepseek.com 注册并充值，建议至少 $2 起充，Flash 档费用极低。
💡 也可通过环境变量配置
export DEEPSEEK_API_KEY="sk-xxxx" 启动时 DSH 自动读取，不弹窗要求输入。
3

选择 / 创建工作区

点击工作区选择器，添加一个本地目录作为 AI 的工作范围。建议新建空目录用于测试，避免误操作重要文件。
⚠️ 安全边界说明
DSH 默认在 workspace-write 模式下运行——文件修改和命令执行被限制在选定工作区内。首次使用建议先观察 AI 的操作审批弹窗，确认行为正确后再授予更高权限。
4

选择运行模式

DSH 支持 5 种运行模式（Standard / Code / Minimal / Creator / 自定义）。新手默认用 Standard 模式即可，开箱即用包含文件编辑、Shell、检索、Skills 和子 Agent。
5

发出第一个任务

在 Workdsh 中新建会话，给出明确任务。推荐先用只读任务校准：
"Summarize this repository and identify its main packages."
观察审批弹窗 → 确认 AI 读取了正确目录 → 验证会话日志完整记录了过程 → 确认无误后再给写入权限。
💡

推荐的第一个任务

Workdsh 的六大模块各司其职，建议按这个顺序体验：
① 用 Projects 创建项目，添加指令和计划
② 用 Library 导入参考资料
③ 用 Experts 保存 Coding Assistant 角色
④ 用 Skills 从 SkillHub 搜索安装一个技能
⑤ 在 Deliverable 预览生成的文档

常用插件推荐

Plugins
dsh-claude-marketplace
工具

加载 Claude Code 本地已安装的 skills 和 commands，让 DSH/Workdsh 继承你的 Claude Code 积累。

dsh-plugin-session-import
工具

从 Claude Code 或 Codex 导入历史会话记录，保留上下文继续工作。

dsh-fail-logger
调试

记录失败的工具调用，方便排查 agent 行为异常，是开发调试必备。

dsh-latex-tools
预览

在 Web UI 中悬停即渲染 LaTeX 公式，适合处理数学文档。

dsh-cloudflare-browser-run
浏览器

提供浏览器工具，让 agent 能在网页上执行操作（需 Cloudflare 账号）。

dsh-at-file
快捷

在输入框输入 @文件名 即可调用文件内容，无需完整路径。

插件安装命令bash
# 安装插件（需要先全局安装 pnpm） # npm i -g pnpm ➜ dsh plugin --profile web add dsh-claude-marketplace ➜ dsh plugin --profile web list # 确认安装结果 ➜ dsh plugin --profile web remove dsh-claude-marketplace # 卸载 # 从 GitHub 直接安装（无需 npm 发布） ➜ dsh plugin --profile web add github:username/repo # 搜索可用插件 ➜ npm search dsh-plugin
💡 从 GitHub 安装的注意事项
从 GitHub 安装拉取的是源码而非构建产物。TypeScript 插件包如果没有构建好 lib/ 目录，需要包作者提供 prepare 脚本，且 pnpm ≥10 需要在 pnpm-workspace.yaml 中设置 allowBuilds 授权才能自动构建。安全建议：只对可信源码授权构建，并锁定 commit。

排障指南

常见问题与解决

!

MISSING_CREDENTIAL 报错

原因：API Key 未配置或环境变量未设置。
解决：在 Workdsh 设置 → 模型中填入 Key，或设置环境变量 export DEEPSEEK_API_KEY="sk-xxxx" 后重启。
!

UNKNOWN_MODEL 报错

原因：选择的模型在当前 provider 中不存在，或 provider 未添加。
解决：先去设置 → 模型确认 provider 已添加，再用模型选择器选择已配置的模型。
!

401 Unauthorized

原因：API Key 错误或账号余额不足。
解决：前往 platform.deepseek.com 检查 API Key 是否正确、账户是否有余额。Flash 模型费用极低，充值 $2 可用很久。
!

插件安装 ERR_PNPM_FETCH_404

原因：npm 包名拼写错误，或 npm 镜像源未同步最新版本。
解决：先用 npm view <包名> 确认包存在；再试加 --registry=https://registry.npmjs.org 指向官方源。
!

文件修改没有生效

原因：工作区目录选择错误，或权限不足。
解决：确认左上角工作区选中的是目标目录；检查目录是否有写权限；如果是首次使用，可先给 Agent 只读权限观察行为。
✓

工作正常但想提速

如果任务简单（如单轮问答），可以在模型选择器切换到 Flash 档，费用更低、速度更快；复杂推理任务用 Pro 档。
缓存技巧：DeepSeek Flash 模型会话内缓存命中率实测可达 97%，连续对话成本大幅降低。

谁适合用 Workdsh？

典型使用场景

Use Cases
🔬 长期项目维护

用 Projects 管理多个项目的指令和计划，AI 始终知道项目背景和目标，不必每次重述上下文。

📚 资料驱动的任务

用 Library 导入参考文档、论文、数据集，AI 可以在任务中直接引用，输出结果更贴合实际背景。

👥 团队知识复用

用 Experts 保存资深开发者的角色设定，用 Skills 沉淀团队的标准化操作流程，新成员可快速继承。

📦 多格式交付物管理

用 Deliverable 预览 AI 生成的 Word / Excel / PPT / PDF，无需切换到其他应用直接在 Workdsh 中核对格式。

🔌 接入外部工具

用 Connectors 连接 GitHub、Jira、数据库等外部系统，让 AI 在统一工作台内完成跨平台任务。

🤖 自动化脚本 / CI

通过 DSH Headless 模式 dsh --profile headless "任务" 将 AI 能力嵌入 CI 流水线，自动化代码审查、文档生成等重复工作。

⚠️ 当前阶段的注意事项
Workdsh 基于 DSH 生态构建。DSH 目前处于 developer preview 阶段（版本 0.1.0-rc.x），官方明确提示会有破坏性变更。如果要在上面构建长期项目，建议锁定版本号，避免上游更新导致配置失效。
