01 Core Positioning

一句话判断：LightAgent 前端模块是「标准 API + 事件流 + 浏览器兼容层」的三位一体接入方案

LightAgent 的前端设计不是「另起一套协议」，而是完全对齐 OpenAI API 风格，让已有的前端代码几乎零改动接入 Agent 能力。核心价值在于把 Python Agent 框架的能力，通过 HTTP / SSE / browser-use 三种路径透传给 Web 前端。

API 风格

OpenAI-compatible

base_url + model + api_key 对齐 OpenAI SDK，前端无需感知底层是哪个推理服务。

通信方式

HTTP + SSE

同步请求走 HTTP，实时事件走 Server-Sent Events，两种模式按场景切换。

浏览器兼容

browser-use

可选的浏览器自动化兼容层，支持网页截图、表单填写、元素操作等前端场景。

02 Integration Modes

三种前端接入模式：选对路径，不做过度工程

前端接入路径对比
OpenAI SDK
最简路径：pip install lightagent 后直接用 OpenAI Python SDK 调用，base_url 指向 LightAgent 服务。适合已有前端零改动迁移。
HTTP REST
手动构造 POST 请求，body 走 model / messages / tools，响应走 result_format="object"。适合需要精细控制请求参数的场景。
SSE 事件流
通过 stream=True 开启 Server-Sent Events，实时推送工具调用、推理步骤和最终结果。适合聊天界面和长任务追踪。
browser-use
可选兼容层：需要 provider helper，适配浏览器自动化场景。适合需要操作真实网页的前端任务。
03 API Contract

关键 API 参数与返回值

参数类型说明
modelstring模型标识符，对齐 OpenAI API 风格
api_keystring认证密钥，支持任意 OpenAI-compatible provider
base_urlstring指向 LightAgent 服务地址
toolsarray工具列表，支持 Python function 或 MCP
result_formatstring"string"（默认）或 "object"（结构化）
tracebool可选，开启结构化可观测输出
streambool可选，开启 SSE 实时流
// 前端接入示例（OpenAI SDK 风格）
from openai import OpenAI

client = OpenAI(
    api_key="your_api_key",
    base_url="http://localhost:8000"  # LightAgent 服务地址
)

# 基础对话
response = client.chat.completions.create(
    model="gpt-4.1",
    messages=[{"role": "user", "content": "Check weather in Shanghai"}]
)
print(response.choices[0].message.content)

# 结构化输出
result = agent.run(
    "Analyze this code",
    result_format="object",
    trace=True
)
print(result.content)
print(result.trace_id)
04 Output Formats

三种输出格式：按需选型，不做过度设计

STRING

默认字符串

最简单场景：直接返回 LLM 生成的文本字符串，前端渲染即可。

OBJECT

结构化对象

result_format="object" 返回 {content, trace_id, metadata}，适合需要解析工具调用结果的场景。

STREAM

SSE 事件流

stream=True 实时推送中间步骤，适合需要展示推理过程的长任务界面。

输出选型建议

一般对话 → 默认字符串；需要解析工具结果 → 结构化对象；需要实时反馈 → SSE 事件流。不要混用，过度设计会增加前端复杂度。

05 Boundaries & Risks

前端集成的边界与风险清单

CORS 跨域

跨域请求配置

生产环境需要正确配置 CORS 头，避免前端请求被浏览器拦截。开发阶段可用代理转发。

流式输出

SSE 兼容性

SSE 在部分 CDN 或 API Gateway 环境下可能被改写，需要确保端到端支持 text/event-stream。

认证安全

API Key 管理

不要在前端直接暴露 api_key，生产环境建议通过后端代理转发请求并做鉴权。

浏览器兼容

browser-use 适配

browser-use 依赖外部服务，部分版本需要 provider helper，不是开箱即用。

场景推荐方案风险提示
通用对话默认字符串 + HTTP最低风险，开箱即用
工具调用结构化对象 + tools需要后端代理做鉴权
实时界面SSE 事件流确认网络路径支持 SSE
网页自动化browser-use依赖外部服务，非标准路径
06 Quick Start

前端接入三步走：安装 → 配置 → 调用

安装 LightAgent

→
前端调用
// Step 1: 安装
pip install lightagent
# 或带可选依赖
pip install "lightagent[mem0,tracing]"
// Step 2: 启动服务（示例）
# 使用任意 OpenAI-compatible 端点
python -m lightagent.server \
  --model gpt-4.1 \
  --base-url https://api.openai.com/v1 \
  --api-key $OPENAI_API_KEY
// Step 3: 前端调用（JavaScript 示例）
import OpenAI from 'openai';

const client = new OpenAI({
  apiKey: 'your-key',
  baseURL: 'http://localhost:8000/v1'
});

const response = await client.chat.completions.create({
  model: 'gpt-4.1',
  messages: [{ role: 'user', content: 'Hello, who are you?' }]
});

console.log(response.choices[0].message.content);
