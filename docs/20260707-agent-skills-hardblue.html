Agent Skills：Google 工程纪律的 AI 工作流

Google Engineering & DevRel Lead @addyosmani 开源。把资深工程师的生产级工程纪律，固化为 AI Agent 可机械执行、强制验证、跨工具复用的工作流。质量不靠提醒，要靠强制流程托底。

核心问题
AI Agent 默认行为
走最短路径——跳过规格、跳过测试、跳过安全评审，给出能跑但不可靠的代码
传统解法局限
靠 prompt 提醒 → 写太细 AI 不敢变通；写太粗 AI 按"最佳实践"猜，永远找不到平衡点
↓
Agent Skills 的立论
质量不靠提醒，要靠强制流程托底。 把"什么时候写规格、测什么、怎么评审、何时发布"固化成 Agent 必须遵循的步骤。

值得点名的设计
doubt-driven-development 原创性
对抗性"新上下文复盘"——CLAIM → EXTRACT → DOUBT → RECONCILE → STOP，可选跨模型升级。针对高代价/不可逆决策的主动质疑机制。
source-driven-development 反幻觉
框架决策必须挂在官方文档上，要引源、要标注未验证项。直接对治 LLM 编造 API。
deprecation-and-migration 工程味
把"代码即负债"单列为技能，配套强制 vs 建议性弃用模式与僵尸代码清除。很少见但有工程味。
spec-driven-development
先写规格再实现，规格是验收标准的来源而非注释的补充。
