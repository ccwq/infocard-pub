01
What is WebMCP

WebMCP 是什么

Web Model Context Protocol — 将网页暴露为 AI 代理可调用工具的浏览器原生开放标准

一句话定义

网页即工具集

WebMCP 让每个网页通过 document.modelContext API 向 AI 代理声明自己的功能（工具），代理用自然语言描述需求，浏览器负责发现、调用、返回结构化结果。

  • W3C 社区组开放标准
  • Google + Microsoft 联合撰写
  • 与 Anthropic MCP 协议对齐
为什么现在出现

DOM 抓取的时代困境

AI 代理操作网页靠「猜测 DOM」——选择器脆弱、跨浏览器不一致、页面一改就失效。用户需要的是「可靠的自动化」，而非「脆弱的屏幕识别」。

  • 元素选择器易失效
  • 截图 + OCR 精度有限
  • 无结构化类型保障
02
Three Pillars

三大核心设计支柱

Discovery、JSON Schema、State 构成 WebMCP 的完整能力三角

支柱一

Discovery · 工具发现

网页通过标准 API 注册工具，浏览器向代理暴露发现接口。代理无需访问页面源码，只需查询浏览器即可知道「页面能做什么」。

  • 标准注册接口：registerTool()
  • 浏览器统一暴露
  • 跨域工具查询（需授权）
支柱二

JSON Schema · 类型化 I/O

每个工具都有 JSON Schema 定义的输入输出——代理不会填错参数，服务器返回结果结构化可解析，从根本上消灭幻觉参数问题。

  • 声明式参数类型
  • 自动验证与纠错
  • 与 MCP 协议完全对齐
支柱三

State · 实时页面状态

浏览器向代理共享当前页面的实时上下文——已登录状态、购物车内容、搜索结果分页……代理与用户看到的是同一份状态。

  • 共享 signed-in 会话
  • 实时 UI 状态同步
  • 代理与用户协作操作
03
Core API

document.modelContext API

核心接口示例与声明式表单两种使用方式

// 声明式：HTML 表单自动生成 WebMCP 工具
<form modelContext tool-name="add-todo"
         tool-description="添加新待办事项"
         tool-param-title="text"
         tool-param-description="待办内容">
  <input name="text" required>
</form>

// 命令式：JavaScript API 完整控制
if (document.modelContext) {
  await document.modelContext.registerTool({
    name: "buyProduct",
    description: "购买商品",
    inputSchema: {
      type: "object",
      properties: {
        product_id: { type: "string", description: "商品 ID" }
      },
      required: ["product_id"]
    },
    execute: async ({ product_id }) {
      // 复用现有业务逻辑
      await addToCart(product_id);
      return { content: [{ type: "text", text: "已加入购物车" }] };
    }
  });
}

07
Fit Assessment

适用场景评估

WebMCP 适合需要 AI 代理可靠操作网页的场景，服务器端 MCP 仍有不可替代的价值

✓

适合 WebMCP

需要 AI 代理操作已有 Web 应用的场景（电商、预订、内容发布）；需要复用现有 UI 逻辑而不重新实现后端 API。

✓

互补关系

WebMCP 与服务器端 MCP 相辅相成：浏览器侧用 WebMCP，本地文件/数据库用 MCP，完整覆盖代理所需工具。

✗

不适合

完全无 UI 的后端 API 调用（用服务器 MCP）；需要毫秒级低延迟的工具调用（WebMCP 有浏览器中介开销）；简单 CRUD 操作（REST 更直接）。
