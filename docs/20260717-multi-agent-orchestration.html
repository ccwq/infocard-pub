多智能体编排 · 技术路线图

三条路线，
三种控制感

AutoGen、CrewAI、LangGraph 都能组织多个智能体协作，但它们把“协作”放在不同抽象层：对话、团队分工、状态图。

核心结论：先判断任务需要的是开放式对话、可读的角色流水线，还是可审计的状态转移；再选择框架。不要用单一“谁更强”替代架构判断。

01 / 三种架构路线

不是同一层级的 API 竞赛，而是三种编排哲学

AUTOGEN · 对话优先

Agent ↔ Agent

把多个 Agent 建模成可对话实体，通过自然语言协作完成任务。

  • 支持一对一、群聊、分层等交互模式
  • 可配置模型、工具、人机交互模式
  • 内置代码执行抽象；v0.4 采用异步事件驱动架构
CREWAI · 团队分工

Agent + Task + Crew

用角色、目标、背景故事描述成员，再用任务与流程把团队串起来。

  • Sequential / Hierarchical 两种流程模式
  • 角色扮演式抽象，适合快速表达业务分工
  • 支持委托、记忆、人类介入与多模型
LANGGRAPH · 状态图

Node → State → Edge

把 Agent 放进图节点，用状态转移表达复杂工作流。

  • 支持循环，而不止是有向无环流程
  • checkpointing 支持断点续跑与状态持久化
  • 多个 Agent 作为节点，通过共享状态协作

02 / 能力与适用场景

以已验证事实为边界；趋势性数字不作为结论依据

维度AutoGenCrewAILangGraph
核心抽象多 Agent 对话 / 群聊角色、任务、团队、流程图节点、边、共享状态
人类介入原生支持原生支持原生支持
代码执行内置 CodeExecution需自定义需自定义
状态与恢复v0.4 强调异步事件驱动；具体性能数值未核实支持短期 / 长期记忆checkpointing / 断点续跑
学习与落地中等；旧版 0.2.x 到 0.4 API 变化较大较低；角色分工表达直观中等偏高；控制力更强
适用场景复杂多轮对话、代码生成、开放式协作快速原型、角色分工流水线有状态多 Agent、循环与复杂工作流
选型提醒：“更灵活”通常意味着需要自己设计更多状态、边界和观测；“更易上手”不等于适合所有复杂对话流。应按任务的可控性需求取舍。

03 / 最小安装片段

仅展示事实包中已验证的安装与初始化方式

AutoGen / Python

pip install autogen-agentchat autogen-ext[openai]

from autogen_agentchat.agents import AssistantAgent
from autogen_ext.models.openai import OpenAIChatCompletionClient

agent = AssistantAgent(
  "assistant",
  OpenAIChatCompletionClient(model="gpt-4o")
)

CrewAI / Python

pip install crewai

from crewai import Agent, Task, Crew, Process

researcher = Agent(
  role="研究员",
  goal="深入研究",
  backstory="资深研究员"
)

04 / 限制与边界

把“未核实”留在卡面上，比过度承诺更可靠

AutoGen

v0.4 与 0.2.x API 有较大变化，迁移时需对照官方指南。Microsoft Agent Framework 的具体发布时间在事实包中标为未核实。

CrewAI

相较 AutoGen，更偏角色扮演范式；复杂定制化对话流的支持被事实包标注为相对弱。精确最新 PyPI 版本号未核实。

LangGraph

图结构与状态控制带来更强表达力，也要求使用者承担更多状态设计与流程治理。事实包未提供可直接复制的安装命令。
