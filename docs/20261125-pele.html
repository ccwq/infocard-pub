核心要点

同步 + 零依赖

render() 传入 Mermaid 文本直接返回 SVG，无异步管线；官方口径直接依赖 0 个，Mermaid.js 是 23 个。

给文档站、知识库或产品嵌入 Mermaid 图——尤其在意暗色主题即时切换、移动端布局自适应、渲染不可信输入——pele 直接进候选：MIT 协议、解析器按 Mermaid 官方规格测试并做差分模糊测试、两周内发了 10 个版本修细节。反过来，需要逐像素复刻 Mermaid 现有输出、依赖 Mermaid.js 插件生态、或要开箱即用公式排版的，先看边界再决定。

到这里已足够判断去留；下面展开 API 三种入口的真实形态、官方对比表、主题变量清单与升级风险。

01 · API 三入口：同步、浏览器、减包

render() 同步出图：拿到的是字符串，插进页面就完事，结果里带 mermaidType（1.7.0 起，如 flowchart-v2）。

import { render } from 'pele';
const { svg } = render(`flowchart LR
  A[Mermaid text] --> B[SVG]`);
document.querySelector('#diagram').innerHTML = svg;

mount() 浏览器形态：渲入元素、从 CSS 读字体、随容器宽度自适应布局（小屏是重排而非缩放整图）；解析/渲染错误就地显示在容器里并保留上一次成功图形的暗态，SVG ID 自动唯一化避免多图冲突。

import { mount } from 'pele';
mount(document.querySelector('#diagram'), text);
// 失败走 onError / Mounted.error，不再 throw

减包两条路：主入口包含全部图型；只要几种图就逐个注册，或用懒加载入口。

import { register, render } from 'pele/core';
import flowchart from 'pele/diagrams/flowchart';
register(flowchart);

import { renderAsync } from 'pele/lazy';
const { svg } = await renderAsync(text);

03 · 主题化：改颜色不重渲染

在 .pele 或任意父元素上设变量，颜色即时生效、不触发重渲染；图表系列色有 8 个槽位。

.pele {
  --pele-bg: #fffcf0;   --pele-fg: #100f0f;
  --pele-muted: #6f6e69; --pele-line: #100f0f;
  --pele-surface: #f2f0e5; --pele-surface-alt: #e6e4d9;
  --pele-border: #cecdc3; --pele-accent: #205ea6;
  --pele-font: sans-serif; --pele-radius: 4px;
  /* 图表系列色：--pele-series-1 … --pele-series-8 */
}

1.12.0/1.13.0 补齐了深浅色细节：自定义填充上的标签自动在 --pele-fg-on-light/dark 里挑对比度高的；饼图、git graph、时间线等系列色改为跟随 Mermaid 的 pie1–8、git0–7、cScale0–7 等主题变量，迁移来的主题配色不再走样。

04 · 安全模型与版本节奏

面向不可信输入的三层防护：转义图内文本、过滤链接与样式、限制输入与输出尺寸；1.9.1 起保证输出恒为合法 XML（清除 U+FFFE/U+FFFF 与未配对代理区）。

迭代速度：2026-10-17 至 10-31 两周发了 10 个版本（1.6.0→1.13.0），kepano 一个人的提交占 384 次，是第二名的 19 倍。细节修到很细：1.7.0 中文/日文长标签按字符换行（不再把图撑宽）；1.6.0 起 mount() 把错误画在容器里而不是抛异常。

升级风险：1.10.0 收紧了两处语法——%% 注释不再吞掉前一个字符、空 title 不再吞下一行；以前「碰巧能画」的图升级后可能直接报语法错误。公式支持（1.8.0 的 math 选项）不含排版器，宿主必须自己提供返回 SVG/MathML 的 resolver，否则标签里显示 TeX 源码。
