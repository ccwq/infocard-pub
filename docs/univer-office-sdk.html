1. Univer 是什么，不是什么

Univer 是一个开源 SDK，用于在你的产品中创建办公应用。它提供电子表格、文档和演示文稿的基础能力，同时不强制你使用托管应用或固定 UI。

当你需要以下能力时，可以使用 Univer：

  • 将电子表格或文档编辑能力嵌入 SaaS 产品、内部工具、BI 流程或 AI 应用。
  • 在服务端运行工作簿 / 文档处理逻辑，并与浏览器端使用同一套架构。
  • 通过插件按需组合功能，或通过预设快速启动。
  • 通过自定义插件、命令、服务、UI 组件和 Facade API 扩展行为。

Univer 不是：

  • 一个成品的 Microsoft Office / Google Docs 替代品。它是 SDK，不是即装即用的办公软件。
  • 一个固定 UI 的 SaaS 产品。它是框架，提供渲染引擎和逻辑层，UI 可以高度自定义。
  • 一个只读文件查看器。它是用于构建你自己的生产力界面的框架，支持可编程读写；实时协作属于另行配置与许可的扩展能力。

2. 三大模块成熟度：Sheets 最稳，Docs 在演进，Slides 开发中

Univer 包含三大文档类型的支持，成熟度差异显著：

2.1 Sheets（电子表格）——最成熟

@univerjs/sheets 提供核心电子表格数据模型和业务逻辑，独立于 UI 层。

  • 官方 README 将 Sheets 定位为当前最成熟的产品面；实际项目仍需功能验收。
  • Facade API 完善：支持 getRange、setValues、getValues、appendRow、clear、merge 等。
  • 支持公式引擎（@univerjs/sheets-formula）、数字格式化（@univerjs/sheets-numfmt）、条件格式等独立插件；图表属于 Pro 扩展。
  • 支持导入导出（需要后端转换服务）。

📦 NPM：https://npmjs.com/package/@univerjs/sheets 📖 官方文档：https://docs.univer.ai

2.2 Docs（文档）——功能在演进

@univerjs/docs 提供文档数据模型和富文本操作核心，独立于 UI 层。

  • 已有 Facade API 支持，但功能集不如 Sheets 完善。
  • 文档协作模式需要后端服务。
  • 支持基本的富文本编辑，部分高级排版功能仍在完善。

📦 NPM：https://npmjs.com/package/@univerjs/docs

2.3 Slides（演示文稿）——开发中

@univerjs/slides 提供演示文稿数据模型和服务。

  • 目前无 Facade API（package.json 的 Facade entry 列显示为 "No"）。
  • 功能相对基础，幻灯片的核心功能在持续开发中。
  • 不适合作为生产级演示编辑器的唯一依赖。

📦 NPM：https://npmjs.com/package/@univerjs/slides

2.4 Board（白板）与 PDF

  • Univer 官方对 Board（白板）和 PDF 功能未声明为默认成熟，不要在对外文档中声称这些功能已达到 Sheets 同等成熟度。
  • 本次官方 README 没有足够信息支撑 Board/PDF 的默认产品成熟度，因此不把它们列为本入门练习已提供的能力。

📖 package README（sheets）：https://raw.githubusercontent.com/dream-num/univer/dev/packages/sheets/README.md 📖 package README（slides）：https://raw.githubusercontent.com/dream-num/univer/dev/packages/slides/README.md

3. Preset 模式 vs Plugin 模式：维度对比

Univer 提供两种集成方式，选择取决于你的定制需求。

3.1 Preset 模式（推荐快速上手）

Preset（预设）是一组经过整理的 Univer 插件集合，包含所需的 Facade API 注册和样式。你只需安装预设包、几行配置即可运行。

优点：

  • 上手快，配置少
  • 自动包含 Facade API
  • 无需关注插件注册顺序

代表包：

  • @univerjs/preset-sheets-core（电子表格预设）
  • @univerjs/preset-docs-core（文档预设）

3.2 Plugin 模式（深度定制）

Plugin 模式让你更底层地控制包、样式导入、locale 合并、Facade API 注册和插件顺序。

优点：

  • 按需加载，减少包体
  • 完整控制插件注册顺序
  • 支持深度定制和自定义插件开发

代表包（需要手动安装很多包）：

  • @univerjs/core
  • @univerjs/sheets
  • @univerjs/engine-formula
  • @univerjs/ui
  • 等数十个独立包

3.3 关键差异对比

维度 Preset 模式 Plugin 模式
Facade API 自动包含，无需额外 import 需要手动 import 各插件的 facade 包
插件注册顺序 预设内部处理，无需关注 需手动确保顺序正确
包体大小 相对较大（包含预设内所有功能） 可按需精简
适合场景 快速原型、标准集成 深度定制、特殊性能需求
懒加载 同步加载预设 支持按需懒加载
学习曲线 低 中高

⚠️ 版本一致性原则：无论选择哪种模式，必须保证所有 @univerjs/* 依赖版本号完全一致。混用不同版本会导致插件冲突或功能异常。

⚠️ 不要重复导入：如果一个插件已经包含在 Preset 中，不要再单独 import 该插件，否则可能引发插件冲突。

📖 官方安装文档：https://docs.univer.ai/guides/sheets/getting-started/installation

4. Headless 运行维度：浏览器之外的可能性

Univer 的核心特性之一是同构设计（Isomorphic）——同一套代码可以在浏览器和 Node.js 环境中运行。

4.1 什么是 Headless Univer

Headless Univer 是指在 Node.js 环境中运行 Univer，不依赖浏览器 DOM 和 UI 渲染层。你可以用它：

  • 在服务端生成、修改工作簿
  • 执行批量数据处理
  • 为 AI Agent 提供工作簿操作能力
  • 自动化报告生成

4.2 Preset 模式下的 Headless

使用 @univerjs/preset-sheets-core 预设包时，可以指定 Headless 模式：

const { univer, univerAPI } = createUniver({
  presets: [
    UniverSheetsCorePreset({
      container: 'app',
    }),
  ],
})

将 container 设为 null 或使用专用的 Headless preset 即可无 UI 运行。

4.3 Plugin 模式下的 Headless

在 Plugin 模式中，只需排除涉及 UI 的插件即可：

import { UniverDocsPlugin } from '@univerjs/docs'
import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
import { UniverSheetsPlugin } from '@univerjs/sheets'
import { UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'
import { UniverSheetsNumfmtPlugin } from '@univerjs/sheets-numfmt'
import SheetsEnUS from '@univerjs/sheets/locale/en-US'

const univer = new Univer({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(SheetsEnUS),
  },
})

univer.registerPlugin(UniverRenderEnginePlugin)
univer.registerPlugin(UniverFormulaEnginePlugin)
univer.registerPlugin(UniverDocsPlugin)
univer.registerPlugin(UniverSheetsPlugin)
univer.registerPlugin(UniverSheetsFormulaPlugin)
univer.registerPlugin(UniverSheetsNumfmtPlugin)

const univerAPI = FUniver.newAPI(univer)

📖 Headless 官方文档：https://docs.univer.ai/guides/sheets/getting-started/node

5. 浏览器容器、CSS、locale、Facade 的意义

5.1 浏览器容器（container）

Univer 的 UI 渲染需要挂载到一个 DOM 容器中。这个容器是一个 HTML 元素的 id（字符串）或 DOM 引用。

UniverSheetsCorePreset({
  container: 'app',  // 对应 <div id="app"></div>
})

注意事项：

  • 容器必须是一个真实存在的 DOM 元素
  • 容器应该有明确的高度（否则 Canvas 渲染区域为 0）
  • 不要在同一个容器中挂载多个 Univer 实例

5.2 CSS 样式

Univer 的 UI 组件依赖 CSS 样式文件。Preset 模式提供了合并后的 CSS：

import '@univerjs/preset-sheets-core/lib/index.css'

Plugin 模式需要分别引入各包的 CSS：

import '@univerjs/design/lib/index.css'
import '@univerjs/ui/lib/index.css'
import '@univerjs/docs-ui/lib/index.css'
import '@univerjs/sheets-ui/lib/index.css'

📖 package README（ui）：https://raw.githubusercontent.com/dream-num/univer/dev/packages/ui/README.md

5.3 locale（国际化）

Univer UI 中的按钮、菜单、提示文字等文本内容通过 locale 配置。locale 是一个对象，包含各语言包的文本映射。

import { LocaleType, mergeLocales } from '@univerjs/presets'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(UniverPresetSheetsCoreEnUS),
  },
  // ...
})

支持的 locale 包括：en-US、zh-CN、zh-TW、ja-JP、ko-KR、es-ES 等。

5.4 Facade API

由于 Univer 底层架构复杂，官方提供了 Facade API 作为高层封装。它是一个包装层，将底层命令和服务封装为直观的方法调用。

为什么需要 Facade：

  • 底层 API 需要理解命令系统、插件注册顺序、状态管理
  • Facade 提供 univerAPI.getActiveWorkbook()、fRange.setValues() 等直观方法
  • 在浏览器与 Node.js 复用 Facade 架构；UI 相关能力不能在无头环境照搬

Preset 模式：Facade API 自动包含，无需额外 import。

Plugin 模式：需要手动导入各插件的 Facade 包：

import { FUniver } from '@univerjs/core/facade'
import '@univerjs/ui/facade'
import '@univerjs/docs-ui/facade'
// 然后将 Univer 实例包装为 Facade API
const univerAPI = FUniver.newAPI(univer)

⚠️ 异步警告：部分 Facade API 是异步的，尤其是修改数据的操作返回 Promise。如果你需要在修改后立即读取数据，必须使用 await 或 .then()，否则可能拿到旧值。

📖 Facade 官方文档：https://docs.univer.ai/guides/sheets/getting-started/facade

6. npm 安装：固定 1.0.3 版本，两个 preset 包

6.1 推荐的 Preset 安装

对于大多数场景，使用 Preset 模式只需要两个包：

pnpm add @univerjs/presets @univerjs/preset-sheets-core

或者等效的 npm/yarn 命令：

npm install @univerjs/presets @univerjs/preset-sheets-core
yarn add @univerjs/presets @univerjs/preset-sheets-core
bun add @univerjs/presets @univerjs/preset-sheets-core

6.2 版本一致性原则

⚠️ 必须保证所有 @univerjs/* 包使用完全相同的版本号。

如果使用 Plugin 模式安装了多个 @univerjs/* 包，确保 package.json 中统一指定同一版本：

{
  "dependencies": {
    "@univerjs/core": "1.0.3",
    "@univerjs/sheets": "1.0.3",
    "@univerjs/ui": "1.0.3"
  }
}

混用不同版本会导致插件注册冲突、数据不一致等难以调试的问题。

8. 核心数据操作：createWorkbook→getActiveSheet→getRange→setValues/getValues

理解这四个 API 的调用链，是所有 Univer Sheets 数据操作的基础。

8.1 调用链路

univerAPI.createWorkbook()
    ↓
fWorkbook = univerAPI.getActiveWorkbook()
    ↓
fWorksheet = fWorkbook.getActiveSheet()
    ↓
fRange = fWorksheet.getRange('A1:C3')
    ↓
fRange.setValues(matrix) / fRange.getValues()

8.2 createWorkbook

创建新的工作簿。如果不传参数，创建空白工作簿。

const workbook = univerAPI.createWorkbook({
  name: "入门预算"
})

期望结果：在工作簿列表中添加一个新工作簿，并自动将其设为活动工作簿。

8.3 getActiveWorkbook / getActiveSheet

const fWorkbook = univerAPI.getActiveWorkbook()
const fWorksheet = fWorkbook.getActiveSheet()

期望结果：返回当前活动工作簿和活动工作表的 Facade 句柄。如果还没有活动工作簿（如 Headless 场景），返回 null 或 undefined。

8.4 getRange 的多种写法

// 单格
const a1 = fWorksheet.getRange('A1')

// 矩形区域
const b2d4 = fWorksheet.getRange('B2:D4')

// 指定行列索引（行 0 = 第 1 行，列 0 = A 列）
const range = fWorksheet.getRange(0, 0, 3, 3) // A1:C3；参数为起始行、起始列、行数、列数

8.5 setValues / getValues —— 正确的二维数组格式

这是最常出错的 API。

setValues（写入数据）

参数是一个二维数组，外层数组的每个元素是一行，内层数组的每个元素是同一行中的一个单元格。

// 写入 2 行 3 列的数据
fWorksheet.getRange('A1:C2').setValues([
  ['项目', '预算', '实际'],      // 第 1 行：A1=项目, B1=预算, C1=实际
  ['人员成本', 50000, 48000],    // 第 2 行：A2=人员成本, B2=50000, C2=48000
])

常见错误：

// ❌ 错误：扁平数组，Univer 不会正确解析
fWorksheet.getRange('A1:C2').setValues(['项目', '预算', '实际', '人员成本', 50000, 48000])

// ❌ 错误：只有一行时，外层数组不能省略
fWorksheet.getRange('A1:C1').setValues(['项目', '预算', '实际'])

// ✅ 正确：即使是单行，也必须是二维数组
fWorksheet.getRange('A1:C1').setValues([['项目', '预算', '实际']])

// ✅ 正确：对象格式（带样式）
fWorksheet.getRange('A1:B2').setValues([
  [{ v: 'Hello', s: 'custom-style-1' }, { v: 'Univer', s: 'custom-style-1' }],
  [{ v: 'To', s: 'custom-style-1' }, { v: '0001', s: 'custom-style-2' }],
])

getValues（读取数据）

返回同样格式的二维数组：

const data = fWorksheet.getRange('A1:C3').getValues()
// 返回结构示例：
// [
//   ['项目', '预算', '实际'],       ← A1, B1, C1
//   ['人员成本', 50000, 48000],    ← A2, B2, C2
//   ['设备折旧', 10000, 10000],    ← A3, B3, C3
// ]
console.log(data[1][0]) // '人员成本'

API 返回类型要按版本核对：本次读取 1.0.3 已安装包类型声明，setValues(...) 返回 FRange，getValues() 返回二维值数组，save() 返回 IWorkbookData；不是统一返回 Promise。公式计算与 UI 更新可能另有生命周期，不要把普通写入返回值当成“所有异步计算已完成”。

📖 FRange API 参考：https://docs.univer.ai/reference/facade/f-range 📖 FWorkbook API 参考：https://docs.univer.ai/reference/facade/f-workbook

10. 保存与加载：快照 JSON vs createWorkbook

10.1 快照（Snapshot）是什么

Univer 的快照是一个 JavaScript 对象（JSON 结构），包含工作簿的完整状态：工作表数据、样式、配置、公式等。

const snapshot = await univerAPI.getActiveWorkbook().save()
// snapshot 结构示例：
// {
//   id: 'workbook-id',
//   name: '预算表',
//   sheets: {
//     'sheet-id': {
//       id: 'sheet-id',
//       name: 'Sheet1',
//       cellData: { /* ... */ },
//       rowData: { /* ... */ },
//       columnData: { /* ... */ },
//     }
//   },
//   styles: { /* ... */ },
//   // ...
// }

快照的特征：

  • 是 Univer 内部格式，不是 Office Open XML（xlsx）
  • 可以用 JSON.stringify() 序列化，适合存储到数据库或 LocalStorage
  • 加载速度快，因为不需要解析第三方格式
  • 不保证与 xlsx 格式完全兼容——复杂样式、宏等可能丢失

10.2 createWorkbook 加载快照

// 加载保存的完整快照，不把 sheets 当作数组
// 如果保存了完整快照
const snapshot = await oldWorkbook.save()
const wb2 = univerAPI.createWorkbook(snapshot)

10.3 JSON 不是 xlsx

⚠️ 重要区分：Univer 的快照 JSON 不是 xlsx 文件。

快照 JSON xlsx 文件
格式 Univer 内部 JSON Office Open XML 标准
用途 内部存储、快速加载 导出给用户、跨软件兼容
生成方式 workbook.save() 需要后端转换服务
用户可见性 否（内部格式） 是（标准办公文件）
Excel 直接打开 ❌ 不能 ✅ 可以

如果你需要生成用户可下载的 xlsx 文件，需要使用 导入导出功能，这通常需要后端转换服务（Pro 版本功能）。

11. Vue / React 中的挂载与销毁

在单页应用（SPA）中使用 Univer 时，正确管理生命周期非常重要——尤其是当用户切换页面时，需要正确销毁 Univer 实例以避免内存泄漏。

11.1 核心原则

在 Vue / React 中，必须在组件卸载时调用 univer.dispose() 销毁实例。

Univer 内部启动了渲染引擎、事件监听、定时器等，如果不 dispose：

  • 内存持续增长
  • 事件监听器累积，导致重复触发
  • Canvas 渲染冲突（多个实例竞争同一 canvas）

11.2 React 中的使用

import { useEffect, useRef } from 'react'
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'
import '@univerjs/preset-sheets-core/lib/index.css'

function UniverSheets() {
  const univerRef = useRef(null)

  useEffect(() => {
    // 创建实例
    const { univer, univerAPI } = createUniver({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(UniverPresetSheetsCoreEnUS),
      },
      presets: [
        UniverSheetsCorePreset({
          container: 'univer-container',
        }),
      ],
    })

    univerRef.current = univer
    univerAPI.createWorkbook({})

    // 清理函数：组件卸载时销毁
    return () => {
      if (univerRef.current) {
        univerRef.current.dispose()
        univerRef.current = null
      }
    }
  }, []) // 空依赖数组：只在挂载时创建，卸载时销毁

  return <div id="univer-container" style={{ width: '100%', height: '100vh' }} />
}

export default UniverSheets

12. 插件增量原则：不重复注册

12.1 插件是增量的

Univer 的插件系统在设计上是增量的——你可以随时注册新插件来扩展功能，无需重新初始化已有实例。但这要求你遵循以下原则。

12.2 不重复注册同一插件

如果一个插件已经通过 Preset 注册，不要再用 univer.registerPlugin() 重复注册相同功能的独立包。

示例——错误做法（Plugin 模式中重复注册）：

import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
// ...
createUniver({
  presets: [
    UniverSheetsCorePreset(), // 已包含 UniverSheetsPlugin
  ],
})

// ❌ 错误：重复注册同一插件
univer.registerPlugin(UniverSheetsPlugin)

正确做法：选择 Preset 或 Plugin 模式，不要混合。

12.3 不混用 Preset 和 Plugin 模式

Preset 模式本质上是预配置好的 Plugin 组合。混用会导致：

  • 插件重复注册（功能异常）
  • 状态冲突（两个插件管理同一份状态）
  • 难以追踪的 Bug

12.4 注册顺序影响功能

在纯 Plugin 模式中，某些插件有依赖关系，需要按顺序注册：

// 正确的注册顺序示例
univer.registerPlugin(UniverRenderEnginePlugin)   // 1. 渲染引擎（基础依赖）
univer.registerPlugin(UniverFormulaEnginePlugin)  // 2. 公式引擎
univer.registerPlugin(UniverDocsPlugin)           // 3. 文档核心
univer.registerPlugin(UniverSheetsPlugin)         // 4. 表格核心
univer.registerPlugin(UniverSheetsFormulaPlugin)  // 5. 表格公式
univer.registerPlugin(UniverUIPlugin)             // 6. UI（最后注册）

📖 官方安装文档：https://docs.univer.ai/guides/sheets/getting-started/installation

13. 公式引擎边界：不能保证 100% Excel 兼容

Univer 内置了公式引擎（@univerjs/engine-formula），支持大部分常用公式，包括 SUM、AVERAGE、VLOOKUP、IF、AND、OR 等。

13.1 支持的公式类型

  • 数学函数：SUM、AVERAGE、COUNT、MAX、MIN、ROUND、ABS、SUMIF 等
  • 逻辑函数：IF、AND、OR、NOT、IFERROR、IFS、SWITCH 等
  • 查找函数：VLOOKUP、HLOOKUP、INDEX、MATCH、CHOOSE 等
  • 文本函数：CONCATENATE、LEFT、RIGHT、MID、LEN、TRIM 等
  • 日期函数：TODAY、NOW、DATE、YEAR、MONTH、DAY 等
  • 统计函数：STDEV、VAR、SUMPRODUCT 等

13.2 不能保证 100% Excel 兼容

⚠️ 重要提示：Univer 的公式引擎在持续完善中，不能保证 100% 与 Microsoft Excel 行为一致。

以下情况可能导致差异：

  • 罕见函数：Excel 有 500+ 内置函数，Univer 支持其中常用的核心集合
  • 函数参数默认值：某些函数的默认参数行为可能不同
  • 数组公式：动态数组函数（如 FILTER、SORT）在部分版本中可能行为不一致
  • 精度问题：浮点数计算精度可能与 Excel 存在微小差异
  • 跨语言 locale：函数名称可能因 locale 设置而异

13.3 实践建议

  1. 在开发阶段对关键公式进行测试验证，不要假设行为与 Excel 完全一致
  2. 关注 Univer GitHub 的 release notes，了解公式引擎的变更
  3. 对于必须 100% 兼容的场景，考虑使用 @univerjs-pro/exchange-client 的后端转换方案
  4. 使用 =IFERROR(formula, fallback_value) 包裹关键公式，避免错误值传播

📖 Headless 文档中有公式引擎配置：https://docs.univer.ai/guides/sheets/getting-started/node

16.1 Agent 通过 Facade API 操作工作簿

  • 自定义公式（可能暴露商业逻辑）

实践建议：

  1. 数据隔离：确保 AI Agent 只能访问它被授权操作的工作簿，不要让 Agent 通过 unscoped API 访问所有工作簿
  2. 最小权限原则：Agent 应只有读取和修改特定工作簿的权限，不应拥有管理所有工作簿的能力
  3. 数据脱敏：在将工作簿数据发送给 AI 分析之前，考虑脱敏处理（移除敏感列、聚合数据）
  4. 操作日志：记录 Agent 的所有工作簿操作，便于审计
  5. 会话隔离：不同用户的工作簿数据应在会话层面隔离，防止跨会话数据泄露

17.2 Agent 权限配置

// 实践建议：按工作簿粒度控制 Agent 权限
const agentPermissions = {
  canRead: ['budget-2024', 'team-roster'],      // 只允许读这些工作簿
  canWrite: ['budget-2024'],                    // 只允许写这个工作簿
  canCreate: false,                             // 不允许创建新工作簿
  canDelete: false,                             // 不允许删除工作簿
}

// Agent 执行操作前检查权限
function agentExecute(univerAPI, workbookId, operation) {
  if (!agentPermissions.canWrite.includes(workbookId)) {
    throw new Error(`Agent 无权修改工作簿 ${workbookId}`)
  }
  // ...执行操作
}

17.3 Headless 场景的数据安全

在 Node.js 中运行 Univer Headless 时：

  • 服务端内存中的工作簿数据应被视为敏感数据
  • 确保服务端进程之间隔离（容器 / 虚拟机级别）
  • 不要将未加密的工作簿 JSON 直接存储在共享存储中
  • 使用 HTTPS 传输工作簿数据

📋 以上为实践建议，不是安全审计结论。请在生产部署前进行专业的安全评估。

18. 排错表：10 项常见问题与解决方案

# 问题现象 可能原因 解决方案
1 页面空白，Canvas 没有渲染 容器 id 不存在或容器高度为 0 确认 HTML 中有 <div id="app"></div>，且 CSS 中 #app 有 height: 100vh
2 createUniver 报 "container not found" container 参数对应的 DOM 元素不存在 检查 UniverSheetsCorePreset({ container: 'app' }) 中的 'app' 与 HTML 中的 id 是否匹配
3 setValues 后 getValues 读不到新值 没有 await 异步操作 修改数据的 Facade API 是异步的，必须 await：await range.setValues(...)
4 数据写入到错误的单元格 二维数组格式错误 确认是 [[...], [...]] 格式而非扁平数组，即使是单行也要是 [['项目', '预算']]
5 插件冲突，功能异常 混用了 Preset 和 Plugin 模式，或重复注册插件 只选择一种模式，不要在 Preset 基础上再用 Plugin 注册相同插件
6 版本不一致导致报错 @univerjs/* 包版本号不统一 将所有 @univerjs/* 依赖锁定为同一版本（如全部 1.0.3）
7 公式不计算，显示原字符串 公式引擎插件未注册 在 Plugin 模式中确保注册了 UniverFormulaEnginePlugin 和 UniverSheetsFormulaPlugin
8 Headless 环境报错 "document is not defined" 代码中引用了浏览器 DOM API Headless 场景下不要使用依赖 DOM 的插件（如 @univerjs/ui），使用 Headless 专用的最小包集
9 xlsx 导入 / 导出失败 缺少 Pro 版本的 exchange-client 包和后端服务 确认使用的是 @univerjs-pro/exchange-client 且已配置后端转换服务；开源版本不支持 xlsx 导入导出
10 组件卸载后内存持续增长 没有调用 dispose() 在 Vue onBeforeUnmount 或 React useEffect 返回的清理函数中调用 univer.dispose()

19. 版本升级的稳定性建议

19.1 升级前必读 Release Notes

每次升级前，务必阅读 Univer 的 Release Notes（发布说明），重点关注：

  • Breaking Changes（破坏性变更）：API 签名变化、插件注册方式变化
  • 已知问题（Known Issues）：当前版本未解决的问题
  • 公式引擎变更：公式兼容性变化
  • 依赖版本要求：是否要求更高版本的 Node.js 或其他依赖

19.2 推荐的升级策略

小版本升级（如 1.0.3 → 1.0.4）：

  • 风险相对低，但仍建议在测试环境验证
  • 重点测试：数据读写、公式计算、导入导出

大版本升级（如 1.0.x → 1.1.0）：

  • 必须完整测试
  • 关注破坏性变更，可能需要修改代码
  • 建议阅读 changelog 并在隔离环境中先行验证

降级：

  • Univer 快照格式可能因版本而异，降级可能导致快照无法加载
  • 如果需要降级，建议同时导出为 xlsx 作为备份

19.3 快照兼容性

⚠️ 快照（snapshot）格式在不同主版本之间可能不兼容。升级前务必导出 xlsx 备份，并在测试环境中验证快照加载正常。
