如果你想让 AI 做多步骤、有依赖、能复用的任务，而不是每次都手写提示词，pi-workflow 是目前最干净的方案：JSON 定义阶段图，Pi subagent 执行业务逻辑，结果自动流转，run 可查可恢复。

内置工作流 · 4 种

直接用，说句话就行

WORKFLOWS
深度研究 deep-research

需要广度、验证、有引用推荐的研究任务。计划问题 → 按深度展开调研 → 归一化排名 → 核实关键论断 → 生成有审计痕迹的报告。

代码审查 deep-review

一次 review 不够的多视角代码审查。分镜选取 → 多审查者产生结论 → 确定性去重 → 对幸存结论挑战测试 → 最终报告只保留有证据的问题。

规格审查 spec-review

需求与实现的一致性检查。提取可测试需求 → 映射到实现和测试 → 验证候选缺口 → 报告哪些需求已覆盖、缺失、模糊或需要人工判断。

影响评估 impact-review

变更的副作用和风险评估。映射影响范围 → 分析合同/状态/验证/文档/安全/性能 → 合并为可能回归项、缺失检查和后续行动。

阶段图架构 · 6 种模式

工作流 = JSON 阶段图

STAGE TYPES
single

单步执行，一个 prompt → 一个 subagent，适合聚焦操作。

foreach

动态发散，上游 JSON 数组 → 每个元素一个 subagent，适合批量处理。

reduce

聚合收敛，多个上游 artifact → 一个综合 subagent，生成最终输出。

loop

有界循环，重复子阶段直到满足确定性停止条件，适合迭代优化。

dag

嵌套图容器，子阶段降级为命名空间任务，暴露选定输出到下游。

dynamic

自适应编排，信任的 bundle 内置控制器可通过 ctx.agent() 创建工作流任务。

工作流定义示例（JSON 阶段图）： 
{
  "defaults": { "agent": "researcher", "tools": ["read","grep","find"] },
  "artifactGraph": {
    "stages": [
      { "id": "plan",  "type": "single",  "prompt": "..." },
      { "id": "inspect","type": "foreach","from": {"source":"plan","path":"$.items"}},
      { "id": "report","type": "reduce", "from": ["plan","inspect"],"prompt":"..."}
    ]
  }
}
上手 SOP · 自然语言触发

装完就能用

USAGE
步骤 操作 说明
① 安装 pi install npm:@agwab/pi-workflow 同时装入 /workflow 扩展、workflow-guide skill 和 execution-router skill。
② 重载 Pi 重启 Pi 应用 扩展加载生效。
③ 自然语言触发 Use the deep-research workflow to research this repository. Pi 自动解析工作流名称，执行对应阶段图。
④ 查看运行状态 /workflow 打开只读 TUI，检查阶段进度、任务输出、fan-out 情况。
⑤ 自定义工作流 /skill:workflow-guide create a workflow for weekly release readiness. 用 workflow-guide skill 创建项目专用工作流，保存为可复用 JSON 阶段图。
⑥ 动态编排（可选） /workflow dynamic "Research and summarize architecture tradeoffs." 不使用预设工作流，让内置动态控制器规划并执行，run 记录在 .pi/workflows/。
execution-router skill · 智能路由

不确定任务该用什么方式处理？让 execution-router 帮你判断：直接单步 / targeted verifier / 已有工作流 / 新建工作流。

/skill:execution-router decide whether this repository review should use a single-agent pass, deep-review, or a targeted verifier.

三层架构

Workflow / Task / Support

ARCHITECTURE

① Workflow

阶段图和运行生命周期：存在哪些阶段、何时运行、输出如何流转。

② Task

agent 支持的工作：聚焦 prompt、动态发散、收敛综合、有界循环。

③ Support

确定性本地轨道：辅助代码、验证、归一化、artifact、run state 可恢复。

运行时依赖
@agwab/pi-subagent

启动和管理 Pi subagent workers，追踪其生命周期，供 workflow task 调用。

pi-web-access

提供 web_search、fetch_content、get_search_content、code_search 等工具，可替换为其他兼容 provider。
