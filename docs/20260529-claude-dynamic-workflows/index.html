Cookbook：4 步把 Dynamic Workflows 用起来

01

先拆任务，不要先写一坨大 Prompt

把目标拆成检索、执行、复核三层。复杂任务优先丢给 subagents，主线程只保留判断与汇总。

  • 适合：调查、对比、代码审阅
  • 要求：每个子任务只有一个清晰输出格式
02

把关键节点接到 hooks / checkpoints

在“开始前 / 中途 / 完成后”挂自动动作：测试、lint、校验、存档、回滚。

  • 适合：长任务、批量改写、发布链路
  • 原则：失败必须可恢复，不要一把梭到底
03

并行工具 + 后台任务一起上

能并行的信息并行抓；耗时任务放后台；最后集中复核结果并合并输出。

  • 适合：多源调查、抓取、编排发布
  • 目标：把“排队等”变成“同时跑”
04

一个最小实战模板

问：帮我查 A、B、C 三个来源并比较差异。
做：拆成 3 个 subagent → 并行检索 → 主线程做差异表 → checkpoint 留档。

这页的重点不是“它有没有一个叫 Dynamic Workflows 的按钮”，而是：Claude 正在把 agent 能力做成动态调度系统，所以真正要学的是工作流编排方法。

Dynamic Workflows 实际对应的 7 个模块

1 Subagents

把复杂任务拆给多个专门代理并行做，主线程只做汇总与裁决。

2 Hooks

在关键节点自动触发测试、lint、校验等动作，减少人工补检。

3 Background tasks

让长任务持续跑，不阻塞主线程，适合抓取、构建、批处理。

4 Checkpoints

每次修改前自动存档，可 rewind，核心是可控试错而不是硬顶。

5 Parallel tool use

同一轮并发调多个工具，能显著压缩等待时间与串行阻塞。

6 Tool Search / Programmatic Tool Calling

动态发现工具，并在代码环境中编排调用，不必全靠手写流程图。

7 Managed Agents

长会话、可恢复 sandbox、外置 session log，走向真正的长时执行层。

和传统 workflow 的差别

传统 Workflow

  • 流程图预先写死
  • 顺序固定
  • 异常分支固定
  • 重点是稳定与可预测

Claude Dynamic Workflow

  • 目标给定，子步骤动态生成
  • 工具按需发现
  • 多代理并行协作
  • 失败后根据反馈改道
  • 带检查点与恢复机制
