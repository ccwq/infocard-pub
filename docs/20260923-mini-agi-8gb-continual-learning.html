01/它反在哪里：现有模型训完就定型

1你现在能拥有的模型都是别人训完然后冻住的。你可以微调它的边缘，但不能在自己的硬件上从零训一个，也没法拿它日常做的事继续训练——一训就忘。结果就是"个人模型永远是别人的模型加一层你的薄壳，发布那天就停止学习"。
2mini-AGI 反着来：读一个字符流，每块做一次梯度更新，同一条代码路径既做训练又做生成——推理和训练没有区别，唯一的不同是下一个字符来自文件还是来自模型自己的 argmax。
3三个设计约束：必须塞进 8GB（训练要梯度和优化器状态，约是权重的 3 倍，所以权重住磁盘、只有工作集常驻）；必须不忘（持续学习又覆盖自己的模型还不如不学）；必须什么都能读（字母表就是 256 个字节值，没有分词器）。

02/显存怎么绕开：专家即文件，按需换页

每个专家是磁盘上的一个文件，装着自己的权重和 Adam 动量。往上叠两级缓存：

层级名字是什么
磁盘—模型拥有的所有专家；容量上限 = 剩余磁盘空间
RAMram_cache最近被要过的专家，LRU 驱逐
VRAMresident工作集——一个字符可能路由经过的专家（常驻约 32 个 / 总池约 5.4 亿参数）
!Adam 动量跟着专家走，不属于它碰巧占的显存槽——否则换入的专家继承陌生人的动量，训练表面健康实际已坏。
!换页决策基于上一个 chunk 实际路由经过的 hidden states 评分（原始 embedding 不带上下文，会导致所有主题都要同一批专家），再加迟滞：候选必须超出常驻者一个 margin 才能替换，新专家有 dwell_chars 保护期。

03/架构：深度循环 MoE + 自适应停机

字节级 · 无分词器

256 字节值 + 9 个结构标记

不用 BPE（3.2万-12.8万词表），直接读原始 8-bit 字节。任何文本/二进制流天然可读，没有 embedding 查表内存，"读你自己的文件"无需任何预处理。

深度循环

2 个稠密前奏块 + 1 个循环块 ×≤24

每轮循环从共享池选自己的 top-8 专家（26 次块应用各选各的，一个字符触达的专家远多于 8 个）；adapter 每轮把潜状态并回输入嵌入，循环不漂移。

PonderNet 停机

简单字符早退，难的深算

停机头给每个字符逐深度打分；训练时所有深度按停机概率加权，模型学会按字符分配算力。实测阅读轨迹在 4-14 行间波动（上限 24），写作比阅读更深：9.9 行 vs 8.0 行。

自然选择

专家重组新生，按"被问次数"剪枝

新专家由现有多个专家的整 hidden 单元重组而来（每个新专家 16 个亲本）；生长要同时过 5 道闸（room/used/earning/fits/honest）。最关键发现：gate 值是反预测的——最小 gate 的恰是最忙的专家，剪枝只看"多久没人路由过它"。

04/最硬的实验：遗忘从 2.23 降到 0.0067 nats

方法：让模型只读 52.4 万字符的国际象棋（batch 1），观察它没在读的另外 7 个学科损失变化——0 表示什么都没忘：

配置未读学科损失变化对随机的保留
工作集冻结，trunk LR = 专家 LR+2.587142.88%
正常换页，trunk LR = 专家 LR+2.230050.68%
换页 + trunk 用 0.1×（正式配置）+0.006799.84%
对照组：七学科全读（不可能遗忘）-0.0077—

trunk（嵌入/注意力/路由/停机头）承载 97.6% 的平方梯度范数，把它压到专家学习率的十分之一，524k 字符单学科轰炸后其他七科纹丝不动（±0.02 nats）。50.68% → 99.84% 的差距只是配置文件里的一个数字。

!防遗忘的机制不是专家池本身：冻结工作集（拿掉池的核心性质）只省 0.3571 nats——136 个专家里 93 个没收到任何梯度，模型照样崩。保住大部分权重并不够。
!损害是位移不是摧毁：把模型读坏再重读全部内容，四分之三的损害在 13.1 万字符内恢复（当初学这些花了约 5000 万字符）。探针期间只有 54/136 专家收到梯度——60% 的模型结构上没被碰，这正是池子的作用：把更新限制在文本真正寻址的部分。

05/现在到哪了：诚实刻度

读 4.09 亿 / 78.8 亿字符（5.13%），855 次评估，held-out 全科 0.7980 nats/char（1.1512 bits/byte，困惑度 2.20）。作者直接贴了原始样本：语法正确、扣题，但明显重复（greedy 解码 8-gram 重复率 24%），chat/推理仍是玩具水平，数学减法会循环。H N 评论区同样直接："远谈不上智能"。作者自己的话：

"就目前而言这是一个小型玩具级模型。这是个小实验，证明从单一数据流持续学习而不发生灾难性遗忘是可能的——而且在普通硬件上就可能。"

但 scaling 曲线是认真的：自有 held-out 上拟合幂律 L ∝ D^-0.243（R² 0.97，介于 Kaplan 0.095 与 Chinchilla 0.28 之间）。按趋势外推，在一张笔记本 GPU 上：约 1 天到 1.10 BPB，约 23 天到 0.80 BPB——全在 78.8 亿字符单遍之内。权重未发布（"还差几周"），作者明确说等读完语料再跑成熟 benchmark；nats 基准因 CUDA 专家调度非确定性约有 0.03 运行间方差，低于此的差异不算数。

06/自己跑一个（参考机 RTX 3070 Laptop 8GB）

// README quickstart · torch 2.6.0+cu124
git clone https://github.com/volotat/mini-AGI.git
cd mini-AGI
pip install torch numpy pyyaml matplotlib flask chess zstandard datasets scipy

python3 -m corpora all          # 8 学科语料，几 GB
python3 train.py read data/train --save --weights-dir weights \
    --held-out data/val --sample-every 10
python3 serve.py --port 8080    # http://127.0.0.1:8080

# 最短路径：让它读你自己的文件（无 --save 即 dry run）
python3 train.py read ~/src ~/docs --passes 3 --save
读你的文件无需预处理——256 字节就是它的母语 每次 read 前后自动测 held-out，明说读了你的文件有没有伤到别处 学习率不是余弦调度（余弦断言训练会结束）——控制器盯着 held-out 双向调节 发散自愈：超 best 1.5× 自动回滚权重、降 lr、缩窗口
判断

值得关注的不是模型能力，而是三个被验证的机制：① 专家即文件 + 按需换页，把持续训练的显存墙变成硬盘问题；② trunk 0.1× 学习率一行配置把遗忘压掉 99.7%（2.23→0.0067 nats），且实验归因干净（位移不是摧毁）；③ gate 反预测、按被问次数剪枝——这是仓库里最有用的单条发现。

保持清醒的部分：模型太小太欠训，不能做泛化声明；权重未发（主张暂不可证伪）；输出重复明显；换页方案在真实负载下是否存活待验证。但「一张游戏本显卡加一个人」这个配置本身——从零训练、持续学习、数据完全自有——已经把"个人拥有一个持续成长的模型"从资本问题降维成了时间问题。
