JiuwenSwarm：把多智能体蜂群直接投送到你的聊天窗口

华为开源多智能体协作框架，四层架构（入口/协议/执行/编排），支持飞书·钉钉·企微·个人微信原生接入，6,000★ · Apache 2.0 · 纯 Harness 不内置模型

入口 / 边界 协议 / 编排 执行 / 进化 记忆 / 持久化 安全 / 合规

① 为什么现在需要 JiuwenSwarm？

2024 年起，AutoGen、CrewAI、LangGraph 等多智能体框架井喷。但它们都有一个共同门槛：你得专门打开一个工作台来使用。JiuwenSwarm 的核心思路不同——不让用户切换场景，而是把多智能体能力直接投送到你已经在用的 IM 工具里。飞书、钉钉、企微、个人微信、Telegram、Discord、Slack、WhatsApp，全部原生支持。

这是 Huawei Open Source 团队的作品（openJiuwen-ai/jiuwenswarm），当前版本 v0.2.4.beta3（2026-08-06，冷启动延迟优化），GitHub 6,000 ★，Apache 2.0 许可证。

⑤ Skill 自演进：让框架自己学会更好的做事方式 ❓ 部分细节未公开

触发机制

每 5 轮任务（或团队任务验收后），Agent 自检，基于任务证据判断是否有可复用的改进点。

EVERY 5 ROUNDS

审查流程

触发后，evolution_reviewer 子智能体用只读工具审查证据，生成结构化提案（diff 格式）。

SUB-AGENT REVIEW

人工审批默认

默认走人工审批——提案不会自动合入。证据门槛 + 人工审批默认开启，体现对自动化改写代码风险的克制。

HUMAN-IN-LOOP

持久化路径

经验存入 evolutions.json；批准后执行 /evolve_rebuild 永久合入 SKILL.md。下次同类任务直接用新版本。

/evolve_rebuild # 永久合入 SKILL.md，持久化演进
⑥ AutoHarness：让 Harness 为自己做后训练（不改模型权重） ❓ 实验性质

Meta 层

改通用底座源码，产出 PR 必须人工审查。影响范围大，审慎处理。

CORE CHANGE

Expert 层

生成领域扩展包，热加载即插即用，无需重启服务。

HOT-PLUG

隔离机制

全程 Git worktree 隔离，CI 自动修复循环。改坏不影响主线。

GIT WORKTREE

关键约束：改 Harness 而非改模型权重

AutoHarness 调整的是 Harness 层（提示词工程、工具定义、流程编排），而不是对 LLM 本身做后训练，因此不会引入模型权重漂移风险。

⑦ Symphony 技能编排：解决技能多了撑爆注意力的问题

技能树索引

离线构建树形索引，Agent 像查目录一样逐层浏览技能，而不是全量注入。

TREE INDEX

技能图谱

节点 = 技能，边 = 输出可衔接输入。生成可确认的执行链，Leader 派发任务时有据可依。

GRAPH INDEX

定位

辅助 Leader 任务派发，不是替代 Agent 自主决策。

ASSIST
⑧ 记忆系统：BM25 + 向量混合 + Dreaming

文件结构

USER.md（用户档案）/ MEMORY.md（长期记忆）/ 每日会话日志 / TEAM_MEMORY.md（Leader 每 round 自动提炼团队经验）。

FILE-BASED

混合检索

BM25 全文 + 向量语义混合搜索，默认 0.7/0.3 加权（可调）。SQLite + FTS5 + vec0 实现。watchdog 监控文件变化，异步更新索引。

0.7 BM25 + 0.3 VECTOR

Dreaming 机制

空闲时 LLM 周期性整理历史会话，提取长期信息。带忙碌退避 + 增量扫描，不打扰正常工作。

IDLE BACKGROUND

外接选项

可选外接 Mem0 / OpenViking 等外部记忆服务，按需扩展。
