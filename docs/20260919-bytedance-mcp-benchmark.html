为什么西方工具垫底？

Core Story
协议层面

MCP 0.5 由字节跳动主导定义，西方工具普遍对该协议的支持停留在早期版本甚至缺失，导致工具调用路径更长、握手开销更大。

架构差异

中国平台（豆包、Kimi、扣子）从一开始就将 MCP 协议内嵌到 AI 助手的核心调用链路中，而 Claude Desktop、Cursor 等采用插件化叠加方式，路径更远。

基准测试规模

102,874 个 MCP 服务器、560 万次调用——这是截至目前规模最大的 MCP 性能评估，足以暴露所有平台的真实极限。

结果意义

西方 AI 工具在 MCP 0.5 生态中的工具调用性能全面落后，Zed 更是实测为 0。此数据由字节跳动官方发布于 2026-09-19。

什么是 MCP 0.5？

Protocol
全称

Model Context Protocol（模型上下文协议）0.5 版本，由字节跳动主导定义，是 AI 助手与外部工具之间通信的开放规范标准。

核心作用

统一 AI 助手调用外部工具（搜索、数据库、API、代码执行等）的通信协议，让不同 AI 平台可以互操作同一套工具生态。

版本演进

MCP 0.5 为最新版本，在协议握手、工具发现、流式响应等关键路径上做了大幅优化，是本次基准测试的核心评测对象。

生态规模

本次测试覆盖全球 102,874 个 MCP 服务器，累计 5,600,000+ 次工具调用，是 AI 工具互操作领域迄今最大规模的实测数据。
