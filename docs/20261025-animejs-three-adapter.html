Core judgment: Anime.js v4.5.0 makes Three.js a first-class animation target through one side-effect import — the practical change is that DOM and WebGL animation can share one timeline API.

Anime.js v4.5.0 was published 2026-06-22 by juliangarnier. The release adds a built-in Three.js adapter, imported as a side effect from 'animejs/adapters/three', plus a general registerAdapter() mechanism that extends animate() and utils.set() to non-DOM targets. Per the release note, the adapter animates Object3D, materials, lights, cameras, audio nodes, UniformNode (TSL), and instanced meshes.

Why it matters: before v4.5.0, driving a Three.js scene with Anime.js meant hand-written render loops and manual property mapping. After v4.5.0, the same Timeline / Stagger / Scroll / spring easing / Draggable primitives of Anime.js 4 can orchestrate DOM elements and WebGL scene objects in one timeline. The adapter flattens nested Three.js paths into Anime.js props — per the source review, mesh.position.x, mesh.rotation.y, and mesh.material.opacity become x, rotateY, and opacity.

02 Three Capabilities in Detail
Side-effect import

One import, seven target types

import 'animejs/adapters/three' registers the adapter. Per the release note it animates Object3D, materials, lights, cameras, audio nodes, UniformNode (TSL), and instanced meshes. The underlying registerAdapter() API is general: it extends animate() and utils.set() beyond DOM targets.

Flattened props

Nested paths become Anime.js props

Per the source review: mesh.position.x → x, mesh.rotation.y → rotateY, mesh.material.opacity → opacity. Rotation values are degrees, not radians; colors accept CSS color syntax. Color blending itself now mixes RGB channels in pseudo-linear space (a v4.5.0 bug-fix note — intermediate colors differ slightly from earlier versions).

3D stagger

Grid gains a depth axis

Stagger auto-grid supports 3D layouts via {x,y,z} coordinates or explicit grid: [columns, rows, depth]. axis accepts 'z'. A new jitter parameter takes a single number or [start,end], and a new seed parameter makes jitter and from:'random' reproducible.

03 Canonical Usage

Enable the adapter, animate the mesh, sync the render

// minimal pattern — imports and calls as documented in the release / source review
// animejs + three imports
import { animate, createTimer } from 'animejs';
import * as THREE from 'three';
import 'animejs/adapters/three';  // side-effect: registers the adapter

// animate a mesh with flattened props (degrees for rotation)
animate(mesh, {
  rotateY: { to: 360 },
  x:       { to: 2 }
});

// render sync via createTimer
createTimer({
  onUpdate: () => renderer.render(scene, camera)
});
04 Scope & Boundaries
Read the limits before adopting
  • This card reports the v4.5.0 release page and the source review — no hands-on install, run, or benchmark was performed.
  • The ~24.5 KB gzipped core size is per the source review only; it was not checked against an actual bundle.
  • Three.js as an optional peer dependency supporting 0.150.0+ is per the source review; it was not found on the release page.
  • Community-reported pitfalls (per the source review): undefined when animating a GLTF model before it enters the scene, and binding a child node instead of the Group.
  • Selection boundary (the source review's own advice): the adapter does not replace AnimationMixer / glTF animation clips for skeletal animation, physics, or large scene roams.
