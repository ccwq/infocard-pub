把代码库翻译成交互式课程的 Skill

codebase-to-course 的目标不是再写一篇 README，而是把一个代码仓库拆成 4–6 个模块、课程脚本、图表、测验和代码 ↔ 白话双栏解释，最后拼成一个可离线打开的单页课程，用来教不会写代码但会用 AI 的人真正看懂项目内部结构。

定位

它要解决的是“看得懂代码库”，不是“再生成代码”

这套 skill 针对的是会用 AI 搭东西、但未必理解底层结构的人。它把代码仓库拆成可以滚动浏览的模块、图表、测验和术语提示，目的是让使用者知道按钮背后到底发生了什么，好去做更稳的架构判断、debug 或和工程师沟通。

教学哲学

Build first, understand later

README 里最关键的反转是：不是先学几年 CS 再去做东西，而是先把东西做出来、先体验它能跑，再沿着真实交互去反推代码流。课程的第一模块总是从一个真实用户动作开始，而不是从术语百科开始。

  • show, don't tell每屏至少一半是视觉而不是段落。
  • trace real usage沿用户真实操作去追数据流。
  • application quiz题目考“怎么做”，不考背定义。
课程骨架

不是一份 HTML 文件，而是一整个课程目录

SKILL.md 明确说输出是一个目录：预置的 styles.css、main.js、_base.html、build.sh，再加每个模块的 HTML 文件，最后 assemble 出 index.html。这比“让 AI 一次写完一个巨型 HTML”更像工程流水线。

生成链路

四阶段：先读代码，再设计课程，再装配页面

01

Codebase analysis： 读取 README、入口文件、主数据流、主要 actors、API、架构技巧和真实 gotchas。

02

Curriculum design： 把代码库压成 4–6 个模块，围绕用户动作、actors、数据通信、外部系统、工程技巧和故障排查来排列。

02.5

Module briefs（复杂仓库）： 先写 module briefs，把代码片段、教学弧线、交互元素和所需 reference 切片下沉给后续子代理。

03

Build course： 复制 references 里的样式/脚本骨架，只写模块 HTML，再用 build.sh 组装。

04

Review： 在浏览器里打开 index.html，检查课程内容、设计和交互是否真的成立。

关键边界这套 skill 不让用户先审 curriculum；它的默认行为是“内部设计课程，再直接构建”，把用户放在验收位置而不是计划审批位置。
references/ 资产

references 不是附录，而是课程引擎

这个仓库顶层几乎没有代码，真正的价值集中在 references：styles.css、main.js、_base.html 提供 UI 骨架；interactive-elements.md 定义测验、群聊动画、数据流动画、architecture diagram、glossary tooltip 的写法；content-philosophy.md 则把“每屏最多几句、至少 50% 可视化”这些教学约束写死。

交互元素

五种元素是强制的，不是可选装饰

  • code ↔ English每个模块至少一个双栏翻译块。
  • quizzes每个模块至少一个，考应用而不是记忆。
  • group chat animation至少一处，用聊天模拟组件对话。
  • message/data flow至少一处，逐步展示流量/消息路径。
  • glossary tooltips技术术语首次出现就要能 hover/tap 看白话解释。
结构策略

Simple repo 走顺序，复杂 repo 走 briefs + 并行

SKILL.md 不是盲目鼓励多代理。它明确规定：简单 CLI / 小 web app 直接 sequential；只有 full-stack、monorepo、内容重、模块 6+ 的仓库，才先写 module briefs 再一批最多 3 个 subagents 并行写模块。这是把 token 成本、质量和上下文污染放在一起做取舍。

设计系统

Warm palette + developer notebook，不走典型 AI 紫色渐变

背景用 warm off-white / aged paper，而不是冷白商务底。
字体Display 用 Bricolage Grotesque，正文 DM Sans，代码 JetBrains Mono。
交互scroll-snap、nav dots、progress bar、keyboard navigation。
代码块深色 Catppuccin 风代码底，同时要求所有代码换行，不允许横向滚动。
有意思的一点：它自己是一个 skill，但内部已经像一个小型前端设计系统 + 内容系统 + 交互脚本仓库，而不是单薄 prompt。
适用边界

最适合“做出来了，但不知道怎么讲清楚”的代码库

A

适合：你已经有代码仓库，想把它讲给不懂工程的人，尤其是 AI 驱动开发者。

B

适合：需要把项目内部 actors、数据流、外部 API、故障路径和工程模式做成课程。

C

不适合：只想要一页静态介绍海报的人；这个 skill 天生更重，更像课程工厂。

一句话结论

它把“看代码”重组为一种课程生产线

codebase-to-course 不是单点教学 prompt，而是一条从代码库理解、课程模块规划、reference 资产复用、交互元素装配到最终 HTML 课程验收的完整流水线。最稀缺的不是“生成漂亮页面”，而是把课程结构、视觉系统和交互教法一起模板化。

为什么值得做卡

它是把“代码知识可视化”产品化的一类代表

如果说 codegraph 解决的是“让 agent 更快读代码”，那 codebase-to-course 解决的是“让人类非工程读者也能顺着交互式路径读懂代码”。两者都在做代码知识的压缩和重表达，只是一个偏语义索引，一个偏课程呈现。
