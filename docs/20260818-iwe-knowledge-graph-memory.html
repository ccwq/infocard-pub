01 · 一句话定位

iwe 是一个 Rust workspace，把磁盘上的 Markdown 目录解析成一张「文档 → 章节 → 链接」的轻量知识图谱。它同时暴露两个面：

  • CLI 面 —— 给人和脚本使用：iwe init --okf 一键初始化文件夹，iwe schema validate 校验文档结构，iwe find --filter 做语义查询。
  • MCP server 面 —— 给 LLM agent 使用：把 search / retrieve / create / refactor 四个工具暴露成 Model Context Protocol，任何 MCP 客户端（Claude Code、Cursor、自研 agent）都可以直接挂载。

底层是同一份 document graph，所以人改 Markdown、agent 通过 MCP 改 Markdown、CI 用 CLI 校验，三条路径看到的是同一份事实。

02 · 工作流与角色分工
左边是 Markdown 作者，中间是 iwe 内部 graph，右边是消费方
作者 VS Code Neovim Zed Helix → .md 文档树 → iwe graph → CLI init validate find → MCP search retrieve create refactor → LLM agent
03 · CLI 命令面（v0.19.1）
面向人和脚本。零依赖装 Rust 工具链后即可使用。

1) iwe init --okf

在当前目录一键生成 iwe 推荐的结构：index.md、章节组织、推荐 frontmatter。

# 把空目录变成 iwe 知识库
$ iwe init --okf
# 已生成 index.md 与子章节模板

2) iwe schema validate

把整棵 Markdown 树当成 schema 文档校验：链接是否断、章节是否孤立、frontmatter 是否完整。

# CI 友好：非零退出码即失败
$ iwe schema validate ./docs
# 3 docs validated, 0 errors

3) iwe find --filter

对图谱做语义查询：按标签、章节类型、引用关系过滤，支持 BM25 全文检索（启用后约 250ms 增量）。

# 找所有 tag=concept 的文档
$ iwe find --filter tag=concept
# 找引用过 auth.md 的章节
$ iwe find --filter refs=auth.md

4) iwe serve / iwe refactor

serve 启动本地 HTTP；refactor 触发安全重命名、链接修复、章节迁移 —— 与 MCP 的 refactor 调用同一份逻辑。

# 本地预览与服务 agent
$ iwe serve --port 4173
# 全局重命名文档标题并修正链接
$ iwe refactor --rename "Old":"New"
04 · MCP 工具面（给 LLM agent 的 4 个工具）
通过 Model Context Protocol 直接挂载到 Claude Code / Cursor / 自研 agent。
工具 作用 关键参数 典型用法
search 在知识图谱中按语义 / BM25 检索相关文档与章节 query, filter, limit agent 在回答前先 search("OAuth 流程") 拿上下文
retrieve 读取指定文档 / 章节的完整内容与元数据 path, section retrieve("docs/auth.md", "token-rotation")
create 新建文档 / 章节，并自动补全反向链接 path, template, frontmatter agent 生成新 ADR / note，自动挂在正确位置
refactor 安全重命名、链接修复、章节迁移 old_path, new_path, cascade 把 auth.md 改名后所有引用一次性更新
05 · 编辑器集成（4 套）
每套都是 LSP 形式直连 iwe 内部 API，不走 HTTP。

VS Code

官方扩展 iwe.vscode-iwe，补全、跳转、graph 面板。

Neovim

通过 nvim-lspconfig 注册 iwe-ls，与 Telescope 配合。

Zed

在 settings.json 里加 iwe LSP，秒级补全。

Helix

内置 LSP 机制直接接管 markdown filetype。

06 · 性能基准（README 合成）
仅来自官方 README 合成结果，非通用性能保证。

Apple M3 Pro · 20,001 files

模式耗时
无 BM25（仅 graph 解析）705 ms
开启 BM25 全文索引958 ms

实测数据集、文件类型分布、命令参数以官方仓库 README 为准；不可外推到其它硬件、文档大小或 markdown 写法。

什么时候这个数字有意义

  • 整树扫描 < 1 秒：做 CI 校验、agent 启动时一次性加载都够用。
  • 增量场景默认不重扫：LSP 监听文件改动，graph 增量更新。
  • BM25 是可选项：需要全文检索才开；纯图谱操作不付这个代价。
  • 不能跨硬件横比：M3 Pro / Apple Silicon 结果与 x86 服务器、笔记本差异较大。
07 · 适用与不适用

✅ 推荐场景

  • 个人 / 团队的 Markdown 笔记系统（Obsidian 替代品倾向）。
  • 把 文档站点（VitePress / Docusaurus 之前）当作 queryable 数据库用。
  • 给 LLM agent 提供 可检索、可改写 的知识库底座。
  • ADR / RFC / 决策记录 的强链接、强校验场景。
  • 需要 纯文本 source of truth、git diff 友好的知识沉淀。

⚠️ 不太适合

  • 需要 全文 + 向量混合检索 的 RAG（iwe 没有内建 embedding 索引）。
  • 非 Markdown 内容为主的 wiki（PDF、视频、数据库 schema）。
  • 实时协作编辑：iwe 是 single-writer of truth（git），不是 CRDT 协同。
  • 需要 富文本所见即所得 编辑器的工作流。
  • 对 超大二进制附件（>100 MB / 文件）的内联管理。
08 · 5 步上手

Step 1 · 安装 iwe

# 推荐从 crates.io（Rust 工具链）
$ cargo install iwe
# 或预编译二进制（见官方仓库 Releases）

Step 2 · 初始化知识库

$ mkdir my-kb && cd my-kb
$ iwe init --okf
# 自动生成 index.md 与模板子目录

Step 3 · 编辑 + 装编辑器扩展

用 VS Code / Neovim / Zed / Helix 任一打开目录，iwe LSP 自动接管 Markdown 文件类型。

Step 4 · 接入 LLM agent（以 Claude Code 为例）

# claude_desktop_config.json / .mcp.json
{
  "mcpServers": {
    "iwe": {
      "command": "iwe",
      "args": ["serve"],
      "cwd": "./my-kb"
    }
  }
}

挂上之后，agent 能用 search / retrieve / create / refactor 直接操作你的 Markdown。

Step 5 · CI 校验

# GitHub Actions 片段
- run: cargo install iwe
- run: iwe schema validate ./docs
