TextToMem
记忆操作协议
定位：记忆操作协议定义层。提供统一的原子指令集（IR 层），通过 JSON 五元组结构实现跨系统标准化，强调工程安全拦截。
核心哲学：把「记忆」抽象为可组合的协议操作，而非具体实现。设计目标是让不同记忆系统可以互操作。
IR 层协议JSON 五元组跨系统标准化
记忆操作：ADD / UPDATE / DELETE / NOOP（协议级）
存储绑定：无（协议不绑定存储）
适用场景：底层工程研发、跨系统互操作、定义行业标准
MemZero
开源工业级中间件
定位：开源中间件 / 工业级落地。强调工程兼容性与动态加载，提供三种记忆分类（语义、情景、程序），优化双存储并行检索策略，适合中低频协作。
核心哲学：即插即用的工业级记忆中间件。强调生产环境可用性，提供完整的记忆 CRUD API，支持多种向量和图数据库后端。
工程中间件动态加载开源
记忆分类：语义 / 情景 / 程序
检索策略：双存储并行检索
适用场景：企业 Agent 系统、团队协作 Agent、多 Agent 通信
Later
MemGPT · OS 虚拟内存
定位：类操作系统虚拟内存管理。模拟计算机内存分层（核心内存 / 归档内存 / 召回内存），引入虚拟内存与 Git 机制，支持主动反思与长期记忆管理。
核心哲学：把 LLM 的上下文窗口看成有限 RAM，用操作系统的思路管理虚拟上下文，实现「无限」记忆的错觉。伯克利出品（UC Berkeley），学术背景扎实。
虚拟内存主动反思无限上下文
来源：UC Berkeley（cpacker et al.）
Git 机制：记忆版本控制与回滚
适用场景：长时程对话、文档分析、多跳推理 Agent
Mem0
文件级人机交互记忆
定位：文件级人机交互记忆。采用 MD 文件存储，透明度高且可手动干预，通过条件触发展现与增量更新，大幅降低 API 成本。2024 年开源即爆火，1 天 1 万星。
核心哲学：记忆即文件。LLM 自然语言驱动决策（ADD/UPDATE/DELETE/NOOP），记忆透明可见，用户可直接编辑 MD 文件干预记忆内容。

MemU
主动学习式记忆系统
定位：主动学习式记忆系统。采用双 Agent 架构（主 Agent + 后台守护进程），通过「显著性感知」机制模拟人脑强化学习，实现 24 小时主动预测。
核心哲学：不等待用户提问，而是主动预测用户需要什么记忆。24 小时后台运行，模拟人脑强化学习机制，显著性高的信息优先存储与召回。

ARCHITECTURE · 存储架构对比
— 3/7

两条技术路线

01
向量数据库路线

向量嵌入 + 语义相似度检索。MemGPT、MemU、Mem0（基础版）均采用。优点：实现简单、检索快。缺点：关系建模弱。

02
向量 + 图数据库双存储

Mem0ᵍ、MemZero 采用。向量 DB 处理语义检索，图 DB 建模实体关系网络。检索时并行查询再融合。优点：关系感知强。缺点：运维复杂度更高。

03
MD 文件路线

纯文本文件存储，Mem0 可选。优点：人类可读、可直接编辑。缺点：检索需额外解析，规模化后性能下降。

MEMORY LAYERS · 记忆分层哲学
— 4/7

三种分层范式

LLM
LLM 原生决策（Mem0 / TextToMem）

让 LLM 自己判断这条记忆是 ADD / UPDATE / DELETE / NOOP。无固定分层规则，依赖 LLM 理解力。

OS
操作系统分层（MemGPT / Later）

类 RAM 分层：核心内存（高优先级）/ 归档内存（低优先级）/ 召回内存（按需加载）。受 OS 虚拟内存启发。

RL
强化学习显著性（MemU）

不给固定分层，由强化学习模型评估每条信息的「显著性」，显著性高的优先存储与高频召回。

JUDGMENT · 综合判断
— 6/7

「失忆」不是模型的问题，是架构的问题

LLM 天生无状态，上下文窗口有限，但「记忆」本质上是信息的选择性存储与高效召回。五大框架代表了三条不同的解决思路：

A
协议抽象（TextToMem）

不解决「如何记」，而解决「记什么」和「怎么互操作」。适合有定制需求的大团队。

B
工程落地（Mem0 / MemZero）

即插即用的记忆中间件，降低接入门槛，适合大多数生产场景。Mem0 偏向个人/隐私，MemZero 偏向企业协作。

C
认知模拟（MemGPT / MemU）

借鉴操作系统或神经科学的记忆模型，让 Agent 自主管理记忆。适合前沿研究与高自主性场景。

SOP · 技术选型四步流程
— 7/7

如何为你的 Agent 系统选记忆框架？

1

明确约束

先回答三个问题：①是否需要用户可见/可编辑记忆？②团队技术栈是否支持额外存储后端（向量 DB / 图 DB）？③是否需要 LLM 自主管理而非人工规则？

2

划掉不适配项

无存储资源 → 排除 MemZero（需后端）。
无 LLM 调用预算 → 排除 Mem0（依赖 LLM 决策）。
无研发资源 → 排除 TextToMem、MemGPT（学习曲线陡）。

3

按优先级打分

选 2–3 个核心维度（如：隐私 / 成本 / 上手速度），每个框架按 1–5 打分。加权求和后取最高。

Mem0 → 隐私 5 成本 5 上手 5
MemZero → 企业 5 协作 5 上手 3
MemGPT → 长程 5 自主 5 上手 2
4

原型验证

选定框架后，用最小数据集跑一周：①检索准确率是否满足？②Token 消耗是否可接受？③用户是否感知到「记住了」？

5

监控与迭代

记忆框架上线后必须监控：检索命中率、Token 消耗增长曲线、用户投诉「失忆」频率。每季度重新评估框架适配度。

CODE · MemGPT 分层机制
— SOP B

核心 / 归档 / 召回 三层

核心内存 Core
最高优先级，始终在上下文窗口内。存放当前任务关键信息。
归档内存 Archival
低优先级，从上下文窗口移出但保留在外部存储。LLM 主动召回。
召回内存 Recall
由 LLM 主动触发检索，系统调用检索工具获取归档内容，加载回核心内存。

KEY INSIGHTS · 核心判断
— END

记忆的本质是信息选择

不是把所有对话都存起来，而是让 Agent 学会判断「这条值得记」。Mem0 的 ADD/UPDATE/DELETE/NOOP 机制是这一理念的最小实现。

存储与检索同等重要

向量 DB 解决「存什么」，图 DB 解决「关系是什么」，双存储路线（MemZero、Mem0ᵍ）是当前最具表现力的架构选择。

没有银弹，只有权衡

隐私优先选 Mem0，企业协作选 MemZero，长程推理选 MemGPT，主动预测选 MemU，底层研发选 TextToMem。技术选型是约束下的最优解，不是寻找完美方案。
