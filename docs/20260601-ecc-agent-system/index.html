ECC：把 Claude Code 变成可编排操作系统

1. 这仓库到底是什么

  • ECC = Everything Claude Code，定位是 harness-native operator system，而不是普通提示词集合。
  • 目标不是“让模型多说话”，而是把 代理编排、记忆优化、安全扫描、持续学习 变成可执行系统。
  • 支持 Codex、Claude Code、Cursor、OpenCode、Gemini、Zed、GitHub Copilot 等多 harness 运行。

2. 核心方法论

Agent-First
复杂任务先拆给专门 agent。
Test-Driven
先写测试，再实现，再重构。
Security-First
输入校验、扫描、避免泄漏是默认项。
Immutability
强调新对象而非原地修改。

3. 你真正能拿走什么

  • 一套 规划 → TDD → Review → Commit 的标准开发节奏。
  • 跨语言支持：TypeScript、Python、Go、Java、Kotlin、Rust、C/C++、F#、Django、Spring 等。
  • 把安装、审查、调试、发布、会话管理、状态导出，统一成可复用工具链。

4. 版本亮点

v2.0.0-rc.1 重点不是“功能再加一点”，而是把 ECC 重新包装成一个更完整的 operator story：公开 Hermess 流程、跨 harness 架构、状态快照与 GUI 仪表盘。

5. 快速判断

  • 适合：要建立 AI coding 工作流、团队规范、质量门槛的人。
  • 不适合：只想装个轻量 prompt 模板的人。
  • 关键词：agents / skills / hooks / rules / MCP / state / cross-harness。

6. 一句话结论

ECC 的价值不是“更多提示词”，而是把 Claude Code 变成可被规划、审查、测试和治理的操作系统。
