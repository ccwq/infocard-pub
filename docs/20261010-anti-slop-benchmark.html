5.4 万星的去 AI 味工具，得分 3/5

GitHub 上最火的 humanizer 工具 blader/humanizer，坐拥 54,072 颗星——但在统一 benchmark 里只拿到 3.0 分（满分 5）。与此同时，一个只有 212 星的工具 sloptrim，拿了 4.5 分，排名第一。

个 rewriter / detector skill 在同一套 harness 下被实测。结论出乎意料：行业共同盲区是——表层用词人人会改，底层结构没人碰。

X 用户 @GoSailGlobal（Jason Zhu，37,410 followers）团队发布横评数据：agentskillshub.top/best/anti-slop/，数据来源 github.com/zhuyansen/agent-skills-hub。

② AI 味的两层模型

表面改词 ≠ 去掉 AI 味

AI 文字在两个层面露出马脚：

Surface · 表层

用词和标点——删除破折号、替换 "delve"/"tapestry"、删掉 stock opener。

  • ✅ 12/15 个 skill 删光了英文帖的所有破折号
  • ✅ 容易修复，也容易被伪造
  • ❌ StoryScope 研究（61,608 故事，COLM 2026）：去掉表层后，结构分类器仍能识别 93.9% 的 AI 文章

Structure · 结构层

叙事选择——说出道理（AI 77% vs 人类 52%）、整齐收尾（47% vs 27%）、单线推进（79% vs 57%）。

  • ✅ 只有 2/21 个 rewriter 改动到这一层
  • ✅ 是真正区分 AI / 人类写作的特征
  • ❌ 19/21 个 skill 完全不动结构，只改用词

理解这个两层模型，是理解整份横评的钥匙。下面的所有数据，都建立在这个前提上：改表层是"化妆"，改结构才是"换人"。

⑨ 术语表

核心概念解释

AI slopAI 生成的低质量、大量复制、有明显「AI 味」的内容。此处特指文字风格层面：结构化、说教感、整齐收尾。
Humanizer将 AI 文字改写成读起来像人类所写的工具，分改写型（rewriter）和检测型（detector）两种。
Detector检测 AI 文字特征的工具，输出 flags 列表而非改写文本。humanizer-skill 是唯一认真检测结构层的检测器。
Phrasing vs Structure 层Phrasing（用词/措辞层）：替换词汇、删除破折号、去掉 "delve/tapestry" 等标志性词；Structure（结构层）：改变叙事选择——删除「说出道理」、留开放式结尾、引入具体细节而非泛指。21 个 rewriter 中 19 个停在 phrasing 层。
Harness统一的自动化测试框架：同一文本 + 同一驱动模型 + 同一评分标准，确保不同 skill 之间横向可比。此处用 Claude Code 驱动 + gpt-6-astra 评分。
⑩ 上手指南 · 用 Claude Code 跑 sloptrim

从零安装到第一次改写 · 命令级步骤

以下以 sloptrim（Benchmark 排名第 1，Human 4.5 分）为演示工具，展示完整的安装与使用流程。sloptrim 官方明确：「Python 标准库，无需网络，无需模型，文本不会上传任何服务器」❓ 评测站实操命令未捕获，按 sloptrim GitHub README 实录。

1
确认环境：Claude Code（任意版本）+ Python 3.9 或更新 + Node.js（用于 hook 机制）。
验证命令：python3 --version · node --version
2
安装 sloptrim（官方推荐方式）：在 Claude Code 对话框粘贴：
Install the sloptrim plugin from https://github.com/seyedehsanhadi/sloptrim
或手动安装： git clone https://github.com/seyedehsanhadi/sloptrim.git ~/.claude/skills/sloptrim
mkdir -p ~/.claude/commands
cp ~/.claude/skills/sloptrim/install/sloptrim-command.md ~/.claude/commands/sloptrim.md
❓ PowerShell 安装命令：New-Item + Copy-Item，需 Windows 实测确认
3
重启 Claude Code，让 skill 目录被扫描到。
4
诊断安装：输入 /sloptrim doctor，应返回 4 个 [OK]。
如果出现错误，按报错信息检查 Python 路径或 Node 依赖。
5
给 AI 文字打一次分（不做修改）：
/sloptrim check draft.txt
输出格式：0–100 分 + 具体 pattern 列表（如 "delve"、"em-dash" 等）。
分段：clean / light tells / mixed / heavy tells / pervasive tells。
6
正式改写（默认模式，含 contract + guard）：
/sloptrim full — 阈值 40 分，触达后自动请求修复
/sloptrim strict — 阈值 20 分，要求逐字清除
/sloptrim lite — 仅显示 contract，不阻止保存
/sloptrim off — 完全关闭
7
验证结果：查看改写后的文件，检查：① 数字/人名是否与原文件一致；② 是否读起来像人写的；③ 结构（说出道理 / 整齐收尾）是否有所松动。
8
为其他 Agent 初始化（如果你用 Cursor 或 Codex）：
/sloptrim init
会写入 ./AGENTS.md 和 ./.cursor/rules/，让非 Claude Code 工具也能响应 sloptrim 规则。
❓ Codex 集成实测步骤未在 README 中找到，需进一步抓取
sloptrim 的局限性（来自其 README）：① 只能检测 71 种已知 pattern，对当前前沿模型（GPT-4o、Claude 3.7 等）的检测 ROC-AUC 仅 0.551（接近随机）；② 只处理 prose，不处理代码；③ 通过 Bash 命令写入的文件不经过 hook，不会被检测；④ writing contract 的效果未经严格测量（n=20，p=0.27，CI 跨 0）。
blader/humanizer 安装（对比参考）：
mkdir -p ~/.claude/skills
git clone https://github.com/blader/humanizer.git ~/.claude/skills/humanizer
重启 Claude Code，在对话框中粘贴或描述要 humanize 的文本即可。

⑫ 结构特征逐项对比

26/26 个 skill 谁也没动的三个特征

这是整个 benchmark 最扎心的发现：所有 21 个 rewriter 在 40 次改写中，对以下三个特征一次都没有真正处理过。

说出道理（Tells / Stated Lessons）

AI 文字 77% 会主动说「这段话告诉我们……」，人类仅 52%。

横评结果：26/26 次改写完全保留——没有一个 skill 删掉这个特征。

实测案例：academic-humanizer 对 1232 字中文帖，只删了「首先」两个字，结尾的「综上所述」纹丝未动。

整齐收尾（Tidy Endings）

AI 文字 47% 用「总结 + 号召」结尾，人类仅 27%。

横评结果：28/28 次改写完全保留——包括所有结构层工具。

实测案例：sepia 触及结构层，反而把中文帖改成了「编号列表 + 更坚定的总结」——更 AI 味了。

单线推进（Single Track）

AI 文字 79% 无副线，人类 57%。

横评结果：40/40 次改写完全保留——所有工具无一例外。

唯一被处理的：表层破折号

英文帖原含 6 个破折号，12/15 个 skill 全部清零。

但 StoryScope 研究证明：清掉破折号后，结构分类器识别率仅从 95.5% 降到 93.9%——几乎没区别。

六维结构特征对照（含评测站数据）

结构特征 AI 文字 人类文字 横评保留率 检测难度
说出道理（Stated lessons） 77% 52% 26/26 全保留 难改
整齐收尾（Tidy endings） 47% 27% 28/28 全保留 难改
单线推进（No subplots） 79% 57% 40/40 全保留 难改
身体感受表达情绪 81% 38% ❓ 未单独测量 需人工
泛指作品而非点名 72% 50% ❓ 未单独测量 需人工
不与读者互动 93% 72% 仅 6 处改变（评测站注明） 相对易改
为什么结构层改不动？表层用词是「规则型」改动（搜索替换、删除固定词组），结构层是「意图型」改动（理解全文目的、重写叙事弧线）。前者可以靠规则文件实现，后者需要真正的写作推理——目前没有工具能可靠做到。

⑭ 两层问题自查 · 表层还是结构层？

判断你文字的 AI 味在哪一层

先用检测器跑一遍，再用下面清单自检。如果检测器通过了但你还是觉得"有 AI 味"，问题一定在结构层。

表层问题自检（检测器能发现）

文中是否出现 "delve"、"tapestry"、"crucial"、"game-changer"、"it is worth noting that"、"in conclusion" 等标志性 AI 词汇？
英文文章中 em-dash（—）是否过多？（AI 文字倾向大量使用破折号分隔句子）
段落开头是否千篇一律用 "Furthermore"、"Moreover"、"Additionally" 连接词？
开头是否有固定套路："In today's rapidly evolving..."、"In the realm of..."、"As technology continues to..."？
是否用了 stock opener / closer（预制开头结尾模板）？
中文文章是否用了「首先、其次、最后、综上所述」等机械连接词？

结构层问题自检（检测器难以发现，需人工判断）

【Tells · 说出道理】文章是否在结尾或段末主动总结「这段话告诉我们 X」？人类写作倾向于让读者自己得出结论，AI 倾向于说教。检测方法：删掉最后一段/句，意思是否仍然完整？
【Endings · 整齐收尾】结尾是否「总结+升华+号召」三件套？人类叙事更常留开放式或意外结尾。
【单线推进】全文是否只有一个主线，没有任何副线或意外？人类故事常有支线情节、插曲、反转。
【泛指 vs 具体】提到「伟大作品」时是否泛指而非点名？AI 倾向于说「许多研究表明」而非「Smith 等人 2023 年的论文」。
【无读者互动】全文是否从未出现「你」、「读者」、「你可能觉得」等人称互动？AI 学术写作常回避第二人称。
【情绪表达方式】情绪是否通过「bodily sensation」（身体感受）而非直接描述？StoryScope 研究发现 AI 文字 81% 用身体感受表达情绪，人类仅 38%。
操作建议：表层问题用 sloptrim / anti-slop 自动修复；结构层问题必须人工介入——删掉结尾的道理陈述、把整齐收尾改成开放式、引入一个具体的人名或地名代替泛指。工具改表层，人改结构，才是正确工作流。

⑮ 完整工作流 · 从草稿到发布

工具改表层 + 人改结构 = 正确姿势

基于 benchmark 结论，最优工作流是「自动化工具处理表层，人工介入结构层」。以下是一套可操作的五步流程，适用于英文博客、技术文档、中文公众号等场景。

1
用 LLM 写初稿（让 AI 完成它最擅长的部分：快速生成内容、填充结构）。
提示词示例：「请写一篇关于 [主题] 的 1500 字文章，面向 [受众]，语气 [风格]。」
2
第一步自动化：用 sloptrim 或 anti-slop 处理表层。
英文：/sloptrim full（1 min，Human 4.5）
中文：/Humanizer-zh（0.5 min，Human 3.0）
这一步删除 AI 标志性用词、破折号过度使用、stock opener/closer。
3
第二步检测：用 humanizer-skill 做结构层扫描。
安装后粘贴文字：「请用 humanizer-skill 检测，重点关注 8 个结构层 flags：stated lessons、tidy endings、no subplots 等。」
输出是清单，不是判决——逐项决定是否修改。
4
第三步人工结构编辑（核心，不可跳过）：
① 删掉结尾的「综上所述/这告诉我们」——让读者自己得出结论
② 把「总结+号召」结尾改成开放式或意外性结尾
③ 引入一个具体人名/地名/案例代替泛指
④ 加入一句第二人称互动（「你可能注意到……」）
⑤ 如写故事：加一条副线或一个意外转折
5
第四步事实核查。
对照原草稿，逐条确认数字、人名、日期、引用来源未被篡改。Benchmark 证明所有工具都保住了事实，但手动检查永远更可靠。
为什么第 4 步不能靠工具？结构层改动是「意图型」而非「规则型」——删除一个「这告诉我们」的句子很容易，但判断这句话是否必要、删掉后文章是否仍然完整、是否影响逻辑链，需要真正的阅读理解能力。当前没有任何工具能可靠完成这一步。

⑰ sloptrim 的 71 种 Pattern · 重点解读

你知道它在检测什么，才能用好它

sloptrim 检测 71 种 AI 写作 pattern，其中 62 个有自动化检测器，50 个影响分数。理解这些分类，有助于你判断：哪些是「化妆级」问题（工具可修）、哪些是「手术级」问题（必须人工）。

Pattern 类别 数量 典型例子 是否影响分数 修复难度
标志性 AI 词汇 ~15 "delve", "tapestry", "game-changer", "crucial" 是 工具可修
连接词过度使用 ~8 "Furthermore", "Moreover", "Additionally" 是 工具可修
Stock 开场白 ~6 "In today's rapidly evolving...", "In the realm of..." 是 工具可修
Stock 结尾语 ~5 "In conclusion...", "It is worth noting that..." 是 工具可修
标点与格式 ~6 破折号过度、冒号后全大写列表 是 工具可修
冗余解释 ~4 已知信息重复、过度展开明显结论 是 需人工审阅
中性表达过度 ~3 避免立场、避免争议、用「可能/也许」过度缓冲 是 需人工审阅
写作建议类（不计分） 12 正式程度、句子长度变化等技术指标 否（建议） 参考用
关于 12 个不计分的 pattern：sloptrim 官方 README 解释，这些主要是「正式程度」和「格式偏好」类指标，测量发现它们标记的是「正式文体」而非「机器 authorship」，因此不计入分数。例如：学术写作本来就应该用复杂句式，不能因此判定为 AI 生成。

sloptrim 分数含义速查

0–20 分Clean：几乎无 AI 特征，可直接使用或仅需微调。
21–40 分Light tells：少量 AI 特征，通常是表层词汇问题，工具可自动修复。
41–60 分Mixed：混合特征，表层 + 部分结构层，需人工审阅。
61–80 分Heavy tells：大量 AI 特征，结构层问题明显，工具效果有限，需大量人工编辑。
81–100 分Pervasive tells：几乎全部是 AI 特征，建议重写而非修修补补。

⑳ StoryScope 研究深度解读

61,608 故事告诉我们的三件事

这份 benchmark 的学术依据是 StoryScope 研究（COLM 2026），由 University of Maryland 和 Google DeepMind 发布（arXiv 2604.03136）。评测站和 GitHub README 都引用了它的关键数字。以下是对这些数字的解读。

研究规模

61,608个故事样本
（AI + 人类各半）
93.2%仅靠叙事结构
区分 AI/人类的 macro-F1
93.9%去除表层后
结构分类器仍能识别

核心实验逻辑

实验 A用原始 AI/人类故事训练结构分类器 → 95.5% 准确率（未去除表层特征）
实验 B用工具去除表层 AI 特征（破折号、标志性词汇等）→ 结构分类器仍达 93.9% 准确率
结论表层特征几乎不影响结构层检测能力；区分 AI/人类写作的关键在于叙事结构，而非用词。

研究对六类结构特征的测量结果

结构特征 AI 文字频率 人类文字频率 差距 区分能力
不与读者互动 93% 72% +21pp ★★★★
单线推进（无副线） 79% 57% +22pp ★★★★
身体感受表达情绪 81% 38% +43pp ★★★★★
说出道理（stated lessons） 77% 52% +25pp ★★★★
泛指作品而非点名 72% 50% +22pp ★★★
整齐收尾 47% 27% +20pp ★★★
「身体感受表达情绪」是最强区分信号：AI 文字 81% 用身体感受描述情绪（「他感到胸口一阵刺痛」），而人类仅 38%。这一特征横评未单独测量，是值得重点关注但被当前 benchmark 遗漏的结构维度。
⚠ 研究局限：StoryScope 全部基于小说/故事类文本。其结论（结构层区分度 93.2% F1）对非虚构写作（帖子、报告、邮件、代码注释）的适用性是未经验证的推测。AI 在非虚构中的结构问题（整齐收尾、说教感）与小说的叙事结构问题不是同一件事。
