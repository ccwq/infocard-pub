01

mattpocock/skills：把工程经验拆成可组合的 Skill

仓库自称 Skills for Real Engineers，强调小、易改、可组合，并可跨模型工作。重点不是多写几句提示词，而是把反复出现的工程判断放进可复用流程。

ALIGN/grill-me先把模糊需求问清楚，减少“做出来才发现没对齐”。
LANGUAGE/grill-with-docs建立共享语言、CONTEXT.md 和 ADR，降低沟通噪声。
FEEDBACK/tdd用 red-green-refactor 给代码持续反馈。
REPAIR/diagnosing-bugs按阶段诊断，而不是凭感觉继续加补丁。
DESIGN/to-spec先审视模块边界，再写实现。
# Claude Code plugin claude plugins install mattpocock-skills # Codex / other agents npx skills@latest add mattpocock/skills # 安装后按仓库说明运行 /setup-matt-pocock-skills
适合谁已经在做复杂工程、嫌 Agent 经常跑偏，又不想被一套庞大流程锁死的人。它的优势是可以只拿需要的 Skill，再按自己的项目改写。
打开 mattpocock/skills
02

ruvnet/ruflo：当一个 Agent 不够时，加上协作底座

Ruflo 把自己定位为 Claude Code 和 Codex 的 agent meta-harness。它在模型外增加路由、工具、memory、循环、sandbox、swarm 和跨机器通信；“98 agents / 60+ commands / 30 skills”等数量应视为项目方 README 的当前描述。

Swarm

把复杂工作拆给多个 Agent，按拓扑协作。

Memory

跨任务保存上下文，支持自学习与 RAG 相关能力。

Hooks / MCP

让日常 Claude Code 使用被路由和工具层接管。

Federation

README 描述跨机器 Agent 协作，同时需要单独审计数据边界。

# full CLI-track install npx ruflo init # Claude Code plugin path（按需选择插件） /plugin marketplace add ruvnet/ruflo /plugin install ruflo-core@ruflo /plugin install ruflo-swarm@ruflo
先理解安装面插件路径与 CLI full loop 不是同一个东西：前者提供 slash commands / agent definitions，后者会写入更多项目文件、hooks、MCP 和 daemon。先看项目状态文档，再决定是否把完整 harness 放进生产项目。
打开 ruflo
03

rtk：压缩 Agent 看到的终端噪声

RTK 拦截 shell 命令并压缩输出：把目录列表聚合、把 diff 和日志折叠、把测试输出聚焦到失败项。仓库 README 称常见开发命令可减少 60–90% bash output，但这不是账单直接减少 60–90%。

命令类型RTK 做什么收益边界
ls / tree树状格式 + 文件计数减少重复路径和逐行噪声
git status / diff / log按状态聚合，保留关键头信息适合 Agent 快速判断工作区
test / pytest / cargo test折叠通过项，突出失败和 traceback不能替代完整测试输出留档
grep / rg / read截断长行、按文件分组、偏向结构摘要需要全文时必须回到原始命令
# install brew install rtk # or cargo install --git https://github.com/rtk-ai/rtk # initialize for an agent rtk init -g rtk init -g --codex rtk init --agent hermes # inspect savings rtk gain
最容易误读的一点“最多减少 90% bash output”测的是命令输出，不是总输入 token、更不是总账单。RTK 的 token 估算是 bytes / 4，绝对值近似；同时要留意 hook、插件和原始输出回退。
打开 RTK
04

addyosmani/agent-skills：把生产生命周期做成九个入口

这个仓库把工程生命周期映射为 slash commands，并强调 spec before code、tests are proof、clarity over cleverness、faster is safer。它更像一套有明确质量门的工作规范，而不是单个效率小工具。

DEFINE/spec把想法和约束写成可执行规格。
PLAN/plan拆成小而原子的任务。
BUILD/build逐片实现，减少一次性大改。
VERIFY/test用测试和调试证明行为。
REVIEW/review合并前审查代码健康度。
SHIP/ship把发布当作流程的一部分。
# install all skills npx skills add addyosmani/agent-skills # browse before installing npx skills add addyosmani/agent-skills --list # install one skill npx skills add addyosmani/agent-skills --skill test-driven-development
可移植性提醒README 说明单 Skill 安装可能只复制 skills/，而不会携带仓库级 references/；如果依赖共享清单，要用完整集成、克隆仓库或把所需 reference 一并放入目标 Skill。
打开 agent-skills
05

怎么选：先补最短的反馈回路

✓ 你总是“需求没对齐”

  • 先看 mattpocock/skills 的 grill / spec / shared language。
  • 重点不是加更多模型，而是让 Agent 先问对问题。

✓ 你需要多 Agent 并行协作

  • 评估 ruflo，但先区分插件轻安装和 full loop。
  • 把 memory、hooks、MCP、daemon 当作基础设施审计。

✓ 上下文总被终端输出塞满

  • 试 rtk，从 git、测试和搜索命令开始。
  • 保留原始命令作为必要时的完整证据入口。

✓ 团队缺少统一交付标准

  • 看 addyosmani/agent-skills 的 lifecycle commands。
  • 把 spec、test、review、ship 变成可重复动作。
06

四个项目叠加时，别忘了三条边界

权限

Agent skills、hooks、MCP 和 shell proxy 都可能扩大操作面；先审查写入、网络和凭据访问。

证据

压缩输出提高效率，但发布、测试和安全审计仍要保留完整可追溯证据。

版本

star 数、命令数量和支持平台会变化；以当前仓库 README、release 和 lockfile 为准。

许可

mattpocock、ruflo、addyosmani 为 MIT；RTK 为 Apache-2.0。部署前核对依赖许可。

不要把“工程化 Skill”误解为自动质量保证Skill 提供流程和约束，harness 提供执行层，proxy 提供上下文压缩；最终质量仍取决于项目测试、权限边界、人工审查和真实运行证据。
