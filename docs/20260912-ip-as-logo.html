01

先做一个决定：你需要“符号”，还是“插画”？

这个 Skill 的价值在于把复杂度压下去，让角色在缩小后仍留下一个明确轮廓。

如果 32×32 的缩略图里只剩一团颜色，说明你做的是插画缩略图，不是可复用的 IP 符号。
SHAPE

4–7 个大几何形

一条连续剪影优先于大量零碎细节。厚、圆、钝；尖角、细线、针状尾巴都要主动改钝。

COLOR

默认三种语义色

两种 IP 基础色 + 一种实底背景。背景要略收敛，不用风景、光晕、投影去制造“高级感”。

COMPOSITION

从角落长出来

主体占据画面大部分，靠左下或右下出现，避免居中站立；角落构图比装饰背景更能保住辨识度。

02

安装与首次使用：先确认 Agent 真能生成图片

仓库本身是一个开放 Agent Skills 格式的单文档 Skill，不是独立 GUI，也不是带渲染引擎的 npm 包。

# 安装到当前 Agent 环境 npx skills@latest add s1dashu/ip-as-logo-skill # 安装为跨项目可用的个人 Skill npx skills@latest add s1dashu/ip-as-logo-skill --global

安装后检查什么

  • Agent 能读取已安装的 `SKILL.md`。
  • 当前 Agent 有内置图像生成能力，并能把结果作为独立 asset 返回。
  • 如果没有生成器，不能假装“已经生成”；应先启用兼容工具。

最小第一次请求

可以从一个简单主体开始：让 Agent 生成“纯色深海军蓝背景上的、极简圆润幽灵角色”。先观察轮廓是否清楚，再进入产品语境和批量流程。

03

完整工作流：为什么一定要先提案、再生成？

顺序本身就是质量控制：它把“模型随机发挥”变成人可以介入的决策点。

阶段你要提供/检查什么通过标准常见错误
上下文优先产品 README、设计 tokens、manifest；不足时一次合并提问背景角色有明确产品关联，不靠猜品牌不看上下文直接让模型“发挥创意”
三方向提案固定格式：IP 主题 — 产品关联 — 决定性剪影每个方向只改变一个主要设计决策给三张几乎一样的图，或只给颜色变体
用户同意明确选全部方向，或选中一个方向确认生成数量与分配方式未经同意自动消耗生成额度
独立批量生成六张全分辨率方图，不能是 contact sheet每张可单独下载、比较、交付生成一张六宫格，或自动筛掉“看起来不完美”的结果
人工选择查看缩略图、轮廓、角落构图和小尺寸识别度选择可进入品牌资产整理的候选把模型一次输出当成最终定稿
04

批量分配规则：三方向 × 两变体

默认不是“随便出六张”，而是让探索空间可比较。

ALL THREE

接受三个方向

生成 A1、A2、B1、B2、C1、C2：每个方向两张，方便比较方向差异与变体差异。

ONE DIRECTION

只选一个方向

生成同一方向的六个受控变体，让物种/比例/表情/角落位置成为主要变化轴。

OVERRIDE

用户改数量优先

如果用户拒绝默认数量或分布，新的明确要求覆盖默认规则；Skill 不应擅自补齐。

重要边界：README 同时强调“生成后原样交付”和“模型输出具有随机性”。因此它不会替你做透明度检查、质量筛选、自动拒绝或静默重试；复绘必须由人明确提出。
05

Prompt 的反直觉约束：不要把用途告诉模型

Skill 要求发送给图像模型的 prompt 只描述方形角色画面，不点破它将被当成 logo、品牌标或 app icon。

为什么不直接说“做 Logo”？

作者的判断是：一旦点破用途，模型容易回到常见的品牌标志套路，加入字母、徽章、复杂负空间或居中的平面图案，反而削弱角色感。

更可执行的表达

描述主体、构图、形状、颜色、背景和禁止项；不要用“高级品牌 Logo”“应用图标设计”等用途标签替代视觉约束。

# 示例：描述画面，不透露用途 Create a very simple, cute rounded ghost character on a solid deep navy background. Use a bold, thick silhouette with minimal facial details. Keep the square image clean and let the character emerge from a lower corner. Avoid text, scenery, glow, dramatic shadows, and complex details.
06

兼容性与风险：它解决的是流程，不是模型供应

安装 Skill 不等于自动获得图像模型、API 配额或某个平台的商业授权。

兼容前提

官方 README 列出 Codex、Coze、Doubao、YouMind、Manus、Gemini Apps、Replit Agent 等兼容环境，但共同前提是 Agent 能调用内置图像生成并返回 asset。

版本与模型边界

仓库没有 npm package.json，也没有 GitHub Latest Release；模型名称和推荐项可能随 README 更新。使用前应以当前官方 README 为准。

商用与署名

代码仓库是 MIT，保留版权与许可声明。README 另对生成后的 logo 资源作商业使用说明；实际交付前仍应检查所用模型、字体、素材与平台条款。

07

发布前自检：不用“看起来可爱”作为验收标准

把一次生成变成可重复的设计检查。

缩小测试

  • 缩到 32×32 后，主体是否仍是一条清楚剪影？
  • 两只眼和必要的小嘴是否仍可辨认？
  • 是否被背景、阴影或细线吞掉？

方向测试

  • 六张图是否真的覆盖方向/变体差异？
  • 是否有一张 contact sheet 冒充六张独立 asset？
  • 是否未经人选就自动淘汰或重试？

一句话带走

IP as Logo 的核心不是“让 AI 画得更复杂”，而是把 IP 设计拆成上下文、提案、同意、批量和人工选择五个可控节点，再用极简剪影保证小尺寸识别度。
