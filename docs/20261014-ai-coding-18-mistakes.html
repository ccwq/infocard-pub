AG雷达 · Agent 工作流

AI 编程的 18 个自查点：
先定位，再做最小实验

把“Agent 不好用”拆成上下文、对齐、验证与架构问题。每项给症状、一个动作和验收信号，不把建议变成一键改规则。

先做一次只读自查，不要同时改18项

选择最近一次真实任务，找一个返工节点；对照日志、差异和测试，标出适用条目。先记录证据，再经授权试一个可逆调整。更短的 Skill、更低的推理档位、更多自动审查，都不是单独的成功指标。

来源是鱼皮推文与配图中的18条英文转录。清单归于 Matt Pocock，但未取得原作者对应原推。下文中文释义、症状、修复动作和验收信号均为编辑建议，不冒充原话或实测效果。

看似矛盾，通常是决策对象不同

既要开工前对齐，为什么又不能频繁对齐？

第 3 条处理目标和授权边界未明；第 4 条处理边界已明后，对低风险细节反复请示。

判断：是否需要再次对齐，看新信息会不会改变目标、范围、风险或验收，不看讨论了多少轮。

配图“小改动先改再对齐”不构成越权许可；未授权、不可逆或高风险动作仍需先确认。

增加自动化审查，会不会与减少人工审查冲突？

第 7 条关注提交前是否有自动化筛查；第 9 条关注人是否被重复的机械检查占用。两者针对不同的审查承担者。

判断：把能提供可核验证据的重复检查交给工具，需承担责任的判断与审批留给人。

自动审查会漏报或误报；报告必须核证，不能用“Agent 审过了”替代必要的人类批准。

快速做原型，会不会削弱 Agent 的自我验证？

第 10 条鼓励用原型回答未知问题；第 11 条要求产出声明有验证依据。原型与生产交付的验收范围不同，二者都需要证据。

判断：先写清本次原型要回答什么，只验证这个问题；进入正式实现后，按正式需求补齐验证。

原型的未验证项必须保留；不能把“看起来能用”写成“可用于生产”。

降低 effort level，是否意味着少思考？

本清单将第 1 条解释为模型推理投入设置，将第 18 条解释为人的独立判断。调低某次模型投入，不替代人的目标选择与证据核对。

判断：简单任务可试较低模型投入，复杂或高风险判断仍应审视假设；具体适用档位不能仅凭这句转录确定。

投入与上下文

01

你的 effort level（推理投入档位）设得过高。这里按模型推理投入解读，不等于要求人少思考。

配图英文：Your effort level is too high

看什么
边界清楚的小任务仍出现长篇推演、反复考虑无关方案，交付内容却没有覆盖更多验收要求。
试什么
不改全局配置；若工具支持单次覆盖且获得授权，用相同的小任务与验收条件试跑较低投入档位。
怎么验
较低档位仍满足原验收条件，输出没有漏掉边界与检查证据；若失败，保留原档位。
02

你的技能文档过长。

配图英文：Your skills are too long

看什么
一次任务加载了大量不相关案例，执行时仍找不到本任务的入口、必要步骤或停止条件。
试什么
选一份常用技能，只在对话中拟出“入口摘要＋按需展开的细节”草案，不覆盖原文件。
怎么验
人工对照后，草案保留所有适用约束与例外，读者能从入口找到当前任务所需步骤。
06

你的自定义工具浪费了太多上下文 token。

配图英文：Your custom tooling is too token-inefficient

看什么
工具每次返回整份日志或大段重复字段，Agent 必须再次查找才能定位当前任务需要的事实。
试什么
选一次已有工具输出，在对话中拟出只保留任务字段、错误与原始记录定位信息的摘要样例，不修改工具。
怎么验
只看摘要仍能回答本次任务问题，必要时能定位完整记录；错误、截断提示与关键上下文没有被隐藏。
13

你的全局指导文件承载了过多规则。

配图英文：You've overloaded your global steering files

看什么
全局文件混有仅适用于个别项目的要求，或相互冲突的规则，Agent 在当前任务中反复误用。
试什么
只读检查全局规则，列出疑似冲突与局部适用项及其出处，提交待人工确认的分层建议，不删改文件。
怎么验
每项建议都有原规则位置、适用范围和保留理由；安全约束未被当成冗余删除，是否迁移由人决定。

任务对齐与放手

03

你没有在开工前对齐任务。

配图英文：You're not aligning before you start work

看什么
Agent 开始实现后才发现目标、修改范围或完成标准与用户理解不同，已有改动需要返工。
试什么
在下一次有歧义的任务开工前，提交目标、范围、验收信号和关键未知项的简短复述，请用户确认影响方案的歧义。
怎么验
实现前已明确成功条件与不做什么；未决问题被标出，而不是由 Agent 默默替用户决定。
04

你对齐得过于频繁，也过于繁琐。

配图英文：You're aligning too often, and too hard

看什么
范围和验收已确认，Agent 仍为局部命名、实现细节反复请求批准，讨论没有带来新的决策信息。
试什么
对一个已获授权的低风险小任务，在任务说明中约定只遇到范围变化、不可逆操作或关键歧义时停下来确认。
怎么验
约定范围内的可回退细节不再逐项打断用户，触及约定边界时仍会停止并说明原因。
12

你过度盯着 Agent 的每一步。

配图英文：You're babysitting the agent too much

看什么
用户不断指定下一条命令或打断执行，Agent 没有机会在既定范围内完成一个可验收的任务单元。
试什么
给一个边界清楚、可回退的任务约定交付物与停止条件，让 Agent 在已有权限内自行完成这个单元。
怎么验
Agent 能交付结果与验证证据，遇到越界或阻塞时主动停下；人不必逐条指挥命令。

验证与审查

05

你的自动化检查过于宽松。

配图英文：Your automated checks are too lax

看什么
检查全绿，但某个已经明确的需求或已知错误没有对应断言，错误输入也不会使检查失败。
试什么
经授权，在隔离环境为一个已知错误构造反例，试跑现有检查，确认它是否真能报错。
怎么验
检查能针对该错误失败并指出原因；正确行为通过，不能只凭退出成功宣称覆盖了需求。
07

你做的自动化审查不够。

配图英文：You aren't doing enough automated review

看什么
人工每次都在重复寻找遗漏分支、边界条件和需求偏离，提交前没有独立的自动审查记录。
试什么
对一份已有差异发起只读审查，让审查 Agent 按需求与风险找问题，并为每个问题提供文件位置和证据。
怎么验
审查报告包含可定位的问题或明确的检查范围与未覆盖项；无法举证的判断不直接进入修复队列。
09

你承担了过多人工审查。

配图英文：You're doing too much human review

看什么
人反复检查机器可验证的格式、类型或同类低风险错误，关键业务取舍却没有被单独列出。
试什么
对下一份审查材料，先让 Agent 只读汇总自动检查证据与风险清单，把需要人判断的事项单列。
怎么验
人能据证据处理业务、安全及不可逆风险，而不必重新做全部机械检查；必要人工审批没有被取消。
11

你的 Agent 无法验证自己的产出。

配图英文：Your agent can't verify its own work

看什么
Agent 写完代码就宣称完成，却没有运行结果；测试入口、可用环境或验证权限缺失。
试什么
先让 Agent 只读核对一个验收步骤的命令、环境与权限，具备条件且获准后执行最小验证，否则明确报告阻塞。
怎么验
完成判断附带实际执行结果；未执行、失败或环境受限都单独标明，不用推测代替验证。
16

你的代码库架构让不可靠的测试容易被写出来。

配图英文：Your codebase architecture allows bad tests to be written

看什么
测试主要断言内部调用或 mock 返回值，真实行为出错时仍可能通过；行为入口与实现细节难以分开。
试什么
选一个现有测试，只读追踪其断言到外部可观察行为，提出一个能区分正确与错误实现的反例及最小测试边界草案。
怎么验
草案指出当前断言漏掉的行为，并说明反例为何应失败；没有试跑时只算审查结论，不算测试能力已改善。

探索与复盘

08

你没有让 Agent 一起复盘之前的编程会话。

配图英文：You aren't reviewing previous coding sessions (with an agent)

看什么
最近的会话重复出现同一种返工或卡点，但下一次仍沿用相同的任务交代方式。
试什么
选一段获准读取且已脱敏的旧会话，让 Agent 只读定位一个返工节点，提出一个下次可试的调整。
怎么验
结论能回指具体会话片段，并区分已知事实与原因假设；调整无需自动写入长期规则。
10

你没有充分用 vibe coding 快速做原型。

配图英文：You aren't vibe coding enough prototypes

看什么
交互或技术可行性尚不清楚，却已经围绕最终实现展开长时间设计，争论缺少可试的样品。
试什么
经授权，在隔离环境围绕一个具体未知点制作可丢弃的最小原型，不接生产数据或直接并入主实现。
怎么验
原型通过可观察的交互或试跑回答了该未知点，并标出不能由这次实验证明的内容。

代码组织与决策

14

你的代码库难以定位和浏览。

配图英文：Your codebase is hard to navigate

看什么
为了一个明确功能，Agent 多次全库搜索仍找不到入口、实现或对应测试，容易改到相似但无关的模块。
试什么
围绕一个具体功能做限定范围的只读定位，在对话中给出入口、实现、测试的路径索引。
怎么验
索引中的路径与关系有代码依据，读者能据此定位目标功能；未确认的关系明确标为未知。
15

你没有建立共同的术语。

配图英文：You aren't building a shared language

看什么
用户、代码与 Agent 对同一个业务词理解不同，或把同一概念叫成多个名字，导致实现范围偏移。
试什么
从当前需求与代码中选一个有歧义的词，在对话中写出定义、对应代码名和不包含的含义，请用户确认。
怎么验
随后对该需求的复述和验收使用同一含义；无法对应的旧名称仍标为待确认，不擅自重命名代码。
17

你对整体方向与取舍考虑不足。

配图英文：You aren't thinking strategically enough

看什么
局部功能不断完成，但当前要解决的业务问题、约束或不做什么说不清，投入与目标缺少对应关系。
试什么
在下一项工作前写出它要验证的目标、关键约束与暂缓项，交由负责人确认是否值得做。
怎么验
该工作能对应一个明确目标，暂缓项有取舍理由；负责人可据此决定继续、缩小或停止。
18

你自己思考得不够。

配图英文：You aren't thinking enough

看什么
接受 Agent 的方案时，无法解释关键假设、潜在失败条件，或为什么不用另一种方案。
试什么
对当前方案独立写下一个关键假设和一个可能推翻它的反例，再与 Agent 给出的证据核对。
怎么验
能用证据说明该假设是否成立；若证据不足就保留疑问，不把 Agent 的自信当作结论。

把清单交给 Agent 的只读提示词

请结合当前项目，按这18个自查点做只读审查。
先报告你实际读取的需求、目录、会话与验证记录。
逐项标记：有证据适用 / 未见证据 / 不适用。
有证据项给出文件路径、日志或会话片段，并区分事实与原因假设。
只选择一个优先问题，提出最小可逆实验、验收信号和回退方法。
不要修改配置、全局规则、代码或权限，不自动执行实验。
测试通过只证明其断言范围；没有实际运行就标未验证。
不要把本次审查授权扩大成发布、推送或长期自动任务。

这是编辑提供的审查模板，不是 Matt 原推。涉及旧会话，先确认读取和脱敏范围。不要把私人日志、密钥或生产数据放进共享提示词。

结束时交付证据，不交付自信

建议记录：条目编号 → 观察证据 → 获准实验 → 实际命令/结果 → 通过、未通过或证据不足。一次实验回答一个问题，不承诺一次解决全部工作流问题。

配图的“小改动先改再对齐”和“每周让 Agent 精简”只按配图附注保留。前者不授权越界；后者不自动建立每周任务或删改安全规则。
