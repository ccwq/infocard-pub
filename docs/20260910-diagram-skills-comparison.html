二 · 逐个拆：每个 Skill 的机制与边界

1 · Diagram DesignEDITORIAL · 37.3K★

上一张卡的主角（已发布详解卡）。编辑向图解：38–39 种图表类型，输出自包含 HTML+SVG，默认无阴影、无外部依赖、可离线打开；支持从 draw.io / Mermaid / Excalidraw 导入后按自己的 layout grammar 重绘，重绘损失记录在 fidelity ledger。适合演示文稿、文章配图这种"读者看"的场景。安装走 Claude Code plugin marketplace 或复制 skills 目录。

2 · ArchifyVERIFIED MAP · 56.8K★

五者中唯一以"可校验"为核心的系统图工具。工作流是：Agent 产出 typed JSON IR（中间表示），Archify 确定性编译成 HTML/SVG——拓扑不由模型自由发挥，因此可校验。支持五种图类型、四套预设、深浅主题。最有辨识度的能力是 Before / Delta / After 对比：把两份校验过的快照做差，精确列出新增、删除、修改、移动、改道的节点与连线，适合在合并前 review 架构变更。交互全部有据可查：搜索节点、溯源到带 revision 校验的源码、追踪上下游影响面，不发明拓扑。导出自包含 HTML 与 PNG/SVG/WebM 及 1200×630 分享卡。

3 · Fireworks Tech GraphGEOMETRY-SAFE · 11.3K★

自然语言直出技术图：几何安全的 SVG+PNG（带完整文本上报与 text_policy: strict 拒绝截断）、可选 SVG 转 GIF 的局部动效、12 种视觉风格、14 种图类型、完整 UML 支持，内置 RAG、Multi-Agent 等常见架构模式模板。中英文描述均可输入，主题自带质量度量上限说明。适合"描述即出图"的快速产出，尤其需要 PNG 投稿或 GIF 演示的场景。

4 · Excalidraw Diagram SkillEDITABLE · 4.7K★

唯一输出可编辑 .excalidraw 文件的方案。主张"图要论证而不是展示"：形状的形态映射概念本身——扇出表达一对多、时间轴表达时序、汇聚表达聚合，拒绝均匀卡片阵。证据工件：技术图里放真实代码片段与实际 JSON payload，而不是占位文字。内置 Playwright 渲染自检回路：Agent 能"看见"自己的输出，发现文字重叠、箭头错位、间距失衡并循环修复后再交付。全部颜色品牌 token 收在一个 color-palette 文件里。安装：复制进 .claude/skills/ 即用。适合白板协作后还要人工继续改的团队。注意：仓库未声明 License，商用前必须先与作者确认。

5 · Visual ExplainerONE-PAGE · 9.7K★

出发点不是"画图"而是"讲清楚"：把架构解释、diff 评审（/diff-review）、计划审计（/plan-review）、复杂表格这些终端里沦为 ASCII 画的内容，变成排版精良的自包含 HTML 页或杂志风幻灯，带深浅主题和可缩放平移的交互 Mermaid。常规使用无构建步骤，唯一依赖是浏览器；可选 MCP 与 PPTX 工具引入少量 Node 依赖。适合评审材料、事后复盘文档这类"人要读"的产物。

四 · 选型决策：按你的场景对号入座
要给读者看
演示 · 文章 · 对外文档

Diagram Design 优先：编辑级审美 + 离线自包含 + 品牌化，"好看"这件事它最专业。

要保证画得对
架构评审 · 变更审计

Archify：typed IR 确定性编译，拓扑可校验，Before/Delta/After 让 merge 前的架构 review 有据可依。

要快速出 PNG/GIF
汇报 · 社媒 · 工单附件

Fireworks Tech Graph：中英描述直出，几何安全，可带动效，产出即拿走。

要继续手改
白板协作 · 设计接力

Excalidraw Diagram Skill：产物是可编辑白板文件，Agent 打底、人接着画（注意 License 未声明）。

要人读的长内容
diff 评审 · 计划审计 · 表格

Visual Explainer：把终端里读不了的东西变成一页 HTML，斜杠命令直达。

组合策略
全装，按任务路由

五者互不冲突：对外图用 Diagram Design，架构 diff 用 Archify，评审页用 Visual Explainer，白板用 Excalidraw。

一条工程判断：五者真正差异不在美观度，而在正确性由谁保证——Archify 用类型化 IR 让拓扑确定性可校验，Excalidraw 用渲染自检让 Agent 自己纠错，Diagram Design 与 Fireworks 把验收留给人，Visual Explainer 干脆不做严格拓扑、专注可读性。先想清楚你的图"错一下的代价"，再选工具。
五 · 30 分钟上手路径与验收

第一步：装 1–2 个，不要全装

# Diagram Design（Claude Code）
/plugin marketplace add cathrynlavery/diagram-design
/plugin install diagram-design@diagram-design

# Excalidraw Diagram Skill（.claude/skills/）
git clone https://github.com/coleam00/excalidraw-diagram-skill.git
cp -r excalidraw-diagram-skill .claude/skills/excalidraw-diagram

# Visual Explainer（Claude Code marketplace plugin，按仓库 README 安装）

Archify 与 Fireworks 按各自仓库 README 提供的安装方式接入（Node.js 渲染 / Python 脚本），装完先跑一次自带的示例再接真实任务。

第二步：用同一道题测所有候选

拿你项目里真实的一小块系统（比如"用户下单 → 支付回调 → 发货"）作为统一输入，分别让每个 Skill 生成。比较四点：节点/边的完整度、文字是否截断、风格是否统一、二次修改的成本。

第三步：逐项验收

  • 拓扑正确：与真实代码/系统的调用关系一致，没有 Agent 发明的节点
  • 文字可读：无截断、无重叠（Fireworks 可加 text_policy: strict 强制拒绝截断）
  • 导出可用：目标格式（PNG/SVG/HTML）在无网络环境打开正常
  • 风格统一：同批图颜色 token 来自同一套品牌配置
  • 可维护：改一个节点后能否低成本重新生成，而不是从头画
  • 许可合规：Excalidraw Diagram Skill 未声明 License，商用前确认
