# Codex 十大必装 Skills：这不是目录，是 agent 工程化入口

- 来源：X 状态 [2060973813010210991](https://x.com/i/status/2060973813010210991)
- 主题：Codex / coding agent 的 10 个常装 Skills
- 取法：保留原帖 1–10 顺序，按“工程纪律 / 命令框架 / Agent 增强 / 生态索引”四条主线重组
- 发布时点：2026-05-31 23:52:17 CST

## 结论

这条 X 帖真正讲的，不是“给 Codex 装 10 个插件就会起飞”，而是：**coding agent 也开始像工程团队一样，被拆成了可治理的能力层**。

我把这 10 个 Skills 归成 4 条主线：

1. **工程纪律层**：先写测试、先做审查、先把执行顺序固定住；
2. **命令框架层**：把复杂任务拆成可调用、可切换的命令；
3. **Agent 增强层**：用文件、上下文、外部服务把 agent 变得“有记忆、有边界”；
4. **生态索引层**：把零散技能汇总成可检索的目录与样板间。

所以这张卡的重点不是“10 个名字”，而是**10 个名字背后的角色分工**。

换句话说，帖子给你的不是单点技巧，而是一套从“写代码”到“管理代码代理”的能力地图。

## 4 条主线

### A. 工程纪律层
- **Superpowers**：把 coding agent 拉回 TDD / review 纪律，避免“看起来能跑、其实有坑”。
- **SuperClaude Framework**：用 slash 命令把复杂任务压成标准动作，适合更强约束的 agent 流程。

### B. 官方 / 参考实现层
- **Anthropic Official Skills**：官方参考实现，价值在于“规范样例”而不是花哨功能。
- **Vercel Agent Skills**：更偏 Web / React / UI 审查的工程实践集合。

### C. Agent 增强层
- **Planning with Files**：把 Markdown 文件当成外置记忆与计划板。
- **Context Engineering Skills**：强调上下文管理，防止 agent 被信息噪声拖垮。
- **Composio Skills**：把 Skills 和外部服务连接起来，让 agent 真的能动手办事。

### D. 生态索引层
- **MiniMax Skills**：更像技能集合包，适合看“别人怎么组织技能”。
- **Antfu Skills**：高手级技能写法的样板，偏方法论与审美。
- **Awesome Agent Skills**：技能索引与发现入口，适合先找，再选，再装。

## 10 个技能逐条看

### 1. Superpowers
- **定位**：编码纪律框架
- **一句话**：让 Codex 像严格工程师一样工作：先测、再写、再查。
- **先试什么**：先拿一个小改动跑 TDD 流程，看它会不会主动补测试与 review。
- **边界**：适合需要稳定性的任务；不适合把它当“万能自动化魔法”。

### 2. SuperClaude Framework
- **定位**：命令式工作流框架
- **一句话**：把 agent 的动作拆成标准 slash command，减少随机发挥。
- **先试什么**：选一个命令，看看它如何拆任务与约束上下文。
- **边界**：命令多、结构强，学习成本高于“轻量技巧包”。

### 3. MiniMax Skills
- **定位**：技能集合包
- **一句话**：以一组工业化技能展示如何把能力打包成可安装模块。
- **先试什么**：先看它的技能目录，再选一个和你当前任务最接近的项。
- **边界**：更适合借鉴组织方式，不适合一口气全装。

### 4. Anthropic Official Skills
- **定位**：官方参考实现
- **一句话**：不是炫技，而是给 skill-creator 提供“官方写法”的样板。
- **先试什么**：先读实现约束，再照着写一个最小技能。
- **边界**：参考价值很高，但不会替你解决具体业务问题。

### 5. Vercel Agent Skills
- **定位**：Web / React 实践集合
- **一句话**：把前端、UI、审查规则和工程习惯打成可复用的技能包。
- **先试什么**：拿一个前端问题让它做 review，看规则覆盖得是否足够细。
- **边界**：明显偏 Web 场景，别拿它去替代通用 agent 方案。

### 6. Planning with Files
- **定位**：文件化计划与记忆
- **一句话**：让 Markdown 文件替 agent 记住计划、状态和下一步。
- **先试什么**：先用一个小任务把 plan 写到文件里，再看它能否持续更新。
- **边界**：非常吃执行纪律；文件乱了，效果会快速下降。

### 7. Context Engineering Skills
- **定位**：上下文管理
- **一句话**：教 agent 怎么把上下文切片、压缩、续接和恢复。
- **先试什么**：给它一个长任务，看它如何控制上下文膨胀。
- **边界**：它解决的是信息组织，不是知识凭空增加。

### 8. Composio Skills
- **定位**：Skills + 外部服务编排
- **一句话**：把 agent 接到真实服务上，强化“能调用、能执行”的闭环。
- **先试什么**：先接一个最常用的外部动作，验证端到端链路。
- **边界**：外部依赖越多，稳定性与权限管理要求越高。

### 9. Antfu Skills
- **定位**：个人技能样板
- **一句话**：看高手如何写技能：结构、边界、命名和实用性都很克制。
- **先试什么**：把它当成技能写作的审美标准。
- **边界**：更偏方法与范式，不是一个直接拿来即用的产品包。

### 10. Awesome Agent Skills
- **定位**：索引目录
- **一句话**：500+ Skills 的发现入口，适合先做扫描，再决定安装。
- **先试什么**：先用它找出你当前任务最接近的技能类别。
- **边界**：它是目录，不是答案；适合筛选，不适合直接执行。

## 常见误读

### 误读 1：这是“安装越多越强”
不是。很多 skills 是框架、参考实现或索引，不是直接提高智力的外挂。

### 误读 2：这是“Codex 专属神装”
也不是。很多能力本质上是给 coding agent 补流程、补记忆、补边界，换到别的 agent 也能用。

### 误读 3：这是“目录大全”
更不对。目录只有名字，真正值钱的是：**先试什么、适合谁、不适合谁**。

## 当前边界

- **skill ≠ model**：技能不会替代模型本身的推理上限。
- **安装 ≠ 会用**：不做任务分解、上下文管理和验证，装再多也只是收藏。
- **目录 ≠ 方法论**：索引告诉你有什么，方法论告诉你怎么选。
- **10x 表述要降噪**：这类帖子最容易把“体系化提升”包装成“神奇倍增”，需要回到具体工作流判断。

## 这张卡建议怎么用

- 如果你在做 coding agent，先看 **Superpowers / SuperClaude / Planning with Files**。
- 如果你在做产品化 agent，先看 **Context Engineering / Composio / Official Skills**。
- 如果你只是想找灵感，先看 **Awesome Agent Skills / Antfu**。
