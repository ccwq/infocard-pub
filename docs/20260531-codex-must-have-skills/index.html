每个技能拆成四问：做什么、适合谁、先试啥、为什么看

这 10 个 Skills，分成四层能力

工程纪律层（#1–2）：约束 agent 怎么干活。
官方参考层（#4–5）：让 skill-creator 有样可抄。
Agent 增强层（#6–8）：给 agent 补记忆、上下文和动手能力。
生态索引层（#3、#9–10）：帮你发现和判断该装什么。

一句话判断：这 10 个不是“10 个都该装”，而是“你要先想清楚缺哪一层，再装哪个”。

怎么读这张卡

每个技能我都拆成了 4 段——它做什么 / 适合谁 / 第一个尝试 / 为什么值得看。你想了解哪个技能，直接看对应区块就够了，不需要逐个读完 10 个。

→ 先读结论 + 对应技能 → 试装 2–3 个 → 再决定要不要全装

10 个技能逐条拆解

list
1
Superpowers
工程纪律框架
它做什么

把 Coding Agent 拉入 TDD + Code Review 纪律。不是“多装一个功能”，而是给 agent 加一个执行规范：先写测试，再写实现，再自动审查差异。

适合谁

适合任何在认真用 coding agent 改源码、但不想让它“跑完就忘”的团队。

第一个尝试

`codex install superpowers`，然后对一个已有小改动跑完整的 TDD 流程。

为什么值得看

它解决的问题不是“更快”，而是“更可追踪”——你永远知道 agent 改了哪里、改之前测试是否通过。

2
SuperClaude Framework
命令式工作流框架
它做什么

把复杂任务拆成标准 Slash Command，减少 agent 的自由发挥空间。30 条 slash 命令覆盖了从架构设计到 bug 修复的常见动作。

适合谁

适合团队风格更“流程化”的场景——先选命令，再让 agent 按命令干活，而不是让 agent 自己决定怎么干。

第一个尝试

先试 `/analyze` 看它怎么拆问题、切上下文、分交付物。

为什么值得看

和 #1 的区别：Superpowers 管的是“怎么做（纪律）”，SuperClaude 管的是“做什么（动作模板）”。

3
MiniMax Skills
技能集合包
它做什么

一组工业化技能包，覆盖前端、全栈、移动端、文档等场景。共 10 个工业级滑卡，展示了“如何把能力打包成可安装的 Skills 模块”。

适合谁

适合想借鉴“别人怎么组织技能集合”的人，而不是期望装完立刻提效的人。

第一个尝试

先看目录和分类，再挑一个与你当前任务最接近的技能读它的 SKILL.md。

为什么值得看

价值在“组织方式”而不是单个技能本身。

4
Anthropic Official Skills
官方参考实现
它做什么

Anthropic 官方发布的 Skills 参考实现。重点不是炫功能，而是给 skill-creator 提供官方写法的样板。

适合谁

适合你想自己写 Skills 的时候——官方怎么写、怎么定义边界、怎么组织命令。

第一个尝试

先读任何一个 Official Skill 的 SKILL.md，看它与社区 Skills 在结构和约束上的区别。

为什么值得看

它是教科书，不是成品工具。读它不是为了直接用，而是为了学会怎么写。

5
Vercel Agent Skills
Web / UI 审查集合
它做什么

Vercel 官方出品的 Skills 包，140+ 条审查规则，覆盖 React、Web 架构、UI 设计和工程习惯。

适合谁

适合做前端/Web 开发时让 agent 做代码审查的场景。

第一个尝试

`codex install @vercel/agent-skills`，然后拿一个 PR 让它做 review。

为什么值得看

140+ 条规则的覆盖面决定了它不只是“检查格式”，而是真的在做工程审查。

6
Planning with Files
文件化计划与记忆
它做什么

把 Markdown 文件当成外置记忆与计划板。让 agent 记住自己在做什么、做到哪了、下一步要做什么。

适合谁

适合跨 session 的长任务管理——agent 不会因为你新开对话就忘记上下文。

第一个尝试

先给一个小任务写 `plan.md`，再看它能不能持续读写和更新。

为什么值得看

核心洞察：agent 的记忆不只在上下文里，也可以在文件系统里。

7
Context Engineering Skills
上下文管理
它做什么

教 agent 怎么把上下文切片、压缩、续接和恢复。解决“context 太多、太长、太乱”的问题。

适合谁

适合你的 agent 经常因为长对话或大仓库而跑偏、丢信息、状态混乱的情况。

第一个尝试

给 agent 一个长任务，观察它如何主动管理上下文——会不会做切片、写中间摘要。

为什么值得看

它解决的是“信息组织”问题，不是“知识增加”问题。

8
Composio Skills
Skills + 外部服务编排
它做什么

把 Skills 和外部服务（API / 数据库 / 第三方平台）连接起来，让 agent 真的能动手办事，而不只是“向你报告怎么做”。

适合谁

适合你的 agent 需要调用真实服务——发请求、查数据、调接口。

第一个尝试

先接一个最常用的外部动作，验证端到端链路是否稳定。

为什么值得看

它补的层是“执行闭环”——不只是说，而是做。

9
Antfu Skills
高手样板
它做什么

看高手（Anthony Fu）怎么写 Skills：结构克制、边界清楚、命名和实用性都非常克制。

适合谁

适合你想学“好的 Skills 长什么样”，尤其是技能的结构与审美。

第一个尝试

读它的 SKILL.md 当成写作参考，而不是安装后直接用它干活。

为什么值得看

本质是方法论和范式参考，不是即装即用的产品包。

10
Awesome Agent Skills
技能索引 / 发现入口
它做什么

500+ Skills 的汇总索引。适合先扫描生态，再决定装什么。

适合谁

适合刚接触 Skills 生态、想了解“都有什么可用”的新人。

第一个尝试

先用它按类别筛选，找出你当前任务最接近的技能类型。

为什么值得看

它是目录，不是答案。帮你找到选项，但不替你选择。

常见误读与边界

caveat
常见误读

"安装越多越强"

不是。很多 skills 是框架、参考实现或索引，不是直接提升智力的外挂；真正提升的是工作流的可治理性。

当前边界

skill ≠ model

技能不会替代模型本身的推理上限；安装 ≠ 会用。
