01
PROJECT OVERVIEW

项目概览

grok-skills 将 Grok（xAI）以插件形式接入 Claude Code 和 Codex，让 Grok 作为第三个 agent 在你的代码库中工作。

🎯 核心定位

不在于替代主 Agent，而是为 Claude Code / Codex 增加第二个（第三个）视角——用 Grok 的推理能力做审查、诊断、代码实现。

作者 Stephane Fourdrinier（@SFourdrinier）称其适合用 fable 框架控制 Grok 在多 Agent 场景下的行为。

⚙️ 架构层次

  • Node companion（companion 脚本）
  • Python wrapper（Grok Agent 封装）
  • Grok CLI（实际调用 xAI Grok）
  • Claude Code / Codex 插件层
  • ACP peer 协议（多轮对话）

📦 两个副智能体

  • grok-engineer-coder：实现代码（通过 worktree 或 live tree）
  • grok-rescue：诊断 / 第二意见（reason / code）
  • 均通过 plugin/agents/ 注册
  • Codex：SessionStart 自动安装

FABLE FRAMEWORK

fable 是什么？

fable 是 Stephane Fourdrinier 自研的 Agent 编排框架，用于控制多个 AI 模型（尤其是 Grok）在同一工作流中的行为。

🔧 fable 在 grok-skills 中的作用

fable 框架是 grok-skills 的"控制平面"——决定何时调用 Grok、如何分发任务、如何处理结果。

  • 多 Agent 任务分发（orchestration）
  • 行为规范（prompt 注入 / 约束）
  • 结果路由（审查结果 → 人类确认）
  • 与 Claude Code / Codex 的 Skill 系统集成

fable 源码未独立公开，作为 grok-skills 内部编排引擎使用。

🧩 fable vs. 其他 Agent 框架

维度fable传统框架
定位轻量级编排引擎重型平台
集成目标Grok + Claude Code/Codex通用多模型
任务分发Skill / subagent 双轨单一大脑
沙盒隔离worktree + 验证各异
安全模型双 runMode（hardened/direct）各异
# fable 编排下的 Grok subagent 生命周期 1. fable 接收 Claude Code / Codex 的任务委托 2. fable 选择合适的 subagent（grok-engineer-coder / grok-rescue） 3. 通过 ACP peer 协议建立 Grok 与主会话的多轮对话 4. Grok 在沙盒 worktree 中执行（hardened 模式） 5. fable 收集验证结果，执行 handoff 逻辑 6. 结果路由回主 Agent，人类确认后合并到主工作树

INSTALLATION

安装与快速上手

不需要手动 clone，通过插件市场直接安装。

📋 前置要求

  • macOS（live 模式需要 Seatbelt 沙盒）
  • Python 3 + Node.js（PATH 中）
  • Grok CLI 已安装并登录（grok --version 正常）
  • Claude Code 或 OpenAI Codex 已安装
  • 无版本锁定：任意可用的 Grok CLI 均可

⚡ Claude Code 安装

# 1. 添加市场并安装 /plugin marketplace add sfourdrinier/grok-skills /plugin install grok@grok-skills # 2. 重载插件 /reload-plugins # 3. 确认安装成功 /grok:setup

⚡ Codex CLI 安装

# 1. 添加市场并安装 codex plugin marketplace add sfourdrinier/grok-skills codex plugin add grok@grok-skills # 2. 开启新会话（SessionStart 自动加载） # Grok Coder / Grok Rescue 出现在 Agent picker 中

🔐 记录集成授权

# 允许直接写入当前工作树（默认） /grok:setup --integration direct # 隔离模式：先进入 worktree，验证后合并 /grok:setup --integration auto # 审查模式：只审查，不写入 /grok:setup --integration review # 强制 worktree + 验证（不直接落地） /grok:implement

SKILLS & COMMANDS

核心技能与命令

所有命令以 /grok: 开头（Claude Code）或同名的 Skill（Codex）。

命令 / 技能用途输出
/grok:preflight环境就绪检查（Grok CLI、登录态、Python、Node）JSON 状态信封
/grok:review代码审查（指定目标路径和任务描述）发现列表 + 修复建议
/grok:code代码实现（派生合约 → Grok 实现 → handoff）JSON 信封（runId）
/grok:implement一键委托循环（code + handoff 验证，强制 worktree）双条件就绪状态
/grok:status --run-id <id>查询运行状态进度 + 状态
/grok:handoff --run-id <id>提取交付物并验证（人工合并前必须调用）patch + manifest
/grok:setup初始化配置（runMode / integration / 通知）确认输出
/grok:dual-lens双视角分析（用 Grok 做对抗性审查）交叉验证结果
/grok:rescue诊断 / 第二意见（不写代码，仅诊断）诊断报告

🛡️ 双运行模式（runMode）

  • hardened（默认）：独立 Grok home、沙盒验证、密钥脱敏、worktree 隔离
  • direct：使用已安装的 Grok CLI 和 ~/.grok 认证，速度更快，隔离更少

🔔 完成后通知

  • 默认关闭（no toast）
  • /grok:setup --notification-mode auto：macOS 原生通知（仅 background 执行上下文）
  • --notification-mode webhook：POST JSON（SSH/CI/Windows）

LIMITATIONS

关键限制与注意事项

了解边界，安全使用。

⚠️ 平台限制

  • macOS 是唯一完整支持 live 模式的平台（依赖 Seatbelt 沙盒）
  • Linux / Windows 目前停留在 probe-required 阶段，待沙盒 profile 验证
  • 直接落地（direct integration）需要先执行 /grok:setup --integration direct 记录授权
  • 无授权的首次直接落地会 fail-closed（拒绝执行）

⚠️ 安全限制

  • 审查命令时需注意：Grok 也会列出被监控的路径（如 .git/hooks/），这会被记录为"文件变更"，属正常行为
  • hardened 模式对 worktree 做了 git 保护：检查 nested gitmodules、hooks/refs 路径
  • watch-hash 机制防止 Grok 在执行期间偷偷修改受保护文件
  • Codex 上的 stop gate / SubagentStop hook 默认休眠，需通过 /hooks 手动信任

📋 版本要求（已验证，2026-07-15）

  • Claude Code CLI：2.1.210
  • OpenAI Codex CLI：0.144.4
  • Grok CLI：无版本锁定，任意可用版本均可
  • 最新版本：grok-skills v2.0.0（2026-07-19）

❌ 不适合的场景

  • 纯 Q&A / 设计讨论（启动 Grok 太重）
  • 单行 typo 修复（直接用主 Agent）
  • 非 Grok 订阅者（Grok CLI 无法工作）
  • Linux/Windows 用户的 live 模式（沙盒未就绪）
  • worktree 中有未提交的变更时（直接模式下的 checkout 守卫）
