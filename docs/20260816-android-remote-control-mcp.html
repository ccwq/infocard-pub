Android Agent · MCP 操作手册

Android Remote Control MCP：把手机 UI 接入 Agent 控制面

基于 v1.11.1 官方事实包：MCP Server 运行在 Android 手机或模拟器上，通过 Accessibility Service 暴露 UI 操作能力；Agent 侧配置 IP、port 与 token 后，经 LAN、模拟器或官方 Remote Access Tunnel 连接。

一句话结论：这是“设备侧 MCP Server”，不是 PC 端遥控脚本。

核心风险与价值都来自 Accessibility Service：它能让 Agent 读取/操作 Android UI，也意味着 token、网络暴露、权限授权必须最小化。本卡不声称本地安装或真机实测。

03
TOPOLOGY

三条连接路径：LAN、模拟器、官方 Tunnel

这张卡的操作中心不是安装命令，而是拓扑选择：Agent 连接设备侧 MCP Server，需要地址、端口与 token 三个字段。

LAN

同网段首选

手机与 Agent 主机在同一局域网时最直接。

重点核对 IP、端口可达与 token 保护。

Emulator

开发验证

Android emulator 适合先跑通配置路径。

它不能自动代表真机权限体验。

Tunnel

官方远程访问

Remote Access Tunnel 用于跨网络场景。

不要把它与裸露公网端口混为一谈。

Token

最低安全线

IP / port / token 是 Agent 侧连接三件套。

泄露 token 等同于暴露控制入口。

04
OPERATOR FLOW

推荐执行顺序：先局域网跑通，再扩大边界

以下为卡内操作手册，不代表本机已执行安装或连接。

# Android Remote Control MCP 接入清单（说明性，不在本机执行） 1. 下载 v1.11.1 FOSS 或 GMS APK，并核对文件大小 2. 在 Android 13+ 设备/模拟器安装 3. 开启 Accessibility Service 4. 按任务需要授予 camera / mic / location / notifications / storage 5. 启动设备侧 MCP Server 6. 在 Agent/MCP 客户端配置： host = <PHONE_OR_EMULATOR_IP> port = <SERVER_PORT> token = <YOUR_TOKEN> 7. 先用 LAN 或 emulator 验证；跨网络再使用官方 Remote Access Tunnel
不要跳步先小范围

为什么先 LAN / Emulator？

Accessibility Service 已经是高权限入口；在跨网络之前，应该先证明版本、端口、token 与设备侧服务都正确。

  • 先验证目标设备是否 Android 13+
  • 先验证 token 认证是否生效
  • 先记录 Agent 能看到哪些 UI 树信息

06
RISK CHECK

上线前风险：Accessibility + 网络 + Token

这类工具的风险不是“能不能连上”，而是“谁能连上、能操作什么、日志里是否泄露 token”。

权限

Accessibility Service 必须被显式视为高权限

它让 Agent 能观察并操作 UI。仅在受控设备、受控任务中开启。

网络

不要默认公网暴露

LAN 和官方 Remote Access Tunnel 是不同边界；不要把端口直接暴露到不可信网络。

Token

把 token 当作控制密钥

不要写入公开截图、日志、卡片示例或 Git 仓库；示例统一使用 <YOUR_TOKEN>。

收口：Android Remote Control MCP 最适合“想让 Agent 操作真实 Android UI”的开发/自动化场景；如果只是文件传输、ADB 命令或投屏控制，它并不是最低成本方案。
