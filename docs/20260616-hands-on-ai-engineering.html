02
项目分类

最有价值的是目录结构：从 Agent 到 RAG 的路线图

仓库根目录直接按能力域组织：ai_agents、OCR、audio、multimodal、rag_apps、fine_tuning。对学习者而言，这比单篇文章更像一张工程地图。

ai_agents
包含 Multi-Agent Financial Analyst、Agentic Form Filler、AI Travel Planning Agent、GitHub Intelligence Agent、Browser Automation Agent、Research Team 等多种自动化工作流。
rag_apps
覆盖 Agentic RAG、Clinical RAG、YouTube Transcript RAG、GraphRAG、Hybrid RAG、HyDE RAG、Reasoning RAG 等检索增强生成模式。
OCR
包括 Image-to-Structured-Data Extractor、LaTeX Formula OCR、Medical Prescription Digitizer，把视觉文档转结构化数据。
multimodal
包含 GLM-OCR Pro、Video Understanding Agent、Multimodal Weather App、Multimodal RAG、Medical Document Parser 等图文音视频结合项目。
03
Agent 工程信号

Agent 目录已经不是“玩具 agent”，而是业务任务清单

AI Agents 分类下的条目覆盖金融分析、销售情报、表单填写、酒店搜索、品牌监控、代码审查、日程预约、Newsletter 自动生成等真实任务。

关键观察：这个仓库最适合用来回答“AI agent 可以落在哪些业务流程上？”——它列出的不是能力口号，而是一个个可以 fork 的任务原型。

多 Agent 协作

  • Market Analyst + Strategy Officer + Creative Director
  • Seek + Scout + team leader research system
  • Planner + Coder + Reviewer coding pipeline

工具链连接

README 中多次出现 Firecrawl、GitHub MCP、YFinance、Trivago MCP、Fetch MCP、DuckDuckGo、Wikipedia、SQLite、ChromaDB、Qdrant 等工程组件，说明它关注的是端到端系统，而非单次 prompt。

04
RAG / OCR / Multimodal

它把文档、图像、音频和视频都纳入 AI 应用样本

与只收集聊天机器人不同，这个仓库把输入形态扩展到 PDF、图像、YouTube 视频、音频、数据库、网页和知识图谱，覆盖更接近企业应用的场景。

RAG

从普通 RAG 到 GraphRAG / Hybrid RAG

不仅有向量检索，也有知识图谱、数据库路由、HyDE、实时 web search 等变体。

OCR

从图片识别到结构化输出

包括处方数字化、公式 OCR、图片转 validated JSON，强调结构化而不是只识别文本。

Multimodal

多模态不止看图问答

包含视频章节总结、天气地图识别、临床文档解析和跨媒体 RAG。

05
使用建议

把它当“AI 工程题库”，不要只当收藏夹

更高效的用法是按业务目标反查项目：要做代码审查、问答、文档解析、研究助手、销售情报，就直接找对应目录拆技术栈。

适合谁

  • 想从 demo 走向可运行应用的 AI 工程师
  • 需要样板项目做内部 PoC 的团队
  • 想比较 Agent / RAG / OCR / 多模态路线的人
  • 需要持续跟踪 AI Engineering 实践的读者

使用方式

  • 先按目录选能力域，不要从 star 数判断价值
  • 阅读 README 后检查每个项目的 requirements 与 .env.example
  • 用一个业务流程替换示例数据源
  • 把模型供应商抽象出来，避免被单一 API 锁死
Recommended path:
1. Pick a business workflow: research / finance / document / support / code review
2. Map it to ai_agents, rag_apps, OCR, multimodal, or audio
3. Run the closest project locally
4. Replace data source + model provider
5. Add evaluation and deployment guardrails
