01

先理解方案：三件工具各自负责什么

别把它们当成重复插件；它们覆盖的是命令行输入链条的三个不同环节。

一句话：fzf 让“找命令”变快，zoxide 让“去目录”变快，ble.sh 让“写命令”更清晰、更可补全。它们仍然运行在 Bash 之上，不会破坏既有脚本、alias 或 Bash 习惯。
HISTORY & PICKER

fzf：把 Ctrl-R 变成搜索框

默认 Bash 的反向历史搜索必须连续匹配。fzf 允许输入零散关键词，实时筛选出历史命令；同一套机制也可参与路径和命令候选选择。

DIRECTORY FREENCY

zoxide：记住你常去哪里

用 z 项目关键词 代替长路径。它会根据访问次数和新近程度排序；越常去的目录，越容易被排在前面。

LINE EDITOR

ble.sh：给 Bash 换一套编辑器

在输入阶段标出命令、选项、字符串与错误；同时改善 Tab 菜单补全、候选浏览和行编辑。Bash 仍是 Bash，交互体验更现代。

02

安装：先上轻量组合，再叠加 ble.sh

适合 Ubuntu / Debian 的已验证路径。其他发行版请使用自己的包管理器安装 fzf、zoxide、gawk。

STEP A · 包管理器

安装 fzf、zoxide 与构建依赖

这一阶段需要管理员权限。gawk 是从源码构建 ble.sh 所需的依赖；单用 fzf + zoxide 时不需要它。

# Ubuntu / Debian sudo apt-get update sudo apt-get install -y fzf zoxide gawk
STEP B · 源码安装

构建并安装 ble.sh 到用户目录

ble.sh 不必写入系统目录。安装到 ~/.local/share/blesh，既不污染系统，也方便后续自行更新。

git clone --depth=1 https://github.com/akinomyoga/ble.sh.git ~/.local/src/blesh make -C ~/.local/src/blesh install PREFIX=$HOME/.local
轻量版选择：如果你只要更好用的历史搜索和跳目录，到这里安装 fzf + zoxide 就够了；ble.sh 是“输入时高亮、菜单补全、编辑体验”的加成，不是前两项工作的前置条件。
03

配置：把三个钩子放进 ~/.bashrc

只影响交互 Bash。建议放在已有 alias、PATH 和 bash-completion 初始化之后。

# ~/.bashrc —— 仅交互 shell 会读取本文件 # 1) fzf：Ctrl-R 历史模糊搜索，以及 Bash 补全整合 if command -v fzf >/dev/null 2>&1; then source <(fzf --bash) fi # 2) zoxide：提供 z / zi 等目录跳转命令 if command -v zoxide >/dev/null 2>&1; then eval "$(zoxide init bash)" fi # 3) ble.sh：只在交互 Bash 且文件存在时加载 if [[ $- == *i* && -r "$HOME/.local/share/blesh/ble.sh" ]]; then source "$HOME/.local/share/blesh/ble.sh" --noattach ble-attach fi

为什么要做存在性检查？

这样你在没有 fzf、zoxide 或 ble.sh 的远程机器上复用同一份 dotfiles 时，Bash 不会因为找不到命令或文件而报错。

如何立即生效？

新开一个终端最稳妥；也可以执行 source ~/.bashrc。如果当前 shell 的交互状态已很复杂，优先新开终端，而不是反复 source。

04

快捷键与日常动作：从今天起少敲一点

先记住三件事：Ctrl-R 找历史、z 去目录、Tab 看候选。

动作怎么用什么时候最省事
模糊找历史Ctrl-R 后输入关键词；用方向键或 Ctrl-J/Ctrl-K 选择，回车带回命令行。知道“以前跑过类似命令”，但不记得完整参数。
跳常用目录输入 z infocard、z wiki 这类片段；用 zi 可打开交互选择。项目路径很深，或多个项目名字有相近部分。
浏览补全候选输入命令或路径前缀后按 Tab；ble.sh 会把可选项以更易浏览的方式展示。子命令、Git 分支、长路径和带大量参数的 CLI。
识别输入错误观察 ble.sh 的输入高亮；未识别命令或不匹配的引号通常会呈现异常颜色。复制长命令、拼接引号、写多层管道之前。
05

10 个使用技巧：把“知道工具”变成肌肉记忆

不需要一口气记住；从前 3 个开始，就会明显减少重复敲命令。

用关键词召回复杂历史

先按 Ctrl-R，再输入不连续的词，如 docker logs api。不要试图记住完整命令。

历史结果带回后再微调

fzf 选中的命令不会立刻执行，而是回填到当前行。你可以先改端口、文件名或日期，再按回车。

把 z 当作 cd 的默认入口

不必等熟悉后再用：每次要去深层项目目录时先试 z 项目名，它会自然学习你的访问习惯。

用 zi 处理同名目录

当 z src 命中多个目录，运行 zi src，用交互列表精确选择，避免跳错项目。

先输入命令骨架再按 Tab

面对陌生 CLI，不必查完整用法。先输入 git、docker 或工具名后按 Tab，按层探索子命令和参数。

把高亮当成提交前检查

输入含引号、变量、管道的长命令时，先看颜色是否异常；它不能替代执行，但能提前发现一类低级拼写错误。

保留已有 alias，不必重造

例如已有 ll、gs、项目快捷命令，照常保留。新工具增强的是发现与输入，不是要求清空 alias。

让历史跨终端更可用

在 Bash 中启用 shopt -s histappend，并在 shell 退出时追加历史；这样 fzf 可搜到更多会话的命令。

远程机器采用降级配置

用本卡的 command -v 与 -r 检查包裹钩子。工具未安装时跳过，不让 SSH 登录被配置错误打断。

把“查路径”变成一次 z 搜索

遇到“那个项目在哪”，先输入 z 关键词。若没命中，再用 find 或 fd；不要先翻 shell 历史。

06

常见问题与排障：先确认加载，再怀疑工具

绝大多数“没生效”不是工具坏了，而是 .bashrc 没有在当前交互 Bash 中被读取。

Q1 · Ctrl-R 还是旧的搜索？

确认 fzf 钩子是否已加载

新开终端，运行 type fzf，再检查 grep -n 'fzf --bash' ~/.bashrc。确保该段位于非交互 shell 的 return 之后。

Q2 · 输入 z 提示 command not found？

检查 zoxide 初始化

运行 zoxide --version，并确认 eval "$(zoxide init bash)" 在 .bashrc。改完后新开 Bash 或 source 一次。

Q3 · ble-attach: command not found？

通常是路径写错或 source 失败

确认 ~/.local/share/blesh/ble.sh 可读，再确认 source 使用的是这个真实路径。构建失败时先安装 gawk，再重新执行 make install。

Q4 · 我不想用 ble.sh？

直接删除/注释 ble.sh 三行

保留 fzf 与 zoxide 的两个 block 即可。它们独立运行，不依赖 ble.sh；这是最小、稳定、低摩擦的增强方案。

事实边界：安装与 PTY 加载状态来自本机已验证环境；不同发行版的包名与安装路径可能不同。来源：fzf · zoxide · ble.sh 官方项目
