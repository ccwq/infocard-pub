01

先理解方案：三件工具各自负责什么

别把它们当成重复插件；它们覆盖的是命令行输入链条的三个不同环节。

一句话：fzf 让“找命令”变快，zoxide 让“去目录”变快，ble.sh 让“写命令”更清晰、更可补全。它们仍然运行在 Bash 之上，不会破坏既有脚本、alias 或 Bash 习惯。
HISTORY & PICKER

fzf：把 Ctrl-R 变成搜索框

默认 Bash 的反向历史搜索必须连续匹配。fzf 允许输入零散关键词，实时筛选出历史命令；同一套机制也可参与路径和命令候选选择。

DIRECTORY FREENCY

zoxide：记住你常去哪里

用 z 项目关键词 代替长路径。它会根据访问次数和新近程度排序；越常去的目录，越容易被排在前面。

LINE EDITOR

ble.sh：给 Bash 换一套编辑器

在输入阶段标出命令、选项、字符串与错误；同时改善 Tab 菜单补全、候选浏览和行编辑。Bash 仍是 Bash，交互体验更现代。

02

安装：先上轻量组合，再叠加 ble.sh

适合 Ubuntu / Debian 的已验证路径。其他发行版请使用自己的包管理器安装 fzf、zoxide、gawk。

STEP A · 包管理器

安装 fzf、zoxide 与构建依赖

这一阶段需要管理员权限。gawk 是从源码构建 ble.sh 所需的依赖；单用 fzf + zoxide 时不需要它。

# Ubuntu / Debian sudo apt-get update sudo apt-get install -y fzf zoxide gawk
STEP B · 源码安装

构建并安装 ble.sh 到用户目录

ble.sh 不必写入系统目录。安装到 ~/.local/share/blesh，既不污染系统，也方便后续自行更新。

git clone --depth=1 https://github.com/akinomyoga/ble.sh.git ~/.local/src/blesh make -C ~/.local/src/blesh install PREFIX=$HOME/.local
轻量版选择：如果你只要更好用的历史搜索和跳目录，到这里安装 fzf + zoxide 就够了；ble.sh 是“输入时高亮、菜单补全、编辑体验”的加成，不是前两项工作的前置条件。
03

配置：把三个钩子放进 ~/.bashrc

只影响交互 Bash。建议放在已有 alias、PATH 和 bash-completion 初始化之后。

# ~/.bashrc —— 仅交互 shell 会读取本文件 # 1) fzf：Ctrl-R 历史模糊搜索，以及 Bash 补全整合 if command -v fzf >/dev/null 2>&1; then source <(fzf --bash) fi # 2) zoxide：提供 z / zi 等目录跳转命令 if command -v zoxide >/dev/null 2>&1; then eval "$(zoxide init bash)" fi # 3) ble.sh：只在交互 Bash 且文件存在时加载 if [[ $- == *i* && -r "$HOME/.local/share/blesh/ble.sh" ]]; then source "$HOME/.local/share/blesh/ble.sh" --noattach ble-attach fi

为什么要做存在性检查？

这样你在没有 fzf、zoxide 或 ble.sh 的远程机器上复用同一份 dotfiles 时，Bash 不会因为找不到命令或文件而报错。

如何立即生效？

新开一个终端最稳妥；也可以执行 source ~/.bashrc。如果当前 shell 的交互状态已很复杂，优先新开终端，而不是反复 source。

04

快捷键与日常动作：从今天起少敲一点

先记住三件事：Ctrl-R 找历史、z 去目录、Tab 看候选。

动作怎么用什么时候最省事
模糊找历史Ctrl-R 后输入关键词；用方向键或 Ctrl-J/Ctrl-K 选择，回车带回命令行。知道“以前跑过类似命令”，但不记得完整参数。
跳常用目录输入 z infocard、z wiki 这类片段；用 zi 可打开交互选择。项目路径很深，或多个项目名称有相近部分。
浏览补全候选输入命令或路径前缀后按 Tab；ble.sh 会把可选项以更易浏览的方式展示。子命令、Git 分支、长路径和带大量参数的 CLI。
识别输入错误观察 ble.sh 的输入高亮；未识别命令或不匹配的引号通常会呈现异常颜色。复制长命令、拼接引号、写多层管道之前。
05

10 个使用技巧：把“知道工具”变成肌肉记忆

不需要一口气记住；从前 3 个开始，就会明显减少重复敲命令。

用关键词召回复杂历史

先按 Ctrl-R，再输入不连续的词，如 docker logs api。不要试图记住完整命令。

历史结果带回后再微调

fzf 选中的命令不会立刻执行，而是回填到当前行。你可以先改端口、文件名或日期，再按回车。

把 z 当作 cd 的默认入口

不必等熟悉后再用：每次要去深层项目目录时先试 z 项目名，它会自然学习你的访问习惯。

用 zi 处理同名目录

当 z src 命中多个目录，运行 zi src，用交互列表精确选择，避免跳错项目。

先输入命令骨架再按 Tab

面对陌生 CLI，不必查完整用法。先输入 git、docker 或工具名后按 Tab，按层探索子命令和参数。

把高亮当成提交前检查

输入含引号、变量、管道的长命令时，先看颜色是否异常；它不能替代执行，但能提前发现一类低级拼写错误。

保留已有 alias，不必重造

例如已有 ll、gs、项目快捷命令，照常保留。新工具增强的是发现与输入，不是要求清空 alias。

让历史跨终端更可用

在 Bash 中启用 shopt -s histappend，并在 shell 退出时追加历史；这样 fzf 可搜到更多会话的命令。

远程机器采用降级配置

用本卡的 command -v 与 -r 检查包裹钩子。工具未安装时跳过，不让 SSH 登录被配置错误打断。

把“查路径”变成一次 z 搜索

遇到“那个项目在哪”，先输入 z 关键词。若没命中，再用 find 或 fd；不要先翻 shell 历史。

五个反模式（新手最常犯）：① 把三件工具当「插件合集」一口气全配满——先跑通 fzf+zoxide 再叠 ble.sh；② 在 .bashrc 里把 fzf 的钩子写在 case $- in *i*) 之前——非交互 shell（scp、cron）会执行到并可能报错；③ 用 alias cd=z 却不知道 cd .. 语义已变——zoxide 处理了大部分兼容，但 cd - 与 dirstack 行为需自测；④ 在 root 与普通用户之间共享同一份 .bashrc——权限差异会让补全缓存与数据库交叉出错；⑤ 出问题先重装——九成问题是 .bashrc 没重新加载或加载顺序错，先走 §06 排障树。
06

常见问题与排障：先确认加载，再怀疑工具

绝大多数“没生效”不是工具坏了，而是 .bashrc 没有在当前交互 Bash 中被读取。

Q1 · Ctrl-R 还是旧的搜索？

确认 fzf 钩子是否已加载

新开终端，运行 type fzf，再检查 grep -n 'fzf --bash' ~/.bashrc。确保该段位于非交互 shell 的 return 之后。

Q2 · 输入 z 提示 command not found？

检查 zoxide 初始化

运行 zoxide --version，并确认 eval "$(zoxide init bash)" 在 .bashrc。改完后新开 Bash 或 source 一次。

Q3 · ble-attach: command not found？

通常是路径写错或 source 失败

确认 ~/.local/share/blesh/ble.sh 可读，再确认 source 使用的是这个真实路径。构建失败时先安装 gawk，再重新执行 make install。

Q4 · 我不想用 ble.sh？

直接删除/注释 ble.sh 三行

保留 fzf 与 zoxide 的两个 block 即可。它们独立运行，不依赖 ble.sh；这是最小、稳定、低摩擦的增强方案。

Q5 · SSH 到服务器上体验卡顿？

ble.sh 在高延迟链路上的取舍

ble.sh 的实时高亮与自动建议需要持续重绘，网络延迟大时输入会有「跟手延迟」。官方提供了性能开关：bleopt complete_auto_delay 调大自动补全触发延迟，或直接在远程机器只用 fzf + zoxide 两个 block（本卡 §03 的存在性检查会自动跳过 ble.sh）。低配机器同理：ble.sh 官方建议 Bash 4.0+ 且终端支持 UTF-8，老环境不必强上。

Q6 · 装完 ble.sh 提示符变丑/变了？

ble.sh 不动你的 PS1

ble.sh 明确不接管 prompt 配置（PS1/prompt/alias 均保持你自己的设置）。若外观变化，通常是 --attach 时机与你的 prompt 主题（如 starship）冲突：把你的 prompt 初始化放在 ble-attach 之后，或按官方「可靠装载法」把 source 放 .bashrc 最顶、ble-attach 放最底（§09 加载顺序铁律）。

Q7 · zoxide 学错了目录 / 分数乱了？

查询、修正与排除

zoxide query 看数据库、zoxide query -s 关键词 带分排序预览、zoxide remove 路径 删掉单条（0.9 起无匹配会报错而非静默）、zoxide add 手工补录。整个库就是 database.zo 一个文件，删掉即重置，z 会从零重新学习。0.10 起 z 尊重 $CDPATH，配置过 CDPATH 的环境行为会更符合直觉。

Q8 · Ctrl-R 里出现乱码或重复行？

编码与历史文件问题

三查：① 终端编码必须是 UTF-8（ble.sh 非 ASCII 仅支持 UTF-8，locale 确认 LANG 带 UTF-8）；② histappend 打开后多个终端并发写 history，偶发交叉行属正常，history -a/-n 手动同步；③ history 文件被 GC 脚本截断过会有断行——fc -l -50 看 Bash 自己读到的最后 50 条是否正常，再判断是 fzf 读坏了还是文件本身坏了。

以下数据为 2026-09-30 从 GitHub API 与官方 Release 现场复核的快照；安装命令不受版本影响。

FZF · JUNEGUNN/FZF

v0.74.4 83,331★

MIT，Go 编写，发布节奏极快（几乎每两周一个补丁版）。本卡 2026-07 写作时主线还在 0.6x：当时 0.66 引入的 raw 模式值得单独一说——历史列表不再过滤掉不匹配项，而是把它们压暗留在原位，上下文一目了然；ALT-R 随时开关，CTRL-N/CTRL-P 在匹配项之间跳。0.70 把过滤性能提升 1.3–1.9 倍（官方基准：500 万行 1.65 秒 → 0.84 秒）。更早的关键节点：0.48 起把 shell 集成脚本直接编进二进制，eval "$(fzf --bash)" 一行搞定，彻底告别「脚本和二进制版本不匹配」这个老坑。

ZOXIDE · AJEETDSOUZA/ZOXIDE

v0.10.0 39,801★

MIT，Rust 编写，2026-07-04 发布的 0.10.0 就是当前最新稳定版（本卡写作时即此版）。这一版补了几件与 Bash 用户直接相关的事：z 开始尊重 $CDPATH；zoxide import 支持从 atuin 导入历史目录、自动识别数据库文件；关闭 history（set +o history）的 shell 不再写入数据库；riscv64 Linux 有了官方构建。往回数：0.9.9 修了 $PROMPT_COMMAND 数组与 $PIPESTATUS 被破坏的问题；0.9.8 给 Bash 带来 Space-Tab 交互补全（输入 z foo 后按空格再 Tab，出候选菜单，选中即 cd，且与 ble.sh 兼容）。

BLE.SH · AKINOMYOGA/BLE.SH

0.4 devel 4,787★

BSD-3-Clause，纯 Bash 写成的行编辑器（无 C 编译、无二进制），替换默认的 GNU Readline。正式 release 停在 0.3.4（2019），devel 线 0.4 持续活跃至 2026-09——本卡用的就是 devel 安装路径，这也是 AUR/NixOS/Guix 包标记 devel 的原因。项目从 2013 年作者在自家 bashrc 里的小实验长成今天这样：0.1 语法高亮（2015）→ 0.2 vim 模式（2018）→ 0.3 增强补全（2019）。支持 Bash 3.0+，官方推荐 4.0+；非 ASCII 仅支持 UTF-8。

08

ble.sh 深度功能：装完之后值得打开的六件事

以下功能均出自 ble.sh 官方 README 与 Wiki（Manual §3/§4/§7），配置写进 ~/.blerc（或 ${XDG_CONFIG_HOME:-$HOME/.config}/blesh/init.sh）。

AUTO-COMPLETE · 自动建议

像 fish 一样「猜你下一个词」

Bash 4.0+ 可开 auto-complete：输入时自动在光标后以灰色显示最可能的补全，按 S-RET 整句接受（行尾也可用 → / C-f），M-→ 只接受第一个词，C-RET 接受并立即执行。这是「把 zsh-autosuggestions 的体验带回 Bash」的核心功能。

MENU-FILTER · 边打边筛

菜单补全 + 实时过滤合体

Bash 4.0+ 的 menu-filter 把候选列表和增量过滤合到一起：按 Tab 弹出菜单后继续输入，列表实时收窄，TAB/S-TAB 与方向键在候选间移动。另有 menu-complete（连按 Tab 逐个吞掉候选）与 dabbrev（从 buffer 里动态缩写展开）。

SABBREV · 静态缩写

把长命令变成两个字母

在 blerc 里注册 ble-sabbrev 'L'='| less' 后，输入 L 再按空格即展开为 | less。官方推荐用 \L 这类「反斜杠 + 字母」命名避免撞上真实单词；~mybin 形式的缩写还能斜杠展开，近似 zsh 的 named directories。

VIM MODE · 编辑模式

set -o vi 的完全体

如果你用 vi 编辑模式，ble.sh 不只是兼容：补齐了 char/line/block 可视模式、replace、command、operator-pending 等模式，支持 operator、text object、寄存器、键盘宏、marks，还提供 vim-surround 选项。Emacs 模式用户则获得 MULTILINE 多行编辑：命令串里含换行时自动进入，C-v C-j 插入真换行，C-j 执行。

HISTORY SHARE · 实时历史

多终端共享同一份历史

bleopt history_share 系列设置让多个终端窗口实时共享历史——比 histappend + 手动 sync 更进一步，fzf 的 Ctrl-R 也能立刻搜到别的窗口刚敲的命令。其他同场加映：状态栏（status line）、右侧提示符（rps1）、transient prompt、xterm 标题自动设置。

SYNTAX · 语法分析级高亮

复杂结构也标得对

与逐字符匹配的 zsh-syntax-highlighting 不同，ble.sh 做真正的语法分析：嵌套命令替换、多重 heredoc 这类复杂结构都能正确高亮，颜色与样式全部可配置。这正是本卡「提交前看一眼颜色」技巧可靠的原因。

官方立场：ble.sh 不提供具体的 prompt、alias、函数配置——它是底层设施，可以与 bash-it、oh-my-bash 等任意 Bash 配置共存。
09

三件套协同：别让它们互相打架

fzf 与 ble.sh 都要接管按键，直接叠加会冲突——官方集成方案各只有一段配置。

CONFLICT · 为什么会冲突

两个都改 Ctrl-R / Ctrl-T，谁赢？

ble.sh 替换了整个行编辑器（Readline），fzf 的 shell 集成则是往 Readline 里挂键位——两者各自绑定 Ctrl-R / Ctrl-T / ALT-C 时后加载的可能失效或行为怪异。ble.sh README 明确警告：想同时用 fzf，必须改用 blesh-contrib 的 fzf integration，不要用 fzf 自带的 fzf --bash 钩子。

FIX · 官方集成写法

blerc 里换成 ble-import

# blerc —— 替代 .bashrc 里的 fzf --bash # bash_completion 先于 fzf 补全加载（与是否用 ble.sh 无关） source /etc/profile.d/bash_completion.sh ble-import -d integration/fzf-completion ble-import -d integration/fzf-key-bindings

-d 表示延迟到提示符出现后在后台加载，启动不卡顿。要追加自己的 fzf 配置时不能直接写在后面（还没加载完），官方给了四条路：去掉 -d（最简单，启动变慢）、追加设置也用 ble-import -d、用 ble/util/idle.push、或用 ble-import -C 挂回调。

ZOXIDE × BLE.SH

Space-Tab 目录候选菜单

zoxide 0.9.8 起官方支持「completions now work with ble.sh」：输入 z proj 后按 SPACE+TAB，fzf 风格的候选菜单就地弹出，回车选中即 cd。这把本卡「zi 处理同名目录」的技巧升级成了不用离开当前行的顺手动。

LOAD ORDER · 加载顺序铁律

.bashrc 里的先后次序

稳定组合是：① bash-completion 初始化 → ② fzf/zoxide 初始化 → ③ ble.sh 在 .bashrc 顶部 source（--attach=none）、末尾 ble-attach。ble.sh 官方的「更可靠装载法」是顶部一行 [[ $- == *i* ]] && source -- ~/.local/share/blesh/ble.sh --attach=none，底部一行 [[ ! ${BLE_VERSION-} ]] || ble-attach——中间照常写你的 alias 与 PATH。本卡为了改动最小用的 --noattach + 立即 attach 等价写法，同样有效。

10

更新、卸载与数据迁移

所有操作只影响用户目录；卸载后你的 Bash 回到原始状态，脚本与 alias 一律不受影响。

UPDATE

三件工具各自怎么升级

fzf / zoxide：apt 装的跟系统更新走；追求新版可从 GitHub Releases 下载对应二进制放进 ~/.local/bin（PATH 优先于 /usr/bin 时生效）。ble.sh 自带更新器：ble.sh 会话里直接跑 ble-update，或会话外 bash ~/.local/share/blesh/ble.sh --update。

UNINSTALL

干净退场三步

# 1) 注释/删除 .bashrc 里三个 block（本卡 §03） # 2) 删安装目录 rm -rf ~/.local/share/blesh ~/.local/src/blesh # 3) fzf/zoxide 如不再需要 sudo apt-get purge fzf zoxide

数据层面：zoxide 的目录库在 ~/.local/share/zoxide/database.zo，fzf 无独立数据（读 shell history），ble.sh 的历史增强数据在其数据目录——删目录即清干净。

MIGRATE

换机器：把「肌肉记忆」带过去

三样东西可迁移：.bashrc 的三个 block（本卡 §03 原文）、zoxide 数据库（复制 database.zo，或在新机 zoxide import 从 z/autojump/atuin 导入——0.10.0 起自动识别数据库格式）、blerc（自定义按键/缩写随文件走）。新机器先装工具、再放配置、最后 source 或重开终端。

风险边界：本卡所有命令均在 Ubuntu/Debian 系验证；CentOS/Fedora 包名不同（fzf/zoxide 同名，构建组换 make gawk gcc）；macOS 用 Homebrew（brew install fzf zoxide）且无需 gawk 步骤的等价构建流程（ble.sh 用 brew install blesh 之外的 nightly 安装同本卡）。远程/受限服务器只需 .bashrc 存在性检查正确，三件工具缺失不报错。

概念课：给初学者的四个「为什么」

理解设计动机，排障时才有方向感；这一节不新增任何操作。

WHY 1

为什么「不换 Shell」是对的起点？

zsh + oh-my-zsh 是更常见的组合方案，但迁移成本真实存在：脚本首行 shebang、$BASH_VERSION 判断、公司服务器只有 bash、已有 alias 体系全部要重验。本卡的三件工具都运行在 Bash 之内：fzf 是独立二进制、zoxide 是独立二进制、ble.sh 是纯 Bash 脚本——它们增强的是「你和 Bash 打交道的界面」，Bash 本身一行没改。#!/bin/bash 的脚本照跑，生产环境无感。

WHY 2

为什么补全要「延迟加载」？

Bash 每次开新终端都要把 .bashrc 从头执行一遍。fzf 的补全脚本、zoxide 的 init、ble.sh 的初始化加起来若在启动时同步执行，开新标签会明显变慢。三家的解法一致：先让提示符出来，再在后台补装重型部件——ble.sh 用 ble-import -d，fzf 的补全本身轻量，zoxide 默认用 PWD hook 只在切目录时计分。这也是为什么「改了配置没生效」时要先怀疑有没有真的重开 shell。

WHY 3

为什么 zoxide 比 cd 快？

cd 是「你告诉它路径」，zoxide 是「它记住你常去的路径」。每个目录有 frecency 分数（frequency + recency），z proj 实际是「在所有去过的目录里找名字像 proj 的、分数最高的那个」。由此推导出使用守则：z 没命中不是 bug，可能是你从没去过；同名歧义用 zi 交给 fzf 选择；z - 回上一个目录（等价 cd -）；不想让它学的目录放进 $_ZO_EXCLUDE_DIRS（支持通配）。

WHY 4

为什么快捷键冲突要「二选一接管」？

终端按键最终由「行编辑器」解释。默认是 Readline；ble.sh 装上后整个替换成自己；fzf 的快捷键则要挂在这两者之一上。所以 Ctrl-R 只能有一个主人——本卡 §09 的集成方案本质是把快捷键挂载点从 Readline 挪到 ble.sh 的机制里，由 ble.sh 在合适的时机调起 fzf。理解了这一点，「为什么直接叠加会失效」「为什么顺序重要」就不再是需要死记的规则。

fzf 单项深化：Ctrl-R 之外的九个用法

安装 fzf 后立即可用（无需 ble.sh）；示例均可在任意目录直接粘贴运行。

FILE · 文件模糊搜索

Ctrl-T：把 find 变成摆设

命令行任意位置按 Ctrl-T（fzf 默认键位，需 eval "$(fzf --bash)" 已加载），弹出当前目录递归文件列表，选中后路径回填到光标处。找 src/utils/date.ts 只需输入 date util 两个片段。

CD · 目录级搜索

ALT-C：没有 zoxide 时的跳转

ALT-C 列出所有子目录供模糊选择并 cd 过去。有了 zoxide 后此键用于「去没去过的地方」——zoxide 只记得访问过的目录，ALT-C 全量枚举。

PIPE · 管道即筛选器

任何列表都能 fzf

git branch -a | fzf # 挑分支 ps aux | fzf # 挑进程 git log --oneline | fzf # 挑 commit

fzf 从 stdin 读列表、把选中行写到 stdout——它是通用交互过滤器，不限于历史和文件。

PREVIEW · 预览窗

选中前先看内容

fzf --preview 'cat {}' git log --oneline | fzf --preview 'git show {1}'

--preview 右侧半屏实时渲染 {}（当前行）指向的内容；挑 commit 时 {1} 是第一列（hash）。

OUTPUT · 拿到结果之后

多选与占位符

vim $(fzf -m) # -m 多选，tab 勾选 fzf --print-source # 0.72+ 新输出模式

命令替换 $(fzf) 是最常见的消费方式；-m 允许勾选多行一起输出。

TMUX · 弹出窗

--popup：不离开当前布局

tmux 用户可给全局加 FZF_DEFAULT_OPTS="--popup"。tmux 3.7+ 起浮动面板不抢主布局、可用鼠标拖拽缩放、可全屏、可开 copy-mode——fzf 0.74 release 的主打特性。

zoxide 单项深化：把数据库养好

zoxide 的体验 = 算法（frecency）+ 数据（你访问过的目录）。这一节讲怎么让它更聪明。

HOOK · 记分时机

prompt 还是 pwd？

zoxide init --hook pwd bash（默认）在每次切目录时给当前目录加分；--hook prompt 则在每次出提示符时加分——你停留越久的目录分越高。有「挂着不动的长会话」习惯选 prompt，普通用户默认即可。

CMD · 改名与替换 cd

--cmd 的三种玩法

--cmd j：命令变成 j/ji（z.lua 习惯）；--cmd cd：直接替换 cd，肌肉记忆零迁移——zoxide 已处理了 fish 里 alias cd=z 死循环这类兼容问题，Bash 侧 0.10 起还尊重 CDPATH。保守派用默认 z，激进派直接替换 cd。

DATA · 库维护

四个日常命令

zoxide query # 看全部记录 zoxide query -s proj # 带分数预览 zoxide remove /x/y # 删单条 zoxide add /x/y # 手工补录

库文件 ~/.local/share/zoxide/database.zo，纯文本可备份。0.10 的 import 能从 z/autojump/atuin 自动识别并导入，还能跳过 $_ZO_EXCLUDE_DIRS 命中的目录。

与 fzf 的关系：zi 与 Space-Tab 都要调 fzf——装了 fzf 的 zoxide 才是完整体；没装 fzf 时 zi 退化为 zoxide 内置的简易选择。
16

ble.sh 单项深化：blerc 精选配置十则

全部写进 ~/.blerc（首次使用可从仓库 blerc.template 起步，注意要用与你版本对应的模板）。逐条独立，按需取用。

01 · AUTOCOMPLETE

打开自动建议

bleopt complete_auto_complete 1 bleopt complete_auto_delay 100 # 触发延迟 ms，默认较激进

Bash 4.0+ 生效。打字跟手但嫌吵就调大 delay；S-RET 接受，M-→ 只要第一个词。

02 · HIGHLIGHT

调整错误色/高亮风格

ble-face -g syntax_error fg=red,bg=default ble-face -g command_builtin fg=blue

ble-face 管理 200+ 命名面（face），错误、字符串、选项、变量各归各类；ble-color-listface 可列出全部。

03 · SABBREV

常用管道缩写

ble-sabbrev '\L'='| less' ble-sabbrev '\G'='| grep ' ble-sabbrev '\J'='| jq .'

空格触发展开；反斜杠前缀避免撞词。展开是纯文本替换，不产生历史噪音。

04 · HISTORY

历史条数与去重

bleopt history_limit_length 100000 bleopt history_default_limit 50000

配合 .bashrc 里的 shopt -s histappend 与 HISTSIZE/HISTFILESIZE；ble.sh 的 history share 让多窗口实时共享，fzf Ctrl-R 立即可搜。

05 · CURSOR

光标形状随模式切换

bleopt keymap_vi_mode_update_terminal 1 ble-face -g cursor_line fg=green

vi 模式用户必备：插入/普通/可视模式光标变形状，一眼知道当前模式。

06 · STATUS LINE

底部状态栏

bleopt prompt_status_line 1

vi 模式指示、补全菜单提示等显示在终端底部一行，不占命令区。同族的 prompt_rps1（右侧提示符）与 prompt_ps1_transient（历史命令行折叠成精简 PS1）都在 Wiki §4。

07 · MULTILINE

多行编辑友好化

C-v C-j 插入真换行；语法未闭合时回车自动续行（依赖 shopt -s cmdhist，Bash 默认已开）。写 here-doc、长管道时不用再拼 \\。

08 · XTERM TITLE

窗口标题自动显示当前命令

bleopt prompt_xterm_title 1

tmux/终端窗口列表里直接看到正在输入的命令，多窗口工作流定位利器。

09 · IGNORE EOF

防误触 Ctrl-D 退出

set -o ignoreeof（Bash 原生，ble.sh 尊重之）——交互 shell 忽略 Ctrl-D 退出，必须 exit。远程生产机建议配上，手滑少一次断线。

10 · DEBUG

ble.sh 自身出问题时

ble-debug dump # 导出诊断信息 ble-util clear # 重绘整个画面

仍异常就临时注释 .bashrc 的 ble.sh 三行二分定位（§03 的存在性检查保证注释后无残留错误）。issue 请附 echo $BLE_VERSION 输出。

场景扩展：远程服务器、Winged 迁移与替代品全景

三个高频追问：公司服务器能装吗？换 Mac 怎么办？还有别的同类工具吗？

REMOTE · 无 root 服务器

没有 sudo 怎么装？

三件工具全部支持用户级安装：fzf 从 GitHub Releases 下载 fzf-* 二进制放进 ~/.local/bin；zoxide 官方安装脚本 curl -sSf https://zoxide.xyz/install | sh（官方短链，等价于 GitHub install.sh）默认装到用户目录；ble.sh 本就装 ~/.local/share/blesh。全流程不需要 root——这正是本卡所有配置都包 command -v 检查的意义：同一份 .bashrc 在有工具的机器上全速，在干净服务器上安静降级。

PLATFORM · 平台差异

macOS 与 WSL 注意点

macOS：brew install fzf zoxide 即用；ble.sh 走 nightly 安装或 brew install blesh --HEAD；默认 Bash 是 3.2（2007 年版本），auto-complete/menu-filter 需要 4.0+，brew install bash 后在 iTerm/Terminal 里把默认 shell 指到 Homebrew 版。注意 macOS 自带 BSD 工具链，ble.sh 构建需要 GNU make 与 gawk。WSL：与原生 Linux 一致，注意 Windows Terminal 的 UTF-8 与真彩色支持已足够。

ALTERNATIVES · 同类全景

知道这些，选型不迷路

fzf 同类：skim（Rust 版 fzf）、percol；zoxide 同类：z.lua、autojump、fasd——zoxide 0.10 的 import 可直接从后两者迁库；ble.sh 同类：bash-preexec + zsh-syntax-highlighting 移植组合只覆盖高亮一角，纯 Bash 实现的完整行编辑器目前只有 ble.sh。若愿意换 Shell：zsh 有 oh-my-zsh + 插件全家桶，fish 开箱即用但语法不兼容 POSIX——即本卡「不换 Shell」路线的对照面。

合规边界：公司服务器上安装用户级二进制前请确认安全政策是否允许；本卡方案不修改系统目录、不提权、不动全局配置，但最终解释权在你们的运维。

下一步：装完三件套之后，值得认识的两个邻居

本卡不展开安装，只说清它们与三件套的关系，避免选型纠结。

ATUIN · 历史数据库化

Ctrl-R 的「重装求解」派

atuin 用 SQLite 保存全部历史（带目录、退出码、时长），支持端到端同步与全文搜索。与 fzf Ctrl-R 的关系：可以共存——atuin 自带 atuin search 的交互界面接管 Ctrl-R，也有人保留 fzf 只用 atuin 做长期归档。zoxide 0.10 已支持 zoxide import 直接吃 atuin 的目录记录，两套体系数据互通。

STARSHIP · 提示符

与 ble.sh 搭配的姿势

starship 是 Rust 写的跨 Shell 提示符，与 ble.sh 互不冲突（ble.sh 不管 PS1）。顺序上让 starship 的 init 在 ble-attach 之后执行即可。ble.sh 的 transient prompt（历史行折叠成精简样式）与 starship 的两行提示符是常见组合。

EQUIPMENT · 加分小件

顺手可配的三个 Bash 原生项

shopt -s histappend # 追加而非覆盖历史 shopt -s checkwinsize # 命令后修正窗口尺寸 bind '"\e[1;5C": forward-word' # Ctrl-→ 按词右移

这三个与三件套正交，纯 Bash 内建，任何环境可用。

ROADMAP · 学习路线图

四周熟练路径

第 1 周：只装 fzf + zoxide，刻意用 Ctrl-R 与 z 替代旧习惯。第 2 周：加 ble.sh，开语法高亮与菜单补全，开始用 Space-Tab。第 3 周：blerc 配 auto-complete + sabbrev，把高频管道变缩写。第 4 周：按需取 §09 集成、§14–16 深化项；此时你已超过 90% 的 Bash 用户。
