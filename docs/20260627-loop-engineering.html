02 · 设计理念

从临时 prompt 到自动化循环

临
临时 prompt 模式
每次手动写 prompt → 执行 → 看结果 → 再写。效率低，不可复用，结果不稳定。
→
Loop Engineering
把任务封装为循环系统：触发 → 执行 → 验证 → 记忆 → 再触发。全程自动运行。
稳
渐进式落地
L1 纯报告 → L2 半自动 → L3 全自动。从低风险场景起步，逐步提升自动化程度。
03 · CLI 工具集

三个实用 CLI，贯穿循环全周期

每个工具对应循环工程的一个环节，开箱即用。

loop-audit
给项目打分，判断它是否适合上循环。分析代码结构、工具链、Agent 边界，输出可行性报告。
loop-init
一键搭建 Loop Engineering 项目骨架。包含目录结构、技能配置、MCP 集成起点。
loop-cost
计算 Token 花销。追踪每次循环调用的模型消耗，估算成本，优化循环效率。
04 · 生产模式

7 个生产模式，L1 → L3 渐进升级

每个模式带启动模板，建议从 L1 起步确认循环稳定，再升级到更高自动化级别。

L1
纯报告模式
Agent 生成分析报告，人工审核后决定下一步。最低风险，适合评估循环效果。
L2
半自动模式
Agent 执行 + 自动验证通过后自动推进；人工介入点保留，兼顾效率与安全。
L3
全自动模式
全流程无人值守。适合高置信场景，配合 Token 成本监控和熔断机制。
