html-explainer

给 Claude Code、Codex 等 Agent 一句话主题，它会把调研、解说词、配音、硬字幕、HTML 画面、逐帧渲染、QC 和多画幅封面串成一条本地流水线。关键不是“能生成视频”，而是每一帧都能复现、每一句都能对齐。

MIT23 种画面风格默认免 API KeyPython 3.9+Node 18+HTML → MP4
先判断：它是不是你的工具
不是录屏器，也不是拖拽编辑器。

它把画面写成可 seek 的 HTML/CSS/GSAP，再按字级语音时间逐帧截图。适合知识讲解和批量生产，不适合真人口播或实拍剪辑。

适合文档、教程、方法论、科普、产品解释
不适合实拍、复刻现有视频、图形化拖拽剪辑
改一句解说词，不再意味着手工重新对齐整条视频。字幕块原文既是观众看到的文字，也是动画的时间锚点；TTS 更新后，时间轴与场景节拍可以一起重排。

DETERMINISTIC RENDERING

为什么它不录屏：把浏览器变成“可定位的摄影机”

02
Agent 写场景

HTML/CSS/GSAP 描述画面与动画，场景遵守字幕带、字体、颜色和 seek 契约。

→
定位到第 t 秒

tl.pause(t, false) 定位 GSAP；再同步 document.getAnimations().currentTime，等待两个动画帧后截图。

→
PNG/JPEG → MP4

每个全局帧号有确定画面；ffmpeg 合成 H.264 + AAC，QC 可固定抽查任意帧。

可验证收益：同一个第 1204 帧再次渲染应得到相同画面；单个场景可以独立重渲；字体晚到、动画抢跑和录屏引导期这类错误被结构性消除。
允许

可 seek 时间轴

GSAP timeline、渲染器可设置 currentTime 的 CSS animation、纯 transform 数字卷轴。

拒绝

墙钟驱动动画

setInterval、靠 requestAnimationFrame 累加计数、CSS transition 入场会被 lint 拒绝。

代价

画面必须写成代码

没有拖拽画布；换来的是可复现、可审计、可局部修复的生产链。

TEXT-ANCHORED BEATS

B() / Be()：让动画跟“被念出的文字”对齐

03

配音引擎先给出每个字或词的真实时间边界。subs.py 再为每个场景生成 beats.js：B('块文本') 是该字幕块开始被念出的时刻，Be('块文本') 是结束时刻。

tl.fromTo('.card',
  { y: 60, autoAlpha: 0 },
  { y: 0, autoAlpha: 1, duration: .7 },
  B('右边卡片'));

tl.fromTo('.verdict',
  { scale: .8 },
  { scale: 1, duration: .6 },
  B('结论句') + .2);
EDITING

改文案后的正确动作

重跑 TTS → timeline → subtitles。字级边界、全局时间轴和 beats.js 一起刷新；保留有效文本锚点的场景无需手动改帧号。

FAIL LOUD

禁止数字兜底

B('x') || 3.2 会把“锚点查不到”藏在过期数字后面。项目选择构建失败，也不接受一条悄悄错时的视频。

TWO CLOCKS

两级时钟

帧长取 MP3 容器时长维持音画同步；末块字幕按语音真实结束时间收尾，两者不能混用。

REAL BOUNDARY

不按字数插值

中文两个同字数短语的发音时长可能差数倍；edge 读取 WordBoundary，火山读取 sentence.words[]。

MULTI-ASPECT COVERS

封面必须独立重排：从横版硬裁 3:4 会丢掉 57.8% 宽度

07
16:9

1920×1080

信息流与播放页。适合左右并置；钩子通常位于左下，四边留出至少 96px。

3:4

1440×1080

主页栅格。主视觉与标题重新做上下堆叠，四边建议至少 110px，不是从横版居中裁切。

9:16

1080×1920 · 可选

竖屏投放。禁止左右两栏；顶部至少 180px、底部至少 160px，让开平台 UI 层。

为什么不能裁：1920px 宽的 16:9 封面居中裁成 3:4，只剩 810px，横向内容损失 57.8%。因此三个画幅共享视觉基因，但构型、字号、钩子位置和留白分别计算。check_cover.mjs 会在动画终态检查边距、最大文字、孤字、行宽、越界以及 9:16 两栏违规。
QUALITY GATES

五层门禁：把“看起来正常、实际上错了”的静默失败挡在交付前

08
01静态契约

查外部字体/CDN、硬编码色值、墙钟动画、CSS transition 入场、缺失 window.__tl、非法 B() 兜底与字幕禁区。

02终态几何

查出画、遮挡、文字重叠、字幕带侵入、安全边违规和疑似未对齐；这是纯文本 lint 看不见的一层。

03帧完整性

合成前逐号核对帧文件，缺帧直接点名场景并阻断 mux；ffmpeg 使用 -xerror，不接受静默截流。

04成片 QC

核对视频流真实帧数、layout 预期时长、响度、漂移和分布式抽帧；只看容器 Duration 不算通过。

05封面几何

seek 到终态后检查边距、钩子字号、行宽、孤字、越界，以及 9:16 是否误用左右两栏。

v1.4.2 · 小数点防止口播“2.4%”在屏幕文本、字幕或节拍归一化中静默变成“24%”。
v1.4.1 · 缺帧修复场景边界浮点舍入导致的单帧空洞：容器时长完整，但视频流在缺口处提前停止。
v1.4.0 · 封面加入终态几何实测器与可选 9:16 独立版式，不再把肉眼当唯一门禁。
RENDER PERFORMANCE

照片型画面慢在哪：瓶颈是浏览器内串行 PNG 编码，不是 seek

09
默认 PNG

对纯 CSS 图形很快；对满幅照片，项目测得约 582ms/帧，编码占单帧时间约 96%。提高并发没有显著改善总吞吐。

node render_video.mjs .
~4.4×

--png-fast 使用 CDP optimizeForSpeed。项目测量中逐像素无损，代价是中间帧体积增加。

--png-fast
~13×

照片密集场景可用 JPEG q95；再用 CRF 与 preset 独立控制最终视频编码，不把草稿帧格式和成片质量绑死。

--jpeg --jpeg-quality 95 --crf 18 --preset medium
磁盘预算：默认 PNG 中间帧每条成片约需 2GB；合成完成并确认无需局部修复后可以删除。性能数字来自项目自己的实测，不应外推为所有机器的固定速度。

BOUNDARIES & DECISION

采用前要接受的边界：可复现来自约束，而不是魔法

11
A
画面是代码

它没有可视化拖拽编辑器。适合愿意让 Agent 维护 HTML/CSS/GSAP 的团队，不适合依赖时间线 GUI 的剪辑流程。

B
动画必须可 seek

结构化限制让逐帧结果可复现；如果创作方式依赖实时物理、随机时钟或外部网页状态，就需要重写。

C
默认离线不等于绝对无网络

核心渲染与 edge-tts 路径免密钥；首次安装缺失依赖、使用 edge 在线语音或火山服务仍可能需要网络。

D
项目还很年轻

公开仓库创建于 2026-09-21；81 stars、13 forks 为 2026-09-28 快照，不能当作长期稳定度证明。

BOTTOM LINE

什么时候值得试

你已经在用 Claude Code、Codex 等 Agent；内容以知识、教程、文档或方法论为主；希望把配音、字幕、画面、封面和 QC 变成可重复流水线；并且愿意用代码换取帧级可复现性。

什么时候直接跳过

主要素材是真人、实拍与复杂剪辑；需要所见即所得拖拽；目标是复刻某条现有视频；或者明确需要 React/Remotion 组件动画作为核心创作模型。
