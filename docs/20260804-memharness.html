01
THE PROBLEM

为什么"回放记忆"会伤害 Agent？

现有记忆增强 Agent 把检索到的经验当作静态记录，忽略了过去与当前状态的差距。

问题

任务相似 ≠ 当前状态相同

找到相似经验后直接塞进上下文——但存储经验的抽象性与决策时的具体状态之间存在巨大鸿沟。

后果

负迁移（Negative Transfer）

旧经验有时反而把决策带偏。论文实验证明：在未见环境中，直接回放原始记忆仅达 76.3%，低于无记忆基线。

人类启发

人类不会原样回忆

人类很少原封不动地回忆过去——会重组和适应检索到的记忆以适应现在的情境。MemHarness 的灵感来源。

论文核心主张：

大多数现有记忆增强 Agent 使用的"回放"范式忽视了存储经验与决策时具体状态之间的差距。MemHarness 提出"重建"范式：让 Agent 主动根据当前上下文重建检索到的经验。

02
THE METHOD

MemHarness 三步重建流程

统一策略模型在每个决策步，对检索到的经验进行批判性重建，生成基于当前状态的行动指导。

STEP 1 — Retrieve
根据当前上下文，从记忆库中检索相关过去经验
STEP 2 — Judge & Reconstruct
将过去经验与当前状态结合，判断哪些有用、哪些需要修改或丢弃
STEP 3 — Act
基于重建后的上下文指导生成行动，而非原样回放
MemHarness 决策流程：

[当前状态] ──→ [检索记忆] ──→ [重建引擎]
                                         │
                                    有用 → 保留
                                    修改 → 适配当前上下文
                                    无关 → 丢弃
                                         │
                                    [上下文引导] ──→ [Agent 行动]

训练信号：GRPO + Task Reward（无需额外标注）
关键设计GRPO End-to-End

端到端训练，无需额外标注

重建能力通过端到端的 GRPO 训练自然涌现。重建目标不仅防止负迁移，还在训练中充当隐式引导，从根本上提升 Agent 的内在推理能力。

04
IMPLICATIONS

关键启示

MemHarness 把 Agent 记忆从"保存过去"升级为"基于当下重建过去"。

范式转变

从"保存过去"到"重建过去"

真正可靠的记忆系统需要知道：哪些经验值得保留、哪些需要重写、哪些应该及时遗忘。这是记忆增强 Agent 的范式转变。

无额外成本

隐式引导，自然涌现

重建能力通过 GRPO 端到端训练自然涌现，无需额外的标注成本。重建目标在训练中充当隐式引导。

鲁棒性

分布外泛化

在未见环境中，MemHarness 比原始记忆回放高出 9.6pp。证明错误使用记忆确实可能比没有记忆更差。

轻量化

基于 Qwen2.5-7B

在 7B 参数规模的模型上验证，无需超大规模模型。说明记忆重建能力可在可部署规模上实现。

05
NOTES

注意事项

局限性

基准范围有限

仅在 ALFWorld 和 WebShop 两个基准上评估，未覆盖更多类型的 Agent 任务（如对话、代码生成）。

工程挑战

记忆存储成本

需要维护检索记忆库并执行检索-重建流程，相比无记忆基线有额外的计算和存储开销。

未验证场景

长期记忆

论文关注单会话内的经验重建；跨会话、跨天的长期记忆管理未涉及。
