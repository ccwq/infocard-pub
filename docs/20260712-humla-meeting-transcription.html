MACOS · LOCAL · MIT

Humla
本地会议转写，音频永远不出电脑

macOS 本地会议笔记应用（MIT）。录音、转写、说话人区分全在本地；也能接 OpenAI/Speechmatics 云端服务，由你选择。笔记与 AI 纪要左右对照，谁说了什么一清二楚。

本地转写 macOS 13+ MIT Tauri 2 + Rust + Swift Whisper

核心原则：你的音频和你的数据留在你的机器上

隐私优先

音频永远不离开电脑

除非你明确选择发送到的目的地（转写/LLM 提供商，或你自己配置的 Ollama），否则 Humla 不会把任何内容发送到网络。

Granola 启发

笔记 + 转写稿 → 结构化纪要

你开会时随手记笔记，Humla 把笔记的意图和转写稿的事实合成为一份结构化纪要——不是纯 AI 生成，而是人机协作的产物。

两路录音：麦克风 + 系统声音分开存

开会时同时录两路声音：你的麦克风和电脑里对方的声音分开存储。谁说了什么——从声音源头就区分清楚了，不会混在一起。

Track 1

麦克风

你的声音、你插的嘴、你的提问。

Track 2

系统声音

对方的声音、视频会议另一端的声音。

转写选择：本地 Whisper / Speechmatics / OpenAI

本地 Whisper

完全离线

使用设备上的 Whisper 模型转写，音频和文字都不出电脑。最严格的隐私要求场景。

Speechmatics

云端转写

通过 Speechmatics API 转写，Humla 只发送音频文件。需要 API key。

OpenAI / 其他

云端转写

通过 OpenAI 或其他兼容 API 转写。同样只发送音频，需要配置 key。

说话人区分 + 名字替换

自动区分

说话人 1 / 说话人 2

转写结果自动区分说话人，标注说话人编号。会后可把"说话人 2"改成同事名字，整篇稿子跟着自动更新。

侧边栏编辑

Notes 侧边栏

左侧是 Notes 区域（你的随手笔记），右侧是 Summary 面板（AI 合成结果），两栏对照，事实和意图都不丢。

AI 纪要：笔记意图 × 转写事实

Humla 不会只给你一份纯 AI 生成的无脑摘要。它合成的是：你的笔记（记录你的关注点和意图）和转写稿（记录实际上说了什么）的交叉结果。

Notes 侧边栏

你在开会时随手记的关键点、问题、TODO。Humla 保留你的原始输入，不覆盖。

Summary 面板

右侧 AI 合成区，结合你的笔记意图和转写事实，生成结构化纪要。

Ollama 本地模型：敏感会议全程不出电脑

会议纪要合成可以用 Ollama 本地运行的模型处理。从录音、转写到 AI 总结，整条链路都在本地，不需要任何云端 API key。适合有严格数据合规要求的场景。

转写用 Ollama

如果 Whisper.cpp 已足够，不需要任何云端服务。

总结用 Ollama

敏感会议不想用 OpenAI，可以接 Ollama 本地模型。

Per-note presets：每次会议单独配置

Humla 支持 per-note presets（每次会议单独的配置预设）：转写用哪个模型、总结用哪个 prompt、系统声音和麦克风分别用什么设备，都可以针对每场会议单独配置。

技术栈与安装

架构

Tauri 2 + Rust + Swift

macOS 原生体验 + Rust 后端性能。Apple Silicon 推荐。

安装

下载 dmg 安装包

访问 humla.team 或 GitHub releases 下载最新 macOS 安装包，macOS 13+。

使用边界：GitHub Stars 因 API 限流无法获取实时数据，以 README 和官方 badge 为准。Whisper 本地转写依赖设备算力，Apple Silicon 体验最佳。两路录音功能依赖 macOS 系统音频路由，不同会议软件兼容性需自行测试。
