Codex CUA via MCP：将 Codex 桌面自动化引擎接入 Claude Code

Codex 桌面版内置的 computer-use 引擎可作为本地 MCP server 暴露给 Claude Code，在后台执行点击、拖拽操作，不占用用户光标，token 消耗比通用 CUA 驱动降低 75%。

不是独立的 CUA 驱动，也不是浏览器自动化。
这是一种 macOS 上的本地技巧：Codex 桌面版已在缓存中内置了一个 unified-computer-use 引擎，打包为符合 MCP 规范的 server。只要定位到它的 .mcp.json 并注册为 Claude Code 的用户级 MCP server，Claude Code 即可在后台调用该引擎执行桌面操作——用户继续自由使用鼠标。

将 cua_repl 注册为 Claude Code 的用户级 MCP server，名称固定为 codex-cu。

工作原理

Codex 桌面应用（macOS 版）内置了一个 computer-use 引擎，封装在插件缓存的 openai-bundled/unified-computer-use 目录中。这个引擎以 MCP server 形式运行，通过本地进程通信。

Claude Code 将其注册为用户级 MCP server 后，即可通过标准 MCP 协议调用该引擎，在后台执行点击、拖拽等桌面操作。

Codex 桌面应用 └─ plugins/cache/ └─ openai-bundled/ └─ unified-computer-use/ └─ .mcp.json ← MCP server 描述文件 └─ cua_repl ← 实际启动命令 Claude Code ├─ 注册 codex-cu（MCP user server） └─ 通过 MCP 协议 → 后台调用 cua_repl → 桌面操作执行（无光标占用）

LIMITATION已知的约束与风险

  • 01不支持悬停（hover）事件。依赖悬停触发的界面交互（如悬停菜单、tooltip）暂无法通过此方式完成。
  • 02依赖未文档化的 Codex 内部 bundle 结构。路径 ~/.codex/plugins/cache/openai-bundled/ 属于 Codex 内部缓存，Codex 更新后可能破坏兼容性。

QUICK REFERENCE设置命令与适用场景

设置命令

claude -p 'Set up Codex computer use as an MCP server for you on my Mac. Find the cua_repl entry in ~/.codex/plugins/cache/openai-bundled/unified-computer-use/*/.mcp.json and register it as a user MCP server called codex-cu with the same command, args and env. Then test it by using Calculator in the background to work out 12 * 12.'

复制到 Claude Code CLI（macOS）执行，一次完成定位、提取与注册。

何时使用 / 何时避免

  • ✅ 后台 GUI 委托：打字或浏览时 Claude 执行自动化操作
  • ✅ 标准 Accessibility API CUA 驱动无法完成的拖拽操作
  • ❌ 依赖悬停触发的界面
  • ❌ 生产环境（依赖未文档化内部缓存路径）
