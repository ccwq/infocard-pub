核心问题：AI 总结长 PDF 虎头蛇尾——前几十页准确，越往后越含糊，结尾靠编。

解决方案：逐页读取 PDF，每页提取知识点存入本地 JSON 知识库；每隔 N 页产出阶段性摘要；全书读完后做全局综合——前后文连续积累，不是各管一段。

01
核心问题

长 PDF 总结：AI 为何虎头蛇尾？

大语言模型有上下文窗口限制，一次性灌输整本书的内容会导致前文被遗忘、后续内容与前文脱节，最终总结变成“靠编”。

上下文遗忘幻觉来源

上下文窗口耗尽

超过模型的上下文限制后，前面的关键信息被挤出窗口，AI 只能基于最近的内容“推测”总结，越往后越偏离原意。

信息衰减TOC 干扰

目录与索引噪音

大部头 PDF 通常包含超长目录、索引页，直接灌入会导致大量 token 被无用内容消耗，有效信息密度极低。

无积累无状态

逐次调用无记忆

用 API 逐段调用时，每段都是独立请求，AI 无法建立跨章节的知识关联，只能给出“碎化摘要”。

02
解决方案

逐页积累 × 间隔摘要 × 断点续读

AI-reads-books 的核心设计原则：不要一次读完，要边读边积累；不要一次总结，要分阶段产出；不要从头再来，要随时可恢复。

JSON 知识库

每页提取 → 本地 JSON

每读一页，提取该页的关键知识点（实体、概念、关系、引用），以结构化 JSON 写入本地知识库文件。全书读完后，知识库即成为可查询的完整知识图谱。

knowledge_bases/
  └── <book_name>_kb.json
{
  "pages": [
    {
      "page": 1,
      "chunk": "...",
      "entities": ["概念A", "人物B"],
      "key_points": ["..."],
      "summary": "..."
    },
    ...
  ]
}
间隔摘要

每隔 N 页 → 阶段性摘要

通过 ANALYSIS_INTERVAL 配置间隔（默认每 10 页），在每个 checkpoint 产出该段落摘要。重置注意力基准线，保证每个阶段的核心信息不丢失。

# 配置示例
PDF_NAME = "my_book.pdf"
ANALYSIS_INTERVAL = 10  # 每10页做一次间隔摘要
MODEL = "gpt-4o-mini"
TEST_PAGES = 5         # 仅测试前5页
断点续读

load existing knowledge

处理中断后，可从已有知识库文件加载历史进度，新页继续追加到同一 JSON，无需从头扫描全书。适合超长文档或网络不稳定场景。

智能跳过

目录 / 索引 / 空白页自动跳过

内置智能过滤器，自动识别并跳过目录页（TOC）、索引页（index keywords）、空白页，避免无效 token 消耗，提高知识库有效密度。

03
输出结构

book_analysis/ 目录：知识库 + 摘要双轨并行

所有输出按功能分目录存储，知识库与摘要分离，互不干扰又可交叉引用。

目录内容格式用途
book_analysis/knowledge_bases/每页提取的结构化知识点JSON可查询知识图谱、断点续读基础
book_analysis/summaries/间隔摘要 + 全局综合摘要Markdown快速浏览、笔记整理、内容复用
book_analysis/raw_pages/原始分页文本（可选）Text调试、审计、回溯
知识库 JSON 支持增量写入，全局摘要由间隔摘要拼接模型重新综合，前后文连续不割裂。
04
核心配置

主要参数一览

开箱即用，支持 PDF / EPUB / TXT / 直接 URL 输入；分析模型可独立选择。

参数默认值说明
PDF_NAME必填目标文件路径，支持 PDF / EPUB / TXT / URL
ANALYSIS_INTERVAL10每隔多少页产出一次间隔摘要（interval summary）
MODELgpt-4o-mini用于摘要和分析的 LLM 模型，可替换为其他兼容模型
TEST_PAGES0（关闭）设为正整数时仅处理前 N 页，用于快速验证流程
CHAPTER_PATTERN正则自动检测自定义章节检测正则，匹配时自动产出章节级摘要
SKIP_TOCtrue自动跳过目录、索引、空白页
05
适用场景

适合谁 / 不适合谁

不是通用 PDF 工具，是面向深度阅读、知识管理、长文档分析的专用流水线。

✓ 适合

适合的场景

  • 学术论文、专著、教科书（200 页+）的深度知识提取
  • 需要完整知识图谱而非简单摘要的研究人员
  • 超长技术文档（如 RFC、规范）结构化处理
  • 多本书同一主题的横向知识整合
  • PDF 版调查报告、白皮书、政策文件的快速梳理
✗ 不适合

不适合的场景

  • 短文稿（10 页以内）——用普通摘要 API 更快
  • 扫描版 PDF（无文字层）——需要先 OCR
  • 纯图片 PDF（漫画、图表集）——无法提取文字
  • 实时对话式文档交互——这是批处理流水线，不是实时聊天
  • 非结构化网页抓取——不是爬虫工具

快速上手

安装与基本用法

git clone https://github.com/echohive42/AI-reads-books-page-by-page.git
cd AI-reads-books-page-by-page
pip install -r requirements.txt

# 设置 API Key
export OPENAI_API_KEY="sk-..."

# 基本运行
python read_books.py
依赖：Python 3.x + OpenAI API Key（或其他兼容模型的 API Key）。模型可配置，推荐 gpt-4o-mini 平衡速度与质量。
安全提示：运行时请将 API Key 放入环境变量，不要把真实密钥写入仓库、日志或知识库。
