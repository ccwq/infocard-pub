给多个 AI Agent 加记忆之前，先把来源、冲突和过期策略管起来

Memanto 不是一个只负责写入和检索的数据库 SDK，而是一个运行在 Agent fleet 旁边的 Memory Agent：提取持久知识、合并重复记忆、处理冲突、执行过期策略，并在 Agent 行动前提供相关摘要。它可以接入 Claude Code、Codex、Cursor 等工具，但“免费”需要拆开理解：本地 On-Prem 路径需要 Docker + Ollama，云端路径需要免费 API key。到底选哪条，取决于数据边界和运维成本。

01

它解决的不是“有没有数据库”，而是记忆资产会不会失控

官方把 Memanto 定义为 companion memory agent，负责跨 Agent 的整理和 briefing。

观察与提取

从 Agent 交互流中提取决策、偏好、事实、失败等持久知识，而不是把完整 transcript 原样归档。

合并与冲突

重复记忆合并；新旧知识冲突时保留“现在相信什么”和“过去相信什么”的差异，交给人审查。

遗忘与 briefing

按策略执行 decay/expiry/deletion，并在 Agent 行动前提供最小相关切片，减少重复上下文。

关键区分：Memanto 的价值不在于“让 Agent 永远记住一切”，而在于让记忆可分类、可追溯、可过期、可迁移。

03

记忆类型与最小工作流：不要把所有内容写成一条长备注

官方 README 列出 14 类记忆，类型让 recall 能够按语义和用途筛选。

输入：有类型的记忆

instruction、fact、decision、goal、commitment、preference、relationship、context、event、learning、observation、artifact、error 等。

中间：管理动作

remember 写入，recall 取回，answer 基于取回内容回答；conflicts 发现矛盾，daily-summary 汇总变化。

输出：可审计上下文

回读时关注 source、provenance、confidence、timestamp 和 active/expired 状态，不只看自然语言摘要是否“听起来合理”。

迁移：把资产带走

memanto memory export --okf 导出 Open Knowledge Format；README 说明它是可读、可 diff、可提交的 Markdown 资产。

# 结构化写入与筛选 memanto remember "User prefers concise answers" --type preference memanto recall "user communication style" --type preference # 时间与变化 memanto recall "deployment policy" --as-of 2026-08-05 memanto recall "deployment policy" --changed-since v2.1
04

过期策略：记忆不是越多越好，而是要知道何时失效

默认没有策略的 Agent 不会自动过期；策略需要显式配置和审查。

策略顺序

memanto policy list-preset 查看 conservative/balanced/aggressive；先用 --dry-run 看哪些内容会过期，再真正 apply。

规则优先级

保留表负责大范围期限，命名规则处理 pinned、低置信度推断等例外；README 说明 first matching rule wins。

可恢复性

过期内容带原因并可在 recall 中以 [EXPIRED] 标识；memory restore 可恢复，永久删除是独立动作。

memanto policy list-preset memanto policy apply-preset balanced memanto policy apply --dry-run memanto policy apply memanto memory expire mem-123 memanto memory restore mem-123
不要跳过 dry-run：先确认哪些事实会被标记过期、命中了哪条规则，以及是否需要 pin；不要把“自动清理”当成无风险后台任务。

安全与主权：本地运行、可迁移和可审计分别是什么

这些是不同承诺，不能用一个“隐私安全”标签全部覆盖。

能力官方描述验收问题
On-PremDocker + Ollama，可不设账号和 API key，数据留在自己的基础设施Docker、模型、网络出口和日志是否确实受控？
Cloud免费路径，需要免费 API key；README 写 100K free operationsProvider 数据条款、额度和密钥保管是否可接受？
Namespace每个 Agent 可有自己的 namespace生产 Agent 是否会读到实验 Agent 的记忆？
Provenance记忆可带 confidence、source、provenance、timestamp答案能否回到进入 fleet 的原始来源？
OKF以 Markdown 形式导出、diff、commit 和迁移导出文件是否含敏感内容、是否纳入访问控制？
06

连接与自动化：Hook 会放大收益，也会放大误读

v0.2.20/0.2.21 引入连接模板更新、session hook、工具身份与 activity tracking 等变化。

连接更新

memanto connect update 可更新已安装 Agent 的 instructions 和 skill；要检查安装版本是否落后。

启动同步

Claude Code、Codex CLI、Cursor 有 session-start/pre-compact 等 hook 路径；它们会改变何时刷新 MEMORY.md。

活动归因

v0.2.21 为 remember/recall/answer 记录工具、Agent、Memanto session 和计数；未知调用者保持 unknown，不猜测。

工程判断：先手动 remember/recall/answer，确认命名空间与回读，再开 schedule/hook；自动化不是第一步验收标准。
07

故障排查、版本和许可证

当前版本快照来自 GitHub API；快速增长项目的 Stars 不代表稳定性。

现象第一检查下一动作
Agent 不认识命令memanto status、连接是否完成、是否重启 CLI重新 connect/update，再用最小记忆测试
回忆结果不对type、namespace、source、时间过滤回到原始记忆与 provenance，不只看 answer
本地路径失败Docker、Ollama、模型和端口先单独验证后端，再连接 Agent
Cloud 额度/密钥问题Provider、API key、额度和网络不要把 key 写入项目文件、日志或文章
策略误过期preset、规则顺序、dry-run 输出restore 后调整策略，再重新 apply
升级后连接陈旧template version、memanto status执行 memanto connect update 并回读

下一步只做一件事

先安装 Memanto → 连接一个 Agent → 写入一条 typed decision → recall/answer 回读 → 检查 source/namespace/状态 → 再决定是否启用本地后端、过期策略、hook 或跨 Agent 共享。
