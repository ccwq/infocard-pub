PI · CONVERSATION COMPACTOR · NO LLM

pi-vcc · 不调用 LLM 的
会话压缩器

pi-vcc 给 Pi agent 提供一条纯算法的会话压缩路径：不调 LLM，不烧 token， 相同输入永远得到相同输出。它把会话切成5 个语义切片加一段滚动转录， 原始 JSONL 全保留，配合 vcc_recall 让被压缩掉的历史依然可被检索回。

L1 / source

原始 JSONL 历史

会话原文存于 ~/.pi/agent/sessions/*.jsonl。压缩从不删除原文，是后续所有召回的事实底座。

L2 / sections

5 个语义切片

用正则与工具调用结构提取：Goal、Files、Commits、Outstanding、Preferences；按 sticky / fresh / union 三种合并策略累积。

L3 / transcript

滚动转录窗口

~120 行最近对话，工具调用折叠成 (#N) 单行引用；旧行随窗口滚出，但仍能被召回。

L4 / recall

vcc_recall 无损召回

跳过摘要直读 JSONL：默认搜索当前血脉，可 scope:"all" 跨血脉，支持正则与多词 OR 排序。

5 个语义切片是什么

Session Goal初始目标 + scope 变更（正则抽取，sticky 合并）

把会话第一目标和后续 scope change 累积下来，避免压缩后 agent 忘了在做什么。

Files & Changes从工具调用里抽取的 modified / created 文件路径

跨多次压缩取并集，自动裁剪到公共根，避免长路径噪声。

Commits会话期间的 git commit（最近 8 条）

只保留 hash 与首行，作为不可丢失的事实锚点。

Outstanding Context未解决项：失败的 lint、悬而未决的问题

每次压缩都被新值替换，避免旧问题被错误延续。

User Preferences用户表达过的 always/never/prefer 偏好

从用户消息正则抽取，sticky 合并，保住语言、风格、流程偏好。

Brief Transcript~120 行滚动窗口，工具调用折叠为 (#N)

保留时间顺序与因果链，旧行滚出但仍可 vcc_recall 调回。

命令速查 install · usage · recall

install pi install npm:@sting8k/pi-vcc

也可 pi install https://github.com/sting8k/pi-vcc，或免装试 pi -e https://github.com/sting8k/pi-vcc。

compact /pi-vcc # 默认压缩 /pi-vcc keep:3 # 保留最后 3 个用户回合 /pi-vcc keep:0 # 全压，不留 tail

注册的是 session_before_compact hook，被动触发也走同一条路径。

recall vcc_recall({ query: "auth token" }) vcc_recall({ query: "hook|inject" }) vcc_recall({ query: "auth token", scope: "all" })

支持正则与多词 OR 排序；默认仅搜当前血脉，scope:"all" 跨所有血脉。

slash recall /pi-vcc-recall auth token /pi-vcc-recall auth token scope:all /pi-vcc-recall auth token page:2

结果以折叠消息显示，并自动喂回 agent 作为上下文；输入 /recall 会自动补全。

expand vcc_recall({ expand: [41, 42] }) vcc_recall({ expand: [41, 42], scope: "all" })

典型工作流：先 search 找到 index → 再 expand 取全文。

config ~/.pi/agent/pi-vcc-config.json { "overrideDefaultCompaction": false, "debug": false }

设为 true 可让 pi-vcc 接管所有压缩路径，连 /compact 也走它。

反直觉读法 · pi-vcc 不是更好的摘要器，而是退一步不摘要： 与其让 LLM 压缩历史，不如用算法切成几块不会变形的语义块，再让原文随时可召回。 压缩越激进，越要保住召回路径——这是它和默认压缩的根本分歧。
