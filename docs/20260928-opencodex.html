03 · ROUTING CONTROL PLANE

Provider choice is only the first routing decision

03
PROVIDER / MODEL

Direct selection

Target anthropic/claude-opus-5, google/gemini-3-pro or ollama/llama3. Provider IDs containing slashes have an alias form, while the raw full-slash form remains accepted.

COMBOS

One virtual model, several backends

Combos expose one model ID with failover or weighted round-robin across providers. Combos let the client pick one model name while OpenCodex handles provider selection and failover behind that name.

SUB-AGENTS

Surface control and fallback

Feature-routed models can appear in Codex’s sub-agent picker; the README names v1/v2 surface controls and fallback chains as the available controls.

AUTH

API key, OAuth or forwarded login

Use OAuth for xAI, Anthropic and Kimi; forward codex login; paste a key; or reference ${ENV_VAR}.

04 · ACCOUNT POOL / THREAD AFFINITY

Quota routing is not the same as mid-thread switching

04
NEW SESSION

Choose a healthy low-usage account

The dashboard can refresh ChatGPT / Codex account quotas across 5-hour, weekly and 30-day windows. Policies include lowest-usage healthy, round-robin and fill-first.

EXISTING THREAD

Keep affinity by default

Existing Codex threads normally remain pinned to the account that started them, so long SSH, tmux or mobile sessions do not jump accounts mid-conversation.

REBIND EVENTS

Exceptions are explicit

Quota reevaluation, failover, account exclusion, affinity expiry, 401/403 and 429 recovery can rebind a thread.

POLICY BOUNDARY

Routing is not an enforcement bypass

Account pooling is described as operational resilience only. It does not guarantee protection from rate limits, suspension or other provider actions.

05 · OPERATE / INSPECT / RECOVER

From one command to a managed local service

05
# install and start
npm install -g @bitkyc08/opencodex
ocx init                 # write config + wire Codex
ocx start                # proxy + dashboard on localhost:10100

# inspect liveness and post-sync readiness
ocx health --json
ocx ready --json --wait --timeout 45

# choose lifecycle semantics
ocx service              # always-on background service
ocx codex-shim install   # on-demand startup when codex launches
ocx stop                 # stop + restore native Codex
/healthz

Immediate liveness

Returns whether the proxy is alive. It is not the same as provider synchronization being ready.

/readyz

Post-sync readiness

Returns 200 only for ready; pending and terminal failed states return 503 with Retry-After: 1.

SERVICE VS SHIM

Daemon or demand

Use the service for restart-on-crash operation; use the shim when a background daemon is unnecessary.

08 · BOUNDARIES BEFORE DEPLOYMENT

Two risks are part of the product definition

08

Remote bind changes the trust model

Default binding is 127.0.0.1. Binding to 0.0.0.0 requires OPENCODEX_API_AUTH_TOKEN, and every request must carry x-opencodex-api-key. Do not expose the proxy by changing the hostname alone.

Provider policy remains upstream

OpenCodex is independent and not endorsed by OpenAI, Anthropic or other providers. The README warns that some providers may suspend or restrict accounts that route API traffic through third-party proxies. Review each provider’s current Terms of Service before connecting it.

What the project explicitly does not promise

Account pools do not guarantee immunity from rate limits, enforcement, suspension or account actions. Routing resilience is an operations feature, not a license to bypass provider rules or share credentials between people.

macOS arm64/x64, Linux x64/arm64 and Windows x64 are listed as fully supported. Node 18+ is required; the Bun runtime is bundled by npm install.

Source development uses bun install, bun run typecheck and bun run test. The published package’s bundled Bun is a different path.
