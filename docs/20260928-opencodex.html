OpenCodex

一个本地代理，同时服务 Codex、Claude Code、Claude Desktop 与 Grok Build，背后接 40+ 家供应商，前台仍是原生工作流。

OpenCodex 把 Codex 的 Responses API 翻译成各家供应商自己的协议。边界留在本地：流式输出、工具调用、推理 token 与图片双向通行；换模型不必换客户端界面。

翻译

边界上是 Responses API

OpenCodex 把 Codex 的 Responses API 转成各供应商的协议形态，而不是要求每个客户端认识所有供应商。

暴露

模型变成可寻址对象

provider/model 即选定路由；省略 provider 时走默认值，或按模型名模式匹配。

03 · 路由控制面

选供应商只是第一个路由决策

03
供应商 / 模型

直接选择

可以指定 anthropic/claude-opus-5、google/gemini-3-pro 或 ollama/llama3。含斜杠的 provider ID 有别名写法，原始全斜杠写法同样接受。

组合模型

一个虚拟模型，多个后端

组合模型把多个供应商暴露成同一个模型 ID，支持故障转移或加权轮询；客户端只认一个模型名，供应商选择与故障转移由 OpenCodex 在这命名背后完成。

子代理

表面控制与回退链

按特性路由的模型可以出现在 Codex 的子代理选择器里；README 点名了 v1/v2 surface 控制与 fallback 链。

鉴权

API Key、OAuth 或转发登录

xAI、Anthropic、Kimi 可用 OAuth；转发 codex login；粘贴 key；或引用 ${ENV_VAR}。

04 · 账号池 / 会话粘性

配额路由不等于会话中途换号

04
新会话

挑一个健康的低用量账号

仪表盘可刷新 ChatGPT / Codex 账号在 5 小时、每周、30 天窗口的配额。策略包括最低用量健康优先、轮询与填满优先。

已有会话

默认保持粘性

已存在的 Codex 会话通常固定在发起它的账号上，长时间 SSH、tmux 或移动端会话不会聊到一半跳号。

重绑事件

例外必须显式

配额重估、故障转移、账号排除、粘性过期、401/403 与 429 恢复都可能重新绑定会话。

策略边界

路由不是绕过执法

账号池被定义为运维韧性手段，不保证躲开限流、封号或其他供应商处置。

05 · 运行 / 检查 / 恢复

从一条命令到可管理的本地服务

05
# 安装并启动
npm install -g @bitkyc08/opencodex
ocx init                 # 写配置 + 接线 Codex
ocx start                # 代理 + 仪表盘监听 localhost:10100
# 检查存活与同步后是否就绪
ocx health --json
ocx ready --json --wait --timeout 45
# 选择生命周期语义
ocx service              # 常驻后台服务
ocx codex-shim install   # codex 启动时按需拉起
ocx stop                 # 停止并还原原生 Codex
/healthz

即时存活

返回代理进程是否活着，并不等于供应商同步已完成。

/readyz

同步后就绪

仅在 ready 状态返回 200；pending 与终态失败返回 503，并带 Retry-After: 1。

服务 vs 垫片

常驻还是按需

需要崩溃自动重启就用服务；不需要后台常驻守护就用 shim。

07 · 内存归属

"本地代理"同样需要运维预算

07
12 个存储

按字节记账的保留

请求日志、调试环、图片缓存、模型缓存、视觉描述、光标 blob 等保留型存储，都在应用自有的内存预算下被淘汰。

24 个注册项

过期与对账

状态存储注册项每 60 秒清扫一次，并按配置代际对账，移除过期的供应商 / 账号键。

36 个类别

查看实时保留字节

README 记录了 36 个进程保留状态类别，并提供 GET /api/system/memory，带管理 token 可看看门狗与淘汰计数。

08 · 上线前先看边界

两个风险本身就是产品定义的一部分

08

改监听地址就改变了信任模型

默认绑定 127.0.0.1。绑到 0.0.0.0 必须设置 OPENCODEX_API_AUTH_TOKEN，且每个请求都要带 x-opencodex-api-key。不要只改主机名就把代理暴露出去。

供应商政策仍在上游

OpenCodex 是独立项目，未获 OpenAI、Anthropic 等供应商背书。README 提示：部分供应商可能对通过第三方代理转发 API 流量的账号做限制或封停。接入前请阅读各供应商当前的条款。

项目明确不承诺的部分

账号池不保证免于限流、执法、封停或账号处置。路由韧性是运维特性，不是绕过供应商规则或多人共用凭证的许可。

09 · 平台 / 构建 / 退出

安装面与退出路径

09
支持平台

macOS · Linux · Windows

完整支持 macOS arm64/x64、Linux x64/arm64 与 Windows x64。要求 Node 18+；npm install 会自带 Bun 运行时。

源码开发

PATH 上要有 Bun

源码开发用 bun install、bun run typecheck、bun run test。这与发布包里自带的 Bun 是两条路径。

卸载

还原、移除、清状态

ocx uninstall 会停代理、移除服务与垫片、还原原生 Codex 并清理状态；之后按需卸载全局 npm 包。
