Hermes vs agent-browser：AI 浏览器工具能力全景对比

8 个工具 vs 108+ 命令；Python 实现 vs Rust CLI；对话式 vs 命令式。选型前先搞清楚谁更适合你的场景。
一句话结论

Hermes 是通用 Agent 的内置浏览器能力，适合快速任务；agent-browser 是专为 AI 设计的浏览器自动化 CLI，适合需要精细控制和 Token 优化的场景。两者定位不同，不存在谁绝对更好。

各自局限性

这些坑你知道吗

Hermes 已知坑
  • 首次导航经常超时（重试即可）
  • stale target 会话失效（supervisor 自动重建）
  • 数据中心 IP 被 Google reCAPTCHA 拦截
  • 截图发送可能失败（微信/QQ 限制）
  • 后台任务禁用浏览器工具
agent-browser 已知坑
  • 无内置视觉分析（需要配合视觉模型）
  • 复杂登录态管理需手动处理
  • 需要 Node.js daemon 常驻后台
  • 部分高级场景不如 Playwright/Selenium
选型建议

根据场景对号入座

  • Hermes 快速网页截图/填表/内容抓取，配合 AI 对话完成，不需要额外安装 CLI
  • agent-browser Claude Code / OpenCode / Cursor 集成，需要精细控制页面操作，想省 Token 预算
  • 两者都不选 传统自动化测试选 Playwright；复杂登录态选 browser-use；性能分析选 Chrome DevTools MCP
