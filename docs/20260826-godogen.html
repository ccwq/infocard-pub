它不是“游戏成品库”

Godogen 是生成游戏项目的源代码与技能流水线：输出的是一个真实、可组织、可继续开发的 game repo，而不是一张概念图或一段孤立代码。

Agent 到底做了什么？

  • 架构设计：根据游戏描述拆出场景、系统、脚本与资产计划。
  • 资产生成：为 2D / 3D 游戏生成参考图、纹理、模型和动画。
  • 代码实现：按引擎指南生成项目结构、场景和运行时逻辑。
  • 真实运行：启动 Godot、Bevy 或 Babylon.js，捕获实际运行结果。
  • 视觉修复：根据截图/视频反馈继续迭代，而不是相信自己的完成宣称。
Godot 4

C# / .NET 项目

支持 build-time scene generation、runtime scripts、Jolt physics，并配套 Godot API 参考与引擎 quirks。

Bevy

Rust / ECS 场景

采用 code-first ECS 场景与离屏捕获，适合用 Rust 构建结构清晰的原生游戏项目。

Babylon.js

TypeScript / Vite 游戏

输出浏览器游戏，支持 live URL、热更新和 Chrome/Chromium WebGL2 捕获。

问题对策

为什么需要 API 参考？

Godot 有 850+ 类，GDScript 与 Python 相似却并不相同。Godogen 用手写规范、XML API 文档和 lazy lookup 减少模型幻觉。

安装前提按引擎选择

运行需要什么？

  • Godot：Godot 4 .NET build、Python 3、系统依赖。
  • Bevy：Rust/Cargo 与本地 Bevy 文档。
  • Babylon.js：Node.js 22.12+、npm、支持 WebGL2 的 Chrome/Chromium。
  • 资产生成：按需配置 Gemini、xAI Grok、Tripo3D API key。
现实边界：完整生成可能持续数小时，并且依赖本地引擎、浏览器、Python/Node/Rust 工具链和相应 API 服务；它不是零配置的一键游戏机。
初步使用publish.sh

把技能发布到新游戏仓库

git clone https://github.com/htdt/godogen.git
cd godogen

# 选择引擎与 Agent 风格
./publish.sh --engine godot   --agent claude --out ~/my-game
./publish.sh --engine babylon --agent codex  --out ~/my-game
./publish.sh --engine bevy    --agent claude --out ~/my-game
适合

想用自然语言探索游戏原型、需要 Agent 处理引擎细节、希望把生成结果保留为可运行项目并持续迭代的开发者。

不适合

只想生成一张游戏概念图、没有本地引擎和 API 条件、或要求 Agent 在没有真实运行验证的情况下保证成品质量。
