给 subagent 分配"最合适的模型"是 AI Agent 编排中的核心难题——通常靠开发者经验甚至运气。agent-routing v1.3.0（@oaustegard）通过 Haiku / Sonnet / Opus 三级路由 + per-agent effort level，把这个决策变成可测量的 calibrate 流程。基于 references/calibration-2026-07-15.md 的实测数据，支持 cheap-first cascade 和 stop-on-regression，适用于 fan-out 多个 agent、需要可观测升级逻辑的场景。

01
PROBLEM

经验和运气 → calibrate 流程

传统 subagent 模型分配靠猜，agent-routing 把模型选择变成可测量、可重复的工程决策。

传统方式

经验和运气

  • 开发者凭经验选模型
  • 不同任务用同一模型（浪费 or 不足）
  • fan-out 多个 agent 时成本失控
  • 无法追踪为什么选了这个模型
  • 优化后无法防止退化
agent-routing

calibrate 驱动

  • 基于实测校准数据（非直觉）
  • per-agent effort level 精细控制
  • cheap-first cascade 降低成本
  • verifier 检查输出质量
  • stop-on-regression 防止退化
02
CORE LOGIC

三级路由 + cheap-first cascade

Haiku → Verifier → Sonnet → Opus，按需升级，每一步都有据可查。

01 / Haiku

最便宜模型先跑

所有任务优先用 Haiku，降低成本第一枪。

支持 per-agent effort level 配置。

02 / Verifier

质量门禁检查

verifier 组件评估 Haiku 输出是否达标。

不通过才触发升级 cascade。

03 / Sonnet

中等级升级

Haiku 不通过 → 升级到 Sonnet 再跑。

平衡成本与能力。

04 / Opus

最高级兜底

Sonnet 也不通过 → 最终升级到 Opus。

处理最复杂任务。

03
MECHANISMS

stop-on-regression + cost lever

Managed Agents 的 effort 机制直接编码，防止优化退化，让成本可见可控。

1

stop-on-regression

优化过程中若质量下降，立即停止并回退。防止"改进"反而降低输出质量。

2

per-agent effort level

每个 subagent 可独立配置 effort 级别，决定它使用哪级模型和验证策略。

3

calibration 数据

references/calibration-2026-07-15.md 提供实测数据，路由决策基于数据而非直觉。

04
USE CASES

适用场景

fan-out 超过几个 agent、不知道该用哪个模型跑哪个子任务、需要可观测升级逻辑。

Fan-out

多 agent 并行分发

当你需要把任务分发到 N 个 subagent，不知道每个该用什么模型时，agent-routing 提供自动路由。

成本控制

cost lever 可见

Managed Agents 的 effort 机制直接编码，每个升级决策都关联成本，方便优化预算。

可观测

升级逻辑可追踪

每一步升级都有 verifier 结果记录，方便审计、回溯和持续优化路由策略。
