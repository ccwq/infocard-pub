Old Coder 把信任从「逐行审查」转移到「约束与证据」，让 coding agent 自证其码。

Old Coder 是受 Uncle Bob（Robert C. Martin）启发、由 AmazingAng 开发的 coding agent skill（74 Stars，MIT，Python）。核心洞察：如果你不打算读代码，那就让代码通过一整套可验证的检查关卡。Human 只读两份文档——写码前的 SPEC（测试计划）和写码后的 EVIDENCE（证据报告）——而不是代码本身。8 层 gauntlet 按风险分级（Tier 1 改错别字只跑 1-2 项；Tier 3 涉金钱/登录/数据/并发全跑，agent 还要先用恶意输入攻击自己的代码）。Demo evidence.md 实录：17 个测试、代码 100% 分支覆盖、8/8 planted bugs 全部被抓——过程中还发现了一个测试原本漏掉的真实 bug（NaN 时间窗口穿过参数校验）。

02
CHAPTER · TDD Loop

TDD Loop · 完整闭环

SPEC → RED → GREEN → REFACTOR → GAUNTLET → EVIDENCE

1

SPEC — Human 唯一要读的文件（写码前）

把请求转化为可执行的验收标准（具体输入/输出/边界/错误情况）。包含 setup plan（工具安装/git 使用/新依赖）。批准它 = 一次性授权整个环境变更。

2

RED — 先写测试，亲眼看它失败

写测试，看它失败。Bug 修复必须从 RED 开始：先写一个重现 bug 的测试，fix 完成后它才是回归测试。

3

GREEN — 写代码直到测试通过

只管让测试变绿，不做优化。禁止在此步改测试。

4

REFACTOR — 清理代码，测试不动

改善代码结构，不改行为。下一行为触发新 RED。

5

GAUNTLET — 跑完所有检查

8 层检查关卡。失败的 gauntlet = 阻塞完成。

6

EVIDENCE — Human 读报告，不读代码

来自一次完整 fresh run 的真实数字，人类一条命令可重跑验证。未验证项只能标 unverified，不能标 pass。

03
CHAPTER · Gauntlet 8 层

Gauntlet 8 层检查

按风险分级：Tier 1 改错别字跑 1-2 项；Tier 3 涉金钱/登录/数据/并发全跑 + agent 先用恶意输入攻击自己代码。

L1

全量测试

有没有东西被改坏？

L2

类型 + Lint + 复杂度

低级错误？函数有没有写得没人看得懂？

L3

改动行覆盖率

每一行新代码都真的被测试跑到了吗？

L4

Mutation Testing

故意埋 bug——测试能抓到吗？

L5

Property-Based 测试

几百个随机输入下规则还成立吗？

L6

真实执行

离开测试环境，它真的能跑吗？

L7

供应链 + 密钥

有没有偷偷引入危险包？有没有泄漏密钥？

L8

套件健康

测试本身稳定吗？换个顺序还全过吗？

Tier 3 额外层：并发测试（go test -race）/ UI 检查（axe-core、Playwright 截图 diff）/ API 兼容性 / 性能基准 / 可观测性断言 / 依赖版本矩阵 / 恶意输入攻击。

05
CHAPTER · Anti-Gaming 规则

6 条硬规则 · 防止 Agent 作弊

规则 1

永不改测试来通过

不能为通过而弱化断言、加 skips、删失败测试。测试疑似有问题 → 发起 spec 对话，不埋掉它。

规则 2

测试和实现不能同步改

一次改一个，运行，再改另一个。

规则 3

Mock 边界，不 Mock 逻辑

Mock 网络/时钟/文件系统，不 Mock 被测逻辑。

规则 4

不要追覆盖率数字

覆盖率是未测代码的探测器，不是目标。mutation testing 专门用来抓"为凑数字加的断言"。

规则 5

不报告未跑的层

诚实记录"跳过：XX原因"，比捏造结果更能维护信任。

规则 6

Gauntlet 失败即阻塞完成

任何层失败即未完成。真的被阻塞了就如实报告失败结果。
