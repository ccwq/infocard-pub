01
核心定位

它不只是一个"更好的 Notion"，而是一套数据自主的 AI 工作区

README 明确说了：Notion 有数据安全和移动端兼容问题，AppFlowy 的目标不是超越功能，而是解决"数据谁控制"和"原生体验"这两个根本问题。

使命

让任何人都能创建适合自己的应用

这不是"另一个笔记工具"，而是一套让个人和企业都能按需定制的工作台——不需要懂底层架构，也能用扩展机制搭建自己的系统。

技术

Flutter + Rust，单代码库多平台

Flutter 保证跨平台 UI 一致性，Rust 保证后端性能和内存安全。一套代码支持 macOS、Windows、Linux、iOS、Android 和浏览器端。

隐私

数据隐私第一，可完全自托管

核心价值主张：你可以把 AppFlowy 部署在自己的服务器上，数据完全归你。没有供应商锁定，没有云端数据泄露风险。

AI

内置 AI，支持本地模型运行

AppFlowy AI 支持 Mistral 7B、Llama 3 等本地模型运行在本地机器上，实现真正的隐私优先 AI 工作流。

02
三大核心价值

数据隐私第一 · 原生体验优先 · 社区驱动扩展性

这是 AppFlowy 团队在 README 里明确写出的三个最高优先级，也是它与 Notion 和其他竞品的本质区别。

数据隐私第一

01
理论

Notion 的主要限制之一是数据安全——你的数据在云端，不在你手里。AppFlowy 从第一天就把数据自主作为第一原则，支持完全自托管。

适合场景

场景A：企业需要对内部文档有完全控制权，不希望数据存在第三方云。
场景B：个人用户对隐私敏感，不想让笔记和项目数据被平台用于训练或分析。
场景C：开发者想在本地部署一个团队协作工作区，不需要维护 Notion 账号体系。

原生体验优先

02
理论

用 Flutter + Rust 构建原生应用，保证跨平台都有接近原生 App 的性能和手感。Notion 在移动端体验弱，AppFlowy 想解决这个痛点。

适合场景

场景A：需要在 iPad / 手机上也能有流畅的笔记和项目管理体验。
场景B：希望桌面端和移动端数据实时同步，但不需要复杂的网络依赖。
场景C：用户习惯原生 App 的交互逻辑，不接受 Web 壳子带来的卡顿感。

社区驱动扩展性

03
理论

AppFlowy 的定位不是"一个产品解决所有问题"，而是为开发者和企业提供构建模块（building blocks），让社区共同扩展功能。AGPLv3 许可证允许自由修改和分发。

适合场景

场景A：开发者想基于 AppFlowy 的数据层做定制化内部工具。
场景B：企业想深度集成到现有工作流，有能力自己维护修改。
场景C：社区成员可以贡献插件、模板和功能扩展，共同完善生态。

03
功能模块

从笔记到 AI 助手，5大核心功能覆盖完整工作流

每个功能模块都设计成可独立使用，也可以组合成完整的项目管理或知识库系统。

Tasks

看板与待办管理

Kanban 看板视图，支持项目追踪、任务分配、截止日期和标签管理，适合个人和小团队的项目管理。

Databases

结构化数据库

类似 Notion Database 的结构化数据管理，支持多种视图切换（表格、看板、日历、画廊），灵活展示项目与任务。

Sites

文档站点构建

快速构建美观的在线文档站点，适合团队知识库、产品文档和公开页面发布。

AI

AppFlowy AI

内置 AI 助手，支持 Mistral 7B、Llama 3 等本地模型运行，数据不离开本地，真正实现隐私优先的 AI 工作流。

Templates

模板市场

社区贡献的模板合集，从项目管理到知识库，覆盖各种场景的开箱即用模板。

04
安装与平台

5大平台全覆盖，随时随地访问你的工作区

官方提供桌面端和移动端安装包，也可通过 Snapcraft、Flathub、SourceForge 等渠道安装。

桌面端

1
安装方式

官方提供 macOS (.dmg)、Windows (.msi/.exe) 和 Linux (.AppImage) 安装包。Linux 用户也可通过 Snapcraft 和 Flathub 订阅安装。

推荐场景

场景A：macOS 用户下载 .dmg 直接安装，体验最完整。
场景B：Linux 用户用 Flatpak 或 Snap 保持自动更新。
场景C：Windows 用户可选 MSI 安装包或便携版。

移动端

2
安装方式

iOS 用户从 App Store 下载，iPad 全功能支持。Android 用户从 Google Play 下载（要求 Android 10+，不支持 ARMv7）。

推荐场景

场景A：iPhone / iPad 用户直接在 App Store 搜索 AppFlowy。
场景B：Android 用户从 Play Store 安装，注意需要 Android 10 以上版本。
场景C：移动端与桌面端数据实时同步，随时随地访问工作区。

自托管

3
部署方式

通过源码自托管是 AppFlowy 的核心差异化能力。开发者文档提供完整的环境配置指南，支持 Docker 容器化部署或直接从源码编译安装。

推荐场景

场景A：企业内网部署，保证数据不出公司防火墙。
场景B：有 DevOps 能力的团队，自定义 API 网关和数据存储策略。
场景C：对数据隐私要求极高的个人用户，不想用任何第三方云服务。

05
适合谁

核心判断：它解决的是"我想用 Notion 但不放心数据安全"这个痛点

如果你的主要痛点是"功能不够"，Notion 本身更成熟；如果你的痛点是"数据控制权"，AppFlowy 是目前最好的开源选择。

值得

应该选 AppFlowy

  • 对 Notion 有强需求，但不接受数据存在第三方平台
  • 企业需要合规要求（数据本地化、内部部署）
  • 开发者想在现有工作区基础上定制或扩展功能
  • Flutter / Rust 技术栈的开发者想参与开源贡献
  • 追求原生跨平台体验（桌面 + 移动）
  • 对本地 AI 有需求，希望 AI 能力完全离线可用
不值得

可以继续用 Notion

  • 只需要基础的笔记和文档协作，不需要自托管
  • 团队重度依赖 Notion 的生态插件（Notion API、第三方集成）
  • 对功能完整度和成熟度要求极高，AppFlowy 仍在快速迭代
  • 不需要移动端原生体验，Web 端足够
  • 只是想找一个简单的 Markdown 笔记工具

一句话判断：如果你有 Notion 的需求，同时对数据控制权有要求（企业合规、个人隐私、开发者定制），AppFlowy 是目前最完整的开源选择。如果只是想要一个笔记工具，先用 Notion 更省心。
