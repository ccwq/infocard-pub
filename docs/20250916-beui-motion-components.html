基础概念

什么是"动效 UI"，为什么它很难做好

动效 UI 不是 CSS transition: 0.3s ease，它是让界面"有生命"的那层交互语言

一句话解释 动效 UI = 界面元素在状态变化时的过渡动画。它不是简单的 fade-in，而是有重量感、速度感、回弹感的物理运动，让用户感知到每个操作的因果关系。

❌ 传统 transition 的问题

线性动画无回弹千篇一律

CSS transition: 0.3s ease 永远是匀速运动，物体突然开始突然停止，没有物理质感。

⚠️ Framer Motion 的门槛

需调参数需理解物理跨组件一致难

Framer Motion 提供了一切可能，但要写出自然动效，需要深入理解 stiffness（刚度）、damping（阻尼）、mass（质量）三者的关系。

🤖 AI Agent 的困境

AI 写 transitionduration: 0.3生硬无质感

AI Agent 生成代码时倾向于使用固定时长 tween，而不是弹簧物理。导致"功能正确但感觉不对"。

弹簧物理三参数——理解它们，你就理解了 beUI 一半的核心

stiffness（刚度）
弹簧的"硬"程度。值越大，弹性越强，拉伸后回弹越快越猛。高刚度 = 短促有力的按压反馈。
damping（阻尼）
阻止弹簧振荡的摩擦力。值越大，弹性衰减越快，到达目标后越快稳定。阻尼过高 = 动效变得迟钝。
mass（质量）
物体的"重"程度。值越大，运动越迟缓但有质感。按钮按压时用低质量让动效轻快；数字滚动时用高质量让它有分量感。
完全弹性 vs 临界阻尼
无阻尼 = 无限振荡（永远弹个不停）。阻尼过低 = 漂亮但略显不稳。临界阻尼 = 到达目标最快且无超调，是大多数交互的最佳选择。

痛点分析

现有方案的距离——为什么需要 beUI

不是现有方案"错了"，而是它们在动效这件事上留下了巨大的补足空间

方案 优点 动效方面短板 适合人群
shadcn/ui 无障碍、样式可定制、社区庞大 只提供静态 UI，无任何动画参数；需要自己引入 Framer Motion 需要完整 UI 组件库
Radix UI 无障碍 API 底层库，框架无关 Headless 无样式，动效完全由使用者实现 自定义样式需求强
Framer Motion 最强大的 React 动画库，API 完整 需要经验调参；跨组件物理一致性难以保证；AI Agent 难以写出自然动效 有经验的动效开发者
Tailwind Motion 原子化类名，快速添加预置动画 预置动画有限，无法覆盖复杂交互；无法自定义弹簧参数 需要简单过渡效果
beUI 复制粘贴即用、弹簧参数已调校、AI Agent 可读 AGENTS.md 需要先了解 motion（Framer Motion）基础；不是完整 UI 组件库 所有 React 开发者

shadcn/ui 的定位

shadcn/ui 是"组件库"，提供可复制的 UI 组件源码（Modal、Select、Tabs 等），让你拥有代码所有权而非 npm 依赖。但它故意不包含动画——那是另一个专业领域的决策。

beUI 与 shadcn 的关系 beUI 通过 shadcn 的注册表分发，使用相同的复制粘贴模式。你可以用 npx shadcn@latest add @beui/button 安装 beUI 组件——和安装 shadcn 组件的方式完全一样。

Framer Motion 的定位

Framer Motion 是 beUI 的底层引擎。beUI 不在 motion 之上做抽象封装，而是直接提供调校好的"配方"——你拿到的是已经验证过手感良好、可直接用于生产的动效组件。

你仍需要懂 motion beUI 是组件，不是黑盒。高级定制时仍需了解 motion 的 API。beUI 让入门变简单，但不阻止你深入。

核心机制

EASE / SPRING 统一物理参数——动效一致性的关键

beUI 的每个组件都使用同一套物理词汇表，让你的产品里所有动效"说同一种语言"

SPRING 参数家族——beUI 中每个组件都会用到

SPRING_PRESS
按钮按压反馈：刚度高、回弹快，用于模拟手指按下屏幕的短促有力感
SPRING_LAYOUT
布局变化动效（列表项移动、模态框展开）：平滑、有质感，不突兀
SPRING_PANEL
面板滑入滑出（Drawer、Bottom Sheet）：速度适中，有重量感
SPRING_MOUSE
连续跟随鼠标（磁吸按钮、光标跟随）：目标点实时更新，是持续跟随而非一次性过渡
SPRING_SWAP
文字/图标切换（按钮文字变化、Swap 组件）：模糊+滚动混合过渡
EASE_OUT
入场动画的标准缓动：开始快、减速停止，模拟物体自然减速的过程
EASE_IN_OUT
双向过渡：淡入淡出、展开收起等需要对称感的场景
EASE_DRAWER
抽屉滑动专属：开合有明显的"惯性感"，关合时比开时要略微快一点

实际使用示例——复制粘贴即可

// 方案 A：复制粘贴组件（推荐）— 物理参数已在组件内部定义 import { StatefulButton } from "@/components/motion/button"; // 直接使用，无需配置任何动画参数 <StatefulButton onClick={handleSubmit}> Submit </StatefulButton> // 方案 B：直接使用 SPRING token 自定义动画 import { SPRING_PRESS } from "@/lib/ease"; <motion.button transition={SPRING_PRESS} whileTap={{ scale: 0.96 }} > Press Me </motion.button>
reduced-motion 支持 beUI 所有组件内置 useReducedMotion() 检测。用户开启系统"减弱动效"时，动效自动降级为简单的透明度过渡，而非直接禁用功能。

🔘 按钮与触发器

Button 系列——不只是"点击"那么简单

按钮是用户接触最频繁的动效元素。beUI 的按钮系列不只是换个样式，而是每一种变体都代表一种不同的物理交互语言：StatefulButton 管理多步操作的状态流，MagneticButton 用 SPRING_MOUSE 实现磁吸效果。

📂 导航与布局

Dock（macOS 风格停靠栏） Animated Sidebar（折叠式侧边栏） Bounce Sidebar（弹跳点导航） Tabs（胶囊/段落/下划线指示器） Expandable Tabs（图标 Tab 栏展开为标签） Preview Rail（悬停预览导航）

可组合的消息组件（气泡、头像、头部、尾部、标记），搭配 MessageBubbleCollapsible 处理长回复的展开收起。

Agent 工作台核心

🚀 ChatApp（工作台外壳）

完整的 AI 工作台外壳，整合侧边栏、消息流、输入框、流式输出、Approval 决策卡、代码块、文件 diff、工具结果等全部子组件。开箱即用，可直接定制品牌样式。

📂 AI Sidebar（侧边栏）

文件树/文件夹/项目/书签管理侧边栏，支持整行拖拽排序、键盘移动、乐观回滚、内联重命名、悬停菜单、打开文件夹图标和溢出滚动标签。

工具与执行结果

📝 Code Block

语法高亮的代码展示组件，支持流式输出的稳定更新（不闪屏）、行号显示、焦点行高亮、文件路径/语言元数据、复制反馈。

📊 File Diff

渐进式文件变更展示，支持语法高亮、稳定行号显示、实时增删计数、流式更新时的平滑跟随、复制和折叠完成状态。

⚙️ Tool Result

终端输出/请求结果展示，有界自动跟随输出、成功/错误/取消状态、完成折叠、复制和重试操作。

决策与加载

✅ Approval Card（审批卡）

人机决策界面：批准/拒绝/修订操作，支持单选题、多选、自由输入或多步骤问题。状态降级为折叠展示时仍保持 reduced-motion 过渡动画。

⏳ Loading States

三种 Agent 加载状态：ThinkingShimmer（思维 shimmer）、AgentProgress（紧凑实时进度）、ReasoningText（ASCII 加载 + 文字闪烁）。每种变体均可独立安装，reduced-motion 安全。

上手教程

三步开始使用 beUI——从零到生产级动效

假设你已有 Next.js 15 + Tailwind CSS 4 项目

Step 1：安装一个组件（以 StatefulButton 为例）

# 使用 shadcn CLI（推荐） npx shadcn@latest add @beui/button # 或直接通过 URL 安装（无需查组件名） npx shadcn@latest add https://beui.dev/r/button.json # 查看所有可用组件 npx shadcn@latest add @beui # 本地预览所有组件 bun install bun run dev # 打开 http://localhost:3000 查看交互式预览

Step 2：在你的组件中使用

// components/Demo.tsx "use client" import { StatefulButton } from "@/components/motion/button" import { AnimatePresence } from "motion/react" export function SubmitButton({ onSubmit, onError, }: { onSubmit: () => Promise<void> onError: () => void }) { return ( <StatefulButton idleText="Submit" loadingText="Submitting..." successText="Done!" errorText="Failed — Retry" onClick={ async () => { try { await onSubmit() } catch { onError() } } } /> ) }

Step 3：组合多个组件构建完整界面

// components/AgentChat.tsx — 使用 AI Agent 组件构建对话界面 "use client" import { ChatApp, MessageBubble, MessageScroller, PromptInput, CodeBlock, ApprovalCard, ToolResult, LoadingStates, } from "@/components/agents" // 完整使用示例（来自 AGENTS.md） export function AgentChat({ initialMessages }: { initialMessages: Message[] }) { return ( <ChatApp> <MessageScroller initialMessages={initialMessages}> {{ message.map(msg => ( <MessageBubble key={msg.id} role={msg.role} content={msg.content} /> )) }} </MessageScroller> <PromptInput onSubmit={handleSubmit} onStop={handleStop} modelState={modelState} /> {/* Approval Card: AI 请求人类决策 */} <ApprovalCard question="确认执行删除操作？" options={[{ label: "批准", value: "approve" }, { label: "拒绝", value: "reject" }]} onAnswer={handleApproval} /> <ToolResult output="Running npm install..." status="loading" /> </ChatApp> ) }
减少动效（Reduced Motion） beUI 所有组件均支持 useReducedMotion()。在系统设置中开启"减弱动态效果"后，弹簧动画自动降级为简单的透明度过渡，不影响功能可用性。这是 beUI 遵守 WCAG 2.1 AA 无障碍标准的方式。

开发规范

beUI 代码规范——来自 AGENTS.md 的最佳实践

beUI 团队在 AGENTS.md 中记录了大量实战经验，以下是最重要的几条

叠加层（Overlay）的三大陷阱

beUI 的 AGENTS.md 专门用一整节讲 overlay 陷阱：

陷阱 1：pointer-events gating overlay 在退出动画期间 open=false 但 DOM 元素还在，用户可以点击已"关闭"的 overlay。使用 PresenceGate 在 exit 开始时立即移除 pointer events。
陷阱 2：fixed 定位在 iOS Safari iOS Safari 下，fixed 元素相对于最近的滚动祖先定位，而非视口。beUI 要求所有 overlay 层渲染在 body portal 下，避免嵌套滚动容器的影响。
陷阱 3：backdrop 必须 paint 每个 fixed overlay 层必须渲染实色背景或空子元素，否则 fixed 定位可能不生效（sweep test 检查这一项）。

列表活跃项的两种方式

识别列表中哪个选项"活跃"（高亮/焦点指示器）：

方式 1（推荐）：在 render 期间确定 用函数式 update 计算光标位置——React render 阶段完成，不会有"错误行先显示再修正"的闪烁。
方式 2（禁止）：在 useEffect 中确定 useEffect 是在 commit 后异步运行，会导致列表首次渲染时光标位置错误，用户按方向键时作用在错误行上。

TypeScript 严格模式 + Biome linting

# 本地类型检查 bun run typecheck # tsc --noEmit # 代码风格检查 bun run lint # biome # 组件注册表验证（新增组件必跑） bun run check:registry # 完整检查（提交前必跑） bun run check
Biome 的 a11y 规则很严格 不要在 div/span 上使用冗余 ARIA role，用真实的 <button> 和 <a> 标签。DockItem 在有 onClick 时渲染 <button>，否则渲染 div 包装——永远不嵌套交互元素。

安装

立即开始——三种方式使用 beUI

方式 A：shadcn CLI（推荐）

npx shadcn@latest add @beui/button
npx shadcn@latest add @beui/dock
npx shadcn@latest add @beui/modal
# 查看全部可用组件
npx shadcn@latest add @beui
通过 shadcn 官方注册表分发，安装方式与 shadcn 组件完全一致

方式 B：URL 直接安装

npx shadcn@latest add \
  https://beui.dev/r/button.json

# 获取组件源码（无需安装包）
curl https://beui.dev/r/button/raw
跳过注册表搜索，直接通过 slug URL 安装特定组件

方式 C：AI Agent 专用 skill

# Claude Code / Codex 专用 skill
npx skills add starc007/ui-components \
  --skill beui

# Pro 版 skill（需购买）
npx skills add starc007/ui-components \
  --skill beui-pro
安装后，Claude Code/Codex 在处理 React 项目时自动识别并推荐使用 beUI

本地开发

# 克隆并本地运行预览站
git clone https://github.com/\
  starc007/ui-components

cd ui-components
bun install
bun run dev

# 打开 http://localhost:3000
# 查看所有组件的交互式预览

# 提交前检查
bun run check
预览站展示所有组件的真实效果，是最好的学习资料
