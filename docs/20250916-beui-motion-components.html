PROBLEM

Motion UI is the hardest part of product dev

Traditional component libraries give you static UI. Framer Motion is powerful but requires deep expertise and time investment.

Static UI only

Component libraries miss motion

shadcn/ui, Radix UI, and Headless UI ship accessible primitives — but no spring physics. You get the skeleton, not the soul of the interaction.

Deep expertise

Framer Motion is powerful but hard

Writing type SpringConfig, tuning stiffness/damping/mass, and getting consistent physics across 20 components is a full-time job.

AI agents struggle

Even AI can't hand-roll physics

AI coding agents produce functional code but often generate duration: 0.3 tweens instead of natural spring physics — stiff, robotic transitions.

SOLUTION

Copy-paste source with physics baked in

beUI ships production-quality spring tokens and exact animation configs — every component uses the same physics vocabulary.

EASE & SPRING TOKENS — use these consistently across all components
EASE_OUT
Default entrance easing — natural deceleration curve for enter animations
SPRING_PRESS
Button press / click feedback — snappy, immediate spring
SPRING_LAYOUT
Layout shift animations — smooth re-flow when items move
SPRING_HOVER
Hover state transitions — subtle lift with bounce
// Copy-paste this — physics is already tuned
const transition = {
  type: "spring",
  stiffness: 400,
  damping: 25,
  mass: 0.8,
}

INSTALL

Get started in seconds

Use the shadcn CLI or add the Claude Code/Codex skill — two paths to production-ready motion.

shadcn CLI — per component

npx shadcn@latest add @beui/button
npx shadcn@latest add @beui/dock
npx shadcn@latest add @beui/modal
or via slug: npx shadcn@latest add https://beui.dev/r/button.json

Claude Code / Codex skill

npx skills add starc007/ui-components \
  --skill beui
Installs the AGENTS.md skill so your AI coding agent knows how to use beUI automatically
