01

什么是 AI Coding Agent

Codex 和 Claude Code 的定位与核心差异

AI Coding Agent 是能在终端中自主完成复杂编码任务（读文件、写代码、执行命令、Git 操作、浏览网页）的智能体。 区别于 Copilot 这类补全插件，它们能通读整个代码库、自主规划路径、跨文件修改并验证结果。 更重要的是：这两款工具同样适合做深度信息调研——让 AI 帮你搜索、阅读、整理、输出报告。

🔍

Codex CLI（OpenAI）

2025年4月开源发布，轻量级终端编码智能体。最大化 o3 / o4-mini 等推理模型能力，支持多模态输入，可在本地读写文件、执行命令。

🤖

Claude Code（Anthropic）

2025年2月发布，终端原生全链路编程智能体。深度集成 Claude 3/4 模型，支持 MCP 扩展、Slash Command、Plan Mode 等高级功能。

📊

共同优势：调研能力

两者均可调用 Web 搜索、读取文件/URL、编写脚本、生成报告，一条指令完成从信息收集到结论输出的全流程。

02

前置准备

安装、API Key 配置、权限模式设置

🟠 Codex 安装

npm 全局安装或 Homebrew 安装

# npm 安装 npm install -g @openai/codex # 或 Homebrew brew install --cask codex # 启动 codex

配置文件：~/.codex/config.toml + ~/.codex/auth.json

🔵 Claude Code 安装

npm 全局安装或 Claude 官方包

# npm 安装 npm install -g @anthropic-ai/claude-code # 启动 claude # 认证状态 claude auth status

API Key：环境变量 ANTHROPIC_API_KEY 或交互式输入

💡 权限模式选择

Codex 和 Claude Code 都有权限/审批模式。调试敏感项目时用 Read Only，自动化脚本执行时用 Full Access。 Codex：/approvals 切换；Claude Code：CLAUDE.md 控制行为边界。

04

调研 SOP 流程

搜索 → 整理 → 分析 → 输出的四步工作流

无论使用 Codex 还是 Claude Code，调研的核心工作流遵循同一套 SOP： 明确目标 → 分步执行 → 验证输出。 区别在于命令语法和交互细节，底层逻辑完全一致。

1

明确目标 + 提供上下文

开始调研前，先给 Agent 足够清晰的背景信息。上下文越充分，输出质量越高。

①
描述调研目标：你想了解什么？期望输出什么格式？（技术报告、竞品对比、选型建议……）
②
指定输出格式：「请用 Markdown 输出，包含目录、各章节小结和参考资料列表」
③
提供参考文档路径：如果有本地文档或上下文文件，用 @ 引用（如 @docs/research-brief.md）
④
建立项目记忆：Claude Code 用 /init 生成 CLAUDE.md，Codex 用 /init 生成 AGENTS.md，让 Agent 永久记住项目规范
Claude Code / Codex /init # 初始化项目记忆文件 → 请在当前目录生成 CLAUDE.md（Claude Code）或 AGENTS.md（Codex），包含： 项目背景、输出规范（Markdown格式/章节要求）、禁止行为约束
2

分步执行：Search → Read → Analyze → Summarize

不要让 Agent 一次性完成所有工作。用分步指令让每一步都可控、可验证。

①
Search（搜索）：让 Agent 搜索目标主题的相关信息，给出多个信源
②
Read（阅读）：让 Agent 读取关键网页、文档，提取核心数据和观点
③
Analyze（分析）：让 Agent 对比不同来源，给出优劣分析和趋势判断
④
Summarize（输出）：让 Agent 按指定格式生成最终报告，写入文件
Claude Code → @research-brief.md 请帮我调研 LLM Agents 2026年最新进展 1. 用 Web 搜索找到 5 个核心信源 2. 读取并比较各信源的技术路线 3. 用 Markdown 格式输出报告到 docs/llm-agents-2026-report.md
Codex → @brief.txt research "LLM Agents 2026 latest developments" - search web for 5 key sources - read each source and extract key findings - output report to llm-agents-report.md in Chinese
3

结果验证与输出

AI 输出需要人工验证。关键信息要求 Agent 提供引用来源，并交叉验证数据。

①
引用来源验证：要求每条关键结论标注来源 URL，无法验证的声明需注明「待核实」
②
数据交叉对比：让 Agent 对比多个来源的同一数据点，如不一致明确标注差异
③
格式规范检查：让 Agent 自我审查：是否符合 CLAUDE.md 中的格式规范？
④
文件写入确认：最终报告写入目标文件，检查内容完整性
Claude Code / Codex → 请检查刚生成的报告： 1. 每条关键结论是否都有 URL 来源？ 2. 数据点是否有交叉验证？ 3. 格式是否符合 CLAUDE.md 规范？ 如有问题请直接修正。
05

Codex 调研命令速查

OpenAI Codex CLI 核心命令与调研场景用法

⚙️ 基础命令

codex # 启动交互式会话 codex ./project # 指定项目目录启动 /help # 查看所有命令 /status # Token 使用量、上下文状态 /model # 切换 GPT 模型（o3/o4-mini/4o） /compact # 压缩对话历史，释放 Token

🔍 调研命令

/init # 初始化 AGENTS.md 项目记忆 /mcp # 管理 MCP 工具连接 /websearch # 触发 Web 搜索（需配置 MCP） /read <url/file> # 读取网页或本地文件 /write <path> # 写入调研报告到文件 /exec <cmd> # 执行 Shell 命令（脚本/工具）
💡 Codex 调研 Prompt 示例

research "your topic" -sources 5 -format markdown -output report.md
Codex 支持自然语言指令组合搜索、读取、写入操作。用 @ 引用本地文件作为上下文。

Claude Code 调研命令速查

Anthropic Claude Code CLI 核心命令与调研场景用法

⚙️ 基础命令

claude # 启动交互式会话 claude ./project # 指定项目目录启动 /help # 查看命令列表 /status # Token 剩余量、权限模式 /cost # 当前会话费用统计 /model # 切换模型（Sonnet/Opus/Haiku）

🔍 调研命令

/init # 初始化 CLAUDE.md 项目记忆 /compact # 压缩对话历史 /memory # 编辑会话记忆文件 /plan # 进入 Plan Mode，规划任务步骤 /doctor # 环境健康检查（MCP 连接等） -r 关键词 # 恢复历史会话（调研中断续） -c # 继续上次对话
💡 Claude Code 调研 Prompt 示例

请调研 "AI Agent Memory Frameworks 2026"，用 Web 搜索找到 5 个核心信源，读取并比较，输出 Markdown 报告到 docs/agent-memory-2026.md，包含参考链接列表。
Claude Code 的 Web 搜索和浏览是原生功能，无需额外 MCP 配置即可直接搜索网页。

07

进阶技巧

多轮对话、文件上下文、Prompt 工程

📂 文件上下文引用

用 @ 引用本地文件或 URL，让 Agent 在具体上下文中分析，避免「幻觉」。 Claude Code 支持 @ 引用多个文件，Codex 支持 @ 和 @@ 多级引用。

→ @docs/brief.md @github.com/xxx 基于这两个文件做调研报告

🔁 多轮对话迭代

不要期望一次性拿到完美报告。用迭代式调研：先拿到大纲 → 补充细节 → 验证数据 → 最终输出。 Claude Code 的 /plan 模式最适合做这种结构化迭代。

🎯 Prompt 工程技巧

角色设定：「你是一位资深技术分析师，负责……」
约束条件：「只输出有来源的数据，禁止虚构」
格式指令：「用 H2/H3 分级，表格对比，末尾附参考文献」

🔌 MCP 扩展能力

两者均支持 MCP（Model Context Protocol）。Claude Code 的 MCP 生态更成熟， 可连接数据库、浏览器、Slack、GitHub Actions 等。 Codex 的 MCP 支持在快速发展中。

📊 会话管理与恢复

调研任务耗时很长时，用 claude -r "关键词" 或 claude -c 恢复会话， 避免从头开始浪费 Token。Codex 同样支持会话历史管理。

🧠 Token 预算管理

/compact（Claude Code）或对应命令压缩历史，避免上下文溢出。 调研大型项目时，定期 /compact 总结中间成果后再继续。

适用场景清单

哪些调研任务适合用 AI Coding Agent 完成

✅ 非常适合

  • 技术栈选型调研（对比工具优劣）
  • 开源项目深度分析（代码 + 文档 + 社区）
  • API 文档研究与集成方案设计
  • 竞品技术路线对比报告
  • Bug 追踪与修复方案调研
  • AI/LLM 最新进展文献综述
  • DevOps 工具链选型调研

⚠️ 需要注意

  • 需要一手采访/一手数据的市场调研（AI 无法替代）
  • 高度敏感的商业机密信息（权限控制要到位）
  • 实时股价/精确统计数字（AI 数据可能有延迟）
  • 法律/医疗等专业领域（需专家复核）
  • 需要验证的多来源数据（交叉核实不可少）
  • 极长程调研（建议分多次会话，分段输出）
🏆 选型建议

Claude Code 更适合需要原生 Web 搜索 + Plan Mode + MCP 扩展的深度调研任务； Codex 更适合代码密集型调研（结合 o3 强推理能力做代码分析）。 两者配合使用效果最佳：用 Claude Code 做信息收集和报告生成，用 Codex 做代码层面的深度分析。
