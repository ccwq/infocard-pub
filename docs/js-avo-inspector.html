Avo Inspector · JS SDK

Web / React Native 的事件 Schema 监控与 Tracking Plan 校验工具

Avo Inspector 不是埋点代码生成器，而是“埋点质量监控层”：自动抽取事件 schema、在 Dev/Staging 校验属性是否符合 Tracking Plan，并支持属性加密与轻量版构建。

02
Core APIs

三个关键接口，覆盖“抽取—上报—仅提取”

从写作视角看，Avo Inspector 的 API 很适合被概括成一个闭环：自动抓取 schema、手动上报 schema、只做本地提取。

1 / 自动

trackSchemaFromEvent(name, props)

推荐入口，自动从事件参数提取 schema 并上报。

2 / 手动

trackSchema(name, schema)

直接传 schema 数组，更适合已有治理逻辑的团队。

3 / 本地

extractSchema(props)

仅提取，不上报；适合做预检或调试。

精简版

avo-inspector/lite

3.1.0+ 生产轻量包，约 20 KB min / 5.2 KB gzipped。

03
What makes it different

不是“再做一个埋点 SDK”，而是把数据质量前移

这张卡的重点不在功能堆叠，而在方法论：把埋点 schema 的错误从数据平台末端，前移到开发阶段和客户端运行时。

1

Dev / Staging 实时验证

对接 Tracking Plan，按类型、必填、正则、数值范围等规则做客户端校验。

2

属性值 ECC 加密

使用 ECC（prime256v1 / NIST P-256）加密属性值，Avo 无法读取私钥。

3

Production 轻量化

Lite build + gzip track 请求体，适合把开销压到更低的 GTM 场景。

04
Release note

3.2.0 的关键变化：请求体 gzip 压缩

最新发布把 track 请求体压缩这件事做到了浏览器原生能力上，优先使用 CompressionStream API，旧浏览器自动降级。

3.2.02026-06-23

更新重点

当请求体超过约 1KB 时启用 gzip，网络传输量显著下降，官方说明约可减少 10x 开销。

05
Takeaway

一句话总结

如果 Avo Codegen 负责“把规范写进代码”，Avo Inspector 负责“把规范守住”，两者合起来才是完整的埋点治理链路。

结论：Avo Inspector 更像埋点质量网关，而不是单纯的 SDK；它的价值在于将 schema 校验、隐私加密、生产轻量化三件事打包成一条可执行的工程路径。
