01 / 语音工程笔记

它是什么：房间里的服务端参与者

先记住这一点

LiveKit Agents 不是网页聊天 UI，也不是一个语音模型。

框架用于创建运行在服务端、可编程的实时参与者。客户端通过 LiveKit 的 WebRTC SDK 加入房间，Agent 在同一实时媒体链路中听、说，并可处理多模态输入。

  • Python 主仓库：livekit/agents。JavaScript / TypeScript 另有 livekit/agents-js。
  • 媒体服务器、Agent 进程、模型服务和客户端是不同组件。
  • 电话接入建立在 LiveKit Telephony / SIP 栈上，不是仅安装 pip 包就得到电话号码。

推文中的“能看见画面”是框架多模态能力。具体视觉效果取决于输入流、模型和应用如何接入，不是所有语音模型都支持图像。

02 / 语音工程笔记

先区分四个核心对象

先记住这一点

把调度、会话和业务指令分开，才能排查故障。

  • Agent：包含业务指令、工具与行为的 LLM 应用。
  • AgentSession：承载用户交互，管理语音管线与 Agent。
  • entrypoint：用户会话开始时的处理入口。
  • AgentServer：主进程，协调任务调度并启动会话。

README 将 entrypoint 类比为 Web 服务器请求处理器。AgentServer 并不替代 LiveKit 媒体服务器；二者需要通过连接信息协作。

03 / 语音工程笔记

级联语音链：STT → LLM → TTS

先记住这一点

可替换插件让你独立选择识别、推理和声音。

  • STT（语音转文字）：将用户语音转成转录。
  • LLM：根据上下文生成回答，也可调用业务工具。
  • TTS（文字转语音）：把回答生成音频并播出。
  • VAD：检测语音活动，是话轮判断的一部分，但不等于理解句子是否讲完。

README 展示 Deepgram、OpenAI、Cartesia 等插件，也展示 LiveKit Inference 统一接口。插件可替换不等于各供应商功能和参数完全一致。

识别错字、模型首 token 延迟、TTS 起音和网络抖动都会影响体验。此卡不提供未经实测的端到端延迟数字。

04 / 语音工程笔记

另一条路线：Realtime 模型

先记住这一点

语音原生模型改变管线，但没有消除话轮和业务边界。

Realtime 模型可把实时音频输入与输出交给同一个模型服务。框架仍负责会话、媒体接入、工具与生命周期。

  • 当前官方文档同时覆盖级联和 Realtime 模式。
  • 使用服务端话轮检测时，模型决定用户是否在打断。
  • 会话级部分 interruption 配置在该模式下不适用，应调模型自身参数。
  • 当前文档注明：服务端检测开启时把 interruption.enabled 设 False 会导致会话启动 ValueError。

不要把级联模式的调参建议原样套到 Realtime 模型。先明确所用 SDK 版本和模型检测模式。

05 / 语音工程笔记

话轮检测：沉默不等于说完

先记住这一点

要分清语音活动、句尾信号和语义上的回合结束。

官方文档列出五种路径：turn detector model、Realtime 模型、VAD only、STT endpointing、manual turn control。模型路径可结合语音含义与声学特征，VAD 辅助时间边界。

  • 普通对话：官方推荐 turn detector；文档当前说明 AgentSession 默认启用 audio turn detector。
  • 追求极低延迟或语言覆盖不足：考虑 VAD only，仍需真实测试停顿。
  • STT 自带 endpointing：例如相应供应商能力，不代表所有 STT 都有同等效果。
  • 按住说话：采用明确的手动边界。
  • min_delay / max_delay 影响停顿后的等待；Python 支持动态 endpointing。

推文强调 transformer 判断结束。它并不保证所有语言、噪声、口音或停顿都被正确识别。

06 / 语音工程笔记

打断：既要让用户插话，也要识别附和

先记住这一点

“嗯”“对”不一定表示用户要抢回话轮。

Adaptive interruption handling 用于区分真正的打断与 conversational backchanneling。误打断处理、背景噪声消除和 VAD 都会影响自然度。

  • 测试用户喘气、长停顿、改口与背景说话。
  • 测试 Agent 正在播报时的插话。
  • 检查中止后的音频、对话上下文和工具状态是否一致。
  • Realtime server-side detection 应按模型文档设置阈值与静音窗口。

不要为了“少抢话”一味拉长等待时间。应分别记录响应延迟、误打断和漏打断；此卡没有替你测量这些指标。

08 / 语音工程笔记

Python 最小示例：明确哪些依赖 Cloud

先记住这一点

这里按仓库 README 示例展示；voice ID 替换为明确占位符，不是生产客服实现。

from livekit.agents import (
    Agent,
    AgentServer,
    AgentSession,
    JobContext,
    RunContext,
    cli,
    function_tool,
    inference,
)


@function_tool
async def lookup_weather(
    context: RunContext,
    location: str,
):
    """Used to look up weather information."""

    return {"weather": "sunny", "temperature": 70}


server = AgentServer()


@server.rtc_session()
async def entrypoint(ctx: JobContext):
    session = AgentSession(
        vad=inference.VAD(),
        # any combination of STT, LLM, TTS, or realtime API can be used
        # this example shows LiveKit Inference, a unified API to access different models via LiveKit Cloud
        # to use model provider keys directly, replace with the following:
        # from livekit.plugins import deepgram, openai, cartesia
        # stt=deepgram.STT(model="nova-3"),
        # llm=openai.LLM(model="gpt-4.1-mini"),
        # tts=cartesia.TTS(model="sonic-3", voice="YOUR_CARTESIA_VOICE_ID"),
        stt=inference.STT("deepgram/nova-3", language="multi"),
        llm=inference.LLM("google/gemma-4-31b-it"),  # low-latency gemma, hosted on LiveKit
        tts=inference.TTS("cartesia/sonic-3", voice="YOUR_CARTESIA_VOICE_ID"),
    )

    agent = Agent(
        instructions="You are a friendly voice assistant built by LiveKit.",
        tools=[lookup_weather],
    )

    await session.start(agent=agent, room=ctx.room)
    await session.generate_reply(instructions="greet the user and ask about their day")


if __name__ == "__main__":
    cli.run_app(server)

README 要求 LIVEKIT_URL、LIVEKIT_API_KEY、LIVEKIT_API_SECRET。示例中的 inference.STT / LLM / TTS 使用 LiveKit Inference，模型名与声音 ID 应以当前服务支持为准。

lookup_weather 返回固定 sunny / 70，是示例占位数据，不调用天气 API。不能当真实天气查询上线。

pip install "livekit-agents[openai,deepgram,cartesia]"

以上 pip 命令是 README 的插件安装示例。直接供应商插件还需相应供应商凭据；不要把密钥放到前端或提交到 Git。

09 / 语音工程笔记

工具调用与 MCP：赋予能力，也引入权限

先记住这一点

工具调用必须有明确输入、授权与失败处理。

README 展示 @function_tool 的 Python 工具，并声明原生 MCP 集成。MCP 用来接入工具服务器，不等于工具自动安全。

  • 语音 Agent 的 runtime MCP：提供业务查询、动作等工具。
  • LiveKit Docs MCP：给 Claude Code 等开发助手查询文档和源码；与用户运行时工具不是同一用途。
  • 先使用只读查询工具，再引入订单、取消、支付等写操作。
  • MCP 超时、工具异常、认证失败要明确反馈，不口头声称成功。

本卡不提供猜测的 MCP 构造参数。README 的一句话能力声明不能替代当前 API 文档与可用服务器配置。

10 / 语音工程笔记

电话链路：SIP、运营商、房间和调度

先记住这一点

电话不是零配置：框架接得上，号码与中继仍需准备。

LiveKit Telephony 通过 SIP 把真实电话接入实时房间。来电与去电需要相应 trunk、呼叫配置和号码服务；Agent 加入房间执行对话。

  • 入站：运营商将来电路由到 SIP，按调度规则接入房间。
  • 出站：应用发起呼叫，需合适的 outbound trunk 与目标号码。
  • 同一房间媒体模型不代表 PSTN 费用消失。
  • 拨号、录音、外呼频率与告知义务受业务所在地规则影响。

推文的“几十行就有客服”描述开发起点。生产还需要身份验证、异常转人工、业务系统、线路质量和合规边界。

11 / 语音工程笔记

测试：事件断言与模型裁判

先记住这一点

文本会话测试不能证明麦克风、SIP 与打断表现。

README 测试例使用 pytest、AgentSession.run(user_input=...)，逐个断言工具调用、工具输出和回复事件；judge 检查回复意图。

@pytest.mark.asyncio
async def test_no_availability() -> None:
    llm = google.LLM()
    async with AgentSession(llm=llm) as sess:
        await sess.start(MyAgent())
        result = await sess.run(
            user_input="Hello, I need to place an order."
        )
        result.expect.skip_next_event_if(type="message", role="assistant")
        result.expect.next_event().is_function_call(name="start_order")
        result.expect.next_event().is_function_call_output()
        await (
            result.expect.next_event()
            .is_message(role="assistant")
            .judge(llm, intent="assistant should be asking the user what they would like")
        )
  • 示例含 MyAgent、google、pytest 等未展示定义，是片段不是独立可运行完整文件。
  • 工具名称、事件顺序等确定性断言适合回归。
  • judge 本身是模型判断，需可重复标准，并注意费用与不确定性。
  • 真实音频识别、网络抖动、电话音质、打断和端到端时延另做集成验收。

本卡源码片段已进行 Python 语法解析，不宣称模型连接或电话链路已实测。

13 / 语音工程笔记

自托管：你能接管栈，不代表所有服务离线

先记住这一点

媒体、Agent、SIP、模型和运维分别算成本。

README 明确整个开源栈可运行在自己的服务器，包括 LiveKit server。要离线或掌控数据路径，模型服务、网络和电话接入也要分别安排。

  • 媒体服务器：信令、WebRTC 和网络可达性。
  • Agent 运行环境：任务调度、进程、插件与资源。
  • 模型端：使用外部 STT/LLM/TTS 仍会传输数据并产生费用；自建推理另算 GPU/CPU。
  • 电话端：SIP 组件与运营商资源，不由 Agent SDK 包含全部成本。
  • Cloud 增强噪声消除等配置不一定适用于自托管。

开源 Apache-2.0 不等于模型 API、电话或云托管免费。此卡不承诺“本地部署后数据永不出站”。

14 / 语音工程笔记

生产前验收：不要只看能对话

先记住这一点

把失败条件写成可复现用例。

  • 冷启动、模型故障、STT 停顿、TTS 起音失败和连接断开。
  • 用户插话、噪声、长沉默、改口，以及多语言切换。
  • 工具重试和幂等性：是否重复下单或取消。
  • 手机号、录音、转录和日志的访问与保留策略。
  • 线程/任务资源、限流、负载与退出清理。
  • 客服应允许拒绝、转人工或结束，不让错误回答无限重试。

这些是本页工程验收建议，不是对项目缺陷的已验证指控。先确定业务可接受标准，再采集真实线路证据。
