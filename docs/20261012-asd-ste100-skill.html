「写给人看的话和写给 agent 看的话，真不是一回事。」

核心论点：ASD-STE100 把航空维修手册那套写话规矩搬来，管住了模型输出质量。

实测痛点：一句话塞三个意思，模型要么挑错一个、要么全忽略，排查半天才发现是自己写得含糊。

改写效果：事实、条件和限定语都保留，只标出歧义并改写，不丢精度。

两档规则：严格档用于流程/报错/工具描述；宽松档用于 README/PR 描述。

🤕② 痛点：Agent 读 Agent 输出，无法回问

人读手册读不懂，可以回头问作者。Agent 读另一个 Agent 的输出，读不懂只能猜——猜错就走向错误方向，调试成本极高。

三种最常见的歧义场景

一句塞三意

「Please check the file, update the log, and notify the team if there's an error」
→ 模型可能只执行第一个指令，其余全部忽略，或者按错误顺序执行。

被动语态无主语

「The config should be updated」
→ 谁更新？什么时候更新？更新成什么值？Agent 无法从文本中反推出这些关键信息。

短语动词多义

「Spin up the service and circle back with the results when done」
→ spin up 是启动还是加速？circle back 是报告还是等待？Agent 在没有上下文的指令流里会做出错误假设。

✈️ 航空类比

机务人员读维修手册，手册必须零歧义——否则飞机上天要出人命。Agent 之间的指令同样需要这种级别的清晰度。

🔁 反馈通道缺失

人与人通信可以追问、确认、澄清。Agent 间没有这个通道，所以写给 Agent 的话必须比写给人看的话更精确。

核心矛盾：人写给人看的自然语言充满省略、指代和语气，而这种"模糊"在 Agent 通信中是不可接受的。ASD-STE100 的价值在于把这套从航空领域提炼出来的规则引入 Agent 写作。

📖③ ASD-STE100 是什么

ASD-STE100 是航空/国防行业标准（asd-ste100.org），原始目的是让非母语机务人员读维修手册不产生歧义。在航空和国防领域已经使用了数十年。

7 条核心规则详解
① 主动语态 Active voice

主语执行动作，消除"谁做了什么"的模糊。被动语态把动作对象放在主语位置，Agent 必须从上下文反推执行者。

❌ "The file should be deleted by the script"

✓ "The script deletes the file"

② 简单时态 Simple tenses only

只用现在时/过去时/将来时，避免完成时和进行时带来的时序歧义。

❌ "The file has been updated, the log should be updated"

✓ "Update the file. Update the log."

③ 一句一事 One instruction per sentence

一个句子只含一个指令，避免模型选择性忽略或错误组合。

❌ "Check the file, update the log, and notify the team"

✓ "Check the file. Update the log. Notify the team."

④ 不省略词 No dropped words

不省略介词、冠词、定冠词，保证每个词都有明确指代。

❌ "Run the script. Check output."

✓ "Run the script. Check the output."

⑤ 一词一义 One meaning per word

同一个词在同一语境只能有一个含义，不产生多义干扰。

❌ "Set the run flag. If the flag is set, skip the run."（flag 一词两义）

✓ "Set the run flag to true. If the run flag is true, skip the run."

⑥ 短句 Short sentences

句子尽量短，降低理解难度和解析错误率。每个句子一个清晰的动作或陈述。

❌ "Before updating the configuration file, ensure that the service is stopped and the backup has been created and verified, then proceed with the update."

✓ "Stop the service. Create a backup. Verify the backup. Update the configuration file."

⑦ 禁用特定词汇 No nominalizations / phrasal verbs / marketing adjectives

禁用名词化动词（make a decision → decide）、短语动词（spin up → run/start）、营销形容词（awesome/powerful/seamless）。

❌ "This awesome tool helps you kick off your workflow by leveraging powerful automation capabilities."

✓ "This tool starts your workflow by using automation. The automation runs tasks without manual input."

版权说明：ASD 官方约 900 词核准词表未转载（标准可免费获取但不可免费转载，未获授权）。7 条核心规则是公开规范，不受此限制。守规矩反而更可信。

🛠️④ 这个 Skill 做什么

输入任意英文文本 → 逐句标注违规 → 确定性重写 → 输出纯改写文本（保留事实/条件/限定语，不丢精度）。

🔴 Strict 模式

适用：流程步骤、报错文案、工具描述

规则锁定最严：主动语态 + 简单时态 + 一句一事 + 无短语动词 + 无名词化

🟢 STE-flavored 模式

适用：README、PR 描述、说明性文字

保留句式纪律，但词汇不必锁定——适合需要一定可读性的说明场景

处理步骤（4 步）
  1. 选模式：Strict 或 STE-flavored
  2. 逐句扫描：标注歧义词 / 复杂时态 / 被动语态无主语 / 多指令句 / 省略词 / 超长句 / 短语动词 / 名词化 / 分号 / 模糊修饰语
  3. 确定性重写：针对每处违规输出改写句子，保留事实、条件、限定语
  4. 输出：纯改写文本（无前缀、无模式声明、无变更摘要）。如故意不改写则输出「Kept as-is:」一行。
触发词示例
「Disambiguate this tool description」 「Apply ASD-STE100 to this instruction」 「reduce ambiguity in this output」

🔄⑤ Before / After 改写示例

三个真实改写场景，展示「主动语态 + 短句 + 不省略词」的效果。

❌ 原文（被动 + 多指令 + 省略词）
The configuration file should be checked and updated by the agent, then the log should be updated to reflect the changes made.
✅ 改写后（ASD-STE100）
Check the configuration file. Update the configuration file. Update the log. These updates reflect the changes made.
❌ 原文（短语动词 + 多义 "circle back"）
Spin up the service and circle back with the results when done.
✅ 改写后（ASD-STE100）
Run the service. Report the results after the run completes.
❌ 原文（名词化 + 营销形容词 + 模糊表述）
This awesome tool helps you kick off your workflow by leveraging powerful automation capabilities.
✅ 改写后（ASD-STE100）
This tool starts your workflow by using automation. The automation runs tasks without manual input.
效果说明：改写后每句只有一个指令，主语明确，动词具体，Agent 不会再选择性忽略或错误理解。注意事实内容完全保留（configuration file、log、automation capabilities），只是表述方式变得无歧义。

🔍⑥ 确定性检查器 ste-lint.py

自动化检查脚本，对英文文本做确定性违规检测——不需要 AI 判断，基于规则匹配，输出结果完全可复现。

检查项目（全部确定性，非概率判断）
分号连接独立从句 软性短语动词 名词化 营销形容词 被动语态 现在完成时 超长句 悬空连词
软性短语动词清单（部分）
spin up reach out dive into kick off circle back touch base
不检查项：名词簇长度（需 POS 词性标注）、列表外软性短语动词、模糊修饰语堆叠。这些项目需要更复杂的 NLP 分析，超出确定性规则匹配范围。

⚖️⑦ 版权立场：守规矩反而更可信

没有复制 ASD 官方 900 词核准词表。

ASD-STE100 标准可免费获取，但不可免费转载。本 Skill 未获授权复制词表，因此没有照搬。7 条核心规则是公开规范，不受此限制。

守规矩反而更可信：不依赖版权词表，靠规则本身就能实现高质量改写。

这个选择也体现了 ASD-STE100 本身的精神：用规则而非词汇表来约束语言。规则是可描述、可验证的，比词汇表更透明，也更容易被 Agent 理解和执行。

✅ 适合场景

  • Agent 间通信消息
  • 工具描述（tool description）
  • 报错文案（error messages）
  • 系统提示（system prompt）
  • 跨 Agent 指令
  • 流程步骤文档

❌ 不适合场景

  • 创意写作
  • 营销文案
  • 需要语气和细微差别的内容
  • 情感表达
  • 对话式交互文本
重要边界：只修形式，不修内容实质。一段没有实质内容的废话，改完也还是空话。ASD-STE100 提升的是表达的清晰度，不是内容本身的质量。如果一段话本身就缺少关键信息，改写不会补全它。
