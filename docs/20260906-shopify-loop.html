Shopify Sidekick 的 continual learning loop：把生产失败压进模型权重

从 rubric 和 judge 起步，把真实生产失败、用户纠正和反复报错当作训练信号，持续压缩进模型权重，而不是只在 prompt 和 harness 上打补丁。

continual learning production failures judge first gisting / SFT / GRPO
一句话结论

这不是“再调几个 prompt” 的故事，而是把线上失败收集成训练闭环，先用 harness 和 judge 找对信号，再把改进推进到参数空间。

Production flywheel

01
What it is

这篇文章讲的是什么

Shopify 讲的是 Sidekick 的 continual learning loop：如何把 production failures 变成训练信号，经过 rubric、judge、harness 和压缩步骤，最终更新到模型权重里。

核心方向

不是单点优化，而是一个持续学习飞轮。前面出错，后面就把错误转成可训练的东西。

为什么重要

前线模型只能帮你起步，真正的大规模收益来自“从真实流量里学习”。这个 loop 试图把优势从 harness 推进到 weights。

02
Loop order

飞轮顺序：从 quality 到 weights

文章把顺序讲得很清楚：先定义 quality，再 calibrate judge，然后改善 harness，接着用 autoresearch、gisting、SFT / GRPO 把经验压进权重。

1

定义 quality

先写 rubric，把 completeness、execution、response quality 和 safety 变成可评分的契约。

2

校准 judge

用人工标注、Cohen's kappa 和回放测试验证 judge 不只是会打分，而是真的接近人类判断。

3

改进 harness

先用 autoresearch 和自修复流程把系统行为变好，再考虑进一步训练。

4

压进权重

通过 self-healing pipeline、SFT、GRPO 和 gisting，把经验从 prompt 级推进到 parameter-space。

03
Quality first

先定义质量，再谈训练

文章最强调的一点是：rubric 不是作文题，而是 reward signal。质量定义错了，后面的 judge、训练、压缩都会优化错目标。

Rubric

四个维度

completeness、execution、response quality、safety，每项都要有锚点。

Calibration

看一致性

用两位最好的标注者盲标 25 个样本，检查 Cohen's kappa；太低说明 rubric 模糊。

Ground truth

别只看金标集

随机流量能暴露真实生产里的坏样本，比 curated examples 更能说明问题。

Judge ceiling

不追求完美

目标不是 100%，而是和人类专家大致对齐。

04
Harness to weights

先改 harness，再进参数空间

Shopify 强调先修 orchestration 和上下文压缩，再进入训练环节；比如用 autoresearch 找失败模式，用 gisting 压缩系统提示词，再做 SFT / GRPO。

Harness 改进

  • 用 autoresearch 先找出失败模式和最优参数
  • 把复杂 harness 先自修复，再考虑训练
  • GraphQL agent 是文章中最清晰的生产闭环示例

参数空间改进

  • SFT 和 GRPO 负责把经验推进到权重
  • Gisting 负责压缩超长系统提示词
  • 目标是更快、更便宜，同时保持或提升质量

06
Use cases

适合什么场景，不适合什么场景

这篇文章适合给 AI product / agent team 看，不适合被断章取义成“所有系统都应该直接训练权重”或“只要压缩提示词就能解决问题”。

✓ 适合

  • 已经有生产流量，能持续采样失败案例
  • 愿意建立 rubric / judge / 标注闭环
  • 目标是把 harness 经验进一步推进到模型权重

✗ 不适合

  • 还没有稳定线上流量就想直接做 continual learning
  • 没有质量定义，只想靠 prompt 微调碰运气
  • 把文章中的结果当成对所有场景都成立的 benchmark
