① Pi Durable 是什么

🎯 定位

Pi Durable 是一个 durable agent harness（持久化 AI Agent 运行框架）。Built on pi-ai（模型访问层）+ chord（文档状态层）。

所有变更通过原子 commits写入存储，进程崩溃前最后一步的状态完整保留，重启后可从断点恢复。

🏗 架构层次

  • pi-ai：统一模型访问层，封装各 LLM API
  • chord：文档状态层，支持共享文档协作
  • pi-durable：持久化 harness，封装 checkpoint / replay / compaction 逻辑

② 核心概念

Harness

打开存储 + 运行 agent 的「机械装置」。所有变更通过原子 commits写入，不展示未提交内容。负责管理 agent 生命周期、checkpoint 与 replay。

Conversation

不可变的对话记录（transcript）。root() 创建根对话，fork() 从历史节点分叉出新分支，类似 Git branch，但每条分支有独立 agent 配置。

Entry

原子记录单元，对应 transcript 中的一条消息：

  • pi.user：用户输入
  • pi.assistant：模型回复
  • pi.tool-result：工具执行结果

Task（状态机）

每个 agent step 结束后保存 checkpoint，包含模型生成、工具调用序列与 document 状态。崩溃重启 → reopen() + resume() 从最后 checkpoint 继续。

③ 断点续传原理

🔄 进程崩溃后恢复流程

  • 1. reopen()：重新打开已有存储，加载最后 checkpoint
  • 2. resume()：从断点继续执行，跳过已完成的 step
  • 3. replay 策略决定是否重跑 tool calls

🔐 replay 策略详解

  • replay: "safe"（默认 false）：幂等操作（read / 查询 / 抓取）可自动重跑
  • replay: "unsafe"（默认 true）：有副作用操作（deploy / 扣款 / 写入）不重跑，向 model 报告 interrupted 错误

④ 存储后端

Pi Durable 支持多种存储后端，满足从开发调试到生产部署的不同场景：

后端 函数 持久性 特点与适用场景
内存 MemoryStorage openMemoryStorage() ❌ 不持久化 开发调试用，进程退出即丢失。测试场景快速验证 harness 逻辑。
推荐 SQLite openNodeSqliteStorage() ✅ crash-safe WAL 模式，crash 安全，支持事务。适合本地服务器长期运行。
日志 JSONL openNodeJsonlStorage() ✅ append-only Append-only，日志友好，适合需要人工审查/回放历史的场景。
生产级 Durable Object openDurableObjectSqliteStorage() ✅ 自动 wake-up Cloudflare Durable Object，进程隔离/驱逐后自动 wake up。PiHarness 集成推荐。

⑤ 会话分叉（Fork）

🍴 类似 Git branch

session.fork(id) 从 transcript 中任意历史节点分叉出一条新路径。原对话完整保留，同时可以探索不同的执行方向。

每个分叉独立存储 agent 配置（模型选择 / extensions / 工具列表 / 工作目录），互不干扰。

🔧 分叉的独立配置

  • 模型：不同分叉可用不同 LLM
  • Extensions：工具 + system prompt + hooks 的命名 bundle
  • 工作目录：独立文件系统路径

重启后每个分叉的 agent 配置自动恢复，无需手动重建。

⑥ 自动压缩（Compaction）

📉 后台自动压缩

当对话历史超过 reserveTokens 阈值时，harness 自动在后台对长 context 进行总结压缩，将大量消息合并为一条摘要 entry。

即便对话包含上万条消息，也不会造成内存压力或模型上下文溢出。

✋ 手动触发

除自动触发外，也支持手动调用 compaction 接口，在合适的时机主动压缩历史（如用户明确要求、或进入新任务阶段）。

压缩后的摘要 entry 保留关键信息，节省 token 成本的同时保留可追溯性。

⑧ 术语表

Harness 持久化 agent 运行框架，打开存储并驱动 agent 执行，所有变更通过原子 commits 写入
Conversation 不可变 transcript，用 root() 创建根对话，fork() 从历史节点分叉
Entry 原子记录单元（pi.user / pi.assistant / pi.tool-result 等），不可变，追加进 transcript
Commit 原子写入操作，conversation.commit() 同时追加 entry 和修改 document
Task 每个 step 的持久化状态机，包含 checkpoint，重启后从最后 checkpoint 恢复
Checkpoint Task 在 step 末尾保存的快照，含模型生成、工具调用与 document 状态
Compaction 自动压缩长 context，超过 reserveTokens 阈值时后台总结，防止爆窗口
Replay Policy "safe" 自动重跑幂等工具 / "unsafe"（默认）报告 interrupted，不重跑有副作用操作
Fork session.fork(id) 从历史节点分叉新路径，类似 Git branch，每分支独立 agent 配置
Storage Backend 存储后端：MemoryStorage / SQLite / JSONL / Cloudflare Durable Object
