先记一句：5h window: 67% used 说的是账号额度，不是 Context 已用了 67%。只有 context usage 才在说当前工作记忆。

总览：两个同名 Window，两个完全不同的问题
01

工作桌 vs 工时包

CONTEXT WINDOW · 工作桌大小
模型能同时看到多少

系统指令、AGENTS.md、历史对话、读过的代码、命令输出、工具结果和正在生成的内容，都可能占据桌面。

  • 单位：token 容量
  • 问题：这一次能装下多少信息？
  • 状态：context used / remaining
USAGE WINDOW · 工时包周期
账号还能用多少 Codex

本地消息与 cloud chats 共享五小时 usage window；不同计划或场景还可能有额外 weekly limit。

  • 单位：allowance / credits
  • 问题：这段时间还能做多少任务？
  • 状态：used / remaining / left
02

“Used” 跟在谁后面，意思就不同

# 例 A：账户限额
5h window
███████░░░ 68% used

# 例 B：当前工作记忆
context window
██████████████░░░░░░ 70% used

例 A 表示本轮五小时额度已消耗约 68%，约剩 32%；例 B 才表示当前线程的可用上下文空间被占去约七成。数字长得像，计量系统不是同一个。

所以“我只说了一句，为什么 Context 这么高？”通常不是那一句话造成的，而是 Agent 已携带的项目状态、文件、日志和历史过程。Hook、MCP 等额外注入也会让一轮的输入更厚。

04

Token：读进去、缓存复用、写出来

Token 是模型处理文本和代码的基本计量单位，不等于“一个字”。一次 Agent 任务会反复读取输入、调用工具、生成输出。

Input Tokens问题、指令、文件、历史、工具结果：模型本轮读进去的东西。
→
Model结合当前 Context 与推理预算，进行多步 agent loop。
→
Output Tokens分析、代码修改、命令、解释等模型写出来的东西。
Cached Input ≠ 不占 Context

缓存可复用已处理过的输入前缀，通常降低重复计算或成本；但一段历史若仍需供模型处理，仍属于当前上下文范围的一部分。

05

两者的关系：不相等，但会间接联动

Context Window 和 Usage Window 不是同一个量表；不过 active context 越大，一次任务可能需要处理更多 token，进而更快消耗 usage / credits。

06

Context 快满时：Compact 是整理，不是删除

/compact 的作用可以理解为把旧日志、讨论和细节压成一份关键摘要，再把摘要继续作为 Context 使用。它腾出了桌面，但不是把任务档案直接清空。

BEFORE

日志 + 代码 + 讨论 + 测试 + 决策

Context88% used
AFTER /compact

关键摘要 + 新工作

Context释放空间

/new 则更像开一张新桌子：保存的 chat/thread 与某次模型调用实际拿到的 current context 不是同义词。

07

最后分清三个轴

CONTEXT记多少资料。Context Window 是桌子总容量；Context Used 是桌上已经放了多少。
REASONING想多深。Reasoning effort 控制推理预算，不是记忆容量。
USAGE还能干多久。5h window、weekly limit、credits 是账户限额/周期层，不是 Context。
