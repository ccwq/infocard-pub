① 引入 · 为什么 AI 正在抢逆向工程师的饭碗

配置逆向环境有多痛苦？JADX + apktool + Frida + IDA Pro + Python 脚本 + 环境变量……新手往往要折腾 几个小时 才能跑通一条最简单的 APK 分析流程。

更别提遇到 JS 加密混淆、iOS binary、.NET DLL、固件 IoT 这些完全不同的场景，每换一次目标都要重新配环境。

reverse-skill 的解决思路：把行业积累的逆向经验封装成 Skill 包，AI agent 遇到任意逆向目标时，自动路由到正确工作流，你只需要说一句话。

⑦ 路由机制 · 单一数据源架构
📋 routing.json — 路由单一数据源

43 条规则（R0-R44），定义"什么任务 → 哪个 skill"。所有路由逻辑的权威来源，AI 和脚本共享同一份数据，保证一致性。

🔀 master-route.ps1 — PRIMARY 分诊

一次性决策脚本，读取 routing.json，根据用户任务描述快速分诊到正确的 Scenario skill，输出下一步指引。

📂 case-init.ps1 — 案例初始化

为每个逆向任务创建标准化目录结构：scope.md（目标范围）/ timeline（时间线）/ workitems（工作项）。

🧪 test-routing.ps1 — 回归基准测试

175 个基准用例，覆盖所有路由规则，CI 中自动运行，确保路由决策始终正确。

进阶文件： RULES.md（全局规则，ACT 前 scope gate）→ MASTER-ROUTING.md（快速阶梯入口）→ routing.md（Task→skill 路由矩阵）→ SKILL.md（主入口）
