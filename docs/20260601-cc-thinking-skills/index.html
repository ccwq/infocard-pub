49| 一句话结论 50|

这份仓库最重要的不是"技能很多"，而是它把思维框架做成了 可调用、可组合、可路由 的工程化入口。你不是在挑一个聪明句子，而是在给 Claude Code 选一套思考方法。

先试顺序

56|

2. thinking-model-selection 选方法；
3. thinking-model-combination 做组合；
4. 再按场景落到决策、排障、估算或产品技能。

根据你的领域和问题类型，路由到正确的思维模型。所有思维技能的单一入口。

84|

为当前问题选择正确的思维模型。适用于遇到新问题、现有方法失效或需要匹配工具与场景时。

85|
86|
87|
88| thinking-model-combination 89| Model Combination 90|
91|

组合多个思维模型进行更丰富的分析。适用于需要多视角的复杂问题、高风险决策或单一模型存在盲区时。

决策与分析

100| 8 项 101|
102|
103|
104|
105| thinking-first-principles 106| First Principles Reasoning 107|
108|

通过质疑假设并从不可约分组件重建，将复杂问题分解为基本事实。适用于创新、挑战现状或传统解决方案失效时。

109|
110|
111|
112| thinking-second-order 113| Second-Order Thinking 114|
115|

超越直接后果思考二阶和三阶效应。适用于战略决策、政策变更和避免意外后果。

116|
117|
118|
119| thinking-inversion 120| Inversion Thinking 121|
122|

通过识别失败路径来反向处理问题，然后系统性地避免它们。适用于风险识别、规划和避免明显错误。

123|
124|
125|
126| thinking-pre-mortem 127| Pre-Mortem Analysis 128|
129|

想象项目失败并逆向追溯原因。适用于项目启动、主要决策前，或当乐观情绪可能掩盖风险时。

130|
131|
132|
133| thinking-kepner-tregoe 134| Kepner-Tregoe Rational Process 135|
136|

用于复杂问题分析、决策和风险评估的系统化理性流程。适用于高风险工程决策、超出5 Why的根本原因分析，以及需要结构化标准的多因素评估。

137|
138|
139|
140| thinking-reversibility 141| Reversibility Thinking 142|
143|

按可逆性对决策进行分类，并匹配相应的决策流程。适用于技术选型、架构决策、流程变更和招聘决策。

144|
145|
146|
147| thinking-regret-minimization 148| Regret Minimization Framework 149|
150|

投射到未来的自己，询问自己会遗憾没有做什么。适用于职业决策、战略转型、风险承担选择和人生重大决策。

151|
152|
153|
154| thinking-opportunity-cost 155| Opportunity Cost Thinking 156|
157|

通过你所放弃的而非所获得的来评估决策。适用于资源配置、优先级排序、构建与购买选择，以及技术债务评估。

认知与行为

166| 7 项 167|
168|
169|
170|
171| thinking-bayesian 172| Bayesian Reasoning 173|
174|

使用概率推理系统地根据新证据更新信念。适用于概率估计、从数据学习和不确定性下的决策。

175|
176|
177|
178| thinking-debiasing 179| Cognitive Debiasing 180|
181|

识别和对抗决策中认知偏差的系统化清单。适用于重大决策前、评估建议时或赌注很高时。

182|
183|
184|
185| thinking-dual-process 186| Dual-Process Thinking 187|
188|

应用卡尼曼的双过程理论来识别何时信任直觉、何时进行审慎分析。适用于高风险决策、易出错情境，或权衡速度与准确性时。

189|
190|
191|
192| thinking-bounded-rationality 193| Bounded Rationality and Satisficing 194|
195|

应用西蒙的有限理性和满意化原则，在现实约束下做出足够好的决策。适用于时间压力下的设计决策、认知局限识别和设定适当的停止标准。

196|
197|
198|
199| thinking-socratic 200| Socratic Questioning 201|
202|

深化理解、挑战假设和揭示隐藏信念的系统化提问框架。适用于需求收集、调试、辅导和批判性分析。

203|
204|
205|
206| thinking-probabilistic 207| Probabilistic Thinking 208|
209|

用区间表达信心，随着新信息更新预测，并持续追踪校准。适用于项目估算、风险评估和不确定性下的决策。

210|
211|
212|
213| thinking-steel-manning 214| Steel-Manning 215|
216|

针对对立观点的最强版本进行辩论，而非最弱版本。适用于设计评审、备选方案评估、冲突解决和决策验证。

系统与策略

225| 7 项 226|
227|
228|
229|
230| thinking-systems 231| Systems Thinking 232|
233|

将问题视为具有反馈回路、涌现行为和非线性效应的互联系统来分析。适用于复杂系统调试、架构决策和理解意外行为。

234|
235|
236|
237| thinking-feedback-loops 238| Feedback Loop Analysis 239|
240|

使用 Meadows 的反馈回路框架分析系统，识别增强回路、平衡回路、延迟和杠杆点。适用于组织动力学、产品增长设计、调试失控或振荡系统，以及寻找高影响力干预。

241|
242|
243|
244| thinking-archetypes 245| Systems Archetypes 246|
247|

识别圣吉的系统原型来诊断反复出现的组织和技术问题，识别修复持续失败的原因，并设计解决根本结构的干预措施。

248|
249|
250|
251| thinking-ooda 252| OODA Loop 253|
254|

动态情况下的快速决策循环。适用于事件响应、竞争场景、时间敏感决策和需要快速适应的情况。

255|
256|
257|
258| thinking-leverage-points 259| Leverage Points 260|
261|

使用 Meadows 的系统干预点层级来识别小变化可以产生大效果的地方。适用于战略决策、系统优化和选择工程工作的重点。

262|
263|
264|
265| thinking-theory-of-constraints 266| Theory of Constraints 267|
268|

识别和管理瓶颈；在约束解决之前，其他地方的改进无关紧要。适用于性能优化、流程改进和资源配置。

270|

272| thinking-cynefin 273| Cynefin Framework 274|
275|

按复杂性域（清晰、繁杂、复杂、混沌）对问题进行分类并匹配相应方法。适用于方法论选择、问题框架和流程设计。

问题解决与创新

284| 7 项 285|
286|
287|
288|
289| thinking-occams-razor 290| Occam's Razor (Parsimony Principle) 291|
292|

应用简洁性原理，偏好假设更少的更简单解释。适用于调试中的假设选择、架构决策和竞争方法之间的选择。

293|
294|
295|
296| thinking-map-territory 297| Map-Territory Thinking 298|
299|

认识心理模型和图表的局限性。适用于模型与现实分离时、调试期望不匹配时，或质疑抽象准确性时。

300|
301|
302|
303| thinking-circle-of-competence 304| Circle of Competence 305|
306|

了解你专业知识的边界并在其范围内运作。适用于评估机会、在你的领域外做决策，或评估何时应该请教专家。

307|
308|
309|
310| thinking-triz 311| TRIZ Thinking 312|
313|

应用 TRIZ（发明性问题解决理论）方法论来解决技术矛盾并找到创新解决方案。适用于工程设计、突破不可能的约束和系统性创新。

314|
315|
316|
317| thinking-five-whys-plus 318| Five Whys Plus 319|
320|

带有明确偏见防护和停止标准的增强型根本原因分析。适用于事件验尸、错误调查和标准 5 Why 可能误导的流程失败。

321|
322|
323|
324| thinking-scientific-method 325| Scientific Method 326|
327|

假设 → 预测 → 测试 → 修订，明确证伪。适用于调试、功能实验、性能调查和 A/B 测试设计。

328|
329|
330|
331| thinking-thought-experiment 332| Thought Experiments 333|
334|

在实证测试不可行时通过假设场景测试想法。适用于架构评估、边缘案例分析、伦理考量和发展策略。

估算与风险

343| 5 项 344|
345|
346|
347|
348| thinking-fermi-estimation 349| Fermi Estimation 350|
351|

通过分解为已知或可估计的因素，对未知量进行数量级估算。适用于容量规划、成本估算、市场规模和技术可行性评估。

352|
353|
354|
355| thinking-margin-of-safety 356| Margin of Safety 357|
358|

为未知的未知数建立缓冲，不要优化到边缘。适用于容量规划、截止日期估算、架构设计和风险管理。

359|
360|
361|
362| thinking-lindy-effect 363| The Lindy Effect 364|
365|

对于非易腐事物，未来的预期寿命与当前年龄成正比。适用于技术选择、框架/库评估和工具寿命预测。

366|
367|
368|
369| thinking-via-negativa 370| Via Negativa 371|
372|

通过移除而非添加来改进。专注于停止做什么、消除负面和减去复杂性。适用于系统简化、流程改进和功能优先级排序。

373|
374|
375|
376| thinking-red-team 377| Red Team Thinking 378|
379|

故意攻击你自己的计划、系统和假设，在对手或现实之前找到弱点。适用于安全评审、架构验证、计划压力测试和发布前准备。
