02 / 词典怎么读：Software Factory 词条全拆解

词典对工厂的定义刻意克制的点在最后一句："把人从启动会话中拿出来，而不是从其他一切环节中拿出来"。词条自带一张触发器对照表：

触发器启动的会话示例
Issue 创建或被打标签探索 / 修 bug / 实现打上 ready-for-agent 标签的 issue 自动获得会话
定时任务（cron）周期性维护每晚自动修一条 lint 规则
CI 失败 / 监控告警诊断 + 尝试修复main 分支构建挂了 → 会话找出 breaking commit 并提修复
另一个会话完成后续工作Agent 开的 PR 触发自动审查，审查意见再触发修复会话
💡

最小工厂定义（防吓退新手）

"一个 cron 任务跑一种会话、开一个可审查的 PR，就是一个工厂。" 从窄循环起步——产出小而相似的 PR，审查它们，看看这个循环能被信任到什么程度，再扩大。词条同时点明：决定哪些决策保持人工，就是工厂设计的主问题。人可以待在任何位置：写并打标 issue、批准计划、合入前做人工审查。

03 / 暗工厂为什么危险：机制级解释

词典把暗工厂定义为"vibe coding 的团队版"：个人 vibe coding 是"这一次我选择不读"，暗工厂是团队对一个代码区域一次性做出这个选择，此后每个改动都没人请求、没人看过，改动到达的速度就是触发器启动的速度。危险在出错时兑现：

"出问题时你不知道改了什么，因为没人读过这些改动。你面对的是一份全队没人读过的代码要调试。病因可能在很多改动中的任何一个——而每一个都通过了检查。"
—— Dark factory 词条

此时仅存的门禁只有两道，词典把它们分得很清：自动化检查（确定性 pass/fail：测试、类型、lint、构建——Agent 可以拿失败输出自校正）与自动化审查（非确定性判断：另一个 Agent 或不同 system prompt 来当 LLM-as-judge）。两道都查不出的问题就直接进了代码库。配套词条 Human review 还有一条锋利的定义：读 diff 才算审查，读 Agent 写的总结不算——叙述不是工件，diff 才是一手来源。

04 / 支撑概念：AFK 的真实风险与 Handoff 工件家族
AFK 词条

离席的风险是"自信地错"

你在场时歧义会变成提问；你离开后 Agent 拍板默认值继续跑。典型失败：回来发现几小时完成度很高的工作，建立在头十分钟一个错误决定上——"工作不烂，只是烂得很有连贯性"。对策：开工前用 grilling（苏格拉底式追问）或写 spec 消歧，跑动中靠自动化检查/审查兜底。

Handoff 家族

spec ⊃ tickets，模型无状态

模型无状态，会话一清全没。Spec（多会话的工作说明，由 tickets 组成）和 Ticket（单会话的工作包，必须在 smart zone 退化前完成）是把决策持久化到环境里的"交接工件"。Ticket 大小可测：如果你的会话总在完工前退化，就是 ticket 太大，拆。

推文没讲但强相关：同一词典还有 Attention budget / Attention degradation 词条——"每个 token 的影响力预算是固定的，上下文越长指令信号越稀释；恢复靠删上下文而不是重贴指令"。这正是"ticket 为什么必须小"的机理解释，也是长会话质量下滑（smart zone→dumb zone）的成因。另注：vibe coding 一词溯源 Andrej Karpathy（2025 年初）。别忘了 Matt 的落地实现：Sandcastle（8,143★），TypeScript 写的沙箱编排库，四个模板里 sequential-reviewer 和 parallel-planner-with-review 就是"有人兜底"路线的产品化。
05 / 落地路线：从一条 cron 到一条产线（按词典精神）
  1. 选一个窄循环：最典型的第一站就是推文作者说的"依赖升级"——cron 触发 → Agent 升级一个依赖 → 跑全量测试 → 开 PR。改动小、模式重复、可审查性极高。
  2. 把门禁写成确定性检查：先补测试和类型检查（自动化检查），这些是 Agent 自校正的原料；flaky 测试按词典定义就是坏的检查，先修它。
  3. 加一道自动化审查：换一个模型或 system prompt 当审查员（LLM-as-judge）；写代码的 Agent 自己审自己不算数——"分离才让它有效"。
  4. 人只守合入门：早晨批量 review 昨晚工厂开的 PR（Matt 本人的用法）；读 diff，不读总结。哪些决策留在人工，逐季度重新划分。
  5. 触发器逐类解锁：issue 标签 → cron → CI 失败 → 上游会话完成。每解锁一类触发器前，先统计前一类的历史通过率——推文那两个数字溯源不到，你自己的流水线通过率才是该盯的数。
  6. 永不为"暗"而暗：词典的警告反着读就是路线图——审查是瓶颈就分层扩审查能力（检查→自动审查→人），而不是跳过审查。
06 / 判断

推文的框架是对的："工厂 vs 暗工厂"的切口、瓶颈从生成速度转移到"目标定义与评测质量"、护城河转向工厂设计——这些都能在开源词典里找到逐字或机制级支撑，比大多数融资话术扎实得多。Matt 本人也用 Sandcastle（8,143★）证明这套词是可实现的。
