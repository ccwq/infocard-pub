01 / WHAT IT IS

它不是单一模型，而是一条“任务—设备—证据”的执行链

官方 README 将 ARTEMIS 描述为让 AI assistant 和 test suite 操作真机的 Android automation 项目。

INPUT

自然语言任务

例如打开设置、进入电池页、确认电量显示并检查崩溃弹窗。输入应明确目标、成功条件和允许操作范围。

GROUNDING

多层定位

优先使用元素索引/无障碍层级；自定义 Canvas、Compose、Flutter 等界面再用 OCR、坐标和视觉模型兜底。

EVIDENCE

结果可回看

任务流可以留下截图、Logcat、action trajectory、structured result 和 execution replay；最终仍由测试人员判断是否通过。

不要混淆：99%+ 是官方 README/API 描述的 AndroidWorld benchmark 结果，不是你自己的 App 在任意设备、任意任务上的成功率。
02 / QUICK START

第一次运行：先让设备连通，再让 Agent 执行

官方 quick start 同时提供 macOS/Linux 与 Windows PowerShell 的启动脚本。

01

准备设备

实体机打开 USB debugging，或启动 Android emulator；确认这是可用于测试的设备。

02

获取代码

clone 官方仓库；不要把真实账号、生产数据或设备密钥写入项目。

03

一键启动

start.sh / start.bat 检测 ADB、scrcpy、FFmpeg、uv 与依赖，并打开本地控制台。

04

做小任务

先运行一个可逆、无敏感数据的短任务，检查截图、状态和错误信息。

05

再接 IDE

确认 CLI/UI 工作后，再安装 MCP 到 Codex、Antigravity、Claude Code 或 Windsurf。

# macOS / Linux
git clone https://github.com/google/artemis.git && cd artemis
./start.sh

# Windows PowerShell
git clone https://github.com/google/artemis.git
cd artemis
.\start.bat

# CLI 最小形状：示例，不是本机执行结果
uv run artemis run "Open Settings, find Battery and tell me current level" --profile flash
uv run artemis status
启动后的验收：本地 Web 控制台默认形状是 http://localhost:8000；先确认设备连接向导、实时投屏/状态面板和 CLI status 正常，再继续配置 IDE。
03 / MCP & IDE

接入 AI IDE：MCP 只是通道，Rules 才是行为约束

官方 README 提供自动安装和手动生成配置两种路径；命令中的路径必须替换成自己的虚拟环境。

一键安装

uv run artemis mcp --install all 可面向支持的 IDE 安装 MCP 与规则；首次配置也可走 artemis init。

手动生成

uv run artemis mcp --generate-config codex 输出配置形状。/path/to/artemis 是占位符，不能原样提交。

Rules 只装一处

Claude Code、Cursor、Codex 等都有自己的规则入口；重复写入全局 CLAUDE.md / rules 会浪费上下文并造成冲突。

# 全部支持的 IDE（官方示例形状）
uv run artemis mcp --install all

# 只安装某个客户端
uv run artemis mcp --install antigravity
uv run artemis mcp --install claude

# 生成配置片段
uv run artemis mcp --generate-config codex
最小 MCP 验收：在 IDE 中能发现 ARTEMIS tools → 设备状态能回读 → 对一个安全短任务产生 trace → 失败时能看到 error/status，而不是只得到一句“已完成”。
04 / FLASH VS PRO

任务路由：快不等于稳，稳也不等于无限授权

官方 README 把两种 profile 设计成不同的执行路径，各有明确缺口。

维度FlashPro选择建议
循环响应式 observe → think → actPlanner / Operator / Checker 多智能体图短、确定、可逆任务优先 Flash；长流程优先 Pro。
速度官方描述单步约 3–5 秒官方描述单步约 15–40 秒这是 README 口径，不是你的设备 SLA。
安全无执行前安全网、检查点和最终报告每个动作有 Safety Net，支持检查点和最终校验涉及敏感页面、长流程或不可逆动作时不要只看速度。
计划无任务计划与 notesPlanner 维护里程碑和 verify/assert需要审计链时选择 Pro。
诊断不能执行 ADB shell含 notes、history、video analysis、ADB diagnostics设备级排障需要 Pro/人工操作员。
失败处理快速循环可能停在错误状态blocked action 形成 execution incident，交回 Operator 恢复失败必须回读 trace，不默认重试。
路由规则：Flash 适合“打开一个页面并读一个状态”；Pro 适合“计划—执行—检查点—报告”链路。两者都不替代权限确认、测试数据隔离和人工终审。
05 / DEVICE HELPER

手机上会出现什么：Accessibility Helper 与回退路径

这部分必须在测试设备上向团队成员说明清楚，否则“多了一个无障碍服务”会变成排障噪音。

首次任务安装

首次在某台设备执行任务时，ARTEMIS 会安装 Artemis Accessibility Helper，用于读取屏幕布局，并在设置的无障碍列表中出现。

状态与移除

uv run artemis helper status / doctor 查看；helper uninstall 移除；可关闭自动安装。

失效时回退

Helper 失效时回退到 UIAutomator2，并在 timeline、mobile_manage_task 状态和最终报告中说明。

uv run artemis helper install
uv run artemis helper status
uv run artemis doctor
uv run artemis helper uninstall

# .env 选择回退 / 禁止自动安装
ARTEMIS_HIERARCHY_BACKEND=uiautomator
ARTEMIS_HELPER_AUTO_INSTALL=false
隐私与权限：官方 README 说明 helper 监听手机本机、不向外发送数据；这是项目设计说明，不应替代你对设备、日志、截图、模型服务和第三方 IDE 的实际数据流审查。
06 / SDK & CI

从手动体验迁移到测试框架：把自然语言包进断言

Python SDK 提供结构化结果与 assertion 形状，可嵌入 pytest 或 CI/CD，但部署主机仍需设备与 ARTEMIS 服务。

Thin client

官方 README 将 artemis-client 描述为开发机上的薄客户端；ADB、Agent、模型和图像处理仍在设备主机。

指定设备

device_serial 可指定 emulator 或真机；不指定时按服务逻辑选择可用设备，生产 CI 应明确锁定目标。

结构化结果

通过 result.succeeded、error/status 和 trace_id 把任务结果接入断言；不要只解析自然语言回答。

uv add "artemis-client @ git+https://github.com/google/artemis.git#subdirectory=packages/artemis-client"

# 代码形状：官方 README 示例，未在本机执行
result = await client.run("Open Settings and verify battery percentage")
assert result.succeeded, result.error or result.status
print(result.device_serial, result.trace_id)
07 / BENCHMARK & LIMITS

99%+ 应该怎么读：它是 benchmark，不是通用承诺

官方 README 给出 AndroidWorld 评测口径；卡片保留任务数、应用数与证据边界。

声明官方口径不能推出
AndroidWorldGoogle Research benchmark，20+ apps、100+ multi-step tasks，README 标为 99%+ completion不能推出任意 App、任意机型、任意自然语言任务都有 99%+。
多模态定位accessibility hierarchy + OCR + visual model / coordinate fallback不能推出自绘界面、遮挡、动画和权限弹窗都能稳定定位。
长流程Pro README 描述支持 100+ steps、continuous loop 与报告不能省略测试数据隔离、超时、回滚和人工停止策略。
IDE 集成MCP 可接 Antigravity、Claude Code、Windsurf 等不能把 IDE 接入等同于拥有 Android Studio 原生插件；路线图仍列为待办。
08 / LICENSE & SAFETY

什么时候不要用：设备权限与数据边界先于“自动化成功率”

Android 自动化触及真实账户、通知、截图和日志，安全问题不是附属说明。

不适合直接跑生产手机

没有明确授权、隔离账号或可逆回滚时，不要让 Agent 跨 App 操作真实数据。

不适合只看最终一句话

必须回读 screenshot、Logcat、trace、action trajectory 和 structured result；失败也要留下证据。

许可证

仓库 LICENSE 为 Apache-2.0，并包含 Minitap, Inc. 开发的源代码；商用前核对许可证与第三方依赖边界。

最短可验证路径

连接一台隔离 Android 设备 → ./start.sh / .\start.bat → 查看 status → 用无敏感数据的短任务跑 Flash → 回读设备状态/截图/trace → 再配置 MCP → 对长流程改用 Pro → 把结果接入 pytest/CI 前先定义停止、失败和权限策略。
