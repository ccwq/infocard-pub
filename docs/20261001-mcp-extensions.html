三类入口：每个 MCP App 最多挂三个
🌐

Global 入口

主侧栏导航常驻——用户随时打开你的 App（Bits & Bolts 的 Parts Library 就在这）。

🧵

Thread 入口

会话内的内容 tab；要有独立标题（如 Parts Tray），别跟插件重名。

📄

File 入口

文件扩展名 handler：.stl/.ipynb 等类型一打开就进你的自定义 Viewer。

🎨

图标规范

SVG 单色透明底 + currentColor 随主题、20×20 视口 1.33px 描边——侧栏不掉价。

注册方式spec 口径

入口写进 _meta["openai/ui"]["entrypoints"]

注册后该入口的可见性不受 _meta["ui"]["visibility"] 控制——入口即用户入口。MCP App 应直接用初始 tool result 首渲染，不要重复调工具。

Deep Links 直达{scheme}://plugins/{pluginId}@{marketplace}/app/{toolName}?path=…scheme: codex(桌面) / chatgpt(移动)
显示模式inline + fullscreen，无 pip；所有入口均为 fullscreen
文件能力：Viewer + 读 + 写 + 订阅file extension entrypoint

安全模型先说清：ChatGPT 永不把原始文件路径给 MCP App

spec 原文：MCP App 跑的是不可信 JavaScript，所以宿主不给裸路径——文件访问一律走 MCP resource methods；要读相对路径或超大文件，做成 MCP Server 的专用 tools。File 入口内 server 调用会被自动附加 _meta["openai/resource"]["path"]（打开资源的绝对路径）。

读 + 订阅resources/read 返回内容 + _meta["openai/resource"]；订阅变更推给 Viewer
写回常规 MCP 只读；File 入口扩展 openai/resources/write——在 ChatGPT 里做富编辑器成为可能
广告类型initialize 里 experimental.openai/resource 声明支持的扩展名（HTML accept 的 ".ext" 形式）
本地文件Opening Local Files 扩展：用户本地文件可交给 App 处理（仅桌面端）
交互层四件套
⚙️

Structured Settings

插件向 ChatGPT 插件详情页贡献设置，平台原生控件渲染——不用自己画设置 UI。

📝

Form Elicitation

扩展表单：缩略图选择、建议值、资源选择（显式/隐式）、预览。OpenAI 注册 server 需 MCP 2026-07-28+ 与 MRTR；直连支持 legacy 流程。

@​

Composer @mentions

插件暴露可搜索列表（人物/文件/频道…），用户在输入框逐项 @；_meta["openai/extensions"]["mentions/search"] 声明，typeahead 返回 resource links。

🧠

Model Context + Messages

ui/update-model-context 向模型上下文放文本/资源链接/嵌入资源/图片（带缩略图）；ui/message 扩展会话消息（移动端有限制）。

推文四层论 · 官方素材印证@mylifcc 分层

Skill → MCP → MCP App → MCP Extensions

推文把 AI App 拆四层：Skill 教 Agent 做事、MCP 给能力、MCP App 给交互界面、Extensions 把整个 App 嵌进 ChatGPT。对照官方素材：Apps 规格确实是「模型调用」与「用户入口」两条路径（MCP Apps 常规只能由模型唤起，Entrypoints 补上静态入口）；文件读写、原生设置、表单选择器均有对应 spec 章节——分层论与官方能力图完全对得上。

视频产品愿景核验侧栏工作台(Global)+拖 .mp4 进 Viewer(File)+@素材(mentions)+表单选模型时长分辨率(forms)+Agent 调后端执行(MCP tools)——每一环都有对应扩展，推文不是画饼
平台支持表DevDay 口径：Global/Thread/Settings/Onboarding 全平台；File 三件套与 @mentions 仅桌面；Deep Links 无 Android
① 试用样板

插件目录装 Bits & Bolts Remote → 侧栏选它打开 Parts Library，五分钟感受「原生功能」长什么样。

② 建插件

按 developers.openai.com/codex/build-plugins 文档创建插件骨架。

③ 接 SDK

Server 端：pnpm add @openai/mcp-extensions，new OpenAIExtensions(server)；App 端：new OpenAIExtensions(app) + app.ontoolresult 渲染。Python 走 openai-mcp-extensions。

④ 挑扩展

按需声明 entrypoints / resource 读写 / settings / mentions / forms——每项都有 capability advertisement 与 schema 示例，spec.md 50KB 全覆盖。

⑤ 装引导

manifest 设 extensions["com.openai"]["onboardingSkill"] 指向打包 skill，用户装完自动进引导对话。

⑥ 发布

仓库用 release-please 流水线：Python/Node 双包独立版本与 changelog，合并 release PR 即打 tag 发版（OIDC 发布）。
