image-blaster：把一张房间图
拆成可交互场景

Claude Code skills场景原型云端生成

它用多项生成服务分别制作背景世界、可移动物件与音效，再放进浏览器查看器；能搭交互原型，但不等于准确恢复真实房间。

拆开生成环境与物件分离
逐步确认先核对再继续
双层环境视觉与碰撞分离
本地预览云端额度另备

先看四件事

不是一个模型包办

Claude Code 的 skills 串起分析、清图、世界、网格和声音；任何一环失败，都要定位到对应产物。

物件不能留两份

背景清理和世界提示都要排除可移动物体，否则背景已有椅子，独立模型又放一把。

外观不等于物理

环境碰撞网格配合物件盒状碰撞体支持交互；不是恢复真实质量、摩擦或房间声学。

速度承诺要分清

README 宣称少于 5 分钟，未给出覆盖各类输入的耗时保证；排队、重试与本地处理都会影响完成时间。

速览决策与阅读分流

适合试：想把房间图片做成可浏览、可抓取物件的交互草模，能接受云服务付费与逐步修正。

先别替代：测绘复原、精确物理仿真，或直接交付完整可编辑网格关卡。

只判断是否适用：读到这里即可。准备动手：看启动条件与卧室拆解。已有失败产物：跳到失败定位。准备导入引擎：读交付边界。

01 / 启动条件

先备好 Claude Code 访问权限、World Labs 与 FAL 的服务额度，以及本地 bun、node、ffmpeg、ffprobe。云生成涉及付费，不在这里估算金额。

git clone https://github.com/neilsonnn/image-blaster
cd image-blaster
claude

复制 .env.example 为 .env，在本机填写密钥。下面仅是占位，不是可用凭据，也不要把真实密钥发到聊天里。

WORLD_LABS_API_KEY=<本机填写>
FAL_KEY=<本机填写>

把图片放入 input/，在 Claude Code 中输入：

blast it and confirm each step with me

这句要求代理逐步确认；项目同时允许 one-shot。确认是技能指令约定，不是脚本强制的审批锁。

02 / 用卧室图理解拆解顺序

以下是教学示例，非实测：把椅子和桌上摆件选为可移动物件，墙与地板保留在环境中，不抽成独立物体。

  1. 分析图片。image-blast-uncover/SKILL.md 引导分析并写入 image.json；用户确认可移动物体后生成 object.json。此时核对椅子、摆件有无漏选或误选。
  2. 清理背景。plate 阶段移除选中的物件；生成世界的提示也排除这些物件。确认清理图没有残留，再进入世界生成。
  3. 分支生成。环境走 World Labs 的 marble-1.1；独立物件先生成白底参考图，再交给 Hunyuan 制作网格。分别检查背景是否干净、参考图是否截错对象。
  4. 组装交互。生成声音、整理产物，并通过 scene.json 摆放物件。椅子落点、尺度与朝向都需要在查看器中检查。

图像清理由 nano-banana 处理，gpt-image-2 可作替代；网格用 Hunyuan/FAL，音效由 ElevenLabs 经 FAL 生成。Claude Code 负责组织这些步骤，而非自己完成全部生成。

03 / 调网格前先查参考图

网格重生成默认复用白底参考图。若参考图已经截错椅子，仅重做网格不会纠正输入；需要重新提取时才用 --regenerate-reference，不要无意重跑整条链路。

参数范围：face-count 为 40000–1500000，项目默认 50000，API 默认 500000；PBR 为 true。generate-type 可选 Normal、LowPoly、Geometry；--polygon-type 的 triangle、quadrilateral 用于 LowPoly。默认值来自不同层，不能混为一谈；这些是参数说明，不是可直接复制的 CLI 命令。

04 / 文件如何对应视觉与碰撞

工作目录按世界组织：worlds/<slug>/source/ 保存源材料；output/world/ 是环境，output/<object>/ 是各物件；环境声音在 output/sfx/，物件声音在各物体的 sfx/。

环境的 .spz 负责视觉呈现，N-world.glb 提供碰撞网格。查看器 WorldCollider.tsx 使用 fixed/trimesh；SceneObject.tsx 给物件动态刚体与 CuboidCollider 盒状碰撞体。

所以，看到椅腿的轮廓不表示碰撞也沿椅腿精确贴合。useObjectGrab.ts 支持抓取并播放音效，属于交互设计，不是从照片推导出真实物理与声学参数。

05 / 哪一步坏了，就查哪类产物

  • 物体重复：回看 plate 与世界提示是否都排除了可移动物体，再核对场景内是否重复摆放。
  • 物件形状错：先看白底参考图，再决定只重做网格，还是重新提取参考图。
  • 云端完成、本地失败：检查 ffmpeg、ffprobe。循环音频处理和分析也依赖它们，不能只检查云端鉴权。
  • 画面正确、碰撞不对：分别检查环境碰撞网格与物件盒状碰撞体，不用视觉外观替代判断。

声音配置包括 2 条各 10 秒的循环环境音，以及每个物件 4 条各 1 秒的撞击音。先核对文件和循环处理，再检查播放；服务生成成功并不表示查看器里已经能听见。

06 / 到哪里算交付

在仓库根目录启动查看器；保持服务运行，在另一个终端从仓库根目录取得世界地址：

bun install && bun run dev

node .claude/scripts/project/show-url.mjs <world-slug>

本地地址形如 http://localhost:5173/<slug>。依次检查：世界能否加载；物件位置、朝向与尺度是否合适；背景与独立物件是否重复；碰撞盒是否妨碍抓取；环境音循环和物件音效是否工作。

若要导入其他引擎，还需核对相应格式插件、尺度、材质与碰撞设置。不能保证所有引擎都能拖入即用，也不要把浏览器演示当成完整关卡交付。

边界与下一步

先拿一张图、少量可移动物件走通流程：在每个确认点保留分析、清图、参考图和声音产物。发现问题时只重做相关阶段；需要精确尺寸、物理或引擎级编辑时，把后续人工处理列入计划。
