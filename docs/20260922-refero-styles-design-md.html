01它解决什么问题

用 AI 写页面的人几乎都遇到过同一个困境：功能写出来了，界面要么不好看，要么一股"AI 味"——默认布局、松散的间距、大路货配色。Refero 官方文档对此的解释是：像"make it premium"这类模糊提示词几乎允许模型生成任何东西（can produce almost anything），AI 需要的不是品味形容词，而是一套可视化的约束系统。一份包含颜色、字体、间距节奏、组件说明的参考，给了模型一个"更小、更锐利的目标"（a smaller, sharper target）。

styles.refero.design 的做法是把真实产品的营销页/产品页反向解析成结构化设计系统：每一个风格条目都带颜色 token、字阶、间距节奏、圆角与阴影规则、组件处理方式、图像处理指引，以及 do / don't 规则——最后打包成一份 markdown 格式的 DESIGN.md 供你免费复制。

02Refero 的三层研究资料：Styles / Screens / Flows

Refero 不止有 styles 站点这一个产品。按官方 MCP 文档，它给 Agent 提供的研究资料分三层，理解这个分层能帮你在正确的场景用正确的资源：

Styles
视觉方向

从真实网页提取的语义化设计参考：字体排印、颜色角色、布局、间距、表面、组件、图像处理和 do/don't 规则。styles.refero.design 就是这一层的免费网页版，2000+ 条。

Screens
具体 UI 模式 · 142K+

真实产品的具体屏幕：仪表盘、定价页、onboarding、结账、设置、付费墙、空状态、错误页。每屏带结构化元数据（描述、UX 模式、UI 元素、布局拆解、字体），Web 74,000+ 屏、iOS 67,000+ 屏。

Flows
任务旅程 · 12K+

多步骤任务旅程：从注册、订阅、升级到取消与账号删除，逐步记录步骤数、决策点、摩擦、恢复路径和系统响应。适合研究"一个任务应该在几步内完成"。

初学者只需要记住：决定"长得像谁"用 Styles（免费网页随便逛）；决定"这个屏幕该放什么"用 Screens；决定"流程该有几步"用 Flows。后两层通过 Refero MCP 提供给 Agent（见第 08 节），网页版免费的是 Styles 层。

04初学者上手五步

1
按任务选风格，不按品牌名选先明确你要做什么：landing page / dashboard / pricing page / onboarding / docs。官方建议按信息密度、语气、受众匹配参考，而不是因为"我喜欢 Linear"就选 Linear。做金融产品看 Origin Financial / Mercury，做开发者工具看 Resend / Vercel / Railway，做知识工具看 Notion。
2
读详情页的 do / don't 规则左右两列里，don't 部分对初学者价值最大——比如 Resend 的"品牌紫永不用于按钮"、Linear 的"圆角只有三个值"。这些禁忌直接决定你的页面会不会"穿帮"。
3
复制 DESIGN.md 放进项目根目录保存为项目根目录（和 package.json 同级）的 DESIGN.md。第三方实测建议：放进仓库而不是引用 URL——AI 工具对本地文件上下文的处理比抓取 URL 可靠，文件也成为可版本管理的稳定快照。
4
把文件"接线"到你的 Agent 工具关键一步，90% 的人漏掉：Agent 不会主动找一个叫 DESIGN.md 的文件。每种工具都有自己的入口配置文件，必须在那里显式指向它。逐工具接法见下一节大表。
5
给具体任务 + 做合规检查任务要具体（"设计一个定价区块"而不是"帮我做个页面"）；生成后让 Agent 对照 DESIGN.md 逐条自查（官方称 compliance pass）。修版时说"对齐 DESIGN.md 的字阶与间距规则"，而不是"再好看点"。

05逐工具接线表：让 Agent 真的读到它

DESIGN.md 是单一事实源（single source of truth），接线只需在每个工具的入口文件里加一行指针。改 token 时只改 DESIGN.md 一处，四个指针共用，避免多副本不同步：

工具自动加载的文件接法
Claude CodeCLAUDE.md（项目根）加一行 @DESIGN.md 导入，或写"写任何 UI 前先读 DESIGN.md"。@ 开头的行会把文件内容拉进会话记忆
Cursor.cursor/rules/*.mdc建一条 alwaysApply: true 的规则，内容指向根目录 DESIGN.md，要求 UI 代码前先读
GitHub Copilot.github/copilot-instructions.md引用或内联 token 块
Windsurf.windsurfrules同样指向根目录文件
AiderCONVENTIONS.md引用 DESIGN.md
Cline (VS Code).clinerules引用 DESIGN.md
v0 / Lovable / 网页对话工具无项目文件系统把 DESIGN.md 全文粘贴为对话第一条消息，前缀一句"以下规范适用于本次会话所有 UI 代码"

Claude Code 的推荐写法（@ 导入保持 DESIGN.md 独立可移植，Cursor/Codex/Copilot 也能读同一份文件）：

CLAUDE.md — 设计规范导入 + 防漂移规则
## Design system
The visual contract for this product lives in DESIGN.md.
@DESIGN.md

Rules:
- Read DESIGN.md before writing or editing any component, page, or style.
- Use only the color tokens, type scale, radius, and spacing values it defines.
- If a value you need is not in DESIGN.md, ask before inventing one.
- Never introduce a new shadow, gradient, or font family without approval.

第三条"缺值先问"是实测中最容易跳过、又最有效的一条：没有它，Agent 找不到 token 时会悄悄挑一个"合理"的近似值——你的产品用 #0061ff，它给你 #3b82f6，没人发现，直到设计评审。有了它，静默漂移变成一次简短对话。

验收接线是否生效（30 秒）：新开会话问 Agent："主色是什么？给出精确 hex 和 DESIGN.md 依据。"如果得到含精确 hex 值的回答 → 接线成功；如果得到泛泛描述或含糊回答 → @ 导入没生效，检查路径和文件名大小写。再让它"只用 DESIGN.md 的 token 建一个禁用态次级按钮"，观察返回的颜色/圆角值是否全部可溯源。

06三个可直接复制的 Prompt 模板

模板 1 · 首次生成新页面
请先阅读项目根目录的 DESIGN.md，这份文件是本项目唯一的视觉规范。 参考它帮我设计一个【定价页/设置页/落地页首屏】。 优先遵守（按顺序）：配色角色 → 字阶 → 间距节奏 → 圆角与组件形态。 不要发明 DESIGN.md 之外的颜色和字号；缺 token 时先问我。
模板 2 · 已有页面觉得"AI 味"重，做定向打磨
这个页面功能正常但视觉平庸。请对照 DESIGN.md 做一次聚焦 pass： 只改排版层级、间距节奏、组件视觉重量、一致性，不改任何业务逻辑。 逐条列出你改了什么、对应 DESIGN.md 的哪条规则。
模板 3 · 生成后的合规检查（官方称 compliance pass）
把你刚才生成的 UI 与 DESIGN.md 逐条对照检查： 颜色是否全部来自调色板？字号是否都在字阶内？间距是否都在 spacing scale 上？ 圆角是否只用了规定值？列出所有偏离项，逐项修复后再汇报。

07DESIGN.md 文件长什么样（Google 开源规范）

DESIGN.md 本身是 Google 开源的规范（google-labs-code/design.md，Apache-2.0 协议），专为 coding agent 设计。一个文件两半，各干各的：

YAML 前置区 — 机器可读 token

  • colors：命名色板，hex 必须加引号
  • typography：每级字体的 family / size / weight / lineHeight / letterSpacing
  • rounded / spacing：圆角与间距档位
  • components：组件级 token，用 {colors.primary} 引用而非重复 hex，保证色板单源
  • 变体不嵌套：button-primary-hover 是兄弟键，不是 button-primary.hover

Markdown 正文 — 人类可读的理由

  • 规范顺序：Overview → Colors → Typography → Layout → Elevation → Shapes → Components → Do's and Don'ts
  • token 告诉 Agent 有什么；正文告诉 Agent 什么时候用、什么时候禁止
  • "一个叫 primary 的 token 不够——Agent 需要知道 primary 属于哪里、避开哪里"
  • 官方 CLI：npx -y @google/design.md lint DESIGN.md，查结构错误 + WCAG 对比度
  • 可导出 Tailwind / W3C DTCG JSON
第三方实测的关键发现（UX Collective，2026-05）：大多数失败的 DESIGN.md 有同一个模式——以色板开头，没有任何产品语境。它们提供的是"描述"（系统长什么样），模型真正需要的是"约束"（系统允许什么、禁止什么、边界情况怎么办）。最强文件把理由直接嵌进 token 定义，例如：primary: #1B4DFF — 只用于 CTA 和激活态。永远不要当背景色，不要装饰性使用。一屏只允许一个 primary 动作；如果你需要两个，先重新考虑布局。另外 8 条精心挑选的"禁止"规则，比把 token 表翻倍更能防跑偏。

给初学者的可操作结论：用 Refero 的 DESIGN.md 做起点完全没问题，但花 10 分钟在文件最前面补 2–3 句产品 brief（产品做什么、给谁用、UI 必须帮用户完成什么），并检查 don'ts 区是否至少有 5–8 条硬性禁止——这两处是模板给不了、只有你能填的部分。原文说得直接："模型能极精准地提取 what；但 why——产品 brief、原则、边界——仍需要设计者的思考。留空这层，模型会用'听起来合理的推断'填满它，而那不是产品知识。"

08进阶：Refero MCP — 让 Agent 自己去研究

不想手动复制粘贴的话，Refero 提供官方 MCP server（需要 Refero Pro 订阅），Agent 在每个设计任务前自动搜索真实参考。官方称其效果为"先研究再构建"（It studies before it builds）：

Claude Code 接入（官方命令）
claude mcp add --transport http refero https://api.refero.design/mcp \
  --header "Authorization: Bearer <token>"
# 然后 /mcp 里登录；OAuth 用户省略 --header 走浏览器授权

# Cursor 写进 .cursor/mcp.json；Codex 写 TOML [mcp_servers.refero]
# Server URL: https://api.refero.design/mcp

接入后可以直接用自然语言驱动："Search Refero styles for developer tool websites"、"Search Refero screens for pricing page annual monthly toggle"、"Search Refero flows for subscription cancellation with retention offer"。官方还提供了一个配套技能（Agent 会先征求你同意再安装）：

Refero Skill（可选，免费，不依赖 MCP 也能用其方法论）
npx skills add https://github.com/referodesign/refero_skill --skill refero-design

两个必须知道的边界（来自官方文档）：① Styles 目前只覆盖网页营销/产品页（落地页、定价页、SaaS 官网），不含应用内 dashboard、登录页、iOS 屏幕的风格系统——做产品 UI 时先用 styles 定视觉语言，再用 screens/flows 补产品逻辑。② 数据全部留在服务端，只有你请求的结果返回。

09初学者最常踩的 6 个坑

坑 1 · 模糊词当 prompt
"高级感""干净""premium"——这些词几乎允许模型生成任何东西。改成引用具体规则："按 DESIGN.md 的 16px 卡片圆角和 96px section gap 做"。
坑 2 · 每个 prompt 换一个风格参考
今天 Linear 明天 Stripe，输出会漂移成风格大杂烩。一个项目锁定一份 DESIGN.md，修版时向同一份文件对齐。
坑 3 · 让模型从 Figma 无人监督生成 DESIGN.md
实测案例：Claude 能极精准提取所有 token，但会跳过产品访谈、自行编造设计原则。token 是对的，reasoning 层是编的。why 层必须人来写。
坑 4 · 文件越长越专业
第三方建议目标是 100–200 行（一屏 token + 一屏规则）。它每次 UI 任务都进上下文，长度是持续成本；Agent 能从代码里读到的东西不要写进文件。
坑 5 · 只下载不接线
放进根目录不等于会被读。Agent 按自己的入口配置文件加载上下文——CLAUDE.md / .cursor/rules / windsurfrules 里必须有一行指针（见第 05 节大表）。
坑 6 · 误以为 styles 覆盖一切界面
官方明确：styles 目前只是 web 营销/产品页的风格系统。做应用内 dashboard、auth、iOS 屏幕时，用 Screens/Flows 层补，别拿落地页风格硬套产品界面。

10使用守则速查

✓ 该这么做

  • 先选一个与产品气质、密度、受众接近的风格，再动手
  • 把 DESIGN.md 放仓库根目录，多工具共用一个事实源
  • 生成后必做一次 compliance pass（模板 3）
  • 修版对齐具体规则："对齐字阶/间距"，不说"再好看点"
  • 文件开头补 2–3 句自己的产品 brief，don'ts 补到 5–8 条
  • 品牌换版后重新生成，旧文件立即过时

✗ 别这么做

  • 别要求 1:1 复刻 Linear/Stripe/Resend——复制系统，不是复制网站（官方原话）
  • 别只按品牌名气选参考，要按信息密度和受众选
  • 别在无规范时用"高级感"类模糊词硬描述
  • 别复制 URL 引用代替本地文件——本地上下文更可靠且可版本管理
  • 别把 token 复制进四个配置文件——三份会悄悄过时
  • 别指望 styles 覆盖 dashboard/auth/iOS 风格系统（官方限制）

11适合谁，怎么开始

最适合三类人：① 不懂设计但高频用 AI 做网页/小工具/Demo 的 Vibe Coding 用户——"AI 味"的本质是 prompt 里缺视觉约束，DESIGN.md 把约束变成可复制文件；② 独立开发者——没有设计师时，2000 个真实产品的设计决策就是你的外部设计团队；③ 前端工程师——把设计评审从"感觉不对"变成"对照第 X 条规则偏离"。开始只需 5 分钟：打开 styles.refero.design → 挑一个顺眼的风格 → 复制 DESIGN.md → 按第 05 节接上你的 Agent → 用模板 1 下第一个任务。

免费额度已经足够个人使用（浏览与复制全部免费；MCP 自动化需要 Refero Pro）。收藏它的正确姿势不是"以后再看"，而是今天就把它接进你正在写的那个项目——下一个页面开始，界面的下限就被这份文件托住了。
