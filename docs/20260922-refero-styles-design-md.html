它和普通"设计灵感站"的区别

普通灵感站给你截图；Refero Styles 用左右两列呈现拆解结果：左边是设计决策（为什么用这种字体、按钮该是什么颜色、卡片圆角多少），右边是具体数值（token 名、px 值、hex 值）。哪些可以做、哪些不要做，都写成了规则。

这些拆解不是拍脑袋——每一条都来自真实产品页面的测量。下面是两个公开样例的原始数据：

Resend
"near-total darkness"——纯黑画布、石墨发丝边框、白字黑底。品牌紫只出现在邮箱字符串和代码高亮，从不出现在按钮上。
黑底终端美学衬线 Hero 96px紫色仅做点缀
品牌色 Iris Violet#9281f7（链接/标签/代码高亮专用）
Hero 字体Domaine Serif 96px / -0.01em，整页仅用 2 次
代码字体Commit Mono——出现 814 次，与 Inter 分庭抗礼
圆角双值系统按钮/徽章/输入框 6px；卡片 16px；禁止混用第三种
间距体系基数 4px，Section gap 96px，容器 1200px
分层方式靠 1px #292d30 边框，不用阴影
Linear
"midnight command center"——近黑表面 #08090a、纸白文字、一支酸性荧光绿做手电筒式点缀。
紧凑密度低字重 400–5100.5px 发丝边框
画布色 Void#08090a；点缀 Acid Lime #e4f222

字距-0.022em @ 48–72px；-0.011em @ 15px

装饰原则几乎无装饰，产品 UI（看板、issue 卡）本身就是唯一视觉纹理

DESIGN.md 怎么用（4 步）

1
选一个喜欢的设计风格在 styles.refero.design 按品牌、情绪、颜色、字体或 URL 浏览，打开详情页。
2
复制 DESIGN.md详情页提供完整的 markdown 规范：结构化 token（颜色/字体/间距/圆角/组件）+ 人类可读的使用理由。
3
放进项目根目录，或直接粘贴给 Agent适用于 workbuddy、trae、Cursor、Claude Code、Codex、v0、Lovable 等任何能读文件的 coding agent。
4
告诉 Agent 参照执行例如："请参考这份 DESIGN.md 的设计规范，帮我设计或优化页面。"AI 会按其中的颜色、字体、间距、组件风格和设计禁忌来写界面。
为什么有效："make it premium" 这类模糊指令几乎可以生成任何东西；而一份含颜色、字阶、间距节奏、组件说明的 DESIGN.md 给了 Agent 一个更小、更锐利的目标。DESIGN.md 本身是 Google 开源的规范（Apache-2.0），YAML 前置区放机器可读 token，Markdown 正文放使用时机与理由——token 告诉 Agent 有什么可用，prose 告诉 Agent 什么时候用。

✓ 适合这么做

  • 先选一个与产品气质接近的风格，再让 Agent 参照
  • 把 DESIGN.md 放在仓库根目录，跨任务复用
  • 生成后让 Agent 做一次"对照规范的合规检查"
  • 修版时说"对齐 DESIGN.md 的字阶/间距规则"，而不是"再好看点"

✗ 别这么做

  • 别要求 Agent 1:1 复刻 Linear/Stripe/Resend——复制系统，不是复制网站
  • 别只按品牌名选参考，要按信息密度和受众选
  • 别在无规范时用"高级感""干净"这类模糊词硬描述
  • 别每次 prompt 都换风格——会漂移成大杂烩

适合谁

不懂设计、但经常用 AI 做网页、小工具、产品 Demo 的 Vibe Coding 用户。功能写出来了、界面却有"AI 味"的问题，本质是 prompt 里缺一套视觉约束——DESIGN.md 把这套约束变成可复制的文件。免费浏览、免费复制，值得收藏。
