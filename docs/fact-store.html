HERMES · MEMORY PLUGIN

fact_store
Holographic 外挂记忆

把零散事实变成可检索、可推理、可纠错的本地知识层：SQLite + FTS5 + Trust Score + HRR，适合在 Hermes 中做“轻量但高密度”的外挂记忆卡片。

定位：本地优先、无外部依赖
核心：9 个 fact_store 动作 + fact_feedback
优势：搜索 / 关联 / 推理 / 矛盾检测
配置：plugins.hermes-memory-store

常用工作流

  • 写入：把新事实、偏好、决策、约束写入 store，形成可复用记忆。
  • 检索：用 search 做关键词召回；用 probe 精准问“某个实体有什么事实”。
  • 关联：用 related 找近邻事实，用 reason 做多实体组合推理。
  • 校验：用 contradict 找冲突事实，避免记忆污染。
  • 维护：用 update 修订，用 remove 清理过期事实，用 list 审视全量内容。

fact_store 全能力

  • add：新增事实，支持信任度初始值。
  • search：全文检索，依赖 FTS5。
  • probe：围绕实体回忆该实体相关事实。
  • related：找语义/实体相关条目。
  • reason：组合多条件、做 AND 式推理。
  • contradict：冲突检测，发现互斥/矛盾信息。
  • update：更新事实内容或属性。
  • remove：删除陈旧条目。
  • list：浏览/盘点当前事实集合。

使用技巧

  • 优先写“实体 + 断言 + 时间/来源”，后续 probe、reason 更稳。
  • 把“偏好 / 约束 / 已知决策”单独存，避免和任务笔记混杂。
  • 遇到不确定结论，先 search 再 contradict，最后再 update。
  • 给高可信事实更高 trust；低可信或临时信息保持保守，降低误召回风险。

上手建议 & 典型场景

  • 上手建议：先用最少字段记录高价值事实，形成“记得住、找得到、改得动”的闭环。
  • 建议搭配：会话结束自动抽取 + 手动补写关键事实 + 定期清理冲突项。
  • 典型场景：用户偏好、长期项目状态、产品规则、人物关系、版本差异、会议结论。
  • 适合对象：需要本地存储、低成本、可解释检索和事实级纠错的 Hermes 用户。
一句话理解：fact_store 不是“聊天记录仓库”，而是把 Hermes 的长期事实做成可搜索、可推理、可修正的本地知识层。
项目要点
存储本地 SQLite，默认路径 $HERMES_HOME/memory_store.db
检索FTS5 全文检索 + 实体回忆 + 组合推理
信任机制默认 trust 0.5，可通过 fact_feedback 调整
配置db_path / auto_extract / default_trust / hrr_dim
