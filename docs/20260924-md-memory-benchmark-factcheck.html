02 / "复杂工具反而翻车"的三个实锤机制

机制一 · 过度切片

写入时切碎，召回时失忆

文章说"六成翻车源于过度切片"。可验证的对应事实：Mem0 写入按 LLM 抽取事实分片存储；MemoryAgentBench 论文实测 Cognee 在准确检索类目仅 22.8 分（满分 100），并专门设了 FactConsolidation 数据集测"选择性遗忘"。切片粒度确实是结构化系统的真实失败面。

机制二 · 写入即滤除

"关键名词当噪音"有同款案例

Reddit 那位"排查大半天"的用户无法溯源，但机制成立：所有抽取式记忆（Mem0/LangMem）都要先过一道"什么值得记"的 LLM 判断——memento 实测显示 LLM 蒸馏偏向用户侧陈述，助理侧问题丢了约 60%（41.1%）。抽错在写入那一刻就发生了，日志里什么都没有。

机制三 · 遗忘即泄漏：文章称"3 个系统要求遗忘后数据泄漏"。直接证据未找到，但有旁证：MemoryAgentBench 的 SF（selective forgetting）类目里，Cognee 得分 2.3/100、MemGPT 也仅 3.0/100——"要求忘掉"和"真的删干净"在主流系统里几乎不成立。删不干净的普遍性，比"3 个系统"这个精确数字更值得警惕。

03 / 纯 MD 为什么能打：四个工程理由

理由机制证据
零写入损耗没有"什么值得记"的预判，原文全量保真，抽错的入口不存在Letta 实验：不做任何抽取直接存文件
检索够用现代模型 + BM25/grep 级检索，长上下文窗口内自读自答Letta 74.0% 仅用 2 个工具；OpenDB FTS5 实测 7.5ms 中位延迟
人类可审计记错了直接打开文件改，git diff 可追溯，错了能修文章核心卖点，与 CLAUDE.md/AGENTS.md 实践完全同构
成本近零无向量化 API、无图谱构建 LLM 调用、无数据库运维对照：图谱系统每问约百次模型调用（第三方估测）

但纯 MD 有边界：memento 数据里它单会话-assistant 类目崩到 41.1%（蒸馏丢助理侧事实）；MemoryAgentBench 显示长史档（115K-1.44M tokens）下结构化方法在事实更新类占优（Zep substring-EM 44%）。语料小、单人用、可全量读 → 纯 MD；跨会话综合、事实频繁更新、多实体关系 → 该上结构。

05 / 判断

可信的部分："先试纯 MD，不够再上专用系统"是被 Letta/memento/Mem0 三方数据共同支持的正确默认顺序；"复杂系统有写入静默失败面"有论文级证据。

别信的部分：97.1 并列最高分、快 5 倍、60% 翻车率、3 系统泄漏——这些精确小数在传播链里找不到母本，且与已知基准数字高度相似（97.1≈LongMemEval 单会话类目、1800≈Mem0 tokens/对话），大概率是"真数字张冠李戴"的二次加工。看见此类"实测 N 个任务"的转述文，先找 benchmark 仓库或论文原文，找不到就按传闻处理。
