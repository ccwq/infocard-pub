🔗 Setup URI 机制

Setup URI 格式为 obsidian://setuplivesync?settings=，包含加密的连接配置（含凭证）。第二个设备无需重复输入服务器凭证，只需导入 Setup URI 即可。

obsidian://setuplivesync?settings=eyJ1cmwiOiAiaHR0cHM6Ly9hbnlzdXMuY...（加密数据）

Setup URI 口令≠ Vault 加密口令。两者分开存储，切勿通过同一渠道传输。建议从运行中的第一台设备导出 Setup URI，而不是在服务器部署时生成的 URI（因为服务器配置可能与客户端实际配置不一致）。

📡 WebRTC P2P 通信模型
Device A ↔ 加密 Vault 同步 ↔ Device B
↑↓ Discovery & Connection ↑↓
Signalling Relay（Nostr 兼容 WebSocket）

· Signalling Relay（必须）：用于节点发现和连接协商，不存储或传输 Vault 内容。LiveSync 使用 Nostr 兼容的 WebSocket Relay。项目提供公共 Relay，也可自建。
· TURN Server（可选）：NAT/防火墙阻止直连时的兜底方案，只转发加密的 WebRTC 流量，无法读取 Vault 内容。
· Signalling Relay vs TURN：Signalling Relay 传输元数据（连接时序、IP 地址），TURN Server 传输加密流量，两者不可互换。
P2P Status 面板：命令 Self-hosted LiveSync: P2P Sync : Open P2P Status 打开。Announce changes（源设备）主动推送变更通知；Follow changes（接收设备）响应通知拉取数据。通知不含 Vault 内容，仅告知"有变更需拉取"。错过通知后 Replicate now 仍可安全执行。
🔐 端到端加密详解
Setup URI 口令
解密 Setup URI 中的加密连接配置（含服务器 URL、用户名、密码）。与 Vault 加密口令不同。
Vault 加密口令
保护同步 Vault 数据本身的密码。与服务器凭证完全独立。即便服务器被攻破，数据仍为密文。
Obfuscate Properties
可选选项：将笔记的文档属性（metadata）也加密。在 CouchDB/对象存储层面，属性名和值均为密文。
加密传输
数据在设备与服务器之间以 TLS 加密传输（P2P 模式为 SRTP/DTLS）。服务器存储的始终是加密后的数据块。

两个口令必须分开存储，切勿通过同一渠道传输。建议将 Setup URI 和口令分别存储在密码管理器不同条目中。

🗂️ 同步扩展：隐藏文件与 Customisation Sync
Hidden File Sync（推荐先配置）
选择性同步 .obsidian/ 中的指定隐藏文件和文件夹。仅在普通笔记同步正常工作后配置。可同步自定义片段、主题和插件配置，无需同步整个 .obsidian 目录。
Customisation Sync Beta（进阶）
独立管理 Obsidian 自定义项（设置、代码片段、主题、插件）。与 Hidden File Sync 不可同时同步相同文件。 适合需要精确控制哪些自定义项同步的场景。

两者均依赖基础笔记同步正常工作后逐步配置，方向明确（初始化来源）可避免覆盖冲突。建议先验证普通笔记双向同步，再开启扩展功能。

📋 CouchDB 快速上手（CouchDB 已就绪版）

前提：CouchDB 服务器已部署并可访问（参考上方部署方式获取 URL + 用户名 + 密码）。

1
在目标 Vault 安装并启用 LiveSync 插件
Community Plugins → 搜索 "obsidian-livesync" → 安装 → 启用
2
点击欢迎 Notice 打开引导向导
安装后出现「Welcome to Self-hosted LiveSync」提示，点击打开配置向导
3
选择「首次设置」→ 确认新建同步
若服务器已有数据，需确认是否覆盖（仅在确定要重建时覆盖）
4
连接方式：选择「手动配置」
或粘贴 Setup URI（推荐）— URI 已包含加密配置，无需手动输入服务器凭证
5
E2E 加密配置（强烈建议开启）
启用「End-to-End Encryption」→ 输入强 Vault 加密口令 → 可选「Obfuscate Properties」加密属性
口令 ≠ Setup URI 口令，两者独立保管
6
选择「CouchDB」→ 填入 URL + 用户名 + 密码 + 数据库名
移动端必须使用 HTTPS；桌面端本地连接可使用 HTTP
URL 格式: https://your-couch.example.com
7
测试连接（可选）→ 创建/连接数据库
测试会向服务器发送凭证（经 Obsidian 内部 API），部分检查需要 CouchDB 管理员权限
8
确认初始化 → 等待进度指示符完全消失
重启后保持 Obsidian 打开，直到状态栏显示「💤 等待变更」且所有进度图标消失
9
创建测试笔记验证双向同步
新建笔记 → 写入内容 → 确认出现在服务器端（或其他设备上）
10
从第一台设备导出 Setup URI，导入第二台设备
命令面板 →「Self-hosted LiveSync: Copy settings as a new Setup URI」→ 输入新口令 → 复制 URI → 第二台设备粘贴
新 Setup URI 由实际运行的配置生成，而非服务器部署时的原始 URI
🔧 常见问题与解决
「No Synchronisation Settings Found」—— 服务器无配置？
若服务器是新建的，选择「Use this device's settings」正常。若你期望有已有配置，先取消，检查选中的远程服务器是否正确。选择错误时取消并保持 LiveSync 禁用直到确认服务器。
「Could Not Read Synchronisation Settings」？
重试，或使用当前设备的设置继续覆盖。覆盖仍需要有效的网络连接。
进度指示符一直不消失？
在删除或重命名文件后，等待所有进度指示符消失再关闭 Obsidian。若长时间卡住，检查网络连接和服务器状态。
无法启动 LiveSync？
在修改或重置远程数据库之前，先尝试 Recovery and flag files（恢复和标记文件）机制，这是比直接修改数据库更安全的路径。
第二台设备同步很慢？
参考 Fast Setup Guide，通过预取服务器数据加速后续设备的初始化同步，减少首次拉取时间。
需要同时使用 Hidden File Sync 和 Customisation Sync？
两者不可同时同步相同文件。Customisation Sync 更适合托管插件/主题/片段配置，Hidden File Sync 更适合选择性同步指定隐藏文件。按需二选一。
P2P 连接失败？
使用 WebPeer（vrtmrz.github.io/obsidian-livesync/webpeer/）测试连接——它使用空 Vault，不测试笔记同步，只验证 P2P 节点发现和连接能力。
早于 Obsidian 1.7.2 的版本？
LiveSync v1.0 需要 Obsidian 1.7.2 及以上。如需在更早版本使用，请提交 Issue 并说明原因，开发者会评估是否可行。否则 Community Plugins 安装器会自动选择兼容旧版。

🖥️ CouchDB 手动配置命令详解

前提：CouchDB 已部署（如 fly.io），需完成以下 9 条配置后方可使用。每个请求需重复执行直到返回 200。Linux/macOS 使用 curl，Windows 使用 PowerShell iwr。

Linux / macOS（curl）
curl -X PUT "${couchHost}/_node/nonode@nohost/_config/chttpd/require_valid_user" -H "Content-Type: application/json" -d '"true"' --user "${couchUser}:${couchPwd}" curl -X PUT "${couchHost}/_node/nonode@nohost/_config/chttpd_auth/require_valid_user" -H "Content-Type: application/json" -d '"true"' --user "${couchUser}:${couchPwd}" curl -X PUT "${couchHost}/_node/nonode@nohost/_config/httpd/WWW-Authenticate" -H "Content-Type: application/json" -d '"Basic realm=\"couchdb\""' --user "${couchUser}:${couchPwd}" curl -X PUT "${couchHost}/_node/nonode@nohost/_config/httpd/enable_cors" -H "Content-Type: application/json" -d '"true"' --user "${couchUser}:${couchPwd}" curl -X PUT "${couchHost}/_node/nonode@nohost/_config/chttpd/enable_cors" -H "Content-Type: application/json" -d '"true"' --user "${couchUser}:${couchPwd}" curl -X PUT "${couchHost}/_node/nonode@nohost/_config/chttpd/max_http_request_size" -H "Content-Type: application/json" -d '"4294967296"' --user "${couchUser}:${couchPwd}" curl -X PUT "${couchHost}/_node/nonode@nohost/_config/couchdb/max_document_size" -H "Content-Type: application/json" -d '"50000000"' --user "${couchUser}:${couchPwd}" curl -X PUT "${couchHost}/_node/nonode@nohost/_config/cors/credentials" -H "Content-Type: application/json" -d '"true"' --user "${couchUser}:${couchPwd}" curl -X PUT "${couchHost}/_node/nonode@nohost/_config/cors/origins" -H "Content-Type: application/json" -d '"app://obsidian.md,capacitor://localhost,http://localhost"' --user "${couchUser}:${couchPwd}"
Windows（PowerShell iwr）
$creds = [System.Convert]::ToBase64String([System.Text.Encoding]::UTF8.GetBytes("${couchUser}:${couchPwd}")) iwr -UseBasicParsing -Method 'PUT' -ContentType 'application/json; charset=utf-8' -Headers @{ 'Authorization' = 'Basic ' + $creds } "${couchHost}/_node/nonode@nohost/_config/chttpd/require_valid_user" -Body '"true"' # 重复以上格式，更改 _config 路径： # chttpd_auth/require_valid_user # httpd/WWW-Authenticate = '"Basic realm=\"couchdb\""' # httpd/enable_cors = '"true"' # chttpd/enable_cors = '"true"' # chttpd/max_http_request_size = '"4294967296"' # couchdb/max_document_size = '"50000000"' # cors/credentials = '"true"' # cors/origins = '"app://obsidian.md,capacitor://localhost,http://localhost"'

关键参数：max_document_size=50MB（50,000,000 bytes）支持大文件笔记；max_http_request_size=4GB（4,294,967,296 bytes）允许大请求；CORS origins 必须包含 Obsidian 移动端 URL，否则移动端无法连接。

🪣 对象存储（S3 兼容）完整配置
1
创建 Cloudflare R2 Bucket（免费方案）
Cloudflare Dashboard → R2 → Create bucket → 命名（如 obsidian-sync）→ 创建 R2 Token（Object 读写权限）→ 保存 Access Key ID + Secret Access Key
2
获取 Endpoint URL
R2 → Manage R2 custom domains → 开启自定义域名或使用默认 R2.dev URL（如 https://abc.r2.dev）
3
在 Obsidian LiveSync 中配置
选择「Object Storage」→ 填入 Endpoint URL + Access Key + Secret Key + Bucket 名称
Endpoint 示例: https://xxx.r2.dev
4
移动端必须使用 HTTPS URL。桌面端本地测试可使用 HTTP。对象存储模式不支持冲突自动合并，覆盖写入。
支持的对象存储
Cloudflare R2（免费） · AWS S3 · MinIO（自建） · Backblaze B2 · 任意 S3 兼容服务。R2 免费 10GB/月，适合个人用户。
⚡ 大型 Vault 性能与注意事项
大文件笔记
max_document_size 需 ≥50MB。建议通过 CouchDB 配置 chttpd/max_http_request_size=4GB 支持超大请求体。
大量文件
首次同步会扫描整个 Vault 并上传全部 chunk。对象存储模式按文件而非 chunk 同步，无最小流量优化。
移动端后台
iOS/Android 可能在后台暂停 Obsidian。大型同步（首次、拉取、重建）期间保持 Obsidian 在前台可见。
CouchDB vs 对象存储
CouchDB 支持增量 chunk 同步，最小化流量。对象存储按文件粒度同步，大库流量更高。
🚀 5 步快速入门（初学者完整路径）

从零开始在第一台设备建立同步，再添加第二台设备。覆盖最小可用路径，所有可选步骤跳过。

1
安装插件
Obsidian → 设置 → 社区插件 → 搜索「Self-hosted LiveSync」→ 安装 → 启用。在要同步的 Vault 中操作（不要在多个 Vault 间共享同一个插件数据目录）。
2
获取 Setup URI
在服务器上运行（需 Deno 2）：
export hostname=http://localhost:5984 export username=你的用户名 export password=你的密码 export database=obsidiannotes export passphrase=你的保险库加密短语 curl -s https://raw.githubusercontent.com/vrtmrz/obsidian-livesync/main/utils/couchdb/couchdb-init.sh | bash curl -s https://raw.githubusercontent.com/vrtmrz/obsidian-livesync/main/utils/setup/generate_setup_uri.ts | deno run --allow-env -
将输出中的 Setup URI（以 obsidian://setuplivesync?settings= 开头）和 passphrase 分别保存。
3
在第一台设备导入 Setup URI
Obsidian → Self-hosted LiveSync → 点击欢迎通知 → 选择「I am setting this up for the first time」→ Connection Method 选「Use a Setup URI」→ 粘贴 URI → 输入 passphrase → Test Settings → 重启并初始化服务器 → 确认覆盖警告（仅首次新建时出现）。
4
验证同步正常
在 Obsidian 中创建或修改一个测试笔记 → 等待几秒 → 在 CouchDB Fauxton 界面（http://服务器:5984/_utils）查看笔记是否出现。确认后删除测试笔记。
5
添加第二台设备
在第一台设备：命令面板 → Self-hosted LiveSync: Copy settings as a new Setup URI → 输入新 passphrase → 复制生成的 URI。
在第二台设备：同样导入新 URI → 选择「I am adding a device」→ 测试笔记同步。

🔑 Setup URI 工作机制详解

Setup URI 是 obsidian-livesync 的核心配置分发机制，以 obsidian://setuplivesync?settings= 开头，包含加密后的连接参数。

passphrase（保险库加密短语）
用于加密同步的 Vault 数据（AES-256）。服务端只存储密文，无短语无法解密。这是保护笔记内容的关键，必须单独安全保存。不同 Setup URI 可使用相同短语（保持端到端加密一致）。
uri_passphrase（Setup URI 短语）
仅用于解密 Setup URI 本身（不加密 Vault 数据）。可与保险库加密短语相同或不同。建议分开保存，降低单一泄漏风险。生成 Setup URI 时，uri_passphrase 若省略，项目会自动生成随机值并只显示一次。

Setup URI 生成原则：每次添加新设备时，从已工作的第一台设备重新生成新 URI（而非使用初始部署时的那条），这样新设备拿到的是第一台设备当前实际使用的配置（包括所有中间配置变更）。

🖥️ LiveSync CLI 完整命令参考

无 Obsidian 环境下同步 Vault 的官方 CLI 工具，支持 daemon / sync / push-pull / P2P / systemd。

核心命令
livesync-cli /data/vault sync # 运行一次同步周期后退出 livesync-cli /data/vault daemon # 持续同步：CouchDB → 本地 + 文件监控 → CouchDB # 首次启动执行全量 mirror 扫描 livesync-cli /data/vault mirror /vault # 将数据库内容镜像到指定 vault 目录 livesync-cli -- init-settings /data/settings.json # 创建默认 settings.json printf '%s\n' "$PASSPHRASE" | livesync-cli -- /data/vault \ --settings /data/settings.json setup "obsidian://setuplivesync?settings=..." # 从 Setup URI 初始化设置文件
文件操作命令
livesync-cli /data/vault ls notes/ # 列出 notes/ 下文件：路径 大小 修改时间 版本 livesync-cli /data/vault cat notes/note.md # 读取数据库中的文件并输出到 stdout livesync-cli /data/vault push ./local.md notes/note.md # 将本地文件推入数据库 livesync-cli /data/vault pull notes/note.md ./local.md # 从数据库拉取文件到本地 livesync-cli /data/vault rm notes/old.md # 在数据库中标记文件为已删除

systemd 服务示例：创建 /etc/systemd/system/livesync.service，内容包含 ExecStart=livesync-cli /path/to/vault --settings /path/to/settings.json daemon --interval 60，然后 sudo systemctl enable --now livesync 开机自启。CLI 支持 --verbose 和 --debug 输出详细日志。Deno 运行时必需。

📡 P2P 同步完整操作流程（无服务器）

P2P 通过 WebRTC 直连两台设备，无需中心服务器。Signalling Relay 负责发现对方，传输内容全程加密，TURN 服务器仅在直连失败时兜底转发加密流量。

1
在第一台设备上配置 P2P
Obsidian → Self-hosted LiveSync 设置 → P2P → 填入 Signalling Relay URL（可使用项目公共 relay）、Group ID、加密短语 → 保存
2
打开 P2P Status 面板
命令面板 → Self-hosted LiveSync: P2P Sync : Open P2P Status → P2P Status 面板显示已连接设备
3
第二台设备加入同一 Group
安装插件 → 填入相同 Signalling Relay + Group ID + 短语 → 打开 P2P Status → 在第一台设备上审批第二台设备的连接请求
4
手动同步（验证配置）
在 P2P Status 中点击 Replicate now 执行一次双向同步。成功后再配置自动通知：源设备开启 Announce changes，接收设备开启 Follow changes
Signalling Relay vs TURN
Signalling Relay（必需）：发现设备、交换连接信息，不存储/传输 Vault 内容。项目公共 relay 只能观察连接元数据（时间/IP），无可用性保证。
TURN（可选）：仅在直连失败时通过中继转发加密流量，不能读取 Vault 内容，但可观察流量元数据。
🔧 常见错误与解决方案矩阵
524 错误 / Cloudflare 超时
Obsidian 插件设置 → Remote Database Configuration → Advanced → 开启「Use Request API to avoid inevitable CORS problem」
移动端无法连接
移动端必须使用 HTTPS。桌面端本地测试可用 HTTP。换用 Caddy / Tailscale / Cloudflare Tunnel profile 获取 HTTPS。
init 容器反复重启
CouchDB 尚未就绪。等待 30 秒后检查 docker compose logs couchdb。健康检查应已阻止此问题。
CORS 报错（浏览器）
确认 CouchDB headers：curl -v -H "Origin: app://obsidian.md" http://localhost:5984/。需包含 app://obsidian.md 和 http://localhost。
Nginx 404 Database not found
Nginx location 不要在子路径挂载 CouchDB（官方推荐挂载在根路径 /）。确认 proxy_pass 指向 localhost:5984。
P2P 设备找不到对方
所有设备 Signalling Relay URL、Group ID 和 P2P passphrase 必须一致。设备名称需唯一。使用「Refresh」刷新发现列表。
Vault 加密短语丢失
加密短语无法恢复。服务端存储的是加密后数据，无短语则无法解密。请使用密码管理器妥善保管。
文件变更未同步
检查 chokidar 文件监控是否正常工作。大型 Vault 首次同步需保持 Obsidian 在前台可见。iOS/Android 后台暂停可能导致同步中断。

🌐 Nginx / Caddy 反向代理配置要点

移动端必须通过 HTTPS 访问 CouchDB，自建 CouchDB 需配置反向代理获取 TLS。官方文档特别指出常见错误和正确配置。

Caddy（推荐，TLS 自动）
sync.example.com { reverse_proxy localhost:5984 encode gzip }
Caddy 自动从 Let's Encrypt 获取 TLS 证书，无需手动管理证书续期。docker/README.md 提供官方 couchdb+caddy docker-compose.yml。
Nginx（需手动配置 TLS）
server { listen 443 ssl; server_name sync.example.com; ssl_certificate /path/to/cert.pem; ssl_certificate_key /path/to/key.pem; location / { proxy_pass http://localhost:5984; proxy_set_header Host $host; proxy_buffering off; # 避免超时卡死 } # 重要：不要在子路径挂载 CouchDB！ # CouchDB 需挂载在根路径 / }
Nginx 常见坑：proxy_buffering on 会导致大请求超时；CouchDB 必须挂载在根路径（/）而非子路径；如配置了自定义 HTTP 头，需同步更新 CouchDB CORS origins。

📱 移动端兼容性、安全加固与加密选项
HTTPS 强制
移动端 Obsidian 要求服务器必须有有效 SSL 证书。本地自建 CouchDB 需通过 Cloudflare Tunnel / Tailscale Funnel / Caddy 反向代理获取公网 HTTPS。HTTP 仅限桌面端本地测试。
CORS 必需配置
CouchDB CORS origins 必须包含：app://obsidian.md,capacitor://localhost,http://localhost。使用 curl -v -H "Origin: app://obsidian.md" http://localhost:5984/ 验证响应头是否包含正确的 Access-Control-Allow-Origin。
后台保活技巧
iOS/Android 在后台会暂停 Obsidian。首次全量同步、大型 Vault 重建期间建议：保持 Obsidian 在前台可见、开启勿扰模式、连接充电器。iOS 可在设置中为 Obsidian 开启「后台 App 刷新」。
Vault 加密（AES-256）
插件设置 → End-to-End Encryption → 填入 passphrase。额外可开启 Obfuscate Properties（混淆文档属性，使文件名、标签、frontmatter 字段名也变成密文）。服务端只存储密文，丢失 passphrase 后数据无法解密。推荐使用 1Password / Bitwarden 保存 passphrase。
安全加固清单
① CouchDB 启用 require_valid_user；② CouchDB 密码与 Vault 加密短语分开管理；③ CouchDB 密码建议 20+ 字符随机串；④ Caddy 反向代理开启 HSTS；⑤ 避免在同一个数据库中混用多个 Vault；⑥ 使用官方 couchdb-init.sh 而非手动配置 admin 账号。
💡 为什么选 LiveSync 而非官方 Obsidian Sync
成本
Obsidian Sync 收费 $4/月/5GB。LiveSync 仅需自建 CouchDB（免费）或 Cloudflare R2（免费 10GB/月）。适合预算有限的个人用户。
自托管
数据完全在自己控制的服务器上，无第三方依赖。服务端只存储 E2E 加密后的密文，服务商无法读取笔记内容。
灵活性
支持 CouchDB / 对象存储 / P2P 三种方式，可根据条件灵活选择。CLI 支持无 Obsidian 环境下的同步和备份脚本化。
与官方 Sync 不兼容
LiveSync 和官方 Obsidian Sync 不能同时开启。切换前需先禁用原同步服务并备份 Vault。
