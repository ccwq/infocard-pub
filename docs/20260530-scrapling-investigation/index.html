一句话判断
Scrapling 更像“可扩展的抓取操作系统”，不是一个页面选择器库。它的定位覆盖：轻量 HTTP 抓取、动态浏览器抓取、反检测、爬虫调度、CLI 工具、MCP 服务化。
它到底是什么

核心组成

  • parser：`Selector` / `Selectors` 负责 HTML 解析与选择器链路。
  • fetchers：`Fetcher`、`DynamicFetcher`、`StealthyFetcher` 覆盖 HTTP、浏览器和反检测场景。
  • spiders：`Spider`、`Scheduler`、`SessionManager`、`Request`、`Response` 形成完整爬虫框架。
  • CLI / MCP：可直接命令行运行，也可作为 MCP server 暴露给模型工具链。

官方信号

  • GitHub stars 约 55,219，forks 约 5,328。
  • PyPI 当前版本 0.4.8，`requires-python >= 3.10`。
  • 仓库自带 Dockerfile 与 server.json，说明容器化 / MCP 都是官方路径。
  • README 明确写了：能从“单次请求”一路扩展到“full-scale crawl”。
验证结果
Direct install：通过
独立环境中 `pip install -e ./Scrapling` 成功。
加上 `[...] [fetchers]` 额外依赖后也成功。
`Selector(html)` 与 `.css(...).get()` 能正常解析本地 HTML。
Container：官方支持，但构建依赖运行时可用
仓库内 `Dockerfile` 完整可用，且包含 Chromium / Playwright 依赖安装。
但只要容器运行时的存储配置存在冲突，构建就可能受阻。
结论：容器路线可行，但不是无条件即用。
最短路径：先直装；需要浏览器自动化 / MCP 服务化 / 环境隔离时，再切容器化。
安装与依赖画像

基础包

  • `lxml`、`cssselect`、`orjson`、`tld`、`w3lib`、`typing_extensions`。
  • 这意味着纯解析 / 轻量抓取门槛不高。
  • 不依赖浏览器就能跑起一部分功能。

额外能力

  • `fetchers` extra 拉入 Playwright / Patchright / browserforge / anti-bot 相关依赖。
  • `ai` extra 加上 `mcp` 与 `markdownify`。
  • 动态抓取和 MCP 服务都属于“重依赖”侧，不是纯解析侧。
建议怎么选
如果你现在只是想把它装起来、调通 API、写解析逻辑：直接安装更优。
如果你要把浏览器依赖、Chromium、Playwright、MCP 一起打包成稳定交付：容器化更优，但前提是容器运行时先可用。
