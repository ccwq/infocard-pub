# book-to-skill：将技术书籍转化为可推理的 Agent Skill

**调查员**：王记者 (Investigative Journalist)
**日期**：2026-05-31
**关键词**：book-to-skill, Claude Code Skill, 知识结构化, Docling, PDF extraction

## 1. 项目概况

**book-to-skill** 由开发者 virgiliojr94 创建，解决了技术从业者的经典痛点：买了一本好书、读了一遍、三个月后连第七章讲过什么内容都不记得了。

该项目的核心命题是：**与其在需要某本书的知识时去搜索 PDF 或依赖大模型的压缩知识，不如在编译阶段将书结构化成一个可直接推理的 Skill。**

- ⭐ **GitHub Stars**：2,800+（发布仅 1 个月）
- 🔀 **Forks**：364
- 📄 **许可证**：MIT
- 🕐 **最近更新**：2026-05-17（2 周前，18 次提交）

## 2. 核心设计：为什么不是 RAG？

项目的 README 花了大篇幅正面回应了一个尖锐问题——"这不就是 RAG 吗？"

| 维度 | RAG | book-to-skill |
|------|-----|---------------|
| **工作时机** | 查询时（query time）分块 → 嵌入 → 向量检索 → 注入 prompt | 编译时（compile time）一次性深度分析 → 结构化输出 |
| **输出本质** | "这是与你的查询相似的文本片段" | "这是作者花数年构建的 12 个框架，准备好推理了" |
| **检索方式** | 语义相似度匹配 | 按章节/概念名称精确加载 |
| **Token 开销** | 每次对话都消耗上下文预算 | 只加载相关章节（on-demand） |
| **幻觉控制** | 依赖分块召回质量 | 锚定在你提供的原始副本上 |

**王记者判断**：这个对比是诚实的。RAG 解决的是"跨 50 本书的搜索"，而 book-to-skill 解决的是"深入一本书并将其框架嵌入工作流"。两者不是替代关系，而是不同场景的优化。

## 3. 生成产物

执行 `/book-to-skill your-book.pdf` 会在 `~/.claude/skills/<slug>/` 生成完整的 Skill 目录：

| 文件 | 用途 | 大小 |
|------|------|------|
| `SKILL.md` | 核心心智模型 + 章节索引 | ~4,000 tokens |
| `chapters/ch01-*.md` | 逐章摘要，按需加载 | ~1,000 tokens/章 |
| `glossary.md` | 术语表，字母排序 + 章节引用 | ~1,500 tokens |
| `patterns.md` | 全部技术、算法与设计模式 | ~2,000 tokens |
| `cheatsheet.md` | 决策表与快速参考规则 | ~1,000 tokens |

**关键创新**：章节文件是按需加载的（on-demand），它们不消耗 Skill 预算，直到你主动询问相关主题时才被加载。

## 4. 提取技术栈：文档智能的务实选择

项目支持 7+ 种文档格式（PDF、EPUB、DOCX、TXT、MD、RST、ADOC、HTML、RTF、MOBI/AZW），并针对不同文档类型设计了分层提取链：

### PDF 提取（最核心场景）
根据书籍类型自动选择提取方法：

**技术类书籍（含代码、表格、公式）→ Docling**
- 由 IBM 开发的文档智能工具，布局感知
- 将表格和代码块作为 Markdown 保留
- 速度：约 1.5s/页
- **基准测试**（103 页技术书）：164s → 27K tokens，保留 48 个表格和 36 个代码块

**文本类书籍（以散文为主）→ pdftotext → PyPDF2 → pdfminer**
- pdftotext（poppler-utils）瞬时完成
- 无额外依赖，适合纯文本内容

### 其他格式提取链
- **EPUB**：ebooklib + BeautifulSoup4 → stdlib zipfile 兜底
- **DOCX**：python-docx → stdlib ZIP/XML 解析器兜底
- **MOBI/AZW**：Calibre `ebook-convert`
- 所有文本类格式（TXT/MD/RST/ADOC）直接读取，零依赖

## 5. 设计原则

项目明确列出了 5 条设计原则，构成了其方法论基石：

1. **密度优先于完整性**——1,000 token 的精炼摘要比 10,000 token 的原始摘录更有价值
2. **实践者口吻**——"当 X 发生时使用 Y"，而非"这本书解释了 X"
3. **SKILL.md 前置加载**——压缩机制保留前 ~5,000 token，最重要的内容放在最前面
4. **按需加载章节**——主题索引告诉 Claude 该读哪个文件，只有需要时才加载
5. **永不出售原始文本**——始终综合、总结、从源头提取信号

## 6. 适用场景与边界

**最适合的场景**：
- 你有一本想要深入掌握的技术书
- 你希望在编码时让这本书的知识"坐在你旁边"
- 书籍包含了 Claude 训练数据中未收录的框架或内部文档

**不推荐的场景**：
- 你需要跨 50+ 本书搜索 → NotebookLM 更适合
- 热门书籍（Clean Code、DDIA）→ Claude 已有通用知识，精细度不如原始副本
- 只想快速查找术语定义 → 传统 PDF 搜索更快

## 7. 王记者结论

book-to-skill 的价值不在于"把 PDF 变成文本"——那是 OCR 厂商 20 年前就做的事。它的真正创新在于**将作者花了数年构建的框架以 Agent 可推理的结构完整呈现**。

这不是又一个 RAG 工具。它是"知识封装器"：让一本书在读完很久之后，仍然能以结构化的方式参与你的日常工作流。

对于使用 Claude Code 或 Amp 进行 AI 辅助开发的重度用户来说，这是一个值得安装的工具。⭐ 2.8k 的成长曲线也说明社区已经用脚投票了。
