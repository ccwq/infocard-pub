核心结论

TL;DR

不是 RAG，是"知识编译"

RAG 在查询时分块检索；book-to-skill 在编译时一次性深度分析，输出作者的框架、原则和反模式——可推理，不可搜索。

按需加载章节

只有你问到的章节才消耗 token。400 页的书不再一次性烧掉 200K 上下文预算。

RAG vs Skill

适用边界

When to Use

✅ 适合

深入掌握一本技术书 · 编码时让书"坐在旁边" · 内部文档/未收录框架的知识结构化

❌ 不适合

跨 50 本书搜索 → 用 NotebookLM · 热门书籍通用问答 · 纯术语查找
