先把“实测数字”放回证据层级99.93% 很值得看，但不能改写成 DeepSeek 或 Pi 的承诺

原帖说了什么？ 用户/社区证据

yibie 转述：EvanDeKim 在 Pi harness 上跑 DeepSeek V4 Flash，缓存命中 99.93%，约 $2.65 换来近十亿 token；原帖还用“$0.87/M 输出、$0.25/M 缓存命中”做了直观换算。

边界声明：这些是用户实测与社区转述，不是 Pi 官方或 DeepSeek 官方对命中率、成本、节省倍数的承诺。命中率取决于请求前缀、缓存生命周期、provider/router 路由与实际 usage；生产预算必须按全 miss 仍可接受来设计。

官方 DeepSeek 价格

官方价格页按模型、输入 cache hit / cache miss、输出分别计费；当前页面显示的 V4 Flash / V4 Pro 费率应以部署时实时页面为准。

官方维度含义
cache hit命中可复用前缀的输入 token
cache miss未命中缓存的输入 token
output输出 token 单独计费

官方源：api-docs.deepseek.com/quick_start/pricing

机制：api-docs.deepseek.com/guides/kv_cache

真正该记录的 telemetry

prompt_tokens = prompt_cache_hit_tokens + prompt_cache_miss_tokens hit_rate = hit / prompt_tokens input_cost = hit/M × hit_price + miss/M × miss_price # 不要只看“估算节省” # 还要加 output、reasoning、重试、路由与质量成本

DeepSeek 官方说明缓存是 best-effort，不保证 100% 命中；应用应读取 API 返回的 usage 字段，而不是凭字符串相似度预测。

03

从“更强”转向“边界内自主”工具选择、结构化输出、按需思考，指向同一个生产化问题

defaultTools：启动面可配置

defaultTools 选择初始启用的内置工具；项目设置可覆盖全局设置。空数组可关闭内置默认工具，但扩展/SDK custom tools 仍可保留；0.84.2 还修复了 custom tools 被误丢的问题。

JSON Schema：让工具输出可约束

0.84.2 的实验性 strict JSON-schema constrained sampling 作用于默认工具，核心不是“让模型更聪明”，而是缩小工具参数的有效空间。实验开关与 provider 支持边界必须写清。

deep_think：把思考变成按需工具

原帖转述 @_can1357 的实践思路：关闭强制 thinking，把深度思考封装成 deep_think 工具，让模型自行判断何时付出额外推理开销。

这是工作流技巧/社区实践，不是 Pi 0.84.x 官方新特性。

一句话判断

缓存优化解决“每轮都贵”，defaultTools 解决“默认能做什么”，Schema 解决“输出能否落地”，deep_think 解决“什么时候值得想深”。共同目标是：把自主性放进可观测、可约束的边界里。

05

一套可复用的 Pi + DeepSeek 成本实验先测量，再优化；不要把一次 warm cache 当成 SLA

固定实验条件

锁定 model、provider/base URL、Pi 版本、session、系统 prompt 前缀与工具 schema；记录时间窗口。

读取原始 usage

保存 prompt_tokens、prompt_cache_hit_tokens、prompt_cache_miss_tokens、output/reasoning tokens 与错误/重试。

做 A/B

对比原始 Pi、pi-cache-optimizer、不同 proxy routing；把命中率与总成本分开看。

按 miss 预算上线

命中是优化收益，不是正确性前提；缓存清理、路由漂移或前缀变化后，系统仍应可接受地运行。
