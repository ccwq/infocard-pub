数据传输架构

Mesh P2P · 直连优先

设备间直接加密传输，防火墙后自动中继，无中心服务器瓶颈。

节点 A 文件 → AES-128 加密
直连 / 中继 BitTorrent 协议传输
节点 B/C/D… 解密写入本地存储
数据不经过任何云端服务器，不存在云端审查、限速或服务商倒闭风险。
适合隐私敏感、需要多设备大文件同步且能接受闭源商业工具的用户；不适合需要开源透明、自托管完全可控、或追求完全免费无限制的用户。

Resilio Sync 通过 P2P Mesh 网络实现设备间直接同步，突破传统云盘的限速、大小限制和隐私风险。v3.0 后免费版已开放原 Pro 功能，非商业用户可免费使用完整特性。缺点是闭源商业软件，无公开安全审计，Connect 服务器需自托管或付费。

2
核心技术

工作原理

BitTorrent 协议改造 + AES-128 加密 + Mesh 组网

传输协议

基于 BitTorrent 协议改造的文件同步，不依赖中心服务器。数据以分片方式在设备间传输，支持断点续传和并行多源下载。

加密机制

AES-128-CTR 加密，密钥可随机生成或由用户自定义。密钥派生自"Secret（密钥）"，通过安全通道分发给其他用户。

网络拓扑

Mesh 网络：所有节点对等，可同时连接多台设备形成网状拓扑。直连优先，无法穿透防火墙时自动通过中继节点转发。

重要约束：至少需要 2 台设备在线才能触发同步。同步对象仅为设备上已有的文件夹，无主动推送通知功能（部分版本有中继邮件通知）。

安装使用

快速上手

各平台安装方式与基本同步流程

Windows / macOS / Linux

  • 访问 resilio.com/individuals 下载对应客户端
  • 运行安装程序，启动后访问 http://localhost:8888/gui/
  • 注册账号（免费，非商业用途）或跳过
  • 点击「+」→ 输入密钥或扫码添加同步文件夹
  • 设置同步方向（双向/单向/只读）

移动端（Android / iOS）

  • 在应用商店搜索「Resilio Sync」或「BitTorrent Sync」
  • 安装后打开，扫码或输入密钥添加文件夹
  • 可在后台持续同步（iOS 需保持 App 运行）

Linux 服务器（headless）

  • wget https://download.resilio.com/stable/linux-x64/resilio-sync_x64.tar.gz
  • 解压后运行：./rslsync --webui-port 8888
  • 浏览器访问 http://服务器IP:8888
  • 或使用 systemd 服务文件长期运行

私有 Connect 服务器（可选）

  • 适用于企业内网中继或公网穿透
  • 需要额外安装 Connect Server 软件
  • 在客户端设置 → 服务器中填入 Connect 地址
  • 官方提供 Docker 部署方式
密钥安全提示

密钥（Secret）= 同步权限。分享密钥即等于授权对方访问该文件夹的完整读写权限。使用「加密文件夹」功能可让对方只下载加密后的数据，无法解密原始内容。

7
隐私安全

加密与风险分析

AES-128 加密 + 密钥管理 + 已知限制

✓

本地存储

数据存于本地设备，不经过任何云服务器，无云端扫描或删除风险。

✓

AES-128 加密

传输过程端到端加密。加密文件夹模式可让中继节点也无法解密内容。

✓

无账号云端数据

不登录则无任何用户数据存于 Resilio 服务器。

✗

闭源无审计

无公开源码，无独立安全审计。AES-128 实现细节未知。

✗

密钥泄露风险

密钥分发依赖手动操作，分享渠道本身存在被拦截风险。

—

公司存续风险

商业公司可能停止服务。Syncthing 为开源替代，Resilio 倒闭后仍可持续使用。

适用场景

最佳用途与局限

明确适合和不适合的场景

适合的场景

  • 摄影师/设计师多设备同步大型素材库（无大小限制）
  • 隐私敏感文档（病历、财务、法律文件）不想上传云盘
  • 团队内网文件共享（配合 Connect 服务器）
  • 本地 NAS 数据异地备份（无额外云成本）
  • 开发者在多台机器同步代码和配置
  • 家庭成员间共享照片视频（无云端审查）

不适合的场景

  • 需要实时通知或主动推送（无此功能）
  • 单一设备场景（需要至少 2 台设备在线）
  • 需要协作编辑同一文件（不提供冲突解决，需用 Git）
  • 希望数据由他人托管（自建成本高，服务商更方便）
  • 对开源有硬性要求
