RESEARCH FRAMEWORK

EnvHarness：给 Agent 配上会调难度的训练场

交互环境建成即静态，不管 Agent 进步多少，规则不变。EnvHarness 把 agent harness 思想反过来用——用插件层包住冻结的环境，使其动态可控。

STATIC ENV → TRAINING GYM

CORE INSIGHT

问题是：环境建成即静态

交互环境贵且建成即静态：不管哪个 agent 来、进步多少，环境行为不变，既不能针对弱点也不能继续教。agent harness 用插件（skills/memory/tools）让冻结的 LLM 变强。EnvHarness 把这个思路反过来用。

用插件层（harness）包住冻结的环境，不碰环境内部代码，只改 agent 观察到什么、能做什么、从哪开始。决定成败的 goal predicate 不动——重塑后的环境保留原 benchmark 的人工验证器。

解决方案：环境插件层

EnvHarness 在标准 reset/step 接口上套一层 harness，三种组件可自由叠加：

  • Setup：重塑初始状态（每次 reset 重放固定动作列表）
  • Rule：重塑交互（per-step 钩子，限动作/改转移/改观察）
  • Link：把另一个环境的任务组合进来

代码即 harness：designer 产出真 Python（子类 _Rules(Rules)），在隔离子进程编译执行，坏的变异变成记录的 trace 而非死跑。

THREE HARNESS COMPONENTS
Setup
RESET 阶段重放
每次 reset() 时，在真实环境执行前先自动重放一段固定动作列表。改变任务起点，但不碰任务目标。
例：Agent 经常从「空目录」开始学不到东西 → Setup 把目录预先填入旧版本代码，使其每次都在「已有部分代码」的场景下挑战
Rule
STEP 阶段拦截
对 agent 发出的动作、环境的转移和返回的观察挂 per-step 钩子。改变 agent 能做什么/看到什么，但不改变 goal predicate。
例：Agent 改完代码就提交不跑测试 → Rule 加约束「没运行测试先不让提交 commit」，强制训练测试习惯
Link
跨环境组合
把另一个环境的任务引用进来，在当前 harness 的上下文中执行。实现多 benchmark 跨域联合训练。
不进入环境特定代码，同一 harness 系统跨 ALFWorld/WebArena/SWE-bench 通用
硬契约：get_env_state 只带数据不带句柄（跨子进程边界）；save_state/from_state 由各 benchmark 自定义； checkpoint JSON 里 harnesses 数组顺序为 innermost → outermost

03
重新试跑
在新重塑的环境里验证策略是否改进，坏变异变成记录的 trace
→
04
迭代循环
Agent 进步后重复循环，共同进化；信号是针对性和持久性
信号特征：针对性的（针对诊断出的具体缺陷）且持久的（agent 进步后环境持续给出新的针对性挑战）。不是随机增强或固定菜单选择——designer 产出真实 Python 代码，不是从固定菜单中选配置。

  2. Claude on Vertex AI：gcloud auth application-default login + GOOGLE_CLOUD_PROJECT
  3. Gemini：GEMINI_API_KEY（多 key 用 GEMINI_API_KEYS 分摊避免 429）

EXTENSIBILITY

新 Benchmark 接入

只需实现 ActionableEnv 七方法接口，下游全复用：

  • reset()
  • step()
  • observe()
  • evaluate()
  • get_env_state() — 只带数据不带句柄
  • save_state()
  • from_state()

两个硬契约：get_env_state 不带句柄；save_state/from_state 由各 benchmark 自定义序列化格式。

checkpoint JSON 里 harnesses 数组按 innermost→outermost 顺序排列；tag 字段是磁盘格式标识，改变会使旧文件失效。

新 Harness 层扩展

子类化 EnvHarness，单轴层 = 单方法覆盖。

例：写一个 MySetup(Setup) → 只覆写 setup() 一个方法即完成新类型 harness。

所有组件叠加在同一标准接口上（reset/step），不侵入 benchmark 内部代码，实现真正的跨域通用。

HONEST DISCLAIMER · READ BEFORE OVER-INTERPRETING
⚠ 计算开销

设计环境有额外计算开销（生成 harness、诊断循环、子进程隔离）。README 与推文均明确承认：步数减少不必然等于总成本降低。

⚠ 实测数据来源

全部实验数据由 Gemini 模型产出（3 次独立运行均值），为研究框架内部评估，非第三方独立 Benchmark 验证。

TAKEAWAY
EnvHarness 把「让静态环境动起来」这件事，交给代码即 harness 的 designer 循环——不碰 benchmark 内部，只用 Setup/Rule/Link 重塑 agent 能做什么和从哪开始，让训练真正追上 agent 的进步。
