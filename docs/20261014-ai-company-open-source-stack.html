身份与首个行动：先判断你在做什么

业务使用者

先改一个工作流

A

销售、产品、财务与支持

先看 Knowledge Work Plugins，选择与你岗位匹配的一个插件。写清“输入是什么、输出谁审核”，先只接只读数据。

首个行动

挑一件重复工作，例如工单分流或会议准备。用脱敏材料走一遍，比较人工修改量；不先开放发送邮件、付款或删除权限。

工程团队

先保住质量门槛

B

已有 coding agent

Addy 更偏工程生命周期；wshobson 更偏按语言与任务分工的插件目录。它们依靠现有宿主运行，不是模型或应用服务器。

首个行动

选一个有测试的小任务，先用 Addy 的规格、测试与审查流程，再按缺口加一个 wshobson 插件；记录实际改动与测试证据。

AI 产品开发者

先建单任务原型

C

需要程序化编排

02

五层地图：它们不是互相替代的十个选项

分层为编辑解释，非官方联合架构；能力有重叠，先查现有功能。

① 工作方法层

wshobson / Knowledge Work Plugins / Addy Agent Skills：为已有 AI 宿主提供角色、技能和工作流程。

回答“怎样做”；缺的是宿主能力、业务权限和真实执行证据。

② 应用与编排层

Claude Quickstarts / Agno / Mastra：分别提供参考实现、Python 框架与运行平台、TypeScript 应用框架。

回答“怎样接入模型与工具并组织步骤”；示例集合不等同于可直接上线的框架产品。

③ 记忆与上下文层

Cognee / Graphiti：前者把文档、代码与对话整理成可检索记忆；后者强调事实随时间变化与来源追溯。

回答“保留和检索什么”；仍需数据隔离、纠错、删除与来源验证。

④ 执行隔离层

E2B：通过 JavaScript 或 Python SDK 管理隔离沙箱，承接 AI 生成代码及相关工具执行。

回答“在哪里运行”；网络出口、密钥暴露和高风险动作依然需要单独治理。

⑤ 评测与回归层

DeepEval：针对 LLM 应用、检索、工具调用和轨迹组织质量评测。

回答“这次是否真的更好”；评分取决于测试集、指标与裁判，不是事实真伪的最终裁决。

按需编排、检索、执行并保留评测轨迹；不必把五层全部装齐。

工作方法 · 按任务扩展

01 · wshobson/agents

具体能力：把领域 agents、skills 与 commands 打包为插件，支持 Claude Code、Codex、Cursor 等多种宿主的不同安装路径。

何时选：已有编码工具，但 Python 开发、代码审查或安全扫描缺少专门流程。先选单插件，而非整套全装。

限制：适配器会改变组件形态、模型映射和权限；只装 skills 不含完整 agents、commands 或 hooks。仓库内部评估也不能代替项目真实验收。

02 · Knowledge Work Plugins

具体能力：按销售、支持、产品、法务、财务、数据等岗位组织技能、命令、连接器及子代理，主要面向 Claude Cowork，也兼容 Claude Code。

何时选：需要把团队术语、流程和业务工具接入已有 Claude 工作环境，而不是开发新服务。

限制：通用模板需要公司化改造；连接器仍要授权。法务和财务插件不是执业判断或合规审批的替代品。

03 · Addy Agent Skills

具体能力：用技能约束从定义需求、计划、实现到验证、审查与交付的工程生命周期，提供不同 coding agent 的接入说明。

何时选：模型能写代码，却经常跳过规格、测试或审查；需要明确的质量关口与退出条件。

限制：技能文本不是执行强制机制。宿主的 slash commands 不一定可移植；单技能安装还可能缺少仓库级共享 references。

04 · Claude Quickstarts

具体能力：提供客服、金融分析、computer use、browser use、编码代理等应用示例；部分展示工具接口，部分展示完整交互流程。

何时选：希望围绕 Claude API 理解实现模式，从一个与场景相符的子目录起步。

05 · Agno

具体能力：SDK 用于构建 agents；AgentOS 承接服务运行；UI 用于管理。官方材料还列出存储、工具集、人工批准、可观测性与权限能力。

何时选：Python 团队要把 Agent 从脚本变为可管理服务，希望掌控数据库与运行部署。

限制：框架能力不等于已正确配置的多租户系统。需实测鉴权、数据隔离、故障恢复和部署依赖；还应审查遥测选项。

06 · Mastra

具体能力：组织 agents、图式 workflows、工具和模型接入，支持人工介入、存储状态、上下文管理、评测与观测，并可接入现有 Web 应用。

何时选：现有 TypeScript / Node / React / Next.js 技术栈，需要受控多步骤流程而不是临时提示词链。

限制：持久化与审批恢复要验证。核心大部分为 Apache-2.0；任何名为 ee/ 的目录属 Mastra Enterprise License，生产使用相应功能需有效企业许可。

记忆上下文 · 持久检索

07 · Cognee

具体能力：将文档、代码和对话变为可复用知识图与检索上下文，提供 remember、recall、improve、forget 等操作及多种接入界面。

何时选：同一任务跨会话重复输入背景，或资料需要结构化整理与可检查证据。

限制：当前材料描述本地小模型、无云密钥文本存储与检索路径，但生成答案、部分媒体处理及增强步骤有额外模型要求。错误内容也可能被持久化。

记忆上下文 · 时序关系

08 · Graphiti

具体能力：围绕实体、事实、有效时间与原始 episodes 建立时序图，支持增量更新与混合检索，追踪当前及历史关系。

何时选：客户偏好、组织关系或政策会变化，问题经常是“当时是什么、现在是什么、根据哪里”。

限制：需自行提供和运维图数据库及外围服务；开源 Graphiti 不等于 Zep 托管平台。图中保留的抽取结果仍可能错，来源可追溯不代表来源真实。

执行隔离 · 代码与工具

09 · E2B

具体能力：创建和管理云端隔离沙箱；通用 SDK、Code Interpreter 与 Desktop SDK 分别面向命令、代码解释和桌面能力。

何时选：Agent 需要执行生成代码、分析文件或操作受控桌面，不希望直接在业务主机运行。

限制：云端快速开始需要账号和 API key，运行资源另算。自托管也要部署和运维；沙箱不是绝对安全，仍要限制出网、秘密注入和敏感文件。

评测回归 · 质量证据

10 · DeepEval

具体能力：评估端到端应用、agent 轨迹及单步调用；指标包括任务完成、工具正确性、相关性与对检索上下文的忠实度。

何时选：更换模型、提示词或记忆方案后，需要判断是否回归，或把质量检查纳入 CI。

限制：部分指标依赖模型裁判并可能调用付费服务；测试数据和阈值需要人工校准。Python 评测与 TypeScript 产品之间要设计数据或 tracing 接入。

04

场景选择：用症状筛选，不用项目名猜需求

  • 岗位规则反复解释：Knowledge Work Plugins，先明确术语和只读连接器。
  • 编码总跳过测试：Addy；缺专项再加 wshobson 单插件，消除规则重叠。
  • Python Agent 要服务化：Agno；想学 Claude 实现模式则先看 Quickstarts。
  • TypeScript 产品要多步审批：Mastra，先测状态持久化与重复执行。
  • 跨会话资料重复输入：Cognee；需要当前与历史关系追溯则看 Graphiti。
  • 必须执行生成代码：E2B，选对 SDK 并最小授权；仅文本任务不用沙箱。
  • 换模型后不知是否回归：先建真实测试集，再用 DeepEval。
普通脚本已能完成任务时先不增加组件。数据库、沙箱和多代理会增加故障面，不一定增加价值。
05

三条最小组合：只是建议，不是已验证集成

组合均未实测，不保证直接互通，也非官方联合推荐。

建议 A · 工程工作流

Addy + wshobson 单插件

分工：Addy 管规格、验证和审查纪律；wshobson 只补一个明确专项，例如 Python 开发。

接入点：同一 coding agent 宿主。先检查两者规则、命令与自动触发是否重叠，再确定谁负责主流程。

试验任务：修复一个可复现缺陷，保存失败测试、修复、通过测试及人工审查结论。

暂不加：记忆服务、云沙箱和额外框架。先证明输出质量提升，不能只看写得更快。

建议 B · Python 知识应用

Agno + Cognee + DeepEval

分工：Agno 组织任务与工具；Cognee 提供可检查记忆上下文；DeepEval 组织回答与检索回归。

接入点：把 Cognee 检索包装为受控工具或上下文来源，记录命中证据及实际输出，再送入评测。

试验任务：用一组脱敏公司政策做带来源问答，覆盖无答案、旧条款、权限外资料与错误记忆。

关键风险：已有框架记忆与新记忆重复；需统一数据范围、删除规则与证据格式。不假定存在即插即用适配器。

建议 C · TypeScript 代码任务

Mastra + E2B + DeepEval

分工：Mastra 控制工作流和批准；E2B 执行生成代码；DeepEval 检查目标完成及工具轨迹。

接入点：E2B 调用封装为工具，产物与异常回写工作流；评测使用可序列化轨迹或官方支持的 tracing 路径。

试验任务：对脱敏表格生成分析结果，同时测试超时、无权限出网与恶意输入。

关键风险：TS 产品与 Python 评测的字段契约、沙箱清理与成本；检查是否触及 Mastra ee/ 生产许可。

07

评测清单：把“看起来好用”变成可以复查的证据

先固定任务和基线，再比较方案。以下为建议验收清单，没有预设达标比例或厂商跑分；阈值由业务风险与人工标注结果决定。

任务结果

结果对不对

  • 同一输入同时保留人工或现有流程基线，记录是否完成真实任务，而不只检查回答流畅。
  • 答案引用的来源能否打开、是否支持该结论；“忠实于上下文”与“上下文本身正确”分别检查。
  • 无证据、资料冲突、过期信息时能否拒绝或标出不确定性，不强行生成答案。
  • 检验工具选择、参数和产物；代码任务保留真实运行输出与失败信息。

边界与安全

失败守不守边界

  • 提示注入、越权请求、隐藏在文档里的恶意指令，是否会引发未授权调用。
  • 用不同用户或租户访问同一记忆服务，验证数据隔离、删除和纠错是否有效。
  • 沙箱超时、网络不可用、密钥缺失时，是否停止并清理，而不是重试失控。
  • 有外部写入或高风险动作时验证人工批准、重复执行防护及必要审计记录。

可复现与成本

收益有没有被夸大

  • 记录模型、版本、配置、测试集、提示词与日期；变更后重跑相同任务。
  • 区分人工审查结论与模型裁判评分；抽查评分解释，避免把偏好当正确性。
  • 记录延迟、调用、重试、沙箱运行和人工修订成本，失败任务也计入。
  • 如果宣称提效，说明基线、任务范围和计算口径；本卡没有“10 倍”效率证据。
保留授权、输出、来源、工具轨迹、失败与成本记录及人工结论；集成完成不等于上线就绪。
08

成本与许可：下载不付费，不代表运行不花钱

预算不只是 token

分别核算模型与宿主订阅、抽取与嵌入、数据库及备份、沙箱与托管、人工接入审查、失败重试和事件处置。自托管仍有资源与运维费用；Cognee 特定本地路径不代表所有功能都无成本。

代码许可和服务条款分开看

MIT：wshobson、Addy、Claude Quickstarts；保留适用版权与许可声明，外部插件另查。

Apache-2.0：Knowledge Work Plugins、Agno、Cognee、Graphiti、E2B、DeepEval；分发要求与专利条款以对应 LICENSE / NOTICE 为准。

Mastra 不是整仓 Apache：核心大部分 Apache-2.0；任何 ee/ 目录为 Mastra Enterprise License 下的 source-available。官方允许开发测试使用，相应功能生产需有效企业许可。先查 LICENSE.md 与具体目录许可。

未逐文件法律审计、未采集套餐价格；不承诺永远免费或任意商用。数据源、模型、连接器、商业托管服务有独立条款。

事实边界和来源：把项目描述、建议与实测分开

事实、建议与实测分开

官方自述：定位、功能、上手方向与许可摘要，不是独立性能验证。编辑建议：五层地图、角色分流、场景选择、三条组合与评测清单。

全部未实测：安装命令、集成、兼容性、部署、成本与效果；没有运行结果或效率倍数。记忆不消除幻觉，沙箱非绝对安全，开源不等于免费，评测不替代人工复核。

部分抽取为头尾截断，不补写缺失依赖；不以星标或厂商跑分排名，原帖仅是选题线索。
