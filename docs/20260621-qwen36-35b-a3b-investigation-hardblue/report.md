# Qwen3.6-35B-A3B 调查报告

## 研究问题

用户给出的判断是：**“Qwen3.6-35B-A3B：第一个真正能干活的本地开源模型！”**

本报告要回答的不是“这句话能不能当宣传语”，而是：
1. 这个模型的**官方权重信息**是什么；
2. “越狱版 / uncensored / aggressive”这类叫法是**官方名称**还是**社区衍生**；
3. 它在本地部署、Agentic Coding、多模态和长上下文上，公开资料到底能支撑到什么程度；
4. 哪些说法属于**可核事实**，哪些只是**社区体验**。

## 证据分层

### A. 官方 / 接近官方的公开信号

公开新闻与转载一致指向以下事实：
- Qwen3.6-35B-A3B 是阿里通义实验室开源的模型
- 采用 **MoE 稀疏混合专家** 架构
- **总参数 35B，激活参数约 3B**
- 主打 **智能体编程** 与 **多模态推理**
- 公开转载反复提到可在 **Hugging Face**、**ModelScope** 下载权重，或在 **Qwen Studio** 体验
- 公开文章多将其许可证写作 **Apache 2.0**
- 一些公开评测文章还给出 **262,144 tokens** 的原生上下文长度说法

### B. 社区使用层

大量本地部署文章开始围绕它展开：
- llama.cpp
- GGUF
- vLLM
- Ollama
- SGLang
- KTransformers
- Unsloth

这些文章把它描述成“本地化自由度高”“6G 显存可跑”“消费级显卡能尝鲜”。但这类说法依赖量化位数、offload、上下文长度和服务端框架，不能当成固定结论。

### C. 命名层

“越狱版”“uncensored”“aggressive”并不是官方稳定名称。更准确的理解是：
- 官方模型：Qwen3.6-35B-A3B
- 社区衍生：量化包、增强模板、本地部署版本、特定对齐方式
- 传播标题：把“本地能跑、能干活、少审查/少约束”的体验打包成更抓眼球的词

## 关键结论

### 1) 它确实是“能干活”的开源模型，但“能干活”主要体现在 Agentic Coding 语境里

公开评测与转载中，经常出现的指标包括：
- Terminal-Bench 2.0：**51.5**
- SWE-bench Verified：**73.4**
- RealWorldQA：**85.3**
- 一些文章还提到 RefCOCO **92**、ODInW13 **50.8**

这些数字共同指向一个方向：它不是单纯的聊天模型，而是面向**代码、仓库、终端、多模态输入**的工作型模型。

### 2) 它的“本地开源”价值，主要来自稀疏 MoE + 量化生态

35B 总参数、3B 激活参数，使它在理论上比同级稠密模型更省算力。真正让它落地的是本地生态：
- Hugging Face / ModelScope 提供权重入口
- llama.cpp / GGUF 让低门槛本地运行成为可能
- vLLM / SGLang 让服务化吞吐更可控
- Ollama / Unsloth 让本地用户更容易尝试

换句话说，**模型本身 + 量化与推理框架**，才是“本地能干活”的组合拳。

### 3) “越狱版”不是事实主体

如果把“越狱版”当成主标题，会有两个风险：
- 误把社区包装当成官方模型
- 误把某个量化/对齐版本的体验，泛化成整个模型的固定能力

更稳妥的表述应该是：
> Qwen3.6-35B-A3B 是官方开源的 MoE 模型；社区中围绕它出现了多种本地部署、量化与增强模板版本，其中一些被营销成“uncensored / aggressive / 越狱版”。

## 使用边界

### 适合
- 本地代码助手 / Agentic Coding
- 仓库级推理
- 长上下文任务
- 多模态理解
- 量化实验与推理框架评估

### 不适合直接当作结论的说法
- “6G 显存一定能跑”
- “完全不需要审查”
- “这是官方越狱版”
- “任何本地部署结果都和官方一致”

## 结论

**Qwen3.6-35B-A3B 是一个非常强的开源工作型模型，尤其适合 Agentic Coding 与本地部署生态。**

但严格来说，真正可靠的结论是：
- 它是官方开源模型；
- 它有明确的 MoE / 35B / 3B 激活 / 多模态 / 长上下文公开信号；
- 社区把它包装成“越狱版”更多是传播与部署语境，不是官方定义。

所以，最准确的描述不是“越狱版”，而是：
> **一个被本地部署生态和社区量化版本真正“用起来”的开源 Agentic 模型。**
