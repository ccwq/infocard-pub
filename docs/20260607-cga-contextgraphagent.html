CGA：把仓库图谱变成 AI 编码的局部证据层

CGA（ContextGraphAgent）是一个 local-first graph context service：它把仓库文件、符号、调用、导入与轻量数据流索引进 FalkorDB，再通过 MCP 工具、Admin Dashboard 和 3D Graph Viewer，给 AI 编码代理提供“只取所需”的局部证据。

01 · 核心判断
local-first graph context

它解决的不是“再做一个搜索框”，而是让 AI 编码代理先拿到证据，再去写。

CGA 的关键价值在于：它把仓库知识从“整文件 / 大搜索结果”降维成“符号片段 + 关系路径 + 最近事实”，让模型在生成之前先看见证据边界。对代理式编码来说，这比直接喂代码更省 token，也更不容易把猜测写成事实。

一句话总结：CGA 不是通用代码索引器，而是一个面向 AI-assisted development 的局部证据层：先把关系说清，再让模型动笔。
02 · 为什么需要它
problem / payoff
问题

LLM 编码常见的失败，不是不会写，而是上下文太散。

  • 整仓库文件被一股脑塞进 prompt，噪音太大。
  • grep 式搜索能找到关键词，但抓不到关系路径。
  • 符号 / 调用 / import / data flow 混在一起，模型容易“猜”。
收益

先给关系证据，再给局部上下文，模型更省 token 也更稳。

  • 定位目标符号摘录、相邻关系上下文、依赖路径与最近项目事实。
  • 本地优先，避免把代码上下文外包给云端搜索。
  • 给 AI 代理一个能“先问图谱，再写代码”的工作流。
README 原话要点：“focused code evidence instead of dumping whole files or broad search results into prompts.” 这句话基本就是整个项目的设计中心。
03 · 架构总览
index → graph → tools
仓库文件 / 符号 / 调用 / 导入
→
FalkorDB 图数据库
→
MCP-Compatible Tools
→
AI 编码代理
数据层

把关系装进图里，而不是塞进文本里。

索引器把 repository files、symbols、calls、imports 和 lightweight data flow 组织进 FalkorDB，形成可查询的项目关系图。

访问层

MCP 工具让代理按需取证。

代理不需要一次性读完整仓库，而是按 symbol、path、dependency、architecture query 分步取用局部证据。

控制层

Admin Dashboard 负责运维与工作节奏。

项目注册、访问组、索引状态、调度、设置、活动简报、备份等都放进可视化控制台。

04 · 你实际能拿到什么
capability matrix
Admin Dashboard
index / settings / schedules
项目注册、访问组、索引状态、设置、调度与运维视图。
3D Graph Viewer
relationship exploration
以图形方式浏览仓库关系，支持布局与可视化控制。
MCP API
agent retrieval
符号、文件、依赖、导入、变量流与架构查询。
CGA-Relay
stdio gateway / sync
单机 relay、stdio MCP gateway、本地扫描同步与安全配置样例。
扩展能力

工作简报、调度自动化、运行时备份一起打包。

  • Work Briefing Aggregation：把活动捕获成简报。
  • Schedule Automation：可定时执行浏览器测试、Agent 激活调用与 HTTP 任务。
  • Runtime Backup：PostgreSQL 与 FalkorDB 快照，支持本地优先的恢复能力。
产品气质

不是单点工具，而是一套局部证据基础设施。

  • 强调 local-first，不把项目上下文直接外包给云端。
  • 强调“先查图谱，后生成”，降低 prompt 浪费。
  • 适合代理式编码、代码审查、仓库问答和关系追踪。
05 · Benchmark 证据
102 cases

README 里给了一个带有方法边界的 live multi-project benchmark：3 个活跃项目、每个项目 34 个 deterministic symbol-level cases，总计 102 个真实代码案例。结论不是“所有项目都赢”，而是“平均上证据层能显著减 token 且改善 HPS”。

关键边界：这个 benchmark 的叙述方式是“带 nuance 的平均值”，不是“所有项目都无条件变好”。这比只讲胜率更可信。
06 · 快速上手
docker / source
Option A: Docker Desktop Release
1. Install Docker Desktop.
2. 下载 CGA-Docker-Desktop-<version>.zip。
3. 解压后双击 start-cga-desktop.cmd。

打开：
- http://localhost:18001/admin
Option B: Run From Source
$ git clone https://github.com/nascousa/cga.git
$ cd cga
$ cp .env.example .env
$ docker compose --profile dev up --build

Windows PowerShell:
PS> Copy-Item .env.example .env
PS> docker compose --profile dev up --build

打开：
- http://localhost:8001/admin
- http://localhost:8001/mcp
- http://localhost:13000

07 · 适用边界
fit / not fit
适合

需要“先取证据，再生成”的编码工作流。

  • AI-assisted development。
  • 仓库问答、代码审查、符号定位、关系追踪。
  • 本地优先、想减少 prompt 噪音的团队。
不适合

把它当成通用搜索引擎或无脑自动编码器。

  • 如果你只想要关键词搜索，它有点重。
  • 如果你不愿意接受 Docker / FalkorDB / 本地运维，这套链路门槛会偏高。
  • 如果你的目标只是“全仓库暴力投喂”，那就偏离了它的设计初衷。
结论：CGA 的定位是“上下文治理层”而不是“新一代搜索框”。它最强的地方，是把关系、证据和工作节奏收敛到同一套本地工作流里。
