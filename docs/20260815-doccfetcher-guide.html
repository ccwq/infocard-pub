DOCFETCHER 为什么是首选

DocFetcher 核心优势详解

基于 Java（JVM）实现跨平台文档解析，Windows 下有绿色便携版，无需安装，下载即用。

零配置

项目目录索引

右键「搜索范围」→「选择目录」即可。只索引你指定的目录，不污染 Windows 全局 Search Catalog，也不影响其他项目。

  • D:\Projects\ → 项目 A
  • D:\Projects\项目A\ → 独立索引
  • 完成后左下角 ☑ 项目 A
中文完整支持

中文搜索无压力

中文文件名和内容均可检索。目录「新能源汽车动力电池管理系统」→ 搜索「动力电池」→ 命中。

  • 中文文件名：✅
  • Word 内容中文：✅
  • Excel 中文：✅
EPL 许可证

免费商用无限制

Eclipse Public License，商业项目直接使用，无任何功能限制，无需申请授权。

  • 无需付费

03
完整操作步骤

DocFetcher 下载 → 索引配置 → 搜索全流程

从下载到完成第一次搜索的 5 步操作指南，无需技术背景，直接跟着做。

1
下载 DocFetcher Portable 版
访问 docfetcher.sourceforge.net，下载 Windows Portable（绿色版，无需安装）。解压到任意目录，推荐项目根目录或 D:\Tools\。
2
命令行启动（可选，推荐）
PowerShell 中定位到 DocFetcher 目录，找到 DocFetcher.exe 并启动：
PowerShell 
$Exe = Get-ChildItem ".\DocFetcher" -Recurse -File -Filter "DocFetcher.exe" | Select-Object -First 1
# 正常输出：FOUND: C:\Users\...\DocFetcher.exe
3
在「搜索范围」空白处点右键 → 选择项目目录
打开 DocFetcher 主界面，找到「搜索范围」面板（左侧树形结构）。在空白区域右键 → 选择「选择目录」→ 定位到你真正要搜索的项目目录（如 D:\Projects\项目A）。
4
等待索引完成
选择目录后会自动弹出「索引配置」窗口，确认「索引目录 = 你刚才选择的项目目录」后点击确认。等待索引构建（根据文件数量可能需要几分钟到几十分钟）。不要提前关闭！
5
确认索引就绪 → 开始搜索
索引完成后，左下角显示 ☑ 项目名（如 ☑ 项目A）。在左下角显示「采购预算」类型标签（Word / Excel / PowerPoint / PDF 等）即支持该格式。输入关键词即可搜索。
完成后左下角示例：显示「☑ 项目A」+「Word」「Excel」「PowerPoint」等标签，说明索引成功且支持这些格式的文档检索。
04
索引隔离

索引必须跟着项目一起走

三种方案：DocFetcher Portable（最方便）、Recoll（最规范）、Tika（自由度最高）。

最方便

① DocFetcher Portable

下载 Portable 版到 ProjectA\ 根目录，索引文件默认留在 ProjectA\ 下，整个目录复制到其他机器也能用。零配置，适合团队共享。

  • 整个 ProjectA\ 打包带走
  • 无需重新建索引
  • 适合团队分发
最规范

② Recoll 独立配置

每个项目独立配置目录，索引存储在 ProjectA\.recoll\ 中，可纳入 .gitignore 或直接提交到仓库（索引文件可压缩）。

Shell 
# 为项目 A 创建独立索引
recollindex -c "D:\Projects\ProjectA\.recoll"

# 查询项目 A
recoll -t -c "D:\Projects\ProjectA\.recoll" -q "新能源汽车"
自由度最高

③ Tika + 自建索引

使用 Apache Tika 解析 Office 文档，自建索引数据库（SQLite / Elasticsearch 等）。支持 .docx .xlsx .pptx .pdf 等全部格式，灵活度最高。

架构 
ProjectA\index\
  docx ─┐
  xlsx ─┼──► Tika ─► 索引数据库
  pptx ─┘

需要一定开发能力，适合 AI Agent 集成场景。

05
运维与故障

JVM 内存占用问题：诊断与修复

大型项目索引时，JVM 可能吃满提交内存导致 DocFetcher 被 OS 终止。以下是诊断与修复方案。

A

关闭异常进程

用 Task Manager 或 PowerShell 找出内存占用异常的进程（排除 DocFetcher 本身），关闭后重试。

B

修正 Windows 页面文件

「系统属性」→「高级」→「性能设置」→「高级」→「更改虚拟内存」→ 取消「自动管理」→ 手动设置页面文件大小。

C

调低 JVM 堆内存参数

编辑 DocFetcher 启动脚本或 DocFetcher.ini，添加：-Xmx512m（最大堆 512MB）限制 JVM 内存上限。

PowerShell · 诊断脚本（找出内存大户） 
$os = Get-CimInstance Win32_OperatingSystem
$pf = Get-CimInstance Win32_PageFileUsage

Write-Host "`n=== SYSTEM MEMORY ==="
[pscustomobject]@{
    FreePhysicalGB = [math]::Round($os.FreePhysicalMemory / 1MB, 2)
    TotalVirtualGB = [math]::Round($os.TotalVirtualMemorySize / 1MB, 2)
    FreeVirtualGB  = [math]::Round($os.FreeVirtualMemory / 1MB, 2)
}

Write-Host "`n=== PAGE FILE ==="
$pf | Select-Object Name, AllocatedBaseSize, CurrentUsage, PeakUsage

Write-Host "`n=== TOP PRIVATE MEMORY PROCESSES ==="
Get-Process | Sort-Object PrivateMemorySize64 -Descending |
    Select-Object -First 20 ProcessName, Id,
        @{N='PrivateGB';E={[math]::Round($_.PrivateMemorySize64 / 1GB, 2)}},
        @{N='WorkingSetGB';E={[math]::Round($_.WorkingSet64 / 1GB, 2)}}

备选方案 · Recoll

Recoll：CLI 自动化与 AI Agent 集成

如果你需要脚本化查询、PowerShell 封装、或 AI Agent 调用搜索，Recoll 的 CLI 是更好的选择。

CLI 强大独立索引

Recoll 核心命令

Shell 
# 创建项目 A 独立索引（-c 指定配置目录）
recollindex -c "D:\Projects\ProjectA\.recoll"

# 查询项目 A（文本模式）
recoll -t -c "D:\Projects\ProjectA\.recoll" -q "新能源汽车"

# 查询项目 A（GUI 模式）
recollq -c "D:\Projects\ProjectA\.recoll" "新能源汽车"

# PowerShell 封装示例：search-docs.ps1
recollq -c ".\.recoll" "报价"

Recoll GUI 支持中文，Windows 二进制需通过第三方渠道获取。

为什么 Recoll 没直接排第一？
Windows 二进制获取路径对普通用户不够直观（GPL 许可，官方未提供 Windows 安装包），需要手动配置 GUI 依赖；GUI 体验略逊于 DocFetcher。但 CLI 能力和索引独立性是 DocFetcher 无法比拟的。
rga（ripgrep-all）为什么不推荐？
Office 覆盖依赖外部转换工具（docx + xlsx + pptx），且不是真正的倒排索引，搜索性能和准确率不如 DocFetcher / Recoll。适合开发者搜索代码，不适合文档检索。
