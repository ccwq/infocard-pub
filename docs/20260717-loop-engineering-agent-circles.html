观点卡 03 / AGENT WORKFLOWLOOP ENGINEERING
从逐轮提示，到可自我推进的任务循环

让 Agent
自己进入循环

大多数人仍在手动提示 Agent：输入任务、等待回答、人工检查、修复错误、再次提示。Loop Engineering 把这段重复劳动改造成循环。

核心转变 / SHIFT
人不再逐轮执行

人的角色，从“下一句该怎么说”转向“循环该如何设计”。

01

问题：人工提示是线性的

MANUAL LOOP

常见工作方式

  • 输入任务
  • 等待 Agent 回答
  • 人工检查结果
  • 发现错误并修复
  • 再次提示 Agent

被切碎的循环

每一步都要由人把下一步“喂”给 Agent。

02

核心概念：把重复任务变成循环

CORE CONCEPT
01输入任务

给出需要完成的目标。

02Agent 判断下一步

不只回答当前一句，而是决定接下来做什么。

03验证

检查当前结果是否满足目标。

04反馈与重试

根据结果调整并再次尝试。

05完成或继续

达成目标就结束，否则回到循环。

03

三种替代：验证、反馈、重试

PRACTICE LENS
VERIFY

验证替代人工盯梢

让循环拥有检查结果的环节，而不是只等待下一次人工判断。

FEEDBACK

反馈替代重新描述

把检查得到的信息送回循环，成为下一步行动的依据。

RETRY

重试替代逐轮提示

出现错误时，让循环继续调整与尝试，而不是每次都由人重新发号施令。

04

角色变化：从执行者到循环设计者

ROLE SHIFT
BEFORE

人是执行者

人负责观察回答、发现问题、修复错误，再次提示。工作被拆成一轮又一轮的手动推进。

AFTER

人是循环设计者

人负责设计任务如何推进、结果如何验证、错误如何反馈，以及何时重试或结束。

05

实践建议：先设计“下一步”

METHOD NOTE

定义目标

先说清楚循环最终要完成什么，而不只写一条即时指令。

设计验证

明确什么结果算通过，让循环可以依据结果做判断。

允许重试

把错误视为反馈信号，为调整与再次尝试留出路径。

提示词只是起点，循环才是执行结构。

Loop Engineering 的关键，不是让人写更多轮提示，而是让 Agent 在验证、反馈与重试中自己判断下一步。

一个简单的设计检查

任务是否有明确目标？

结果是否可以被验证？

错误是否会产生反馈？

失败后是否允许重试？
