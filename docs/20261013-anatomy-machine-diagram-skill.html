01 · Project Positioning

The object is the explanation.

多数「工作原理」讲解画成方框和箭头——告诉你部件存在，但不告诉你部件做什么，读者还得自己在脑子里想象箭头的运动。Anatomy 反其道而行：直接把东西本身画出来。一个真实物件，其运动部件的行为方式就是那个概念的运作方式。

方框告诉你部件存在，但不告诉你部件做什么。Anatomy 的解法：发明一个真实、做工精良的东西，其工作方式就是概念。

❌ 方框箭头流程图

告诉你部件存在，不告诉你它们做什么。读者要在脑子里补完箭头的运动。抽象层次固定，无法交互。

✅ Anatomy 等轴测机器图

每个零件都在运动，显示的数字都来自驱动这些零件的同一个模型。零件自己就是解释。

02 · Two Failure Modes

太抽象 vs 太扁平，两者的解药相同

太抽象

叠板、漂浮板块、贴标签的方框，读不出任何东西。零件之间没有真实的遮挡关系，没有体积感，读者无法「触摸」它。

太扁平

一块大板加几道线，没有体积、没有零件、没有可发现之处。每个数字都对，但看起来像草图而非机器。

解药：许多各自做事的实心小零件构成的可辨识机器

该机器绝不从参考图临摹。参考图只能提供质感、材质和氛围；物件是发明的，不是临摹的。

03 · Three Words That Decide Output

interactive / WebGL / 3D

这三个词每一个都具体改变了什么，各有代价：

词改变了什么代价
interactive 图回应指针和键盘：拖拽、按压、长按键。不写这个词得到的是静态图。 交互逻辑需要额外构建；reduced motion 下需静止。
WebGL 为火、水、等离子体、流动空气和光做 shader，画在同一等轴测相机内的零件之间。 shader 渲染增加复杂度；每个值需走包络防止跳变。
3D 零件在深度上真正转动，每帧重投影重排序，而不只是看起来是等轴测。 慢：以小时计，不是分钟。一次只转一个主体，完整审计要 15–20 分钟。

Prompt 示例：/anatomy explain how an LRU cache evicts entries, interactive · /anatomy explain how a jet engine afterburner works, interactive, WebGL · /anatomy explain why the Earth has seasons, interactive, 3D

04 · Claude's 10-Step Workflow

质量在前四步就定了

Claude 有一个固定工作顺序，十步走完一张图。前四步定生死，后面只是执行。

01
定尺寸（Size it）先说明这是 Figure / Hero / Epic，大致多久。
02
先有真相（Truth first）收集真实数字和行为，写成一个小型模型，运动和读数都从它读。真实代码见下方 spring() 示例。
03
发明物件（Invent the object）机制与想法一一对应的机器。
04
列零件（List the parts）至少四十个，分组为 base / structure / mechanism / controls / 唯一一个被点亮的 subject，每个都坐在另一个上面。
05
规划世界（Plan the world）世界单位，平面用圆角矩形和圆，相机，然后适配卡片。
06
几何一次性构建（Build the geometry once）所有静态路径提前算好，运动部件在静止态构建后再移动。真实代码：dial gauge 示例，四个按深度排序的车削脚、带倒角的板、内缩五单位的凹槽、四角各一颗带环螺钉，每一个都是套件里的实体。
07
从后往前上色（Paint back to front）按深度排序，包裹零件拆两半，密集时用一次审计证明顺序。
08
装框（Frame it）带编号、标题、交互提示和实时读数的卡片。文字不进入绘图内。
09
让它活起来（Make it live）平静的、基于时间的运动，闲置巡游，指针和键盘，reduced motion 下静止。
10
像批评家一样验收（Verify like a critic）截图、接触印相表、四倍裁切和两项自动检查，直到没东西可修。

第 2 步示例：spring() 小模型（test rig，玻璃按钮在手指下如何鼓起和倾斜）

// Truth first: 每个读数都来自驱动零件的同一个模型 function spring(held: Spring, want: number, dt: number, [stiff, drag]: Tuning, calm: boolean) { const damping = calm ? 2 * Math.sqrt(stiff) : drag; const steps = Math.max(Math.ceil(dt * SUB_RATE), 1); const slice = dt / steps; for (let step = 0; step < steps; step++) { held.rate += (want - held.at) * stiff * slice - held.rate * damping * slice; held.at += held.rate * slice; } if (Math.abs(want - held.at) < QUIET && Math.abs(held.rate) < QUIET) { held.at = want; held.rate = 0; } }

05 · Three Sizes & Time

三档尺寸：Figure / Hero / Epic

无论哪个尺寸，第一小时内浏览器里就有可用页面。剩下的时间都花在深化它。

尺寸承载内容时间启动策略
Figure 40–80 零件，SVG 至多一个 shader 30–90 分钟 不问直接建。
Hero 80–150 零件，多个 shader 或一个转动部件 2–4 小时 先宣告再建。
Epic 整辆车、整栋建筑或整座工厂 6 小时以上 绝不擅自开工——Claude 给出估算，提出保留核心的 Hero 方案，并列出完整版会多加什么。
06 · Eight Drawing Rules

让图读起来像实体而非草图

  • R1单一相机（One camera）：等轴测，从角落向下俯视 30°。绝不用透视，平行边保持平行。
  • R2实体（Solids）：每个零件填充并按序上色，前面的遮住后面的。没有透视可见边。
  • R3四阶色调（Four tones）：每个面按朝向光源的方式着色，顶面更亮。
  • R4唯一强调（One accent）：恰好一个零件被点亮——读者该看的那个。
  • R5线条必须落点（Lines resolve）：每条线终止于一个面、另一条线或一个点。没有引线、气球标注或箭头。
  • R6四倍下的细节（Detail at 4×）：正常尺寸读起来是一台机器；放大后每个区域仍有真实的东西可发现。
  • R7内部无文字（No words inside）：文字住在绘图周围，绝不在其上，最多一个小小的雕刻标签。
  • R8真实数字（True numbers）：每个读数都来自驱动零件的同一个模型。

互斥锁

10 · Three Technical Layers

SVG / WebGL / 3D 对比

SVG

手表纯 SVG——按朝向的四阶色调，夹板展开时每一帧重新求解的画家顺序，只重绘运动零件。

四阶色调 画家算法

WebGL

涡扇增加一个 canvas 画进气流痕、涵道风、燃烧室火焰、涡轮辉光和排气。每个值都走包络，不会跳变，读数永不与画面矛盾。

火焰/蒸汽 包络插值

3D ❓beta

Seasons 把 26 个零件在真 3D 中转动，每帧重投影，读数来自天文年历的太阳公式：在北纬 50 度，6 月白昼 16 小时 22 分，12 月 8 小时 04 分。

60 fps（26 零件） ~20 fps（380 零件） beta

12 · Honest Limits

诚实与限制（作者原话，必须保留）

Claude 擅长构建，不总是擅长「看见」

它优化的是一幅能工作的图；一个零件可以每个数字都正确而看起来仍然不对。最重要的修复来自「玩一下图、描述哪里感觉不对」。

慢是特性

skill 要求每张图至少四十个零件，不会为速度牺牲细节。需要快的就说，会得到 Figure 而不是 Hero。

3D 是 beta

一次只转一个主体，一个转动图的完整审计要 15–20 分钟，所以只在零件真的必须在深度上移动时才值得要求。

参考图只给质感

给它一张照片，它取走质感，不是物件。忠实临摹别人的画不是它的用途。机器绝不从参考图临摹。

所以把第一张图当草稿

玩它、发现不对劲、说出来、再问一次。作者自己的 skill 建造过程就是这个循环。集合里有 33 个图，全部在线可玩，没有一个是手画的。
