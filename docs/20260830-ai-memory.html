01 / 正文缩略 · 为什么是 Markdown + Git

这不是把记忆藏进一个不可见的黑盒，而是把上下文写成普通 Markdown，再由 Git 保留变化轨迹。它适合需要审阅、迁移和整体备份的编码工作：人可以直接打开笔记，Agent 可以在后续会话读取历史；但它不等于语义检索系统，复杂的相似度召回仍可能需要专门的索引方案。

04 / 交接场景 · 中断不是丢失

Claude Code · 今天 14:20实现到一半，提示词、工具调用和会话节点被整理进目录；任务因上下文或时间中断。
→
Codex · 几小时后在同一目录读取 Markdown 与 Git 历史，先确认“上回做到哪”，再从未完成节点继续。

这是工作流示意，不代表任何特定 CLI 的默认配置或兼容保证。

05 / 与向量数据库方案对比 · 不是谁替代谁

维度Markdown + Git向量数据库
可读性人可直接审阅、编辑、diff通常需要检索界面或应用层解释
可迁移性文件夹与 Git 仓库易搬运依赖 schema、embedding 与服务迁移
备份复用 Git、压缩包和现有备份策略需备份索引、元数据与底层存储
依赖复杂度低：文件系统 + Git高：数据库、embedding、检索链路
检索能力全文搜索与结构化导航清晰语义相似度召回更有优势

选择规则：重视审阅、迁移、审计和简单备份时，文件型记忆更顺手；需要跨表达、模糊意图和大规模召回时，向量方案可能更合适，也可以组合使用。

06 / 快速上手 · 只做安全的只读检查

git clone https://github.com/akitaonrails/ai-memory.git
cd ai-memory
sed -n '1,220p' README.md
find . -maxdepth 2 -type f -name '*.md' -print

以上只克隆并查看仓库内容，不假设额外安装命令；正式运行前请按仓库 README 与当前文档完成配置。

07 / 适用边界与风险 · 先看记录什么

安全提醒：敏感提示词、源码片段、令牌或路径信息可能被记录。启用 hooks 前检查其写入范围；检查 .gitignore、仓库权限与远端备份策略，避免把机密带入 Git 历史。

✗ Markdown + Git 不是语义检索的替代品；全文搜索找不到“意思相近但措辞不同”的内容时，需要其他索引能力。

✓ 跨工具兼容性、hook 触发点和目录约定以项目当前文档为准，不把原帖提到的工具数量或支持清单当作永久保证。
