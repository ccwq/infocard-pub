EverOS：给 Agent 的 memory layer

它不是再造一个 Agent，而是在补 Agent 真正缺的那一层基础设施：可读、可编辑、可版本管理、可由人和 Agent 共同维护的记忆层。EverOS 把记忆做成 Markdown 源文件，下面再接 SQLite 和 LanceDB 作为可检索的本地索引，走的是一条比 context 增长、RAG 向量库、memory API 更务实的第四路线。

Markdown 记忆源 user / agent 双轨 SQLite + LanceDB 多模态摄入
FOURTH PATH ≠ MORE CONTEXT
从“记住更多”转向“记得更对、改得更快”。
Context

上下文增长

粗暴堆 token，把历史一起塞进 prompt。简单，但容易臃肿、昂贵、失控。

RAG

向量检索

把历史 embedding 后检索。比堆上下文更好，但往往只是“搜出来”，不是“管起来”。

Memory API

封装成接口

把记忆做成 API 调用。工程化更强，但通常离人可检查、可编辑的源文件更远。

EverOS

可编辑知识层

Markdown 是源头；人和 Agent 都能读、改、回滚、版本化，记忆变成一层共同维护的基础设施。

记忆不只是 recall，而是让系统逐渐更懂任务、更懂用户、更懂自己。
EverOS 的关键不是“再存一次”，而是把真实使用中反复出现的 cases 和 skills 提炼出来，让重复模式沉淀为可复用能力。它更像 memory OS，而不是单点记忆插件。
1Context最直观，但 token 线性增长，越聊越贵，越聊越乱。
2RAG向量库检索历史内容，解决“找得到”，不一定解决“改得好”。
3Memory API把记忆封装成调用接口，工程化更强，但离知识源不够近。
4EverOSMarkdown + 索引 + 人机共编，记忆成为可维护的基础设施。

WHY IT MATTERS

为什么它像基础设施

1

Markdown 是记忆源

记忆以可读、可编辑、可 diff 的 Markdown 保存，人可以直接打开，Agent 也能直接读，天然适合放进 Obsidian。

2

双轨记忆分离

用户记忆回答“这个人是谁 / 喜欢什么 / 发生过什么”；Agent 记忆回答“我做过哪些任务 / 哪些流程有效 / 哪些错误不要再犯”。

3

本地三件套务实

Markdown + SQLite + LanceDB，兼顾人类可检查性、结构化过滤、BM25 和向量检索，不依赖重型托管栈。

WHAT IT DOES

它实际做什么

Multimodal

多模态摄入

不只吃 chat history，还能把文本、图片、网页、会议录音、邮件和代码仓库统一进 searchable memory。

Self-evolving

从真实使用中长出能力

把重复出现的工作模式提炼成 cases 和 skills，让系统越用越懂任务，而不是每次从零摸索。

Local first

查询与维护可离线进行

README 明确把“idle / offline reflection”和可编辑知识页列为后续方向，路线是把 memory 变成长期可维护层。

INSTALL · CONFIG · UNINSTALL

安装 / 配置 / 卸载边界

安装

uv pip install everos，或源码仓里 uv sync 后运行；默认还会配合 everos init 生成 .env。

默认依赖

聊天 / 多模态默认走 OpenRouter，embedding / rerank 默认走 DeepInfra；也可以改成其他 OpenAI 兼容提供方。

多模态

需要时安装 everos[multimodal]，Office 文档还要系统级 LibreOffice（soffice）。

运行

everos server start 启动后，curl http://127.0.0.1:8000/health 应返回 {"status":"ok"}。

卸载 / 迁移

EverOS 的记忆主体是本地 Markdown 和索引目录；卸载时只要删除 Python 包与本地数据目录（通常在 ~/.everos 或自定义 XDG 路径）即可。源文件可迁移到 Obsidian 或 Git 仓库继续维护。

ARCHITECTURE

为什么它比“记住更多”靠谱

用户轨 / Agent 轨

把“这个人是谁”与“这个 Agent 做过什么”分开，后续做权限、检索、迁移、复用都更顺。

知识 Wiki 方向

README 明确写了 Knowledge Wiki：把 memory 转成可编辑、source-backed 的 Markdown 知识页，而不是只吐检索结果。

Reflection

系统空闲或离线时做连接、压缩、改善 profile / skills 的反思，把使用中的信号沉淀下来。

RISKS · OPEN QUESTIONS

它还没解决的问题

记什么，不记什么？

错误记忆、隐私边界、权限隔离、同步冲突、质量衡量，都是 memory 系统的硬问题；EverOS 的价值在于把这些问题摆到台前，而不是假装它们不存在。

为什么值得关注

因为它把“记忆”从黑盒能力改成了可检查、可编辑、可版本管理的知识层，builder 终于能像改文档和代码一样改 memory。
