Deep Reinforce · Ornith 1.0 · Agentic Coding

会先搭工作台的开源 AI 编程智能体模型

Ornith 1.0 的关键不只是“会写代码”，而是把任务拆成可执行的工作台：先确认数据来源、API Key、模块边界、结果展示与测试验证，再进入代码实现和自动重规划。

开源 AI 编程自动任务执行Self-ScaffoldingMIT / HF 可核查
核心判断：Ornith 更像“先造脚手架再施工”的 coding agent model。

它试图减少传统模型因为缺依赖、环境不匹配、API Key 缺失而满屏红字的失败方式；但 9B 本地量化效果与复杂真实项目中的工作台稳定性仍需继续验证。

02
SELF-SCAFFOLDING

核心特性：先搭建工作台，再执行任务

Deep Reinforce 官方 README / Blog 把 Ornith 1.0 描述为 self-improving、self-scaffolding 的 agentic coding 模型族：强化学习不仅优化解题 rollout，也优化驱动 rollout 的 scaffold。

WORKBENCH

不是裸奔写代码

先确认数据来源、密钥、模块、展示、测试，把“能不能跑”变成任务的一部分，而不是最后才发现环境错配。

SCAFFOLD

脚手架也进入学习目标

官方说法是 jointly optimizing the scaffold and the resulting solution：模型不只学答案，也学如何组织搜索轨迹。

REPLAN

高自由度自适应重规划

API Key 缺失、接口受限、网页不可用时，理想行为不是报错停止，而是换数据源、重构模块、重新验证。

03
ANTI-GAMING SAFETY

防作弊机制：RL 不能只学会“骗过测试”

官方博客明确承认风险：自生成脚手架可能通过读取可见测试、硬编码期望产物、复制环境里的 oracle solution 来拿高分。因此需要三层边界。

风险点

为拿高分偷动环境

强化学习奖励若只看分数，模型可能篡改测试脚本、读取隐藏路径、触碰验证文件或硬编码输出。

固定边界

环境与工具面不可变

外层 trust boundary 固定：运行环境、工具表面、测试隔离在模型触达范围之外，模型只能演化内部策略 scaffold。

双重裁判

规则监控 + 模型裁判

确定性 monitor 拦截明确违规；冻结 LLM judge 作为 veto 层复查意图级绕过，剔除可疑轨迹。

实战表现：重点看“遇到约束后怎么改路”

以下以用户素材为主，作为任务行为样例呈现；外部公开页面本次可核的是 self-scaffolding、模型族、MIT、HF 模型与 benchmark 口径。

新闻爬取任务

X 平台接口受限时，改用公开网页抓取并重规划流程；关键不是绕限制，而是选择可访问、可验证的数据入口。

05
ASSESSMENT

当前亮点与待验证项

公开资料显示 Ornith 在 Terminal-Bench 2.1、SWE-Bench Verified、NL2Repo、OpenClaw 等 coding / agentic coding benchmark 上展示强势结果；但对普通开发者，更关键的是本地可跑性与真实项目稳定性。

亮点：跑分可与一线模型抗衡；更重要的是在约束变化时，能通过脚手架重规划来减少“缺依赖 / 环境不匹配 / API 不可用”的红字失败。
待验证：9B 在普通电脑上的量化运行效果；复杂真实项目里，工作台机制能否长期稳定，而不是只在 benchmark 或演示任务中表现突出。
