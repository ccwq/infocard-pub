⚡ 核心洞察：AI 一分钟能吐几百行跨七八个文件，人根本不可能逐行看完。但 AI 和人的分工可以这样切——AI 擅长找问题，人不擅长；人擅长决策取舍，AI 不擅长。
01
背景：为什么需要这套流程

Viking 的 TinyShip 是一个 monorepo 模板产品，包含 Next.js、Nuxt.js、TanStack Start 三个 app，同时支持 PG 和 SQLite 两种数据库。任何一个改动都可能影响另外两个。每次 feature 提交 1000+ 行时，无法逐行 review。

于是他将 Code Review 流程做成了一个可复用的 Skill：review-forge（GitHub）。

02
总览：五步流程
  1. Review — 多模型独立审同一份代码，各出一份报告
  2. Synthesize — 合并报告，去重排序，生成带优先级的 Checklist
  3. Human Gate — 人工逐条判断：这个 bug 真的会出事吗？值得修吗？
  4. Fix — 用 Claude 作为 fix agent 执行修复
  5. Verify — 用 Codex 作为 verify agent 验证修复

03
为什么需要多 Agent Review

一开始 Viking 只用单一服务（Bugbot / CodeRabbit / Codex review mode），效果还行但有两个问题：

  • 单个模型审同一份代码存在注意力盲区——边界条件、异常路径、跨文件副作用不一定全覆盖
  • 单模型发现的问题需要额外验证"这真的是 bug 还是理解偏了"

改用多个模型独立审查后，发现很有意思的结果：

  • 重叠的问题 — 直接看，不需判断"是不是真的 bug"
  • 独有的发现 — 每个模型捕捉到自己特有的问题，互补性好
  • 高优先级重叠项 — 不纠结，直接修

多模型审查的价值有两层：覆盖率更高（多个视角互补）、信任度更高（重叠项无需二次验证）。

常用模型组合：GPT-5.5 Composer 2.5 DeepSeek Pro V4

04
Synthesize：合并报告生成 Checklist

将不同模型的 review 报告交给 AI 分析和提取排序，生成一个带 checkbox 的 checklist。重合的问题按优先级排在前面，每条附带共识度指标：

- [ ] `RF-002` - severity: high - reviewer_agreement: 2/3 (composer, codex)

文件结构示例：

code_review/checkout-refactor/ gpt5.md ← GPT-5.5 的报告 composer.md ← Composer 的报告 deepseek.md ← DeepSeek 的报告 summary.md ← Synthesize 生成的 Checklist fix-plan.md ← 修复计划 status.md ← 进度跟踪 verify.md ← 验证报告
05
人工筛选：最重要的一步

AI review 完会给一个长长的列表，按严重程度标签排列。但实际情况是：AI 缺乏项目上下文和取舍判断力，倾向于把所有发现当成重要问题去修复，过度优化。

Viking 的做法——逐条回答两个问题：

  1. 这个问题真的会导致用户出 Bug 吗？
  2. 修复的性价比高吗？
"大多数 AI 标记的问题，第一个问题答案就是不会。它只是在理论上不完美。真正要修的是那种要出事的——用户会看到错误页面、数据会被写坏、支付会失败，这种二话不说修。"

AI 列十几条，真正动手修的通常就三四条。这不是 AI 不行，是 review 和修代码是两件完全不同的事。AI 擅长找问题，不擅长决策。

06
Fix / Verify：不同模型各司其职

筛选完后进入修复验证阶段，用两个不同 agent：

  • Fix Agent (Claude) — 执行修复，创建 fix-plan.md，跑测试
  • Verify Agent (Codex GPT-5.5) — 验证修复是否正确
# Fix agent（Claude） /review-forge fix feature: checkout-refactor # Verify agent（Codex GPT-5.5） /review-forge verify feature: checkout-refactor

关键原则：不能用同一个模型既 fix 又 review。 自己修的自己审，天然存在 confirmation bias——会顺着自己的思路验证，很难发现新问题。

07
总结：给 AI Code Review 的实战建议
  • 大改动走全套流程（十几个文件以上的功能），小修小补用一个模型就够了
  • 多模型独立审比单模型 coverage 高 2~3 倍，重叠项无需二次验证
  • AI 出清单，人做决策——AI 找问题，人判断值不值得修
  • Fix 和 Verify 必须用不同模型，避免 confirmation bias
