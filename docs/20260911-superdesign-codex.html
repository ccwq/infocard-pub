让 Agent 顺手撸 UI，结果往往是深色大卡片 + Logo 失踪 + 毫无呼吸感的留白——因为设计依赖专门的视觉模型能力、上下文资产沉淀和反复微调，而 Codex 对话框天生不是为视觉设计而生的。

Codex 插件 设计画布 资产感知 自我迭代 一键落地
1 为什么直接在 Agent 里做 UI 总做不好？
资产沉淀缺失 每次都要在 Prompt 里重新交代 Logo、配色、排版、间距、Design Token、动效风格——漏了 Agent 就自己发挥，结果和产品调性完全脱节。
UI 可探索性差 设计强依赖变体探索（极简风 / 深色科技风 / 扁平插画风），让 Agent 在本地代码库里做多 Variant 探索极麻烦，每次改动都要重新运行。
Superdesign 的核心价值：自动扫描读取代码库 UI 资产与品牌风格，把原生 Logo、调性直接融入设计稿；Agent 自我质检与二次迭代；画布微调后一键落地到本地项目。
2 接入 Codex 四步
1
在插件商店一键启用

打开 Codex 的插件中心，搜索 superdesign，找到 01 Superdesign，点击「立即试用」，完成浏览器授权与绑定。

2
双屏联动，右侧画布流式渲染

在 Codex 左侧输入设计需求，右侧自动弹出 Superdesign 设计画布，生成时流式实时渲染，所见即所得。

亮点：Superdesign 自动扫描并读取代码库里的 UI 资产与品牌风格，把原生 Logo、调性直接融入设计稿，无需手动描述。
3
Agent 自我质检与自动二次迭代

生成第一版后，Agent 会对生成质量做完整的 Code Review 与视觉审查，自动发现第一版缺少接入步骤、模型列表和页脚，发起第二轮优化，补齐完整代码演示区、多模型选择 Tab 和 FAQ。

4
画布自由微调，一键应用回代码库

在画布里直接进行多视觉探索：分叉出不同设计变体、微调局部文案和组件样式。选定后告诉 Agent「就用这版，应用到代码库」，最终代码和样式自动落到本地项目，工作流闭环。

3 关于 AI Design 的三点关键洞察
💡 洞察一

设计资产沉淀是走向生产环境的必经之路

无状态生成工具无法在真实业务落地。工程级设计工具的第一件事一定是「资产感知」——感知 Logo、色板、字体、间距规范、Design Token 与动效风格，才能持续输出一致的设计。

💡 洞察二

画布（Canvas）比对话流更适合视觉探索

对话流是线性的，而设计是网状和并行的。画布模式把各种变体平铺开来供直观筛选和审视，支持并行对比、分叉探索——这才是设计迭代的正确姿势。

💡 洞察三

专业的事交给专业工具

通过官方插件系统，把最强的设计模型、画布体验和资产管理能力，无缝嫁接到开发者每天都在用的 Codex / ChatGPT 工作流里——不用切换工具，不破坏已有习惯。

4先做选择：你需要的是设计 Agent，还是普通代码补全？
适合用你已经有一个 Web 项目，想探索多个 UI 方向、建立或补齐设计系统，并让 Agent 把选定方向落回代码。
先别用你只需要改一个变量、修一个报错、写一段无视觉判断的业务逻辑；这类任务直接用普通 coding agent 更短。
先准备项目目录、可运行的开发命令、当前入口页面、Logo/字体/色板/组件约束，以及“这次不改什么”的非目标清单。
成功定义不是生成一张好看的图，而是得到可比较的变体、可追踪的设计决策，以及能在本地项目运行的实现。
初学者第一原则：先让 Superdesign 设计一个单页、一个状态或一个组件，不要第一次就要求重做整套产品。
5安装入口：不要把当前 Skill 和旧版扩展混在一起
通用 Skillnpx skills add superdesigndev/superdesign-skill；适用于 Codex、Cursor、Claude Code 及其它支持 skills 的 coding agent。
CLI 登录npm install -g @superdesign/cli@latest 后运行 superdesign login；这是官方页面描述的 CLI 路径，本机未实测。
Claude Code/plugin marketplace add superdesigndev/superdesign-skill，再执行 /plugin install superdesign@superdesign。官方提醒不要同时再装第二份 npx 副本。
避免混淆旧的开源 VS Code extension 与当前 superdesign-skill 不是同一入口。遇到安装文档时，先确认仓库是否为 superdesigndev/superdesign-skill。

安装后检查：重启你的 coding agent，在空项目中输入 /superdesign 或明确写出 “Use Superdesign to …”。如果命令不存在，先检查 skill 安装目录、CLI 是否完成授权、当前 agent 是否支持 slash command；不要立即重复生成。

610 分钟首次使用：从一个 Pricing Page 走完闭环
1
冻结目标和非目标

写下“为现有 SaaS 做 Pricing Page”，并补充品牌色、用户层级、主 CTA、移动端优先；明确不改登录流程、不改后端计费逻辑。

2
让 Agent 先读项目

要求它先找现有入口、组件、Design Token、字体、Logo 和运行命令，再开始设计。验收证据是它能列出引用了哪些文件，而不是只回复“我了解了”。

3
生成三个有差异的变体

不要只说“做得高级”。指定三个方向，例如信息密度优先、品牌叙事优先、移动转化优先；要求每个变体写出取舍，不要只换背景色。

4
画布中比较而不是线性改稿

从布局、层级、CTA、价格对比、空状态和移动端折叠逐项比较。选定一个方向后，记录“采用 A 的信息层级、采用 B 的按钮状态、拒绝 C 的原因”。

5
应用回代码并做浏览器验收

最后再告诉 Agent 应用选定版本。运行项目的 build/dev 命令，打开桌面和移动端，检查真实文字、键盘焦点、按钮点击、窄屏换行和控制台错误。

最小完成条件：有一份变体比较记录、一份采用/拒绝清单、一个落地到项目的页面，以及至少一次桌面和移动端浏览器检查。
7设计系统上下文：让“资产感知”变成可检查的输入
输入清单

先给已有事实，再给审美形容词

提供 Logo 文件位置、字体、色板、间距单位、圆角、阴影、按钮状态、组件目录和当前页面截图/入口。若没有正式 Design Token，就明确标注“待建立”，不要让 Agent 猜出一套并把猜测当规范。

检查方法

要求 Agent 回报它实际读取了什么

让它列出使用的 CSS 变量、组件、图片和字体；把“读取代码库”从宣传语变成可审查的文件清单。发现它没有读到 Logo 或 token，就先补上下文，不要进入第二轮视觉返工。

迁移规则

保留产品约束，不机械照抄画布

画布中的视觉稿是探索结果，不是自动生成的产品规范。把颜色、间距、组件状态和响应式规则转译为项目自己的 token；品牌资产、用户数据和外部图片必须按授权边界处理。

8变体评审矩阵：如何从“我觉得好看”变成可讨论
信息层级首屏是否能在 5 秒内回答“这是什么、给谁、下一步是什么”？证据：标题、副标题和 CTA 的阅读顺序。
品牌一致Logo、字体、色板、圆角、间距是否来自项目真实资产？证据：对应文件或 token，而不是“看起来像”。
状态完整默认、悬停、按下、加载、错误、空状态和禁用态是否有处理？缺状态的漂亮静态稿不能直接交付。
响应式390px/480px 附近是否仍能读、点、滚动？表格、导航、卡片和长文案是否有明确折叠策略？
实现成本是否复用已有组件，是否引入不必要依赖，是否把装饰效果变成长期维护成本？
9失败态与排障：看到“生成了”不等于流程成功
命令不存在检查当前 runner、Skill 目录和 CLI 登录状态；Claude Code 的插件入口与 npx 全局入口不要混装。确认后重启 agent。
设计很泛补充真实 Logo、字体、token、组件路径和非目标；要求先输出资产读取清单，再重新生成，不要只追加“更有质感”。
变体只是换色重新定义每个方向的用户任务、信息结构和交互策略；如果结构和取舍不变，就不算有效探索。
落地后页面坏回到浏览器检查：先看 console/page errors，再看字体加载、资源路径、CSS 冲突、移动端溢出和交互状态；不要用设计画布截图替代运行页面。
10交付前自检：从画布方案到可用 UI
内容

□ 目标用户、任务和非目标明确　□ 变体有真实结构差异　□ 采用/拒绝理由可追溯　□ 未把来源方观点写成平台保证

工程

□ 项目 build 通过　□ 真实页面可打开　□ console 无新增错误　□ 复用 token/组件　□ 图片、字体、图标来源清楚

体验

□ 桌面/移动端均检查　□ 键盘焦点与触控尺寸可用　□ loading/error/empty 状态存在　□ CTA 和主要路径可操作

11把一次设计任务写成可复用模板
输入模板目标页面 + 用户任务 + 现有入口 + 品牌资产 + 技术约束 + 不改范围 + 验收标准。
输出模板资产读取清单、变体说明、选择理由、实现文件、运行命令、桌面/移动端检查结果和遗留风险。
复盘模板记录哪条设计决策减少了返工、哪个组件最容易被 Agent 猜错，以及哪些规则应该沉淀到 DESIGN.md 或项目文档。
下一步：把这份模板保存到项目自己的任务说明中；下次换页面时只替换目标和约束，不要复制上一版的盲点。
