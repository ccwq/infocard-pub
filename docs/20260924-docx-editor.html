是什么

docx-editor 是纯浏览器运行的在线 DOCX 编辑器，不需要任何后端服务。直接操作 OOXML（DOCX 的底层格式），不走传统 DOCX→HTML→DOCX 转换路线，从根本上避免排版丢失。

作者是 Jedr Blaszyk（GitHub: eigenpal），他用 Claude Code 辅助，在几个晚上内完成了商业级质量的产品。

核心技术方案

OOXML 直读直写 Yjs 实时协作 修订模式 AI Agent MCP 插件系统 所见即所得

痛点与解法

传统方案痛点docx-editor 解法
Word Online 需要微软账号和企业订阅 → 纯浏览器打开即用，无需注册登录
DOCX​→​HTML​→​DOCX 转换排版丢失 → 直接操作 OOXML 内部结构，保真还原
在线协作文档需要 Google Docs 账号 → 内置 Yjs，支持多人实时协同编辑
文档审稿依赖人工比对修订 → 修订模式 + AI Agent MCP 自动审稿

AI Agent MCP 集成亮点

MCP（Model Context Protocol）：docx-editor 通过 MCP 与 AI Agent 深度集成，可让 AI 直接读取、审校、建议修改文档内容，实现「AI 辅助写作 → 自动修订」的闭环。

典型场景：法律/合同文档的 AI 审稿、标准化文书的 AI 批量润色、多人协作时的 AI 语法检查。MCP 让 AI 拥有对文档的「工具级」操作权限，不再只是生成文本。

适用场景

适合不适合
✓ 个人/小团队文档协作（无需 Google/微软账号） ✗ 需要完整 Word 功能的企业级文档（复杂表格、脚注）
✓ 需要 AI 辅助审稿的法律/合同文档 ✗ 已有 Google Docs / Microsoft 365 工作流的企业
✓ 嵌入现有 React/Vue/Nuxt 应用内使用 ✗ 需要与 Outlook/SharePoint 深度集成的场景
✓ 注重隐私、不希望文档上传到云端的用户 ✗ 依赖 .doc 旧格式（仅支持 .docx）

已知局限

⚠ 注意：复杂表格（合并单元格、嵌套表）、图片精确编辑、脚注/尾注的精细编辑目前支持不完美，使用前请在 Demo（https://docx-editor.dev）上实测你的文档类型。
