01它是什么 · 什么时候该用

AntV Infographic 是一个声明式信息图生成与渲染引擎：你写一段自定义 DSL 只描述“结构 + 数据”，它负责把坐标、布局、连线、留白与配色渲染成一张 SVG 信息图。官方给的定位就是一条公式：

Infographic = Information Structure + Visual Expression
A

你只写结构，不写坐标

三步流程就写三个有序条目，五条要点就写五个 - label，方案对比就写两个根节点。谁是第一步、谁和谁并列、谁属于谁——这些关系写完就够，像素位置不用管。

B

它补上排版与绘制

模板决定“长什么样”：横向箭头、时间轴、金字塔、漏斗、象限、泳道、树、脑图、词云；主题决定“什么皮肤”：手绘、图案、渐变、字体与配色序列。两者组合出成品，默认输出 SVG。

C

谁在做、多新

AntV（蚂蚁集团可视化团队）出品，MIT 许可。仓库 2025-09-11 建仓，主语言 TypeScript；npm 首个版本 2025-11-12 发布，截至 2026-09-29 已迭代到 0.2.20，处于快速迭代期（GitHub 22 个 open issue）。

D

什么时候应该用它

把报告、复盘、流程、方案对比、趋势、词频在一两分钟内变成“能直接发出去”的图；尤其是让大模型边生成边出图——它的语法容错性高，天生为流式渲染设计。

E

什么时候别用它

需要像素级精确控制的成品设计稿；需要缩放、筛选、联动等复杂交互的数据看板。前者交给设计工具，后者交给 BI / 图表库。

03五分钟跑通第一个例子
1

装依赖

npm install @antv/infographic。包同时提供 ESM、CJS 与 UMD 三种形态，前端项目、Node 脚本、甚至纯 HTML 页面都能用。

2

给一个容器

只声明容器与尺寸（width:'100%'、height:'100%'），宽高自适应交给页面布局；加 editable: true 会打开内置编辑器，生成完可以手工二次编辑。

3

写一段 DSL 丢给 render()

第一行是 infographic + 模板名，下面用 data 块给数据。下面的例子是官方 README 的快速开始原样：一个横向箭头流程，三个并列步骤。

4

需要存档就导出 SVG

await infographic.toDataURL({ type: 'svg' }) 拿到 SVG 数据，可以直接落文件、贴进文档，或再交给下游编辑器。

README 快速开始 · TypeScript
import { Infographic } from '@antv/infographic';

const infographic = new Infographic({
  container: '#container',
  width: '100%',
  height: '100%',
  editable: true,
});

infographic.render(`
infographic list-row-simple-horizontal-arrow
data
  lists
    - label Step 1
      desc Start
    - label Step 2
      desc In Progress
    - label Step 3
      desc Complete
`);
新手最容易忽略的一步：等字体就绪后再渲染一次。官方 HTML 模板里会写成 document.fonts.ready.then(() => infographic.render(syntax))——首次渲染时若字体还没加载完，文字宽度会量错，导致换行或重叠。
04语法的七条硬规则

这套语法的规则不多，但每一条都是硬约束。写错任意一条，渲染就会失败或静默降级。下面七条来自官方 Skill 的自检清单：

1

第一行必须是 infographic 前缀

写法是“infographic + 空格 + 模板名”，例如 infographic list-grid-badge-card。模板列表里只写模板名本身，真正输出时必须显式带上前缀。

2

只有 data 与 theme 两个块

块内统一两个空格缩进。缩进层级就是数据层级，多一个空格少一个空格都会改变从属关系。

3

键值对写“键 空格 值”，数组条目以 - 开头

没有冒号、没有等号、没有逗号——label 获客、value 12.5、- label Step 1 就是全部语法糖。

4

data 里只放一个主数据字段

lists、sequences、compares、root、nodes、values、items 只能出现一个，且必须与首行模板匹配（下一节有对照表）。

5

语义型条目都要带 icon

可以写精确图标 ID（如 mingcute/server-line），也可以写语义短语（如 rocket launch）。语义短语用空格分隔，不要用短横线——写 rocket launch，不要写 rocket-launch。

6

palette 是裸色值

写法 palette #4f46e5 #06b6d4 #10b981：不加引号、不加逗号、不加括号。

7

value 只放纯数值

单位写到 label 或 desc 里。要表达“12.5 秒”，就写 value 12.5 再加一句说明，而不是把 12.5s 塞进 value。

完整 DSL 示例 · 官方 Skill 原文
infographic list-row-horizontal-icon-arrow
data
  title 产品增长要点
  desc 聚焦获客、转化、复购三个阶段
  lists
    - label 获客
      desc 多渠道投放与内容触达
      icon rocket launch
    - label 转化
      desc 优化路径并减少流失
      icon chart line
    - label 复购
      desc 会员权益与分层运营
      icon repeat
theme
  palette #3b82f6 #8b5cf6 #f97316
05data 主字段怎么选

选错主字段是最常见的“渲染不出来但不知道错哪”的原因。规则很简单：先看首行模板属于哪个家族，再定 data 里写什么。

模板家族data 里写什么
list-*lists：并列要点。每项 - label，可加 desc、value、icon。
sequence-*sequences：有序步骤。可选 order asc|desc 控制方向。
sequence-interaction-*sequences + relations：泳道交互。每条泳道要有 label，节点写在泳道的 children 下（每项都必须含 label，可带 id、icon、step），跨泳道连线写在 relations。
compare-binary-*
compare-hierarchy-left-right-*		compares：必须且只能有两个根节点，真正的对比项写在各自 children 下；即使一侧只有一个指标，也要写成含一个对象的 children。
compare-swot
compare-quadrant-*		compares：直接放多个根节点（SWOT 按象限、象限图放 4 个），不要再套成两两对比。
hierarchy-structureitems：平铺结构清单。
hierarchy-*（含 mindmap）单个 root，靠 children 递归嵌套出树与脑图。
relation-*nodes + relations：节点关系图，简单关系也可以用箭头语法直接写。
chart-*values：单条有序序列，label 表示类目、value 表示数值；折线图的顺序就是条目顺序。
判断不出来先用 items 兜底，再回到模板列表里找更贴合的家族。

A

stylize：一键换画风

rough 手绘、pattern 图案填充、linear-gradient 与 radial-gradient 渐变。写在 theme 块里，不改内容只改质感。

B

base.text.font-family：换字体

用 theme.base.text.font-family 指定字体，官方示例里给的是 851tegakizatsu 这类手写体，配合手绘风格很合适。

C

palette：定义主色序列

一行裸色值决定整张图的配色基调，模板会自动把颜色分配到各个数据项上。

为什么手绘和渐变开箱就能用：看它的运行依赖——roughjs（手绘）、culori 与 tinycolor2（色彩计算）、@antv/layout 与 d3（布局）都已经内置，不需要额外装插件。

08五个官方 Skill 各管一段

仓库里有 5 个给 AI Agent 用的 Skill，命名相似但职责完全不同，装之前先分清：

1

infographic-creator

最常用。给一段内容，直接产出“能渲染的 HTML 文件”，并带上导出 SVG 的能力。

2

infographic-syntax-creator

只产出 DSL 语法本身，不生成 HTML。适合你已经有自己的渲染端，只缺“结构翻译”。

3

infographic-structure-creator

生成自定义结构设计——内置模板不够用时，用它造新的版式骨架。

4

infographic-item-creator

生成自定义数据项设计，改的是“一个条目长什么样”（图标、徽标、卡片形态）。

5

infographic-template-updater

面向开发者，用来更新模板库，把上面造出来的结构/数据项沉淀回模板集合。

流式渲染 · 让大模型边生成边出图
let buffer = '';
for (const chunk of chunks) {
  buffer += chunk;        // 增量拼接 LLM 输出
  infographic.render(buffer);   // 语法高容错，可以反复重渲染
}
为什么它能流式：DSL 是按行“渐进可解析”的——前半段写完了就先画前半段，后面的行到了再补。这就是官方说的“生成一个字，就能看到一个字的版式”。
09新手自检清单 · 十条
1

首行漏写 infographic 前缀，直接写模板名 → 解析失败。

2

data 里同时出现 lists 和 sequences → 只允许一个主数据字段。

3

compare-binary-* 写了三个根节点 → 必须恰好两个，对比项下沉到 children。

4

children 下的条目忘了 label → 每一项都必须显式带 label。

5

palette 里加了引号或逗号 → 裸色值，空格分隔。

6

语义 icon 用了短横线（rocket-launch）→ 改成空格分隔的 rocket launch。

7

value 里塞了单位（12.5s）→ value 只放数值，单位写进 desc。

8

sequence-interaction-* 的泳道节点没写成 children 下的 - label 条目 → 泳道会渲染成空。

9

输出里混进 JSON、解释性段落或多余的 Markdown 代码块 → 只该有 DSL 本身。

10

中文输入却被翻译成英文文案 → 文案语言要跟随用户输入，不要自动互译。
