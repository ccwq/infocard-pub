01是什么 & 不是
Tailcat 是

Tailscale 数据面（WireGuard + magicsock + DERP）的独立版本。让你在没有 Tailscale 账号、控制面、用户管理员的情况下，在两台机器之间建立加密隧道。

Tailcat 不是

不是 Tailscale 的替代品——没有审计日志、访问策略、持久网络成员资格。不适合需要身份认证和权限管理的生产环境。

典型使用方式

在可迹机器上运行 tailcat listen 拿到 tc1q... 地址，通过任意渠道（聊天、邮件、纸条）交给另一侧，另一侧 tailcat connect，即可建立加密连接。

不改变系统网络

全程用户空间操作，不创建 TUN 设备、不修改路由表、不需要 root 权限。操作系统完全不知道这条隧道存在。

02技术架构四层
WireGuard端到端加密，密钥对在本地生成，公钥编入 tc1q 地址
magicsockNAT 类型检测 + UDP 打洞，尝试直连，失败时退回到 DERP
DERPTailscale 托管中继（可自建），仅在打洞失败时承载流量
gVisor Netstack用户空间 TCP/IP 协议栈，操作系统只负责发 TCP 消息

连接建立流程：Server: tailcat listen --port N → 生成 tc1q... 地址（包含公钥 + DERP 区域信息）→ Client: tailcat connect tc1q... → DERP 完成初始协调 → magicsock 尝试 UDP 打洞建立直连 → 成功则 DERP 退出，失败则继续走 DERP 中继。

03安装与核心命令
安装方式

Go: go install tailscale.com/cmd/tailcat@latest

Homebrew: brew install tailcat

Cargo: cargo install tailcat（Rust crate）

直接下载: GitHub Releases 预编译二进制

核心命令

tailcat listen [--port N] — 启动监听，生成 tc1q... 地址

tailcat connect — 连接对端，建立隧道

tailcat ssh [--bind addr] — 免认证 SSH 服务模式

tailcat proxy :port — 本地 SOCKS5 代理模式

tailcat files — 点对点文件传输

# 机器 A（服务端）：建立监听 $ tailcat listen --port 2222 tc1q8kj3f2n4... # ← 把这串地址分享给机器 B # 机器 B（客户端）：接入隧道 $ tailcat connect tc1q8kj3f2n4... # 连接建立后，机器 B 可以直接访问机器 A 的端口 $ curl http://[tailcat-addr]:2222
04AI Agent 使用场景
Agent 临时访问

AI Agent 无法完成 OAuth 登录和复杂的网络配置。用 tailcat 把 tc1q 地址发给 Agent，它即可通过隧道到达目标机器、执行命令、获取结果。

临时开发环境访问

开发者需要临时连接到测试机、CI runner 或客户环境，不需要配置 VPN 或开放防火墙端口。

跨 tailnet 临时连接

不同 Tailscale 网络之间的机器需要临时互通，不需要加入同一个 tailnet。

CI/CD 快速 SSH

CI pipeline 需要 SSH 到部署目标，不需要在每台机器上安装和配置 Tailscale。

隔离环境访问

沙盒、测试机、短暂存在的云实例，需要临时打开访问通道，不需要永久开放端口。

文件传输

tailcat files 在两台机器之间点对点传文件，全称加密，穿越 NAT。

05密钥管理与安全边界
临时密钥（推荐）

每次 listen 生成新密钥对，连接关闭后密钥丢弃。更安全，适合一次性访问。

保存密钥

稳定的 tc1q 地址可跨重启使用——但任何持有此前地址的人都可以重连，需要评估信任范围。

公网 DERP 限制

Tailscale 提供的公共 DERP 中继是免费、有限速、无 SLA 的。生产环境应自建 DERP 服务器。

自建 DERP

DERP 协议有完整文档，MIT 许可证，可以完全自主运行。不依赖 Tailscale 公司基础设施。

没有控制面的代价：Tailcat 删除了身份认证层。持有 tc1q 地址 = 持有连接能力。把地址发给不该发的人，等于开放访问权限。密钥管理是使用者的责任。
