核心概念速查

GitHub Actions 是 GitHub 内置的 CI/CD 引擎，通过 .github/workflows/ 目录下的 YAML 文件定义流水线。

术语表

  • Workflow：完整流水线（YAML 文件）
  • Job：流水线中的一个步骤组
  • Step：Job 内的具体操作
  • Action：可复用的 Step
  • Runner：执行 Job 的机器
name: CI on: [push, pull_request] jobs: build: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - run: npm ci && npm test
02

Matrix：一次定义，多版本并行

Matrix 策略让你用一行配置生成 N×M 个并行 Job，覆盖多版本、多 OS、多依赖组合。

jobs: test: runs-on: ubuntu-latest strategy: matrix: node-version: [18, 20, 22] os: [ubuntu-latest, windows-latest, macos-latest] exclude: - os: windows-latest node-version: 22 steps: - uses: actions/setup-node@v4 with: node-version: ${{ matrix.node-version }} - run: npm ci && npm test
最大并行数：免费版 5 Job；Pro 10 Job；Team 15 Job；Enterprise 180 Job。

04

GITHUB_TOKEN：最小权限原则

每个 Workflow 自动获得 GITHUB_TOKEN，默认权限最小化，需要显式申请。

# Job 级别权限（推荐） jobs: build: permissions: contents: read # 读取仓库代码 pull-requests: write # 写 PR 评论 id-token: write # OIDC 令牌 runs-on: ubuntu-latest steps: - uses: actions/checkout@v4
危险配置：permissions: write-all 意味着 Workflow 可以推送代码到任何分支，引入供应链安全风险。
05

OIDC：无需存储云 Secret

OIDC（OpenID Connect）让你完全不存储 AWS/GCP/Azure 密钥，每次 Workflow 运行动态换取临时凭证。

对比

传统：创建 AWS_ACCESS_KEY → 存入 GitHub Secret → 密钥长期有效
OIDC：配置 IAM 信任策略 → Workflow 请求 JWT → 云端验证 → 自动获取临时凭证（数小时内失效）

# AWS OIDC 示例 - id-token: write permissions: contents: read - uses: aws-actions/configure-aws-credentials@v4 with: role-to-assume: arn:aws:iam::123456789:role/github-actions-role aws-region: ap-northeast-1 # 之后即可直接调用 AWS CLI，无需任何 Secret - run: aws s3 sync ./dist s3://my-bucket/

Concurrency 与常见失败

Concurrency：取消冗余 Run

# 同一 PR 只保留最新 run，自动取消旧 run concurrency: group: ${{ github.workflow }}-${{ github.ref }} cancel-in-progress: true # 团队分组：同分支队列执行，不取消 concurrency: group: deploy-${{ github.ref }} cancel-in-progress: false

常见失败模式

错误原因解决
Resource not accessiblepermissions 不足在 job.permissions 声明
Cache not foundcache key 不匹配检查 hashFiles 路径
Secret not found未配置 SecretsSettings → Secrets and variables
Runner 不响应超时（默认 360 分钟）添加 timeout-minutes
⚠️ 安全注意事项
🔑 Secret 管理
永远不要把 Secret 写入 Workflow 文件或日志。使用 ${{ secrets.SECRET_NAME }}。
🏴‍☠️ 供应链攻击
避免用未审核的 Actions；用版本号 pin 而非 @master。
⏱️ 自托管 Runner
无超时限制，需要配置触发条件避免滥用。
