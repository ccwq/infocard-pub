CONCEPTS

Core Concepts

GitHub Actions is GitHub's built-in CI/CD engine. Pipelines are defined via YAML files under .github/workflows/.

Terminology

  • Workflow: complete pipeline (YAML)
  • Job: step group inside pipeline
  • Step: specific operation inside job
  • Action: reusable step
  • Runner: machine executing job

Minimal Example

name: CI
on: [push, pull_request]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci && npm test

MATRIX

Matrix: One Config, Multiple Parallel Jobs

Matrix strategy lets you generate NxM parallel jobs with one config block.

node x os matrix
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: [18, 20, 22]
        os: [ubuntu-latest, windows-latest, macos-latest]
        exclude:
          - os: windows-latest
            node-version: 22
    steps:
      - uses: actions/setup-node@v4
        with: node-version: ${{ matrix.node-version }}
      - run: npm ci && npm test

TOKEN

GITHUB_TOKEN: Least Privilege Principle

Every workflow auto-receives GITHUB_TOKEN with minimal default permissions. Explicit grants required.

Job-level permissions
jobs:
  build:
    permissions:
      contents: read
      pull-requests: write
      id-token: write
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
Dangerous Config
permissions: write-all allows workflow to push code to any branch - supply chain risk.

OIDC

OIDC: No Cloud Secrets Required

OIDC (OpenID Connect) lets you skip storing AWS/GCP/Azure keys. Workflow dynamically requests short-lived credentials.

Traditional: Create AWS_ACCESS_KEY, store in GitHub Secret, key valid long-term.
OIDC: Configure IAM trust policy, workflow requests JWT, cloud verifies, temp credentials issued (expire in hours).
AWS OIDC example
permissions:
  contents: read
  id-token: write

- uses: aws-actions/configure-aws-credentials@v4
  with:
    role-to-assume: arn:aws:iam::123456789:role/github-actions-role
    aws-region: ap-northeast-1

- run: aws s3 sync ./dist s3://my-bucket/

CONCURRENCY

Concurrency Control

Control redundant runs: keep latest per branch, auto-cancel old ones.

Cancel old runs on same branch
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

# Team grouping: queue same branch, no cancel
concurrency:
  group: deploy-${{ github.ref }}
  cancel-in-progress: false

SECURITY

Security Notes

Supply chain attacks are the largest Actions security risk.

Secret Management
Never write secrets into workflow files or logs. Use ${{ secrets.X }}.
Supply Chain
Avoid unreviewed Actions. Pin versions instead of @master.
Self-hosted Runners
No timeout limit. Configure trigger conditions to prevent abuse.
