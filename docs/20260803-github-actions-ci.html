概念

核心概念

GitHub Actions 是 GitHub 内置的 CI/CD 引擎。流水线通过 YAML 文件定义在 .github/workflows/ 目录。

术语

  • Workflow（工作流）：完整流水线（YAML）
  • Job（任务）：流水线内的步骤组
  • Step（步骤）：任务内的具体操作
  • Action（动作）：可复用的步骤
  • Runner（运行器）：执行任务的机器

最小示例

name: CI
on: [push, pull_request]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci && npm test
02
矩阵

Matrix：一套配置生成多组并行 Job

Matrix 策略让你用一个配置块生成 NxM 个并行 Job。

node x os 矩阵
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: [18, 20, 22]
        os: [ubuntu-latest, windows-latest, macos-latest]
        exclude:
          - os: windows-latest
            node-version: 22
    steps:
      - uses: actions/setup-node@v4
        with: node-version: ${{ matrix.node-version }}
      - run: npm ci && npm test

Token

GITHUB_TOKEN：最小权限原则

每个 workflow 自动获得 GITHUB_TOKEN，权限默认最小。需要明确开放。

Job 级别权限
jobs:
  build:
    permissions:
      contents: read
      pull-requests: write
      id-token: write
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
危险配置
permissions: write-all 允许 workflow 推送代码到任意分支——供应链风险。
05
OIDC

OIDC：无需云端密钥

OIDC（OpenID Connect）让你跳过存储 AWS/GCP/Azure 密钥。Workflow 动态请求短期凭证。

传统方式：创建 AWS_ACCESS_KEY，存入 GitHub Secret，密钥长期有效。
OIDC 方式：配置 IAM 信任策略，workflow 请求 JWT，云端验证后下发临时凭证（数小时过期）。
AWS OIDC 示例
permissions:
  contents: read
  id-token: write

- uses: aws-actions/configure-aws-credentials@v4
  with:
    role-to-assume: arn:aws:iam::123456789:role/github-actions-role
    aws-region: ap-northeast-1

- run: aws s3 sync ./dist s3://my-bucket/

并发

并发控制

控制冗余运行：每个分支保留最新，自动取消旧的。

同一分支取消旧运行
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

# 团队分组：同一分支排队，不取消
concurrency:
  group: deploy-${{ github.ref }}
  cancel-in-progress: false
!
安全

安全注意事项

供应链攻击是 Actions 最大安全风险。

密钥管理
永远不要把密钥写入 workflow 文件或日志。使用 ${{ secrets.X }}。
供应链
避免使用未审查的 Actions。锁定版本而非 @master。
自托管 Runner
无超时限制。配置触发条件防止滥用。
