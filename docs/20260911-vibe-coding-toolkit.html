01

安装：三步起跑，但要知道哪些是可复制命令

ONBOARDING

Step 1 · Claude Code

README 提供的起步链：先安装 Claude Code，再添加官方插件市场。

npm install -g @anthropic-ai/claude-code /plugin marketplace add anthropics/claude-plugins-official

Step 2 · Superpowers

安装作者推荐的第一件工具。它不是“更多 prompt”，而是把探索意图和计划放到写代码之前。

/plugin install superpowers@claude-plugins-official

Step 3 · 项目入口

复制 CLAUDE.md 模板，然后从 Playbook 而不是工具列表开始阅读。

cp templates/CLAUDE.md.template CLAUDE.md # 接着阅读 docs/02-playbook-onboarding.md
第一次不要全装：先跑通 Superpowers + CLAUDE.md，再按实际瓶颈加入波浪编排、lint gate、Graphify、记忆或浏览器工具。

04

波浪式并行：不是“多开几个 Agent”

ORCHESTRATION

先做依赖图

把任务按输入/输出、文件边界和先后依赖分类。同一波内只能放相互独立的任务；需要前一波产物的任务必须后置。

按文件所有权拆分

一个子 Agent 负责一个明确文件集合，避免两个 Agent 同时改同一配置、组件或测试文件。冲突消失在结构上，不靠提醒。

主 Agent 只编排

主会话负责拆题、派发、收集、审查和合并，不应在等待子 Agent 时偷偷开始实现另一套版本。

最小验收：画出“波次 → 任务 → 文件 → 依赖”的表；若两个任务共享同一文件，就不能放入同一波。
05

质量门禁：把 warning 变成迁移工作

QUALITY GATES

分层，不是全红

总是 bug 的规则设 error；需要逐步治理的架构压力先设 warning，再用 burndown 计划逐批清零。否则一次性升格只会阻塞交付。

Lint 是架构边界

ESLint/Biome 不只查格式，也可以限制跨层依赖、危险导入、模块职责和单文件规模。

350 行上限

它不是美学数字，而是提醒：文件变长后上下文、审查和修改成本同时上升，应该进入拆分迁移。

# 具体规则以项目 docs/tools/06-eslint-biome-quality-gates.md 为准 # 不把本卡的示例命令当作任何项目的自动化结果
06

跨会话记忆：什么值得写下来？

MEMORY

应该记录

  • 一次错误修复后形成的稳定规则
  • 代码中不明显的业务约束
  • 工具的真实限制和项目 workaround
  • 未来会话会重复付出的昂贵教训

不应该记录

  • 一次性进度、临时 TODO
  • 没有复用价值的过程日志
  • 未经验证的猜测
  • 秘密、密钥、客户数据

两层结构

Claude Memory 负责常驻小索引；Obsidian 作为更大的长期资料库，通过 MCP 访问。不要让 MEMORY.md 变成所有东西的垃圾桶。

07

适用边界、风险与真实落地路径

BOUNDARIES
证据边界：作者说明方法来自受 NDA 保护的真实 fintech 项目；源代码不可公开，因此仓库展示的是提取和泛化后的方法，而不是那个项目的公开 changelog。605 Stars、116 Forks 和“26.5 天/596 星”均为不同时间点的快照，卡片以 GitHub API 2026-09-10 的 605/116 为准。

适合：已经使用 Claude Code/Codex、希望把 Agent 纳入正式团队流程的人；技术负责人要固化架构约束、lint 门禁和并行责任边界的人。

不适合：只想复制一条 prompt 立即生成结果、不愿定义验收标准、没有权限修改项目配置的人。

最小一周试行：第 1 天装 Superpowers；第 2 天复制 CLAUDE.md；第 3 天用两项独立任务跑一波并行；第 4 天把一个 warning 迁移成 error；第 5 天记录一次昂贵教训；第 6–7 天复盘冲突、返工和 warning 数量变化。
