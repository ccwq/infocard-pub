02 · 唯一分类轴：User-invoked vs Model-invokedCLASSIFICATION

这是仓库唯一明示的分类维度，原文引述：

These split on one axis — who can invoke them.
• User-invoked：只有你输入时才触发（如 /grill-me），职责是 orchestrate
• Model-invoked：你或 agent 都能触发，承载可复用的纪律
• 约束：user-invoked 可调用 model-invoked，反之不可

也就是说 README 与 ask-matt 全文没有"运行模式（手动/自动）/ 链路位置 / 专业领域"这种三维标签系统。

❌ 存疑项：原始文本称"按运行模式（手动/自动）、链路位置、专业领域三维打标签"。仓库中并未出现这三个标签维度，分类轴只有 user-vs-model 一种。
03 · ask-matt：仓库的路由入口ASK-MATT

Frontmatter：

---
name: ask-matt
description: Ask which skill or flow fits your situation. A router over the skills in this repo.
disable-model-invocation: true
---

关键语义："You don't remember every skill, so ask."

  • 作用是 router / 路由器，不是"上下文压缩器"或"决策投喂器"
  • disable-model-invocation: true：只能用户显式调用，模型不能自动触发
  • SKILL.md 用纯 Markdown 列表描述 main flow / on-ramps 等路径，不包含 Mermaid 代码块
⚠️ 名称与机制核验：
  • 原始文本写作 "ask me" 技能；仓库实际名称是 ask-matt（连字符，无空格）
  • 原始文本称"把决策浓缩成上下文喂给模型"；ask-matt 实际是 让用户问 → skill 给出路由答案，机制是"显式 ask + 文字 flow 路由"，不是"上下文压缩"——这一点已被 SKILL.md 与 disable-model-invocation 配置共同验证

05 · 项目动机：反 vibe codingWHY

README 在 "Why These Skills Exist" 章节明确表态：

Approaches like GSD, BMAD, and Spec-Kit try to help by owning
the process. But while doing so, they take away your control...
→ Goal: Keep control · Fix common failure modes

核心立场：不完全相信模型能自己管好 skill 调用，因此用显式 user-invoked 的 orchestrator + 文字化的 flow 把决策权留在人手里。

⚠️ 动机核实、机制未核实："复杂场景下不完全相信模型 / 反 vibe coding / 保留人对流程的控制权"这一动机层面已被 README 原文验证；但原始文本把动机落到"HTML 索引 + Mermaid 流程图 + 决策浓缩"这三件实现上，其中后两件未在仓库中得到证据支持（详见 §02 / §04 存疑标记）。仓库实际提供的"流程控制工具"是 ask-matt 路由 + User/Model invoked 二分轴。

07 · 安装 / 使用方法USAGE

1. 安装全部 skills（官方推荐 precondition skill）：

# 在 Claude Code 中执行
/setup-matt-pocock-skills

2. 单 skill 安装（复制到本地 skills 目录）：

git clone https://github.com/mattpocock/skills
# 把某个 skill 子目录复制到 ~/.claude/skills/<name>/
cp -r skills/engineering/ask-matt ~/.claude/skills/ask-matt

3. 触发方式：

  • User-invoked：在对话里直接 /<skill-name>，如 /ask-matt、/grill-me
  • Model-invoked：模型根据任务描述自行调用，无需手动触发
  • 前置依赖：部分 skill 需要 /setup-matt-pocock-skills 先把本地目录建好

4. 中文本地化版本（第三方）：vinvcn/mattpocock-skills-zh-CN

08 · 适用 vs 不适用SCOPE
✅ 适合 已经用 Claude Code / Claude Agent SDK，希望把工程流（debug / 出活 / 合 PR / 改设计 / 架构梳理）沉淀成可复用 skill；想要 user-invoked 的 orchestrator 明确路由；想摆脱 vibe coding，让模型决策有 trace。
