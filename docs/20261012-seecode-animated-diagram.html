工具本质

JSON spec → 可交互动画图表。模型只描述"有什么"和"怎么连"，渲染器负责布局、排版与动效。

🧩

核心价值

节省 token、提升图表质量、支持导出多格式，模型专注逻辑而非渲染细节。

🚀

5步工作流

定类型 → 写 JSON（≤9节点/12边）→ 渲染验证 → 修复迭代（≤3轮）→ 导出。

🎯

典型场景

架构图、流程图、时序图、状态机、数据可视化；文档、RFP、技术分享、Demo 演示。

🤖

适用人群

使用 Claude Code / Cursor / Codex / OpenCode 进行开发的工程师和技术写作者。

JSON spec 核心字段参考完整字段文档
节点配置
  • "row" / "col"：网格定位（渲染器自动对齐）
  • "label"：节点标签（1~3词）
  • "sub"：技术副标签（灰色小字）
  • "focal"：主路径节点（描边高亮）
  • "evidence"：代码溯源 {file, line}
边与动效
  • ["a", "b", "label"]：三元组定义边
  • "primary"：主路径边（加粗高亮）
  • "motion"：auto/none/reveal/trace/step/loop
  • "watermark"：水印开关（默认开）
  • "data" / "links"：CSV/JSON 数据源

与手写 SVG 的对比为什么 JSON spec 更好

模型手写 SVG 的问题

  • SVG 标签庞杂，模型生成容易出错
  • 布局计算消耗大量 token
  • 每次改动需重新生成整段代码
  • 路径坐标不一致，图表不整齐
  • 动效需额外写 CSS/JS，复杂度倍增

JSON spec 的优势

  • 描述意图而非实现，token 消耗低
  • 渲染器保证像素级对齐
  • 小补丁即可微调，无需重写
  • 自动路由连线，避免交叉
  • 动效由类型自适应，无需手动配置
典型适用场景实际落地案例

技术文档

README / API 文档中的架构图，时序图，自动生成保持与代码同步。

RFP / 提案

给客户的技术方案文档，用 Wardley map / quadrant 展示战略定位。

教学演示

等距物体（isometric）做 3D 示意图，GIF/MP4 导出用于幻灯片。

代码评审

SC scan 从源码结构自动生成架构图，标注文件行号溯源。

数据可视化

CSV 数据直接生成 bar / line / Sankey 图，无需手动在图表工具中录入。

迁移项目

用 SC import 把 draw.io / Excalidraw 图转成 JSON spec，再重新渲染。

局限性需知事项
  • 需 Node.js 运行环境，不支持纯浏览器端
  • JSON spec 有上限（≤9节点/12边），复杂图需拆分为多个
  • 修复迭代最多 3 轮，超出后需人工判断
  • v0.6.1 仍为早期版本，API 可能随更新变化
  • 部分图表类型（等距物体/桑基图）对 JSON 字段约定较严格
