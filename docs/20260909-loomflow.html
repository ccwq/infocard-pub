POSITIONING · 定位
01

它解决的不是“节点不够多”，而是从想法到接口太慢。

LoomFlow 把主线收敛成：自然语言 → 工作流 → 画布 → API。它明确面向个人开发者和三五人团队；Dify、n8n 的对照是项目自身的定位表达，不应理解为客观性能排名。

QUICK START · Docker
04

先跑起来，再决定是否深入配置。

git clone https://github.com/banmu123/LoomFlow.git cd LoomFlow bash scripts/init-env.sh docker compose up -d # 打开 http://localhost:5000

官方路径包含 PostgreSQL、PostgREST 与 Nginx；初始化脚本生成环境变量和随机密码。首次部署后立即修改管理员密码，生产环境不要沿用示例凭据。

CANVAS · 节点
05

12 类节点，把常见自动化动作装进画布。

项目 README 列出的节点示例包括 LLM、HTTP、Code、Template、Search、Excel、Loop、Human Confirm 等。它们覆盖模型调用、外部请求、代码处理、搜索、表格和人工审批等路径。

节点用途
LLM生成、改写、分类等模型任务
HTTP连接外部服务与现有 API
Code / Template转换数据、固定输出格式
Loop / Human Confirm重复处理与关键动作人工确认
API · 发布
06

工作流成为产品能力，而不只是后台草稿。

发布后的 workflow 可通过 HTTP endpoint 调用。项目 README 声称同一把全局 API Key 可调用已发布工作流，并提供调用日志；密钥首次展示后，应妥善保存并在需要时从 API Keys 页面轮换。

curl -X POST https://your-host/api/publish/{workflowId}/execute \ -H "Authorization: Bearer YOUR_KEY" \ -H "Content-Type: application/json" \ -d '{"inputs":{"query":"..."}}'
DEBUG · 可观测性
07

知道哪一个节点跑挂，比重跑更重要。

项目提供节点级执行追踪：状态、耗时、模型、tokens 与错误会进入时间线。Brew Notes 用来记录设计决策、问题、解决方案和优化心得；画布 AI 助手可结合运行历史回答流程为什么失败。

SELF HOST · 边界
08

私有部署降低数据外流，但不等于免配置。

README 提供 Docker 自托管方案，并说明数据库可切换到自托管 PostgreSQL。模型 API Key、搜索服务和对象存储仍需要按实际使用场景配置；自托管用户还要负责更新、备份、网络暴露和密钥轮换。

项目 README 给出的最低服务器参考为 1 CPU / 1GB RAM / Ubuntu 20.04+ / Node ≥20.9；这是项目声明快照，不是本机实测保证。
