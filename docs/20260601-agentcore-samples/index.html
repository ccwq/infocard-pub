Amazon Bedrock AgentCore Samples：官方示例库怎么读

这是一个面向“如何把 AI Agent 真正部署和运营起来”的官方样例库，不是单点 demo。它把 Runtime、Gateway、Memory、Identity、Observability、蓝图应用和基础设施模板拆成可复用路径，主入口已转向 AgentCore CLI，旧 Starter Toolkit 样例仍在迁移中。

定位官方示例库
主入口AgentCore CLI
覆盖面Runtime / Gateway / Memory / Identity
状态Legacy 样例迁移中

01 / 核心判断

判断
一句话结论

AgentCore Samples 的价值，不在于“给你一个能跑的例子”，而在于把 Agent 的开发、接入、部署、观测、权限与演进 拆成一套可照抄的工程路径。它适合拿来学生产化方法，不适合只当成单个脚本仓库理解。

先试顺序

  1. 想快速上手：先跑 agentcore create → agentcore dev → agentcore deploy → agentcore invoke。
  2. 想看 AgentCore 的能力边界：优先看 features/ 里的 Runtime、Gateway、Memory、Identity、Tools、Observability。
  3. 想做真实业务样板：看 end-to-end/ 和 blueprints/。
  4. 想补云资源与交付模板：看 infrastructure-as-code/。

怎么读这张卡

先认清它的主线：CLI → 示例 → 生产化能力。如果你只盯着某个 demo，容易忽略这个仓库真正想教的是“如何把 agent 变成可部署、可观测、可治理的系统”。

主线

AgentCore 不是单一模型或单一框架的玩具，而是给多框架、多模型 agent 提供基础设施。

迁移

仓库从 Starter Toolkit 迁到 AgentCore CLI，旧样例集中在 legacy/。

价值

它最适合做“参考实现 + 学习路径 + 生产化模板”。

02 / 目录结构怎么用

结构
getting-started/快速开始

最适合第一次接触 AgentCore 的人。分 Python / TypeScript 两条线，强调从 CLI 直接创建、开发和部署。

features/能力深挖

把 Runtime、Gateway、Identity、Memory、Tools、Observability、Evaluation、Policy 拆成独立示例，适合补单项能力。

end-to-end/完整应用

面向生产化用例，通常含部署说明、架构图和测试指南，适合看完整链路怎么拼。

blueprints/参考蓝图

更像可改造的完整应用骨架，包含认证、业务逻辑与集成服务，适合做二次开发起点。

infrastructure-as-code/基础设施模板

给想直接落 AWS 的团队用，覆盖 CloudFormation、CDK、Terraform 等资源编排方式。

legacy/迁移中的旧样例

这里仍有依赖 Starter Toolkit 的样例。读法是“历史兼容层”，不要把它当成 AgentCore CLI 的最新主路径。

03 / 适合谁先看

建议
最有用的三类人：
  • 刚开始做 Agent 的工程师：先看 getting-started/，把 CLI 的创建、开发、部署、调用跑通。
  • 想把 agent 变成可运营系统的人：重点看 runtime / gateway / memory / observability，理解权限、接入与监控。
  • 要落地到业务应用的团队：优先看 end-to-end/、blueprints/ 和 infrastructure-as-code/，别从零拼。

别误读的地方

  • 它不是“任何框架都能直接上线”的魔法箱，框架无关不等于“免工程化”。
  • 它也不是单纯的教程合集，很多目录本质上是 参考实现。
  • 如果你只关心某个 demo 能不能跑，可能会错过它最核心的价值：Agent 基础设施的操作手册。
