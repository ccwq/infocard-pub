Starship：给所有 Shell 统一一套极速可定制提示符

它不是一张“好看的主题皮肤”，而是一个按模块拼装的 prompt runtime：安装一次、接入各个 shell、写一份 `starship.toml`，就能把目录、Git 状态、语言版本、命令耗时和环境信息统一到同一套提示符里。

01

它解决的不是“换个 prompt 样式”，而是“给 shell 一个统一的状态面板”

Starship 的核心是跨 shell、跨系统、跨项目的 prompt 组合器：提示你现在在哪、仓库是否干净、是否在虚拟环境里、命令刚刚跑了多久。

核心定位

把目录、分支、状态、语言版本和耗时放进同一条 prompt，而且每个模块都能按需开关。

Starship 适合把终端做成“工作台”：你不必在每个 shell 里维护不同 prompt 方案，只要初始化一次，再用 `~/.config/starship.toml` 管理布局、样式和模块触发条件。

03

配置模型只有三层：格式、模块、样式

先理解 `format`，再调模块触发条件，最后做视觉微调。

全局项优先看这几个

  • format：整条 prompt 的骨架
  • right_format：右侧显示时间、状态、耗时
  • add_newline：是否在 prompt 前插空行
  • scan_timeout：目录扫描超时（仓库大时有用）
  • command_timeout：模块命令执行超时
  • palette：自定义颜色名对应的调色板

最小可用配置示例

"$schema" = 'https://starship.rs/config-schema.json'
add_newline = false
scan_timeout = 20
command_timeout = 800
format = '$directory$git_branch$git_status$line_break$character'
right_format = '$time'

[character]
success_symbol = '[➜](bold green)'
error_symbol = '[➜](bold red)'

[directory]
truncation_length = 3
truncate_to_repo = true

05

三个最实用的 prompt 模板

不要一上来把所有模块都开起来，先按场景选模板。

模板 A：最清爽的开发 prompt

  • 只保留 directory + git_branch + git_status + character
  • 把 package / python / rust / nodejs 先关掉
  • 适合：看仓库状态、写代码、跑测试

模板 B：项目型工作台

  • 左侧看目录和 Git 状态
  • 右侧放 time / cmd_duration / status
  • 适合：编译、测试、排障、长命令

模板 C：SSH / 运维场景

  • username + hostname + directory 优先
  • hostname 设成 ssh_only = true
  • 适合：远程服务器、临时排障、多人切换账号

推荐的视觉节制

  • 路径太长先裁目录
  • 模块太吵先关掉默认不看的项
  • 想要更清楚，就把时间/状态移到右侧
06

适合谁，不适合谁

Starship 适合把终端当工作台的人，不适合把 prompt 当装饰品的人。

适合

  1. 长期在终端里工作的开发者
  2. 同时用多个 shell 的用户
  3. 想把仓库状态、语言版本、耗时做成统一提示的人
  4. 需要低打扰、低维护成本的 prompt 方案的人

不适合

  1. 只想要一次性炫酷主题、后续不愿维护的人
  2. 不愿意安装 Nerd Font、又想让图标完美显示的人
  3. 希望所有模块默认都显示、但又不想控制复杂度的人
  4. 把 shell prompt 视为“越花越好”的人
07

常见坑位：不是 Starship 坏了，通常是配置和字体没对上

这几个坑最容易让人误判工具本身有问题。

高频故障

  • 图标变方块：终端没有 Nerd Font
  • 改了配置没效果：shell 没重载，或者改错了配置路径
  • prompt 太长：目录没截断，模块开太多
  • 启动变慢：`scan_timeout` / `command_timeout` 需要调整

排障顺序

  1. 先确认 `STARSHIP_CONFIG` 指向哪
  2. 再确认 shell init 是否已执行
  3. 然后检查字体是否支持图标
  4. 最后再怀疑模块配置或超时参数

09

结论

如果你的目标是“统一 shell 提示符并且尽量少维护”，Starship 很值得直接上。

一句话总结

Starship 不是终端美化玩具，而是一层轻量、统一、可编排的 prompt 运行时；它最值钱的地方是让你在不同 shell 里保持同一种工作语义。

实用提醒

先接 shell init，再定 format；先保留高频模块，再谈装饰性细节。这样改，稳定性最好。
