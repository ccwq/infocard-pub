Jan 23, 2026
Unrolling the Codex agent loop
Michael Bolin

Core agent loop 机制详解：Prompt 构建、工具调用、上下文窗口管理、自动压缩。

· Agent Loop = 用户输入 → 推理 → 工具调用 → 追加上下文 → 重复
· Prompt = instructions + tools + input（优先级 system > developer > user > assistant）
· 二次方增长问题：每个 Turn 携带完整历史 → Prompt Cache 缓解 → 自动上下文压缩
· 支持 OpenAI / Ollama / LM Studio / Azure Responses API

📄 架构文档 ②

Feb 4, 2026
Unlocking the Codex Harness
Celia Chen

App Server 设计：Codex Core + JSON-RPC 协议，把 Harness 变成可集成的产品平台。

· Codex Core = 线程生命周期 + 配置/认证 + 工具执行与扩展
· App Server = stdio reader + message processor + thread manager + core threads
· 三个原语：Item（原子单元）→ Turn（工作单元）→ Thread（持久容器）
· JetBrains / Xcode / VS Code / macOS App 全部由同一 Harness 驱动

HARNESS 架构 · PRODUCT vs CODEX

分工边界：谁负责什么

Harness 开放的核心洞察：产品负责 Context / 业务规则 / 工具定义，Codex 负责 Agent Loop。

产品 / 开发团队

你负责

Context 维护 · 业务规则定义 · 工具集实现（Shell / MCP / 文件操作） · 审批策略 · 沙箱权限

Codex Harness

Codex 负责

Agent Loop 逻辑 · 推理调度 · 工具调用编排 · 上下文压缩 · 线程持久化 · 事件流

⚙
三种集成方式 · INTEGRATION METHODS

把 Codex 嵌进产品

按需选择：轻量脚本 / 原生库 / 完整 App Server。

codex exec

轻量脚本 / CI

一次性任务、非交互流、结构化输出、日志记录、明确成功/失败退出码。

Codex SDK

TypeScript 库

原生库接口，适合服务端工具和工作流集成，比 App Server 轻量但功能面更小。

App Server

完整平台集成

全功能 Harness 暴露为稳定事件流，支持 Sign in with ChatGPT、模型发现、配置管理。

# 安装 Codex CLI curl -fsSL https://chatgpt.com/codex/install.sh | sh # 用 App Server 启动（stdio 模式） codex app-server # 代码集成：SDK npm install -g @openai/codex # 快速脚本 codex exec "run tests and summarize failures"

🧠 上下文管理

context window
二次方增长问题
每个 Turn 携带完整历史，prompt 长度趋于二次方增长
Prompt Cache
精确前缀匹配复用计算，命中时采样从二次变线性
自动上下文压缩
超阈值自动调用 /responses/compact，保留模型"理解"摘要
变更处理策略
工具/模型/沙箱变更时，插入新 role=developer 消息而非修改历史

🛡️ 安全模型

sandbox + approval
沙箱隔离
Shell / 文件工具在受控环境执行，可配置权限和目录范围
审批流（Approval）
Agent 需要输入时（如执行危险命令）发 server request，暂停 Turn 等待客户端 allow/deny
MCP 服务器支持
用户通过 MCP 服务器提供自定义工具，Codex 在统一策略模型下编排
ZDR 配置
Zero Data Retention 模式下保持全请求无状态，不使用 previous_response_id

X 原帖

OpenAI 今天发布了关于 Codex 的文章，开始重新定位 Codex。

Codex 现在已经不只是 App、CLI 或 IDE 里的 Coding Agent。OpenAI 把背后的开源 Harness 单独拿了出来。

Context 怎么维护、工具怎么调用、任务怎么跨轮继续、什么时候需要 approval、沙箱怎么限制——这些 Agent loop 里的东西都可以直接复用。

开发者现在可以通过 "codex exec"、SDK 和 app-server，把这套 Agent 能力嵌进自己的产品。

文章里也提到了一个判断：以后做 Agent 产品，没必要都造一个聊天框。

客服可以继续用客服后台，安服可以继续看 incident dashboard，运营可以继续看自己的业务系统。产品负责 Context、业务规则和工具，Codex 在下面负责 Agent loop。

我觉得这也可能是 Harness 接下来很重要的一种形态。

模型负责能力，Harness 负责把这种能力真正接进一个具体工作流里。Codex 正在开始做这一层的平台。
