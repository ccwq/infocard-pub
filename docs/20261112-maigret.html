Maigret：按用户名跨站收集账号档案

给一个用户名，它批量检查上千个站点，报告哪些站点存在该账号，并从命中页面提取资料。本文所有数字来自 2026-11-12 对 maigret 0.6.6 的实跑与 main 分支源码核对——包括工具自报的 58.58% 弱信号检查占比，它决定了输出该怎么读。

边界

同名 ≠ 同一人

CLAIMED 只说明该站点存在这个用户名。两个平台上的同名账号可能是完全不同的人；讨论同一性必须依赖页面资料提取（--enrich）等交叉证据。README 明确仅供合法用途，使用者自担合规责任。

弱信号与误报机制 · 源码核对

CLAIMED 什么时候不可信

判定逻辑在 maigret/checking.py 里逐条可查。四个已知假阳性来源都能定位到具体代码行，也就有对应的手工复核方法。

机制行为误报风险与复核方法
presence 默认真message 检查且站点未配 presence 字符串时，任何返回页面都算命中（checking.py 默认真规则）弱标记站点上任何 200 页面都可能报 CLAIMED；点开报告里的 URL 人工确认
仅凭状态码status_code 检查：2xx 即 CLAIMED，不看页面内容站点把“用户不存在”也返回 200 时误报；占启用站点 51.3%，是最大弱信号面
非 ASCII 防护中文等非 ASCII 用户名若未出现在返回正文中，一律改判未检出（issue #2633 防护）降低中文用户名的假阳性；但页面若 JS 渲染用户名，仍可能查不到
反代丢状态码经 FlareSolverr/Webgate 的检查拿不到上游真实状态码，按 200 处理源码自带告警：“弱标记站点可能因此误报 CLAIMED”；配合 --print-errors 观察
disabled 站点739 条记录默认跳过；--use-disabled-sites 才启用帮助原文警告 “may cause many false positives” ——这些记录正是因为不可靠才被停用
库自检回路--self-check 用库内已注册/未注册用户名回验每条记录，--auto-disable 自动停用失败站点维护数据库时跑；发现 “Unclaimed user detected as claimed” 即该条记录有误报史
实测演示 · 2026-11-12 · venv 实跑

一条只查合成用户名的复现命令

演示用户名 noonewouldeverusethis7 来自 Maigret 数据库自带的“未注册用户名”字段——数据库维护者设计它就是为了保证几乎不可能有人注册。整个演示只请求 GitHub 一个站点，不涉及任何真实个人。

# 安装（Python 3.10+）
pip3 install maigret

# 先看库况：规模、弱信号占比、反爬站点数
maigret --stats

# 合成用户名单站演示（-fo 指定报告目录）
maigret noonewouldeverusethis7 --site GitHub \
  --no-autoupdate --no-color --print-not-found

# 控制台关键输出（实测）：
[-] GitHub: Not found!
[!] Too many errors of type "Connecting failure" (50.0%).
    ... try `-n 10` to lower parallelism
[*] Short text report:
Search by username noonewouldeverusethis7 returned 0 accounts.

# --json simple 报告内容（0 命中时）：{}

0 命中时 JSON 报告是空对象——判读报告先看 returned N accounts，再看 CLAIMED 条目的 URL 是否真的打开。--print-errors 能展开每个失败站点的具体错误（连接、验证码、地区封锁等）。

结果四态 · 判读规则

四个状态各代表什么

状态含义判读动作
CLAIMED按站点配置的检查方式检测到账号点开 URL 人工确认；弱信号站点必查
AVAILABLE未检出（多数站点默认不打印，需 --print-not-found）不代表用户名全局可用，只代表已扫站点
UNKNOWN检查出错：连接失败、验证码、地区封锁换代理/降并发后重跑，--print-errors 看明细
ILLEGAL用户名不符合该站点的字符规则正常现象，不是错误
连接失败过多怎么办 实跑中出现 “Too many errors of type Connecting failure (50.0%)” 时，官方提示是降低并发：-n 10（默认并发 100）。对慢站点加大 --timeout（默认 30 秒）、增加 --retries（默认 0）。
并发 · 代理 · 限速

默认参数与流量控制

默认值来自 0.6.6 的 resources/settings.json。Maigret 没有按站点限速的配置，流量压力靠并发数、超时和重试三个旋钮控制。

参数默认值说明
-n / --max-connections100并发连接数；被目标站限流或大量连接失败时降到 10
--timeout30 秒单请求等待；调大能等来慢站点，也拉长总耗时
--retries0临时失败请求的重试次数
--top-sites N500默认按 Alexa 排名扫前 500 站；-a 全量
--proxy / -p无http/socks5 代理；socks5:// 与 socks5h:// 等价，均由代理解析 DNS（源码按传输层规范化写法，避免本地 DNS 泄漏，issue #2955）
--tor-proxysocks5://127.0.0.1:9050Tor 网关；另有 --i2p-proxy（默认 http://127.0.0.1:4444）
--dns-resolverasync每个站点都报 DNS 错误时切 threaded（遵循系统 DNS，issue #2688）
--cloudflare-bypass关闭需本地自行运行 CloudflareBypassForScraping 实例
-T txt-C csv-H html-X xmind-P pdf*-M md-G graph--neo4j-J json--ai†

* PDF 需额外安装 pip install 'maigret[pdf]' 并装系统图形库。† --ai 调 OpenAI 兼容 API 生成结果分析，需自备 API key，默认模型名 gpt-5.4。

边界与行动

怎么用才算用对了

适用条件：核对自己（或获得授权）的用户名在各站点的暴露面；教学演示；数据库维护。README 原文 “For educational and lawful purposes only”，并提醒使用者自担 GDPR、CCPA 等合规责任。

假阳性复核三步：① 只认带 URL 的 CLAIMED，逐条打开；② --stats 先看弱信号占比（本版 58.58%），占比越高越要人工复核；③ 弱信号站点命中后，用 --enrich 抓取页面资料，比对头像、简介、关联账号是否指向同一个人。

下一步验证：在自己控制的用户名上复跑本文命令；如输出与本卡不符，先确认数据库版本（maigret --version）——站点数据库每天都在变。

01

maigret --stats：了解当前库的规模、弱信号占比与保护站点数。

02

小范围扫描：--site 或 --tags 限定站点，再按需 -a 全量。

03

报告判读：CLAIMED 逐条开 URL；UNKNOWN 用 --print-errors 定位原因。
