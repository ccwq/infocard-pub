② 传统终端的 5 个并发之痛

当你在终端同时跑 5+ 个 agent 时，传统工具会暴露这些问题：

😰 找不到哪个需要关注 — 20 个 tab 全靠标题猜状态，agent 自绘界面根本不在 shell prompt 里显示
😰 端口冲突 — 不同 worktree 的 Claude/Codex 同时跑，抢占 localhost 端口，要么报错要么串会话
😰 agent 与 diff 分离 — agent 在终端里改代码，git diff 要么另开窗口要么在 IDE 里来回切换
😰 上下文丢失 — 切走再切回来，scrollback 还在但刚才在哪个 agent 里已经搞混了
😰 成本黑盒 — Claude/Codex 跑了多少次、消耗多少 tokens、哪个项目最费钱，一无所知

③ Termany 是什么

Termany 是 Agent-Native Terminal：为运行多个 coding agent 而生的本地终端，核心理念是「让 agent 作为一等公民存在于终端里」，而不是把 agent 当作一条普通的 shell 命令。

④ 四级嵌套组织结构

Termany 的会话管理遵循严格的层级关系，每一层都是持久化的：

Workspace → Page → Tab → Pane
层级说明
Workspace远左栏，一个业务上下文（如一个客户、一个产品线）
Page左栏边栏，一个项目（对应一个代码仓库）
Tab上栏，一个 shell 会话，背景保留 scrollback，切走不丢失
Pane可分割视图，支持 ⌘D 垂直 / ⇧⌘D 水平切分
✅ 每个 Tab 持久化，scrollback 在后台保留；每个 Pane 独立 SSH 目标（密码/key 认证）

⑤ 红绿灯状态感知

Termany 通过读取前台任务输出和屏幕变化来判断 agent 状态，而非依赖 shell prompt。这对自绘界面的 agent（如 Claude Code 的 ANSI 渲染）同样有效。

working 正在执行任务
needs attention 等待输入或出错
done 任务完成
✅ ACTIVE 栏置顶：需要关注的 session 自动上浮，无需在 20 个 Tab 里肉眼扫描

⑦ ⌘E 窗格视图切换

在任意 pane 内按 ⌘E 循环切换视图模式：

📁 Files
文件树 + CodeMirror 编辑器；支持预览 md / html / img / video / audio / pdf / docx / xlsx / pptx
🔀 Git diff
staged / unstaged / untracked；跨 worktree 切换，⇧⌘H 保留 session history
💬 Conversation
ACP（Agent Communication Protocol）chat 视图，直接在 pane 内查看与 agent 的对话记录
🌐 Browser
内置 webview；当 pane 内启动了端口服务（localhost:xxxx），自动提示打开浏览器预览

Activity Monitor（⇧⌘M）：CPU / 内存 / 交换 / 进程列表 / 端口占用 / 可终止进程，一站式系统资源监控。

⑧ Bot 组群协作系统

Termany 支持定义可复用的 Bot 配置（名称/头像/角色/model/工作目录），并支持组群协作：

L
Lead 协调者：Bot 组群中的主 agent，负责拆解任务、分派给其他 Bot
@
@mention 路由：在组群中 @mention 指定 Bot，将消息精确路由到目标 agent
T
Topic 隔离：不同 topic 的上下文相互隔离，避免多 agent 之间的信息污染
$
成本仪表盘（⇧⌘U）：读取 Claude 和 Codex transcript，估算成本 / input+output+cache tokens / 日趋势 / 按 model 和 project 分类。⚠️ 其他 agent 暂不支持
ACP Bridge
内置集成✅ ACP bridge 无需单独安装 node/npx
协议Agent Communication Protocol（agent 间消息路由标准）
成本追踪仅 Claude + Codex transcript，其他 agent 待支持
