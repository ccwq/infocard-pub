01推文核查：11 条机制主张逐条对账

推文主张核查结果
封装 Claude Code、Codex、Grok、Gemini、Cursor、OpenCode 等到统一 GUI属实且保守：README 表格实列 7 个——还支持 pi（@earendil-works/pi-coding-agent），推文漏列
SQLite 事件源持久化，会话/消息/轮次落盘，重开完整恢复逐字属实：SQLite 存 projects/sessions/messages/tool calls，重启跨会话保留
每聊天会话绑定独立 Git worktree，并行改同一仓库互不干扰属实：per-chat worktrees + per-repo settings + worktree 内 scoped @-mention
云端工作区：桌面关掉继续跑，手机（Expo 推送）审批属实：托管 E2B workspace + Expo push（approval-needed/completed/error 等五类事件）；移动端 expo 依赖树实证存在
Provider 双平面：管理平面共享池、会话平面独占进程逐字属实：管理平面按配置键租用/单飞缓存/空闲回收；"startup 超时必须拒绝挂起请求，不得留下中毒池条目"为文档原话
单一数据流：命令→SessionDomain→SQLite→游标→运行时→ClientBus→UI逐字属实：realtime-runtime.md 给出同一条 7 步链路
WebSocket 可抛弃；断连重连先画缓存再追补（512 事件/1 MiB 上限）逐字属实："A client WebSocket is disposable"为原文；追补上限 512 events / 1 MiB 精确命中
DO 只做"不透明字节路由器"，命令走 WorkspaceMailbox 加密邮箱逐字属实：WorkspaceGateway DO "opaque byte router with no replay buffer"；WorkspaceMailbox 独立持有加密投递/租约/回执
bun run check:architecture 架构 lint 防渲染层直写实证存在：package.json scripts 命中，ratchet 渲染层 raw-RPC、SessionDomain 绕过等
六瓶颈：机器/规划/编排/测试/评审/合并，各配机制逐字属实：spec 第 1 节原文六条；microVM 活进程快照、双模型规划+批评、5–9 并行 worker、90 秒视频证据全命中

02推文没讲的三个关键设计

A会话平面为什么默认独占进程——文档直接回答了多 CLI 混跑最脏的并发问题：除非 provider 协议明确保证多路复用安全，否则一个会话独占一个进程（独占通知、审批、工具、凭证）；管理客户端永远不许携带会话级 MCP 配置，会话客户端不许拿去做后台探测。Login/OAuth/配置写入不算"读"，必须走隔离 client。
B durablity 预算是精确数字，不是口号——ACP provider 50 ms 或 4 KiB 内 flush；首屏快照 900 KiB 投影预算，更早消息走游标分页；活跃 checkpoint 每 100–250 ms 或 16 个事件落一次；归档 = 停写 + 最终加密 R2 转录 + 沙箱暂停 30 天（不是删除）。
CFork 安全：先隔离、再换锁——ADR 0033 承认 fork 是"比特级复制品"，克隆会继承父机全部密钥。方案：宿主层断网启动 → 隔离舱里销毁继承密钥、进程冷启、机器本地生成新 Ed25519 密钥对 → 单次注册 token 换新身份 → 才放网。任何一步失败就整机销毁重 fork（fork 约 1 秒，销毁重试便宜过修复）。预览 URL 永不迁移："links die honestly"。

03路线图的可信与存疑

spec 的自我定位诚实："activation-and-extension sequence, not a rewrite"——Phase 1 的隧道（PR-E #266）与推送（PR-H #272）已落地并标注验证日期 2026-07-18。三个最险假设也自己列了：A1 活进程快照/fork 生产可用性（Phase 2 内嵌 spike 先验证，fallback 降级为分钟级冷启）；A2 用户真的会在"计划之计划"高度批准；A3 无人值守跑的成本/质量过不过目标门禁（先拿自家 repo 3–5 张票试跑）。

明确不做清单（spec 第 5 节）反而加分：不碰生产环境操作、不做云上 iOS/安卓模拟器、不做全 OS 级 computer use、不做浏览器全客户端。"自主功能永远不先于其验证配套发布"（D3: Evidence over trust）写成硬规则。
冷静面：180★（09-26 实测）、单人主导（作者 wiz/swarajbachu，244 followers）、macOS + x64 Linux only、云端 Phase 2-8 全是 roadmap；"Boat (super cheap) or E2B" 沙箱选项出自 QRT 推文，属宣称非实测。路线图完成度 = Phase 1，其余是设计文档，不是已交付能力。

05判断

值得跟踪的理由：这是少见的把"Agent 宿主"当分布式系统问题来解的项目——双平面进程模型、事件溯源 + 有界游标、加密邮箱解休眠投递、fork 隔离重密钥，每块都有 ADR 级文档和架构 lint 兜底。推文转发它不亏。

需要警惕的：spec 宏大与 180★ 体量的落差；路线图兑现速度（周更 release 是好信号但均为桌面端迭代）；AGPL-3.0-only 对商业集成的约束。
