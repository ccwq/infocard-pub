01
WHAT IT IS

它是什么，不是什么

官方的自我定位是「开源、自托管的 Slack 替代品，团队和 AI 代理一起工作」。与「聊天软件 + 旁路 bot」的组合相比，差别在于代理是工作区的一等成员。

定位

代理是有编制的群成员

每个代理有角色、指令、所选模型、月度预算和一位 owner。它们读频道、在该回答时回答、把工作交还给人，全程大家都看得见。

  • 模型：Claude、OpenAI、Gemini、DeepSeek、Kimi、Z.ai、MiniMax 或 OpenRouter 任一模型
  • 组织在应用内自带模型 key，服务器本身不需要 key
官方对标

两类「替代对象」

官方原文把对标对象分成两类：给团队聊天外挂 AI bot 的产品，以及单机的 agent 应用（README 点名 Grok Bot、ChatGPT dots、OpenBot.run、OpenMausBot 等，并支持从它们导入）。

  • 导入走预览确认：skills 到位即启用，key 永不导入
  • 工作区可以整体导出为一个文件
边界

它不是什么

它不是托管 SaaS 绑定：云版只是同一代码库的托管运行。也不是模型网关：它不转卖模型调用，每家组织自己付模型钱。

  • 桌面/手机 app 是 Beta，Mac 构建未公证、Windows 安装器未签名
  • 官方自己注明部署容量（sizing）尚未实测，2 vCPU / 4 GB / 20 GB 只是起步建议

03
BUDGET & APPROVALS

预算和审批是怎么「真的」起作用的

这一节不只是转述宣传语：预算机制核对到了设计文档 ADR 0012 与源码树，审批边界按 README 原文口径陈述。

预算ADR 0012

每次调用前先做预留，超了直接拒绝

ADR 0012（已接受，2026-10-14）写明：Model Gateway 在每次代理调用前的一个事务里锁住该代理当月预算行、按最坏情况估算成本并登记预留；余额不够时压缩输出上限，剩余不足 256 个输出 token 或没有余额时，在任何模型供应商被联系之前抛出 BudgetExceededError。并发调用靠行锁串行化，预留 + 已花费之和不会越过预算。源码树里能看到对应实现与测试（packages/engine/src/context-budget.ts 及 budget 相关测试）。

  • 预算口径：UTC 自然月，按代理记账；中途设预算立即生效
  • Router、摘要等组织级调用计到组织凭据，不占单个代理预算
  • 结算永远记录供应商的实际计费成本，预估算上线
审批边界如实说

审批覆盖「被预设为敏感」的动作，不是全部动作

README 原文：合并、部署、回滚和连接器标记为敏感的操作要等代理的 owner 或管理员批准，以聊天卡片呈现；被批准的动作只按批准执行一次；Router 从不授予权限。反过来说：没有列入敏感清单的日常动作（跑命令、读写代理电脑上的文件）并不逐个审批——代理电脑上命令执行默认开启：桌面 app 配对的电脑在 Preferences → Tools 一个开关关闭；默认安装里服务器本身充当的代理电脑，则在该机上用 agentes-runner tools disable commands 关闭（或安装时对该步回答不启用）。把「有审批机制」理解成「代理所有动作绝对安全」是不成立的。

  • 代理邮箱（Beta）发送默认要审批
  • 记忆只能「提议」修改自己的指令，由人接受
  • Wiki 代理默认只读，人要求时才写
数据流一句话：聊天与业务数据存你自己服务器的 Postgres；出站 HTTPS 按官方口径分两层——必需的是组织自己 key 的模型 API 调用，以及你启用的任何服务（连接器、代理浏览器/邮箱、备份桶等）；另有默认开启的出站项要知道：匿名用量统计默认开启，每天上报 agentes.chat（可在 Settings → General → Usage statistics 或 TELEMETRY=off 关闭），代理网页搜索始终开启（默认走 DuckDuckGo，无需 key）。模型密钥用从 AGENTES_SECRET 派生的密钥加密存储，官方声明永不下发浏览器。预算控制适用于代理的模型调用，组织级调用走组织凭据记账。
04
SELF-HOST IN ~10 MIN

十分钟自托管：先审脚本，再按步骤走

以下为 SELF_HOSTING.md「Quick start」路径的转述（官方声称，作者未实测）。前提：64 位 Linux 服务器、Tailscale 免费账号、Docker Engine + Compose v2 ≥ 2.23.1（没有的话安装器会先询问再补装）；镜像约 2 GB。

1

准备 Tailscale：MagicDNS + HTTPS + 一次性 auth key

在 console.tailscale.com 打开 MagicDNS 与 HTTPS Certificates；在 Settings → Keys 生成一个 auth key（tskey-auth-…，只显示一次）。服务器进私网靠它，证书也来自这条链路。

2

先读安装脚本，再执行（curl | sh 之前多一步 less）

脚本共 904 行，对下载的 pinned Bun 和 Compose 资产做 SHA-256 校验后才运行；想先看计划可以加 --plan（只打印、什么都不做）。

// 审查后执行 · SELF_HOSTING.md 原文命令
curl -fsSLo install.sh https://agentes.chat/install
# 通读脚本内容（重点看下载源与 SHA-256 校验逻辑）
less install.sh
sh install.sh
# 或只看计划不执行：
curl -fsSL https://agentes.chat/install | sh -s -- --plan
3

安装交互：4 次回车

回车确认 Tailscale → 粘贴 auth key → 回车跳过邮件（或选 Email 配置）→ 回车让这台服务器成为「代理的电脑」→ 回车确认用量统计。脚本会检查 Docker、生成只对你可读的 .env、拉起三个容器（应用、Postgres、Tailscale）、等证书和 /api/health 就绪。

4

预期输出（官方文档给出的完成样例）

// 完成时的关键行（SELF_HOSTING.md 原文样例）
◇  On your tailnet as agentes.tail1234.ts.net
◇  .env: PUBLIC_URL=https://agentes.tail1234.ts.net
◇  HTTPS certificate ready
◇  agentes.chat <version> is up
◇  Agents' computer: this machine
●  agentes.chat is up
     https://agentes.tail1234.ts.net

在你的 tailnet 设备上打开这个地址注册：第一个账号自动成为 owner，之后注册关闭、只能邀请。组织首次引导时会要求添加模型 key（Settings → AI and usage）。

5

两件别忘的事

① Tailscale 服务器密钥默认 180 天过期，到期服务器会掉出私网——在管理台对服务器执行 Disable Key Expiry，或改用永不过期的 OAuth client secret；② PUBLIC_URL 必须与浏览器打开的地址完全一致（协议、主机、端口都算），否则登录报 Invalid origin、保存报 bad_origin。

05
FIRST RUN · NO SIDE EFFECTS

建频道、建代理，再做一次无副作用的验证

UI 步骤转述自官方文档（作者未实测）。验证任务特意不接任何连接器、不给浏览器和电脑工具，目标是零外部副作用；但注意官方文档称代理网页搜索始终开启（默认 DuckDuckGo），严格零出站无法由产品保证，只能靠任务设计不触发工具。

1

建频道，拉一个代理进来

在应用里新建一个公开频道；再到代理设置里创建一个代理：填角色与指令、选模型（比如你组织已配 key 的任意一家）、设一个很小的月度预算（比如 1 美元）、指定 owner（就是你自己）。把它加进频道。

2

验证任务：让它只动嘴，不动手

在频道里 @这个代理，问一个不需要任何工具的常识问题，例如「用一句话介绍你自己」。创建代理时显式不给它浏览器、电脑（命令）工具——命令默认开启，须逐项排除。这条消息也可以故意不带 @，考验 Router：预期消息下面注明是「谁」决定让它回答的。

3

预期结果与判定（依官方文档推断，未实测）

✅ 代理在频道里直接回复；✅ 消息标注挑选者（若走了 Router）；✅ 没有任何审批卡出现（任务不含敏感动作；审批只覆盖被预设为敏感的操作，此预期是推断不是保证）；✅ 代理页面的用量记录里出现本次调用的成本。若它请求连接器或工具权限，说明配置里给了不该给的 scope，回去收紧。

4

如果它没反应

先查组织模型 key 是否有效（Settings → AI and usage）；再查代理预算是否设成 0 或已被用完（预算不足会在联系供应商前直接拒绝，代理会报 BudgetExceededError 类错误）；最后确认你 @ 的名字与代理成员名一致。

07
RISK & LICENSE

风险与合规边界：装之前想清楚五件事

1

curl | sh 模式：先读再跑

安装脚本对下载内容做 SHA-256 校验、支持 --plan 预览，但本质仍是管道执行远程脚本。正确姿势是官方自己给的三行：下载、less 通读、再执行。企业环境建议改用 npx @agenteschat/setup（MIT 许可）走可审路径。

2

服务器默认变成代理的电脑

默认安装会让服务器本身充当代理执行命令的机器，桌面 app 配对的电脑上命令默认开启。这不是漏洞，是设计默认值：不想让代理在你这台机器跑命令，装完第一件事去关——桌面 app 配对的电脑在 Preferences → Tools，一个开关管这台机器上所有工作区；服务器本身的代理电脑在该机跑 agentes-runner tools disable commands，或安装交互时对「代理的电脑」一步回答不启用。

3

审批有边界，预算有前提

审批只拦被预设为敏感的操作类别；预算按代理月度记账，Router 等组织级调用走组织凭据、不占代理预算。安全设计是「分层缓冲」，不是「全动作绝对安全」——给代理的 scope 越多，未审批面越大。

4

AGPL-3.0-only + 归属条款

核心代码 AGPL-3.0-only；NOTICE 附 section 7 条款：应用商店分发客户端被明确允许，但每份副本和修改版必须在 About 界面保留「Based on agentes.chat by Codari Global, LLC」。agentes 名称、logo 是商标，不随 AGPL 授权（TRADEMARKS.md）。setup CLI 单独为 MIT。

5

项目非常新，Beta 面不小

仓库 2026-11-09 才公开；代理浏览器、邮箱、Postgres 连接器、手机/桌面 app、无 Docker 模式、跨应用导入都是 Beta，桌面构建未公证/未签名。生产采用前把「正式功能清单」当成真实边界，Beta 组件当成可能变动的部分。

6

升级单向，先备份

迁移随启动执行且不可变：回滚旧镜像会被拒绝启动，只能恢复升级前的 dump。compose 自带可选 backup 服务（pg_dump 定时进 S3 兼容桶）；手动备份记得加 umask 077——dump 里是全部消息和文件。
