Agentic Engineering Patterns：把 coding agents 变成工程循环

Simon Willison 把 Claude Code / OpenAI Codex 这一类 coding agents 视为可控的工程循环，而不是一次性 vibe coding。核心不是“让模型写代码”，而是把 prompt、工具、Git、测试、浏览器自动化和 subagents 组合成可复用的工作流。

Principles Git TDD Browser QA
Subagents System Prompt Tools Loop Manual Testing
一句话结论：coding agents 不是替你“自动完工”，而是把你的工程习惯放大。

写代码更便宜了，但好代码仍然有成本；真正有效的做法，是把知识、历史、测试和审查都放进一个可重复的 compound engineering loop 里。

AT A GLANCE

Guide structure

这篇 guide 把 agentic engineering 分成四个实际层：原则、工作机制、Git 协作、测试与 QA。

“Writing code is cheap now. Good code still has a cost.”

它不是 vibe coding 的宣传帖，而是一份“把 agent 当工程系统使用”的操作手册。

作者把 agentic engineering 定义成：让 coding agents 参与到真实工程流程里，用 Git、测试、浏览器自动化和 subagents 去限制风险、提升速度，而不是把模型输出直接当成成品。

01
PRINCIPLES

从“代码便宜了”转向“工程习惯更值钱”

这一层是整篇 guide 的价值观核心：别被模型的速度迷惑，真正决定产出的仍然是你怎么组织知识、怎么审查、怎么复用、怎么控制债务。

Cheap codeNot free code

写代码便宜了，不代表质量不重要

代码生成成本下降，但 review、架构、测试和维护成本仍在。好代码依旧有价格，只是成本结构换了。

HoardRecombine

把“会做的事”存成知识库存货

把你会做的东西 hoard 起来，再让 agent 帮你重新组合。工程能力会因为重组而放大。

DebtAvoid

避免把未审查代码甩给协作者

最明确的 anti-pattern 之一：让未 review 的 agent 输出直接污染协作链路。

CompoundLoop

把流程做成 compound engineering loop

Agent、Git、测试、手工校验彼此咬合，形成可持续迭代的工程闭环。

02
WORKING WITH AGENTS

LLM + system prompt + tools in a loop

这一层解释 coding agents 到底怎么工作：不是“一个大模型回答你”，而是“提示词、工具、缓存、推理与循环”共同构成的运行时。

LLMSystem prompt

工作机制不是单次问答，而是循环

  • Chat templated prompts 把上下文打包成模型可处理的形式
  • Token caching 让重复上下文成本更低
  • Calling tools 让 agent 进入真实外部世界
  • Reasoning 与工具调用交替推进任务
Anti-patternReview gap

别把模型输出当最终答案

模型给出的第一版往往只是一个起点；真正的价值来自：试、看、改、再试。缺少人类检查，循环就会变成风险放大器。

“Coding agents can handle these for us” 的前提是你先把任务、工具和边界定义好。
Prompt

Chat templated prompts

把输入包装成模型认识的结构，减少歧义。

Cache

Token caching

重复上下文更便宜，适合长流程代理。

Tools

Calling tools

让 agent 真正执行查询、修改、验证动作。

Loop

Reasoning loop

思考 → 调工具 → 看结果 → 继续推进。

03
GIT + SUBAGENTS

让 Git 成为 agent 的安全底座

作者把 Git 当成与 coding agents 配套的工程治理工具：可回滚、可重写历史、可并行、可分工。subagents 让多任务协同成为可控而不是混乱。

1

Git essentials

把版本控制当作 agent 输出的约束层：每一步都能审查、回退、比较。

2

Rewriting history

当 agent 走偏时，历史重写比继续堆修补更有效，前提是你把仓库状态管理好。

3

Subagents

把探索、并行和专门任务拆给不同 subagent，减少单一上下文污染。

ExploreParallel

Explore / Parallel / Specialist subagents

这三类 subagent 对应三种常见需要：先探索，再并行跑，再交给擅长某一件事的专家子代理处理。

Core conceptsPrompts

用提示词明确“谁做什么”

subagents 不是炫技，而是把角色边界显式化：任务拆解、并行执行、结果汇总。

04
TESTING & QA

先跑测试，再让 agent 参与修改

这一章最实用：TDD、人工测试、浏览器自动化、理解代码的方式都被纳入到 agent 的使用模式里。

Red / greenTDD

红绿灯式测试

先让测试失败，再让 agent 修复，再确认通过。比起“先写完再看”，它更适合自动化协作。

BrowserUI QA

浏览器自动化做 Web UI 验证

网页界面不能只靠读代码，要让 agent 真的打开浏览器，执行交互并观察结果。

ManualAgentic

Agentic manual testing

人手工测，但让 agent 帮你记录、对照、总结和生成下一轮测试计划。

ShowboatNotes

让 agent 做笔记，而不是只做动作

Showboat / Present 这类工具的价值，在于把“理解代码”的过程也记录下来，方便回看。

AnnotatedPrompts

用注释化 prompt 去做解释与理解

当你要 agent 帮你理解代码、word cloud、线性 walkthrough 时，注释化 prompt 比纯命令更稳定。

05
APPENDIX

把 agent 输出接进真实工作流

Appendix 里的 prompts / artifacts / proofreader / alt text / podcast highlights 表明：agent 的产物不只是代码，也可以是内容、摘要、修订和素材。

ArtifactsOutput

把产物标准化

prompt、artifacts、proofreader 这些角色/步骤，说明输出需要被结构化地再加工。

Alt textAccessibility

内容也要可访问

即使是图像、GIF、播客亮点，也应该进入可阅读的内容流程，而不是停留在原始媒体层。

Follow-upNext prompt

下一轮 prompt 比本轮更重要

代理式工作最有价值的地方，是把“下一步怎么问”也变成可复用资产。

核心总结： coding agents 最有效的使用方式，不是替代工程，而是放大你的工程纪律。先定义边界、再做循环、再让测试与 Git 兜底，最后让 subagents 和浏览器自动化去提速。
06
CODE · FOOTER-BLOCK

把原则写成可执行的循环

这不是“看起来很聪明”的摘要，而是可以直接复用的 agentic workflow 起点。

// recommended loop
1. 先让 agent 读上下文和目标
2. 跑测试 / 读代码 / 打开浏览器
3. 输出第一版改动
4. 人类 review，必要时重写 history
5. 继续循环，直到可合并

收口说明

Simon Willison 这份 guide 的重点，不是告诉你“agent 很强”，而是教你把 agent 嵌入工程流程：知识 hoard、compound loop、Git、TDD、browser QA、subagents。

  • 适合：使用 Claude Code / OpenAI Codex / 其他 coding agents 的工程协作
  • 不适合：把模型输出直接当最终代码
  • 边界：agent 提速，工程纪律兜底
