记忆的四层结构

01 / MEMORY

可读写的记忆块

用 /memory 查看，用 /remember 让 Agent 写入长期事实；/doctor 审计和整理记忆结构。

02 / SKILLS

把经验变成技能

技能可以是全局、项目级或 Agent 级；用 /skills 查看，/skill-creator 创建，避免每次重复解释工作方法。

03 / MEMFS

让上下文进入 Git

MemFS 跟踪记忆块等上下文；通过 /memory-repository set 同步到自定义 GitHub 仓库。

04 / DREAMING

空闲时做反思

/sleeptime 配置周期性反思；/reflect 对转录内容发起整理，而不是把所有历史原样塞回 prompt。

5 步跑通：先在本地建立一个会持续学习的 Agent

安装

Node.js 需要 22.19+，全局安装 CLI：

npm install -g @letta-ai/letta-code
创建教程 Agent

进入一个测试项目目录，先不接入真实生产权限：

letta --new-agent --personality tutorial
连接模型

在会话内运行 /connect 配置模型，再用 /model 切换。密钥交给 secrets/配置界面，不要写入仓库。

写入与检查记忆

用 /remember 我偏好... 写入一条可验证事实；随后执行 /memory、/doctor 检查是否真的保存。

让它跨天工作

用 /sleeptime 配置反思；需要跨机器时登录 Letta Cloud，再运行 letta server --computer-name "work-laptop"。

跨设备不是魔法：状态放在哪里决定能力边界

不登录：本地优先

Agent 状态保存在本地，适合个人实验和敏感项目；但没有 Cloud 同步、远程机器路由和跨机器 secrets。

登录：云端状态 + 远程执行

登录后可在 chat.letta.com、桌面应用和 Telegram / Slack / Discord 中继续访问；执行位置仍可能是笔记本、VM、GitHub Actions 或 Mac Mini。

安全边界：记忆不是权限系统。仍需审查 Agent 的 hooks、permissions、MCP、secrets 和远程机器；不要因为“它记得上下文”就授予生产写权限。

什么时候值得用，什么时候不值得

值得用

  • 长期维护的代码项目
  • 需要沉淀团队工作习惯的 Agent
  • 本地 CLI、桌面和远程机器之间切换
  • 希望用 Git 审查记忆变化

先别用

  • 一次性问答，不需要长期状态
  • 无法接受登录云服务的敏感环境
  • 没有权限审计和备份策略的生产 Agent
  • 把“自动学习”误当成事实正确
