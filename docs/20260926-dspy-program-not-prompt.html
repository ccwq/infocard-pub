02三层抽象：代码长什么样

Signature 声明"做什么"——两行起步，类型即约束（Literal 枚举直接限定输出取值，嵌套 pydantic 模型也行）：

class Emotion(dspy.Signature):
    """Given a context, judge the emotional tone of it."""
    context: str = dspy.InputField(desc="facts here are assumed to be true")
    sentiment: Literal['sadness','joy','love','anger','fear','surprise'] = dspy.OutputField()

# 更快的手写法：内联签名，一行就能跑
classify = dspy.Predict('sentence -> sentiment: bool')

Module 定义"怎么做"——同一签名可无痛换执行策略：dspy.ChainOfThought(sig) 加推理步、dspy.ProgramOfThought 生成代码解题、dspy.ReAct 走工具循环。官方文档明确：模块、适配器、模型三者互相独立，换任何一个不改其余代码。

Optimizer 调"怎么问"——拿到程序 + 少量标注 + 一个指标，它自己改提示词：

import dspy
lm = dspy.LM('openai/gpt-5.2', temperature=0.7)
dspy.configure(lm=lm)

from dspy import MIPROv2
teleprompter = MIPROv2(
    metric=my_metric,
    auto="medium",   # light / medium / heavy 三档预算
)
optimized = teleprompter.compile(
    dspy.ChainOfThought("question -> answer"),
    trainset=my_trainset,
)
optimized.save("optimized.json")   # 存盘复用，不再手抠措辞

03两个旗舰优化器的真实机制

AMIPROv2 = 生成 + 贝叶斯搜索——为程序里每个 predictor 生成候选 few-shot 示例与新指令，再用贝叶斯优化搜最佳组合；auto 三档控制预算（light/medium/heavy），小任务几条数据就能出效果。
BGEPA = 会反思的提示词进化（Jul'25）——采样完整轨迹（推理、工具调用、输出），用自然语言反思诊断问题、提出并测试提示词更新，再从自己尝试的 Pareto 前沿合并互补经验。论文数字：六任务平均超 RL 方法 GRPO 6%（最高 20%）且 rollout 省 35 倍；超此前最强的 MIPROv2 10%+（AIME-2025 +12% 精度）。一句话：能"从错误里学规则"的提示词优化器，不是随机搜索。

04上手四步（含官方数据预算）

  1. 安装：pip install dspy（v3.4.0；跟进 main 用 pip install git+...）。配模型一行：dspy.configure(lm=dspy.LM('openai/gpt-5.2'))，走 LiteLLM 所以本地 vLLM/Ollama 也认（clients/ 目录 34 个文件：openai/local/databricks/streaming/cache 全套）。
  2. 定义任务：从单个 dspy.ChainOfThought 起步，别急着拆管道。 signature 里用 desc= 写字段约束，输出用 Literal 限枚举。
  3. 攒数据 + 定指标：官方给的预算参考——30 条就有实质收益，建议奔 300 条去。评估器内置：dspy.Evaluate + SemanticF1/answer_exact_match 等现成 metric。
  4. 跑优化器：一个反直觉的官方建议——prompt 优化器用 20% 训练 / 80% 验证的反向划分（提示词优化太容易在小训练集上过拟合）；但 GEPA 例外，它要训练集越大越好、验证集够反映分布就行。优化完 optimized.save() 存 JSON 复用。
选型速记：先 MIPROv2(auto="light") 摸底 → 认真上 GEPA（效果最好、会反思）→ 要动权重走 BootstrapFinetune/GRPO → 两个优化器可以串着跑。24 个官方教程里 papillon（本地小模型+外部大模型的隐私委派）和多跳 RAG 最值得先读。

05冷静面与判断

四个折扣点：① 优化器要标注数据和 metric——没有评测集的项目享受不到核心收益，"零成本变强"不存在；② GEPA 的反思循环要跑多次 LM 调用，token 账单比手写一条提示词贵（省的是 rollout 数，不是免费）；③ v3.x 迭代快（110 个 release），教程与 API 版本错位的坑在社区 issue 里常见，跟官方 docs 版本走；④ 抽象有学习成本——Signature/Module/Adapter/Optimizer 四层概念对新手是 upfront 投资，单个一次性提示词任务用 DSPy 是杀鸡用牛刀。

判断：DSPy 是"提示词工程软件化"这条路上最认真的学术系实现——38K★、736 个活跃 issue、三天一个 release 的社区热度是真的。它换来的核心能力是可移植（换模型不重写）和可优化（数据进、质量出），适合：多步管道（RAG/agent）、要长期维护的 AI 功能、频繁换底层模型的团队。不适合：一次性问答、没有评测数据的探索期项目。推文那句话是准的：提示词不该是手艺活，该是能被编译和优化的代码。
