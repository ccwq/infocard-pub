Agency Agents：把“角色工厂”拆成可安装的 AI 团队

agency-agents 不是单一工具，而是一套按工程、设计、安全、营销等分工组织的角色库。它把 AI 从“通用聊天框”升级成“可选择、可安装、可分工、可交付”的团队。

一句话结论

它的真正特有点，不是“角色多”，而是把角色写成可安装、可复制、可执行的工作流单元：Frontend Developer、Code Reviewer、Incident Response Commander、Whimsy Injector、Threat Intelligence Analyst、Growth Hacker……每个角色都带人格、流程和交付标准。

可安装可分工可交付人格 + 流程 + 产物

角色库的视觉锚点：团队，而不是模板

README 明确把它描述成“a complete AI agency”，核心不是堆 prompt，而是按 division / role / deliverable 组织一个可执行组织结构。

01
核心定位

它卖的不是“角色很多”，而是“角色能干活”

README 的核心叙事非常明确：它来自 Reddit thread 和持续迭代，目标是把一个抽象的 AI agency 变成一组能直接安装和调用的专家角色。每个角色都不是泛化 prompt，而是带 personality、process 和 deliverables 的工作单元。

工程角色Frontend Developer

Frontend Developer

面向现代 Web 技术、React/Vue/Angular、UI 实现与性能优化，强调响应式、可访问性和 pixel-perfect 落地。它代表的是“把设计真的做出来”的角色，而不是只会写建议。

质量角色Code Reviewer

Code Reviewer

重点是正确性、可维护性、安全性、性能，不纠缠风格偏好。它的独特性在于：评论风格是 mentor，而不是 gatekeeper，目标是让反馈本身能教会人。

事件角色Incident Response Commander

Incident Response Commander

把 3 AM 的生产事故变成结构化指挥：分级、协同、复盘、SLO/SLI、on-call 文化。这个角色非常“特有”，因为它不是写代码，而是把混乱收敛成流程。

02
角色特征

几个最有辨识度的角色，分别对应不同的“团队职能”

这套仓库最值钱的地方，是它把“AI 应该扮演谁”讲得很细：有干活的、把关的、救火的、做品牌的、做情报的、做增长的。你不是在挑 prompt，而是在挑岗位。

DesignWhimsy Injector

Whimsy Injector：给品牌加“有分寸的好玩”

它不是纯装饰角色，而是专门负责“人格 + 愉悦感 + 记忆点”的设计工作。适合在不破坏专业感的前提下，让体验更不无聊。

  • 增加 delight，但不打乱品牌秩序
  • 适合 landing / onboarding / 空状态 / 提示文案
  • 重点是“策略性个性化”，不是卖萌
SecurityThreat Intelligence Analyst

Threat Intelligence Analyst：把威胁转成可操作情报

这个角色把攻击者、ATT&CK、campaign、检测规则串起来，强调的是“提前知道对手会干什么”。它对应的是安全团队里最难自动化的一类工作。

  • 跟踪 adversary groups
  • 输出 actionable intelligence
  • 辅助 detection engineering
MarketingGrowth Hacker

Growth Hacker：把增长变成实验系统

它不是“会发广告”的角色，而是擅长 funnel、实验、viral loop、cohort 分析的增长引擎。适合需要数据驱动试错的团队。

  • 增长策略
  • A/B testing 和 multivariate testing
  • 渠道与转化漏斗优化
EngineeringFrontend / Reviewer / Incident

工程侧三角：写、审、救火

Frontend Developer 负责落地，Code Reviewer 负责质量，Incident Response Commander 负责事故与复盘。三者合起来，才像一个真正可运行的工程组织。

  • 执行
  • 质控
  • 恢复与复盘
03
使用场景

适合把 AI 组织成团队，不适合把它当万能聊天框

这类角色库最适合的，是“你知道要什么结果，但还想把执行拆分成岗位”的场景。它的价值在于分工、标准和交付，不在于回答长篇百科。

适合

什么时候最有用

  • 你需要给 Claude Code / Cursor / Copilot 等工具装上明确角色
  • 你希望不同任务由不同 persona 负责，不想一个 prompt 包打天下
  • 你想把“团队协作”变成可复制的文件与命令
不适合

什么时候别硬用

  • 只想要一个简单问答机器人
  • 不愿意维护角色文件、安装脚本和 division 结构
  • 任务没有明确岗位边界，只有一句模糊目标
04
最小上手路径

先安装 division，再激活角色；不要把它当一次性 prompt 粘贴

README 里给了明确的安装与使用路径：`./scripts/install.sh --tool claude-code` 或按 division 安装，然后在工具里直接激活某个角色。它的设计思路是“角色先存在，工作再发生”。

安装

Claude Code 安装

./scripts/install.sh --tool claude-code cp engineering/*.md ~/.claude/agents/
分支

按 division 安装

./scripts/install.sh --tool claude-code --division engineering,security
激活

激活具体角色

"Activate Frontend Developer mode" "Help me review this PR like Code Reviewer"
