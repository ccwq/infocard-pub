llmwiki 维护手册

收录、审计与编译是三条独立路径，权限各自独立
维护顺序：审计 → 收录 → 编译 → 提交

llmwiki 是一套本地知识库维护链路。原始文章进入 raw/articles/，复制到 sources/ 供编译器读取，人工或自动生成的知识页进入 concepts/ 与 entities/，index.md 是唯一权威索引，log.md 记录每次动作。

本手册写给要长期维护这套知识库的人。核心结论只有一条：收录、编译、提交是三件独立的事，各自需要单独授权。把「已收录」当成「已编译」是最常见的误判。

三条路径的能力边界

路径做什么写到哪授权粒度
收录把原文按身份写入 raw 与 sourcesraw/articles/、sources/写文件
编译读源文件，抽出概念，生成互链页wiki/concepts/、wiki/MOC.md整库操作
提交写入索引、日志，推送到远端Git 仓库commit / push 分开

编译器写的是 wiki/ 子树，仓库根的 concepts/、entities/、index.md 不会被覆盖。两套目录并存，不是「重写索引」。

四种审计状态

COLLECTED MISSING OUTDATED UNDETERMINED
状态含义该做什么
COLLECTED身份与当前正文一致，raw 与 sources 同字节不用动
MISSING正文存在，但没有匹配的收录记录补录
OUTDATED收录的是旧版本正文新增一条，旧版不删
UNDETERMINED证据不足，无法判定保留待判定，不强行收录

只有任务记录、没有正文也没有冻结 manifest 的目录不是文章，不进入语料分母。人工登记目录始终保留审查路径。

文章身份的构成

身份用两个哈希锁定，缺一不可：

wx-publish-<sha256(文章身份)>-<sha256(正文字节)>.md
  • 身份哈希保证同一篇文章的不同版本各存一份
  • 正文哈希保证内容变化时新增记录，旧记录不覆盖

两个身份不同但正文相同的目录，必须各有一份。用一个顶替另一个会造成事实错位。

维护流程

1审计
2收录
3编译
4提交

第 1 步：审计

cd /home/ccwq/utils/wx-publish
bun run test:wiki-ingestion
bun run wiki:check --wiki ~/hehome/hermes-data/home/wiki \
  --report /tmp/wiki-check.json

先跑离线测试，再跑全量审计。报告按状态计数，不按文件名猜测覆盖率。

正文绑定失效时，以冻结 manifest 记录的正文为准。绑定漂移单独列为待确认，不改写正文，也不手改任务台账。

第 2 步：收录

写入四个位置：raw/articles/、同名 sources/、index.md 入口、log.md 记录。

raw 与 sources 必须同字节

正文逐字附加，不改行尾，不裁剪空白。写完逐字节校验

旧版本不删不覆盖

新正文哈希不同就新增文件，历史 raw 全部保留

分批写、逐批回读

每批两篇，写完回读并跑审计，两次结果一致才进下一批

写前先存快照

记录原有未提交状态与文件快照，写后核对未授权文件未变

只有 HTML 变体时，先列出各变体让维护者指定正式版，再转成 Markdown，转换后做保真度核对：原文可见文本必须全部落入 Markdown，Markdown 不得引入原文没有的句子。

第 3 步：编译

编译器是独立 CLI，provider 凭据只走环境变量，不改任何项目文件。

export LLMWIKI_PROVIDER=anthropic
export LLMWIKI_MODEL=claude-sonnet-4-6
export ANTHROPIC_BASE_URL=http://127.0.0.1:15721
export ANTHROPIC_AUTH_TOKEN=<REDACTED>

cd ~/hehome/hermes-data/home/wiki
llmwiki compile --review --verbose

--review 把结果写进 .llmwiki/candidates/，不写知识页。审完用 llmwiki review approve 或 reject 处理。

警告：先在隔离目录编译单篇代表源，测出单篇耗时与候选页质量，再用「单篇耗时 × 源数量 ÷ 并发」估算总量。直接开全量再发现质量不合格，代价是整库返工。

编译能带来什么

能力说明验证
自然语言提问选相关页并生成带互链的答案✓
行号溯源每段断言标注源文件行号区间✓
自动互链判断哪些页该互相引用✓
概念切分一篇长文拆成多个细粒度概念页✓
语义搜索依赖 Voyage 嵌入，未配 key 时跳过✗

实测单篇约 3700 字正文产出 7 个候选页，耗时 74 秒。语义搜索缺少嵌入凭据时跳过，不阻断编译与提问。

编译的代价与风险

项实测影响
源文件规模1782 个，平均 3039 字节全量耗时以小时计
预估概念页约 10169 个产物体积 40 至 60 MB
LLM 调用抽取与生成两阶段，约 20000 次消耗模型额度
输出语言未指定时可能产出英文页与现有中文页体系不一致
根日志编译会追加项目根 log.md跑全量前必须备份
警告：未显式指定 --lang 时，产出可能是英文，与现有中文知识页体系不一致。中文体系请加 --lang Chinese。

第 4 步：提交

提交与推送分开授权。推送后必须回读远端，不能以本地状态代替远端验证。

cd ~/hehome/hermes-data/home/wiki
git log origin/main --oneline -1
git status --porcelain -uall
git ls-tree origin/main -- raw/articles/ | head

知识库可能有后台同步进程自动提交并推送。检查间隙里刚写的文件可能已经被提交。「我没提交」不等于「远端没有」。

编译状态分层

层级含义
SYNCED_ONLY原文已进 raw 与 sources，知识页未生成
COMPILED本轮编译完成且产出非空
PARTIAL_COMPILE只完成部分来源
RUNTIME_LIMIT达到运行时限，进程正常退出
FAILED编译中断或报错

限时脚本退出码为 0 不代表全量编译完成。报告必须给出本轮处理量与结束原因。

常见误判

  • 把「raw 已收录」说成「知识页已编译」
  • 把「限时脚本退出码 0」说成「全量编译成功」
  • 把「审计器报 MISSING」直接等同于「文章从未收录」，忽略历史记录缺协议字段
  • 用 grep 命中数当卡片覆盖率
  • 因为嵌入失败就判定编译失败
  • 因为「我没提交」就判定远端没有该文件

相关组件

llmwiki compile llmwiki refresh llmwiki review llmwiki query wiki:check SCHEMA.md

本文命令与路径取自本机实测环境。provider 代理地址与模型名按本机配置填写，换机器时以 ~/.claude/settings.json 的实际值为准。
