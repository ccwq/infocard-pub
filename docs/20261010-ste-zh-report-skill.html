01引入：AI 汇报三大病症

你的 Agent 是不是这样说话？

AI 在汇报任务结果时，常见三大病症：

  • 过程冗长——先讲思路、再讲过程、最后才说结果，context window 白白烧掉
  • 推测含糊——「应该是」「大概」「应该没什么问题」，证据缺失
  • 漏验证证据——说「测试通过了」但不写测了什么、覆盖范围多大

来看一个真实 Bug 修复场景的对比（来源：ste-zh README）：

❌ 常见 AI 汇报

「好的，我先看了一下登录相关的代码，发现问题应该是出在 token 刷新的逻辑上，大概是并发的时候两个请求同时去刷新导致的。然后我对 auth/refresh.ts 进行了修改，加了一个锁来实现串行化处理，另外顺手把一些日志之类的也优化了一下。测试基本都跑过了，应该没什么问题，不过 iOS 那边因为没有环境暂时没法验证。你看要不要我再把重试逻辑也一起改了？」

02ste-zh 是什么

面向 AI Agent 的中文任务汇报规范 Skill

ste-zh（dualface/ste-zh，MIT，2026-10-05 创建）是借鉴航空/工业界 ASD-STE100（Simplified Technical English，简化技术英语）原则的中文汇报规范。

核心定位：只规范 Agent 向用户汇报与讨论时的表达方式，不影响项目代码、注释、Commit 信息及生成的文件内容。

「已把 ste-zh 设为所有 agent 启动必读 skill；费一点 context window，但回答清晰有条理、脑力消耗大降。」——作者 @dualface，2026-10-10，97 赞/10 RT/7,298 views

03五要素拆解

规范化汇报的 5 条核心规则

①

关键信息先行

首句按回复类型写。结果写「状态+完成范围」；进度写「当前动作」；需求总结写「总结范围」。普通解释不强套模板。

②

状态固定

工作状态与验证状态分开表述，各自限定范围。「已完成」≠「已验证」。代码改完 ≠ 运行通过。

③

如实写验证

写明检查方法+结果+覆盖范围。资料内容证据不能代替运行验证。包含新增测试要注明文件名和行号。

④

一词一义 + 主动语态

消除虚化动词（「进行」「完成」替换为具体动作）、歧义长句，降低阅读心智负担。

⑤

选项化决策

遇到需要人工定夺的决策点，自动整理为带推荐倾向的编号选项（如「推荐 1：撤回 / 2：保留」），用户输入数字即可快速推进。

⚠ 范围外改动处理

顺手改动（如 logger.ts 改动）要主动标出，给出「保留」或「撤回」选项，不能假装没发生。

04前后对比实解

Bug 修复汇报怎么变短变硬

以 README 中的 token 刷新 Bug 为例，逐行拆解规范版为什么更好。核心洞察：规范版比常见版更短（更少 token 消耗）却信息密度更高——因为删掉了思维过程、语气词、犹豫词，把空间留给事实。

除了结果汇报示例，SKILL.md 还包含 5 种标准化输出模板：

  • 结果汇报 — 任务完成后结构化输出（上述 Bug 修复即此类）
  • 进度汇报 — 进行中任务的状态更新
  • 需求总结 — 多任务或迭代的需求摘要
  • 建议 — 向用户提出建议时遵循的格式
  • 待决事项 — 需要用户决策时整理的选项

examples/task-summary.md 还提供了多任务与迭代需求总结的改写前后对比，演示如何处理多个并行任务的汇总汇报。

06进阶用法

全局常驻 + 上下文衰减恢复 + 与 Kander 协同

全局常驻（每个会话自动开启）

将以下内容写入 Claude Code 的 ~/.claude/CLAUDE.md 或 ~/.claude/rules/ 规则文件：

每个会话开始时加载 ste skill（dualface/ste-zh）。
所有任务汇报遵循 ste-zh 规范：关键信息先行、状态固定、实证说话、选项化决策。

❓ 写入 CLAUDE.md 的实际效果量化数据尚无公开实测报告。

上下文衰减与 /ste 恢复

极长会话或发生上下文压缩（compaction）后，Agent 可能遗忘规范。此时重新发送 /ste 即可恢复。作者建议在发现输出风格退化时主动重发。

❓ compaction 后规范恢复率暂无公开数据。

与 Kander 多 Agent 看板协同实战

作者使用 Kander（规则驱动的多 Agent 看板调度工具）并行调度多个任务时重度依赖 ste-zh：

  • 高效扫视：看板上多张任务卡并行流转，每张卡汇报首句给出当前关键信息，扫一眼即知任务进展
  • 完成与验证分开：代码修改执行完毕、运行检查未执行时，可写「已完成：代码修改。运行效果未验证。」——不混淆状态
  • 极简数字决策：阻塞点被格式化为编号选项，回复数字即可快速放行，多 Agent 并行时效率倍增

❓ ste-zh 与其他 Agent（Cursor、Codex 等）的兼容实测暂无公开数据。

07适用与不适用

什么场景收益最大，什么时候别用

适用 ✅不适用 ❌
AI Agent 向用户汇报任务结果项目代码、注释、Commit 信息
多 Agent 并行调度（Kander 等看板）生成的文件内容
需要人工确认决策点的复杂任务纯创意写作、闲聊、解释性问答
调试/修复类任务的进度报告需要完整思维链展示的教学场景
需要留存可追溯证据的交付物简短的一次性查询

最大收益场景：多 Agent 并行调度时，每个 Agent 的输出都要被人类快速扫视决策——首句关键信息 + 数字选项化决策，是这个场景的效率倍增器。

❓ 与 LangGraph、CrewAI 等框架的集成方式暂无官方文档。

与 SKILL.md 自检清单配合

每次汇报前，可用 SKILL.md 末尾的自检清单快速核对：

  • 首句是否给出了关键信息（状态 + 范围）？
  • 「已完成」和「已验证」是否分开、是否限定了范围？
  • 验证部分是否写明了检查方法、结果与覆盖范围？
  • 虚化动词是否替换为具体动作词？
  • 需要人工决策的点是否整理为带推荐的编号选项？

这套自检流程可内化为肌肉记忆，显著降低漏项概率。

与 terminology.md 配合：受控情态词与虚化动词替换

references/terminology.md 中有两张核心表：

  • 受控情态词：规范「可能/也许/大概」等模糊推测词的替代写法，只在有实证时才使用确定性表达
  • 虚化动词替换表：「进行」→「执行/写入/调用」；「完成」→「写入完毕/验证通过/已串行化」——替换后动作具体可查

❓ 虚化动词替换表的具体条目数量暂无公开数据，需查阅仓内文件。

08与 ASD-STE100 的关系

谱系、改造与合规声明

ASD-STE100 是什么

ASD-STE100（Simplified Technical English）由欧洲航空航天与国防工业协会（ASD）维护，是一套针对英文技术维护文档的受控语言规范，核心目标是消除歧义与理解偏差，在航空/工业领域已有数十年实践验证。

ste-zh 的改造方式

  • 提炼 ASD-STE100 核心原则，结合 AI 交互特点重构为中文实用规则体系
  • 25 条核心规则独立设计，非原文直译
  • 未收录 ASD-STE100 原文与受控词典（原文词典需向 ASD 官网免费申请）
  • 核心文件：SKILL.md（25 条规则 + 5 种输出模板 + 自检清单）、references/terminology.md（受控情态词/虚化动词替换表）

合规声明

「本项目为个人开源项目，未收录 ASD-STE100 原文与受控词典，与 ASD 组织无隶属关系。ASD-STE100 与 Simplified Technical English 的权利属于 ASD。如需研读 ASD-STE100 英文原版标准，可在其官网免费申请。」——ste-zh README

09术语表

ste-zh 核心术语

受控语言（Controlled Language）
通过词汇、语法限制消除歧义的语言体系。ASD-STE100 是英文技术文档的受控语言规范，ste-zh 是其面向 AI Agent 汇报场景的中文改造版。
ASD-STE100
Simplified Technical English，欧洲航空航天与国防工业协会（ASD）维护的英文技术文档受控语言规范，已有航空/工业领域数十年实践验证。官网免费申请。
Compaction（上下文压缩）
Agent 长会话中上下文超过限制时，系统对历史对话进行压缩合并的操作。压缩后 ste-zh 规范可能被遗忘，需重发 /ste 恢复。
虚化动词（Weak Verb）
语义模糊、缺乏具体动作指向的动词（如「进行」「完成」「处理」）。ste-zh 要求替换为具体动作词（如「写入」「调用」「串行化」）。
SKILL.md
ste-zh 的入口文件，包含生效机制、适用范围、25 条核心规则、5 种标准化输出模板（结果汇报/进度汇报/需求总结/建议/待决事项）及自检清单。
references/terminology.md
ste-zh 的术语字典，包含 ASD-STE100 关键词译法、受控情态词列表、虚化动词替换表、固定状态词与标点规范。
已完成 ≠ 已验证
ste-zh 核心区分：代码改完 =「已完成」，实际运行效果验证通过 =「已验证」。两者分开表述，各自限定范围。
Kander
dualface 开发的规则驱动多 Agent 看板调度工具，内置独立审核与自动化交付门禁。与 ste-zh 协同使用是其典型场景。
skills CLI
Vercel Labs 推出的 Agent Skill 管理工具，支持 Claude Code、Cursor、Codex 等主流环境。自动将技能安装至对应目录。
