Chatbox vs BotGem：真正同步才是分水岭

目标不是“电脑和手机都能装”，而是：可保存自定义 Agent/系统提示词，并让助手配置、对话与数据在 PC 和移动端持续一致。按这个硬门槛，原始两款都不是当前最稳选择。
必须：自定义 Agent 提示词必须：PC ↔ 手机同步偏好：免费 / 开源允许：自建服务
一句话结论
LibreChat / Open WebUI

愿意自建：前者更像多模型 Agent 工作台，后者功能最全、PWA 最成熟。想轻量：NextChat。想零运维原生 App：Chatbox 更顺手，但要接受“多端可用 ≠ 自动同步”。

Recommended shortlist

通过 Gate 的三种路线

评分仅在通过/条件通过者之间比较；满分 10
01

LibreChat

首选 · Agent 深
9.0/10

最适合把“自定义提示词”升级为真正的 Agent：指令、模型、工具、Skills、MCP、文件与代码解释器可组合；同一自建实例的账号与数据库天然跨端一致。

MIT 开源；多模型、多用户、响应式网页
Agent Builder 明确支持自定义 Instructions
代价：需要 Docker/云服务器与升级维护
适合：重视 Agent 能力、模型兼容与长期可迁移性。
02

Open WebUI

首选 · 功能全
8.9/10

服务端集中保存账号、对话、模型包装与知识库；手机使用官方 PWA，PC 可浏览器或桌面 App。自定义系统提示词、工具、知识、参数和动态变量都很完整。

移动 PWA 有官方明确文档，跨端路径最清楚
部署与 Agent/知识库/工具生态最丰富
代价：许可证带品牌保留要求，并非宽松 MIT
适合：要一套“私有 ChatGPT 平台”，愿意承担运维。
03

NextChat

条件首选 · 轻量
7.5/10

体积小、PWA/桌面/移动覆盖广，可用 Mask 保存系统提示词与上下文模板，并提供 Upstash/WebDAV 同步路线。更像轻客户端，不是完整 Agent 平台。

MIT 开源，部署成本最低，界面上手快
同步需自行配置，能力和冲突处理应先小范围验证
项目更新与新模型跟进弱于前两名
适合：只要提示词角色 + 基础聊天同步，不追求复杂工具链。

Cherry mobile status

Cherry Studio 到底有没有手机版？

答案：有，而且是官方项目

CherryHQ/cherry-studio-app 是官方 iOS/Android 客户端，采用 Expo React Native；GitHub 已发布 v0.1.0–v0.1.7，并提供安装资产。不是第三方“类似版”。

官方移动端iOS / Android

但仍不能替代桌面版

移动端 README 写明模型 Provider 仍在逐步接入；早期发布说明提醒按钮失灵、交互未完善和偶发闪退。v0.1.6 还提示当前数据库将废弃。

早期 / 内测功能未齐

最大缺口：桌面 ↔ 手机同步

v0.1.6 明确写道：待“桌面 V2 + 移动 v0.2”稳定后才开始数据同步工作；最新仍为 v0.1.7。故当前只能判定“手机版存在，统一同步未完成”。

Action map

直接照着选

我不想折腾服务器选 Chatbox；接受手工备份/恢复，或把不同设备当独立客户端。
我要真正 Agent + 同步选 LibreChat；一套服务器，多端登录同一账号。
我要知识库、工具和 PWA选 Open WebUI；功能最多，但先看许可证和运维。
我只要轻量提示词角色选 NextChat；先用 2 台设备验证 Mask、对话和冲突同步。
我最喜欢 Cherry Studio桌面继续用；移动端先作为内测，不迁移主数据。
我原本想选 BotGem除非你确认不需要同步且实测自定义 Agent 满足，否则不建议。
Evidence & limits

证据、风险与未验证项

已确认

Chatbox/BotGem 均有 PC 与移动 App；两者官方都强调本地存储。Cherry 官方移动端存在，但同步工作尚未开始。LibreChat/Open WebUI 的自定义 Agent 与服务端形态有官方文档。

仍需 POC

NextChat 的 WebDAV/Upstash 是否完整同步 Mask、Provider 设置、聊天分支与附件；手机端长对话体验；自建实例外网访问与备份恢复。
