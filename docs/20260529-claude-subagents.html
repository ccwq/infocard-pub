01 · 什么是子智能体
Core Concept
核心定义

子智能体是一个命名的、隔离的 Claude 实例，拥有独立的系统提示、独立上下文窗口、独立工具访问列表和独立权限模式。父 Agent 将任务委托给子 Agent，子 Agent 独立运行并只将最终结果返回给父级。

核心价值
上下文隔离、并行执行、权限最小化、成本优化。
工作原则
子任务噪音停留在子 Agent 上下文中，不污染主会话；主 Agent 只汇总结果，不追踪中间过程。
隔离独立上下文 / 独立权限
并行多个子任务同时处理
最小权限tools 字段硬约束
成本按任务选 haiku / sonnet / opus
ReadGlobGrepWriteEditBashWebSearchmcp__*
⚠ 注意子 Agent 每次调用都是全新实例，无前序记忆。需要持久上下文时，优先通过文件传递或启用 memory。

04 · SKILL 角色如何转化为 SUB-AGENT
Skill → Agent
Skill 是什么
Skill 是基于文件系统的可复用资源，提供领域专属知识：工作流、上下文、最佳实践。它是对 Claude 说“先读这份文档再行动”的机制。
# SKILL.md 典型结构
---
name: docx
description: 当用户需要创建 Word 文档时使用此技能...
---
## 操作流程
1. 先 view SKILL.md
2. 安装依赖 python-docx
3. 按规范生成文档...
映射对照
SKILL.mdname: docx / description / body
Agentname: docx-specialist / tools / model
关键差异Skill 是被动文档；Sub-Agent 是主动执行者
💡 关键差异转化后 Agent 自带工具权限和独立上下文，父 Agent 只需委托指令无需读取文档。
实际转换步骤
①
提取 SKILL.md 的领域知识将操作流程、约束规则、输出格式要求直接复制到新 Agent 的系统提示中。
②
强化 description 为触发短语将 Skill 的触发描述改写为以 “MUST BE USED for…” 或 “Use proactively when…” 开头的委托指令。
③
根据任务性质限定工具文档生成类：BashWriteRead；代码审查类：ReadGrep。
④
定义输出格式明确 Agent 返回内容的结构，让父 Agent 能直接使用而无需解析。
完整转换示例：docx-specialist
--- # .claude/agents/docx-specialist.md
name: docx-specialist
description: "MUST BE USED when user asks to create Word (.docx) documents, reports, memos, or letters. Use proactively for any document generation task requiring professional formatting."
tools: Bash, Read, Write, Edit
model: sonnet
---
你是 Word 文档专家。执行前先运行：pip install python-docx

## 标准流程
1. 分析用户需求和文档类型
2. 使用 python-docx 生成文件
3. 输出到 /mnt/user-data/outputs/
4. 返回：文件路径 + 内容摘要

Models
模型适用场景成本
haiku快速检索、格式转换、简单分类、代码搜索最低

06 · 核心编排模式
Patterns
S
串行管道（Sequential Pipeline）pm-spec → architect → builder → validator → documenter。每步输出作为下步输入，通过 PLAN.md 传递状态。
P
并行扇出（Parallel Fan-out）主 Agent 同时派发多个子任务（研究 A/B/C），等待结果后聚合。适合研究、批量分析。
C
审核循环（Checker Loop）Builder 生成代码 → Validator 审查 → 若失败重新委托 Builder 修复，直至通过。
A
异步委托（Async Delegation）派发子 Agent 后主会话继续其他工作，子 Agent 完成后返回更新。适合长时间任务。
团队工作流：典型 4-Agent 系统
📋 PM-Spec
tools: Read, Write · model: opus
读取需求 → 生成详细 spec → 写入 PLAN.md
🏗 Architect
tools: Read, Write · model: sonnet
读取 spec → 设计方案 → 写入技术文档
⚙ Builder
tools: all · model: sonnet
按方案实现功能，每个功能独立 worktree
🧪 Validator
tools: Read, Bash · model: haiku
运行测试 → 代码审查 → 标记 READY/BLOCKED

07 · 安全最佳实践
Safety
最小权限原则
每个 Agent 的 tools 字段只包含完成任务所需的最少工具。审查员不需要 Bash；研究员不需要 Write。
✓
Reviewer Agent 仅含 Read, Grep, Glob
✓
生产部署 Agent 用 permissionMode: default
✓
机密用环境变量，不写入 PLAN.md
✓
并行 Agent 使用 Git worktree 隔离
✓
项目 Agent 提交 Git 前团队 review
⚠ 常见问题
症状原因 & 解法
Agent 未被自动调用description 不够明确。在开头加 “MUST BE USED for…”
同名 Agent 行为异常检查优先级冲突，项目级会覆盖用户级同名 Agent
Agent 重复读取相同文件子 Agent 无记忆。将上下文通过参数传入或写入共享文件
工具调用被拒绝tools 字段缺少该工具；检查 permissionMode 设置
并行 Agent 冲突为每个 Agent 创建独立 Git worktree：git worktree add
