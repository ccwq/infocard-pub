02
THE LOOP

核心循环机制

8 步迭代 + 8 条铁律

执行流程

每次迭代 8 步

  1. 复盘当前状态 + git 历史 + 结果日志
  2. 基于成功 / 失败 / 未尝试的组合，挑下一次改动
  3. 做一次聚焦改动
  4. git commit（验证前先存档）
  5. 跑机械验证（测试 / 基准 / 评分）
  6. 改善则留，变差则 git revert
  7. 记录结果到 TSV 日志
  8. 重复直到达到迭代次数或目标
8 条铁律

Setup 阶段的硬约束

  • 默认有界：每条命令有默认迭代上限，无限模式需 opt-in
  • 先读后写：改前必须理解完整上下文
  • 一次一改：原子改动，坏了就知道为什么
  • 仅机械验证：拒绝主观「看起来不错」
  • 自动回滚：失败立刻 revert
  • 简洁优先：同等效果 + 更少代码 = 保留
  • Git 是记忆：用 experiment: 前缀 commit，agent 每次迭代前读 git log
  • 卡住时多想：重读、合并接近解、尝试激进改动

HOOKS · SAFETY

9 条安全钩子

v2.1.1 默认开启，保护每次会话

保护

上下文 / 隐私 / 危险命令

  • scout-block：拦截 node_modules / .git 灌入上下文
  • privacy-block：拦截 .env / SSH key / 凭据被读
  • dangerous-cmd-block：拦截 force-push / rm -rf / reset --hard
上下文注入

跨压缩 / 子智能体

  • iteration-context：压缩后注入最近 TSV 数据
  • subagent-context：子智能体感知当前 loop 状态
  • dev-rules-reminder：注入计划路径 + 代码规范
  • session-init：会话开始时建立项目上下文
门禁 / 通知

门禁 + 通知

  • simplify-gate：400 行警告 / 800 行拦截出货
  • stop-notify：会话结束终端通知 + 可选 Webhook
  • 用 .ckignore 自定义拦截目录

07
RISK · LIMITS

风险与边界

量化指标任务：起飞；主观审美任务：失灵

1

机械验证必要

必须有可执行的测试 / 基准 / 评分函数。「让代码更好看」「让产品更好用」这类主观目标会失败——agent 无法量化。

2

成本不可控

25 轮默认 + 无 opt-in 上限意味着 agent 可能跑一整夜。需用 Iterations: N 或 --chain 限制；token 成本按调用次数累加。

3

Git 状态强依赖

回滚机制基于 git，必须是 git 仓库且工作区干净。子智能体调用上下文会注入 loop 状态，需要协作约定避免冲突。
