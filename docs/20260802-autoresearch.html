AutoResearch

让 Agent 自主循环改代码、自动验证、自动回滚

它的核心是受约束实验循环：每次只改一处，用机械指标决定保留或撤销。

Quantified goalMechanical verificationBounded iterationsGit memory
不是自动化越多越好

AutoResearch 适合有明确指标的工程优化；没有可执行验证函数时，循环只会更快地放大误判。

PROJECT IDENTITY

AutoResearch 是什么

把 Karpathy autoresearch 的“指标 + 约束 + 快速验证 + 回滚”泛化到 coding agent。

REPOSITORY

MIT 开源项目；卡片原始来源记录为 v2.2.1 与 5,623 stars，动态数据需按发布日复核。

ORIGIN

PLATFORMS

Claude Code / OpenCode / Codex

以 agent skill / command 形态接入多种 coding agent。

FIT

可量化任务

测试覆盖、性能、错误清零、安全审计等有机械验证的任务更适配。

02
CONTROL LOOP

Modify → Verify → Keep / Discard

核心不是“自动写代码”，而是以受约束循环让改动可比较、可撤销。

01

设置 Goal + Metric

明确目标、指标、迭代上限与允许修改范围。

02

读取当前状态

查看代码、Git 历史和既往实验结果。

03

做一次聚焦改动

避免同时改变多个变量，保留归因能力。

04

先保存再验证

以 Git 保存候选状态，然后运行测试、基准或评分。

05

保留或回滚

指标改善才留下；变差则 revert 并记录结果。

06

迭代直到停止条件

达到目标、到达上限或发现无效指标时停止。

03
SAFETY

安全钩子与运行边界

自动化循环必须限制上下文、权限、成本和 Git 状态。

CONTEXT

上下文保护

避免 node_modules、.git、凭据等内容进入上下文；敏感信息应被阻断。

COMMANDS

危险命令门禁

force-push、破坏性删除与 reset 等需要明确拦截或人工确认。

COST

有界迭代

默认迭代上限；无限循环必须 opt-in，并把 token 成本视为运行预算。

GIT

干净工作区

回滚与实验记录依赖 Git；并发 Agent 必须先定义写入边界。

04
COMMAND SURFACE

命令体系的作用

命令代表不同目标管线，不应被理解为对任何项目都安全的默认自动化。

CLASSIC

/autoresearch

经典 modify → verify → keep/discard 循环。

PLANNING

plan / debug / fix

把目标转配置、做假设驱动调试或逐个清理错误。

QUALITY

security / scenario / regression

面向安全审计、边界用例与基线稳定性。

DELIVERY

ship / improve / evals

面向出货流程、改进探索与结果趋势分析。

05
COMPARISON

何时选择 AutoResearch

它适合可衡量的优化，不替代通用 coding assistant 或人工产品判断。

维度AutoResearchAiderSWE-AgentKarpathy 原版
主目标量化目标的自主迭代交互式代码协作Issue 解决ML 调优实验
验证测试 / 基准 / 评分通常由用户驱动任务测试明确指标
回滚Git keep/discard需人工决策依任务流程实验归档
不适合纯审美、无指标问题——非 ML 类任务
