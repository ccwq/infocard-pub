01它到底是什么

Awesome Claude.md 的本质不是“再造一个 prompt 仓库”，而是把公开项目里的高质量 `CLAUDE.md` / `AGENTS.md` onboarding 文档做成可学习的索引系统。它既是样例目录，也是评分标准、发现系统和浏览站点：告诉你什么样的 AI onboarding 文档真的有用，什么样的结构值得抄，什么样的项目上下文最能帮 AI 少走弯路。

03为什么这类仓库有价值
对项目作者你不用从零猜 `CLAUDE.md` 该怎么写。这个仓库把公开优秀样例按类别拆开，并附分析，能直接借鉴架构说明、命令清单、测试路径、handoff 习惯和部署说明。
对 AI 使用者它帮助你理解：为什么有的代码库 AI 一进来就能工作，有的却总在瞎猜。核心差异往往不是模型，而是 onboarding 文档的结构质量。
04内容优先的评分体系
30

Content Depth： 是否写清架构、工作流、测试、部署、排查与上下文，而不是几句空话。

25

Educational Value： 是否真的教会别人可迁移的 AI onboarding 模式。

15

AI Effectiveness： 对 AI 是否结构友好、命令明确、上下文可消费。

20

Project Maturity： 是否有活跃维护、真实生产或长期使用痕迹。

10

Community Recognition： 星标、引用和社区认可只占 10%，不主导结果。

关键判断：这不是“谁 stars 多谁先进榜”，而是“谁能教会 AI 更快理解代码库谁更值钱”。仓库把质量门槛直接写成 60+ 才收录。
05自动发现系统

仓库并不只靠人工维护。`AUTOMATED_DISCOVERY.md` 和 `CLAUDE.md` 里定义了每周自动搜索 GitHub 的发现流程：搜 `filename:CLAUDE.md`，过滤已收录项目，按内容优先的规则打分，再自动开 issue 给维护者人工审核。

A

Weekly GitHub Action 每周一 UTC 9 点跑一次。

B

发现脚本模块化：loader / searcher / evaluator / reporter / utils。

C

只把 Top 10 候选列进 issue，走 community review。

这很关键：它让“收集 CLAUDE.md 样例”从一次性整理，变成一个持续更新的情报系统。也就是说，这个 repo 的第二层价值不是目录，而是 discovery pipeline。

07核心反模式
Never copy仓库明确禁止把别人的 `CLAUDE.md` 直接复制进来，只能链接原文、写分析、保留署名和 license 信息。
Star-based selection is forbidden星标只是 10% 权重，不能靠“热门仓库”替代内容质量评估。
08一句话结论

Awesome Claude.md 不是静态清单，而是一个围绕 AI onboarding 文档搭起来的轻量研究系统：样例库负责展示最佳实践，评分模型负责约束收录质量，自动发现系统负责持续更新，GitHub Pages 负责浏览体验。如果你想知道“一个代码库该如何让 Claude / Copilot / Agent 更快上手”，它提供的是一个现成的公开答案池。
