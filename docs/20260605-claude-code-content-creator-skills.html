这不是“收藏夹”，而是一条可执行的内容生产链

这 10 个 Skills 的价值，不在于“数量感”，而在于它们刚好覆盖了内容创作者最耗时的五段：调研选题、知识整理、内容生成、视觉化呈现、跨平台分发。真正的提效，不是让 Claude 多写一段，而是让它把整条链路跑完。

原帖主张

“真正的提效，是让 AI 按照你的创作流程完成调研、整理、写作、视觉化和分发。”

一个很清晰的受众信号

可见回复里有人直接问“有没有 codex”，说明这类资源帖的用户不只想看 Claude 生态本身，而是在找“同类、可替代、可迁移”的工作流能力。换句话说，大家想要的是一套方法，不只是一个仓库名录。

怎么把这 10 个 Skills 组合起来

workflow stacks
01 研究入口
Deep Research + NotebookLM
先把信息源和引用链打稳，再开始写。适合所有高信息密度内容。
02 流程固化
Skill Creator + Memory Bank
一个负责把 SOP 变成 Skill，一个负责维持长期风格和连续性。
03 成果表达
Frontend Design + Diagram + PPT
把文章变成网页、图表和演示稿，让内容具备“可展示”的形态。
04 分发放大
HTML Anything + Repurposer + GitHub Researcher
把长内容拆开、包装、再分发，同时继续寻找下一个选题。

评论 / 讨论摘录

discussion
可见回复
“感谢，有没有 codex”
最直接的反馈：这条资源帖的价值，是让读者继续追问“可替代方案是什么”。
解读
这类内容的重点不是“仓库清单”，而是“如何先后装、如何组合用、如何按创作链路挑选”。
如果把它做成卡片，最重要的是把路径讲清楚，而不是把名字堆满。

适合直接收藏的人

  • 想把 Claude Code 用到内容生产，而不只是代码生成的人。
  • 想快速建立 Skill 生态认知、并知道先装什么的人。
  • 想把调研、写作、可视化、分发串成一条工作流的人。

使用提醒

  • 先装最能补短板的 1–2 个，不要一口气全收。
  • 优先看 README、示例和工作流说明，而不只看仓库名。
  • 长期项目优先考虑上下文连续性和可维护性。
