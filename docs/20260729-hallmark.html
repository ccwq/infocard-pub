一句话结论：

Hallmark 是一个设计质量门禁系统，在 AI 生成的代码到达你之前，先过 57 道 slop-test + 六轴 critique（Philosophy / Hierarchy / Execution / Specificity / Restraint / Variety），确保输出不再是千篇一律的"紫色渐变 + 三个卡片"。

Hallmark 是 Together AI 出品的反 AI-Slop 设计技能，通过 57 道门禁测试和六轴 critique，让 Agent 生成不再是「紫色渐变 + 三个卡片」的同质化 UI。

AI coding agent 时代，Agent 生成的 UI 正在快速同质化：紫色渐变背景、三个 feature card、"Revolutionize your workflow" hero——这套模板统治了 90% 的 AI 生成页面。Hallmark 的核心贡献在于编码了一套可执行的设计质量门禁，把「品味判断」变成「可测试的规则」，在代码输出前拦截掉所有已知反模式。它支持 build（生成）、audit（打分）、redesign（重建）、study（提取 DNA）四个动词，内置 20 个主题目录，覆盖 Claude Code / Cursor / Codex 三大主流 Agent IDE。

01
FOUR VERBS

四个核心动词

Hallmark 的四种使用模式，覆盖从生成到诊断到重建的完整工作流。

默认模式

build

扫描类型 → 宏观结构 → slop test → 六轴 critique → 输出自包含 HTML+CSS 页面。

  • 输入：页面类型 + 品牌要素
  • 输出：设计系统级 HTML
诊断模式

audit

对现有代码打分，列出所有违反设计原则的反模式，并给出修复优先级。

  • 定量评分
  • 逐项反模式清单
  • 优先级排序
重建模式

redesign

扔掉现有视觉结构，保留品牌要素和路由逻辑，从零重建布局与排版。

  • 保留品牌 / 路由
  • 重建宏观结构
  • 重配字体 + 色彩
提取模式

study

提取现有设计的 DNA 结构：宏观结构 + 字体配对 + 色彩锚定，形成可复用的设计规范。

  • 宏观结构分析
  • 字体配对提取
  • 色彩锚定映射
02
SIX-AXIS CRITIQUE

六轴 critique 系统

在代码输出前，每个设计都必须通过以下六个维度的审视。

P

Philosophy

设计的整体哲学是否清晰？信息层级是否反映了真实优先级？页面是否有明确的叙事逻辑？

H

Hierarchy

视觉层次是否符合内容优先级？标题、正文、辅助信息之间的对比是否到位？是否有视觉噪音干扰核心信息？

E

Execution

技术实现是否精良？间距、边框、圆角是否一致？响应式断点是否合理？交互状态是否完整？

S

Specificity

设计是否具体且有针对性？是否避免了泛泛的"AI 默认样式"（如通用渐变、通用卡片）？

R

Restraint

设计是否克制？是否避免了过度装饰、信息过载、不必要的动画和视觉噪音？

V

Variety

设计是否有多样性？是否避免了与主流 AI 生成页面的同质化？是否有独特的视觉个性？

04
SLOP TEST

57 道门禁：紫色渐变问题的系统性解法

AI-Slop 的本质是「统计平均美学的过拟合」——所有模型都在同一批网页上训练，输出必然趋同。Hallmark 的 57 道门禁把「反模式」逐条编码为可测试规则。

AI-Slop 典型症状 vs Hallmark 门禁 ↔
维度 AI-Slop 典型症状 Hallmark 门禁规则
色彩 紫色/蓝色渐变背景，毫无色彩锚点 检测全局渐变滥用；验证色彩锚点（主色/辅色/中性色的对比关系）
布局 三个等宽 feature card 并排，高度雷同 检测等宽等高卡片组；验证布局节奏变化和视觉层级差异
文案 "Revolutionize your workflow" / "Cutting-edge solution" 检测套话关键词库；验证文案是否具体、是否有真实信息密度
字体 全站 Inter / Roboto，无字体层次 检测字体配对（标题/正文字体是否形成对比）+ 字号梯度是否完整
层次 标题/正文/注释之间无视觉区分 验证字重/字号/色彩的三层对比是否到位；检测"扁平化层次"反模式
排版 行高过大/过小，段落间距随机 检测基线网格偏离度；验证段落间距是否是字体大小的整数倍
动效 全站 fade-in，无目的的微动效 检测无信息量的装饰性动效；验证动效是否服务于信息传达
