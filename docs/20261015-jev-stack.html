01 核心结论 · 三个硬伤

推文不算编造，但它把三件需要限定的事说成了结论

清单提到的东西基本都存在，五个仓库都能打开、能安装。问题出在读法：

一、stars 与代码活动严重不匹配。 jev-ultrafast 有 22982 stars，但 commits API 只返回 3 条、contributors API 只返回 1 人、真实订阅者 56 个。本卡不指控任何事，只给判断方法：看 commit 活跃度、contributor 数、issue 回复质量，不要拿 stars 当成熟度。
二、自曝全在 README 没提的 docs/performance.md 里。 7.1 秒的口径、3 对对照样本、成本不含浏览器部分，作者都自己写清楚了，清单没带。
三、五者不是一套，是五家。 四个仓库都要 TYPESAFE_API_KEY，装一个就多一个云端依赖和一次调用成本；它们由不同作者分别发布，没有官方集成。

04 7.1 秒的完整出处

README 只给结果，docs/performance.md 给了口径和样本量

README 首屏只写「Zürich → London on Google Flights in 7.1 seconds」，然后指向 docs/performance.md。清单转述了前半句，没带后半句。

计时的起点和终点

当前视频跑完 Flights 任务 7.073 秒（1× 速度）。计时从第一次预测开始，到被接受的 DONE 结束，不含浏览器准备、初始导航，也不含事后独立复核。

指标原始分支优化后变化
中位耗时9.450 s7.092 s−25.0%
TypeSafe 请求数2217−5 次
浏览器协议调用1,092101−991 次
Jev 中位延迟178 ms178 ms单次计时中记录

对照条件

matched 对照只有 3 对、共 6 次运行。同一 Chrome profile、同一目标、1120×780 视口、TypeSafe jev-1.13.0、文本模型 inception/mercury-2.5、关闭文本推理。作者自己把这定性为小样本受控对比，不是通用 agent benchmark：

「三对样本不足以支撑强统计结论（双侧符号检验 p = 0.25）。这是一个小规模受控输入对比，不是通用 agent 基准。」 “Three pairs are too few for a strong statistical claim (two-sided sign-test p = 0.25). This is a small controlled-input comparison, not a broad agent benchmark.”

单次计时的构成

  • 17 次 Jev 请求；10 次交互 + 1 次显式 WAIT；2 次 helper 调用。
  • Jev 中位延迟 178 ms。
  • 搜索执行在 5.217 s，最终确认完成 7.073 s。
  • 文本生成：Zurich 581 ms，London 346 ms。

其他冒烟检查

原文注明这些不是对照，只是冒烟检查：Wikipedia 打开 Gödel 不完备性定理条目 2.798 s，结果为精确文章 URL；本地酒店 fixture 搜 Lisbon + Design + Free cancellation 并打开 Casa Flora 1.896 s，结果含房源与三项筛选。

05 成本 · 没有依据的说法

「成本双杀」这句话在仓库里找不到依据

⚠ 作者自曝：报出的金额不是任务总成本

录制的 17 次 Jev 请求共 90,558 输入 token / 6,325 输出 token。OpenRouter 对两次文本调用报 $0.00006272。原文紧接着写明这只是 text-helper 的费用，不是任务总成本：TypeSafe 响应里带 token 数但没有计费金额，浏览器成本被完全排除。

换句话说，仓库能给的只有文本 helper 的钱和一个 token 计数。Jev 侧的美元金额和浏览器侧成本都没有出现在这份文档里。任何基于此的成本结论都是清单作者的推断，不是仓库结论。

成本项仓库是否给出已知数值
文本 helper 调用有$0.00006272（OpenRouter，两次调用）
Jev 请求 token部分90,558 in / 6,325 out，无美元金额
浏览器成本无原文明确排除
任务总成本无无法计算

顺带说明为什么四个仓库都装不了「离线版」：Jev 在 TypeSafe 云端，每次决策都是一次外部 API 调用。不想再多依赖一个外部服务，这五个仓库一个都用不了。

06 LIMITS · 全卡最硬的边界

performance.md 的 Limits 段：不支持什么，以及 DONE 不算证据

「一个合法的操作仍然可能是错的，而 DONE 永远不是成功与否的独立证据。」 “A valid operation can still be wrong, and DONE is never independent evidence of success.”

DOM reader 的能力边界

  • 只支持常见 HTML / ARIA 控件。
  • 不实现完整的 accessible-name 算法。
  • 不遍历 shadow root 和 frame。
  • click guard 有意放行与当前任务无关的可见更新。

明确列为不支持的功能

canvas 文件上传 新标签页 嵌套滚动 任意键盘组件

这五类不是「暂时没做」，是文档里写明不支持。按这五条筛任务，比看 7.1 秒有用。

7.073 秒之后还有事

计时到 DONE 为止，不含事后独立复核。仓库提供的 examples/flights.py --keep-open 会做航班搜索、检查真实路线 / 日期 / 结果并保存 trace——也就是把验证放在计时之外。README 也明确写了它不会选、也不会订机票。

07 JEV 机制 · 它不写文本

Jev 是决策模型，不是文本生成模型

Jev 来自 TypeSafe，官网 docs.typesafe.ai/introduction，README 称其为 “System One” 决策模型。它的定位是：它从不写文本。你给它当前 state 和一个类型化问题，它回一个带校准概率的结构化答案。

四种问题类型

NOUL

二元判断

yes / no。例：「这次失败是瞬时的吗？」

CHOICE

单选

从若干候选里选一个。例：「这个 bug 归哪个子系统？」

SCORE

有序评分

严重度、复杂度、风险这类可排序的量。

TEXT

文字生成不在范围内

需要真文字时另找一个小模型：demo 用 OpenRouter 上的 inception/mercury-2.5（关闭 reasoning），也可用 Gemini、GLM、DeepSeek 的 OpenAI 兼容接口。

配置

四个仓库都需要 TYPESAFE_API_KEY。Console 在 console.typesafe.ai/settings/keys（另有 console.typesafe.ai/keys 的写法）。写入 ~/.hermes/.env，建议 chmod 600。

// ~/.hermes/.env — 本卡不含任何真实密钥 
TYPESAFE_API_KEY=[REDACTED]
TEXT_MODEL_API_KEY=[REDACTED]      # 仅 jev-ultrafast 需要，用于 TYPE_TEXT
08 五仓库逐个读

逐仓库要点与边界

1 · browser-use/jev-ultrafast（最核心，也最需要泼冷水）

README 描述语：a browser agent with a dynamic, indexed action space。机制是每次观察都生成新的带索引元素表，元素形如：

// 每次观察重新生成的带索引元素表 
[1] button    Change ticket type · Round trip
[2] combobox  Origin
[3] link      Sign in

操作空间固定为八种：CLICK、TYPE_TEXT、SELECT、SCROLL_UP、SCROLL_DOWN、WAIT、DONE、BLOCKED。Jev 在一次请求里同时选出 operation 与 target，小模型只负责 TYPE_TEXT 时的文字。README 的说法是 “Two decisions, one network round trip.”，每个 target head 只含兼容元素。

没有站点专用脚本。原文：“There are no site-specific action scripts or prepared field strings in the policy.”

// 安装与运行 
git clone https://github.com/browser-use/jev-ultrafast
cd jev-ultrafast && uv sync
cp .env.example .env          # 填 TYPESAFE_API_KEY 与 TEXT_MODEL_API_KEY
uv run jev                    # 打开 http://127.0.0.1:8766

Chrome 通过 browser-use/browser-harness 接入，需开远程调试，uv run browser-harness --doctor 诊断。库用法有 Agent(url, goal) 的 context manager。仓库另有 Browser Use Cloud waitlist 入口（browser-use.com/ultrafast）。

⚠ 用它之前先接受三件事
  • 上面第 03 节的 stars 异常，以及 200 个未关闭 issue。
  • 第 06 节 Limits 段的五类不支持功能与 shadow root / frame 不遍历。
  • 7.073 秒不含浏览器准备、初始导航与事后复核。

2 · keeltrace/hermes-nerve

定位：asynchronous System-1 supervisory layer for Hermes Agent。README 自述 Nerve / Reflex 是 watchdog 与 forecaster，最终 stop / continue 权限归主 orchestrator / reviewer，不是它自己拍板。核心插件零依赖，模型运行时放在 sidecar。

⚠ 版本纪律值得单独抄走

README 开头就写明开发状态：当前 main 标识为 0.3.2.dev0，最新稳定版是 v0.3.1。main 含 0.3.1 之后的开发工作，与稳定发布不是同一棵树。Hermes 目录安装走精确 commit-SHA 固定，可能落后于 main，直到目录 SHA-bump PR 被审阅合并。

Dev17 新增 reflex_backend=openjev，并把 Jev-authoritative shadowing 推广到 Laya 或 OpenJev 两者，配 crash-safe 的 Jev / Laya / OpenJev 矩阵 runner。关键词：typed System One decisions、ranking、verification、token-aware oversight、opt-in tool gate。

3 · DECRUX9812/typesafe-skill-router（最小可试的一个）

解决的问题原文：Hermes 展示每个已装 skill 的一行描述，几百个 skill 时模型会跳过真正能干活的那个。做法是先把请求发给 TypeSafe（模型 jev-latest），确有匹配时向用户消息追加一行 <skill_relevance>…</skill_relevance>；不匹配就一行都不注入。

// 安装（要求 Hermes Agent >= 0.21，Python 3.10+，仅标准库无依赖） 
hermes plugins install typesafe-skill-router
hermes plugins enable typesafe-skill-router
hermes typesafe-skill-router on
# 若安装前 Hermes 已在运行：hermes gateway restart 加载一次 hook
# 之后开关即时生效

失败路径是设计过的：默认 opt-in（enabled: false），缺 key、无 roster、超时、传输错误都只记一行日志并返回 None。原文原话：

「路由问题永远不会搞坏一个 turn。」“A routing problem can never break a turn.”

仓库描述里提到约 $0.001 per routed turn。这个数字出自仓库描述，不是 performance 文档，口径不明，引用时按「仓库自述」对待。

4 · kerpopule/hermes-jev-skills（功能最宽，也最需要边界提醒）

定位：给 agent 一个便宜快的第二大脑处理小决策。README 把 token 浪费点列为 decisions 而非 prose：哪台模型该答、377 个 skill 里该加载哪个、哪些检索片段值得看、哪些轮次能在摘要后存活、下一个按钮是哪个。速度约 0.4 秒，成本约为几分之一美分。

覆盖：模型路由、搜索结果筛选与充分性判断、社交研究、计算机与浏览器操作、记忆过滤、压缩。
自称跨 Hermes / Claude Code / Codex。
边界：它是一个 skills 合集而非插件，安装后仍需各自配置与 API key。README 里的实测数字是它自己仓库的 demo 结果，不能当第三方基准。

5 · ajensenwaud/hermes-jev-plugin（最小）

四个工具对应四种问题类型：

TOOL

jev_evaluate

在同一 state 上多次判断，一次调用，可混合类型。

TOOL

jev_check

Noul，二元判断，如「这次失败是瞬时的吗」。

TOOL

jev_route

Choice，单选，如「这个 bug 归哪个子系统」。

TOOL

jev_score

Score，有序评分，如严重度 / 复杂度 / 风险。

配置项：model（默认 jev-latest）、timeout_seconds（默认 30）、max_questions（默认 20）。内置 skill jev:jev-questions，用 skill_view("jev:jev-questions") 载入。安装：hermes plugins install ajensenwaud/hermes-jev-plugin。

09 选型结论

按目标选，五者没有统一入口

你想做什么选哪个理由与代价
最小试一下ajensenwaud/hermes-jev-plugin12 stars，4 个工具，装一条命令。代价：无条件即引入一个外部 API key。
最小试一下（更保守）DECRUX9812/typesafe-skill-router14 stars，仅标准库无依赖，默认 opt-in，失败不破 turn。要 hermes gateway restart 一次。
真研究浏览器动作空间browser-use/jev-ultrafast唯一给出可读实现与性能文档的。但先接受 Limits 段与 200 个未关闭 issue。
给 Hermes 加监督层keeltrace/hermes-nerve注意 0.3.1 稳定版与 main 开发线的区别，目录安装按 commit-SHA 固定。
跨框架的决策类 skillkerpopule/hermes-jev-skills377 个 skill 覆盖最宽。装完仍需各自配 key。
不再依赖外部服务五个都装不了Jev 在 TypeSafe 云端，没有本地部署选项（未核实是否有自托管，仓库未提供）。

顺序建议：先用 router 或 plugin 试，失败路径干净且代价小；确认 Jev 的判断质量对你的任务有用，再去看 jev-ultrafast。反过来从 22982 stars 那个开始，容易把 star 数当成成熟度。

10 核查方法 · 未核实项

本卡怎么核的，以及哪些没核

已核实

  • 五仓库元数据：GitHub REST API，2026-10-15 快照。
  • jev-ultrafast 的 commit / contributor / subscriber / issue 数：同一 API。
  • 7.1 秒的口径、样本量、成本自曝、不支持清单：README 与 docs/performance.md 全文逐段读取。
  • 四个仓库的安装命令、配置项、默认版本号：各仓库 README 全文。
  • browser-use 组织信息：组织主页与仓库列表。

未核实

  • 7.073 秒未在本卡环境中复现。原视频与原始 trace 未取到，只读了文档。
  • OpenRouter 的 $0.00006272 未复算；它是两次文本调用的报价，且原文声明不含浏览器成本。
  • typesafe-skill-router 的 $0.001 per routed turn 只有仓库描述一句，无明细。
  • hermes-jev-skills 的 0.4 秒与几分之一美分来自其自述 demo。
  • TypeSafe 是否提供自托管或本地推理：README 未提，本次未查证，标为未核实。
  • hermes-nerve 目录 SHA-bump PR 的实际审阅进度未查。

收口

这五个仓库值得看，但值得看的理由不是 star 数。Jev 提供的是类型化决策而不是文本生成，这是它真正的新意；jev-ultrafast 把「一次网络往返里同时选操作和目标」写成了可读实现，这是它最大的价值。同一份文档里，作者自己写下了 3 对样本、p = 0.25、成本不含浏览器，以及 DONE 不是成功证据。读 README 和读 performance.md 会得到两个不同的结论。

  • 选 12–14 stars 的那两个先试，失败路径干净。
  • 看成熟度看 commit、contributor、issue 回复，不看 stars。
  • 速度数字先问起点终点，成本数字先问含哪些项。
