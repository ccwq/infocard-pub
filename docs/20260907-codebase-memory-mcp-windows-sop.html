01 · 先理解五层关系

MENTAL MODEL
Codex理解任务、选择 MCP 工具、生成修改
MCP 前端把 Codex 请求转给本地服务
daemon共享索引、watcher、UI 和并发协调
知识图谱函数、类、调用、路由、测试关系
源码仓库真实代码仍是最终证据
关键边界：关闭 watcher ≠ 删除索引；删除索引 ≠ 禁用 MCP；停止 daemon ≠ 卸载。图谱适合结构问题，具体实现与运行错误仍需读取源码、日志和测试。

02 · Windows 安装 + Codex 接入

ONE-TIME SETUP
01

下载并检查

Invoke-WebRequest -Uri https://raw.githubusercontent.com/DeusData/codebase-memory-mcp/main/install.ps1 -OutFile install.ps1 notepad .\install.ps1
02

安装

Unblock-File .\install.ps1 .\install.ps1

策略拦截：powershell -ExecutionPolicy Bypass -File .\install.ps1

03

检查改动

codebase-memory-mcp install --dry-run

只显示将修改的配置、Skill、AGENTS、hooks，不写入。

04

重启并信任

codebase-memory-mcp --version

完全重启 Codex；通过 /hooks 审查并信任 hooks。

Codex 会被写入什么

$CODEX_HOME/config.tomlAGENTS.mdSkill3 个只读 AgentSessionStartSubagentStart

更新只迁移仍与官方模板字节一致的定义，不覆盖你已修改的 Agent 定义。

如果只想装二进制

.\install.ps1 --skip-config

不自动配置 Agent。更推荐先运行 install --dry-run 获取本机准确路径。

03 · 推荐项目配置：受控自动模式

SAFE DEFAULT

全局运行策略

codebase-memory-mcp config set auto_index false codebase-memory-mcp config set auto_watch true codebase-memory-mcp config set watcher_enabled true codebase-memory-mcp config list

陌生项目不会自动建库；手动索引后由 watcher 保持图谱新鲜。

限制允许索引的根目录

[Environment]::SetEnvironmentVariable( "CBM_ALLOWED_ROOT", "D:\Projects", "User")

重开终端/Codex 后生效；UI 索引接口同样受限。

项目专属扩展名

// repo\.codebase-memory.json { "extra_extensions": { ".mjs": "javascript", ".blade.php": "php" } }

项目配置覆盖全局冲突项；扩展名必须带点。

忽略不该索引的文件：`.cbmignore`

dist/ coverage/ generated/ *.min.js secrets-local/

顺序：内置忽略 → `.gitignore` → `.cbmignore`；符号链接始终跳过。

缓存放到其他磁盘

[Environment]::SetEnvironmentVariable( "CBM_CACHE_DIR", "D:\cbm-cache", "User")

切换前关闭所有 CBM 会话并停止 daemon；同一账户不能同时用两个缓存根。

04 · 第一次索引与状态确认

PROJECT BOOTSTRAP
01

进入仓库

cd "D:\Projects\my-app" codex
02

让 Agent 索引

使用 codebase-memory-mcp 索引当前仓库；返回项目名、模式、文件数、节点数、边数和覆盖缺口。
03

CLI 直接索引

codebase-memory-mcp cli --progress index_repository --repo-path "D:\Projects\my-app"
04

确认项目名

codebase-memory-mcp cli list_projects --format json --detail stats codebase-memory-mcp cli index_status --project my-app

`--project` 使用返回的 name，不要猜。

05 · 六套开发 SOP

DAY-TO-DAY

① 接手陌生项目

索引 → 架构 → 入口/热点 → 关键链路 → 覆盖检查 → 源码确认。

Prompt：用图谱分析模块、入口、路由与三条核心调用链；对引用路径运行覆盖检查，再读关键源码核验。

② 开发新功能

找相似实现 → 调用模式 → 扩展点 → 修改 → 测试 → detect_changes。

Prompt：查找现有同类功能和惯用模式，拟定最小改动方案；完成后分析 git diff 影响半径。

③ 修改核心函数

qualified name → 双向 trace → 测试关系 → 风险分层 → 修改。

Prompt：先不要改代码。追踪 X 的双向调用链（深度 3），列出调用者、下游、接口、测试和高风险影响。

④ 排查 Bug

错误文本 search/rg → 符号 → 调用链 → 源码 → 复现和测试。

Prompt：先定位错误文本，再映射调用链；区分图谱证据、源码证据和运行时推断。

⑤ 重构

架构/热点 → 耦合边 → 死代码候选 → 影响范围 → 小步修改。

Prompt：识别 X 的高耦合节点和边界；负面结论先查索引覆盖，禁止仅凭无调用边认定死代码。

⑥ 提交前审查

刷新索引 → detect_changes → 遗漏测试/调用者 → 测试 → 残余风险。

Prompt：分析当前 git diff 的受影响符号、模块与风险，核对测试覆盖并指出人工验证路径。

06 · 四级暂停 / 禁用索引

DO NOT CONFUSE
目标命令 / 操作仍然可用后果
禁止新项目自动索引config set auto_index false手动索引、watcher、查询默认就是 false
会话不注册 watcherconfig set auto_watch false其他项目 watcher、手动索引后续连接生效；线程仍运行
彻底关闭 watcherconfig set watcher_enabled false
daemon stop		daemon、查询、auto_index、手动索引下一 daemon 启动生效
暂停后台服务daemon stop配置和磁盘索引保留现有客户端可能断开
删除单项目图谱cli delete_project --project NAME软件和其他项目重新使用需再索引
完全移除uninstall源码不受影响移除 owned 集成；索引删除会确认
恢复推荐模式：`auto_index false`、`auto_watch true`、`watcher_enabled true`，执行 `daemon stop`，再重启 Codex。

07 · UI、daemon、更新与卸载

OPERATIONS

打开图谱 UI

codebase-memory-mcp --ui=true --port=9749

访问 http://localhost:9749；UI 由共享 daemon 持有。

管理 daemon

codebase-memory-mcp daemon status codebase-memory-mcp daemon start codebase-memory-mcp daemon stop

修改 daemon 级环境或 watcher 总开关后先 stop。

Windows 更新

codebase-memory-mcp update

只打印应运行的更新命令；复制其输出运行旁边的 `install.ps1`。

卸载

codebase-memory-mcp uninstall

移除 owned 配置、Skill、hooks 和程序；索引另行确认。

11 · 日志、数据与安全边界

FILES & RISK

默认数据位置

缓存：`~/.cache/codebase-memory-mcp/`
运行配置：`_config.db`
UI：`config.json`
daemon：`logs/cbm-daemon.log`
冲突：`daemon-conflicts.ndjson`

永远拒绝的根

盘符/UNC 根、`C:\Windows`、`C:\Users`、`C:\ProgramData`、`C:\Program Files`、用户主目录，以及 `.ssh/.aws/.kube/.docker` 等凭据目录。

安全事实

本地、无遥测，但索引范围内所有可读文件都可能进入图谱。凭据规则是 denylist，不是敏感信息识别器；仍需 `.cbmignore` 与根限制。

12 · 故障决策表

TROUBLESHOOTING
现象原因最小处理
找不到命令PATH 未刷新/安装失败重开 PowerShell；重跑安装；查版本
Codex 看不到工具未重启/未写配置/hook 未信任`install --dry-run` → 安装 → 重启 → `/hooks`
Agent 仍只用 rg规则未加载或未索引确认项目；要求结构问题优先 MCP
索引过期auto_watch/watcher 关闭`config list` → 恢复 → `daemon stop` → 重索引
改总开关无效旧 daemon 未退出`daemon stop` 后重启 Codex
缓存根冲突会话仍占用旧根退出所有 Agent/CLI，stop 后统一环境
secure endpoint 错误Windows 目录 ACL 不安全设置 owner-only 的 `CBM_RUNTIME_DIR`
更新文件占用exe/daemon/Agent 活跃status → 退出持有进程 → 重跑安装器
内存/CPU 高仓库大、worker 多调低 workers/内存预算，查看 daemon 日志
UI 打不开daemon/UI/端口/资产问题查 status/log；换端口；核对安装
