WHAT IT IS

它本质上是 Claude Code 的操作手册 + 组件地图

README 直接把 Claude Code 相关构件拆成一张“概念表”：Subagents、Commands、Skills、Workflows、Hooks、MCP Servers、Plugins、Settings、Memory、Checkpointing、Statusline。价值不在单条技巧，而在于把这些零件放回同一套协作框架。

一句话：这份仓库最适合已经会敲 Claude Code，但总被上下文混乱、盲目提示词、重复返工拖慢的人。
02
WHY IT HELPS

它解决的不是“不会用”，而是“不会稳定地用”

用户常见问题不是没有命令，而是不知道什么时候该切 plan mode、什么时候拆 subagent、怎么用 memory / rules 保持风格一致，怎么让 MCP 与 hooks 真正落地。这个仓库把这些隐性协作规则显式化了。

核心组件关系

  • Skills：可复用任务模块
  • Subagents：把复杂任务拆给专职角色
  • Commands：高频入口与快捷流
  • MCP：接入外部能力与数据面

为什么能减少混乱

  • 把“怎么分工”标准化
  • 把“什么写进 memory/rules”讲清楚
  • 把实际工作流而不是单点提示词放到前面
  • 把常见坑转成可复用清单
03
WORKFLOW

推荐读法：先计划，再拆分，再固化

README 与 Tips 区域传递的主线很明确：不要上来就让模型乱冲，要先 plan，再让 Claude 采访你补全需求，再把垂直切片分给 agent，最后用 review / tests 收口。

STEP 1先看 Concepts，建立 Claude Code 组件地图。
STEP 2用计划模式明确任务，不直接写大段实现。
STEP 3把子任务交给 subagents / skills，不让主对话过载。
STEP 4用 memory、rules、hooks、MCP 把高频经验沉淀下来。
04
PITFALLS

仓库真正有用的地方：把坑点前置

Tips 区明确反对 babysit 式微操，强调先做计划、先让模型自查、先证明方案，再动大改。也强调上下文、session、rules、agents、git/PR、debugging 都有各自的操作纪律。

高频坑

  • 不做 plan 就直接写
  • 把 prompt 当万能药，不建规则层
  • 需求没问清就开工
  • 所有事情都挤在一个上下文里

仓库给的对策

  • 从 plan mode 起步
  • 用 AskUserQuestion 补需求
  • 用 subagents 降低上下文污染
  • 把常用约束沉到 CLAUDE.md / rules / memory
05
BOTTOM LINE

适合谁：复杂项目、多角色协作、想把 Claude Code 用成工程系统的人

如果你只是偶尔让 Claude 改两行代码，这个仓库会显得重；但如果你在做多文件开发、需要子代理分工、想让 Claude Code 逐渐“记住团队做事方式”，它能直接省掉大量试错成本。
