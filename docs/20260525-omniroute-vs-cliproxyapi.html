OmniRoute 独有核心能力（6 项）
1. 🚀 Combo 智能路由链
将多个 Provider 串联成 4 层 fallback 链（订阅→API→廉价→免费），quota 用尽 / 失败 / 成本飙升时自动无缝切换，真正实现"永不停机"。CLIProxyAPI 的轮询是平等轮转，不区分优先级。
2. 💸 RTK + Caveman Token 压缩
双重压缩叠加，工具调用场景节省 78-95% Token。代码块/URL/JSON 始终保护不压缩，输入 prompt 无损压缩后传给模型。对免费额度用户价值极高，相当于免费 Token 量翻 5-20 倍。
3. 🧩 MCP / A2A Agent 原生协议
OmniRoute 本身即是 MCP Server（37 工具）和 A2A Server（5 skills）。Claude Desktop / Cursor 可直接控制 OmniRoute 本身。它不仅是网关，更是可编程的 AI 基础设施。
4. 🌍 地域封锁全面绕过
3 层代理（Global / Per-Provider / Per-Connection）+ 1proxy 免费代理市场 + TLS 指纹伪装。SOCKS5 支持。在受限 / 封锁地区仍可访问全部 177 Provider。
5. 📊 可观测性与安全
内置 Evals golden-set 评测、Guardrails（PII/注入/视觉）、3 层 Circuit Breaker、p50/p95/p99 延迟遥测、Webhook + 合规审计。生产级可靠性。
6. 📱 多平台 + i18n
支持 npm / Docker / Electron 桌面 / Termux(手机) / PWA / Arch AUR。界面支持 40+ 语言。CLI 命令 60+ 个，完整 TUI 交互。
升级 / 迁移代价评估
⚠️ 重要信号
CLIProxyAPI 官方 README 已将 OmniRoute 列为"更多选择"之一，说明开发者认可 OmniRoute 的技术路线。但两个项目生态和技术栈完全不同，迁移并非无代价。
技术栈切换
  • CLIProxyAPI = Go 编译
  • OmniRoute = Node.js (npm)
  • 需准备新的运行时环境
  • Go 在高并发下通常更轻量
配置不兼容
  • OmniRoute 有独立配置格式
  • 不提供直接迁移脚本
  • Provider 账号需重新配置
  • OAuth 授权需重新完成
生态锁定成本
  • CLIProxyAPI 有 16+ 衍生项目
  • CPA-Manager / Dashboard 等生态绑定
  • OmniRoute 生态相对较新
  • 中文社区 QQ/TG 群在 CLIProxyAPI
学习成本
  • OmniRoute 功能更复杂
  • Combo / Compression / MCP / A2A
  • 4 层 fallback 策略需理解
  • IDE 端配置改动极小（OpenAI API 兼容）
面向开发者选型决策树
✅ 选 OmniRoute 如果
  • 需要最大化免费 Provider 利用率（Token 压缩 + 50+ 免费）
  • 需要智能 Combo / 4 层 fallback（不想手动管理多账号）
  • 使用 Claude Desktop / Cursor 等 MCP 客户端
  • 在受限 / 封锁地区使用 AI
  • 需要可编程 AI 网关（A2A 协议驱动）
  • 追求 Token 压缩延长免费额度的重度用户
  • 愿意切换到 Node.js 运行时
✅ 选 CLIProxyAPI 如果
  • 已有稳定配置，不想折腾迁移
  • 深度依赖 Go 生态 / 二次开发
  • 主要使用 Claude Code / Codex / Gemini CLI OAuth 订阅
  • 需要更强的中文社区支持（QQ 群 / 中文 README）
  • 追求 Go 运行时的高性能低内存
  • 不想学习新概念（Combo/Compression/MCP/A2A）
  • 使用 CPA-Manager / CPA-XXX 等管理面板
一句话总结
OmniRoute
不只是 API 兼容层，而是智能路由平台。177 Provider + Token 压缩 + Combo 自动 fallback + MCP/A2A = 全功能 AI 网关，适合追求最大化利用率和自动化的高级用户。
CLIProxyAPI
经典的OAuth 封装代理。稳定可靠、社区活跃、Go 高性能。适合已有配置、主要通过 OAuth 使用 Claude Code / Codex / Gemini、需要中文支持的开发者。
