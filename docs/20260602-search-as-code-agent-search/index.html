01

一句话结论

Search as Code 不是“更好的搜索 API”，而是把搜索拆成 primitives，让模型用 Python 编排检索、排序、过滤、去重、抽取、验证与状态管理。
02

传统搜索为什么不够

query → results 太粗

人类浏览链接够用；Agent 需要拆问题、并行检索、筛来源、抽取、验证、回填。

上下文污染

黑盒 pipeline 把中间结果塞进上下文，token 贵、延迟高、推理质量下降。

03

SaC 三层架构

Model 控制平面理解任务、生成策略、写代码。
Sandbox 执行环境安全执行 Python，管理并发、重试、缓存、状态与文件。
Search SDK 能力层提供检索、排序、过滤、fan-out、去重、抽取、验证等 primitives。
04

CVE 案例为什么重要

帖子强调 Perplexity 的 CVE 案例：找 2023–2025 年 200+ 高危 CVE，引用厂商官方 advisory，并证明修复版本和 CVE 绑定。SaC 生成的是程序化证据链。

模型负责策略；代码负责确定性执行；搜索基础设施负责外部信息 I/O。
05

价值与挑战

价值

复杂研究、多源证据、长链路任务更可控；减少无效 token、降低延迟与噪声。

挑战

模型代码能力、SDK 设计、沙箱安全、状态可观测性、外部 benchmark 复现都是门槛。
