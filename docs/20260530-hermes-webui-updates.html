Hermes 最近 7 天能力更新：桌面端、模型选择器、网关路由、TUI 稳定性
核心摘要：origin/main 在最近 7 天里没有只做单点修补，而是同时推进了 桌面应用落地、模型选择器分组与描述升级、网关/平台路由修复、TUI 与 CLI 体验抛光，外加一批把系统“变得更稳、更不容易坏”的硬化改动。
调查窗口：2026-05-26 → 2026-06-02 · 当前发布时间：2026-06-02 07:22 CST
调查结论
结论：这 7 天的更新重点不是“又修了几个 bug”，而是把 Hermes 往可安装、可选型、可路由、可持续运行的方向推了一步。
看法：最显眼的变化来自桌面端与模型选择器；最实际的体验提升来自 TUI/CLI 与网关路由；最重要的底层收益则是大量 fail-closed、原子写、路径校验、缓存与权限加固。
边界：下面把“用户能感知的能力变化”和“主要是稳定性/安全硬化”的内容分开写，避免把修补都误读成新功能。
7 天内最值得关注的 5 类变化

1. 桌面端正式成形：安装、首启、自更新开始成体系

这段时间里最像“新能力”的，是 Hermes Desktop 相关提交开始成组出现。

  • 桌面应用落地：Add Hermes desktop app 说明桌面端不再只是概念或分支，而是正式进入发布链路。
  • 安装链路更清晰：fix(install): build desktop in 'desktop' stage，把桌面构建从“悄悄跳过”改成明确执行，避免装了却没有桌面产物。
  • 会话信息更完整：desktop_contract 被写进 lazy session.create 信息，桌面端对会话能力的自描述更明确。
  • 自更新更可信：track main for self-update now that GUI merged，说明 GUI 合并后自更新路径开始跟随主线。
  • 启动体验补强：thin out setup — Quick Setup via Nous Portal + Full Setup defaults，把首次配置拆成快速路径与完整默认路径，降低上手门槛。

代表提交：51c68d4ab、fa4ebaa8b、77bb64813、3ef97a61b、de4f40ed0

2. 模型选择器不再只是列表：开始按“分组 + 描述 + 直觉选择”工作

这周 model picker 的变化非常集中，方向很明确：让用户更快判断“选哪一组、再选哪一个”。

  • 分组层有描述：description on group layer, plain labels on members，组级别开始承载解释信息，成员只保留简洁标签。
  • 组内成员有短描述：show short description on grouped provider rows，把差异点直接暴露在 picker 内，而不是让用户离开界面再查。
  • Provider 文案刷新：refresh provider picker descriptions，说明选择器文案本身在持续校准。
  • 多端点提供者合并：group multi-endpoint providers under one row，减少视觉噪音，让同一供应商的多个入口看起来像一个能力族。
  • 模型目录更鲜活：refresh model catalog hourly instead of daily，模型列表更新频率从日级提升到小时级，更适合快速变化的模型生态。

代表提交：93e6a05ef、84d82453a、c9a28dfb0、47d2d0589、e1293bde4

3. 网关与平台路由补强：消息、主题、延迟与错误处理更稳

这一组改动对用户最直接的意义是：平台消息不容易丢，路由 metadata 不容易丢，失败时更少“默默坏掉”。

  • Telegram DM topic 元数据保留：preserve Telegram DM topic routing metadata in synthetic notifications，避免 topic 语义在转发/通知环节丢失。
  • DM topic 解析修复：resolve _get_dm_topic_info on adapter class, not instance，路由逻辑更一致。
  • 中止命令更可靠：/stop can interrupt a sibling participant's run，多参与者线程里停止指令的作用范围变清楚。
  • WhatsApp / Weixin 批量节流：add text debounce batching，减少短消息高频刷屏与调用压力。
  • 邮件目标更直观：recognize email addresses as explicit targets，把邮箱地址直接当目标，减少歧义。
  • 网络抖动时别乱停：never auto-pause platforms on transient network/DNS failures，提高平台侧连续性。

代表提交：4259bab7d、eb3cf9750、1044d9f25、b0ce47daa、d3724c0be、45465b0d5

4. CLI / TUI 不只是“修 bug”：而是在把使用体验变成可控系统

这部分改动很像“骨架+手感”一起修：会更好用，也更不容易被边缘环境击穿。

  • 终端 cwd 保持真实：preserve live session cwd in terminal_tool，避免终端工具的工作目录和会话状态不同步。
  • 模型/提供者选择器迁移到 curses：把 setup 里的 picker 从 simple_term_menu 换掉，键盘输入与箭头键处理更稳。
  • Prompt 大小诊断：add hermes prompt-size diagnostic，用户能更容易知道自己输入到底有多大。
  • TUI 在窄屏/抖动场景更稳：修复 bogus terminal dimensions、吞掉鼠标 burst 噪音、避免启动卡死、让视口重绘不再制造空白块。
  • 声音能力更实用：allow /voice over SSH when a sound server is reachable，语音功能从本地可用扩展到 SSH 场景可用。
  • 调试提示更可见：surface /agents nudge while delegate_task is in-flight，代理任务在跑时，界面会更及时提示用户。

代表提交：7a315bd70、087be0073、61268ff7a、b1d34cf6e、cd067ab91、d4e7b2fc1、9d2571c86

5. 安全与稳定性硬化：大量改动不是“新功能”，但直接提升可靠性

这类更新不一定会被用户一眼看见，但它们决定 Hermes 能不能长期跑、会不会在奇怪环境里翻车。

  • 路径与媒体安全：denylist config.yaml for media delivery、anchor relative-path resolution to absolute base、support Windows absolute paths in MEDIA tag regex，路径处理更严格。
  • 原子写与文件处理：make write_file/patch atomic、handle UTF-8 BOM in read_file / write_file / patch，减少写入中断和编码异常。
  • 更早失败：fail fast on non-retryable image download errors、fail closed on empty oneshot responses，错误不再悄悄吞掉。
  • 权限与密钥防线：restrict sensitive store file permissions、validate verification token、use 403 not 500 for missing-secret rejection，把安全失败变成明确拒绝。
  • 守卫与日志更准确：emit guardrail halt message to client before closing stream、stop duplicating tool-call args，帮助客户端正确感知中止原因。

代表提交：4ec0adebe、96643b4a5、51d165a8e、39f6b6e9f、5f84c9144、b4cf114f6、f378f00bf、15aa6884a、38b8d0da8

证据链与边界
✅ 直接可见的能力变化
桌面端开始真正进入发布链路，不再只是概念。
模型选择器从“纯列表”升级成“分组 + 描述 + 简化标签”的决策界面。
TUI / CLI 在输入、视口、cwd、提示与 voice 可用性上都明显更成熟。

原子写、路径校验、权限收紧、fail-closed、重试边界，这些多半不是新卖点，但会显著降低故障率。
很多 commit 是“让系统别坏”，不是“让界面多一个按钮”。
所以这 7 天的总体结论是：能力在扩，稳定性也在补，两条线是一起走的。
