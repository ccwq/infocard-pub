  • 跳转定义
  • 引用 / references
  • 悬停 / hover
  • 代码 action
  • 重命名 / rename
  • 诊断 / diagnostics
  • 自动补全 / autocompletion
LSP 体验

把“终端编辑器”推近“完整 IDE”

用户不必记一堆插件拼装方式，常见 LSP 能力默认可用，目的是让语言理解、代码修复和导航成为编辑器的一部分，而不是额外工作流。

它适合日常写代码、快速查错、批量重构，也适合在远程终端环境里保留相对完整的开发体验。

06QuickJS 沙箱插件说明

插件怎么跑

Fresh 的扩展采用 TypeScript plugins，运行在 QuickJS sandbox 中。含义很直接：插件有脚本能力，但默认不直接接触宿主进程的全权上下文，扩展边界更克制。

README 里列出的可扩展方向包括 color highlighter、TODO highlighter、merge conflicts、path complete、keymaps 等，说明它偏向“围绕编辑器行为做轻量自动化”。

适合什么，不适合什么

  • 适合：编辑器内的高亮、规则、快捷动作、局部工作流自动化。
  • 适合：想保留一定隔离度，避免插件把主进程直接拖垮。
  • 不适合：把重型后台服务硬塞进插件沙箱。
  • 如果要做更重的系统级集成，最好还是外部工具 + 编辑器接口协作。
07Fresh 0.4.3 · 默认快捷键参考

完整收录官方 default.json 的 263 条绑定。同一个键在不同位置可能执行不同动作。默认先显示常用项，可切换完整清单。其他版本和自定义键位不在此表范围。

先分清两个搜索：F3／Shift+F3 导航普通搜索；Alt+N／Alt+P 对应选中文本匹配，运行时也能在已确认搜索结果间前后移动。Ctrl+R 打开替换；Ctrl+H 向后删除一个词，不是替换。
点号文件在哪打开？侧边文件面板：先用 Ctrl+E 聚焦侧栏，再按 Alt+X 打开 Explorer 菜单，选择 Show Hidden Files。该开关会持久化 file_explorer.show_hidden 设置。点号隐藏与 Git 忽略是独立过滤；同时被 Git 忽略的文件，还须开启 Show Gitignored Files。该菜单项在本机0.4.3运行中存在，菜单未显示快捷键；默认 JSON 没有 file_explorer_toggle_hidden 绑定。打开文件对话框：Alt+. 对应 file_browser_toggle_hidden。Ctrl+I 是 Git 忽略文件开关，不能当作点号隐藏文件开关。

08场景化配置方式
纯 SSH 远程编辑

通过 SSH 连接到远程服务器时，建议在 ~/.config/fresh/init.ts 中关闭鼠标和内联诊断以减少延迟：

// init.ts if (editor.getEnv("SSH_TTY")) { editor.setSetting("editor.diagnostics_inline_text", false); editor.setSetting("terminal.mouse", false); }
多项目并行

Fresh 自动加载 ~/.config/fresh/config.json 作为全局配置；项目级覆盖通过 FRESH_PROFILE 环境变量实现：

# .zshrc / .bashrc export FRESH_PROFILE=writing # 写作模式：自动换行 80 列 export FRESH_PROFILE=coding # 编码模式：全功能 LSP

在 init.ts 中读取并应用：

if (editor.getEnv("FRESH_PROFILE") === "writing") { editor.setSetting("editor.line_wrap", true); editor.setSetting("editor.wrap_column", 80); }
特殊文件编辑

JSON / YAML 等结构化文件可配置自动格式化并关闭侵入式 LSP 诊断：

// init.ts — 检测文件类型并应用规则 editor.on("buffer_opened", (buf) => { if (buf.name.endsWith(".json")) { editor.setSetting("editor.trim_trailing_whitespace", true); } }
大文件（GB 级）

Fresh 的核心优势之一：大文件无预加载、按需渲染。无需额外配置，但建议关闭语法高亮和 LSP 以获得最佳性能：

// init.ts if (editor.getEnv("LARGE_FILE")) { editor.setSetting("editor.syntax_highlight", false); editor.setSetting("lsp.enabled", false); }
配置层级总结：~/.config/fresh/config.json → 全局静态偏好 → init.ts → 启动时环境检测覆盖 → 命令面板 / 设置 UI → 运行时覆盖（临时）
09设置同步方式

Fresh 的配置集中在 ~/.config/fresh/ 目录。多机器同步只需同步该目录中与机器无关的文件：

✅ 同步
config.json（主题、键位、Tab 大小等）
init.ts（启动脚本）
themes/（自定义主题）
plugins/（插件源码）
🚫 不同步
logs/（运行时日志）
cache/（LSP 缓存）
sessions/（会话状态）
plugins/packages/（可通过插件管理器重新安装）
Git Dotfiles
将 ~/.config/fresh/ 软链接到 Git 仓库
ln -s ~/dotfiles/fresh ~/.config/fresh # dotfiles 仓库推送后，其他机器 clone 并重建软链接即可
Rsync / Syncthing
实时单向同步，适合不想把配置纳入 Git 的场景
rsync -av --exclude='logs/' --exclude='cache/' ~/.config/fresh/ user@remote:~/.config/fresh/
GitHub Gist
将 config.json 和 init.ts 保存为私密 Gist，多设备手动拉取更新
机器特定 Keymap
macOS 有专用 keymap（见快捷键节），其他平台用默认 keymap。将 "keymap": "macos" 写入 config.json，跨平台时在 init.ts 中用 getEnv("OSTYPE") 条件切换。

11Keymap 自定义与下载维护
内置 keymap：Fresh 默认使用 default keymap；macOS 推荐切换到 macos keymap（在 config.json 中写入 "keymap": "macos"）。切换后 Ctrl+Shift 组合被替换为 Ctrl+Alt，Unix readline 传统（Ctrl+Y 粘贴、Ctrl+K 剪切行尾）被保留。

交互式键位编辑器

打开 Edit → Keybinding Editor，或 Ctrl+P 输入 > 后搜索 Keybinding Editor。这里查看实际启用绑定、动作、上下文和来源；用户配置会覆盖默认keymap。

按 / 搜索文字，r 录制按键，c 筛选上下文，s 筛选来源。Enter 编辑，a 新增，Ctrl+S 保存。以上编辑器内部操作来自官方说明；本次未逐一运行。

正确的覆盖格式

{
  "keymap": "default",
  "keybindings": [
    {"key": "s", "modifiers": ["ctrl"], "action": "save", "when": "normal"}
  ]
}

keybindings 是数组，不是旧卡的“ctrl-s → editor.save”对象。动作名使用真实标识。修改前备份用户配置。官方内置键位位于 crates/fresh-editor/keymaps/；不把未核验的 init.ts 钩子或目录建议当作现成接口。

12README 预览

Quick install + huge file + IDE workflow

Fresh 的整体定位非常清晰：先把“写代码时最常碰到的动作”做成默认能力，再把大文件性能、鼠标、菜单、LSP 和插件扩展连接起来。它不是在终端里复刻一套古典模式，而是把终端编辑器向现代 IDE 的体感靠拢。

如果你想要的是“我坐下来就能改代码”，它是这类工具里很典型的答案。
