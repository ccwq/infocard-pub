01

30 秒接入：先初始化，再让 agent 连接

# 为一个或多个已支持 agent 完成无人值守初始化与 MCP 写入 npx wigolo init --agents=claude-code,codex # 检查组件与本地环境 npx wigolo doctor # 未在内置列表中的 MCP 客户端：先只装本地引擎 npx wigolo init # 然后把 MCP 命令设为：npx wigolo mcp
初始化的取舍：init 默认下载浏览器引擎和设备端模型、做健康检查；加 --no-warmup 可延后下载，组件会在首次使用时按需加载。README 说明组件下载失败不会阻断 MCP 接线，输出会标出未就绪组件与修复提示。
02

支持哪些 agent？

内置 --agents 安装器

可逗号分隔指定：

claude-code · cursor · codex · gemini-cli · vscode · windsurf · zed · antigravity

其他 MCP 客户端

可省略 --agents 完成引擎设置，再手工登记 MCP。源码注释表明 wigolo mcp 走 stdio；README 也说明不带子命令时默认启动 MCP stdio server。

通用 MCP JSON 示例

{ "mcpServers": { "wigolo": { "command": "npx", "args": ["-y", "wigolo"] } } }

注意：不同客户端的配置路径和键名并不相同；例如 VS Code 使用 servers，Zed 使用 context_servers，Codex 使用 TOML。以官方 README 的“Manual MCP setup”表格为准。

03

MCP 工具面：一次接入的能力边界

工具用途（官方命名 / 源码注册）使用提示
search网页搜索；可用于答案式输出的上游检索。核心工具无需 API key；答案合成属于可选 LLM 能力。
fetch获取单个网页内容。适合给 agent 提供指定 URL 的内容。
crawl抓取 / 爬取 URL 集合。远程内容仍是不可信输入，应按你的 agent 策略审阅。
extract内容提取。与 fetch、crawl 组合处理网页资料。
cache本地缓存操作。README 将缓存列为本地 Web 工作流的一部分。
find_similar查找相似内容。核心无需 API key。
research / agent研究与自治收集循环。若要让它们撰写最终答案，须配置可选 LLM provider 与相应 key。
diff / watch内容差异与监视。watch/webhook 是安全策略特别关注的可选子系统。
04

配置：默认本地，合成能力按需开启

无需 key 的核心

官方 README 将 search、fetch、crawl、extract、cache、find_similar 列为无需 API key 的核心能力。

可选 LLM 合成

research、agent 与 search format=answer 会用 LLM 写最终答案。需在 shell 或 MCP 的 env 中设置 WIGOLO_LLM_PROVIDER 及对应 provider key；不要把密钥写进公开配置或仓库。

配置与移除

用 npx wigolo doctor 先诊断。若不再使用，官方给出的清理命令是 npx wigolo config --uninstall --yes。

公开 HTTP 服务是另一模式

若使用 serve 并绑定非 loopback 地址，官方文档要求配置 token；生产加固建议用 WIGOLO_API_TOKEN_FILE，避免 token 出现在进程环境中。

05

隐私 · 网络 · 安全：知道本地不等于零风险

本地优先声明

README 表述核心工具无需 key，且“它触及的内容”保留在 ~/.wigolo/。这描述的是其本地数据处理定位；当你主动抓取 URL 或配置外部 LLM 时，仍会发生相应网络请求。

远程内容与 SSRF

SECURITY.md 点名：watch/webhook 的 SSRF 与 URL 校验、可选云 LLM key 的凭据处理、以及抓取/爬取远程内容影响主机的路径，都是报告重点。

源码可核查的服务防护

在非 loopback 绑定的 serve 模式，源码会拒绝以 localhost、127.x.x.x、::1 等 literal loopback 为目标，除非显式设置 WIGOLO_SERVE_ALLOW_LOCAL_TARGETS=1。源码注释明确：这不是 DNS rebinding 覆盖声明。

漏洞报告

不要公开开 issue。官方要求通过仓库 Security 页的 Report a vulnerability 私下提交；public beta 期间安全修复面向最新已发布版本。

06

排错清单：先看本机状态，再缩小变量

① 初始化或组件未就绪

  • 确认 Node ≥ 20、可用磁盘约 1.5 GB。
  • 执行 npx wigolo doctor。
  • 检查初始化输出的具体组件提示；网络受限 / 离线时可用 --no-warmup 延后下载。

② Agent 看不到工具

  • 确认 agent 在官方支持列表，或按手工 MCP 配置接入。
  • 检查命令为 npx wigolo mcp；README 同时说明默认无子命令即 MCP stdio。
  • 核对客户端特有配置键与文件位置。

③ 研究 / 答案合成不可用

  • 核心检索不需要 key；不要误把它与合成能力混淆。
  • 需要最终答案合成时，检查 WIGOLO_LLM_PROVIDER 与对应 key 是否仅在私有环境变量中提供。

④ serve 或 watch 的安全问题

  • 非 loopback 监听时配置强随机 token；优先 token 文件方式。
  • 不要为图省事放宽本地目标或私网访问策略；只有理解风险时才调整相关环境变量。
  • 疑似漏洞走私密 Security Advisory，而非公开 issue。
