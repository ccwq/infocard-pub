这条帖的要点不是“万能爬虫”，而是分层能力栈。

它把公开调研、社媒抓取、批量 scraping、登录页处理、真实浏览器操作和全自动流程，拆成不同层级的工具选择。真正有价值的是“用最轻的一层先完成任务”，而不是一上来就自动化到底。

01
Core claim

它在主张什么：一套够用的 Claude Code 网络访问技能包

这张海报并不是单纯展示功能清单，而是在建立一个分层操作系统：先用最轻的能力拿到结果，只有在公开资料不够、登录态必要、或者需要复杂流程时，才往更重的层级走。

lightresearch

先调研，再决定要不要进入抓取层

Deep Research 代表的是多源公开资料的整合能力。它优先解决“先把事实摸清楚”的问题，不把浏览器当默认起点。

  • 适合公开资料、背景调查、主题扫描
  • 目标是把问题定义准，而不是先跑工具
socialreach

Agent Reach 把社媒当成单独抓取层

这里的意思不是“去抓所有网页”，而是面向小红书、X、抖音、YouTube、公众号、Reddit 等社媒平台做可达性处理。

  • 把平台差异显式化
  • 先解决入口，再谈采样与聚合
heavyautomation

最重的是自动化，不是默认起点

Web Access 的位置在最底层：它是流程自动化和复杂认证的手段，只有在前面的层级都不够用时才上。

  • 自动访问适合复杂流程和任务编排
  • 不应该成为所有问题的默认答案
02
Six-layer stack

6 个 Skill 怎么分工：从公开信息到真实浏览器，再到自动化

这张图最有信息量的部分，是把“抓数据”拆成了六个决策层。每一层对应不同的输入条件、风控成本和执行方式，顺序本身就是方法论。

01

Deep Research

多源调研 / 公开资料。先在公开世界里查清楚、汇总好，再决定下一步，是最轻的一层。

02

Agent Reach

社媒抓取 / 13+ 平台。它不是泛化爬虫，而是面向社交平台的可达性与数据获取层。

03

Scraping

批量抓取 / 突破反爬。真正进入采集层时才碰反爬、批量化、结构化抓取这些问题。

04

Browser View

登录页面 / Cookie 隔离。需要登录态时再引入受控浏览器视图，而不是把登录页当通用入口。

05

Chrome

真实浏览器 / 人工操作。这里强调的是真人环境的操作一致性，用于需要手工介入的复杂步骤。

06

Web Access

自动访问 / 流程自动化。它负责把前面的步骤串起来，做完整工作流，而不是替代前面所有层级。

03
Workflow

执行顺序不是装饰：Search → Social → Scrape → Login → Automate

底栏的五段流程实际上就是一条从轻到重的选择树。它告诉你，任务应该先在哪层解决，什么时候才值得升级工具。

01 SEARCHresearch

搜公开资料，先把问题缩小

这一步只做公开信息上的调研和定位，不要求登入、不要求自动化。它是所有后续动作的地基。

02 SOCIALmultiplatform

扒社媒，多平台分流

当数据散落在社媒平台时，先用 Agent Reach 处理入口差异，再决定是否需要进一步抓取。

03 SCRAPEscale

批量抓数据，才进入反爬对抗

这一步是数据规模化的入口，意味着你已经不满足于手工浏览，而是要做系统性采集。

04 LOGINcookie

登录后的页面，用 Cookie 隔离处理

这一层把身份与会话分离出来，避免把需要登录的页面和公开页面混在一起处理。

05 AUTOMATEorchestration

最后才自动化，把流程串起来

自动化是工作流编排，不是所有问题的第一步。只有当前面的层级都不足以解决任务，才升级到这一层。

“从轻到重，够用就停，能不开浏览器就别开。”
这句话就是整张海报的操作原则。
04
Case takeaway

这条案例对实际使用有什么价值

它的价值不在“工具很多”，而在于把工具的边界说清楚。对实际操作来说，这能减少误用：先调研、后社媒、再抓取、再登录、最后才自动化。

适合公开调研

适合什么场景

新闻核查、竞品扫描、社媒信号汇总、页面抓取、登录态页面处理、知识库沉淀，都能找到对应层级。

边界not universal

不适合什么场景

它不是“万能浏览器替代品”。如果问题能用公开资料、摘要或最轻的一层解决，就不该直接上重工具。
