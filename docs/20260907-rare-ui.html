01 · WHAT IT IS

它是什么：一份可以装进项目的动效参考库

核心机制：registry 直装源码

Rare UI 按 shadcn 官方 registry 规范发布（registry.json 符合 ui.shadcn.com schema）。每个组件是一个独立的 .tsx 文件，用官方 shadcn CLI 一条命令装进项目：CLI 把源码写进 components/ui/，把依赖装进你的 package.json。没有中心化 npm 包，代码完全归你，想改就改。

为什么适合"给 AI 当参考"

抽象描述"要一个有弹性的动画"AI 只能猜；把一个具体组件源码丢给 AI，触发条件、时长、缓动曲线、状态切换全部可读。Rare UI 的组件都按真实交互场景组织（文件夹展开、删除二次确认、验证码输入、AI 图加载占位），天然是高质量参考样本。

质量基线

  • 全部组件用 Motion 做动画，统一尊重系统的 prefers-reduced-motion 降级；
  • TypeScript 编写，props 带默认值注释（如 FluidOrb 的 size 默认 240、color 默认 #1A73F2）；
  • MIT 许可（Copyright 2026 Swami Malode），可商用、可改、可再分发；
  • 仓库 2026-06 创建，项目较新，具体 props 与行为以组件页和源码为准。
核心原则：给 AI 具体参考，不给抽象描述。一个可读的组件源码胜过十句"要一个有弹性的动画"。
02 · PREREQUISITES

准备工作：先把地基打好

运行环境Node.js（建议 20+）+ 包管理器 npm/pnpm
项目要求已配置 shadcn/ui 的 React 项目（官方栈是 Next.js + Tailwind + TS）
还没有项目用下面的 init 命令从零建一个
npx shadcn@latest init

init 做了什么：创建或初始化项目、生成 components.json 配置、建立 @/lib/utils 路径别名（cn 工具：clsx + tailwind-merge）。Rare UI 所有组件都依赖这个 cn 工具，CLI 安装组件时会自动带上 utils——前提是项目已初始化。

03 · INSTALL SOP

三步装进项目（核心流程）

1

按场景挑组件

打开 rareui.com/components，按 6 个分类浏览实时预览：导航类（Bounce / Hook / Proximity Sidebar、Gooey Nav、Scroll Progress）、输入类（Duration Picker、OTP Input、Delete Button）、反馈类（Emoji Reaction、Notification Bell）、展示类（Folder、Code Block、Gravity Letters、GitHub Activity、Step Player）、AI kit（Fluid Orb、Grid Reveal）。

2

一条命令安装

npx shadcn@latest add swamimalode07/rare-ui/fluid-orb

CLI 自动完成三件事：源码落入 components/ui/fluid-orb.tsx；公共依赖 utils（cn 工具）自动补齐；组件声明的 dependencies（如 motion）自动 npm install。无需手动装依赖。

3

导入并渲染

import FluidOrb from "@/components/ui/fluid-orb";

export default function Hero() {
  return <FluidOrb size={320} color="#15803d" />;
}

多数组件是默认导出；部分组件同时提供具名导出，如 DeleteButton：

import { DeleteButton } from "@/components/ui/delete-button";

<DeleteButton
  onConfirm={() => removeItem(id)}
  onCancel={() => restoreItem(id)}
/>

04 · AI WORKFLOW

先按交互场景找原型：给 AI 的参考工作流

场景地图先行

Rare UI 的价值在于提供"类似这个交互"的具体参考，让 AI 读取触发条件、动效结构和反馈节奏，而不是只给一句抽象需求。先明确你的场景（导航切换？删除确认？AI 图加载？），再从对应分类挑最接近的组件。

参考回路：复制不是终点

组件页 → registry → 产品语义 → 可访问性。接入后要删除不必要的装饰、补键盘与 reduced-motion 行为，并检查低端设备上的动画性能。所有组件已内置 prefers-reduced-motion 处理，你的业务改造不应破坏它。

第 1 步把装好的 .tsx 源码直接给 AI："参考这个文件的动效结构"
第 2 步让 AI 按业务语言重构：触发条件、时长、缓动、状态机
第 3 步删除不需要的装饰，保留动画骨架
第 4 步降级验收：键盘操作、reduced-motion、移动端性能
05 · TROUBLESHOOTING

新手常见坑与排查

现象原因处理
add 命令报组件不存在用了展示名registry 名与展示名不同，用上表 registry 名（folder-component 而非 Folder）
报 @/lib/utils 不存在项目未初始化 shadcn先跑 npx shadcn@latest init，再装组件
装完样式错乱组件按 Tailwind 类编写确认项目已配置 Tailwind（官方站用 v4）；检查类名是否被自己的 CSS 重置覆盖
Fluid Orb / Gravity Letters 不动WebGL 不可用，或系统开了"减少动态"换支持 WebGL 的浏览器；reduced-motion 下 Fluid Orb 冻结在初始帧，这是内置降级不是 bug
想统一升级组件源码已拷进项目，没有中心包diff 上游仓库 components/ui/ 手动对齐；升级不是自动的，这是"代码归你"的代价
家族抽屉类组件装完报错缺 vaul 等三方库重跑 add 命令让 CLI 补装 dependencies；别只复制 tsx 文件不装依赖
06 · LOCAL DEV & BOUNDARY

本地跑官方站 / 适合与边界

想改组件或贡献？本地跑起来

git clone https://github.com/swamimalode07/rare-ui.git
cd rare-ui && npm install && npm run dev

组件在 components/ui/。改了组件或 registry.json 后，用 npm run registry:build 重建 registry 输出。贡献流程见仓库 CONTRIBUTING.md，Issues 和 PR 均欢迎。

✓ 适合

  • 给 AI 具体动效参考，替代抽象描述
  • 需要现成交互原型快速起步的 React 项目
  • 想完全拥有组件源码、深度改造的团队
  • 重视 reduced-motion 可访问性的产品

✗ 不适合

  • 想要 npm 包统一版本管理的团队（源码拷贝，升级手动）
  • 想要 100+ 组件大而全的（那是 rareui.in，另一个项目）
  • 非 React 技术栈（Vue/Svelte 需自行移植）
  • 不能接受 Tailwind 依赖的项目
