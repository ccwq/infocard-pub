§ 01 — 声明树结构

四层结构，把计划压成一棵可扫描的树

运行 /html-plan 后产出自包含单文件 HTML，把整个计划组织成「声明树」——每一层有明确语义，读者按需展开，不需要线性读完。

ROOT

标题 · Title

这是什么（短名）+ 作者自己的解释一句话

L1

用户届时能做什么 / 看到什么

UI 草图或状态机——成果物的直观描述，读者一看就知道上线后是什么

L2

如何实现

调用栈、数据 schema、关键代码片段——工程师能评估复杂度和风险

L3

代码在哪里

具体代码位置（文件路径、行号区间）src/handlers/auth.ts:42-78

§ 02 — 三个核心设计

不只是展示，是完整的反馈闭环

html-plan 的交互设计解决了「计划写了没人看」的根因：信息密度、决策定位、反馈门槛，三个问题同时解决。

1

渐进披露 Progressive Disclosure

折叠态即摘要——页面初始只展示高层结构（L0/L1），按需一层层展开。读者不需要线性读完所有细节，只需沿着自己的问题导航。

Collapse to summarize · 按需展开
2

编号决策点 Decision Points

页面底部有按钮，逐个跳转到未决项。每一项都有编号，审阅者可以直接说「我对第 3 项有意见」，不必复述上下文。

Numbered anchors · 精准定位反馈
3

原地反馈闭环 In-place Feedback

直接在页面上选选项、改 schema、对某行代码写评论。完成后一键生成整合答复，粘回 Claude Code 继续对话——不需要切换窗口。

Inline comment · one-click export

§ 04 — 使用流程与纪律

反馈回来之前，不准开工

html-plan 不只是工具，更是工作纪律的强制执行机制。它的核心约定：计划未经审阅，不得开始构建。

标准流程

  1. 发起计划：运行 /html-plan，Claude Code 生成声明树 HTML
  2. 审阅计划：打开 HTML，按需展开各层，定位关注点
  3. 编号反馈：对第 N 项写评论 / 选选项 / 改 schema
  4. 导出答复：一键生成整合反馈，粘回 Claude Code
  5. Claude 修订：收到反馈后更新声明树，双方对齐后再开工

安装方式

  1. 添加插件市场：claude plugin marketplace add anthropics/claude-plugins-community
  2. 安装插件：claude plugin install html-plan@claude-community
  3. 使用：在对话中运行 /html-plan
⚠

核心纪律

Do not start building until that response arrives——反馈回来前不准开工。

「反馈闭环」比「写得快」更重要。
§ 05 — 边界与同类

官方插件 ≠ 同名独立实现

GitHub 上有另一个同名项目，两者不是同一回事。注意区分，避免安装错误版本。

OFFICIAL anthropic/claude-plugins-community

本文介绍版本。Anthropic 社区插件市场（4542 stars），每夜从内部审核管道同步，所有插件经过安全扫描。作者 Thariq（Claude Code 团队），计划文档专用，技能写法为「手写 HTML + 小运行时」。

OTHER noonsleeping/Linkc-Chen / linkc-skills

GitHub 上的独立实现（陈言，@noonsleeping）。7 种 tab 类型 + localhost sidecar + state.json，受 Theric K「HTML is the new Markdown」演讲启发。与官方插件不是同一项目。

为什么这很重要？

WHY IT MATTERS

  • 从「写完再说」到「先审后建」：改变人机协作节奏，从源头减少返工
  • 声明树让计划可导航：不是线性文本，而是有结构的决策地图
  • 编号决策点让反馈精准：说「第 3 项」比复述上下文快 10 倍
  • 原地反馈让循环完整：不出页面、不切窗口，一键导出答复
  • linting 减少失败：从流程设计层面规避 Claude 的常见失败模式
  • 单文件输出易分享：只需要浏览器，任何人都能审阅和反馈
