WeSight：本机 AI Agent 的桌面控制台

它把本机 CLI、模型供应商、IM 通道、技能市场、运行监控和桌面宠物收进一个可视化工作台。对已经在终端里跑 Claude Code、Codex、OpenClaw、Hermes Agent 的人来说，WeSight 不是再造聊天壳，而是把散落的配置和执行路径统一到一个控制面。

01

核心定位：把碎片化的本机 Agent 工作流收进一个控制面

先看判断，再看细节：WeSight 解决的不是“能不能跑 Agent”，而是“怎么把安装、权限、模型、IM、监控和扩展统一管理”。

先给结论

WeSight 的价值在于把终端原生编码 Agent 的碎片化流程产品化：你不必分别处理 CLI 安装、模型配置、权限事件、文件 diff、消息通道和运行监控，而是把它们放进同一张桌面工作台里，按任务去驱动。

如果你已经有一套可用的终端 Agent 生态，它更像“控制台”和“编排器”；如果你还没有稳定的本机环境，它更像一条更友好的上手路径。
02

工作流链路：它怎么把“本机 Agent”变成可管理系统

这部分不是功能清单，而是使用顺序：先发现/复用，再路由，再观察，最后扩展。

1. 发现并复用本机 CLI

A1
理论

WeSight 先做的是“识别你机器上已经有的 Agent 入口”，而不是强迫你重装一遍。这个设计把新手安装和老用户迁移放在同一条路径里。

用途
  • 从终端工作流迁移到图形化工作台。
  • 复用 Claude Code / Codex / OpenClaw / Hermes Agent 的既有配置。
  • 减少重复安装、重复登录和重复调试环境变量。

2. 统一模型供应商

A2
理论

模型配置在一个地方管理，再按引擎映射过去；这避免了“每个 CLI 一套模型设置”的分裂状态，也方便在同一任务里切换供应商比较效果。

用途
  • 在 OpenAI、Anthropic、Gemini、DeepSeek、Qwen、OpenRouter、Ollama 之间切换。
  • 给不同引擎设置不同的默认模型。
  • 接入 OpenAI-compatible 的私有网关或团队 endpoint。

3. 可视化执行与审计

A3
理论

它把一次 Agent 任务当成可追踪的运行单元：引擎、模型、Token、TTFT、TPS、工具耗时、状态和总耗时都被记录下来，方便比较和回放。

用途
  • 观察长任务卡在哪里、慢在哪一步。
  • 比较不同模型/引擎的输出速度和工具调用表现。
  • 在 live workspace 里直接看文件变更和产物落地。

4. 接入 IM 通道

A4
理论

WeSight 不把 Agent 限定在桌面前台，它能把任务变成 IM 入口和机器人配置。这样，执行、提醒、通知和互动就能脱离单一页面。

用途
  • 把飞书等消息路由到指定 Agent 引擎。
  • 按引擎隔离机器人配置，避免混用凭据。
  • 适合团队里做消息转任务、任务回执和协作通知。

5. 技能、记忆与调度

A5
理论

WeSight 不是单次会话工具，而是把技能市场、定时任务和记忆系统放在一起，让 Agent 形成连续工作流，而不是做完一轮就散。

用途
  • 安装和管理技能，扩展研究、创作和自动化能力。
  • 创建重复任务、监控任务和提醒任务。
  • 依靠记忆系统保留跨会话偏好与上下文。

界面证据：README 里真正展示出来的不是概念图，而是工作台

这 4 张图基本就把它的产品形态说清了：聊天、引擎、监控、工作区，不是单点工具。

▲ Cowork Chat / 协作对话

把本机 coding agent 直接放进桌面聊天流，适合对话、工具面板和权限事件一起看。

▲ Agent Engines / 引擎设置

Claude Code、Codex、OpenClaw、Hermes Agent、OpenCode、Qwen Code、DeepSeek-TUI、内置 runtime 一起管理。

▲ Runtime Dashboard / 运行仪表盘

▲ Live Workspace / 实时工作区

文件写入、代码变化、产物和活动记录同步可见，适合长任务和调试。

04

架构总览：Electron 主进程负责“管”，Renderer 负责“看”

这是它为什么适合做控制台，而不是单纯聊天壳的关键：职责分层清晰，安全边界明确。

Main Process / 主进程做什么

主进程负责窗口生命周期、托盘、桌面宠物、SQLite 持久化、Agent 引擎路由、外部 CLI 适配、IM gateway、技能管理、定时任务和文件活动跟踪。换句话说，真正“管活儿”的地方都在这里。

  • 用户、会话、消息、runtime calls、技能和 token 都落库。
  • OpenClaw / Hermes gateway 生命周期被单独处理。
  • 需要敏感权限和系统能力的操作都不直接暴露给 renderer。

Renderer / 渲染层做什么

渲染层负责 Cowork Chat、Studio、Live Workspace、Runtime Dashboard 和设置界面；它更像“操作台”，展示状态、接收输入、渲染流式输出和文件变更。

  • React + Redux Toolkit + Tailwind CSS。
  • 消息流、工具调用、命令输出、图片和权限事件都能可视化。
  • 安全隔离靠 preload bridge，而不是让页面直接拿 Node 能力。
05

边界与上手：它适合谁，什么时候该直接用，什么时候该谨慎

这是决策卡里必须说清楚的部分：它是本机 AI Agent 控制台，不是通用云端 SaaS。

适合谁

  • 已经在终端里使用 Claude Code、Codex、OpenClaw、Hermes Agent 的人。
  • 需要把 IM 通知、技能、调度和监控收拢到一起的团队。
  • 想在 macOS 上快速验证本机 Agent 工作台形态的开发者。

不适合 / 要注意什么

  • 它面向本机环境与桌面工作流，不是纯在线聊天产品。
  • README 说明当前公开版主要面向 macOS Apple Silicon 和 Intel。
  • 开发环境要求 Node.js >=24 <25，部分能力还需要你已经有可用的本机 CLI。
# 本地开发最小路径
git clone https://github.com/freestylefly/wesight.git
cd wesight
npm install
npm run electron:dev # 启动开发工作台
# 如果下载的是 macOS DMG，先移除隔离属性再打开
xattr -cr /Applications/WeSight.app

一句话结论

WeSight 不是一个“再做一个 AI 聊天框”的项目，而是一个把本机 Agent 生态变成可视化、可配置、可审计、可扩展控制面的桌面工作台；如果你已经在做本地 Agent 工作流，它很值得看。

来源：freestylefly/wesight 仓库 README / README_zh.md / package.json。关键事实：支持 8 种 Agent 引擎、10 类模型供应商、技能市场、IM 集成、定时任务、记忆系统与本地工作台；公开版本以 macOS 构建为主，开发要求 Node.js 24.x。

适合什么判断

当你要评估一个“本机 AI Agent 桌面控制台”值不值得用，优先看它是否把 CLI、模型、权限、IM、监控和技能统一到一个入口，而 WeSight 正好把这条链路完整展示出来了。

最小使用建议

  • 有现成本机 CLI：直接复用现有配置。
  • 没有本机环境：先从 release 版感受 UI 和工作流。
  • 要团队化：优先验证 IM 通道、技能市场和运行审计。
