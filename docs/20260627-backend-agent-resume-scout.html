一句话判断
Star 数不是标准，源码证据才是。帮你在 GitHub 里找到真正经得起面试追问的简历项目。
解决什么
不再靠 star 数选项目
不再把 demo、浅层 CRUD、框架壳子当成简历项目。Skill 会主动淘汰这些。
怎么验证
必须拉源码，不能只看 README
最终入选项目必须拉取本地源码，提取负责功能和技术难点，不是靠模型记忆。
交付什么
直接可用的简历项目包
80-120 字项目简介 + 5-6 条技术难点 + 面试追问方向 + 改造建议，Markdown + PDF。
使用方式
Use $backend-agent-project-selector 推荐模式：mixed 技术栈：Java / Python 目标岗位：后端实习 时间预算：2 周 背景水平：普通本科，无实习 项目偏好：一个新奇 Agent 项目， 一个有业务闭环的扎实后端项目 避开方向：浏览器插件、简单聊天机器人、 IoT、硬件接入
直接在 Codex / Cursor 的 Skill 输入框里粘贴上述内容，Skill 自动执行完整工作流：搜索 → 筛选 → 用户确认 → 源码验证 → 输出简历包。
为什么有这个 Skill

大多数求职者找简历项目的问题不是"找不到"，而是"不知道什么值得写"。

• 按 star 数找 → 选了过热、同质化、烂大街的项目

• 选 demo / 薄封装 → 面试官一看就知道深度不够

• 简历写"负责 XXX" → 一问源码、异常处理、状态流转就露怯

牛肉项目雷达把"找项目"变成可验证的决策流程：先搜候选池，再让源码说话。
01
推荐模式
必须先选模式，Skill 才开始搜索。不选模式 = Skill 会反问。
模式 说明 适合人群
agent-only 只推荐有完整业务闭环的 AI Agent 项目，排除 demo 和简单聊天机器人 想把 Agent 项目写进简历的人
backend-only 只推荐传统软件后端项目，默认排除 IoT / 硬件接入类 投纯后端实习 / 校招的人
mixed 推荐一个 Agent 项目 + 一个传统后端项目 没有明确方向，想两边都准备的人
safe-mode 推荐容易落地、依赖少、部署成本低的项目 时间紧、快速出活的候选人
challenge-mode 推荐更难、更有差异化、适合深度改造的项目 有 2-4 周时间、想深度准备的人
02
工作流程
README 和搜索只能用于前置筛选，"负责功能 / 技术难点"必须来自本地源码。
用户画像与推荐模式 ↓ 联网搜索 GitHub / Web（构建多样化候选池） ↓ README probe 与项目类型初筛 ↓ 输出 3-4 个短名单项目（含淘汰理由） ↓ 用户确认方向 ↓ 拉取 GitHub 仓库到本地 ↓ 基于源码提取证据点 ↓ 生成 Markdown / PDF 简历项目包
关键原则：README 和网页搜索只能用于前置筛选。最终"负责功能 / 技术难点"必须来自本地源码验证，不靠 README 或模型记忆判断。
03
淘汰哪些项目
Skill 会主动排除这些，不出现在候选名单里。
明确淘汰

• Demo 级项目（没有完整业务流程）

• 薄封装 / 框架壳子（只套了一层框架）

• 浏览器插件（技术深度难证明）

• 简单聊天机器人（无业务数据）

• 浅层 CRUD（无法区分于课设）

优先覆盖

• 电商交易系统（含订单、支付、物流状态）

• CRM / ERP（含权限、审批流转）

• 协作办公平台（含消息、任务、工单）

• 知识库 / Agent 工作流（含多步骤串联）

• 业务型 AI Agent（含真实用户数据）

04
输出内容
简历项目包的内容结构。
输出文件 包含内容
backend-agent-project-shortlist.md 候选项目、选择理由、主要风险；用户确认后进入下一阶段
backend-agent-project-resume-pack.md 最终简历项目包：源码验证摘要 + 80-120 字项目简介 + 5-6 条技术难点 + 面试追问方向 + 改造建议
backend-agent-project-resume-pack.pdf Markdown 的 PDF 版，适合阅读和分享
repo-source-manifest.json 本地源码拉取结果和仓库状态记录
