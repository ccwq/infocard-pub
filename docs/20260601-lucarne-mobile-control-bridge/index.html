Lucarne：本地 AI Agent 的微信/Telegram 移动控制桥

Lucarne 不改你的 agent 工程，不加 hooks、skills 或 MCP；它把通知、审批、续接上下文和会话控制，接到手机上的微信 / Telegram 里。

01 / 核心判断

takeaway
一句话结论

Lucarne 不是一个新聊天工具，而是把本地 AI agent 的“盯进度、批命令、接上下文”搬到移动端的事件桥。你依然在本机跑 Claude / Codex / Gemini / Copilot / Pi，只是把关键控制放到微信或 Telegram 里做。

这张海报在说什么

Stop babysitting local AI agents. 这是它的产品主张：不再守着电脑盯 agent，而是通过手机通知、审批和回复来接管关键节点。

适合谁：已经在本地跑 agent、但不想一直守着终端的人。

不适合谁：想把它当成通用 IM、或想完全替代 agent CLI 的人。

02 / 能力表格

capabilities
能力 它做什么 第一步 边界
通知 把完成、卡住、失败、需要介入的关键事件推到手机。 lucarned init 只推关键事件，不是全天候流水账。
审批 在手机上对命令做 Approve / Deny。 /panel 入口 chat 需要 Topics / thread mode。
续接上下文 引用通知即可恢复对应的 agent session。 直接回复那条通知 依赖 message_id 或引用文本 hash。
会话控制 查看状态、打断、分支会话，继续在原上下文里工作。 /status / /interrupt / /fork 一个 topic 对应一个 live session。
双通道接入 同时面向 Telegram 和 WeChat，保留你已有的通讯习惯。 先选一个入口开始 更多渠道在 roadmap 里，不是当前主线。
Agent 兼容矩阵摘要

Claude / Codex / Gemini / Copilot / Pi 都可接入；其中 Claude、Codex、Gemini 的结构化审批和 Resume 支持更完整，Copilot 偏轻量，Pi 偏基础但可用。

关键判断

Lucarne 的价值不在“多一个 UI”，而在把 agent 工作流里的关键动作变成可移动、可审批、可续接的事件流。

03 / 入口与证据

onboarding

使用顺序

1. 安装 lucarned；2. 跑 lucarned init 配好 agent 和入口 chat；3. 执行 lucarned autostart install --start；4. 在 Telegram / WeChat 中打开面板并接收通知。

最先试的不是新命令，而是先让“通知 → 审批 → 续接”这一条链跑通。

仓库里原本就提供了二维码入口。 如果要快速给别人演示，二维码比长链接更适合传播。
