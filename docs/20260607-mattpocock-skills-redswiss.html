0FOUR FAILURE MODES · 为什么需要这些技能
#1
Agent 没有做我想要的

你和 Agent 之间存在"沟通缺口"——你以为它懂了，它实际在猜。

Fix: /grill-me / /grill-with-docs
#2
Agent 说得太冗长

Agent 落入项目后要自己猜行业术语，用 20 个词说 1 个词能说清的事。

Fix: Ubiquitous Language + /grill-with-docs
#3
代码跑不通

没有反馈闭环：Agent 写完代码不知道是否真的 work，盲飞。

Fix: /tdd（红绿重构）+ /diagnose（调试环）
#4
架构变成泥球

Agent 加速了开发，也加速了软件熵增——代码库复杂度以前所未有的速度增长。

Fix: /to-prd + /zoom-out + /improve-codebase-architecture
1ENGINEERING · 代码工作流 · 10 个技能
/diagnose调试

将最佳调试实践封装为结构化循环：reproduce（复现）→ minimise（最小化）→ hypothesise（假设）→ instrument（埋点）→ fix（修复）→ regression-test（回归验证）。用于定位棘手 bug 和性能回退。

/grill-with-docs需求对齐

比 /grill-me 更强的版本：在需求对齐的同时，帮助建立 Ubiquitous Language（统一语言），更新 CONTEXT.md 和 docs/adr/ 中的 ADR 决策记录。适用于需要深度澄清的复杂变更。

/triageIssue 分诊

通过分诊角色状态机对 Issue 进行分级分类。需要先通过 /setup-matt-pocock-skills 配置 labels。输出结构化 triage 结果，适合团队协作流程。

/improve-codebase-architecture架构重构

基于 CONTEXT.md 中的领域语言和 docs/adr/ 中的决策记录，分析代码库中模块深度不足的地方，找出可以"深化"（deep module）的机会。建议每隔几天跑一次，防止架构熵增。

/setup-matt-pocock-skills初始化

为仓库建立 per-repo 配置（Issue Tracker / Triage Labels / Docs 路径），是其他所有工程技能的依赖项。每个仓库只需运行一次。

/tdd测试驱动

强制红-绿-重构循环：Agent 先写失败测试，再修复测试，最后重构代码。每次只推进一个功能竖切片（vertical slice），保持反馈频率高、步子小。

/to-issues需求拆分

将任意计划、规格文档或 PRD 拆解为可独立领取的 GitHub Issues，按垂直切片原则组织。每个 Issue 足够小、可测试、可独立合并，适合团队分发任务。

/to-prdPRD 生成

将当前对话上下文合成一份 PRD，提交为 GitHub Issue。不需要额外访谈，直接基于已讨论内容生成结构化产品需求文档。

/zoom-out宏观视角

让 Agent 在更宏观的上下文背景下解释代码：模块在整个系统中扮演什么角色、依赖关系如何、为什么这样设计。用于接手陌生代码库时的快速理解。

/prototype原型验证

构建可丢弃的原型来验证设计决策：状态/业务逻辑问题用终端可运行程序，UI 问题用多条完全不同风格的路由变体（同一 route 可切换）。快速试错，不污染主分支。

2PRODUCTIVITY · 工作流工具 · 5 个技能
/caveman压缩

极压缩通信模式：将 token 消耗降低约 75%，同时保留完整技术准确性。去掉填充词，只留技术核心。适用于高速迭代或 token 预算紧张时。

/grill-me需求对齐

最受欢迎的技能：对计划或设计方案进行"审讯式追问"，直到决策树的每个分支都被覆盖。适用于所有需要开始变更的场景，确保你想清楚了再做。

/handoff交接

将当前对话压缩为交接文档，让另一个 Agent 可以继续当前工作。包含上下文摘要、已做决策、待解决问题、下一步建议。

/write-a-skill技能创作

创建新技能的标准工作流：结构化模板 + 渐进式信息展示 + 打包资源（references/templates/scripts）。确保技能小、可复用、有清晰的触发条件。

3MISC · 辅助工具 · 4 个技能
/git-guardrails-claude-codeGit 安全

为 Claude Code 设置 Git Hook，在危险命令执行前拦截：push、reset --hard、clean 等不可逆操作需要显式确认。防止 Agent 意外破坏仓库历史。

/migrate-to-shoehorn类型迁移

将测试文件中的 as 类型断言迁移到 @total-typescript/shoehorn，实现编译期类型安全检查。减少运行时类型错误，提升 TypeScript 项目健壮性。

/scaffold-exercises练习脚手架

创建标准化练习目录结构：包含 sections（章节）、problems（问题）、solutions（解答）、explainers（讲解）四个部分。适合教学、团队内部分享或自学。

/setup-pre-commitGit Hooks

配置 Husky pre-commit hooks：lint-staged + Prettier + 类型检查 + 测试。确保每次提交前强制执行代码规范和类型检查，保持代码库质量基线。

核心设计哲学：这些技能不是"AI 做主"的黑盒流程，而是"AI 辅助工程"的工具集。软件工程基础比以往任何时候都更重要——这些技能把数十年工程经验压缩为可重复实践的操作步骤。Small · Composable · Adaptable。
