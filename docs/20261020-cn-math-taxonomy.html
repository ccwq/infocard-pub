02

图谱的三层结构

图谱分三层：节点层 802 个知识点、边层 1299 条先修关系、题库层 3355 道题，另挂 310 条课标做对齐锚点。字段是固定的，节点记录含 id、name、domain、grade、semester、chapter、type、description、mastery_criteria、diagnostic_question、external、standards、root_reason，边记录只有 topicId、prerequisiteId、strength、reason 四项。

取一条真实记录看：九年级「配方法」。它的两条 hard 先修分别指向「直接开平方法」和「完全平方公式」，边上的 reason 字段就是用来写清为什么必须先掌握前者——没有这两项，配方这一步做不动。

domain:    数与代数

chapter:   第二十五章 一元二次方程 25.2
type:      procedural
description: 通过配方把方程化为 (x+m)²=n 的形式再求解，
             配方时加上一次项系数一半的平方。
mastery_criteria: ["能完成配方", "能用配方法解方程"]
standards: cms-2022:4.NA.27 · confidence = exact
hard 先修:
  - cnm_220 直接开平方法 · reason: 配方后用直接开平方
  - cnm_148 完全平方公式 · reason: 配方依据完全平方公式

这道题绑定了一道真实选择题，四个选项与错因都是数据文件里的原文：

题号:  cnm_221_q1
题型:  choice · difficulty: standard
题干:  用配方法解 x²-4x-1=0。下列配方及结果正确的是哪一个？
A:     (x-2)²=3，x=2±√3
B:     (x+2)²=5，x=-2±√5
C:     (x-2)²=5，x=2±√5

答案:  C
explanation: 移项 x²-4x=1，两边加 (4/2)²=4 得 (x-2)²=5，所以 x=2±√5。
             A 漏加了常数项的处理，B 符号错，D 配方时加错了数。

03

答错才回溯的自适应诊断

规则来自 diagnose/engine.js 的头注释与测试名，本卡按原文顺序整理成六个动作。同一知识点最多出 2 题，出题序列由随机种子决定，可复现。

① 第一题答对判为掌握，并顺带推断它的祖先知识点也已掌握，不再逐点重复出题。
② 第一题答错或不会先补一道同级或更容易的题：优先取 basic，其次同难度，再取更容易的。
③ 第二题答对判为不稳，到此为止，不回溯。
④ 判薄弱并回溯第二题仍错才向先修回溯——这是整台引擎的分岔点，回溯时 hard 先修排在 soft 之前。
⑤ 生成学习路径取根因知识点与全部不稳点的后代，减去已掌握的部分，按拓扑序排列。
⑥ 图谱呈现知识图谱默认只画当前点向上 2 层、向下 1 层的局部图，祖先超过 40 个时按年级收起。
整册筛查模式：题量上限在 20 到 60 之间可调，默认 40；筛查范围之外的先修知识单列提示，不混进题目；结果页按章汇总，薄弱章排在前面。

要强调口径边界：以上是代码规则与本地测试覆盖下的行为。本卡没有在浏览器实跑诊断页，也没有真实学生样本的定位准确率数据，「测试通过」不能写成「教学有效」。

05

边界与未验证项

边界必须分档写，混在一档里就会把作者自陈读成实测结论。本卡把全部条目拆成事实、作者自陈、本卡未验证三档。

事实档（本卡亲手复算）

  • 逐条解析 raw JSON 得到 802 / 1299 / 3355 / 310，与仓库自带 scripts/validate.py 输出交叉一致。
  • 本地实跑：validate 输出 VALIDATION PASSED（exit 0）；node tests/test_engine.js 输出 82 passed、0 failed，即 82 项测试全过。
  • 复核分五轮：全量盲解 1401 题（19 个解题者）发现 3 处不一致，经计算裁决全是解题者算错；风险题盲解 752 题、小学 864 题独立复核均 0 不一致。

作者自陈档（README 与数据内标注）

  • AI 生成初稿，未经一线教师审核；先修边 hard / soft 判定需要教师复核后才能用于教学。
  • 532 题无法自动核验，且本卡统计发现它们全部集中在初中（这批题的 verify 字段为空）；高中 1084 题的答案与核验式同源、没做初中那种独立盲解。
  • 310 条课标里 153 条 verbatim 为 false，未与教育部 PDF 逐页核对；教材目录取自 dzskb.com 等第三方站点、无页码。
  • 复核解题者与出题者同属一个模型家族，共同的系统性误解不一定查得出；几何题只按文字条件解，无图形。

本卡未验证档

  • 未在浏览器实跑 /diagnose/ 页面，机制结论只由代码规则加本地测试支撑。
  • 未安装成教学系统，没有真实学生样本的定位准确率测试。
  • 难度分级 basic / standard / advanced 的实际区分未独立验证。
  • 原帖「AI 辅导工具可升级成个性化学习规划工具」是转发者的评价，不是仓库自述。

册次到 grade 的映射（必修第二册记成高二必修一类编号）是为分册做的排序，不是教学进度规定。另有一条 open issue #3（2026-10-20 07:17 UTC）：2026 年 9 月发布的新版教材尚未对齐，仓库目前用的是 2024 年审定的人教版新版初中目录，按教材页码或章节定位时要重新核对。

06

接手检查清单

下面五条动作按「先复算、再抽核、后接场景」排，每条给一个可观察的完成信号。

  1. 跑一遍自带校验，复现本卡口径：仓库根目录执行 python3 scripts/validate.py，再执行 node tests/test_engine.js。输出 VALIDATION PASSED 且 82 passed、0 failed，说明你抓的 main 与本卡同一条线；不一致就先比对 commit。
  2. 抽查 5 条 hard 边，逐条判断先修方向是否成立——是「不会前者就没法做后者」，还是只是「先学更顺」。每条边都能写出一句具体的障碍；写不出的，降级为 soft 或送教师复核。
  3. 单独复核 standards 为空的两点：cnm_130 全等三角形的常见辅助线与模型、cnm_192 四边形中的折叠与动点问题。补上课标映射，或明确标注为不对齐条目；800 / 802 的覆盖数因此可被解释。
  4. 按自己手里的教材版本重新核对册次与章节，尤其是 2026 年 9 月新版教材与 open issue #3 涉及的目录差异。每个用到的知识点能锚定到具体册次和章，且与第三方目录站点的旧数据冲突时知道以谁为准。
  5. 商业使用前先取授权：CC BY-NC 4.0 禁止商用，接入付费辅导或规划产品前与作者谈书面许可，同时自查所引课标条文自身的版权。留档授权沟通记录；vendor 三个图形库的 MIT 声明随仓库保留，分发时不要剥离。
核心判断：数据可核验、机制有测试、许可写清楚了，但先修关系仍是机器初稿——接手省下的是搭骨架的时间，省不掉的是教师复核。
