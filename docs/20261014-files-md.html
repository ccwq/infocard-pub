FILES.MD / 本地 Markdown 工作流

笔记先落在自己的文件夹，
再决定是否同步

Files.md 是以普通 .md 文件为核心的开源笔记应用。用浏览器捕获想法、写日记、整理任务；不是必须安装的桌面软件，也不应把它当成默认带 AI 的聊天工具。

本地优先浏览器 / PWAMITWeb Beta
适合谁想保留可被文本编辑器直接打开的笔记，愿意用文件、链接和简单清单组织内容的人。
先不要迁移什么整盘资料、机密文档、依赖复杂插件的笔记库；官方说明只支持一层目录嵌套。
第一步：新建一个空测试文件夹，打开 Web 应用，只授权这个文件夹。先确认一条笔记真的保存到磁盘，再考虑接入现有资料。

01 / 先验证保存

首次使用：浏览器 → 文件夹 → 一条笔记

  1. 用 Chromium 系浏览器打开 app.files.md。README 认为 Chrome、Brave 等对 File System API 的支持更好；不保证所有浏览器行为一致。
  2. 打开本地测试文件夹，确认浏览器的文件访问授权。要将修改持久保存到普通本地文件，必须打开本地文件夹；看到编辑界面不等于已写入目标目录。
  3. 新建 test.md，写入一句可辨认的文字并保存；用外部文本编辑器打开该文件，核对内容。
  4. 关掉再打开应用，重新进入同一目录，检查能否读回；需要时重新授权。然后复制一份目录作为备份。

上述步骤是建议的首次验收路径，并非我们已操作应用的实测记录。

地址栏的 “Install files.md” 是可选 PWA 安装入口。无需安装桌面客户端也能用；README 宣称支持离线，但先完成应用加载与目录授权，再验证你的浏览器能否离线读写。
02 / 不打断当前工作

聊天式捕获，只是快速写入入口

按 Cmd/Ctrl + Enter 打开 chat，输入内容再按 Enter，笔记会保存为 Markdown 文件。这里的“chat”指捕获界面，不等于内置 LLM 对话。

  1. 先把“周五前把报告发给同事”写进去，不急着建分类。
  2. 空闲时再决定去向：具体笔记移入文件，稍后任务转到 Later，日记转到 Journal。
  3. 拆分长记录：一条笔记讲清一个想法，再通过文件链接连接相关内容。
临时收集Chat.md：先落笔，稍后整理
主题笔记brain/*.md 或根目录下的 *.md
归档与资源archive/*.md、media/

这些是 README 给出的文件约定，不是要求首次就建齐所有目录。配置文件为 config.json；不清楚字段含义时，不要猜值修改。

03 / 给记录一个明确去处

日记、稍后任务与清单

今天发生了什么点击 “To Journal”，或在消息末尾加空格与 jj / жж。记录进入 journal/YYYY.MM Month.md。
以后要做什么点击 “To Later”，任务进入 Later.md。把“做一个项目”改成“写出项目的第一份需求草稿”这类可执行小步。

书单、观影和购物清单对应 Read.md、Watch.md、Shop.md；习惯记录示例为 habits/*.md。按需要逐步使用，不要把文件结构误当自动提醒、日历或完整项目管理系统。

小样验收：保存一条日记，去目录核对实际月份文件；再创建一条任务并勾选，核对 Markdown 内容。不同入口与配置的显示细节，以当前应用为准。
04 / 先学少量高频操作

文件之间用链接连接

输入 [ 可插入文件链接；优先用应用生成的链接，不要自行假定任意 Obsidian 插件或整个 vault 都兼容。先建两份测试文件、插一条链接，再验证跳转。

快捷键用途使用提醒
Cmd/Ctrl + K搜索文件先找已有笔记，再决定是否新建
Cmd/Ctrl + N新建文件先在测试目录试命名和保存
Cmd/Ctrl + M移动文件移动后检查相关链接

Cmd/Ctrl + T插入表格适合简短、结构化记录
05 / 选择数据经过谁

本地优先，不代表每条同步路线都只在本地

README 区分四种配置。隐私判断要看实际存放目录、是否启用同步、谁运营服务器，不能把本地模式的说明套到所有路线。

路线文件位置 / 同步隐私边界与选择条件
纯本地设备上的文件夹；不跨设备同步；无需笔记同步服务器README 称本地模式不发送笔记数据。适合先验证本机工作流；不等于网页加载等活动“零联网”。
云目录iCloud / Dropbox / Google Drive 目录；由云服务同步不必自己部署服务器，但供应商会处理同步数据。只授权愿意交给该服务的笔记。
Go 自托管自己的或本地服务器；支持跨设备同步需要部署、维护和访问控制。数据会经过所部署的服务；局域网可用是场景，不是自动安全保证。
托管同步作者管理的 api.files.md；支持跨设备同步笔记离开本机，交由外部服务处理。接入 Telegram Bot 同样引入 Telegram 与相关服务的传输边界。
选择规则：只需一台电脑 → 先纯本地；接受现有云商 → 云目录；需要自己掌控同步服务且能维护 → 自托管；选择托管或 Bot → 先确认可接受外部传输。

自托管按官方 部署文档操作；Bot 参见 说明。本卡不把这些路线描述为端到端加密，也不承诺同步自带可靠备份。

06 / 先约束，再给访问

Agent 能读 Markdown，不等于可以无限改写

普通 .md 适合交给外部 Agent 读取或整理。README 建议放置 AGENTS.md，也强调可以让 LLM 扩展应用源码；扩展源码是开发定制路线，不是默认内置 AI 功能。

以下是可自行采用的约束示例，不是官方默认配置，也不是强制权限机制：

# 笔记处理约束（示例）
默认只读；先列出拟修改文件与理由。
只处理 test-notes/ 中的样本，不读相邻目录。
未经确认，不删除、移动或批量改写文件。
修改前由用户制作独立备份，再做小样并核对差异。
未经授权，不将笔记发送到云端模型或外部服务。

确认 Agent 实际使用的模型提供商和工具权限。云端 LLM 可能收到笔记内容；本地应用并不会自动让外部 Agent 也变成本地处理。真正的访问范围应由目录权限、沙箱和工具配置落实。

07 / 先保护文件，再排错

遇到问题，从最小样本检查

看得到文字，磁盘却没找到文件？

先确认已经打开目标本地目录、授权允许写入；用 test.md 做外部编辑器核对。不要把浏览器里的初始存储当成已经导出的普通文件。

换浏览器、清理数据或撤销权限后打不开？

重新选择原目录并授权。浏览器清理数据或撤权可能影响保存的目录访问状态；先用系统文件管理器确认原文件还在，不要直接覆盖或重建整个笔记库。

旧界面、深层目录或同步出问题？

README 建议用 Cmd+Shift+R 获取新版本，但强制刷新不是备份。目录只支持一层嵌套，先用浅目录复现；同步异常时先复制各端现有文件，再排查，不做未经核对的双向覆盖。

备份建议：定期把整个笔记目录复制到独立位置，保留多个时间点；包含 .md、媒体与配置。试着从副本恢复一条记录。同步可能传播删除，所以“另一台也有”不等于可恢复备份。

这不是自动安全的机密库。是否适合敏感信息，还取决于设备保护、目录权限、云服务、服务器配置及 Agent 数据流。
