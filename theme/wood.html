AGENTIC ENGINEERING ≠ VIBE CODING
从“能跑的原型”到“可交付的工程”。
Vibe Coding

Karpathy 风格

更偏 prototype level，通常不做代码审查，追求快速摸到结果。

Agentic Engineering

Willison 风格

面向 production-ready：review + testing + harness，强调可维护与可验证。

写代码变便宜了，写好代码并没有。
当直觉告诉你“不值得手工做”时，可以试试异步 agent；最坏情况也只是浪费几分钟 token，但换来的是一次更快的探索和一个可验证答案。
1 定目标 先让问题空间里出现足够多的候选解法。
2 给工具 提供足够详细的规格、上下文和边界。
3 验结果 用测试、运行和证据验证输出可靠性。
4 写回 harness 把学到的东西固化成可复用系统。

PRINCIPLES

五大原则

1

定义边界

专业工程师的能力上限不是 vibe coding；人类负责定目标、供工具、验结果、写回 harness。

2

接受新约束

写代码便宜了，但写得好仍然昂贵；要克服跳过测试、文档与重构的老习惯。

3

囤积可复用解法

把可运行、可证明的片段保留下来，让 verified examples 彼此组合。

4

质量应上升

把任务交给 agent 之后，技术债应当被清理；指令也要在任务后继续变好。

5

严守反模式

不能提交未 review 的 PR；代码必须能跑、体量要小、上下文要够、要有测试证据。

MECHANISM · GIT · SUBAGENT

先懂机制

Agent 机制

LLM + System Prompt + Tool Loop

长对话成本更高，模型本身无状态，所以上下文需要反复传入；复杂调试时 reasoning / thinking 依然有用。

Git

大胆用，不必背

把“恢复今天的改动”“整理 git mess”“git bisect 找回退点”等任务交给 agent，Git 更像一个可操作对象而不是记忆负担。

Subagent

省上下文，但别过度切碎

Explore 先摸清仓库结构；Parallel 并行改多文件；Expert 负责 review / run / debug 并只回报结果。

TESTING · CODE UNDERSTANDING

测试与理解代码

Testing
  • TDD：先写测试，再确认失败，再实现到通过。
  • 新对话先跑全量测试。
  • 手动验证：`python -c`、`curl`、`Playwright`。
  • Showboat：留下真实命令与输出，避免 AI 编造结果。
Good Code

要能运行、能证明跑过、解决正确的问题、处理错误路径、尽量简洁并维持可维护性，同时保持 safety 与 observability。

Pay back cognitive debt

对陌生代码做线性 walkthrough；用工具理解而不是手工复制；必要时用可暂停、可调整的交互式说明方式去补认知债。
